# NotificationStack

`NotificationStack` 是一份通知队列的可视出口：把队列里的通知固定显示在视口边缘，并集中处理自动消失、悬停暂停、关闭、通知动作与“详情”对话框。它本身不创建通知；宿主挂一个视口，就能显示经该队列发出的通知。队列缺省是 `useNotification()` 的模块级队列；要隔离时（一个窗口一份、Lab 场景、测试）用 `createNotificationQueue()` 自建一份传给 `queue`。

## 布局

通知按创建顺序纵向排列（不论位置，最早的在上、最新的在下），间隔 8px；每项由 `Notification` 渲染。最多显示最新的 `maxVisible` 条（缺省 4）；更早的折起来，整列最上面是一个折叠小条“还有 n 条较早的通知”。点它展开全部（文字变成“收起”），展开时列表在一个纵向滚动区里，最高到视口高度减去上下留白，展开时与新通知到达时滚到最新一条（通知减少时不滚）；总数回到上限以内时自动回到收起态。折叠只按时间，不区分常驻的错误与限时的提示；折起来的限时通知照常到时消失。固定容器最大宽度为 448px（含两侧各 16px 内边距），单条通知内容区最大约 416px。默认固定在视口底部水平居中，也可固定在右上或右下；靠右时卡片离右边 16px（容器的内边距），窄屏上整列不越过左边。通知不拦截空白处的指针事件，单条通知可交互。

在窄屏中仍使用所选边缘位置和居中规则，宽度受视口与外边距约束，内容超长由通知自身排版；进入和离开分别淡入淡出并沿纵向移动 8px。

## 交互

- 队列中的通知由队列自动移除；指针进入某条通知时暂停它的自动关闭计时，离开后按剩余时间恢复，且至少留出 800ms；暂停期间队列改了它的时长（`update`）也只记下新的到期时间，不会到点移除。
- 带动作的通知显示动作按钮。点击后调用该通知携带的 `action.run()`，随后移除该通知；`run` 抛错时同样移除，错误照常抛给 Vue 的错误处理。
- 不论通知是否有自动关闭时长，视口都将每条通知设为可关闭；点击“关闭通知”按钮后从队列移除该项。
- 带进度的通知显示进度条（`Notification` 的 `progress`），发出方经队列的 `update` 推进。
- 带详情的通知（`hasNotificationDetail(item.detail)`）显示“详情”。点它打开一个 `DetailDialog`：标题是“通知标题：详情”，通知没有标题时只写“详情”；内容是点开那一刻的原文快照，通知在对话框打开期间被移除，对话框照常显示。标题由快照里的文字值在渲染时翻译，打开后切换语言标题跟着换。同一时间只有一个详情对话框。
- 对话框打开期间整个视口 `inert`，层级降到模态之下、被遮罩盖住：通知平时的层级高于对话框，不这样的话通知会画在遮罩与对话框上面、还能点，与“模态”矛盾。所以看着原文时点不到“重试”，要先关对话框（已接受的取舍）。
- 关对话框后焦点回到打开它的“详情”按钮；那条通知已经不在（被移除或折进了折叠小条）时，焦点落到视口根上（`tabindex="-1"`，不滚动页面），不落到 `body`。
- 折叠小条是真实按钮，带 `aria-expanded` 与 `aria-controls`；展开收起后焦点留在它上面。视口根是 `role="region"`，可访问名称“通知”，键盘与读屏用户能到达这一块。
- 动作、详情与关闭按钮的键盘、焦点和可访问名称由子组件 `Notification` 的按钮承担；本组件自身不注册快捷键。

## 数据

```ts
type NotificationPosition = "bottom-center" | "bottom-right" | "top-right";

interface NotificationStackProps {
    /** 通知堆叠位置；默认 "bottom-center"。 */
    position?: NotificationPosition;
    /** 每条通知关闭按钮的可访问名称与 title；不给则每条通知按界面语言取缺省（中文 "关闭通知"）。 */
    closeLabel?: string;
    /** 显示哪份队列；默认 `useNotification()` 的缺省队列。挂载时取定，之后换 prop 不生效，换队列应换一个视口实例。 */
    queue?: NotificationQueue;
    /** 最多显示几条（最新的）；默认 4。不是有限数时取 4，否则向下取整、至少 1。 */
    maxVisible?: number;
}

interface NotificationStackEmits {}
interface NotificationStackSlots {}
```

没有 `update:*` 事件，通知列表不受控于 props；组件不 expose 方法或属性。根节点是一个固定定位的容器（`data-notification-stack`），未声明的 attrs 落在它上面。

## 状态与边界

- 空队列：容器内没有通知。
- 有通知：按队列顺序堆叠；通知的 tone、标题、消息、动作、进度和时长来自队列里的 `NotificationItem`，其中标题、消息与动作名是文字值，渲染时按当前语言翻译。
- 视口强制每条通知 `dismissible: true`，所以视口中总有关闭按钮。
- 超过上限：只渲染最新的 `maxVisible` 条，最上面一个折叠小条；展开后全部渲染。
- 详情对话框打开：视口 `inert`、在遮罩之下；对话框里是快照，与队列之后的变化无关。
- 本组件没有禁用、只读、加载或错误状态。

## 不支持

- 不提供创建、更新或清空通知的 props、slots、emits 或 expose API；这些动作由队列（`NotificationQueue`）提供。
- 不提供逐条可配置的停留时长或动作确认流程；时长及动作函数随通知数据一起提交。
- 不按通知类型分别折叠，不去重，没有“全部关闭”与通知历史。

## 隐藏通道理由

`env:timer`：自动关闭计时器由队列管理，视口在悬停时暂停、离开时恢复该计时器。计时与通知队列生命周期相同，集中在队列里处理。

`state:local`：折叠小条是否展开、详情对话框的开关与快照、打开它的按钮。

`env:portal`、`env:global`、`env:clipboard`：来自内部挂的 `DetailDialog`（对话框传送到 body、Escape 与焦点锁定、复制原文），理由见 [`DetailDialog.md`](DetailDialog.md)。视口自己挂这一份对话框，而不是发事件让宿主去开：每个挂视口的宿主都要同一个对话框，焦点归还又要知道是哪颗按钮打开的。

`state:inject`（翻译端口）：队列里通知的标题、消息与动作名是文字值（字符串、语言映射或文字引用），本组件在渲染时经注入的翻译端口翻成当前语言，切换语言后已显示的通知跟着换文字；字符串原样显示。折叠小条、视口根的名称与详情对话框的标题经 `useUiText()` 取；关闭按钮的缺省名称由 `Notification` 经翻译端口取（见 [`Notification.md`](Notification.md) 的隐藏通道理由）。`closeLabel` 给了就原样传给每条通知，不给则不传。
