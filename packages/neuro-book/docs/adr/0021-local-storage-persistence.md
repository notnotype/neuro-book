# ADR 0021：本地持久化、客户端分区与布局消费

- 状态：Accepted
- 日期：2026-09-16
- 决策来源：开发者确认首期本地持久化、project 尺寸、项目内存储与浏览器标题栏优先；计划审查后回复“可以，优化补充”
- 补充：[ADR 0020](0020-user-project-storage-boundaries.md)；其中当时未决的本期持久化与消费者归属由本 ADR 收敛，职责与两个 scope 保持有效
- 行为合同：[storage.persistence](../../../../docs/specs/storage/persistence.md)、[ui.nested-grid](../../../../docs/specs/ui/nested-grid.md)

## 背景

NeuroBook 的持久化同时服务主工作台、内置插件和后端模块。只抽一个前端 KV 接口，不能解决 Project 代次、
同项目多标签、浏览器身份、目录复制、备份和旧 Pinia 写者之间的关系。
开发者当前通过备份恢复轮流使用不同机器，要求状态在 data 内，同时希望尺寸按项目、本客户端分别记忆。

审查还确认主界面的平面 grid 可用性不能证明插件嵌套布局可复用，必须在冻结其保存格式前完成最小嵌套验证。

## 决策

1. **本地持久化先行。** Config 沿用原服务与统一同步目标；Storage 首期不建设独立 data 之间的同步协议。
   `local/shared` 表达状态定义的客户端归属差异，默认 local；shared 只省略客户端维度，不代表跨用户共享或已同步。
2. **状态值存于 data。** user 放在 WorkspaceRoot 的 `.nbook/storage`，project 放在各 ProjectRoot 的 `.nbook/storage`。
   项目内记录自然随完整目录移动、复制、删除，首期无需为了布局建立全局 Project UUID 或路径墓碑索引。
3. **身份与文件携带分别处理。** 主体由服务端验证，身份域随 data 保留；客户端由宿主适配器定位。
   浏览器标识不承载状态值。完整备份包含 local 文件，但不同主体/客户端不自动认领它们；
   手工复制桌面浏览器数据可能一并复制客户端身份，这属于开发者已接受的整目录复制缺口。
4. **使用逐记录原子替换与条件写。** 一个文件共同保存值、schema 版本、revision 与删除状态；
   mutation 在锁内完成读取、条件检查和替换。user 使用有界跨进程 owner 分区文件锁；project 依附 occupancy 提供跨进程隔离，
   进程内按 owner 实际分区串行，覆盖 quota 检查与 mutation，不能仅锁单条记录。
   不以进程内 Map 锁宣称跨进程互斥，也不支持绕开服务直接并发写原始文件。
5. **Project 生命周期是访问边界。** 前端路径和本地 revision 不构成服务端有效代次证明；
   服务端签发的上下文绑定用户、客户端、运行期和精确 Project 引用。正常离开、全局关闭、删除与物理目录替换分别遵守原领域合同。
6. **保存事实与界面应用分离。** 订阅刷新已确认值，工作台持有独立当前显示和本地意图；跨标签更新不抢布局。
   主工作台与 World Engine 尺寸归 project/local，视图定制归 user/local，分别保存。尺寸冲突只重放明确修改字段。
7. **插件通过宿主消费。** owner 定义逻辑键和可选稳定资源标识，宿主注入持久化及内存上下文。
   一个 owner 可以同时使用 user、project 和不持久化状态；grid 只拥有几何与序列化原语。
8. **先验证第二个消费者。** 在主页面接入前提供最小插件与横纵嵌套 grid 样例，补齐该场景必要的原语能力和恢复验证。
   World Engine 整页、Agent Chat Flow、命令系统及桌面多窗口按后续任务分别推进。

## 备选与取舍

- 全部留浏览器：无法满足状态集中于 data 和后端直接消费，故采用后端 authority 加宿主适配器。
- 一份公共服务端布局：会使不同客户端互相覆盖，故 local 增加客户端分区。
- 全部状态立即跨设备同步：需要身份对齐、离线冲突和删除收敛，当前没有必要为本地布局引入这些依赖。
- 直接持久化主 grid 的完整渲染树：会把夹取、未知引用过滤和当前固定 Part 带入长期记录；
  采用宿主拥有记录、原始值与呈现分离，简单尺寸键不依赖复杂 grid 格式。
- 首期改为通用数据库：当前状态是有界、独立键，不需要跨键事务；逐记录文件便于审查与项目复制。
  若消费需求需要索引、事务或大量对象，先评估是否属于领域 Store，再评估替换物理适配器。

## 后果与限制

- Storage 内部路径必须同时接入 user-assets/Project 文件消费策略、备份与项目 ZIP，不能只实现读写 API。
- 用户分区也需要应用退出排空；单条坏记录不会成为整个 Project 打开的 required 失败门禁。
- 已确认保存保证进程重启可恢复，不作整机断电零丢失承诺；在线备份按记录一致，不作跨领域整体快照承诺。
- 删除标记首期不自动清理；owner 可显式回收，先持久化新分区代次使全部旧条件凭据失效，再释放墓碑容量，活值保持原样。
- 旧桶迁移采用单写者与原件保留，不能按 schema 失败直接重写默认；具体升级与回滚见 [迁移合同](../migrations/storage-state.md)。
- 该 ADR 批准设计与文档，不证明运行时、跨端同步、嵌套 grid 或全部主页面视图已经实现。
