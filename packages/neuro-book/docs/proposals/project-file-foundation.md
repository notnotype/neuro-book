# 项目文件底座与 Files 竖切

- 定位：[可扩展应用平台](extensible-application-platform.md) 阶段 2“Files 竖切”的需求与设计。它把 Files 从“一个资源管理器插件”扩成整个项目的文件底座，资源管理器与编辑器是底座的第一批使用方。
- 与既有提案的关系：
  - [Files 与资源管理器第一版](files-explorer.md)（`accepted`）的 F1–F9 产品策略与切换性能设计（控件复用、模型按引用保留）继续有效，本文不重定义；它的“内容节点模式”改由本文的[三类文件夹](#2-三类文件夹)承担。
  - [第二版草案](files-explorer-v2.md)（快速打开、删除恢复）不在本文范围。
  - 剧情篇章的改造（活页夹）在本文确定方向，剧情模型与迁移另起设计，见[后续重构](#后续重构不在本次)。

## 问题

开发者实际使用中的可观察问题：

1. **打开项目要等全量预读。** frontmatter 最初是为了让实际文件名（例如英文）与展示名（例如自定义的中文名）分开，同时决定排序和类型图标。资源管理器为了显示内容节点的展示名、排序和图标，打开项目时读取所有文件并解析 frontmatter（这一步最耗时），缓存建好后才进入工作台。早期没有加载界面时，表现为工作台直接卡住。项目越大越慢。
2. **切换文件约 0.3 秒延迟。** 本机 B/S 方式下点击文件到正文出现约 0.3 秒，原因未测量。
3. **剧情篇章有两份编排。** 剧情数据库的 `StoryAct`、`StoryChapter` 用 `sortOrder` 保存章节顺序，正文目录的顺序只是“装饰”；用户在文件树里排的顺序与剧情里的顺序可能不一致。
4. **资源寻址不统一。** Agent 工具、剧情、用户资产各自用路径或私有引用格式，无法用同一套读写、检索与变更通知访问项目、会话工作目录、临时目录和数据库中的数据。

## 目标与非目标

**目标：** 把项目文件底座重做成按 URI 方案分派提供者的资源层，写入带来源并发出变更事件，文件夹分三类、按需加载并由文件监视增量更新。资源管理器和编辑器建在这一层上，用起来像本地 IDE 一样流畅；Files 合并成一个插件，读写与事件走[插件通道](../../../../docs/specs/runtime/plugin-channel.md)。

**使用者：** 写作者（资源管理器、编辑器）；Agent（文件工具）；底座之上的插件（本次是 History，之后是剧情与用户资产）。以后可能的使用方：搜索与快速打开（读文件名与清单）、导出与备份（一致读取整个项目），不在本次范围，但底座的接口不应妨碍它们。

**成功标准：** 在生产构建、参考机器的本机浏览器（B/S）上（2026-10-03 确定参考机器、桌面版不单独测，见[决策记录](#决策记录)），用约 3000 个 Markdown 文件、3–5 层目录、单章 5–30 KB 的项目测：

| 场景 | 标准 |
|---|---|
| 打开项目 | 1 秒内看到可操作的文件树；第二次打开约 300 毫秒 |
| 点击文件 | 资源管理器选中状态与标签页在下一帧（16 毫秒内）切换，不等正文 |
| 正文出现 | 已打开过的文件 100 毫秒内；未打开过的普通章节 200 毫秒内 |
| 展开目录 | 几百个子项不卡，滚动流畅 |
| 任何时候 | 界面不被后台扫描、解析或同步冻住 |
| 回归 | 首版文件操作（F1–F9）不回退、不变慢 |
| 扩展性 | History 作为内置插件，只依赖底座的事件独立工作 |

**非目标：** 全文搜索、文件快速打开（`Ctrl+P`）、回收站、Git、远程文件系统；`chapter://` 与 `plot://` 的提供者及剧情模型改造；`lorebook/` 等目录的路径迁移；预读策略的具体取舍（只留扩展口）。

## 当前行为与证据

- **打开项目：** 资源管理器的树由 `server/workspace-files/project-file-index.ts`（`ProjectFileIndexAdapter`）与 `content-node-schema.ts` 构建，内容节点的展示名、类型与顺序来自各子目录 `index.md` 的 frontmatter（从代码推断，未测量各步耗时）。打开项目时等预读与缓存完成才进入工作台（开发者报告）。
- **切换文件：** 约 0.3 秒为开发者报告，未测量。首版在隔离样本、生产构建下测得同组热切换 p95 为 38–54 毫秒（[t24](../../../../.agents/works/w00017-application-runtime-architecture/tasks/t24-files-switch-performance/README.md)），与实际体验的差距尚未定位。
- **剧情篇章：** [Plot 系统合同](../../assets/reference/plot/system.md) 规定章节顺序权威在 `StoryAct.sortOrder` / `StoryChapter.sortOrder`，正文通过 frontmatter `chapter: <章名>` 反指所属章，Scene 以 `chapterId` 挂章；剧情实体之间已用 `scene://{id}`、`thread://{id}` 等轻量引用。Scene 早先用章节路径 `chapterPath` 挂章，已迁为 `chapterId`；Decision 的 `content` 锚点仍存内容节点的相对路径（`anchorPath`）。开发者指出剧情功能以项目里的章节相对目录为键，需要重新设计。
- **路径耦合：** `lorebook/` 在内置资产（Agent 提示词、技能、参考文档）中出现 73 个文件 237 处，服务端 10 个文件、前端 18 个文件引用；`manuscript/` 涉及 58 个文件（2026-10-02 统计）。

## 分项决定

以下逐条经开发者确认（2026-10-02）：

| 主题 | 决定 |
|---|---|
| 文件夹分类 | 普通文件夹（默认，只显示真实文件名，按文件系统规则排序，不解析 frontmatter）；内容文件夹 `*.content/`，清单 `content.xml`；活页夹 `*.binder/`，清单 `binder.xml`，归剧情插件 |
| 识别方式 | 只看文件夹名后缀，列出父目录即可知道类型，不读目录内部 |
| 清单格式 | XML；一份清单描述整棵子树（一个内容文件夹只在根上放一份） |
| 稳定身份 | 只有活页夹的章节有稳定身份（编号 id，`chapter://1`）；普通文件按路径处理，不建引用维护机制 |
| 剧情篇章 | 编排只看 `binder.xml`；`ls chapter://` 按编排顺序列出，`ls` 原始目录看到的是 id 顺序；编号由剧情服务加锁分配 |
| History | 底座负责写入来源与变更事件；`nbook.history` 是默认启用、非启动必需的内置插件 |
| 用户资产 | 在资源管理器中作为第二个根，地址 `user://`，复用三类文件夹规则，权限与作用域独立，Agent 默认只读 |
| 切换体验 | 标签页当帧切换，编辑区保持空白，超过 800 毫秒才显示进度条（2026-10-03 由 100 毫秒改定），不保留旧正文；预读只留扩展口 |
| 本次的 URI 方案 | 提供者框架，加上 `project://`、`user://`、`tmp://`、`local://`、`docs://`（只读参考文档） |
| 迁移 | 一次性迁移，只写在项目迁移脚本里，业务代码不带兼容分支 |

## 方案

### 1. 资源寻址：URI 方案与提供者

资源统一写成 `方案://路径`。文件服务按方案把请求分派给提供者，提供者声明自己的能力；读写、列出、glob、grep、监视都经文件服务，写入在这里记录来源。

| 能力 | 真实目录型提供者 | 虚拟提供者（如以后的 `plot://`） |
|---|---|---|
| 读 | 能 | 能，读到实体的文本呈现 |
| 写 | 能，经文件服务，带来源 | 只走结构化写入（专用工具或命令），不接受改文本后解析回写 |
| 列出与 glob | 能 | 由提供者枚举 |
| grep | 能，可直接在真实路径上运行 ripgrep | 由提供者实现，或对少量实体逐个读取后匹配 |
| 监视 | 文件监视 | 提供者自行发出事件 |
| bash | 能（转成真实路径） | 不能；工具明确报错，需要时导出只读快照到 `tmp://` |

本次提供者：

| 方案 | 映射 | 说明 |
|---|---|---|
| `project://` | 当前项目根 | 资源管理器的第一个根 |
| `user://` | 状态目录下的用户资产根 | 资源管理器的第二个根；跨项目共享 |
| `tmp://` | 按系统映射的临时目录 | bash 可直接使用 |
| `local://` | Agent 会话的工作目录 | bash 在这里运行 |
| `docs://` | 产品参考文档目录 | 只读 |

bash 绕过文件服务，它的写入由文件监视发现，来源记为“外部”，能按会话工作目录推断时记为对应会话。插件可以注册自己的方案，剧情改造时由剧情插件注册，那时也检验“插件注册方案”这一扩展点：

- `chapter://`：**真实目录型**，映射到 `manuscripts.binder/`，bash、grep、glob 都能直接用。它比普通目录多两样：按编号寻址（`chapter://1`，也可写 `chapter://00001-{章名}.md`），以及 `ls chapter://` 按 `binder.xml` 的编排顺序列出（`ls manuscripts.binder/` 看到的是编号顺序）。推荐 Agent 直接使用 `manuscripts.binder/` 目录。
- `plot://`：**虚拟型**，剧情实体（Scene、Thread、伏笔、Decision）的数据在数据库里，读到的是文本呈现，写入走剧情工具，bash 不可用。

### 2. 三类文件夹

| 类型 | 识别 | 编排信息 | 渲染者 |
|---|---|---|---|
| 普通文件夹 | 无后缀 | 无，只显示真实文件名 | 文件底座 |
| 内容文件夹 | `*.content/` | `content.xml`：整棵子树的展示名、顺序、图标 | 文件底座，用户可自定义 |
| 活页夹 | `*.binder/` | `binder.xml`：分组（卷）、章节顺序与标题、`nextId` | 剧情插件 |

```xml
<!-- manuscripts.binder/binder.xml -->
<binder nextId="4">
  <group title="第一卷 青石镇">
    <chapter id="1" title="初到青石镇"/>
    <chapter id="3" title="旧账"/>
  </group>
  <chapter id="2" title="夜雨"/>
</binder>
```

`lorebook.content/` 默认就是内容文件夹，用户可以把任何普通文件夹转成内容文件夹以自定义展示名与顺序。

活页夹由剧情系统创建和管理，目录平铺章节文件 `00001-初到青石镇.md`：编号是稳定 id，文件名中的章名由系统按 `binder.xml` 同步，只是给人和 Agent 看；`chapter://1` 只认编号，外部只改了文件名中的章名部分也不影响。调整编排只改清单，不移动、不改名文件。卷在清单中表达为分组，不对应目录。编号由剧情服务加锁分配（取 `nextId`），外部撞号时检测并提示。

规则：

- 清单里没有的子项按真实名字排在末尾（活页夹里则进入“未编排”分组）；清单里有、磁盘上没有的条目忽略并标出为缺失。外部（bash、文件管理器）增删子项时不会丢失。
- 资源管理器默认隐藏清单文件本身，可开关显示；清单是可见文件，Agent 用 `ls` 能直接读取。
- 去掉后缀即退回普通文件夹；把普通文件夹转成内容文件夹，就是改名加后缀并生成清单（按当前子项初始化）。
- 章名和展示名以清单为准；普通文件夹不读任何文件的 frontmatter。
- 展示与编排相关的 frontmatter 字段由项目迁移脚本一次性迁入清单，其余 frontmatter 原样保留为文件内容。

资源管理器为“某类文件夹”提供渲染贡献点：文件底座渲染普通与内容文件夹，剧情插件为 `*.binder` 提供自己的渲染。这是底座扩展点的第二个检验。

### 3. 写入来源与变更事件

- 每次经文件服务的写入都带来源：人（写作者）、Agent 会话、系统、外部。
- 文件服务发出变更事件：新建、修改、改名（带旧路径与新路径）、删除，附来源。外部改动由文件监视发现，来源记为外部（见上节 bash 的推断规则）。
- 普通文件没有稳定身份：外部改名表现为删除加新建；需要跨改名追踪的使用方（History）自行按内容关联。

### 4. History 插件

`nbook.history` 订阅底座的变更事件，提供时间线、快照、审查收件箱与还原，复用 `@notnotype/nb-history` 的观察型记账（只给写后内容，由它推断写前内容）与跨改名追踪。默认启用，非启动必需：History 失败或被关闭时，文件功能照常工作。Agent 的“别人改了什么”提示与审查收件箱依赖它。

### 5. 按需加载与增量更新

- 打开项目只列出根目录（及上次展开的路径），不读文件内容、不解析 frontmatter。
- 展开目录时列出该目录；遇到内容文件夹或活页夹，读一次它的清单。
- 文件监视增量更新已展开的部分；大目录的列表虚拟滚动。
- 是否需要持久化索引，由测量决定：去掉全量 frontmatter 解析后，列目录预计已满足“第二次打开约 300 毫秒”，未达标再加。

### 6. 打开与切换

- 先测量：把 0.3 秒拆成请求、服务端读取、前端解析、编辑器重建、界面重渲染，按占比修改，不以笼统的缓存或防抖代替定位。
- 乐观切换：资源管理器选中状态与标签页当帧切换；编辑区保持空白，800 毫秒内不显示任何加载提示，超过 800 毫秒才显示顶部进度条；不保留旧文件正文，避免误写入旧文件。
- 沿用第一版的切换设计：同组同类编辑器复用控件，文档模型按打开引用保留，dirty、冲突、在途保存不淘汰；外部修改经变更事件同步到已打开的编辑器。
- 预读留扩展口；候选为“悬停约 100 毫秒预读”与“打开某章时预读活页夹前后各两章”，实际体验后再定。

### 7. 用户资产根

`user://` 在资源管理器中作为第二个根，标题“用户资产”，默认折叠；复用三类文件夹规则（例如用户级技能目录可以是内容文件夹）。写入落在状态目录、跨项目生效；Agent 默认只读，写入需 Profile 显式授权。用户资产的目录布局（技能、配置等）另行设计。

### 8. Agent 文件工具

读、写、列出、glob、grep 改为基于文件服务实现，接受上述 URI；bash 只接受有真实路径的方案，在 `local://` 运行。Agent 的写入带会话来源，进入 History 与审查收件箱。

### 9. 插件化

按平台设计阶段 2：合并现有两个 Files 插件为 `nbook.files`；读写、批量与事件走插件通道；向 workbench 贡献视图与命令，定义 `explorer/context` 菜单位置；打开文件执行 `nbook.editor.open` 命令。阶段 1 留下的 `nbook.platform-files`（受根约束的文件能力）作为真实目录型提供者的实现基础进入产品清单；`nbook.project` 的浏览器部分（本窗口当前 Project 与切换事件）随本次实施。

## 后续重构（不在本次）

- **路径迁移：** `lorebook/` → `lorebook.content/`、`manuscript/` → `manuscripts.binder/`。仓库内置资产与代码批量替换，用户项目由项目迁移脚本改名；用户自定义资产（状态目录中的用户级技能、改过的 Profile）写死旧路径的不会自动更新，安装器只能提示。开发者已接受这一代价。
- **剧情模型改造：** `StoryAct`、`StoryChapter` 退役，场景改为挂靠活页夹章节编号，ChapterBrief 按章节编号存；剧情插件注册 `chapter://` 与 `plot://`（统一现有 `scene://`、`thread://` 等引用）；Decision 的 `content` 锚点等仍存相对路径的引用一并评估。候选：用户在正文或笔记中写 `plot://` 链接，由编辑器渲染为可点击的标题。需单独的剧情设计稿与迁移说明。
- **展示名迁移：** 现有 `index.md` frontmatter 中的展示名、顺序、图标迁入清单，由项目迁移脚本完成。
- **预读策略**与**用户资产目录布局**按实际体验另定。

## 备选方案与取舍

| 问题 | 采用 | 放弃的方案及原因 |
|---|---|---|
| 内容节点元信息 | 每个内容文件夹一份清单 | 子目录 `index.md` frontmatter：展开要读 N 个文件，调整顺序要改 N 个文件且混入正文历史 |
| 篇章编排 | 活页夹清单，章节编号即稳定 id | 文件树即编排加 frontmatter id：剧情等仍需处理改名追踪，规则复杂；独立大纲（平铺文件加大纲）：本质相同，选活页夹形态 |
| 稳定身份范围 | 只有章节 | 所有文件都有 id：需往用户文件写 id 并维护引用，而普通文件基本不被引用 |
| 文件夹类型识别 | 文件夹名后缀 | 目录内清单文件：列父目录时无法感知，需进入每个目录；`project.yaml` 登记：路径上看不出类型，外部改名后登记失配 |
| 清单格式 | XML | YAML：层级深时依赖缩进，Agent 修改时缩进错误会悄悄改变层级 |
| History | 内置插件订阅底座事件 | 并入底座：底座与历史存储耦合，也无法检验底座的扩展性 |
| 用户资产 | 资源管理器第二个根 | 单独视图：要重写一套树、拖拽与文件操作 |
| 加载中的编辑区 | 保持空白，800 毫秒后显示进度条 | 保留旧正文：写作场景中可能把输入打进旧文件；100 毫秒后显示进度条：正常打开在 100–200 毫秒之间完成，进度条会闪一下 |

## 数据、接口、安全、迁移、发布与回滚影响

- **数据：** 新增清单文件（`content.xml`、`binder.xml`）；文件夹名加后缀。迁移由项目迁移脚本完成，业务代码只认新布局。
- **接口：** 文件服务、提供者注册与能力声明、变更事件、文件夹渲染贡献点是新的插件接口，按[插件公开 API](../../../../docs/specs/runtime/plugin-api.md) 的远程形态约束设计；Agent 文件工具的入参改为 URI。
- **安全：** `user://` 跨项目，Agent 默认只读；`docs://` 只读；bash 只能访问有真实路径的方案，不扩大现有授权；提供者不向浏览器暴露服务端绝对路径。
- **依赖：** 新增 XML 解析库（例如 `fast-xml-parser`）。
- **发布与回滚：** 底座、资源管理器与 Agent 工具按切片推进；路径迁移与剧情改造另行发布，迁移脚本需提供回滚或备份。
