# SettingsLoadState

设置区段的整块状态占位，两种形态二选一：

- `variant="loading"`：居中的旋转指示 + 一句能独立成立的说明（`role="status"` + `aria-busy="true"`）。默认文案「正在读取设置…」，可用 `message` 覆盖。
- `variant="error"`：状态图标 + 原因 + 重试按钮（`role="alert"`）。原因由调用方传入（`message`），重试发 `retry`。

它只负责**画**这块状态，不取数、不判断什么时候该显示——那是宿主的策略：

- 读得快时不该闪：只在「确实没有内容可显示」时用加载形态，并且由宿主等一小段延时（`useSettingsSnapshot` 的 `blockingLoading`）再决定是否显示；
- 有旧内容可显示时保留内容，只给细进度条，不把整块换成加载态；
- 失败形态只在没有内容可显示时使用；有内容时保留内容 + 系统通知即可，不必把整屏换成错误页。

占满容器：组件根是 `h-full`，调用方给一个有高度的容器（外壳的内容区、区段体的内容列）。

```ts
interface Props {
    variant: "loading" | "error";
    /** 说明文字；加载态留空用默认文案，失败态传真实原因 */
    message?: string;
    /** 重试按钮文案；留空用默认文案 */
    actionLabel?: string;
}

interface Emits {
    /** 失败态的重试动作 */
    (event: "retry"): void;
}
```

## 布局

不做骨架：占位形状会暗示一个还不知道的结构。两种形态都在既有内容列宽内居中，出现与消失都不推动周围内容（它们占满自己的区域，不参与内容流的高度计算）。

## 交互

只有失败态有动作：`retry`。加载态没有任何可交互元素，纯播报。

## 不支持

不取数、不管重试之外的动作、不接受插槽、不读写 store 或路由。它不知道自己是「整页」还是「区段内」，尺寸由父容器决定。

## 隐藏通道理由

- `state:inject`：只注入应用 i18n 的 `useI18n()` 拿默认文案；文案随宿主语言切换，不适合由父组件逐条传入。
