# LowCodeFieldShell

低代码表单里一个字段的外壳：把标签、必填标记、说明、右侧扩展位和错误列表统一排好，中间留一个口子给真正的字段控件。它不认识值、不产生事件、不判断禁用——存在的原因只是让文本、下拉、复选、资源预设这些各不相同的控件共用同一套排版和同一种错误呈现方式，避免每个字段各写一遍。

## 数据

```ts
interface LowCodeFieldShellProps {
    /** 字段描述（来自低代码表单 DTO）；必填；本组件只读其中的 label / description / required */
    field: LowCodeFieldDto;
    /** 该字段的服务端问题列表；默认空数组；为空时不渲染错误区域 */
    issues?: LowCodeFormIssueDto[];
}
```

插槽有两个，都是具名的：

```ts
/** 标签行右侧的操作位，与说明文字顶对齐；放不下时靠右收缩（例如继承/覆盖切换） */
interface ActionsSlot {
    // 无插槽参数
}

/** 字段控件本体，渲染在标签行与错误列表之间 */
interface DefaultSlot {
    // 无插槽参数
}
```

没有 emits，没有 `expose`。未声明的 attribute 落到根元素上（`class` 与内置类名合并）。

## 布局

竖向排列三块：标签行、控件、错误列表，间距固定。标签行是顶对齐的左右两栏——左侧是标签与说明（说明可选，宽度不够时换行），右侧是 `actions` 插槽，整行有最小高度，没传 `actions` 时右栏为空。控件占满整行宽度。错误列表在最后，一条一行，`warning` 用提醒色、其余（含默认的 `error`）用危险色。

必填字段在标签后追加一个星号标记。数据变多时是说明与错误列表换行增高，标签行的两栏不会互相挤压到看不见。

## 已知偏差

- 标签当前是一个独立的 `<label>` 元素，没有和具体控件建立关联（既没有 `for`/`id`，也没有包裹关系），因此屏幕阅读器读字段名要依赖控件自身的可访问名称。文档要求标签与控件关联；实现待补。
