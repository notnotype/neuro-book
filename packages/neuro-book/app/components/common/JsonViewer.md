# JsonViewer

在界面里展示一段结构化数据的 JSON 查看器，默认只读。产品里到处需要「把一个对象摊开给人看」——工具调用的入参出参、工作流的中间结果、调试面板里的原始记录，这个组件是那个统一出口。基于 `json-editor-vue` 封装。

三个特点是它和直接扔一段 `<pre>` 的区别：

- **同一份数据三种看法**，文本、树形、表格随时互切，不用换组件也不丢当前数据。
- **高度自己收着**。容器有最大高度，内容再长也在内部滚动，不会把外层撑开，也不会带出页面级滚动条。
- **传字符串和传对象行为不同**。传字符串时保留用户此刻的原始输入，哪怕 JSON 还没写完、暂时不合法也不会被吞掉或重排。

## 布局

由工具栏和编辑器主体两块组成。工具栏在上，分左右两组：左组是三个模式按钮，成组显示在一个带边框和浅底色的分段容器内，同一时刻只有一个处于选中态；右组是复制、展开全部、折叠全部三个独立的动作按钮。工具栏可以整体关闭。

编辑器主体占据剩余空间。容器有最大高度约束，内容超出后由编辑器自己在内部滚动，不把外层撑高。最大高度设为 0 表示不限制。

工具栏高度固定，切换模式或数据变化都不改变它的尺寸，因此不会引起布局位移。

窄屏下结构不变。工具栏的六个按钮在一行内排布，均为紧凑尺寸。

## 交互

- 点击模式按钮切换文本、树形、表格三种查看方式。当前模式的按钮呈选中态，且始终有且只有一个处于选中态；点击已选中的按钮不产生变化。
- 键盘聚焦到模式组后，方向键在三个模式之间移动。
- 点击复制把当前内容写入系统剪贴板。字符串原样复制，其它值格式化后复制。内容为空时不做任何事。复制失败只在控制台留一条警告，界面不提示。
- 点击展开全部或折叠全部作用于所有节点。这两个动作只在树形模式下可用，其它模式下按钮为禁用态。
- 六个按钮都有可访问名称，与鼠标悬停提示一致。
- 键盘可以逐个聚焦到按钮并用回车或空格触发，焦点有可见的聚焦环。组件不注册任何快捷键。

## 数据

```ts
/** 三种查看模式。取值与 vanilla-jsoneditor 的 Mode 一致。 */
type JsonViewerMode = "text" | "tree" | "table";

interface JsonViewerProps {
    /** 要展示的 JSON 值。对象、数组、字符串均可。必填。 */
    value: unknown;

    /**
     * 模式。不是纯初始值——外部改变它会覆盖用户在工具栏里的选择，
     * 用户点工具栏则只改内部状态、不回传父组件。
     */
    mode?: JsonViewerMode;      // 默认 "tree"

    /** 是否只读。只读时编辑器不接受输入，工具栏仍然可用。 */
    readOnly?: boolean;         // 默认 true

    /** 是否显示本组件的工具栏。关掉后六个按钮都没有，只剩编辑器主体。 */
    mainMenuBar?: boolean;      // 默认 true

    /** 是否显示编辑器自带的导航栏。 */
    navigationBar?: boolean;    // 默认 false

    /** 是否显示编辑器自带的状态栏。 */
    statusBar?: boolean;        // 默认 false

    /** 容器最大高度，单位像素。0 表示不限制。 */
    maxHeight?: number;         // 默认 300
}

interface JsonViewerEmits {
    /**
     * 内容变化时发出。
     * 传入 value 是字符串时，携带的是用户此刻的原始文本，
     * 可能是还没写完的非法 JSON——这是有意的，不做拦截也不做补全。
     */
    (e: "update:value", value: unknown): void;

    /**
     * 紧跟在 update:value 之后发出，报告这次的内容能否被解析。
     * 只做「能不能 JSON.parse」这一件事，不按任何 schema 校验。
     * 非字符串值与纯空白字符串一律报告为无错。
     */
    (e: "validation-change", hasErrors: boolean): void;
}
```

没有 slot。

## 状态

- 默认：按 `mode` 呈现内容，工具栏可用。
- 只读：编辑器不接受输入，工具栏仍可切换模式与复制。
- 空数据：正常渲染空结构，复制动作不做任何事。
- 非树形模式：展开与折叠按钮为禁用态，视觉变淡且不可点击。
- 出错：组件自身没有错误态。内容不合法只通过 `validation-change` 报给父组件，界面不变；复制失败只写控制台警告。

## 不支持

- 不支持按 schema 校验。`validation-change` 只回答「能不能解析」，不回答「结构对不对」。
- 工具栏不提供搜索、跳转或按路径定位的入口。
- 不支持持久化用户选择的模式或展开状态，每次挂载都回到 `mode` 指定的初始状态。
- 不支持读取剪贴板，只写不读。

## 注意事项

- **`maxHeight` 默认 300，不是不限制。** 放进一个自己已经管好高度的容器时必须显式传 `0`，否则内容会在 300 像素处被截住并出现内部滚动条，看起来像数据不全。这是使用中最容易踩的一处。
- **父组件不要把 `mode` 当只读初始值。** 父组件每次改变 `mode` 都会覆盖用户当前的选择；反过来用户在工具栏切换不会通知父组件。想让模式跟着用户走，就不要在 `mode` 上绑一个会变的值。
- **传字符串和传对象是两条不同路径。** 传对象时组件按结构渲染；传字符串时按原始文本处理，用户的中间输入原样保留。同一处使用方混着传两种类型，行为会不一致。

## 隐藏通道理由

`env:clipboard`：复制按钮直接调用浏览器剪贴板接口。这个动作与被展示的内容强绑定，复制的文本需要按当前值的类型决定格式；交给宿主处理会让每个使用方都重复一遍同样的格式化逻辑。写入的是用户主动请求复制的展示内容，不涉及产品数据。

## 已知偏差

- 展开全部与折叠全部的禁用条件与「交互」一节不符。实现中这两个按钮只在表格模式下禁用，文本模式下仍可点击，但点击不产生任何效果——展开与折叠是树形结构操作。文档写的是应当成立的行为，实现待订正。
