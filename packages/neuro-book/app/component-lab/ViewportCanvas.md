# ViewportCanvas

Lab 中栏里包着被检视组件的那个盒子。**它只解决一件事：让这个盒子的宽高可以被自由控制，从而看组件在不同尺寸下长什么样。**

三个特点是它和「直接把组件放在一个 div 里」的区别：

- **宽高是受控的两个数**，既可以由使用方一次设成手机或平板尺寸，也可以由用户拖手柄连续调。两条路改的是同一对值。
- **拖手柄可以用键盘操作**，方向键调尺寸，不是只能用鼠标。
- **盒子比舞台大时靠滚动看，不缩放。**看到的像素就是真实像素，不会因为缩放而对不上。

仓库里没有同类物：nb-ui 的 `AspectRatio` 锁的是宽高比而不是具体尺寸，`Panel` 只管容器外观。

**这个零件不是 iframe，没有样式隔离。**这一条影响它能回答和不能回答哪些问题，务必读「注意事项」第一条。

## 布局

三层，从外到内：

- **舞台**：占满中栏的可用空间，是滚动容器。盒子比它大时在这里横竖两个方向滚动。
- **尺寸盒子**：在舞台里居中，宽高由 `width`、`height` 决定。被检视的组件放在它里面，撑满它。
- **手柄**：贴在盒子的右边、下边和右下角，三个。右边只调宽，下边只调高，右下角同时调两个。

盒子上方显示当前尺寸，例如 `390 × 844`；宽或高为不限制时那一维显示为 `自动`。

宽或高传 `0` 表示那一维不设限，由可用空间决定；两维都传 `0` 时盒子铺满舞台，等于没有这一层约束。**这与 `JsonViewer` 的 `maxHeight` 用 `0` 表示不限制是同一个约定**，仓库里保持一致。

内容变多时先让位的是舞台的可视范围——盒子尺寸是被指定的，不会因为里面塞不下就变大，塞不下就在盒子内部溢出，怎么处理由组件自己决定。

`390×844` 下本零件结构不变，但舞台会很窄，盒子多半比舞台大，两个方向都要滚。手柄仍在原位，只是可能要滚过去才够得着。

## 交互

- 拖右边手柄改宽，下边改高，右下角同时改两个。拖动过程中尺寸显示实时更新。
- 松手后发出 `update:width` / `update:height`。**拖动中不发**——中间尺寸每像素发一次事件对使用方没有意义，还会让接了持久化的使用方写一串垃圾。
- 尺寸不会被拖到小于 `minSize`。上限只受舞台可滚动范围限制，不设硬上限。
- 拖动中盒子内的组件正常渲染，不冻结、不遮罩。**看组件在尺寸变化过程中怎么重排，是这个零件存在的一半理由。**

键盘：

- 三个手柄都可以 Tab 聚焦，有可见的聚焦环。
- 聚焦在手柄上时，方向键每次调 10 像素，按住 Shift 每次调 1 像素。右手柄只响应左右方向键，下手柄只响应上下方向键，角手柄四个方向都响应。
- 键盘调整时**每按一次就发一次事件**，与鼠标拖动松手才发不同——按键本身就是离散动作，没有「中间过程」。
- 手柄的无障碍角色是分隔条，并报告当前值与最小值，使读屏能读出「宽度 390」这样的信息。
- **换组件时的焦点去向不归本零件管。**本零件只知道 slot 里有内容，不知道内容什么时候被换掉，也没有可靠办法察觉。谁负责换组件，谁负责在换之前把焦点收走。

## 数据

```ts
interface ViewportCanvasProps {
    /**
     * 盒子宽度，单位像素。0 表示这一维不限制，由可用空间决定。
     * **受控值，组件自身不修改**，拖动与按键都只发事件。
     */
    width: number;

    /** 盒子高度，单位像素。0 表示不限制。受控值，同上。 */
    height: number;

    /** 拖动与按键能调到的最小边长，单位像素。 */
    minSize?: number;    // 默认 200

    /** 是否显示当前尺寸。关掉后手柄仍可用，只是没有数字提示。 */
    showSize?: boolean;  // 默认 true
}

interface ViewportCanvasEmits {
    /**
     * 宽度变化。鼠标拖动时松手才发一次；键盘每按一次发一次。
     * 携带的是期望的新宽度，组件不会自己改 width。
     */
    (e: "update:width", value: number): void;

    /** 高度变化，时机与 update:width 相同。 */
    (e: "update:height", value: number): void;
}
```

一个 slot：`default`，放被检视的组件。

不 expose 任何方法或属性。未声明的 attribute、`class` 与 `style` 按 Vue 默认行为落到根节点（舞台）上。

`state:local` 是拖动过程中记住的起点坐标与起始尺寸，组件销毁即丢失，不伸出组件之外。

## 状态

- **默认**：按 `width`、`height` 摆出盒子，三个手柄可用。
- **不限尺寸**：某一维传 `0` 时，那一维的手柄仍然可拖——一拖就等于给这一维定了一个具体值，随即发出事件。尺寸显示中那一维为 `自动`。
- **拖动中**：被拖的那条边高亮，尺寸显示实时更新，页面上不出现文字选区。
- **空**：没有传入内容时盒子照常按尺寸摆出来，里面是空的。**这是有意的**——一个空盒子能让人看清当前尺寸到底有多大，比显示「请选择组件」有用。

禁用、只读、加载中、出错四种状态本零件都没有，见「不支持」。

## 不支持

- **不提供预设尺寸按钮。**手机 `390×844`、平板 `768×1024` 这些预设由使用方设置 `width` 与 `height` 实现，预设清单不写死在零件里。
- **不支持缩放。**盒子大于舞台时靠滚动看。缩放会让看到的像素与真实像素对不上，正是这个零件要避免的。
- **不支持横竖屏切换按钮。**使用方交换 `width` 与 `height` 即可，零件不重复提供。
- **不支持记住尺寸。**两个值都是受控的，要不要存由使用方决定。
- **不支持样式隔离。**见下面第一条注意事项，这是最重要的一条限制。
- **不支持禁用、只读、加载中、出错四种状态。**本零件是个容器，这些状态属于它装的组件。

## 注意事项

- **不是 iframe，没有样式隔离，因此媒体查询不跟着盒子走。**盒子调到 390 像素宽时，里面组件的 `@media (max-width: 768px)` **不会**触发——CSS 媒体查询看的是浏览器窗口宽度，与盒子多宽无关。本仓库的组件普遍在用媒体查询（例如 `MarkdownStudioWorkbench` 有 `@media (max-width: 1180px)`），所以这个限制会立刻碰到。

  **后果要说清楚**：这个盒子能回答「组件在 390 像素宽的空间里会不会被挤坏、会不会横向溢出」，**不能**回答「组件的窄屏布局长什么样」。真实的窄屏验收仍然必须缩浏览器窗口或用设备模拟，盒子替代不了。同理，Lab 的页面样式与盒子里的组件共享同一个环境，两边会互相影响。

- **拖动改的是盒子，不是组件。**组件在盒子里撑不撑得满、溢不溢出，是组件自己的行为，本零件不干预也不裁剪。看到组件溢出盒子，那就是组件的真实表现。
- **`width` 与 `height` 是受控的**，不接两个事件的话手柄拖得动但一松手就弹回原尺寸。

## 隐藏通道理由

`state:local` 只用于拖动过程：按下时记住指针坐标与当时的盒子尺寸，松手后丢弃。它不读写 store、不访问浏览器存储、不发请求、不注册全局监听。拖动期间需要在整个窗口范围内跟踪指针，这一部分监听在按下时注册、松手或组件销毁时解除，不构成 `env:global`——它不是常驻监听，也不响应与本次拖动无关的事件。
