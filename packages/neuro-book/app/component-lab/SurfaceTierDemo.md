# SurfaceTierDemo

5 档表面角色对照板。把库里登记的 5 档表面、加上 `FormSelect` 实际在用的那一档并排摆出来，用于**挑选哪一档适合大面积 chrome**。

## 用途

这不是产品组件，是 Lab 内部的演示工具。它解决一个具体问题：库里有 5 档表面角色（工具栏、侧栏、浮层、窄条、面板），每一档在 nbook 下的不透明度、模糊强度都不同，而 FormSelect 的下拉菜单实际用了内联覆盖（65% 面板底）、不走那 5 档里的任何一档。

**要给侧栏、工具条这类大面 chrome 定一个标准盒子，得先看这 5 档哪一档在复杂背景下读得清。** 这个组件就是干这个的。

## 交互

无交互。6 个并排的卡片，每张卡片是一档表面，上面有：

- 档位名称（工具栏 / 侧栏 / 浮层 / 窄条 / 面板 / 下拉实测）
- 一段示例文本，用来判断可读性
- 这一档在 nbook·昼 的实际取值（不透明度 + 模糊配方）

最后一档标着「库里没登记」：它是 `FormSelect` 用内联 style 写死的配方，不是库里的角色。放进来是因为它是实测下来唯一能读的那一档。

**判据写在明处：背景复杂时，文字能不能读。** 如果底纹从字后面浮上来、得盯着看才能认出字，这一档就不适合铺在整栏那么大的面上。

## 实测结论

2026-09-02 在一张色彩复杂的照片背景下走查，结论是：

- **库里登记的四档玻璃全部读不了**——工具栏 30%、侧栏 26%、浮层 14%、窄条 38%，都要盯着才能认出字
- **只有「下拉实测」那一档读得清**，而它库里没有登记
- 三处差别都指向可读性：面 65%、底取暖而亮的 `--bg-panel` 而非冷的 `--bg-sidebar`、饱和降到 130% 且亮度不加
- **饱和 190% 是在增强背景**，让背景和文字抢注意力——这是前四档读不了的主因，不只是透明度

这条结论是「盒子规范」要登记哪一档的直接依据。

## 2×2 对照

上面六档里，能读的（65% + 弱模糊）和读不了的（26% + 强模糊）是**两个变量一起变的**，分不出主因。第二组四格把它们拆开：底色全部固定成 `--bg-panel`，每格只变一个变量。

| | 强模糊 sat(190%) bright(1.12) | 弱模糊 sat(130%) bright(1.0) |
|---|---|---|
| **面 26%** | A（＝现在的侧栏，已知读不了） | B |
| **面 65%** | C | D（＝下拉实测，已知能读） |

怎么读结果：

- 只有 **B** 读得清 → 主因是模糊配方，透明度可以放宽
- 只有 **C** 读得清 → 主因是不透明度，模糊配方无所谓
- **B 和 C 都读得清** → 两个各自都够，任选其一
- 只有 **D** 读得清 → 两个都必须改，缺一不可

### 结果（2026-09-02 走查）

**C 和 D 能读，A 和 B 不能。**

分界线整齐落在不透明度上：65% 的两格都能读，26% 的两格都不能。强模糊那一栏里 65% 照样能读、26% 照样不能，所以**模糊配方不影响可读性**。

**但 65% 不是可以直接抄的下限。**这四格是巴掌大的色块，实际把 65% 铺满一整条侧栏之后仍然要盯着看——面越大，同样的透光量累积出来的干扰越多。Lab 现在取的是走查调出来的 80%（器械）与 92%（内容）。这一组格子证明的是「该调哪个变量」，不是「该调到几」。

两条推论：

1. 规范该定的是**不透明度下限**，不是模糊配方的规则。
2. 模糊配方可以留给主题自由发挥——玻璃的观感不必为可读性让路，这两件事实测下来是独立的。nbook 的 `saturate(190%)` 是它的身份，可以保留。

## 验证方法

1. 切换顶栏的「桌面」到「自定义图片」，选一张色彩复杂的照片（例如动漫场景、城市夜景）
2. 或者切到「极光」，那是大面积、低频、高饱和的渐变，也能看出模糊之后会不会糊成一片
3. 看 5 张卡片哪一张的正文还能一眼认出来，不用盯着看

## 数据

无 props，无 emits，无 slots。5 档的配方写死在组件里，取的是主题变量（`--toolbar-surface` / `--sidebar-surface` / `--overlay-surface` / `--strip-surface` / `--panel-surface`）。

## 状态

只有一个：默认。无禁用、无加载、无出错、无空状态。

## 不支持

- 不响应任何用户输入
- 不消费 fixture 数据
- 在非 nbook 主题下可能看不出区别（aurora / editorial 把所有 chrome 都改成实心了）
- 不接 `state:shared-read` 或任何 `io:` / `persist:` 标签，所以它能在 Lab 里直接挂载
