# HighlightBox

在页面上空画一个不吃鼠标事件的框，框住某个矩形区域，旁边挂一个标签。Lab 用两个实例：一个常亮框住被检视的零件本身，一个跟着鼠标框住指到的元素。

**它只画框。**框哪里、框多大、标签写什么，全部由使用方算好传进来；本零件拿到一个矩形就画，拿到 `null` 就什么都不渲染。它不测量任何元素，不监听滚动或尺寸变化，不知道被框住的是什么。

它和「给元素加一圈 `outline`」的区别是**不碰被框的元素**：改元素自己的样式会挤动布局、覆盖它原有的边框、还可能被组件内部的样式盖掉。画在上空则被框的元素一个字节都不变，这正是调试时需要的——看到的仍然是零件本来的样子。

仓库里没有同类物。产品里的选区高亮 `SelectionOverlay` 画的是文本选区，坐标来自 Range，与这里「框一个 DOM 矩形」不是一回事。

## 布局

一个绝对定位在视口坐标系上的框（`position: fixed`），边框 1 像素，无填充或极淡填充，不遮挡下面的内容。

标签默认贴在框的**左下外侧**；框的底边离视口下沿不足一个标签高度时翻到**左上外侧**，避免标签跑出屏幕。标签本身不换行，过长时截断。

框和标签都不接收鼠标事件（`pointer-events: none`），因此它盖在谁上面，谁都照常可点、可悬停。这是硬要求：探针模式下框一直跟着鼠标，会吃事件的话整个预览区就点不动了。

`tone` 只改颜色，不改尺寸或位置：

- `subject`：主色调，配实线边框。用于常亮框住零件本体。
- `probe`：中性偏亮，配虚线边框。用于跟随鼠标。

两个实例同时出现时靠这个区分谁是谁，因此两种 tone 的颜色不能相近。

## 交互

没有交互。它不接收鼠标事件，也不接收焦点。

键盘：不参与 Tab 序列，不响应任何按键。

**它对读屏用户不可见**（`aria-hidden`）。框住某个东西是纯视觉的调试辅助，读出来只会是噪音；被框住的元素本身在无障碍树里没有任何变化。

## 数据

```ts
interface HighlightRect {
    /** 视口坐标，单位像素。直接用 `getBoundingClientRect()` 的四个值即可。 */
    top: number;
    left: number;
    width: number;
    height: number;
}

interface HighlightBoxProps {
    /**
     * 要框住的矩形，视口坐标。`null` 表示当前没有要框的东西，
     * 此时本零件不渲染任何节点（不是渲染一个尺寸为 0 的框）。
     */
    rect: HighlightRect | null;

    /** 框旁边的标签文字。空串或不传则不画标签，只画框。 */
    label?: string;

    /** 配色档位，见「布局」。 */
    tone?: "subject" | "probe";   // 默认 "subject"
}
```

没有事件、没有 slot、不 expose 任何方法或属性。未声明的 attribute、`class` 与 `style` 按 Vue 默认行为落到根节点上。

没有能力标签：不读写 store、不访问浏览器存储、不发请求、不注册任何全局监听。它是个纯函数式的呈现零件——同样的 `rect` 与 `label` 永远画出同样的结果。

**测量与监听刻意留在外面。**知道「该框谁」的是 Lab：它知道当前挂的是哪个 fixture、鼠标在哪。零件把 `ResizeObserver` 和滚动监听收进来的话，就得同时知道被框元素的引用和它所在的滚动容器，那是两个它没有理由知道的东西。

## 状态

- **默认**：按 `rect` 画框。
- **空**：`rect` 为 `null` 时不渲染任何节点。

禁用、只读、加载中、出错四种状态本零件都没有：它不接收输入，也不发起任何会失败的动作。

## 不支持

- **不测量元素。**不接收 DOM 元素引用，只接收算好的矩形。使用方用 `getBoundingClientRect()` 自己量。
- **不跟踪变化。**元素移动、改尺寸、页面滚动之后框不会自己跟上——使用方重新量一遍、传新的 `rect` 进来即可。谁该在什么时候重新量，只有使用方知道。
- **不画多个框。**一个实例画一个框。要框两处就用两个实例。
- **不带箭头、连线或标注尺寸线。**标签写什么由使用方决定，本零件不替它拼「宽 × 高」这类文字。
- **不做出现或消失的动画。**探针模式下框每帧都在动，加过渡只会拖影。

## 注意事项

- **传的是视口坐标，不是文档坐标。**页面滚动后同一个元素的视口坐标会变，`getBoundingClientRect()` 每次返回的都是当下的视口坐标，直接传即可；如果使用方自己加了 `scrollY` 换算成文档坐标再传进来，框的位置就会错。
- **框画在视口坐标系上，因此不受任何祖先的 `overflow: hidden` 裁剪。**被框的元素滚出容器之后，框还会停在原处——这是使用方该负责停止绘制的情形，本零件看不出来。
- **`transform` 过的祖先会让 `position: fixed` 改为相对该祖先定位**，此时框的位置会偏。Lab 的预览区没有 `transform`，但把本零件挂到别处时要留意。
- **零尺寸的矩形仍会画出一条线。**宽或高为 0 的元素（例如空的行内元素）框出来是一条线段，不是 bug。
