# MarkdownView

把一段 Markdown 文本渲染成只读的排版结果。Lab 右栏的「文档」tab 用它把组件文档和组件实物摆在一起看。

**它只做渲染，不做别的。**没有编辑、没有目录、没有搜索、没有代码高亮、没有复制按钮。给一段文本，出一块排好版的内容。

仓库里已经有一个 Markdown 渲染入口 `app/utils/markdown/render.ts`，本零件**不用它**：那一个渲染的是产品里的正文，会把工作区引用链接、内联批注、引用芯片这些产品概念一并解释掉。组件文档里不存在这些概念，用它等于让开发工具依赖产品的领域规则。本零件直接用 `marked` 加 `dompurify`，只解释标准 Markdown。

## 布局

一块内容，没有外框、没有内边距、没有背景。撑满给它的宽度，高度由内容决定。滚动、留白、边框都由使用方在外面决定——因为放在 tab 面板里和放在弹窗里需要的外框不一样。

**排版按稿面而不是界面**：宋体、比界面字号大一档、阅读行高。这里渲染的是要一段一段读下去的正文，不是控件上的标签，两者在材料语言里是两种东西。给不出宋体的主题会回落到界面字体——那些主题本来就没有稿面这一档。代码与行内代码仍然是等宽字体。

标题、段落、列表、表格、代码块、引用、分隔线按常规排版。代码块横向溢出时在代码块内部横向滚动，不把整块内容撑宽。

窄到 `390` 像素时排版不变，只是行更短；表格与代码块在自己内部横向滚动。

## 交互

只读，没有交互，除了两件事：

- **文本可以选中复制。**
- **链接可以点。**外部链接在新标签页打开并带上防跳转劫持的标记；页内锚点链接**不特殊处理**，点了会怎样由浏览器决定——组件文档里的锚点大多指向文档站，在 Lab 里跳不到有意义的位置，与其半对不如不假装支持。

不接收键盘焦点，因为没有可操作的东西。里面的链接照常可以 Tab 到。

## 数据

```ts
interface MarkdownViewProps {
    /**
     * 要渲染的 Markdown 文本。传空串渲染出空内容，不显示占位文字。
     */
    source: string;
}
```

没有事件、没有 slot、不 expose 任何方法或属性。未声明的 attribute、`class` 与 `style` 按 Vue 默认行为落到根节点上。

没有能力标签：不读写 store、不访问浏览器存储、不发请求、不注册全局监听、不使用剪贴板。渲染是同一次调用内完成的纯计算。

## 状态

- **默认**：按内容排版。
- **空**：`source` 为空串时渲染出一块空内容。**不显示「暂无内容」之类的占位文字**——是否需要占位、占位说什么，取决于使用方的语境，不该由渲染零件替它决定。

禁用、只读、加载中、出错四种状态本零件都没有：它本身就是只读的；文本是同步传进来的，不存在加载中；Markdown 没有语法错误这一说，任何文本都能渲染出结果，最差是渲染成一段纯文字。

## 不支持

- **不支持编辑。**要编辑用编辑器组件，本零件是只读的。
- **不支持代码高亮。**代码块渲染成等宽字体的纯文本。高亮要引入语言包，对「看文档」这个用途不值得。
- **不支持产品方言。**工作区引用链接、内联批注、引用芯片、ruby、双语这些在本零件里都是普通文本，见开头的说明。
- **不支持目录、锚点跳转、搜索、复制按钮。**这些是文档阅读器的功能，不是渲染零件的。
- **不支持流式渲染。**`source` 变了就整段重新渲染，没有为「一个字一个字往里加」做优化。组件文档是一次性给全的。

## 注意事项

- **渲染结果经过净化后用 `v-html` 插入。**Markdown 里允许写 HTML，不净化就等于让文档内容执行脚本。净化用 `dompurify`，`marked` 自身的转义不能代替它——`marked` 只负责生成 HTML，不负责判断这段 HTML 安不安全。
- **净化会静默删掉东西。**文档里写了 `<script>`、`onclick` 这类内容，渲染结果里会直接消失，不报错也不提示。看到文档里有内容没显示出来，先怀疑这一条。
- **排版样式跟着主题走**，用的是主题变量而不是写死的取值。同一份文档换个主题，颜色、字体和字号都会变——给宋体的主题下是宋体、比界面大一档，不给的主题下回落成界面字体。行高固定取阅读档。
- **本零件不限制高度。**内容很长时它就很长，需要滚动请在外面套滚动容器。这是有意的：谁提供滚动条，决定了滚动条出现在哪一层，这个决定属于使用方。
