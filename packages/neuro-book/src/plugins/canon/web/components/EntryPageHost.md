# EntryPageHost

条目页 `nbook.canon.entry` 的宿主（[`canon/author-ui.md`](../../../../../../../docs/specs/canon/author-ui.md) 输出 6 到 15、26、27、38、54）：按标签的状态（`state`，编辑器给每个标签的那一份）经读取层读条目、章表、渲染与情节，交给 `EntryPage` 与各分页的组件；数据分页按类型用 `canon.component-views` 交来的界面，没有、贡献方停了或加载失败时用 `FieldsDataView`。由 `entry-page.ts` 的页面实现创建。

## 布局与交互

布局都在 `EntryPage` 与各分页的组件里，本组件只决定画哪个分页、给它们什么数据：

- 分页依次是文字（条目有主文字时）、每个启用的命名空间一个、情节；条目种类登记的默认设定组（`entryKinds`，条目读取的 `kind`）的分页排到文字前面，次序同命名空间的顺序。当前分页记在标签状态里，没有了就选第一个。“添加设定组”对话框（`AddComponentDialog`，宿主开、记下这时条目的版本）列登记了的全部类型（带各自的 `kinds`，列表按条目的种类分出“适用于”），标出条目上已经有的与去掉过的，按登记它的插件分组（`componentPlugin`），顶上是这个种类的预设（`entryKinds` 的 `presets`，经 `kindPresets` 去掉没登记的类型）；点了已有的一组切到它的分页。勾的几组一次写入、一条修订（标题一组时写它的名字，几组时把名字连起来）；被拒时按被拒的那一项（`problems[].path` 的 `ops[i]`）指名，对话框不关；成功后关上、切到第一个有命名空间的新加的一组。关上后焦点没处去（加完最后几组，“＋”没了）时交给选中的分页。右键菜单的下一级仍是能加的类型，适用的在前。情节的第一页不论在哪个分页都读，分页名后要写总条数。
- 数据分页的 `context`（`component-views.ts`）：别的组的只读视图（`other`，只认界面声明里 `uses` 列了的类型）、加一组设定、切分页、这一组上字段的增改名去恢复与去掉过的各项，写入的原因交回界面自己写；就地改的编辑器 `FieldEditor` 与值的细节 `FieldDetail`（输出 51）。`FieldEditor` 挂上时按路径登记、卸载前撤掉（计数，同一路径两份卸一份不影响另一份）；草稿标了就地、并且此刻有编辑器挂着这条路径时不出确认条，编辑器在锚在值下方的浮层里画同一份编辑卡的内容（短项是单行输入；成段的文字与原文同宽、原文不动，内容高度封顶在可用高度；放不下时翻到上方，原文长到上下都腾不出 240 像素时改贴原文露出来的第一行（nb-ui `Popover` 的 `reference`），避让以条目页为界，不越出编辑区）；打开时锚不在窗口里就滚进来（切走再回来时页面从顶上挂上）；同一项已经开着时再点它只把焦点放回自己这页的输入框、不重开；二选一的写法（`chapter` 给“第 N 章”）、“发生了什么”与它进修订标题见 `in-place-edit.ts`。短项的浮层里点外面、Escape、取消都是放弃；成段的文字点外面不收起，Escape（焦点在编辑卡里）与取消是放弃；输入法组字中、保存在途时不算。字段被去掉或改名时清掉它的草稿；累出来的数被拒时把这个字段设成正在看细节的。保存或预览失败回来时这次填写已经放弃或换了一个就不写回。
- 文字分页里点一个值，在标签状态里记下它（`state.origin`），只读它的来历；再点收起。来历在世界版本、所选位置或模式变了以后按已读的步数重读。
- 文字分页有两个视图（输出 39、44 到 46）：阅读（`EntryText`）与整篇编辑（`EntryTextEditor`），有这个条目的主文字稿（`draft`）时是编辑。写入都在这里与 `text-tab.ts`、`text-whole.ts`：编辑的是各块连起来的整篇（块之间空一行），每次输入换成整篇的一次改写，提交时整篇写进第一块、其余的块删掉（没有块时加一块，整篇是空白时全部删掉）；提交带读取戳、被拦下就重读再发。提交时读到的整篇与开始编辑时的不同（别处也改了这篇文字）就出 `TextConflictDialog`，只问一条（“现在的”或“我的”）；别处改的是别的东西时不问。有稿时这一页的位置停在稿开始的地方、按实际读，页头的位置、线与“按计划”锁住（标签状态里记的位置与“按计划”这期间不作数；标签标题与面包屑另读一份缺省位置的）。稿开始的那一章或那条线已经不在了时，这一页回到自己的位置上读（否则刷新以后整页读不出来），编辑视图只读地显示稿里的整篇、只能放弃。点“编辑”读不出块、主文字里有被剧情变更碰过的块、或块数超过一次能写的上限时，人还在阅读视图，原因写在页头下面（`actionError`）。编辑视图的“插入”列本条目各设定组的字段，选了在光标处写入 `<V of="命名空间.字段" />`。条目已删除而稿还在时，稿列在“已删除”下面（`EntryPage` 的 `deleted` 插槽）：能看、能放弃，提交不可用并写原因。这一页挂着时把“提交主文字”交给页面实现（`onCommitReady`），标签的保存命令调它；现在写不了（只读、别人独占、断开、条目已删除）时不发，原因照整批的说明显示，原因没了（独占放开、重新连上）就收起。页面转入后台、卸载时把稿写进暂存。
- 编辑时的预览（输出 48）：标签状态里记着预览开没开（`state.preview`，缺省开）。在文字分页里编辑、开关开着时，把输入框里此刻的整篇交给世界服务渲染（`text-preview.ts`：作者停顿后读，世界变了或重新连上马上重读，只认最后发出的那一次；不走窗口的读取层），结果用 `EntryText` 不能点的画法放进编辑视图的预览栏，并让 `EntryPage` 放宽。写得不对时预览栏顶上写行、列与原因，栏里留着上一次读得出来的样子；读不出来（连接断着、结果太大）时写原因。还没读到过时栏里什么都不画（整篇是空的才画“还没有主文字”）。已删除的条目只列稿，不预览；读不出块时（开始编辑的那一章或那条线不在了）编辑视图不出预览栏，也不读。整篇超过一次肯渲染的长度（`RENDER_SOURCE_MAX`）时不发请求，栏顶上写太长。编辑视图的语言是 `canon-entry`（`entry-language.ts`）。
- 主文字没有按块的入口：阅读视图没有每一块的剧情菜单与文末的“在剧情里加一块”，也没有对应的对话框；改主文字只有整篇编辑一条路。
- 数据分页：类型有交付的专门界面就用它（加载期间写“读取中…”），没有、撤回或加载失败时用 `FieldsDataView`，加载失败另在上面写原因。能换着看“用户视图 | AI视图 | 原始视图”（输出 54；入口是选中分页上的看法菜单，`EntryPage` 的 `looks`、`look`），缺省用户视图，换分页回到用户视图：“AI视图”是 `ComponentAgentView`，字用 `shared/agent-fields.ts` 的 `fieldsText` 按这一组写（同后端 `canon_read`），节头要用设定组类型列表：它还没读到时写“读取中”，读失败时写原因与“重试”，不拿空列表凑一段与模型所见不同的字；“原始视图”是 `ComponentRawView`，只在看它时读存下来的条目（`object`，取初值里这一组）与按 `namespace` 筛的剧情变更（每页 20 条），每条只留落在这个条目这一组下的改动；两次读取各自的“读取中”分开给，先回来的那节先画。
- 标签标题与面包屑只在读的是缺省位置、实际模式时报上去（`onHead`），换位置看到别的名字时标题不变。
- 页面下方浮着窗口里那一份保存后的提示（`PageNotices`）：挂着时向它登记（`usePageNotice`），所以提示显示在这里而不是工作台通知；“还原”打开窗口里那一个还原对话框。页头自己的写入（名字、简介、别名、恢复）与菜单里加一组设定失败时，原因进它的失败那一行。世界只读时页头上面有一条横幅写原因。
- 页头的名字、简介点了在原处开就地改的浮层：两个 `fieldEditorOf("entry")`（路径 `entry.name`、`entry.summary`）锚在页头的按钮上。
- 另读作品里有没有计划（`changes` 按 `plan` 筛、一条就够）与有没有任何剧情变更：前者决定时间点的勾选项，后者决定“情节”与声明了 `needsChanges` 的附加分页出不出。
- 加一组设定：“＋”或右键菜单打开时记下条目的版本，选一项时带它写入；成功后记下那一组的命名空间（`pendingTab`），等它出现在读取结果里再切过去；作者先换了分页就不切。
- 给人物分页与形象分页 provide“打开选图”的一次性标记（`LOOK_PICK_KEY`，输出 49）；作者换到形象分页以外的分页时放倒它。

## 状态

- 加载中：章表或条目第一次还没读到。
- 读取失败：章表或条目第一次就没读出来（`EntryPage` 的 `failed`）。
- 找不到、已删除、未出场、断开：见 `EntryPage`。
- 选过的章被删掉：位置回到缺省，`state.positionGone` 为真，作者再选一个位置后清掉。

## 数据

```ts
type EntryPageHostProps = {
    id: string;
    /** 编辑器给这个标签的响应式状态（`EntryPageState`）。 */
    state: EntryPageState;
    world: CanonWorld;
    fetchOrigins: (address: TextAddress, position: ReadPosition, mode: "actual" | "planned", cursor?: string) => Promise<OriginsPage>;
    /** 世界客户端的读取（预览、读一个对象）。 */
    client: Pick<CanonClient, "call">;
    /** 本窗口的保存后的提示。 */
    notices: CanonNotices;
    /** 本窗口的还原对话框（提示里的“还原”）。 */
    revert: RevertRequests;
    views: ComponentViewRegistry;
    open: (ref: {readonly kind: "entry" | "change"; readonly id: string}) => void;
    /** 打开一次修订的回执页。 */
    receipt: (revision: string) => void;
    /** 读到页头时报给页面实现：标签标题与面包屑用它。 */
    onHead: (head: EntryHead) => void;
    /** 这个条目的主文字稿；会话在窗口的登记里（`text-drafts.ts`），不随这一页卸载。 */
    draft: TextDraftSession;
    /** 源文字的输入框（编辑器插件的代码输入框）；窗口里没有时为 null，编辑视图用普通文本框。 */
    sourceInput: Component | null;
    /** 这一页挂着的时候交出“提交主文字”，卸载时交 null。 */
    onCommitReady: (commit: (() => Promise<void>) | null) => void;
    /** 登记的条目种类（已并好）：默认设定组的分页排在文字前面；不给时没有。 */
    entryKinds?: readonly EntryKind[];
    /** 设定里的图片（取图地址、候选、上传，输出 53）；没有时图片只能手填路径、显示成“图片找不到”。 */
    images?: CanonImages | null;
    /** 登记这个设定组类型的插件 id：“添加一组设定”按它分组；不给时都算“插件”。 */
    componentPlugin?: (type: string) => string | null;
};
```

## 隐藏通道理由

- `env:timer`：预览等作者停下输入再读（`text-preview.ts` 的定时器）。
- `io:read`：读取随标签的状态变（换位置、换分页、展开一个值），只读当前分页要的；预览的读取随输入框里的整篇变；这些状态在页面里，宿主（编辑器）不知道条目页要读什么。只在真实界面里验证（`entry-page.dom.test.ts`），Lab 里看 `EntryPage` 与各分页的组件。
- `env:global`：监听文档的 `visibilitychange`（页面转入后台时把主文字的稿写进暂存），卸载时解除。
- `io:mutate`：就地改、记一笔、删除条目、提交主文字要按页面里的状态（在改哪个值、所选位置、读到的值与版本）拼写入，写完由读取层重读；宿主不知道这些。
- `state:shared-write`：保存成功后往窗口里那一份保存后的提示放一条；挂着时向它登记；点“还原”时往还原对话框里放要还原的那一次。
- `state:inject`：经 `useCanonText()`、`useText()` 取翻译端口。
