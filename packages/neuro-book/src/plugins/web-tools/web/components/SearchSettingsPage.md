# SearchSettingsPage

设置窗口 AI 分组下的“搜索与网页”页（[`web/settings-page.md`](../../../../../../../docs/specs/web/settings-page.md)）：`nbook.web` 贡献的 fill 页面，只在“用户”标签下可用。选网页工具（`web_search`、`web_fetch`）用哪家搜索服务、填各家的密钥并检测，设搜索规则与各家的高级项。它是页面，不是宿主：密钥与检测全在数据模块（`web/search-store.ts`），各设置项经传入的配置服务读写用户层（同“网络”页）；写失败交给窗口通知（`reportWriteFailure`）。改了就写，没有“未保存”状态。

## 布局

- 左栏（200px，同“服务商与模型”页的左栏，多了“使用中”一格）：顶上“搜索规则”（行尾写屏蔽了几个网站），一条分隔线，下面每家一行：logo（[`ProviderLogo`](../../../../ui/provider-icons/ProviderLogo.md)）、名称、定宽的“使用中”一格、行尾定宽的状态一格。行等高，同种零件同列。
- 右边是选中项的详情，自己纵向滚动，换项时淡入淡出：
  - 服务商：标题区（logo、名称、右边“使用中”徽标或“设为使用中”按钮，同一格互换）；[`ApiKeyField`](ApiKeyField.md)；“检测”按钮、计费提示与检测结果同一行；“高级”折叠（接口地址；Tavily 另有搜索深度）。
  - 搜索规则：默认结果条数（数字框）、屏蔽网站（标签输入），都是设置行（`SettingsRow`：标题、改过的标记与恢复默认）。
- 页面声明 `container-type: inline-size`；宽不到 600px 时左栏收起，右边顶上换成一个下拉（“搜索规则”与各家，使用中的写“（使用中）”）。
- 顶上可能有一句只读或密钥文件读不了的提示。

## 交互

- 第一次挂载时让数据模块取状态（`start()`），并选中使用中的那家；拿到状态之前密钥框是“读取中”。
- 左栏是导航：当前项 `aria-current="page"`，上下键与 Home、End 移动并选中，只有当前项在 Tab 序列里；每行的“使用中”与状态图标另写成读屏描述。
- 状态格只在出问题时有图标：这家在本次打开里检测没通过（危险色警示），或它是使用中而没有密钥（警告色钥匙）。
- “设为使用中”：这家有密钥、或使用中的那家也没有密钥时直接写 `nbook.web/provider`；否则进入“等着启用”，不切、焦点进这家的密钥框、密钥行右边写“填写密钥后即可启用”，这家的密钥写入成功后自动写设置。换选别的项、清除这家的密钥、离开这页时等待作废。使用中的那家没有密钥时，密钥行右边写“未填写”。
- 密钥的写入、清除、检测同前（Spec 输出 3 到 8）；检测结果写在按钮同一行，不推动下面的内容。
- 搜索规则：数字框改到 1 到 10 的整数就写，范围外原位提示；屏蔽网站每加一项把整串归一化（只留主机、小写、国际化域名转 punycode、去重）后写，有一项不像域名时原位提示、整串不写。
- 高级：有改过的项时默认展开；接口地址失焦或回车时写，清空回到缺省，不是 http 或 https 时原位提示；搜索深度点了就写。
- 写失败：密钥经 `reportWriteFailure(“<服务名> 的 API 密钥”, …)`，设置项的主语是这一项的标题（“使用”、各设置行的标题），原因用设置窗口写入失败的同一套说法；`unknown-outcome` 时 `uncertain` 为真。

## 数据

```ts
defineProps<{
    store: SearchStore;                                             // 浏览器入口建的数据模块
    settings: SettingsService;                                      // 本插件的配置服务：读写各设置项
    writable: boolean;                                              // 当前标签那一层能不能写（页面上下文的 writable）
    reportWriteFailure: SettingsPageContext["reportWriteFailure"];  // 写失败交给窗口通知
}>();
```

没有 emits、slots 与 expose；attrs 落在根元素上。

## 状态

- 读取中、只读、密钥文件读不了：同前（Spec 输出 2、7）。
- 选中项、等着启用、每家的“高级”开合、接口地址与条数的草稿与原位提示：只在页面里。
- 检测：空闲、检测中、通过、失败、没检成（在数据模块里，离开这页再回来还在）。

## 不支持

- 本作品标签下编辑（只有用户层）。
- 显示已存的密钥；环境变量引用。
- 从别处按 `focus` 定位到某家。

## 隐藏通道理由

- `state:local`：选中项、等着启用、开合与草稿（见“状态”）；密钥框里有没有待交出的输入（`ApiKeyField` 的 `pending`），决定第一次填写时“检测”能不能点。
- `state:inject`：文字经宿主注入的翻译端口取。

数据模块、配置服务、`writable` 与 `reportWriteFailure` 都经属性传入，读写走的是这条明面通道，所以页面没有 `io:*` 与 `state:shared-*` 标签，能在 Lab 里用内存里的远程合同替身与设置宿主摆出来（场景见 `SearchSettingsPageFixture.vue`）。
