# RolesPage

设置窗口 AI 分组下的“模型角色”页（[`models/settings-pages.md`](../../../../../../../docs/specs/models/settings-pages.md) 输出 13 到 18）：给角色绑模型。梯度四档（轻量、快速、主力、深度）与专精角色（内置的“压缩”和用户自建的）各一组，每行一个角色、一个可搜索的模型下拉（只列启用且可用的模型，第一项“不绑定”）、一个思考档下拉，选了立即写。未绑定的标红写“未绑定”，绑定的模型不可用时写原因。与 [`ProvidersPage`](ProvidersPage.md) 共用同一个数据模块；它也是页面，不是宿主。

## 布局

页面顶上一句说明解析规则；下面两组，每组一个标题行（组名与一句说明）和角色行。角色行四列：角色图标加名字与说明（自建角色是图标按钮加两个输入框）、模型下拉（200 到 280px）、思考档下拉（140 到 180px）、删除按钮（只有自建的有）。页面根是自己的容器（`container-type: inline-size`）：不到 640px 时模型下拉换到名字下面一行、思考档在它右边；不到 520px 时模型与思考档各占一行。内容列封顶 760px。

## 交互

- 模型下拉选了即写（`setRole`），选回原值不写。绑着的模型现在不可用时，下拉里补一个停用的项写着它的引用，原因里也写出是哪个模型。
- 思考档下拉的选项来自绑定模型的推理能力：第一项“跟随模型”（清除）；能真正关闭的模型有“关闭”；只能降到最低档的模型没有这一项；档位没验证（OMP 对缺证据的模型物化的通用档）的选项带说明。选了立即写（`setRole` 只带 `effort`，不动绑定）。
  - 没绑定、绑定的模型不可用、模型不推理、不能调档时下拉停用，原因写在框里（“先绑定模型”“不可用”“这个模型不支持思考”“不能调档”）；已存的档位仍显示在原因前，旁边有清除按钮。
  - 已存的档位不在当前模型的选项里（改绑模型后）：补一个停用的项，写“当前模型没有这一档，实际用 X”（X 是请求时夹取的结果，同内核的优先级），不替用户改掉。
- 自建角色左边的图标按钮打开图标菜单，选了写 `setRole` 的 `icon`；内置角色只显示自己的图标。
- 自建角色的名字与说明在失焦或回车时写（`updateRole`），名字清空时恢复原名、不写。
- “添加专精角色”加一个名为“新角色”的角色（`addRole`），它出现后焦点进它的名字框并全选。
- 别处改了角色时只换没在编辑的那几行的草稿，正在编辑的失焦后再以快照为准；回车之后紧接着失焦不重复写。
- 删除自建角色（`removeRole`）不确认：角色本身没有别的数据，绑定随之消失。
- 写失败交给窗口通知（`reportWriteFailure`），控件随快照回到实际值。
- 打开到一个角色（`focus` 是角色 id，对话的“去绑定”用）：角色列表到了才取走（`takeFocus`），滚到那一行、焦点放在它的模型下拉上（`data-role-model` 钩子，不依赖行内控件的顺序）；不认识的 id 取走后不动。窗口已开在这一页时再来一次照样定位。

## 数据

```ts
defineProps<{
    store: ModelsStore;
    writable: boolean;
    reportWriteFailure: SettingsPageContext["reportWriteFailure"];
    focus?: string | null;                          // 页面上下文的 focus；缺省 null
    takeFocus?: () => string | null;                 // 取走 focus（页面上下文的 takeFocus）；缺省总是 null（Lab 与测试不给时不定位）
}>();
```

没有 emits、slots 与 expose；attrs 落在根元素上。

## 状态

- 读取中：第一份快照之前写“读取中”。
- 只读：同 `ProvidersPage`，写控件全部停用。
- 出错：未绑定标红；绑定的模型目录里没有了、没启用或没有密钥时写原因，下拉标出错。

## 不支持

- 内置角色改名与删除（服务端拒绝为 `builtin-role`）；梯度角色只有四档，不能加。
- 自动回退：角色未绑定时报错，不换用别的模型（模型角色合同）。

## 隐藏通道理由

- `state:local`：自建角色名字与说明的输入草稿。
- `state:inject`：文字经宿主注入的翻译端口取。
- `env:portal`：下拉与提示传送到 `body`。

数据模块、`writable` 与 `reportWriteFailure` 都经属性传入，读写走的是这条明面通道，所以页面没有 `io:*` 与 `state:shared-*` 标签，能在 Lab 里摆出来。
