# FormStatus

表单里固定位置的状态行（t10 计划 3.1“状态行与表单错误”）。提交之后才知道的错（服务端回的失败码、网络不通）写在这里，不在字段下插字；空着时也占同样的高度，所以出错与恢复都不推动表单里别的东西。写法照 nb-ui 对话框页脚的状态行：危险色、带图标、超长截断、全文在 `title` 里、`aria-live` 播报。账号页每一节保存成功之后的那一句（计划 3.12 的“已保存”）也写在这里，换成成功色与对勾，由页面到时清掉。

## 布局

宽屏一行高（当前字号的行高）；窄屏（560px 及以下，与稿纸的手机版式同一个断点）两行高：手机上没有悬停，`title` 看不到，原因要在行内读得全。高度只随宽度变，不随有没有原因变。有原因时：图标、原因文字、可选的动作链接排在一起，图标对齐第一行；文字超出行数时截断加省略号，全文放进 `title`。

## 交互

- 换成另一件事（`reason` 变了）时旧的淡出、新的淡入，叠在同一个位置；同一件事只改文字时原地换字，不闪（例如倒数的秒数）。
- `aria-live="polite"`：原因出现或改变时读屏会读。字段标红时由 `Field` 的 `error` 给同一句话，读字段时连原因一起读；也可以用 `aria-describedby` 指向这一行的 `id`。
- 文字按秒变的状态行要关掉 live：live region 里的字每变一次读屏就读一遍，倒数时就是每秒一遍。这时给 `spoken` 一句不带变化部分的话（例如“操作太频繁，请稍后再试”），live region 只读它，看得见的 `text` 对读屏隐藏（`aria-hidden`）。
- 出错时的文字可以选中复制。

## 数据

```ts
defineProps<{
    /** 根元素的 id，给字段的 `aria-describedby` 用。不给时没有 id。 */
    id?: string;
    /** 要显示的原因；空串表示没有。默认空串。 */
    text?: string;
    /** 这一条是哪件事（通常是失败码）。决定换内容时淡入淡出还是原地换字。不给时按文字区分。默认空串。 */
    reason?: string;
    /** 给读屏的固定说法；给了时看得见的 `text` 不进读屏。`text` 会按秒变时必须给。默认空串，表示读屏读 `text`。 */
    spoken?: string;
    /** 失败（`danger`）还是成功（`success`）。默认 `danger`。 */
    tone?: "danger" | "success";
}>();

defineSlots<{
    /** 跟在原因后面的动作，通常是一个链接（例如“去注册”）。只在有原因时显示。 */
    action(): unknown;
}>();

// emits：没有。expose：没有。attrs：透传到根元素 `p`。
```

## 状态

- 空：占着同样的高度，什么都不显示；根元素没有 `data-site-form-status-error`。
- 有原因：危险色的图标与文字；根元素带 `data-site-form-status-error` 与 `data-site-form-status-tone="danger"`。
- 成功：成功色的对勾与文字；根元素带 `data-site-form-status-tone="success"`，没有 `data-site-form-status-error`。

## 不支持

- 不支持超过上面行数的原因，也不支持提示类（中性、警告）的颜色：这里只放失败的原因与刚完成的那一步。
- 不自己计时清掉成功的那一句：多久清、换成别的时清不清由页面定（`pages/form-feedback.ts` 的 `showSuccess`）。
