# FormStatus

表单里固定位置的状态行（t10 计划 3.1“状态行与表单错误”）。提交之后才知道的错（服务端回的失败码、网络不通）写在这里，不在字段下插字；空着时也占一行的高度，所以出错与恢复都不推动表单里别的东西。写法照 nb-ui 对话框页脚的状态行：一行、危险色、带图标、超长截断、全文在 `title` 里、`aria-live` 播报。

## 布局

一行高（当前字号的行高）。有原因时：图标、原因文字、可选的动作链接排成一行；文字过长时截断加省略号，全文放进 `title`。

## 交互

- 换成另一件事（`reason` 变了）时旧的淡出、新的淡入，叠在同一个位置；同一件事只改文字时原地换字，不闪（例如倒数的秒数）。
- `aria-live="polite"`：原因出现或改变时读屏会读。字段可以用 `aria-describedby` 指向这一行的 `id`，读字段时连原因一起读。
- 出错时的文字可以选中复制。

## 数据

```ts
defineProps<{
    /** 根元素的 id，给字段的 `aria-describedby` 用。不给时没有 id。 */
    id?: string;
    /** 要显示的原因；空串表示没有。默认空串。 */
    text?: string;
    /** 这一条是哪件事（通常是失败码）。决定换内容时淡入淡出还是原地换字。不给时按文字区分。默认空串。 */
    reason?: string;
}>();

defineSlots<{
    /** 跟在原因后面的动作，通常是一个链接（例如“去注册”）。只在有原因时显示。 */
    action(): unknown;
}>();

// emits：没有。expose：没有。attrs：透传到根元素 `p`。
```

## 状态

- 空：占一行高，什么都不显示；根元素没有 `data-site-form-status-error`。
- 有原因：危险色的图标与文字；根元素带 `data-site-form-status-error`。

## 不支持

- 不支持多行原因，也不支持成功或提示类的颜色：这一行只放错误的原因。
