# V9 草稿规则

这份规则同时给两种读者用：手工写金标的标注者，和抽取管线里的模型。两者按同一份规则写同一种“章草稿”，程序再把草稿编译成记忆图。

## 一、总原则

1. **站在读者的位置，逐章往前读。** 写第 N 章的草稿时，只能用第 N 章及之前的内容。任何文字里都不能出现后文才有的名字和后文才揭晓的事。
2. **只记以后会被问到的。** 关系、身份、来历、能力、规则、目标、状态变化、谁知道什么，这些要记。一次性的动作、表情、环境描写不单独记，写进情节的步骤里。
3. **分清是谁说的。** 旁白写的、角色说的、角色想的、书页或公告上写的，是四种不同的来源。角色说了一件事，不等于这件事是真的，也不等于他相信。
4. **不知道就说没写。** 原文没有交代的事不要补全，不要用常识替原文下结论。推断可以写，但要标成推断并写出理由。
5. **每条记录都要能在原文里找到出处。**

## 二、通用写法

- **原文位置**写成“章.段”，例如 `4.49`；同一章的连续几段写成 `4.49-4.52`。第 1 段是章名。只能引用本章的原文。
- **编号**由你来写，格式是“字母＋章号＋短横线＋本章内序号”，例如第 4 章新建的第 2 个对象是 `e4-2`。各类记录的字母：

| 记录 | 字母 | 例子 |
| --- | --- | --- |
| 对象 | e | `e4-2` |
| 说法 | s | `s4-17` |
| 段落块 | b | `b4-3` |
| 时间点 | t | `t4-1` |
| 情节 | p | `p4-2` |
| 知情 | k | `k4-1` |
| 状态变动 | l | `l4-1` |
| 疑问 | q | `q4-1` |
| 秘密 | x | `x4-1` |

- 引用前面章节已有的记录时，直接用它的编号（见“已有记录”）。不要给已有的对象再建一个新的。
- 所有文字用简体中文写成完整的句子，让人不看原文也能读懂。

## 三、各部分怎么写

### 1. 时间点 `times`

故事里的一个时刻或一段时间。同一场连续的戏用同一个时间点，时间跳了才新建。

- `day`：主线第几天。主线第一天（苏天晴醒来那天）是 1。**只在这是第一章，或原文直接写出了是第几天时才写 `day`。** 原文写“翌日”“三天后”“当天晚上”这类相对说法时，不要自己往后数，改在 `rel` 里写相对天数：`{"type": "after", "to": "t4-1", "days": 1}` 表示比 t4-1 晚一天（“翌日”是 1，同一天的另一场戏是 0，“三天后”是 3），程序会据此算出第几天；两者都写了时程序会核对。算不出相隔几天就只写先后，并在 `gap` 里写原文的说法。
- `part`：一天里的时段，取值 `dawn` 凌晨、`morning` 早晨、`forenoon` 上午、`noon` 中午、`afternoon` 下午、`dusk` 傍晚、`evening` 晚上、`night` 深夜。原文看不出就不写。
- `clock`：原文给出钟点时写，例如 `"20:00"`。`date`：原文给出日期、星期或“开学前的第二天”“月底”这类相对日期时照原文写。
- 钟点或日期比这段戏本身交代得晚时（先写她回到家，过了十几段才说离开时是八点），用 `clockAt`、`dateAt` 写明是哪一段交代的，例如 `"clock": "20:00", "clockAt": "5.29"`。这种情况下 `label` 里也不要写这个钟点或日期。
- 第几天或时段是从别处倒推出来的（例如“坐了两小时地铁后刚过中午”，所以出门前是上午），照常填写并加 `"basis": "inferred"`。
- `rel`：与别的时间点的先后，`{"type": "before" | "after" | "same", "to": "t1-1", "gap": "五分钟", "days": 0}`；`days` 是相隔的整天数，能看出来就写。主线开始之前的事（前世、半年前）没有 `day`，必须用 `rel` 写明在哪个时间点之前。
- `at`：能看出这个时间的原文位置。
- 沿用已有的时间点时不用重复写，直接引用编号。

### 2. 段落块 `beats`

把全章原文从第 1 段到最后一段连续、不重叠地切成若干块，每块写一两句概括。

- 一块通常是 5 到 20 段：一小段完整的对话、动作或说明。章首的章名、作者声明和分隔线合成一块；章中间的分隔线并入它前面的一块，不单独成块。
- `time`：这一块发生在哪个时间点。章名、作者声明这类副文本写 `null`。
- 回忆、倒叙、补叙要单独成块，写 `"narration": "flashback"`，`time` 指向被回忆的那个时间点。
- 概括只写这一块里有的内容。

### 3. 对象 `entities` 和称呼 `names`

对象是全书都会用到的查询入口。

- **什么时候建**：有名字或会反复出现的人物、组织、地点、道具；重要的设定名词（魔法少女、怪人、神典石）；任务。一次性的背景物（镜子、沙发、路人）不建。
- **类别 `kind`**：`person` 人物（含会说话的非人角色）、`persona` 身份（见下）、`group` 组织、`place` 地点、`item` 物品、`concept` 概念或类别、`task` 任务、`other` 其他。类别只用于显示，拿不准就选最接近的。
- **`label`**：整理用的一句话标签，不是书里的称呼。只能用首次出现时已知的信息，例如第 8 章刚出现的陌生猫娘写“坐到旁边的猫女”，不能写后文才有的名字。
- **`note`**：可选的一句说明。和标签一样只写长期成立的内容，不要写“本章还没有名字”这类只对当章成立的话。
- **`at`**：首次出现的段落。
- **`names`**：书里实际出现过的称呼，每个称呼写上首次出现的位置。称呼必须是那一段原文里能找到的字串。
  - `primary: true` 标主要称呼（本名、正式代号）。显示名取当前最新的一个主要称呼，所以“黑色古书”和后来自报的“墨丘利秘典”都标主要。
  - `note`：一句话说明谁在什么场合这样叫，例如“苏天晴对它的叫法”“英雄协会定的代号”。
  - 不登记单个字的称呼，也不登记“她”“对方”这类代词。“哥哥”“老师”这类泛称一般也不登记，除非书里固定用它专指这个对象。
- 已有对象出现了新称呼，写在 `names` 里：`{"entity": "e1-2", "text": "小破书", "at": "1.49", "note": "…"}`。

**马甲和身份（`persona`）**：一个人以另一个身份活动，而书里有人只认识这个身份、不知道背后是谁时，给这个身份单独建一个对象。例如魔法少女“风信子”和她的本人“南小风”是两个对象，再用一条“身份同一”的说法把它们连起来（见说法）。网名、账号也按身份处理。普通的昵称、外号不用单独建，登记成称呼即可。马甲对象的 `label` 只用它首次出现那一段已经知道的信息，不要用同一场戏后面才出现的说法（例如后面才报出的名号）。

**身份不明的人**：出场时看不出是不是已有的某个对象，就新建一个对象，标签写成当时看到的样子（“写字楼顶的深蓝猫娘”）。如果有线索指向某个已有对象，另写一条“身份同一”的说法并标 `certainty: "candidate"`。以后原文点明了，再写一条确定的说法。

**类别和个体**：一类东西（守护之星、每日任务）建成概念对象；具体的某一个（苏天晴的那枚守护之星、今天的每日任务）另建对象，用一条 `membership` 说法连到类别。`about` 里先写个体，最后写类别；几个个体属于同一个类别时可以写在同一条里。

**同名不同人**：各建各的对象。程序默认把一个称呼算给最早登记它的对象；个别地方指的是另一个对象时，用 `mentions` 标出来。两个对象本名相同时，次要的那个可以把书里用来区分它的叫法标为主要称呼（例如这副身体原来的主人标“原主人”），本名照常登记，不标主要。

### 4. 提及 `mentions`

程序会自动在原文里找出每个已登记称呼的每一次出现，你不用标。只在两种情况下写：

- 同一个字串在这一段指的是另一个对象：`{"at": "3.59", "text": "苏天晴小姐", "entity": "e1-3"}`。
- 一个重要的代称需要记下它指谁（例如某角色心里想的“另一只金毛狐狸”）：同样的写法，`text` 写那个代称。

### 5. 说法 `statements`

一条说法是一个可以单独成立的陈述，加上它的出处。

**记什么**：

| 要记 | 不记（写进情节的步骤） |
| --- | --- |
| 身份、关系、所属、住处 | 一次性的动作和表情 |
| 外貌、性格、来历、能力 | 环境和气氛描写 |
| 世界设定、力量规则、道具的作用 | 没有信息量的寒暄 |
| 任务的内容和奖励、角色的目标和计划 | 同一件事的重复转述 |
| 对人对事的态度、评价、误会 | |
| 角色对一件事的说法或想法（尤其是和实情不同的） | |
| 事件的关键结果，后面会被提起的 | |

**`text`**：一句完整的话，写清主语，保留原文里的保留语气（“恍惚间看见”“可能”“自称”）。只用此时已经出现过的称呼。不要在说法里写“本章没有交代”这类话：没有交代的事记成疑问。

**`family`**（大类，12 选 1）和 `label`（自由填写的小标签）：

| family | 含义 | 例子 |
| --- | --- | --- |
| `identity` | 两个对象是同一个个体（换了名字、身份或显露真身）；只写“甲就是乙” | 风信子的真名是南小风 |
| `kinship` | 亲属 | 南嘉鱼是南小风的姐姐 |
| `social` | 人际关系：朋友、同学、敌对、同伴、契约 | 苏天晴与秘典签了契约 |
| `membership` | 属于某组织、某类别 | 魔法少女受英雄协会管辖 |
| `possession` | 拥有、持有 | 这枚守护之星是苏天晴的 |
| `location` | 住在哪、在哪、位于哪 | 绿心公园在蓉城中心城区 |
| `trait` | 外貌、性格、来历、背景 | 原主人社恐孤僻 |
| `rule` | 设定、能力、规则、道具作用 | 怪人都会散发魔力气息 |
| `goal` | 目标、计划、任务内容 | 每日任务要求找茬魔法少女 |
| `attitude` | 态度、评价、情感 | 她后悔签约 |
| `event` | 对一件发生过的事的陈述 | 公告说风信子凌晨三点才被解救 |
| `other` | 都不合适时 | |

**`about`**：这条说法涉及的对象。`identity` 类必须正好两个，而且都是人物或身份，不能连到任务、物件之类。给人取名、拜师、同行、捆绑、替代、猜测“可能是”都不是同一个个体：前几种写 `event`、`social`、`kinship` 或 `attitude`；`identity` 的两个对象只能是“被说成同一个个体”的两头，认出这件事的人、说破这件事的人、被捆住的人都不是其中一头，他们的反应写成 `event` 或知情。例如“国丈认出眼前的和尚是孙大圣”，两头是和尚与孙悟空，国丈不在 `about` 里；“七个女子其实是女妖，把玄奘捆在梁上”，玄奘不在 `about` 里；“法明和尚给江流取法名玄奘”是取名，写 `event`，不写成两人同一；原文没有明确说就是同一个个体、只是猜测时，写 `identity` 并标 `certainty: "candidate"`。讲世界整体、不针对具体对象时可以为空。挂在哪个对象上，按“这件事在书里是以哪个身份为人所知”来选：魔法少女的公开事迹挂在身份（风信子）上，私人生活挂在本人（南小风）上。

**`src`**（出处）：

- `at`：原文位置，可以多处。
- `ch`：来源渠道。
  - `narrator` 旁白叙述，包括用第三人称转述角色处境的叙述。
  - `speech` 角色说出口的话。
  - `thought` 角色心里想的：第一人称的内心独白，或“心想、觉得、猜”引出的内容。
  - `document` 书页、公告、新闻、视频、系统提示上的文字或播报。脑中响起的系统提示音也算这一类，`by` 写发出它的对象，原文没有交代是谁就写 `null`。
  - `author` 作者声明等正文之外的文字。
- `by`：`speech`、`thought`、`document` 要写是谁说的、谁想的、谁发布的；确实看不出来写 `null`。`narrator` 和 `author` 不写。
- `to`：听到这句话、读到或看到这段文字的人。写了之后程序会自动记下他们“听说”或“读到”了这条说法。
- `mode`：不是平铺直叙时写，`question` 提问、`guess` 猜测、`promise` 承诺、`plan` 打算、`deny` 否认、`condition` 有条件。

**断言类型由程序按渠道填**：旁白是世界事实；心理是这个角色的信念；台词和文字是这个角色（或这份文字）的说法。所以角色说的话不会自动变成事实。只有两种情况需要你写 `kind`：

- 想把台词、心理或文字的内容记成世界事实：写 `"kind": "fact"`，并且必须写 `reason` 说明为什么可信。尽量不这样做。
- 旁白转述的其实是某个角色的看法：写 `"kind": "belief"` 或 `"claim"`，并在 `src` 里用 `by` 写明是谁的看法。这是旁白可以写 `by` 的唯一情况。

**推断**：原文没有直接写、是你把几处内容合起来得出的，写 `"basis": "inferred"`，在 `reason` 里写理由，在 `premises` 里列出依据的说法编号。推断是你站在读者位置得出的，渠道约定写 `narrator`。

**其它可选字段**：

- `certainty: "candidate"`：只是“可能”。
- `neg: true`：否定，例如“不是同一个人”。
- `time`：内容讲的是别的时间（回忆、转述昨天的事）时，指向那个时间点。不写就取出处所在段落块的时间。
- `secret`：这条说法属于哪个秘密（见下一小节）。
- `rel`：和前面某条说法的关系，`{"type": "confirms" | "contradicts" | "revises", "to": "s3-5"}`。后文印证了前面的说法用 `confirms`；和前面的说法相反（谎言被戳穿、新闻与实情不符）用 `contradicts`；前面那条被取代了用 `revises`：读者先前的认识被纠正，或者角色后来改变了态度和判断。

### 6. 秘密 `secrets`

少数关键的、书里有人知道有人不知道的事。主要是身份秘密（谁是哪个魔法少女、谁是重生者），以及少数关键隐情。每章新增通常不超过两个。

- 写法：`{"id": "x4-1", "title": "风信子就是南小风", "about": ["e3-4", "e4-1"]}`，再给表达这件事的说法加上 `"secret": "x4-1"`。
- 标题用当时已经出现的称呼，也只写当时已经知道的事；同一场戏后面才出现的说法不要提前用。
- 前面章节里已经有说法表达过这件事时，在秘密里用 `statements` 把它们的编号列上：`"statements": ["s4-25"]`。
- 建了秘密，就要在“知情”里写清当时谁知道。之后每一章都要对照“已有记录”里的秘密清单，看有没有变化。
- 同一个称呼可以先后指不同的人或不同的一次：老母在第 14 回是观音化的，到第 84 回是观音另一次化的老母，这是两个秘密。后文揭晓时先对照“已有记录”里的秘密：是同一次，才在原秘密上补知情；是另一次，就新建对象或秘密，知情记在新的那个上。看不出是不是同一次时，宁可新建。

### 7. 情节 `episodes`

一段有头有尾的事。每章通常 2 到 5 个。

- `title` 一句话标题，`summary` 两三句话概括，`at` 所在段落范围（可以多段），`time` 时间点，`place` 地点对象（有就写）。
- `who`：在场或参与的对象。只被提到、不在场的不算。以某个身份出场时写 `as`：`{"e": "e4-1", "as": "e3-4"}` 表示南小风以风信子的身份出场。
- `steps`：按顺序列出关键动作，每条一句话加位置。一次性的动作和细节都放这里。
- `outcome`：结果。
- 给两个已有的情节补一条连接时（后文才看出的因果，或回忆里的事和主线情节的关系），写在草稿的 `episodeLinks` 里：`{"from": "p1-2", "type": "enables", "to": "p2-2"}`。读法和情节自带的连接相同：`from` 相对于 `to`，这个例子的意思是“p1-2 因为 p2-2 才可能”。
- `links`：和前面情节的关系，**只要有相关的前情就必须写**。`after` 在它之后发生，`continues` 接着它发展，`retells` 是对它的回忆或转述，`causes` 由它导致，`motivates` 它是动机，`enables` 它使这件事成为可能。回忆和倒叙里的事也单独建情节，用它自己的时间点。

### 8. 知情 `knowledge`

谁对哪条说法或哪个秘密处于什么状态。

- `who`：对象编号，或 `"reader"`（读者）。
- `about`：一条说法的编号，或一个秘密的编号。
- `state`：`knows` 知道、`believes` 相信、`suspects` 怀疑、`heard` 听说、`read` 读到、`unaware` 不知道。
- `how`：一句话说明怎么知道的，或者从哪里看出不知道。
- `at`：依据的原文位置。一般引用本章；给后建的秘密补记“前面章节里某人当时就知道”时，可以引用当时的原文。

**程序会自动生成三类知情，不要写**（写了只是重复）：角色的心理活动意味着他自己相信；写了 `to` 的台词和文字意味着对方听到或读到；旁白确认“某个身份就是某人”之后，本人知道自己的这层身份。

**这一条有例外**：程序的前提是本人在用这个身份行事（变身、化名、冒充）。转世、前世、失忆、被附身、被蒙蔽这类本人未必知道的身份，旁白点破只说明读者知道（例如旁白一句诗说“金蝉子转世为玄奘”，不等于玄奘自己知道）；这种情况要自己为本人写一条知情记录，写 `unaware` 并加 `"basis": "inferred"`，`how` 里写“这是转世（或失忆等）的身份，原文没有写他自己知道”；之后原文写到他得知，再写 `knows`。程序看到本人已有记录，就不再替他补“知道”。

**需要你写的**：

- 秘密的知情变化：谁在这一章得知了、起疑了。
- 已有记录里标为“推断”的知情判断（例如推断某人知道或不知道某个秘密），本章出现了新的依据，不管是支持还是反驳，都再写一条知情记录：引用本章原文，`how` 写明新依据是什么，仍标 `inferred`。旧记录不用改。
- **“不知道”只在有依据时写**，分两种：
  - 原文明说：旁白写“她全然没有注意到”。直接写 `unaware`。
  - 原文没明说，但从表现看得出：她把同一个人的两个身份当成两个人来对待、当面问“你是谁”。写 `unaware` 并加 `"basis": "inferred"`，`how` 里写是什么表现。
- 原文完全没有涉及某人是否知道时，**什么都不写**。没有记录不等于不知道，查询时会如实显示“没有记录”。
- 读者靠推断才能知道的事，可以写一条 `who: "reader"` 的记录并标 `inferred`。旁白明写的事不用写，程序会算出读者从哪里起知道。

### 9. 状态变动 `ledger`

会随情节变化、以后会被问到“现在是多少”的量。只记真正发生的变化，不记标价和悬赏。

- `owner`：谁的。`track`：哪个量。**同一个量全书用同一个名字**，沿用“已有记录”里的写法。
- 数量（神典石、粉丝数）：`gain` 增加、`spend` 减少，写 `amount`；原文直接给出当前数值时用 `set` 并写 `value`。增减的同时原文也写了变动后的数值，就把它填进 `value`，程序会用它核对。原文没写变动后的数值就不要自己算了填。
- 持有的东西（`track` 写“道具”）：`get` 得到、`lose` 失去、`use` 用掉，`item` 写物品对象。
- 进度和阶段：`track` 写成“任务：任务名”或“魔杖强化阶段”这样的名字，用 `set`，`value` 写“进行中”“已完成”“8/10”。任务名用任务的标题，不用“每日任务1”这种每天会重用的编号。
- `reason`：一句话原因。`at`：原文位置。

### 10. 疑问 `questions` 和 `questionUpdates`

书里提出、暂时没有回答的问题：悬念、来历不明的人和物、没解释的现象、角色自己想不通的事。角色心里的疑惑也算：某人知不知道某件事、两件相似的事是不是巧合、某个安排是不是冲着自己来的。

- 新疑问：`{"id": "q1-4", "text": "造物主是谁？", "at": ["1.66"], "about": ["e1-6"]}`。是书里某个角色在问时加 `by`。
- 后文再次提起、部分解答或解答时，在 `questionUpdates` 里写：`{"q": "q1-4", "type": "raised" | "partial" | "answered", "at": [...], "answer": "s20-3", "reliability": "narrator" | "claim" | "belief" | "inferred"}`。`answer` 指向给出答案的说法；`reliability` 说明答案是旁白确认的（`narrator`）、只是角色说出来的（`claim`）、是角色自己心里的想法（`belief`），还是推断出来的（`inferred`）。
- 每章对照“已有记录”里未解的疑问，看有没有新的进展。本章的说法哪怕只是和某个疑问有关的一条线索、还算不上解答，也要写一条 `partial`（有了部分答案）或 `raised`（只是再次提起），`answer` 指向那条说法，`note` 写这条线索说明了什么。以后被问到这个疑问时，查疑问就能找到全部线索。
- 读者已经知道答案、只是某个角色还不知道的事（例如角色当面问“你是谁”，而旁白早已写明），不记成疑问，用秘密的知情来表达。

### 11. 重要程度 `tier`（说法和情节）

给每条说法和每个情节写一个 `tier`，表示它对理解主线有多重要。只按你此时读到的内容判断，不猜后文。

- `1` 主线必需：身份与秘密、关键设定和规则、主要人物的目标和关系变化、推动故事的关键事件。少了它后文会看不懂。
- `2` 有用：人物的背景和能力、次要人物的关系、有后续可能的事件。
- `3` 琐碎：一次性的态度和情绪、日常琐事、环境细节。少了它不影响理解。

三档的比例大约是两成、五成、三成：1 级是少数，3 级不少。态度、情绪、一次性的评价默认写 3，除非它会影响后面的行动；日常对话里顺带交代的细节也写 3。拿不准时写 2。

情节用同一个尺度：多数情节写 2；只有推动主线、少了它后文会看不懂的写 1；过渡性的日常场景写 3。

## 四、整理稿（每隔若干章写一次）

- `merges`：发现两个对象其实是同一个且建重了，写 `{"keep": "e3-1", "drop": "e7-4", "reason": "…"}`。马甲和本人不要合并。
- `summaries`：给主要对象按方面写摘要。方面 `facet` 取值：`overview` 概览、`appearance` 外貌、`personality` 性格与说话方式、`relations` 人际关系、`history` 经历、`abilities` 能力与道具、`goals` 处境与目标。每句话在 `deps` 里列出依据，至少一个；依据可以是说法、情节、知情、状态变动的编号。
- `arcs`：把相关的情节归成故事线，写标题、概括、包含哪些情节、是否还在进行。编号是 `a` 加整理到的章号加序号，例如读到第 5 章时写 `a5-1`。一个情节可以属于多条故事线。

## 五、输出格式

一章一个 JSON 对象，字段如下，没有内容的数组可以省略：

```json
{
  "chapter": 4,
  "times": [], "beats": [], "entities": [], "names": [], "mentions": [],
  "secrets": [], "statements": [], "episodes": [], "episodeLinks": [], "knowledge": [],
  "ledger": [], "questions": [], "questionUpdates": []
}
```

## 六、常见错误

- 给已有对象又建了一个新对象。先查名册。
- 文字里用了后文才出现的名字。
- 把角色的话、角色的想法、公告的说法写成旁白事实。
- 把悬赏和标价记成收入和支出。
- 原文没写某人是否知道，却写了“不知道”。
- 把前世、转世、被蒙蔽的身份当成本人知道（见知情一节的例外）。
- 把“某人认出了某人”“某人给某人取名”“某人把某人捆住”写成这几个人互相同一。
- 把后文另一次的化身并进前文的秘密，只因为称呼一样。
- 甲认为乙知道某件事，就给乙写了一条“知道”。这只是甲的想法，应记成甲的一条说法；乙是否知道要有乙自己的依据。
- 把一次性的动作写成说法，导致说法又多又碎。
- 情节没有连到前面的相关情节。
