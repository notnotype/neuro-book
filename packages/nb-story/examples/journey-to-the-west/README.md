# 示例：《西游记》全 100 回

用 nbstory 抽取管线抽出的《西游记》记忆图，可以直接导入，不用调用模型。原作明代，公有领域；原文取自维基文库《西遊記》（世德堂本系），整本转成简体。

- `xiyouji-graph.json.gz`：V9 记忆图，解压后 9 MB；原文、100 回的人物、称呼、说法、谁知道什么、情节、悬念、时间线都在里面。
- 抽取模型是 `gpt-6-luna`（OpenAI Chat 接口），2026-10-24 抽成。

## 导入

```bash
gunzip -c xiyouji-graph.json.gz > xiyouji-graph.json
nbstory import xiyouji-graph.json --title 西游记
nbstory books
```

导入后书库里是 100 章、852 个对象、2,136 条说法、98 个秘密、387 个情节。书进的是默认书库（`~/.local/share/nbstory`）；想和自己的书分开放，每条命令都加同一个 `--library <目录>`。

## 走读

```bash
# 孙悟空读到第 7 回时是什么样：称呼、神通、关系、秘密，不含之后的事
nbstory card 孙悟空 --at 7

# 谁知道什么：读到第 27 回，每个秘密谁知道、谁不知道，附“章.段”出处
nbstory knows --at 27

# 两个人之间的说法、一起出场的情节、互相知道的事
nbstory between 孙悟空 唐僧 --at 14

# 搜说法和原文：紧箍咒，读到第 20 回为止
nbstory search 紧箍咒 --at 20

# 网页查看器（秘密页、关系图、人物卡、时间线、原文、问答），打印登录链接
nbstory serve --open
```

`--at` 限定阅读位置，之后的内容不出现。例如 `search 紧箍咒 --at 20` 只给第 14 回的两条说法和一段原文。

内置问答要先 `nbstory config init` 配模型，再 `nbstory ask "孙悟空知道戴在头上的是什么吗？" --at 14`。

### 已知的抽取错误

这份示例是用 0.1 的管线抽的，没有经过后来的马甲核对（[t35](../../../../.agents/works/w00024-nb-story/tasks/t35-persona-check/README.md)）与规则收紧（[t40](../../../../.agents/works/w00024-nb-story/tasks/t40-fix-issue-264-extraction-errors/README.md)）。下面几类错误在 [issue 264](https://github.com/notnotype/neuro-book/issues/264) 里逐条核对过，别把这份示例当准确数据：

- **身份说法连错了人**：取名、拜师、认出、捆绑被写成“同一个个体”，所以 `knows` 里人名后的别名会混进不相干的人。孙悟空后面有须菩提祖师（他的师父）、国丈、白鹿；玄奘后面有法明长老（金山寺收养他的和尚）、七个妖精、女子。唐僧显示成“法明长老”也是这一类。
- **本人的身份被当成本人知道**：秘密 x12-1“金蝉子就是玄奘”里，玄奘一行写着“知道，这是本人自己的身份”，依据只是旁白的一句诗，原文没有写玄奘自己知道。同一条秘密里，白骨精、金角大王和银角大王、山中妖精确实知道，`knows` 里却是“没有记录”。
- **同一称呼的两次化身接成一件事**：秘密 x14-1（第 14 回传紧箍咒的老母是观音）的猪八戒、沙悟净一行，依据是第 84 回观音另一次化作老母。

后两类和第一类的写法已在抽取规则里收紧，只对之后新抽的书生效；这份示例要重新抽过才会改正。
