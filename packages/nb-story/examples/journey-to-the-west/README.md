# 示例：《西游记》全 100 回

用 nbstory 抽取管线抽出的《西游记》记忆图，可以直接导入，不用调用模型。原作明代，公有领域；原文取自维基文库《西遊記》（世德堂本系），整本转成简体。

- `xiyouji-graph.json.gz`：V9 记忆图，解压后 9 MB；原文、100 回的人物、称呼、说法、谁知道什么、情节、悬念、时间线都在里面。
- 抽取模型是 `gpt-6-luna`（OpenAI Chat 接口），2026-10-30 抽成：按 [t40](../../../../.agents/works/w00024-nb-story/tasks/t40-fix-issue-264-extraction-errors/README.md) 收紧后的规则重抽，替换了 2026-10-24 的第一版。

## 导入

```bash
gunzip -c xiyouji-graph.json.gz > xiyouji-graph.json
nbstory import xiyouji-graph.json --title 西游记
nbstory books
```

导入后书库里是 100 章、894 个对象、2,048 条说法、117 个秘密、432 个情节。书进的是默认书库（`~/.local/share/nbstory`）；想和自己的书分开放，每条命令都加同一个 `--library <目录>`。

## 走读

```bash
# 孙悟空读到第 7 回时是什么样：称呼、神通、关系、秘密，不含之后的事
nbstory card 孙悟空 --at 7

# 谁知道什么：读到第 27 回，每个秘密谁知道、谁不知道，附“章.段”出处
nbstory knows --at 27

# 两个人之间的说法、一起出场的情节、互相知道的事
nbstory between 孙悟空 唐僧 --at 14

# 搜说法和原文：紧箍咒，读到第 20 回为止
nbstory search 紧箍咒 --at 20

# 网页查看器（秘密页、关系图、人物卡、时间线、原文、问答），打印登录链接
nbstory serve --open
```

`--at` 限定阅读位置，之后的内容不出现。例如 `search 紧箍咒 --at 20` 只给第 14、15 回的三条说法和一段第 14 回原文。

内置问答要先 `nbstory config init` 配模型，再 `nbstory ask "孙悟空知道戴在头上的是什么吗？" --at 14`。

### 已知的抽取错误

这份示例是 t40 收紧规则后重抽的，比第一版（[issue 264](https://github.com/notnotype/neuro-book/issues/264) 逐条核对过的那版）错得少，但不是准确数据，别当成标准答案：

- **身份说法仍有连错的**：按“确定的、连两个对象的身份说法”逐条看，约有 9 条把不同的人连成了一个：
  - `s17-5`、`s86-7`：孙悟空自报“是三藏的徒弟”“护送三藏取经”，被连成和玄奘同一个。后果是 `find 唐僧` 找到的是孙悟空，称呼里混着唐僧；玄奘前世金蝉也进了同一组。
  - `s14-9`：玄奘和太宗皇帝。`s5-20`：孙悟空和他的官衔。`s70-7`：孙悟空和朱紫国的正宫。
  - `s78-21`：孙悟空和国丈（国丈连着白鹿，所以白鹿也进了同一组）。
  - `s9-2`：陈萼和他的籍贯地区。`s47-10`：陈澄和他弟弟。`s89-8`：两个狼头精。
  - 孙悟空那一组里其余的连线（变作某某）是书里的变身，连着没错。在查看器里，这些连错的可以在人物卡“同一身份”里逐条断开，断开后可撤销。
- **第一版里的几处已经没有了**：须菩提祖师、法明和尚、七个妖精不再被连进孙悟空和玄奘；第 2 回的秘密写成“不得泄露师父是谁”；第 84 回观音再次化作老母单独成了秘密 x84-1，没有再挂到第 14 回的 x14-1 上。
- **丢了一条悬念**：第 72 回“七个女子就是盘丝洞的七个女妖”这条秘密没有了，因为新图从一开始就只有“七个女妖”一个对象，读者看不到“她们原来是妖精”这个悬念。
- **没有逐条核对的**：本人身份被当成本人知道（新图里这类记录有 12 条）、漏掉的知情人（例如白骨精）。只抽查了第 2、14、27、84 回，不能说已经修好。

规则收紧只对之后新抽的书生效；这份示例是第二版，不是最终版。
