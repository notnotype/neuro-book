# 示例：浮动窗口的桌面

用 `@notnotype/nb-layout` 搭一个“桌面加窗”的布局：四扇窗浮在桌面上，可以拖标题栏移动、拖边角缩放、最大化、最小化、关闭，最下面是列着四扇窗的底栏。把窗拖到桌面的左缘或右缘，它就“平铺”进布局的树里、占掉那一侧；取消平铺或再拖别的窗贴同一侧，它又飞回桌面上。布局存在浏览器里，重新打开还在。

库本身不带窗的外观与操作：它管的是一棵布局树、浮动窗的摆放与过渡、缩放手柄、拖动会话与落点反馈。窗有哪些按钮、最小化是什么意思、哪里算贴边，都是这个示例自己写的，这正是它要演示的。

## 跑起来

```sh
npm install
npm run dev
```

这个目录可以单独拷走：它只依赖 `@notnotype/nb-layout` 与 `vue`，只经包的公开入口导入。它跟着仓库 master 上的 nb-layout，可能用到 npm 上还没发布的名字；照已发布的版本抄时，看仓库里那个版本的标签下的这个目录。

## 读的顺序

1. `src/model.ts`：模型。一棵网格（只有桌面、底栏和平铺进来的窗）加四扇窗各自的状态；状态与操作的对应表（哪个状态下哪个操作能做）；平铺的树操作与它的顺序；试平铺；夹取的几何；存档与读档。
2. `src/drop.ts`：拖标题栏时的落点规则。哪里算贴边；落点的完整动作。
3. `src/App.vue`：把模型接到 `NestedGrid`（`useGridHost`、`floats`、内容层）、整窗移动用的拖动会话（`useDragSession`）、缩放手柄（`FloatWindowHandles`）、落点反馈（`DropFeedbackOverlay`）、按下抬升。
4. `src/WindowFrame.vue`、`src/WindowBody.vue`、`src/Taskbar.vue`：标题栏、正文与底栏。

## 几个值得先知道的点

- 窗在“浮动”与“平铺”之间来回时，它的叶 id 不变（都是窗的 id）：浮动时它不在树里、矩形由 `floats` 给，平铺时它是树里的一块叶。库看见同一个 id 换了一边，就把它从原来的位置飞到新的位置。
- 窗的矩形有两份：模型里记着的“最后一次浮动的矩形”，和画出来的矩形。画之前先夹进桌面，视口变小、平铺占了地方之后窗都在桌面里；记录的矩形不改，视口变回来窗回原处。
- 整窗移动由拖动会话驱动：会话管按下、起拖门槛、Escape 与失焦取消、放下；窗跟着指针挪由网格的 `placeFloat` 做。松手在边缘时先把拖到的矩形发布出去，下一帧再改树，窗才从松手处飞进那一侧。
- 平铺时树怎么改取决于桌面叶此刻的父节点（竖向的根，还是已经有平铺窗的横向分支），不取决于“这是第几扇”。

## 绕过的库的空缺与已知限制

- 拆到放不下时库不拒绝，只按约束压缩并在布局结果里报 `over-constrained`。示例在一棵复制的树上先平铺一遍，放不下的落点显示 “Not enough room”、松手时窗停在松手处，不平铺（`model.ts` 的 `previewTile`）。
- 库没有 `grid.clone()`：复制一棵树用快照加读档，快照不带最小尺寸与保留像素，策略要按 ref 再给一遍，全示例只有一个出处。
- 库不交出某块叶此刻的矩形：桌面叶的矩形示例自己按布局摆一遍。
- `clampFloatRect` 只收宽高、夹在从 0 开始的区域里：桌面叶左边有平铺窗时它不从 0 开始，示例的 `deskClamp` 先减原点、夹完再加回；缩放手柄的 `max` 是尺寸不是边界，预览与提交都要先与桌面求交。
- `removeLeaf` 会把只剩一个孩子的分支展平：同一侧换窗时先加新的、再删旧的。
- 浮动窗的矩形变化库不做过渡：最大化与恢复是瞬间的。
- 窗的正文只是一个文本框，打的字不进存档：重新载入后是空的。
- 拖动只能用指针；窗的缩放与移动有键盘（聚焦手柄按方向键），整窗移动没有键盘。
- 窗口缩小到连桌面的最小尺寸都放不下时照库的行为压缩。
