# 示例：标签编组

用 `@notnotype/nb-layout` 搭一个“标签停靠”的布局：左边一个可以收起的侧栏，右边几组标签。标签可以在编组之间拖、拖到一个编组的边上拆出新编组、拖到正文中央移进去；关掉最后一个标签，编组就缩回去；布局存在浏览器里，重新打开还在。

库本身不带标签条与停靠规则：它管的是一棵布局树、按约束算尺寸、拖分隔线、拖动会话与落点几何。标签、编组、哪里算落点，都是这个示例自己写的，这正是它要演示的。

## 跑起来

```sh
npm install
npm run dev
```

这个目录可以单独拷走：它只依赖 `@notnotype/nb-layout` 与 `vue`，只经包的公开入口导入。它跟着仓库 master 上的 nb-layout，可能用到 npm 上还没发布的名字；照已发布的版本抄时，看仓库里那个版本的标签下的这个目录。

## 读的顺序

1. `src/model.ts`：模型。一棵网格加一张“编组里有哪些标签”的表，两者按叶的 id 对上；每个 ref 的策略（保留像素、最小尺寸、收起）只有一个出处；拆分、挪动、关闭的步骤与顺序；存档与读档。
2. `src/drop.ts`：落点规则。哪里算落点、算什么落点；落点的完整动作。
3. `src/App.vue`：把模型接到 `NestedGrid`（`useGridHost`）、标签的正文放在内容层、一场拖动会话（`useDragSession`）、落点反馈（`DropFeedbackOverlay`）、焦点。
4. `src/TabBar.vue`、`src/TabPanel.vue`：标签条与正文。

## 绕过的库的空缺与已知限制

- 拆到放不下时库不拒绝，只按约束压缩并在布局结果里报 `over-constrained`；深度与节点数的上限也要拆了才知道。示例在副本（`grid.clone()`，连同策略）上先试拆一次，做不成的落点只显示、不提交（`model.ts` 的 `canSplit`）。
- 快照不带策略（保留像素、最小尺寸、收起策略）：读档时策略要按 ref 再给一遍，漏给了库不报诊断，所以全示例只有一个出处（`policyFor`）。
- 删叶时只剩一个孩子的中间分支会被展平，分支自己的约束会丢，所以示例只给叶挂策略。同向拆分并进父分支，不会越拆越深。
- 最后一个编组的最后一个标签不能关：只剩侧栏时没有编组可拆（侧栏保留像素，拆它会被拒绝），标签就没有地方放了。
- 标签放不下时标签条横向滚动。拖动会话的边缘滚动只滚竖向，拖到标签条两端它不会自己滚：要放到滚出去的位置，先把标签条滚过去再拖。
- 收起状态不在网格快照里，示例另存；展开回到快照里的宽度意图，收起前的宽度不用另存。
- 拖动只能用指针：拖动会话支持键盘拖动，示例没接。标签条本身能用键盘：方向键在标签之间走，Delete 关掉当前标签，F6 在侧栏与编组之间走。
- 窗口缩小到放不下时照库的行为压缩。
