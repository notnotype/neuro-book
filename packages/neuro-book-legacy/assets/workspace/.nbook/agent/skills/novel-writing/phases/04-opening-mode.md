# 环节四：开局模式（黄金三章）

新书首轮写作循环的特化。开局设计不是单独的流程：它用环节一的方法设计、环节二落库、环节三成文，本文只补充开局特有的判断和检查。默认关注前三章附近的阅读体验，但章节数量由节奏决定，不被“三章”机械限制。

默认按用户主导推进：先了解用户想要的开局画面、第一股压力、主角第一个选择和不想采用的套路。可以给 2 到 4 个开局推进方向作为灵感（发散不足时用 `parallel-brainstorm` workflow），让用户选择或修正；只有用户明确要求“你来设计”“直接给完整开局方案”时，才由 Agent 主导拆完整开局。

## 前置要求

开始前应尽量具备：

- 小说简介、类型基调和核心 hook。
- 主角基础定位。
- 最小世界书条目。
- World Engine 已初始化并记录开局相关角色、地点或势力。

缺基础时回 `novel-setup` 对应阶段。setup 阶段留下的 `initial-plot-seed`（剧情种子）是本模式的输入之一，但开局的具体剧情在这里设计，不是种子的照搬。

## 锁定开局承诺

先询问或整理读者在开篇会看到什么：

- 主角第一眼处境。
- 第一股压力。
- 第一个主动选择。
- 第一轮爽点或情绪释放。
- 章末继续阅读的理由。

如果用户还没有明确方向，先给几个互斥开局候选，说明它们分别会带来怎样的阅读期待。

## 多视角开局推演

开局设计不要只从作者视角安排事件，应在几个视角之间切换（方法细节见 `01-plot-design.md`）：

- 上帝视角：分析开篇承诺、节奏、压迫感、爽点、悬念、读者期待和章末钩子。分析后给出可选强化方向，让用户调整。
- 主角代入：只使用主角当前知道的信息、性格、欲望、恐惧、资源和误判，推演主角可能的第一反应和第一个主动选择。
- 多角色代入：代入开局出场人物、反派、旁观者或间接影响局势的人，检查他们各自想要什么、害怕什么、会怎样误判。
- 随机扰动：当开局太顺或太线性时，给出破坏型、帮助型、误导型、无关型或反噬型素材，让用户决定是否加入。

## 整理开局段落

用户确认开局方向后，再按节奏自然拆成 2 到 5 个开局段落或章节草案，不强行三章。

每段至少说明：

- 本段发生什么。
- 本段的读者期待是什么。
- 主角做了什么选择。
- 本段结尾留下什么钩子。

## 落库与成文

- 开局方向确认后，走环节二（`02-canon-commit.md`）：用项目日历字符串确定开局时间，按 LOD 判断哪些角色、地点、势力需要 subject，写入关键位置、状态、认知、关系和势力动向。不把未确认的候选剧情写入时间线。
- 每章走环节三（`03-chapter-loop.md`）成文。引用优先指向已有 lorebook 和 World Engine subject，不要把动态剧情事实倒灌成稳定世界设定。

## 开局评审加严

开局章节的评审在环节三基础检查之上，额外检查：

- 开篇是否迅速给出压力或异常？第一章有没有在前几段抓住读者？
- 主角是否有主动选择，而不是只被带着走？
- 核心 hook / 金手指是否及时亮相，没有被设定铺垫淹没？
- 每段是否都有读者期待和推进功能？低谷与释放是否有铺垫？
- 每章结尾是否留下下一步问题、目标或威胁？
- 最狠的一问：**读者会不会在第三章弃书？** 找出最可能弃书的段落并给出修改建议。

## 完成标准

- 开局范围明确，且不被“三章”机械限制。
- 开篇压力、主角行动、低谷、释放和钩子成立。
- 开局方向由用户确认，不是 Agent 单方面定稿。
- 已通过多视角切换检查主角行动和其他角色反应；采用的随机扰动经过用户确认。
- 开局事实已按环节二落进 World Engine，正文按环节三产出并通过加严评审。
