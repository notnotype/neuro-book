## 迁移范围

源为浏览器 `novel.ide.local` 中的 `leftPanelWidth`、`agentPanelWidth`、`projectPickerLayoutMode`。
其它字段继续由现有 owner 管理；`novel.ide.session`、正文、撤销栈、Agent Session 和草稿不整桶迁移。

| 源 | 目标 | 缺失时 |
|---|---|---|
| 全局左右尺寸 | 显式未开项目/用户资产工作面的 user/local 尺寸记录；同一合法旧值可初始化两个已列出的工作面 | 使用产品默认，不自动落盘 |
| 全局左右尺寸 | 各 Project 不自动继承；原值保留在迁移备份中 | 项目使用当前产品默认尺寸，首次主动调整后才保存 |
| 书架模式 | user/local 书架模式记录 | 使用产品默认，不自动落盘 |

映射仅用于本次旧用户偏好迁移，不建立 user 到 project 的运行期继承。
默认尺寸从产品唯一常量读取，不在迁移文件中维护另一套数值。

## 启动顺序与单写者

1. 在旧 Pinia 持久化插件可能重写 `novel.ide.local` 前捕获完整原始字符串。迁移适配器先将原件写入专用浏览器暂存并回读核验，
   多标签创建暂存与转换旧 writer 共享初始化互斥；原件已存在时不得用后续旧桶覆盖。暂存带版本、来源与摘要，原始值上限 8 MiB。
   这是一项仅用于旧值迁移的宿主例外，不供组件读写普通状态；data 备份登记相同原件容量上限。
2. 暂存核验成功后，未迁字段继续由原 owner 持久化。迁移期 serializer 只固定三个源字段为捕获值（原本缺失的保持缺失），
   不接受新尺寸或书架意图回写源字段；完整旧 JSON 损坏时仍保留原始暂存，其它字段使用各自默认并允许正常保存。
   初始化可持久恢复的客户端身份后，将原始字符串、迁移版本与来源信息保存为 data 内的只读迁移备份并核验。
   身份不可恢复时不开始导入；data 暂不可达时保留暂存与源字段，界面提示迁移未完成，不阻断未迁字段的 writer。
3. 逐项校验源字段，非法字段只记录诊断并保留原件。读取目标后，仅对从未创建、也没有删除标记的记录做条件初始化。
   已有记录、用户重置形成的删除标记和未知高版本均不被旧值覆盖。
4. 每个目标确认写入后登记迁移进度；失败保留源和已完成进度。下次启动继续未完成项，不重复导入或回滚已有目标。
5. 三个字段的全部读取和提交入口同批切换到新 authority，初始化未就绪时遵守加载与未保存反馈合同，不启用旧值写入。
   全部目标处理完成后，从旧持久化 `pick` 移除三个字段，解除仅用于保留源值的 serializer；其它字段一直由原 writer 管理。
   如旧消费者仍需 Pinia，只保留新 authority 的投影，旧尺寸赋值入口改为宿主提交意图，禁止镜像触发第二次保存。
6. 核验新记录、迁移标记、data 原件和当前可持久恢复身份；再清理旧桶内已迁字段和浏览器原件暂存，保留其它字段。
   迁移进度与完成标记独立于目标记录保留，墓碑维护回收后也不重新导入；正常运行不维护旧版双写副本。

多标签同时迁移由 Storage 条件写和迁移记录互斥；一个标签已完成的工作不会被另一个的旧快照覆盖。
迁移备份本身不因读取坏值而被解析重写，且不进入普通文件树或内容索引。
data 原件、进度和完成标记由受信 `workbench.migration` owner 的 user/local 专用备份边界拥有，
使用本次迁移版本和来源定位，不跟随尺寸目标的删除或分区回收。每个身份域/主体/客户端的本次迁移仅保留一份原件，
原件上限 8 MiB，进度/完成元数据上限 64 KiB，连同封装预留总计 9 MiB；不占普通状态 quota。
其它客户端或源版本不能改写该完成标记；多标签恢复读取同一标记，不能把读取失败当作尚未迁移。

## 失败与回滚

- 浏览器原件暂存失败或超过上限：保留完整旧桶，暂不启动会重写它的 writer；明确提示该桶偏好目前仅内存生效并提供重试。
  只有无法先保留原件时才冻结整桶，不能将后端不可达或新目标保存失败扩大为整个桶无法持久化。
- data 原件备份失败：保留浏览器暂存与三个源字段，提供重试；未迁字段继续持久化。
- 客户端身份不可持久保存：停留在未开始导入状态，不写临时客户端分区、不登记完成、不清源；身份恢复可用后重试。
  已验证可持久不等于保证浏览器未来永不驱逐；用户事后清除浏览器资料仍遵守客户端身份丢失合同。
- 目标写入失败：保留源与进度，失败字段继续显示未保存状态；重试以最新目标 revision 为条件。
- 部分目标已存在：按目标权威值恢复，不用源覆盖；未支持版本遵守禁止普通覆盖合同。
- 运行旧应用版本：旧版不会读取新 Storage，不保证展示新保存的布局；不会为兼容旧版持续双写。
- 需要恢复旧行为时：停止应用写入，从完整迁移前备份恢复，或显式导出所需旧字段；保留新 Storage 原件以便再次升级。
  该客户端的 data 迁移原件由迁移适配器/恢复工具取回，不要求用户手改持久化内部文件。
- data 原件与迁移标记不自动删除；浏览器暂存按完成步骤退役。未来 data 清理需独立定义保留与回滚窗口。

## 验收

- 正常旧值、缺失字段、非法 JSON/非法字段、已有目标、高版本目标分别验证。
- 在原件保存、目标写入、进度登记和旧桶清理处中断，重启后能安全继续。
- 后端不可达/磁盘满时修改未迁字段并刷新仍可恢复；原件暂存失败时整桶冻结和提示可观察，原始损坏 JSON 仍可取得。
- 身份不能持久恢复时刷新两次不产生临时分区导入；恢复稳定身份后只导入一次；墓碑回收后不重新迁入旧值。
- 两标签同时迁移、一个标签仍持有旧投影时，目标不被覆盖；旧写者不能重新生成尺寸字段。
- 从主页面旧 resize 入口、新 Workbench、书架分别修改并刷新两次，仅新记录变化，未迁字段保持原归属。
- Project A/B 没有旧尺寸复制；未开项目与用户资产按明确 user 记录恢复；重置后不会重新导入旧值。
- 导出备份能取得迁移原件；所有测试使用隔离根与浏览器存储 fixture。
