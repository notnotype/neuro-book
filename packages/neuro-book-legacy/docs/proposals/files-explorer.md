## 问题

现有文件面板混合基础文件管理、领域 UI 与默认产品依赖，难以在 Lab 隔离验证；文件点击到正文可交互还有 Issue #128 报告的延迟。第一版要让主页面的真实文件操作与编辑保存闭合，而不是只给旧面板套一个插件入口。

## 目标与非目标

**已确认的范围变化**：首版只做好基础文件资源管理与 NeuroBook 内容节点展示。资源管理器中的角色、世界书等领域模板、专用明细和领域操作可以移除；不再要求为这些几乎未使用的功能建设扩展机制。移除的是界面耦合，不是删除用户文件、frontmatter、数据库或撤销服务端访问保护，也不授权清理其它独立领域工作面。

主页面左侧是真实交付面：通过内置 Files 服务取得真实项目数据，完成文件操作、打开编辑和保存；Lab 仅作局部确定性验证。两个模式操作同一数据，不建立第二套内容树持久记录；模式切换不能重开文档或丢失未保存内容。多选、复制/剪切/粘贴属于首版基础能力，不随领域功能一起裁掉。

本机使用优先，跨机器可用，先沿用 HTTP 请求 + SSE 通知；不以 WebSocket 作为插件化或低延迟前提。首版不做非内置可执行插件安装、公开 SDK、动态 API 注册、沙箱、热卸载、Git、全文搜索、远程文件系统或高延迟公网专项协议。也不预建领域贡献平台；设计只保留文件访问、文档打开、呈现和宿主交互的明确接缝。

## 模块、宿主能力与数据归属

沿已确认方向，**Files = `workspace-files`，资源管理器 = `files-view`**；两者均作为内置插件接入。`platform-files` 仍是下层基础设施。下表是逻辑模块，不要求每行成为插件或 npm 包；文档/编辑器内部拆法仍是设计候选。

| 模块 | 负责 | 不负责 |
|---|---|---|
| `platform-files`（已实现） | 经授予的根内 I/O、监听、锁与释放 | 目录展示、dirty、多文件业务事务 |
| `workspace-files` | 精确工作区绑定下的文件访问与操作、树快照/变更、条件写入及现有 History 接线；浏览器代理和后端入口分别装配 | UI 模式、选中、展开、编辑器正文缓冲；不另建 watcher/index owner |
| 宿主 API 适配 | 认证、参数/目标校验、调用 Files 服务、结果/事件映射 | 自动把任意服务对象公开到网络；插件自行开端口 |
| `document-session` | 文档身份、唯一正文缓冲、dirty、输入结算、保存/冲突与恢复 | 文件树、布局几何、普通 UI 状态持久化 |
| 资源操作协调（工作台内部模块） | 统一菜单/拖动/粘贴意图，协调本窗口待结算输入与文件操作结果，再更新文档绑定 | 后端授权、跨窗口事务、第二份正文；不另发包或强行单独插件化 |
| `files-view` | 普通/内容节点投影、筛选、多选、焦点、菜单和操作反馈；贡献既有 View/刷新入口 | 直接 fetch、全局 store、领域明细或模板、自己的文件事实与正文缓存 |
| `editor-support` / Editor Host | 编辑器选择、组/标签、模型绑定、视图状态、命令句柄 | 最终文件写盘、Project 全局关闭 |
| 宿主已有能力 | Project/身份绑定、命令、View、Storage、确认/输入/通知/进度及环境剪贴板 | 把运行时小内核变成理解文件/角色的万能容器 |

调用方向：`files-view → 文件查询接口 / 文档打开接口 / 资源操作协调`；协调模块消费文档会话与 Files，后端 Files 只依赖 Project 授予、平台文件及其数据合同，不反向调用浏览器文档会话。关闭 View 只释放本实例订阅；工作面负责文档/视图，Project owner 才能关闭共享后端代次。基础浏览不依赖 World/Plot/Agent 激活。

浏览器与服务端服务对象不跨进程 DI。Files 插件可以提供同位置服务；网络接口仍由宿主适配。Project opening 的索引/History 资源先沿现有模块工厂建立，对外 Files 等精确 ready 绑定，避免 Files 与 Project 相互等待。受信内置代码的依赖约束不是恶意代码沙箱。

## 接口与通信设计

沿用 `/api/workspace-files/*` 的单一入口族，复用请求与 SSE 分工；新增复制/批量能力需在同一协议族明确输入、结果与授权，不声称现有 API 已覆盖它们。传输选择不泄漏到面板；不存在“注册服务便自动生成网络 API”的机制。当前事实见 [树请求](../../app/stores/novel-ide.ts)、[事件订阅](../../app/composables/useWorkspaceFileEvents.ts) 与 [插件服务合同](../../runtime/plugins/contracts.ts)。

| 接口接缝 | 输入 | 输出与必须消除的歧义 |
|---|---|---|
| 工作区文件查询 | 已签发绑定、根内资源标识、取消信号 | 原始目录项/树快照、元信息、可执行能力、版本；完整性与失败不能伪装为空树；不按 UI 模式剔除 `index.md` |
| 文件读取/条件保存 | 资源身份、预期版本/现有磁盘基线、内容 | 内容及确认版本，或冲突/访问拒绝/失效；确认不覆盖保存期间的新输入 |
| 变更订阅 | 精确绑定与已有快照版本 | 变更/失效通知、连接状态；断线重连后先重新确认绑定并刷新快照，不能假设从未漏事件；不承诺逐条可靠重放 |
| 文件操作 | 固定源列表、目标目录/名称、操作种类及明确冲突意图 | 操作关联及逐项源/目标/结果；完成、拒绝、取消、未执行、部分完成、结果未知不能混成布尔值；字段命名在实现时沿现有协议确定，不重开已批准的结果语义 |
| 文档打开 | 真实资源标识、目标组、preview/permanent 意图 | 正确文档 ready、失败或被新意图取代；内容节点先映射真实 `index.md`，普通目录不进入编辑器 |
| 面板受控面 | 两种呈现的派生模型、选择/展开/焦点、操作与连接状态 | 选择/打开/刷新/路径操作意图；用户目标按触发时固定，不在异步完成时重读“当前选中” |

旧的树快照缓存、Project 代次和正文缓冲复用，不平行创建新事实。Files 快照必须能支撑普通模式展示真实目录项；内容模式隐藏是前端投影，不是服务端过滤或迁移文件。

**操作协调建议**：操作前结算当前输入、校验源和目标，必要时协商 dirty；提交到后端后根据明确结果重绑定文档、标签与树。移动失败不恢复整份历史 store 快照覆盖期间新输入；同一路径被删除再创建不能继承旧写入资格。预检不是锁，后端提交仍需重验。外部进程/另一窗口的操作通过文件变更与条件保存暴露为冲突，本窗口不能替其它窗口确认丢弃内容。

保留 `nbook.files`、`nbook.view.files`、`nbook.view.refresh-files` 和 `workbench.files` 的既有身份与恢复入口。命令、菜单和拖动完成应共用操作实现；不将每次光标/拖动中间态命令化。新命令 id/来源仍须走现有词表与校验，不因“内置插件”就绕过命令合同。

### 创建空白正文与既有校验

静态核对：[创建文件路由](../../server/api/workspace-files/create-file.post.ts) 的可选正文经 [tracked 包装](../../server/workspace-files/tracked-workspace-files.ts) 到 [文件写入](../../server/workspace-files/workspace-files.ts)；`createWorkspaceFile` 写入 `content ?? ""`，没有强制 frontmatter schema。`createWorkspaceContentIssues` 另行返回格式诊断，不是这个创建链的写入门禁。因此空白 `index.md` 无需取消现有保护或改变内容格式；它仍可能出现缺少领域字段的诊断，不能声称已创建完整领域节点。该结论来自源码核对，不是本轮运行实验。

普通模式不改变服务器许可结果；路径/Storage 边界、既有目标拒绝与格式诊断保留。首版只创建基础正文，不自动补齐领域模板，不运行修复或迁移。

### 协议与协调接缝

服务端不依赖 UI 确认才能执行所有合法 API 调用；确认针对本窗口用户意图，授权与数据保护由服务端独立守住。网络超时、取消和断线不能证明写操作未执行；先核对现状再提供重试，不为本片顺便引入万能自动重试或通用 RPC。

协议建议：读取返回 `{resource, content, version}`，树快照返回 `{binding, revision, entries, issues}`；操作请求固定 `{binding, kind, sources, destination, conditions}`，结果包含逐项 `source/target/status/reason` 与需重读的受影响路径。这是内部接缝草案，不是现有 DTO 或公开 SDK 声明；`version/conditions` 必须映射到真实可校验的既有基线，不能自造一个前端 revision 冒充服务端锁。

批量并发建议：同一源的重复提交在未结算时不再接纳，剪切不得同时粘贴到两个目标；彼此独立的操作无需全局串行。复制目录不承诺跨文件一致快照，复制过程中检测到源变化应报告而不声称整棵树为同一时刻；移动源不得先删除再假报目标已完成。遇到控制文件、不可访问子项或链接时，沿原保护拒绝/报告，不能因为父目录可见就扩大授予。部分结果只包含有权披露的路径，不泄漏拒绝根外的绝对位置。

外部文本引用和 Markdown 链接不随普通文件操作自动重写；现有引用校验仍有效，失效引用需要可诊断，不能把“文件移动成功”描述成“所有引用已修复”。这不改变内容格式，也不引入领域重构器。

## 切换性能：分开文件、模型和控件的寿命

历史需求已定位到 [Issue #128：降低 Novel IDE 文件打开的可感知延迟](https://github.com/notnotype/neuro-book/issues/128)：从左侧树点击到正文出现约一秒是开发者报告，不是本轮测量。其验收要求可复测的冷开/热开基线、热开普通 Markdown 不再出现约一秒空等，以及连续切换不串正文、不丢编辑与恢复状态。本设计沿用这些要求；下述生命周期问题是待采样的候选原因，不提前认定瓶颈。

已读当前 [novel-ide.ts](../../app/stores/novel-ide.ts)：`activateEditableWorkspaceFile` 对已缓存正文直接激活标签，`findWorkspaceNode` 复用树内元信息；已有工作面代次、逐组激活序号、文档身份与内容修订。不能把旧调研里的“每次重新请求”当当前事实，也不应再增加一份平行缓存。

[VS Code 编辑器研究](../research/vscode/06-editor-architecture.md) 的有效借鉴是 `EditorInput / model reference / EditorPane / control.setModel` 分层，不是把整套 VS Code 装配搬入产品。固定提交中的 [TextResourceEditorInput](https://github.com/microsoft/vscode/blob/a5b500951314efd502d07465bd138dfbd714a960/src/vs/workbench/common/editor/textResourceEditorInput.ts) 缓存模型引用、释放时归还；[AbstractTextResourceEditor](https://github.com/microsoft/vscode/blob/a5b500951314efd502d07465bd138dfbd714a960/src/vs/workbench/browser/parts/editor/textResourceEditor.ts) 等待解析后检查取消、绑定模型并恢复视图。这是所有权与绑定方式的源码证据，不是 NeuroBook 的性能数据。建议目标：同组同类型编辑器的控件可复用；切文件切换模型并恢复视图状态；文档模型的保留与最后引用释放由文档/编辑支持 owner 负责，不能由一次组件离场决定正文寿命。

需要明确保持的行为：

- 热切换指同一有效绑定下、已加载且仍有打开引用的文档之间切换：只取得已有正文/模型并绑定视图，无失效事件时不为 A→B→A 重读 A，也不因路径 key 每次销毁重建同类重控件。单击替换 preview 与已打开 permanent 标签往返分开验收，前者可能结束旧文档最后引用，不能偷换成同一种缓存命中率。
- 冷打开读取元信息/正文；同一绑定、同一文件的并发读取合并。一个等待者离开不取消其他编辑组仍需要的读取；迟到结果不能抢当前组焦点或发布到新 Project 代次。
- 光标、滚动、选区按视图/编辑组保存，不能被同文件另一组覆盖。未保存正文保持单一 authority；模型复用不得绕开现有 `accepted/conflict/stale` 输入回执。首期推荐保留现有跨组独立撤销语义：正文由文档会话共享，Monaco 模型按文档身份 + 编辑组/编辑器类型管理引用，控件按组复用；不直接共享同一个 Monaco model 来隐式合并两组撤销栈。对同一视图 A→B→A，保留 A 的模型/撤销/视图状态；外部或兄弟视图更新继续按现行合同同步并重设对应视图历史。若以后要共享文档级撤销，另作产品取舍。
- Markdown 源码和富文本分别处理：Monaco 的模型切换不能直接当作 Tiptap 的复用方案。富文本需要保留对应文档/视图的编辑状态与历史，在控件重新绑定时不得仅从 Markdown 重建而丢撤销；具体状态挂接适配先按 Tiptap 当前公开接口验证。富文本解析、源/富文本同步、待结算输入和撤销状态单独计量；图片/只读等编辑器不强行套文本模型。
- 保留打开文档所需的模型；dirty、有未决冲突、在途保存的模型不得按普通缓存淘汰。最后引用关闭后的干净模型可释放；不预设任意 LRU 容量、不永久挂载所有文件的 DOM、不预读整个项目。若测量证明需要预览文件短期复用，再定义有界策略与上限。
- 文件外部修改、删除、改名和 Project 关闭重开都要使相应缓存身份或版本失效。dirty 不被远端快照覆盖，保存继续携带现有 `baseContent` / `expectedMtimeMs` 并显示冲突；保存确认只确认提交时内容，不清掉保存期间的新输入。
- 复用的是控件，不复用旧目标的写入资格。每次绑定仍签发新的绑定 token，携带精确文档身份/代次；旧异步 ready、计时输入、菜单和命令句柄失效。先让旧输入结算，再解绑旧模型、绑定目标；目标失败不销毁未结算候选，不把旧正文标成新文件。取消/失败是显式结果，不以空白编辑器冒充打开成功。

当前证据：[EditorViewHost](../../app/components/editor-workbench/EditorViewHost.vue) 在文档 target 改变时清空实例；其[合同](../../app/components/editor-workbench/EditorViewHost.md)只保留同文档内不同编辑视图。[MonacoCodeEditor](../../app/components/editor-workbench/MonacoCodeEditor.md)明确每实例独占 model，兄弟视图通过权威正文同步且不共用撤销。这支持优先测量“已有正文但重新创建视图/模型”的成本，不足以证明它是总延迟的最大部分。

备选方案：整份文件面板仅套插件入口，改动小但隐藏依赖和编辑重建仍在，不能满足本轮目的；每个文件永久保留整棵编辑器 DOM 能减少部分重挂，但内存/监听随访问文件增长，故不选作默认策略；同 URI 共享一个 Monaco model 省模型内存，却改变现有跨组撤销与冲突语义，首期不采用。推荐复用每组控件，独立管理有明确 owner 的文档缓冲与视图模型；具体保留范围由真实打开引用及测量约束。

上述是待验证设计，不是当前性能结论。树派生/排序、DOM 渲染、请求瀑布、Monaco 重建、Markdown 解析各自先测量，按实际占比修改；不以一般性的“缓存/虚拟列表/防抖”替代定位。

## 主页面与 Lab 验收分工

首版必须在主页面左侧完成真实文件访问、两种模式、批量操作、打开编辑与保存；不能只在 Lab 使用内存替身便宣称完成。Lab 展示的仍是主页面使用的同一完整基础面板，不是另一棵简化文件树；“完整”以本次已批准首版为准，不再包含角色/世界书等领域明细与模板。

产品与 Lab 共用受控组件、Files 客户端核心与控制逻辑，仅在传输/持久化/宿主能力接缝替换依赖。场景拥有内存文件、局部文档/命令及模型引用，真实维护内容/版本和变更，不以 `return ok` 伪造写入；切场景释放。辅助数据/延迟/失败控制进入 `LabFixtureControls`，画布只显示被测组件。Lab 不访问当前 Project，不发产品 `/api/` 请求，不恢复常驻产品宿主。

建议矩阵：两模式的同一数据、根正文/空目录/普通文件/含附件内容目录，多选与父子重叠、同名冲突、部分复制、剪切后源失效、dirty 与在途保存、断线后刷新、快速 A/B 切换、窄面板键盘/焦点、场景离开清理。真实磁盘、鉴权、SSE、Project 关闭重开与多窗口、History 仍在隔离产品宿主验证；运行浏览器评测需独立授权。

## 性能验收与实施顺序

用户关于迟缓的观察是问题依据；当前没有新测量，不能给出“已定位主因”或提升百分比。实施的第一步建立隔离数据基线，记录浏览器/机器、构建模式、固定文件集合和大小；冷打开、热切换、源码、富文本、单/多编辑组分组统计。至少记录点击→反馈、点击→正确正文绘制且可编辑的 p50/p95、请求次数、模型/控件创建次数及往返后的保留资源；主线程任务和解析耗时仅用于归因。相同条件重复运行并保留波动范围，开发热更新首次构建不混进稳态数据。

验收目标不止“没有变慢”：沿 Issue #128，热开普通 Markdown 不再出现约一秒可感知空等；热切换消除无必要读取与重控件重建，端到端改善须超过基线波动。绝对时延预算根据固定样本基线确定并在实施前冻结，不在未知设备/文档规模上随意承诺毫秒数，也不能把仅有统计改善但仍约一秒空等判为通过。持久保存、冲突与撤销不能退化来换速度，Lab 内存测量不替代产品 HTTP 路径的结果。

本次只收口设计/规范并起草第二版，不创建下一批实施 Task。未来实施先固定样本与性能基线，在主页面贯通读树→打开→编辑→条件保存；再接统一文件操作协调与批量行为，同步用 Lab 验证受控面板；最终移交启动/关闭责任并清除旧调用入口与已批准移除的领域 UI 耦合。不是先搬完所有应用服务再接一棵树，也不保留仅在 Lab 生效的副本。
