# Agent 对话视图重做提案

状态：accepted（2026-09-28 起草并由开发者接受）

已批准的行为写入 [`ui.agent-conversation-view`](../../../../docs/specs/ui/agent-conversation-view.md) 与 [`ui.component-lab.timeline`](../../../../docs/specs/ui/component-lab-timeline.md)，两者均为 planned；实现以 Spec 为准，本提案保留取舍依据。

关联：执行记录见 Work [w00019](../../../../.agents/works/w00019-agent-conversation-view/README.md)；新视图将来作为[应用运行时与内置插件架构](application-runtime-and-plugins.md)中 `agent-ui` 功能插件的视图部分；数据层与后端的问题另见[数据层后续提案](agent-session-data-layer.md)。

## 问题

右侧 Agent 面板是用户和 Agent 协作的主界面，现在有三类问题。

**用户看得到的问题。** 消息流里一条消息对应一个气泡，每个气泡都带一行头部（头像、角色、时间、常驻的 3 到 4 个操作图标）；ReAct 过程中的每一步也各自重复这一整套，再加上思考行和用量页脚。在 390 宽的侧栏里，一问一答约占 280px，一屏只能看到两轮多；一个 12 步、每步带思考的 ReAct 过程约占 1500px（按 Lab 实测节点高度估算）。长对话里很难找到结论。system reminder 这类写给模型看的内容也直接显示出来。顶栏挤了 7 个图标按钮，标题被截成“第一…”这样读不出来。

**维护者看得到的问题。** 目录约 3 万行，其中宿主 `AgentChatSurface.vue` 4494 行。视图入口 `AgentSidebarView` 把 12 组 props 和约 70 个事件原样透传给子组件；同一字段在多组里重复（`sessionId` 出现在 6 组）。消息分派经过 4 个文件，有两套工具注册表，其中一套全仓无人引用。同一类块用了 Bubble、Card、Node、Prompt、Panel 五种后缀。卡片外壳各自手写，圆角、底色、边框都不统一。

**扩展者看得到的问题。** 新增一种工具的专用渲染要改分派组件；顶栏按钮、面板、输入框上方的待处理区、状态栏都写死在模板里。插件没有地方登记。

## 目标与非目标

### 目标

1. 在 `packages/neuro-book/app/components/agent/` 下重新实现一套纯视图组件，顶层组件为 `AgentConversationView`。参考旧代码的行为，不继承旧结构。
2. 视图与外部之间只走 props 和事件：渲染器统一接收节点和只读上下文（下称 ctx），用户意图合并为一个 action 事件，扩展点注册表作为 prop 显式传入。
3. 消息流改为分轮折叠视图（D3），保留逐条消息的原始视图作为调试模式。
4. 卡片与气泡的结构和视觉一起统一（D4）。
5. 提供 D2 列出的扩展点，内置功能与将来的插件走同一套登记方式。
6. Component Lab 覆盖全部状态，新增时间线回放能力和长对话场景（D5）。
7. 功能基线：[附录 A](#附录-a功能基线) 的 61 项全部保留，交互方式可以按本提案调整。

### 非目标

- 不改后端接口，不写后端规范。
- 不重写会话模型层和数据层，相关问题记入[数据层后续提案](agent-session-data-layer.md)。
- 不接入主页面，只以 Lab 验收；开发期间主页面的 Agent 面板不可用可以接受。旧目录 `app/components/novel-ide/agent/` 本次不修改也不删除。
- 不含 Inline AI。
- 左侧会话栏 `AgentModeSessionSidebar` 和 Trace Viewer 不重做，只保证各自的 Lab fixture 可用。
- 不实现插件加载。只提供注册表和稳定合同，插件入口等 w00017 定型后再接。

## 方案、备选方案和取舍

### D1：视图合同

**方案：** `AgentConversationView` 是纯受控视图，组件规范下的能力标签只有 `state:local`（以及弹窗必需的 `env:portal`）。

```ts
type AgentConversationViewProps = {
    /** 只读领域状态：会话、轮次与消息、运行状态、输入框所需数据、各面板数据。 */
    ctx: AgentConversationContext;
    /** 扩展点注册表，见 D2；内置功能也登记在这里。 */
    registry: AgentViewRegistry;
    /** 消息流视图模式；缺省为分轮视图。 */
    viewMode?: "turns" | "raw";
};

type AgentConversationViewEmits = {
    /** 所有用户意图都从这里发出，由宿主执行。 */
    (e: "action", action: AgentViewAction): void;
    (e: "update:viewMode", mode: "turns" | "raw"): void;
};
```

- action 是一个按 `type` 区分的联合类型，命名采用“对象.动作”的形式，例如 `message.copy`、`message.retry`、`branch.switch`、`turn.stop`、`composer.submit`、`session.create`、`attachments.search`。插件登记的动作使用带插件前缀的 `type`，宿主按前缀路由。
- **状态归属规则：** 只影响界面呈现的状态留在视图内部，例如弹窗开关、面板展开、轮次折叠、输入框里尚未发送的文字；需要持久化、需要调接口或影响会话数据的，一律通过 action 上报，结果再经 ctx 回来。
- 渲染器（消息、步骤、工具、面板）统一接收 `node`（或各自的数据）和 ctx 的只读切片，只发出 action，不直接读 store、不自己发请求、不自己计时轮询。Workflow 的实时进度由 ctx 提供。
- 新目录不 import 旧目录 `app/components/novel-ide/agent/` 的任何模块。需要复用的纯逻辑（例如 Markdown 渲染、diff 展示）移植进新目录，这样将来删除旧目录时不会牵连新代码。
- Markdown 的 HTML 消毒函数通过 ctx 或注册表传入，不再用字符串 key 做 provide。

**备选：**
- 类型化的 provide/inject 上下文：模板最干净，但按[组件规范](../../../../docs/standards/code/components.md)，inject 属于隐藏通道，所有区段容器都会计入耦合，Lab 还要额外提供假上下文。放弃。
- 按会话隔离的 Pinia store：样板最少，但组件会变成读 store 的领域视图，和现行规范偏离最大，也违背本次“只做视图”的范围。放弃。

### D2：扩展点与注册表

**方案：** 注册表作为 prop 显式传入 `AgentConversationView`。内置功能通过同一个注册表登记；Lab fixture 在本地创建注册表，这和 w00017 提案 D5“Lab 不建产品级注册表，依赖由局部显式适配满足”一致。每个登记项至少包含 `id`、排序值和可选的显示条件（以 ctx 为输入）。

| 扩展点 | 登记内容 | 本次 |
|---|---|---|
| 工具渲染器（按工具名） | 完整卡片或单行样式；折叠时的摘要文案；图标；**类别**（探查、修改、交互、其他，决定分组与折叠后是否露出，见 D3）；折叠后在轮次摘要里露出什么 | 实现 |
| 条目渲染器（按条目类型和来源） | 系统条目的各种来源、插件自定义条目 | 实现 |
| 消息操作 | 复制、重试、分支之外的新操作，例如“插入到编辑器” | 实现 |
| 顶栏动作与面板 | 按钮或菜单项，以及点开后的面板；窄屏时多出的按钮收进溢出菜单 | 实现 |
| 输入框上方的待处理区 | Workflow 待处理、文件变更、排队消息之外的新条目 | 实现 |
| 状态栏条目 | 新的指标芯片 | 实现 |
| 输入框 | 触发菜单来源（`@`、`$`、`/` 或新字符）、slash 命令的菜单项、工具栏按钮 | 定接口；命令执行属于数据层，视图只负责菜单和发出 action |
| Markdown 扩展 | 引用协议（如 `@chapter://`）的 chip 渲染与点击、代码块渲染器 | 预留接口 |
| 空状态起手提示 | 提示词来源 | 预留接口 |

注册表的具体形状（显示条件用函数还是声明式表达、插件如何批量登记与撤销）依赖 w00017 的插件协议，本次按内置需要定最小形状，写进 Spec 时标明哪些部分对插件稳定。

**备选：** 继续用静态表加 `v-if` 分派。无法支持插件，新增工具仍要改多处，放弃。

### D3：消息流改为分轮折叠视图

**层级：**

```text
对话
└─ 轮次（turn）= 用户消息 + 过程 + 最终回复
   └─ 过程（transcript）= 中间的思考、说明文字、工具调用、系统提醒
      └─ 工具组 = 连续的同类工具调用
```

**轮次边界：** 从一条用户消息开始，到下一条非 steer 用户消息之前结束。中途提问后继续运行（新的 invoke）、运行中插入的 steer 消息，都算在同一轮里。分轮规则属于视图层的纯逻辑，由新组件目录提供；数据层只需提供按顺序排列的消息和当前运行状态。

**折叠后仍然可见：**
- 用户消息和最终回复（本轮最后一条带正文的 assistant 消息，且之后没有工具调用）；
- 一行摘要，例如“用时 2 分 14 秒 · 12 步 · 读 8 个文件 · 改 2 个文件 · 1.2 万 tokens”，点击展开；
- 关键结果：改动过的文件做成 chip（点开看 diff），错误，仍在后台运行的 Workflow。每类工具在注册时声明自己折叠后露出什么。

**自动展开与折叠：**

| 轮次状态 | 默认 |
|---|---|
| 运行中 | 展开，自动吸底 |
| 正常结束 | 自动折叠。用户在运行中手动展开或折叠过时，保持用户的选择；用户正在往上阅读时，以最终回复为锚点保持阅读位置，不让页面跳动 |
| 等待用户回答或审批 | 保持展开 |
| 出错或被停止 | 保持展开，方便看清上下文再决定是否重试 |
| 从历史加载 | 折叠 |

**过程内部：**
- 改用时间线样式（左侧竖线加圆点），每步默认一行，不再一步一张卡片。
- 连续工具调用按渲染器声明的类别分组：

  | 类别 | 例子 | 处理 |
  |---|---|---|
  | 探查 | read、grep、list、检索设定 | 连续的合成一行，如“读取 5 个文件，搜索 2 次”，点开看每一项 |
  | 修改 | write、edit、patch | 不并入探查组；每个改动单独一行紧凑显示，如“chapter-01.md +12 −3”，点开看 diff |
  | 交互 | 提问、模式切换审批 | 不合并，独立卡片 |
  | 其他 | 任务清单、Workflow | 不合并，独立卡片 |

- Agent 在工具之间说的话显示为一行淡色说明文字，同时隔开分组。
- 分组在运行中保持折叠，避免内容跳动；组头实时显示当前动作，例如“正在读取 chapter-3.md…”。组内有工具出错时，出错的那一项自动露出来。
- 思考折叠为一行摘要。
- system reminder 默认隐藏，只留“3 条系统提醒”这样的计数标记，点开可看；上下文压缩、分支摘要等结构性提示始终以分隔线显示。

**其他省高度的措施：** 消息操作图标改为悬停或聚焦时显示（触屏下提供等价入口）；时间戳改为悬停提示；用量合并到轮次摘要，不再每步一个页脚。按实测节点高度估算，前述 12 步轮次折叠后约剩 40px 的摘要行，展开并分组后约 200px。

**原始视图：** 保留一条消息一个气泡的逐条视图，作为调试模式，通过 `viewMode` 切换。

**备选：**
- 按一次 invoke 划分过程：边界和底层一致，但提问后继续运行会被切成几段。放弃。
- 连续工具全部合并：最省高度，但文件改动会被藏进组里。放弃。
- 不合并工具，只靠时间线样式压缩：实现最简单，长过程仍然很长。放弃。

### D4：卡片与视觉统一

**方案：**
- 定义少量共享外壳，覆盖消息正文、过程步骤行、独立卡片、面板和待处理区条目；圆角、底色、边框、内边距统一按 [nb-ui 设计语言](../../../nb-ui/docs/design-language.md)和 [UI 开发规范](../../../nb-ui/docs/ui-development-spec.md)的 Surface 分级取值，渲染器只填内容。
- 卡片最多嵌套一层，Workflow 卡片不再三层套框。
- 顶栏只保留标题和最常用的一两个动作，其余收进溢出菜单，保证 390 宽时标题可读。
- “投递状态未知”改为带文字说明的内联提示，写明可能已经发送、重发可能重复。
- 视觉方案先在 Lab 里做出对比，由开发者确认后再推广到全部渲染器。

**命名规则：** 一个概念只用一个后缀。

| 后缀 | 含义 |
|---|---|
| `View` | 顶层视图，只有 `AgentConversationView` |
| `Message` | 用户或 assistant 的消息正文 |
| `Turn` / `Transcript` | 轮次与轮次内的过程 |
| `Step` / `StepGroup` | 过程里的一步和一组 |
| `Card` | 有边框的独立块，例如提问、Workflow |
| `Panel` / `Dialog` / `Tray` / `Bar` | 面板、弹窗、输入框上方待处理区、顶栏和状态栏 |

组件不再使用 `Bubble` 和 `Node` 作为后缀。

### D5：Component Lab

**方案：**
- **时间线回放：** Lab 提供通用的时间线控件，支持播放、暂停、单步、倍速、拖动进度和重置，使用虚拟时钟：跳到第 N 步时先重置、再同步应用前 N 步，结果可复现，也方便截图对比。回放脚本是仓库里的固定输入，内容是一串按时间排列的 ctx 变更，例如“向某步追加一段文字”“新增一次工具调用”“运行状态改为等待”。本次不回放服务端事件，服务端事件回放等以后有了新的会话模型层再加。
- 这符合 [Component Lab 规范](../../../../docs/specs/ui/component-lab.md)中“固定输入、不访问网络、不伪造业务成功结果”的要求。该规范已是 `implemented`，而时间线回放尚未实现，按 Spec 规则另立一份 planned Spec，不混入现有规范。
- **新增场景：** 多轮长对话（含 12 步以上的 ReAct、系统提醒、上下文压缩分隔线）、运行中的轮次、等待回答的轮次、出错的轮次、历史分页、原始视图，以及上述场景在 390 宽下的表现。
- 旧目录的 fixture 保持不变；新组件各自登记新的 fixture。

**备选：**
- Lab 里起一个假的 SSE 接口：需要加服务端路由，违反本次不动后端的范围和 Lab 不访问网络的规定。放弃。
- 用 Service Worker 在浏览器里拦截请求：要新增依赖，而且只多验证了 SSE 文本解析，这部分已有单元测试。放弃。

## 数据、接口、安全、迁移、发布与回滚影响

- **数据与接口：** 后端接口和持久化格式都不变。新的视图合同（ctx、action、注册表）是前端内部接口，将来的数据层按它提供数据、执行动作。
- **安全：** Markdown 的 HTML 消毒必须保留，消毒函数由外部显式传入；视图不直接访问浏览器存储。
- **迁移：** 旧目录保持原样，主页面继续引用旧组件。新组件切入主页面、删除旧目录，放到数据层后续提案对应的 Work 中完成。本次不改 `AgentChatSurface.vue`，[ADR 0015](../adr/0015-architecture-boundaries-and-deferred-structure.md) 第 4 节暂不修订。
- **发布：** 新组件不被任何页面引用；Lab 只在源码开发环境存在。是否进入产物以构建结果为准，验收时检查。
- **回滚：** 删除新目录和新增的 fixture 即可。

  - 状态：空、未选择会话、加载中、运行中、等待回答、出错、被停止、归档只读、不可用；分轮视图的折叠规则与原始视图；
  - 副作用：无（全部通过 action 交给宿主）；
  - 失败：ctx 数据缺失或不完整时的降级显示；
  - 验收：Lab 场景清单与 390 宽检查。
- **新增** `docs/specs/ui/component-lab-timeline.md`，`status: planned`，capability `ui.component-lab.timeline`：时间线回放的控件、虚拟时钟、脚本格式与确定性要求。现有 `ui.component-lab` 已是 implemented，不在其中混入未实现的能力。
