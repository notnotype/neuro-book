# JsonViewer

在界面里展示一段结构化数据的 JSON 查看器，默认只读。产品里到处需要「把一个对象摊开给人看」——工具调用的入参出参、工作流的中间结果、调试面板里的原始记录，目前这些位置都用它。基于 `json-editor-vue`（`vanilla-jsoneditor` 的 Vue 封装，只有这一个依赖，两个名字指的是同一套东西）。

三个特点是它和直接扔一段 `<pre>` 的区别：

- **同一份数据三种看法**，文本、树形、表格可以互切，不用换组件。
- **高度可以自己收着**。给了 `maxHeight` 时内容再长也在内部滚动，不把外层撑开；传 `0` 就没有这层保护，见「注意事项」。
- **传字符串时保留用户的原始输入**，哪怕 JSON 还没写完、暂时不合法也不会被吞掉或重排。

## 布局

由工具栏和编辑器主体两块组成，工具栏在上。工具栏分左右两组：左组是三个模式按钮，成组显示在一个带边框和浅底色的分段容器内，同一时刻只有一个处于选中态；右组是复制、展开全部、折叠全部三个独立的动作按钮。工具栏可以整体关闭。

`maxHeight` 约束的是**整个组件**，工具栏也算在内，不是只约束内容区。所以内容区实际可见高度是 `maxHeight` 减去工具栏高度。内容超出后由编辑器自己在内部滚动，不把外层撑高。

`navigationBar` 与 `statusBar` 打开时位于编辑器主体内部，同样算进 `maxHeight`，会进一步压缩内容区。

工具栏高度固定，切换模式或数据变化都不改变它的尺寸，因此不会引起布局位移。

窄屏下结构不变。工具栏的六个按钮在一行内排布，均为紧凑尺寸。

## 交互

- 点击模式按钮切换文本、树形、表格三种查看方式。当前模式的按钮呈选中态，且始终有且只有一个处于选中态；点击已选中的按钮不产生变化，编辑器不重新挂载。
- 点击复制把当前 `value` 写入系统剪贴板。字符串原样复制，其它值用两个空格缩进格式化后复制，键序不变。内容为空时不做任何事，也不留任何提示。复制失败只在控制台留一条警告，界面不提示；复制成功同样没有任何界面反馈。
- 点击展开全部或折叠全部递归作用于所有层级的节点，不是只作用于当前可见的一层。这两个动作只在树形模式下可用，其它模式下按钮为禁用态（当前实现见「已知偏差」）。
- 六个按钮都有可访问名称，与鼠标悬停提示一致。

键盘：

- 工具栏有 **4 个 Tab 停靠点**，不是 6 个：三个模式按钮合起来算一个（进入后由方向键在组内走），三个动作按钮各算一个。
- 焦点在模式组内时，方向键只**移动焦点**，不切换模式；切换要再按回车或空格。走到两端会绕回另一端。
- 动作按钮用回车或空格触发。所有按钮的焦点都有可见的聚焦环。
- 组件自己不注册任何快捷键。底层编辑器自带的快捷键见「上游边界」。

## 数据

```ts
/** 三种查看模式。取值与 vanilla-jsoneditor 的 Mode 一致。 */
type JsonViewerMode = "text" | "tree" | "table";

interface JsonViewerProps {
    /**
     * 要展示的值。任何能被 JSON.stringify 处理的值都可以，
     * 不限于对象、数组和字符串。必填。
     */
    value: unknown;

    /**
     * 模式。不是纯初始值——这个 prop 的值真正发生变化时会覆盖用户
     * 在工具栏里的选择；父组件重新渲染但值不变则不受影响。
     * 用户点工具栏只改内部状态，不回传父组件，没有 update:mode。
     */
    mode?: JsonViewerMode;      // 默认 "tree"

    /** 是否只读。只读时编辑器不接受输入，工具栏仍然可用。 */
    readOnly?: boolean;         // 默认 true

    /**
     * 是否显示**本组件的**工具栏。关掉后六个按钮都没有，只剩编辑器主体。
     * 底层编辑器自带的主菜单栏由本组件恒定关闭，这个 prop 与它同名但无关。
     */
    mainMenuBar?: boolean;      // 默认 true

    /** 是否显示编辑器自带的导航栏。 */
    navigationBar?: boolean;    // 默认 false

    /** 是否显示编辑器自带的状态栏。 */
    statusBar?: boolean;        // 默认 false

    /** 整个组件的最大高度，单位像素。0 表示不设上限。 */
    maxHeight?: number;         // 默认 300
}

interface JsonViewerEmits {
    /**
     * 编辑器内容变化时发出。只读时用户无法输入，因此默认配置下不会发出。
     * 传入 value 是字符串时，携带的是用户此刻的原始文本，
     * 可能是还没写完的非法 JSON——这是有意的，不做拦截也不做补全。
     */
    (e: "update:value", value: unknown): void;

    /**
     * 紧跟在 update:value 之后发出，报告这次的内容能否被解析。
     * 只做「能不能 JSON.parse」这一件事，不按任何 schema 校验。
     * 非字符串值与去掉空白后为空的字符串一律报告为无错。
     */
    (e: "validation-change", hasErrors: boolean): void;
}
```

组件不提供 slot，也不 expose 任何方法或属性。未声明的 attribute、`class` 与 `style` 按 Vue 默认行为落到根节点上。除此之外，外部只能通过上面这些 props 和 emits 与它交互。

用法上有一处会让人栽跟头，所以给一段示例：事件叫 `update:value` 而不是 `update:modelValue`，因此常规的 `v-model` 写法不报错但完全不生效。

```vue
<!-- 只读展示，交给父容器管高度 -->
<JsonViewer :value="payload" :max-height="0" />

<!-- 可编辑：必须写成 v-model:value，写 v-model 会静默失效 -->
<JsonViewer v-model:value="draft" :read-only="false" @validation-change="onInvalid" />
```

## 状态

- 默认：按 `mode` 呈现内容，工具栏可用。
- 只读：编辑器不接受输入，工具栏仍可切换模式与复制，两个事件都不会发出。
- 空数据：正常渲染空结构。复制动作在格式化结果为空串时不做任何事，也就是 `value` 为 `""` 或 `undefined` 时；`{}`、`[]`、`null`、`0` 都能正常复制。
- 非树形模式：展开与折叠按钮为禁用态，视觉变淡且不可点击（当前实现见「已知偏差」）。
- 出错：组件自身没有错误态。内容不合法只通过 `validation-change` 报给父组件，界面不变；复制失败只写控制台警告。

## 不支持

- 不支持按 schema 校验。`validation-change` 只回答「能不能解析」，不回答「结构对不对」。底层编辑器的校验器能力没有透出。
- 工具栏不提供搜索、跳转或按路径定位的入口。
- 不支持把用户选的模式告诉父组件，也不支持持久化模式或展开状态。没有 `update:mode` 也没有 expose，**使用方自己也拿不到用户当前选的是哪个模式**；每次挂载都回到 `mode` 指定的初始状态。要「记住上次的选择」得先给组件加事件。
- 不支持指定树形模式的初始展开层级，默认展开状态由底层编辑器决定。
- 不支持读取剪贴板，只写不读。
- 关掉工具栏后，复制、展开、折叠三个能力就没有任何入口了——没有 slot、没有 expose、没有对应事件。

## 上游边界

本组件承诺的只有：工具栏这六个按钮的行为、`maxHeight` 的高度约束、props 与 emits 的语义。**其余全部来自底层的 `json-editor-vue`，本组件既不改写也不承诺，升级底层库时可能变化。**

落在底层那边、本组件不作承诺的有：可编辑时的撤销、粘贴、节点拖拽、右键菜单；编辑器自带的快捷键（是否有搜索快捷键未核实）；树形模式的默认展开层级；导航栏与状态栏的内容和交互；校验器能力。要依赖这些行为，去查底层库的文档并自己实测，不要以本文档没提到就当作不存在。

**配色是例外，本组件负责。**底层编辑器的全套主题变量在这里被接到项目的配色角色上，因此换配色时它跟着变，包括明暗切换。两处兜底要知道：`--color-scheme` 与 `--overlay-bg` 是 nb-ui 配色契约自有的两个变量，产品自己的主题系统还没有，缺它们时分别退回「暗色」与「半透明黑遮罩」。字号是个例外中的例外，仍是写死的 11px。

## 注意事项

- **`maxHeight` 默认 300，不是不限制，而且它管的是整个组件。** 放进一个自己已经管好高度的容器时要显式传 `0`，否则内容会被截在 300 像素减去工具栏高度的位置，看起来像数据不全。这是使用中最容易踩的一处。反过来，传 `0` 之后组件不再自己设上限，高度完全由父容器的布局决定——「不把外层撑开」这个保证也随之失效，父容器必须自己管住高度。
- **父组件不要把 `mode` 当只读初始值。** 父组件每次真正改变 `mode` 都会覆盖用户当前的选择；反过来用户在工具栏切换不会通知父组件。想让模式跟着用户走，就不要在 `mode` 上绑一个会变的值。
- **复制的是 `value`，不是编辑器内部状态。** 只读场景两者一致。可编辑且用 `v-model:value` 绑定时也一致；不绑定而让用户改动只留在编辑器里，复制出来的会是父组件手上那份旧值。
- **传字符串和传对象是两条不同路径。** 传对象时组件按结构渲染；传字符串时按原始文本处理，用户的中间输入原样保留。同一处使用方混着传两种类型，行为会不一致。

## 隐藏通道理由

`env:clipboard`：复制按钮直接调用浏览器剪贴板接口。这个动作与被展示的内容强绑定，复制的文本需要按当前值的类型决定格式；交给宿主处理会让每个使用方都重复一遍同样的格式化逻辑。这条通道只往外写，写出去的就是父组件已经传进来、用户此刻看得见的那一份 `value`，组件不额外读取任何组件之外的数据。写出的内容本身可以是产品数据，这一条不构成对内容敏感性的判断。

## 已知偏差

- 展开全部与折叠全部的禁用条件与「交互」一节不符。实现中这两个按钮只在表格模式下禁用，文本模式下仍可点击，但点击不产生任何效果——展开与折叠是树形结构操作。文档写的是应当成立的行为，实现待订正。
- 内容不是合法 JSON 时切到树形或表格模式会发生什么，未核实：可能切换失败，也可能丢掉用户的中间输入。只读场景下遇不到，因为 `value` 由父组件提供。可编辑场景下依赖此行为前需要先实测。
- 表格模式对非同构数组的数据会呈现成什么样，未核实。
