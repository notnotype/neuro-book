# EventLogPanel

按时间倒序列出一串已经发生的事件。Lab 右栏的「事件」tab 用它显示被检视组件发出过哪些事件、每次带了什么。

**它只负责显示一个列表。**事件从哪来、什么时候记、记多少条，全部由使用方决定；本零件拿到一个数组就渲染，拿到空数组就显示空状态。

它和「用 `v-for` 铺一个列表」的区别只有一个：**每条事件的负载可以就地展开看，展开状态由它自己记着。**这是它存在的唯一理由，别的都可以在外面做。

仓库里没有同类物。产品里的通知列表 `NotificationCenter` 是给用户看的消息，会自动消失、有已读未读，与这里「一条不落地记下来给开发者看」不是一回事。

## 布局

一列条目，最新的在最上面。每条一行：

- 左边是**时间**，只到秒，等宽字体。
- 中间是**事件名**，一个芯片。
- 右边是**负载摘要**，一行以内，超出截断。

带负载的条目整行可点，点开在下面展开完整负载。展开的负载用 `JsonViewer` 的只读形态渲染。不带负载的条目不可点、没有展开箭头。

同一个事件连续发出多次时**不合并、不折叠**。「连着发了 30 次」本身就是要看的信息，合并掉就看不见了。

没有外框、没有内边距、没有背景，撑满给它的宽度。滚动由使用方在外面提供——列表会很长，谁提供滚动条决定滚动条出现在哪一层。

窄到 `390` 像素时时间与事件名仍在一行，负载摘要换到第二行。

## 交互

- 点带负载的条目展开或收起它的负载。可以同时展开多条，展开一条不会收起别的。
- 展开状态按条目 `id` 记，列表新增条目不影响已经展开的那些。
- 「清空」不由本零件提供，见「不支持」。

键盘：

- 可展开的条目能 Tab 聚焦，有可见聚焦环，回车或空格展开收起。
- 不可展开的条目不接收焦点——聚焦一个按了没反应的东西，对读屏用户是噪音。
- 条目的无障碍状态报告展开与否。

**列表新增条目时不自动滚动、不移动焦点。**新的在最上面，正在看下面某条的人不该被拽走。

## 数据

```ts
interface LabEventEntry {
    /** 条目标识，展开状态按它记。使用方保证同一列表内不重复。 */
    id: string;

    /** 事件名，例如 "update:collapsed"。 */
    name: string;

    /** 发生时间。由使用方记录，本零件不取当前时间。 */
    at: Date;

    /**
     * 事件负载。`undefined` 表示这个事件没有负载，条目不可展开。
     * 注意 `undefined` 与 `null` 不同：发出了一个值而这个值是 null，
     * 属于有负载，可以展开。
     */
    payload?: unknown;
}

interface EventLogPanelProps {
    /**
     * 要显示的事件，**已经按时间倒序排好**。本零件不排序——
     * 它不知道使用方是按发生顺序还是别的顺序在记。
     */
    entries: LabEventEntry[];

    /** 一条都没有时显示的文字。 */
    emptyText?: string;   // 默认 "还没有事件"
}
```

没有事件、没有 slot、不 expose 任何方法或属性。未声明的 attribute、`class` 与 `style` 按 Vue 默认行为落到根节点上。

没有能力标签：不读写 store、不访问浏览器存储、不发请求、不注册全局监听。展开状态是组件内部的普通响应式变量，随组件销毁而丢失，不伸出组件之外，因此也不算 `state:local` 那种需要说明的隐藏通道——它就是一个受用户点击直接控制的显示开关。

## 状态

- **默认**：按传入顺序列出条目。
- **空**：`entries` 为空数组时显示 `emptyText`，居中、次要色。
- **展开**：被展开的条目下方显示完整负载。

禁用、只读、加载中、出错四种状态本零件都没有：它是个显示列表；数据是同步传进来的，没有加载中；它不发起任何会失败的动作。

## 不支持

- **不提供「清空」按钮。**清空是改数据，数据在使用方手里。使用方在自己的工具栏里放清空按钮，把数组清掉即可。
- **不限制条数、不做裁剪。**要只留最近 200 条，由使用方在 push 的时候裁。零件替使用方丢数据是危险的默认行为。
- **不记时间、不生成 id。**两者都由使用方提供，因为只有使用方知道该用哪个时钟、id 该怎么编。
- **不排序、不合并、不过滤、不搜索。**列表给什么就显示什么。按事件名过滤这类能力，等真的有几百条时再说。
- **不自动滚动到最新。**见「交互」最后一条。
- **不区分事件的严重程度。**没有错误、警告这些级别——组件发出的事件本来就没有级别之分，硬加一层是凭空发明概念。

## 注意事项

- **`entries` 必须已经排好序。**传入顺序就是显示顺序。传了正序进来，界面上最新的会在最下面，本零件不会纠正。
- **`payload` 为 `undefined` 的条目不可展开**，为 `null` 的可以。使用方转发事件时如果把「没有负载」写成了 `null`，界面上会多出一个展开后只有 `null` 的条目。
- **负载里的函数、DOM 节点、循环引用显示不出来。**负载交给 `JsonViewer`，它按 JSON 的规则处理，处理不了的会显示成空或报错在它自己那一层。组件事件的负载通常是普通值，真遇到这种负载请在使用方那边先转成能看的形式。
- **`id` 重复会让展开状态串台。**展开一条时另一条跟着展开，就是这个原因。
