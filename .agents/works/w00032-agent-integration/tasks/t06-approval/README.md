# 审批、提问与 Agent 模式

## 目标与范围

定工具审批（等级、模式、持久化与跨重启应答）、Agent 向用户提问，以及 Agent 模式（normal、discuss、plan）与只读模式下哪些工具算写。

来源：需求 9；清单外第 8 项（[报告](../t01-survey/artifacts/report/index.html)）。

合同：本 Task 只做设计讨论，行为合同未变；定稿后在计划里写明改哪些 Spec。

## 要讨论的问题

- 等级（读、写、执行）与审批模式；用户按工具设 allow、deny、prompt；审批模型（让另一个模型先判）。
- 等待：会话多一个“等用户”的状态；持久化与重启后应答（分支已做）。
- 提问：ask 的形状（标题、问题、选项、自由输入、表单），用 nb-form 的展示态。
- Agent 模式的语义；只读模式下哪些工具算写；bash 怎么办。
- 插件被禁用时，正在等审批的调用怎样结算；子代理的审批（t14 细化）。
- 命令系统的 `confirm` 通道复用这条（t16）。
- 拿例子过：discuss 模式下改一章的审批卡片（显示 diff）；问“这章用第一人称还是第三人称”的提问。

## 决定（开发者 2026-10-28）

具体细节与 Spec 到实施时再详细讨论；方向如下。

1. 审批照搬分支：读、写、执行三档，四种模式（每次都问、放行写入、交审批模型、全部放行），按工具设放行、询问、拒绝（全局用户配置），工具可按参数声明风险，会话内批准记忆。审批模式放 Profile 设置（t05），会话里可切换。默认模式“放行写入”：小说文件的改动能用 nb-history 撤回（t13），执行类默认询问。
2. Agent 模式（normal、discuss、plan）与审批模式分开；discuss、plan 是只读模式，写与执行的调用弹审批（同旧应用），只读模式优先于审批模式。模型用 `switch_mode` 申请切换，用户批准后生效。只有改项目内容才算写：写会话自己的目录（t08 的会话 home）与临时目录不算，所以计划文件放会话目录，不再需要旧应用的“计划目录豁免”。discuss 与 plan 的区别在提示词（t05 的 `Reminder`）。
3. 哪些算写：按工具声明的等级，没声明按执行；改状态的非文件工具声明为写，可按参数动态声明（SQL 的 SELECT 算读）。bash 按白名单判断是不是单纯的只读命令，是算读，其余算执行；白名单在 t12。
4. 审批卡片：工具、等级、理由，参数用 nb-form 展示态；工具可声明预览（edit 给 diff）；操作有批准一次、本会话都批准、拒绝（可附理由交给模型）。“改了再批”不做。
5. 提问：内置 `ask` 工具，一次 1 到 4 个问题、每题 2 到 4 个选项、可多选、总带“其它（自由输入）”；工具经 `ToolContext.ask` 提问，可传 TypeBox schema 由 nb-form 编辑态画表单；回答作为工具调用的结果。
6. 分支 t20 待确认的三条追认：yolo 下工具声明的询问也放行（危险操作用拒绝规则拦）；重启后回答提问不重跑工具、回答作为调用结果，要在回答后继续做事的工具拆成“问”与“做”；在 `interaction` 事件里立即应答也受理。
7. 会话里切换的审批模式与 Agent 模式同 t09 决定 5，是会话级设置，回退不切回（2026-10-28 按 t09 的同一条理由推及，待开发者知悉）。
8. 接口：插件被禁用时等审批的调用按 `tool-unavailable` 结算（t04）；子代理的审批转到父会话界面（t14）；命令系统 `confirm` 级命令复用同一条待处理通道（t16）。

## 改判（开发者 2026-10-30，t13 讨论时）

- 决定 1 的默认模式改判：即使有 nb-history 也不默认放行写入，写入要审批。“放行写入”仍保留为可选模式。
- 实现顺序：最先做“全部放行”（yolo），其次做“交审批模型”（auto），之后才是要审批界面的人工审批（界面在 t17 第 9 条）。
- 规则与模式的关系（开发者提出黑白名单跳过自动审批，主 Agent 补全的写法，待确认）：按工具设的规则（可带参数条件）先于模式判定。命中拒绝即拒绝、不问审批模型；命中放行即执行、不问审批模型；命中询问即交给用户、不问审批模型；都没命中才按模式处理（auto 交审批模型）。yolo 下询问也放行、拒绝照样拦（同决定 6）。
