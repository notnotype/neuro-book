# Agent 操控 NeuroBook 与 nbook project 子命令

## 目标与范围

定 Agent 调用工作台命令的工具与确认通道，以及给外部 Agent 用的 nbook project 子命令。

来源：需求 18、20（[报告](../t01-survey/artifacts/report/index.html)）。

合同：本 Task 只做设计讨论，行为合同未变；定稿后在计划里写明改哪些 Spec。

## 要讨论的问题

- Agent 调命令的工具（列出、执行）；暴露级别；确认通道复用 t06。
- 命令提案里待决的三项：插件的命名空间、Ctrl+P 搜哪些东西、两种模式动作集的关系。
- `nbook project` 子命令给谁用（外部 Agent 配 Skill，还是应用内也走它）；要不要求应用在运行。

## 已知情况（2026-10-30 读代码与 Spec）

- 命令系统 `nbook.commands` 在服务端与每个浏览器窗口各有一张命令表，彼此看不见；它只依赖诊断、公开状态与配置，不依赖 workbench（workbench 依赖它：命令面板与键位分发归 workbench）。
- 现有命令全部由浏览器插件登记（explorer、editor、workbench、settings、html-preview、projects 的 `web/plugin.ts`），服务端命令表是空的；命令的 `when` 只读本窗口的公开状态，参数也常带窗口里的身份，所以 Agent 执行命令前必须先选定窗口。服务端已能经 `nbook.commands/remote` 的 `.at({client})` 列出与执行某个窗口的命令。
- 按钮没有声明式的命令绑定：标题栏、资源管理器的按钮在点击处理函数里调命令服务；关闭对话框、表单、树节点等控件只是组件事件。
- nb-ui 的 `useModalLayer` 维护全应用的模态栈，Dialog 的关闭一律经 `request-close`，Esc 只有最上层收得到（第 10 条的通用命令建在这上面）。

## 需求（开发者 2026-10-30）

- Agent 能当引导者，教用户使用 NeuroBook；用户能做的操作 Agent 也能做。
- Agent 能给用户当前看到的画面截屏，让它的视觉和用户同步。
- 用户操作 NeuroBook 有两种方式，Agent 也都能用：
  - 界面：截屏（要用户审批），截屏后列出画面里可操作的控件和 id；操作页面；高亮某个区域或控件，像应用里的引导界面那样实时生成；
  - 命令系统：有些操作走命令更方便。
- 第三种：能否直接改插件的内部状态（例如插件没提供换主题的接口时直接改主题）。

## 决定

第一轮（2026-10-30）：

1. 命令的列表与执行：列表走资源 `commands://`，只列暴露级别不是 `never` 的命令，每条带说明、参数形状、此刻是否可用与原因；执行一个入口（`id`、`args`）。不把每条命令变成一个工具。（入口的最终形式随第 4 条改为 CodeAct 里的函数，见下一轮。）
2. 在哪个窗口执行：用户当前的窗口。浏览器没有全局的“当前窗口”，由各窗口把焦点变化报给服务端拼出来；没有窗口在显示这个会话时的退路、用户中途切窗口时跟不跟，待定。截屏、界面操作、高亮与命令共用同一个目标窗口。
3. 高亮：实现时先看 driver.js 能不能满足、扩展性够不够，不行就自己写，先作为一个子项目。
4. 界面操作的工具很多，一定要渐进式披露，而且一定用 CodeAct：这些能力不作为内置工具，写成一份文档，模型要用时先读文档，再在 eval 里调用。所以界面层依赖 [t21](../t21-eval-codeact/README.md) 的 eval。
5. 给 Agent 一个指针：有些操作要拖动；以后移动端也要拖动手势。
6. Agent 正在操作时窗口要有可见的提示（以后多人远程协作也用得上）。
7. 不是所有按钮都绑定命令（例如关闭对话框）；快照只在控件明确声明了命令绑定时才标出命令 id。

第二轮（2026-10-30）：

8. 控件稳定名的 Vue 接口形态（`v-nb-target` 一类指令，尤其是列表项的写法）好不好用，实施时先审查再定。
9. 指针与拖动延后，搁置。第一轮第 5 条（给 Agent 一个指针）不进第一版。

第三轮（2026-10-30）：

10. 不让所有控件都绑定命令。按判据分：动作脱离具体控件也说得清、目标能写成“当前活动的某某”或可序列化的参数、值得被搜索、绑快捷键或审计的才绑；实例内部的交互、表单输入、流程里的确认按钮、高频交互流不绑。Dialog 这类通用控件用少数几条作用于“最上层”的通用命令（关闭最上层，等同 Esc；确认最上层，等同 Enter），由 workbench 登记、调用 nb-ui 的模态栈，不给每个实例各绑一条。这套命令规范改动范围大、要反复打磨，优先级调低，放到后面做。
11. Agent 与命令系统的对接（第 1 条的命令列表与执行、确认通道、第一批开放的命令）搁置；Agent 经浏览器操作 NeuroBook 界面（快照、动作、截图、高亮）可以做。

第四轮（2026-10-30）：

12. NeuroBook 以后会有桌面外壳：由外壳提供可信输入与真实截图，拖动问题随之解决；在 web 里自动回退（页面内模拟事件、DOM 重画截图）。
13. 拆成核心包加两个插件：核心包 `nb-page-agent`（纯 TS，只管在一个页面里做事）；内置插件 `nbook.page-agent` 把它装进每个窗口，经 eval 向 Agent 提供 `nbook` 全局对象；可选插件 `nbook.browser` 驱动真实浏览器操作外部网站，向 eval 提供 `browser`，把同一个核心包注入外部网页、动作经 CDP 发可信输入。eval（t21）要有让插件登记全局对象的贡献点（名字、一行摘要、文档、宿主侧处理函数、审批档位，即 omp 的 prelude）。
14. Agent 操作 NeuroBook 界面另开 [w00033](../../../w00033-page-agent/README.md)；浏览器插件另开 [w00034](../../../w00034-browser-use/README.md)。

第五轮（2026-10-30）：

15. `nbook project` 的推荐开发者全部确认（一个命令行同时给用户与内外 Agent、第一批五个子命令、写操作要求应用在运行、`check` 可扩展且 `--fix` 只做安全修复、模板先不做、旧的 `node` 组不搬、提示词与 Skill 两条路让 Agent 知道它），记在 w00035。
16. `nbook` 命令行的设计另开 [w00035](../../../w00035-nbook-cli/README.md)，`nbook start`、`nbook serve`、注册系统服务的讨论也放在那里。

### 讨论过、开发者没有表态的推荐（转到对应 Work，开工时再定）

- 插件的内部状态不对 Agent 开放；插件对 Agent 开放的面是命令、配置项、公开状态（只读）。改设置用按声明校验的接口（草案 `settings.list/get/set/unset`，以用户编辑的身份写、审计记为 Agent），不让 Agent 直接改 `settings.json`。（w00033）
- 接口命名：自己定义，语义相同处借用 Playwright 的子集名并写明是子集；实施时先做“子集名对自造名”的对照实验再定。接口文档由类型定义生成。（w00033 t01）
- `nbook` 全局对象的范围：命令、窗口状态、设置、界面都进这一个对象；其中命令部分随第 11 条搁置。（w00033）
- 窗口状态：只读的公开状态键（打开的作品、活动文档、选区、可见视图），哪些键能读由键的拥有者声明。（w00033）
- 截图的同意粒度（每次都问，还是可选“本会话都允许”）；用户中途切窗口时 Agent 跟不跟；没有窗口显示这个会话时的退路；第一版范围（推荐先做快照、高亮、截图，界面动作第二批）。（w00033）
- 包名 `nb-page-agent` 是暂名。
- 命令提案的三个待决项（插件命名空间推荐直接关掉、`Ctrl+P` 搜哪些东西移到工作台、无头与在场只用一套命令表），随第 11 条一起搁置。

调研：[Agent 操作宿主应用与网页界面](../../research/2026-10-30-host-control-survey.md)（三轮：宿主命令、网页界面、截图与高亮；omp 的浏览器与 eval；CodeAct 的文档形式；页面内可复用的库）。
