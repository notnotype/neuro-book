# 运行控制：插话、排队与中止

## 决定（开发者 2026-10-28，全部同意推荐）

1. 插话、排队、继续照搬分支：插话在下一次模型请求时送达（已发出则在当前工具批次后），日志里标为补充说明；排队在本次运行以 completed 结束后按序作为新输入，出错或中止时不处理；中止默认清空队列；继续在末尾是用户消息、工具结果或出错回复时受理。
2. 中止补强制接管：宽限期内等各方自己收口，过期由运行时写“已中止”、回到空闲，之后迟到的工具结果与模型消息不写日志。宽限期按模型流断开的实际耗时放宽（约 2 秒，计划时定），不照搬旧应用的 150 毫秒。
3. 排队的消息写进日志：入队、出队、删除各写一条会话级条目（不进对话树）；重启后队列还在但不自动发出，等用户确认。
4. 等审批时在输入框发出的文字等于“拒绝这次审批并附上这段话”，模型立即收到；等提问时文字作为自由输入的回答；输入框给相应提示。
5. 还没送出的排队消息可以删除、修改、改成插话立即送出。
6. 运行中不能回退、重试、编辑重发、切换分支（按钮置灰，提示先停止）：运行中改叶子会让正在写的条目挂到错误分支。
7. 进程中断后不自动续跑：按分支的恢复规则收口（没有结果的工具调用标为中断、结果未知），保留 master 的进程中断收尾；界面显示“上次运行被中断”并给“继续”。

运行步数上限放 Profile 设置（实施时定）；子代理的中止连带在 t14。
