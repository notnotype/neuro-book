# eval 内核在会话关闭后保留，重置原因写准

## 目标与范围

会话关闭不再结束 eval 内核：内核照样按 30 分钟空闲与 8 个上限回收，会话再打开、叶子与 Profile 没变时接着用；重置提示的原因写准（关闭期间被空闲回收或被回收、换了 Profile、意外退出各写各的）。来源：开发者 2026-11-19 在 t21 交付后的问答里确认（不做内存转储）。

合同：[`agent/eval.md`](../../../../../docs/specs/agent/eval.md) 输出 11、12，“状态与转换”的状态表与时序，“副作用与数据”，实现合同的两条不变量。

## 决定

1. 不做内存转储与自动恢复（开发者 2026-11-19）：Bun 没有把运行中的堆存下再载回的接口；`bun:jsc` 的 `serialize` 只还原纯数据（实测 Map、Date 能还原，自定义类丢原型，函数报 `DataCloneError`）；重放之前的单元会把写文件、调工具这些副作用再做一遍。
2. 会话关闭不结束内核，重置原因写准（开发者 2026-11-19 “第一条可以直接做”）。不写计划、不做设计审查：开发者要求直接做，改动集中在 eval 的宿主一侧。
3. 换 Profile 照旧重置内核：沿用 t21 待确认清单第 23 行（开发者 2026-11-18 追认）。内核本身不依赖 Profile（工具集与全局对象每个单元重新给），只是原因现在单独写成“换了 Profile”。要让变量跨 Profile 留着，去掉 `SessionKernel` 里那一个判断即可。

## 改动

- 内核与重置原因、单元计数、叶子计数这些跨调用的记账从会话的工具实现搬到 `SessionKernel`，按会话 id 存在全服务端的 `KernelRegistry` 里：工具实现只管“这次打开关了没”，`dispose` 不再结束内核。登记表按最近用过排序，活着的内核超过 8 个回收最久没用的；没有内核、只记着原因的持有者至多留 256 个。
- 服务端停止时，`runtime.stop()` 关完会话之后再结束登记表里的全部内核（`evalTool` 交回 `{implementation, stop}`）。
- 重置原因：新增“换了 Profile”；两次调用之间内核被外部结束写“意外退出”（原先落到默认原因）；默认原因改成“服务重启或分叉”。
- 实施中发现：语法错误这类提前交回的调用不重新计空闲。原先会话关闭会结束内核，所以不显；内核留下之后就只剩总数上限能回收它。改成每个出口都重新计空闲。

## 验证

- `eval.test.ts` 与 `backend/eval/kernel.test.ts`：45 条过。新增与改写的用例：
  - 会话关闭不结束内核：再打开接着用（变量还在、没有提示）；关闭期间推满 30 分钟，内核与它起的子进程结束，再打开提示“空闲”。
  - 会话关闭之后回退：提示“回退或切分支”。
  - 换了 Profile 之后再调：提示“换了 Profile”，旧内核已结束。
  - 服务端停止：会话关闭之后留着的内核与子进程也结束。
  - 两次调用之间被外部杀掉：提示“意外退出”。
  - 30 分钟空闲：最后一次是语法错误也回收。
  - 登记表单测：按会话交回同一个持有者、超上限回收最久没用的、只记原因的持有者有上限、停止后不再交回。
- 变异检查（改坏实现，对应用例失败，恢复后通过）：不接回留着的内核、去掉每个出口的空闲计时、去掉 Profile 判断、去掉两次调用之间的存活检查、停止时不结束登记表。
- 示例场景 10：4 条过（换 Profile 的提示改成“换了 Profile”）。
- 应用类型检查过。
- `test:affected --since master`：3652 过、11 失败。其中 7 条（服务端插件清单与内置插件名单少了 `nbook.stickers`）在 master 6f5f9382d 上同样失败，与本 Task 无关；3 条项目子进程的停止用例在负载 13 左右超时，在分支上单独重跑 9 条全过；1 条是场景 10 的旧提示，已改。
