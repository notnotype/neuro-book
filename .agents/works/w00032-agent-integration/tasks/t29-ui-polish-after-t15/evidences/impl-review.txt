## 1. 重要 / 正确性：删除当前选中的服务商后，“选中下一家”取决于快照事件与写入结果谁先到，事件先到时选中落到“全部模型”

- 位置：packages/neuro-book/src/plugins/models/web/components/ProvidersPage.vue:306-307（`removeProvider` 里的 `if (selected.value !== provider.id) return selected.value;`）与 :49-52（快照 watch）。
- 现象：新加的“删的是别的一家时选中不变”判断放在 `await store.call("removeProvider")` 之后，读的是此刻的 `selected.value`。页面顶部的 watch 在“当前选中的那家从快照里消失”时会把 `selected` 改成 `"all"`。如果快照变更事件先于 `removeProvider` 的结果到达（base 的注释本身就承认两种先后都可能：“删除的结果经快照事件回来，可能晚于写入返回”），watch 已经把 `selected` 改成 `"all"`，这里 `"all" !== provider.id` 成立，直接返回 `"all"`：选中停在“全部模型”，焦点落到“全部模型”条目，而不是下一家。
- 为什么是问题：违反 Spec settings-pages.md 输出 12“删的是当前选中的那家时，选中并聚焦下一个服务商”。base 是无条件 `selected.value = neighbour?.id ?? "all"`，两种先后都对；这次是回归，且只在其中一种先后下出，e2e（事件晚于结果）测不出来。
- 如何核实：从代码推断。构造 fake remote，让 `changed` 事件在 `removeProvider` 的 Promise resolve 之前发出，删当前选中的中间一家，看 `selected`。
- 建议改法：在 `removeProvider()` 同步段（await 之前）取 `const wasSelected = selected.value === provider.id`，await 之后用它判断；不要在 await 之后再读会被别的 watch 改写的状态。补一条页面级 dom 测试覆盖“事件先到”。

## 2. 重要 / 正确性：可删除时，鼠标悬停在条目上行尾那格就被隐藏，问题图标的 Tooltip（“悬停写原因”）永远出不来

- 位置：ProviderRail.vue:285-287（`.provider-rail__row.is-removable:is(:hover, :focus-within, .is-menu) .provider-rail__end { visibility: hidden; }`）与 :144-148（Tooltip 的触发器在 `.provider-rail__end` 里）。
- 现象：Tooltip 的触发器是行尾那个 14px 的图标。用户要悬停它，就得先把鼠标放进这一行；一进这一行，`:hover` 命中，`.provider-rail__end` 变 `visibility:hidden`，图标不再接收指针事件，叠在上面的删除图标（pointer-events:auto）接管。键盘聚焦同理（`:focus-within` 也隐藏）。只有 `disabled`（只读）时 `is-removable` 不加，Tooltip 才可达。结果：正常可写状态下，视力用户没有任何办法看到“没有密钥/环境变量没有值/检测失败”的原因，只有读屏的 `aria-describedby` 有。
- 为什么是问题：Spec 输出 1“这一格换成图标，悬停写原因”落空；这是“密钥有问题”这个主要提示信息的唯一视觉出口。ProviderRail.md 也写了“图标悬停写原因”。dom 测试只断言了 describedby 文本，没碰 Tooltip，e2e 也没测，所以没被发现。（Spec 输出 1 与输出 12 在这一格上本身就冲突：悬停既要写原因又要出删除图标。属于需要定的设计点，不能只靠 CSS 掩过去。）
- 如何核实：从代码推断（`visibility:hidden` 的元素不是指针命中目标，这是 CSS 规定）。在真实浏览器里给一家设“没有密钥”，鼠标移上去，看 300ms 后有没有提示。
- 建议改法：二选一，需要开发者定：(a) 原因的提示挂在整条条目上（Tooltip 包整个 item，或给条目设 `title`），不依赖行尾图标；删除图标显示时提示仍可达；(b) 悬停时只在没有问题的条目上换删除图标，有问题的条目让问题图标与删除图标并排（需要放宽“一格”）。补一条 e2e：悬停有问题的条目能读到原因。

## 4. 重要 / 不变量（可达性）：条目按钮里放了 sr-only 原因文字，又用 aria-describedby 指向它，读屏会念两遍

- 位置：ProviderRail.vue:137、150；ProfileRail.vue 对应的 `aria-describedby` 与 `<span ... class="sr-only">`（statusIdOf）。
- 现象：`sr-only` 的 span 是 `<button>` 的子节点，且没有 `aria-hidden`，所以它已经并入按钮的可访问名称（“DeepSeek 2 个模型”“OpenAI 没有密钥”）；同一个 span 又被 `aria-describedby` 引为描述，名称与描述内容重叠，读屏念成“OpenAI 没有密钥，没有密钥”。副作用：按钮的可访问名称变了——所有 `getByRole("button", {name: "DeepSeek"})` 精确匹配都会受影响（现在 e2e 用 data 属性，没暴露）。ProviderRail 的行尾数字与图标都是 `aria-hidden`，所以意图明显是“名称只含服务商名，状态放在描述里”，实现没达到。
- 为什么是问题：brief 重点 1 点名问的重复朗读，确认存在；测试只断言了 `getElementById(describedby).textContent`，没断言可访问名称。
- 如何核实：dom 测试里用 testing-library 的 `getByRole("button", {name: "OpenAI"})`（不加 exact:false）会找不到；或在浏览器 devtools 的 Accessibility 面板看名称与描述。
- 建议改法：把 sr-only span 挪到按钮外（作为 `.provider-rail__row` 的兄弟，仍被 describedby 引用），或给它 `hidden`（aria-describedby 可以引用隐藏元素，且隐藏元素不会进名称）。补一条断言可访问名称等于服务商名。ProfileRail 同改。

## 5. 建议 / 正确性：`shortTarget` 把含 `://` 的 shell 命令与搜索词也当地址截断

- 位置：packages/neuro-book/src/plugins/agent/web/subagent-card.ts:77-81（`shortTarget`），调用在 :130。
- 现象：后端 `targetOf`（backend/subagents/tree.ts:28）的取值键是 `path`、`pattern`、`command`、`query`、`url`，不只是路径。`shortTarget` 只要字符串里有 `://` 就取它之后最后一段：shell 命令 `cat project://正文/第二章.md` 变成 `第二章.md`，丢了 `cat`；`cd project://a && rm -rf project://tmp/x` 变成 `x`；`curl -s http://localhost:8080/api/x` 变成 `x`；grep 的 `pattern` 是 `https?://` 时最后一段为空而原样返回，写法前后不一致。壳工具的说明（texts.ts:11）明说“命令里直接写出的资源地址”，所以 shell 命令里出现 `project://` 是常态。
- 为什么是问题：Spec 输出 33 写“对象是地址时只写最后一段”，是整个对象是地址时；这里把子串当地址，会把子代理正在做什么写错。
- 如何核实：`subagent-card.test.ts` 加 `{tool: "nbook.agent.shell", target: "cat project://正文/第二章.md"}`，期望仍是原串；现在得到 `第二章.md`。
- 建议改法：只在整个字符串是单个地址时截：`/^[a-z][a-z0-9+.-]*:\/\/\S*$/u`；空白、命令不匹配就原样。补边界测试：命令、结尾斜杠、只有协议、被 120 字截断带 `…` 的长路径（最后一段是被截断的，不会错但应有一条断言说明这是预期）。
