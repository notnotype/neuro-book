# 上下文压缩

## 目标与范围

定上下文压缩的触发（手动、溢出、阈值）、摘要模型、压缩条目与恢复。

来源：清单外第 1 项（[报告](../t01-survey/artifacts/report/index.html)）。

合同：[`agent/compaction.md`](../../../../../docs/specs/agent/compaction.md)（实施时新建）、[`harness/runtime.md`](../../../../../docs/specs/harness/runtime.md) 输出 46–52；其余见 [plan.md](plan.md)。

## 要讨论的问题

- 触发：手动 `/compact`、溢出后、一轮结束超过阈值。
- 摘要用哪个模型（角色，t09）；压缩条目的形状与恢复。
- 与会话树（在某个分支上压缩）、工具发现的缓存边界的关系。
- 插件贡献压缩方法。

## 材料

## 前置

## 讨论进展（2026-10-28）

事实见[外部参照](../../../../../docs/research/agent-runtime-references.md)“上下文压缩”一节（omp、Claude Code 的源码与提示词）。

开发者第一轮意见：

- 固定 80% 不行（1M 与 256K 窗口的 80% 差别很大），参考 omp。
- 分清“就地压缩”（用原模型、吃得到缓存）与“摘要模型压缩”（上下文交给摘要模型），后者可以先 shake 再交摘要模型；摘要模型单独一个角色，缺省为 fast。
- 要调研摘要的输出格式与压缩提示词（Claude Code、omp、phistory）。
- 压缩块要能点开看详细。

调研纠正一处：omp 里吃得到缓存的是 handoff（原样上下文加一条请求），不是 soft；soft 把对话序列化成文字、换摘要系统提示词，即使同一个模型也吃不到缓存。Claude Code 的压缩是就地的。

## 决定（开发者 2026-10-28：先这么定，压缩提示词与压缩结果实施时细化，并随实际体验与反馈持续优化）

1. 阈值照 omp 三层：缺省按预留量（触发点 = 窗口 − max(窗口的 15%, 16,384)）；全局可改为百分比或固定 token 数；按模型单独设（token 基数、百分比或固定触发点，可前缀匹配），放在模型服务的模型配置里（t09）。保留最近 20,000 token，摘要上限 16,384 token。
2. 方法分三种：就地（`inplace`，会话模型、原样上下文末尾追加压缩请求，吃得到缓存，已溢出时不能用）、摘要模型（`summary`，对话序列化后交“压缩”角色的模型，太长分段）、shake（丢能找回的大块内容，不调模型）。缺省组合：超过阈值时 shake → 就地；服务商报溢出时 shake → 摘要模型。两种情况各一个方法顺序，放 Profile 设置。第一轮只做这三种；remote、snapcompact 以后登记。
3. “压缩”是单独的专精角色，首次设置时复制 fast 当时绑定的模型，之后各改各的（不在模型角色合同里开“跟随”的例外）。t09 决定 3 的“压缩摘要用 fast”相应改为用这个角色。
4. 触发：手动 `/compact [要求]`；每次模型请求前检查阈值（运行中途也查）；服务商报溢出时自动压缩后把同一请求再发一次，最多一次（改掉分支“不自动重试”的决定）；字节太大（413）时先 shake，不用会生成图片的方法。压缩在运行之中，界面显示“正在压缩”，可以停止。
5. 摘要正文归压缩方法：内置方法的格式按写小说改造，合并两家长处——用户的要求（原文）、约束与偏好（文风、人称、禁忌）、已定的设定与情节决定、进度（章节完成、在写、待办）、关键上下文（文件路径、章节、引用段落）、未回答的问题、下一步（引用原话）；再次压缩时原样保留旧摘要里“用户的要求”。
6. 压缩之后放回什么是公共流程（同种子，t05）：重新渲染的种子；最近读过的至多 5 个文件重新读入并截断；`session://plan.md`；加载过的 Skill；完整对话记录的地址（提前做 t08 留给 t14 的渲染对话记录）。
7. 额外要求合三处来源：Profile 的要求、`/compact` 后面的话、t20 的压缩前钩子，以“压缩要求”交给方法。
8. 压缩条目统一形状 `{method, firstKeptEntryId, replacement, tokensBefore, tokensAfter, details}`，是当前路径上的节点，只对其后生效；插件经 `agent.compactionMethods` 贡献方法，结果不合格按失败换下一个。
9. 界面：对话里一条分隔线，点开看方法与模型、压缩前后 token 与花费、摘要全文、放回的文件与 Skill、用到的压缩要求，以及“看压缩前的原文”（只读）。

## 计划确认时的修改（开发者 2026-11-05）

改上面决定里的三处：

- 决定 1：按模型的阈值不做前缀匹配。阈值写在每个模型自己的配置里，同一系列的模型逐个设。
- 决定 6：shake 之后不放回。它没丢对话，放回最多约 2 万 token，会把省下的又加回去。“加载过的 Skill”这次不放回：Skill 还没实现，有了之后加一段。
- 决定 9：不做“看压缩前的原文”。对话视图显示整条路径，压缩前的内容就在分隔线上面。

设计审查之后（开发者 2026-11-05）再改三处：

- 决定 6：完整对话记录用现有的 `sessions://<本会话>/session.jsonl`，不提前做渲染版。渲染版留给 t14，要带过滤。
- 决定 2：缺省顺序末尾都加摘要，超过阈值与手动 `shake → inplace → summary`。
- 决定 9：轮中压缩的分隔线常显，整轮收起时也露出来。
