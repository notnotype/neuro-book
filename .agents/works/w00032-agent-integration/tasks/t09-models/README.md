# 模型服务与模型角色

## 目标与范围

定模型服务插件：服务商与模型目录、密钥存法、模型角色合同的落地，以及会话怎样取模型。

来源：清单外第 3 项；需求 1 的模型选择（[报告](../t01-survey/artifacts/report/index.html)）。

合同：本 Task 只做设计讨论，行为合同未变；定稿后在计划里写明改哪些 Spec。

## 要讨论的问题

- 模型服务插件：服务商、模型目录、自定义服务商、模型发现。
- 密钥存法：明文配置项（2026-10-20 定）、环境变量名（nb-story，ADR 0032）、OMP 凭据存储与 OAuth（分支）三选一或组合。
- 模型角色：合同落成 Spec；会话怎样取模型（Profile 指定、角色、用户在 Composer 里选）。
- 推理档、上下文窗口、单价“未知”与“免费”。
- nb-story 接入应用后共用这一套。

## 材料

- [模型角色合同](../../../../../docs/proposals/model-roles-contract.md)、[`settings/configuration.md`](../../../../../docs/specs/settings/configuration.md) 的密钥一节
- [`story/qa.md`](../../../../../docs/specs/story/qa.md) 的配置、[ADR 0032](../../../../../docs/adr/0032-nb-story-keys-from-startup-env.md)
- 分支上的 `docs/specs/harness/models.md`、`config.md`

## 前置

t02。

## 决定（开发者 2026-10-28）

1. 模型服务单独做插件，不放进 Agent 插件：服务商（OMP 内置目录加自定义的 OpenAI 兼容服务商）、模型发现（`/models`）、模型能力（上下文窗口、看图、推理档、工具调用）、密钥、角色绑定。编辑器行内 AI（w00025 t12）、nb-story、以后 nb-memory 的向量模型都用它。设置页用 nb-form 与 w00027 的设置机制。
2. 密钥统一存 OMP 的凭据库 `<状态根>/agent/credentials.db`（API Key 与 OAuth 令牌），配置里不放密钥；同样不加密，只是把 2026-10-20 的“明文配置项”换成“明文凭据库”（OAuth 令牌会刷新，不适合当用户手改的配置项；配置导出与分享不带密钥）。密钥的值可以写成 `env:<变量名>`，启动时读取。nb-story 命令行照 ADR 0032 读环境变量，在应用里改用模型服务的密钥。
3. 模型角色照合同（`docs/proposals/model-roles-contract.md`）做并写成 Spec：梯度四档（tiny、fast、main、deep）加可自定义的专精角色，每个角色绑一个模型，不回退。系统功能各用一个梯度角色（标题 tiny、审批模型 fast；压缩摘要改用 t11 的“压缩”专精角色，2026-10-28），用户在对应功能的设置里可改。自动回退链不做（合同定为另立提案）。
4. 会话取模型：会话里明确选的 → Profile 设置里的角色或模型 → 全局缺省（main）。Profile 声明的能力（t05）不满足时，Composer 提示并不让发送。
5. 模型与推理档的切换是会话级设置，不跟对话路径走（开发者 2026-10-28：旧应用按路径记，用户换了模型再回退，模型也跟着切回去，不符合习惯）。会话级条目不进对话树（同 t03 的标题）；每条助手消息照旧记下是哪个模型、哪个档位生成的，供显示与统计。本条改了 t03 决定 1、t05 第一轮“会话里中途换模型跟着路径走”的说法。
6. 推理档按模型支持的档位夹取（master 的 `clampEffort`），Composer 只显示支持的档位。
7. 上下文窗口：OMP 目录里的模型自带；自定义模型必须填（压缩要用）。单价 `null` 为未知、`0` 为免费，界面分开显示；用量按会话汇总。
8. nb-story 在应用里跑时，模型与密钥从模型服务取；它在应用里的配置页留到 nb-story 接入时再定；命令行不变。

25. 浮层面要分档（开发者 2026-11-01 会话，看了四档对比）：下拉菜单这类小浮层 65%–80% 最好；一级对话框 80%–85% 最好、90% 也能看；一级、二级都 90% 时二级看不出是一层新的面。评审板 v6 按区间中间取“小浮层 72%、一级 82%”请确认，二级用不透明还是 95% 待定。这要在 nb-ui 加主题变量（对话框一档、二级一档），连同决定 20 的 `Dialog` 嵌套判断一起做。

26. 开发者看 v6 后要一级对话框的百分比再高一点，并要控件自己挑：Lab 草稿加了“调面板”两个场景（`tune-dialog`、`tune-menus`），右下角三个滑块实时改小浮层、一级、二级的不透明度（初值 72%、88%、不透明）。开发者挑定数值后写进这里，再落到 nb-ui 的主题变量（2026-11-01 会话）。

27. 浮层面三档（开发者 2026-11-01 在 Lab 调面板里挑定）：小浮层（菜单、下拉、弹出框、提示）72%；一级对话框（设置窗口这类）90%；二级对话框（叠在一级上的）也是 90%，仍是玻璃（不用不透明）。都是面板色的百分比加现有的模糊。实现：nb-ui 加对话框一档与二级一档的主题变量，`Dialog` 判断自己是不是叠在另一个对话框上；圆角不大于底下的窗口（决定 20）。评审板的 `overlay-tiers`、`nested-surface` 撤下。

28. 连接一节按第四轮的稿做（`connect-r4` = 是，开发者 2026-11-01）：说明收进标题旁的“?”，只在出错时写一行；接口地址的“?”写实际请求地址；目录服务商也能改地址（改过时出现“恢复目录地址”，能力与单价仍按目录）；默认收起的“高级”里是认证方式（按接口格式、Authorization: Bearer、不要认证）与服务商级请求头；模型级请求头在编辑对话框的“高级”里，同名时用模型的；请求头的值支持 `env:变量名`。

29. 服务商与模型页改了就写（开发者 2026-11-01 会话）：同设置窗口的普通设置项，开关、下拉立即写，输入框在失焦或回车时写，密钥也是；编辑模型、管理模型两个对话框自带“保存”“完成”。页面没有“未保存”状态，不用 Lab 样板的草稿加保存栏。

30. 补齐的几处按最后一轮的稿做（`final-r5` = 是，开发者 2026-11-01）：“添加服务商”是可搜索的对话框（已添加的停用、本机端点标“不要密钥”、只能登录的停用并写“第一版不支持”、最下面是自定义 OpenAI 兼容服务商）；删除服务商的确认写明去掉几个模型、密钥一起删、哪些角色变成未绑定；检测失败点红色图标看归类后的原因、服务商原文与“重新检测”；开箱时右边是引导；页面不到 600px 时左栏收成顶上的下拉加“添加”。设计定稿。

31. 小浮层的不透明度（开发者 2026-11-01，设计审查 S2 后）：亮色 72%、暗色保持 75%；一级、二级对话框亮暗都 90%。
32. `env:` 引用存哪（开发者 2026-11-01，设计审查 O5 后）：变量名存服务商设置的 `apiKeyEnv`（同 nb-story），凭据库只存真密钥；界面不变，密钥框里写 `env:变量名` 即存成引用并清掉库里的密钥。
33. 原生插件怎么分发（开发者 2026-11-01，第 1 片收尾时发现的阻塞 1）：`@oh-my-pi/*` 不打进服务端 bundle，作外部模块；应用包清单写上对它们的依赖，npm 安装时只装本平台那份原生包（同 omp 自己的发法）。放弃“清单没有依赖”，安装多约 122 MB，包仍跨平台。
34. postmortem 的进程级信号处理（同上，阻塞 2）：先调研有没有更好的办法；没有就把 OMP 放进 Worker 线程（postmortem 在 Worker 里不装信号处理），并先审查这个方案是否可行、有没有隐患。
35. 决定 34 的结果（开发者 2026-11-01）：Worker 方案经 omp 设计审查（阻断 4、重要 7，[证据](evidences/design-review-omp-isolation.txt)，[方案稿](omp-isolation.md)）后不做；查明这是 OMP 对嵌入方的缺陷（SDK 文档称“完整的嵌入面”，导入即装硬退出的处理，没有开关），已报上游 can1357/oh-my-pi#17674。先用“宿主接管”的临时做法：服务端入口在导入 OMP 前记下监听、导入后摘掉 OMP 挂上的，停止结算后跑 OMP 的清理；上游有开关后换成开关。向上游提 PR 先等 #17674 的反应（OMP 的贡献规则：开了 issue 的工作他们的机器人可能会接，PR 正文要开发者亲笔一句）。需要隔离原生崩溃与内存时再做模型服务子进程。决定 33、35 记为 [ADR 0036](../../../../../docs/adr/0036-app-package-installs-omp.md)。
