# t26 计划第一稿的设计审查与处理

审查者：omp（默认模型），对象 `plan.md` 第一稿（提交 `eb8d5b8c5`），报告 `design-review-omp.txt`。会话到 2 小时上限被截停，报告逐条追加、共 27 条（阻断 10、重要 17，第 22 条与第 16 条重复），末尾没写“未发现问题的方面”。分类按 reviewing Skill 的“处理结果”。

几条阻断出自同一个根因：第一稿把暂存拆成“远程 `stage` 建暂存 → 写 → 远程 `commit`”两次远程调用，于是租约跨调用、`stage` 结果不确定、token 所有权、跨盘回退的前缀过滤都成了问题。第二稿改为**写入方自己在根的暂存目录里写、只发一次 `commit`**，并把提交从 `replaceLocked` 拆成单独的函数、带锁内的成功阶段。

| 条 | 级 | 要点 | 处理 |
|---|---|---|---|
| 1 | 阻断 | `adopt` 进 `replaceLocked`：重做与失败收尾会删掉唯一的暂存；目标不存在时 `root.replace` 先要求文件已存在 | 成立，要改：提交另写 `commitStaged`（与 `replaceLocked` 共用锁与身份核对的辅助），暂存文件只在被消费或调用方丢弃时删；目标不存在时按位置解析与加锁 |
| 2 | 阻断 | 跨盘回退的 `.nbook-staging-` 前缀没有共用的过滤点，别的实例的临时文件也会被当外部改动 | 成立，改设计消掉：不再在目标目录放暂存；跨盘时由拥有根的进程在锁里拷进同目录的临时文件再改名，临时文件用现有的 `temporaryPath`（同一实例的回声）。两个实例互看临时文件是现有行为，记为基线问题 |
| 3 | 重要 | 1 小时没改动就清理会删掉另一个实例里暂停的写入 | 成立，要改：每个暂存文件由写入方持一把跨进程锁（proper-lockfile，10 秒不刷新算残留），清理只删取得到锁的 |
| 4 | 重要 | 内容相同不能证明这次提交执行了 | 成立，要改：去掉按哈希判定成功，结果不确定一律交 `unknown-outcome`；Spec 随之改 |
| 5 | 重要 | 租约不能从 `stage` 跨到 `commit` | 成立，改设计消掉：只有一次 `commit` 远程调用，在一次 `withProject` 里 |
| 6 | 重要 | `read` 不能一律先 `readPath`：虚拟根由提供者生成文字 | 成立，要改：`read` 按方案分派，虚拟根交回文字的字节与它的基线 |
| 7 | 阻断 | `entry` 不在 `ChangeSource` 的 schema 里 | 成立，要改：Agent 来源加 `entry?`，事件与 `as` 共用同一个 schema |
| 8 | 重要 | `realPath(read: true)` 浏览器也能调，会拿到根外的绝对路径 | 成立，要改：读路径与 `commit` 只接受服务端的 `nbook.files`，按调用方身份核对，不靠参数 |
| 9 | 重要 | 回声在锁放了之后才登记，外部在其间原地改写会被当成回声 | 成立，要改：提交在锁里改名之后立即取状态、登记回声，再放锁 |
| 10 | 阻断 | 根外读路径与现有 `resolve` 的根内检查冲突；挂载方案的授权形状 | 成立，要改：项目与 `user://` 另写只读解析（词法路径核对控制目录，跟随链接到最终目标，目标在根内时再核对控制目录）；挂载方案不跟随到挂载点外，照现有授权 |
| 11 | 阻断 | 硬链接就地写：两个链接名拿的是两把锁，会交错写坏 | 成立，改设计消掉：不再为硬链接就地写，与浏览器保存一样改名替换（链接断开）。偏离已接受的提案，记待确认 |
| 12 | 阻断 | 结果不确定之后的核对用了已取消的 `signal`；谁删暂存 | 成立，按第 4 条消掉核对；暂存由写入方保留并持锁到远程调用结算，结果不确定时放锁不删，交给拥有根的进程（它在锁里消费或下次启动清理） |
| 13 | 重要 | `dev` 相同不保证能改名（bind mount 会 `EXDEV`） | 成立，要改：不预判，改名得 `EXDEV` 时在锁里拷进同目录临时文件再改名 |
| 14 | 重要 | 新文件的权限位会是暂存的 `0o600` | 成立，要改：新建的目标按 `0o666 & ~umask`（与“新建文件”一致），覆盖的沿用原文件 |
| 15 | 阻断 | 记账、回声、事件都要在锁里，`replaceLocked` 没有锁内成功阶段；顺序与 Spec 不一致 | 成立，要改：`commitStaged` 带锁内成功回调，按 Spec 的顺序：替换 → 记账槽 → 登记回声 → 发事件 → 放锁 |
| 16 | 阻断 | `absent` 与“新建文件”取的是两把锁，改名会覆盖刚建的文件 | 成立，要改：`absent` 用 `link`（目标已存在即 `EEXIST`，原子）加删暂存；文件系统不支持硬链接时用 `open(目标, "wx")` 拷入 |
| 17 | 重要 | `ToolContext` 里没有工具名 | 成立，要改：`AgentTools` 把工具 id 交给资源视图的构造，`call(ctx)` 用它作缺省标题；`tools.ts` 进范围 |
| 18 | 重要 | 内核资源接口改按字节解码后丢了严格 UTF-8、BOM 与 NUL 的规则 | 成立，要改：复用 `files-service.ts` 的 `decodeText` |
| 19 | 阻断 | 提交前整份读旧内容，替换大文件时内存与时间随旧文件变大 | 成立，要改：锁里分块算旧内容的哈希，只在 32 MB 内留字节给记账 |
| 20 | 阻断 | `.nbook/`、`staging/` 可能是链接，清理会删到根外 | 成立，要改：逐层 `lstat`，要求是根内真实目录、不跟随链接；清理只删普通文件且名字合格式 |
| 21 | 重要 | 记账 2 秒超时的语义 | 成立，要改：Files 等至多 2 秒就继续、放锁；记录带根内单调序号与 id，迟到的完成被忽略，记账者按序号去重排序（第 3 阶段接 History 时实现） |
| 22 | 重要 | 同第 16 条 | 与第 16 条合并处理 |
| 23 | 重要 | 浏览器能直接调新方法并拿到暂存的绝对路径 | 成立，按第 8 条与新设计消掉：远程只有 `commit`，只接受服务端的 `nbook.files`，不交回路径 |
| 24 | 重要 | `call(ctx)` 的门面没注入 `ctx.signal` | 成立，要改：`call(ctx)` 的门面把 `ctx.signal` 合进每次调用；取消后 `sink.write` 失败、不提交 |
| 25 | 重要 | `stage` 本身的结果不确定没法收口 | 成立，按新设计消掉（没有远程 `stage`） |
| 26 | 重要 | 分组缺 `note` | 成立，要改：分组的形状统一为 `{id, title, note?}` |
| 27 | 重要 | “每个方法按第 4 条判权限”会把合法的读也拒掉 | 成立，要改：只有写与文件操作按 `classify.write` 判，读与列出按方案的读授权 |
