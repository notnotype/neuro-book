# 旧应用的 trace 与新应用的现状

t30 开工时的参照清单（2026-11-15）。旧应用只读；“推荐”一列是主 Agent 的建议，开发者定了以后写进 Task README。

## 旧应用怎样记

代码在 `packages/neuro-book-legacy/server/agent/observability/`（`traced-provider.ts`、`pi-request-recorder.ts`、`pi-trace-reader.ts`、`trace-segments.ts`）与 `server/api/agent/traces/`。

- **记录点**：所有服务商调用（主轮、压缩、模型连通性检查）都经过 `tracedStreamSimple` 与 `tracedCompleteSimple` 这一个入口。开关关着时直接透传原来的调用，不包装。
- **记下的内容**：
  - 规范化的请求，包括系统提示词、消息和工具；
  - 服务商原生的请求体（经 `onPayload` 取，可以关）；
  - 服务商、API、模型、Base URL 与推理档；
  - 分区归因与工具集指纹（Task 126）；
  - HTTP 状态和响应头。响应头去掉 cookie、authorization，以及名字里含 token、secret、apikey 的头，限流头除外；
  - 停止原因与用量：输入、输出、缓存读、缓存写、1 小时缓存写、推理；
  - 错误文字（遮盖过）；
  - 开始时间、首 token 时间、总时长。
- **不落盘的**：请求头、密钥。带附件的请求不存原生请求体。
- **存放**：
  - 每条记录一个 `.nbook/agent/traces/<范围>/<编号>.json`，每个范围另有一份 `index.jsonl`，列表只读这份索引。
  - 范围是会话编号；不属于任何会话的请求放在 `_system`。编号全局递增。
  - 每个范围默认只留最近 100 条。设置有三项：开关（缺省开）、存不存原生请求体（缺省存）、条数上限。
  - 写入串行、尽力而为，写失败不影响调用。记录有全文，所以不进可分享的日志包。
- **接口**：
  - 列出各范围；
  - 跨范围的最近 N 条（缺省 50，最多 200）；
  - 某个范围的索引；
  - 单条记录的全文；
  - 清空一个范围。
- **另一个用户**：上下文检查器的缓存时间线与诊断也读 trace 索引（Task 126）。

## 旧应用的查看器

代码在 `app/components/novel-ide/agent/trace-viewer/`（`AgentTraceViewerDialog.vue`、`AgentTraceList.vue`、`AgentTraceDetail.vue`、`trace-view-model.ts`）。

- **入口**：活动栏的图标（`activity`）打开一个大弹窗，标题“Pi 请求记录”。
- **顶部**：
  - 范围下拉：缺省“最近请求（全部）”；会话按“#编号 标题”列出并带条数；另有“系统（无 session）”。
  - 刷新。
  - “清空当前范围”，要先确认；“最近请求”下不能用。
- **左栏列表**（360px）：
  - 同一次调用（invocation）连续的几条折成一组，组头写“调用 xxxxxxxx… · N 条”；不属于任何调用的写“独立调用”。
  - 每行第一行：状态点（成功绿、失败红、中止黄）、类型徽标（turn、compaction、health-check）、模型、#编号。
  - 每行第二行：时间、来源会话（只在“最近请求”下显示）、T 轮次、token、TTFT、时长、停止原因。
  - 选中的那行高亮。打开或切换范围时自动选中最新一条。
- **右栏详情**：
  - 顶部：“#编号 · 状态”，“打开会话 #编号”（跳到那个会话并关掉弹窗），有错误时一条错误条。
  - 概览：键值表，列出类型、模型、API、Base URL、推理强度、开始时间、TTFT、时长、HTTP、停止原因、token 明细、Invocation、Profile、Turn、Mode。
  - System：全文。
  - Messages（条数）：每条消息一块，有角色徽标和备注（工具名、调用 id、error）。块里的文字直接显示；思考用斜体、左边一条线；工具调用显示名字加参数 JSON；认不出的内容给 JSON。
  - Tools（个数）：每个可以展开，写名字、描述的前 120 字和定义的 JSON。
  - Payload：原生请求体的 JSON；没存时说明原因。
  - 响应：响应元数据的 JSON。
  - 换一条记录时回到概览。
- **空状态**：
  - 范围里没有记录；
  - 还没选中记录，提示“选择左侧一条记录”；
  - 请求体没存；
  - 记录已被保留策略清理。

## 新应用的现状

- **日志里有什么**：内核每发一次请求写一条 `modelStarted`，记序号、用途（`turn`、`approval`、`compaction`、`background`）、模型、请求的哈希和改过请求的扩展。结果写成 `assistant`、`modelEnded` 或 `modelFailed`，带用量（含缓存与费用）、停止原因、失败类别与码、重发第几次。请求全文不存。
- **单次请求**：会话标题这类 `complete()` 请求不经会话，也不写日志（`docs/specs/harness/runtime.md` 输出 56）。所以只靠会话日志，会漏掉这些请求。
- **预览**：`preview` 只能算出当前叶子上的下一次请求；`atRequest`（过去的某一次请求）第一版不支持。
- **上下文检查器**（t28）：只看下一次请求的组成与缓存命中，不做缓存时间线与请求选择（t28 计划的决定 3）。
- **400 与 413 的请求全文**：`pi-ai` 会把这两种失败的请求全文写进 `~/.omp/logs/http-400-requests/`，适配器把文件路径取出来并删掉文件（t27）。
- **适配器**：OMP 适配器 `nb-harness/src/kernel/model/omp.ts` 是 `ModelRequest` 与服务商之间唯一的转换点。它已经把 `fetch` 包了一层，用来数重发次数。原生请求体和响应头能不能在这里取到，推断能，计划里要核实。
- **编辑区页面**：可以经页面贡献点 `editor.pages` 放不对应文件的页面，设置和 Lab 都这样做。
- **能复用的组件**：
  - nb-agent-ui：对话视图里消息、思考与工具的渲染，上下文检查器；
  - nb-ui：`Tabs`、`Splitter`、`Table`、`Badge`、`CodeBlock`、`DiffView`、`Tree`、`EmptyState`、`CopyButton`。
  - nb-ui 没有 JSON 查看器。

## 逐项做不做

| 编号 | 旧应用的行为 | 推荐 | 理由 |
|---|---|---|---|
| 1 | 所有模型调用经同一个记录点 | 做，记录点放在模型端口那一层，单次请求也记 | 只读会话日志会漏掉 `complete()` |
| 2 | 规范化的请求（系统、消息、工具） | 做 | 核心 |
| 3 | 服务商原生请求体 | 做，可以关 | 查适配器转换的错要看它 |
| 4 | HTTP 状态、去掉敏感项的响应头 | 做 | 查限流要看 |
| 5 | 用量、停止原因、错误、首 token 时间、总时长 | 做，加上费用 | 新内核有费用 |
| 6 | 分区归因与工具集指纹 | 不做分区；工具集变了的那次在列表里标出来 | 下一次请求的组成上下文检查器已经有；内核有 `toolsAnnounced` |
| 7 | 请求头、密钥不落盘 | 做 | 同旧应用 |
| 8 | 带附件的请求不存原生请求体 | 改：图片不存字节，只记类型与大小 | 体积 |
| 9 | 按会话分开存、每个会话留 100 条、三项设置 | 做；存放位置与上限在计划里定 | |
| 10 | 清空一个范围 | 做 | |
| 11 | 不进可分享的诊断包 | 做 | 有全文 |
| 12 | 活动栏图标加大弹窗 | 待定（问题 1） | |
| 13 | 范围下拉 | 改成筛选：会话、用途、状态 | 新内核的用途有四种 |
| 14 | 按 invocation 分组 | 改：按会话的轮次分组 | 新内核一轮里会发好几次请求 |
| 15 | 列表一行的内容 | 做，加上缓存命中与费用（问题 2） | |
| 16 | 打开时自动选中最新一条 | 做 | |
| 17 | 手动刷新 | 待定（问题 5） | |
| 18 | 详情的六页 | 做；概览改成详情顶部常驻的一条（问题 3） | |
| 19 | 打开会话 | 做 | |
| 20 | 换记录时回到概览 | 改：停在当前这一页 | 前后两次请求常要在同一页对着看 |
| 21 | 缓存时间线与诊断 | 不做 | t28 决定不做；列表逐行有缓存命中 |
