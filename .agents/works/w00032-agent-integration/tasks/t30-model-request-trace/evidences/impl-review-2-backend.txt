### 1. 清空记录后远程缓存仍可读出正文和请求体

- **严重程度**：重要；**类别**：安全与数据清理
- **位置**：`packages/neuro-book/src/plugins/agent/backend/requests.ts:60-81,156-174`
- **现象**：`requestsRemote()` 为 `content` 和 `payload` 各建一个 `RecentTexts`，命中后永久保留到淘汰；`clear` 只调用 `recorder.clear()`，不使这两个缓存失效。清空后用原哈希或 id 再读，服务端直接返回缓存值，不会得到合同规定的 `content-not-found` 或 `payload-not-found`。
- **如何核实**：`/tmp/nb-t30-review-2-lab/clear-cache-leak.ts` 用真实 `RequestRecorder` 与远程实现先读取 `cleared-content`、`cleared-payload`，再清空；再次读取的输出仍分别包含完整正文 JSON 与 `cleared-payload`。
- **为什么是问题**：查看器的清空操作应使记录数据不可再从记录服务取回；当前同一宿主内的其他页面或之后的调用仍能读出已清除内容，且内容哈希可跨请求复用。
- **建议改法**：清空成功后按被删除的内容哈希和请求 id 清除远程缓存；全量清空清除全部缓存。记录器内按哈希的查找文字缓存也应同步失效，避免清理后的正文继续驻留。
### 2. 大量删除拆成同一序号的事件后，客户端只应用第一段

- **严重程度**：重要；**类别**：正确性
- **位置**：`packages/neuro-book/src/plugins/agent/backend/requests.ts:177-181`；`packages/neuro-book/src/plugins/agent/web/requests-page.ts:328-334`
- **现象**：远程层把超过 5000 个 id 的一次 `removed` 拆成多条事件，但每条复用同一个 `seq`。页面收到第一段后把 `#seq` 更新为该值，后续段在 `change.seq <= this.#seq` 检查处全部丢弃。
- **为什么是问题**：一次清空或按天清理超过 5000 条记录时，其他已打开页面最多移除前 5000 条，剩余行继续显示为已不存在的记录；这些行在下一次刷新或重连前不能通过变更事件消失。
- **如何核实**：代码路径的数值边界是确定的：`ids.length = 5001` 时第一段含 5000 个 id，第二段与第一段同为一个 `seq`，页面的序号门禁只允许第一段。当前测试没有覆盖超过 5000 条的 `removed` 事件。
- **建议改法**：为分段事件增加同一逻辑变更内的段号并让客户端按“序号加段号”去重，或让事件协议一次携带可完整消费的删除集合；不能让多段共享一个会被客户端立即消费掉的唯一序号。
### 3. 重启后既有后台标题请求失去所属会话

- **严重程度**：重要；**类别**：正确性
- **位置**：`packages/neuro-book/src/plugins/agent/backend/agent.ts:153-156`；`packages/neuro-book/src/plugins/agent/backend/requests.ts:83-103`
- **现象**：`RequestOwners` 只在运行期间收到 `added` 事件时登记 `titleSessionId(session) -> session`。记录器打开历史索引时不发 `added`，启动代码也没有从既有记录或会话表恢复所属关系。
- **为什么是问题**：服务重启后，已经落盘的标题会话请求会被返回为 `background: {owner: null}`，facet 也会单独列出标题会话；按所属会话分组、标题显示、后台筛选和清空后的界面归类都与重启前不同。之后新开的前台会话只能修复未来的标题请求，不能修复已有行。
- **如何核实**：`/tmp/nb-t30-review-2-lab/owners-restart.ts` 先用一个标题会话写入真实记录，关闭记录器，再用新的 `RequestRecorder` 和空 `RequestOwners` 打开并调用真实远程实现；输出的行含 `background:{owner:null}`，facet id 是 `session-title-...` 且带 `background:true`，没有归并到 `owner-session`。
- **建议改法**：启动时用可用的持久化会话清单登记所有前台会话的标题 id，或让记录器打开时交出历史会话集合后登记；历史标题请求必须和运行期间新增请求使用同一归属路径。
### 4. Unicode 大小写折叠使命中正文和高亮偏移错误

- **严重程度**：重要；**类别**：正确性
- **位置**：`packages/nb-harness/src/kit/requests/search.ts:20-23`；`packages/nb-harness/src/kit/requests/recorder.ts:516-529`；`packages/nb-agent-ui/src/request-trace.ts:410-424`
- **现象**：服务端和界面都把 `toLowerCase()` 后的字符串索引直接当作原文的 `slice` 偏移。某些 Unicode 字符大小写折叠会改变 UTF-16 长度，导致服务端返回的 `first.before`、`first.text` 不是真实命中，界面高亮也会切错字符。
- **如何核实**：真实记录器实验 `/tmp/nb-t30-review-2-lab/search-boundaries.ts` 写入 `İxfoo` 并查 `foo`；结果的第一处为 `before: "İxf"`、`text: "oo"`，预期应为命中 `foo`、前文 `"İx"`。
- **为什么是问题**：请求列表会显示错误片段，详情查找条的命中位置和当前高亮可能错位；服务端 `hits` 的 ordinal 也无法对应界面展示的字符。
- **建议改法**：建立大小写折叠字符串到原文 UTF-16 偏移的映射，或采用不会扩展长度且与界面一致的 Unicode 查找算法；不要把折叠后的索引直接用于原文切片。
### 5. 查找跨内容块时服务端命中数与界面高亮不一致

- **严重程度**：建议；**类别**：正确性
- **位置**：`packages/nb-harness/src/kit/requests/search.ts:20-23`；`packages/nb-agent-ui/src/request-trace.ts:383-407,410-424`；`packages/nb-agent-ui/src/vue/requests/AgentRequestDetail.vue:166-172`
- **现象**：记录器把一条内容的多个可查文字块用换行拼成一个字符串后查找，界面却逐块调用 `highlightSegments`，不把块之间的换行作为可高亮文本。查找词跨越两个块时，服务端会计数并返回命中，界面没有对应高亮或查找条位置。
- **如何核实**：`/tmp/nb-t30-review-2-lab/search-abort-ui.ts` 写入相邻文字块 `foo`、`bar`，查找 `foo\nbar`；真实记录器返回 `server count 1`，同一份内容经真实界面纯函数逐块高亮得到 `ui count 0`。
- **为什么是问题**：列表上的“另 N 处”、详情查找条总数、当前命中跳转和可见高亮依赖同一处数合同；跨块输入时这些状态互相矛盾。
- **建议改法**：服务端按界面可显示的块分别计数，或让界面按同样的拼接流建立跨块偏移映射；两端必须共享分隔符是否可匹配的规则。
### 6. 查找首个分段前不检查中止信号和时间预算

- **严重程度**：建议；**类别**：正确性与资源使用
- **位置**：`packages/nb-harness/src/kit/requests/recorder.ts:437-464`
- **现象**：`search()` 只在处理完每 20 条记录、让出事件循环后检查 `signal` 和 `budget`。查找开始时已中止的信号仍会扫描并返回结果；预算为 0 时也会先处理首条记录，实际预算至少多出一个分段，单条内容读取期间也不能及时响应中止。
- **如何核实**：`/tmp/nb-t30-review-2-lab/search-abort-ui.ts` 用真实记录器对已中止信号查找，输出 `already aborted resolved`；同一实验传入 `budgetMs: 0`，仍输出 `budget zero 1`。
- **为什么是问题**：页面换词时旧查找可能继续做无用的文件读取和解析；合同要求新查找中止旧查找、并在时间上限到达时交回截断结果，首个分段不检查使取消和预算边界失效。
- **建议改法**：进入扫描前先检查 `signal.aborted` 与预算，且按记录或可中断的读取边界检查；保持已扫描游标和 `truncated` 结果的一致性。
