# 第二轮深入审查（宏观）的处理

对象：提案 [文件访问与改动记账](../../../../../../docs/proposals/file-access-and-history.md)，提交 `49a2a85e7`。审查者：omp（默认模型，架构，报告 `proposal-review-r2-omp.txt`，阻断 1、重要 6、建议 1）与 Claude Sonnet（接口与作者体验，报告 `proposal-review-r2-sonnet.txt`，重要 12、建议 6）。分类按 reviewing Skill 的“处理结果”。

## omp

| 条 | 级 | 要点 | 处理 |
|---|---|---|---|
| 1 | 阻断 | 两个服务端同开一本书：后开的照样写文件，只把账本设为只读不够 | 成立。后开实例的写入怎么办交开发者定（见 README 第 23 条） |
| 2 | 重要 | `projects://` 每次调用取放租约，shell 执行期间项目可能进宽限期、停监视 | 成立，要改：shell 在命令期间持有项目租约，推断归属绑定这个租约 |
| 3 | 重要 | History 可选却在锁内被调用，依赖方向与寿命没定义 | 成立，要改：Files 定义自己拥有的记账槽（贡献点），History 贡献；槽空、撤回、超时、出错时提交只写盘并写诊断 |
| 4 | 重要 | nb-history 的 `revert`、`restore` 直接写盘（`workspace-history.ts:105,286,498`），绕开 Files 的锁、期望与事件 | 成立，要改：History 只生成恢复内容，经 Files 提交，操作者记为用户还原 |
| 5 | 重要 | 大文件能写不能恢复，快照上限与用户可见语义没定 | 成立。上限数值交开发者定；超过上限的版本在时间线标明不能恢复 |
| 6 | 重要 | 监视丢事件后没有兜底对账，基线扫描与写入的先后没定 | 成立，要改：溢出、监视出错、项目启动与定时都触发对账（先比 stat）；扫描期间的写入照常走提交，扫描遇到已记账的路径跳过。Windows、macOS 的监视库仍按开发者决定到平台验收时定（接受取舍） |
| 7 | 重要 | `history.sqlite` 随书走时，同步盘、备份、WAL、跨机器没有合同 | 成立。是作品数据还是本地缓存交开发者定 |
| 8 | 建议 | 暂存提交依赖同机共享文件系统，接口没写这个前提 | 成立，要改：写明前提；暂存以句柄交回，由 Files 管路径与清理 |
| 交付顺序 | — | 第一阶段不接 History，只交写入接口，解锁 t12 | 采纳为推荐，交开发者确认 |

## Sonnet

| 条 | 级 | 要点 | 处理 |
|---|---|---|---|
| 1 | 重要 | `forSession` 位置矛盾；绑定时还不知道条目 id | 成立，要改：Agent 的门面按会话绑定，条目 id 由每次工具调用带入 |
| 2 | 重要 | Agent 的 `SessionResources` 与写入接口是两套方法 | 成立，要改：`SessionResources` 是写入接口的会话绑定版，加地址改写与分类，不另写方法 |
| 3 | 重要 | 没有“一次逻辑操作”，拆章、导入几百章时收件箱逐个文件列 | 成立，要改：加不保证原子的操作分组（标题、说明），Agent 的一次工具调用自动成一组 |
| 4 | 重要 | 内容文件夹的清单同步、`delete`/`move` 的期望、结果里的清单都丢了 | 成立，要改：沿用现有文件操作的语义 |
| 5 | 重要 | `await using` 在插件模板里编译不过 | 成立，要改：改成回调式 `stage(address, async (sink) => …)`，回调正常结束即提交，抛错即丢弃 |
| 6 | 重要 | 基线要作者自己对读到的字节算，示例用 `.text()` 会错 | 成立，要改：加 `read`，交回字节与基线（有大小上限）；示例改正 |
| 7 | 建议 | `readPath` 只读却看不出来 | 成立，要改：命名与文档写明，写入的后果写清 |
| 8 | 重要 | “结果不确定”的核对交给作者 | 成立，要改：提交内部核对后再交结果 |
| 9 | 重要 | 项目实例里的插件没有写入入口 | 成立，要改：同一接口在项目实例里进程内提供 |
| 10 | 重要 | 记账范围前后矛盾（t13 决定 14 只记 `project://`）；挂载方案“发事件”与 Spec 矛盾 | 成立。t13 决定 14 被 2026-11-02 的决定取代，在 t13 README 注明；挂载方案按 Spec 不发事件、不记账 |
| 11 | 重要 | shell 推断缺登记接口；“全部还原”会还原用户自己的改动 | 成立，要改：shell 工具经 Agent 门面登记执行区间。推断条目进不进“全部还原”交开发者定 |
| 12 | 重要 | 操作者词汇三套 | 成立，要改：统一成一套（用户、会话、插件、外部、推断），与现有 `ChangeSource` 对齐 |
| 13 | 重要 | SDK 没有 `/files`，第三方写不了 | 成立，要改：照 `/storage` 的先例开子路径 |
| 14 | 建议 | 二进制只显示“已更改”，图片看不到前后 | 成立，留给 t13 的界面：存了全量的图片可以并排预览 |
| 15 | 建议 | 名字与现有代码对不上 | 成立，要改：对齐 |
| 16 | 建议 | 外部改名与经接口改名两种样子 | 成立，要改：安静期内哈希完全相同的删除加新建配成改名 |
| 17 | 建议 | History 不在时用户看不出不能找回 | 成立，留给 t13 的界面 |
| 18 | 建议 | 示例编译不过；失败两种交付方式 | 成立，要改：回调式暂存后，失败统一经结果交回 |
