# t12 设计审查第一轮的处理

审查者：omp 默认模型，报告 [design-review-omp.txt](design-review-omp.txt)，17 个标题、有效 16 条（阻断 2、重要 14），第 13 条审查者自己撤回。审查对象为提交 `6be1259d2` 的计划。审查 worktree 缺依赖，插件层的合同测试没跑；审查者用本机已装的 `pi-natives` 做了十几个只读小实验（引擎写回、长行、引号、搜索配额、真实 JSONL 存储读回），关键结论有实测。

| # | 级别 | 归类 | 处理 |
|---|---|---|---|
| 1 | 阻断 | 成立，要改 | `edit` 动手前经资源视图读取并冻结每个目标的基线，写回只用冻结的基线；引擎读之后被别人改了得 `conflict` |
| 2 | 阻断 | 成立，要改 | 读与搜索改为“定位（`realPath` 加 `follow`，由文件服务跟随最后一段链接并核对包含与受保护位置）后本机读”；不再用不跟随链接的 `realPath` 作读的授权 |
| 3 | 重要 | 成立，要改 | `artifacts/` 的全文由宿主直接流式写盘（上限 64 MiB），不经文件服务的文本写；`read` 改为本机分页读，超过 960 KiB 的文件也能读回 |
| 4 | 重要 | 成立，要改 | 内核规定图片的脱敏（`redacted` 丢图）、改写判断（比较图片哈希）与出站过滤（不做文字替换） |
| 5 | 重要 | 成立，要改 | 压缩与预览按图片口径估算 token（宽 × 高 / 750，至多 1,600），不按 base64 长度 |
| 6 | 重要 | 成立，要改 | `shell` 输出一开始就流向 `artifacts/` 文件，内存只留尾部窗口；超时、中止、异常都关闭文件 |
| 7 | 重要（审查者收窄） | 成立，要改 | 定位支持“从最近的已存在祖先接上余下的段”，`shell` 的新文件目标与 `edit` 的新建都能用 |
| 8 | 重要（审查者收窄） | 成立，要改 | 按引号上下文编码替换后的路径（引号外、单引号内、双引号内各自的规则），验收用含 `$`、反引号、`'` 的路径 |
| 9 | 重要 | 成立，要改 | 用 `editInspect` 预检，有删除、移动就整次拒绝；多文件中途失败如实报告已改的文件 |
| 10 | 重要 | 成立，要改 | 搜索边搜边过滤：流式 `onMatch`、按文件核对、够 `limit + 1` 条可见结果就停 |
| 11 | 重要 | 成立，要改 | 预检时任何目标不是合法资源地址就整次拒绝；`cwd`、`homeDir` 不指向真实目录 |
| 12 | 重要（审查者收窄） | 成立，要改 | 没有完整展示的行时登记 `[0]`，截断的长行不算看过；超过 4 MiB 不登记快照 |
| 13 | — | 撤回 | 审查者自己撤回 |
| 14 | 重要 | 成立，要改 | 输出里的地址一律用全局地址（`agent/resources.md` 已定），输入仍接受单数写法 |
| 15 | 重要（审查者限定） | 成立，要改 | 新 Spec 定失败码：资源与文件服务的码原样，引擎失败为 `edit-<errorKind>`，`shell` 的 `exit-nonzero`、`timeout`、`cancelled`，`invalid-pattern`；放在 `details.code` |
| 16 | 重要 | 成立，要改 | `grep` 的 `maxColumns`、总字节上限、`limit` 与 `context` 的硬上限、扫描期限，期限到了标“不完整” |
| 17 | 重要 | 成立，要改 | `agent.tools` 声明加 `customFormat` 并由 `AgentTools` 转给内核 |

第 2、3 两条一起改变了读的做法：读不再经文件服务的读方法。这一点与 `workspace/resources.md` 的“读写都经文件服务”有出入，第二稿把它写成显式的分工（定位经文件服务、读在本机），提交前请开发者确认。
