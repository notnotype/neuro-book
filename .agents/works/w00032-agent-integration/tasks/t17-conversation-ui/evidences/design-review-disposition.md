# t17 设计审查的处理

审查对象：提交 `d38f26b3c` 上的计划第一稿与 Spec 草稿。前端 Claude Sonnet，报告 [design-review-sonnet.txt](design-review-sonnet.txt)，26 条（阻断 1、重要 14、建议 11）。后端 omp，报告 [design-review-omp.txt](design-review-omp.txt)，写到第 9 条时额度用完（403）；按规则不续跑，剩余部分改派 Claude Opus，报告 [design-review-opus.txt](design-review-opus.txt)，16 条（重要 10、建议 5，第 16 条是 F4 到 F17 的汇总）。共 51 条。

主会话抽查了会改变方案的几条（按钮圆角写死、页面切标签卸载、Vue 层边界、Storage 没有窗口作用域、换进程后节点终态、`Spend` 的形状、`ToolSessionContext` 的形状），都属实。审查者的实验数字（`diffChars` 耗时、时序实验）没有重跑。

结论：第一稿低估了接内核这部分。除下表“接受”与“不改”的，都按审查者的方向进了第二稿，多数原样采纳。

## 改变方案的

| 来源 | 问题 | 第二稿 |
|---|---|---|
| omp 1、Opus 1 | 预览放进工具实现、写进事件：懒包装接不通，提前激活提供方；加 `args` 超过 256 KiB 内联上限，向导画不出来 | 改成只读查询 `approvalPreview`，不进内核、不进日志。一个改法同时解决三件事 |
| omp 2 | 单文件预览表示不了一次改多文件的 `edit` | 结果按文件分组 |
| omp 3 | 批量 `ask` 没有回答合同 | 定 `AskAnswerData`；工具校验，不合规交回模型 |
| omp 4、Opus 7 | 按 `path` 的 seq 补齐会把回退分支接回来；`path` 不含会话级事件 | 写成打开算法：订阅、快照（`head`、`leaf`）、固定叶子取路径、处理缓存 |
| omp 5 | 后台会话的同步 `ask` 永远等 | `ToolSessionContext.background`，后台得 `ask-unavailable` |
| omp 6 | `activity` 没有数据源 | `SessionTable` 维护；只覆盖运行与同步等待，异步提问写进不承诺 |
| omp 7 | 快照 `usage` 没有 token | `Spend` 加 token；费用告警用快照与设置算 |
| omp 8 | 停止后已生成的文字刷新后消失 | `modelFailed.partial` 落成消息；中断判定写明 |
| omp 9 | 换进程后不能重新打开 | 走现有 `FailurePage` 重新加载，加载后从存储恢复 |
| Opus 2 | “第 1 / 3 个”算不出来：写入工具 exclusive，待处理永远一条 | 分母按这条回复没结算的调用算；同一段内向导不离开 |
| Opus 3、16 | F8、F4 站不住 | 进内核小改动 |
| Opus 4 | 没有实际模型的数据源，上下文百分比没有分母 | 快照加 `model` |
| Opus 5、6、8 | 工具状态、事件表、渲染器都有缺口 | 写完整的事件表、状态映射、渲染器清单 |
| Opus 9、10 | 状态栏条目的激活时机；命令没有落点 | 入口 `onStartup` 只放轻量部分；窗口级位置登记 |
| Opus 11 | 验收映射写不出来（文件名、vitest 跑不了 Bun API、端点不够） | 第 6 节重写 |
| Sonnet 16、17 | `diffChars` 主线程卡死（阻断）；一个字的改动显示整段两遍 | 规模上限与预算；段内折叠 |
| Sonnet 18、19、20 | `DiffRow` 撑不起按块动作；无障碍；两栏滚动 | 形状定到够用；前缀与语义元素；一个 grid、容器查询 |
| Sonnet 2、1 | 按钮圆角写死；e2e 断言写死 | `--radius-button-*`；断言读 token |
| Sonnet 6 | nb-agent-ui 不许依赖 nb-form | `renderers.form` 注入 |
| Sonnet 7、8、21、23、24 | 动作名不一致、排队消息、`ctx` 字段、注册表、action 表 | 都写进第二稿 |
| Sonnet 9、10 | 页面切标签卸载；Storage 没有窗口作用域 | 位置键放插件级、计数加延迟；存“最近用过的”，交开发者定 |
| Sonnet 11、12、13、14 | 第二个 `ResizeObserver`；焦点与读屏；矮窗口；浮层规范 | 向导放进内容 sticky；焦点规则；最小高度；规范加一行 |
| Sonnet 15 | 去掉 gutter 的后备方向反了 | 用 `OverlayScrollbar` |
| Sonnet 22 | 发送被拒、停止清空排队、停止兜底、空状态、复制反馈、陈旧响应 | 都进第二稿 |

## 接受或不改

| 来源 | 问题 | 处理 |
|---|---|---|
| omp 3 的一部分 | 内核 `resolve` 不校验回答，建议结算前校验 | 不改内核。回答只来自自己的向导与将来的父会话；工具收到后校验，不合规交回模型。多一层结算前校验收益小 |
| Opus 12 的一部分 | 模型同时发 `ask` 和 `write` | 接受，靠工具说明，写进风险 |
| Sonnet 4 | 书架卡片圆角 16、34、22 不动 | 开发者只提了对话、面板这些；看图时不协调再说 |
| Sonnet 26 | 气泡走 `--radius-panel` 后别的主题也变 | 接受，第 1 片各主题看一眼 |
| Opus 13 | `modelsSettingsContract` 整包给了对话视图 | 接受，浏览器入口都是可信的内置代码；另开只读合同第一版不值得 |
| F5、F6、F9、F10、F16、F17 | Opus 核对后站得住 | 第一版不做 |

## 开发者定的（2026-11-05）

- Opus 2 问的“第 1 / 3 个”和拒绝之后怎么办：开发者提出同一条回复的审批和 `ask` 一样一起作答，全部答完或全部拒绝。主会话读了 `run/tools.ts`，可行：切段之前加审批阶段。替换第二稿的“分母按没结算的调用算”和“其余都算拒绝”。
- 按停止时排队的消息保留。
- 当前会话：运行期间各窗口各选各的，刷新后回到最近切到的。
- 不做第二轮设计审查。
