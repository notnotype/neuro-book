### 4. 用 path 的最后 seq 作补齐游标，会把回退掉的分支重新接进当前对话
**严重程度**：重要
**类别**：正确性与并发
**位置**：/home/notnotype/CodeRepository/neuro-book/docs/specs/agent/conversation.md:56；/home/notnotype/CodeRepository/neuro-book/.agents/works/w00032-agent-integration/tasks/t17-conversation-ui/plan.md:74-81,98；/home/notnotype/CodeRepository/neuro-book/.worktree/w00032-t17-conversation-ui/packages/nb-harness/src/kernel/session/session.ts:326-340；同 worktree 的 packages/neuro-book/src/plugins/agent/backend/remote.ts:121-125；packages/neuro-book/src/plugins/agent/shared/remote.ts:143-144
**现象**：path 的事件确实有 seq，但只包含当前路径的 path-scope 事件，不返回日志 head/through/实际 leaf；log 则包含所有分支及 session 事件。Spec 要求“取 path，丢掉 seq 不大于它的帧”，没有一个可用的日志游标，也没定义 leafChanged 的重投影。远程分页每页都重新读当前叶子，未固定 leaf 时页间切分支会混合两条路径。
**为什么是问题**：先订阅只能防漏帧，不能把路径末尾的 seq 变成全日志的扫描边界。已经回退的会话打开或重连时，会重放被放弃的旧回复；只依靠事件类型追加的适配器也处理不了 leafChanged。第一版没有分支树入口不等于不存在回退后的会话，远程服务与其他调用方已经能改树。
**如何核实**：bun /tmp/review-t17-design/kernel-review.ts，经真实两轮 send 后 rewind：日志 head 从 23 到 25，当前 path 最大 seq 为 13；按它补 log 立即读到第二轮被回退的 runStarted/input/assistant/runEnded（seq 15/18/21/23），以及 seq 24 的 leafChanged。无内部函数调用。另据 remote.ts，path 每页只带 items/more/next，from 是数组下标；snapshot.head 与 leaf 尚未纳入计划中的同一补齐协议。
**建议改法**：定义两个独立状态：全日志游标和当前叶子。最小接法为先订阅并缓存，再取 snapshot 的 head/leaf，所有 path 页固定该 leaf，按 snapshot.head 补齐并处理缓存；遇到 leafChanged 按指定叶子重建路径，不把各分支日志直接追加成对话。也可让远程首屏查询原子返回 leaf/head 与有界路径页。覆盖页间回退、订阅期间切分支、回退后首次打开、带过滤的 progress。

**现象**：对话 Spec 要求服务端换进程后自动重新打开会话，验收 5 又要求重启后能回车继续；平台的远程链路合同明确，旧浏览器节点收到 server-restarted 后是终态：所有订阅结束、不再重建、之后远程调用一律 unavailable、再次连接仍失败，客户端宿主要求重新加载。只重新调用 agent.sessions.create/subscribe 并不能修复该节点。
**为什么是问题**：后续实现若照对话 Spec 在同一 host 上自动重订阅，会持续失败，且依赖旧订阅的 activity 可能保留过时的 active=true。不能把“本页重连恢复”当成已有能力，也没有定义自动重载与本地状态、未确认写入、多个窗口之间的边界。
**如何核实**：对照上述两个 Spec 和 packages/nb-runtime/src/remote 的服务端进程标识握手实现；这是两份现行合同的直接矛盾，尚未运行浏览器或服务重启。用户禁止开发服务与 e2e，因此不以未运行场景声称复现。
**建议改法**：明确使用既有宿主的刷新/重新加载合同，或先改平台使节点支持安全重建；分别写明用户提示、重载后按当前窗口与位置恢复 sessionId、幂等 commandId 重试以及 activity 状态清理。验收应从 server-restarted 到真实宿主终态再到重新加载后的完整会话恢复，不只在同进程假断线中重新订阅。
