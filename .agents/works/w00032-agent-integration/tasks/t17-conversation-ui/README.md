## 决定（开发者 2026-10-30 同意，方向）

已知情况：对话视图在 nb-agent-ui 已有 Spec [`ui/agent-conversation-view.md`](../../../../../docs/specs/ui/agent-conversation-view.md)（planned）；消息流与输入框在 w00019 做完，顶栏、状态栏、待处理区、提问向导、面板与弹窗没做（w00019 t11，并入本 Task）。工作台视图（[workbench.views](../../../../../docs/specs/workbench/views.md)）给默认位置，用户可拖到别处。

1. 落位：对话是一个工作台视图，默认在右栏，一个视图显示一个当前会话。编辑区标签里开会话先不做：`editor.pages` 只能按页面 id 开一个、不带参数；以后要同时看两个会话时再给它加参数。
2. 切换会话：点顶栏标题弹出会话列表（`AgentSessionList`），新建在顶栏；列表默认当前项目的会话、可切到全部（t03 决定 4）；归档、恢复、改名在列表里。子会话（t14）不进列表，从父会话的子代理卡片进入，子会话顶栏有回到父会话的入口。每个窗口各选各的当前会话，两个窗口开同一会话看到同一份。
3. 标题：第一轮结束后用 tiny 角色生成，用户改过的不再自动改；旧应用每 16 次调用重写标题与摘要的做法不搬。（2026-10-30 t18 改：标题与一句说明一起生成，说明供会话列表第二行与顶栏悬停，压缩后更新，见 [t18](../t18-builtin-profiles/README.md) 决定 1。）（2026-11-05 t18 定：tiny 没绑时用第一句话的前 30 个字符作兜底标题、没有说明；新建会话默认 `nbook.agent.main`，菜单不列目录里 `hidden` 的 Profile，见 [t18](../t18-builtin-profiles/README.md)。）
4. Profile：新建会话时选（只有一个可用时不问），显示在顶栏；会话中途不提供换 Profile 的入口，Profile 自身更新按 t04 决定 6。
5. 模式：工具栏一个按钮显示 Agent 模式（t06 决定 2），点开菜单分 Agent 模式与审批模式（t06 决定 1）两组；Shift+Tab 只循环 Agent 模式；审批模式不是默认值时在状态栏标出，“全部放行”用警告色。Spec 现在只有 Agent 模式按钮，要改。
6. 附件：按内容哈希存进 `session://attachments/`，不放项目里；图片交给模型、文件给路径（Spec 已定）；最多 8 张、单张 16 MB（沿用旧应用）。
7. 触发符：`/` 斜杠命令（t10）、`$` Skill（t15）、`@` 引用（t10），第一版 `@` 只列项目文件与章节；第一版内置斜杠命令 `/new`、`/compact [要求]`、`/fork`、`/rename`、`/model`。
8. 草稿：按会话存在浏览器本地，10 条、30 天过期（沿用旧应用）；另一个窗口看不到草稿，接受。上方向键调出的已发送内容取自会话日志。
9. 审批与提问：等审批的调用与会让运行停下的提问都用提问向导替换输入框（t14 已把两者合成一条通道），审批显示 diff，子会话冒泡来的标明来源；不停下运行的提问是对话里的卡片（t14 决定 30）。待处理区第一版只放排队消息（t07）；“上次运行被中断 · 继续”（t07 决定 7）放输入框上方的横幅。Workflow 待回答（t24）、工作区变更（t13）、后台任务（t22）随各自 Task 再接。
10. 状态栏：上下文占用（点开上下文检查器）；累计 tokens 与费用（单价未知不显示费用，为 0 显示“免费”，t09 决定 7）；运行阶段（含“正在压缩”，t11）；非默认模式的标记。上下文占用的口径（w00019 t13 转来）：最近一次模型回复的输入、缓存读取与缓存写入之和，即下一次请求至少要带的量；实施时对照 omp 核实。
11. 视图不在眼前时：工作台状态栏加一个 Agent 条目（`workbench.statusbar-items`），显示运行中与等你处理的会话数，点击打开对话视图并切到那个会话。通知中心与系统通知以后（[workbench.notifications](../../../../../docs/specs/workbench/notifications.md) 的非目标）。
12. 第一版的面板与弹窗：会话列表、分支树（t03 的回退与分支要用）、简版上下文检查器（只显示组成，系统提示词的查看并进来）。附件面板、“关联 Agent”（由子代理卡片与父会话入口代替）、缓存时间线不做。
13. 出稿：落位、顶栏与会话切换、输入框工具栏（模式菜单）、审批向导、状态栏按 design-review 在 Lab 出静态稿评审。界面文字的写法等 w00028 t03 合入，不影响出稿。

## 新内核的消费面（t20 深入审查）

t20 实现的深入审查（[处置](../t20-hooks/evidences/deep-review-disposition.md)）用 Sonnet 对照 nb-agent-ui 适配器的需求，看了新内核推出的帧与日志查询。内核这边已经改了：中止时半截回复进日志；增量带用途、按订阅者编号；被过滤的事件推 `progress`；等用户的事项不带原文；过滤器有上下文。下面这些要等视图改接新内核时，按真实用法在内核里补（Sonnet 报告的条目号见处置表）：

- 正在生成的那条：刷新后补发已推出的前半段（F5）；`toolArgs` 增量带工具名（F8）；过滤后一次请求的流结束信号，以及怎样对待找不到调用的工具事件（F17）；过滤队列的背压（F16）。
- 首屏与重连：原子的订阅起点（例如 `subscribe(listener, {afterSeq})`，F6）；向前翻页、按事件类型筛、字节上限（F10）；`path()` 分页、`log()` 带叶子、过滤后 `parent` 链断开的处理（F9）。
- 状态：逐个工具调用的结束帧（F4）；异步提问与暂停的运行进快照（F14）；附件的名字与大小、上下文用量（F15）。

## 注意力排序（开发者 2026-11-05）

右栏里从高到低：等你处理的事（审批向导，替换输入框）、消息流、输入框、运行状态（只在运行中）、顶栏（标题加 Profile 名）、上下文和费用（一行小字，快满时变色）。说明、费用明细悬停才看到；会话列表点标题才弹出；审批模式只有非默认才标；工作台状态栏条目空闲时不显示。

1. 状态栏是输入框下面单独一行细条。
2. 审批的 diff 太长时，向导最高占视图的 60%，diff 在内部滚动，消息流留在上方。
3. 几个审批逐个处理，向导标“第 1 / 3 个”，不加“全部同意”。

## 横屏与低代码（开发者 2026-11-05）

1. 第一版不定横屏方案。现在是竖屏视图；应用也可以做成 Agent 模式（活动栏的一个标签放会话列表，中间是对话，右栏是文件和正文），开发者不要求一定这样，关键是注意力排序：对话是注意力很频繁的位置，放右栏可能有问题。[w00026](../../../w00026-layout-package/README.md)（布局包）还在规划中，等它做完再考虑，开发者要亲自体验、慢慢调整。
2. 第一版为此只做三件事：对话的逻辑与摆放位置分开；多贡献一个编辑区页面“Agent 对话”和一个放会话列表的侧栏视图；默认位置还是右栏，不做一键切换与预设。
3. 低代码就是 nb-form。
4. `ask` 进第一版，和权限审批一样走同一个向导（改第一版范围）。内核与工具这边都要新做：`ask` 工具、`ToolContext.ask` 现在都没有。
5. 模型可以出表单（`ask` 的参数带 schema，过 nb-form 的 Agent 策略）；也可以配置成像 Claude Code、omp 那样用固定的 schema，声明更短、省 token。
