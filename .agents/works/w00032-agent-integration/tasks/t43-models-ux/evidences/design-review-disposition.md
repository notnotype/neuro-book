# t43 计划设计审查的处理（第 1 轮）

审查对象：`plan.md` 提交 `f7aba6415` 的固定副本。三位审查者同时审：omp（后端与计划，默认模型）、Claude Sonnet（前端）、Claude Sonnet（拉远看，只审方向）。报告原文：[`design-review-omp.txt`](design-review-omp.txt)、[`design-review-sonnet-frontend.txt`](design-review-sonnet-frontend.txt)、[`design-review-sonnet-zoomout.txt`](design-review-sonnet-zoomout.txt)。

归类按 reviewing 的“处理结果”：说明没写清 / 成立要改 / 成立但接受取舍 / 不成立；要开发者定的单独标出。

## 拉远看（Sonnet，7 条：重要 4、建议 3）

| 条 | 归类 | 处理 |
|---|---|---|
| 1 `proxy: false` 已能强制直连，中继只剩 SOCKS5 | 成立，**交开发者重定决定 18** | 主 Agent 复测：环境 `HTTPS_PROXY`、`HTTP_PROXY` 指向死端口时，`proxy: false` 对 http 与 https 都直连（Bun 1.4.4）。推荐第一版不做中继：跟随系统与自定义用 `proxy: <url>`，直连用 `proxy: false`，SOCKS5 拒收并提示用 HTTP 混合端口；`engines.bun` 抬到 1.4.3；断言 pi-ai 设了 `PI_PROXY` 时 `proxy: false` 仍直连 |
| 2 出口放在应用插件；与 models 互相依赖；“应用级”只接模型请求 | 成立，要改（范围一项交开发者） | 出口规则、系统代理读取与 `fetchFor` 放与应用无关的模块（nb-host 的子路径），`nbook.network` 只剩设置与页面；入口级依赖写清（models 后端 → network 服务，network 网页 → models 远程合同，不成环）。web-tools 的两个 provider 已收可注入的 `fetch`，是否一起接（改决定 5 的范围）交开发者 |
| 3 来源里没了的模型被引用时应仍可解析 | 成立，要改 | 被启用或被角色引用的模型从来源消失时，沿用上一次物化的 `Model` 继续可调用，快照标 `missing`，用户在界面上移除；只有来源请求失败才标 `stale` |
| 4 配置 v2 单向迁移，降级时整键丢弃 | 成立，**降级策略交开发者** | 推荐不为降级做新旧键并存（预览版、窄场景），发布说明与 Spec 兼容节写明“装回旧版会丢服务商与角色设置”；`icon.image` 上限降到 16 KB；关掉“自动加入”的冻结与再打开的往返写进 Spec |
| 5 范围太大，按根因、网络、推理档加选择器拆开 | 成立，要改 | 不另建 Task，计划改成三段，每段单独合入、单独实现审查：A 推理档与选择器（旧形状上加可选字段即可先行）、B 服务商模板化与模型来源（含设置页）、C 网络与代理 |
| 6 `os-proxy-config` 带原生模块、两个平台无法验证 | 成立，要改 | 不引依赖：启动环境变量，加各平台命令行读法（Linux `gsettings`、KDE 配置，macOS `scutil --proxy`，Windows `reg query`）；Windows 在 pc-notype 上验证，macOS 标未验证 |
| 7 取舍没集中讲，缺 ADR | 成立，要改 | 计划加“取舍”一节（模型清单的真相源、`Model.provider` 规则与不上游改的理由、出口的 owner）；新增 ADR 记决定 1 与这三条 |

## 结论

计划不能小修后实施。前端与方向审查的问题大多可直接改；后端的问题集中在“模型来源”这一块：直接套用 OMP 的目录工厂与 `ModelManager`，带进了缓存身份、认证、地址覆盖、部分失败、更新时间、分类等一串问题（第 5、6、13、22、23、28、30 条）。改为：OMP 只当静态元数据（打包目录加在线目录）与请求传输，发现与缓存由我方按实例的有效协议、地址、认证来做。另外模型身份（第 7、24、25 条）要改内核的会话日志。

计划改成三段，各自单独写计划、审查与合入（交开发者确认）：A 推理档与选择器（含 nb-ui 与角色页），B 服务商模板化与模型来源，C 网络与代理。
