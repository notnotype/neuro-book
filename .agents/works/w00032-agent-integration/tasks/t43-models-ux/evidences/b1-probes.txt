2. 会按环境变量改址的 pi-ai 分支
   - pi-ai/src/providers/openai-shared.ts:274-277 MOONSHOT_BASE_URL；connection-prewarm.ts:23 还提到 XAI_BASE_URL；
     anthropic-http-options.ts:140 ANTHROPIC_BASE_URL。
   - 实测（wire.ts）：moonshot 模型 baseUrl=<端点>/v1 时实收 /v1/chat/completions；
     设 MOONSHOT_BASE_URL=<同主机>/other/v1（只改路径）实收变成 /other/v1/chat/completions；
     设成 localhost（换主机）实收打到 localhost/zzz/v1。即环境变量会把已配置的地址整体改掉，含只改路径的情形。
   - 结论：B1.3 的出站核对必须比完整线地址（不只比源），已按此实现（nb-harness models/target.ts 的 wireGuard）。

3. OpenRouter 的线协议
   - 打包目录里 OpenRouter 对话模型的 api 是复合的 "openrouter"（588 个；另有 video、images、embeddings、rerank 等非对话行）。
   - pi-ai/src/stream.ts:925、1759、2008：PI_OPENROUTER_RESPONSES 不为 "0" 时走 /responses，为 "0" 时走 /chat/completions。
   - 实测：api=openrouter 缺省实收 /api/v1/responses，设 PI_OPENROUTER_RESPONSES=0 实收 /api/v1/chat/completions；
     显式 api=openai-responses 在 PI_OPENROUTER_RESPONSES=0 下仍是 /responses，显式 openai-completions 仍是 /chat/completions。
   - 结论：物化时把 "openrouter" 换成显式协议，线协议不随环境变量漂移（nb-harness models/catalog.ts）。

5. 中性身份四种协议的实收（wire.ts，baseUrl=<端点>/gw/v1）
   - openai-completions → /gw/v1/chat/completions，Authorization: Bearer
   - openai-responses   → /gw/v1/responses，Authorization: Bearer
   - anthropic-messages → /gw/v1/messages，Authorization: Bearer（中性身份下不是 x-api-key）
   - google-generative-ai → /gw/v1/models/m-1:streamGenerateContent?alt=sse，x-goog-api-key
   wireGuard 按这几种后缀与查询参数核对完整地址。

6. 库自己的请求构造做协议检测（B2 用的小实验，部分完成）
   - 同一脚本里假端点回 500、选项给了 maxHttpAttempts: 1：completions 与 google 各实收 1 次，
     responses 实收 6 次、anthropic-messages 实收 11 次（库在内层自己重试，maxHttpAttempts 没挡住这两种）。
   - 结论：检测不能指望关重试，要在注入的 fetch 里拿到第一个请求就中止（或直接回应、不放行），确认恰好一次 HTTP。
     “抓第一个请求后中止”本身还没写成实验，留到 B2.3 先做。
