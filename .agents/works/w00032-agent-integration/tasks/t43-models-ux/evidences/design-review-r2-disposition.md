# t43 计划设计审查的处理（第 2 轮）

审查对象：`plan.md` 第二稿（提交 `014cea7a2`）。后端与计划：omp 默认模型，38 条（阻断 3、重要 33、建议 2）；前端：Claude Sonnet，14 条加 1 条核对说明（重要 6、建议 8）。报告原文：[`design-review-r2-omp.txt`](design-review-r2-omp.txt)、[`design-review-r2-sonnet.txt`](design-review-r2-sonnet.txt)。两份到齐后一起归类；处理写进计划第三稿。

## 总体判断

52 条里没有推翻开发者已确认的决定 1–24。问题集中在两处：

- **段 B 的来源与缓存**（omp 第 3 到 11、17 到 19、22、25、26、30、32、33、35 条）。第一轮把“直接用 OMP 的 `ModelManager`”改成自己做列表、缓存、协调器，新增的自有机制又各带一批边界。本稿的处理是**删机制、不再补边界**：删掉 `retired`（成员行自带物化字段与 `missing` 标记）、删掉“列表协议与推理协议联动”（模板分开声明）、不复用上游取目录函数（自己取并管 ETag）、地址与凭据在最内层发送前核对（一处管 omp 第 1、25 条）、不设“跟随”的活合并之外的第二套状态。
- **出口的重定向**（omp 第 2、24 条）。第二稿让出口包装自己跟随最多 5 跳，牵出探测次数、网页工具的 3xx 合同、请求记录与正文外泄四处问题。本稿**删掉出口里的重定向逻辑**：模型请求一律 `redirect: "error"`，列表与探测用 `manual`，网页工具保持现状，出口只管选路。

按轮数规则（同一对象最多三轮）：段 A、段 C 的改动是局部的，不再审计划；**段 B 的改动较多，开工前对第三稿的段 B 单独再审一轮**（只审段 B，后端 omp，前端一份 Sonnet），段 A 先开工。

## 交开发者知悉的取舍

以下由主 Agent 定，开发者没有异议前照做，都写进第三稿与 Spec：

- 服务商返回 3xx 时模型请求报错，不跟随（原写“最多跟 5 跳”）。
- “测试代理”访问 Cloudflare 的 `cdn-cgi/trace` 取出口 IP，并写进外联清单；旁路时不报“代理正常”。
- “检测协议”只测已保存的配置，改了地址要先保存。
- 本机与空白模板里类型不明的模型默认启用，云服务商的不启用。
- 思考档不加 `activation: "manual"`，方向键即选中。
