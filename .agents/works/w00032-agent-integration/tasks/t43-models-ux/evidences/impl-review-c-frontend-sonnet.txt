### 1. 地址框：别处改了地址后，失焦会用旧草稿写回去，Spec 说的“失焦后换成实际值”没有实现
**严重程度**：重要　**类别**：正确性 / 竞态
**位置**：NetworkPage.vue:59-91（urlFocused、watch(url)、urlBlur）；NetworkPage.md“交互”
**现象**：`watch(url)` 在框有焦点时直接忽略新值，没有像 ProviderDetail 的 `draftField` 那样记 `deferred`，失焦时也没有“换成实际值”这一步；`urlBlur` 先 `commitUrl()`。
**为什么是问题**：框里有焦点期间地址被别处改成 B（手改 settings.json、另一个窗口），用户没改字直接失焦：`commitUrl` 比较 `草稿(A) !== url.value(B)`，于是把 A 写回去，B 被静默覆盖。NetworkPage.md 明写“失焦后换成实际值”，实现里没有这一步，行为与文档相反。
**如何核实**：从代码推断。dom 测试补一条：focusin 后 `settings.update(proxyUrl, B)`，再 focusout，断言 `settings.get(proxyUrl)` 仍为 B、框里是 B。现有测试没有这条。
**建议改法**：记“草稿是否被用户改过”（input 事件置位），只有改过才 commit；失焦且没改过时把框换成 `url.value`。也可直接复用 ProviderDetail 的 `draftField`（把它抽到共用处）。

### 2. 写失败后框里仍留着没保存的地址（网络页与服务商代理都是）
**严重程度**：重要　**类别**：正确性 / 状态不一致
**位置**：NetworkPage.vue:43-49（write）、76-84（commitUrl）；ProviderDetail.vue:280-284（resetToken 的 watch 没有处理代理）
**现象**：网络页：`write` 失败只调 `reportWriteFailure`，`urlDraft` 不回到实际值；框里仍是没写进去的地址，下一次点“测试”时 `commitUrl` 因 `value !== url.value` 把它再写一次（可能再失败一次，再弹一条通知）。服务商详情：`resetToken` 的 watch 只重置 `keyField`、`urlField`，没有重置 `proxyDraft`、`proxyProblem`、`choosingCustom`；ProviderDetail.md 写着“写失败时……由页面递增 resetToken 通知”，代理这一项没做到。
**为什么是问题**：界面显示的地址不是生效的地址；Lab 里已有 `write-failed` 场景，但没有断言框里的字。
**如何核实**：从代码推断；dom 测试 `host.user.failWrites(...)` 后填地址、回车，断言框里回到旧值。
**建议改法**：`write` 失败（`!result.ok`）时把 `urlDraft` 置回 `url.value`（失败后焦点多半还在框里，也要处理）；ProviderDetail 的 resetToken watch 里加 `proxyField.reset(); proxyProblem.value = ""; choosingCustom.value = false`。

### 3. 状态变化基本没有动效，也没有尺寸稳定处理（决定 31、规范第 8 节“状态变化有动效”）
**严重程度**：重要　**类别**：动效 / 对照需求
**位置**：SettingsActionRow.vue:46-59、118-132；SettingsRow.vue 新增的 `.settings-row__below`；NetworkPage.vue:188-236；ProviderDetail.vue 代理地址框 `v-if="proxyMode === 'custom'"`；ModelRow.vue 新增的标
**现象**：新增与改动的文件里没有 `<Transition>`，也没有 `transition-*`（grep 只有 SettingsPageList 与 ProviderDetail 一处旧的 chevron）。逐项：
- 测试 / 更新状态行出现、消失、换内容：行高从 0 直接跳到 18px+间距，下面整个“模型目录”小组被顶下去，没有过渡。建议状态行做高度展开（`grid-template-rows: 0fr→1fr`，`--motion-move` + `--ease-layout`，显式列出属性），内容换文字用 `--motion-fast` 淡入。
- 代理方式下面的行下信息：同上，且 `v-if` 在插槽上，整块进出；用同一配方。
- 自定义地址行（SettingsRow）与“测试代理”行随方式出现 / 消失：整行蹦出。用 `<Transition>` 包行，高度 + 透明度，`--motion-move`（有高度形变）。
- ProviderDetail 的代理地址框、ModelRow 的“列表里没有”标：出现无过渡；标用 `--motion-fast` 透明度即可。
- “测试”换“取消测试”、“更新”换“更新中”：按钮宽度跳（文字 2 字 → 4 字、多一个方块图标），靠右排的按钮左缘移动；“更新中”也没有转圈。给按钮设 `min-width`（取两种文字里宽的），进行中的图标换成转圈（`--ease-loop`）。
**为什么是问题**：开发者反复指出“状态变化要有动效”；规范明文要求时长只用令牌。当前零处满足，且 Lab 场景（`testing`、`test-failed` 等）全是静态终态，看不出缺口。
**建议改法**：先在 SettingsActionRow 与 SettingsRow 的 `below` 各做一次高度展开，网络页的行用 `<Transition>`；`prefers-reduced-motion` 由令牌归零，不用另写。

### 4. 选“自定义”后立刻出现红字错误，焦点也不进地址框
**严重程度**：重要　**类别**：交互 / 对照需求
**位置**：NetworkPage.vue:101-114（summaryLine 的 `summary.error !== null` 分支）；NetworkPage.dom.test.ts:104-105；对照 ProviderDetail.vue changeProxyMode（有 `nextTick` 聚焦）
**现象**：点“自定义”→写入 mode→`describe()` 回来后，代理方式下面马上出现危险色的“代理地址不对：要是 http 或 https 地址，不带用户名密码”（测试 105 行把它当预期行为断言）。用户刚做完选择、一个字还没输就被报错；地址框出现后焦点留在分段控件上，要自己 Tab 过去。
**为什么是问题**：把“还没填”当错误报，是对用户自己动作的指责；同一个动作在服务商详情里是焦点进框、地址填好之前不写不报。决定 16 的静态稿没有这条红字。
**如何核实**：从代码与 dom 测试读出；Lab 场景 `custom-empty` 就是它。
**建议改法**：地址为空时行下不写错误（或淡色“还没填地址”），“测试”点下去再报；选“自定义”后 `nextTick` 把焦点放进地址框（保留键盘焦点在分段控件上的体验取舍：键盘用户用方向键切方式时抢焦点会打断，只在指针点击时聚焦，或同 ProviderDetail 的做法并在 Spec 里写明）。ProviderDetail 那边另有风险：Select 关闭后 Reka 会把焦点还给触发器，`nextTick` 的 focus 可能被盖掉（从代码推断，未验证）。

### 5. 地址格式错误只在标题后的小图标提示里，失焦后看不见
**严重程度**：重要　**类别**：可访问性 / 可发现性
**位置**：NetworkPage.vue:195-218（`:reasons` 传给 SettingsRow）；SettingsRow.vue:153-160
**现象**：`urlProblem` 经 `reasons` 变成标题“代理地址”后的一个 14px 图标，文字在 Tooltip 里，只有悬停或“控件有焦点”（`controlFocused`）时才显示；读屏用的是 `sr-only` 的一段，没有 `role="alert"`。回车报错时焦点在框里，提示会开；Tab 或点别处失焦后，提示收起，页面上只剩一个小图标，输入框的红边（`invalid`）是唯一可见线索。点“测试”时 `commitUrl` 报错并把焦点移回框，才会再看到文字。

**如何核实**：从代码推断；Lab 里往地址框填 `socks5://x` 后 Tab 走，看是否还有文字。

### 6. “更新”进行中按钮被停用：键盘焦点丢失，且测试与更新对 `writable` 的处理不一致、停用无理由
**严重程度**：建议　**类别**：可访问性 / 一致性
**位置**：NetworkPage.vue:226-236（测试按钮 `:disabled="!testing && !writable"`）、258-267（更新按钮 `:disabled="... || updating"`）
**现象**：(a) 更新进行中 `disabled`：焦点在按钮上的键盘用户，按钮一停用就失去焦点（Chrome 里 activeElement 仍指它但不再接收键盘，结束后也不会回来）；测试按钮专门做了“换文字不换元素、焦点不掉”，更新按钮没有。SettingsActionRow.md 写“点击、停用、进行中的文字都由调用方管”，两个调用方做法不同。（浏览器行为未在本次实测，按常见行为推断。）(b) `writable` 为假时“测试”停用，“更新”不停用；测试与更新都不写设置，停用测试没有可见理由（页面里没有“为什么不能用”的字）。dom 测试没有 `writable=false` 的用例。
**建议改法**：更新进行中用 `aria-disabled="true"` + 忽略点击（保留焦点，同“取消测试”的思路），加转圈；`writable` 为假时两个动作都可用，或两个都停用并写出原因，二选一并在 NetworkPage.md 的“状态”里写清。

### 7. 服务商代理：清空已保存的自定义地址再失焦，框是空的而生效的仍是旧地址
**严重程度**：重要　**类别**：正确性 / 状态不一致
**位置**：ProviderDetail.vue commitProxy（`if (value === "") { proxyProblem.value = ""; return; }`）
**现象**：服务商已是 `custom http://a`，用户把框清空后失焦或回车：`commitProxy` 直接 return，不写、不报、也不把框恢复。框里空着，生效的仍是 http://a。同一文件的 `commitUrl` 对空值是 `urlDraft.value = effectiveUrl.value` 复原。md 只写了“地址填好之前不写（停在‘自定义’）”，没有覆盖“已保存后清空”。
**为什么是问题**：用户以为清掉了地址（或变成了未设置），实际仍走旧代理；这是“看着是 A、实际是 B”的类型，且这是网络出口，影响请求去向。
**建议改法**：已保存的自定义地址被清空时，要么复原框（同 `commitUrl`），要么当作“回到跟随应用”写 `proxy: null`；在 md 里选一种写明。再补 dom 测试。

### 8. 回车后紧接失焦会重复写；重复失败会弹两条通知
**严重程度**：建议　**类别**：竞态 / 与相邻组件不一致
**位置**：NetworkPage.vue:76-91
**现象**：`@keydown.enter="commitUrl"` 之后用户 Tab 走：`urlBlur` 再调一次 `commitUrl`，此时第一次的写入还没回来，`url.value` 仍是旧值，于是再写一次同样的值。ProviderDetail 用 `draftField.claim`（`lastSent`）挡掉了这种重复，网络页没有。重复写成功时无害；失败时 `reportWriteFailure` 会被调两次，通知重复。`pending` 只记最后一次写入，前一次没被等。
**如何核实**：dom 测试：回车后立刻 focusout，数 `settings.update` 次数。
**建议改法**：与第 1 条一起处理：用 `lastSent` 或“草稿是否改过”（回车后清掉）挡住第二次。

### 10. 可访问性细节：说明区不是播报区、地址框的标签指向悬空 id、分段控件的名字
**严重程度**：建议　**类别**：可访问性

### 12. 时间不跟界面语言、与静态稿的相对时间不同；Lab 与真实选路有出入
**严重程度**：建议　**类别**：对照参照 / 一致性

### 13. 代码质量：校验规则三份、`sourceText` 兜底会写错来源、设置里的坏值路径没有验证
**严重程度**：建议　**类别**：代码质量
**位置**：NetworkPage.vue:68-75、94-99；ProviderDetail.vue validProxy；nb-host 里服务端同一条规则
**现象**：
- “http 或 https、无用户名密码”的判断在网络页、ProviderDetail、服务端各一份，注释写“服务端同一条规则”：规则一改就要三处同改。网络页和服务商详情至少该共用一个 `nbook/plugins/network/shared` 里的函数（两处都不依赖 DOM 类型，`URL` 是通用的）。
- `sourceText` 对 `direct`、`none`、`local` 这些 kind 都落到“来自自定义地址”。类型允许，当前路径碰不到（route 为 `bypassed` 且 source 为 `local` 时，测试目标是本机，生产里测试目标固定是 Cloudflare），但拿一个兜底把别的来源标成“自定义地址”，以后加来源会静默写错。用穷举的 `switch`，漏项交给 tsc。
- `proxyMode` 被手改成三种之外：我没有读 settings 服务对坏值的处理（未验证）；页面里 `mode.value` 若为未知值，`SegmentedControl` 无选中项、`mode !== 'direct'` 为真，会显示“测试代理”行；应确认服务回落默认值并有提示。`proxyUrl` 不合规（手改）时，自定义行直接显示该值，没有就地标红，只有行下选路的错误。
- ProviderDetail 去掉了“已改，模板是 X”：协议改离模板后，界面不再标出协议与模板不同（只剩 `overridden` 的“恢复模板地址”按钮针对地址）。后果的解释按决定 31 该删，但“与模板不同”本身是状态，可以保留成一个小标（同模型行的“已改”）；这是取舍，请开发者定。
**建议改法**：抽共用校验函数；`sourceText` 穷举；补坏值的 dom 测试。
