## 后端（omp，阻断 2、重要 6）

| # | 发现 | 归类 | 处理 |
|---|---|---|---|
| 1 | 回显的密钥绕过遮盖：JSON 转义形式、截在 8 KB 上的半个、夹着控制字符的 | 成立，要改（降为重要：攻击者是收到密钥的服务商本身，浏览器是同一个用户的） | `sanitizeProviderText` 先去控制字符再遮盖，原样与 JSON 转义形式都遮盖；检测留开头时多读一字节，截过时去掉末尾那半个密钥。`probe.test.ts` 的 400 回显（夹控制字符）与“密钥跨在原文上限上” |
| 2 | 不流式的 JSON 网关判失败；只报输出 token 的 SSE 被适配器空回复重发吃掉 | 前半不成立（对话也用不了不流式的网关，检测判失败是对的，Spec 草稿删掉这句承诺）；后半成立 | 检测给一个空的 `transport` 打开 `acceptEmptyResponse`，适配器不再按空回复重发，正常收尾报了输出 token 的（思考不外露）判通过。`probe.test.ts`“没交文字、正常收尾且报了输出 token” |
| 3 | 400 让 OMP 把请求全文写进日志目录，中止后的调用不经删除 | 成立，要改 | 非 2xx 在 `send` 里读完正文后抛中止错误，不再重建 400 交给适配器；文字里不带状态码（Gemini 的 SDK 从抛错文字里认出 `HTTP 400` 也会写盘，复测时发现）。审查者的 `probe-cases.ts 400`、`json-echo` 在隔离 HOME 下复测，四种协议都不再写盘（`bun test` 下 OMP 不写盘，没法进用例） |
| 4 | 流里报错后连接挂着：`tee` 的另一路不读、取消要等它，拖到 15 秒时限 | 成立，要改 | 去掉 `tee`：正文只有适配器一个读者，经过时留下开头（`recording`）。`probe.test.ts`“流里报错之后连接挂着，也按报错结束”（旧实现上 Anthropic、Gemini 两行 5 秒超时失败） |
| 5 | 混合协议的模板（OpenCode Zen）选回缺省协议即删覆盖，每个模型按目录各用各的协议，试的与写的都不是选的那种 | 成立，要改 | `withApi` 只对单一协议的模板恢复跟随，混合协议的总是钉成选的那种。前端结果是否有效补上“等于检测时的版本”这一条（前端第 9 条）。`models.test.ts`“混合协议的模板” |
| 6 | 连接版本不含模型级请求头与缺的环境变量 | 一半成立 | 缺的环境变量进连接版本（加在认证输入之后）。模型级请求头不进：协议是服务商级的选择，检测只拿一个模型做样本，换了某个模型的请求头不改变哪种协议能用；Spec 写明不含 |
| 7 | 凭据预检只看服务商级请求头，与发请求用的合并结果不一致 | 成立，要改 | 先选模型，再按与发请求同一份合好的请求头预检；没有模型时预检只看服务商级。`models.test.ts`“混合协议的模板”里的三步 |
| 8 | 检测行的 `baseUrl` 带用户信息与查询串 | 成立，但影响小（快照与地址框里本来就有同一个值、同一个浏览器）；改法便宜，照改 | 检测行的地址去掉用户信息、查询串与片段，请求照用完整的 |
