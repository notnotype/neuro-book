## 后端（omp）

| 条 | 结论 | 处理 |
|---|---|---|
| 2 列表错误正文进快照（可能回显密钥） | 成立 | 失败只按状态码写说明，正文不读、直接取消。用例：401 正文回显密钥，结果里没有 |
| 4 删 `discoverModels` 漏了 nb-story 的问答服务 | 成立 | 恢复 nb-harness 根入口的 `discoverModels`（只给 nb-story，模型服务走列表适配器）。之前把 nb-story 的 `serve` 用例失败当成 worktree 缺构建，实际是这个导入错误，记一笔 |
| 6 第一次拉取失败后改地址，后台仍带旧密钥去新地址 | 成立 | 记最近一次拉取（成功或失败）与读到的缓存的身份，自动拉取只给从没拉过或身份相同的。重启后只看缓存：失败过又改了地址、再重启的情形接受（同一密钥对话请求本来也会发往新地址）。用例（变异通过） |
| 19 清了密钥，在途的列表还会发下一页 | 成立 | 每页发出前核对身份；配置或凭据一变，服务核心作废快照时让身份不再相同的在途拉取立刻中止。用例：第一页不回、清密钥后照样收尾，下一页没发（变异通过） |
| 3 作废的结果仍可能写盘 | 成立，收窄 | 排到写盘时（队头）再核对身份；核对到改名之间只剩一次文件写，接受 |
| 7 设置读不到时只禁回收、没禁出站 | 成立 | 设置不可写时不出站：手动拉取为 `settings-unavailable`，后台检查跳过。用例（变异通过） |
| 1 云模板类型不明的模型“加入并启用”被当成冗余条目丢掉 | 成立 | 只有去掉条目后照样自动加入、启用也一样的才省略。用例：加入后在列表、启用、可用（变异通过） |
| 12 在线目录不逐行验证 | 成立，改法不同 | 逐行验：窗口与上限要正整数，原文价目要是非负有限数，id 有界；不合格的行丢掉、其余照收（整份拒收会让一行坏数据挡住全部新模型）。用例 |
| 9 坏分页信封当成成功短表 | 成立 | Gemini 的错误信封、无关对象、非字符串游标，Anthropic 非布尔的 `has_more` 都是 `bad-response`；`{}` 仍是空表。行数上限按原始行算。用例 |
| 11 外部名称能冲过 RPC 帧 | 成立 | 列表与在线目录的名称截到 200 个字符 |
| 18 Gemini 图片模型被列表标成对话模型 | 成立 | 目录认得这个 id 时以目录为准，目录说不是对话模型的不收。用例（变异通过） |
| 8 Anthropic 换了认证头仍判为同一凭据 | 成立 | 凭据按真正发出的头算。没有单独的用例：要跟随模板的真实地址才走得到，逻辑只有一处 |
| 5 关掉自动加入把缺窗口的写成启用 | 成立 | 冻结时记实际启用与否；重新打开时按“与缺省相同”判纯冻结条目。用例（变异通过） |
| 14 文件名按 uid 十六进制可超长；先建目录再查链接 | 成立 | 服务核心给定长键（`uid` 的 SHA-256 前 32 位），文件里存原 `uid`；建目录逐段核对、不在链接指向处建；暂存文件随机名排他创建。用例：`agent` 是链接时目标目录里什么都没建 |
| 17 30 秒截止不覆盖写盘、写盘卡住时收口不完 | 成立，部分 | 写盘前过了截止就按超时丢弃；停止时在途请求与写盘一起至多等 2 秒。已开始的文件写本身取消不了，接受 |
| 10 普通测试里的服务端仍会去取真实的在线目录 | 成立 | Bun 测试预加载把 `NBOOK_MODELS_CATALOG_URL` 缺省设空（进程内与子进程的服务端都覆盖）；模型场地也设空。补了真实设置下“自动更新开时设密钥就拉、关时不出站”的应用级用例 |
| 15 `refreshSource` 会写缓存却声明成读 | 成立 | 改为 `write` |
| 20 兼容服务的列表信封不再认 | 成立 | 认 `data`、`models`、`result`、`items` 与顶层数组 |
| 13 Cloudflare 改写过 id 的在线行价目变未知 | 成立，接受 | 只影响一家网关、改写 id 的新行，价目显示“未知”不出错；要保留映射前的出处得改 OMP 的映射函数，记为已知限制 |
| 16 `304` 用内存副本刷新 | 不改 | 内存副本是验证过的同一份正文，用它重写文件没有坏处；计划里“本地文件可读”的字面要求按此理解 |
| 21 单家状态变化重算全部服务商 | 接受取舍 | 常见规模（几家、几百个模型）下只是几次映射；真慢时把状态与行版本分开失效 |
