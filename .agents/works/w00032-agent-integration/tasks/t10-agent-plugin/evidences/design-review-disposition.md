# t10 设计审查的处置

审查：omp（默认模型），对象 `plan.md` 第一稿（master `3961ef6e2`），报告 [`design-review-omp.txt`](design-review-omp.txt)。20 条：阻断 4、重要 16。逐条对照代码核实，全部成立，按下表改进计划（第二稿）。

| # | 级别 | 问题 | 核实 | 处置（计划的节） |
|---|---|---|---|---|
| 1 | 阻断 | Profile 写了 `tools` 时内核滤掉绑定加的工具 | `run/tools.ts` 的 `current()` 确有二次过滤 | 改内核：宿主的声明是最终工具集，`required` 只判缺失（3.1 第 1 条） |
| 2 | 阻断 | `profilesChanged` 借扩展通知不会重新解析 Profile | `reassembleNow` 用 `core.assembly.profile`，同哈希直接返回 | 新的内核操作：重新 `resolve`、同哈希也换对象（3.1 第 2 条） |
| 3 | 重要 | 平台接收者与内核接收者的对接没写清 | 内核 `revoke` 已会删预占；撤回原因内核不用 | 适配器：`WeakMap` 一对一、原因映射、`prepare` 抛错的回滚（3.3） |
| 4 | 重要 | 声明保留时内核不释放已建的工具实现 | `ToolBox` 按 id 缓存，`retire` 只看声明 | 宿主的工具包装：撤回作废这一代、执行中最多等 5 秒、之后释放（3.3） |
| 5 | 重要 | `onAgentSession` 只激活声明了它的入口；与 `agentKey` 成环 | 平台按声明激活；激活环得 `unavailable` | 提供方必须声明、不能依赖 `agentKey`，失败写诊断、装配按缺依赖处理（3.3、4） |
| 6 | 重要 | 只触发一次，晚登记的提供方漏掉 | 事件不回放给后登记的入口 | 每次建或开会话前触发（3.3） |
| 7 | 阻断 | 句柄的打开、关闭与空闲计时没有并发控制 | `AgentHost` 的 Map 只存完成的句柄 | 自己的句柄表：三态、共享 Promise、引用计数、串行段里重查（3.5） |
| 8 | 重要 | 停止没覆盖打开中的会话与停止期间的新调用 | `onStop` 不自带排空门 | `stopping` 门：关门、等已接纳的、再关闭（3.2） |
| 9 | 重要 | 远程方法没用调用方身份视图 | `as(issuer)` 是唯一切换身份的入口 | 远程一律用户视图；会话身份只经同进程（3.5） |
| 10 | 阻断 | `startTask` 是写操作却没有幂等键 | 通道写请求可能 `unknown-outcome` | 调用方给 `taskId`，作会话 id 与 `send` 的 `commandId`（3.6） |
| 11 | 重要 | `project` 调用方可指定任意项目 | 调用方身份不带项目 | 合同只给浏览器；项目实例要用时另加校验（3.5） |
| 12 | 重要 | 失败码不能原样透传 | 合同按方法定义码与详情 schema；通道码保留 | 按方法列码与详情、通道码不进表、类型对照测试（3.5） |
| 13 | 重要 | 大查询与大帧超过 1 MiB 消息上限 | 通道单条消息 1 MiB | 按字节分页、大事件换占位并分段读、增量切块（3.5） |
| 14 | 重要 | 合并与内核按订阅者编号的关系没写 | `n` 是内核订阅者局部的 | 每个远程订阅一个内核订阅，合并后重编号（3.5） |
| 15 | 重要 | 会话头没有 `background` | `SessionHeader` 没这个字段 | 内核会话头与列表加可选字段（3.1 第 3 条） |
| 16 | 重要 | 用户 Profile 不能直接用第三方装载器，且与“不运行期编译”冲突 | 装载器输入是已安装插件 | 自己的装载器、共用外部导入检查；Spec 写明受信例外（2、3.4、4） |
| 17 | 重要 | 内容哈希没进内核版本，改动可能不可见 | 内核哈希只算 id 与 version | 生效版本 = 自写版本 + 包哈希（3.4） |
| 18 | 重要 | 监听与打包的并发没有状态机 | `fs.watch` 事件不一一对应 | 每个 Profile 一个状态机、代次丢弃、原子发布、失败保留旧包（3.4） |
| 19 | 重要 | 验收表缺高风险的失败与竞态 | 第一稿第 6 节确无这些行 | 补测试行，全部走真实远程链路（6） |
| 20 | 重要 | `startTask` 没有原子的“建并发送” | `send` 空闲时同时开始 | 建会话（`session-exists` 时打开）加一次带 `commandId` 的 `send`（3.6） |

审查者没有逐条列出的“未发现问题的方面”：报告在第 20 条后结束。
