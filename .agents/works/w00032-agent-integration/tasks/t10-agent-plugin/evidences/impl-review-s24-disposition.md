# t10 第 2–4 片实现审查的处置

审查：omp（默认模型），对象第 2–4 片（`61358c890`、`f21519330`、`68eb38df8`），报告 [`impl-review-s24-omp.txt`](impl-review-s24-omp.txt)。16 条：重要 15、建议 1。逐条核实，全部成立，修正在 Work 分支 `c781c3d14`。

| # | 问题 | 处置 |
|---|---|---|
| 1 | 工厂建实现时运行已中止，迟到的实现照样执行 | 建好之后、执行之前复核中止、撤回与会话关闭，任一成立就不执行 |
| 2 | 停止时还在建的会话漏关、锁不放 | 建会话与发起任务整段登记为在途，停止关门后先等它们登记完再关 |
| 3 | 工厂挂住时撤回的 5 秒上限不生效 | 一次调用从等工厂起整段算进在途、与撤回的 5 秒竞速；释放不等挂住的工厂 |
| 4 | 远程输入只核对是对象 | 用户的话、附件、回答、设置补丁按结构校验；只有 `payload`、`data` 是自由 JSON |
| 5 | `path` 等聚合结果超过 1 MiB | `path` 分页；页预算算上外层开销；不分页的结果超限得 `result-too-large` |
| 6 | 诊断分页不前进、筛选失效 | 内核 `diagnostics()` 按参数过滤（根因在内核）；远程按诊断 id 游标分页、长文字截短 |
| 7 | 订阅打不开的会话被吞掉 | 远程订阅等会话真的打开，打不开就以失败结束；同进程的订阅写诊断 |
| 8 | 同进程服务停止后仍返回成功 | 服务的每个入口先过停止门 |
| 9 | 每次工具调用永久登记撤回回调 | 调用结束时移除它的回调 |
| 10 | 首次打包期间依赖变化没让结果作废 | 打包一成功就记下用到的文件并监听；打包期间的变化都让这次作废 |
| 11 | 首次打包失败后修好依赖不重试 | 失败的 Profile 在它关心的目录有变化时重试 |
| 12 | 计算出来的裸导入绕过检查 | 包里有变量作说明符的导入就以 `module-not-shared` 失败 |
| 13 | 发布者叫 `user` 的插件的 Profile 被路由到用户层 | 来源按登记判定；用户 Profile 撞上插件的 key 标不可用 |
| 14 | 纯度名单漏了 nb-harness | 平台档案的宿主包加 nb-harness，直接导入时提示改用 SDK 的 `/agent` |
| 15 | 失败详情共用任意对象 schema | 按内核 `CommandErrorDetails` 逐码写详情，没有详情的码不收；类型层对照输入与详情 |
| 16 | 状态根经过符号链接时旧包的模块缓存删不到 | 缓存目录启动时换成真实路径 |
