# 设计与调研

## 目标

在写实现代码之前，把智能输入法 spike 的需求、功能边界和关键技术方案调研清楚，形成可由开发者逐项裁决的设计。本 Task 不写产品代码；必要的小型可行性测量（例如 Jev 延迟）需在报告中标明为测量脚本。

## 待讨论清单

按依赖顺序排列，前面的结论会影响后面的设计。

| # | 议题 | 要回答的问题 | 状态 |
|---|---|---|---|
| 1 | 需求与验收 | 「写起来舒不舒服」如何观察：首选命中率、专名命中率、每字按键数、候选延迟、主观记录各用什么口径；spike 的用户就是开发者本人还是要给别人试 | 待讨论 |
| 2 | 功能范围 | 第一版包含哪些：全拼、简拼、双拼、模糊音、整句、联想、标点与中英混输、候选翻页、用户造词；哪些明确不做 | 待讨论 |
| 3 | 拼音解码方案 | 自研 TS 解码器、librime 编译到 WASM、移植 libime 思路三者的取舍；切分、词图、语言模型、用户词库各层的实现方式 | 调研中 |
| 4 | 词库与语言模型数据 | 基础词库和字词频来源、授权（GPL 能否打包）、体积与加载时间、n-gram 阶数与平滑方式 | 待调研 |
| 5 | 实体提取 | 造词信号、新词发现统计、模型分类三路信号如何合并；读音来源；用户确认交互；权重随章节衰减规则 | 待讨论 |
| 6 | 上下文重排（Jev） | 放在按键回路还是提交后联想；请求时机、去抖、过期丢弃；候选位的稳定性规则；中文效果和延迟实测 | 待测量 |
| 7 | 语音输入与纠错 | 识别服务选型（云端或本地）、热词注入、deepseek-flash 纠错提示词与「只纠错」的结构约束、diff 确认交互 | 待讨论 |

| 9 | 包结构与接口 | 新 package 名称与边界（引擎无界面、playground 独立）；写作上下文提供者接口；以后接 NeuroBook 的替换点 | 待讨论 |
| 10 | 数据与隐私 | 正文发往 Jev 和 flash 模型的范围；本地缓存与日志落点 | 待讨论 |
