### 1. 表情节点紧挨字母或数字时写不出：在中文里打字就会触发“写不出”，保存被挡
- **严重程度**：阻断；**类别**：不变量
- **位置**：stickers.md:70（边界规则）、:116（输出 18）；plan.md:38（写法“原样写 raw”）、:40（不变量）、:65（切片 1）
- **现象**：Spec 规定开头的 `:` 前面、结尾的 `:` 后面不能是 Unicode 字母或数字。写法由 `writeInline.sticker` 原样写 `raw`，节点不能被转义。编辑器里节点前后一旦紧挨字母或数字（中文每个字都是 `\p{L}`），写出的文字读回就不再是节点。
- **为什么是问题**：降级阶梯（`codec/write.ts` 的 `LADDER`）四级只改转义、写法与 `<strong>`，对原样写出的节点都无效，最后是 `unrepresentable`，编辑器进入 workbench.editor 输出 61 的“写不出”状态，保存被挡。触发路径都很日常：在刚打出的 `:开心:` 后面不空格继续打“今天”；在已有的节点前面补一个字；删掉节点与文字之间的空格；中文写作几乎不空格。
- **如何核实（已跑）**：`/tmp/review-w00050-t02-design/lab-frontend/probe.ts` 用 nb-markdown 的真实 `createMarkdownLanguage` 与 `codecFor`，按 Spec 的边界规则实现了 `sticker` 节点（`marked` 行内扩展、`readInline`、`writeInline` 写 raw），`bun probe.ts` 的结果：
  - 段落 [文字“好”, 节点 `:开心:`] → `FAIL 各级写法都读不回来`；
  - [节点 `:开心:`, 文字“好”] → 同样 FAIL；
  - [文字 `:ab`, 节点 `:cd:`] → FAIL；
  - 中间有空格（`:开心: 好`）与节点挨节点（`:a::b:`）→ OK。
  把边界规则去掉（`STRICT=0 bun probe.ts`）后，上面三例都写得出（`好:开心:`、`:开心:好`、`\:ab:cd:`）。
- **建议改法**：二选一，改完补进验收：
  1. 去掉前后字符的边界规则（同 Discord）。认不出的写法本来就显示原文，误认只多出一个原子节点，代价由 plan 已接受的“未知名字也变成节点”承担。我跑的结果是 `a:b:c` 读成 `a`、`:b:`、`c`，显示仍是原文。
  2. 保留边界规则，但让写法在邻接字母数字时有可读回的写出（例如在节点与邻接文字之间插入空格并改变内容，不可取）。所以实际只剩第 1 种。
  另外，现在 Spec 的边界规则在读侧用“前一个词法单元的最后一个字符”判（同 `text-marks` 的 `previousChar`），在强调、链接文字这类嵌套分词里前一个字符是空串，所以 `很**:开心:**` 读成节点而 `很:开心:` 不是；`InputRule` 看的又是 `textBefore`（节点位置是 `%leaf%`），三处判断各自为政，规则本身就难保一致。

### 2. 方言与目录“晚到”是常态路径，不是少数：视图在建立时取定语言，晚于它的方言永远不生效
- **严重程度**：重要；**类别**：正确性
- **位置**：plan.md:38、:98（风险 2 “对话通常晚于它”）、:37；stickers.md:24、:124；markdown-syntaxes.md 输出 6、7；markdown-display.md 输出 1
- **现象**：计划只处理“浏览器目录晚到不重画”，没提另一层更根本的晚到：表情方言是 `nbook.stickers` 的浏览器入口经 `markdown.syntaxes` 交付的外来方言，`SyntaxCatalog.#load` 里要 `await handle.implementation().load()`（动态 import）之后才进 `active`。`languageFor(catalog)`（`language-registry.ts`）在视图建立时取 `active.value` 并锁定，展示器“挂上时取当时的语言，直到卸载都用这一份”。
- **为什么是问题**：窗口一打开就恢复上次的 Agent 会话，历史消息的 `MarkdownDisplay` 与方言加载、目录取回是竞争关系，没有任何顺序保证（`nbook.agent` 浏览器入口对 `markdownKey` 是必需依赖，对 `nbook.stickers` 没有依赖）。竞争输了：那一批展示器没有表情方言，`:开心:` 永远是普通文字，直到卸载重挂；目录晚到则是方言在、`lookup` 返回空，块不重画。Spec“已知限制”只写了后者，并且推断“窗口启动时就取，对话通常晚于它”没有依据，历史会话恰恰是启动时最早渲染的内容。
- **如何核实**：读 `web/language-registry.ts` 的 `languageFor`、`syntax-catalog.ts` 的 `#load`、`markdown-syntaxes.md` 输出 7；在 `late-dialect.dom.test.ts` 的做法上，让表情方言晚于展示器挂载交付，断言历史块仍显示原文（这条测试 plan 的验收映射里没有）。
- **建议改法**：这是上游选择的问题（plan 在迁就“外来方言经贡献点交出”）。候选：把表情写法做成 nb-markdown 的内置方言，节点、读写、静态视图、编辑器节点视图都放在包里，目录通过宿主端口 `resolveSticker`（形状同 `resolveAsset`，已有“读取中显示占位、读不到显示说明文字、卸载时释放”的现成生命周期，见 markdown-display.md 输出 4、8 与 `MarkdownImage`）交进来；这样方言从第一份语言起就在，目录晚到是端口自己的状态，不是“块不重画”。代价：把一个 NeuroBook 专有写法放进已公开发布的包（nb-markdown 已有批注、双语这类专有方言，先例在）；外来方言机制不能被它第一个无标签用户证明。若仍走外来方言，至少要：让展示器等待表情方言就绪再取语言，或交付顺序由 `nbook.agent` 对 `nbook.stickers` 的声明依赖保证，并把这条竞争写进验收。

### 3. “普通文字里的 `:abc:` 没有退路”不成立，而且它的写回会把同一段里无关的字节一起改掉
- **严重程度**：重要；**类别**：正确性
- **位置**：plan.md:97（风险 1）、:38（InputRule）；stickers.md:116、:155（验收 4）
- **现象**：计划说“普通文字里打了 `:abc:` 又不想要表情时，没有退路，只能改写法（例如写成全角冒号）”。实际有两条路会让普通文字 `:abc:` 留在文档里：
  1. Tiptap 的 `InputRule` 默认 `undoable: true`，核心 `keymap` 把 Backspace 绑到 `undoInputRule`（`@tiptap/core` 的 `commands/undoInputRule.ts`、`extensions/keymap.ts` 第 14–16 行），刚转成节点后按一下退格就还原成文字 `:abc:`。
  2. 粘贴：纯文字粘贴不触发输入规则（输入规则只对打字触发），粘进来的 `:abc:` 留作文字。
- **为什么是问题**：编解码器对这种文字的做法是降级到第 2 级（`full` 转义）再逐个试撤，结果是 `\:abc:`，但整块同时降到 `canonical` 写法。我用真实编解码器验证：原文段落 `你好 _斜体_ 和 __粗体__ ，见 [链接](...) ...`，末尾追加文字 ` 新增` 写回是原样（只多一段）；追加 ` :abc: 新增` 写回变成 `你好 *斜体* 和 **粗体** ，见 ... \:abc: 新增`，`_斜体_` 与 `__粗体__` 被改写成 `*斜体*`、`**粗体**`（`probe2.ts`）。也就是 Spec 输出 18 的“编辑别处后写回仍是原文”对这种段落不成立，用户的作品文件里出现他没碰过的字节变化，同时新增了他看不懂的 `\:`。
- **如何核实**：`/tmp/review-w00050-t02-design/lab-frontend/probe2.ts`（先 `bun probe.ts` 会把 probe 的输出一起打出来，只看 `source:` 之后两行）。
- **建议改法**：
  - 风险 1 的说明改对：有退路（退格、粘贴），代价是整块降级；
  - 让文字 `:abc:` 不触发降级：节点的读法对写出的 `\:` 之外还有第二种保持原写法的路径，例如读法允许“`\:abc:` 形式的文字”原样保留；或者让输入规则与粘贴路径都不产生文字 `:名字:`（粘贴时 `transformPasted` 转成节点，退格还原成 `\:`）；
  - 验收 4 补两个用例：退格还原后写回的字节；段内有 `_斜体_` 时，只追加文字 `:abc:` 的写回。

### 4. “一段只有表情时显示大图”在编辑器里不会随旁边的编辑更新；展示器与编辑器是两套机制，外观一致无法保证
- **严重程度**：重要；**类别**：正确性
- **位置**：plan.md:38（`resolve` 标 `alone`、列入 `derivedAttrs`；节点视图“按所在段落现算大小”）；stickers.md:94（输出 8）、:116
- **现象**：计划给了两种算法：读入时 `resolve` 给节点标 `alone` 属性（展示器用，`renderHTML` 只收节点），编辑器节点视图“按所在段落现算”。
- **为什么是问题**：
  1. ProseMirror 的节点视图只在节点自己变了（或装饰变了）时才被 `update`：`prosemirror-view/src/viewdesc.ts` 的 `findNodeMatch`/`matchesNode`，相同节点直接复用，不调 `update`。用户在只有一个表情的段落里往旁边打字，表情节点没变，节点视图不会重算，大图一直是大图，直到整段重读。反过来删光旁边文字也不会变大。
  2. `derivedAttrs` 的“写回被接受后按读回的值回填”是停手、失焦时才发生，不是每次按键；而且 `alone` 若是节点属性，回填会改节点、触发撤销历史与 dirty 判断，需要确认；若不是属性就没有 `derivedAttrs` 这回事。计划没有说选哪个。
  3. `resolve` 收到的是顶层块的 JSON；列表项、引用块、表格单元格里的段落要递归，计划没提。标题、单元格里只有一个表情时是不是大图，Spec 只说“段落”，也没说。
  4. markdown-display.md 输出 2 要求“展示器与编辑器生成的方言元素结构与类名相同”，现在是两处各画，没有说明共用一个构造函数（nb-markdown 的提示块、图片是 `buildCallout` 这类共用外观函数）。
- **如何核实**：编辑器 dom 测试：段落 `:害羞:` 渲染为大图后，在旁边键入一个字，断言节点元素的大小类名变了；再删掉，断言变回。按现在的设计这条会失败。
- **建议改法**：大小不要放进节点属性，也不要放进节点视图里现算；用一个编辑器插件给“只有表情与空白”的段落加节点装饰（类名），展示器在读入后给同一个 `<p>` 加同一个类名（展示器的 `renderer.ts` 已有读入后处理 DOM 的先例 `decorateLinks`），两边共用一份判断函数与一份 CSS。同时：写明列表、引用、单元格里按“最近的文本块”判；写明标题是否算。

### 5. 表情的 `<img>` 被核心的 Image 扩展认成图片：复制粘贴会把应用内部的取图地址写进作品文件
- **严重程度**：重要；**类别**：正确性
- **位置**：plan.md:38（`renderHTML` 画 `<img>`，没提 `parseHTML`、复制文字）；stickers.md:22（“从展示器里复制”列为不承诺）、:116
- **现象**：展示器与编辑器的元素是 `<img src=".../api/nbook.stickers/image/...">`。`language/syntax/core/index.ts:409` 配置的 Tiptap `Image` 的 `parseHTML` 是 `img[src]:not([src^="data:"])`（`@tiptap/extension-image/src/image.ts:118–123`），会匹配它。
- **为什么是问题**：
  - 从展示器（对话里）选中一段含表情的文字复制，粘贴进 Markdown 编辑器：HTML 剪贴板里是 `<img src=...>`，会被解析成图片节点，写回成 `![](/api/nbook.stickers/image/user.lyra/开心.webp)`，一个只在本机应用里有效的地址进了作品文件。编辑器内部复制粘贴同理（拖动、剪切再贴），除非表情节点自己的 `parseHTML` 规则优先级更高。
  - 编辑器里复制含表情的选区，纯文字剪贴板：原子节点没有 `leafText`/`toText`，表情在文字里是空的（`nb-markdown/src` 里没有任何 `leafText`/`toText`）。`transformPasted`/`clipboardTextSerializer` 计划也都没有提。
  - 可访问名称与“选中复制”：计划只写了“悬停提示 `:名字:`”（`title`），没写 `alt`。Chrome 复制含 `<img alt>` 的选区时纯文字里带 alt（Twitter、Discord 表情靠这个复制回文字；此条是依据习惯的推断，未在本机实测），所以 `alt=":名字:"` 同时给出了读屏名称和“复制得到原文”，Spec 的不承诺项（stickers.md:22）可以免费变成承诺。
- **如何核实**：编辑器 dom 测试：把展示器输出的 HTML 当作 `text/html` 粘贴，断言文档里是表情节点（原文 `:名字:`），不是 `image` 节点；编辑器内复制再粘贴同样断言。
- **建议改法**：节点的 `renderHTML` 带 `data-sticker="<raw>"` 与 `alt`、`title`，`parseHTML` 用 `img[data-sticker]` 并设高于 Image 的 `priority`；加 `leafText`（或 `toText`）输出 `raw`。把这三条写进 Spec 输出 18 与验收映射。

### 8. 读侧的边界规则让中文里不加空格的表情读不出，与仓库的 CJK 友好约定相反
- **严重程度**：重要；**类别**：正确性
- **位置**：stickers.md:70（边界）、:153（验收 2 只测了有空格的例子）；plan.md:38
- **现象**：规则要求开头 `:` 前不是字母或数字、结尾 `:` 后不是字母或数字。汉字属于 `\p{L}`。模型与用户写中文几乎不空格：`今天写完啦:开心:明天见`、`好的:害羞:`，开头、结尾的冒号都紧贴汉字，按规则一个都不是表情。验收 2 的示例 `今天写完啦 :开心: 明天见` 特意带了空格。我用同一套探路实现验证：`今天:开心:好` 读成纯文字，去掉边界规则后读成 `今天`、节点、`好`（`probe.ts` 的 read2、read3）。
- **为什么是问题**：`flanking.ts` 的约定是把汉字当作标点（CJK 友好，`==`、`~~` 都按这个），表情规则恰好相反。规则要挡的 `10:30:00`、`a:b:c` 本来就挡得住：表情名不能以数字开头，认不出的写法照原文显示，误认没有显示后果，只在编辑器里多出一个原子节点。规则收益是编辑器里少几个误节点，代价是中文场景下的主路径失效。
- **如何核实**：同第 1 条的 probe；也可对照验收 2 加一个不空格的用例。
- **建议改法**：与第 1 条一起去掉边界规则；若要保留一点防误认，只对 ASCII 字母数字生效（挡 `a:b:c`、`10:30`），且必须配套保证节点邻接 ASCII 字母数字时写得出（第 1 条），否则写不出的问题还在。待确认项“未知名字也变成节点”要在这个前提下才接受：现有中文文章里的半角冒号（`他说:你好:再见`）去掉规则后会在编辑器里变成两个原子节点，不能在里面改字，只能整体删。

### 9. 编辑器里创建表情的路径只有“打出半角冒号”，中文输入法下基本走不通；也没有补全、没有已有写法的编辑
- **严重程度**：建议；**类别**：正确性
- **位置**：plan.md:38、:96（不做：插入菜单与补全）；stickers.md:20、:116
- **现象**：`InputRule` 在 `view.composing` 为真时直接返回（`@tiptap/core/src/InputRule.ts` 第 105–107 行），中文输入法的标点默认是全角 `：`，`：开心：` 不匹配。要创建表情只能先切到半角标点再打，而且 Spec 同时把“插入菜单与补全”列为不做，作者没有任何看得见的入口，只能知道写法。
- **为什么是问题**：Spec 输出 9、18 承诺“作品文件在编辑器里同样显示成图”，作者是中文用户；能显示、几乎不能新建，只服务于模型写出的和手敲的少数情形。
- **建议改法**：本片不做补全也行，但在 Spec 的不承诺里说明“输入法下需要半角冒号”，别让这成为之后的验收缺口；或者补一个最小入口（命令面板的“插入表情”），它产生的节点不走输入规则，也避开第 3 条的退路问题。不要把全角 `：` 也当表情定界符：中文正文里 `说：你好：再见` 太常见。

### 10. 图片显示面没有尺寸与数量边界，图片地址不带版本
- **严重程度**：建议；**类别**：安全与性能
- **位置**：stickers.md:57（2 MiB、500 项）、:94（输出 8）、:147（路由）；plan.md:36–37、:103
- **现象**：
  - 清单只限制文件大小，不限制像素：一个 2 MiB 的 WebP 可以是数千像素见方，解码后几十 MB；展示器按 `2em` 显示，不会用缩略图。长对话里同一张反复出现不是问题（缓存），不同的几十张是问题。浏览器目录又一次带回全部包（至多 500 项乘包数）。
  - 动图（`.gif`、动画 WebP）在长对话里一直播；没有 `prefers-reduced-motion` 的处理（markdown-display.md 输出 7 对流式光标是有的）。
  - 一段只有表情时每个都是大图，没有数量上限（Discord 的放大规则有上限）：一行写 30 个表情就是 30 张 120 像素高的图。
  - 图片地址 `/api/nbook.stickers/image/<id>/<文件名>` 不带版本。现有图片（`markdown/web/parts/asset-urls.ts`）用 `files.rawUrl` 加 `?v=` 和文件监视，文件换了会刷新；表情是用户放在 `user://stickers/` 里、同名换图的场景，已显示的块不更新（Spec 已承认），之后显示的则取决于响应头，Spec 只列了 `ETag`，没有 `Cache-Control`。这条与后端审查重叠，只列前端后果。
- **建议改法**：清单校验加像素上限（读判型时顺带取宽高，例如 512 乘 512），并把宽高放进目录条目，`<img>` 写 `width`、`height` 属性避免加载时跳动；`loading="lazy"` 与 `decoding="async"`；动图在 `prefers-reduced-motion` 时不播（只显示首帧较难，至少文档说明）；大图规则加“至多 N 个，多了按行内小图”；URL 的版本问题与后端审查者的专用路由是否复用 `files.rawUrl` 一起定。

### 11. 写法的文法没有写全，`sticker-ref.ts` 与测试照字面写会各写各的
- **严重程度**：建议；**类别**：文档
- **位置**：stickers.md:63–71、:104；plan.md:31
- **现象**：
  - `:包/名字:` 里“包”这一段能含什么没有定义：输出 12 的最长写法是 `:表情包 id/名字:`，而 id 形如 `user.lyra`、`<插件 id>.<文件夹名>`，含 `.`；文件夹名规则（小写字母、数字、连字符）不含 `.`。
  - 名字“至多 32 个字符”按码点还是码元没说；名字里的字母没有规定 NFC：macOS 文件名是 NFD，清单里的名字与写法里的名字不同形时认不出，`:é:`、日文浊音都会遇到。
  - 名字区分大小写与否没说（文件夹名是小写，名字可含大写）。
  - 输出 5 “按文件夹名认到不止一个是认不出”，与“重名时 `:包/名字:`”的写法互相独立，但写法里的包段若同时是某个 id 又是另一个文件夹名，按 id 优先，这一点在两处写法判断（读侧、`InputRule`）要一致。
- **建议改法**：在 Spec 的“表情写法”里写出完整文法（包段字符集、名字按码点计、规范化到 NFC 后比较、大小写规则），`sticker-ref.ts` 的测试逐条覆盖；读侧、`InputRule`、槽里的“最短写法”三处共用 `sticker-ref.ts` 的同一个正则。

### 12. 验收映射的缺口
- **严重程度**：建议；**类别**：测试
- **位置**：plan.md:74–86
- **现象**：计划里每条测试都是“好路径”：新一行打出 `:害羞:`、读写字节不变。下列行为有设计、没有测试：邻接字母写回（第 1 条）、退格还原与粘贴（第 3 条）、段内编辑后大小更新（第 4 条）、HTML 粘贴往返（第 5 条）、方言与目录晚到（第 2 条）、展示器与编辑器同一份语料元素结构一致（markdown-display.md 验收 3 的同类，输出 2 要求）、图片读取失败显示原文（输出 7）、`check:dist`。
- **建议改法**：按这些补进验收映射的“方言的展示器 dom 测试”“方言的编辑器 dom 测试”两行；其中展示器与编辑器一致用同一份语料断言元素结构与类名相同。

## 未发现问题的方面
- 无标签的外来方言本身能走通声明与配对：`DialectDeclarationSchema` 的标签都是可选，内置的 `callout`（`{order: 20}`）已经是无标签方言；`syntax-catalog.ts` 的 `sameSet` 对两边都为空成立；`dialectTable` 的指纹只看标签，加一个无标签声明不改指纹，书架统计不会因此整轮重扫。
- 读侧的核心语法抢占：`marked` 的扩展分词规则先于内置分词，`createMarkdownLanguage` 按列表倒序登记（`language.ts`），外来方言排在核心语法之前；`text-marks` 的 `==` 已有“用前一个词法单元取前一个字符”的先例，实现方式可行（只是它的边界规则本身有问题，见第 1、8 条）。`http://` 的自动链接、行内代码里 `:名字:` 不被认，我读到的规则与探路实现的行为都没有发现抢占问题；没有逐一对 `emStrong`、`_` 强调边角做实验。
- 不编辑时字节不变（markdown-syntaxes 输出 8）：只要读成节点且写原样 `raw`，未编辑的块写原文，我没有发现不守的路径；编辑过的块的风险在第 1、3 条。
- 方言不生效时：`:abc:` 读成普通文字，最小转义不转义 `:`，字节不变，无问题。
- 方言撞名：节点名 `sticker`、模块名等与内置不撞（`reservedSyntaxNames`），按名字比较的规则不挡它。
- 重名、白名单合成的语义与 Skill 一致，我只看了前端部分，白名单与槽归后端审查。

## 对计划末尾“待确认”各项的判断
1. 大图高约 120 像素、槽至多 60 个、清单上限 500 项、2 MiB、说明 200 字：120 像素可以，但应是一个 CSS 变量；2 MiB 之外要加像素上限（第 10 条）；槽 60 个是后端预算，我不判；500 项乘包数一次取回，可以，但目录条目要带宽高。
2. 内置表情包不另设 `builtin` 来源，由内置插件经 `stickers.packs` 交出：同意，符合 ADR 0027，设置页分组“我的在前、各插件一组”也自然。
3. 编辑器里打出未知名字也变成节点：只在去掉边界规则、并让邻接字母数字写得出（第 1、8 条）、且退格能还原（第 3 条）之后才接受；现在的组合下它会制造“写不出”与整块降级。
