### 1. 双语对照的译文行对比度不够（亮色 3.57:1、暗色 4.22:1）
- **严重程度**：重要
- **元素与位置**：`.nb-bilingual-block::before`（“老人缓缓走向祭坛。”），free 与 420x900 两套图都有；`packages/nb-markdown/src/display/markdown.css:327-333`。
- **现象**：量得字号 11.9px（0.85em）、颜色 `--text-muted`。亮色 #8b857b 落在纸面 #fffcf5 上对比度 3.57:1；暗色 #918a7e 落在 #2d2925 上 4.22:1。两套都低于正文小字应有的 4.5:1。
- **为什么是问题**：译文是回复正文的一部分（用户要读它），不是装饰性的辅助标签；小字加弱色是最容易读不清的组合。`--text-muted` 在设计语言里是“次要、可忽略”，不是“要读的次要内容”。
- **改法**：颜色改 `var(--text-secondary)`（亮色 #57534b，6.89:1；暗色 #c3bcb0，8.08:1），层级仍靠 0.85em 字号和位置区分。若想保留“更淡”，至少用 `color-mix(in srgb, var(--text-main) 62%, transparent)`，亮色约 4.6:1，暗色约 5.3:1（按 72% 的注音色同法推算，未逐值量）。

### 2. 文件引用小块左边有间隙、右边零间隙，右侧文字贴在边框上
- **严重程度**：重要
- **元素与位置**：第一行“林雪”“第三章”两个小块；free 与 420x900 图的第一行。`packages/nb-markdown/src/chip/chip.css:104-135`。
- **现象**：图标段有 `margin-inline-start: 0.1rem`（1.6px），末段 `.nb-chip-link--end` 没有任何右外边距。量得“林雪”块右缘 x=103.0，后一个字“的”从 103 开始，间隙 0；“第三章”块后面是全角逗号，逗号字形自带左侧空白所以看不出，但同样没有留白。左侧“了”到图标段边框约 1.6px 加字形空白。放大 4 倍的截图里，“的设定和”的“的”几乎贴着块的右边框，左右明显不对称。
- **为什么是问题**：同一个小块两侧留白不一致，读起来像贴歪了；`InlineChip.vue` 那套（`.nb-chip`，`margin: 0 0.1rem`）两侧对称，静态视图版本漏了右侧。
- **改法**：`.nb-chip-link--end { margin-inline-end: 0.1rem; }`，与左侧同值。批注把链接拆成多段时，只有末段带这条，不会在段与段之间加缝。

### 3. 批注波浪线正好压在小块的下边框上，并挤向下一行的注音
- **严重程度**：建议
- **元素与位置**：“林雪”小块里的批注（`<comment>` 只盖“林”字）；free 与 420x900 的第一行下方。`markdown.css:131-136`（`text-underline-offset: 0.3em`）。
- **现象**：小块下沿 y=22.7（相对展示器顶），波浪线用 0.3em（4.2px）偏移，4 倍图里量得波浪占 y≈21.8 到 25，骑在小块下边框（22.7）上，边框线从波浪中间穿过。它下方 3px 左右就是第二行“祭坛”的注音 “jì tán”，三个东西挤在 x=68 到 77 附近：小块边框、波浪线、注音小字。
- **为什么是问题**：同一处同时出现两条横向线条，批注色（橙）与小块边框（灰）互相打架，看起来像渲染故障；批注的意图（被批注的正文有下划线）被小块边框吃掉。
- **改法**：小块里的批注用单独规则，让波浪完全落在小块内侧或完全落到边框外：`.nb-chip-link comment { text-underline-offset: 0.12em; }`（目标：波浪在小块下内边距里，距下边框 ≥2px）。这条数值我没实测，改后用放大截图核对；若觉得波浪压字，改成给小块内的批注加淡底色（`background: color-mix(in srgb, var(--status-warning) 18%, transparent)`，沿用 `.nb-comment-current` 的做法）。

### 4. 块后第一行的注音只离上一块 2px，吃掉了 8px 块间距
- **严重程度**：建议
- **元素与位置**：列表第 1 项“祭坛”的注音 “jì tán”；free 与 420x900 的第 2 行。`markdown.css:213-219`（注音）与第 13-15 行（块间距）。
- **现象**：展示器里注音是原生 `ruby`，行高写死 23.8px 时 Chrome 不给这一行加高：li 高度仍是 23.8px，注音盒 y=24.8 到 37.8，上沿高出这一行 7px，伸进 8px 的块间距里；上一段小块下沿 y=22.7，两者盒间距只有 2.1px，字形间距约 5px。底下则与“祭坛”字形只隔约 2.5px。
- **为什么是问题**：注音要靠“上有空、下贴字”才读得出是注在谁身上；现在上方空间被邻块占掉，注音更像挂在上一行的小字。若注音出现在段落中间行，实验里行间只多出约 2px，勉强不叠，但仍紧。
- **改法**：给含注音的块加行距：`.nb-markdown :is(p, li):has(> ruby) { line-height: calc(var(--markdown-line-height, 1.7) * 1em + 0.45em); }`。我用页面内注入这条样式量过：li 高度 23.8→30.1px，注音上沿 24.8→27.8，与上一块小块下沿的盒间距 2.1→5.1px，注音与基底关系不变。代价是含注音的整段行距多 6px，印刷里本就如此。

### 5. 所有块之间都是 8px，带框块与文字没有层级，居中小标题悬在两边中间
- **严重程度**：建议
- **元素与位置**：整页纵向节奏；`--markdown-block-gap` 由宿主给 8px（`markdown.css:13-15` 读取）。
- **现象**：量得相邻块间距全是 8px：正文→列表 8、列表→提示块 8、提示块→“—— 改写示例 ——”8、小标题→双语块 8、双语块→HTML 卡片 8、卡片→图片 8、图片→“参考”8。行高 23.8px，8px 只有 0.34 行。结果是：提示块、HTML 卡片、图片这三个带边框或底色的大块，与相邻文字的距离和段与段一样；居中小标题与上下块等距，分不出它是后面双语块的引子；HTML 卡片和图片两个重块 8px 叠在一起，像一个组件。
- **为什么是问题**：近似律——同组靠近、异组拉开；整页等距就没有分组。
- **改法**：带框块前后加大到 12px，小标题与它引出的块贴近：`.nb-markdown > :is(.nb-callout, .nb-html-embed, p:has(> .nb-markdown-image)) { margin-block: 12px; }`（注意 `> * + *` 的 margin-top 要被它盖过，写成 `.nb-markdown > .nb-callout + *` 等同理），`.nb-markdown > align + * { margin-top: 4px; }`。数值是建议，不依赖实测。

### 6. 可渲染 HTML 卡片的源码被硬切，没有任何滚动提示
- **严重程度**：建议
- **元素与位置**：HTML 卡片源码区 `.nb-html-embed__source`；free 图里“二十岁”的“岁”被切掉半个，420x900 图里停在 `#cc`。`markdown.css:526-529`，`white-space` 取 `pre`。
- **现象**：量得 `scrollWidth` 672 > `clientWidth` 604，源码区 `overflow-x: auto`，但覆盖式滚动条不显示；右边 14px 内边距要滚到底才出现，初始状态文字直接压在卡片右边框上被切断，没有渐隐、没有省略号。窄宽下一行只露约 38 个字符。
- **为什么是问题**：回复里的卡片是给人读的，读者看不出还有后半段，也看不出能横向滚；字形被切半又像渲染错误。仓库里 `.nb-html-block`（同文件 377-380）已用 `pre-wrap`，这里没跟。
- **改法**：展示器里读用，改成折行：`.nb-html-embed__source { white-space: pre-wrap; overflow-wrap: anywhere; }`（编辑器里可留 `pre`）。若坚持横滚，加右缘渐隐：`mask-image: linear-gradient(to right, #000 calc(100% - 24px), transparent)`。

### 7. HTML 卡片源码 14px 等宽，比同页所有同类“源码”都大
- **严重程度**：建议
- **元素与位置**：`.nb-html-embed__source`（free 图第 4 个块，420x900 图同位）；`markdown.css:526-529`。
- **现象**：量得源码区字号 14px（继承正文，因为是 `pre` 而不是 `code`，吃不到 `.nb-markdown code` 的 0.9em）；同一块的表头是 11.9px（0.85em）；行内原样片段 `<kbd>Ctrl</kbd>` 是 11.9px（0.85em）；普通行内 `code` 是 12.6px（0.9em）。同一类“显示源码”，四个字号里最大的恰是占面积最大的这块，14px 等宽字的 x 高又比 14px 汉字大，看上去比正文还重（截图里 `<div style=...` 一行比上下正文都粗大）。
- **为什么是问题**：设计语言是正文一档、辅助小一档；源码块不该反过来比表头大 2.1px，也比自己的行内兄弟大 2.1px。
- **改法**：`.nb-html-embed__source { font-size: 0.85em; line-height: 1.6; }`，与 `.nb-html-block`（374 行）一致；注意 `.nb-markdown pre` 的 `padding: 0.75em 1em` 会随字号缩小，若嫌挤再写回 `padding: 0.75rem 1rem`。

### 8. 图片是直角，与相邻的 6px 圆角块不一致
- **严重程度**：建议
- **元素与位置**：图片 `.nb-markdown-image__img`（free 图蓝色大块，420x900 图同）；`packages/nb-markdown/src/display/MarkdownImage.vue:92-97`。
- **现象**：量得图片 606×227（原图 640×240，缩到容器宽），圆角 0；紧接在它上面的 HTML 卡片是 6px，再往上提示块也是 6px。HTML 卡片下边两个圆角（6px）与图片上边的直角贴在一起，间隔 8px。图片是整页面积最大的元素（占展示器高度 40%），它的直角比文字小块的圆角更抢眼。
- **为什么是问题**：同一栏里的块级元素一套圆角（提示块 6、HTML 卡片 6）才读成一族；占面积大的反而是方的，不协调。
- **改法**：`.nb-markdown-image__img { border-radius: 6px; }`（占位与失败态本来就是 0.3rem，一并改成 6px，不要出现 6/4.8 两套）。若担心图片边缘与纸面糊在一起（浅色图在亮底上），再加 `outline: 1px solid color-mix(in srgb, var(--text-main) 10%, transparent); outline-offset: -1px;`。

### 9. 高亮没有水平内边距，底色紧贴字形，右边正好撞上句号
- **严重程度**：建议
- **元素与位置**：“可以压到两句”的 `mark`；free 与 420x900 图的第 3 行。`markdown.css:344-348`。
- **现象**：量得 `mark` 宽 84px（正是 6 字 × 14px），内边距 0，圆角 2px，高度 19px（只有字体内容区）。底色左缘贴着“，”，右缘贴着“。”，色块边缘与字形边缘重合；亮色底色是 (223,200,167) 的土黄，在暖米色纸面上偏脏，但对比度（文字对底色 10.5:1）没有问题。
- **为什么是问题**：荧光笔式高亮要比字多出一点边才像“涂过”，现在像字下面垫了一块色块。高度也比同行的小块（22.4px）低 3.4px，两种行内底色各用各的盒高。
- **改法**：`padding-inline: 0.15em; margin-inline: -0.15em; border-radius: 4px; box-decoration-break: clone;`（负外边距抵消内边距，文字位置不动）；高度可加 `padding-block: 0.05em`，与小块的上下 0.05em 对齐。

### 10. 行内底色元素的圆角、盒高各用一套数
- **严重程度**：细节
- **元素与位置**：行内元素：`mark` 2px（`markdown.css:346`）、原样片段 3px（382-385）、`code` 4px（87-93）、文件小块 6.4px（`chip.css:105-119`，`0.4rem`）。
- **现象**：量得盒高分别为 19px（mark）、18px（原样片段）、22.4px（小块），圆角 2 / 3 / 4 / 6.4，同一行里并排出现时（第 3 行：`<kbd>` 片段与高亮）看得出一个更方、一个更圆。
- **为什么是问题**：同一类“行内高亮盒”应在一个圆角档里，现在是四档；小块用 rem 而其余用 px 或 em，编辑器字号变大时（稿纸）小块的圆角与内边距不跟字号，其他的跟，比例会变。
- **改法**：行内盒统一 `border-radius: 4px`（小块保留 0.4rem 也可，但把 mark、原样片段拉到 4px）；小块的 `padding` 与 `border-radius` 改 em（`0.45em` 约等于 0.4rem@14px）。

### 11. 小块上下只比行高少 1.4px，相邻两行的小块几乎相碰
- **严重程度**：细节
- **元素与位置**：`.nb-chip-link` 与 `.nb-chip-link__icon`；`chip.css:104-135`。
- **现象**：量得小块高 22.4px（19px 字体内容区 + 上下 0.05em 内边距 + 上下 1px 边框），行高 23.8px，上下各剩 0.7px，相邻行小块间只隔 1.4px。我把第一段复制进 150px 宽的容器后，换行的两排小块上下边框紧挨着，第一排小块里的批注波浪线露在两排之间时还被下一排小块盖住。
- **为什么是问题**：行高 1.7 是为纯文字定的；小块加框后占掉大部分行距，一段里小块多时成了一串粘在一起的框。
- **改法**：去掉上下内边距，`.nb-chip-link, .nb-chip-link__icon { padding-block: 0; }`（高度 21px，相邻行间隙 2.8px）；仍紧则把小块的上下边框改成 `outline`/内阴影不占盒高。

### 12. `<kbd>Ctrl</kbd>` 在回复里按源码原样显示，带虚线框的小字很像漏出来的标签
- **严重程度**：细节
- **元素与位置**：列表第 2 项“对话里的 <kbd>Ctrl</kbd> 是笔误”；free 与 420x900 图第 4 行。`markdown.css:367-385`。
- **现象**：量得是 `.nb-raw-inline-html`：11.9px 等宽、1px 虚线框、`--bg-subtle` 底、`--text-secondary` 字；全句最显眼的就是尖括号。简报把它与注音、高亮并列写成“方言元素”，但代码里 `kbd` 没有方言，是原样片段（Spec 输出 9）。
- **为什么是问题**：Agent 对话里读者想看到的是“按 Ctrl 键”，现在读到一个像报错的 HTML 标签；这个形态在编辑器里是对的（要整体选中或删除），在只读展示里没有这个必要。
- **改法**：Spec 若定了展示器也原样显示，样式上至少降噪：边框从虚线改成实线 1px 的 `--divider`，标签部分弱化。更好的是展示器认出 `kbd`、`u`、`span` 这些常见标签给最小样式，这属于功能范围，交开发者决定。

### 13. 窄宽下列表第 2 项末行只剩“写法。”两个字
- **严重程度**：细节
- **元素与位置**：420x900 图第 2 项末行（量得容器宽 386px 左右）。`markdown.css:68-79`。
- **现象**：第 2 项折成两行，第二行只有“写法。”，约 2 个汉字宽，悬挂缩进 21px。
- **为什么是问题**：孤行（orphan）让段落末尾轻飘，在短回复里尤其扎眼。
- **改法**：`.nb-markdown :is(p, li) { text-wrap: pretty; }`（Chrome 117 起支持，不支持的浏览器忽略，无副作用）；标题可加 `text-wrap: balance`。

### 14. 行高 23.8px 不是整数，块顶落在 .4 与 .2 上
- **严重程度**：细节
- **元素与位置**：`--markdown-line-height: 1.7` 乘 14px；`markdown.css:10`。
- **现象**：量得各块顶 y：31.8、87.4、135.2、167.0、222.0、307.5、542.8，提示块（高 39.8px）的边框线落在 87.4 上。设计语言“行内的文字块与控件同奇偶，行高取整数”的原话对象是控件居中，这里没有居中控件，Chrome 也会把边框吸附到物理像素，我没在 1 倍屏上看到发虚，所以只算细节。
- **改法**：宿主给 `--markdown-line-height: 24px`（14px 字下为 1.714）。若不想固定，用设计语言里的 `round(nearest, calc(1em * var(--leading-ui)), 1px)`。

### 15. 暗色里 HTML 卡片的表头几乎融进页面，源码区反而比页面亮
- **严重程度**：细节
- **元素与位置**：暗色两张图里的 HTML 卡片；`markdown.css:495-504`、`87-100`。
- **现象**：暗色表头底 `--bg-subtle` 约 (41,38,34)，页面 (45,41,37)，对比 1.06:1；源码区 `--bg-hover`(58,53,48) 与页面 1.19:1，比页面亮。亮色里表头略亮、源码区更暗（页面 1.26:1）。也就是亮色是“凹下去的槽”，暗色是“浮起来的块”，同一组件两套主题方向相反；暗色里表头靠一圈边框撑住。
- **改法**：源码区改用不随主题翻转的底，例如 `background: color-mix(in srgb, var(--text-main) 5%, var(--bg-panel))`，表头 `--bg-subtle` 不动；或接受现状，仅此一条记入“暗色里卡片层级与亮色相反”。

## 看起来没问题的部分
- 注音（9.8px，约 72% 正文色）对比度亮 6.63:1、暗 6.95:1，居中对齐准确（注音盒与基底盒都是 x=49 到 77）；换行段落中间行带注音时行距只多出约 2px，没有叠字。
- 提示块：整圈 1px 细边框、圆角 6px、标题 14px/600，亮色标题 #9a5b00 在底色上 4.50:1（刚到线，14px 半粗不算大字，若主题再调浅就不及格），暗色 5.34:1；折叠态的内边距 7px/14px，箭头 18.2px 的点击盒，右缘距边 15px，与图标左缘距边 15px 对称。
- 小块的图标段与文字段等高、底色与边框连成一体（y=0.3，高 22.4px 两段一致）；小块内文字对底色 13.9:1（亮）、9.3:1（暗）。
- 上下标：10.5px（0.75em），行高 0，不撑高行；“H₂O”“x²”位置自然。
- 外部链接 #0060df 在亮色纸面 5.48:1，暗色 #5eb0ff 6.27:1，下划线清楚，与小块是两套视觉语言，各司其职。
- 双语对照译文与原文间距 3px（0.25em），原文比译文大一档，层级清楚（颜色问题见第 1 条）；对齐块居中无偏移。
- 暗色整体：提示块、高亮在暗色里的对比度都过线（高亮文字 6.17:1），没有出现亮色里的“脏黄”。
- 窄宽（420x900）：小块、提示块、图片都随容器收缩，没有溢出或遮挡。
