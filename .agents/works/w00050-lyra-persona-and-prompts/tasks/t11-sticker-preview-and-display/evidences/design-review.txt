### 1. 选择器面板自己的“焦点离开就收起”必然关掉面板，对话框随面板一起卸载
严重程度：重要
类别：接口与合同 / 依赖机制
位置：packages/neuro-book/src/plugins/stickers/web/components/StickerPickerPanel.vue:138-142（onFocusout）；MarkdownStickerCard.vue:31-36；agent/web/sticker-composer.ts:49-52；计划“选择器 StickerPickerPanel”与“风险”
现象：面板根上 `@focusout` 的判断是 relatedTarget 不在 root 里就 `emit("close","blur")`。ImagePreviewDialog 是 reka 模态，焦点陷阱把焦点移进传送出去的对话框（DOM 上在 root 之外，relatedTarget 为对话框内元素或 null），所以一打开对话框面板就发 close("blur")。两个宿主（MarkdownMenus.closeSticker、composer 的 closePopover）收到后都把弹层置空，AnchoredPopover 不再渲染面板；对话框若是面板的子组件就一起卸载，表现是“预览一闪就没了”。AnchoredPopover 自身不处理点外面与焦点外（.md“不处理 Escape 与点外面”），所以唯一的收起路径就是面板这条 focusout。
为什么是问题：计划把它写成“要核对不会被触发”，但按代码它一定被触发，不是待核对项；决定 4 与计划都承诺“面板不关”，没有给机制。
如何核实：读 StickerPickerPanel.vue 的 onFocusout 与两个宿主的 close 处理；happy-dom 里没有真实的焦点陷阱，我没有在真实浏览器里复现（未实验），按代码判断。
建议改法：面板持有 previewOpen 状态，打开期间 onFocusout 直接 return，对话框 closed 之后焦点回到底部按钮（reka 自己会还给打开前的元素）；对话框放在面板里而不是宿主里，这样两个宿主都不用改。并且要在真实浏览器里验（见第 12 条），不能只靠 happy-dom。

### 2. 编辑器的 previewSticker 要加进 indirectHost，计划没写，漏了则功能静默失效
严重程度：重要

### 4. 单击即预览没有区分手势：夹在链接里的表情会同时触发两个动作，修饰键与选区手势也会误开
严重程度：重要
类别：遗漏 / 对照参照
位置：计划“buildSticker ... 在 <img> 上监听 click”；packages/nb-markdown/src/display/MarkdownDisplay.vue:131-136（根上的 onClick）；packages/nb-markdown/src/editor/link-open.ts:50-70；neuro-book/.../comments/MarkdownCommentLayer.vue:370-382
现象：
(a) 表情可以在链接里：core 的 link 读法是 `context.inline(link.tokens)`，表情是内联 token，所以 `[:lyra/开心: 点这里](url)` 读出带 link 标记的 sticker 节点（从代码推断，未跑）。展示器里点其中的 `<img>`：img 上的监听先发 `sticker`，事件冒泡到根的 onClick，`closest("a[href]")` 命中，再发 `link`；AgentMarkdown 先开预览再 emit `link.open` 给宿主。编辑器里 Ctrl 点同理：MarkdownLinkOpener 开链接，img 监听又开预览。
(b) 编辑器里同类交互都有手势约束：链接要 Ctrl/⌘ 点才打开，普通点击放光标；批注是 Ctrl 点“看”。计划里表情是无条件单击预览，Shift 点扩选区、Ctrl 点看批注或开链接、双击选词都会弹模态；双击还会因第二次按下落在遮罩上（Dialog 的 onOverlayPointerUp 判为点外面）把刚开的对话框关掉。
(c) 输入法组字中点表情、只读文档同样走这个监听。
为什么是问题：开发者定的是“编辑器里单击表情直接预览”（决定 2），但没有定修饰键与链接里的情形，这是实现必须补的合同；不补会在 4 号切片之后才出现重复动作。
如何核实：读上面三处；Spec markdown-display 输出 5 写“点击外部链接发出 link”，表情在链接内时没有规定。
建议改法：监听里 `event.button !== 0 || shift/ctrl/meta/alt || event.detail > 1` 时不处理；`closest("a[href]")` 命中时只发 link（表情在链接内不预览）；编辑器侧在 `view.composing` 时不处理。写进 Spec 输出 46，并各补一条 dom 测试。

### 5. 样式挂载：入口归属会逼出 storage 依赖、首帧闪动、Lab 与单独使用无路径、选择器特异性与类名含糊
严重程度：重要
类别：遗漏 / 隐含耦合 / 前端规范
位置：计划“浏览器入口激活时，在 document.head 挂 <style>”“.nb-sticker.has-image.is-sticker-display”；packages/neuro-book/src/plugins/stickers/web/plugin.ts:35-70；packages/nb-markdown/src/stickers.css:35-58
现象与分析：
(a) 机制本身不违反规范：已有先例（ui/theme/document-theme.ts 的图标 style、nb-ui theme-loader 的 fallback style），没有 CSP 限制 style（grep 只在文件与预览路由上有 CSP），样式只含尺寸、没有颜色，不涉及主题；stickers.css 与它同样是不分层的，所以不会输给原子类。多窗口：设置窗口、桌面版各是独立 document，各自激活入口、各挂一份，没有共享一个 document 的前提；仓库里没有弹出窗口（没搜到 documentPictureInPicture、popout）。用属性或变量替代不能少掉“按包选中”的选择器，所以我认为这条路本身可取。
(b) “浏览器入口”有三个：browser 入口只依赖 diagnostics，注释明说 Markdown 激活要等它提供的 stickerResolverKey，所以 picker 入口才单独拆出来拿 storage。读偏好要 storage，写在 browser 入口里会让 Markdown 与 Agent 的激活排在 storage 之后。应放 picker 入口（已有 storage）或新开一个入口。page 入口也没有 storageKey，开关要它，没有 storage 时的行为（隐藏？只在本次生效？）计划没写。
(c) 偏好读到之前先按小图画一遍，读到后整个对话重排；对话里是长文，建议至少在 Spec 写一句。
(d) 选择器写“按 [data-sticker-pack] 选中”：单独的属性选择器特异性是 (0,1,0)，压不过 `.nb-sticker.has-image`(0,2,0) 的 margin 与 `.nb-sticker-block .nb-sticker__image`(0,2,0)；高度写在子元素 `<img>` 上，不是 `.nb-sticker`。计划同时又提一个类 `.is-sticker-display`，但没有谁给元素加这个类，stickerDisplayStyle 也是另一份声明副本，写两份。图读失败的 showText 要把 data-sticker-pack 一并清掉。
(e) Lab 与单用 nb-markdown 的宿主没有挂载路径，Lab 的“夹着贴纸的段落”场景要自己插 style，计划没写。
建议改法：nb-markdown 导出 `mountStickerDisplayStyle(doc, packIds): () => void`（内部生成 `.nb-sticker.has-image[data-sticker-pack="x"]` 与 `... .nb-sticker__image` 两类规则，只写一份声明，不要 is-sticker-display 类），宿主与 Lab 都调它；neuro-book 放在 picker 入口或单开 display 入口，并写明无 storage 时的行为。

### 6. 预览“原尺寸不放大”对贴纸来说看不大：小图预览可能不比贴纸显示的 120 像素更大
严重程度：重要（需要开发者定）
类别：上游选择 / 与已定设计一致
位置：packages/nb-agent-ui/src/vue/parts/OriginalImagePreviewDialog.vue:73（`Math.min(1, availableWidth / size.width, availableHeight / size.height)`）；计划“行为原样保留：原尺寸不放大”与 Spec 输出 46；Task README 目标“点表情能看大图”
现象：预览按 natural 尺寸显示、只缩不放。表情包常见的图是 64 到 512 像素（Lab 的占位图 128 乘 128；规则只限上限 1024，没有下限，Spec 输出 29）。一个 128 像素的表情预览出来还是 128：比行内小图（约 27 像素）大，但与“按贴纸显示”的 120 像素高几乎一样，对贴纸显示开着的用户，点图什么也没放大。开发者要的是“看大图”，决定 3 说“复用现有对话框”，但没有明确说连“不放大”也沿用，这是计划把原图预览的规则原样带过来的副作用。
为什么是问题：对话里有的是 AI 生成的 SVG/小 PNG，预览的价值恰在放大；沿用“原尺寸不放大”会让这条功能对小图形同虚设，而且 Spec 还把“预览不能缩放”写进了不承诺，后续难改。
如何核实：看 measure() 的 scale 上限；在 Lab 里用 labStickers 的 128 像素图点预览（计划已有场景）。
建议改法：给 ImagePreviewDialog 加一个可选 prop，例如 `fit: "natural" | "fill"`（缺省 natural，原图预览不变；表情用 fill，按可用空间放大到不超过某个上限，比如宽高中较大边至多 480 像素，并带 `image-rendering` 的取舍），在 Spec 输出 46 写清“表情预览放大到约 N 像素”。把它交开发者确认，不要悄悄沿用。

### 7. 输入框里每个贴纸 120 像素：光标、单行版式、最大高度都没有量，验收里也没有输入框的用例
严重程度：重要
类别：遗漏 / 验收映射
位置：packages/nb-markdown/src/prompt/PromptEditor.vue:1036（maxHeight 缺省 200）、1165（line-height 1.6）、1138-1160（`img.ProseMirror-separator` 隐藏）；packages/nb-agent-ui/src/vue/composer/AgentConversationComposer.vue:949-965（单行版式：控件与正文最后一行的中线对齐、贴底）；计划“待确认 3”与验收映射
现象：
(a) 输入框 body 的 maxHeight 缺省 200，一个 120 像素的贴纸占 60%，两个换行就出滚动条，且内容在内部滚动，贴纸可能被滚出视野；
(b) 单行版式里控件“与正文最后一行的中线对齐、正文长高时留在底边”，最后一行是 120 像素高的贴纸时这个对齐的前提（一行的高度）不成立；
(c) 光标挨着一个 120 像素高的 contenteditable=false 行内块时，Chrome/ProseMirror 的光标高度常随相邻的行内块变高（stickers.css 现有的 `vertical-align:-0.16em; line-height:0` 是为 1.6em 小图调的，大图用 bottom 对齐后行内基线的位置会变）；这一点我没有在浏览器里量，是风险推断。
为什么是问题：待确认 3 开发者已同意，代价写成“输入框会被撑高”，但没有说约束（最大高度内滚动？滚到光标？）也没有一条验证。验收映射里 dom 测试只覆盖对话；e2e 只写“同一条回复里夹在文字中的表情”，没有输入框。
如何核实：这几项必须在真实 Chrome 的 e2e 里量：在输入框里打开某个包的开关后插入一个表情，断言输入框高度不超过 maxHeight、光标矩形高度在合理范围（不等于 120）、单行版式下控件仍贴底。
建议改法：在 e2e 加输入框这一条（高度、滚动、光标）；若量出光标变高，输入框里让贴纸显示改回缩放到不超过行高 2 倍，或在计划里把输入框排除出输出 47，改成“对话与编辑器生效”（这需要重回待确认 3）。

严重程度：重要
类别：验收映射

### 10. 底部“指着的表情”按钮：外层 footer 是 aria-hidden，触屏没有入口
严重程度：建议
类别：遗漏 / 对照参照
位置：packages/neuro-book/src/plugins/stickers/web/components/StickerPickerPanel.vue:228-232（`<footer ... aria-hidden="true">`）；同文件 pointed 只由 pointerenter 与 focus 更新（:219-221）
现象：
(a) footer 现在整块 aria-hidden（因为它重复格子的名字）。计划把里面的小图改成按钮，但没说怎么处理 aria-hidden：留着则是可聚焦元素在 aria-hidden 里（读屏与 axe 都报），去掉则读屏会把名字念两遍；而决定 4 说“预览从底部一行指着的表情的图打开”，按钮的名字是“查看大图”，名字里该带表情名。
(b) “指着的表情”靠鼠标悬停或键盘焦点，触屏点格子就是插入并关面板，所以手机或平板上没有任何办法打开预览。决定 4 已认可“先这么做”，但应在 Spec 输出 39 与不承诺里写明，而不是留成隐含。

建议改法：把按钮从 aria-hidden 的 footer 里拿出，footer 只留文字，按钮单独放；`aria-label` 写“查看大图：名字”；mousedown 阻止默认；Spec 补触屏说明。

### 12. stickers.display 记录：locality、失效的包 id、记录读不到、改包名后的行为没有定
严重程度：建议
