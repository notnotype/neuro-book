# 表情包设置页：新建、编辑、导入导出

## 目标与范围

设置里加表情包页：新建包、拖图进来、改名字与描述、标常用、删除；包导出为 zip、从 zip 导入（以后表情包市场的分发格式）；插件带来的包只读，可复制到我的。后端补 user://stickers/ 的写入，Spec 输出 20 与“应用不写里面的文件”要改。界面先出静态稿。依赖 t07 的格式。来源：开发者 2026-11-18 意见第 1 条；市场另开 Work。

合同：[`agent/stickers.md`](../../../../../docs/specs/agent/stickers.md)输出 20、25 到 38、验收 9、10（planned）。计划：[`plan.md`](plan.md)。

## 决定

开发者 2026-11-18 在会话里定（设计评审的注意力排序与交互）：

1. 布局：左列表右详情，同 Profile 页。左边按来源分组列表情包（我的在前、各插件一组），带表情数，底部“导入 zip”、组头“新建”；右边头部是显示名与说明，带“导出”与更多菜单，下面是表情网格，末尾一格是加图片（也能拖进来）。
2. 改表情：选中网格里的表情后，在旁边的属性栏改（大图预览、名字、说明、常用、删除），不弹对话框。
3. 加进来的图片超过 1024 像素或 2 MiB：静态图按比例自动缩小再存、格式不变；超限的动图拒绝并说明原因。
4. 导入的 zip 与已有的表情包同名：询问替换，或另存为新包（自动起名，如 `cat-2`）。

第 1 轮评审板（[`artifacts/review`](artifacts/review/index.html) v1，2026-11-18 答复）：

5. 有清单之后只认清单里的表情（选 A，维持 t07 的规则）：文件夹里没列进清单的图片不算表情。设置页要处理“文件夹里有没加进来的图”。
6. 整页版式不通过：“样式有点丑，用了 /frontend-design /ui-development 这种 skill 了没”。第 2 轮重做视觉，布局（左列表右详情、属性栏）不变。
7. 包名建好后可以改，改之前要告诉用户代价（旧消息与文件里用旧包名写的表情认不出来）。
8. 当不了名字的图在网格里标出来、选中直接改名：同意。
9. 插件的包只读，“复制到我的”之后再改：同意。
10. 导入同名的对话框：同意，样式要优化。

第 2 轮评审板（v2，2026-11-18 答复）：

11. 整页样式仍不通过：“不用做白边也可以，并且表情包不能因为图片的大小而随意变动，这会破坏布局，而且要注意表情包也是应该支持矩形的，并不一定要你展示的这种透明 png 的”。第 3 轮：去掉模切白边；每个表情占固定大小的格子，图在格子里按比例缩放、居中；选中与悬停画在格子上（对矩形图同样成立）；样本加入不透明的矩形图（宽图、竖图）。
12. 有清单的包里没加进来的图放在网格最后一组，可以一键全部加进来：同意。
13. 改包名的入口（更多菜单、属性栏“改…”）与写清代价的对话框：同意。
14. 导入同名对话框的第 2 版样式：同意。

第 3 轮评审板（v3，2026-11-18 答复）：

15. 整页按第 3 轮的格子做：同意。每个表情占 72px 的固定格子，图按比例缩小、居中；悬停加深格子底色，选中是格子的强调色描边；属性栏的大图是固定高度的格子。草稿 `StickerPacksPageDraft`（草稿 worktree，不合并）是实现的样子。

计划前的四问（2026-11-18 会话里，都选推荐）：

16. 改包名不迁移白名单：改名对话框列出选了它的 Profile，改名后要去 Profile 页重新勾选（它们列在“已删除或不可用”）。第 2 轮稿里“Profile 里选了它的照常可用”一句改掉。
17. 没有清单的包里改名字、说明、常用，一律先把文件夹里的图全列进一份清单再改清单，文件不改名；之后它就是有清单的包。
18. 超限图片：GIF 超过 1024 像素或 2 MiB 一律拒绝（Bun 的图片库写不出 GIF，也分不出动图）；动态 WebP 读文件头判断，超限拒绝；静态图缩到 1024 以内后仍超 2 MiB 的改存 WebP，扩展名跟着变。
19. zip：里面是一个以包名命名的文件夹（清单加图片）；导入也接受图片直接放在 zip 根上的（包名取 zip 文件名）；导入的 zip 至多 64 MiB、解开至多 256 MiB、至多 600 个文件，子文件夹与别的文件忽略。
