# 星璃真名契约仪式与初始记忆生成设计

## 目标与范围

设计首次启用星璃（Lyra）时的**「真名契约仪式（True Name Contract Ceremony）」**全屏互动演出与契约落盘流程（本次只做设计，不写代码实现）：

1. **定位与平台归属（对接 `w00043` NeuroBot）**：
   - 按已接受的 [NeuroBook 的 bot 提案](../../../../../docs/proposals/neurobot.md)，星璃在产品中是常驻 Bot（而非普通一次性会话），记忆与契约产物归属 **`bot://memory/`**（而非早期实验用的 `profile://memory/`）；
   - 首次启用前的默认初见记忆表达为“漫长等待后终于迎来了属于我的契约者，尚未正式举行真名契约仪式”，避免开场假定已完成缔约。
2. **触发入口与二次访问分流**：
   - 独立仪式插件同时提供 UI 按钮入口、Skill 入口（`$skill` + 附属仪式说明文件）以及经 `agent.evalObjects` / `agent.tools` 暴露的仪式工具（供星璃通过 `eval` 工具发现并调用）；
   - 首次调用：先弹确认对话框询问用户是否与星璃开始仪式，确认后进入应用内全屏演出；
   - 第二次及以后调用：根据 `bot://memory/` 中持久化契约记录分流，不再覆盖既有记忆，而是展示已签契约书（陪星璃重温契约、可无损微调称呼）。
3. **核心交互范式：以《万界真典》契约书为视觉主角 + 仪式插件作为「实时对话中间人」**：
   - **视觉舞台**：以**「一本大比例展开的《万界真典》交互古籍 + 旁侧星璃专属立绘差分 + 极轻低高度对话条」**为视觉核心（不复用 `brand/mascot/gallery/` 现有插画，后续单独生成专属书页视觉与 7 张半身立绘差分）；
   - **手写体与多处并行魔法浮现（无 TTS）**：全书普通文字采用手写体并从空白以星墨**多处错峰并行快速书写**浮现（行云流水、无需跳字补丁）；第一版不做文字转语音，星璃的实时流式台词同样采用星墨魔法浮现；支持配书房声景音效；
   - **对话中转机制**：用户确认进入仪式后离开普通 Agent 聊天框，完全身处应用内全屏仪式舞台；用户在仪式界面中既可操作书页（定称谓、定/请星璃共创笔名、定代词、写星域初愿、手写签字与封缄），也可随时打字与星璃自由交流——**所有交流由仪式插件作为中间人中转进星璃的主对话会话**，星璃通过回复与隐身舞台工具实时驱动立绘差分、翻页与书页星墨浮字；
   - **双主持模式同架构**：设计阶段同时覆盖**「星璃自主持（V1 优先落地）」**与**「仪式插件扮演司仪（V2 扩展）」**两种模式；
   - **不绑单书的星域视角**：第 3 幕不将契约绑死在某一本特定作品，而是记录执笔者的「专属星域初愿 / 第一颗启明星」，对齐 `w00043` 常驻 Bot 不绑定单一作品的架构原则。
4. **自定义称呼、笔名、代词与记忆生效机制**：
   - 契约结果（日常称谓、执笔笔名、代词、星域初愿、初见约定、亲笔签名 SVG）写入 `bot://memory/` 持久存储，同时将自定义称呼写入 Profile/常驻配置；
   - **即时生效不刷新会话**：仪式结束后主对话完整保留仪式期间的真实对话上下文，星璃当轮直接依靠上下文自然改口并记得仪式中聊过的一切；Profile/常驻提示词中的称呼在下一次自动压缩（compaction）重读 `opening` 时自动更新生效。

详细演出分镜、舞台构图、专属立绘差分清单、五幕剧本、中间人协议与音效表见 [`design.md`](design.md)。

合同：行为合同未变（本阶段仅做仪式全屏演出、交互流程、立绘差分、书页结构、音效与中转协议设计，不改动代码；待设计定稿且 `w00043`（`t06`/`t09`）落地后另起 Spec 与实现计划）。
