### 1. 恢复随机选项里的片段会提前量化，不能还原合法历史
- **严重程度：**重要
- **类别：**不变量
- **位置：**recipes.md:272, 310-313, 335-340；prompt.md:198-199
- **现象：**生成要求随机项、片段引用、词的权重全部乘完才量化一次；恢复变化或缺失的片段却调用输出 21，先把片段引用权重乘进词并量化，再保留外面的随机项。两个过程不等价。
- **为什么是问题：**一次成功生成、快照完整的历史，恢复后会得到不同的实际权重；某些本来可生成的历史甚至不能拆开。不是已批准的四位精度代价，而是两条合同规定了不同的量化层次。
- **如何核实：**已运行 Decimal 最小合同模型：choice.weight=10000，其一个选项是 fragment(F,weight=0.0001)，F.core=[rain@0.0001]，另一选项为 snow@0.0001。文件及 choice 的直接乘积约束都合法。生成 rain 的权重为 round4(10000×0.0001×0.0001)=0.0001；随后 F 改了或删除，恢复按输出 21 得 rain@round4(0.0001×0.0001)=0，外层再乘 10000 仍为 0。另取 choice=0.0001、fragment=10000、词=10000，生成最终为 10000，拆片段的中间乘积却是 100000000，输出 21 必须拒绝。
- **建议改法：**恢复时以整条活跃权重链为单位处理，拆引用之前先把随机项外层倍率无损分配到选项，并在最终叶项只量化一次、再校验持久 Prompt；不能直接复用会独立量化及检查中间范围的输出 21。补上述下溢与中间超范围两类历史恢复验收。
### 2. I-JSON 被写成二进制精确表示，正常的四位小数权重会被拒收
- **严重程度：**重要
- **类别：**正确性
- **位置：**recipes.md:58, 379；prompt.md:69, 195-198；recipes.md:407
- **现象：**新增前置条件要求所有数“都能用双精度浮点数精确表示”，F1 又把双精度表示不了的数列为 invalid-file。按字面，这会拒绝正常权重 0.8、1.05、0.0001、1.2345；它们都不能以 binary64 精确表示。场景 1 自己就使用 0.8。
- **为什么是问题：**I-JSON/JCS 的可互操作数值域，不等于十进制字面值必须在二进制中完全精确。实现者若真的验证“精确”，大多数权重和采样参数不能存；若直接 JSON.parse 又接受了前置条件明文禁止的数据。
- **如何核实：**已运行 Fraction(十进制字符串) 与 Fraction.from_float(float(字符串)) 比较：上述四个值全为 false，只有 0.5 为 true。RFC 7493 第 2.2 节限制超过 binary64 的量级或精度，没有禁止普通十进制小数；RFC 8785 第 3.2.2 明确给出解析时发生舍入的例子，附录 B 包含 0.1 等常规数值。
- **建议改法：**明确以 IEEE 754 binary64 的解析后数值作为 JSON 数值语义，按 JCS 规范化；权重再按四位十进制小数规则校验。若确需十进制字面值逐位无损，必须另选字符串/定点表示并改公开格式，不能用“满足 I-JSON”代替这个产品决定。
### 3. 不完整扫描虽不再改磁盘，仍会把可见副本当作原件解析（第 2 轮第 23 条未完全处理）
- **严重程度：**重要
- **类别：**正确性
- **位置：**recipes.md:184-193, 310-311, 317-325
- **现象：**输出 3 新增“这一次扫描不改记录，也不换 id”，只禁止持久副作用。读不了目录里的文件仍被排除于索引；输出 4 的“只有一个文件的 id 是 x：它就是 x”仍会选中剩下的可见副本。
- **为什么是问题：**同一个引用可以在一次临时权限或挂载故障期间，静默改用另一份已编辑过的预设/片段，并成功生成、把错误内容记进历史。修订挡住了上一轮的永久重编号，但没有保护按 id 查到的内容身份。没有修改 ids.json 不等于没有认错原件。
- **如何核实：**已有记录 x→A/P.preset.json；A 是 rain，B/P-copy.preset.json 是外部复制后改成 snow 的同 id 副本，尚未被插件修复。启动时 A 目录不可读，B 可读。按输出 3 索引仅有 B，且记录保持 A；按输出 4 的单候选规则 B“就是 x”；配方引用 x，展开得到 snow，而不是原件 rain，也没有本轮失败集合里的任何问题。已执行该候选集合与规则的最小模型。
- **建议改法：**不完整扫描时同时约束引用解析：不能把不可观测的既有原件视为不存在，也不能提升可见副本；保留不可解析状态并明确使依赖它的展开失败。只有确认旧路径不存在、或者作者选定原件后才允许迁移身份。
### 4. 等预设写成功再清差异，仍没有保护等待期间来源节的新编辑
- **严重程度：**重要
- **类别：**不变量
- **位置：**recipes.md:239-243, 359-364；相邻 workbench/editor.md:37, 67-69, 165-166
- **现象：**目标预设的期望写入保护了磁盘文件，但写成功后要清空“这一节”的全部差异，没有绑定发起时的来源配方修订，也没有规定写入与确认期间来源节怎样处理新编辑、换预设或被删除。
- **为什么是问题：**目标 CAS 不保护来源文档。照字面在回调里清当前节差异，会删掉本次更新根本没写进预设的新修改。editor 的 commit 支持 baseRevision，但本合同没有要求把它绑定到此次更新使用的来源修订；用完成时最新修订提交仍然合法且会丢数据。
- **如何核实：**P=[a]；B 引用 P，差异 add(b)，开始把 [a,b] 写回 P。写入在途时作者继续在 B 加 c，当前差异为 add(b)、add(c)。P 成功写成 [a,b]；输出 12 此时清空 B.diff，B 立即从 [a,b,c] 变 [a,b]，c 没有进入任何磁盘文件。已运行该两次来源修订、一次目标写入的最小状态模型。
- **建议改法：**将确认、写回内容与来源修订绑定；成功后只有来源仍是该修订才清空差异，否则保留新编辑并按新预设重算，或交由编辑器以原修订形成可裁决冲突。来源换了引用或已关闭时，不再清另一个状态下的差异。这里只补来源时序，不重开“照样写磁盘、目标 dirty 时标变化”的已定决定。
### 5. 句子内权重原本平衡，编辑外层权重后仍会产生连写并清掉后续项（第 2 轮第 7 条未完全处理）
- **严重程度：**重要
- **类别：**正确性
- **位置：**prompt.md:121-122, 145-152, 170-179；recipes.md:307, 313
- **现象：**新增规则检查句子读入前后的权重状态相同，并把带控制符句子排除于往返承诺，但写出仍把句子照原样放进外层数值分组，且无条件保证“不出现连写”。编辑句子权重后，原本平衡的句内数值作用域不再对外层透明。
- **为什么是问题：**不承诺文字往返，不等于允许发给后端的实际权重被改写。合法句子和后续项可正常展开，适配器照规范写出却会得到 chained-weight，甚至让读回退成 raw。句子平衡检查不能保护后来新增的外层作用域。
- **如何核实：**原文 `A girl stands, 2::red clothes ::.` 是一个句子：开头和句号处都没有开着的权重，符合输出 2。把句子权重编辑为 3，再接 rain@3；输出 10 的同权重合并得到 `3::A girl stands, 2::red clothes ::., rain ::`。句内 `2::` 替换尚未结束的 `3::`，后面的 `::` 又清掉外层，rain 变为 1，不是 3；已运行表中数值前缀/结束符规则的最小模型，得到 chained=1、rain=1。即便不合并 rain，句子自身也从开头有 3 到结尾没有 3，按新规则读回整段 raw。
- **建议改法：**对句子采用能无损处理内部权重的写出合同；不能表示时给明确不可写/不可生成结果，不要继续成功输出。至少不能仅靠排除往返范围后仍承诺规范结果无连写、按项实际权重成立。补“原先平衡的句子被改外层权重”而非只测输入已经不平衡的句子。

第 2 条出处勘误：已在线逐段核对 RFC 7493 第 2.2 节、RFC 8785 第 3.2.2 节与附录 B。附录 B 的实际示例是 0.000001，不是原条目写的 0.1；第 3.2.2 节明确展示解析后数值舍入。此处只更正示例出处，不改变 Decimal/Fraction 反例及第 2 条结论。
### 6. 项的键没有隔离种类，普通词会与片段、随机项及图中文字碰撞
- **严重程度：**重要
- **类别：**正确性
- **位置：**prompt.md:60-66, 163-169, 173, 179；recipes.md:228-235, 351-354
- **现象：**词与句子的键直接用任意规范化文字，另几种项却把 `@{…}`、`choice:`、`text:`、`item:` 当前缀。合法 tag.text 并没有禁止这些字符串；输出 14 也只是排除文字往返，不是禁止经 JSON 保存它们。
- **为什么是问题：**本来不同的持久项会被唯一键规则强制合并，丢掉内容或引用；差异也会把替换引用识别成同一项的字段编辑。这不是随机项内部二维数组分隔是否无歧义的问题，而是整个键空间没有类型命名域。
- **如何核实：**已按输出 13 运行键模型：① fragment(ref=abcdefghijkl) 与 tag(text="@{abcdefghijkl}") 的键都为 `@{abcdefghijkl}`；② text(text="Hello") 与 tag(text="text:") 都为 `text:`；③ choice([[tag(a)],[tag(b)]]) 与 tag(text='choice:[["a"],["b"]]') 都为 `choice:[["a"],["b"]]`。将任意一对按先后放进同一个预设，输出 30 必须只留最后一项的内容，前一项消失。三对均符合公开 Item 形状，普通词的语法字符仅使文字往返不受保证。
- **建议改法：**所有项的键统一采用带种类鉴别的无歧义编码，例如规范 JSON 的 ["lexeme",规范化文字]、["fragment",ref,part]、["choice",二维子键]、["text"]、["unknown",整项]。词与句子是否共用 lexeme 身份可维持现有决定，但不能让普通文字占用其它种类的编码空间。
### 7. 允许交给后端的 raw 可带未闭合权重，下一节会继承它
- **严重程度：**重要
- **类别：**正确性
- **位置：**prompt.md:122, 153-158；recipes.md:307, 315, 320-325；依据提案 image-generation-v1.md:115-118、ADR 0047:32-35
- **现象：**raw 只因包含随机写法或 Text: 被拒绝，其余原样交适配器。因句内权重不平衡而回退的 raw 正好可以有未闭合花括号/数值权重，却没有规定它与前后 Weighted 项拼接时要重置权重状态。
- **为什么是问题：**合法的一节会改变另一节的实际权重，违背每节自成一段及 Expanded 中各项独立权重的合同。适配器若直接串接，结果错；若自行插入 `::`，又是在未规定的边界上改变 raw 的原样写出。只有“raw 原样交给适配器”不足以定义这个公共交接。
- **如何核实：**第一内容节原文 `A girl wears {red clothes.`，按 prompt 输出 2/11 得 raw；它没有随机写法、没有 Text:，所以 recipes 输出 26 允许生成。下一节只有 night@1，展开为 [raw(A),night@1]。按 raw 原样写出并用逗号串接得到 `A girl wears {red clothes., night`，NovelAI 的线性规则使 night=1.05，不是 1。已执行花括号状态模型核对后续 night=1.0500。
- **建议改法：**明确 raw 作为独立作用域交接时的隔离合同：发给 NovelAI 前在每个 raw 边界恢复中性状态，且不得改变段内权重；无法隔离的 raw 就用明确失败拒绝。提供方必须写明所有适配器可依赖的含义，不把是否补结束符留给各适配器猜。
### 8. 句子里的 Text: 绕过结构化图中文字规则，也仍满足往返承诺
- **严重程度：**重要
- **类别：**正确性
- **位置：**prompt.md:118-126, 146, 170-177；recipes.md:316, 320-322, 390-391
- **现象：**文字往返条件排除了词开头的 Text:，但没有排除句子里的 Text:。结构化 sentence 的 text 是任意字符串；配方展开只按 kind=text 抽取图中文字，raw 的 Text: 检查也不覆盖 sentence。
- **为什么是问题：**句子符合输出 14 的全部条件，写出后输出 3 却必须把后半句变成另一种项；配方里的后续节还可能被吞成图中文字。在负面里，这种合法 sentence 会绕过 misplaced-text，以控制指令形式发给后端。raw 新增的拒绝规则没有封住结构化项。
- **如何核实：**直接经公开 JSON 写入 {items:[{kind:"sentence",text:"A girl reads Text: Hello.",weight:1}]}，无 source、停用、未知项、引用、权重写法，按输出 2 单独读是大写三词以上并以句号结束的句子，符合输出 14。规范写出保持原字串；输出 3 必须另读出 text("Hello.")，不再是原来的单个 sentence。已运行前置条件与 Text: 抽取的最小模型。若接另一节 night，后端见 Text: 后面的 night 也属于图中文字。
- **建议改法：**在结构化文字项的写出/生成边界统一检查会改变语法的 Text:、随机控制符等，不只检查 raw 或 Item.kind；能无损转换就转换，不能就明确失败。同步收窄往返条件，至少排除所有会被其它语法规则解释的句子内容。

### 10. 片段可展开为空，拆掉它后合法历史变成禁止保存的空随机选项
- **严重程度：**重要
- **类别：**正确性
- **位置：**prompt.md:74, 219；recipes.md:151-159, 269-272, 310-313, 335-342
- **现象：**随机项每个选项必须非空，但片段的 core/support 没有最少项数要求，合法片段或关掉全部陪衬词的引用可以展开为空。恢复缺失/变化片段时无条件把引用替换成展开项，没有处理随机选项因此变空的情形。
