# `images/prompt` 与 `images/recipes` 设计审查第 1 轮的处理

审查对象是 `e2b447417` 的初稿。审查者是 omp 的默认模型：开发者 2026-11-10 说“本 session 可以派 omp 审查”。审查在只读的审查 worktree 里进行，用时约 26 分钟。报告在 `spec-review-r1-omp.txt`，共 31 条：阻断 2、重要 26、建议 2，另有 1 条是对已定决定的质疑。

主会话按规范的字面写了一个小脚本，验证修订后的差异规则：随机生成两组各 5000 对“预设内容 P、节内容 S”，包括调换顺序、停用与重新启用、权重变化。按输出 12 算出差异、再按输出 10 套回去，结果都与 S 相同。“更新预设后不保存就关掉”这个场景下，旧差异里那条“加”判为作废，内容不重复。

## 逐条

第 1 到 30 条都成立，已改，没有撤回的。

| 条 | 处理 |
|---|---|
| 1 差异只能改权重 | “改”带任意字段；P 里有、S 里没有的字段记 `null`，套回时去掉 |
| 2 锚点没有 nth（阻断） | 预设，以及引用了预设的节，同一段里键不重复，重复的合并；`nth` 去掉 |
| 3 SD 原文当 NovelAI 写回 | 只有按 NovelAI 读法读入才保留 `source`；从文件拿到时重读核对，对不上就丢掉，给出 `source-stale` |
| 4 往返不变的适用范围 | 输出 14 写明条件，不满足的只保证 JSON 存取不变 |
| 5 随机项的内外层权重 | 选项从权重 1 起独立读；写出时把随机项的权重乘进各选项；补验收场景 3 |
| 6 权重溢出 | 输出 20：量化规则、`-0` 记为 0、绝对值上限 10000，超出的整段按原文保存 |
| 7 句子、段落与权重的先后 | 段落最先切；句子不跨段落，句子里的权重写法留在文字里；没闭合的整段按原文保存 |
| 8 先去后改让 nth 移位（阻断） | 键不重复以后不再需要 `nth`；“加”的作废改按做完“去”以后的内容判断 |
| 9 更新预设后来源节的差异 | 清空是对打开着的配方的一次编辑；不保存就关掉时，旧的“加”判为作废 |
| 10 组合的同种多条覆盖 | 输出 18：一次套用里每节最多接一条，按同名、同种第一节、新建的顺序 |
| 11 参数的合成 | 参数要么引用预设，要么直接写 `values`，二者取一 |
| 12 展开丢了节的边界 | 结果每张带逐节的内容（节的 id、种类、名字）与角色框 id |
| 13 原文段里的随机写法 | 新失败码 `raw-random` |
| 14 多处图中文字 | 主提示词各节的图中文字用空行连起来；负面里有图中文字就失败，码 `misplaced-text` |
| 15 换 id 没有门禁 | 版本更新或只读的不换；开在编辑器里的走编辑；写到磁盘以后索引才收录 |
| 16 记录对不上、三个副本 | 输出 4 按“有几个文件带这个 id”分情况 |
| 17 规范 JSON 不唯一 | 照 RFC 8785 |
| 18 主体数量算早了 | 每张在角色框展开、抽签、去掉停用的项以后再算，并写明补在哪里 |
| 19 复制的引用闭包 | 输出 23：复制时连同被引用的预设与片段一起复制，引用官方预设的照旧 |
| 20 配置键的格式 | 改为 `nbook.images/defaultStyle`，只允许写在项目层 |
| 21 引用存在但用不了 | 新失败码 `invalid-reference`；引用的文件版本不认识也让展开失败 |
| 22 `year 2025::` 的歧义 | 只有逗号段开头的 `数值::` 才开始权重；写出时结束的 `::` 前空一格 |
| 23 `Text:` 后的空格 | 冒号后紧跟的一个空格属于写法，其余字符都是内容 |
| 24 更新开着的预设 | 文件开在本窗口编辑器里时，改动作为一次编辑交给编辑器 |
| 25 恢复与片段 | 恢复以“内容与当时一样”为准；片段变了或不在了，就拆成当时的普通词 |
| 26 停用项的依赖 | 展开先去掉停用的节、角色框与项，再解析引用；随机项每个选项的引用都要解析 |
| 27 节与角色框的 id | 在配方里唯一，复制配方时保留，别处引用时连同配方 id |
| 28 数值的范围 | 尺寸、张数为正整数；种子为不小于 0 的整数或 `null`；`part` 为从 0 起的整数 |
| 29 失败码不编号、`duplicate` 重名 | 失败码与诊断码都编号；诊断码改名为 `duplicate-item` |
| 30 写不成判据的句子 | 删去“改一处只显示一处 Git 改动”；“纯运算”改写成“不持有隐含的状态” |
| 31 对 P1 的质疑 | 交开发者。主会话的处理：保留 P1；读入时调用方可以给“已知标签”的判断，认得的不读成句子；种类可以事后改 |

另外，修订在中间插入了条目，两份 Spec 的输出编号因此改过。改之前的版本还没有测试引用这些编号。
