# 提示词与配方合同

## 目标与范围

定提示词模型（文本加权重跨度、片段引用）、生成配方（展开后的快照，预留源图与遮罩）与后端能力声明（细到模型加档位），写成 Spec。

提示词模型不能是括号树，见[调研的权重语法一节](../../research/2026-11-06-tag-sources-and-novelai.md#权重语法)。合同：新写 [`images/prompt`](../../../../../docs/specs/images/prompt.md) 与 [`images/recipes`](../../../../../docs/specs/images/recipes.md)（planned）；后端能力声明归 t06 的 `images/generation`。

- 体检与粘贴拆到各节要提示词的语法切分：数值权重、花括号与方括号、SD 的圆括号写法、句子（16）。

### 假设

每条后面是主会话的推荐。

1. **批准依据。**按 [提案规则](../../../../../docs/proposals/README.md#何时需要提案)，新增产品功能、新的持久化格式要先有提案。现在的决定散在 Work 决定表、t07 的“已定”18 条和评审板上。推荐：写一份提案《图像生成第一版：工作台、配方与标签库》，把这些决定连同取舍收到一处，接受后再写 Spec。另一种做法是不写提案，Spec 的批准依据直接指向 Work 与 t07 的决定记录。
2. **配方是作品里的一个文件。**打开它就是工作台这个标签页；保存、未保存标记、外部改动照编辑区已有的规则；Agent 用读写文件的工具就能看和改。另一种做法是存进数据库，在专门的列表里管理。推荐文件。
3. **本书的预设和片段也是作品目录里的文件**，资源管理器里看得见，平时在词库侧栏里管理；“我的书架”放用户目录。另一种做法是藏起来，只能经侧栏看到。推荐看得见。
4. **历史批次的记录跟着配方存，图片照 t06 已写的做法**：没采用的图在缓存里，采用（“用作插图”）后才进作品目录。缓存只由作者手动清；清掉以后那一批还能恢复配方，只是没有图。
5. **节的种类固定**：主体、画风、质量、场景与构图、自然语言、角色、负面，加参数。顺序可以按配方调整，第一版不能自己建节。
6. **预设的改动按“项”记。**画风里一位画师、一个年份、一个压制词各算一项；质量与负面里一个词算一项；参数里一个字段算一项。改动只有三种：加一项、去一项、改一项的值。预设更新后把这些改动重新套上去；预设里已经没有那一项时，这条改动作废，并提示一次。
7. **第一版的角色只能自己写或用片段。**静态稿里的“来自设定”入口等角色视觉档案（t11）做了再出现。
8. **读 NovelAI 图片里的元数据进第一版。**把图拖进工作台，走粘贴拆分的同一张预览，一次带出主提示词、负面、角色与参数。只读图片文件里标准的文本元数据。推荐做：有了粘贴拆分以后，多出来的只是读元数据这一步。

还要等的：t02 没测，token 数与费用怎么算、V5 的质量词与负面预设由谁添加，都等它的结论；这些只影响 `images/generation`，不挡 `images/prompt` 与 `images/recipes`。

### 模型

- **模型 1：**节是有序列表，每节有种类和可选的名字，同一种可以有几个；种类由系统定：主体、画风、质量、内容（原“场景与构图”）、自然语言、通用，加角色、负面、参数。新配方每种一节。取代第 5 条。
- **模型 2：**风格组合进第一版：一次套画风、质量、负面、参数；“本书默认”就是默认的那一组。
- **模型 3：**粘贴默认按原文段落分节、保住词序；勾“存成画风预设”时才把画风词归拢成一节，并提示挪动几个词。
- 数据形状：负面分官方段、我的负面、要避开的画师三节；权重存在每一项上，拆过或改过的节按规范写法写出（改了第 1 轮“原文原样写回”）；角色框带自己的负面；“图中文字”单独一项、展开时总在主提示词最末；参数预设不含尺寸、张数、种子；片段可分主提示词一段加各角色一段；差异的“加一项”带锚点；项与节可以停用；预留底图字段，项可以不是文字。
- 规则：“压制”按词的类别判断，不看正负号；换预设时差异照“更新预设”的规则处理；`||a|b||` 随机写法在本地抽签，历史记抽到的词。
- 以后：“几选一”项、LoRA 与区域提示词、画风预设带氛围参考图。维持：种类由系统定、一份预设只管一种节、差异只有加去改三种、片段不加差异层（只记关掉了哪些陪衬词）。
- 生成记录按节的 id 存内容。
- 等 t02：词序的作用；连写数值权重是替换还是相乘；`0::词::` 是否等于没写；随机写法是否服务端抽签。

### 图片存储（2026-11-10 开发者“都按推荐”）

开发者提出：生成的图都不想丢，好的图作者会收藏；大部分是失败品，空间清理时可以清；要一套像 Telegram 的空间管理（例如预留 40 GB）；有些图跟着书走，收藏的图本地另存一份，是应用级的。主会话的方案开发者同日按推荐定：

- **两处存放。**
  - 本机一个应用级的图片仓库：这台机器上生成的全部原图，按内容哈希存、不重复；收藏的图也在这里，只是钉住。
  - 书里：生成记录、缩略图、`.image` 插图文件夹，跟着书走、进 Git。
- **收藏**是应用级的：在仓库里钉住，出现在跨书的“我的收藏”里，书删了还在。收藏时另存完整来历（按节的提示词、当时预设与片段的名字和内容、参数、模型、种子、来自哪本书哪份配方）；原图字节不改，NovelAI 写在图里的元数据留作备份。
- **跟书走：**用作插图，或被定妆图、源图、参考图引用时，复制进书；收藏的图拿到另一本书里用也是复制进去。同一张图在仓库与书里各一份是有意的。
- **空间管理**（设置里的“图片空间”分区）：占用条（可清理的原图、收藏、缩略图；书里的图单列只显示）；按书列出占用与最早日期，可单清一本，移出书架的书单列一组；只有一个开关：上限，缺省 40 GB。不做按时间保留。
- **存储 1：**到上限自动清：最久没看过的先清，清到上限的九成，状态栏提示一次清了多少；最近 7 天生成的、等审阅的候选（t10）不清。清掉的原图，书里的缩略图与记录还在，能恢复配方。
- **存储 2：**上限只管没收藏的原图；收藏与书里的图不会被自动删，占用单独显示。
- **存储 3：**第一版收藏只存本机，做“导出收藏”（可读的文件名加来历说明）；跨机器同步等平台的同步提案。备份整个状态根会连明文凭据库一起带走，所以导出是收藏唯一的备份手段。
- **平台代价：**仓库放在图像插件的私有目录（状态根下）。`runtime/plugin-api.md` 写插件私有目录“另定”，[插件的数据与状态](../../../../../docs/proposals/plugin-data-model.md) 说大文件走“文件或资产服务”，都还没有，图像插件是第一个使用方。生成在服务端跑（凭据在那里），原图由服务端写；生成记录、缩略图与插图文件夹由项目实例写；两步之间崩了会留孤儿，仓库启动时对账。仓库目录不对作者开放，要拿图走导出。
- **用词：**图片与标签都叫“收藏”，界面与规范里写全“收藏的图”“收藏的词”。

### 写 Spec 前的假设（2026-11-10 列出，同日确认）

这些是提案没定、会改变行为的细节，每条后面是主会话的推荐。开发者 2026-11-10 答“可以”，全部按推荐写进 Spec。

`images/prompt`：

- P1 **词与句子怎么分。**按逗号切成词。以大写字母开头、至少三个词的一段算句子的开头，句子一直到句号、问号、感叹号或末尾为止，中间的逗号不切。含中文的一段算句子。依据是 Danbooru 标签全是小写。
- P2 **片段在“原文”里的写法。**写成 `@{片段名}`，按名字找本书的片段，找不到时体检提示。
- P3 **规范写法的数值。**保留到小数点后四位（1.05 的平方 1.1025 能原样写出）；权重为 1 的词不包；相邻同权重的词合成一段。
- P4 **SD 写法的识别。**出现 `(词:数值)` 就按 SD 读，预览里可以改回 NovelAI 读法。
- P5 **全角逗号与下划线。**全角逗号当逗号读；下划线照原样保留。两样体检都提示，都能一键改。
- P6 **长度上限。**一段原文最多 65536 个字符，超过就报错，不解析。

`images/recipes`：

- R1 **文件格式与位置。**带版本号的 JSON，扩展名是 `.recipe.json`、`.preset.json`、`.fragment.json`、`.style.json`。插件按扩展名在全书里找，放在哪个目录都行；新建时缺省放 `插图/配方/`、`插图/预设/`、`插图/片段/`。
- R2 **本书默认存在哪。**本书项目层配置里的一项“默认风格组合”，指向一个组合文件。
- R3 **我的预设库与官方预设。**
  - 我的预设库放在 `user://image-presets/`。拿进书里是复制一份、给新 id、记下来源；放回库里同理。
  - 官方预设随插件安装、只读，id 以 `official:` 开头，配方可以直接引用。
- R4 **片段的用途。**固定七种：外貌、服装、动作、表情、互动、场景、构图，照静态稿第 3 轮。
- R5 **项的规范化文字。**转小写、下划线换成空格、连续的空白合成一个、去掉首尾空白。差异与“重复的词”都按它认项。
