# 产物管理的纸面模拟与提示词模型的压力测试

2026-11-10，w00042 t03。开发者看过提示词模型以后提了两件事：产物怎么管还没设计，工作台以后用起来最烦的就是它；模型撑不撑得起日常使用、灵活度够不够。主会话派了五个子代理：三个按不同用法在纸面上模拟几个月的使用，一个调研现有工具怎么管产物，一个拿社区提示词的本地数据给模型做压力测试。本文只写方法、统计与结论；完整报告、脚本与输出留在本地（`.local/agent/works/w00042-image-generation/tasks/t03-core-contracts/reports/`），因为压力测试的报告引用了不许再分发的法典图鉴原文。下面的例子都是自己编的。

决定记在 [t03 的“产物管理与模型灵活度”](../tasks/t03-core-contracts/README.md#产物管理与模型灵活度2026-11-10-开发者都按推荐)。

## 产物：和现有规则的冲突

主会话核对过：

1. **历史写进配方会丢数据。** 作者正改着配方没保存时，生成结果写回同一个文件就是磁盘冲突；编辑器遇冲突只给“重新载入磁盘版本”或“覆盖磁盘版本”（[`workbench/editor.md`](../../../../docs/specs/workbench/editor.md) 输出 15），总要丢一样。
2. **配方文件会撑破上限。** 作品文件正文上限约 960 KiB（[`workspace/files.md`](../../../../docs/specs/workspace/files.md) 的“正文上限”）。每批记录约 2.5 KB，常用的配方两三周就超。
3. **`.nbook/` 下的图浏览器读不到。** 文件服务拒绝控制目录，按地址读字节得到 404（同上，控制目录与验收 10）。放进看得见的目录又会淹没资源管理器与 Git。
4. **插图对照表不能放 Storage。** project 分区 Storage 在 `.nbook/storage.sqlite`，用 Git 时要忽略（[`storage/persistence.md`](../../../../docs/specs/storage/persistence.md)），克隆后全书插图会断。
5. **采用的图会在 History 里再存一份。** [文件访问与改动记账](../../../../docs/proposals/file-access-and-history.md) 规定 32 MB 以内的二进制全量存快照。
6. **canon 的图片存路径。** `image` 的值是“作品内路径加说明”（[`canon/components.md`](../../../../docs/specs/canon/components.md) 输出 15），改名、移动、换版本都要改 canon。
7. **插件私有目录还没有。** [`runtime/plugin-api.md`](../../../../docs/specs/runtime/plugin-api.md) 写“插件私有目录随资源寻址与文件服务另定”；[插件的数据与状态](../../../../docs/proposals/plugin-data-model.md) 说大文件走“文件或资产服务”，也还没有。
8. **“我的书架”与书架页重名**（[`workbench/bookshelf.md`](../../../../docs/specs/workbench/bookshelf.md)）。

## 产物：模拟里的其它问题

- **清缓存连带清掉要用的图：** 好图、预设样图、花过点数的图、局部重绘的源图与遮罩。
- **找不到图：** 历史缩略图带到几百批翻不动；没有跨配方的地方；Agent 没有可查的数据。
- **引用靠路径会断：** 配方、预设改名或移动以后，历史认不得它们。
- **点一批就恢复配方，翻历史会把正在写的配方换掉。**
- **后台候选没有收件箱，`<image-gen>` 没有 id：** 改稿、拆章以后候选挂错地方、重复出图。
- **同一张图被复制到几处，彼此不知道是同一张。**

## 现有工具的做法

- **NovelAI 网页版**的历史只在页面会话里，刷新即清空；参数写在下载文件的元数据里，右键另存不带。
- **A1111** 靠文件名模板与日期子目录，收藏靠扩展，备份重装后收藏全丢。
- **ComfyUI** 把整个工作流嵌进每张 PNG，有人从公开图片里扫出几百个有效的 API key；Preview 只写临时目录，Save 才写输出目录。
- **InvokeAI** 文件加 SQLite 两份真相；删除被使用的图时按位置列出用处，只是警告。
- **Lightroom** 把旗标、星级、色标分成三个维度，删除分三档（移出集合、移出目录、从磁盘删）。
- **Obsidian** 的附件是普通文件；旧的清理插件漏看一类引用而误删，新插件改成先列清单、默认进回收区。

反复出现的机制：参数嵌进图片、拖回即恢复；临时区与正式区分开；轻标记；删除分档；删前查引用。几乎所有库类工具的主要故障是**外部索引与文件对不上**。对本地优先、作品进 Git 的写作软件：主记录用可 diff 的文本，图内元数据只当备份并只写白名单字段；不让用户在索引管着的目录里挪文件。

## 模型：压力测试的统计

测的是 11-10 当时的模型：节的种类固定、每种一个、顺序可调；四种节能套预设，一节一个，引用加差异；片段是纯引用。

| 发现 | 数据 |
|---|---|
| 每种节一个会改掉词序 | 拆进各节再拼回，词序不变的 V5 只有 5.4%、V4.5 9.8%；换成最合适的节顺序也只有 8.6%、14.1%。约六成条目有一节被大段打断（两段以上、每段至少 3 个词） |
| 权重跨节 | 约 36% 的条目有一个权重同时管着几节的词；约一成画师和别的画师共用一个权重 |
| 负权重不都是压画风 | V5 负权重的词里画风类与内容类大约各半（`-1::hat::` 是去掉帽子） |
| 负面是三层 | V5 80% 的负面包含完整的官方 Heavy；个人另加的中位 35 到 49 项；再加随画风换的“要避开的画师”。只挂一份预设会显示成“Heavy 另加 51 个词” |
| 引用加差异可行 | 约九成负面、八成画风节离另一条不超过 5 项 |
| 画风与别的节绑在一起 | 画师相同的两条，负面里的画师、压制、质量词、采样参数相同的比例 61% 到 98%，随机两条只有 1% 到 34%；尺寸与内容不跟画风 |
| 角色框 | 27.5% 的 V5 条目给角色单独写了负面（官方叫角色的 Undesired Content）；18% 的框装的是文字、物体或分格 |
| 图中文字 | 11% 的 V5 条目用 `Text:`；官方文档要求它在主提示词最末 |
| 片段 | N5 法典三成的片段同时带角色框的内容；用的时候约一半被改过 |

按原文段落分节（同种节可以有几个）实测：中位拆成 3 到 4 节，约两成的词落进“通用”节，只有 40% 到 60% 的条目能得到一整个可以挂预设的画风节。

自编的例子：粘进“画师甲, 画师乙, very aesthetic, 画师丙, 1girl, 雨夜街道”。每种节一个时，画师丙被挪到质量词前面，`1girl` 被挪到最前；同一个种子大概率出不了原图（推断）。

## 要 t02 实测的

- 同一种子、同一参数、同一模型能否重抽出同一张图；Opus 订阅免费的范围；PNG 元数据的字段；局部重绘与放大的结果带不带元数据。
- V4.5、V5 里词的位置对作用有没有影响（官方只对 V3 及更早明说）。
- 连写的数值权重（`1.6::甲, -1::乙`）是替换还是相乘；`0::词::` 是否等于没写；`||a|b||` 随机写法是否由服务端抽签。
- V5 支不支持氛围迁移。
