# 评审板：页面里作答、侧栏确认，给页面更多地方

## 目标与范围

开发者 11-10（t22 评审板第 13 题与随后的两问）：评审板现在是中间 HTML、右边答题，题多了找不到题对应的材料，中间的页面也太小。定为：nbdev 提供评审板模板，答题控件放进页面里每道题的材料旁边，页面里填的只进草稿、在侧栏确认提交；给页面更多横向与纵向空间；手机上“页面 | 答题”两个切换（从 t22 第 3 条移来）。

合同：[面板](../../../../../packages/dev-panel/docs/panel.md)的“两个来源”与产物页、[文件格式](../../../../../packages/dev-panel/docs/file-formats.md)的提问标记；[Proposal](../../../../../docs/proposals/dev-panel.md) 第六条追加决策记录（iframe 只改草稿）。计划见 [plan.md](plan.md)。

## 决定（开发者 2026-11-10）

- 页面里填，侧栏确认：答题控件放进页面里每道题的材料旁边，页面里填的只进草稿，提交在面板自己的界面上按（页面脚本能伪造取值，最多改动草稿，不能替开发者提交）。
- 空间：横向给页面更多地方；纵向也省一点。
- 模板参考开发者 visualize skill 的经验。
- t22 第 3 条（手机“页面 | 答题”两个切换）并进本 Task。

- 计划：开发者 11-10 说“继续后续的任务”，按 [plan.md](plan.md) 实施。

## 实施中自定的（偏离计划或计划没写到的）

开发者 2026-11-10 追认：下面几条都按推荐。

1. **收起答题栏后的提交栏不直接提交**：计划写“提交栏 [提交 M 题]”；改成按钮展开答题栏（有改动时写“去提交 M 题”）。页面里填的要在侧栏看过一遍再交，收起时直接交就跳过了这一步；提交逻辑也只在表单里有一份。要改回：给 `AnswerForm` 加 expose 的提交，提交栏调它。
2. **点题跳转用题目后的小按钮**：nb-ui 没有链接样式的按钮，题目本身不改成按钮；页面上有元素的题（页面标记登记的）在题目后放 `IconButton`“在页面里看”，`ask` 登记的题不给。
3. **答题栏用 nb-ui 的 `Splitter`**：它已冻结（只给 nb-story、dev-panel 用，新代码用 nb-layout 的），dev-panel 的外壳左栏也在用、dev-panel 还不依赖 nb-layout；等 w00026 t14 迁移时一起换。答题栏宽 18rem 到 45rem，缺省 24rem。
4. **窄屏两个标签用 nb-ui `Tabs`**（换去处，不是 `SegmentedControl`）；同一个 `Splitter` 把没选中的一块收成 0，两块一直挂着，切换不重载页面。跨 1024px 断点时答题栏的根在 `aside` 与 `div` 之间换（`aside` 不能带 `tabpanel` 角色），表单重建、草稿不丢。
5. **页面里提交在途时也只读**：只读原因加一条“正在提交”，成功后草稿整份清空，在途时页面里改的会悄悄丢掉。
6. **iframe 点进外站**：外站也可能冒充页面发 `ready` 读到草稿；只在开发者自己点了页面里的外链之后发生，记为已知风险，没有加机制（窄场景）。
