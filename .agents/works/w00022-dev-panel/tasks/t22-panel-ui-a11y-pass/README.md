# 面板 UI 与可访问性的一次大检查

## 目标与范围

开发者 2026-11-10：做一次大型的 UI、可访问性检查，现在前端有些地方对用户不太友好。先逐页取证（自动检查加截图、键盘走查），按属实的问题定范围，再分批修。

分支 `feat/w00022-t22-ui-a11y`，worktree `.worktree/w00022-t22-ui-a11y`。开发者 11-02 定本 session 不做代码审查；这次的走查请了一个独立的前端审查者看截图与代码，是取证的一部分。

## 取证（2026-11-10）

- 真实面板只读走了 15 页 × 1440 与 390 两种宽度 × 亮暗两态，共 60 张截图（本地 `shots/`，不入库）；每张跑 axe，桌面亮色下按 Tab 45 次记焦点。没有点会写入的按钮。加载中拍到的 5 页重拍过一次。
- 独立审查者（Claude Sonnet）只读截图与代码写了 28 条（[报告](evidences/ui-review.txt)）；主会话逐条对过截图与代码：属实 25 条，部分属实 2 条（左栏展开箭头键盘可用、分隔线聚焦有提示但太弱），不采纳 1 条（条件不满足时提交按钮不灰：与 nb-ui 表单规范冲突）。
- axe 的大头是对比度：nb-ui 浅底徽标用强调色与状态色当 11px 字色（2.9 到 3.9）、字段说明用 `--text-muted`（3.0），面板自己的空状态灰字、已结束运行整行降透明度。其余是标题跳级、两个同名 `aside`、可滚动的代码块不可聚焦、按钮名字与看到的字不一致。
- 对话框焦点在隔离的面板上试过，没问题。

## 评审板

`artifacts/review`（kind review），第 1 轮：直接修的客观缺陷清单（不用答），12 道选答题定版式与文字的改动，最后一题收集开发者觉得不友好、上面没提到的地方。

## 决定（第 1 轮评审板，开发者 2026-11-10 答复）

全部按推荐：

1. `upstream-contrast` = 改上游：nb-ui 浅底与描边徽标的字色改用 `--accent-text` 与各状态色往深混一档，字段说明改用次级色；nb-layout 分隔线聚焦时加粗加底色。NeuroBook 应用里的徽标字色随之变深，要在 Lab 看受影响的场景。
2. `task-page-order` = 做：Task 页右栏最上面放“产物与文档”，手机上 README 之前一行“产物 N 个 · 待答 M”；checkout 与提交挪到右栏下面。
3. `artifact-mobile` = “页面 | 答题（N）”两个切换，有待答时默认停在答题。
4. `work-table` = 做：待答与谁在动改成状态旁的小标记（手机上也有），去掉“记录”列（不在 master 时状态旁写分支），产物数并进“当前情况”。
5. `lists` = 三个都做：产物列表完成态不画徽标、要处理的排前、手机标题独占一行；在跑页在跑的置顶、已结束收起、日志路径换成复制按钮；checkout 页手机上一项一张卡片。
6. `sessions-header` = 做：页头的 herdr 指标只在不正常时显示，正常时收进顶栏状态点；详情头留标题、状态、Task，其余收进“详情”。
7. `terminal-font` = 观看时字号设下限（约 10px），放不下横向滚动、贴着光标。
8. `code-banner` = 做：“知道了”按代码版本记住，加“复制命令”。
9. `wording` = 三项都做：编号与路径默认收起（出错时照写题号）、英文术语换中文（checkout、Work、Task 保留）、删掉不看也能操作的灰色说明。
10. `ephemeral-frame` = 保留虚线框：没人在动时不画、标签底色跟着所在的面、颜色与字号达标（后一项第一批已做）。
11. `lease-chip` = 改成链接，点了去会话页的这个会话；关键状态写成看得见的字；收件箱行里只显示。
12. `header-actions` = 做：每页一个主要操作用实心小按钮（Work 页“新建 Task”，Task 页“编辑 README”）。
13. `extra`（开发者原话）：“还有这个评审版，现在是中间 html，右边答题。我觉得可以尝试把答题内嵌到 html 中。nbdev 可以提供一套评审版模板。现在题目过多，很难找到题目对应的材料。还有评审版中间这个 html 展示空间太小了”。这是评审板本身的设计，另建 Task 讨论（见“下一步”）；第 3 条的手机切换等它的方向定了再做，免得返工。
