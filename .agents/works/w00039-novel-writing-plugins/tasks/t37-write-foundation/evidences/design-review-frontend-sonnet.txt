[1] 重要（F5 照字面实现会返工）| 依赖的机制不存在 | 计划“二、技术选型”条目选择器行、“三.4 引用”
现象：计划写“nb-ui 的 SearchSelect，按输入调新的 findEntries”，理由是“仓库已有；否决把全部条目一次读进下拉”。
核实：packages/nb-ui/src/components/form/SearchSelect.vue 的 emits 只有 update:modelValue（选中时）与 focus（第 61-64 行）；
输入的文字是组件内部的 query，不对外发出；候选列表是 `props.options.filter(option.label 包含 query)`（约第 90 行，本地过滤）；
SearchSelect.md“不支持”一节明写“多选、自由输入、异步加载选项、分组标题；按拼音或说明搜索：只按名称包含”。
为什么是问题：
 a. 宿主拿不到搜索词，没法“按输入调 find”；组件只能一次拿全量 options，正是计划否决的做法。
 b. 就算宿主把 findEntries 的结果塞进 options，组件还会再按 label 做一遍“包含”过滤：findEntries 靠别名命中的条目（label 是名字，不含搜索词）会被本地过滤掉，作者搜别名搜不到。
 c. 已选项的显示靠 options 里有同值的项（selected = options.find）：选中后 options 随搜索词换成别的结果，输入框会变空；引用字段的当前值（不在这次搜索结果里）也显示为空，除非宿主另外把它塞进 options。
 d. 同一个坑会出现在元素对话框里 nb-form 的自定义条目控件、新建对话框“上级与另一个身份的候选改用 findEntries”（现在是已读到的条目传给 Select，Select 同样是静态 options）。
建议改法：计划里补一项 nb-ui 改动（或在 nb-ui 里加 `filter: false` 加 `search` 事件的远程模式，同步改 SearchSelect.md 与 forms.md 输出 30），写成 F4/F5 的前置；或者用 SuggestionMenu 自己搭一个“远程搜索选择”组件放进 canon/web 并写进 Lab 场景。两种做法都要说清：已选项的显示名由谁给（建议值旁带 {id,name}，不靠 options 反查）、搜索请求的去抖与晚到作废、搜索失败与无结果的行。

[4] 重要 | 依赖的机制 / 遗漏 | 计划“三.4 Agent 改了东西”
现象：计划写“窗口收到 changed 事件，by 是 Agent 时给一条提示”。读 canon/web/world.ts：
 a. onEvent 里 `changed` 只在 `event.version > known` 时处理，且只是 invalidate；事件根本没有交给任何订阅者（CanonWorld 接口没有事件出口）。
 b. `known` 在每次读取回来时被抬高（第 315 行 status 读取、第 477 行本窗口写入）：作者保存的写入返回 v7 之后，Agent 的 v6 事件才到（两次写入的返回与事件的先后链路上没有保证），事件被丢弃，作者永远看不到 Agent 的那次修改；重连后的 resync 期间漏的事件同理不会补提示。
 c. `by.kind === "agent"` 区分 Agent 与作者足够；“本窗口发起”不用区分（本窗口的写入 by 是 author）。但另一个窗口里作者的写入在这个窗口里也是 changed，by 为 author，不提示——合理，只是 Spec 要写。
 d. 提示是“同一时间只有一条，新的顶掉旧的”（notices.ts、author-ui 输出 18）。Agent 一轮对话常常连着写几次：每次顶掉上一条；更糟的是它会顶掉作者自己刚保存的那条（作者的“撤销”不见了），也会在作者点了“撤销”、还原对话框开着时把提示换掉（输出 18 专门规定点撤销时提示先留着，为的是焦点有地方回）。计划只写“和保存后的提示是同一个组件，只是触发源不同”，没有写叠放规则。“Agent 改了 3 处”里的 3 是编辑项数，而 notice 只带一个 revision，撤销只能还原最后那一次。
 e. 没有页面挂着时，每次 Agent 写入都会成为一条工作台通知（notices.show 的分支），连着写就连着弹。
 f. 回执页与改动记录里把 Agent 标成“Agent”：receipt.ts 第 232 行、revisions.ts 的 actorText 与写入者筛选（REVISION_WRITERS 含 agent）已经做了，计划把它当新工作，不要重复做。
如何核实：world.ts 约第 160-172、315、470-480 行；notices.ts；receipt.ts、revisions.ts。
建议改法：CanonWorld 增加事件出口，在 `known` 比较之前、按 revision id 去重地发给“Agent 提示”这一个消费者（不依赖是否 invalidate）；提示规则写进 Spec：Agent 提示单列一条（或并入同一条但带计数“Agent 又改了 N 次”），不顶掉作者自己的提示、不在还原对话框开着时替换；撤销指向最近一次，或点开“看改动记录并按写入者 Agent 筛选”；没有页面挂着时按时间窗合并成一条通知。

[5] 重要 | 遗漏（会写坏数据）| 计划“三.4 语义档”“列表（nb-form 元素对话框）”
现象：人物闭环最重要的两个列表（知情的“他以为的”、态度的“态度”）带语义档子字段（plot/shared/declarations.ts 第 48-54、97-101 行；components.md 输出 20），计划把语义档只当顶层字段（改起点、记一句）讲，元素对话框把子字段当普通文字输入。读 canon 引擎：buildEntryView 交给界面的是 fieldValue 的结果，语义档有事件时是归纳后的文字，没归纳是“起点；之后：事件1；事件2”（engine/views.ts semanticValue/listValue）；以引用为键的列表还会把每个元素加上 `label`（labelKeyedElements），而 listItemProblem 对 keyedBy:ref 的元素带 `label` 直接判 type-mismatch。
为什么是问题：
 a. 对话框拿读到的值预填，作者哪怕只动别的子字段，“只发改过的”若把预填值当原值就不会发出这个子字段，但作者一动它，发出去的就是“起点；之后：…”的派生文字，覆盖起点，之后的事件还在，下次又拼一遍，越改越长。顶层语义档的现有确认条也有同一个预填（draftText(state.value)），但计划让这个问题在元素里放大。
 b. 元素子字段的“记一句”（地址 `态度[元素].态度`）在计划里没有入口：RecordForm 只在面板分页，人物页的行没有它。
 c. 元素的 `label`：非引用列表的元素 `label` 是必填字符串（listItemProblem），“从 item 声明生成表单”不会有它，`listAdd` 会 type-mismatch；引用列表相反，元素带 label 就拒。计划四与三.4 都没写 `id`、`label` 这两个不在 item 声明里的键怎么处理（独立设计 5.3 也没写）。
建议改法：fieldsToSchema 对语义档子字段给只读展示加“记一句 / 改起点”两个小按钮（起点用 unreduced.anchor 预填，不用显示值），元素对话框加一个“名字”输入（仅非引用列表），引用列表不带 label；把这三条写进计划与 author-ui.md；“只发改过的”按声明的原始值（对象的 `object` 读取）比，不按显示值比。

 d. “让 Agent 起草”之类入口计划里没做，（独立设计提了），是合理取舍，不记问题。

[10] 重要 | 遗漏（入口找不到）| 计划“三.4 主文字：文末‘加一段’（addBlock）”
现象：EntryPageHost.vue 的 tabs 计算只在 `view.text.length > 0` 时才出“文字”分页（author-ui 输出 9：条目没有主文字时不出“文字”分页）。新建的条目没有主文字，于是“文末加一段”所在的分页根本不存在，作者没有办法给任何条目写第一段主文字。主文字是作者写设定最自然的地方（开发者原话“要用户和 agent 都能改”），这一条会让 Agent 能写、作者不能写。
另：
 a. “改这一段”要的 MDX 源文字，在条目读取的 `view.text`（Block，带 source）里有，不在 render 的结果里（render 是语法树，只有出错块带 text）；EntryPageHost 现在不用 view.text 的内容，计划要说明改用它，并且是“所选位置上有效的源文字”（块可能被某章的 replaceBlock 换过），不是 init.text。
 b. 写错的 MDX 内核照存，渲染成“出错的块”；确认条里的预览只有“写回哪里与带来的变化”，作者保存之前看不到这一块会出错。计划“三.4”没有要求预览显示渲染错误。
 c. 文字分页现在没有确认条挂载点（见 [2]），块旁的“改这一段”也是文本框而不是确认条，意图（改设定、剧情里变了）与预览的位置要明确。
如何核实：EntryPageHost.vue tabs 计算（`entry.tabs.text` 的条件），nb-canon engine/types.ts 的 EntryView.text。
建议改法：文字分页对有写权限的作者总出（空时写“还没有主文字”加“加一段”），Spec 输出 9 同步；预览返回渲染诊断时显示。

[11] 重要 | 对照需求（仍改不了的数据）| 计划“一、Context：作者……都能改设定的全部数据”
对照开发者原话与计划列出的范围，核对条目与 Component 的字段后，仍无入口的数据：
 a. 条目的“从哪里出场”（appears）与“它是谁的另一个身份”（sameAs）：新建对话框能填，之后没有任何地方能改；EntryOp 的 `place` 只有上级、分组、种类、顺序，没有这两项。写错了只能删了重建（引用它的地方要重指）。
 b. 带实例声明的类型（现在登记的“面板”就是 instanceFields: true，没有任何内置字段，字段全靠条目上自己声明）：没有“声明一个字段”“删掉一个声明”的操作，EntryOp 没有，Agent 的 canon_write 也没有，作者与 Agent 都无法给面板加第一个字段，面板分页永远写着“这个面板还没有内容”。
 c. 图片字段只有“路径加说明”两个文本框，没有选文件、没有预览缩略图；作者要凭记忆手打作品内相对路径（components.md 输出 15 文件不存在照存），独立设计提了预览框，计划丢了。
 d. “从第 N 章起有”（剧情里的 `启用`）计划已写明不做，不记问题。
这些不一定都要在 t37 里做，但计划一的“全部数据”与“都能改”要改成带限定的说法并列出不做的清单（现在“八、不做与风险”没有这几条），否则验收时开发者会按原话认为缺了。
建议改法：a 给 place 加 appears、sameAs（内核小改，界面在移动对话框里）；b 要么加 `declare` 操作要么写进“不做”并说明面板暂不可用；c 至少显示“路径所指文件存在与否”的一行。

[12] 重要 | 接口与合同 / 遗漏 | 计划“三.4 列表元素对话框（nb-form）”与计划二“选用 nb-form”
核实了 nb-form 的自定义控件接口：确实存在（forms.md 输出 22，packages/nb-form/src/vue/widgets.ts 的 FormWidget：name、component、score、fallback；组件收到 modelValue、node、readonly、disabled、invalid、id、labelledby、locale、issues、options、meta；发出 update:modelValue 与 commit，暴露 focus），“条目选择要远程搜”靠自定义控件可以做，这一点计划是对的。但以下没写，F5 动手前要定：
 a. 控件需要的 `targets` 怎么传：hints.ts 的 HintsSchema 只认 label、help、placeholder、unit、widget、options、itemLabel、searchable、rows、choices、recommend、visibleWhen，其它 `x-form` 键 checkDescription 报 `unknown-hint`、readHints 直接丢。所以不能写 `x-form.targets`；要么放在 schema 顶层自定义关键字（要核对 checkDescription 对未知关键字的态度），要么用闭包按字段路径查表。
 b. 条目控件要调 findEntries（世界客户端），是闭包注入；每个字段一个控件实例，去抖、晚到作废、已选项的显示名（选中后不在搜索结果里）都要自己管，见 [1]。
 c. 值的映射：表单里一个引用字段的值是什么？世界里是 `{ref: id}`，nb-form 的字符串/对象控件是通用的；清空在 nb-form 里“删去键”（输出 4），世界里“未知”是 null；字段声明转描述时要写成 `T | null` 的联合，清除才会写 null。计划只写“字段声明经一个纯函数转成它的描述”。
 d. “只发改过的”：表单整值受控（输出 3），改一行 = 对每个改过的子字段一个 `set`（各自 `read`，各自按来历路由，可能一次修订同时改初值与几条不同的变更）；对话框里“剧情里变了”一项会让这些 set 合成一条变更。预览与保存之间原值变了，要按子字段重算“改过的”，不是整个元素。计划没写。
 e. 保存前的校验：文字与数字草稿在失焦或回车才提交（输出 15），对话框的“保存”按钮要先 `commit()`，并考虑 draft-state（unparseable）；计划没提 SchemaForm 暴露的 commit 与 draft-state。
 f. 服务端失败回到表单字段：计划新增的问题细项 path 是 `ops[2]` 这样的操作序号，不是表单的 JSON Pointer，element 内的某个子字段不合规（选项不在范围内、数超范围）没法标到对应的控件上，只能写在对话框顶部，要定。
 g. 超过 50 项的列表、没有元素的列表（现在 FieldRow.items 是字符串数组，丢了元素 id）：FieldTable 的行模型要带元素 id、是否来自变更，见 [3]d。
建议改法：计划二加一行“自定义控件登记两个：canon-entry（远程）、canon-image”，写明 targets 的传递（建议用 schema 顶层关键字 x-canon-*，并在 canon 的描述生成函数的测试里固定）、null 的写法、diff 的来源（对象读取的原始值）。

[13] 建议 | 别扭与反常 | 计划“三.4 列表元素的‘去掉’出路”
 a. “去掉时元素来自某章变更，就写明是哪一章加的，给‘打开那条变更’与‘剧情里变了’”：作者要在点了“去掉”以后才被告知（element-from-change 来自预览的失败）。每个元素行事先并不知道来历。要么行上一直标“第 N 章加”（来历读取是按页读的，列表每行都读要 N 次），要么点“去掉”才预览，计划需要写成后者并给“去掉”的确认对话框一个固定形状（预览中、失败的两条出路、成功的“带来的变化”）。
 b. “剧情里变了”在这里意味着落一条新的剧情变更到所选位置（初值上不可用）；对话框要显示“发生在第 N 章末尾”并提示作者可以在页头换位置，确认条里已有同样的措辞，直接复用。
 c. 出路“打开那条变更”打开变更详情页，那里的“改”只支持数（author-ui 输出 21：数的改动旁有“改”），元素增删的补丁没有入口；所以“打开那条变更”其实仍然去不掉这个元素。要么变更详情页同时给出“去掉这一笔”（内核有 `deleteChange`？未核实），要么把出路改成只有“剧情里变了”一个。
建议改法：写明 c 的现状，二选一。

[14] 建议 | 验收映射 / 可维护性 | 计划“六 界面与 e2e”“五 切片”
 a. e2e 1“空作品点‘新建人物’”需要一个空世界的测试环境，canon-author.e2e.ts 现在全用星瑕样本；计划没写空环境的生成方式（项目目录、租约、状态根）。
 b. 没有对应测试的行为：Agent 提示的叠放与不顶掉作者的提示、change 事件在 known 之后到达也提示（见 [4]）；元素对话框的版本冲突与值刚变了；element-from-change 的两个出路；已删除页的“恢复”；入口在只读、独占、按计划下的不可用与原因；别名 ×、加或去设定的失败；390 像素下页头（别名一行、“更多”新菜单、分页末尾“＋添加设定”）与设定视图空状态没有横向滚动（输出 14 现在只覆盖旧的页）；键盘（输出 11 只覆盖“改”按钮到确认条这一条链，新对话框、别名标签、元素行的 Tab 顺序与焦点回位没写）。
 c. 切片顺序：F4 的“新建对话框上级候选改用 findEntries”与“移动对话框”需要远程选择器，而选择器在 F5 的引用里才第一次出现；应单独成一片先做（组件加 .md、dom 测试、Lab 场景），F4、F5 依赖它。
 d. 每个新组件按仓库规则要有同名 .md、dom 测试与 Lab 登记（canon/web/components/*.md、src/plugins/lab/web/fixtures/index.ts）；计划只写“组件 dom 测试、Lab 场景”，没有列新组件清单（元素对话框、条目选择器、图片输入、别名行、设定加或去菜单、移动对话框、块编辑框、Agent 提示），实现时容易漏登记。
 e. 页头的 sticky：EntryPage 页头在 ≥481px 时 sticky，页头加别名一行后更高，与确认条 sticky top-0 叠放（见 [2]）；窄屏已有“不吸顶”的规避，宽屏没有对策。

[15] 建议 | 别扭与反常（可避免的两套输入栈）| 计划“三.4 共享的‘字段声明到输入’”
计划把“字段声明到输入”的知识放进 shared/ 供确认条与元素对话框共用，思路对，但实际是两套渲染：确认条用手写的 NumberInput/Select/Switch/Textarea（ConfirmBar.vue），对话框用 nb-form 的控件；数的解析也是两份（numbers.ts 的 parseDecimal 接受千位逗号与“−”，nb-form 的 numberCodec 自己一套）。引用与图片又要各写两遍（确认条版、nb-form 控件版）。
为什么要提：同一个字段在两个入口里行为会不一致（例如“1,500”在确认条里能存，在对话框里不能），新输入每加一种要写两份。
建议改法：确认条的输入区改用 nb-form 的 SchemaField（bare 模式，forms.md 接口已有）画单个字段，canon 的自定义控件只写一份；parseDecimal 并进 nb-form 的数字控件或两处共用同一函数。若觉得动确认条风险大，至少在计划里写明“确认条的引用、图片输入直接用同一个自定义控件”，不要各写一份。
