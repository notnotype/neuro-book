## 重要发现

### R2-01 · 版本相等不能证明 Agent 读取前提仍有效

- **类别：** 正确性 / 并发写入前提
- **位置：** `tasks/t37-write-foundation/plan.md` 第三节“关键设计”中 Agent 的 `sameVersion` 规则；对照 `packages/nb-canon/src/service/reads.ts:324–354`、`packages/nb-canon/src/service/service.ts:1264–1288,1330–1349`
- **现象：** 计划把 Agent 的新鲜度约束写成世界版本与 `baseVersion` 相等。真实服务可在世界版本不变时改变读取结果：已运行的真实 `WorldService` 探针先在 `ch2` 末尾按默认线读取到“主线值”，再仅更改该章的线映射；前后世界版本均为 `4`，读取结果变为“支线值”，`inputDigest` 也从 `f29df3c65fce8b54d02efbac95acb18a387792cbcf63bcb0468777df96b5d052` 变为 `40f36a7862079e386160c151891ed5379265dc46c00c7abe8be28c2f820dd3e8`。因此版本比较不能覆盖 Agent 实际读到的叙事输入；依赖缺省线、正文或其他输入作出的写入可能通过版本门槛而依据过期。
- **核实方法：** `/tmp/w37/review-design-backend-r2/same-version-line-probe.ts` 使用目标版本的真实 `WorldService`、真实分段日志和服务夹具执行；命令 `bun /tmp/w37/review-design-backend-r2/same-version-line-probe.ts` 成功。此探针证明读取前提可同版本改变，未调用尚不存在的 `editEntries`，不代表已复现未来批量入口接受过期写入。
- **建议改法：** Agent 请求携带与其读操作绑定的 `ReadStamp`，至少比较 `version` 与 `inputDigest`；在服务写队列内、幂等重放判定之后、候选计算及发布之前核对。不能只在队列外先查戳再排队。若产品有意只拒绝新修订而接受同版本输入变化，应在设计与确认记录中明确收窄，不要把它称作完整的读取前提校验。
- **限制：** 探针显式从目标 worktree 导入 nb-canon 与服务夹具；依赖目录位于主工作区且包链接指向主工作区，跨包依赖的逐项解析来源未核完。

### R2-02 · 旧合同订阅失败没有计划所说的刷新提示

- **类别：** 兼容恢复 / 远程合同升级
- **位置：** `tasks/t37-write-foundation/plan.md:173`；对照 `packages/nb-runtime/src/remote/node.ts:594–626,635–660`、`packages/neuro-book/src/plugins/canon/web/world.ts:198–200`、`packages/neuro-book/src/plugins/canon/web/WorldBanners.vue:21–25`
- **现象：** 计划写旧页签遇到 `version-changed` 后“照现有提示刷新”。运行时代码确实会对合同版本不符拒绝调用或订阅，但 canon 浏览器读取层把订阅失败归并为 `ended`，现有横幅只显示“世界已断开”及“重试”，没有刷新提示或重新载入路径。旧页签反复重试同一旧合同不会自行升级，因此计划依赖的恢复指引在现有界面中不存在。这个判断来自源码映射；本轮没有运行旧浏览器对新提供方的端到端场景。
- **核实方法：** 对照合同版本拒绝、客户端失败结果保留及读取层映射，再读横幅可见文案；在 canon 浏览器目录未找到刷新或 `location.reload` 处理。
- **建议改法：** 在 v2 迁移设计中明确旧页签如何获知版本不匹配并重新加载新客户端；保留并显示 `version-changed`，或提供明确的刷新动作。把相应旧页签／新提供方组合加入后续运行时验收，不把通用重试视为刷新。
- **限制：** 本轮未在真实浏览器运行组合场景；结论是现有代码路径与计划所称“已有刷新提示”不符，不外推为已观察到的端到端画面。

## 第一轮 01–11 处理判断

- **01：成立。** 预览与发布共用候选计算并在追加前完整读回核对，符合防止发布未核实候选的要求。
- **02：成立。** Agent 请求 id 绑定会话与 `ctx.invocation`，同次重发复用整份解析请求；仍须保留异输入复用 id 时的 `request-id-reused` 合同。
- **03：成立。** 批内创建的新条目、Component 与列表元素只允许在创建操作给初值，后续修改拒绝，避免生成没有独立来源的批内修订。
- **04：部分成立。** 新修订导致版本变化时拒绝并要求重读的方向成立；版本相等不保证叙事读取输入不变，详见 R2-01。
- **05：成立。** 章首剧情变化按新变更的 `slotAfter` 读回，针对章首键的旧缺陷补到了正确的读取位置。
- **06：成立。** 解析、来源核对与副本保留显式线 id，仅持久化安放省略主线，避免把“缺省读取线”误作“主线安放”。
- **07：成立为明确的范围限制。** 只允许修改或删除完全来自初值且未被该线剧情变更或 `carry` 碰过的元素；其余拒绝并指向 story，符合当前不追踪元素级历史来源的决定。
- **08：成立为迁移合同。** 单项入口复用路由和候选计算，同时保留旧请求摘要、字段、失败码及 `route`；计划要求以旧日志重放和重发测试锁定兼容。
- **09：成立。** `canon_write` 固定为 write，移除 Agent 预览分支，预览留在作者界面，回应了首轮工具等级问题。
- **10：成立。** 查找合同排除墓碑，按指定或缺省读取位置匹配名称与别名，并包含尚未出场条目的标记。
- **11：验收设计成立，性能结果未验证。** 以 14 的约 520 条目规模预热后重复测内核方法中位数并记录负载，方法可复现；本轮没有运行该基准，不能据此声称达到 20 ms。

- **113：** 按开发者“作者与 Agent 都能改设定”的方向接受底座范围；“可改图片字段”不应被扩写成已承诺文件选择、上传或存在性校验，这些由 120 明确排除。
- **114：** 可按四工具 `defaultForAll`、不另建设定助手 Profile 推进；代码中 `defaultTools: false` 与用户绑定可移除非 required 工具，因此“所有会话”只能解释为默认贡献，不是强制可用。
- **115：** 接受 creative 下别名、列表和块增删只落初值，来源不合格时拒绝并指向 story；这是可解释的阶段边界，需把拒绝语义落实到合同。
- **116：** 按开发者暂时接受对象级冲突，并记录同一人物不同字段仍会冲突、要求重读；这是有意承担的并发体验成本，不是字段级冲突已解决。
- **117：** 接受先交付查、读、树与写，推后 `changes` 和全文 `search`；当前阶段可用 `read.history`，检索索引另有成本。
- **118：** 保持待确认。让 `auto` 下每次 `canon_write` 都询问模型审批，会改变平台权限语义；“作品内路径自动放行”本身不能说明语义写入是否应被当作路径权限处理。本轮没有独立核完权限规范的适用合同，不能替开发者定案。
- **119：** 接受创作修改只触及完全来自初值且该线从未被任何剧情变更碰过的元素；成本是限制较强，符合不追踪元素级变更来源的既定范围，需在失败结果中指出相关剧情变更。
