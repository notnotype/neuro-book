## 1. 重要 / 正确性：OriginList 改成固定列的网格后，窄屏（390）位置列只剩约 42 像素
位置：packages/neuro-book/src/plugins/canon/web/components/OriginList.vue 的 `.origin-list__row`（grid-template-columns: minmax(0,1fr) 5rem 6rem 4.5rem，column-gap 0.75rem）
现象：变化、结果、按钮三列加三个间隙固定占 80+96+72+36 = 284 像素，位置列拿剩下的。390 视口下条目页内容列净宽 326（左右各 32 内边距），来历再嵌在值下面，位置列不到 42 像素；“第 12 章”“第 3 章末尾”这类位置（12px 字）放不下，会在位置列里折成两三行，一步变得很高。base 的位置列是固定 `w-16`（64 像素）、发生了什么在窄时换行，没有这个问题。
为什么是问题：输出 14（窄屏）要求 390 下条目页可用；e2e 验收 14 只量“没有横向滚动”，量不出折行。网格列是 `minmax(0,1fr)` 所以不会横向溢出，是静默变丑。面板分页右边一栏更窄，同样受影响。
如何核实：Lab 里 OriginList 场景把画布设 vp=390x844，看“第 2 章末尾”那类行；或从 DOM 量 `.origin-list__where` 的 getBoundingClientRect().width。
建议改法：窄时（容器查询或 max-[480px]）把结果与按钮挪到第二行，或让变化、结果两列在窄时收窄；至少给位置列 `min-width` 并让整行在窄时换成两行布局。
（从代码推断，未在浏览器量）

## 2. 建议 / 正确性：减弱动效时换分页仍有约两帧的空白，与文档“直接换”不符
位置：EntryPage.vue `<Transition name="entry-page-tab" mode="out-in">` 与同文件 style 的 `.entry-page-tab-enter-from { opacity: 0 }`
现象：Vue 的 Transition 先把 `enter-from` 类加上，要等两个 requestAnimationFrame 之后才去掉，旧内容的离场同理（leave-to 也是两帧后才加）。令牌时长是 0 时，计时在 `whenTransitionEnds` 里立即结束，但这两帧的等待仍在：旧内容多停两帧，新内容以 opacity 0 出现两帧再出来，约 30 到 60 毫秒闪一下。样式里只对 `prefers-reduced-motion` 去掉了 transform，opacity 0 的那段没去；应用自己的“减弱动效”设置（令牌为 0）连 transform 的 12px 偏移也还在这两帧里。
为什么是问题：EntryPage.md 与代码注释写“减弱动效时直接换”，实际换分页每次有一次短暂空白。
如何核实：e2e 里 emulateMedia({reducedMotion:"reduce"}) 后点分页，用 MutationObserver 记 tabpanel 内容层有没有 `entry-page-tab-enter-from` 类出现过；或看 Vue runtime-dom 的 Transition 的 nextFrame。
建议改法：减弱动效时不挂 Transition（`:css="false"` 或按设置给 `name` 空），或给 enter-from/leave-to 的样式放进 `@media (prefers-reduced-motion: no-preference)`，并把应用设置的减弱动效也接进来；或改文档写“约两帧”。
（从 Vue 源码推断，未在浏览器验证）

## 3. 建议 / 正确性：ComponentRawView 的“初值”一段用变更列表的条数判断加载，会闪出“初值里没有这组设定”
位置：ComponentRawView.vue 初值一段 `v-if="props.loading && props.changes.length === 0"` / `v-else-if="props.initial === undefined"`；数据来自 EntryPageHost.vue 的 `rawView`（`loading` 是两个读取的或，`initial` 来自 `rawEntry`）
现象：初值与变更是两条独立的读取。变更先回来（非空）而条目对象还在读时，`loading` 为真但 `changes.length > 0`，第一个分支不成立，`initial === undefined` 成立，初值一段写出“初值里没有这组设定”，等条目读回来再换掉，是一句错话闪一下。反过来，条目已读到而变更还在读且为空时，初值段显示“读取中”，已有的初值被藏着。
为什么是问题：初值一段的“有没有”应该由条目读取自己的状态决定，不能借变更列表的条数。
如何核实：Lab ComponentRawView 场景里 `loading:true, changes:[2 条], initial: undefined`，看初值段文字；或 dom 测试里补这一组 props（现有 ComponentViews.dom.test 的场景没有这一组）。
建议改法：宿主分别给 `initialLoading`（rawEntry）与 `changesLoading`（list），两段各用各的。

## 4. 建议 / 不变量（键盘与读屏）：Tab 离开搜索框时焦点掉到文档末尾
位置：AddComponentPicker.vue `onKeydown` 的 `event.key === "Tab"` 分支（`emit("close", false)`，不 preventDefault）
现象：浮层传送到 body 末尾，焦点在里面的搜索框上。按 Tab 时 close(false) 把浮层卸掉，焦点不回到“＋”，浏览器从被卸掉的节点之后找下一个可聚焦元素，落到文档末尾或浏览器界面，再按 Tab 从页面最前开始。键盘用户打开浮层又想放弃，要重新走一遍整页。
为什么是问题：Spec 输出 38 只写 Escape 回到按钮，Tab 没写，但 AddComponentPicker.md 把 Tab 定为 close(false)，结果是焦点丢失，不是“离开”。
如何核实：e2e 里 Tab 之后读 document.activeElement（预计是 body）。
建议改法：Tab 时先把焦点放回锚（close(true)），不 preventDefault，默认动作会接着从锚走到下一个元素；dom 测试把“Tab 发 close(false)”改成断言焦点位置。
（从代码推断）

## 5. 建议 / 测试与代码质量：`alignPanel` 里真正起作用的是强制回流引起的滚动夹取，`scrollTop += gap` 分支几乎走不到，e2e 也区分不出
位置：EntryPage.vue `alignPanel`；e2e/canon-author.e2e.ts 分页排法一条里“滚过分页条以后换分页”那几行
现象：out-in 时旧内容先被移除，`before-enter` 里读 `getBoundingClientRect()` 会强制回流，这时分页内容是空的，文档变矮，浏览器把 scrollTop 夹到 0（`article` 是 `min-h-full`，空面板时文档不会比视口高）。夹完以后 `gap` 几乎总是 ≥ 0，`scroller.scrollTop += gap` 不执行。也就是“新的一页从吸顶页头下沿开始”靠的是这次回流的副作用，不是那行写入；谁把这次“只读”的读取改成别的写法（例如挪到 nextTick），行为就变成停在半中间。e2e 在 ≥481 宽度下页头吸顶、分页条一直可点（点击不需要滚动），后面量 `gap`∈[0,40)，没有 alignPanel 也满足，变异检查大概率活下来。
为什么是问题：注释写的机制和实际机制不一致；测试没有真的覆盖这条判据。
如何核实：变异检查：把 alignPanel 整个删掉，重建三份产物后跑该条 e2e，看是否仍通过；或在 before-enter 里临时 console.log(scroller.scrollTop) 看夹取后的值。
建议改法：注释改写成真实机制（空面板时的滚动夹取），或显式 `scroller.scrollTop = 0`/按吸顶高度写入而不依赖回流；e2e 改成在窄宽度（≤480，页头不吸顶、分页条会滚出视野）下，用 scrollTo 滚到分页条以下再用键盘（focus 加方向键）切分页，避免 click 自带的滚动。
（从代码推断，未做变异检查）

## 7. 建议 / 不变量：EditorGroup 换 OverlayScrollbar 后，所有页面标签的横向滚动条一并被隐藏；滑块轨道会盖住页面右缘的控件

现象：`nb-ui-scrollbar-none` 把 `scrollbar-width: none` 加到页面容器上，容器是 `overflow-auto`（双向），OverlayScrollbar 只画竖向。OverlayScrollbar.md 明写“需要横滚的元素不要用本组件”。条目页自己保证不横向溢出（验收 14），回执页、变更详情页、台账页（LedgerPage 的表格自带 `overflow-x-auto`）也有内层滚动，当前没发现真的会横溢的页面；但页面是别的插件也能贡献的（editor 的页面合同），第三方页面横向溢出时既没有滚动条也没有提示。另外，滑块显示时轨道（10px，pointer-events:auto）盖在页面右缘，页面内容右缘有必须点到的控件时（别的插件的页面）鼠标悬停在页面上就点不到。
如何核实：写一个贡献宽表格的测试页面放进编辑区，看有没有横向滚动条；悬停时点右缘按钮。
建议改法：EditorGroup.md 里把这条限制写明（页面合同：不得横向溢出、右缘留 10px），或页面容器改 `overflow-y-auto overflow-x-hidden`；第一版接受则记为已知限制。
（从代码与组件文档推断，未验证）
