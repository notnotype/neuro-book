## 一、4 张图上发现的其他问题

### 1. 短资料区 6 行重复“填写”反客为主，且全页空状态不统一
- **位置**：`01-person.png` 右侧短资料区（`性别` 到 `生死`），对比 `现在的状态` 与 `说话方式`。
- **问题**：
  1. 真正有值的 `身体：女`、`现在的样子：哥哥` 被压在 6 行相同的“填写”下面，人物卡第一眼全是待填表单噪音，且日常题材未必需要“生死”“所属”等字段常驻占行。
  2. 空占位写法分裂：短资料统一写按钮味很重的“填写”，下面 `现在的状态`、`说话方式` 却是场景化举例灰字，标准不一致。
- **建议**：
  - **推荐做法（减负优先）**：仅保留 3 个最高频默认项（如 `性别`、`年龄`、`身份`），把 `所属`、`现在在哪`、`生死` 移进 `+ 添加一项资料` 的快捷建议列表，用时一键添加（“此刻没用的就不出现”）。
  - **空值样式统一**：短资料未填时不要满屏写“填写”，改为极淡的短横线 `—`（hover 整行出现微弱底色，横线变为“填写”或直接给出编辑态光标），让已填内容立刻跳出来；下面长句字段保留现有的举例式灰字。

### 2. 短项编辑浮层定位压字、切意图后失焦像禁用态、且缺少字段标识
- **位置**：`02-short-editor-a.png`、`03-short-editor-b.png` 编辑浮层及背后的 `身份` 行。
- **问题**：
  1. **压住标签列**：浮层左缘偏左，直接把 `现在在哪` 的“哪”字切了一半。
  2. **不知道在改哪项**：浮层内部没写字段名、主输入框也没 placeholder；更严重的是切换到 `从第 3 章起`（`03-short-editor-b.png`）后，背后 `身份` 旁 `填写` 的浅灰高亮也消失了，视觉锚点彻底断开。
  3. **主输入框像被禁用了**：`03-short-editor-b.png` 切到 `从第 3 章起` 后，顶部主值框和下方原因框都是浅灰实底 + 灰框，且**两者都失去焦点**，第一眼像 readonly/disabled，用户还得再点一次才能打字。
- **建议**：
  - **对齐与锚定**：浮层左缘对齐触发的值起点（而非左跨到标签列）；打开浮层期间，原行保持极轻的选中底色（不随浮层内部焦点转移而消失）。
  - **输入态清晰**：可编辑输入框用白底 + 清晰边框（焦点蓝框），区别于禁用灰底；主值框加简洁 placeholder（如 `填写身份…`），一眼知道在改什么。
  - **焦点接管**：切换 `从最初起 | 从第 3 章起` 后，若主值框仍为空，焦点自动回到主值框；若主值已改过且切到 `从第 3 章起`，焦点自动落到“发生了什么”框，省一次点击。

### 3. 编辑浮层空值时“保存”仍亮蓝，原因框占位语偏长
- **位置**：`02-short-editor-a.png`、`03-short-editor-b.png` 浮层底部按钮与原因输入框。
- **问题**：
  1. `身份` 原值为空、输入框也未输入任何内容，但右下角 `保存 ↵` 是全饱和蓝色主按钮。尤其在“从第 3 章起”下，空值可点保存容易误造一条无意义的空变更。
  2. 原因框文案 `发生了什么（选填，不填就写“身份变了”）` 几乎撑满输入框，遇到长字段名（如 `现在的样子`）会截断，也略显唠叨。
- **建议**：
  - 与原值无实质变化时，`保存 ↵` 置为禁用态（仅当输入了新值，或对原有值执行清空时亮蓝）。
  - 原因框占位符缩短为 `发生了什么？（选填）`，或最多 `发生了什么？（留空记作变更）`，不把字段名硬拼进窄框里。

### 4. `现在的状态` 夹在右栏底部，层级不清且造成左右失衡
- **位置**：`01-person.png` 短资料区最下方（`+ 添加一项资料` 下方隔着一根短线）。
- **问题**：
  - 它被放在 `+ 添加一项资料` 之下、短资料栏之内，既不像上面的档案字段，又没和下方全宽的 `性格` 对齐；同时把右栏拉得比左边立绘框长出一截，立绘下方留出一块空洞。
  - 它的内容往往是一句短语或一串标签（如 `受伤、被通缉、刚搬家`），挤在窄右栏里极易折行。
- **建议**：把 `现在的状态` 移出右栏，放到「立绘 + 短资料」双栏区块**正下方**、全宽呈现（单行轻条：`现在的状态` 在左，内容在右，或浅灰胶囊行），下面再接全宽分割线与 `性格`。左右两栏高度更齐整，状态也有充足横宽。

### 5. 分页条右端 `+` 错位在“剧情”组外侧，空间归属混乱
- **位置**：`01-person.png`、`08-add-component.png` 分页条。
- **问题**：竖线 `|` 把左侧设定组（`人物 形象 文字 面板`）和右侧剧情（`经历 情节 20`）隔开了，但用于“添加一组设定”的 `+` 却放在 `情节 20` 很远的右端。视觉上像给剧情加分页，新加的设定组插回竖线左侧时还会造成空间跳跃。
- **建议**：将 `+` 紧贴在最后一个设定组分页右侧（竖线 `|` 左边）：
  `人物  形象  文字  面板  +  |  经历  情节 20`
  同时 hover 时给原生轻提示 `添加一组设定`；竖线右侧保持只放固定剧情视图（或让剧情区右对齐，彻底拉清两边职责）。

### 6. 来历入口（`前史改过`、`第 2 章改过`）与空占位灰字同色，看不出可点
- **位置**：`01-person.png` `身体`、`现在的样子` 两行值右侧。
- **问题**：`前史改过`、`第 2 章改过` 与上方 `填写` 的字号、灰度几乎完全一样，无背景、无边框、无图标，像纯静态注释，用户意识不到点它能看修改历史。
- **建议**：给来历入口一个克制的可交互外观——极淡的暖灰/冷灰胶囊（圆角 `4px`，浅灰背景 + `11px` 中灰字，或前置一个 `12px` 细线时钟/分支小图标），hover 时底色微深、文字转主色，一眼区分于不可点提示字。

### 7. 短资料区局部对齐与间距细节
- **位置**：`01-person.png` 短资料区。
- **问题**：
  1. **5 字标签贴值**：标签列宽不够，`现在的样子` 离 `哥哥`、`现在的状态` 离 `受伤…` 只有约 6–8px，几乎粘在一起。
  2. **`+ 添加一项资料` 左偏**：带按钮内边距导致 `+` 比上方 `性别`/`现在的样子` 右偏了约 8–10px，像二级缩进。
  3. **行尾 `...` 漂浮常驻**：`身体`、`现在的样子` 行尾的 `...` 隔着大半栏空白常驻在最右边，既产生噪点，又难一眼对应归属行。
- **建议**：
  - 标签列设固定最小宽（容纳 5–6 字，约 `84px–96px`）+ 固定列间距 `16px`，标签文字用中灰，值用深黑拉开对比。
  - `+ 添加一项资料` 用负左外边距（或去左 padding）与标签左缘严格齐平。
  - 行尾 `...` 默认隐藏，仅在 hover/focus 该行时淡入，同时给整行加极淡的 hover 底色条把左侧值与右侧 `...` 视觉连起来。

### 8. 头部 `+ 添加别名` 与 `< 在看 第 3 章末尾 >` 共行，语义混杂且易撞车
- **位置**：`01-person.png` 标题与简介下方一行。
- **问题**：别名属于条目自身属性，而“在看 第 3 章末尾”是整页所有分页的时间视角开关；两者并排既模糊层级，别名一旦添加 3–4 个标签就会直接撞上右侧时间控件。另外 `<` 和 `>` 与中间胶囊间隔偏松，不像一体控件。
- **建议**：
  - 把 `<` `[在看 第 3 章末尾 v]` `>` 收紧成一个紧凑的组合胶囊（3 像素内间距或一体化分段框），移到标题行右侧（`星瑕` 同行、`...` 左侧），或单独贴靠在分页条右上侧——把“整页视角控制”与“别名行”拆开，别名行即可自由换行展示多个标签。

## 二、三十多个设定组时，“添加一组设定”怎么设计

现状（`08-add-component.png`）的纯文字 5 行列表没有图标、没有说明、没有检索，到 30+ 组会完全不可用，且像“知情 / 知识点 / 态度”这类抽象词光看名字分不清区别。

### 交互形态：锚在 `+` 下的带搜索分组浮层（不做重弹窗，不打断浏览）
- **尺寸**：宽 `340px`，最大高 `420px`（列表区独立滚动），点 `+` 立刻展开且**自动聚焦搜索框**。
- **搜索**：支持中文名、拼音首字母、简述关键词与插件名过滤；输入时拍平结果，支持 `↑ / ↓` 移动、`Enter` 添加、`Esc` 关闭。
- **顶部轻量筛选胶囊**（仅当可用组 > 12 且跨 2 个以上分类时显示）：`全部` · `设定` · `剧情` · `插件`（无插件组则不显示 `插件`）。
- **单列紧凑行（每行高 46px，不用纯图标大网格）**：抽象设定组需要一句话说明才能区分，单列行最利于快速扫读。
  - 左侧：`18px` 线性图标（装在 `28px` 浅底圆角框内，风格与分页条图标完全一致）。
  - 中间：第一行组名（`13px` 中黑），第二行一句话说明（`11.5px` 浅灰，单行）。
  - 右侧：插件组加极淡来源标签（如 `修仙包`），内置组留白。
- **按当前条目类型智能置顶**（“系统能判断的不留给用户”）：
  - 顶部先给 `推荐给「人物」`（仅列 3–4 个最常配当前条目类型且未添加的组，如技能、物品栏、关系、态度；全加完后该分组自动消失）。
  - 往下按 3 个语义组排：`属性与设定`（人物、形象、面板、技能、物品栏、关系、组织、地点、物品等）、`剧情追踪`（态度、知情、伏笔、目标、知识点等）、`插件扩展`。
- **已添加的组怎么处理**：
  - 不可重复添加的组默认沉底收进折叠行 `已添加（4）▸`，不挤占视窗；**但搜索命中时直接显示并标 `已添加`，点击直接切换到那个已有分页**（不灰掉让人干瞪眼，“能替人做的就直接做”）。
  - 允许添加多份的组保留在主列表中正常可点。
- **添加后的即时反馈与防误触**：点击即添加并**自动切到新分页**；在底部 6 秒提示条中带一个轻量的 `撤销`（误点空组可一键收回，不留垃圾分页）。

## 三、分页切换动画方案

写作工具切分页是高频动作，核心要求是**快、稳、顺方向、随时可打断**，绝不做整页大滑屏（晕且拖沓）。

### 1. 方向（随分页条排布自动同步）
- **分页横排时（窄屏/当前截图状态）**：
  - 蓝色指示条：沿 **X 轴**平滑滑动并匹配新标签宽度。
  - 内容区：**微位移 + 淡入淡出**（位移量仅 **`12px`**，只给方向线索不晃眼）：
    - 向右切（如 `人物 → 形象`）：旧页向左 `8px` 淡出，新页从右 `+12px` 移入 `0`。
    - 向左切（如 `面板 → 人物`）：旧页向右 `8px` 淡出，新页从左 `-12px` 移入 `0`。
- **分页竖排时（宽屏状态）**：
  - 指示条沿 **Y 轴**滑动；内容区改为 **Y 轴 `8px–10px`** 微位移（向下切从下微入，向上切从上微入），保证控件排列与内容运动同轴。
- **减弱动态偏好**（`prefers-reduced-motion: reduce`）：位移设为 `0`，只保留 `80ms` 纯淡入淡出。

### 2. 时长与曲线（总耗时压在 160–180ms 内）
- **指示条**：`180ms`，`cubic-bezier(0.2, 0, 0, 1)`（快启稳停，不加弹性回弹）。
- **内容区采用“快退 + 轻进”短交错**（避免两页文字长久叠影发花）：
  - 旧页离场：`60ms`，`opacity: 1 → 0`，位移 `0 → ∓8px`（`ease-in`）。
  - 新页入场：约 `40ms` 后启动，持续 `120ms`，`opacity: 0 → 1`，位移 `±12px → 0`（`cubic-bezier(0.2, 0, 0, 1)`）。
- **可打断**：连续快点多个分页时，立即中止旧过渡直接进入最后一次点击的目标，不排队、不锁交互。

### 3. 高度不同的两页怎么过渡
- **不要给外层容器做 `height` 补间动画**。当前页面中分页内容下方没有紧贴着它的公共模块；如果强行做高度动画，只会让右侧滚动条滑块在 180ms 内抽搐拉伸，还会触发连续重排导致长文本页掉帧。
- **具体做法**：
  1. **防抖宽**：滚动容器配合 `scrollbar-gutter: stable`（同时一并解决第 5 条横向跳动），无论新旧两页是否触发滚动条，内容区宽度零位移。
  2. **文档流处理**：采用上面“旧页 `60ms` 淡出卸载 → 新页挂载 `120ms` 淡入”（或在容器内 `position: relative` 下旧页离场瞬间转 `position: absolute; inset: 0; pointer-events: none`，新页直接按自然高度占流），两页互不挤压高度。
  3. **长页切短页的滚动钳制**：若旧页（如长文页）滚得很深，切到短页（如空面板）时，不要停在底部空白，自动将滚动位置收回至分页条顶部（若页面未滚过分页条，则保持当前 `scrollTop` 不动，头部零跳动）。
