# 作者体验 E2（先写后补的作者）体验记录
角色：写网文的懒作者，前 3 章已写（《反派魔法少女》：重生成金毛狐女苏天晴，绑定墨丘利秘典，当反派魔法少女，去蹲风信子）。第一次用 NeuroBook。
依据：docs/proposals/world-engine-kernel.md（下称“提案”），小节号指第四节下的小节，写作“4.x”。

======================================================================
步骤 1　新建作品，把前 3 章贴进来
======================================================================
1. 我想做什么：我已经有 3 章正文，没有任何设定文档。我想新建一个作品，把三章放进去，然后开始写第 4 章。

2. 照提案会发生什么：
 - 提案 4.7“开始一部作品”写的是：新建作品，选题材模板或空白；“把故事种子发给 Agent”，Agent 先问几个挡住开局的问题，再建条目、记前史和开局状态、起草剧情线，然后我审阅。
 - 这是为“先有一句故事种子”的人设计的。我没有种子，我有三章成稿。
 - 提案第三节说章节在活页夹里（`*.binder/`，章节编号是稳定身份），所以三章大概是放进活页夹。但“怎么导入已有正文”“导入后会不会自动触发记账”，提案没写。

3. 哪里不清楚：
 - 提案没写：已有正文的导入入口。我不知道是粘贴、拖文件，还是让 Agent 去读。
 - 提案没写：导入后是“一次性把 3 章当成 3 次记账”，还是“当成故事种子让 Agent 一口气建条目”。这两条路径的审阅量差很多：前者我要审三轮，后者一大堆东西堆在一起。
 - “选题材模板或空白”：模板新建被明确推到 t12（第二节非目标）。所以第一次用的人到底有没有模板可选，提案自己都没交代。我只能选“空白”。
 - 第 7 小节开头说“入口：通过 NeuroBook 的界面，不直接编辑条目所在的文件夹”。那我的正文呢？正文是不是也只能在界面里写？提案没说，不过第三节说活页夹属于剧情插件，我猜正文照旧是文件。
4. 严重程度：重要（不阻断，我会自己想办法把文字弄进去；但“已有成稿的作者怎么起步”是很多人的真实起点，提案只覆盖了从零开始）。

======================================================================
步骤 2　看系统和 Agent 从正文里长出了什么
======================================================================
1. 我想做什么：三章贴进去之后，我想知道它“读懂”了多少：建了哪些条目、记了哪些变更、有什么要我确认的。

2. 照提案会发生什么（4.3、4.7、4.8、待定项 8）：
 - 照 4.8 的“记账”：Agent 读本章，提出本章的变更，作者审阅；待定项 8 推荐“整章一起接受，每条都可以单独驳回，有疑问的进待确认”。
 - 我能想象的产物：条目大概有 苏天晴、墨丘利秘典、守护之星、风信子、蓉城、绿心公园、英雄协会、兽人互助协会、神典石、太奶；变更大概有“重生成狐女”“绑定秘典签约”“发现守护之星、初次变身”“接到每日任务1（奖励 100 神典石）”“翻到任务夙愿（奖励 500）”“预测风信子今晚到绿心公园”。剧情线大概有“反派魔法少女”“找茬风信子”“夙愿”。
 - 例子 4.9 的日志样子（一行一条，有章、状态、出处、涉及、补丁）我看得懂，这一块写得好。
 - 我会不会去看：第一次会，因为是“我的书被读成了什么样”，好奇。但三章加起来可能一次冒出几十条，我大概只会扫条目名和待确认。看完信不信，取决于出处能不能一点就跳到原文（4.3 的字段表有“出处：正文 1.21–1.30”，我希望是可点的链接，提案没明说）。

3. 哪里不清楚、让我不放心：
 a) 提案没写：记账只说“提出本章的变更”，没说新设定（正文里第一次出现的人和物）由谁建条目、放进条目树的哪里。4.7 的“开始一部作品”是 Agent 建条目，日常循环里的“记账”却只提变更。只有 4.8 的自动预查提了一句“没找到的词……可能是这一章新引入的设定”。我作为作者看到的可能是：变更里写着“风信子”，但条目树里没有风信子。
 b) 条目树放哪由 Agent 决定，而我并没有分类意图。第二节说条目树“只用来组织和浏览”，那我怎么知道它放得合不合我的习惯？我只想要“按名字找得到”。
 c) 我这三章有大量内心独白（“我重生了”“这应该是魔法少女的变身道具”）和书里给的信息（秘典写“预测风信子将前往迎击”）。4.8 说“角色说的、想的不算世界的变化，第二版记成知情”。那第一版里，“秘典说风信子擅长近战”到底记成事实还是不记？我怀疑 Agent 会直接记成风信子的设定，但这其实只是秘典的说法（后面可能被打脸）。知情/说法分层被推到第二版，我这种“信息有来路”的书第一版就会遇到。
 d) 苏天晴有两层身份：前世的“我”（死于急性心肌炎）和原身“苏天晴”（死于暴发性心肌炎），同名，一个人占了另一个人的身体。照待定项 5，这种要做成“子条目，父子关系表示身份同一”；可第二节又说条目树“不表示地理上的包含或组织上的从属”。我作为作者听到“子条目”就以为是从属关系，提案自己用同一个树表示两种意思，这会让我困惑。
 e) 变身前后（狐女睡裙形态 vs 变身洋装）又是另一回事：4.9 里是 `character.形态` 字段而不是子条目。我怎么知道什么时候该做字段、什么时候该做子条目？

4. 严重程度：
 - a 记账能不能建条目：重要
 - c 说法与事实不分：重要（第一版接受的取舍，但我要知道会发生）
 - d、e 子条目与字段的取舍、条目树语义自相矛盾：重要
 - b 条目树的整理由谁负责：建议

======================================================================
步骤 3　准备写第 4 章：找回“秘典给的任务奖励”和“风信子擅长什么”
======================================================================
1. 我想做什么：我想不起每日任务1的奖励和夙愿的奖励是多少，也想不起秘典怎么介绍风信子。要找回来再动笔。

2. 照提案会发生什么：有两条路。
 - 路 A，问 Agent：我敲“秘典给的任务奖励是多少？风信子擅长什么？”。4.8 的自动预查只按名字和别名精确匹配（待定项 9）。我写的是“秘典”，条目名是“墨丘利秘典”，除非别名里有“秘典”，否则它会被当成“没找到的词”（4.8 说可能是新设定，也可能是写错）。Agent 之后要靠自己调 `lookup` / `search`，大概能找到。回答里带不带出处，提案没写（只有情节视图的“问一句”写了“每句标出处”）。
 - 路 B，自己去界面翻：条目页里有“情节”Tab，有分页、按章/剧情线/已写或计划筛选、关键词和语义检索、“问一句”（4.5）。那我得先知道奖励记在哪个条目里：秘典？苏天晴？还是有个“每日任务1”的条目？

3. 哪里不清楚、麻烦：
 a) 作者这边没有“全书搜索”。4.5 的检索都在“某个条目的情节视图”里，而条目树“只用来组织和浏览”。我要找的是一个数字，不知道它记在哪个条目下。这是最常见的找回场景，提案没写作者怎么全局搜。“search”工具是给 Agent 的，作者想要同样的一个搜索框。（提案没写）
 b) 奖励这种数字记在哪？v1 只有人物、面板、情节三种 Component。任务奖励不是人物，也不是我声明的面板字段，大概率只存在于变更的“描述”那一句自然语言里（“接到每日任务1：找茬魔法少女，奖励 100 神典石”）。所以要查数字只能读那句话，没有结构化的“任务”可以列出来看。我想要的是“秘典里有哪些任务、各自奖励多少、做完没有”这样一张表，提案里最接近的是“伏笔是一条剧情线”和“计划是状态为计划的变更”，我拼不出任务表。
 c) “风信子擅长什么”：人物 Component 的字段是“本名、性别、外貌、性格、说话方式、立绘等”（4.5），没有“擅长/能力/技能”，字段清单还要 t10 才定。所以这句话多半落在风信子条目的主 MDX 或情节描述里，也可能因为是“秘典的说法”被 Agent 写进自由命名空间。我怎么知道去哪找？
 d) 我把“秘典”“小破书”“狐狐”“天晴”混着叫。精确匹配只认名字和别名，别名谁来补？不补就等于每次都落到“没找到”。对我这种随手叫的作者，预查能命中的比例会很低。
 e) 好的一面：如果答案带了“出处：正文 2.79–2.84”并能跳过去核对，我就放心了。希望每个数字都带可点的出处。

4. 严重程度：
 - a 作者没有全局搜索：重要
 - b 任务奖励这类结构化信息没处放（只在描述句里）：重要
 - c 人物没有“擅长/技能”字段：重要（t10 未定）
 - d 别名漏补导致预查不命中：建议

======================================================================
步骤 4　发现 Agent 把一个数值记错了（任务奖励），改掉
======================================================================
1. 我想做什么：假设我在上一步看到某条变更写的是“奖励 1000 神典石”，但正文 2.84 写的是“奖励：100神典石”。我要把它改成 100，并且希望以后问到都是 100。

2. 照提案会发生什么：
 - 数字在变更的“描述”里时：我得改一条已经“已写”的剧情变更的描述。提案区分了两种改法（4.3 的表）：剧情变更（讲于第几章）与创作修改（改设定本身）。“界面要问这是剧情里的变化还是改正”。我这是“改正”。但我改的对象是一条变更记录本身的文字，不是条目的某个字段。那这算创作修改吗？变更能不能被改？“改过去”（4.4）说“改了某条变更”后面的状态都要重算，这个是支持的。
 - 数字在 `panel` 字段里时（比如 Agent 把“神典石余额”记成 +1000）：我在面板 Tab 里看到“当前值和流水”，点那条流水改。核对点（正文写明的数，和累加结果比，不对就报）能帮我自动发现，这点很好。
 - 数字既在描述里，又被 Agent 复制进了主 MDX 的文字或某个自由字段：这些地方各自成为一份真相源。提案反复强调“状态只有一份真相”，但没说描述里的数字和字段里的数字不一致时怎么办（4.4 的核对点只覆盖“正文里写明、面板上显示的数”）。

3. 哪里不清楚、让我不放心：
 a) 任务奖励这类“不在面板上”的数字没有核对点，Agent 记错了不会有任何程序报警，只能靠我自己读到、对原文才发现。这就是我想交出去的那种累活，而它恰好没人看管。
 b) 改一处是否会让别处跟着变？如果描述里的 1000 被引用进了别的条目的主 MDX（4.2 说主 MDX 可以引用别的条目的数据，不过引用的是状态字段，不是描述句），不会跟着变，我得逐个找。
 c) 改完之后，我怎么确认“这个数现在全书都对了”？提案没有“这个数在哪些地方出现”的反查。
 d) 4.3 说“作者和 Agent 的修改都记录在案，并且带描述”。我改一个数，要不要写描述？如果每次都要我写“为什么改”，很烦；如果 Agent 代写，我又不知道它写了什么。提案没写。
 e) 如果 Agent 是“聊天里被我纠正后自己动手改”的（4.8 写入工具），我如何发现它改对了、没顺手改别的？提案只说“Agent 可以直接写作者的文件，这一点不限制”，“靠修改历史与作者审阅兜底”（第五节），但“修改历史”长什么样、我在哪看，提案没写。我希望有一个“最近改了什么”的列表，每条一句话加前后对比。
 f) 术语负担：界面问“这是剧情变化还是改正”，我这个例子是“Agent 记错了”，既不是剧情变化，也不太是“我改了主意的改正”，是“纠错”。三选一里没有它。大概算“创作修改”，但名字里的“创作”二字会让我想成“我改设定”。

4. 严重程度：
 - a 非面板数字没有核对点：重要
 - e 看不到 Agent 改了什么：重要（提案已列为兜底，但没描述）
 - c 没有反查：建议
 - d、f 改动要问“剧情变化还是改正”、没有“纠错”选项：建议

======================================================================
步骤 5　写到第 3 章才决定要给主角加神典石面板（以前没记数），现在加
======================================================================
1. 我想做什么：我决定神典石是个要精确记账的东西（后面任务奖励、花钱、兑换），给苏天晴加一个“神典石”面板。前面三章没有记过数，神典石目前是 0。第 3 章我还想顺带记下“存款”，但正文只写了“捉襟见肘”，没写数目。

2. 照提案会发生什么：
 - 照 4.7“手动建一个人物”的第 3 条：对苏天晴“加‘面板’Component，声明字段，填初值”。4.5 说作者声明字段：数值、上限、枚举、能不能为负；Tab 显示当前值和流水。我声明“神典石”，不能为负，初值 0。也可以直接对 Agent 说，让它去做。
 - 4.4 说初值由创作修改设定，“排在前史之前”：条目在任何位置的状态 = 初值 + 之前的补丁。所以神典石从全书第一行起就是 0。
 - 这次加面板不是在第 3 章发生的事，是我改设定，记为创作修改，不挂章。

3. 哪里不清楚、让我不放心：
 a) “面板从第 3 章才有”这件事表达不了。我选“第 1 章开头”看苏天晴，面板上也会有一个“神典石 0”，而第 1 章里她连秘典都还没签。对 Agent 渲染也是同样（4.6 的带值写法），它会读到一个第 1 章就存在的面板。也许无害，但写第 1 章的补写（比如要不要加一段她第一次看到神典石）时，Agent 会以为面板早就在。提案没写 Component 本身有没有“从哪章生效”。
 b) 已有三章的变更怎么补？正文里“奖励：100神典石”只是悬赏，还没拿到，所以补丁不用动。但假如我这个面板在第 2 章就该有变化（比如首次变身送了 50），我需要在第 2 章中间“插进一条”补丁。4.4 说插进一条，后面的状态都要重算，这个支持；但“谁来插”“Agent 要不要自动回头给前三章补账”，提案没说。“改稿后的重新记账”被推到 t22（第二节非目标），所以大概要我手动让 Agent 补。
 c) 存款：正文没数。表单要我填初值。我会随便填个 3000？这个数没有任何正文凭证。4.3 说凭证可以是“作者在界面上的操作”，也就是我自己说了算，可以接受。但 4.4 还说“正文里写明的数记成核对点”：我这个数没写在正文，以后正文写了不一样的，系统是报错还是默默改？提案没写。
 d) 我得懂“数值、上限、枚举、能不能为负”四个概念，才能声明字段。对一个只想记“神典石：0”的人，这四项里至少“上限”“枚举”是白填的。希望最少只填名字和数值。
 e) 术语：4.7 和界面会叫我“加 Component”“声明字段”“命名空间”（4.2 提到面板、人物是“命名空间”，渲染里到处是 `panel.神典石`）。我是作者，不是程序员，我会问“为什么人物表单是 character、面板是 panel，英文？”。4.6 的悬停显示路径，我悬停就会看到 `panel.神典石` 这种东西。
 f) 对“Agent 去做”：对它说“给苏天晴加一个神典石面板，不能为负”，4.7 里没有明确说 Agent 可以做创作修改里的“加 Component”。4.8 的写入只写“记一条剧情变更，或者做一次创作修改，都带描述”，应该可以，但提案没把“加/去 Component”列进去，待定项 6 说去掉 Component 时数据保留隐藏。

4. 严重程度：
 - a 面板没有“从哪章开始”：重要（会让 Agent 对更早章节的认知有误）
 - b 前三章不会自动回头补账：重要
 - d、e 填表要懂数值/上限/枚举，路径英文暴露：建议到重要之间，按“很别扭但能用”记为重要
 - c 随填的初值没有凭证、以后与正文不一致时怎么处理：建议

======================================================================
步骤 6　随手写一张“技能和数值备忘”（自由文字），想让它也算进设定里
======================================================================
1. 我想做什么：我顺手写了一段备忘，比如“变身后：飞行、魔力 8000 起；守护之星：每日任务、变身；神典石 100 能兑换一次技能”。格式随意，想让系统以后写章节、审细纲时把它当设定。

2. 照提案会发生什么：
 - 提案里“作者手记”出现在三处：4.1 的“凭证”（正文段落、作者手记（原话）、作者在界面上的操作）、第五节“作者手记”是新的项目数据、4.9 例子里“手记1”“手记2”是变更的出处。所以手记是存在的，而且是“出处”的一种。
 - 4.9 里手记 1、手记 2 产生了前史变更和一条计划。看来流程是：我写手记，Agent 读它，提出变更，我审阅。
 - 但提案没写：我在哪里写手记？手记是一份文档，还是聊天记录？“原话”意思是保存我的原文吗？写了之后需要我点什么吗？
 - 备忘里的内容是“技能、数值”。v1 只有人物、面板、情节三种。数值（魔力 8000）可以进面板。技能（飞行、兑换）没有对应的 Component。大概进自由命名空间（待定项 7，推荐要）或主 MDX。

3. 哪里不清楚、让我不放心：
 a) “让它算进设定”没有明确的动作。我没找到“把这段文字转成设定”的入口。我只能对 Agent 说“看看我这张备忘，更新设定”。Agent 会做创作修改和变更。我怎么知道它转得对不对？同样靠审阅，但这次它转的是我的随手文字，我可能自己都没想清楚（比如“魔力 8000 起”是初值，还是第一章结束时的值？）。
 b) 两份真相源：我的备忘是自由文字，转写出来是结构化的字段。以后我改备忘，已转写的东西不会跟着改（重新记账的机制是 t22 的）。我该改备忘还是改面板？提案的原则是“作者通过界面操作”，备忘算不算被“界面”接管了？没写。时间长了，备忘和设定一定分叉，这正是我想用这个系统摆脱的旧版问题（第一节：设定会随剧情变，分不清哪句话是那时候成立的）。
 c) 备忘是“我心里的设定”，不是“已发生的事”。转写成变更时，是“前史”“初值”还是“计划”？这个分类提案靠 Agent 判断（4.3 例子里前史、已写、计划都有）。懒作者最怕的是被问“这条是前史还是计划？”。
 d) 自由格式文字里的“数”：4.5 说面板要精确数值，“魔力 8000 起”这种带“起”的模糊说法，进面板必须变成一个精确数。谁定？Agent 会猜，我审阅时才发现。
 e) 如果备忘里写的是以后要用的数值规则（升级所需、兑换比例），这是“规则”，不是“某个条目的状态”。提案里没有规则/系统设定的位置（条目是“人物、组织、地点、物品、概念、剧情线”，大概可以建一个“神典石兑换规则”的概念条目，只有主 MDX）。我作为作者不太会想到去建这个。

4. 严重程度：
 - a、b 备忘不能直接作为设定、写完以后分叉：重要
 - c 前史/初值/计划靠 Agent 猜：建议
 - d 模糊数字：建议
 - e 规则型设定没有明确位置：建议

======================================================================
步骤 7　不想每章都审阅记账结果：“它自己记，有问题再叫我”
======================================================================
1. 我想做什么：每写完一章都要点开变更清单逐条看，太累。我想设成“Agent 自己记，只有它觉得有问题或者对不上的时候再叫我”。

2. 照提案会发生什么：
 - 4.7 日常循环写死了：写正文、记账、审阅本章的变更。待定项 8 推荐“整章一起接受，每条可驳回，有疑问的进待确认”。没有“自动接受”的模式，也没有“按条件叫我”。
 - 提案里能算作“叫我”的信号只有：核对点对不上时“报”（4.4）、改初值时列出后面改过同一字段的变更（4.4）、文本 diff 三方合并失败时由 Agent 提出合并写法让我确认（4.4）、待确认条目（待定项 8）。这些都是“出现在界面里”，没有说“通知我”“数量提示”“下次打开提示我”。
 - 也就是说，不审阅的后果是什么，提案没写：
   · 未接受的变更，算不算“已写变更”进状态（4.4）？如果算，那我不看时 Agent 的错误已经成了“真相”，并且下一章的写手上下文（4.8，“涉及条目在第 N 章开头的渲染”）就会用上。
   · 如果不算，那我不审阅 = 状态不更新，Agent 在第 5 章拿到的是第 3 章的状态，越拖越旧。

3. 哪里不清楚、让我不放心：
 a) 没有“信任度”的概念。我希望：核对点通过、没有待确认的章，直接生效；有问题的才排队。提案里的零件都在（核对点、待确认），缺一个“默认接受”的开关，以及接受的语义。
 b) 我不审阅，却没有任何替代的“发现错误”手段。步骤 4 的数值错误如果不在面板上、也不是待确认，就不会有人发现。这会让我不敢放手。我希望定期有一个“这几章 Agent 记了 N 条，其中改动较大/不确定的是……”的摘要，而不是 N 条原文。
 c) “有问题再叫我”的“问题”由谁判？Agent 自己觉得不确定才会标待确认，它自信地记错（比如把秘典的预言记成事实）不会被标。提案没有任何“抽查”机制。
 d) Agent 直接写我的文件“不限制”（4.3、决策记录 11-01）。若再加“自动记账”，那 Agent 对我作品的所有改动我都不看，只有“修改历史”可回溯。第五节说“靠修改历史与作者审阅兜底”，两个兜底我都关掉了，就只剩理论上的历史。
 e) 回退：事后发现错了，能不能“把这一章的账整章撤回重记”？4.4 说改过去会重算，第二节说回档/世界线是非目标。整章撤销重新记账提案没写（t22 相关）。
 f) 好的一点：状态能随时重建（4.4 缓存可重建），错误至少不会不可逆。

4. 严重程度：
 - a 没有“自动记账、有问题才叫我”的模式：重要（我最想要的功能之一，提案里是缺口）
 - b、c 没有抽查和摘要，自信地记错没人发现：重要
 - 未接受的变更是否进状态没写清楚：重要
 - e 整章撤销重记：建议

======================================================================
问题清单（按严重程度排）
======================================================================
说明：没有一条我会因此直接放弃（没有“阻断”）。但“重要”里的几条合起来，会让一个不愿意盯着看的作者不敢把记账交出去。

阻断：无。

重要：
 1. 没有“自动记账、有问题再叫我”的模式（步骤 7）。现象：日常循环固定为“记账、整章审阅”；希望：核对通过的章默认生效，只把核对不上、不确定、改动大的排进待确认并提示我。
 2. 未接受的记账结果算不算进状态没写（步骤 7）。现象：不审阅时 Agent 下一章用的是什么状态不明；希望：写明“未接受的变更”是否参与渲染，并在渲染里标出“有 N 条未确认”。
 3. 看不到 Agent 改了什么（步骤 4、7）。现象：Agent 能直接写我的东西，兜底是“修改历史与审阅”，但没描述我在哪看；希望：一个“最近改动”列表，每条一句话加前后对比，能一键撤销。
 4. 不在面板上的数字（任务奖励等）记错了没人报警（步骤 4）。现象：核对点只覆盖面板上正文里写明的数；希望：任务/奖励这类数字也能被核对，或者至少能在某处集中列出来让我对原文。
 5. 已有成稿的作者起步路径没写（步骤 1）。现象：只写了“发故事种子”；希望：导入已有章节后，Agent 一次读完前几章，建好条目和变更，并明确告诉我“建了哪些、要我确认哪些”。
 6. 记账能不能给新设定建条目、放哪里没写（步骤 2）。现象：记账只提变更；希望：新出现的人和物自动建条目，并告诉我放在了哪。
 7. 作者没有全书搜索，也没有任务/奖励这类结构化清单（步骤 3）。现象：想找“奖励多少”只能进某个条目的情节视图，而我不知道它挂在哪个条目下；希望：一个全书搜索框，命中后直接显示原文出处。
 8. 人物没有“擅长/技能”这类字段，技能和规则性设定没处放（步骤 3、6）。现象：v1 只有人物/面板/情节，字段表还没定；希望：至少有一个“能力/技能”的文字栏，或明确告诉我写进哪里。
 9. 面板没有“从第几章开始存在”（步骤 5）。现象：后来加的面板在所有章节都有；希望：能说“从第 3 章起”，或者 Agent 知道早于此的章节不该提它。
 10. 前三章不会自动回头补账（步骤 5）。现象：加了面板后，前面章节的账要我手工让 Agent 补；希望：加 Component 时 Agent 主动问“要不要把前几章里相关的数补进去”。
 11. 自由备忘不能直接算进设定，改备忘不更新设定（步骤 6）。现象：备忘和结构化设定会分叉；希望：备忘改动后系统提示“有 X 条设定来自这段备忘，要不要同步”。
 12. 说法和事实不分（步骤 2）。现象：秘典说“风信子擅长近战”会被记成事实；希望：至少能标出“这是谁说的”，第一版就不做知情，也该留出标注位。
 13. “子条目”表示身份同一，与“条目树不表示从属”自相矛盾（步骤 2）。现象：我对树的含义没法理解；希望：用词分开，身份同一单独叫“同一个人的另一个身份”，别借用树的父子。

建议：
 14. 填表要懂“上限、枚举、能不能为负”，路径里露出 `panel.神典石` 这类英文（步骤 5）。希望：最简只填名字和数值，路径悬停显示的是中文名。
 15. 改一个值要先问“剧情变化还是改正”，且没有“纠错”这一项（步骤 4）。希望：选项用大白话：“是故事里发生的”“是我记错了/改主意了”“Agent 记错了”。
 16. 别名靠作者补，精确匹配对“秘典/小破书/狐狐”这类随口称呼命中率低（步骤 3）。希望：Agent 在记账时自动把正文里出现的称呼补进别名，并告诉我。
 17. 没有“这个数在哪些地方出现”的反查（步骤 4）。
 18. 整章撤销重记（步骤 7）；初值随填没有凭证、与以后正文冲突时怎么办（步骤 5）。
 19. 备忘里的“前史/初值/计划”分类靠 Agent 猜，会反过来问我（步骤 6）。希望：默认当“设定初值”，不确定的才问。

用下来觉得好的地方
======================================================================
 - 例子 4.9 的变更日志（一行一条，带章、出处、涉及、补丁）一眼就懂，“发生了什么、依据在哪一段”这种账，对我这种记不住全书的作者是真有用。
 - 变更和创作修改分开记（4.3 的表）。“是故事里发生的，还是我改了设定”这个区分是对的，旧版就是因为分不清而乱的。
 - 核对点（4.4）：正文写了余额，系统和累加结果比对，不对就报。这是我最想让机器替我做的事，而且比旧版的“断掉”友好。
 - 改过去会重算，并且改初值时把后面改过同一字段的变更列给我看（4.4）。我可以放心地“后来才想起来加个面板”。
 - 简单条目只要一段文字就合法（第二节目标 6）。懒作者可以不填表单，先留空（4.7 第 4 条）。
 - 按章看（4.7“按章看”）：能选“第 N 章开头/末尾”看某个人当时的样子，写补叙和改稿时很实用。
 - 计划也是变更，可以用“按计划”视图看“照计划第 N 章会是什么样”（4.4）。
 - 情节视图的“问一句”每句标出处（4.5），是我愿意信任它的前提。
