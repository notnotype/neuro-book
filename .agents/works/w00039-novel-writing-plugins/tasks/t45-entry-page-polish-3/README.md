# 条目页第三轮：添加设定组改成对话框与有名字的预设、三种看法挪到分页上、成段文字在下方编辑（开发者 11-27）

## 目标与范围

开发者 2026-11-27 试用 t43 之后的四条反馈：加设定组要能一次加几组、有几种有名字的预设，入口改成对话框；“三种看法”改名、挪位置；成段文字的编辑卡不要盖住原文；人物分页要能编辑。前三条在本 Task 做，第 4 条归 w00055（见“决定”第 4 条）。t44（Lab 与组件目录）排在本 Task 之后。

合同：[`canon/author-ui.md`](../../../../../docs/specs/canon/author-ui.md)（输入一节的 `canon.entry-kinds`，输出 4、9、38、51、54 要改）；nb-ui `Tabs` 的同名 `.md`。计划见 [plan.md](plan.md)。

## 开发者的四条（2026-11-27 原话摘要）与查到的原因

1. “我记得是有预设的吧，就是人物这种，应该可以给他预设几种常用的设定，用户好一次性把设定添加进去。这个添加设定要不要做成一个弹窗？”现有的两样都不是这个：种类登记的默认设定组（人物默认人物、形象两组，只在新建条目时勾上）；人物这一组的预设字段（种族、生日这些，只在“添加一项资料”里用）。“添加一组设定”的浮层一次只能选一项。
2. “卡片 | 给AI看 | 原始视图”改成“用户视图 | AI视图 | 原始视图”，放在这个位置不太好。现在是分段按钮，在设定组内容上方单独占一行、靠右。
3. “人物这个 Component 的视图不能编辑的吗？”查到：4317 的开发服务从 11-26 下午一直开着，期间加的 `entry.views.*` 文案键页面上读不到（日志 00:32 有四条 `missing-key`），开发者看到的是旧页面；已重启。生产构建里人物分页 13 个值点了都能改。开发者答复见“决定”第 4 条。
4. “形象 Component 中的外貌字段，点击编辑后，这个 popover 为什么没有像其他 popover 一样放在输入框的下方，现在直接覆盖了输入框。”原因：t43 按开发者“改外貌不要把现在穿的挤下去”把成段文字的编辑卡浮在原文上面（Spec 输出 51），连“外貌”标题也被压住一点；短项的浮层在值的下方。

## 决定

开发者 2026-11-27 在会话里答（四道选择题，主会话的推荐与 Gemini 顾问的意见一起给出）：

1. **预设做成几种有名字的预设**：种类可以登记几种有名字的预设（例如人物有“基本”与“主要角色”），插件可以往同一个预设里追加；“添加一组设定”改成对话框，顶上点一个预设就把它的几组勾上；新建条目对话框里也能用。
2. **三种看法的切换放在选中的设定组分页上**：选中的那一页写“人物 ▾”，点开选三种；不在用户视图时分页上写明（例如“人物 · AI视图 ▾”）。名字改成“用户视图 | AI视图 | 原始视图”。
3. **成段文字在原文下方出浮层**，原文不动、浮层盖住后面的内容（不推开）。Gemini 推荐的“原地展开、推开下面的内容”与 t43 第 5 条的决定相反，开发者没选。
4. **人物分页的编辑要的是 MDX 富文本编辑器模式**（开发者答“我要的是 mdx 富文本编辑器模式的编辑”）。这是 [w00055](../../../w00055-entry-rich-text/README.md) 定下的“设定组分页改成作者能改的默认模板”（它的 t02 计划里的后续 t05），不在本 Task 做；本 Task 不加“看得出能点”的提示（会被默认模板取代）。开发者的这句要求由 w00055 开 t05 时接上（主会话不改别的会话的 Work 记录，交付时提醒开发者）。

设计顾问（omp `@designer`，Gemini，[意见](evidences/designer-r1.txt)）另提、主会话照做的：对话框里已经加过的组勾着、不能取消、写“已添加”；预设只补勾、不取消手选的；什么都没勾时 Enter 直接加高亮的那一项；非缺省的看法在分页上写明。没照做的：390 宽改成底部抽屉（nb-ui 的对话框在 390 宽左右各留 16 像素，够用）。
