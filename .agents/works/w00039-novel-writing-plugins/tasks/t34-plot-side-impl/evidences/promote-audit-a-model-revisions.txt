- 公开入口：`@notnotype/nb-canon`（packages/nb-canon/package.json 的 exports "."）：对象与写入请求的 schema 与类型、`World`（发布、预览、还原、章序调整、就地改）、两个引擎 `createReferenceEngine` 与 `createIncrementalEngine`、`ChapterOrder` 与位置函数、`buildRegistry`、`buildMarkRegistry`、`buildDiagnosticRegistry`、`canonicalJson`、`authorizationBinds`、`editInPlace`、`recordDelta`；`@notnotype/nb-canon/schema`（只有 schema 与类型，另有 `PendingPage`、`CanonReadView`、`Finding`、`DiagnosticCompute` 等读取侧类型）；`@notnotype/nb-canon/node`（`WorldService`、`createReadView`、`pageOf`、`readStampOf`、日志存储）。应用侧：`nbook/plugins/canon/shared/contracts`（`canonWorldContract`、`canonClientKey`、`canonProjectKey`、`CANON_DIAGNOSTICS_POINT`、`CANON_MARKS_POINT`）。
- owner 与依赖方向：packages/nb-canon 持有对象形状、计算与诊断的处理；packages/neuro-book/src/plugins/canon 是宿主，注入文件、锁、时钟、摘要、作者来源校验，并把世界服务经远程合同交给浏览器与别的插件；packages/neuro-book/src/plugins/plot 经 `canonProjectKey` 登记诊断。nb-canon 依赖 `@notnotype/nb-time`、TypeBox 与 MDX 解析链，不依赖 neuro-book；主入口不引用 node:* 与 bun:*（packages/nb-canon/tests/architecture.test.ts）。
- 关键不变量（不超过五条）：
  - 增量引擎与整本重算对同一份输入的每个回答逐字相同，一次读取总等于在这份读取输入上从头计算（输出 5 到 13、36）。测试 packages/nb-canon/tests/differential.test.ts 的“差分：增量更新与整本重算逐字相同”下 `种子 %d，60 步`（模板 `种子 ${steps} 步`）与“序列里套不上的变更足够多（至少 10%），翻转与传染的路径走到了”；packages/nb-canon/tests/service.test.ts“同一份读取输入两次读取，戳逐字相同；重开后同样的日志与正文得到同样的戳”。注：差分生成器没有列表元素语义档的核对点（见上面的不一致）。

  - 全序与读取位置：初值、前史、第 N 章开头各不相同；同键时按版本再按 id 数值部分（输出 2）。测试 tests/model.test.ts“读初值是原来的值，读第 1 章开头已套上前史”；tests/core.test.ts“按数值部分比较，c9 在 c10 之前”。

## 实现合同草稿
- 公开入口：`@notnotype/nb-canon`：`World`（`publish`、`preview`、`revert`、`previewRevert`、`reorder`、`dependents`、`requested`）、`WriteRequest` 与 `Revision` 的 schema 与类型（`WriteRequestSchema`、`RevisionSchema`）、`WriteFailure`、`WriteResult`、`editInPlace`、`recordDelta`、`replaceOnce`、`authorizationBinds`、`requestDigest`、`fieldsDigest`、`signedContent`；`@notnotype/nb-canon/node`：`WorldService`（`publish`、`preview`、`revert`、`editInPlace`、`recordDelta`、`outcome`、`revisions`）。应用侧：`nbook/plugins/canon/shared/contracts` 的 `canonWorldContract`（方法 publish、preview、revert、editInPlace、recordDelta、outcome、revisions）。
- owner 与依赖方向：packages/nb-canon 的 `World` 持有写入校验、冲突、带来的变化、还原与依赖、作者授权的核对；`WorldService` 持有排队、落盘与独占（canon.project）；宿主（packages/neuro-book/src/plugins/canon）注入时钟、摘要、作者来源的签名校验与项目标识，并签发来源。nb-canon 只校验授权、不签发；不依赖 neuro-book。
- 关键不变量（不超过五条）：
  - 一个写入请求要么整个发布、版本加一，要么整个拒收、世界不变、不占版本号；跨条目的修改在同一次修订里（输出 1）。测试 packages/nb-canon/tests/revisions.test.ts“失败的请求不改世界、不占版本号”“临时 id 换成正式 id，新建存整份；转账两边在一次修订里”。
  - 版本冲突按对象判，没被改过的对象即使世界版本前进了也不冲突（输出 7）。测试 tests/revisions.test.ts“两人同时改：改过的对象报冲突并给出当前值，没改过的对象不冲突”。
  - 同一个请求 id 最多发布一次，内容不同拒收，重放日志后同样成立，重放得到的世界与发布出来的相同（输出 16）。测试 tests/revisions.test.ts“同一个请求 id 再提交返回第一次的结果，不多出修订；内容不同得到 request-id-reused；重放后照样”“重放日志得到与发布出来相同的世界”。
  - 还原是发布一次补偿修订；有依赖时不单独还原，连同依赖一起还原时从后往前补偿，补偿本身可以再还原（输出 11、12）。测试 tests/revisions.test.ts“还原新建条目的修订：后面引用了它的修订是依赖，不单独还原；连同依赖一起还原后都消失，再还原补偿又回来”。
  - 作者来源由内核比对 binds，不信宿主的校验结果；出处 `source` 只由内核在接受授权时写，请求里改它拒收（输出 21）。测试 packages/nb-canon/tests/decisions.test.ts“签名校验对什么都答通过时，挪到另一条决策照样被拒：binds 是内核比的；没有校验时一律不通过；用不上的、重复的授权都拒收”“请求里改了出处：source-not-writable；取出重新打开后的整份对象只改候选写回：不要来源，出处不变”。
- 实现入口：packages/nb-canon/src/world/world.ts（发布、预览、还原、依赖、章序调整）；就地改在 packages/nb-canon/src/world/edits.ts；作者授权在 packages/nb-canon/src/world/authorization.ts。
- 合同测试：packages/nb-canon/tests/revisions.test.ts（用真实 World 与真实 Component 登记，读取与发布走同一条路径，日志靠真实重放）；packages/nb-canon/tests/edits.test.ts、tests/decisions.test.ts（真实 World，授权用真实的 authorizationBinds 与注入的签名校验函数）。
- Smoke：不适用——本能力没有独立的运行入口，由 canon.project 的 Smoke 一并覆盖。现有写法仍对：project.md 的 Smoke 行列的文件都存在（packages/nb-canon/tests/sample.test.ts 我跑过，通过；两个实例写同一份日志的 packages/neuro-book/src/plugins/canon/two-process.test.ts 未跑）。
