# 揭示计划、一致性检查与试读者

## 目标与范围

把 nb-story 的秘密矩阵扩到作者侧（哪一章让谁知道什么），定三层（正文、设定、计划）对齐后报出哪些差异，以及作者写完一章后看到的“试读者”视角。三者都是拿读者此刻知道的与作者的设定、计划比，一起定。

合同：讨论 Task，只定设计，行为合同未变；定稿后的 Spec 改动在实施时另定。

前置：t02、t04。

## 要讨论的问题

### 秘密、知情与揭示计划

1. 作者层的秘密与读者层的秘密是不是同一个对象；作者没登记、抽取发现的秘密怎么处理。
2. 揭示计划的形状：对“读者”与对各角色分开计划；挂章节还是挂场景。
3. 泄底检测：计划第 N 章揭示，正文层在更早的位置已经让读者知道（或推断得出）；推断算不算泄底。
4. 旧版章级 brief 的“信息控制”四项与这里的关系：brief 从揭示计划编译出来，还是作者手写。
5. 误导与红鲱鱼：作者故意让读者相信错的东西，模型怎么表达（读者层的“相信”加作者层的“真相相反”）。
6. 与 t04 的交叉：回档后谁记得什么。

### 三层对齐与一致性检查（原 t08）

1. 差异的种类：设定有正文无（待写、伏笔未埋）；正文与设定矛盾（吃书）；计划未兑现；提前泄底；正文出现设定里没有的对象（要不要补进设定）。
2. 什么时候跑：每章写完、抽取完、手动、写手 Agent 交稿前。
3. 报给谁、怎么呈现：问题面板、章节旁的标记、给 Agent 的提醒；误报怎么消（标“有意为之”）。
4. 抽取本身有错（V9 实测秘密、状态、疑问三类最不稳）：误报率高时这个功能还有没有用，最低要多准。
5. 矛盾的处理方向：改正文、改设定，还是记成有意的反转。

### 剧情图谱进工作台与试读者（原 t18 的一部分）

1. “试读者”能给作者什么：本章读者新得知的、仍未解的悬念、对某人的印象；与上面的差异报告怎么分工。
