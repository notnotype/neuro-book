# 作品的来路：模板新建、旧项目迁移与导入已有作品

## 目标与范围

定一部作品进入新版的三种方式：从模板新建（现在新建只写 `.nbook/project.json`）、迁移旧应用的作品、导入已有正文（续写、同人）并用抽取结果起步。三者产出的都是同一种目录与设定，一起定。

合同：讨论 Task，只定设计，行为合同未变；定稿后的 Spec 改动在实施时另定。

前置：t09、t10。

## 要讨论的问题

### 项目模板

1. 模板的内容：目录骨架、清单、设定类型的 schema、示例条目、推荐启用的插件、项目级 Agent 指令。
2. 谁提供：内置、插件贡献、用户另存（放 `user://templates/`）、以后从市场装（接 w00038）。
3. 内置几种：空白、长篇网文、短篇、同人、剧本？按题材（修仙、都市、推理）分要不要。
4. 新建对话框里怎么选、预览；新建后能否再套用另一个模板的部分内容（例如只加一组设定类型）。
5. 模板升级：模板改了，用它建的旧作品要不要跟着改（倾向不改，只提示）。
6. `nbook project create`（w00032 t16）要不要带 `--template`。

### 旧项目迁移（原 t13）

1. 迁不迁：有多少用户、多少旧作品；只迁正文与设定，还是连剧情、世界状态一起迁。
2. 怎么迁：一次性迁移脚本（项目文件底座定的做法），还是导入向导；失败与回滚（备份）。
3. 旧 frontmatter（`retrieval`、`governance`、`ext`、相对路径 `refs`）的去向。
4. 旧 World 的切面与 patch、Plot 的两棵树、伏笔与决策映射到新模型的规则；映射不了的怎么保留。

### 导入已有作品：续写与同人（原 t25）

1. 导入入口：只导正文、正文加抽取、抽取结果直接生成设定条目。
2. 提升规则：哪些读者层记录可以直接变成设定（人物、地点、关系），哪些要作者确认（推断、角色的说法）。
3. 第三方作品的版权与只读：原作正文只读、设定可改。
4. 这是不是新模型最先能落地、最能检验合并价值的场景。
