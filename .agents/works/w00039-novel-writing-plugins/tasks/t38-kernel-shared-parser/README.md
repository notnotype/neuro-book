# 内核改用与章节相同的解析器

## 目标与范围

条目主文字只留一个解析器：扩展章节编辑器现有的解析器（marked），内核也改用它，作者与 AI 的写法不变（开发者 2026-11-23 定，另写 ADR 部分取代 0038 决策 1）。从 t28 拆出来单独做（开发者 2026-11-23 同意），排在主文字的编辑与条目树之后。

合同：[`canon/rendering.md`](../../../../../docs/specs/canon/rendering.md)（白名单、按块解析、带值写法与回写）；只换解析器时读法变化的清单写进它，同时换写法时它要重写，重新开工时定。

## 来由与已知的难点

t28 的设计审查（2026-11-23，[后端 omp 报告](../t28-entry-mdx-editing/evidences/design-review-backend-omp.txt)第 1 到 5 条、[独立设计](../t28-entry-mdx-editing/evidences/independent-design.txt)）指出换解析器比 t28 计划第 1 稿写的深，而且牵涉保密，所以单独成 Task、要有自己的设计与审查：

- **定位**：marked 的词法单元不带位置。按叶子的 `raw` 在原文里回搜会静默定位错（链接标题里有同样的表达式、引用与列表去前缀、CRLF、表格里转义的竖线）。要在分词时带着范围，或按容器逐行对齐，每处定位都校验、对不上就报错。
- **写入合同**：旧内核拒收的写法（没闭合的 `{` 或标签、`{a; b}`、空表达式）不能因为“marked 当普通文字”而变成放行；花括号的配平要用完整的 JS 词法（注释里的 `}`），表达式要整段校验、不只看 acorn 解析出的前缀。
- **保密关卡**：缩进代码、`$…$`、脚注、裸网址这些新出现的不透明容器会吞掉原来认得出的表达式与条目引用，给写手的简报因此从扣整块变成放行原文。要么条目的文法不带这些容器，要么认出“不透明容器里有条目写法”并照样记依赖或拦下。
- **带值回写**：`writeback.ts` 的 `scanAnnotations` 自己猜哪些 `{` 在 Markdown 的代码与链接里，要改成由同一份文法给出范围。
- **读法变化的清单**：独立设计实测的那张表（`a < b`、自动链接、缩进代码、单个波浪线、任务列表、引用定义、裸网址吞表达式、中文强调的边角）。
- 做法上先拍旧实现的快照、加随机生成的对照测试（独立设计的生成器与 omp 的反例脚本在本机 t28 的 `reports/` 下），用真实的旧日志穿过作者读取、Agent 读写与简报。

共用的文法放在哪个包、nb-canon 能不能依赖 nb-markdown 的纯入口（omp 第 12 条）也在这里定。

- 标签登记表（插件提供 `<StatBar>` 这类标签）与 `<html>`、`<jsx>` 沙箱块：本 Task 最多做登记表与内置的几个标签、留出沙箱块的标签名，数据通道与 JSX 运行时另开 Task。

t28 的 spike（分支 `spike/w00039-t28-entry-editor`）演示过富文本编辑主文字的效果，t39 会用到。

**设定组的展示部分用标签拼（2026-11-24 记下的想法，先不做）。**开发者在 [t41](../t41-character-component/README.md) 的评审板上问角色卡的展示部分是 MDX 还是 Vue 组件做的：“其实我也想看看用 MDX 的表达能力能不能做出这种角色卡。我们要提供什么接口给他们（MDX或者 vue 组件）。需要讨论一下。或者其实这可以可以两者都要：提供 react 组件，mdx 就写这一个 tag。”讨论后开发者定：“同意先做 Vue 组件。mdx 可以先不做。这里的想法可以先记一下。”记下的是：

- 现在的 MDX 做不出角色卡（同日用内核的写入检查实测，只收 Markdown、`{字段}`、`<Ref>`、`<Image>`）：没有左图右字这类版式；`<Image>` 只显示说明文字；值是只读的，不能就地改；没有循环，衣柜这种“有几套画几张”写不出来。能做的是标题、成段文字里嵌值、用表格排一张资料表。
- 设想的做法：展示部分先用 Vue 组件写，拆成只吃“字段地址加接口”的小零件（立绘、资料格、一段可就地填的文字、衣柜）；以后有了标签登记表，把这些零件登记成标签，每个类型的展示部分就是一段 MDX 模板，缺省可以只有一个标签（人物是一个角色卡标签），作者能改模板，也能在主文字里自己摆标签。这里是 Vue，不是 React；条目的 MDX 不执行，标签只认登记过的（[ADR 0038](../../../../../docs/adr/0038-world-engine-entry-text-is-whitelisted-mdx.md)）。
- 两种写法共用的接口：按字段地址读此刻的值；就地改（一直是这样，或从这一章起）与列表加减；这个值的来历。标签另登记三样：标签名、哪些属性是字段地址（依赖与保密靠它）、给模型看的文字。
- 可以做的小实验：在 Lab 里用一段 MDX 拼出与 Vue 版相同的角色卡，并排看差在哪。
