# 条目主文字的分屏预览与源文字高亮

## 目标与范围

编辑条目主文字时能一边写源文字、一边看渲染后的结果（宽处左右分屏，窄处预览排在下面）；源文字的输入框按条目的写法着色（Markdown 的标题、列表、强调，花括号里的字段，Ref 与 Image 标签）。开发者 2026-11-24：“可以再做一个分屏编辑（试试预览）。然后是代码编辑可以用 Monaco 这个组件来实现，还有文本高亮”。

范围：内核只加一条只读的方法（把一段没提交的源文字当作条目的主文字渲染），不改写入与写法；预览只能看；富文本、换解析器照旧搁置（[t38](../t38-kernel-shared-parser/README.md)）。

合同（都是 planned）：[`canon/rendering.md`](../../../../../docs/specs/canon/rendering.md) 输出 16、[`canon/project.md`](../../../../../docs/specs/canon/project.md) 方法表的 `renderSource`、[`canon/author-ui.md`](../../../../../docs/specs/canon/author-ui.md) 输出 48 与验收 16 新加的一句。

## 当前状态

2026-11-24 做完并合入 master（合并提交 `588438dc5`，分支 `feat/w00039-t40-entry-text-preview`）。[实施计划](plan.md)第 2 稿；开发者要的是先用起来，计划没有先交确认，主会话自定的几处记在[待确认清单](../../pending-confirmations.md)（t40 的 4 行）。

做了什么：

- **预览**：编辑主文字时状态行上有“预览”开关（缺省开，记在标签上）。开着时把输入框里此刻的整篇交给世界服务渲染，字段是值、条目引用是名字，画在预览栏里；预览里的值与引用只是文字。作者停下输入约四分之一秒后换成新的，别处的写入让世界变了也跟着重读。写得不对时栏顶上写出错的行、列与原因，栏里留着上一次读得出来的样子并变淡。
- **版式**：编辑区放得下两栏（不窄于 880 像素）时输入框与预览左右各半，条目页的内容列随之放宽；预览栏吸在页头下面、自己滚动，作者打字以后滚到光标所在的那一段。放不下时预览排在输入框下面。
- **着色**：输入框本来就是 Monaco，原来的语言是 `markdown`，花括号与标签没有专门的颜色。现在经 `editor.languages` 登记了一门语言 `canon-entry`：标题、列表与引用的记号、代码、加粗与强调、链接，花括号里的字段名（含中文）、字符串、数与运算符，标签的名字与属性。认不出的字照正文画。
- **内核**：世界服务加了一条只读的方法 `renderSource`（把一段没提交的源文字当作条目的主文字渲染成给作者的一块）。它的解析不进内核的解析缓存，结果里的位置只留块一级节点的起始行，源文字超过 5 万个字符不渲染。

实施中查到、改了设计的三件事：

- 内核的解析按原文留结果（上限一万条），窗口的读取层也留最近 64 个不用的读取。预览每停顿一次就是一份新的整篇，两处都会被撑大，所以预览的解析不进缓存、读取不走读取层。
- 字段名先归在 `variable` 这一类，Monaco 真实分词器的单测全过，真实浏览器里却没有颜色：主题里 `variable` 与正文同色。改归 `type`。
- 1440 的窗口、两边侧栏都开着时编辑区只有约 600 像素，预览按设计排在下面；要看到左右分屏得把窗口拉宽或收起一侧侧栏。

实现审查（2026-11-24，审在 `07e3d6b03..c4e732693`；[前端报告](evidences/impl-review-frontend-sonnet.txt)、[后端报告](evidences/impl-review-backend-sonnet.txt)、[逐条处理](evidences/impl-review-resolution.txt)）：前端 Sonnet 7 条（重要 3、建议 4），内核与后端 Sonnet 5 条（都是建议），没有阻断，都成立、都改了。最要紧的两条：预览读取的监听写错了，实际是每个按键都马上发一次整篇渲染、停顿白等；渲染结果比源文字大十几到四十倍，原先 20 万字符的上限起不到作用。修正批没有再审。没补的一处：条目页这一层没有“预览关着时不读”的断言（读取那一层有）。

验证（2026-11-24，负载 2 到 9）：

- 类型检查通过（应用包三份配置、内核包）。
- 内核 `bun test` 686 通过；应用 `bun test`（canon、lab、architecture）245 通过；vitest（canon、lab、editor 的组件）247 通过。
- 重新构建三份产物后 e2e `canon-write` 7 条、`canon-author` 7 条通过：预览里出现字段的值、字段名有颜色、1440 时预览在下面、1920 时在右边且吸顶的位置跟着页头、开关能关能开；八十段的长文里打字后预览栏滚到光标那一段，页面往下滚时预览栏吸在页头下面、整栏在视口里。
- 变异检查两处：去掉“只认最后发出的那一次”、把监听改回旧写法，对应的用例都失败。
- Lab 截图 6 个场景（手机宽与 1500 宽，亮色）没有页面错误与越界；真实页面的分屏截了一张。截图在本机的 `shots/`。
- 合入前 master 比分支多的 37 个提交都没有碰 `packages/`，合入后没有重跑。

没有验证的：几万字的条目下预览的手感（只量了渲染时间：5 万字符 0.03 到 0.4 秒）；两个窗口同时编辑时的预览；暗色主题下的着色。

已知限制（都在待确认清单）：预览只能看，不能在里面改、点了不跳到源文字，两栏不同步滚动；开关记在各自的标签上，不是全局偏好；整篇超过 5 万个字符不预览。左右分屏、页面还没往下滚时，预览栏的底边会比看得到的区域低几十像素，往下滚一点它就吸住。

查到的旧问题（不在本 Task 的范围，没有改）：存下来的块里嵌套极深的引用（两万层以上，只会来自粘贴），写入检查能过，之后渲染会栈溢出、条目页读不出来。预览这条路已经接住；存下来的块那条路要另修。
