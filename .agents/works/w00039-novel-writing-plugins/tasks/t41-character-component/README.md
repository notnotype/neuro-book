# 人物设定组：图片、给作者填的表单、在条目上加字段

## 目标与范围

第一个做完整的设定组——人物：能放图片，有一份好用的表单给作者填数据，能在某个人物上自己加字段。开发者 2026-11-23：“第一个设定组——人物，能放图片，并且提供一份生动的表单给作者填数据”；2026-11-24 讨论后定：人物设定组允许实例字段、给加字段的入口（开发者：“这个功能可能还是挺常用的吧”）。

范围按[内置设定组的清单](../t10-setting-schema/component-catalog.md)的第一期：内核补四项（在条目上加、改名、删字段的写入操作；文字字段的建议值；允许加字段的类型不止面板；重整人物的字段），人物（重整）与形象（立绘、外貌、服装、现在穿的）两组，把人物类的设定画成一张角色卡的“资料”分页，图片的显示、从作品里选与上传。清单的第二、三期（数值的预设项、技能、物品栏、关系；组织、地点、物品与新建条目的模板）到时另建 Task。

合同：要改 [`canon/components.md`](../../../../../docs/specs/canon/components.md)（实例字段的写入、字段声明的建议值）、[`canon/author-ui.md`](../../../../../docs/specs/canon/author-ui.md)（“资料”分页、图片的选与显示）与 [`canon/project.md`](../../../../../docs/specs/canon/project.md)（写入操作），具体条目在计划里定。

## 当前状态

2026-11-24 经 nbdev 新建，尚未开工。同日开发者补充方向：默认带一个好看的面板（作者填表单）与一组预设；人物只放最通用的，立绘、服装与换装、魔力、技能各自成组；“一次性先把所有我们要做的 Component 先设计好”。所以先在 [t10](../t10-setting-schema/README.md) 出清单（第 1 稿已写，等开发者定末尾的六条），本 Task 等清单定了再开工。面板的版式开发者已选“角色卡”（左边立绘、右边名字与基本资料、下面分区就地填）。

现状的截图（人物分页是一行一个字段的表，面板分页是数值卡加流水）在本机的 `shots/`。

同日开发者看过[清单](../t10-setting-schema/component-catalog.md)：“这个划分我同意……其他都同意”，清单末尾的六条都定了；清单第六节（设定组多了以后）等确认。主会话在草稿 worktree（`.worktree/w00039-t41-drafts`，分支 `feat/w00039-t41-drafts`，不合并）的 Lab 里搭了角色卡的静态稿 `CharacterCardDraft`（真实的条目页骨架与 nb-ui 控件，样本内容写死），七个场景：填好的、刚新建的、就地改一段文字、就地改一个短项、添加一组设定、添加一项资料、全套（加上数值、技能、物品栏、关系）。[评审板](artifacts/review/index.html)第 1 轮已发布，四道题：角色卡的样子、改一项时就地展开还是沿用页顶的确认条、“添加”分成两个入口、设定组多了以后都排在一页还是各一个分页。

搭稿时看到的一处现状（没有改）：条目页的页头与内容列在宽窗口里左边不对齐，内容比页头多缩进 32 像素（`EntryPage` 的内容列在 760 像素的上限里面又加了左右内边距，页头的内边距在上限外面）。

评审板第 1 轮的答复（开发者 2026-11-24）：

1. 角色卡的样子：**不同意**。原话：“感觉有点不太对啊。先给我讲一下这个 Tab 是什么？Tab 是 Component 吧。我之前想的是服装可以做成一个单独的 Component。你现在的这种做法是全部堆在一个 Component 了吧。”“一个 Component 不是由两个东西组成的吗？：数据部分和展示部分。这个角色卡就是展示部分”“这个角色卡的展示部分是用 MDX 做的吗还是直接用 vue 组件做的？因为其实我也想看看用 MDX 的表达能力能不能做出这种角色卡。我们要提供什么接口给他们（MDX或者 vue 组件）。需要讨论一下。或者其实这可以可以两者都要：提供 react 组件，mdx 就写这一个 tag。”“我有哪里没有表述清楚吗？有没有术语需要纠正？”
2. 改一项时：选 A，就地展开。
3. “添加”分成两个入口（添加一项资料、添加一组设定）：同意。
4. 设定组多了以后：选 B，**每组各一个分页**（没按主会话推荐的“都排在一页”）。

主会话核对了代码：开发者的理解与实现一致。一个设定组是数据（`canon.components` 的声明）加展示（`canon.component-views` 登记的 Vue 组件，没登记用通用字段表；它拿到的 `context` 只有本组的命名空间），另有给 Agent 的文字视图（`agentView`，MDX）；数据分页一组一个。第 1 稿的“资料”页把人物与形象两组画在一页，偏离了这个模型。所以[清单](../t10-setting-schema/component-catalog.md)第五节（角色卡是跨设定组的一页）与第六节第 5 条（分页不跟着变多）作废，形象那一组的划分要重定（主会话的建议：立绘与外貌留在人物，服装与换装单独成组），展示部分用 Vue 组件还是 MDX 要与开发者讨论。
