### 1. 本章计划 `set` 整张以引用为键的列表（例如卫兵的 att.态度），对用马甲的本体那一行连同称呼照写

类别：正确性 / 关卡被绕过（第一轮第 7 条的修正只覆盖了带行键的地址与 listAdd、listRemove）
位置：packages/neuro-book/src/plugins/plot/core/brief/parts.ts:61-67（changeShape：路径不带 `[行键]` 时一律 "value"）、parts.ts:116（值经 gate.value 写出）、gate.ts:302-307（row：行头写 name(id)，各列照写，不看 relationVisible）

### 2. 身份不给写手的本体，他的隐秘目标（名字与为什么）仍写进这一场的秘密，挂在马甲名下；本章计划仍写他的目标的字段变化

### 4. 种子网的判据对称谓表左栏的本名整体放行：“本名 = 马甲”这种直接写出不给内容的揭穿的一行，网抓不到
严重程度：重要
类别：测试 / 判据放得过宽（第一轮第 10 条“左栏按例外判，不要整列跳过”只做了一半）
位置：packages/neuro-book/src/plugins/plot/core/brief/secrecy.test.ts:29（commonFor：名字是本体的本名时，整列左栏都不查）、:40-44（pairs 只按“左栏是马甲名、右栏含本名”这一个方向配对）
现象：判据把“左栏可以写本名”的例外写成了无条件：只要名字属于某个用马甲的本体，左栏就不查。而例外的条件（Spec 输出 7、16：视角人物认得他且揭穿给了写手）没有进判据。配对检查只认“马甲 = 本名”，不认反方向的“本名 = 马甲”。实测：在 400 个种子里找出称谓表有一行右栏是马甲、而那组揭穿在这一份不给写手（真值 pairs 的 needed 为 null）的书，把那一行的左栏换成本名（模拟 narrativeName 写错成本名），照抄的判据报 0 条违规：
  seed 18: "人2号 = 马甲7号"，变异前 0 条，变异后 0 条
  seed 20: "人2号 = 马甲8号"，0 → 0
  seed 84: "人2号 = 马甲10号"，0 → 0
这一行就是验收 8 明确禁止的写法（身份绝密时称谓表要写“灰袍客 = 灰袍客”），是第一轮第 8 条那类泄漏的镜像。现在的实现没有写出这种行（左栏走 recognizes），所以不是产品泄漏；但网对这一处是盲的，以后改 narrativeName 或 recognizes 时退化不会被发现。
另外两处网的盲区与本轮的发现直接相关：
- 真值里没有“关系”这一类：态度行的称呼是 `称呼N`，不在 hidden/requires 里；计划补丁也没有态度行的 set、listAdd（第一轮第 10 条点名要加）。所以第 1 条（整张 set 写出对本体的称呼）、第一轮第 7 条的修正，网都不守。
- 真值没表达 11-10 的决定：身份不给写手时，本体的目标名、挂在本体上的决策只受“藏着的知识点”约束，不受身份约束；决策原话用 `决N号` 记号、不含本名。所以第 2、3 条网走不到。
为什么是问题：计划第五节让种子网兜住“没想到的组合”；判据宽一格，网再大也兜不住那一格。
如何核实：`bun test /tmp/review-w00039-t35-impl-2/exp/net.test.ts`（判据逐字照抄 secrecy.test.ts 的 violations 的相关部分；变异只改结果里称谓表的一行，不改产品代码）。
建议改法：判据里左栏的本名按条件放行：对每一份，这个本体在这一份戴着马甲（右栏是马甲名）时，左栏含本名就要求 pairs 的 needed 不为 null 且 satisfied（与“马甲 = 本名”同一个条件；视角人物认不认得可以不判，宁严）；不戴马甲时照放行。配对检查改成无序：左右两栏一边是马甲、一边含本名都算。生成器补态度行的 set/listAdd（行键随机含用马甲的本体，称呼用独特记号并按那个本体的身份约束），决策的原话里随机带上 about 里人物的本名。

### 5. 同一段里一个人先后戴两个马甲：第二个马甲不进关卡，它的简介、别名、正文照给，写出本名与身份
