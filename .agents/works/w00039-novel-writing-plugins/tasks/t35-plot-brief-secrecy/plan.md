## 关键设计

### 一、关卡：`packages/neuro-book/src/plugins/plot/core/brief/gate.ts`（新）

简报里每一个条目的名字、每一个值、每一块作者文字，都只经这个模块写出。别的文件不再从 `context.ts` 拿 `nameOf`（`nameOf` 挪进 `gate.ts`，不导出）。

分两步算，先事实、后写法，避免“写秘密那一段时要知道另一个目标遮不遮”的循环（现在靠 `shown` 预算绕开）：

1. **遮挡事实**（`Concealment`，每个框架算一次）：
   - `shown`：这一场的秘密里给内容的知识点（保密档，或绝密而本章计划暗示、揭示）；
   - `masks`：本体 → 这一场用的马甲。来源有两种：参与者带 `as`；参与者的 `who` 本身是马甲条目（`sameAs` 指向本体）。
2. **写法**（`Gate`）：

```ts
export interface Gate {
    /** 条目在简报里的写法（新输出 16 的表）。 */
    name(id: string): string;
    /** 名字能不能照写：name(id) 就是本名。不是条目的 id（列表行自己的 id）算能写。 */
    plain(id: string): boolean;
    /** 值：引用写 name；带 id 的列表行写 name 或 label 加各列；图片写说明；不出现 id 与 JSON。 */
    value(value: unknown): string;
    /** 一块作者文字（内核的纯文字渲染）：出错，或引到的条目有一个不 plain，整块换成固定句。 */
    block(block: PlainBlock): {readonly text: string; readonly withheld: boolean};
    /** 绝密不给内容时“有一件涉及某某的绝密设定”的某某：沿父条目往上，取第一个名字不是占位的。 */
    subject(point: string): string;
}
```

`name(id)` 按顺序取第一条成立的：

| 条目 | 写法 |
|---|---|
| 不是条目（列表行的 id） | 原样 |
| 已删除、读不到 | “已删除的条目” |
| 保密以上的知识点，不在 `shown` | “一件绝密设定”（沿用现在的固定句） |
| 目标，`隐秘` 指向的知识点不在 `shown`，且是保密以上或已删除、读不到 | “某某的一个隐秘目标”（某某 = `name(持有者)`） |
| 本体在 `masks` 里 | `name(马甲)` |
| 其余 | 条目名 |

- 目标不按出场筛：直接读 `view.object` 确认类型，再读 `隐秘`（还没出场的条目照样读得到命名空间，已核对 `nb-canon/src/engine/views.ts`）。修 I12 第 2 项。删除的目标走第二行，修第 3 项。
- `subject` 沿父条目往上，跳过名字是占位的（隐秘目标、不给内容的知识点、已删除）；主体是用马甲的人时得到马甲。都跳完写“某件事”。修第 4 项。
- 一章分段讲两条线时，写作指示的视角人物一行与称谓表这些共同的段用合并的关卡：几份里有一份的写法不是本名，就用那一份（取第一份）。修第 9 项的回溯章。

**马甲的身份不是秘密时**（没有“揭穿”这个马甲的知识点，或它不到保密档）：按开发者定的规则各段写马甲，写手就对不上马甲背后是谁（例如验收 1：保密的“勇者特征”写着“知道的：旅人”）。推荐：在场的人里这个人那一项加一行“旅人是勇者用的马甲”。这是规则没覆盖到的一种情况，**请开发者确认**。

### 二、各段改走关卡：`core/brief/{secrets,parts,appearance,index}.ts`

- `secrets.ts`：持有者名单、“在人前的表现”、隐秘目标与冲突、主体，都用 `gate`。`concealedGoal`、`hiddenGoals` 并进关卡的遮挡事实，不再单独维护。
- `parts.ts`：`pointName`、`shownName`、`displayName`、`valueText`、`rowText` 删掉，改用 `gate.name`、`gate.value`。在场的人里的态度对象与起因、本章计划的字段主人与知情变化、称谓表的右栏，都走 `gate.name`。
- 称谓表左栏（叙述用的称呼）补一条：这一场用马甲、而“揭穿”这个马甲的知识点不给写手的，用马甲名，不看视角人物知不知道（视角人物知道一件不给写手的绝密时，叙述也不能叫出本名）。
- 决策：已定决策与到期的待定决策用同一个函数取“挂着的保密以上知识点”（条目挂点与地址挂点都算）。修第 5 项。
- 伏笔（输出 8）：主文字的每一块经 `gate.block`，有一块被扣就整段写“回收方式按细纲写”并给提示（判断标准改成 `gate.plain`，行为与现在相同）。

### 三、涉及条目的样子改成纯文字：`core/brief/appearance.ts`

- 不再用给 Agent 的带值写法再做文字替换（`maskRefNames` 删掉）。修第 1 项。改用内核的纯文字渲染，每块经 `gate.block`；被扣的块写固定句“（这一段写到本章不能写的设定，略去）”。写手不回写，带值写法的注记与条目 id 对他没有用，伏笔段已经是纯文字。
- 跳过伏笔类型的条目（它们只在伏笔段写）。修第 6 项。
- 用马甲的本体换成它的马甲条目：写马甲的名字、简介、正文与字段；本体的字段与正文不写（本名与身份多半写在里面）。
- 字段一行写“字段显示名：`gate.value(值)`”，不写 `命名空间.字段` 与 JSON。

### 四、内核的纯文字渲染：`packages/nb-canon/src/render/{render,syntax}.ts`

`renderBlockPlain` 目前没写进任何 Spec（t34 为简报加的），本 Task 补进 `canon/rendering.md`，并修：

- 引用字段的值是 `{ref}` 时写那个条目当时的名字（删除的写“已删除的条目”），并把它加进 `references`；值是带 `id` 的列表时，各行的 `id` 都加进 `references`。修第 7 项。
- `<Image>` 标签写它的说明（`alt`，没有就不写），属性里的表达式不再拼进标签，但引用照收。`ParsedBlock` 记下图片标签的起止。修第 8 项。
- 出错的块：`PlainBlock` 带 `error`，`references` 为空。简报把出错的块一律当作被扣（拿不到引用就判断不了）。

给 Agent 与给作者的渲染不改。

### 五、验收的网：`plot/testing/brief-world.ts`（新）与 `core/brief/secrecy.test.ts`（新）

逐条用例只能守住想到的路径。另做一张随机的网：

- **生成器**（`testing/`，不含断言）：用 `PlotWorld` 随机造一本小书：人（一部分这一场用马甲，揭穿它的知识点随机为普通、保密、绝密）、知识点（随机档位，父条目随机挂在人、目标或别的知识点下）、目标（`隐秘` 随机，出场在本章之前、本章、之后）、伏笔（主文字随机用 `<Ref>`、表达式、引用字段的值、带 id 的列表引别的条目）、决策（条目挂点、地址挂点，已定、待定到期）、删除、两段讲两条线的章。每个会被遮的东西都用独特的名字（例如“秘名甲3”），作者写的文字（细纲、计划原话、场景条件）里不出现这些名字。
- **判据**（照 Spec 直接写，不调关卡的代码）：
  - 绝密而本章计划不暗示、不揭示的知识点：名字在整份上下文里不出现；
  - 保密的知识点、隐秘目标：名字只要在某一份里出现，那一份的这一场的秘密里就有它（或它藏着的那个知识点）的“真相”项；
  - 用马甲的本体：本名只出现在“揭穿”这个马甲、给了内容的那一项里；
  - 共同的段（写作指示、称谓）：只能出现每一份都允许的名字。
- 固定几十个种子，每个种子拼每一章的简报。失败时打出种子与章，方便复现。

I12 的 10 条各有一条确定的用例（照它的复现写），种子网兜住没想到的组合。

## 不做与风险

- **不在生产里扫文字**：把要遮的名字集中起来在拼好的文字里查，作者自己写的文字（细纲、计划原话、字段里的字符串）里本来就可能有，短名字（两个字的人名）还会撞上别的词，误判会把无关的项扣掉。所以生产只靠关卡，扫描只做测试的判据，用独特的名字避开误判。
- **作者文字里的秘密**：没挂对知识点的原话、字段里的字符串照写，与输出 9 已有的说法一致（程序只守挂上的东西）。在 Spec 输出 16 里写明。
- **同一章两段，一段用马甲、一段不用**：两段各按各段写，写手可能从两段相同的目标与态度对上。这是故事本身把两个身份放进了同一章，记为已知限制。
- **整块扣下会少给写手一些不相干的内容**：比逐处换名字粗，但逐处替换正是前三轮漏的地方，取简单、扣得住的这边。
- 风险：片 2 改动面大（简报的所有段）。验收 2 到 7 的现有用例期望不变，作为回归的底；种子网在片 3 补，片 2 提交前先跑一遍 I12 的复现用例。
