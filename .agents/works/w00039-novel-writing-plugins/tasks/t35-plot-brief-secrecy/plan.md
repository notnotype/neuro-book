## 关键设计

### 一、关卡：`packages/neuro-book/src/plugins/plot/core/brief/gate.ts`（新）

简报里每一个条目的名字、每一个值、每一块作者文字、每一条秘密的真相，都只经这个模块写出。别的文件不再读条目的名字与简介（`nameOf` 挪进 `gate.ts`，不导出；`secrets.ts` 写真相也经关卡）。模块头写明这条不变量，实现审查按它逐文件核对。

分两步算，先事实、后写法：

1. **遮挡事实**（`Concealment`，每个框架算一次）。凡是“是不是秘密”的事实，都取两处里更严的一边（P1 第 7 条：本章计划自己把知识点升成绝密、把目标设成隐秘，这一章就要遮）。两处是：章首 = 这个框架的读取位置（补叙章是补叙处）；章末 = 要写的这一章在这个框架的线上的章末，计划模式（P2 第 6 条）。
   - `secrecy(point)`：两处保密档的较高者；
   - `shown`：这一场的秘密里给内容的知识点：保密档，或绝密而本章计划暗示、揭示；
   - `hides`：目标 → 它藏着的知识点的集合（章首与章末的 `隐秘` 的并集，P2 第 11 条：本章计划把隐秘改指另一个知识点时两个都算）；不按出场筛，只要到本章末已出场（P1 第 13 条：遮与给用同一份事实）。“藏着的知识点给了内容”指集合里的都给了内容，归到集合里排第一的那一项（保密档高的在前，同档按 id）。这一场的秘密那一段要列的目标、本章涉及的集合在简报一侧要补的知识点，都从它取；
   - `unmasks`：马甲 → 揭穿它的全部知识点，作为一组处理（P1 第 14 条、P2 第 4 条）：组里有一条是保密以上而不给内容，这个身份就不给写手，组里每一条都按“不给内容”写（名字占位，没有真相），连普通档的那条也一样；组里保密以上的都给了内容，身份才给写手；
   - `masks`：本体 → 这一场用的马甲，只从参与者的 `as` 取（内核写入时已把 `who` 为马甲的归一成本体加 `as`，P1 第 9 条）。同一段里几条计划用了不同的马甲，取按计划先后最早的那个；有一条用了马甲就算这一场用马甲。只有揭穿这个马甲的知识点里有保密以上的（按更严的一边），这个本体才算要遮；身份不是秘密（没有揭穿它的知识点，或都不到保密档）时照写本名，称谓表左栏仍按输出 7 写马甲（开发者 2026-11-10 定，见“待确认”第 1 项）。
   - `late`：到章末还没出场的条目，但不含这个框架里本章计划的参与者（`who` 与 `as`）（P1 第 10 条：本章才出场的人照常写；内核的“已出场”按读取位置算，章首读时本章才出场的也算没出场，所以不能直接用章首的 `appeared`。P2 第 7 条：计划里写了这个人在场，就按在场写；出场记晚了，写成已写变更时内核以 `not-appeared` 拒收，作者在那时改）；
   - `recognizes(X, P)`：P 这一场用马甲，X 对揭穿这个马甲的某条知识点有 `knows` 的有效知情，且这个身份给写手（身份不是秘密时这一条自然成立）。在场的人的态度与称谓表左栏都用它（P2 第 3 条：两处同一个判断）。
2. **写法**（`Gate`）：

```ts
export interface Gate {
    /** 条目在简报里的写法（新输出 16 的表）。 */
    name(id: string): string;
    /** 遮的种类：plain 照写；rename 改名（用马甲的本体）；placeholder 占位（下表其余几行）。 */
    kind(id: string): "plain" | "rename" | "placeholder";
    /** 秘密的种类（P2 第 1 条）：none 不涉秘密（plain、rename、不到保密档的知识点）；shown 给了内容的秘密（shown 的知识点、藏着的知识点都给了内容的目标）；withheld 其余 placeholder。决策与伏笔的提示都按它判。 */
    secretClass(id: string): "none" | "shown" | "withheld";
    /** 值：行的 id 是条目时一律写 name(id)，不用行上内核补的 label（它是本名，P1 第 8 条）；id 不是条目的行用作者写的 label；图片写说明；字符串列表用顿号连；不出现 id 与 JSON。 */
    value(value: unknown): string;
    /** 一个条目的正文：经内核的纯文字渲染（名字回调用 name），每块给不给、不给的原因（见四）。调用前提：这个条目自己是 plain（本条目自己的读取不进 reads）。 */
    blocks(entry: string): readonly {readonly text: string; readonly withheld: null | "placeholder" | "rename" | "problem"}[];
    /** 称谓表左栏：叙述用的称呼，按输出 7 的整套顺序（含视角人物认得他时写本名，P2 第 5 条）。 */
    narrativeName(pov: string, person: string): string;
    /** 绝密不给内容时“有一件涉及某某的绝密设定”的某某：沿父条目往上，取第一个 kind 不是 placeholder 的；都不是写“某件事”。 */
    subject(point: string): string;
    /** 这一场的秘密里给内容的知识点的真相（名字与简介）；不在 shown 时为 null。 */
    truth(point: string): string | null;
    /** 藏在 shown 知识点下的目标的名字、为什么、冲突；否则为 null。 */
    hiddenGoal(goal: string): string | null;
}
```

`name(id)` 按顺序取第一条成立的：

| 条目 | 写法 | 种类 |
|---|---|---|
| 已删除、读不到（含不是条目的 id，P2 第 12 条：列表行的 label 归 `value` 管） | “已删除的条目” | placeholder |
| 在 `late` 里 | “一个之后才出场的人或物” | placeholder |
| 保密以上的知识点，不在 `shown`；身份不给写手的那一组揭穿知识点（不论档位） | “一件绝密设定”（沿用现在的固定句） | placeholder |
| 目标，藏着的知识点在 `shown` | “某某的一个隐秘目标，见这一场的秘密”（P1 第 4 条，Spec 输出 4 原有） | placeholder |
| 目标，藏着的知识点不在 `shown`，且是保密以上或已删除、读不到 | “某某的一个隐秘目标” | placeholder |
| 本体在 `masks` 里且要遮 | `name(马甲)` | rename |
| 其余 | 条目名 | plain |

“某某”是 `name(持有者)`；持有者用马甲时得到马甲。一章分段讲两条线时，写作指示的视角人物一行与称谓表这些共同的段用合并的关卡：按人取，这个人在哪一份里的写法不是本名，就用最早那一份的写法；称谓表的左右两栏用同一份；左栏写本名的例外要每一份都允许（P1 第 15 条的补充、P2 待确认的判断）。

### 二、各段改走关卡：`core/brief/{secrets,parts,appearance,index}.ts`

- `secrets.ts`：持有者名单、“在人前的表现”、主体经 `gate.name`、`gate.subject`；真相与给内容的隐秘目标经 `gate.truth`、`gate.hiddenGoal`；要列的隐秘目标从 `hides` 取。`concealedGoal`、`hiddenGoals` 删掉。本章涉及的集合（`pointsBeforeWriting`）不改，它也给写完以后的检查用（knowledge 输出 10）；简报一侧另外并上 `hides` 里参与者的目标藏着的知识点。
- `parts.ts`：`pointName`、`shownName`、`displayName`、`valueText`、`rowText` 删掉，改用 `gate`。逐处：本章计划的字段主人、知情变化的人与知识点、列表增减的一行；在场的人的人名、目标、态度对象与起因；伏笔；读者已知；决策。
- **决策**（P1 第 2 条、P2 第 1 条）：已定决策与到期的待定决策用同一个判断，取 `about` 里的条目（条目挂点与地址挂点都算），按 `gate.secretClass` 分：有 `withheld` 的，只写“有一条涉及保密设定的决定”；没有 `withheld` 而有 `shown` 的，原话写进排第一的那一项（目标折算成它藏着的知识点），决策段写“另有关于某某的决定，见这一场的秘密”；全是 `none` 的照原话写在决策段（rename 算 none：只守挂上的秘密，与输出 9 一致）。验收 6 的现有期望不变。
- **用马甲的人的态度与称呼**（P1 第 3 条）：
  - 称谓表左栏（`gate.narrativeName`）：P 这一场用马甲 M、而 `recognizes(视角人物, P)` 不成立时，先取视角人物对 M 这个条目的 `称呼`，再取 M 的名字，排在“视角人物对本体的称呼”之前（Spec 输出 7 的顺序随之改）；成立时照输出 7 原来的顺序，可以是本名（开发者 11-10 定的例外）。
  - 在场的人：X 对一个这一场用马甲的人 P 的态度，`recognizes(X, P)` 成立时列 X 对 P 本体的那一行；否则列 X 对马甲条目的那一行（有的话）。X 不认得他，或身份不给写手时，对本体的态度不能挂到马甲名下（绝密的知情者在人前怎么表现，走输出 4 的“在人前的表现”）。
  - 涉及条目的样子不写 `att` 命名空间：态度在在场的人一段已按“两人都在本章”给出，样子里再列一遍既重复、又绕过上面这条。
- **伏笔**：主文字经 `gate.blocks`，有一块被扣就整段写“回收方式按细纲写”，并给提示 `payoffWithheld`，提示带上原因（`answer`：答案不给内容；`placeholder`、`rename`、`problem`：主文字的哪一类问题），作者才知道去改哪里（P2 第 5 条）。rename 只在读了用马甲的本体的字段时扣；写到他的名字经名字回调写成马甲，不扣（P1 第 5 条）。
- **其余出口**（P1 第 12 条、P2 第 8 条）：写作指示的补叙一行写“补叙第 N 章的事”（安放在前史时写“补叙前史里的事”），不写安放的 JSON；“与第 N 章同时”按章序算 N，不写章 id；本章计划每项的 label 用计划原话的前 12 个字（进“已省略”的就是它），不用计划 id；列表行与地址里不是条目的元素写行的 label。

### 三、涉及条目的样子改成纯文字：`core/brief/appearance.ts`

- 不再用给 Agent 的带值写法再做文字替换（`maskRefNames` 删掉，修 I12 第 1 项）。正文经 `gate.blocks`，被扣的块写固定句“（这一段写到本章不能写的设定，略去）”。写手不回写，带值写法的注记与条目 id 对他没有用；伏笔段已经是纯文字。
- 跳过：知识点、目标、伏笔（只在伏笔段写，修 I12 第 6 项）、这一场用马甲而身份不给写手的本体（马甲条目本来就在本章涉及的条目里，P1 第 9 条）、`late` 的条目。本章才出场的条目照常写（现在被跳过，与输出 13 不符，一并修）。
- 第一行写 `gate.name`；一句话描述与别名照写，但身份不给写手的马甲条目不写这两样（P2 第 10 条：程序知道它是谁的马甲，作者最可能在这里写出身份）；字段一行写“字段显示名：`gate.value(值)`”；不写 `know`、`att` 两个命名空间。
- 跳过本体的代价：写手拿不到这个人本体上的字段（外貌、状态）。这一场他以马甲示人，马甲条目上的就是他这一场的样子；把本体的字段并到马甲名下，身份、封号这类字段会把人对上。记进“不做与风险”。

### 四、内核的纯文字渲染：`packages/nb-canon/src/render/{render,syntax,entry}.ts`、`service/reads.ts`

`renderBlockPlain` 目前没写进任何 Spec（t34 为简报加的），本 Task 补进 `canon/rendering.md`。不按值的形状逐个补（P1 第 1 条：单个列表行、引另一块原文、算出来的引用都漏过），改成通则：

- **调用方给名字**：`view.renderPlain(entry, position, mode, options?: {entryName?: (id: string) => string | null})`。`<Ref>`、值里的引用、以引用为键的列表行，名字都经它写（不给时用条目当时的名字，删除的写“已删除的条目”）。简报传 `gate.name`，用马甲的本体就写成马甲，不必扣块（P1 第 5 条）。
- **每块给出三样**：
  - `text`：纯文字；
  - `reads`：表达式读了谁的数据：字段引用与表达式里的 `ref(...)` 的条目，含图片属性里的表达式；加上路径里以引用为键的列表的行键（`{att.态度["e1"].称呼}` 读的是关于 e1 的数据，本条目自己的字段里的行键也算，P2 第 2 条）；本条目自己不算；
  - `mentions`：文字里写了谁的名字（`<Ref>`、显示出来的 `{ref}`、以引用为键的列表行）；
  - `problems`：这块文字有写不干净的地方：`syntax`（块出错，`text` 是原样源文）、`raw-value`（结果是没有显示写法的对象，例如取出的单个列表行）、`quoted-block`（结果是另一块的原文，`text[...]`）、`unavailable`（读不到值，例如还没出场、已删除、没启用）。
- 显示写法只对字符串、数、真假、引用、图片、字符串列表（顿号连起来）、带 id 的列表有定义；别的一律记 `raw-value`。带 id 的列表里，行的 id 是一个条目时名字经回调写并记进 `mentions`，否则写行的 label（与 `gate.value` 同一条判断，P2 第 12 条）。
- `<Image>` 标签写它的说明（`alt`，没有就不写），属性里的表达式不再拼进标签，引用照记进 `reads`（I12 第 8 项）；`alt` 本身写成表达式时记一条 `raw-value`，不写说明（P2 第 12 条）。`ParsedBlock` 记下图片标签的起止。

`gate.blocks` 的判断，按这个先后给原因：有 `problems` 记 `problem`；`mentions` 或 `reads` 里有 placeholder 记 `placeholder`；`reads` 里有 rename 记 `rename`（读马甲本体的任何字段都扣：`entry.name` 不经名字回调）。给 Agent 与给作者的渲染不改。

### 五、验收的网：`plot/testing/brief-world.ts`（新）与 `core/brief/secrecy.test.ts`（新）

逐条用例只能守住想到的路径。另做一张随机的网：

- **生成器**（`testing/`，不含断言）：用 `PlotWorld` 随机造一本小书，并**自己记下真值**（谁是什么档、本章揭示什么、谁用马甲、谁挂在谁下面），真值按段记（两段讲两条线的章，每段的计划、揭示、马甲、升档各一份，P2 第 13 条），判据只用这份真值，不调 `context.ts`、`gate.ts`（P1 第 6 条）。`testing/` 下加一个测试用的 Component（一个图片字段、一个作者写的带 id 列表、一个引用字段）登记进生成器的世界，`PlotWorld` 加一个造两段章的方法（P2 第 9 条）：
  - 人：一部分这一场用马甲（同一段可以两个马甲），揭穿它的知识点随机为普通、保密、绝密，可以有两条；一半的揭穿知识点名字里含本名；
  - 知识点：随机档位，父条目随机挂在人、目标或别的知识点下；一部分由本章计划升档；
  - 目标：`隐秘` 随机（一部分由本章计划设上），出场在本章之前、本章、之后；
  - 伏笔与物件的正文：随机用 `<Ref>`、字段引用、引用字段的值、单个列表行、带 id 的列表、`text[...]`、条件表达式、图片标签引别的条目；以引用为键、指向要遮条目的列表字段；
  - 决策：条目挂点、地址挂点，挂在知识点、目标、人上；已定、待定到期；原话里放与所挂秘密对应的独特记号；
  - 删除；两段讲两条线的章；之后才出场的人（与本章参与者分开造，另有一条确定用例覆盖“计划里在场、出场却记在之后”）；
  - 写作指示：一部分章带视角人物与视角方式，一部分带补叙与“与某章同时”。
  - 每个会被遮的东西都用独特的名字（例如“秘名甲3”），细纲、计划原话、场景条件里不出现。
- **判据**（照 Spec 写）。份内的段（本章计划、简报里除称谓以外的各段、涉及条目的样子）按那一份的真值判；共同的段（写作指示、细纲、称谓、上一章末尾）按“每一份都允许”判（P2 第 13 条）：
  - 绝密而那一份不暗示、不揭示的知识点：名字在那一份里不出现；
  - 保密的知识点、隐秘目标、挂在秘密上的决策记号：在某一份里出现，那一份的这一场的秘密里就有它（或它藏着、它挂着的那个知识点）给了内容的一项；
  - 要遮的本体（揭穿它的知识点里有保密以上的）：本名只出现在揭穿它的保密以上知识点都给了内容的那一份里（以份为单位：Spec 输出 4 让别的段写那一项的名字，名字里可能含本名；这时整组揭穿都给了内容，P2 第 4 条）；例外是称谓表左栏：视角人物对揭穿有 `knows` 且每一份都给了写手时，左栏可以是本名（“待确认”第 2 项）；身份不是秘密的本体不在这条判据里；
  - 之后才出场的人：名字不出现；
  - 与名字无关的：上下文里不出现世界里的任何 id（生成器记下全部 id 逐个查，含章 id），不出现 `<Ref`、`<Image`、`{"`、`{ref(`；
  - 共同的段（写作指示、称谓）：只能出现每一份都允许的名字。
- 固定几十个种子，每个种子拼每一章的简报。失败时打出种子与章，方便复现。

## 不做与风险

- **不在生产里扫文字**：把要遮的名字集中起来在拼好的文字里查，作者自己写的文字（细纲、计划原话、字段里的字符串）里本来就可能有，短名字（两个字的人名）还会撞上别的词，误判会把无关的项扣掉。所以生产只靠关卡，扫描只做测试的判据，用独特的名字避开误判。
- **作者文字里的秘密**：没挂对知识点的原话、字段里的字符串照写，与输出 9 已有的说法一致（程序只守挂上的东西）。在 Spec 输出 16 里写明。
- **跳过用马甲的本体**：身份不给写手时，写手拿不到他本体上的字段（外貌、状态），只有马甲条目上的；马甲条目就是他这一场示人的样子，把本体的字段并过来会把人对上（P2 第 10 条，取 b）。
- **计划里在场、出场却记在之后的人**：按在场写，不加提示；写成已写变更时内核以 `not-appeared` 拒收，作者在那时改出场（P2 第 7 条建议的提示没加）。
- **引另一块原文（`text[...]`）的块整块扣下**：不递归渲染被引的块（要防自引用的循环），作者在伏笔与条目正文里这样写的少。以后要用再加。
- **读不到值的块整块扣下**：本章才出场的人在章首读不到字段值，引它字段的块会被扣；名字（`<Ref>`）照常写。少给一点，不给写手“（尚未出场）”这种内核占位。
- **同一章两段，一段用马甲、一段不用**：两段各按各段写，写手可能从两段相同的目标对上。这是故事本身把两个身份放进了同一章，记为已知限制。
- **同一章两段，一段升档、一段照写**（实现审查 I1 第 17 条）：各段的保密档、`隐秘` 各算各的，一段升成绝密的知识点在另一段照写名字。开发者 2026-11-10 定：窄场景取复杂度低，记为已知限制（Spec“不承诺”）。
- **作者写的列表行 id 撞上条目 id**（实现审查 I1 第 11 条）：纯文字渲染与关卡按“行的 id 是不是条目”区分两种列表，作者恰好用一个已有条目的 id 当行 id 时会写成那个条目的名字（不泄漏，写错）。接受：要按字段声明的 `keyedBy` 判，得把声明随值传过内核的渲染，收益小。
- **整块扣下会少给写手一些不相干的内容**：只对 placeholder（不给内容的秘密、要遮的目标、删除、之后才出场）这样做；改名（马甲）经名字回调，不扣。
- 风险：片 2 改动面大（简报的所有段）。验收 2 到 7 的现有用例期望不变，作为回归的底；片 2 提交前先跑 I12 与 P1 的复现。
