# 插件切分、包边界与工作台里的形态

## 目标与范围

定这套功能分几个插件、几个包、彼此怎么依赖，nb-story 的独立命令行与工作台插件的双重身份，现有 `nb-memory` 包的去留，以及剧情图谱查看器搬进工作台的形态。

合同：讨论 Task，只定设计，行为合同未变；定稿后的 Spec 改动在实施时另定。

前置：t02、t09。

## 要讨论的问题

### 插件切分、包边界与 nb-memory 去留

1. 插件怎么切：剧情图谱（nb-story）、设定库（含表单）、剧情工坊（活页夹、大纲、伏笔）三个，还是一个“小说创作”插件；共享模型单独成包。
2. 依赖与降级：只启用设定库、不启用剧情工坊时能用到什么；`.binder` 由哪个插件认领。
3. nb-story 的双重身份：已发布到 npm 的独立命令行 `nbstory` 与工作台插件共用核心；合并模型后它的数据格式、命令行要不要改。
4. `nb-memory`（episode、facts、主体注册表）与新模型重叠：废弃、并入还是作为底层。
5. 中文名与命名：剧情图谱、设定库、剧情工坊、世界引擎这些名字在新模型下还对不对。

### 剧情图谱进工作台与试读者（原 t18 的一部分）

1. 独立查看器的页面（本章、人物、秘密、数值、悬念、时间线、原文）搬进工作台的形态：一个视图多页签，还是拆成多个视图与面板。
2. 对作者的书：阅读位置默认跟随当前编辑的章节，还是最新一章。

材料：[剧情图谱：以后接入 NeuroBook](../../../../../docs/proposals/novel-story-app.md)；[`monorepo-boundaries.md`](../../../../../docs/modules/monorepo-boundaries.md)；[剧情图谱查看器](../../../../../docs/specs/story/viewer.md)。
