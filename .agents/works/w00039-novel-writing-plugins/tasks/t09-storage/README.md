# 真相源、存储形态与项目文件结构

## 目标与范围

定世界引擎的数据放在哪：只存的六种对象（条目、剧情变更含计划、核对点、未决问题、正文建议、修订，见 [t16 原型的类型](../t16-plot-workbench-ui/artifacts/review/r3/model.ts)）各自是文件还是数据库；条目树与 `lorebook.content/` 的关系，主 MDX 按块怎么落盘；修订（只存变了的字段，带发布时算好的“带来的变化”）放在哪，与 nb-history 怎么分工；Agent 能不能经文件直接改主 MDX，能的话旁车记录与块标记用什么格式；语义档的归纳缓存与索引放哪；项目文件结构（原 t11）与系列作品共享世界观（原 t24）。存储一定，目录布局与 Spec 才能写，所以排第一。

合同：讨论 Task，只定设计，行为合同未变；定稿后的 Spec 改动在实施时另定。

## 重切后要定的（2026-11-02）

1. 六种对象各自用文件还是数据库，依据是本地优先、可审查、Agent 能不能直接读，以及规模（百万字、几万条剧情变更与修订）下的打开与重算速度。
2. 条目与 `lorebook.content/`：一个条目是一个文件还是一个目录；主 MDX 的块 id 存哪（提案：不写进正文）。
3. 修订与改动记录：只存变了的字段与“带来的变化”（11-02 定）；正文与手记的历史归 nb-history，世界模型的修订自己存。
4. Agent 直接改文件这条路要不要：要，就定旁车记录与块标记 `{/* block:b7 */}` 的格式（提案第 5 节“并发”）；不要，Agent 只经工具改，块标记用不上。
5. 派生数据：语义档的归纳缓存（`reductions`，按输入的摘要做键）、检索索引，放 `.nbook/` 还是插件数据目录，进不进 Git，丢了怎么重建（重建要调小模型）。
6. 原 t11、t24 的目录与系列作品问题照旧要定（见下）。

## 10-31 的原问题

10-31 按“与 nb-story 合成一套故事模型”的方向写，原样保留作参照。剧情、状态、知情的形状已由提案定（一条剧情变更日志，状态由折叠算出），下面第一组的 2、3、4 条按提案理解；文件与数据库、目录、系列作品仍要定。

### 真相源与存储形态

1. 设定：文件（一条一个 Markdown，字段在 frontmatter）还是数据库。倾向文件：本地优先、可审查、Agent 能 grep、History 能记录。
2. 剧情（场景、剧情线、伏笔、决策）：[项目文件底座](../../../../../docs/proposals/project-file-foundation.md) 定了 `plot://` 虚拟型、数据在数据库，依据是旧 Plot 的形态；设定改文件后这一条要不要改。旧版 World、Plot 选 SQLite 的理由没有查到记录，要先查。
3. 状态变动、知情、揭示计划这类细粒度、量大的记录：文件里怎么放（一个对象一个文件、一章一个文件、一个日志文件），并发写与合并冲突。
4. nb-story 抽取的图：派生数据，放项目里（`.nbook/`）还是插件数据目录；要不要进 Git；能否从正文完全重建（重建要花模型费用）。
5. 规模：百万字、几千条设定、几万条状态变动时打开、查询、对齐的速度；要不要索引、索引放哪。
6. 与 History、外部编辑（bash、文件管理器）、同步的关系：外部改了文件后派生数据怎么失效。

### 项目文件结构（原 t11）

1. 顶层目录：`manuscripts.binder/`、`lorebook.content/` 已在 Spec 里约定；剧情、资料、大纲、灵感要不要固定目录。
2. 目录名用英文还是中文、是否可以由用户改名（插件靠什么找到设定目录：固定名、后缀、`project.json` 登记）。
3. `.nbook/` 里放什么：身份、启用的插件、派生数据、缓存；哪些进 Git、哪些忽略。
4. 旧版项目里的 `AGENTS.md`、`agents/`（Profile 记忆）、`manual/`、`reference/`、`upload/` 在新版还要不要；Profile 已放到状态根（w00032 t05），项目级 Agent 指令放哪。
5. 封面、插图、立绘等图片资产放哪。
6. 一部作品多卷、多部（见下面“系列作品与共享世界观”）时的目录形状。

### 系列作品与共享世界观（原 t24）

1. 共享方式：一个作品里分多部、用户资产 `user://` 里的共享设定库、一部作品引用另一部的设定。
2. 时间与世界线跨作品：第二部接在第一部结尾，状态从哪继承。
3. 第一版要不要支持，还是先记下不做。
