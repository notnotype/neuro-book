w00039 t09：修订日志占多少硬盘，作者用 Git 时 .git 涨多少（2026-11-02，主会话）

脚本：scripts/git-growth.sh <章数> <分段 KiB>（仓库根执行）。日志由 scripts/log-scale.ts 生成，形状同 log-scale.txt；
文字字段（情节描述、原句、依据、条目的一句话与主 MDX 块）从样本书前 20 章的段落里轮流取句，压缩率接近真实
（只用同一句话重复时 gzip 后接近 0，Git 的数会偏乐观）。原文只读进临时目录，跑完删除。
在临时仓库里每记完一章提交一次（330 章提交 330 次），关掉 gc.auto；Git 默认要攒到约 6700 个零散对象才自动打包，
这里 1000 次提交约 3000 个，本来也不会触发。“gc 前”是作者不手动 git gc 时的样子。

330 章，一个文件：日志 6.3 MB（gzip 后 1.1 MB）；提交 330 次后 .git：gc 前 274.0 MB，git gc 后 1.4 MB
1000 章，一个文件：日志 19.0 MB（gzip 后 3.3 MB）；提交 1000 次后 .git：gc 前 2496.9 MB，git gc 后 5.8 MB
330 章，按 256 KiB 分段（26 段）：日志 6.3 MB（gzip 后 1.1 MB）；提交 330 次后 .git：gc 前 13.4 MB，git gc 后 0.7 MB
330 章，按 1024 KiB 分段（7 段）：日志 6.3 MB（gzip 后 1.1 MB）；提交 330 次后 .git：gc 前 43.9 MB，git gc 后 0.7 MB
1000 章，按 256 KiB 分段（77 段）：日志 19.0 MB（gzip 后 3.3 MB）；提交 1000 次后 .git：gc 前 41.3 MB，git gc 后 1.9 MB
1000 章，按 1024 KiB 分段（20 段）：日志 19.0 MB（gzip 后 3.3 MB）；提交 1000 次后 .git：gc 前 136.5 MB，git gc 后 2.0 MB

读法：
- 日志本身：百万字约 6.3 MB，gzip 后 1.1 MB；同样字数的正文 UTF-8 约 3 MB，日志约是正文的两倍。
- 一个只追加的文件放进 Git，每次提交都存一份整个文件的压缩副本：百万字提交 330 次后 .git 是 274 MB，三百万字 1000 次是 2.5 GB；
  手动 git gc 以后只剩 1.4 MB、5.8 MB，但作者一般不会去跑。
- 按 256 KiB 分段（写满开新的一段，旧段不再变）以后，每次提交只多存最后一段：百万字 13 MB、三百万字 41 MB，gc 后也更小。
  1 MiB 一段是 44 MB、137 MB。段数是 26 段、77 段，打开时多读几十个文件，可以忽略。
- 同步盘同理：只追加的单个文件每次修订都变，同步工具若不做块级增量就要重传整个文件；分段以后只有最后一段在变（同步工具的行为没有逐个核实）。
