# 写手的上下文：章级 brief 与检索

## 目标与范围

定写一章时给写手 Agent 的上下文：章级 brief 怎么编译、设定与状态取哪一刻的、怎么检索相关设定、上下文太长时怎么取舍。

合同：讨论 Task，只定设计，行为合同未变；定稿后的 Spec 改动在实施时另定。

前置：t06、t16、t20。

## 要讨论的问题

1. 旧版 brief 的七段（章目标、参数、信息控制、节奏、禁写、剧情点、建议读取）哪些留；由程序编译、Agent 起草还是作者手写。
2. 按位置取上下文：只给写到本章为止的状态与已揭示的秘密，未来的计划给不给写手（给了容易提前写出来）。
3. 检索：按引用、按在场者、按名字匹配、向量检索（旧版 `EmbeddingText`）；要不要向量检索、索引放哪。
4. 前文怎么给：全文、摘要、nb-story 的章节变化；长篇写到几百章时的上限。
5. 旧版写手 curated 模式因工具在 Profile 定义期固定而延后；新 Profile 机制（w00032 t05、t20）下能不能做。

材料：[调研：三、五节](../../research/2026-10-31-repo-survey.md)。
