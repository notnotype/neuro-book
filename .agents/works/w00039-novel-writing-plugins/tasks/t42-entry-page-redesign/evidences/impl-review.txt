### 1. 提示的暂停（指针、焦点）在提示被关掉时不放开，之后所有提示都不再自己收起
**严重程度**：重要　**类别**：正确性（不变量：暂停计数）
**位置**：packages/neuro-book/src/plugins/canon/web/components/PageNotices.vue:36-52（holdBy、releases，只在 onBeforeUnmount 清）；packages/neuro-book/src/plugins/canon/web/notices.ts hold（holds 计数）
**现象**：作者那一行的暂停来源只靠 pointerenter/pointerleave 与 focusin/focusout 放开。点“关闭”（鼠标点必然指针在行内、按钮拿到焦点）或键盘回车关闭时，`notices.dismiss()` 把 `props.notice` 变 null，整行被 v-if 摘掉（TransitionGroup 离场后移除）。被摘掉的元素不会再收到 pointerleave（Chrome 对已从 DOM 移除的节点不补发边界事件；焦点在被移除元素上时 focusout 也不可靠），`releases` 里的 "pointer"、"focus" 两项就留着。组件没有任何 watch 在 notice 变 null 时放开它们，`PageNotices` 本身还挂着（页面没卸载），于是 `holds` 一直是 1 或 2。之后每一条新提示：`setCurrent` 看到 `holds > 0` 不排计时，提示永远不自己收起，直到这个页面标签被卸载（切标签、关页）才放开。
**为什么是问题**：违反 Spec 输出 18“提示出现 6 秒后自己收起”。触发路径是最常见的操作（点右上角的 ×），之后的所有保存提示（含别的页面挂着的）都变成常驻，且没有任何可见线索。brief 重点 1 里“宿主卸载与重挂、暂停期间换了新提示、页面卸载时没放开的暂停”测的是卸载放开，没有测“提示先消失、页面还在”。
**如何核实**：真实运行时未跑（本机没有 Playwright 浏览器，按规则不起开发服务），下面是对计数逻辑的实验：/tmp/review-t42-impl/scratch/leak.test.ts（`bun test`，通过）：show、hold()、dismiss()、不调用 release、再 show，推进 60 秒，`current` 仍非 null。浏览器里“被移除的节点不发 pointerleave”这一步从 Chrome 的已知行为推断，需要主会话在 e2e 里确认：指针移到作者那一行、点“关闭”、再触发一次保存，等 7 秒看提示是否还在。PageNotices.dom.test.ts 只测了卸载时放开（第 5 条用例），没有“关闭后再来一条”。
**建议改法**：在 PageNotices 里 `watch(() => props.notice === null, (gone) => gone && releaseAll())`（把 onBeforeUnmount 里的循环抽成 releaseAll 共用）；暂停来源本来就是“这一行上的”，行没了来源就没了。补一条用例：hover 后 setProps({notice: null})，断言 release 已发生。

### 5. 提示行离场时仍占着位置，上面那一行在它离场结束后瞬间掉下来（TransitionGroup 的 move 没生效）
**严重程度**：建议　**类别**：界面（状态变化要有过渡、布局不跳）
**位置**：packages/neuro-book/src/plugins/canon/web/components/PageNotices.vue:157-176（.page-notice-leave-active 没有 `position: absolute`，只写了 `.page-notice-move`）
**现象**：三行（Agent、作者、失败）放在 `TransitionGroup` 里，栏是底边贴着锚点往上叠。作者那一行 6 秒自己收起（或点关闭）时，它在离场动画期间仍在文档流里，动画结束后元素才被移除，这时上面的 Agent 行（或失败行）才失去下面这一行的位置，瞬间下移约 44 像素。TransitionGroup 的 move（FLIP）是在更新那一刻按“离场元素仍占位”的布局量的，所以没有位移可补，`.page-notice-move` 的过渡实际没用。最常见的触发：Agent 改了设定的提示常驻，作者保存后 6 秒收起。
**为什么是问题**：设计语言“状态不同，布局要相同”“状态变化有过渡”；本组件 .md 写了“出现与收起都不推开内容”，这里是提示行之间的跳动。
**如何核实**：Vue 官方文档对 TransitionGroup move 的要求：离场元素必须脱离文档流（`position: absolute`）。在 Lab 的 PageNotices“Agent 也改了”场景里让作者那一行收起，看 Agent 行有没有一次跳变（需要真实浏览器，我没有跑）。
**建议改法**：`.page-notice-leave-active { position: absolute; }`（栏是 `align-items: center`，离场元素定位成绝对后水平位置要保持：给它 `left/right: 12px; margin-inline: auto; width: fit-content` 或者让栏的子元素外面再包一层定宽容器），move 过渡随之生效。补一条 Lab 场景或 e2e：作者行收起时 Agent 行的 y 随时间连续变化。

### 6. 页头名字按钮的“负外边距加 max-w-full”：名字一字一行（作者已在 README 记为待修，审查范围内的提交里仍在）
**严重程度**：重要　**类别**：界面
**位置**：packages/neuro-book/src/plugins/canon/web/components/EntryPage.vue:276-285（h1 里的名字按钮 class：`-mx-1.5 inline-flex max-w-full px-1.5`）；Task README“真实页面走查”那一条写“发现页头的名字一字一行……待修”
**现象**：h1 是一个按内容定宽的 flex 子项（`flex flex-wrap` 里默认 `flex: 0 1 auto`）。按钮的负外边距让它对 h1 的内容宽度只贡献“文字宽 T”（T + 12 内边距 − 12 负外边距），所以 h1 宽度恰好是 T；而按钮的 `max-w-full` 把它的 border-box 封在 h1 宽度 T 上，扣掉左右各 6 像素的内边距，文字可用宽度只剩 T − 12，放不下一整个名字，于是对每一个名字都会折行；`break-words` 加上 `min-w-0` 让中文名折成一字一行。这是 README 里作者在真实页面看到的现象，推导出来的原因与它写的“最大宽度比按钮自身窄 12 像素”一致。本分支的最近一次提交 b25b4fadb 没有改这里，提交范围内仍是原样。
**为什么是问题**：条目页的主标题在所有宽度上都坏；e2e 与 dom 测试量不到（happy-dom 无布局，e2e 只断言可见与文本）。
**如何核实**：真实页面（nbdev 开发服务样例作品）打开任一条目，看名字是否竖排；或在 Lab 的 EntryPage 场景（editable）里量 h1 里按钮的 offsetHeight 是否大于一行。我没有跑浏览器。
**建议改法**：不要用负外边距与 max-w-full 同时存在：把“浅底”做成伪元素（`::before { inset: 0 -6px; }`，按钮自身 padding 为 0），或给按钮 `max-w-[calc(100%+12px)]`。补一条 e2e：名字按钮高度等于单行高度（可用 `boundingBox().height < 2 * lineHeight`）。

### 12. 页面末尾的留白只按一行提示留，Agent 提示常驻再加作者那一行（或 390 宽折行）时最后几行滚不出来
**严重程度**：建议　**类别**：界面
**位置**：packages/neuro-book/src/plugins/canon/web/components/PageNotices.vue:119-122（`.page-notices { height: calc(var(--control-h-md, 2.25rem) + 24px) }`）、:123-130（锚点 bottom: 16px）、:149（`.page-notice` 允许 flex-wrap）
**现象**：留白固定为一行提示加 24 像素（约 60 像素），而栏里最多同时有三行（Agent、作者、失败），390 宽时每行的动作还会折到第二行（本组件 .md 自己写了“窄了动作换到第二行”）。Agent 的提示不自己收，所以“Agent 一行加作者一行”不是瞬态：两行加间距加 16 像素底距约 96 像素，比留白多出约 36 像素，页面滚到底时最后一行内容被盖住、滚不出来，直到作者关掉 Agent 的提示。Spec 输出 18 写的是“页面末尾常留一段与提示等高的空白，最后几行能滚到提示上方”，单行时成立，多行不成立。
**如何核实**：Lab 的 PageNotices“Agent 也改了”场景里加长页面内容，滚到底量最后一行与提示栏的重叠；我没有跑浏览器（从 CSS 数值推断）。
**建议改法**：留白高度不用常数，改成栏的实际高度：把栏放进页面里与留白同一个元素（栏用绝对定位贴在留白底部，留白用 ResizeObserver 或 CSS grid 让高度等于栏高），这样提示多少行留白就多高，出没时留白变高变矮会让页面末尾位移，但那是页面末尾不是正在看的内容；或者保持现状并在 Spec 写明只保证单行。

### 13. “添加立绘”一次到位的标志在“没真正切过去”时会留着；await 之后不看人还在不在人物分页
**严重程度**：建议　**类别**：正确性（窄边界）
**位置**：packages/neuro-book/src/plugins/canon/web/components/CharacterView.vue（onPortrait：`await pending` 之后 `lookPick.value = true; context.showTab(LOOK_COMPONENT)`）；EntryPageHost.vue:`showTab`（目标分页还没出现时只记 `pendingTab`）与 `watch(() => state.tab, () => { pendingTab.value = null; })`；LookView.vue:`onMounted` 才消费标志
**现象**：
1. 形象这一组刚加上、读取结果里还没有它的命名空间时，`showTab` 只设 `pendingTab`，标志已经立起。作者此时（写入返回到条目重读之间）点了别的分页，`state.tab` 的 watch 会清掉 `pendingTab`，不会切到形象分页，但标志留在宿主的 shallowRef 里。之后作者自己点“形象”分页，LookView 挂上读到标志，立绘的选图莫名其妙地打开。形象分页加载失败（`dataView.failed`）时同理，标志一直留到某次成功挂上。
2. `await pending` 返回后不检查 CharacterView 是否还挂着、人物分页是否还是当前分页：这期间作者切到别的分页，加完之后仍被拉到形象分页并打开选图（`showTab` 是宿主的闭包，卸载后照样能调）。
**为什么是问题**：Spec 输出 49 只要求“成功后切过去、打开立绘的选择”；两处都会让选图在作者没点它的时候出现。窗口很窄（加一组设定的往返时间），按“窄场景选简单改法”记为建议。
**如何核实**：读代码；复现需要在写入返回与条目重读之间插入一次分页点击，没有写测试。
**建议改法**：标志不跨时间存在：宿主 `watch(() => state.tab, (tab) => { if (tab !== lookTab) lookPick.value = false; })`（切到别处就放倒）；onPortrait 在 `await` 之后先看 `getCurrentInstance()` 是否已卸载、`context` 里的当前分页是否仍是人物，不是就什么也不做（只加上，不切）。

### 14. 横排与竖排切换时，焦点在分页上的话会丢到 body
**严重程度**：建议　**类别**：界面（键盘与读屏）
**位置**：packages/neuro-book/src/plugins/canon/web/components/EntryPage.vue:316-358（`v-if="!rail"` 的横排 Tabs 与 `v-if="rail"` 的 EntryPageNav 是两套互相替换的元素）
**现象**：键盘用户焦点在选中的分页上（roving tabindex 的那一个）时，用快捷键开关侧栏、拖分隔条使编辑区宽度越过 1040 或 1024，`rail` 翻转，旧的那套分页元素被卸载，焦点落回 `document.body`，下一次 Tab 从页面开头再来。Spec 输出 9 说“两种排法选中同一页，直接换”，没提焦点。
**为什么是问题**：键盘与读屏用户在改窗口宽度的操作之后丢了位置；改动小，窄场景。
**如何核实**：e2e 里聚焦一个分页、改视口宽度跨过阈值，看 `document.activeElement`；我没有跑。
**建议改法**：翻转前若焦点在旧的分页里，翻转后（`nextTick`）给新那套的选中项 `focus()`（两套都有 `data-tab-value`）。如果认为不值得，在 EntryPage.md 记为已知限制。

### 15. `impactIsQuiet` 与 `impactLines` 各写一遍“什么算变化”，没有测试把两者对齐
**严重程度**：建议　**类别**：代码质量
**位置**：packages/neuro-book/src/plugins/canon/web/impact.ts:21-26（impactIsQuiet）与 :28-54（impactLines）
**现象**：回车先看变化的“安静”判断（决定存不存）和预览那几行（决定作者看到什么）是两份独立的规则：前者逐个数 pendingAdded、pendingResolved、broken、brokenOn、被 skip 之外的 values，后者逐个写句子。`Impact` 以后多一类（现在已有 `rekeyed`，两边都没算），其中一个漏改，就会出现“预览上写了变化、回车却直接存进去”或反过来。现有测试（revisions.test.ts:34-45）只测了 impactIsQuiet 自己。
**建议改法**：最少部件的做法是让 `impactLines` 直接返回 `{lines, quiet}`（`quiet` 就是没有往 `lines` 里加任何一句），删掉 `impactIsQuiet`，这样“写出来的句子”与“算不算变化”是同一段代码；`in-place-edit` 的 `describe` 取 `quiet` 即可。若保留两个函数，补一条性质测试：对一组 Impact 样本，`impactIsQuiet(i, skip)` 为真当且仅当 `impactLines(i, {skip, ...})` 只有 `edit.noImpact` 那一句。

### 16. EntryPageNav 的“焦点跟到新选中的一行”没有断言；“添加一组设定”的用例直接对子组件 `$emit`
**严重程度**：建议　**类别**：测试
**位置**：packages/neuro-book/src/plugins/canon/web/components/EntryPageNav.dom.test.ts:49-70；EntryPageNav.vue:`move`（`await nextTick(); …focus()`）与 EntryPageNav.md“焦点跟到新选中的一行”
**现象**：键盘那条用例里 `modelValue` 固定不变，只断言发出的 `update:modelValue`；`move` 里最后一步 `focus()` 没有任何断言，删掉那一行（或者把 `data-tab-value` 查询写错）测试仍通过，而这是竖排导航键盘可用的关键（方向键后下一次按键落在哪一个按钮上）。“添加一组设定”的用例用 `menu.vm.$emit("update:open", true)` 与 `$emit("select", …)` 直接替 DropdownMenu 发事件，没有走真实的打开与选中，DropdownMenu 的事件名或语义变了这条仍绿。
**建议改法**：键盘用例给一个受控的外壳（`modelValue` 跟着 `update:modelValue` 变），断言 `document.activeElement` 是新选中的 `[data-tab-value]`；菜单用例改成点触发按钮、点菜单项（DropdownMenu 传送到 body，从 document 里找）。
