### 核心结论

**把页头的“线”和“时间点”合并为一个视角控件，放在页头最底行右对齐（紧压在设定内容的分割线上方），按钮只写当前看到的结论（`在看  第 3 章末尾 · 主线 ▾`），彻底拿掉按钮上的“跟着章”。** 只有主线时不提线，只有一个时间点且无计划时整块不出现。

## 一、页头的“线”与“时间点”

### 1. 作者为什么看不懂

* **在 `01-线的选择.png`、`02-时间点菜单.png` 页头右上角，及 `03-手机页头.png` 简介下方**：
  1. **只给值、不给主语和动作**：`跟着章（此刻：主线）` 和 `🕒 第 3 章末尾` 都没有前缀动词，视觉上又和条目更多操作 `...` 挨在一起，容易被误解成“人物归属”“最后修改时间”或“版本历史”，看不出它在控制下面属性表显示的是哪一刻的值。
  2. **暴露了程序机制，且因果顺序倒置**：作者的心智是先选“看哪一章”，再关心“哪条线”。现在把依赖项（线）放在左边、用最重的灰底边框样式抢了主视觉，把被依赖项（章）放在右边、用裸文字淡化处理；“跟着章”又没说清跟着哪个章，两块外观不统一，作者根本连不到一起。
  3. **内部词汇与自相矛盾**：`跟着章（此刻：主线）` 是状态机拼出来的文案。下拉里同时出现 `跟着章（此刻：主…` 和 `主线`，作者分不清两者差别；而且第一项文案在菜单里直接被截断，分支项 `重来的那个晚上` 只有空白缩进没有树形引导，看起来像排版歪了。
  4. **时间点菜单缺状态反馈、且信息重复**：在 `02-时间点菜单.png` 弹出菜单里，每一章重复写两遍章标题（`开头` / `末尾` 各占一行），章节一多极长；底部的 `算上计划中的情节` 没有复选框或开关，看不出它是开关还是按钮，也看不出当前开没开。

---

### 2. 具体改造方案

#### A. 合并为一个控件，并调整摆放位置

* **为什么合并**：设定的值由唯一坐标 `(时间点, 故事线)` 决定，合为一个“在看”控件后，一句话就能自我解释，消灭两个控件的视觉割裂与主从错位，同时解决窄屏占两行的问题。
* **放在哪**：
  * 把条目级更多操作 **`...` 留在第一行与标题“星瑕”同行右对齐**（宽屏、窄屏一致），不再和视角控件混在一起。
  * 把合并后的 **“在看”控件下移到页头最底行右对齐**（宽屏与 `+ 添加别名` 同行，不增加页头高度），紧贴内容区上方的分割线——它直接压在受控数据正上方，视觉上立刻和下方的 `前史改过`、`第 2 章改过` 建立因果关系。

**宽屏页头草图（替代 `01-线的选择.png` 页头）**
```text
星瑕                                                                 ···
前蓝星最强的魔法少女，隐退后以哥哥的样子把妹妹接回家住
+ 添加别名                                    [ 在看  第 3 章末尾 · 主线 ▾ ]
─────────────────────────────────────────────────────────────────────────
人物        │  [添加立绘]   性别  不明             年龄        十八
```

**窄屏页头草图（替代 `03-手机页头.png` 页头）**
```text
星瑕                                                                 ···
前蓝星最强的魔法少女，隐退后以哥哥的样子把妹妹接回
家住
+ 添加别名
[ 在看  第 3 章末尾 · 主线                                             ▾ ]
─────────────────────────────────────────────────────────────────────────
人物    形象    文字    面板    目标…
```

#### B. 按钮文案与各状态规则（不用时钟图标，靠文案自解释）

按钮统一用浅灰小字前缀 `在看`（与底部状态栏“在看”一致，复用已有概念）+ 深色主值，不要在默认态出现“跟着章”：

| 场景 | 按钮文案 | 视觉与细节 |
| :--- | :--- | :--- |
| **只有主线，有多个时间点** | `在看  第 3 章末尾 ▾` / `在看  最初 ▾` | 不提“主线”，不放时钟图标 |
| **多条线，处于默认自动切线** | `在看  第 3 章末尾 · 主线 ▾` | 直接显示当前解析到的线名（若选到分支里的第 4 章，自动变为 `第 4 章末尾 · 重来的那个晚上`） |
| **多条线，手动固定看某条分支线** | `在看  第 3 章末尾 · 重来的那个晚上 ▾` | 按钮左侧加分支图标并给轻微主题色描边/淡底，提示此刻偏离了默认视图，防误改 |
| **开启了“算上计划中的情节”** | `在看  第 3 章末尾 · 主线 · 含计划 ▾` | 关掉菜单后依然可见，避免作者忘了自己开着计划视图 |
| **只有主线、只有一个时间点、且无计划** | 不显示 | 按“此刻没用的就不出现”整块隐藏 |
| **窄屏线名过长** | `在看  第 3 章末尾 · 重来的那个… ▾` | 保证时间点完整，只对线名做尾部省略 |

#### C. “跟着章”换成什么说法

* **页头按钮**：不出现，直接写当前生效的线名。
* **弹出菜单里**：改为 **`按章节自动`**，右侧用浅灰副字标出当前结果 `当前：主线`（不要塞进括号里导致截断）。
* **底部状态栏（`03-手机页头.png` 右下角）**：现在写着 `[分支图标] 在看：跟着章`，建议同步改为 `[分支图标] 故事线：主线（按章）`（固定分支时为 `[分支图标] 故事线：重来的那个晚上`），做到“同一件事处处一样”，且一眼能看到当前到底在看哪条线。

#### D. 弹出菜单排版（替代 `01-线的选择.png` 与 `02-时间点菜单.png` 的两份菜单）

* 弹出层宽度设为自适应内容或最小 300px（禁止锁死等于触发按钮宽度而截断选项），窄屏下用全宽弹层或底部抽屉。
* **三大改进**：
  1. 用分区小标题（`故事线`、`剧情进度`）自己说明选项含义；只有主线时整块隐藏 `故事线` 分区。
  2. 章节改为**一章一行**，把菜单高度砍半、消灭重复章标题：点击整行默认选**末尾**（最高频），行尾放两个轻量小按钮 `[开头]` `[末尾]` 供精确切换。
  3. 底部开关固定不随章节滚动，明确加复选框 `☐ 算上计划中的情节`（作品无计划情节时隐藏该项）。

**多线时的弹出面板草图**
```text
┌────────────────────────────────────────────┐
│ 故事线                                     │
│  ✓ 按章节自动                   当前：主线  │
│    主线                                    │
│    └ 重来的那个晚上                        │
├────────────────────────────────────────────┤
│ 剧情进度                                   │
│    最初                           起始设定 │
│    第 1 章  好哥哥真难当      [开头] [末尾] │
│    第 2 章  用钱说话          [开头] [末尾] │
│    第 3 章                    [开头][✓末尾] │
├────────────────────────────────────────────┤

```
* 注：`最初` 右侧加 4 个字浅灰副标 `起始设定`，不用长解释就能说明它不是“第 1 章开头”。分支线用 `└` 树形线明确从属关系，避免空白缩进像错位。

## 二、这 3 张图上看到的其他问题（按影响从大到小）

### 1. 手机端横向分页栏看不到后面还有 4 个分页，且 `+` 号位置易误解
* **位置**：`03-手机页头.png` 页头下方横向分页栏（`人物  形象  文字  面板  +`）。
* **问题**：对照 `01-线的选择.png` 可知后面还有 `目标与态度`、`知道什么`、`经历`、`情节 24` 共 4 个分页。但在 390 宽画面里，4 个分页被完全截断在视野外，右侧没有任何截断或渐隐暗示，紧挨着 `面板` 直接摆了一个裸 `+` 号，看起来像“一共只有 4 个分页，点 `+` 新建”，作者极易找不到 `经历` 和 `情节 24`，也容易在试图左滑时误点 `+`。
* **建议**：
  1. 调整横向间距或右侧加淡出渐变，让可视区右缘**露出半个被截断的下一个标签**（例如 `面板` 后露出 `目标…`），直观表达“可横向滑动”。
  2. 把 `+`（添加一组设定）放到**横向滚动条的末尾**（并保留短文案 `+ 添加`），或者收进页头 `...` 菜单，不要固定卡在右侧把后面分页挡死。

### 2. 属性表下半段空行常驻大量 `...`，且与上半段规则割裂
* **位置**：`01-线的选择.png`、`02-时间点菜单.png` 属性表中间两列，及 `03-手机页头.png` 下半部属性列表。
* **问题**：前 6 项（性别、年龄、身份、所属、现在在哪、生死）行尾全部没有 `...`，从 `身体`、`现在的样子` 开始往下的 8 项——即使根本还没填值（如 `种族 填写 ...`、`身高 填写 ...`）——行尾都常驻了 `...`。页面上既没有把内置项和自定义项做分组，又让满屏空行挂着次要操作按钮，视觉嘈杂，还容易让人误以为前 6 行坏了或不能改。
* **建议**：桌面宽屏下把行尾 `...` 改为**悬停该行时再出现**（聚焦键盘时同理），日常页面保持干净；若内置项与自定义项需要区隔，应在两者间放轻量留白或分组线，而不是靠 `...` 有无来暗示。

### 3. 手机端“添加立绘”空占位过大，把核心设定挤出首屏
* **位置**：`03-手机页头.png` 内容区顶部（`添加立绘` 虚线竖框）。
* **问题**：在尚未上传立绘时，窄屏沿用了桌面端的高大竖卡占位，一个人占掉近三分之一屏高，导致打开人物卡首屏一半是空白，真正有值的 `身体（女）`、`现在的样子（哥哥）` 被挤到屏幕最底端。
* **建议**：窄屏且**无立绘**时，将空占位收拢为紧凑的横向条（高度约 56–64px，图标与“添加立绘”水平居中排成一行）；上传图片后再按实际比例展开显示。

### 4. 下拉菜单宽度锁死导致选项截断、且分支缩进无引导
* **位置**：`01-线的选择.png` 展开的线的菜单。
* **问题**：菜单宽度硬绑定为按钮宽度，结果第一项 `✓ 跟着章（此刻：主…` 自己截断了自己；第三项 `重来的那个晚上` 只有左缩进没有分支符号，看着像对齐出错。
* **建议**：即使先局部修改而非立刻合并，也应让菜单设置 `min-width` 随最长项适度撑开，并给分支线补上树形连接符 `└` 或分支图标。
