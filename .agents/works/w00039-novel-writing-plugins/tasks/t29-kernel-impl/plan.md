## 技术选型

| 问题 | 选用 | 理由 | 否决 |
|---|---|---|---|
| MDX 解析 | `micromark` + `micromark-extension-mdxjs`（表达式、JSX、ESM 三项，带 acorn）+ `mdast-util-from-markdown` + `mdast-util-mdx` | unified 生态的底层件，只出语法树、不编译成 JS；表达式自带 estree，白名单直接在树上查；必须带 ESM 扩展，否则 `import` 会被当成普通文字放行。浏览器端约增 200 KB，第 5 片先 spike | `@mdx-js/mdx`：编译成可执行 JS，我们不执行；手写解析器 |
| GFM 表格与删除线 | `micromark-extension-gfm-table`、`-strikethrough` 与对应的 `mdast-util-gfm-*` | 同一生态，按需取两项 | 整个 `micromark-extension-gfm`：带进脚注、自动链接等不要的写法 |
| 中文标点旁的强调 | `micromark-extension-cjk-friendly`（remark-cjk-friendly 的底层） | t28 已点名的现成方案 | 自己改强调规则 |
| 带值写法的扫描 | acorn（随 mdxjs 已在依赖里）：`parseExpressionAt` 取 JSON 值的边界、`tokenizer` 找顶层的 `->` | 都是 JS 词法，直接用解析器 | 手写字符串与括号扫描 |
| 中文数字 | 先找维护中的库（候选 `nzh`），只做“从原句里抽出数字串再换算”；没有合适的再自写，用表格测试覆盖全角数字、千分位、“两”、“3万”、“三千五” | 中文数字的组合手写易错 | 不经核对直接手写 |
| 归纳缓存的键 | `ohash/crypto` 的 SHA-256（锁文件里已有 ohash 2.0.11，同步、浏览器走纯 JS），输入先写成稳定的 JSON | 同步、前后端一致 | Web Crypto（异步，会把纯计算变成异步）；`Bun.hash`（浏览器没有）；53 位小哈希（会撞） |
| 持久化对象的校验 | TypeBox（仓库标准） | 日志的每一行与写入请求都按 schema 校验 | 手写校验 |
| 跨进程锁 | 宿主注入；canon 插件用 `packages/neuro-book/src/backend/locked-replace.ts` 的 `holdLock` | 与 Files、配置层同一把锁的写法；nb-canon 不依赖 proper-lockfile | nb-canon 自己加 proper-lockfile |
| 活页夹清单 | 插件里用应用已有的 `fast-xml-parser` 读 `binder.xml` | 应用已有依赖 | 另加 XML 库 |

## 关键设计

### `packages/nb-canon/`（新包）

- `package.json`：`@notnotype/nb-canon`，`private`，`exports` 两个：`.`（纯计算，前后端共用）与 `./log`（只在 Bun 里用：分段日志的读写）。测试用 `bun test`。登记进根 `package.json` 的 workspaces 与 `docs/modules/monorepo-boundaries.md`。
- 模块（依赖从上往下单向）：
  - `src/core/`：六种对象、修订、写入请求的 TypeBox schema 与类型（只用 `Value.Check`，不用 `Clean`，未知字段原样保留）；地址的解析与格式化；位置的比较与序列化（只此一处）；中文数字；输入摘要；
  - `src/components/`：类型登记、声明校验、字段 id 生成、撞名、版本与“类型不在”的判定；
  - `src/model/`：补丁的执行、整条套上、语义档的起点与事件；
  - `src/engine/`：状态计算（见下）、来历、待处理、计划进展；
  - `src/revisions/`：写入请求转成操作、校验、带来的变化、冲突、就地改、记一笔、文字替换、还原与依赖、章序调整；
  - `src/render/`：白名单、切块、求值、给作者的结构、带值写法、回写解析；
  - `src/service/`：世界服务的语义：打开与重放、单写者队列、独占写入、事件、补归纳的排队。外部能力经接口注入（日志存储、章序、正文、小模型、时钟），主入口不引用 `node:*`，由一条架构测试守住；
  - `src/node/`（子路径 `./node`）：分段日志的读写、写一半与坏行的识别、追加加 fsync、分段、截回、归纳缓存文件；锁由调用方传入。
- **状态计算不从头算**：
  - 一条剧情变更套没套上，只取决于它之前的状态，与读取位置无关。打开时做一次整本前向遍历，得到每条变更的结果，以及**每个条目的时间线**：按位置排好的事件（补丁、核对点、语义档的起点与事件），每隔 8 个事件存一份共享结构的快照。读任意位置上的一个条目：二分找到最近的快照，再重放最多 7 个事件。
  - 跨条目的原子性：处理一条变更时，从各个涉及的条目的时间线取它在该位置的状态，在草稿上套全部补丁，成就一起提交，不成就都不套、标不完整。
  - 发布：新建、改、删的对象让相关条目从某个位置起“变脏”，按全序只重算涉及脏条目的变更；一条变更的结果翻转时，它涉及的别的条目也变脏。每次发布得到新的时间线对象，整体换上，读取总是看到某一个版本；预览走同一个纯函数，只是不换上，所以两边逐字相同。章序变化时整本重建。
  - 精确档的核对点不改状态，在前向遍历之后按时间线比较；语义档的核对点是起点，按 `place` 进时间线（Spec 要相应写清，见“Spec 与文档改动”）。
  - 待处理按记录维护（每条变更的套不上、每个核对点的不符各一张表）；带来的变化只比较这次被重算的记录与地址的前后；嫌疑区间在读到具体条目时扫它的时间线。
  - “按计划”模式是覆盖层：把有效的计划当作插入的变更，只重算计划涉及的条目，其余复用实际模式的时间线；第一次用到时建。计划进展按实际模式的结果判定。
  - 另外三份缓存：MDX 块的解析结果（按源文）、名字到条目的索引（给 `lookup`）、语义档的摘要。
  - 可观测：每次发布与打开记下重算了几条变更、几个条目、各段耗时，进 `status` 的诊断。
  - **最重要的测试是差分**：随机生成修订序列，增量算出的结果必须与整本重算逐字相同。整本重算保留在测试里当参照。
- **修订的依赖**：按“对象加路径”建倒排索引（同一对象内按路径前缀判重叠）、“谁建的”表、“谁引用了它”表、兑现组索引；只加元素的列表不计入；传递闭包用 BFS。都在重放时建，不存盘。
- **精确档的数**：按 10⁴ 缩放成 BigInt 做加减，比较与输出时再转回十进制文字或 JSON 数（Spec components 输出 14：小于一万亿、最多 4 位小数，缩放后超出安全整数，所以不用 number）。
- **请求 id**：重放时建“请求 id → 修订”的索引；发布前查它（Spec revisions 输出 16）。
- **独占租约**：到期时间由注入的时钟算；令牌、持有者说明与调用方实例 id 存在 service 里，调用方断开由插件通知 service（Spec project 输出 10）。
- **别的进程写的行**：`node` 子路径提供“日志尾部”的读取与目录监视（`fs.watch`，变化后去抖再读尾部）；service 在新的世界上重放新增的行、整体换上、逐行发 `changed`（Spec project 输出 17）。
- **id**：每种对象一个前缀（`e`、`c`、`k`、`q`、`s`、`r`），编号取日志里出现过的最大号加一（删掉的也算），所以不复用；列表元素与块在各自的列表里同理。
- **错误的形状**：所有失败码与诊断都带“对象、路径、说明”同一形状。

### `packages/neuro-book/src/plugins/canon/`（新插件）

- 照 `src/plugins/storage/` 的写法：插件 `nbook.canon`，入口 `project`（拥有世界）、`browser`（经远程服务调用）、`server`（经远程服务调用，给以后的 Agent 工具与后台任务）。
- `project` 入口：在 `<项目>/.nbook/world/log/` 打开世界，锁放 `.nbook/locks/`；读 `manuscripts.binder/binder.xml` 得到章序与章节文件，监视它的变化后把新章序交给世界；正文按章 id 读章节文件；小模型第一版不接（语义档一直是“未归纳”的写法），接口留着。
- 世界服务的语义在 nb-canon 的 `service`；插件只把它的方法与事件接到远程服务上，并把日志存储、锁、章序、正文接成 nb-canon 要的接口。
- 贡献点 `canon.components`：插件清单声明；内置的人物、面板两个最小类型（字段只够测试与样本用）先登记在本插件里，完整字段清单等 t10。
- Lab：把 t16 原型的界面接到真实的世界服务上（只为验收与看效果，不是正式界面）。

## 切片

1. **包骨架与 core**：schema、地址、位置、中文数字、摘要；Component 的声明校验与登记。
2. **补丁与整本折叠**：补丁执行、整条套上、不完整、核对点与嫌疑区间、语义档、计划进展、出场与删除、来历、待处理；覆盖 Spec model 的全部验收场景。
3. **增量引擎**：按条目的时间线、脏传播、按计划的覆盖层；差分测试（随机修订序列，增量等于整本重算）；同时出规模脚本，量 Spec project 输出 14。
4. **修订**：写入请求、校验、预览与发布、带来的变化、冲突、就地改、记一笔、文字替换、还原与依赖、章序调整。
5. **渲染**：先 spike MDX 依赖与 CJK 扩展；白名单与切块、求值、两种渲染、带值写法、回写。
6. **node 存储**：分段读写、写一半、坏行、fsync 失败截回、跨进程锁与长度核对（真跑两个子进程并发写）。
7. **service**：打开与重放、单写者队列、独占写入、事件、补归纳的排队（用真实的 node 存储与临时目录）。
8. **插件与验收**：项目入口、活页夹、远程服务；星瑕样本在世界服务上逐步重放并与原型对照；三百万字的速度；Lab 接上原型界面。

每片单独提交；每片结束跑 nb-canon 的 `bun test` 与类型检查，第 8 片另跑应用的受影响测试。改到引擎、序列化、索引的切片重跑规模脚本。

## 不做与风险

- 不做：Agent 工具、记账与写正文的管线、正式的作者界面、内置 Component 的完整字段、检索、schema 升级、截到上限。
- 风险：按计划模式第一次读取要建覆盖层；Spec project 输出 14 的“20 毫秒”是否包含它，要在审查后写清。
- 风险：MDX 与 CJK 扩展的包名、与 micromark 内置强调规则的替换方式没核实，第 5 片先 spike；浏览器包体约增 200 KB。
- 风险：活页夹现在只有清单格式的 Spec（`workspace/folder-kinds.md`），没有剧情插件；本插件只读清单、不写，新建章节靠作者在资源管理器里建或测试夹具。
