# 随剧情变化的状态

## 目标与范围

定会随剧情变的东西（境界、所在地、阵营、生死、持有物、数值、关系）怎么记、怎么查，消除旧版“设定原型”与“当前状态”两份真相源。

合同：讨论 Task，只定设计，行为合同未变；定稿后的 Spec 改动在实施时另定。

前置：t02、t04。

## 要讨论的问题

1. 设定文件只放不变的原型与初始值，变化记成带时间（世界线加时间点或章节）的状态变动，这个分法行不行；哪些字段算“会变的”，由 schema 标注还是用户随时把某个字段变成随时间变化。
2. 记录形式：事件溯源（每次变化一条）还是关键帧快照；nb-story 的数值流水（逐笔加核对）与旧 WorldEngine 的 patch 能否统一。
3. 补写过去：在已有变化之前插入一条，旧版 `increment`、`append` 会断（`broken-relative`）；新设计用绝对值、相对值还是两者并存，断了怎么提示。
4. 按什么取“当前状态”：按故事时间、按章节、按阅读位置；作者写第 N 章时看到的状态是哪一刻的。
5. 关系的变化（敌对转盟友）是状态还是说法。
6. 删除与改正：变化记错了怎么改，要不要保留旧值（旧版 patch 不存旧值）。

材料：[调研：二、五节](../../research/2026-10-31-repo-survey.md)。
