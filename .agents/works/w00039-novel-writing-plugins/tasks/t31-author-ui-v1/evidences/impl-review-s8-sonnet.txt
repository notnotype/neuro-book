### 1. 待处理视图没有交 badge()，底部面板入口条上看不到条数
- 严重程度：建议（本该用上而没用上的新合同）
- 类别：不变量 / 合并带进来的新合同
- 位置：packages/neuro-book/src/plugins/canon/web/plugin.ts:215-223（`createPendingView(...)` 的结果直接放进 contributions，没有 `badge`）；合同在 docs/specs/workbench/views.md 输出 17；外壳读取在 workbench/web/components/WorkbenchShell.vue:280、550（`props.views.badge?.(viewId)`）；合同类型 workbench/web/contracts.ts:42 `badge?(): number | null`
- 现象：master 合进来之后，底部面板每个视图一个入口，视图实现交 `badge()` 就会在入口（“只含一个视图的入口”）和面板头标题后写数。canon 的“待处理”是隐式容器、一个视图，正好满足；但没有交，截图 artifacts/s8-screens/06-pending.webp 里入口条写的是“待处理”，状态栏却是“待处理 1”。同一个数只在状态栏出现。
- 为什么是问题：输出 25 把“待处理 N”定成与待处理视图里那一组的数相同，入口条是作者在面板里最先看到的地方；通知视图已经按这个合同用了（workbench/web/plugin.ts:328 `badge: () => notifications.center.unread.value`）。数据现成：`pendingCount.count`（pending-count.ts），与状态栏同源，不会两处不一致。
- 如何核实：看 plugin.ts 里 pendingView 的构造与 views.md 输出 17、WorkbenchShell.vue:550；看 06 截图的入口条。
- 建议改法：`const pendingView: ViewImplementation = {...createPendingView(...), badge: () => pendingCount.count.value}`（为 0 外壳自己不写）。注意这会让入口按钮的可访问名称带上数字：e2e 验收 5 里 `getByRole("button").filter({hasText: /^待处理 1$/u})`（canon-author.e2e.ts:234、254）要改成限定在状态栏里找，否则可能出现两个匹配而在严格模式下失败，或 `toHaveCount(0)` 被入口按钮挡住。Spec 在输出 25 补一句“入口条与面板头上同样写这个数”。

- 类别：不变量 / 合并带进来的行为

### 4. 设定树跟着条目页选中这件事，真实编辑器与浏览器里没有任何测试
- 严重程度：建议
- 类别：测试
- 位置：entry-page.dom.test.ts:322-342（新用例）；e2e/canon-author.e2e.ts 全文没有断言树的选中态
- 现象：新用例用 `pageStandIn()` 手动 `mount` / `unmount` 条目页来模拟“开 A、开 B、切回 A”。整个机制的前提是“编辑器只挂活动标签，切回来重新挂上”（entry-page.ts 里 `shown` 的注释）。这个前提只在 editor/web/pages.dom.test.ts 的“两个同种页面的标签”（每个标签一个 EditorGroup、非活动的不渲染）里被验证，canon 与编辑器的这个组合没有测过；e2e 的验收 1、2 都在树里点开条目、切标签，却没有一处看 `aria-selected`。如果编辑器以后给页面套 keep-alive 或同一个 EditorGroup 复用，本 Task 的两处测试都不红，树会悄悄不再跟着。
- 为什么是问题：这是 S8b 唯一的功能，测试绕过了真实运行时（用替身编辑器），而决定它是否成立的恰恰是真实编辑器的挂载方式（审查规则：实验若绕过真实运行时，要在真实运行时复现）。
- 如何核实：读 pages.dom.test.ts:214-270 与 EditorGroup.vue:268-270（`<component :is=pageComponent v-if=...>` 没有 key，靠每个标签各一个 EditorGroup 才会重挂）。我没有在真实浏览器里点过，结论从代码推断：现在是成立的（01 截图里选中的是星瑕）。
- 建议改法：e2e 验收 2 里“点星瑕标签”之后加一句 `await expect(row(page, "星瑕")).toHaveAttribute("aria-selected", "true")`，点星瑾标签后同样判星瑾（并断言星瑕不是选中）。几行，不需要新用例。

### 5. e2e 验收 5 的两条否定断言没有对照，可能空过
- 严重程度：建议
- 类别：测试（否定断言）
- 位置：e2e/canon-author.e2e.ts:253-254
- 现象：`page.locator("[data-pending-row]", {hasText: "存款对不上"})` 的 `toHaveCount(0)` 与 `getByRole("button").filter({hasText: /^待处理 \d+$/u})` 的 `toHaveCount(0)`。前一条：待处理视图被切走、卸载（例如面板收起或当前容器换了）时同样为 0，并不能证明那一条被处理了；后一条：状态栏条目因宽度放不下被收走（priority 40 的条目可能被收）也为 0。两条都没有“视图还在、别的东西还在”的正面对照。另外，待处理组头里数字是单独的 span（PendingView.vue:100），按钮的文字是“待处理1”（没有空格），所以后一条的正则也不会匹配到视图里的组头，不能顺带当对照。
- 为什么是问题：规则是否定断言要能区分“消失了”与“从来没有/没看见”。
- 如何核实：读 PendingView.vue:90-101 的组头结构；对该用例做变异（例如保存之前就断言）看会不会红。
- 建议改法：先正面断言 `page.locator('[data-pending-group="pending"] [data-pending-count]')` 的文字是“0”（视图在、数变了），再断言行不存在；状态栏那条前面先确认状态栏本身在（例如状态栏里另一个必在的条目可见）。这样才有“消失”的含义。

### 7. `shown` 按“挂上”触发，页面因别的原因重挂也会改树的选中（从代码推断，未验证）
- 严重程度：建议（小；与已记的两组限制同源，但不止那两种）
- 类别：正确性 / 隐含耦合
- 位置：canon/web/entry-page.ts:93-95（`onMounted(... options.shown?.(arg))`）、plugin.ts:178-180
- 现象：待确认清单已记“拆成两组时在组之间换焦点不会让树跟着变”“树里没加载到的不展开”。另一面没有记：只要条目页组件重挂（把标签拖进另一组、刷新后拆成两组的布局同时恢复两个活动页、插件重新交付页面实现后页面组件换新）就会触发 `shown`，树跳到这个页对应的条目，哪怕用户当前焦点在另一组、或刚在树里选了别的。刷新恢复多组布局时，选中的是最后挂上的那一页，次序不由用户决定。
- 为什么是问题：不严重（树的选中只是提示，且 Spec 没有写），但“挂上 = 成为活动标签”的注释比实际行为强：挂上只说明它显示了，不说明它是用户此刻在看的那个。
- 如何核实：EditorGroup.vue 每个标签一个组件实例；拖标签换组会销毁重建。没有在浏览器里复现。
- 建议改法：不改代码；把待确认清单那一行改成“按条目页挂上判断，拆组、拖动标签换组与刷新恢复时可能选到并非用户焦点所在的页”。等编辑器公开活动页面地址后改成跟着它。

### 8. 输出 29 的 `result-mismatch`：Spec 写“服务给的说明”，实现写的是读回的值
- Spec 条目：输出 29；失败与恢复表
- 严重程度：建议（实现与 Spec 不一样，改 Spec 即可）
- 类别：Spec 与实现不一样
- 位置：canon/web/failures.ts:30（`canonText("failure.resultMismatch", {reason: displayText(failure.got)})`）；locales/zh-CN.json:174（“写完的结果对不上：{{reason}}”）；内核 nb-canon/src/world/edits.ts:44、250（失败只带 `got`，没有说明；章或行找不到时 `got` 是 undefined）
- 现象：Spec 写“`result-mismatch` 写服务给的说明（例如‘你改的那一笔是 +10，差额是 −800’）”。内核的失败里没有说明字段，只有读回的值 `got`；界面写成“写完的结果对不上：{值}”，章节没找到时 `got` 为 undefined，作者看到“写完的结果对不上：未知”。Spec 里的例句没有任何地方产生。
- 如何核实：读 edits.ts:250 与 failures.ts:30。没有测试触发它（canon/web 下没有任何测试出现 result-mismatch）。
- 建议改法：按实现改 Spec：“`result-mismatch` 写‘写完的结果对不上’与读回的值（读不回时写‘未知’）”。若要保留例句的效果，是内核补说明（跨 nb-canon，中等），建议记待确认清单而不是现在做。

### 10. 输出 4：“放在谁下面”“它是谁的另一个身份”“种类”的候选只来自树里已经读到的条目
