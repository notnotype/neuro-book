# w00039 t31 B2-1 前端实现审查报告（Sonnet 审查，固定在 626b256d4）

### 1. 页面与分页的“重试”对外部读取失败不起作用
严重程度：重要
类别：正确性
位置：packages/neuro-book/src/plugins/plot/web/components/SecretsPage.vue:71-72、LedgerPage.vue、GoalsPage.vue 的 Banner 的“重试”按钮；canon/web/reads-service.ts:`retry: () => world.retry()`；canon/web/world.ts:`retry`（只在 `connection === "ended"` 时才做事）
现象：外部读取失败（剧情实例没启动、`external-failed`、`line-not-found` 等）时，页面显示 Banner 与“重试”，点“重试”调用 `reads.retry()`，它就是 `world.retry()`。`world.retry()` 第一行是 `if (connection.value !== "ended" || disposed) return;`，连接是 online 时什么也不做。失败的 slot 已经把 `slot.generation` 写成当前代，没有任何路径会再取它，直到世界下一次变化。
为什么是问题：Spec plot/author-ui.md“失败与恢复”表写 `external-failed` 的处理是“界面按输出 4，‘重试’再取”，输出 4 要求“剧情的数据读不出来”并有“重试”。现在按钮可以点、点了没有任何反应，用户会一直卡在错误页上（直到有人发布新修订）。CanonReads 的接口注释也只写“订阅被提供方结束以后重新订阅”，与页面的用法不符。
如何核实：从代码推断，未跑。读 world.ts 的 `retry`（约 L486）与 reads-service.ts 的 `retry`；测试里 grep 不到任何“重试”或 `external-failed` 的页面级用例（plot/web 三个 dom 测试都没有失败路径）。
建议改法：读取层加一个“重读这个键”的入口（例如 `ReadState` 的句柄上给 `reload()`，或 `retry()` 在 online 时把有 error 的 slot 的 generation 置 -1 后 `run()`），页面的“重试”改调它；补一条真实世界上“取数先抛错、再恢复，点重试后换上”的测试。

### 2. 三张表读取失败时整页换成错误条，丢掉已读到的旧内容
严重程度：重要
类别：正确性
位置：plot/web/components/SecretsPage.vue（`<Banner v-else-if="failure !== null"` 在 `loading` 与正文之前）、LedgerPage.vue、GoalsPage.vue 同样的写法
现象：读取层的失败不清 `data`（`state.value = {...state.value, error, loading:false}`），页面却先判 `failure !== null` 就只画错误条。已经显示着表的页面，只要某一轮重读失败（`external-failed`、`line-not-found`、`chapter-not-found`），整张表立刻消失。
为什么是问题：canon/author-ui.md 输出 26 与输出 34 都写了“读到过以后的失败留着旧内容”“回到跟着章之前的那一轮读取可能得到 `line-not-found`：有旧内容的页面留着旧内容，没有的写原因”。条目页（EntryPageHost 的 `status`）是照这个写的：`entry.value === undefined` 才算 failed。剧情三张表反过来。具体场景是 Spec 验收 5 的反面：选着的子线被撤销时，那一轮 secrets 读取得到 `line-not-found`，页面先闪一下“这条线读不到”，而且 `useSwitching` 在新键读到之前继续显示旧句柄（它带着 error），错误条要到新线读到才消失。
如何核实：从代码推断，未跑。可在 plot/web/tables-pages.dom.test.ts 的风格上加：世界里分叉被撤销，断言页面一直有表的行、没有 `role=alert`。
建议改法：判断改成“有 data 时留着旧内容，错误只在没有 data 时整页写；有 data 又有 error 时可在表上方放一条不挤掉内容的提示”。三张表共用一个小函数更好，免得第四处再漏。
### 3. 人物与秘密条目页的四个分页吞掉失败，把“读不出来”画成“还没有……”
严重程度：重要
类别：正确性
位置：plot/web/components/KnowingView.vue（`read === null || read.loading` 之后直接画 `groups`）、AttitudeView.vue（`v-else-if="(data?.goals.length ?? 0) === 0 && ..."` 写“还没有目标与态度”）、PointView.vue（`data !== undefined` 才画，失败时整块空白）、ExperienceTab.vue（失败时 `sections` 空，写“还没有经历”）
现象：这四个界面都没有读 `read.error`。剧情实例没启动或取数抛 `external-failed` 时：知道什么写“还没有知情”，目标与态度写“还没有目标与态度”，经历写“还没有经历”，谁知道什么除了“字段”一节什么也没有，也没有重试。
为什么是问题：作者会把读取故障当成“这个人确实没有知情/目标”。Spec plot/author-ui.md 输出 4 与“失败与恢复”表要求界面按输出 4 写“剧情的数据读不出来”与说明。三张表有错误条（虽有第 1、2 条的问题），分页没有，两处处理不一致。
如何核实：从代码推断，未跑。让 `client.call` 对 `person` 返回失败后挂 KnowingView，观察文字。
建议改法：四个分页与三张表共用一个“失败就写原因并给重试”的小组件，没有 data 且有 error 时画它，有 data 时留旧内容。
### 4. “谁知道什么”的分段筛选用例等不到筛选结果，断言恒真
严重程度：重要
类别：测试
位置：plot/web/secrets-page.dom.test.ts 约 L95-98（“选读者还不知道只剩那几行”）
现象：点了“读者还不知道”之后等的是 `rows.length === 3 && !text.includes("读取中")`。换分段时读取层按设计继续显示上一份结果（`useSwitching` 的 previous），所以点之前就是 3 行、也没有“读取中”，等待立刻通过；样本里三个秘密读者都不知道，筛选前后行数本来就一样。最后只断言了 `state.segment` 和面包屑。用例名写“只剩那几行”，实际一个关于筛选结果的判据都没测。

如何核实：我在实现 worktree 跑了 `bunx vitest run src/plugins/plot/web`：5 个文件 11 条全绿（含这条）。把样本改成让读者知道其中一个秘密，筛选前后行数才会不同。
建议改法：样本里让读者知道一个秘密，点“读者还不知道”后等行数从 3 变成 2 再断言留下的是哪几行；账本补一条“已放弃”分段用例。

### 8. 伏笔节点带的 key 会重复；章表里找不到的章画成“0”并带当前章标记
严重程度：建议
类别：正确性
位置：plot/web/components/NodeBand.vue:21-34（`key` 是 `${index}-${role}-${written}`；`props.chapters.get(node.chapter) ?? 0`）
现象：同一章有两个同角色同状态的节点（例如一章里两处呼应都写了）时两格的 key 相同，Vue 开发构建报重复 key，生产里更新会错位。节点指向的章已不在章表里（章被删或改名）时序号取 0，格子写“0”、排在最前，初值位置（`now = 0`）下还会带“当前章”的圈。

如何核实：从代码推断。喂给 NodeBand 两个相同节点，或节点的章不在章表里，看控制台与渲染。
建议改法：key 里加下标；找不到的章用原 id 或省略并另画一格“?”，且 `cell.index === props.now` 要排除 0 以外才比较。

### 10. 失败的说法与 Spec 不符：只写失败码，不写服务给的说明；`not-found`、`chapter-not-found` 没有对应处理
严重程度：建议
类别：正确性（对照 Spec）
位置：plot/web/page-shell.ts:31-34 `failureText`；locales/zh-CN.json `page.failed`；canon/web/world.ts `thrown`（`detail` 里放了错误文本）
现象：`failureText` 只区分 `line-not-found`，其余都写 `剧情的数据读不出来：{{reason}}`，`reason` 填的是 `failure.code`（例如 `external-failed`）。取数抛错时读取层把错误消息放在 `failure.detail`，界面不显示，也没有任何地方记一条诊断，作者与开发者都看不到为什么读不出来。

如何核实：从代码推断，未跑；grep `找不到` 在 plot 目录里没有命中。
建议改法：`failureText` 用 `failure.detail`（字符串时）作说明，加 `not-found` 的键；`settled` 里用读取层已有的诊断出口（或 console.error）记一条。
### 11. SegmentedControl 的 `wrap` 改动：没有场景与测试，行尾分隔线悬着，`.md` 的“不截断”不严格

### 12. 目标表的“看谁”留着已不在列表里的人时，整页写“还没有主要角色”

现象：
(a) Spec 与计划写“窗口没有绑定项目时 `canonReadsKey` 为 null，调用方写‘打开作品后可用’”；实现总是给一个对象，没有项目时 `connection` 是 `no-project`、各组合函数给 null，页面据此写“打开作品后可用”（reads.ts 的注释也是这样写的）。调用方按 Spec 写 `if (reads === null)` 的话永远走不到。
(b) Spec 35 列“窗口的线（只读）与改它的入口、可选的线、章表”；`CanonReads` 里没有 `chapters`，调用方（plot 的每个页面与分页）各自再 `useRead("chapters", ...)` 一次，共四处重复，`usePosition` 内部又读一次。能合并成同一个读取，没有功能影响。
(c) plot Spec 的命令表写“暴露方式按缺省”，实现四条都写 `expose: {agent: "never"}`（与 canon 的两个视图命令同理由）。
为什么是问题：Spec 是跨插件接口的合同，应该与实现是同一件事；这是第一个被别的插件用的读取服务，第二个调用方会照 Spec 写。
如何核实：读 reads.ts、reads-service.ts 与 Spec 35 对照。
建议改法：订正 Spec 35（“没有项目时 `connection` 为 `no-project`”）；`chapters` 要么进 `CanonReads`、要么从 Spec 里去掉；命令的暴露方式二选一订正（写 never 并说明理由，更贴近现状）。
### 14. 几个 Spec 判据没有任何测试覆盖
严重程度：建议
类别：测试
位置：canon/web/window-line.dom.test.ts、entry-tabs.dom.test.ts、world.dom.test.ts；plot/web/*.dom.test.ts；e2e/plot-author.e2e.ts
现象：我对照 Spec 逐项找了断言，下面这些没有（dom 与 e2e 都没有；e2e 我没跑，按文件内容判断）：
- `nbook.canon.pick-line` 命令本身：快速选择的项（第一项“跟着章”、按树缩进）、选了以后改公开状态、选着的线刚不在了时标题写“原来看的那条线已经不在了”并只说一次（`lost` 与 `acknowledge`）。commands.test.ts 只给它传了个空实现，e2e 的 `pickLine` 走过“选线”这条路，但没测“丢了”那句。
- 条目页附加分页：`order` 排序与按贡献 id 的次序、换到没启用 `requires` 的位置时分页消失且选着它的标签回到第一个、贡献方停止后分页消失（输出 36 的三句）。现有用例只测了“启用才出、排在数据分页之后与情节之前、组件拿到条目与位置”。
- `context.FieldTable`：嵌进专门界面的字段表能不能点开来历、点“改”出确认条、`state.open` 与专门界面自己的状态不冲突。entry-views 只断言页面文字里有“字段”和“听过的说法”，e2e 只断言“改”按钮可见（`toBeVisible`），没点它。
- 读取层：外部读取换输入时旧的接着显示、新的读到才换（`useExternalRead` 的 `useSwitching`）、组件卸载后句柄释放（`users` 归零）；外部列表读失败后的重试；`behind` 只有普通外部读取有用例，外部列表没有。
- Spec plot 输出 5、7、10、21：点名字打开条目页、“再显示（还有 N 项）”并进已有的组、选要看的人（上限 12、缺省前 3 个）、分段筛选的方向键与 Tab 顺序，都没有用例（NARROW 版式只有 e2e 的秘密页断言了 `[data-secrets-list]`，账本窄版式只量了无横向滚动，没断言换成了列表）。jsdom 里没有 ResizeObserver，`useContainerWidth` 在 dom 测试里恒为“很宽”，窄版式在 dom 层根本进不去。
- e2e 验收 5 的“没有出现加载占位”是否真量得到：这是否定断言，按仓库做法需要先做变异检查（例如临时让 `useSwitching` 不留 previous，看 `watchBusy` 会不会变真）。t31 的 evidences 目录里没有关于 plot-author e2e 的变异检查记录（只有设计审查、规模与 B1 的审查证据）。
为什么是问题：这几项正是本批新加的合同；缺了其中任何一个行为，现有测试都不会变红。
建议改法：按上面清单补，优先 pick-line（含 lost）、附加分页的消失与回退、FieldTable 的展开与改；读取层的换输入与释放可以在 world.dom.test.ts 里用真实世界补。

### 16. 窄屏第一帧先画宽版式再换成列表
严重程度：建议
类别：UI
位置：plot/web/page-shell.ts:`useContainerWidth`（`shallowRef(Number.POSITIVE_INFINITY)`，到 ResizeObserver 第一次回调才有值）
现象：容器宽度在挂载后异步才量到，在那之前 `width` 是无穷大，“谁知道什么”与“伏笔账本”先按宽屏画一个表格（带 `overflow-x-auto`），下一帧才换成列表。390 宽的手机上会闪一下表格；数据在读取中时看不到（先是占位），所以主要出现在切回已读过的标签、或读取很快的时候。
为什么是问题：Spec 输出 6 要求容器宽度不足 640 时只渲染列表；闪一下的表格与验收 6“都没有横向滚动”在时间上矛盾（e2e 在量之前等了 `[data-secrets-list]` 可见才量，所以量不到这一帧）。
如何核实：从代码推断，未跑。可在 e2e 里把视口设成 390 后立刻 `page.goto` 并用 MutationObserver 记 `[data-secrets-table]` 是否出现过。
建议改法：`onMounted` 里同步读一次 `root.value.clientWidth` 作初值（不用等观察者），观察者只负责之后的变化。
