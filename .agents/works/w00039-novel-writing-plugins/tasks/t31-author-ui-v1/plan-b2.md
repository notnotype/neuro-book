## B2-1 的关键设计

### 一、剧情读取的补口（`plugins/plot/core/`、`backend/plugin.ts`、`shared/contracts.ts`、`shared/checks.ts`）

四项，都只是读，算法复用现有函数；写进对应 Spec 的 planned 条目，各配包测试（真实 `World`）：

| 项 | 加什么 | 给谁用 | Spec |
|---|---|---|---|
| P1 保密账本带主体与“打算怎么揭” | `secretLedger` 每行加 `subject`（知识点在条目树里的父条目，根下为 null）、`reveal`：这条线上指向它的揭示计划（计划 id、章、`hint` 或 `explicit`、兑现没有）与挂在它上面的决策（id、状态、结论、到期章） | 谁知道什么的分组与“打算怎么揭”一列 | `plot/checks.md` 输出 9 |
| P2 知情行带位置 | `knowing` 的每行加 `at`：让这一行成为现在这样的那条变更的安放（章 id，前史为 null，推出的行同样有）；`source` 为 `secretGoal` 的取目标出场处 | 人物页“知道什么”每行的“第 N 章”“前史” | `plot/knowledge.md` 输出 3 |
| P3 一个知识点谁知道 | 新读方法 `point {point, position?, mode?}`：有有效知情行的每个人（程度、怎么知道、谁告诉的、他以为的、`at`），没有行的有名字的人数；读者的程度与第一次怀疑、知道的讲述（章、段、那一段的前 80 个字）；和它有关的：挂在它上面的决策、以它为答案的伏笔（阶段）、`起因` 是它的态度（持有者、对象）、`隐秘` 是它的目标 | 秘密条目页的“谁知道” | `plot/knowledge.md` 新输出 11 |
| P4 目标最近一次动过 | `goals` 的每个目标加 `lastChanged`：读取位置为止最近一次改到这个目标条目的那条变更所在的章（没有为 null），与 `stalled`（`plot.goals` 输出 4 的停滞规则在这个位置成立与否） | 目标表右边的“第 2 章动过”“2 章没动过” | `plot/goals.md` 输出 5 |

不另给名字：界面按第一批的做法读条目的名字（`object-heads` 那一套，一页最多 50 个对象）。

### 二、canon 浏览器入口的三处扩展（`plugins/canon/web/`、`shared/contracts.ts`、`shared/`）

1. **读取服务**：`shared/contracts.ts` 加服务键 `canonReadsKey` 与接口（只放类型与键）：`read(method, input)` 与 `list(method, input)` 同第一批读取层的读法；`external(key, fetch)` 把任意一个异步读取挂进同一代、同一轮（`key` 决定合并，`fetch` 收到当前代的世界版本）；`connection` 与 `retry()`。实现就是 `world.ts` 的那一份，入口启动时按调用方提供。失效的事件不变：剧情插件存的写作指示、自陈与检查记录变了时它报告新的诊断数据版本，canon 已经发 `inputChanged {what: "diagnostics"}`（K-d），整代作废。
2. **窗口看哪条线**：
   - 公开状态 `nbook.canon/line`：窗口在看的线的 id，或 null（跟着章：读取位置不写线，按 `canon.worldlines` 输出 12 取那一章讲的线）。缺省 null，不存盘，刷新后回到 null。
   - 状态栏条目 `nbook.canon.line`（右侧）：“在看：线名”，null 时写缺省位置那一章讲的线的名字；点了弹出线的列表（`lines` 在实际模式下存在的线，按树缩进；第一项“跟着章”），选了改公开状态。窗口没有绑定项目、世界没读到时不显示。
   - 条目页与剧情的几个页面：读取位置都带上窗口的线（null 时不带）。页头在世界有两条以上线时显示同一个线的选择，改的是窗口的那一个；只有一条线时不显示。
   - 选着的线不在了（分叉被撤销）：回到 null，状态栏的线列表顶上写一句“原来看的那条线已经不在了”。
   - 待处理、改动记录两个视图这一期不跟线（仍按缺省位置），B2-3 再定。
3. **条目页的附加分页**：新贡献点 `canon.entry-tabs`：声明 `{title?, requires: Component 类型 id, order?}`，条目启用了那个类型时出这个分页，排在数据分页之后、“情节”之前；只收浏览器入口、必须交实现，同 `canon.component-views` 的校验（`idPrefix: "plugin"`）。实现 `load()` 交组件，组件收到 `{context: EntryTabContext}`：`entry`、`position`（带窗口的线）、`mode`、`version`、`state`、`place(at)`、`open(ref)`；不给写入入口。第一批的 `ComponentViewRegistry` 照样管它（同一个注册表多一种），贡献方停止时这个分页消失。

位置选项与选择控件挪到 `src/ui/`（技术选型），canon 条目页改用挪过去的那份，行为不变（第一批的组件测试兜底）。

### 三、剧情插件的浏览器入口（`plugins/plot/web/`，新）

- 描述符 `locations` 加 `browser`；入口启动时激活（视图与页面的实现要在启动时交），按 canon 的读取服务读。
- **侧栏视图** `nbook.plot.sidebar`（“剧情”，图标 `i-lucide-git-branch`，`order: 20`，排在“设定”之后）：两组。“表”：谁知道什么、伏笔账本、目标表，点了开对应页面（时间线在 B2-3 加）；“剧情线”：种类为“剧情线”的条目（canon `tree` 读到的那些，按条目树的顺序），点了开它的条目页。窗口没有绑定项目时一句“打开作品后可用”。“这几章”在 B2-2 加。
- **三个页面**（编辑器的无参数页面，刷新后恢复）：`nbook.plot.secrets`（谁知道什么）、`nbook.plot.ledger`（伏笔账本）、`nbook.plot.goals`（目标表）。页头：标题、位置选择、“把计划也算上”、（两条线以上时）线的选择；面包屑“剧情 › 页面名”，点“剧情”显示剧情视图。位置、模式、筛选、选的人是标签自己的状态（同第一批输出 7）。
  - 谁知道什么：P1 的 `secretLedger`（一页 200 行，再多“再显示”）。行按主体分组（“关于星瑕”，没有主体的归“别的”），组按主体在条目树里的顺序；列：秘密（名字链接、保密档）、选中的人各一列、“别的人”（没选的人里知道、信错、怀疑的，写名字与程度，没有写“没有人知道”）、读者（程度与“第 N 章第 M 段起”）、打算怎么揭（揭示计划的章与明说或暗示、决策的结论或“还没定”与到期章；都没有写“没有打算”）。分段筛选：全部、只有读者知道（读者到怀疑以上、角色里没人知道）、读者还不知道、没打算怎么揭，各带条数。“选要看的人（3 / 12）”：候选是在任何一行里出现的人加目标的持有者；缺省选持有目标的人里的前 3 个（按名字），没有时选出现在行里最多的前 3 个。程度的格子写文字（知道、信错了、怀疑、不知道、忘了），不只靠图标。
  - 伏笔账本：`ledger`。分段筛选：还没收（阶段不是已回收）、很久没提（`dropped`）、没打算怎么收（没有计划的回收节点且没回收）、全部。列：伏笔（名字链接，没打算怎么收的下面写一句）、到哪一步、上次提到（“第 N 章”，很久没提的另写“N 章没提”）、接下来（位置之后最早的计划节点“第 N 章呼应”；没有且没回收写“没有打算”，警告色）、节点带。节点带只画有节点的章，按章序排，中间跳过的章收成一个省略格；写了的实心、打算写的虚线框，格里一个字（埋、应、误、部、收），旁边有图例；节点带在 390 宽时换到名字下面一行。
  - 目标表：`goals`（P4）。按持有者分组：持有者名字链接、他的态度一行一个（“对星瑾：想对她好……”）；目标一行一个：状态（进行、受挫；“也列达成与放弃的”开关打开后另列）、名字、有 `隐秘` 时“瞒着别人”、“和这些打架：持有者：目标”（链接）、“因为：知识点”（链接）、右边“第 N 章动过”，`stalled` 时用警告色写“N 章没动过”。顶上按持有者筛（“所有主要角色”或一个人）。
- **人物与秘密条目页的分页**（canon 的两个贡献点）：
  - `canon.component-views` 给 `nbook.plot.knowing`（“知道什么”）：两组，“保密的事”列出保密档以上的全部知识点（`secretLedger` 给全集，没有行的写“不知道”），“别的事”只列有行的；每行写程度、知识点链接、他以为的或怎么知道（“当时在场”“听某某说”）、右边 `at`（“第 N 章”“前史”）。
  - `canon.component-views` 给 `nbook.plot.attitude`（“目标与态度”）：这个人的目标（同目标表的一组）与态度表（对象链接、态度、起因链接、称呼）。
  - `canon.component-views` 给 `nbook.plot.point`（“谁知道”）：P3。三节：角色（有行的人，一行一个：名字链接、程度、怎么知道或他以为的、`at`；末尾“别的 N 个有名字的人都不知道”）、读者（程度、从哪一段起与那一段的开头）、和它有关的（决定、伏笔、态度、目标，各一行链接与一句状态）。
  - `canon.entry-tabs` 给 `nbook.plot.experience`（“经历”，`requires: nbook.canon.person`）：`experience`，按章分段（“前史”“第 N 章”），每条写剧情变更的文字与同时在场的人；末尾“还有 N 条没记谁在场”；一页 50 条，“再显示更早的”。
  - 知识点、人物没有启用对应的 Component 时不出这些分页（第一批的规则）。
- **命令**（域 `plot`，加进命令的域词表）：`nbook.plot.open-secrets`、`nbook.plot.open-ledger`、`nbook.plot.open-goals`、`nbook.plot.show-sidebar`。打开条目用 canon 的 `nbook.canon.open-entry`。
- 界面文字走界面文字机制（`plot/locales`，同 canon）；取值走 token；390 宽时三个页面与几个分页都没有横向滚动（表格在窄屏改成一行一条的列表：秘密名在上，下面一行写选中的人的程度）。

## 验收映射

以 S0 写成的 `plot/author-ui.md` 编号为准，写 Spec 时回填。粗分：页面与分页的内容由各自的组件测试接真实的世界服务与剧情项目入口断言；窗口的线由 canon 的组件测试断言（两条线的世界，换线后条目页与剧情页面读到另一条线的值）；分页的出现与消失由注册表测试断言；e2e 走样本上的一遍：打开剧情视图、三张表、星瑾的三个分页、一个秘密的“谁知道”、换一条线。

## 验证

- 真实运行：开发服务加新生成的样本，亮色 1440 与 390 宽截图，控制台没有错误、390 宽没有横向滚动，发成 report 产物。
- 规模：P1 到 P4 在 1000 章样本上各量一次（`canon-scale.ts` 不覆盖剧情读取；在脚本末尾加剧情插件的这四个读取，与第一批同样报中位与最大）。
- 未验证的边界：线超过 20 条时的列表样子；知识点上千时谁知道什么的分页（只测 200 行一页的翻页）。

## 不做与风险

- 不做：B2-2 到 B2-4 的内容；待处理与改动记录跟线；剧情表；表格里就地改知情（改知情从剧情变更的详情页走，第一批已有）。
- 风险：读取服务把 canon 读取层变成跨插件的公开接口，以后改它要顾及剧情插件。用 canon 的组件测试加一条“外部读取与世界读取在同一轮换上”兜底（真实世界服务、真实的剧情读取）。
- 风险：`secretLedger` 在知识点多时一页 200 行，谁知道什么要拿全集算“选要看的人”的候选；超过一页时候选只按已读的页算，写进 Spec 的已知限制。
