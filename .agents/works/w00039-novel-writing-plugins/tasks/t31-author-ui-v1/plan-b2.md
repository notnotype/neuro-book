审查核实出的现状（改变了第一版的前提）：

- 剧情现有读取的口径是给写手上下文、检查与 Agent 工具定的：保密账本只有知道、信错、怀疑三组，读者只有整书第一次揭示；经历按故事先后正序；目标表的持有者是有任一目标的人；态度只给文字，不给归纳状态；伏笔的 `dropped` 是作者“放弃”，不是“很久没提”。
- 规模没量过：1000 章、250 个秘密、100 个目标的作品，输入一变，保密账本第一次读 33 到 76 秒、人物知情 59 到 66 秒、目标表 41 到 56 秒（omp 在别的会话占着机器时量，冷读各一次）；同一份输入再读 20 到 520 毫秒。一行能大过远程单次预算。
- 剧情项目入口依赖存储，存储用 `bun:sqlite`，组件测试的 Node 侧场地装不上。
- 样本生成器只登记内置类型，不装剧情插件；生成宿主没有作者来源的校验，发不了已定的决策；样本里没有世界线的分叉；`lines` 不含主线。
- 跨插件运行时只能引对方的 `shared/contracts.ts`；第一批的读取钩子、页头、横幅都在 canon 的 `web/` 里。

工作方式：自主推进（开发者 2026-11-19 说“继续”，接着 11-18 指定的自主推进）。代码在实现 worktree `.worktree/w00039-novel-writing-plugins`（分支 `feat/w00039-t31-author-ui`，先并入 master）；记录与 Spec 在主工作区；主会话写代码；前端审查派 Claude Sonnet，后端审查开 omp；每期做完合入 master，不 push。

## B2-1 的关键设计

### 一、作者用的剧情读取（`plugins/plot/`：新 `shared/author.ts`、`core/author/`、`backend/plugin.ts`）

新远程合同 `nbook.plot/author`（项目实例提供，调用方 `browser`）。现有的 `nbook.plot/world`、`nbook.plot/checks` 不动：写手上下文、检查与 Agent 工具照旧用它们。每个方法给一个页面块要的全部东西，用同一份读取输入算：结果带 `version`、`inputDigest`、实际读的线 `line`（服务端按 `canon.worldlines` 输出 12 解析出来的）、名字表 `names`（结果里引用到的每个条目 id → 同一线、位置、模式上的名字与种类）。游标先校验再算（旧游标不必等全量重建才拒）。

| 方法 | 给什么 | 口径（写进 Spec） |
|---|---|---|
| `secrets {position?, mode?, segment?, people?, cursor?, limit?}` | 秘密表的一页：每行秘密、保密档、主体、`people` 里每个人的有效程度（含忘了、显式不知道、没有记录）、别的人里知道、信错、怀疑、忘了的、读者在这个位置的程度与整书第一次怀疑与知道、“打算怎么揭”；整张表的分段条数、候选的人与主要角色 | 行按主体在条目树里的顺序、再按名字；“打算怎么揭”= 所选线上可见的揭示计划（未来的也列；取消、被取代、失效拆出的不列）各带在所选位置的实际进展，加直接挂在它上面、待定或已定的决策（已定才写结论）；读者的程度按读取位置截到的讲述算；“只有读者知道”= 读者到怀疑以上而没有人知道、信错、怀疑；子列表各有上限与总数 |
| `point {point, position?, mode?}` | 一个秘密的“谁知道”：每个有行的人（程度、怎么知道、谁告诉的、他以为的、来处），没有行的人数，读者，和它有关的（直接挂的决策、读者守卫的决策、以它为答案的伏笔与阶段、起因是它的态度、隐秘是它的目标） | 人群是所选线、位置、模式上已出场、未删除的人物与组织，按本体去重；没有行只在保密以上算“不知道”，否则“没有记录”；来处分初值、事件（章与段）、目标出场、从别的线带过来（另给原证据的位置与线） |
| `person {person, position?, mode?}` | 人物页“知道什么”与“目标与态度”：所有秘密（含没有行的）与有行的别的知识点的知情行（同上的程度与来处），他的目标（各状态）与态度（带归纳状态） | 同上；态度的语义档未归纳时给“还没归纳” |
| `goals {position?, mode?, holder?, finished?, cursor?, limit?}` | 目标表：主要角色一组一组，目标带状态、隐秘、冲突、基于、最近一次动过的章与没动过的章数，组带态度 | 主要角色 = 所选位置上持有进行或受挫目标的人或组织；“动过”只算改到目标 `goal` 命名空间、在这个位置与模式下真正计入且套上的变更，没动过的章数从最近一次（没有时从出场）算到读取位置所在的章，与停滞诊断共用一个函数 |
| `ledger {position?, mode?, segment?, cursor?, limit?}` | 伏笔账本的一页：阶段、意图（放弃）、重要程度、上次提到、间隔章数与“久没提”、真正的下一步计划（角色与章）、没打算怎么收、节点带的节点；分段条数 | “久没提”与诊断 `nbook.plot.fs.longSilence` 同阈值同算法；下一步计划是所选位置之后、有效、未兑现的最早计划节点 |
| `experience {person, position?, mode?, cursor?, limit?}` | 经历：从新到旧分页，每条带安放、文字、同时在场的人、是不是“记得原线上的” | 同 `plot.knowledge` 输出 8；没记参与者的条数口径同 `canon.model` 输出 29 |

### 二、剧情读取的规模（`scripts/perf/plot-scale.ts`，细设计量过以后写）

1. 先量：`plot-scale.ts` 加作者要用的现有读取（`secretLedger`、`knowing`、`goals`、`ledger`、`experience`），分开报“输入变了以后的第一次”“同一份输入再读”“下一页”“游标过期的拒绝”，形状按 omp 探针的密度（250 个秘密、100 个目标、100 个伏笔）补齐，负载低于 3 时跑。
2. 再定：按剖析找出第一次读慢在哪（知情索引、目标的冲突、伏笔物件的扫描、揭示与决策的逐秘密查找），给 `nbook.plot/author` 定索引与缓存（同一份读取输入按需建、跨页复用），写进本计划的细设计，派 omp 审一轮。
第一轮（2026-11-19，进程内，负载 7 到 12，[证据](evidences/b2-plot-scale-m1.txt)）：五个现有读取输入一变后第一次 23 到 178 毫秒，同一份输入再读多在 1 毫秒以内，目标表没有缓存（再读也是 87 毫秒）。omp 经远程量到的 33 到 76 秒进程内复现不出来，下一步在远程路径（真实项目子进程、写作指示变了以后）上复现与剖析，再写细设计。
3. 预算（草案，细设计时按测量改）：1000 章、上面的密度，每个作者读取在输入变了以后第一次 1 秒以内，同一份输入再读与下一页 100 毫秒以内；一行不超过远程单次预算。

细设计（2026-11-19，负载 2 到 4 时量，[证据](evidences/b2-plot-scale-1000.txt)）：没有缓存时第一次都在预算以内（10 到 202 毫秒），超预算的只是再读（`person` 中位 135、`secrets` 最大 159），原因是每次请求整张重算，不是索引慢。所以不改知情索引等结构，只把 `core/author/` 导出的七个读取按视图缓存整张结果（沿用知情索引的 `perViewCache`，键是模式、位置与参数），请求只做分页、这一页的名字表与结果大小的核对；规模脚本另经 `remoteAuthor` 量六个方法（含下一页）：第一次 15 到 198 毫秒，再读与下一页至多 12 毫秒。原定“细设计派 omp 审一轮”是为了改索引结构的风险，这个风险没有了，审查并进收口的后端实现审查。omp 经远程量到的 33 到 76 秒仍没在进程内复现（同一输出里阶段 F 的读待处理慢在 t34 的写作检查，第一轮已有），收口时在 e2e 的真实项目上看作者读取的远程耗时。

### 三、canon 浏览器入口的扩展（`plugins/canon/web/`、`shared/contracts.ts`）

1. **读取服务 `canonReadsKey`**（整个窗口一份，没有绑定项目时为 null）：
   - 组合函数：`useRead`、`useList`（世界的读取，同第一批的 `use-reads.ts`，含换输入时旧的接着显示）、`useExternal(method, input, fetch)`、`useExternalList(method, input, fetchPage)`。外部读取的键 = 调用方插件 id + 方法名 + 输入，取数只由输入决定；取数抛错由读取层包成失败 `external-failed`，剧情的失败码从 `detail.code` 归一；结果的 `version` 比 canon 已知的旧时标过期、下一轮重读。外部列表页长上限 200，重读时按真实页长追游标重建已读的条数，同一读戳才换上。`run` 的一轮用 `try/finally` 复位。
   - 窗口的线：`line`（只读，字符串，空串是跟着章）、`setLine`、`lineOptions`（主线加实际模式下存在而且可建的线，按树缩进）、`chapters`。
   - 组件：`PageHead`（标题、位置选择、“按计划”、两条以上线时的线选择、断开与只读的横幅；第一批条目页改用它）。
2. **窗口在看的线**：公开状态 `nbook.canon/line`（字符串，空串是跟着章）与 `nbook.canon/lineReady`（布尔）；命令 `nbook.canon.pick-line`（走 quickPick：第一项“跟着章”，其后主线与各线，按树缩进；选着的线刚不在了时标题写“原来看的那条线已经不在了”）；状态栏条目 `nbook.canon.line`（`when.requires: lineReady`）：只有主线时“在看：主线”，两条以上时跟着章写“在看：跟着章”，选了线写“在看：线名”。换线不改页面的位置。canon 常驻一个 `lines` 读取，选着的线不在了（不存在、不可建、成了计划线）就回到跟着章。标签标题固定按缺省位置、不带窗口的线读。
3. **专门界面带通用字段**：`ComponentViewContext` 加 `FieldTable`（组件：这一页的通用字段表，可传 `fields` 只列其中几个），专门界面在自己的内容之外嵌一节可改的字段；第一批的人物、面板不变。
4. **附加分页 `canon.entry-tabs`**：声明 `{title?, requires, order?}`；条目在所选位置上启用了 `requires` 那个类型时出，排在数据分页之后、“情节”之前；标签状态按贡献 id 存；与 `canon.component-views` 各一个注册表实例（同一个类）；`EntryTabContext` 同 `ComponentViewContext` 去掉写入入口与字段。这一期只有剧情的“经历”用。

### 四、剧情插件的浏览器入口（`plugins/plot/web/`，新）

- 描述符 `locations` 加 `browser`，入口启动时激活；登记清单：`web/plugins.ts` 的浏览器插件表与 `builtinPluginCatalogs`、Lab 的文字夹具、模块头注释、每个组件的同名 `.md`。
- 侧栏视图 `nbook.plot.sidebar`（“剧情”，`order: 20`）：“表”（谁知道什么、伏笔账本、目标表）与“剧情线”（种类为“剧情线”的条目）；选中项的说法同第一批（最后显示出来的那一页对应的一项）。
- 三个无参数页面 `nbook.plot.secrets`、`nbook.plot.ledger`、`nbook.plot.goals`，页头用 canon 的 `PageHead`，面包屑“剧情 › 页面名”。内容列封顶 1100 像素，容器宽度 640 以下切成列表（只渲染一种）。
  - 谁知道什么：`secrets` 一次读完一页；按主体分组；列：秘密（名字、保密档）、选中的人、别的人、读者、打算怎么揭（决策不可点，写结论或“还没定”与到期）；分段筛选的条数来自服务端；“选要看的人”用多选弹层，候选与缺省（主要角色按名字的前 3 个，没有时出现最多的前 3 个）来自服务端。
