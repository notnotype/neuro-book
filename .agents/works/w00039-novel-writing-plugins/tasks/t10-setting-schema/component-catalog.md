# 内置设定组的清单

2026-11-24 第 3 稿（第 2 稿之后开发者定：一个分页对应一个设定组；形象单独成组、人物的展示可以引用它；展示部分先用 Vue 组件，MDX 模板的想法记在 [t38](../t38-kernel-shared-parser/README.md)）。以下保留第 2 稿的说明：开发者同日看过第 1 稿：“这个划分我同意……其他都同意”，第八节的六条都已定；并问设定组多了（例如三十多个）作者会不会不知道选哪个、有关联的设定组（人物与形象）怎么处理，主会话的回答写成第五节之后的“设定组多了以后”，等开发者确认。

第 1 稿的来历：开发者当天说：“人物设计组，我希望 NeuroBook 默认就提供一个好看的面板（用户填表单），也提供一组预设好的值”；问到“预设”指什么时四样都要（预设的资料字段、选项类字段的预设选项、数值面板的预设项、新建人物的整套模板），并补充：“还要支持立绘，人物的服装，换装功能（当然这些外貌相关、或者换装功能我觉得其实也可以单独做一个 Component）。我觉得人物这里放最通用的，例如魔力，万一还有技能呢？我觉得我们可以一次性先把所有我们要做的 Component 先设计好”。面板的版式选了“角色卡”（左边立绘，右边名字与基本资料，下面按外貌、性格、背景分区，点进去就地填）。

本稿只定“有哪些设定组、各放什么、预设什么、内核要补什么、先做哪些”。界面的样子另出 Lab 稿评审；实施时各自写计划。

## 一、现状（2026-11-24，从代码读出）

- 内置的带数据的类型只有两个（`canon/shared/components.ts`）：人物（`character`，6 个文字字段：外观、状态、现在的态度、身体、现在的样子、性格，是为星瑕样本凑的）与面板（`panel`，没有固定字段，每个条目自己声明）。
- 剧情插件另有五个（`plot/shared/declarations.ts`）：知识点、知情、伏笔、目标、态度。本稿不动它们。
- 字段的种类有七种：数、文字、选项、是否、列表、图片、引用；数与文字分精确档与语义档。
- 条目的种类（“人物”“组织”）只是一段文字，新建条目时自己勾要哪些设定组；没有“这个种类自带哪些设定组”的登记。
- 界面：每个设定组一个分页。人物分页是一行一个字段的表，面板分页是数值卡加流水。图片字段现在只能手填路径与说明，不显示图。

## 二、划分的原则

1. **一个设定组只回答一个问题。**“他是谁”“他长什么样”“他有多少”“他会什么”各是一组。组小，作者才能按书的类型取舍：日常文不要数值与技能，游戏文全要。
2. **人物只放每本书都用得上的。**某类书才有的（魔力、技能、种族）不进人物：数值进“数值”，技能进“技能”，种族这类零散的资料靠“添加一项”（预设里给，一点就加）。
3. **会随剧情变的放字段，不放主文字。**（开发者 11-24 定）所以“现在在哪”“现在穿什么”“现在的状态”都是字段。
4. **一件事只记在一处。**重要物品是条目，谁拿着记在物品上；人物那边看到的是查出来的，不另存一份。
5. **字段少而准。**每个字段都要让记账的模型读一章就能判断“变没变”。拿不准要不要的不内置，放进可加的预设项。

## 三、清单

共十组：人物用的六组，别的条目用的三组，加上已有的剧情五组不动。“随剧情”一栏写这个字段在故事里常不常变（都能变，这里只是提示记账该盯哪些）。

### 1. 人物（`character`，已有，重整）

他是谁。每个人物都有。

| 字段 | 种类 | 预设的建议值 | 随剧情 | 说明 |
|---|---|---|---|---|
| 性别 | 文字 | 男、女、不明 | 少 | 建议值可点选，也能自己填 |
| 年龄 | 文字 | | 少 | 写“17 岁”“看上去二十出头”都行，不做成数 |
| 身份 | 文字 | | 常 | 一句话：职业、社会身份 |
| 所属 | 引用（组织） | | 常 | |
| 性格 | 文字，会在正文里重述 | | 少 | |
| 背景 | 文字 | | 少 | 来历、经历 |
| 说话方式 | 文字，会在正文里重述 | | 少 | 口癖、语气 |
| 现在的状态 | 文字，语义档 | | 常 | 受伤、被通缉这类处境 |
| 现在在哪 | 引用（地点） | | 常 | |
| 生死 | 文字 | 活着、已故、失踪 | 少 | |

可加的预设项（不内置，“添加一项”里列出）：种族、生日、身高、喜好、弱点、动机、初次登场。

与现在的差别：“外观”搬到形象；“身体”“现在的样子”是星瑕那本书专有的，改由“性别”与马甲各自的形象表达；“现在的态度”与剧情插件的“态度”重复，去掉。

### 2. 形象（`look`，新）

他长什么样。立绘、服装与换装都在这里。马甲条目各有一份自己的形象（11-02 已定：本体只放原身的外观）。

| 字段 | 种类 | 随剧情 | 说明 |
|---|---|---|---|
| 立绘 | 图片 | 少 | 角色卡左边那张 |
| 外貌 | 文字，会在正文里重述 | 少 | 身体特征：发色、眼睛、体型 |
| 服装 | 列表：名字、样子（文字）、图片 | 少 | 衣柜：有哪几套 |
| 现在穿的 | 文字 | 常 | 填服装的名字；界面从衣柜里给选项。换装就是改这一项 |

### 3. 数值（`panel`，已有，显示名建议从“面板”改成“数值”）

他有多少。每个人物的数值项不一样，所以没有固定字段，全靠“添加一项”。

预设项（一点就加，带好单位与上下限的关系）：体力与体力上限、魔力与魔力上限、等级、经验、金钱（单位可改）、声望。作者也能加自己的数值项。

### 4. 技能（`skill`，新）

他会什么。

| 字段 | 种类 | 说明 |
|---|---|---|
| 技能 | 列表：名字、说明（文字）、等级（文字，语义档）、消耗（文字） | 等级写“入门”“熟练”或“3 级”都行 |

### 5. 物品栏（`bag`，新）

他带着什么（不值得单独建条目的东西）。

| 字段 | 种类 | 说明 |
|---|---|---|
| 物品 | 列表：名字、说明（文字）、数量（数） | 重要物品不记在这里：它是条目，“持有者”记在它自己身上，角色卡上把它查出来一起列 |

### 6. 关系（`rel`，新）

他和谁是什么关系。

| 字段 | 种类 | 说明 |
|---|---|---|
| 关系 | 以引用为键的列表（人物、组织）：关系（文字）、备注（文字） | 关系是“妹妹”“师父”这类不大变的；“现在怎么看他”“怎么称呼”在剧情插件的“态度”里。角色卡上两边按对象合在一行看 |

### 7. 组织（`org`，新）

| 字段 | 种类 | 随剧情 |
|---|---|---|
| 性质 | 文字（建议值：国家、门派、公司、帮派、学校） | 少 |
| 徽记 | 图片 | 少 |
| 首领 | 引用（人物） | 常 |
| 据点 | 引用（地点） | 常 |
| 成员 | 以引用为键的列表（人物）：职位（文字） | 常 |
| 现状 | 文字，语义档 | 常 |

### 8. 地点（`place`，新）

上下级（城里的街、街上的店）用条目树表达，不设字段。

| 字段 | 种类 | 随剧情 |
|---|---|---|
| 性质 | 文字（建议值：城市、建筑、房间、野外） | 少 |
| 图片 | 图片 | 少 |
| 样子 | 文字，会在正文里重述 | 少 |
| 归属 | 引用（组织、人物） | 常 |
| 现状 | 文字，语义档 | 常 |

### 9. 物品（`item`，新）

值得单独建条目的东西（信物、武器、关键道具）。

| 字段 | 种类 | 随剧情 |
|---|---|---|
| 性质 | 文字（建议值：武器、信物、文书、消耗品） | 少 |
| 图片 | 图片 | 少 |
| 样子 | 文字，会在正文里重述 | 少 |
| 作用 | 文字 | 少 |
| 持有者 | 引用（人物、组织） | 常 |
| 现在在哪 | 引用（地点） | 常 |
| 状态 | 文字，语义档 | 常 |

### 不做成设定组的

- 世界观的规则、历史、概念：是成篇的文字，用条目的主文字。
- 知情、态度、目标、伏笔、知识点：剧情插件已有。
- 任务、状态栏这类给扮演玩法用的：等那条线开始时再设计。

## 四、四样预设各落在哪

| 预设 | 做法 |
|---|---|
| 预设的资料字段 | 第三节各组的固定字段，新建就有 |
| 选项类字段的预设选项 | 做成“建议值”：文字字段带一组可点选的值，也能自己填。不做成封闭的选项：内核的选项字段只收列出的值，“性别”这类每本书都可能有例外 |
| 数值的预设项 | “数值”的“添加一项”里列出，点了就在这个人物上声明这个数值项 |
| 整套模板 | 新建条目时选：人物（资料加形象）、人物（带数值、技能、物品栏）、组织、地点、物品。模板定的是带哪几组设定、预先加哪几个数值项。**不往里写示例内容**：写进去的值会被当成这本书的事实，记账与写手都会读到；示例只作为空字段里的提示文字出现 |

## 五、展示部分：一组一个分页，人物的角色卡引用形象

开发者 2026-11-24 在 [t41 的评审板](../t41-character-component/README.md)上定：一个设定组是数据加展示，一个分页对应一个设定组；形象单独成组，人物的展示可以引用它；展示部分先用 Vue 组件写。

- **人物分页**是角色卡（人物这一组的展示部分）：左边立绘，右边基本资料与现在的状态，下面是性格、说话方式、背景。立绘读自同一条目上的形象组；条目没有形象组时那里是“添加形象”。
- **形象分页**是形象这一组的展示部分：大图、外貌、衣柜、现在穿的。
- 其余各组各一个分页、各有自己的展示部分；没写专门界面的用通用的字段表。
- 展示组件现在只拿得到本组的字段。要加一个入口：展示组件声明它会用到哪几组，从 `context` 读、改同一条目上的那几组；那一组不在这个条目上时得到“没有”。

下面是第 1 稿的原文（已作废，留作对照）：

开发者选的角色卡把立绘（形象）、基本资料（人物）、外貌（形象）、性格（人物）画在同一页。所以人物类的条目多一个“资料”分页，把这个条目上人物类的几组设定按分区画成一张卡：有的分区就地填，没有的分区是一个“添加”。各组原来的分页怎么处理见第六节第 5 条。

## 六、设定组多了以后（等开发者确认）

开发者 2026-11-24：“有些设定组之间是有关联的。例如人物一般和形象会一起出现。以后设定组会不会变成 30 多个导致用户选择困难呢？例如地点下面可能也会出现几个地点专属的。这里怎么设计？”

原则：选择不发生在“建一个条目”的时候。设定组的总数可以多，一个条目面前只有属于它的那几个，而且多数时候不用选。

1. **种类带一套默认的设定组。**种类（人物、组织、地点、物品）是登记项：名字、默认的分组、默认带哪几组设定。新建人物直接带人物与形象，不再勾。作者照旧可以写新的种类，没有默认的一套。第四节的“整套模板”落在这里。
2. **设定组声明自己适用于哪些种类。**“添加一组设定”只列适用于这个条目种类的，其余收进“全部”。是适用不是限制：内核不拒收不适用的（给帮派加数值也行）。
3. **一本书定一次。**作品设置里一张表：这本书各个种类默认带哪些设定组（缺省是登记的那一套）。游戏文开书时把数值、技能、物品栏勾进人物，之后新建的人物都带。
4. **用到时再加。**角色卡底部有“添加”；记账提议的变更落在条目还没有的设定组上时，提议里带上“先加这组设定”。
5. （作废）~~分页不跟着变多：人物类的设定组都画在“资料”一页的分区里。~~开发者定每组各一个分页。
6. **强关联才用依赖。**一组设定离了另一组不成立时声明“需要”，加它时自动带上被需要的。人物与形象这种“通常一起”靠第 1 条，不绑死。

要新增的：种类的登记、设定组声明里的“适用的种类”（都进第一期）、作品级的那张表（与模板一起在第三期）。种类仍然只是条目上的一段文字，内核的模型不变。

## 七、内核与底座要补的

| 要补的 | 现状 | 谁要用 |
|---|---|---|
| 在条目上加、改名、删字段的写入操作 | Spec（`canon/components.md` 输出 4）写了，内核的写入操作里没有；现在只能靠初值带入 | 数值的预设项、各组的“添加一项” |
| 文字字段的建议值（声明里加一项，内核不校验，界面与 Agent 都读得到） | 没有 | 预设选项 |
| 允许加字段的类型不止面板 | 只有面板开着 | 人物、形象等的“添加一项” |
| 展示组件读、改同一条目上的另一组设定 | `context` 只有本组的字段 | 角色卡上的立绘（读自形象组） |
| 重整人物的字段 | 第一版没有升级函数，改类型要升版本、旧数据只读 | 人物 |
| 图片：显示、从作品里选、上传 | 设定这边只有手填路径；文件插件有取图的地址与上传，章节编辑器有选图卡片，可以接 | 立绘、服装、徽记 |
| 按引用反查（哪些物品的持有者是他） | 在内核与设定插件的非测试代码里没搜到这样的读取 | 角色卡上列重要物品 |
| 种类的登记（默认带哪几组设定）、设定组适用于哪些种类 | 种类只是一段文字，新建时自己勾设定组；“添加一组设定”列出全部登记的类型 | 新建条目、“添加”、整套模板 |

重整人物字段的处理建议：现在没有发布过带世界引擎的版本，真实数据只有样本与开发时的试验作品，所以直接改声明、重做样本，不为此做升级函数；试验作品里旧字段的值留在日志里，界面上看不到。

## 九、开发者定的（2026-11-24：“这个划分我同意……其他都同意”）

1. 划分与字段清单照第三节。
2. “面板”的显示名改成“数值”。
3. 预设选项做成可以自己填的建议值，不做成封闭选项。
4. 模板不写示例内容，示例只作提示文字。
5. 重整人物字段时直接改声明、重做样本，不做升级函数。
6. 先后照第八节，第一期做完先接记账。
