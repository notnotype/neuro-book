# 设定类型、schema 与设定表单

## 目标与范围

定设定类型（人物、地点、势力……）的 schema 写在哪、用什么写、怎么演进，以及按 schema 由 nb-form 画出的设定表单与设定库界面。来自旧版用户反馈：设定、人物管理太复杂，只能通过文件来设定。schema 的 `x-form` 提示与要补的控件是同一份决定。

合同：讨论 Task，只定设计，行为合同未变；定稿后的 Spec 改动在实施时另定。

前置：t09。

## 要讨论的问题

### 设定类型与 schema 演进

1. 写法：JSON Schema 加 `x-form` 提示（nb-form 直接用，不执行代码，Agent 能生成），还是旧版的 Zod TS（单文件、不能 import 是痛点）。
2. 放在哪：项目里（`lorebook.content/<类型>/schema.json`）、模板里、插件里；三层覆盖（内置、插件、用户、项目）要不要。
3. 内置哪些类型、各有哪些字段；用户自定义类型与自定义字段的上限。
4. 演进：加字段、改名、改类型、删字段时已有文件怎么处理（旧版不做版本化与迁移）；校验失败的旧文件怎么显示。
5. Agent 生成或修改 schema：走 nb-form 的 `policy: "agent"` 检查；Agent 改 schema 要不要审批。
6. 哪些字段会随剧情变化（接 t04），引用别的设定的字段怎么声明（接 t02）。

### 设定表单与设定库界面（原 t15）

1. 旧版其实有人物表单，用户仍觉得复杂：先弄清复杂在哪（字段多、要懂 frontmatter、两份状态、找不到入口），再定界面。能不能找到原始反馈。
2. 表单与文件的分工：结构化字段进 frontmatter、自由描述是正文；表单里怎么同时编辑两部分。
3. nb-form 要补的控件：引用另一条设定（可搜索的下拉）、图片（立绘）、随剧情变化的字段（显示当前值、点开看各章各线的变化）、标签。
4. 列表层面：卡片墙、表格（批量改字段）、按类型与标签筛选、搜索。
5. 新建设定的入口：表单、从正文选中文字创建、让 Agent 起草。
6. 表单与文件同时被改（Agent 写文件、用户开着表单）时的冲突处理。
7. nb-form 的 Spec 还是 `planned`，这里是它的大使用方，要不要一起推它定稿。
