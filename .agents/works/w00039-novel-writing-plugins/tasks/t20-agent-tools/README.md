# Agent 工具与写手的上下文

## 目标与范围

定这套插件给 Agent 的工具（设定、剧情、状态、图谱的读写与查询），以及写一章时写手拿到的上下文（章级 brief、取哪一刻的状态、检索）。上下文靠工具取或由程序编译进去，是同一个取舍。按 w00032 t04：一个工具只做一件事。

合同：讨论 Task，只定设计，行为合同未变；定稿后的 Spec 改动在实施时另定。

前置：t04、t10、t14、t19。

## 要讨论的问题

### 小说创作的 Agent 工具

1. 工具清单：查对象、读设定、写设定、记状态变动、查某时刻状态、查谁知道什么、读剧情、改大纲、查差异……数量多时怎么让 Agent 找得到（w00032 t04 搁置了工具发现）。
2. 设定是文件时，Agent 直接用 read、edit 改文件，还是必须走专用工具（专用工具能校验 schema、维护引用）。
3. 旧版 `execute_world`（CodeAct 沙箱）的教训：bigint 时间、日历字符串、两套问题码；新工具的参数怎么让模型少出错。
4. 防剧透与权限：写手只读；按阅读位置限制写手能看到的未来设定（见下面“写手的上下文”）。
5. nb-story 命令行与 Skill 已有一套查询接口，插件工具与它共用到什么程度。
6. 写入的审批与 History 记录（w00032 t06、t13）。

### 写手的上下文：章级 brief 与检索（原 t21）

1. 旧版 brief 的七段（章目标、参数、信息控制、节奏、禁写、剧情点、建议读取）哪些留；由程序编译、Agent 起草还是作者手写。
2. 按位置取上下文：只给写到本章为止的状态与已揭示的秘密，未来的计划给不给写手（给了容易提前写出来）。
3. 检索：按引用、按在场者、按名字匹配、向量检索（旧版 `EmbeddingText`）；要不要向量检索、索引放哪。
4. 前文怎么给：全文、摘要、nb-story 的章节变化；长篇写到几百章时的上限。
5. 旧版写手 curated 模式因工具在 Profile 定义期固定而延后；新 Profile 机制（w00032 t05、t20）下能不能做。
