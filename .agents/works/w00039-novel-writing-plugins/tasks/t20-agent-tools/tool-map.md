## 开发者 2026-11-23 定的

- **现在最首要的是世界引擎的管理与记录。** 写手任务、记账管线先不考虑（第 5 节的第 3、4 档）。
- **Agent 这条线暂且不推。** 先按下面的路径做作者这一侧：
  1. 最基础的条目加主文字（MDX）的编辑器，目标是“世界引擎能像文件系统一样记录东西”（[t28](../t28-entry-mdx-editing/README.md)）；
  2. 第一个设定组：人物。能放图片，给作者一份生动的表单填数据。
- **Agent 恢复时要先做得到的事**（开发者举的例子）与主会话对照这张图查出的缺口：

  | 例子 | 用什么 | 缺口 |
  |---|---|---|
  | 作者让助手列出所有条目 | `canon_tree` | 一次只给一层、最多 50 项，整棵树要逐层读；恢复时看要不要给一次列全（带上限）的读法 |
  | 开书：确定历法，初始化设定条目 | 条目用 `canon_write`（一次最多 30 项） | 历法是作品设置里的数据（[`canon/time.md`](../../../../../docs/specs/canon/time.md)），15 个工具里没有改它的 |
  | 建立人物：外貌、关系等 | `canon_write` | 人物之间的关系没有结构化的存放处：关系设定组 11-01 定为第一版不做，现有的只有“态度”（按对象的列表） |
  | 记账 | `canon_record`（记一条剧情变更），数与语义档也可以用 `canon_write` 的剧情意图 | `canon_record` 还没做 |

  “记账”这一条是主会话的理解：指助手用工具把发生的事记进世界；程序跑的记账管线属于上面“先不考虑”的。

## 一句话

主 Agent 是作者唯一的对话对象，带工具。写正文、写完检查、记账是程序跑的后台任务，不带工具。

给主 Agent 的工具一共 15 个：

- 做了 4 个；
- 8 个的服务端方法已经有了，差工具这一层（参数、名字解析、上限、回话的文字、测试）；
- 3 个连后面的东西都没有：检索、写手任务、记账管线。

## 1. 谁用工具

| 角色 | 形态 | 用不用工具 |
|---|---|---|
| 主 Agent | 作者在右栏对话的会话，现在是内置的“主创” | 用：第 2 节的 15 个，加底座的文件工具 |
| 写手 | 后台任务：程序拼好上下文，模型一次生成 | 按细纲写时不用。自由发挥时有两个只读的查与读，按视角人物过滤（服务端已有 `openViewpoint` 一组方法） |
| 写完检查 | 后台任务：程序圈出候选，模型回答窄问题，另做一次不知道真相的试读 | 不用。已实现（[`plot/checks.md`](../../../../../docs/specs/plot/checks.md)） |
| 记账 | 后台管线：备料、起草、校验、修复、发布 | 不用，程序直接发布成一条修订 |
| 找旧写法 | 后台会话，作者改了设定以后起 | 用：底座的 `grep`、`read`，加设定的查与读；结果由程序存成正文建议 |
| 角色对话（以后） | 会话 | 只读的查与读，按这个角色知道的过滤 |

## 2. 给主 Agent 的工具

状态三种：**已做**；**差工具面**（服务端方法已有）；**后面没有**（服务或任务本身还没做）。“档”见第 5 节。名字是暂定的。

| 工具 | 它回答什么、做什么 | 后面的服务 | 状态 | 档 |
|---|---|---|---|---|
| `canon_lookup` | 这个名字是哪个条目 | `lookup`、`findEntries` | 已做 | 0 |
| `canon_tree` | 条目树的一层有什么 | `tree` | 已做 | 0 |
| `canon_read` | 一个条目在某个位置的样子：字段、主文字、来历、最近的修订 | `entry`、`render`、`origins`、`revisions` | 已做；待补读一条剧情变更或决策的原记录（`object`） | 0 |
| `canon_write` | 改设定：建条目、改各种字段、加去设定组、移动、删除、恢复、还原一次修订 | `editEntries`、`revert` | 已做 | 0 |
| `canon_changes` | 前面发生过什么：按章、涉及的条目、在场的人、剧情线、已写或计划列出剧情变更 | `changes`、`presence` | 差工具面 | 2 |
| `canon_pending` | 还有什么没处理：待处理、提示、没定的决策、没处理的正文建议 | `pending`、`decisions`、`suggestions` | 差工具面 | 2 |
| `canon_record` | 记剧情：记一条剧情变更或计划（描述、哪一章、在场的人、对条目的改动、正文原句、兑现哪条计划），撤销，取消或替代计划，加核对点，提一件要作者定的事，把待定的变更改成生效 | `publish`、`preview` | 差工具面（这一组里最大） | 2 |
| `canon_search` | 哪里提过这个词：在条目的文字与剧情变更的描述里找 | 没有 | 后面没有 | 2 |
| `canon_time` | 一件事在什么时候、两件事隔多久、某人当时几岁、某段时间里发生了什么 | `time` | 差工具面 | 2 |
| `plot_chapter` | 这一章开写前要看的：写作指示、计划、涉及的决策与到期没定的、该动的伏笔、检查结果；可以预览写手会拿到的上下文 | `beforeWriting`、`decisionsFor`、`brief`、检查的 `record` | 差工具面 | 2 |
| `plot_knowledge` | 谁知道什么：某人此刻知道哪些、某个秘密谁知道与怎么知道的、读者从哪里起知道 | `knowing`、`reader`、`secretLedger`、`readerKnown` | 差工具面 | 2 |
| `plot_ledger` | 几本账：伏笔（阶段、多久没提、打算在哪回收）、目标与冲突 | `ledger`、`goals`、`conflicts` | 差工具面 | 2 |
| `plot_draft` | 让写手写这一章，交回任务号 | 上下文的拼法已有（[`plot/brief.md`](../../../../../docs/specs/plot/brief.md)），写手任务没有 | 后面没有 | 3 |
| `plot_check` | 查这一章有没有穿帮、泄底、违反写作指示 | 检查的 `run`、`status`、`record` | 差工具面 | 4 |
| `plot_finish` | 这一章定稿，开始记账 | 没有 | 后面没有 | 4 |

写入怎么分：

- 知识点、知情、伏笔、目标、态度都是条目或条目上的设定组，用 `canon_write` 写；
- 剧情变更、计划、核对点、决策不是条目，用 `canon_record` 写；
- 正文、细纲、手记是作品里的文件，用底座的 `read`、`write`、`edit`、`grep`。

## 3. 工具周边

| 事 | 做什么 | 现状 |
|---|---|---|
| 自动预查 | 作者的消息里出现条目的名字时，程序先查好、每个一行附在消息后面 | 没做（经 `agent.extensions`） |
| 用法提醒 | 一组设定第一次出现、上下文压缩之后，补一段它怎么用；不进系统提示词 | 没做 |
| 欢迎页的示例 | 对话欢迎页给几条和设定有关的例子 | 没做 |
| 写世界要不要每次问 | 见“请开发者定”第 4 条 | 现在每次都问 |
| 真实模型验收 | 让真实模型照作者的话用这些工具 | 没做过 |

## 4. 一章走下来，各步用什么

| 步 | 谁 | 用到的 |
|---|---|---|
| 建设定、补设定 | 主 Agent，或作者在界面上 | `canon_lookup`、`canon_tree`、`canon_read`、`canon_write` |
| 讨论与审细纲 | 主 Agent | 读细纲文件；`plot_chapter`；按需 `canon_changes`、`canon_search`、`canon_time`、`plot_knowledge`、`plot_ledger`、`canon_pending` |
| 提计划 | 主 Agent | `canon_record`（计划）；`canon_write`（知识点、目标这类条目） |
| 写正文 | 写手任务，由主 Agent 的 `plot_draft` 或作者的按钮发起；作者、主 Agent 也可以自己写 | 程序拼的上下文 |
| 写完检查 | 检查任务，由 `plot_check` 或按钮发起 | 程序圈的候选 |
| 定稿记账 | 记账管线，由 `plot_finish` 或按钮发起；后面的步骤要用这一章的账而它没记时自动补记 | 程序备的料 |
| 处理待处理 | 作者在界面上；问到主 Agent 时 | `canon_pending`、`canon_read`（来历）、`canon_record` |
| 改设定以后 | 找旧写法的会话 | `grep`、`read`、设定的查与读 |

## 6. 和旧稿不一样的地方

流程草稿写于 11-02、独立设计写于 11-04，之后底座多了几样东西，下面几处前提变了：

- **子代理、任务中心、按工具的权限规则、`eval` 现在都有了。**
  - 写世界要不要逐次问，可以直接用权限规则表达，不用再等底座。
  - 一次读很多条目再汇总，模型可以在 `eval` 里调这些工具，不为批量另造工具。
  - 草稿把写手做成后台任务有三条理由，其中“派子代理的工具还没有”不成立了，另两条还成立（见“请开发者定”第 1 条）。
  - 任务中心现在只收子代理与后台命令，插件自己的任务进不去。写手与记账任务怎么登记、怎么等，要么给任务中心加口子，要么用 `agent.startTask` 起后台会话，定参数时一起定。
- **不另起“写作助手”Profile。** 草稿打算由插件贡献一个。现在内置的“主创”就是通用写作助手，设定的四个工具对所有会话生效。
- **工具数从 12 变成 15。** 独立设计把剧情侧的读取并进 `read` 的地址。本稿把它们拆成 3 个工具，另把“还有什么没处理”与“记剧情”各立一个（见“请开发者定”第 2 条）。

## 请开发者定

开发者 2026-11-23：第 1 条“同意”，“其他的都同意”。每条第一句就是定下的做法。第 1、5 条里写手与记账的部分随上面“先不考虑”一起搁着。

1. **分工：主 Agent 带工具对话；写手、检查、记账是程序跑的后台任务，不带工具。** 剧情侧提案里有这句话，但流程草稿的六条你还没看过。写手现在也可以改成子代理（底座有了 `agent_spawn`）。推荐不改：写一章不需要来回调工具，程序备好上下文一次生成，重写只是重跑这一步；记账的实验里，带工具的做法在第一次写入前调了 20 次工具，19 次是在读程序本来就能备好的东西。
2. **剧情侧的读取由剧情插件自己出 3 个工具（`plot_chapter`、`plot_knowledge`、`plot_ledger`），不并进 `canon_read`。** 这偏离了剧情侧提案的字面，提案写的是“先并进 `read` 的地址，模型找不到再拆”。理由：`canon_read` 是“读一个条目”，再塞进按章、按账本的读法，每个参数都要注明用于哪种读法；剧情的语义也该留在剧情插件里（ADR 0041），不让设定的工具认识伏笔账本。代价是工具表多 3 项。改回的代价：给 `canon_read` 加一个让别的插件登记读法的口子。
3. **检索第一版做专用工具，在内存里的世界上按关键词找，不建索引、不做向量检索。** 范围是条目的名字、简介、主文字、文字字段，与剧情变更的描述、正文原句；可以按章、按条目筛。正文、细纲、手记是文件，用底座的 `grep`。三百万字的书上要多久没量过，做之前先量。你 11-02 问过“把条目渲染成只读文件，让 Agent 用 grep 和 glob 读”，那个实验一直没做。推荐不做文件视图：一份文件只能是一个位置上的样子，而设定随章变，问“第 5 章时她知道什么”还是要回到工具；底座的 `grep` 也搜不了虚拟目录，得把渲染结果另存成真实文件、每次改动后重写。你想先看数据的话，可以在第 2 档里两种各做一份、用真实模型比一次，代价是多做一份导出。
4. **写世界的审批：`ask` 模式照旧每次问；`auto` 模式直接放行。** “写世界”指 `canon_write` 与 `canon_record` 的调用。现在 `auto` 下每次都要另问一次审批模型，因为这两个工具没有文件路径、套不上“写在作品里就放行”的规则。放行的理由：每次写入都是一条可还原的修订，作者在条目页看得到 Agent 的提示、能撤销。后台任务由程序发布，不是工具调用，不经审批。
5. **写手第一版只做“按细纲写”，自由发挥排到第 5 档。** 按细纲写：先有本章的细纲与计划，写手拿程序拼的上下文一次生成，没有工具。自由发挥：只有粗纲，写手可以自己查设定、新编内容，写完交一份自陈，记账时把新编的标成“推断，等作者确认”。后者多一套按视角过滤的只读工具，也更依赖检查与记账。
6. **先后按第 5 节的五档，下一步做第 1 档。** 第 1 档不加工具，做的是让现有四个工具真的用得起来，连同界面的可用性。

## 这张图不定的

Agent 这条线恢复时在本 Task 里接着定：

- 每个工具的参数、条数与字数上限、续读的游标、失败时的回话；工具的名字；
- 细纲与写作指示存在哪（两份 Spec 都写着“随写作流程另行定义”，归 t19）；
- 写手与记账任务怎么登记、怎么等待与取消；
- 自动预查与用法提醒的做法；
- `auto` 放行写世界的规则怎么写。
