# 三层对齐与一致性检查

## 目标与范围

定三层（正文、设定、计划）怎么对齐、报出哪些差异、什么时候跑、报给谁。这是合并成一套模型的主要收益，要先说清值不值。

合同：讨论 Task，只定设计，行为合同未变；定稿后的 Spec 改动在实施时另定。

前置：t02 到 t07。

## 要讨论的问题

1. 差异的种类：设定有正文无（待写、伏笔未埋）；正文与设定矛盾（吃书）；计划未兑现；提前泄底；正文出现设定里没有的对象（要不要补进设定）。
2. 什么时候跑：每章写完、抽取完、手动、写手 Agent 交稿前。
3. 报给谁、怎么呈现：问题面板、章节旁的标记、给 Agent 的提醒；误报怎么消（标“有意为之”）。
4. 抽取本身有错（V9 实测秘密、状态、疑问三类最不稳）：误报率高时这个功能还有没有用，最低要多准。
5. 矛盾的处理方向：改正文、改设定，还是记成有意的反转。

材料：[V9 试做结果](../../../../../docs/proposals/novel-memory-v9.md)。
