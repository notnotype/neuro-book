# 写作流程与内置 Profile

## 目标与范围

定从故事种子到一章写完的流程里，每一步由谁做、做到什么程度，以及由此得出的内置 Profile 与 Skill（原 t23）：开局（种子 → 建条目、前史、未决问题，回执）、细纲讨论与计划、写正文、记账、改设定以后协助改正文、写手。

合同：讨论 Task，只定设计，行为合同未变；定稿后的 Spec 改动在实施时另定。

前置：t02（已完成）。不再依赖 t06。

## 重切后要定的（2026-11-02）

1. 开局：没有挡住开局的问题就直接建；Agent 可以建结构（比如面板的字段），但不替作者填数，没定的列成未决问题（11-02 定，缺口 6）。
2. 记账：一条情节多大（粒度规则）；正文重述设定时把句子链到字段上（11-02 定）；正文里可能是未决问题的答案时附上提示，不替作者关掉问题（缺口 2）；细纲里讲到的过去的事记成前史，出处写细纲（缺口 5）；语义档字段只记一句“发生了什么”。
3. 改设定以后：链到字段的句子直接给建议，其余（换了说法的、还没记账的章、细纲、别的条目）由 Agent 自己找、自己判断（11-02 定）。
4. 细纲讨论：从细纲提出计划；计划与正文数额不符以正文为准，差额写进回执。
5. 写手拿什么（接 t20）；Profile 与 Skill 的清单（原 t23 的问题照旧）。

### 写作流程

1. 环节：构思与设定 → 大纲与剧情线 → 场景分章 → 章级 brief → 写正文 → 抽取 → 对齐与修订。旧版“设计、确认、写 World、更新 Plot、写作”四阶段（`assets/reference/world-engine/workflow.md`）哪些留。
2. 作者不按流程走时（直接写正文、事后补设定）各功能是否还能用；最小可用路径是什么。
3. 正文写完后，状态变动、知情这些作者层记录由谁维护：作者手填、Agent 从正文提议、直接用抽取结果。
4. 人在环节之间的确认点：哪些写入要审批（接 w00032 t06 默认写入要审批）。

2. 旧版 leader、writer 两个 Profile 与其记忆文件的去留。
3. Skill：nb-story 的 Skill 已有；设定、剧情工坊要不要 Skill；第一版 Skill 只由用户 `$` 触发（w00032 t15）。
4. 提示词按 `docs/standards/prompts.md`（w00032 t18 定）写；评测接 t26。
