# 写作流程：Agent 在产品里怎么用起来（草稿，待开发者确认）

2026-11-02 主会话起草。依据：已接受的[内核提案](../../../../../docs/proposals/world-engine-kernel.md)第四部分第 8、9 节；[ADR 0037](../../../../../docs/adr/0037-world-engine-story-change-log.md)、[ADR 0039](../../../../../docs/adr/0039-world-engine-segmented-revision-log.md)；Work README 决定表 11-02 开发者对 Agent 怎么用的意见（记账在后台用工作流跑、不开会话；记账期间先不允许作者改；正文作者、写作 Agent、主 Agent 都可以写；触发方式四种待定）；t02 第二轮夹具里 deepseek-flash 记第 4 章的工具调用（[`design-review-F3-calls.log`](../t02-story-model/evidences/design-review-F3-calls.log)）。

## 一句话

主 Agent 是作者唯一的对话对象。写正文、记账、改设定后找旧写法，是世界引擎插件自己的**后台任务**：程序拼好输入，按固定几步调模型，程序校验后发布，作者看回执。记账在定稿后跑一次；后面的步骤要用到前面的账时，先自动补记。记账期间世界只读，正文照样能改。

## 1. 现在的底座能用什么

子代理按代码与 Task 记录查的，2026-11-02：

| 东西 | 现状 | 对本流程的意思 |
|---|---|---|
| nb-workflow | 库已实现（journal 重放、取消、进度），但没接进新应用；内置的后端不支持进程重启；Agent 只经端口发起“一轮”，工具循环要宿主做。接入它的 w00032 t24 已搁置 | 第一版不依赖它 |
| 主 Agent 派子代理（`agent_spawn` 等） | w00032 t14 定稿，没实现 | 第一版不依赖它 |
| 插件起一个后台会话 | `agent.startTask` 已实现：给 Profile 与输入，建一个（可以是后台的）会话跑到结束，按任务 id 幂等 | 要工具循环的后台活可以用它 |
| Profile | 插件经 `agent.profiles` 贡献，已实现；Profile 只能声明要哪些工具，不能排除别的工具 | 插件贡献“写作助手” |

所以开发者说的“用工作流做，类似 nb-story 的管线”，第一版就照 nb-story 的写法在插件里做：一个任务是程序写的几步，不是会话；以后 w00032 t24 接上 nb-workflow 再搬过去。

## 2. 谁做什么

| 角色 | 形态 | 谁触发 | 读什么 | 写什么 |
|---|---|---|---|---|
| **主 Agent**（“写作助手”） | 会话，作者在右栏和它说话 | 作者 | 六个世界工具、文件工具 | 世界经 `write`（开局、计划、作者让它改的）；细纲、手记、正文文件 |
| **写正文** | 后台任务 | 作者的按钮，或主 Agent 的工具 | 程序拼的写手上下文 | 章节文件的新一版（旧版在 nb-history） |
| **记账** | 后台任务 | 定稿时；依赖兜底（第 4 节） | 程序拼的记账输入 | 一次修订、回执、待处理 |
| **找旧写法** | 后台会话（`agent.startTask`，带检索工具） | 作者改了会在正文里重述的文字字段 | 链到字段的句子，加它自己检索到的 | 正文建议 |

开局留在主 Agent 的会话里：它要先问几个挡住开局的问题，是来回对话，不是固定几步。

主 Agent 也可以自己写正文（开发者 11-02：作者、写作 Agent、主 Agent 都可以写），用文件工具写进章节文件；定稿与记账的规则和别的写法一样。

开发者原话是“主 Agent 派发写作 Agent”。这里把写作 Agent 做成后台任务而不是子代理：派子代理的工具还没有；写一章不需要来回调工具，上下文由程序拼好、一次生成就够；重 roll 只是重跑这一步。作者看到的效果一样。

## 3. 记账做成管线，不做成带工具的 Agent

t02 第二轮夹具里，deepseek-flash 记第 4 章，在第一次写入之前调了 20 次工具：

- 19 次是读程序本来就能备好的东西：条目树、本章正文与细纲、待处理、变更列表（3 次）、本章计划的原记录（3 次）、涉及的 7 个条目的样子（9 次）；
- 1 次 `lookup` 查 4 个不认识的名字；
- 之后 2 次预览、1 次提交。

每次调用都要带上前面全部的上下文再发一遍。改成管线：

1. **备料（程序）**：本章正文；本章计划与写作指示；本章已经记过的变更（含作者记的一笔）；正文里出现的名字与别名按当前位置精确匹配（同提案的自动预查），匹配到的条目在本章开头的渲染与它们最近的变更；各 Component 的记账说明。总量有上限，与书长无关。
2. **起草（一次调用）**：输出一份修订草稿（结构化）：新条目、剧情变更（补丁、讲述、兑现）、核对点、与设定冲突、没把握、没建条目的名字。草稿里可以先列“还要查的”（不认识的名字、“这件事以前记过吗”），程序检索后把结果补进输入，再起草一次。
3. **校验（程序）**：提案第 5 节的发布前校验，再预览一次：核对点对不对得上、补丁算不算得下去、引用的条目与计划在不在。
4. **修复（一次调用，最多一次）**：把校验结果交回模型改；还不过的进待处理。
5. **发布（程序）**：一次修订，算好“带来的变化”，出回执。

一章大约 2 到 4 次调用，每次带的材料只有一份；带工具的做法是二十几次、每次都把前面的再发一遍。省多少没量。**t26 的第一份基线在同样的 5 章上两种都跑**，比错记、漏记与费用，再定。夹具里的六个工具留给主 Agent 用。

## 4. 什么时候记账

开发者列的四种：

| | 记几次 | 日志里留下什么 | 作者忘了怎么办 | 回到前一版正文 |
|---|---|---|---|---|
| 1. 写完自动记账（阻塞），重写一版再记 | 每版一次 | 每版一次记账，弃掉的版本要撤销 | 不会忘 | 正文回到前一版，账也要换回那一版的 |
| 2. 作者手动 | 一次 | 干净 | 后面的步骤用到旧账 | — |
| 3. 写完自动记账并自动接受，重 roll 再记 | 每版一次 | 一对对“记了又撤” | 不会忘 | 同 1 |
| 4. 主 Agent 等作者满意后记一次 | 一次 | 干净 | 作者自己写的章没人触发 | 正文的版本 nb-history 已存，回去以后再记一次 |

**推荐 4，加依赖兜底：**

- **定稿的信号**：主 Agent 写的章，作者说“就这版”，主 Agent 调“本章写完”；作者自己写的章，点编辑器上的“本章写完”。
- **依赖兜底**：要用到第 N 章状态的步骤开始前（写第 N+1 章、审第 N+1 章的细纲、主 Agent 读第 N 章之后的位置），程序先查第 1 到 N 章是否都记过、记完以后正文的原句有没有被改（判断同 t22）。没记的按章序补记，完成后再继续；作者看到“先补记第 3 章”。这样作者忘了按也不会读到旧账，也不用每次保存都跑。
- **每一版正文“预览记账、不发布”**（方便作者比较两版对世界的影响）留作以后的选项：每次重 roll 多一次记账的费用。
- 定稿以后再改正文的，交 t22（可能过期、重新记账）。

## 5. 记账期间

- **世界只读**（开发者 11-02）：作者在条目页保存、就地改、处理待处理，主 Agent 的 `write`，都拒绝并说明“第 N 章记账中”。读照常，读到的是记账开始时的版本。
- **正文照样能改**，包括正在记的这一章：记账用开始那一刻的正文；记完发现原句被改过，这一章的账按 t22 标“可能过期”。
- **一个作品一次只跑一个写世界的任务**；补记几章时按章序排队。作者可以取消排着的与正在跑的。
- **中断**：一章的记账是一次修订，没发布就等于没记，重跑这一章即可（同 nb-story 只丢没提交的章）。
- **费用**：每次调用的 token 与单价照 nb-story 记一份，回执里写这一章花了多少。

## 6. 写正文

- 程序拼写手上下文：本章细纲、计划与写作指示；涉及条目在本章开头的渲染；最近一两章正文；按需检索的结果。各部分的上限在 t20 定，t26 第三项量它是否与书长无关。
- 按需检索：一个前置调用先列出要查的（“上次兄妹和好是哪章”），程序检索后放进上下文。检索用世界引擎的工具还是渲染出来的文件视图，等 t09 的检索实验。
- 一次生成（长章可以分段），写成章节文件的新一版，在编辑器里打开；重 roll 只重跑生成，作者的新要求记成写作指示。
- 写之前先过依赖兜底：第 N−1 章没记的先补记。

## 7. 主 Agent 写世界要不要逐次审批

现在 Agent 的写入默认每次都问。世界的每次写入都是一次修订、有回执、能还原，提案也定了“记账默认生效”；主 Agent 每建一个条目、记一个计划都弹审批，和这个方向冲突。

**推荐**：世界引擎的 `write` 默认放行，作者在回执与改动记录里看、在那里还原。要等 w00032 t06 的“按工具放行”规则；在那之前按会话的审批模式走（作者可以把写作助手设成放行写入）。后台任务由程序发布，不是 Agent 的工具调用，不经审批。

## 8. 找旧写法

开发者 11-02 定了：链到字段的句子直接是候选，其余（换了说法的、还没记账的章、细纲、别的条目）交给 Agent 自己找、自己判断。

- 作者保存一处会在正文里重述的文字字段（外观、性格这类），回执里写“正在找正文里的旧写法”。
- 用 `agent.startTask` 起一个后台会话，Profile 是“找旧写法”：输入是改前改后的值与链到字段的句子；工具是检索、读正文、读条目、写正文建议。它先判断链到的句子，再自己检索别的写法。
- 结果进“建议”，按上下文分组，作者逐条采用、自己改或不改（提案第 8 节）。

这是唯一需要来回调工具的后台活（要自己找、找到的多少事先不知道），所以用会话而不是管线。

## 9. 重切后要定的几条规则

1. **开局**（11-02 已定）：没有挡住开局的问题就直接建；Agent 可以建结构（面板的字段），不替作者填数，没定的列成未决问题。回执与其它写入同一种。
2. **记账的粒度**：一条剧情变更是一个生效位置上的一件事；改了状态的必须成条；只是说话、心理不成条（“说了这句话”这个行动后文要用时才记）。和 t26 答案的“必记、可记”用同一个口径，答案写完后回头校这一条。正文重述设定的句子链到字段（11-02 定）；正文里可能是未决问题答案的，附提示、不关问题；细纲里讲到的过去的事记成前史、出处写细纲；语义档字段只记一句“发生了什么”。
3. **改设定以后**：见第 8 节。
4. **细纲讨论**：作者让主 Agent 审细纲时，它按吃书、吃设定、严谨三类列问题，指到条目或变更；顺带从细纲提出本章的计划，作为一次修订写进去，作者在计划上直接增删改。计划与正文的数对不上以正文为准，差额写进回执（11-02 定）。
5. **Profile 与 Skill**：插件贡献两个 Profile：“写作助手”（主 Agent，六个世界工具加“写正文”“本章写完”两个工具，加文件工具）和“找旧写法”（只给检索、读、写建议）。写正文与记账的提示词是插件自己的，不是 Profile（同 nb-story）。第一版不做 Skill。w00032 t18 的内置“主创”是通用的，和写作助手各管各的。

## 11. 对其它 Task 的影响

- **t26**：第一份基线在同样的 5 章上跑两种记账（管线、带工具），比错记、漏记、费用与耗时。
- **t20**：主 Agent 的工具加“写正文”“本章写完”；写手上下文与记账备料的上限；检索方式等 t09 的检索实验。
- **t14**：后台任务放在插件的项目进程里，任务队列一个作品一条；以后接 nb-workflow（w00032 t24 搁置中）。
- **t16**：编辑器上的“本章写完”、记账中的只读提示、任务进度与取消、补记的提示。
- **t22**：定稿后再改正文的处理。
- **w00032**：依赖 t06 的“按工具放行”；不依赖 t14 的子代理与 t24 的 nb-workflow 接入。

## 请开发者定

1. **分工**：主 Agent 是作者唯一的对话对象；写正文、记账是插件的后台任务（程序几步、不开会话、不用子代理），找旧写法是插件起的后台会话。推荐是。
2. **记账做成管线**（程序备料、起草、校验、修复、发布），不做成带工具的 Agent；t26 基线两种都跑，用数据确认。推荐是。
3. **触发**：定稿后记一次，加依赖兜底；定稿的信号是作者对主 Agent 说“就这版”，或点“本章写完”。推荐是。
4. **记账期间**：世界只读，正文照样能改，改了按 t22 标“可能过期”；一个作品一次只跑一个写世界的任务。推荐是。
5. **主 Agent 写世界不逐次审批**：每次都是可还原的修订、有回执；要等 w00032 t06 的按工具规则，之前按会话的审批模式。推荐是。
6. **写正文**：程序拼上下文、一次生成，重 roll 只重跑生成；检索方式等检索实验。推荐是。
