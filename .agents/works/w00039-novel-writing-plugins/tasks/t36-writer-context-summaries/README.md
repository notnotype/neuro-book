# 写手上下文：文风、分级摘要与前情

## 目标与范围

写完一章后做三级 L 摘要与两两合并的 S 摘要、滚动摘要；写手上下文按“系统、写作提示词、稳定的设定、前情、这一章”五块拼，文风与稳定的设定来自作品里的文件

合同：要改 [`plot/brief.md`](../../../../../docs/specs/plot/brief.md)（写手上下文的组成与顺序、体积预算），并新写摘要的 Spec（开工时定放在 `docs/specs/plot/` 的哪一份）。

依据（开发者 2026-11-10 在 t16 评审板第 10、11 版定的，原话在 [t16](../t16-plot-workbench-ui/README.md)）：

- **L 摘要**管一章，三级：L1 不超过原文一半，L2 约三分之一，L3 两三百字。探索时的提示词与结果在 `.worktree/w00005-novel-understanding-spike/.agents/works/w00005-novel-understanding-spike/tasks/t01-novel-understanding-spike/evidences`。写完一章后用小模型做；详细的可以转成粗略的（开工前先对比“逐级转”与“各自从正文做”）。
- **S 摘要**管一个范围，按“两两合并”做（`s-scheme=merge`）：每满 10 章用这 10 章的 L2 合成一段（约 400 字），相邻两段同样大小的再合成一段更粗的，字数不变、管的章数翻倍；给写手时用最少的几段盖满“很久以前”，最远的用最大的段；不满 10 章的零头由每章的 L3 顶着。参数可调：原文几章（2）、L1 几章（3）、L2 几章（4）、L3 至少几章（11）、多少章合一段（10）、每段多少字（400）。
- **摘要专注情节，不注重设定**（设定已经有设定库）。S 与 L 的提示词要在实际体验里不断调。
- **滚动摘要**：每章滚一次，每 10 章从 S 摘要与最近几章的 L3 重新写一份（`s-rolling=reset`）。
- **前情**缺省给“前面几章的摘要加上一章最后的原文”，要可配置（`r6-recap`）。
- **文风**分三个部分：文风提示词；参考正文（可选，通常为空）；文风检查提示词（写完以后用它查一次，写手也看得到，“开卷考试”）。
- **写手上下文五块**：系统（NeuroBook 的系统提示词加用户的额外指令）；写作提示词（文风等）；稳定的设定；前情（从远到近：S 摘要、L3、L2、L1、最近两章原文，最后是滚动摘要）；这一章（写作指令、细纲与现有的简报）。前三块跨章能吃到缓存。
- **稳定的设定**先按作品里的一个文件（`s-stable=file`），但开发者认为这一块值得再设计：大多数用户不自己写写手的 Profile（导入社区的或用内置的），要有一种不改 Profile 就能控制写手上下文的办法，例如“写战斗场景时注入某个写作提示词”；旧应用的“Profile 自带表单选项”可能不够。方案在 t16 评审板上讨论，定了再写进本任务。
- 规则：摘要只从正文做，不给摘要的模型看设定里的真相；每份摘要记着是从哪一版正文做的，正文改了标成过期、可以重做；中间插章或调章序让后面的范围摘要全部过期，记为已知的代价。
- 界面：工作单“细纲”一步里“写手还会拿到”的文风、前情两行（t16 第 6 轮图 2）；“再查一项”里自己写的一句存成文件后就是每章都跑的检查（`r6-checks`）。
