## 讨论项

### 1. 时间轴：精确、现在这种，还是两者兼顾

开发者 11-04 问：旧 WorldEngine 用精确时间轴，nb-canon 用的是模糊的，哪个好，有没有两者兼顾的架构。

先更正一个说法：nb-canon 现在的时间轴不是模糊的，而是**只有先后、没有时间**：前史有序号，之后按章序、章内按排序键排成一条全序。它说不出“过了多久”，也不认“同一天下午”。

| | 旧 WorldEngine：精确时间轴 | nb-canon：按章排先后 |
|---|---|---|
| 每件事的时间 | 必须有一个精确到秒的时刻（bigint），配项目日历 | 没有时间，只有先后 |
| 能算的 | 年龄、过了几天、利息 | 只有谁先谁后 |
| 代价 | 作者不知道的时间也得编一个；同一时刻只能有一个切面，写入撞上就报错（示例世界的第一次写入就撞）；Agent 门槛高（旧应用调研的痛点第 6 条） | 平行视角、同章补叙排不对；“十五岁那年”“三百年前”放不进去 |

主会话推荐第三种（推断，要在样本上验证）：**时间是一组约束，精度按事件各自定；程序从约束推出先后与可能的时间范围；什么都没写的，按讲到的先后排（就是现在的行为）。**

- 每件事可以写零到几条时间说法，精度不限：
  - 只有先后：“在大灾难之后”“和 A 同时”；
  - 相对的量：“A 之后两三天”“十五岁那年”（出生之后十五到十六年）；
  - 日历上的日子，可以只到年或月，可以带“约”（“约三百年前”“王历 312 年春”）。
- 程序把这些说法当作区间约束（“B 比 A 晚 2 到 3 天”），推出每件事最早、最晚可能在什么时候，以及谁一定在谁前面。这是成熟的做法：时间约束网络（Simple Temporal Network，Dechter、Meiri、Pearl 1991），一组“两件事相差多少”的不等式，用最短路求可行范围、查出互相矛盾的说法。日期的“约”“不确定”“只知道到年”可以借用 EDTF（ISO 8601-2）的分法。
- 状态折叠仍然要一条全序：时间推得出先后的按时间排；推不出的（区间重叠、没写时间），按讲到的先后排，和现在一样。所以不写时间的书，行为与现在完全相同。
- 说法互相矛盾时（“十五岁那年”早于出生），进待处理“时间对不上”。
- 模型只写说法，不写算出来的时间：nb-story 的评测里，让模型累加天数会错，一处错让后面全错一天（[nb-story 对照](../../research/2026-11-04-nb-story-vs-canon.md)第 5 节）。
- 日历：作品可以有一个日历，用来输入与显示（公历、“第 N 天”、自定义纪年）；里面统一换算成天数加精度。
- 世界线是另一个维度，和精度无关：每件事在一条线上，线从另一条线的某个时间分出来，折叠沿着线走。

要改到内核的地方（推断）：安放加上时间说法与所属的线；排序从“章序加排序键”改成“约束推出的先后，推不出时按讲述”；读取位置“第 N 章末尾”要定义成“第 N 章写到的故事时间”（补叙的章不往回拨）；改了时间说法以后，先后可能变，增量计算要从最早受影响的位置重算。

待开发者定：用这种兼顾的做法，还是另有想法。
