## 讨论项

### 1. 时间轴：第一版方案

开发者 11-04 问精确时间轴（旧 WorldEngine）、现在这种（nb-canon 只排先后）还是两者兼顾；主会话推荐兼顾的做法（时间是一组约束，精度按事各自定），开发者同意，并要求：时间要能查（记账时 Agent 能在很长的时间轴里缩小范围）；支持自定义历法（例如一天 48 小时、月份有特殊叫法）；问是否采用 EDTF 与 STN。

方案由主会话写、一个只拿到目标的 Sonnet 子代理独立另出一版（[`evidences/time-independent-design.md`](evidences/time-independent-design.md)），两版在主要取舍上一致；下面采用了独立设计里的三处（安放不进网络、分叉是一种剧情变更并带“带过去的地址”、范围带依据）与按历法层级分桶浏览。原型与例子的输出在 [`evidences/time-examples.txt`](evidences/time-examples.txt)，代码在 `prototype/time/`。

**原则**

- 时间是一条条“说法”，精度各自定；程序从说法推出每件事最早、最晚可能的时间、谁一定在谁前面、哪几条说法打架。
- **时间不决定状态按什么顺序算**：状态仍按安放（前史的序号、章序、章内排序键）折叠。大量事件没写时间、补叙与回溯会让按时间折叠的加减断掉（旧 WorldEngine 的痛点），两版设计都这样定。
- 安放的先后不放进时间网络：一处安放错了，不会让整张网矛盾、什么都查不了。安放与时间对不上（按安放 A 在 B 前，时间上 B 一定更早）单独报出来，提示挪安放、标平行或改前史的序号。
- 不写时间的书，行为和现在完全一样。

**记什么**

- 剧情变更上可选的时间说法（可以几条，同时成立），每条带原话与依据（正文写明、作者定的、推断）：
  - 日历上的日子，精度到年、月、日、时段或时（“王历 590 年”“霜月 3 日午后”）；
  - 在另一件事之后或之前，带间隔的范围（“三天后”“觉醒后不久”）；
  - 持续多久（有起止的事，“离家那几年”）；
  - 某人几岁那年（相对出生）。
- 出生、建国这类“锚”就是前史里的剧情变更（补丁可以为空），不加新的对象；年龄是查出来的，不存字段。
- 模糊词表是作品级的设置：“几年”“几天”“不久”换成范围，所有 Agent 用同一份，不各自估。
- 章可以标“与第 M 章同时”（平行视角）。
- 前史的序号：写入时按时间在前后邻居之间取一个数；之后改了时间不自动重排，由检查报出来。

**历法**

- 在作品设置里用数据定义：一天几小时、一小时几分、各月的名字与天数（个数不限）、闰年规则、纪年名、一天里的时段名。缺省是“相对公历”：开篇那天是第 1 天，之前显示成“开篇前 N 年”。
- **存的是作者说的话，不存换算结果**：历法定义与每条说法都按历法上的写法存（王历 590 年、霜月 3 日午后、三天、“几年”这个词），绝对时间只在内存里算。所以改了历法，所有说法自动按新历法理解（“霜月 3 日”还是霜月 3 日，“三天后”是新历法的三天），不用重新换算；改了模糊词表也一样。新历法里不成立的说法（删掉的月、超出月长的日子）报诊断，列给作者改。
- **内存里的绝对时间**是从历元起的整数分钟，用 JS 的数（不是 bigint）：
  - 旧 WorldEngine 用 bigint 秒，是因为它把绝对时刻当唯一真相源存进数据库（持久化成字符串），理由写在旧应用的 `assets/reference/world-engine/calendar-system.md`：覆盖“量劫级跨度（约 2920 亿年）”。这里绝对时间不落盘，这条理由只剩“范围够不够”；
  - JS 的数能精确表示到 2^53，按分钟约 171 亿年（一天 24 小时）或约 85 亿年（一天 48 小时）；更长跨度的世界可以把历法的最小单位设成时或天（按天约 24 万亿年）；
  - 时间网络要“没有上界”与快速加减：数有 `Infinity`、能放进类型化数组；bigint 都没有，也不能直接写进 JSON。
- 自己写，不用库：独立设计查过，Temporal 的两个 polyfill 与 `@internationalized/date` 只有内置历法，`edtf` 只管公历，`chrono-node` 不认自定义历法，都表达不了一天 48 小时与自定义月份。

**EDTF 与 STN**

- **STN（时间约束网络，Dechter、Meiri、Pearl 1991）采用**，作为计算模型：每条说法是“两件事相差 lo 到 hi”，最短路给出每件事最早、最晚的时间，负环就是矛盾，环上的说法就是打架的那几条。算法很小（原型里一百来行），自己写。
- **EDTF（ISO 8601-2）只借概念**：精度（只知道到年、到月）、约、不确定、开放的区间。不用它的字符串格式，因为它只管公历。

**怎么算与查**

- 范围带依据：最早、最晚各是哪几条说法定的（“她出生在开篇前 19 到 20 年：由‘她今年十九’和‘开篇那天早上’定”）。
- 推不出的一端，用安放上最近的、写了时间的邻居补上，只用于查询，并标出来。
- 查询：某件事、某章的时间范围与依据；某段时间里可能、一定发生的事（可按条目筛）；两件事相差多久；某人在某事时几岁；某章写到的故事时间；按历法层级分桶浏览（纪、年、月、日，逐级往下看）。
- 记账时缩小范围：正文写“王历 590 年前后”，按这几年查，428 件事里剩 5 件候选。
- 规模（原型）：1 万件事、1.15 万条说法时一致性检查 5 ms、全部范围 7 ms、按时间查 4 ms；5 万件时 26、48、14 ms。

**世界线**

- 分叉是一种剧情变更：父线、切口（父线上哪件事之后，按安放）、触发分叉的事、往回多久（回溯）、种类（回溯、分支、梦境、IF）、带过去的地址（例如她的记忆）。
- 某条线某个位置的状态 = 父线到切口为止的变更 + 带过去的地址取父线在触发处的值 + 本线到这个位置的变更。仍按安放折叠，增量引擎在切口处取父线的快照。
- 读取位置带线；回溯之后，后面各章缺省读新线。
- 时间网络里，新线上的事不早于“触发处往回多久”的那一刻；不同线上的事不比先后。
- 谁带着记忆过线、别人的知情回到哪里，留到知情的讨论项。

**对内核的改动（推断，写提案时细化）**

- 剧情变更加可选的时间说法；分叉作为一种剧情变更；安放与读取位置加线；按线折叠（增量引擎按线分快照）。
- 新的诊断：时间说法打架、安放与时间对不上、分叉的时间与切口对不上。
- 历法、说法、网络与查询放进一个新的无依赖包（独立设计建议叫 `nb-time`），nb-canon 与 nb-story 共用；nb-story 的 `day`、`part`、`rel` 能映射成相对历法上的说法。

**原型验证了什么**（[`evidences/time-examples.txt`](evidences/time-examples.txt)）

| 例子 | 结果 |
|---|---|
| 星瑕只有粗略的说法（六岁那年、十五岁那年、离家那几年、刚回家） | 第 1 章 17 到 28 岁；补一句“她今年十九”后收窄到 19 岁，“那几年”收窄成 2 到 5 年，并说出是哪两条说法定的 |
| 再写一句“大灾难那年第一次变身” | 报出打架的三条：六岁那年、十五岁那年、大灾难那年 |
| 艾尔达王国（示意）：一天 48 小时，十个月各有名字 | 王国历史按纪年显示，“约三百年前写成”的书落在王历 291 到 332 年，写成时建国 289 到 331 年；“三天后”按 48 小时一天算 |
| 记账时缩小范围 | 428 件事里按“王历 590 年前后”查到 5 件 |
| 第 5、6 章写同一天的两个人 | 不标平行时报“安放与时间对不上”；标成平行后不报 |
| 第 8 章回溯约 6 小时 | 新线上存款回到 20,000、回溯次数 0、记忆带过来；原来那条线存款 15,000；不分线时报“安放与时间对不上” |

原型从简的地方：一次只分一层线；历法的年、月按最短与最长的长度换成分钟，所以“十五年”是一个小范围（产品里按历法逐年算）；模糊词只有三个。

**第一版不做**

- 按故事时间读状态（“王历 612 年霜月 5 日那天她有多少钱”）：要相关地址的先后都确定才答得出，第二版再看。
- 中文时间说法的自动解析：记账 Agent 写成结构、附原话，不做解析器。
- 跨线的知情与记忆：在知情的讨论项里定。

**待开发者定**

开发者 11-04 定：几套历法并存放第二版；历法、说法与网络单独成一个包（暂名 `nb-time`），nb-canon 与 nb-story 共用。原来的第三问“改了历法以后要不要重新换算”撤回：说法按历法上的写法存，改历法不需要换算（见上面“历法”）。

### 2. 知情：第一版方案

开发者 11-04 同意开始讨论，看过下面的草稿后四条都同意，要求用例子在内核上跑一遍。主会话先写了一版草稿，一个只拿到目标的 Sonnet 子代理独立另出一版（[`evidences/knowledge-independent-design.md`](evidences/knowledge-independent-design.md)）。两版的主干一致（要紧的事做成条目、用 Component 与补丁表达、不加新的存储对象、揭示计划就是计划、穿帮靠程序圈候选再问窄问题）；三处采用了独立设计的：知情记在人物身上、读者由讲述上的“揭示”标记算、加一档“绝密”。下面是合并后的草稿。

**要解决的**：谁知道什么、什么时候、怎么知道的；全知问题（卫兵认出勇者是泄露，铁匠与药师认不认识草药是按常理推）；读者知道什么；回溯以后谁还记得。规则沿用 [剧情分析第十三节](../../research/2026-11-04-plot-capabilities.md)：**没记的可以推，推出来的标出来；重要的标保密，保密的不许推。**

**知道的东西：知识点**

- 要紧的事做成条目（种类“知识点”），挂在它说的那个条目下面；命题写在一句话描述里（“勇者的额头有星印”“月见草能止血”“管家是凶手”）。只有建成知识点的才有知情，其余靠常理。
- 知识点上的 Component 写它的保密程度与一句话规则：
  - 常识：人人都知道；
  - 行内：按规则推（“药师、草药商认识，普通人不认识”），给写手当常理；
  - 保密：没记下来的人一律当作不知道，写手不许推；
  - 绝密：给写手只说“有一件涉及某某的保密设定”，不给内容，免得写进文字里露出来。
- 设了马甲（`sameAs`）时，提示作者建一个“甲就是乙”的知识点，本人那一行由程序补上。

**知道的人：记在人物（或组织）身上**

- 人物上的“知情”Component 是一个列表，每行：哪个知识点、程度（知道、误信、怀疑、不知道、忘了）、误信时他自己以为的那句（“以为是园丁”）、怎么知道（亲历、听说、推断、读到、传闻）、谁告诉的。
- 记在人物身上而不是知识点上：写一场戏要的是“在场每个人知道什么”，读这几个人物就够了；回溯时分叉只要带过去“星瑕的知情”这一个地址，别人的知情自然回到切口；组织也是条目，同样能记。代价是“谁知道这个秘密”要反查，知识点只建要紧的，量小。
- 谁在哪章知道了，是一条剧情变更给他加一行（或改程度）；随章节、随世界线变，都沿用现有的折叠、来历、撤销。传话的“谁告诉的”在那个位置上必须已经知道，不然报“传话链断了”。
- 精度三档：精确是行；粗略是知识点的规则；没记就让写手推，推出来的由记账写成依据为“推断”的行，作者确认后改成作者定的。

**读者**

- 读者不是条目，不记行。读者知道什么，由正文讲述上的“揭示”标记算：某一处讲述标了揭示哪个知识点、到什么程度（明说，或只是暗示），读者从那一章起知道（暗示算怀疑）。
- 读者的钟是章序，角色的钟是故事里的位置与世界线，两个钟分开算。nb-story 把两者放进同一张表，“读者知道被当成角色知道”成了知情题最大的错因。
- 不从“角色在讲出来的场景里知道了”自动推读者：场景讲出来了，读者不一定知道（“他凑到她耳边说了几句”）。

**揭示计划与提前泄底**：揭示计划是一条计划，细纲里那处讲述带揭示标记；已写的章里读者更早知道了（或程度更强），报“提前泄底”，作者可以改计划接受（“故意让人猜”）。

**拿它做的事**

1. 写手的上下文按场景给：在场每个人对本章涉及的保密以上知识点知道、误信、不知道什么；行内的附规则。示意：“卫兵：不知道勇者额头有星印（只有国王、贤者知道），不得写成被认出”。
2. 写完查穿帮：本章涉及的保密知识点 × 在场且没有行的人，逐对问记账 Agent 窄问题（“卫兵有没有按这件事说话，引原句”），有的进待处理，不自动改。nb-story 的经验：知情抽取最不稳，程序圈候选再问窄问题有效。
3. 新的待处理：可能穿帮、提前泄底、传话链断了、正文里有人知道却没有记录。

**内核要补的（推断）**：字段里引用别的条目（现在只有数、文字、枚举、是否、列表、图片，“哪个知识点”“谁告诉的”只能存成文字，改名、删除跟不上，还原时的依赖也查不到）；按引用反查；讲述上的“揭示”标记。

**第一版不做**：角色按自己的目标行动（模拟）；角色背景另建字段（职业、出身已在人物的主文字里，独立设计指出另建会重复）。

**两处没把握**（独立设计提出）：简报里“相关的知识点”按本章涉及的条目圈，会漏间接相关的；穿帮窄问题的准确率要用真实模型测。

**开发者 11-04 定**：知情只管建成知识点的事，其余靠常理；知识点是条目、知情记在人物身上，用 Component 与补丁表达；读者由讲述上的揭示标记算，不从角色的知情推；保密分常识、行内、保密、绝密四档。

**在内核上跑的结果**（[`evidences/knowledge-kernel-run.txt`](evidences/knowledge-kernel-run.txt)，代码 `prototype/knowledge/run.ts`，直接用分支上的 nb-canon）：

| 例子 | 结果 |
|---|---|
| 卫兵与勇者 | 第 4 章简报写出“勇者的额头有星印（只有国王与贤者知道）：卫兵不知道，不得写成知道”；写完后的窄问题两条（卫兵、勇者各一条） |
| 铁匠、药师与草药 | 简报给出行内规则“药师、草药商认识，普通人不认识”，不列谁知道 |
| 星瑾的误信 | 第 1 章她“误信（以为哥哥不想回家）”；第 6 章听女仆说以后变成“怀疑”（给元素的子字段赋值，现有补丁就能做）；查出传话链断了：女仆自己并不知道 |
| 命案 | 读者第 12 章起“怀疑”，侦探第 18 章“知道”；绝密的简报不给内容，女仆误信的那句照给；查出提前泄底：计划第 20 章揭示，读者第 18 章已经怀疑 |
| 反讽 | 第 4 章读者知道星印，同场过的勇者、卫兵都不知道 |

原型从简：简报里“相关的知识点”按本章涉及与在场的条目圈；回溯后谁记得没在内核上跑（内核还没有世界线，时间原型里已经跑过“带过去的地址”）。

**现有内核已经能做的**：知识点条目与人物上的知情列表按章折叠；元素 id 用知识点的条目 id，同一个人对同一个知识点再加一行会被拒（套不上），一人一点一行不用另加约束；同一次写入里的临时 id 在元素 id 里也会换成真实 id；改程度是给元素的子字段赋值。

**内核要补的（实测确认）**：

1. **引用**：知情行的元素 id（哪个知识点）、“谁告诉的”、讲述上揭示标记里的知识点，内核都不当作引用。实测还原“建知识点”那次修订时没有列出依赖，直接成功，留下一行指向被撤掉的知识点。要让这几处算作条目引用：写入时校验存在、改名与删除跟得上、还原时查得到依赖。做法在提案里定（字段种类加“条目引用”，或者列表声明“元素 id 是条目引用”）。
2. **揭示标记**：讲述的 schema 不限多出来的键，`reveals` 写进去会原样存下，但不校验（指向不存在的条目也写入成功）。要正式加进讲述的形状，并校验。
3. **算出来的视图**：读者的知情、简报、穿帮候选、传话链、提前泄底、反讽，原型都是在内核外面算的；产品里放进 nb-canon（和待处理一样是读取时算出的），新的待处理种类见上。
4. **世界线**：回溯带过去“星瑕的知情”依赖时间方案里的分叉。


### 3. 伏笔：第一版方案

开发者 11-04 定先讨论伏笔，看过下面的草稿后四条都同意，要求用例子在内核上跑一遍。主会话先写了一版，一个只拿到目标的 Sonnet 子代理独立另出一版（[`evidences/foreshadow-independent-design.md`](evidences/foreshadow-independent-design.md)）。主干一致：伏笔是条目加 Component；节点按读者读到的章算，不按情节的安放；状态由节点算出；悬念连知识点时揭示不重复记。采用了独立设计的种类与节点角色、两级检查、“像伏笔的句子不自动猜”、写手简报里回收前不给真相；节点标记放在哪一处和它不同（见下）。

**伏笔是什么**：对读者的承诺。正文里放下一样东西（一件物品、一个疑问、一句预言、一个反复出现的意象），读者会记住、会等它再出现或得到回答。作者要一本账：欠读者什么、埋在哪、多久没提、打算在哪回收；写手要知道这一章埋什么、提什么、什么还不能碰。

**怎么记**

- 伏笔是条目（种类“伏笔”）：名字与一句话写“许了什么”（写手看得到的那一面）；主文字写打算怎么回收（真相，回收那一章才给写手）。Component 上：种类、重要程度（主要、一般、次要）、作者的意图（进行或放弃，放弃写原因）、悬念的答案（连到一个知识点）、参考间隔（可选，至少每隔几章提一次）。
- 种类四种：埋设回收（先埋后收，例如彗的魔偶）、悬念（读者心里的疑问，可以连答案知识点）、预言（兑现方式写进回收打算）、意象（反复出现，不要求回收；镜像呼应并进这一类）。
- **节点是讲述上的标记**：正文某处讲述标“这里对哪个伏笔做了什么”，五种：埋下、呼应、误导、部分回收、回收，可以带一句给写手的指示。位置就是那处讲述所在的章，按读者的章序算，和读者的知情一样。只是提了一句、世界没变的，记成一条没有补丁的剧情变更带这处讲述。
  - 独立设计把节点做成剧情变更上的一种连接，位置取这条变更第一处正文讲述的章。主会话改放在讲述上：一件事可以在几处讲到（回忆里再讲一次算呼应），标在具体那一处更准；揭示标记也在讲述上，两种读者看到的东西用同一个地方。
  - 不用补丁记节点（两版一致）：伏笔是写法，不是故事里的状态；补丁套不上会让整条剧情变更不算数，伏笔条目删了会连累真实事件。
- **计划**：细纲那处讲述带节点标记，就是打算在那一章埋或收。兑现这条计划的已写变更，第一处正文讲述默认继承计划上的节点标记（自己标了的除外），作者或 Agent 只说“兑现了这条计划”就够。
- **悬念连着答案知识点时不重复记**：读者对答案的揭示自动算节点，暗示算呼应、明说算回收。所以“提前泄底”改成：明说早于计划的回收才报；有悬念认领的暗示是有意的，不报；没有悬念认领的暗示只给提示。（这改了第 2 项知情原型里的一条结果：袖扣那句暗示不再报泄底。）
- **状态由节点算出、不另存**：未埋、已埋、呼应中、部分回收、已回收；放弃的显示“放弃（已埋）”。按实际模式与按计划模式都能算。

**检查分两级**

- 进待处理（要作者拍板）：没埋就回收；计划的节点那一章写完了却没有；回收以后又埋；明说早于计划的回收（泄底）。
- 只在账本里提示：已埋但没排回收（意象除外）；设了参考间隔却太久没提；放弃了但正文还留着埋下的句子（列出原句）；没有悬念认领的暗示。
- 正文里“像在埋伏笔”的句子不自动猜（nb-story 的经验：自动找错准确率只有 5% 到 27%）。只问两种窄问题：这一章计划里有节点的，“引出做到它的原句，或者答没写”；有进行中的伏笔的名字或别名出现在这一章的，“是不是呼应，引原句”。新伏笔由作者与细纲提出。

**给写手的上下文**：这一章要埋、要呼应、要回收的（回收时才给真相与回收打算）；已埋、回收在后面或还没排的，只给“许了什么”，写明不要回收、不要点破；答案知识点是保密或绝密的，照知情的规则不给内容；意象给出上次出现的章。

**内核要补的（推断，验证时确认）**：讲述上的标记（揭示与节点一起）；条目引用（答案知识点，与知情共用）；读者位置（章序加排序键）的计算，伏笔、知情与 nb-story 共用；新的待处理种类与简报段由插件登记。

**两处没把握**（独立设计提出）：同一章里先埋后收只能按排序键比，可能漏报；两个悬念的答案连到同一个知识点时会同时认领同一处揭示，先提示，看真实写作再定。

**开发者 11-04 定**：伏笔是条目加 Component，节点标在讲述上、按读者读到的章算；种类四种、节点五种；悬念连答案知识点，揭示自动算节点，有悬念认领的暗示不算泄底；检查分两级，“像伏笔的句子”不自动猜。

**在内核上跑的结果**（[`evidences/foreshadow-kernel-run.txt`](evidences/foreshadow-kernel-run.txt)，代码 `prototype/foreshadow/run.ts`）：

| 例子 | 结果 |
|---|---|
| 彗的魔偶（埋设回收） | 那条情节安放在前史（当年的事），第 1 章回忆里讲到：节点按讲述算在第 1 章，不是前史。第 15 章的简报给出回收打算与指示“魔偶自己动起来，不要写成她召唤的”；第 15 章写出来、兑现了计划，没标节点也继承成“回收”；另一种走向（第 15 章那条撤销）读到第 16 章报“计划的节点没写出来” |
| 命案（悬念，答案是绝密知识点） | 第 12 章袖扣的暗示由悬念认领成“呼应”，不报泄底；第 14 章靴印是“误导”；第 16 章有人把凶手说破，报“泄底：计划第 20 章回收，第 16 章已经明说”；简报里只说答案是绝密，不给内容 |
| 开篇的预言 | 没排回收时提示“已埋没排回收”；改成放弃以后显示“放弃（已埋）”，并列出第 1 章还留着的原句 |
| 银白长发（意象，参考间隔 3 章） | 第 9 章出现“银白长发”但没标节点，窄问题问“是不是呼应”；读到第 14 章提示“上次在第 1 章，已经 13 章” |
| 王都的暗道 | 第 5 章回收、之前没埋，报“没埋就回收” |

**现有内核已经能做的**：伏笔条目与 Component；讲述上的标记原样存下；计划的兑现与进展（`fulfills`、`progress`）直接用来判“计划的节点没写出来”；放弃是改伏笔条目的初值。

**内核要补的（实测确认，与知情合并）**：

1. **引用**：讲述上的节点与揭示标记、伏笔的“答案”字段都不当作引用。实测还原“建伏笔”那次修订时没有列出依赖，留下一个指向被撤掉的伏笔的节点；“答案”写在文字字段里，同一次写入里的临时 id 也不会换成真实 id（列表元素的 id 会换，文字字段不换）。
2. **讲述上的标记**：节点（伏笔、角色、给写手的指示）与揭示（知识点、明说或暗示）一起正式加进讲述的形状，并校验。
3. **读者章序上的计算**：节点的位置、兑现计划时继承节点、悬念从揭示认领节点、阶段与两级检查、窄问题与简报，原型在内核外算；产品里放进 nb-canon 或剧情插件，与知情的读者计算共用。

原型从简：同一章里的先后只按章比；阶段只按最强的节点算；没有做“回收以后又埋”的例子（检查写了，样本里没有这种情况）。


### 4. 角色的目标：第一版方案

开发者 11-04 定先讨论角色的目标。主会话先写了一版，一个 Sonnet 子代理另出一版（[`evidences/goals-independent-design.md`](evidences/goals-independent-design.md)；它读 README 时看到了主会话的草稿，写明没有照它）。主干一致：长期目标是条目、按故事时间算、隐秘的目标挂知识点、弧光就是计划。采用了它的：目标上的冲突行与“后继”、态度改成按对象的列表、三级检查。

**只结构化长期目标**：人物主文字本来就能写目标；结构只在三件事上值得：目标随章节变（主文字答不了“第 12 章她在追什么”）、和知情挂钩（信念变了要提醒）、跨角色查冲突。场景里的小目标、策略、动机的推演不进结构，由细纲、计划与写手处理。只给主要角色建，每人三五条。“角色按自己的目标自主行动”属于模拟，不做。

**目标**

- 目标是条目（种类“目标”），挂在持有者（人物或组织）下面；名字写“他想要什么”。
- 目标上的字段：状态（进行、受挫、达成、放弃）、轻重（主要、次要）、层次（想要或需要，可选）、为什么（动机，一段文字）、基于（连到知识点：这个目标成立依赖他对这件事的看法）、冲突（一行一个对方目标，写怎么冲突）、后继（目标变了时，旧的置放弃、指向新的）。
- 状态的变化都是剧情变更改它，按安放（故事时间）折叠：目标是故事里的事实，写插叙时要的是那一刻的目标。读者知不知道某人的目标，用讲述上的揭示标记，和知情一样。
- 隐秘的目标（反派的政变）就是同一个条目再加知识点的 Component（保密或绝密），谁知道记在知情里；没加的按公开处理，别人看得出来。
- 冲突只记一边，两边都查得到；读取时只显示两边都在进行的。冲突由作者提出，记账建新目标时对照进行中的目标问作者，不自动发现。

**态度**

- 人物上的一个列表，一行一个对象：元素 id 是对象的条目 id，子字段是态度（语义档：记一句发生了什么，由小模型归纳）与起因（连到知识点，可空）。
- 不沿用 t16 原型“每个对象一个实例字段”：那样对象只是字段名里的文字，改名就断，也查不到“谁对星瑕冷淡”。
- 内核现在的语义档只支持条目上的字段，列表元素的子字段还不行（补丁与归纳缓存都按字段记），要放开。

**弧光**：几条计划加一条剧情线。计划改目标的状态或态度，沿用现有的兑现与按计划模式；剧情线的主文字写起点与终点。

**检查**

| 检查 | 级别 | 怎么算 |
|---|---|---|
| 前提变了 | 待处理 | 进行中的目标“基于”的知识点，持有者那一行在目标最近一次被触及之后变了（误信变成知道）。目标被任何已写变更触及就消失，作者答“还成立”也算一次触及 |
| 缺一步 | 只提示 | 按计划模式：计划在某处把目标达成、放弃或改态度，而它的前提在那个位置上持有者仍是误信 |
| 停滞 | 只提示 | 进行中、超过若干章（缺省 10）没被触及；长期搁置常常是有意的 |
| 行为与动机不符 | 不自动查 | 靠写手的上下文预防；作者点了才问窄问题（“某某这一章的做法和他的目标一致吗，引原句”），结果只提示 |

**给写手的上下文**：在场每个人一段：此刻在追的目标与为什么、对在场其他人的态度、他信的事（来自知情）。别人的目标只给本人、知道的人（误信的给他自己的版本）与公开的；绝密的不给内容。示意：“星瑾：想要哥哥先开口认错（进行，主要）；为什么：她以为哥哥这些年不想回家（误信，此刻不要让她知道真相）；对星瑕：冷淡。”

**记账**：它本来就逐章读正文，说明里加一句“在场角色进行中的目标，这一章有没有推进、受挫、达成、放弃，引原句”，不另开模型调用。

**开发者 11-04 定**（“先这样，没问题”）：只结构化长期目标，目标是条目、挂在持有者下面、按故事时间算；态度做成人物上按对象的列表（内核要放开列表元素的语义档子字段）；“前提变了”进待处理，“缺一步”“停滞”只提示，“行为与动机不符”不自动查；弧光是计划加一条剧情线。这一项没有在内核上跑例子。

### 5. 决策与章级写作指示：第一版方案

开发者 11-04 定讨论决策与章级写作指示。主会话先写了一版，一个 Sonnet 子代理另出一版（[`evidences/decisions-independent-design.md`](evidences/decisions-independent-design.md)；它读 README 时扫到了主会话草稿的头三条，稿首写明“决策与未决问题合一”这一条不算独立）。主干一致：决策是未决问题长大，不另建对象；写作指示挂在章上、不进世界；旧版的四项信息控制不再手填；视角人物决定简报与穿帮检查的范围。采用了它的：已定必须有作者原话、可由程序检查的“守卫”、四项检查、写作指示的字段、剧情线的写作指示就是一条决策、穿帮检查分对白与叙述两层。

**决策：未决问题长大成一条完整的生命周期**

- 还是六种对象之一，叫“决策”；状态只由修订改变（它是创作上的事，不随故事时间变）。
- 待定（作者没想好，可带候选、最晚第几章前要定）→ 已定（结论、理由、风险，给写手的刹车点）→ 被取代（指向新的决策）或放弃；作者可以把已定的重新打开。作者直接说出的决定可以一建就是已定。
- **已定必须带作者的原话出处**：Agent 不能自己定；想改作者定了的事，只能新建一条待定的、指向旧的，由作者定。记账不关闭决策，只往“正文里可能的答案”里补。理由没说的不许编，账本提示“没记理由”。这是防旧版“开放决策蒸发”的办法。
- 挂在一个或几个对象上：条目（含剧情线、知识点、伏笔、目标）、剧情变更、地址、章、另一条决策；可以限定章的范围（“第一卷”）。
- **约束**是一句给写手的祈使（“第一卷不得让星瑾知道哥哥是魔法少女”），可选带**守卫**：某个地址在范围内不准取某些值（星瑾对这个知识点的那一行不准是“知道”），由程序检查，不另造条件语言。没有守卫的文字约束，记账时对涉及本章的最多 5 条各问一个窄问题。

**决策的检查**

| 检查 | 级别 | 怎么算 |
|---|---|---|
| 违反已定的约束 | 待处理 | 守卫在范围内每章末尾检查，按计划模式也查计划；文字约束用窄问题 |
| 写死了未定的事 | 地址被补丁定死：待处理；只是写到了相关条目：提示 | 待定决策挂的对象被本章的变更或计划碰到 |
| 到期没定 | 待处理，到期前 3 章提示 | 要写的下一章已到最晚那一章仍待定；写正文的任务先拦一下，作者可以选“照写，保持未定” |
| 悬空 | 待处理 | 挂的对象或范围指向被删的章或条目 |

泄底、穿帮这些诊断附上相关的决策，作者能看到“当初为什么这样定”。

**章级写作指示**

- 按提案，挂在活页夹的章上、和细纲放在一起（章附带文档的头部），不进世界：记账期间世界在写，指示仍要能改；重写时的新要求也往这里记。canon 只接收视角人物与在场的人这两个参数，不认识文件格式。存在哪个文件随细纲在实现时定。
- 字段（都可选）：这一章读完读者该有什么变化、视角人物与视角方式（第一人称、有限、全知；缺省有限）、语气、开场、结尾、不写的、其他（重写要求）。
- 旧版的四项信息控制不再手填：读者已知由揭示标记算，角色已知由知情算，必须隐藏是保密或绝密，可暗示是计划里的暗示揭示。
- 分工：细纲是情节的原文；计划是世界要变成什么样（包括谁知道了什么）；写作指示是怎么写、不写什么。能写成世界状态的进计划，不进指示。本章排了计划而指示说不写，简报里并列报出，由主 Agent 提议挪计划；同一条指示在好几章反复出现，建议升成决策。
- **剧情线的写作指示**（“兄妹心结：克制，不煽情”）不另加字段，就是一条挂在这条线上的已定决策；本章有这条线的计划或变更时进简报，基调换了就新建一条取代它。

**视角人物**

- 有限视角下，叙述只能写视角人物知道的：简报按他的知情展开，其他在场的人只给对白上的限制。
- 穿帮检查分两层：对白层照旧按在场的人查；叙述层只查视角人物对本章保密事项“不知道、误信”的，问“叙述有没有写出她不知道的事”。全知视角不查叙述层。

**写手的上下文**由程序拼：写作指示 + 细纲 + 本章计划 + 知情、伏笔、目标、决策的简报 + 涉及条目的样子。决策一段最多 8 条，有守卫的优先；挂着绝密知识点的只说“有一条涉及保密设定的决定”，作者另写了给写手的版本才给。

**没把握的**：守卫只管地址的取值，“让读者慢慢发现”这类读者层的约束只能靠泄底检查；“相关”按挂的对象与本章涉及的相交来判，会漏间接的；窄问题的准确率要用真实模型测；怎么认定“作者原话”（消息引用的格式）要和 t20 一起定。

**开发者 11-04 定**（“没问题”）：决策是未决问题扩成的完整生命周期，已定必须有作者原话；约束可带由程序检查的守卫，文字约束用窄问题查；写作指示挂在章上、和细纲放在一起、不进世界，四项信息控制不再手填；剧情线上的写作指示是一条挂在线上的已定决策；有限视角下叙述层只按视角人物查穿帮。这一项没有在内核上跑例子。
