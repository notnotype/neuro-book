# nb-canon 角色目标、动机与态度：第一版独立设计

注：t32 README 第 4 项已有一份主会话草稿（目标做条目、态度用语义档实例字段），我没有照它，下面有两处与它不同：态度改成按对象一行的列表（第 2 节）、“前提变了”进待处理（第 5 节）。

## 1. 质疑

- **反对：只写在人物主文字里行不行？** 行，是最小做法。想要与需要（Truby、Weiland 一脉）和 GMC（目标、动机、冲突，Dixon）都只要求作者想清楚，不要求结构化（凭记忆，未查证）；Campfire 一类的角色页大概是文本字段（未查证）。结构只在三件事上赚回成本：目标随章节变（主文字答不了“第 12 章她在追什么”）、和知情挂钩（前提变了要提醒）、跨角色查冲突。所以只结构化长期目标，策略和场景小目标留给文字。
- **成本：** 只给主要角色建，每人三五条。变化靠记账顺带：它本来就逐章读正文，说明里加一句“在场角色的进行中目标，本章有无推进、受挫、达成、放弃，引原句”，不另开模型调用。
- **体验与关系：** 作者要一张“谁想要什么、谁和谁打架”的表；写手要在场每人此刻要什么、信什么、对谁什么态度。隐秘目标就是知情的保密，基于的信念就是误信，弧光就是计划，不另起一套。
- **可观测与维护：** 状态、冲突、前提变了都在读取时算出。字段登记后不能改种类，所以第一版字段要少。

## 2. 推荐设计

### 存哪里：目标是条目，态度是人物上的行

用现有机制表达，内核不为目标单加东西，复用知情和伏笔本来就要补的“条目引用”（Spec 现在没有这种字段种类）。

- **目标 = 条目**（种类“目标”，挂在持有者下面，持有者可以是组织）。名字和一句话描述写“他想要什么”。Component `canon.goal`：状态、轻重、层次（想要或需要）、动机、基于（知识点的引用）、冲突（行）、后继（引用）。
- **隐秘的目标：** 同一个条目再加“知识点”Component（保密或绝密），谁知道记在人物的知情行里。没加的目标按公开处理：别人看得出来。
- **态度 = 人物上的 Component `canon.stance`**，一个列表，每行一个对象，元素 id 是对象的条目 id，子字段有“态度”（语义档）和“起因”（知识点引用，可空）。不沿用 t16 原型 p13 的“每个对象一个实例字段”：那样对象只是字段名里的文字，改名断开，查不到“谁对星瑕冷淡”。要确认列表的子字段能不能声明成语义档（components.md 只写了 `precision` 用于 number 与 text，没写元素子字段）；不能就让内核放开。
- **动机** 是目标上的精确档文字，用 `set` 换，不做语义档，省模型调用。

### 状态与生命周期

状态：进行、受挫、达成、放弃，都是剧情变更对目标的 `set`。

- “还没立下”用 `appears` 或 `启用`（从某章起有这个 Component）。
- “改变”不另设状态：旧目标置放弃，`后继` 指向新目标条目。
- 受挫的原因写在那条剧情变更的描述里。
- 不校验状态转换，作者随时可以改回。

### 按谁的钟算

按故事位置（安放）算，不按读者章序：目标是故事里的事实，写手写插叙、倒叙时要的是那一刻的目标。读者是否知道目标，由讲述上的“揭示”标记决定，与知情共用。

### 基于什么信念

`基于` 引用知识点：目标的成立依赖持有者对它的看法（星瑾对“哥哥被软禁”是误信）。

### 目标之间的冲突

目标上的一行 `冲突`，元素 id 是对方目标的条目 id，子字段“怎么冲突”是文字。只记一边，两边都能查（靠按引用反查）。读取时只显示两边在该位置都是进行中的。持有者可以是同一人（星瑕的三个目标）或不同人（英雄对反派）。冲突由作者提出，记账说明里要求新建目标时对照进行中的目标、问作者。不自动发现。

### 弧光与计划

弧光是几条计划加一条剧情线：计划改目标状态或态度，沿用现有的兑现与计划模式；剧情线的主文字写起点与终点，不加新字段。

### 检查

| 检查 | 级别 | 怎么算 |
|---|---|---|
| 前提变了 | 待处理 | 实际模式下，进行中的目标 `基于` 的知识点，持有者那一行在目标最近一次被触及之后变了（程度或“他以为的”）。目标被任何已写变更触及（包括只有一句备注）就消失，作者答“还成立”也是一次触及 |
| 缺一步 | 只提示 | 按计划模式：计划把某目标放弃或达成，或改某个态度，而它的 `基于` 或 `起因` 在那个位置上持有者仍是误信或不知道 |
| 停滞 | 只提示 | 进行中且超过 N 章没被触及（N 缺省 10，目标上可设），只列在账本里，不进待处理，因为长期搁置常常是有意的 |
| 行为与动机不符 | 不自动做 | 预防靠写手的上下文。只提供作者点了才用的“查某人动机”窄问题（引原句），结果只提示。依据：nb-story 自动找错准确率 5% 到 27%（README 第 3 项） |

### 给写手的上下文

每个在场角色一段，来自读取，不是模型生成的：

> 星瑾：想要哥哥先开口认错（进行，主要）。为什么：她以为哥哥这些年不想回家（误信，真相是被软禁，此刻不要让她知道）。对星瑕：冷淡。冲突：无。
>
> 反派（只有他和心腹知道）：绝密目标，不要写成别人看穿。

别人的目标只给持有者本人、知道的人（含误信的，用他自己的版本）和公开目标；绝密不给内容，只说“有一件涉及某某的保密设定”，规则与知情一致。

### 类型草图

```ts
type GoalState = "进行" | "受挫" | "达成" | "放弃";
interface GoalComponent {            // namespace "goal"，种类为“目标”的条目
  状态: GoalState; 轻重: "主要" | "次要"; 层次?: "想要" | "需要";
  动机: string;                      // 精确档
  基于: EntryRef[];                  // 知识点；要内核补“条目引用”
  冲突: {id: EntryRef /* 对方目标 */; 怎么冲突: string}[];
  后继?: EntryRef;
}
interface StanceComponent {          // namespace "stance"，人物或组织
  对象: {id: EntryRef; 态度: string /* 语义档 */; 起因?: EntryRef}[];
}
```

## 3. 备选与为什么没选

- **目标做成人物上的列表行（不建条目）。** 省条目，一致于知情。没选：目标要被计划、冲突、知识点引用；隐秘目标又必须是知识点条目，会变成两处各记一份；组织共有的目标也无处挂。
- **只用语义档字段“当前目标”和“对X的态度”（t16 原型做法）。** 零新增，是最省的第一步。没选：查不到冲突与前提变了，没有终态，不能反查。
- **用 nb-story 的 `goal` 类说法加 `motivates` 连接。** 没选：`motivates` 是情节之间的因果，内核第一版不做因果；`goal` 只是一类说法，没有状态与生命周期。

## 4. 用例子走一遍

1. **星瑕的三个目标。** 三个目标条目，轻重：不让妹妹发现（主要）、修复关系（主要）、攒钱（次要）。冲突行：“不让发现”对“修复关系”写“要解释离家的几年就暴露身份”；“攒钱”对“修复关系”写“打工占掉陪妹妹的时间”（这一条是我假设的）。读取表一眼看到冲突。写手拿到“她被两个主要目标拉扯”。攒钱的进度不绑面板存款（要地址引用），第一版写在文字里。
2. **星瑾的误会。** 知识点 K1“哥哥被软禁”（保密）。星瑾的知情行：K1 误信，“他以为”写“哥哥不想回家”；态度行：对星瑕 冷淡，起因 K1。目标 G“等哥哥先认错”，基于 K1。第 22 章计划里她听到真相，K1 变为知道。若作者写完第 22 章而没碰 G，实际模式里出一条待处理“前提变了”：G 基于的 K1，星瑾那一行变了，问“这个目标还成立吗”。作者选放弃，后继指向 G2“和哥哥好好谈”，这一次触及就让待处理消失。
3. **反派的政变。** 目标条目 G“第 30 章发动政变”，加知识点 Component（绝密）。反派本人和心腹各有知情行；国王没有行。第 30 章有一条计划把 G 置为达成。第 10 章写国王的场景，写手拿到“国王不知道反派要政变”，不给内容；写心腹的场景才看到。反派另有公开目标“效忠国王”，国王对它的看法用同一个机制记。
4. **星瑾对哥哥的态度弧光。** 对星瑕那一行初值冷淡。第 10 章有一条计划追加一句“松动”，第 25 章一条计划把态度换成“和好”，都在剧情线“星瑾与哥哥和好”下。按计划读第 24 章末尾是“冷淡；之后：松动”，第 25 章开头是“和好”。如果作者把第 22 章揭示真相的计划删了，“缺一步”提示出现：第 25 章要和好，而星瑾的 K1 在那里仍是误信。

待开发者定：态度用按对象的列表还是沿用 t16 的实例字段；“前提变了”进不进待处理。
