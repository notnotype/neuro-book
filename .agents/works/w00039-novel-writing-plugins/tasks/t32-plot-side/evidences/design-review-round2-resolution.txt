一、归类的原则

第二轮的大部分意见是“方向对，但还没写成可执行的合同”。提案只写取舍与规则，合同（字段、状态转换表、编码、失败码、验收）
按 docs/proposals/README.md 的分工写进 Spec，由 Spec 的审查兜底。所以分两类：
- 设计层（第三版要改）：规则本身缺了、互相冲突、或者照字面做不出来；
- 合同层（写 Spec 时定）：规则已经有，缺的是字段、编码、转换表与验收。第三版在第六节逐条列出，交给写 Spec 的 Task。

二、设计层：第三版要改的

世界线（A2 20、21、22、23、30，第一轮 1、2、8、11、12 的剩余部分）
- A2 20 成立：子线自己的变更必须安放在分叉激活点之后，写入时拒收越界的；多层分叉按父线的激活点传递。
- A2 21 成立（降为重要）：“带过去”的合成赋值是内部事件，不是作者记录；排在切口之后、本线第一条变更之前；
  来历里显示“从原线带过来”，不进计划、检查与待处理；它的依据是父线在触发处的值。
- A2 22 成立：计划跨线的规则：切口之前的计划是每条后代线的只读前缀；兑现只能指向本线看得到的计划；子线兑现父线的计划不影响父线的进展；
  切口之后在父线上建的计划不进子线。
- A2 23 成立：读者读的是活页夹里的正文。规则改成：活页夹的每一章讲的是哪条线（一章可以分段讲两条线，回溯章就是），
  读者知情取当前活页夹正文里能定位到的讲述；RP 读档或重写章节以后，旧正文里的讲述定位不到就不再算读者读过（旧版在 nb-history）。
  放弃的分支不进活页夹。
- A2 30 成立：受影响的线由内核按线树计算（祖先前缀、后代、兄弟排除），不由调用方传；改分叉参数与线归属是结构变更，后代线强制重建；
  淘汰只丢派生缓存，重建后与未淘汰时逐字相同（按线差分验收）。
- 另做：把世界线原型扩到 A2 要的情形：多层分叉、同章切口、切口与触发之间改过带过去的地址、跨线兑现计划，在真实引擎上跑一遍。

在场与知情（A2 24）
- 成立：由在场推出的知情在读取时算出、不另存；同一个人对同一个知识点，按安放取最后一次（显式的行或在场的揭示），后者覆盖前者，
  “忘了”“不知道”也一样；回溯时带过去的是她在触发处算出的结果。

讲述发生点（A2 25；第一轮 3 的剩余）
- 成立：只有正文里的讲述有段位置、进读者的钟；细纲、消息、界面、种子的讲述用各自的锚点（细纲的块、消息 id、确认 id），只参与计划与来源，
  不进读者钟。原句在章里出现几次时取作者或记账指定的那一处，指定不了的进提示。

内核与插件（A2 26）
- 成立：第三版写出两个贡献点的轮廓：讲述标注（种类 id、版本、载荷 schema、引用声明）与诊断（id、版本、输入、输出、稳定键的组成）；
  插件停用时，标注原样保留、只读，诊断不再算出，按组件“类型不在”的同一套规则。字段细节写 Spec。

待处理与作者的处理（A2 27；第一轮 13 的剩余）
- 成立：作者对一条诊断的处理（有意为之、以后不再提）记成一条挂在这个诊断键上的决策（复用决策的作者原话与生命周期，不另建对象）；
  诊断键的编码与状态转换写 Spec。

决策的来源（A2 28；第一轮 9 的剩余）
- 成立：作者原话的来源由宿主签发（作者身份、消息或确认 id、会话、原文摘要、引用范围、时间），内核只认带签发来源的转换；
  普通写入请求只能建待定或“作者未确认”的建议。签发与校验的接口写 Spec。

守卫（A2 29）
- 成立：t32 README 第 5 项里“每章末尾检查”的旧说法与提案第二版“逐变更检查”冲突；以提案为准，改 README。

写手简报（B2）
- B2 3 成立：“保密的真相只出现一次”照字面做不到（读者已知、目标、决策本身就带着真相）。改成：每一处带秘密的话都标明“写手知道、
  谁不知道”，并合并成一个“这一场的秘密”块，其它段只引用它。
- B2 6、17，F1 23、26 成立：窄问题补两层：写作指示层（视角越界、结尾停在哪、“不写”有没有写）与新事实层（正文里有、自陈里没有、
  世界里也没有的事实，例如小梅怎么知道“十一点”）。
- B2 7 成立：“在场的人”给了非视角人物的动机，写手就会写进叙述（Sonnet 自己也犯了）。改成：非视角人物的动机与心理只用来决定他的
  言行，段首写明“不写进叙述”。
- B2 8 成立：场景事实（谁在哪、几点、光线）没有来源。改成：细纲或计划写“场景条件”，简报照抄；没写的，主 Agent 审细纲时问，
  或写明“本章不透露”。地点 Component 以后做，这一版靠细纲。
- B2 1、10 成立：样例里手写做对的几处（场景光线、视角人物自己的秘密可以写进心理、代词）写进规则。
- B2 19 成立：简报要有字数预算：按段给上限，超出按优先（视角人物、保密、本章节点、在场者）裁；通用的规则句只说一次。
- B2 13、18：要开发者定（见第四节）。
- 其余建议（B2 2、4、5、9、11、12、14 到 16、20、21）：成立，改简报规则或样例的措辞；不改设计。

三、合同层：写 Spec 时定（第三版第六节列出）

第一轮 A 的 1、2、3、4、6、8、9、12、13、14、15、17、19 的剩余部分，与第二轮 A2 的字段与编码部分：世界线与分叉的持久化形状、

受众身份的绑定、拒绝码与审计；计划节点的覆盖关系；决策的状态字段与转换表；ADR 0037、0039 的逐条取代矩阵与日志格式的公开失败合同。

四、要开发者定的

1. 绝密遇到“在场的人知道它”（B2 18）：写第 16 章时管家在场、他知道自己是凶手，写手要让他的言行合乎这个事实，又不能知道内容。
   推荐：绝密的知识点上加一项作者写的“持有者在人前的表现”（例如“镇定，回避书房的话题”），在场者知道这件事时给写手这一句，不给内容；
   本章计划要暗示或揭示它时才给内容（开发者 11-04 已定）。
2. 读者层用“盲读”（B2 13）：现在的读者层问题由知道真相的记账 Agent 回答，系统性偏向“能确定”；而且只看本章、不累计前文。
   推荐：读者层改由一次单独的“试读”调用回答：只给它到本章为止、与这个知识点有关的讲述原文，不给世界的真相，问“你觉得是谁、有多确定”；
   只对有揭示计划、计划之前的保密以上知识点做，每章有上限。多一次便宜模型调用。
