# nb-story 的功能能否落在 nb-canon 上

路径省略前缀：Spec 在 `docs/specs/story/`（Q=queries、I=ingest、A=qa、V=viewer、C=cli-skill、R=revisions），代码在 `packages/nb-story/src/`。canon 栏含剧情侧提案；“推断”无运行证据。样例书（`tests/fixtures/sample-100ch.json.gz`）：176 对象、1739 说法、1356 知情、247 情节、186 账本、257 悬念、11 秘密。

## 1. 功能清单与判断

| 用户能做的事（Spec；代码） | 在 canon 上 |
|---|---|
| 导入整本 TXT 切章、不依赖项目（I 输出 1 至 3；`ingest/`） | 补适配器：canon 要宿主给章序。切章复用，内核只吃章序（推断） |
| 逐章抽取、核对修复、马甲核对、整理（facets、arcs）、原子提交、断点续抽、追加（I 输出 1 至 15；`ingest/chapter.ts`、`compile.ts`） | 管线留下，输出改写 canon 修订（单写者加版本号等于章提交）；facets 对应语义档，arcs 对应剧情线加计划。canon 不抽取，作者端靠 Agent 记账 |
| 修订：确认、驳回、手连、改种类、挪称呼、撤销（R；`core/overlay/`） | 能做且更强。小补：`sameAs` 要有候选态 |
| 不剧透，位置到章.段（Q 输出 1） | 补：读取位置只到章，见 2.1 |
| 找对象、人物卡、称呼首现、泛称（Q 输出 4、6、7、22） | 补：别名和 `lookup` 能做；称呼出现位置（9615 条）要扫正文，做派生索引 |
| 身份按读者或角色视角合并（Q 输出 3、5；`core/identity.ts`） | 补：`sameAs` 无视角，见 2.4 |
| 说法：12 类、渠道、明说或角色说法或认为、持有人、印证反驳 | 做不了：canon 不记角色说的话。belief 672 加 claim 612，占 74% |
| 谁知道什么、秘密矩阵（Q 输出 9） | 补（提案已含）。差别：1356 条知情里 1019 条（75%）由程序从台词和心理推出，canon 只管建成知识点的事 |
| 悬念分次进展（Q 输出 11） | 补（提案已含）：伏笔节点五种 |
| 情节：在场者及化名、步骤、6 种连接（Q 输出 13） | 补一点：剧情变更能装事件；步骤、连接、化名没有 |
| 数值账本、对账、起始未知（Q 输出 10） | 能做且更强（核对点、嫌疑区间）；起始未知见 2.5 |
| 时间线、补叙（Q 输出 12） | 补（提案 `nb-time`，未实现）：时间约束网络是偏序；补叙对应“安放与时间对不上” |
| 记录等级 tier、伏笔候选（Q 输出 23 至 27；`core/tiers.ts`） | 做不了：依赖读者端后文回响 |
| 搜索、读原文、章摘要（Q 输出 14、15） | 补：无正文检索；章摘要用 `changes` 能做 |
| 查看器 11 页含关系图、全书图，书架、导入页、设置页（V；`web/`） | 页面复用，数据层换适配器；关系词、认知线要说法（工作台版是 t18） |
| 内置问答：图当目录读整章、全读、出处校验、对话（A；`qa/`） | 引擎复用，只依赖查询工具集（`qa/tools.ts`），canon 版提供同名工具 |
| 命令行 28 条、Skill、书库（C；`cli/`、`skill/`） | 命令面随查询接口；书库和“一代”留 nb-story |

## 2. 做不了或代价大的

| # | 项 | 建议 | 理由 |
|---|---|---|---|
| 1 | 读者位置到段 | 补进内核，小改 | 讲述加段号，写入时由原句在章内定位（原句本就校验在章内）。题库只到章，只有查看器和出处要段 |
| 2 | 带渠道的说法、印证反驳 | 不进内核；做 canon 上的插件 Component，或留 nb-story | 作者知道真相，渠道是读者端的不确定性；占记录 74%。只有 C 类 5 题要 |
| 3 | tier 与伏笔候选 | 留 nb-story | 规则表只在两本书上校准，只对读者端后文有意义。回响算法以后可做“漏标伏笔”检查，低优先 |
| 4 | 身份按视角合并 | 读者视图里的函数，不改内核 | `sameAs` 加提案里“甲就是乙”的知识点和揭示位置，已揭示才合并。H 类要它，性价比高 |
| 5 | 起始金额未知 | 不补内核 | `add` 在未知上套不上；写入者给带“估计”的初值，嫌疑区间会标出。失去相对余额显示；账本累计只有 41 条，代价小 |
| 6 | 不依赖项目的整本导入 | 无项目宿主适配器，放 nb-story | 外部书不需要作者端工具，别进内核 |
| 7 | 情节因果连接 | 先不补，看评测 E 类 | 剧情变更已有 `links`，加 `causes` 是小改 |

## 3. 评测怎么复用

**资产**（带“未合并”的先复制进 master）：

- 样例书 V9 图含原文，在 master。题库 v3.2 的 `questions-ch21-100-fixed.json`（56 题）和 `questions-knowledge16.json`（16 题）、判分器 `t22-eval-v2-grading/scripts/judge-v2.ts`，在 w00005 worktree 的 `.agents/works/w00005-novel-understanding-spike/tasks/`，t11 到 t34 没提交。回归脚本 `.agents/works/w00024-nb-story/tasks/t05-qa/scripts/qa-eval.ts` 在 master。
- 题型：56 题为 A、B、D、H、C、E、M、N 各 5，G、I、J、F 各 4；16 题为 B5、H5、I2、D2、N2。
- 判分：给要点和原文，分答对、答对但不全、没把握、答错。作答 gpt-6-luna xhigh，规则 v5，一审为准。跑法 `qa-eval.ts answer|judge|check`。基线 graph56 答错 33/168（19.6%）、graph16 不超过 11/48。
- 分辨力：同批复核有 7.4% 进出答错，3 个百分点内不能当真；每类仅 4 至 5 题。

| 直接适用 | 要改或降级 | 不适用 |
|---|---|---|
| M 数值（最强）、N 悬念、B 认人、A 与 I 摘要、G、F | H 知情（要提案的知情加读者列）、D、E（无连接）、J（分清“没记”和“不知道”，提案精度三档能做） | C 来源可信度（要渠道说法，最多降成“实际经过”那半问） |

题、答案、判分器不动。读取位置用“第 N 章末尾”，正好对上 `requiredPrefix`（章级），防剧透由 canon 的读取位置保证。

**关键洞察**：nb-story 的查询、查看器、问答、命令行都只读 V9 数据文件（`book.import` 收的就是它）。最省的“重写”不是换存储，而是写 canon 到 V9 的投影：世界加位置得到数据集，缺的字段（说法、tier）留空。问答引擎、`qa-eval.ts`、判分器全部原样跑（推断：说法为空能过校验）。

**第一个实验**：

- 书：样例书。章：前 50 章。题：`requiredPrefix` 在 50 以内的，即 21 到 50 章 27 题加 16 题里 9 题（I21、I22、B21、B22、D22、D24、H21a、H23、H24）。
- 数据：V9 转成 canon 世界，零模型费用。信息量与 V9 相同，只验“装得下多少”，覆盖率本身是结果。
- 比：V9 图当目录对 canon 投影图当目录，同模型、规则、判分，各 3 次，约 100 份；每份约 ¥0.07 至 0.09，合计约 ¥10 至 20（推断）。V9 基线要重跑一次定噪声。
- 判据：总答错率不高于 V9 加 3 个百分点；M、N、B 不降，H 补读者列后追平。C、E、D 预计掉，用来决定补什么。
- 局限：证明不了 canon “更好”。已有结论是 100 章内全读最准，所以问答证据的上限是“不比 V9 图差”；canon 的价值在作者端，要用 t26 的漏记率、静默错记率量。

## 4. 路线

1. **落资产**（半天，¥0）：题库、判分器进 master，`qa-eval.ts` 可指向任意书库。
2. **V9 转 canon 的转换器加覆盖率报告**（1 至 2 天，¥0）：对象到条目，情节和账本到剧情变更，知情和悬念按提案落，输出“装不下清单”及占比，**这是最早的证据**。
3. **canon 到 V9 的投影，跑第一个实验**（2 至 3 天，约 ¥15）。
4. **按错因补缺**：读者位置到段、身份视角合并、读者列；E 类错多再加 `causes`。
5. **重新记账对照**（前 20 章，约一周）：同模型用 canon 记账，对 V9 在 20 章上的数据（55 题五组），比每百万字费用（V9 ¥44 至 64）、漏记错记、问答。这才回答“canon 记账是否更省或更准”。
6. **之后再定换不换数据层**。建议不换：做法 A 要丢书库、不依赖项目的导入和说法。作者自己的书走 canon，第三方书走 nb-story。
