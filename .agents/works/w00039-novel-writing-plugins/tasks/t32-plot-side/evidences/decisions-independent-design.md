# 决策与章级写作指示：独立设计

声明：读 README 时扫到第 5 节开头三条（决策并入未决问题的生命周期、挂任何对象、状态只由修订改变），不算完全独立；下面各点按自己的理由重推。

## 一、质疑

- **精简**：决策与未决问题是同一件事的两端，分成两个对象，交接处就是“开放决策蒸发”的缺口，所以合一。旧版 11 个字段里，信息控制 4 项已被知情（读者揭示标记、人物知情行、保密分档、计划上的暗示标记）覆盖，节奏并入语气；剩下没有别处可放的是视角、读者感受、语气、开头结尾、禁写。
- **成本**：约束检查靠已有的地址与读取位置，程序算、零模型费用；文字类约束只在记账时对本章触及的最多 5 条各问一个窄问题。
- **体验**：作者多半在对话里说“第一卷别让她发现”，主 Agent 记，作者只确认。写手要短的祈使句；记账要少而准的待查项。
- **可观测与维护**：诊断附上相关决策；写手上下文记下用了哪些；回执写新定几条、关了几个未决。不再为决策另建一套类别。

## 二、推荐设计

### 1. 决策 = 未决问题长大

**存哪**：沿用“未决问题”这个对象，改名决策，仍是六种之一。不做成条目：条目状态按故事位置折叠，决策是创作上的事，只由修订改变，还要挂在章上（章不是条目）。

**生命周期**：

| 从 | 到 | 条件 |
|---|---|---|
| 新建 | `open` | 想不好的事，可带候选与最晚第几章前定 |
| 新建、`open` | `decided` | 必须带作者原话出处；Agent 没有出处不能定 |
| `decided` | `superseded` | 指向新决策，旧的不进简报 |
| `open`、`decided` | `dropped` | 带原因与作者出处 |
| `decided` | `open` | 作者重议 |

Agent 想改作者定的事，只能新建 open 决策指向旧的，由作者定。记账不关闭决策，只往 `hints` 加“正文里可能的答案”。

**约束**：`about` 是列表，可指条目（含剧情线、知识点）、变更（含计划）、地址、章、另一条决策；`scope` 是章区间，缺省整本书。`choice` 一句祈使，`why`、`risk`（写手的刹车点）选填，`guards` 选填：某地址不准取某些值，缺省值表示范围内任何改动都报。`why` 作者没说时不许编，账本提示“没记理由”。

**进写手上下文**：已定的（范围覆盖本章且 `about` 与本章涉及的条目、线、计划相交，或整本书适用）写 `choice`、`why`、`risk`；未决的（触及本章，或到期前 3 章内）写“不要替作者定”加候选。上限 8 条，有 `guards` 的优先。`about` 连着绝密知识点时只写“有一条涉及保密设定的决定”，作者填 `forWriter` 才给内容。

**检查**：

| 检查 | 级别 | 算法 |
|---|---|---|
| 违反已定约束 | 待处理 | `guards` 在范围内每章末尾读取，并按计划模式读计划 |
| 写死未定 | 地址被补丁定死：待处理；只涉及条目：提示 | open 决策的 `about` 被本章变更或计划触及 |
| 到期没定 | 待处理；前 3 章提示 | 下一章要写的是 `due` 或更后仍 open；写正文任务拦一下，作者可选“仍写，保持未决” |
| 悬空 | 待处理 | `about`、`scope`、`due` 指向被删的章或条目 |

泄底、穿帮等诊断附上 `about` 相交的决策，作者能看到“为什么”。

### 2. 章级写作指示

**存哪**：章附带文档头部，与细纲同处，不进世界。理由：重 roll 时新要求往里记，记账期间世界只读而指示仍要可编辑，版本归 nb-history。canon 只接收参数（`pov`、在场人物），不认识文件格式。

```ts
type Target = { kind: 'entry' | 'change' | 'chapter' | 'decision'; id: string }
            | { kind: 'address'; entry: string; path: string };
type Decision = { id: string; title: string; about: Target[];
    scope?: { from?: ChapterId; to?: ChapterId }; by: string } & (
  | { status: 'open'; due?: ChapterId; options: { text: string; leaning?: boolean }[]; hints: Hint[] }
  | { status: 'decided'; choice: string; why?: string; risk?: string; forWriter?: string;
      guards?: { at: Address; forbid?: Value[] }[]; source: Narration }
  | { status: 'superseded'; by: string }
  | { status: 'dropped'; reason: string; source: Narration });

interface ChapterDirective {          // 全部可选
  purpose?: string;                   // 读完读者该有什么变化
  pov?: { who: EntryId[]; mode?: 'first' | 'limited' | 'omniscient' };  // 缺省 limited
  tone?: string; opening?: string; ending?: string;
  avoid?: string[]; notes?: string[]; // notes 放重写要求
}
```

**分工**：细纲是情节原文；计划是世界要变成什么样（含知情变化）；指示是怎么写、不写什么。能写成世界状态的进计划，不进指示。计划排在本章而指示说“不写”，简报并列报出，由主 Agent 提议挪计划。同一条指示在第二章又出现，建议升为决策。

**视角人物**：有限视角下叙述只能写 `pov` 知道的，简报按 `pov` 展开知情，其余在场者只给对白层限制。穿帮检查收窄：对白层照旧按在场者；叙述层只查 `pov` 对本章保密点是“不知道、误信”的，问“叙述有没有写出她不知道的事”。全知视角不查叙述层。

**剧情线的指示**：不新建字段，就是 `about` 指向该线、无 `due` 的已定决策，本章有该线的计划或变更时进简报；基调换了就取代旧的。

## 三、备选

- **决策做成条目加 Component**（同知识点、伏笔）：没选。时钟不对，且要挂在章上。
- **指示也做成“挂在章上的决策”**：没选。每条要 `why`，轻量指示被迫写理由；记账期间被锁；重 roll 的临时要求污染决策账。
- **保留旧 11 个字段**：没选，信息控制 4 项与知情重复，手填会和推导打架。

## 四、例子

1. **“第一卷不让星瑾发现哥哥是魔法少女”**：decided，`about` 是该知识点与星瑾，`scope.to` 是第一卷末章，`guards` 是星瑾对该知识点的知情行不准取“知道”，出处是作者这句话。第 7 章有变更改成“知道”就报“违反已定约束”并附决策，改成怀疑不报。“让读者慢慢发现”不是地址，靠提前泄底检查，报时附上本决策。
2. **“双王”第 8 章前要定**：open，`due` 是第 8 章。第 5 到 7 章简报有“未决，不要替作者定”；第 6 章有补丁把它写成“兄妹”，报“写死未定”；写第 8 章前拦下，作者答后带原话转 decided。
3. **第 12 章“只让妹妹误会，不要和好；视角星瑾；结尾留悬念”**：“误会”写成计划（星瑾对哥哥那行变“误信”）；指示里 `pov` 是星瑾，`avoid` 写“兄妹和好”，`ending` 写“留一个悬念”。简报按星瑾展开知情，叙述层只查她；本章若排了“和好”的计划，并列报出矛盾。
4. **剧情线“兄妹心结”基调克制，不煽情**：一条决策，`about` 指该线，`choice` 是“克制，不煽情”，整本书适用。第 12 章有这条线的计划，所以进简报；第二卷改基调时新建一条取代它。

## 五、没把握

- `guards` 只覆盖地址取值，读者层约束靠泄底检查，漏了的看真实写作。
- “相交”判定可能漏间接相关；窄问题准确率要用真实模型测。
- `source` 如何识别“作者原话”（消息引用的格式）要和 t20 一起定。
