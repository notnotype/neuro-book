# nb-canon 故事时间第一版：独立设计

## 一、质疑（按视角）

- **反对与精简**：不做全局唯一的精确时刻，旧版 bigint instant 全库唯一、一刻一切面，撞了就 409，还逼作者猜。现成库不能直接用：`@js-temporal/polyfill` 0.5.1（2025-03 后未更新）、`temporal-polyfill` 1.0.7（活跃）、`@internationalized/date` 3.12（活跃）都只有内置历法，没有“一天 48 小时、月份自定义”；`edtf` 4.11（活跃）只管公历，但“精度由写法决定、近似、区间”的想法值得借；`chrono-node` 2.10 不懂自定义历法和中文古风说法；`interval-tree-1d` 自 2021 年未更新，三十行的排序数组加区间最大值就够。历法和传播自己写，约几百行。
- **成本**：传播和查询是纯程序，一万件事毫秒级，不调模型。记账 Agent 只写“说法”（原话加相对关系），数交程序：nb-story 评测里模型累加天数晚一天、后面全错，所以只让它写相对间隔，由程序累加。
- **使用者体验**：作者记不全，所以 `when` 全可选，没写就是未知，未知不算错；写得越细范围越窄。写代码的 Agent 拿到的是小而稳定的 API。记账 Agent 用 `time.parse("十五岁那年", 锚点)` 得到结构，不自己算刻数。
- **迁移与兼容**：`when` 是变更上新增的可选字段，日志里未知字段本来就原样保留。`Placement`、按章排序和 rank 键一个字不改，旧日志照读。
- **可观测与排障**：每个范围带“怎么缩出来的”链（哪条说法收窄了它），矛盾给出最小冲突集。时间只出诊断，不让读取失败，与现有“读取不失败”一致。
- **长期维护**：时间和世界线都放进独立模块（建议新包 `nb-time`，只含历法、说法、传播、区间索引，无运行时依赖），nb-canon 与 nb-story 共用。提案里“位置是独立类型，换掉模块调用方不改”的承诺由它兑现。

## 二、推荐设计

### 1. 核心原则：时间不决定折叠顺序

折叠仍按叙事位置（前史、章序、章内键），时间只做**标注、检查、查询**。理由：补叙、梦境、回溯下按故事时间折叠会让相对加减断裂（旧痛点 2）；大量事件时间未知，没有全序可依。代价：不能直接回答“故事里某刻的状态”。第二版可加 `stateAtTime`，只在相关地址的先后全部确定时才回答，否则答“不确定”。时间与折叠冲突时只报诊断：同一地址上叙事先后与故事时间先后相反、且后者不是补叙标记，报 `time-order`，提示把这条变更的安放挪到前史。

### 2. 数据形状

```ts
type Tick = bigint;                       // 日志里存十进制字符串；单位由历法定义（缺省 1 秒），正负皆可
type Span = [lo: Tick, hi: Tick | null];  // 时长区间，null = 无上界

type TimeClaim =                          // 同一件事的多条说法同时成立，取交集
  | {k: "abs"; lo?: Tick; hi?: Tick}      // 绝对区间 [lo,hi)；“312 年”= 整年，精度即宽度
  | {k: "rel"; to: Id; dir: 1 | -1; gap: Span} // 本事件起点 = 锚点终点 ± gap；缺省 gap=[0,null]
  | {k: "dur"; span: Span};               // 持续多久
// 每条说法另带 text?（原话）、basis: {told: Telling} | "estimate"
interface TimeSpec {claims: TimeClaim[]}  // 加在剧情变更上：when?: TimeSpec
```

- **锚点就是剧情变更**，不新增对象。“星瑾出生”“大灾难”都是补丁可为空的变更，放前史；“年龄”不存字段，是查询结果，避免数字过期。
- **精度/模糊词**：“几年”→[2,5]年、“十几年”→[10,20)年，词典放在历法里，写入时展开成区间并保留原话。
- **历法**（世界设置，随 Component 类型登记；不是第七种对象，改历法是一次修订，刻数不变，只改显示与重解析，原话保留供重解析）：

```ts
interface Calendar {
  tick: string;                                   // 基础刻名
  units: {name: string; per: number}[];           // 刻→分→时：时有 48 个/日，则 日=48 时
  months: {name: string; days: number}[];         // 各月叫法与天数，个数不限
  leap?: {every: number; month: number; extra: number}[]; // 闰规则，闭式计数，O(1)，不逐年遍历
  weekdays?: string[]; eras?: {name: string; fromYear: number; dir: 1 | -1}[];
  vague: Record<string, Span>;                    // “几年”之类
}
```

### 3. 程序怎么算

每件事有起点可能范围 `[lo,hi]`。`abs` 直接给，`rel` 沿图双向传播（向后推上界，向前推下界），同一事件取交集。图基本无环：拓扑序一遍，O(边数)；有环的强连通分量内用 Bellman-Ford 找负环。结果：

- **范围与比较**：`compare(a,b)` 返回 `before|after|overlap|unknown`（偏序，解决 nb-story 的“日子未知单独成组”）。
- **矛盾**：范围变空报 `time-conflict`，带冲突链；环报 `time-cycle`；原话解析不了报 `time-unparsed`。
- **夹逼**：没有 `when` 的事件，用叙事先后里最近两个已知邻居夹出软范围，标 `basis: squeezed`。它假定叙事大体向前，只用于查询排序，不报诊断，补叙要有说法覆盖。
- **补叙**：故事时间早于前文已写到的最晚点，就是补叙（同 nb-story `timeline.ts`），派生，不存。
- **前史**：新增前史变更且有时间范围时，程序按范围在邻居之间取中间数填 `order`；之后不隐式重算。

### 4. 查询（给 Agent）

```
time.find({overlaps|within: "王历312–315年", world?, about?: 条目}) // overlaps 召回，within 确定
time.window(ref)   // 某事件、某章的可能范围和依据链（explain）
time.between(a,b)  // 间隔区间
time.age({entry, at})   // 年龄 = at 范围 − 出生锚点范围
time.timeline({from,to,lod: "纪|年|月|日"}) // 按历法层级分桶，给每桶计数和代表事件，逐级下钻
```

索引：排序数组加区间最大值，一万件事重建约毫秒；另维护“章→时间包络”，反查“这段时间可能写在哪几章”，用于缩小记账时的查找范围。

### 5. 世界线与回溯

世界线是一个字符串 id，缺省 `main`；变更、核对点和读取位置都带可选 `world`。**分叉是一种变更**（`kind: "fork"`），不增加对象种类：

```ts
interface Fork {
  parent: string; cut: Placement;       // 新线继承父线安放在 cut 之前的变更
  from: Id; back?: Span;                // 从父线哪件事触发；新线起点时间 = 该事件 − back
  mode: "rewind" | "branch" | "dream" | "alt";
  carry: Address[];                     // 带过去的地址，如她的记忆：取父线在触发处的值作为起点
}
```

线 L 在位置 P 的状态 = 祖先线在各自 cut 之前的变更，加 L 自己位置 P 之前的变更，全是叙事先后，照旧折叠。`rewind` 之后各章的缺省世界线改为新线；`dream`、`alt` 必须显式指定。早于分叉的位置读新线等于读父线。梦中的结果要带回现实，用父线上普通变更写。**cut 由叙事位置定，不由时间定**，时间只做核对：cut 之前的父线变更范围明显晚于分叉时间，报 `fork-time-mismatch`。各线缓存在 cut 处取父线检查点，沿用现有增量引擎。

## 三、备选

- **A 单一精确时刻**（旧版）：每件事一个全局唯一时刻，排序和折叠都简单。没选：作者不愿记全，逼出编造的精确值，撞时刻又失败。
- **B 时间主导折叠**：按故事时间排序折叠。没选：未知时间无法排序，补叙、梦境、回溯会破坏相对加减，等于回到旧版痛点。
- 世界线做“整库写时复制并可合并”的分支也没选：合并语义远超第一版，普通变更已能表达带回。

## 四、三个小例子

**1. 澜历王国**（一天 48 时；月份：霜月、融月、苗月、雨月……每月 29 到 31 天，一年 363 天）。
- “开国”abs=澜历 1 年霜月 1 日。
- “大灾难”写“开国后约三百年”：`rel(开国,+[290年,310年])`，范围约 290 到 310 年。
- “王都南迁”写“灾难后五年内”：`rel(大灾难,+[0,5年])`，范围 290 到 315 年。
- “新王加冕”写“澜历 307 年雨月，灾难之后”：abs 加 `rel(大灾难,+[0,null])`，反向传播把灾难收窄到 290 到 307 年，南迁随之收窄到 290 到 312 年。
- `time.find({overlaps:"澜历300–312年"})` 返回灾难、南迁、加冕，各带可能范围和依据链。

**2. 她第 1 章多大**。设前史变更“出生”B（时间未知）。“十五岁那年第一次变身”：`rel(B,+[15年,16年))`。“离家”：`rel(变身,+[0,null])`。“第 1 章回家”：`rel(离家,+几年→[2年,5年])`。
- `time.age(她, 回家)` 得到“至少 17 岁，上界未知”。
- 补一句“离家时十七岁”：`rel(B,+[17年,18年))`，答案变成 19 到 22 岁，并给出依据链。

**3. 第 8 章回溯 6 小时**。
- Agent 查 `time.find({overlaps:[T−6时,T], world:"main"})`，得到第 8 章前半的几条变更，把 `cut` 定在其中最早一条之前。
- 记 `fork{mode:"rewind", parent:"main", from:回溯事件, back:6时, carry:[她.记忆]}`，新线 `w2`。
- 第 9 章缺省读 `w2`：被刺伤的 hp 回到 cut 之前的值，她的记忆取回溯瞬间的值；读 `main` 仍是作废前的主线。
- cut 之前若有变更范围晚于 T−6 时，报 `fork-time-mismatch`。
