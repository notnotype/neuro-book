# 伏笔与悬念

## 目标与范围

把旧 Plot 的伏笔账本（埋下、推进、受挫、回收）与 nb-story 的悬念（提出、部分解答、解答）合成一套：作者看计划中的伏笔，也看读者此刻实际有哪些悬念。

合同：讨论 Task，只定设计，行为合同未变；定稿后的 Spec 改动在实施时另定。

前置：t02。

## 要讨论的问题

1. 伏笔与悬念是不是同一个东西：作者有意埋的伏笔读者可能没察觉；读者产生的悬念作者可能没打算回答。两者怎么对齐。
2. 状态：open、fulfilled、abandoned 之外要不要“已埋但读者未察觉”“读者已猜到”。
3. 挂在哪：场景、章节、段落；回收距离太远、长期没推进的提醒要不要做。
4. 旧版的 Decision（ADR 式创作决策）放在这里还是单独一类。

材料：[调研：三节](../../research/2026-10-31-repo-survey.md)；[剧情图谱：悬念](../../../../../docs/proposals/novel-story-app.md)。
