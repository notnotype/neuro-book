# t28 实施计划（第 3 稿）：主文字按块编辑，暂存加提交，冲突按块判

2026-11-23 主会话按开发者的决定改写，待开发者确认。第 1 稿（一个解析器、富文本、整篇提交）见提交 `8ba019e28`，第 2 稿（整篇提交、内核对回各块）见 `0ab76478c`；三份设计审查的逐条处理见 [`evidences/design-review-resolution.txt`](evidences/design-review-resolution.txt)，其中写着“改进第 2 稿 3.1”的几条（omp 第 5 到 8、14 条）在这一稿里因为不再有整篇提交而不适用，见本稿第 8 节。

## 1. Context

**为什么做。** 开发者 2026-11-23：先让“世界引擎能像文件系统一样记录东西”。现在改主文字要点“改这一段”、在对话框里改源文字。

**开发者已定的**（Work README 决定表 2026-11-23）：

1. **主文字就是一组带编号的块，系统不自动分块**，分块交给作者和 Agent。内核存的本来就是这样（`BlockSchema`），产品代码里也没有地方自动切块；这一稿不引入任何自动切块。
2. **编辑按块来**：阅读视图点“编辑”后一块一个编辑框；想分才分（加一块、从光标处拆开、并到上一块、删掉）。新条目只有一块，用起来就是编辑一个文件。
3. 这一轮用**源文字**编辑，编辑框是 Monaco；富文本等 [t38](../t38-kernel-shared-parser/README.md) 之后。内核的解析器不动。
4. 改动自动暂存；点“提交”才发布成一条修订；Ctrl+S 等于提交；标签上有未提交的圆点。
5. **冲突按块判**：别处改的是作者没碰的块，直接保留；同一块两边都改了才问作者。
6. 继续用页面标签，给它补未提交的圆点与 Ctrl+S。
7. 直接编辑都算改设定；“这一块在剧情里变了”收进阅读视图里每一块的菜单。
8. 先保证功能与 UX，界面先不打磨。交互照 Lab 的交互稿 `EntryTextEditDraft`（场景 `single`、`blocks`、`draft`、`empty`）。
9. 条目树像文件树一样用是紧接着的下一个 Task。

**开发者知悉的代价**：块的大小由人定以后，剧情里的文字变化整块替换、给写手的简报按块扣秘密、冲突按块、修订存整块的改前改后。建议的用法是默认一块，会随剧情变的与带秘密的部分单独拆成块；这句话写进给 Agent 的工具说明。

**依据。** [`canon/revisions.md`](../../../../../docs/specs/canon/revisions.md) 输出 7、8、16、25；[`canon/author-ui.md`](../../../../../docs/specs/canon/author-ui.md) 输出 7、10、28、30、39；[`canon/rendering.md`](../../../../../docs/specs/canon/rendering.md) 输出 1、3；[`workbench/editor.md`](../../../../../docs/specs/workbench/editor.md) 输出 33、53；[`storage/persistence.md`](../../../../../docs/specs/storage/persistence.md)。

## 2. 技术选型

| 问题 | 选用 | 理由与否决 |
|---|---|---|
| 源文字的编辑控件 | Monaco：复用编辑器插件已有的加载器与主题（`editor/web/code/load-monaco.ts`、`monaco-theme.ts`），另做一个可嵌入的小组件 | 开发者定。现成的 `MonacoControl.vue` 绑的是文件文档，不能直接放进页面。仓库里没有封装好的 CodeMirror |
| 提交 | 内核现有的三种操作：`set text[块 id]`、`addBlock`、`removeBlock`，一批一条修订 | 编辑按块以后不需要“整篇对回各块”。内核只补三处小的（3.1） |
| 暂存放哪 | 插件的项目记录（`scope: project`、`locality: local`、按条目 id 分键） | 页面标签的状态刷新后不保留；`local` 是这台机器这个浏览器配置自己的 |
| 未提交的圆点与 Ctrl+S | 给编辑区的页面声明加两个可选项 | 页面组件只在标签活动时存在，挂在组件上非活动标签就没有圆点。否决：把条目主文字做成编辑区的一种文档——要给编辑区加四样新东西，改动面没摸清，开发者这一轮定了用页面标签 |

## 3. 关键设计

### 3.1 内核补三处：`packages/nb-canon/src/`

现有的 `editEntries` 已经能改一块（`set`，可带读到的值 `read`）、加一块（`addBlock`，可写插在哪一块之后）、删一块（`removeBlock`）。按块编辑还缺：

1. **加在最前、连续加几块的先后。** 现在 `addBlock` 不写 `after` 是放到最后，没有办法放到最前；同一批里几项写同一个 `after` 时后写的排在前面。改成：`after` 可以写 `null`，意思是放在最前；同一批里写同一个 `after` 的几项，按写的先后排。
2. **按块核对读到的值。** `removeBlock` 加可选的 `read`（读到的原文），与 `set` 的 `read` 一样：这一块现在的原文与 `read` 不同、或已经不在，整批拒收（`value-conflict`），详情逐块给出 `{块 id, 读到的, 现在的（没了为 null）}`。界面据此弹出逐块的对照。主文字的 `set` 现在带 `read` 时的行为照此核对一遍、补上详情里“现在的”。
3. **条目读取里每一块带它的来历。** 现在读出来的块只有 id 与原文。加两个标记：`inInit`（在初值的文字里）与 `touchedBy`（被哪一章的剧情变更改过、加出来或删过，取最近一处，没有为空）。界面用它决定哪些块不能删、不能并（被剧情碰过的照 `element-from-change` 会被拒收）、新块该挂在谁后面（改设定时 `after` 只认初值里的块）。

不改的：不引入自动切块；`splitBlocks` 没有调用方，这一轮从 `canon/rendering.md` 输出 3 里拿掉“调用方用它切块”的说法（函数先留着，t38 定去留）；修订的形状、路由、校验都不动；远程合同不加方法。

提交用当时最新的世界版本作 `baseVersion`，块的并发由各项的 `read` 把关。条目对象在这之间又被别处动过时得到 `version-conflict`，界面重读版本后自动再发一次（各块的 `read` 还在把关），所以作者自己在别的分页改字段、改名不会被当成“别处改过”。

### 3.2 页面标签的未提交与保存、可嵌入的代码输入框：`packages/neuro-book/src/plugins/editor/`

`EditorPageImplementation`（`web/pages.ts`）加两个可选项，和 `title?(arg)` 一样按参数取：

- `uncommitted?(arg): boolean`：响应式地读。标签条的圆点对页面标签取它；公开状态 `dirty` 在活动标签是页面时取它。
- `commit?(arg): Promise<void>`：活动标签是页面且有它时，`nbook.editor.save`（Ctrl+S、命令面板）调用它。

不加关闭与离开时的询问：内容已经暂存。状态栏的未保存计数、关窗结算只算文件，不变。

**代码输入框**：编辑器插件经合同多交一个组件（暂名 `CodeInput`）：属性是文字、语言、只读、可读名，事件是文字变了、请求保存（在它里面按 Ctrl+S）、光标位置（“从光标处拆开”要用）。高度随内容。底下用现有的 `loadMonaco` 与主题。文字由外面给：外面换了文字（并块、放弃）时换内容，自己打字引起的回声不重设。一页里可能有很多块：编辑框进入视野或拿到焦点时才建 Monaco，之前画等宽的原文。

### 3.3 暂存：`packages/neuro-book/src/plugins/canon/web/`（新 `text-drafts.ts`）

窗口里一份暂存登记，不随页面组件卸载（圆点要给非活动的标签用）。

- **记录**：`canon.text-drafts`，`scope: project`、`locality: local`、按条目 id 分键、上限 1 MiB。值是 `{base: {position（写明线）, blocks: [{id, source}]}, items: [{id（新加的为 null）, text, deleted}], pending?: {requestId}}`。
- **一个条目一份。** 有暂存时条目页的位置选择与“按计划”开关锁在暂存的位置上，要换先提交或放弃。
- **什么时候写**：输入停 300 毫秒、编辑框失焦、页面转入后台时。写失败时页面上写“暂存失败”并留着内存里的内容。最后不到一秒的输入来不及写就关窗的情形不兜（Spec 写明）。
- **能按块编辑的大小**：各块原文合计不超过 200 KB（暂存要同时存现稿与各块原文）。超过时“编辑”不可用并说明，阅读视图里块的菜单还能用。
- **有没有未提交的内容**：有一块改了、加了、删了。改回原样就不算，暂存随之删掉。
- **提交的结局**：发出前把这次的请求 id 写进暂存；成功后删暂存；回复丢了或刷新了，下次打开先按请求 id 查结局（`outcome`），已发布就删暂存，没发布留着。提交在途时编辑框只读。
- 条目被删、世界只读、别人独占、断开时：暂存留着，“提交”不可用并写原因。

### 3.4 文字分页：`packages/neuro-book/src/plugins/canon/web/components/`

- **阅读视图**：现有的 `EntryText`（值显示成数、点开来历）。右上角“编辑”；没有主文字时是“开始写”。“改这一段”“删掉这一段”“加一段”三个按钮去掉；所选位置是某一章时每块有一个菜单：“这一块在剧情里变了……”“在剧情里删掉这一块……”，文末“在剧情里加一块……”，沿用现在的对话框、只留剧情这一种意图。
- **编辑**：一块一个代码输入框，按顺序排。上面一行：未提交几块、“已暂存”或“暂存失败”，“放弃”（要确认）与“提交”；没有改动时是“取消”。打开一个有暂存的条目直接进编辑。
- **块的操作**：
  - 在最前、在某一块后面加一块；
  - 从光标处拆开：前半留在原块（保留编号），后半成新的一块；
  - 并到上一块：文字接到上一块后面（空一行），这一块删掉；
  - 删掉，可以恢复。
  - 被剧情碰过的块（`touchedBy`）不能删、不能并进别的块，按钮不可用并写原因；能改字、能拆。
- **提交**：改过的块发 `set`（带 `read`），删掉或清空的发 `removeBlock`（带 `read`），新加的发 `addBlock`（`after` 是它前面最近的、留下来的初值块，没有就是 `null`），一批一条修订。一批最多 50 项是现有的上限，超了在那一行说明。
  - `value-conflict`：弹出逐块的对照（只标出两边不一样的那一截），作者逐块选“我的”或“现在的”，再提交；选“我的”是把那一块的 `read` 换成现在的原文再发（那一块已经不在时改成在原处加一块），选“现在的”是去掉我对那一块的改动。再发时世界又变了，再问。
  - 其它校验失败：失败详情里有是第几项，对回是哪一块，在那一块下面写原因并把焦点放进去。
  - 成功：回到阅读视图，出现有的保存提示（可撤销）。
- **世界变了**：有暂存时不动编辑框、也不提示，提交时才问；没有暂存时阅读视图照常更新。
- 页面状态里“在改哪一块”（改设定的那部分）与对应的对话框代码去掉；文字分页这一段从 `EntryPageHost.vue` 挪进新的组合式函数与组件，不再往这个九百多行的文件里加。

## 8. 不做与风险

**不做：**

- 自动分块、整篇提交（第 2 稿的 3.1 作废）；调换块的顺序（要调就剪切文字，或删了再加）。
- 富文本编辑器、换解析器（t38 及其后）；编辑时看值、插入条目引用与表达式的入口。
- 条目树像文件树一样用（下一个 Task）；欢迎页的设定入口；给 Agent 的新写法（现有的按块工具够用）。
- 简报按块扣秘密的粒度不变（块大扣得多，偏安全）。

**审查意见在这一稿里的去向**（与 resolution 不同的几条）：omp 第 5 条（拼成整篇再读边界会变）、第 7 条（整篇表达不了块的身份）、第 8 条（展开后的上限）、第 14 条（失败定位不到草稿块）都源于整篇提交，按块编辑以后不再有这个问题：界面发的就是对某一块的操作，失败回来的也是第几项。第 6 条（只带版本拦不住并发）改由各块的 `read` 把关（3.1 第 2 处）。

**风险：**

| 风险 | 怎么兜 |
|---|---|
| 已有的条目分得很细（样本里每段一块），编辑时是一串小编辑框 | “并到上一块”收拢；编辑框按需才建 Monaco；这是数据的现状，不是这一轮造成的 |
| 作者把所有东西写进一块，剧情替换与简报都变粗 | 开发者知悉；工具说明里写清什么时候该拆块；阅读视图的菜单只在选了某一章时出现，用到时作者自然会先拆 |
| 动了编辑区的页面合同，别的会话也在改编辑器插件 | 只加可选项；动手前并 master；编辑区的 e2e 守着 |
| 一页里很多个 Monaco | 进入视野或拿到焦点才建；S2 的组件测试与 S4 的 Lab 场景看二十块时能不能用 |
| 暂存与世界的事务不在一起 | 暂存里记请求 id，打开时按结局清理（3.3） |
| 作者以为关掉就是保存了 | 标签的圆点、再打开直接进编辑并写着未提交；条目树上的标记放到做树的那个 Task |
