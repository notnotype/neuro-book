# t28 实施计划（第 4 稿）：主文字按块编辑，暂存加提交，冲突按块判

2026-11-23 主会话按第二轮后端设计审查（omp，14 条，5 条阻断）改写。交互与开发者已定的九条不变；变的是提交怎样对内核说话、哪些块能做哪些操作、暂存怎样结算。逐条处理见 [`evidences/design-review-resolution-r2.txt`](evidences/design-review-resolution-r2.txt)。前几稿：第 1 稿 `8ba019e28`（一个解析器、富文本、整篇提交），第 2 稿 `0ab76478c`（整篇提交、内核对回各块），第 3 稿 `d9514f8c3`（按块编辑、逐块核对读到的值）。

## 1. Context

**为什么做。** 开发者 2026-11-23：先让“世界引擎能像文件系统一样记录东西”。现在改主文字要点“改这一段”、在对话框里改源文字。

**开发者已定的**（Work README 决定表 2026-11-23）：

1. **主文字就是一组带编号的块，系统不自动分块**，分块交给作者和 Agent。
2. **编辑按块来**：阅读视图点“编辑”后一块一个编辑框；想分才分（加一块、从光标处拆开、并到上一块、删掉）。新条目只有一块，用起来就是编辑一个文件。
3. 这一轮用**源文字**编辑，编辑框是 Monaco；富文本等 [t38](../t38-kernel-shared-parser/README.md) 之后。内核的解析器不动。
4. 改动自动暂存；点“提交”才发布成一条修订；Ctrl+S 等于提交；标签上有未提交的圆点。
5. **冲突按块判**：别处改的是作者没碰的块，直接保留；同一块两边都改了才问作者。
6. 继续用页面标签，给它补未提交的圆点与 Ctrl+S。
7. 直接编辑都算改设定；“这一块在剧情里变了”收进阅读视图里每一块的菜单。
8. 先保证功能与 UX，界面先不打磨。交互照 Lab 的交互稿 `EntryTextEditDraft`；“单独编辑一个块”这类调整放到用过以后。
9. 条目树像文件树一样用是紧接着的下一个 Task。

**开发者知悉的代价**：块的大小由人定以后，剧情里的文字变化整块替换、给写手的简报按块扣秘密、冲突按块、修订存整块的改前改后。

**第 4 稿相对第 3 稿变了什么**（主会话按审查定的，记进待确认、默认追认）：

1. **被剧情碰过的块只能改字**：不能删、不能拆、不能并（第 3 稿写的是还能拆）。拆与并会把文字从一条记录搬到另一条记录，别的章读到的就变了（审查第 9 条，已在真实内核上复现）。
2. **新块不能插在剧情加出来的块前面**：内核里改设定的块只能挂在初值的块后面，剧情加出来的块总是紧跟它的锚点，这个位置表达不出来（第 1 条）。紧跟在它们后面可以。
3. **提交带读取戳**：内核现有的 `readStamp` 要求“世界还是我读的那一版”。之间有任何别的写入，界面重读、把作者的改动对到新的块上、没有冲突就自动再发（至多 3 次），有冲突才问。第 3 稿的“逐块带读到的原文、版本冲突就抬版本再发”拦不住块换了来源、锚点被占这些情形（第 3 条）。
4. **不再按条目大小限制能不能编辑**：暂存只存动过的块，上限按这次改动实际的字节数判（第 11、13 条）。
5. **两个窗口同时改同一个条目的文字**：后写的那个窗口被告知，不自动覆盖对方的暂存（第 7 条）。
6. **提交的结果不明时**（断线、刷新）保持“正在确认”，只原样重发同一个请求，不换请求再发（第 8 条）。

**依据。** [`canon/revisions.md`](../../../../../docs/specs/canon/revisions.md) 输出 4、7、8、16、24、25；[`canon/author-ui.md`](../../../../../docs/specs/canon/author-ui.md) 输出 7、10、28、30、39、43；[`canon/rendering.md`](../../../../../docs/specs/canon/rendering.md) 输出 1、3；[`canon/worldlines.md`](../../../../../docs/specs/canon/worldlines.md) 输出 12；[`workbench/editor.md`](../../../../../docs/specs/workbench/editor.md) 输出 33、53；[`storage/persistence.md`](../../../../../docs/specs/storage/persistence.md)。

## 2. 技术选型

| 问题 | 选用 | 理由与否决 |
|---|---|---|
| 源文字的编辑控件 | Monaco：复用编辑器插件已有的加载器与主题（`editor/web/code/load-monaco.ts`、`monaco-theme.ts`），另做一个可嵌入的小组件 | 开发者定。现成的 `MonacoControl.vue` 绑的是文件文档，不能直接放进页面 |
| 提交 | 内核现有的三种操作 `set text[块 id]`、`addBlock`、`removeBlock`，一批一条修订，带现有的读取戳 `readStamp` | 读取戳在写队列里比、判过请求 id 之后比（探针 `stamp.ts`）。否决：给 `removeBlock` 加 `read`、让块上的 `value-conflict` 带两边原文（第 3 稿）——有了读取戳它们是多余的，冲突的两边由界面重读后自己对 |
| 哪一块能做什么 | 内核给一个读取 `textBlocks`，与写入的拒收用同一份判断 | 界面自己按“最近一次改动”猜会放出必败的按钮（第 5 条） |
| 暂存放哪 | 插件的项目记录（`scope: project`、`locality: local`、按条目 id 分键），条件写（`expect`） | 页面标签的状态刷新后不保留；条件写让两个窗口不会互相盖掉 |
| 未提交的圆点与 Ctrl+S | 给编辑区的页面声明加两个可选项 | 同第 3 稿 |

## 3. 关键设计

### 3.1 内核：`packages/nb-canon/src/`

**写入补四处**（`world/entry-edits.ts`、`core/schema.ts`）：

1. **`addBlock` 的 `after: null` 与同一处几项的先后。** `after` 写 `null` 是放在最前，两种意图都是；不写仍是放在最后（剧情变化是这个位置上最后一块之后）。同一批里落在同一处的几项按写的先后排：改设定是在初值里依次接在上一项后面；剧情变化是后一项的锚点换成这一批里上一项刚发的块 id。只改这一次请求怎样排，补丁的执行（`apply.ts`）与已有日志的重放不变。Agent 工具 `canon_write` 把 `null` 原样传下去。
2. **删初值的块：被当作锚点也算被碰过。** 现在只查“地址是这一块”的补丁；剧情加出来的块以它为锚点时删它，那条变更就套不上、连带的块跟着消失（已复现）。`touchedBy` 的匹配加上 `addBlock` 的 `after` 是它，拒收仍是 `element-from-change`、`reason` 列出变更。
3. **已删除的条目上加块、删块拒收**（`field-unavailable`，带 `op`）：现在删块会成功、加块得到 `result-mismatch`（探针 `stamp.ts`）。
4. **块的原文过不了校验时带序号。** 校验细项现在指到候选对象的路径（`init.text[b3]`、某条变更的 `patches[0]`），对不回是第几项。定方案时已经知道每一项写到哪，`checkPlan` 据此给能对上的细项补 `op`（`Problem` 加可选的 `op`）。不解析消息里的行列。

**读取加一个** `textBlocks`（`service/service.ts`、远程合同、`world/text-blocks.ts`）：给条目 id 与读取位置（只有实际模式），返回读取戳、**服务器解析后的位置**（写明线）与这个位置上的每一块：

| 字段 | 意思 |
|---|---|
| `id`、`source` | 块的编号与原文 |
| `write` | 改设定时改这一块的字会写到哪：`init`（初值）、`change`（给出它的那条变更，另带 `change` 是哪条）、`none`（不能这样改：从别的线带过来的） |
| `fixed` | 碰过它的变更 id（地址是它、或以它为锚点；这条线上没撤销的，不看先后，与删块的拒收同一个函数）。非空就不能删 |
| `anchor` | 改设定时“放在这一块后面”该写的 `after`：初值里的块是它自己；剧情加出来的块是它沿锚点追到的那个初值的块，追到最前是 `null` |
| `init` | 在初值里是第几块；不在初值里时没有 |

条目不存在或已删除为 `null`；位置的章或线不在时是 `chapter-not-found`、`line-not-found`。算法：扫一遍这条线上的变更，按块记下碰过它的变更与每个增块的锚点；`write` 与 `routeSet` 的块路由共用一个函数（主线上没被碰过的初值块直接是 `init`，其余才取来历）。只在进入编辑、重读时调用，不加到通用的 `entry` 读取上。

不改的：补丁的执行、修订的形状、日志格式、`set` 的路由；`splitBlocks` 没有产品里的调用方（审查核对过），留着，t38 定去留。块 id 在删掉尾块后会被新块复用（审查第 3 条）：有了读取戳，旧稿不可能写到复用的 id 上，不改发号。

### 3.2 页面标签的未提交与保存、可嵌入的代码输入框：`packages/neuro-book/src/plugins/editor/`

与第 3 稿相同。`EditorPageImplementation`（`web/pages.ts`）加两个可选项，按参数取：

- `uncommitted?(arg): boolean`：响应式地读。标签条的圆点对页面标签取它；公开状态 `dirty` 在活动标签是页面时取它。
- `commit?(arg): Promise<void>`：活动标签是页面且有它时，`nbook.editor.save`（Ctrl+S、命令面板）调用它。没有 `commit` 的页面与文件标签的行为不变。

不加关闭与离开时的询问。状态栏的未保存计数、关窗结算只算文件。

**代码输入框**：编辑器插件经合同多交一个组件（暂名 `CodeInput`）：属性是文字、语言、只读、可读名，事件是文字变了、请求保存（在它里面按 Ctrl+S）、光标位置。高度随内容。底下用现有的 `loadMonaco` 与主题。文字由外面给：外面换了文字时换内容，自己打字引起的回声不重设。编辑框进入视野或拿到焦点时才建 Monaco，之前画等宽的原文。

### 3.3 主文字的稿：`packages/neuro-book/src/plugins/canon/web/`

分两层：纯函数的稿模型（`text-draft.ts`，不碰界面与存储，表格测试）与窗口里的暂存登记（`text-drafts.ts`）。

**稿的形状**（也是存下来的值）：

```ts
interface TextDraft {
    at: ReadPosition;                  // textBlocks 回来的位置，写明线；稿只能在实际模式下开
    order: string[];                   // 现在的块序：旧块写块 id，新块写本地键（"n1"…）
    base: Record<string, string>;      // 动过的旧块读到的原文（改了字、删了）；没动过的不存
    texts: Record<string, string>;     // 动过的旧块与新块现在的文字
    removed: string[];                 // 删掉的旧块（并掉的也在这里）
    pending?: {requestId: string; stamp: {version: number; input: string}};
}
```

拆开是“原块改字加一个新块”，并是“上一块改字加这一块删掉”，不另设操作。没动过的块只在 `order` 里占一个 id，文字每次从世界读，所以稿的大小跟着改动走。

**三个纯函数**：

- `allowed(read, draft)`：每一块能做什么，照 `textBlocks` 的字段：
  - 改字：`write` 不是 `none`。
  - 删、拆：`write` 是 `init` 且 `fixed` 为空（新块随便）。
  - 并到上一块：这一块能删；上一块能改字；两块都是旧块时，上一块也要是没被碰过的初值块，且两块在初值里相邻（`init` 差 1）。
  - 在某处加一块：这一处后面紧挨着的旧块在初值里、或后面没有旧块了。也就是不能插在剧情加出来的块前面。
- `rebase(draft, read)`：把稿对到新读的块上，返回新稿与冲突。
  - 没动过的块：照新读的来（别处删的拿掉，别处加的插在它新读的位置）。
  - 动过的旧块，现在的原文与读到的相同：留着；它是我要删的、而现在不能删了（`fixed` 非空或 `write` 变了），记一条冲突“现在不能删”。
  - 现在的原文变了：与我的结果相同就当作已经一致、不再算我动过；否则记冲突“两边都改了”（给出我的与现在的）。
  - 这一块不在了：我是删它，当作已经一致；我是改它，记冲突“这一块被删了”。
  - 新块跟着它前面的那个键走；前面的键不在了就接到再前面的。
  - 解决冲突（界面逐条选，也是纯函数）：“我的”把读到的原文换成现在的；“现在的”去掉我对这一块的改动；被删了的可以“当作新加的一块留着”或“去掉”；“现在不能删”只能撤掉删除。
- `compile(draft, read)`：没有待解决的冲突时编成一批操作：改了字的 `set`（带 `read`，多一道保险）、新块 `addBlock`（`after` 取它前面最近的旧块的 `anchor`，前面没有旧块是 `null`；同一处的几块按顺序）、删掉的 `removeBlock`，顺序是改、加、删（加块要用的锚点可能正是要删的块）。另给出每一项对应稿里的哪个键、放不进去的新块（那一处表达不出来）、项数。净变化是零时不发请求，直接删暂存。

**提交**（`text-drafts.ts`）：

1. 读 `textBlocks`，`rebase`；有冲突交界面问；`compile`。
2. 冻结：把请求 id 与这次读的戳写进稿的 `pending`、条件保存，**存储确认了才发**。`pending` 在的期间稿的内容不能改（编辑框只读），所以请求能逐字重建。
3. 发 `editEntries`：`baseVersion` 与 `readStamp` 都是这次读的，位置是稿的 `at`，意图是改设定。
4. 结果：
   - 发布了（或 `repeated`）：按 `pending` 那一版的 revision 条件删除暂存。
   - `stale-read`、`version-conflict`、`value-conflict`：世界在读与写之间变了。清掉 `pending`，回到第 1 步；自动至多 3 次，之后告诉作者别处一直在改、稍后再提交。
   - 校验没过：清掉 `pending`，按 `op` 把原因写到对应的块下面。
   - 结局不明（`unknown-outcome`、`write-failed`、连接断了）：**留着 `pending`**，页面写“正在确认上一次提交”，连上以后原样重发同一个请求。内核先判请求 id：已经发布就返回第一次的结果；没发布过就这一次发布；`request-id-reused` 说明那个 id 已经发布过，同样算已发布。迟到的原请求带着同一个戳，世界一动它就过期，不会多出一次修订。不拿 `outcome` 的“没发布”当定论（审查第 8 条：它可能早于原请求落盘）。
5. 打开一个带 `pending` 的稿：从第 3 步接着做。

**暂存登记**：

- 记录 `canon.text-drafts`，`scope: project`、`locality: local`、按条目 id 分键、上限 1 MiB。窗口里一份登记，不随页面组件卸载（圆点要给非活动的标签用）。
- 这个窗口对一个条目的写是串行的，都带上一次确认的 revision。写的时机：输入停 300 毫秒、编辑框失焦、页面转入后台。放弃与提交成功以后，迟到的保存按本地的代次丢掉，不会把稿写回来。
- 条件写得到 `conflict`（别的窗口写过这条记录）：停止自动暂存，页面写“另一个窗口也在改这个条目的文字”，两个按钮：“用这里的”（读最新的 revision 后覆盖）、“换成那边的”。两边的内容都不自动丢。
- 存不下（`too-large`）或写失败：页面写“没有暂存”，内容留在内存里；这时关掉会丢，那一行写明。编成的请求超过 Canon 的消息预算、或超过 50 项：提交不可用并写原因，稿照常能改、能暂存。
- 有稿时条目页的位置与“按计划”开关锁在稿的位置上。稿的位置读不出来了（章被删、线不在）：编辑区只列出稿里动过的文字（能复制）、只能放弃。
- 条目被删、世界只读、别人独占、断开时：暂存留着，“提交”不可用并写原因。

### 3.4 文字分页：`packages/neuro-book/src/plugins/canon/web/components/`

- **阅读视图**：现有的 `EntryText`。右上角“编辑”；没有主文字时是“开始写”；按计划模式下不可用（现有的写入口同样）。“改这一段”“删掉这一段”“加一段”三个按钮去掉；所选位置是某一章时每块有一个菜单：“这一块在剧情里变了……”“在剧情里删掉这一块……”，文末“在剧情里加一块……”，沿用现在的对话框、只留剧情这一种意图。这三个对话框的写入带打开时的读取戳；被拦下（`stale-read`、`version-conflict`）时重读这一块：原文没变就带新戳再发，变了就在对话框里写明并把“原来的”换成现在的，作者的输入不动（第 10 条）。
- **编辑**：一块一个代码输入框，按顺序排。上面一行：未提交几块、暂存的状态，“放弃”（要确认）与“提交”；没有改动时是“取消”。打开一个有稿的条目直接进编辑。
- **块的操作**：加一块（最前、某一块后面）、从光标处拆开（前半留在原块、编号不变）、并到上一块（中间空一行）、删掉（可以恢复）。能不能做照 `allowed`，不能做的按钮不可用并写原因（“第 3 章的剧情改过这一块，只能改字”“这里紧挨着剧情加出来的块”）。
- **冲突对话框**：`rebase` 给出的冲突逐条列：两边都改了的并排写“现在的”与“我的”、只标出不一样的那一截，逐条选；被删了的与现在不能删的照 3.3 的选项。确认后接着提交；再发时又变了再问。
- **成功**：回到阅读视图，出现有的保存提示（可撤销）。
- **世界变了**：有稿时不动编辑框、也不提示，提交时才对；没有稿时阅读视图照常更新。
- 页面状态里“在改哪一块”（改设定的那部分）与对应的对话框代码去掉；文字分页这一段从 `EntryPageHost.vue` 挪进新的组合式函数与组件。

## 8. 不做与风险

**不做：**

- 自动分块、整篇提交；调换块的顺序。
- 被剧情碰过的块的拆与并、插在剧情加出来的块前面（要有内核管着同一条剧情来源的结构操作才做得对，等用到再说）。
- 富文本编辑器、换解析器（t38 及其后）；编辑时看值、插入条目引用与表达式的入口。
- 条目树像文件树一样用（下一个 Task）；欢迎页的设定入口。
- 给 `removeBlock` 加读到的值、块 id 永不复用：界面与 Agent 工具的写入都带读取戳（Agent 的从 t37 起），用不上。
- 稿的位置失效以后改绑到别的位置（只给复制与放弃）。

**风险：**

| 风险 | 怎么兜 |
|---|---|
| 读取戳比版本冲突严：别处写得勤时提交要重试 | 重读、对一遍、再发都是自动的，一次往返几十毫秒；3 次不成才告诉作者。现在只有一个作者、Agent 这条线暂停 |
| `rebase` 的情形多，漏一种就丢改动或写错块 | 纯函数，逐情形的表格测试；发出去以后还有读取戳与 `set` 的 `read` 两道 |
| 界面的“能不能做”与内核的拒收不一致 | 同一个函数算；用例断言 `fixed` 非空当且仅当删块被拒收 |
| 已有的条目分得很细，编辑时是一串小编辑框 | “并到上一块”收拢（只对没被碰过的初值块）；编辑框按需才建 Monaco |
| 作者把所有东西写进一块，剧情替换与简报都变粗 | 开发者知悉；工具说明里写清什么时候该拆块 |
| 动了编辑区的页面合同，别的会话也在改编辑器插件 | 只加可选项；动手前并 master；编辑区的 e2e 守着 |
| 作者以为关掉就是保存了 | 那一行分清“已暂存”与“没有暂存”；标签的圆点、再打开直接进编辑 |
