# t28 实施计划（第 2 稿）：主文字用源文字编辑，暂存加提交，冲突按段判

2026-11-23 主会话按三份设计审查与开发者的决定改写，待开发者确认。第 1 稿（一个解析器、富文本编辑器、整篇提交）见提交 `8ba019e28`；逐条处理见 [`evidences/design-review-resolution.txt`](evidences/design-review-resolution.txt)。

## 1. Context

**为什么做。** 开发者 2026-11-23：先让“世界引擎能像文件系统一样记录东西”。现在改主文字要点“改这一段”、在对话框里改源文字。

**这一轮的范围**（开发者同日定，Work README 决定表）：

1. 主文字这一轮用**源文字**编辑（“先用代码编辑器代替都可以”“这种纯文本的编辑我觉得可以”），富文本编辑器等 [t38](../t38-kernel-shared-parser/README.md) 换完解析器再接。内核的解析器这一轮不动，所以只有内核一个解析器在读文字。
2. 文字分页默认是阅读视图（现有的渲染），点“编辑”换成整篇源文字。
3. 编辑中的内容自动暂存；作者点“提交”才发布成一条修订；Ctrl+S 等于提交；标签上有未提交的圆点。
4. **冲突按段判**：别处改的是作者没碰的段落，直接保留；同一段两边都改了才问作者。
5. 继续用页面标签，给它补未提交的圆点与 Ctrl+S。
6. 直接编辑都算改设定；“这段文字在剧情里变了”收进每一块的菜单。
7. 先保证功能与 UX，界面先不打磨（开发者看过 Lab 的交互稿 `EntryTextEditDraft` 后说的）。
8. 条目树像文件树一样用是紧接着的下一个 Task；换解析器是 t38。

**依据。** [`canon/revisions.md`](../../../../../docs/specs/canon/revisions.md) 输出 7、8、16、25；[`canon/author-ui.md`](../../../../../docs/specs/canon/author-ui.md) 输出 7、10、28、30、39；[`canon/rendering.md`](../../../../../docs/specs/canon/rendering.md) 输出 1、3；[`workbench/editor.md`](../../../../../docs/specs/workbench/editor.md) 输出 33、53；[`storage/persistence.md`](../../../../../docs/specs/storage/persistence.md)；审查：[omp](evidences/design-review-backend-omp.txt) 第 6 到 11、14 条，[Sonnet](evidences/design-review-frontend-sonnet.txt) 第 2、3、5、6、9、10、15、17、18 条，[独立设计](evidences/independent-design.txt)问题 3、5、6。

## 2. 技术选型

| 问题 | 选用 | 理由与否决 |
|---|---|---|
| 源文字的编辑控件 | Monaco：复用编辑器插件已有的加载器与主题（`editor/web/code/load-monaco.ts`、`monaco-theme.ts`），另做一个可嵌入的小组件 | 行号、查找替换、撤销历史都有。现成的 `MonacoControl.vue` 绑的是文件文档，不能直接放进页面。仓库里没有封装好的 CodeMirror（搜过全部包，只有 JSON 查看器的第三方库内部用到）。否决：nb-ui 的 `Textarea`（没有查找与撤销历史，长文难用） |
| 整篇文字对回各块 | 内核里自写：先把没动过的块按原文整段认回去，剩下的缺口交给内核现有的 `splitBlocks` | 没动过的块不重新切，边界不会漂。不引 diff 库：输入是几十到几百块的字符串 |
| 暂存放哪 | 插件的项目记录（`scope: project`、`locality: local`、按条目 id 分键） | 页面标签的状态刷新后不保留；`local` 是这台机器这个浏览器配置自己的，不跟别的客户端共用 |
| 未提交的圆点与 Ctrl+S | 给编辑区的页面声明加两个可选项 | 页面组件只在标签活动时存在，挂在组件上非活动标签就没有圆点（Sonnet 第 2 条、独立设计问题 6）。否决：把条目主文字做成编辑区的一种文档（Sonnet 第 21 条）——要给编辑区加文件之外的文档来源、页面与文档的关联、只能手动保存的模式、刷新后保留未保存内容四样，改动面没摸清，开发者这一轮定了用页面标签 |

## 3. 关键设计

### 3.1 整篇提交：`packages/nb-canon/src/world/`

`editEntries` 加一项操作：

```ts
{op: "text", entry: Id, base: {id: Id, source: string}[], value: string, resolve?: Record<Id, "mine" | "theirs">}
```

`base` 是作者进入编辑时读到的各块（按顺序），`value` 是交回的整篇。读取位置、线与模式用这一批的 `position`（必须写明线，没写拒收 `line-required`，同带值回写）。

**对回各块**（新的纯函数 `alignText(base, value)`，单独成文件、单独测）：

1. 换行统一成 LF。
2. `base` 的每一块在 `value` 里找“前后都是空行或文字两端”的整段出现，取先后不交叉、块数最多的一组，算**没动过**（保留 id，不重新切）。
3. 相邻两个没动过的块之间是一个缺口：缺口里的文字用 `splitBlocks` 切成新段；缺口里原有的块与新段按先后配对成**改**（保留 id），多出的新段是**加**，多出的原块是**删**。
4. 量有上限：`value` 不超过 256 KiB、切出的段不超过 2000；超了拒收 `too-large`。这一项内部展开多少步不受“一批 1 到 50 项”的限制，那个数只管公开的项数（omp 第 8 条）。

**核对与冲突**（在写队列里、对当前的世界做，omp 第 6 条）：

- 作者**动过**的块（改或删）：它现在的原文必须等于 `base` 里的；不等或已经不在，记成一处冲突。
- 作者**没动过**的块不核对：别处改了、删了、加了，都照现在的留着。
- 有冲突而 `resolve` 没给全时整批拒收，失败码 `text-conflict`，详情逐块给出 `{id, base, current（没了为 null）, mine（删为 null）}`。`resolve` 里 `mine` 是照我的改（那一块已经不在时，改成在原来的位置加一块），`theirs` 是这一块不动。确认之后世界又变了，会得到新的冲突，再问一次。
- 这样判冲突不看条目对象的版本：作者自己在别的分页改字段、改名不会被当成“别处改过”（Sonnet 第 6 条）。

**落成修订：**

- 改、删走现有的路由（改设定写回给出这段文字的那条记录；来自剧情变更的块按改设定删时照旧拒收 `element-from-change`）。
- 加的块直接插进初值的文字里它该在的位置（前面最近的一块初值块之后，前面没有就在最前），同一处连续几块保持先后。公开的 `addBlock` 做不到这两样（不写 `after` 是放最后，同一个 `after` 连加几块会倒序），所以这一步在内核里直接排，不经 `addBlock`。
- 调换段落顺序（剪切再粘贴）落成“删一块、加一块”，那一块得到新 id；被剧情改过的块因此挪不动，照 `element-from-change` 拒收并指到那一块。
- 没有任何差别时不发布，结果写明“没有改动”（不产生空修订，omp 第 8 条）。
- 同一批里对同一个条目另有 `text[…]`、`addBlock`、`removeBlock` 时拒收（`duplicate-address`）。
- **失败指得到地方**（omp 第 14 条）：校验不过时，详情带这一处在 `value` 里的起止偏移（内核知道每个新段在整篇里的位置），界面据此选中，不解析文案。

远程合同不加方法。`canon_write` 这一轮不加这一项。

### 3.2 页面标签的未提交与保存：`packages/neuro-book/src/plugins/editor/`

`EditorPageImplementation`（`web/pages.ts`）加两个可选项，和 `title?(arg)` 一样按参数取：

- `uncommitted?(arg): boolean`：响应式地读。标签条的圆点（`tab.dirty`）对页面标签取它；公开状态 `dirty` 在活动标签是页面时取它。
- `commit?(arg): Promise<void>`：活动标签是页面且有它时，`nbook.editor.save`（Ctrl+S、命令面板）调用它。

不加关闭与离开时的询问：内容已经暂存，关掉再开还在。状态栏的未保存计数、关窗结算只算文件，不变。

**可嵌入的代码输入框**：编辑器插件经合同多交一个组件（暂名 `CodeInput`）：属性是文字、语言、只读、可读名，事件是文字变了、请求保存（它里面按 Ctrl+S 时）。底下用现有的 `loadMonaco` 与主题；不带文件文档的东西。文字由外面给：外面换了文字（放弃、别处的新内容）时换模型的内容，自己打字引起的回声不重设（Sonnet 第 12 条）。

### 3.3 暂存：`packages/neuro-book/src/plugins/canon/web/`（新 `text-drafts.ts`）

窗口里一份暂存登记，不随页面组件卸载（圆点要给非活动的标签用）。

- **记录**：`canon.text-drafts`，`scope: project`、`locality: local`、按条目 id 分键、上限 1 MiB。值是 `{text, base: {position（写明线）, blocks: [{id, source}]}, pending?: {requestId}}`。
- **一个条目一份**（omp 第 9 条取“单份”）。有暂存时条目页的位置选择与“按计划”开关锁在暂存的位置上，要换先提交或放弃；别的窗口打开同一个条目看到的是同一份。
- **什么时候写**：输入停 300 毫秒、编辑框失焦、页面转入后台时。写失败（存不下、断开）时页面上写“暂存失败”并留着内存里的内容，不显示“已暂存”（Sonnet 第 9 条）。最后不到一秒的输入来不及写就关窗的情形不兜（Spec 写明）。
- **能整篇编辑的大小**：主文字的 UTF-8 不超过 200 KB（暂存要同时存现稿与各块原文，提交的请求上限约 983 KB，omp 第 11 条）。超过时“编辑”不可用并说明，块的菜单还能用。
- **有没有未提交的内容**：暂存的文字与 `base` 各块连起来不同（Sonnet 第 10 条）。改回原样就不算，暂存随之删掉。
- **提交的结局**（omp 第 10 条）：发出前把这次的请求 id 写进暂存；成功后删暂存；回复丢了或刷新了，下次打开先按请求 id 查结局（`outcome`），已发布就删暂存，没发布留着。提交在途时编辑框只读。
- 条目被删、世界只读、别人独占、断开时：暂存留着，“提交”不可用并写原因（Sonnet 第 15 条）。

### 3.4 文字分页：`packages/neuro-book/src/plugins/canon/web/components/`

- **阅读视图**：现有的 `EntryText`（值显示成数、点开来历）。右上角“编辑”；没有主文字时是“开始写”。“改这一段”“删掉这一段”“加一段”三个按钮去掉；所选位置是某一章时每块有一个菜单，里面是“这一段在剧情里变了……”“在剧情里删掉这一段……”，文末“在剧情里加一段……”，沿用现在的对话框、只留剧情这一种意图（按钮用 nb-ui 的菜单，键盘可达，Sonnet 第 7 条）。
- **编辑**：整篇源文字（各块用空行连起来）放进代码输入框。上面一行：未提交的标记与“已暂存”或“暂存失败”，“放弃”（要确认）与“提交”；没有改动时是“取消”。打开一个有暂存的条目直接进编辑。
- **提交**：一项 `text`。成功回到阅读视图并出现有的保存提示（可撤销）；`text-conflict` 弹出逐段的对照（只标出两边不一样的那一截），作者逐段选，再提交；其它校验失败在那一行写原因并选中详情指的那一段。
- **世界变了**：有暂存时不动编辑框，也不提示（开发者定的是“提交时告诉”，Sonnet 第 6 条）；没有暂存时阅读视图照常更新。
- 页面状态里“在改哪一块”（改设定的那部分）与对应的对话框代码去掉；`EntryPageHost.vue` 里文字分页的这一段挪进新的组合式函数，不再往这个九百多行的文件里加。
- 交互稿定的走法照做：Lab 的 `EntryTextEditDraft`。

## 8. 不做与风险

**不做：**

- 富文本编辑器、换解析器（t38 及其后）；编辑时看值、插入条目引用与表达式的入口（等富文本）。源文字里表达式与标签照字面显示。
- 条目树像文件树一样用（下一个 Task）；欢迎页的设定入口。
- 给 Agent 的整篇写法。
- 编辑中预览（内核还不能按一段没提交的文字渲染）。

**风险：**

| 风险 | 怎么兜 |
|---|---|
| 对回各块认错（两段原文相同、块里本身有空行） | 相同的两段认哪一个结果都一样（都没动）；块按整段原文认、不按空行切，所以块里的空行不影响；性质测试用随机的块与随机的编辑 |
| 动了编辑区的页面合同，别的会话也在改编辑器插件 | 只加可选项；动手前并 master；编辑区的 e2e 守着 |
| Monaco 在页面里与编辑区的键位、焦点打架 | 代码输入框自己接 Ctrl+S 并发事件，不指望编辑区的键位；S2 的 dom 测试与 e2e 断言焦点 |
| 暂存与世界的事务不在一起（提交成功、删暂存失败） | 暂存里记请求 id，打开时按结局清理（3.3） |
| 作者以为关掉就是保存了 | 标签的圆点、再打开直接进编辑并写着未提交；条目树上给有暂存的条目一个标记（下一个 Task 做树时加） |
