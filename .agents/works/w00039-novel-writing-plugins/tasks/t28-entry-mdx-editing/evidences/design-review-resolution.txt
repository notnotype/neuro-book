后端（omp）
1. 叶子 raw 回搜会静默定位错（阻断）：成立，主会话读了它的反例（链接标题里有同样的表达式）。这一轮不换解析器，转 t38（已写进 t38 README 的“定位”）。
2. marked 的普通文字兜底与 acorn 的前缀解析留不住写入合同（阻断）：成立。转 t38（“写入合同”）。
3. 合法的旧表达式被吞进不透明容器时，简报关卡从扣整块变成放行（阻断）：成立，omp 用真实的简报入口证实旧内核会扣下。转 t38（“保密关卡”）。
4. 带值回写另有一套对 Markdown 上下文的猜测（重要）：成立，其中链接地址与标题里的花括号是现有缺口。转 t38（“带值回写”）。
5. 存储块分别解析与拼成整篇解析结果不同（阻断）：成立。这一轮改法：编辑器是纯文本，不解析；内核对回各块时把没动过的块按原文整段认回去、不重新切，只把动过的缺口交给 splitBlocks（计划 3.1）。富文本那时按块读入的做法转 t38 之后。
6. 只带世界版本拦不住并发写入（阻断）：成立，改。请求带作者读到的各块（base）；在写队列里对当前的世界核对动过的块；位置必须写明线（计划 3.1）。
7. 整篇文字表达不了块的顺序与身份（阻断）：成立，改。base 带 id，没动过的认回原 id；加的块由内核直接排进初值（最前、连续几块的先后都对）；调换顺序落成删一块加一块、得到新 id，被剧情改过的块照旧拒收并指到那一块。两段原文相同时认哪一个结果一样，接受。
8. 展开后的上限与零改动的发布没有定义（重要）：成立，改。公开的项数与内部展开分开，另定整篇 256 KiB、2000 段的上限；没有差别不发布（计划 3.1）。
9. 暂存只按条目寻址，没定窗口、位置与线的归属（重要）：成立，改。取“一个条目一份”：locality 用 local，暂存记着位置（写明线），有暂存时位置与“按计划”锁住（计划 3.3）。
10. 暂存与发布缺待确认态（重要）：成立，改。发出前把请求 id 写进暂存，下次打开按结局清理；提交在途时编辑框只读；失焦与转入后台时写暂存。最后不到一秒来不及写的情形不兜，写进 Spec（计划 3.3）。
11. 1 MiB 暂存上限与能提交的范围不一致（重要）：成立，改。能整篇编辑的主文字不超过 200 KB，超过时“编辑”不可用、块的菜单还能用（计划 3.3）。
12. 文法子路径不等于纯内核的依赖闭包（重要）：成立。转 t38（“共用的文法放在哪个包”）。
13. S2 提前换掉作者渲染的形状、消费方到 S7 才迁（重要）：成立。这一轮不改渲染的形状（阅读视图照用 EntryText），不再适用；富文本那时生产与消费放在同一片。
14. 批量失败定位不到作者刚编辑的草稿块（重要）：成立，改。text 操作的失败带这一处在整篇里的起止偏移（计划 3.1）。
15. 现有规模脚本给不出新解析器的冷读证据（建议）：成立。解析器的部分转 t38；对回各块的工作量在 3.1 里设了上限，不做全文的二维对比。

前端（Sonnet）
1. 工具栏与菜单的动作经编辑区的活动句柄，页面里点不动（阻断）：成立，主会话在 spike 上实测属实。这一轮没有工具栏（代码输入框自带键位），不适用；富文本那时要么让编辑区的命令认页面里的编辑器、要么组件自带本地执行，记在 t28 README 的 spike 结论里。
2. 未提交与保存建在页面组件上，非活动标签没有圆点，保存命令不通（阻断）：成立，改。挂到 EditorPageImplementation 上，暂存登记不随组件卸载（计划 3.2、3.3）。独立设计得出同一结论。
3. 没有正在提交的状态（重要）：成立，改。提交在途只读，请求 id 进暂存（计划 3.3）。
4. 按顺序贴 parts 在有暂存时贴错值（重要）：成立。这一轮编辑时不显示值，不适用；转富文本（按原文键值，或内核给“按一组原文求值”的读法）。
5. 暂存没说位置、按计划、窗口的线（重要）：成立，改（同 omp 第 9 条）。
6. 冲突按条目对象的版本太粗；提示没说改了什么；放弃没有确认；“世界一变就提示”比已定的多走一步（重要）：成立，改。按块判；冲突的对话框逐段给出两边并标出不同；放弃要确认；有暂存时世界变了不提示，提交时才问（计划 3.1、3.4）。
7. 键盘与读屏（重要）：部分适用，改。块的菜单用 nb-ui 的菜单、键盘可达；值的原子节点那一条转富文本。
8. 块菜单的块与内核的块不是一回事（重要）：这一轮菜单在阅读视图里，EntryText 的块就是内核的块，不适用；转富文本。
9. 暂存自己的失败没有状态（重要）：成立，改（计划 3.3、3.4 的“暂存失败”）。
10. “有没提交的内容”没有定义（重要）：成立，改（计划 3.3）。
11. 条目语言没有章节方言的节点时动作没有防护（重要）：转富文本。spike 里实测过：包一层当作不可用能避免抛错，但不是正式的机制。
12. 嵌入组件没处理受控文字的回声与外部重载（重要）：对代码输入框同样成立，改（计划 3.2）。markdown 的懒加载约定那一半转富文本。
13. 取代 EntryText 时现有能力没有对照（重要）：这一轮不取代 EntryText，不适用；转富文本。
14. 版面：嵌套滚动、提交条的位置、390 像素（重要）：部分适用。提交那一行在分页内容的最上面、随页面滚动粘住；390 宽在 S4 的 Lab 场景里量。开发者 2026-11-23 说界面先不打磨，只保证不溢出与能操作。
15. 只读各情形下有暂存时怎么办（重要）：成立，改（计划 3.3 最后一条）。
16. 与章节编辑器相比没说做不做的项（重要）：这一轮明确不做插入条目引用与表达式的入口、图片粘贴（计划“不做”）；撤销历史由 Monaco 给。记为已知的不足，等富文本。
17. 关掉页面后没提交的内容没有痕迹（重要）：部分改。标签的圆点、再打开直接进编辑并写着未提交；条目树上的标记放到做树的那个 Task。
18. “刷新、关窗口都不丢”按写入链路不成立（建议）：成立，改措辞与做法：300 毫秒、失焦、转入后台时写；最后不到一秒不兜，Spec 写明。
19. 过渡与界面文字（建议）：过渡照交互稿的做法保留（阅读与编辑的切换、那一行的出现）；文字用交互稿里的。开发者说界面先不打磨。
20. Spec 改动范围与验收映射漏项（建议）：成立，第 2 稿的第 4、6 节重写。
21. 上游选择：为什么不把条目主文字做成编辑区的一种文档（建议）：写进计划第 2 节。主会话向开发者提过两条路（页面标签加口子；做成文档），开发者这一轮选页面标签。做成文档要给编辑区加四样（文件之外的文档来源、页面与文档的关联、只能手动保存的模式、刷新后保留未保存内容），改动面没摸清。

独立设计（与计划第 1 稿不同、被采纳或记下的）
- “以我的为准”只套用“起点到草稿”的差，不整篇覆盖：采纳（计划 3.1 的核对与 resolve）。
- 有暂存时锁住位置选择：采纳（计划 3.3）。
- 页面合同加 uncommitted、commit：采纳（计划 3.2）。
- 换序时不静默换 id：这一轮落成删一块加一块，被剧情改过的块拒收；不另做提示。
- addBlock 加 sources、提交前用 previewEntries 预检：没采纳前者（加的块由 text 操作在内核里直接排，不改公开的 addBlock）；预检没采纳（失败时详情已带位置，少一次往返）。
- 解析器放 nb-markdown 的纯入口、差分与随机测试、读法变化的表、容器里的多行表达式直接拒收：转 t38。
- 按一组原文求值的读方法、值与条目引用的输入规则：转富文本。

第 2 稿的后端部分（3.1 的 text 操作、3.3 的暂存）是新的核心规则，开发者确认后再交 omp 审一轮；前端部分照审查建议落地，不再开设计审查。
