# nb-story 与 nb-canon 的剧情模型对照

路径省略前缀：nb-story 为 `packages/nb-story/src/`，canon Spec 为 worktree 的 `docs/specs/canon/`。标“推断”的没有运行证据。

## 1. nb-story 的剧情模型

所有记录都挂在阅读位置 `{chapter, paragraph}` 上（`core/dataset.ts:41`）：记录的 `at` 取出处最后一段，不晚于阅读位置才可见（`core/position.ts:17`）。

| 记录 | 字段与来源 | 查询 |
|---|---|---|
| 说法 `dataset.ts:94-126` | 12 类 `family`、出处（渠道、说话人、听者、`mode`）、`kind` fact/belief/claim、`holder`、`certainty`、`rel`（印证/反驳/修正）、`tier`。模型写，`kind` 与 `holder` 由程序按渠道填 | `entity.statements`（`queries/entities.ts:145`） |
| 情节 `130-145` | 在场者（含 `as` 化名）、步骤、结果、地点、时间点、6 种连接（`causes`、`motivates`、`enables` 等）；每 5 章整理出主线 `arcs` | `episodes.list`（`queries/episodes.ts:30`） |
| 故事时间 `64-92` | `day`、`part`、`rel`、`order`，段落块带 `flashback`。模型只写相对天数，程序累加并拓扑排序（`ingest/compile.ts:657-751`） | `timeline`（`queries/timeline.ts:31`）；补叙 = 早于前面章节已写到的点 |
| 实体经历 | 无专门记录，由情节在场者、说法、账本、知情、整理稿 `history` 与 `goals` 拼成。情节只按 `who` 匹配，只当地点的物品和国家不算（`queries/context.ts:106-122`，推断） | 人物卡各列表 |
| 知情 `147-160`、秘密 `128` | 6 种状态。心理活动推出相信，写了听者的台词推出听说，本人的马甲身份推出知道（`compile.ts:583-613`） | `secrets.matrix`（`queries/secrets.ts:34-104`）；没记录显示“没有记录”，不等于不知道 |
| 悬念 `181-197` | `raised/partial/answered` 分次进展，答案指向说法，带可靠度 | `questions.list`（`queries/questions.ts:46`） |
| 伏笔、承诺 | 无记录。`mode: promise/plan` 存了，查询里没找到用到它的地方（推断）。“伏笔候选”= 先验 3 级而后文回响强，现算（`core/tiers.ts:101`） | `tierFlag` |
| 状态流水 `162-179` | 6 种 `op`；程序重算余额并与原文报数核对（`queries/ledger.ts:46-82`） | `ledger.track` |
| 身份、关系 | `persona` 对象加身份同一说法；亲属、社交、所属类说法 | 读者与角色视角分别合并 |
| 动机、目标、记忆 | 无记录：`goal` 类说法、`motivates` 连接、摘要的 `goals`。角色记忆 = 角色视角过滤出的知情与说法；目标兑现不追踪 | — |

## 2. 逐项对照 nb-canon

| 内容 | nb-canon |
|---|---|
| 事件 | 有：剧情变更（`model.md` 输出 5） |
| 事实（会变的状态） | 有且更强：字段补丁、套不上诊断、来历（输出 6 到 8、15） |
| 说法（自然语言陈述加渠道与断言类型） | 没有：角色说的话不记，留给第二版知情（提案第 9 节） |
| 阅读位置（到段） | 没有：读取位置只到章开头或末尾（输出 2） |
| 故事时间（day、part、rel） | 没有：只有章加前史（目标与非目标） |
| 实体经历 | 有：`involves`，`changes` 可按条目筛（输出 20，project.md） |
| 知情、秘密 | 没有（目标与非目标；决定表 11-01） |
| 悬念 | 部分：未决问题只有 open/answered/dropped 加 `hints`，没有分次进展（输出 17） |
| 伏笔 | 部分：剧情线条目自带状态（输出 18） |
| 承诺、计划 | 有，作者端更强：`fulfills/replaces/splitFrom`（输出 13） |
| 数值流水 | 有且更强：核对点、嫌疑区间（输出 11、12） |
| 身份、马甲 | 部分：`sameAs`，没有按视角合并（输出 23） |
| 关系；情节间因果 | 没有，第一版不做 |
| 出处 | 部分：`told` 是章加原句，不到段；写入时校验原句在章内（revisions.md 输出 3） |
| 目标、动机、记忆 | 没有 |
| 修订 | 有且更强；nb-story 的覆盖层只有身份、种类、称呼三类 |

## 3. 两个视角根本不同的地方

1. **阅读位置与“讲于第几章”。** nb-story 一条记录一个可见位置。作者要两个：“风信子就是南小风”第 1 章前史就成立，第 4 章才对读者揭晓。canon 只有一个安放，默认取第一次讲到的章（提案第 4 节）。
2. **不确定的含义。** nb-story 的是抽取不可靠：20 章抽取中 53 条关键记录平均错 3.3、缺 6.0（提案 12.9）。作者的是故意没定：“双王”指什么，是未决问题。canon 的 `held/unsure` 指 Agent 没把握，不是剧情没定。
3. **计划。** 第 4 章计划“救下风信子”，读到第 3 章的读者不该看到。读者视角就是 canon 实际模式加阅读位置上限（推断）。
4. **秘密对读者与对角色。** 作者要排“读者第 4 章知道、苏天晴第 5 章才知道”。nb-story 评测里，“读者知道被当成角色知道”是各组共同的最大错因。
5. **角色的话与补叙。** “古书自称来自星空彼岸”，nb-story 存为 claim，canon 不记；nb-story 补叙按故事时间排，canon 同章补叙按排序键。

## 4. nb-story 建在 nb-canon 上是否可行

可行，但有三个硬障碍：（1）canon 位置是全序，nb-story 故事时间是偏序，日子未知的点单独成组（`timeline.ts:62`）；（2）nb-story 的说法是带渠道的自然语言，canon 的状态是带类型字段的补丁，关系、态度、特征、规则难落成字段；（3）canon 依赖项目、活页夹和章 id，nb-story 导入第三方整本书（西游记 100 回：894 个对象、2,048 条说法、432 个情节）。

**做法 A：nb-story 直接用 canon 存。**
- canon 要补：段级安放；成立与揭晓两个位置；故事时间类型；带渠道与持有人的陈述记录；知情与秘密；悬念分次进展；视角参数。
- 迁移：对象到条目，persona 到 `sameAs`；情节和说法到已写变更，`told` 要由段号取回原句；账本要先声明字段，而 canon 不能给未知值加减（输出 6），“起始金额未知”的相对余额无处放。`tier`、整理稿、`arcs` 不能迁。
- 失去：独立书库（npm 0.2.1 已发布）、不依赖项目的导入。代价最大。

**做法 B：只共用底层骨架。**
- 骨架是一件事、涉及谁、出处、在故事哪里。canon 剧情变更已有文字、`involves`、`told`、安放，只需抽出 `Placement`、`Telling` 为公共类型，`told` 加段范围。nb-story 基本不动，不迁移。
- 代价：两套存储与修订；同一部作品两边各抽一遍会有两份，就是 10-31 否决过的“对齐”。
- 推断：作者自己的书不用抽取，canon 已有按章安放的变更，读者视角是过滤，没有第二份。抽取只服务第三方书，所以 B 够用；A 只在要让第三方书也用作者端工具时才值得。

## 5. 经验对作者视角的启示

| 经验 | 证据 | 启示 |
|---|---|---|
| 数交程序 | 账本余额、道具、诚实边界三类三次抽取从不翻（12.9） | canon 已采纳 |
| 天数不让模型累加 | 模型把“翌日”记成第 1 天；改成相对天数后，相隔几天仍判错，第 4 章夜晚晚一天，后面全错（12.4） | 故事时间由程序排，只让人或 Agent 写 `rel`，用“不完整”诊断暴露传递的错 |
| 知情最不稳 | 同配置抽三次，53 条里 22 到 29 条不一致；两份草稿知情只有 36% 一致 | 第二版知情不靠单次记账（推断） |
| 推理档比投票有效 | 中档：翻转 29 降到 17，错 4.3 降到 2.3，费用低一成；投票翻转没降，但标记罩住 10/11 条错 | 记账用中档以上，投票只标待核实 |
| 读者知道不等于角色知道 | 16 道知情题，作答规则 v5 把答错从 41.7% 降到 25.0%（12.11） | 知情分读者行与角色行，旁白揭示不推角色知情 |
| 自动找错与修复不可靠 | 逐章顺带报告准确率 5% 到 27%；事后扫描召回 6/8，严格口径仅 5% 到 7% 成立；修复 4 条对 1 条（t33）。程序圈候选加窄问题有效（t34） | 与 canon“有问题进待处理”同向；canon 默认生效，记账也需抽查（推断） |
| 成本 | 西游记 ¥26.1，每百万字 ¥44；第 100 章单章 ¥0.17 涨到 ¥0.29，规则筛选后输入 −37%（t10） | 记账输入设上限，提案已定 |
| 不支持改稿 | 原文变了报 `ingest_text_changed`（ingest Spec F2） | 作者端必须支持改稿后增量记账 |
