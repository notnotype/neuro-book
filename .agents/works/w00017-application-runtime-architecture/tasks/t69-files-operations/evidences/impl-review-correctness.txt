## C7 · 阻断 · 不变量：等操作锁后不重解析目标父目录，根外链接替换被直接用于提交

- **位置**：`packages/neuro-book/src/plugins/files/backend/batch.ts:166`、`:172`、`:175`；`backend/operations.ts:223`、`:226`、`:227`；`backend/entry-ops.ts:63`。

## C6 · 阻断 · 正确性：客户端预算只算扁平地址，合法批量突破消息上限并断开窗口

- **位置**：`packages/neuro-book/src/plugins/files/web/client.ts:37`、`:88`、`:271`；`backend/batch.ts:248`；`shared/contracts.ts:177`。
- **现象**：1000 项移动，每条源/目标路径约 488 字节、带 `identify` 正常取得的 32 字符令牌。扁平地址数组编码为 `983001` 字节，小于预算 `983040`；实际 `{operation,items}` 为 `1049062` 字节，已超过 RPC 消息上限 `1048576`，尚未算帧包络。客户端照常发送，得到 `unknown-outcome`、`cause: disconnected`，同一窗口下一次 `list` 为 `unavailable/disconnected`。
- **为什么是问题**：`sameScheme` 只检查字符串数组，遗漏每项 `source/target/expected` 的属性与令牌；后端检查 `items` 太晚，超限帧在提供者收到之前就断开。合法路径、正常令牌、最多 1000 项都满足，却破坏窗口连接、在途结果和订阅。无 `expected` 时属性包络也可使请求超过 Spec 的业务预算。
- **依据**：`docs/specs/workspace/files.md:89` 双端按输入 JSON 核对，超限客户端 `too-large` 且不发出；`docs/specs/runtime/plugin-channel.md:115` 单消息上限与断线；`:88` 已发写请求结果未知。`budget-ws.ts` 使用真实产品后端 `startServer`、端口均 `0`、真实 WebSocket、浏览器内核和文件门面；实测发送一帧 `1049414` 字节并得到上述结果。实验源为不存在路径，`expected` 是 `keep.md` 的真实 identify 令牌；此处验证完整报文的预发送门禁，不宣称这些项本应完成移动。应用 `closed`、服务端 exitCode `0`。
- **建议改法**：先构造要发出的完整业务请求，再对该请求统一调用 `encodedBytes`，通过才交给远程方法；后端同样核对完整请求。`identify` 与删除复用该边界，不让 `sameScheme` 承担不完整的大小检查。保持现有 64 KiB 帧余量，无需分片或大块通道。

## C9 · 重要 · 不变量：`holdLock` 无锁身份复核，旧释放会删除新持有者的锁

- **位置**：`packages/neuro-book/src/backend/locked-replace.ts:101`、`:104`、`:108`；`packages/neuro-book/src/plugins/files/backend/rooted.ts:199`。
- **现象**：真实窗口改名已提交、等清单锁时，删除它的操作锁目录，另一持有者重新取到同路径锁。放行清单后改名返回成功，旧操作释放把新锁目录删掉；第二次释放报告 `Lock is already released`。
- **为什么是问题**：新增 `holdLock` 没有 `replaceLocked` 已具备的锁目录 dev/ino 检查，持有期间失效也只记诊断、不阻止后续清单提交。锁被 stale 接管或外部破坏后，旧 owner 继续写且释放新 owner 的锁，破坏协作互斥。检测延迟是已接受取舍，但释放前从不复核身份不是检测延迟。
- **依据**：`docs/specs/platform/files.md:57`、`:90` 探测失效后停止依赖；`:59` 释放失败明确留痕。真实内核窗口门面与独立 Bun 子进程持锁：`edges.ts lock-loss`、`lock-holder.ts`，第二 owner PID `1816219` 在 marker 写出后保持在途；旧操作 `RENAME {ok:true,value:{}}`，随后 `SECOND_OWNER_LOCK_REMAINS false`。持有者由 stdin 正常结束、exitCode `0`，全部内核 `closed`。同进程复现另外得到新 owner 的 `Lock is already released`，跨进程复验确认新锁被删除，未伪称等待了心跳失效通知。
- **建议改法**：复用 `replaceLocked` 的锁身份与 compromised 状态，返回持有资格检查和幂等 release；各提交前检查资格，失效则按已发生文件事实报告部分完成，旧 owner 不得释放新 owner 的锁。不要保留两套失效语义。

## C1 · 重要 · 正确性：改名内容根不取该树的操作锁，两个成功操作留下错误清单

- **位置**：`packages/neuro-book/src/plugins/files/backend/operations.ts:53`、`:260`；`backend/batch.ts:170`。
- **现象**：窗口 A 把 `lore.content/alice` 改为 `alicia`，文件已提交，等待清单文件锁。窗口 B 随即把内容根 `lore.content` 改为 `moved.content`，返回成功。释放清单锁后 A 也返回成功、无 `manifests`，但磁盘是 `moved.content/alicia/notes.md`，新位置清单仍是 `<item name="alice" title="爱丽丝">…</item>`。
- **为什么是问题**：`placeOf` 只取祖先，顶层内容根本身返回 `null`。内容根改名、移动、删除因此不与树内操作互斥；旧清单路径消失又被当作无需维护，不报告部分完成。两项成功后清单与磁盘不一致，违反跨窗口一致性合同。
- **依据**：`docs/specs/workspace/folder-kinds.md:75` 操作锁覆盖读源条目、提交文件、更新清单、事件；`:121` 两窗口交错操作结束后清单与磁盘一致。真实四内核场景、两个窗口门面、真实清单锁屏障：`edges.ts root-rename` 输出 `ROOT_RENAME {ok:true,value:{}}`、`INNER_RENAME {ok:true,value:{}}`、`FINAL_CHILD true`，`FINAL_MANIFEST` 仍含 `name="alice"`。所有内核关闭为 `closed`。
- **建议改法**：统一由操作范围求锁集合；目录自身是内容根或包含内容树时，搬移/删除它也纳入受影响的树锁，目标名对应的锁也参加顺序取锁。锁内重解析源与目标、确认清单所在位置，再完成提交与事件。不要只在 `convert` 特判锁目录自身。

## C2 · 重要 · 正确性：复制不在源树锁内捕获条目，合法交错静默丢展示名与子树

## C3 · 重要 · 正确性：跨树移动把子树捕获绑定在源清单写成功上

## C4 · 重要 · 不变量：副作用完成后才采集回声状态，重复报自操作并吞掉真实外部修改

- **位置**：`packages/neuro-book/src/plugins/files/backend/operations.ts:268`、`:272`；`backend/batch.ts:194`、`:219`、`:241`；`backend/changes.ts:244`、`:287`。
- **现象一**：改名文件已落盘、清单更新被锁挡住，监视先 flush。订阅收到 `deleted(alice, external)`、`changed(alicia, external)`、`changed(alicia/notes.md, external)`；放锁后又收到用户来源的精确 `renamed` 与清单 `changed`。
- **现象二**：同一窗口期间外部将目标子文件写为 `EXTERNAL`，先不 flush，放锁后完成操作，再推进监视直到外部屏障到达。磁盘已是 `EXTERNAL`，订阅只有用户 `renamed` 与清单 `changed`，没有子文件的外部修改事件。
- **为什么是问题**：回声在整个清单修改完成、树锁释放后才 `lstat` 捕获“现在的身份/ctime”；早于登记的自操作事件无法过滤，早于采样的外部变化反而被记成自己的预期状态。遗漏真实变化、来源误标与重复事件都违反订阅合同；这不是恶意 TOCTOU，也未扩大最后一次系统调用的承诺。
- **依据**：`docs/specs/workspace/resources.md:78` 自操作回声不重复发、之后外部修改仍发；`folder-kinds.md:75` 锁覆盖事件。真实窗口订阅/递归 fs.watch/真实锁屏障：`edges.ts echo-duplicate`、`edges.ts echo-swallow`，前者确有上述三条外部回声，后者 `BODY EXTERNAL` 而 `EVENTS` 仅两条用户事件；均用真实外部文件事件作屏障，关闭均 `closed`。
- **建议改法**：在 owning I/O 边界记录提交时的已知目录项状态，并在副作用出现时同步登记，清单等待不能留下未登记窗口；精确事件仍在树锁内按操作顺序完成。监视处理与尚未完成操作竞态时保留待核对路径，无法区分则发 `resync`，不要事后快照认领外部 ctime。

## C5 · 重要 · 正确性：同目标移动绕过 `expected`，源已换身份仍报告完成

## C8 · 重要 · 正确性：结果裁剪只清空 `partial`，超预算的详情与清单路径仍原样返回

- **位置**：`packages/neuro-book/src/plugins/files/backend/batch.ts:262`、`:267`、`:270`。
- **现象**：两种真实 WebSocket 请求都突破结果预算。第一种输入 1000 个不存在的合法路径，每个名字含 156 个可编码控制字符和四位编号；完整业务输入 `952062` 字节，返回 `1001031` 字节，大于预算 `983040`。第二种经根内目录链接 `alias` 复制 1000 个文件到约 1.8 KiB 的实际内容树路径，清单不合法；请求帧仅 `47194` 字节，返回 1000 个 `done` 与对应清单问题，结果 `2077031` 字节，超过 1 MiB。
- **为什么是问题**：按字符截到 200 不能约束 JSON 字节数（字符可转义成六字节）；`fitBudget` 没有第二阶段详情裁剪或再次核对，非 `partial` 结果完全不处理。`done.manifests[].path` 重复携带完整实际清单路径，使短合法输入也能生成很大的结果。两例都已真实往返，证明预算与一条消息上限的合同未被实现；此环境没有因这两份结果断线，不将输入超限的断线证据移用到输出。
- **依据**：`docs/specs/workspace/files.md:89` 超预算结果先省略范围、再截短详情、保证一条消息；计划 `plan.md:67`。真实产品后端/浏览器内核/真实 WebSocket，`budget-ws.ts` 输出 `RESULT_BUDGET {inputBytes:952062,outputBytes:1001031,budget:983040,ok:true,length:1000}` 与 `MANIFEST_RESULT_BUDGET {inputBytes:60781,outputBytes:2077031,budget:983040,ok:true,length:1000}`；后一个 `inputBytes` 是含地址方案的门面输入数组，实际请求帧更小，为 `47194`。输出字节计入 `{ok,value}` 门面包络，扣除该固定包络仍明显超预算。正常关闭 exitCode `0`。
- **建议改法**：由一处按最终 `{items}` JSON 字节预算收敛结果；清空范围后若仍超限，按编码字节裁剪详情并约束清单路径的可重复表示，最后再断言整份结果在预算内。不能假定字符数等于字节数或结果只有 `partial` 会变大。

    console.log("DEVICES", (await lstat(join(scene.project, "src.md"))).dev, (await lstat(targetRoot)).dev);
    console.log("MOVE", JSON.stringify(await files(scene.window).move([{source: "project://src.md", target: "project://disk2/moved.md"}]).result));
    console.log("SOURCE", await readFile(join(scene.project, "src.md"), "utf8"));
    console.log("TARGET", await lstat(join(targetRoot, "moved.md")).then(() => true, () => false));
} finally {
    console.log("CLOSE", JSON.stringify(await scene.world.close()));
    if (mounted && Bun.spawnSync(["umount", targetRoot]).exitCode !== 0) throw new Error("卸载实验 tmpfs 失败");
    await rm(root, {recursive: true, force: true});
}

## 未发现问题的方面

- **排他与静态路径边界，已运行验证**：Linux 上目标为既有文件、空目录、悬空链接时不覆盖；源/目标控制目录及链接别名拒绝，根本身不能作为目录项操作对象。改名与删除根外链接只影响链接项，复制保留链接原文，不复制根外内容。具体竞争窗口例外见 C7。
- **跨设备与复制/删除事实，已运行验证**：独立 user/mount namespace 内真实 tmpfs 的设备号为 `51` 与 `65`；移动返回逐项 `unsupported`，源仍是 `KEEP`，目标不存在。文件复制保留字节和权限位，另测 `0o6750` 得到源/目标均 `3560`；FIFO 导致 `unsupported` 与残留范围，只读删除拒绝、递归遇错停下并报告最外层已删范围。
- **批量预处理与结果对齐，已运行验证**：按目录项去重、目录覆盖、链接别名去重、同 inode 两个硬链接名分别处理；普通同目标移动无事件、复制同目标冲突、后代目标拒绝、单项失败后独立项继续。1000 项结果与输入对齐；源身份的两处例外见 C5。直接合同调用 1001 项在 schema 边界为 `invalid-input`，未将其误记为业务执行后的 `too-large`。
- **清单非并发路径，已运行验证**：正常改名与跨树移动/复制保留展示名和嵌套条目；清单注释、声明与顺序由有序编辑保留；无效或只读清单不覆盖，转换来回保留已有清单；树锁超时报告 `busy`。并发和源清单写失败的例外见 C1–C3、C9。
- **停止、取消与代次，已运行验证**：业务取消只命中同一调用方，在途 id 重复为 `busy`，别的窗口取消不到；当前项按真实结果结算，后续项按取消、根消失或停止分别处理。提供入口与真实项目子进程停止等待当前项结束。补测调用方入口停止得到 `unknown-outcome/cancelled`，放锁后当前项清单完成，第二项源保留、目标不存在。
- **事件常规收口，已运行验证**：来源按调用方归属、控制目录隐藏、订阅释放后不复活、根消失结束、断线重连 resync 的既有测试通过。推进超过 60000 ms 后外部 chmod 仍发出外部变化；移动含 1001 个子文件的目录得到一次 resync。锁等待期间的回声例外见 C4。
