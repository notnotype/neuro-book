## F03：记录级“放弃”只移除队首，继续保存该记录的后续修改，不回到已确认值

- **严重程度**：重要。
- **类别**：正确性。
- **位置**：`packages/neuro-book/src/plugins/workbench/web/state/layout-store.ts:159`（`discard`）；`packages/neuro-book/src/plugins/workbench/web/components/WorkbenchShell.vue:131`。
- **现象**：已保存侧栏宽度 300 后断线，连续调整到 250、200；未保存队列为 2。点击记录级放弃所调用的 `discard('side')` 后，显示仍是 200、队列为 1，并立即尝试发送剩余修改。重连并重试后盘中侧栏宽度成为 200，没有回到已确认的 300。
- **为什么是问题**：外壳 Spec“失败与恢复”和验收 10 明确要求“放弃回到已确认值”，action 注释也承诺放弃这条记录的暂停修改。底层 `PersistedField.discard()` 的合同却是只丢暂停的队首、重新投影剩余意图并继续队列。直接转发混淆了单意图操作与产品的记录级放弃；真实用户在保存失败后继续拖动即可触发。现有布局失败测试每条记录只有一次修改，未覆盖这条路径。
- **如何核实**：本目录 `storage-probe.ts` 使用现有 `storageWorld`、`openLayout`，真实内核、远程链路与 SQLite；无替身、无手造失败。cwd `packages/neuro-book`：`NBOOK_AGENT_TEMP_ROOT=<本报告目录> bun --tsconfig-override tsconfig.json <本报告目录>/storage-probe.ts`。输出依次为 `seed: sidebarWidth=300 / revision=1`、`paused: sidebarWidth=200 / queue=2 / unknown-outcome`、`discard-result: discarded`、`after-discard: sidebarWidth=200 / queue=1 / saving`；重连成功，重试 `saved`，盘中 `sidebarWidth=200 / revision=2`。两个真实实例均以 `closed` 收口。Bun 在结果之后另打印一次内部 `directory mismatch ... tsconfig.json` 诊断，实验已完整执行，不将运行器诊断归为产品问题。
- **建议改法**：保留通用字段的既有队首语义，在布局拥有者提供真正的记录级取消全部暂停/排队意图并采用最新 base 的操作，不能用反复 `discard()` 循环（第一下会泵出下一条）。优先给现有字段补一个明确的原子清队列操作，再由唯一记录级 action 调用；不增第二套保存队列。补失败后同一记录继续改两次、一次放弃、重连后也不保存被放弃修改的验收。

## F02：面板拖到零后，“显示面板”命令没有清除拖收起位，不能恢复记忆尺寸

- **严重程度**：重要。
- **类别**：正确性。
- **位置**：`packages/neuro-book/src/plugins/workbench/web/state/layout-store.ts:111`（`setPanelHidden`）；`packages/neuro-book/src/plugins/workbench/web/components/WorkbenchShell.vue:126`（状态栏仅按 `panel.hidden` 决定显隐）。
- **现象**：底部面板从 sash 用 Enter 拖收起到 0px 后，状态栏仍显示“隐藏面板”。点击它隐藏，再点击“显示面板”，面板叶回来但高度仍为 `0`，框架按钮也全被裁掉。`set-panel-hidden {hidden:false}` 只清 `hidden` 和 32px `collapsed`，留下 `dragCollapsed.panel=true`；对已非 hidden/collapsed 的零面板，甚至按同值直接不写。
- **为什么是问题**：`docs/specs/ui/workbench-shell.md` 输出 8 和验收 3 承诺从拖到零通过按钮、命令或 Enter 恢复记忆尺寸。当前只有 sash 的 Enter/指针能恢复；到了紧凑呈现没有 sash，仍按拖收起位移除面板落点，用户只能先扩大窗口。用户请求“显示面板”后得到零面板，违反命令的可观察结果。旧命令也只清两位，照搬它并未满足本次明确的恢复合同。
- **如何核实**：真实产品 `/` 页，1440×900。聚焦 `[role="separator"][aria-label="调整 editor 与 panel 的高度"]`，按 Enter，等待 panel 高度为 0；依次点击状态栏“隐藏面板”“显示面板”，等待叶消失再出现。两次量得 panel 高度均为 `0`，状态栏末态仍为“隐藏面板”。操作路径全经真实 Grid 和五条产品命令。
- **追加核实**：同一产品页拖到零后缩到 390×844，再按状态栏隐藏、显示。实测 `mode=compact, panelPresent=false, toggle='隐藏面板', separators=0`：整个面板及其框架控件仍在停放区，当前窄屏没有边界可恢复。截图 `panel-zero-compact.png`。
- **建议改法**：把“显示面板”的单次定制意图合并为清除 `panel.hidden`、`panel.collapsed` 与 `dragCollapsed.panel`，同值判断同时纳入这三项；保留高度/宽度记录，不写 0。状态栏把拖到零也视为需要显示的状态，单击即可恢复。无需新增命令或保存路径。

## F01：最大化只把编辑器叶压到 0，没有停放内容；Tab 仍进入不可见编辑器

- **严重程度**：重要。
- **类别**：不变量。
- **位置**：`packages/neuro-book/src/plugins/workbench/web/components/WorkbenchShellLayout.vue:169`（`syncTargets`，行 169–176；Teleport 行 238–241）；`packages/neuro-book/src/plugins/workbench/web/shell/layout.ts:258`。
- **现象**：面板最大化后，编辑器叶的高度为 `0`，编辑器内容仍 Teleport 到该叶，没有进入 `hidden inert aria-hidden` 停放区。在 Lab 场景中聚焦面板标题按钮后按一次 `Tab`，焦点进入已被裁掉的编辑器输入框；输入框仍为 `tabIndex=0`，祖先没有 `inert`。
- **为什么是问题**：违反 `docs/specs/ui/workbench-shell.md` 输出 7、10 和验收 6：最大化应停放编辑器，停放内容不可交互且不进读屏与 Tab 顺序。零几何与 `overflow:hidden` 只裁剪像素，不移除键盘/无障碍交互。当前测试只断言 editor 高度为 0、样例不重挂，没有验证停放和键盘顺序。拖到零的可交互 Part 内容也共用这条落点路径。
- **如何核实**：启动隔离开发服务（`NBOOK_STATE_ROOT=<本报告目录>/dev-state NBOOK_DEV_PORT=43865 NBOOK_DEV_BACKEND_PORT=0 NBOOK_DEV_RPC_PORT=0 bun src/server/dev/main.ts`，完整环境与运行目录见最终验证记录），用内置 Chromium 打开 `/lab?c=WorkbenchShellLayout&s=default`，2300×1100 视口；点击场景控制的“最大化”，等待 `[data-leaf="editor"]` 高度为 0；`focus('[data-shell-focus-target="panel-title"]')`，`press('Tab')`。实测 `document.activeElement` 为样例 `INPUT`，`hiddenEditor=true, parking=false, inert=false, editorHeight=0`。截图：`maximized-focus.png`。使用真实组件、真实网格和真实键盘，没有伪发组件事件。
- **建议改法**：在同一份落点解析中排除最大化时的 editor 和拖到零的 Part，让已有 Teleport 自然回到唯一停放区，不另加一套 CSS 隐藏状态。以呈现中可交互的 Part 决定落点，并保留恢复时的滚动/焦点记忆；补真实 Tab 与停放属性的验收。
