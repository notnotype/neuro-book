## U1：最大化后的编辑器没有停放，零高内容仍进入读屏与 Tab 顺序

- **严重程度**：重要；**类别**：界面。
- **位置**：`packages/neuro-book/src/plugins/workbench/web/components/WorkbenchShellLayout.vue:169`、`:239`；`packages/neuro-book/src/plugins/workbench/web/shell/layout.ts:258`。
- **现象**：最大化只把 editor 叶的高度设为 0；`syncTargets()` 仍登记这个叶，编辑器槽仍 Teleport 到零高叶里，而非 `hidden inert aria-hidden` 的停放区。真实 Lab 场景点击“最大化”后，editor 高度为 **0px**、停放区的 Part 数为 **0**；从“面板”标题倒着按两次 Shift+Tab，焦点到达不可见的样例 `<input>`。Chrome 无障碍树仍列出这个 textbox 和全部 **80** 行正文。产品页最大化后同样没有停放 editor。
- **为什么是问题**：直接违反 Shell 输出 7、10 与验收 6 的“最大化时停放、不可交互、不进读屏与 Tab 顺序”。`overflow:hidden` 只裁像素，不移除交互或无障碍语义；接入真实编辑器后会把键盘送入看不见的正文。当前 e2e 只核对实例、值、滚动和零高度，没有检查停放或 Tab 顺序。
- **如何核实**：启动本报告末尾的隔离开发服务；打开 `/lab?c=WorkbenchShellLayout&s=default&vp=1440x900`，点击场景控制中的“最大化”，聚焦舞台里的“面板”，按 Shift+Tab 两次；`document.activeElement` 是 `[data-shell-sample-input] input`。读取 `[data-leaf="editor"]` 高度为 0，`[data-shell-parking] [data-shell-slot]` 为空。打开 `/` 点击最大化也可读到零高 editor 槽仍在叶内。以上使用真实 nb-ui、真实 Vue 与 Chrome，未直接调用内部 action。
- **建议改法**：在唯一的落点表里把被最大化挤走的 editor 视为没有可见落点，搬进现有停放区；还原后搬回。以同一份可见性判断驱动焦点转交，不再用“叶存在”等同“内容可交互”。补在既有 lifetime e2e 中检查停放、无障碍树与 Tab 顺序。

## U2：800px 以上的分栏布局可把面板压成 55px，三个框架按钮被完全裁掉

- **严重程度**：重要；**类别**：界面。
- **位置**：`packages/neuro-book/src/plugins/workbench/web/components/WorkbenchPanelSurface.vue:95`；`packages/neuro-book/src/plugins/workbench/web/shell/layout.ts:312`、`:389`；`packages/neuro-book/src/plugins/workbench/web/shell/sizes.ts:94`。
- **现象**：默认产品页在 **840×900** 的窗口里仍走 `split`，实测外壳宽 830px（页面预留 10px scrollbar gutter），侧栏 340px、右栏 373px，编辑器与底部居中面板只有 **55px**。五个 26px 框架按钮加四个 2px 间距共 138px，动作区 `flex:0 0 auto`，外框裁剪；“收起”“最大化”“隐藏”三项可见宽度均为 **0px**，“对齐”仅露 17px。欢迎标题与正文也被裁成窄条，根的降级诊断却为空。使用默认偏好即可复现，不需要坏记录。
- **为什么是问题**：Shell 输出 4 声明编辑器最小可用 120×120，输出 11 与组件规范要求框架按钮可达；实现把 editor 的最小宽度写成 0，只在所有列的理论最小值不够时退紧凑，没有为当前分配保留可用内容宽或按钮宽。390px 截图因走纵向布局不会暴露这一段窗口宽度的裁切。“标题先截断、按钮保持可点”的同名文档承诺不成立。
- **如何核实**：真实产品 `/` 从 1440×900 缩到 840×900，等待布局稳定，读取 `[data-leaf="editor"]`、`[data-leaf="panel"]` 与 `[data-panel-action]` 的 client rect；将按钮矩形与 panel 矩形求交得到上述数字。证据：本报告同目录 `product-840.json`、`product-840.png`。未修改产品代码、未调用内部布局函数。
- **建议改法**：分配时为中心内容保留真实可用最小宽，必要时先按已有规则压缩侧栏；面板动作在宽度不足时用 nb-ui 现有 Dropdown 合并成一个具名入口，不让固定动作区越出叶。补一个临界分栏宽度的真实浏览器判据，检查按钮的可见命中面积，不能只检查页面 `scrollWidth`。

## U3：紧凑布局跳过短高度降级，260px 高时编辑器只剩 0.67px

- **严重程度**：重要；**类别**：界面。
- **位置**：`packages/neuro-book/src/plugins/workbench/web/shell/layout.ts:346`、`:367`、`:443`；`packages/neuro-book/src/plugins/workbench/web/components/WorkbenchShellLayout.vue:95`。
- **现象**：真实产品页设为 **390×260**，默认 200px 面板仍保持展开；标题栏 36px 与状态栏 22px 后主体只有 202px，面板占去 200px，侧栏、编辑器、右栏三者各分约 **0.67px**。编辑器欢迎文字完全不可见，根的 `data-layout-diagnostics` 为空。框架按钮与状态栏的隐藏／显示仍可点击；隐藏再显示后问题相同。
- **为什么是问题**：Shell 输出 5 及计划验收映射明确要求“高度不足时面板退到 32px 标题头”，先保护编辑器再取非负余量；这个策略只在 `distributeBranch()` 的 split 路径调用 `preflightPanelCollapse()`，compact 直接把展开面板夹到主体高度后等分剩余量。这里不仅没有退标题头，正的 2px 余量也绕过了 `rest <= 0` 的诊断。现有纯模型的 260px 用例只有 1440px 宽，e2e 的紧凑用例只有 844px 高，二者的组合未覆盖。
- **如何核实**：在真实 `/` 已切为英文的界面，将浏览器视口设为 390×260；等待外壳高为 260px 后读取所有 `[data-leaf]` 的 client rect，得到 panel=200px、editor=0.671875px；点击“Hide or Show Panel”再点状态栏“Show Panel”，恢复后仍是该布局。截图为本报告同目录 `product-390x260.png`。
- **建议改法**：把高度降级作为两种呈现共用的投影步骤，根据 compact 实际分给编辑器的高度决定是否退标题头，沿用现有 `effectivePanel.collapsed` 和诊断；只改呈现，不改保存的 `collapsed` 与尺寸。补 390×260 的既有浏览器场景断言，核对 panel 为 32px、编辑器获得可用高度及诊断。

## U6：样例生命周期计数在每次 setup 都重置，身份断言不能发现重挂

- **严重程度**：重要；**类别**：测试。
- **位置**：`packages/neuro-book/src/plugins/lab/web/fixtures/shell-scene/ShellSampleEditor.vue:10`、`:15`、`:20`；`packages/neuro-book/e2e/workbench-shell.e2e.ts:292`。
- **现象**：注释称“计数放在模块里，跨实例累计”，但 `counters` 位于 `<script setup>`，每次实例创建重新得到 `{next:1,created:0,unmounted:0}`；输出永远为实例 1、创建 1、卸载 0，卸载只改该旧实例自己的对象，`unmounted` ref 也不跟着更新。真实 Lab 的默认场景填入文字后，经场景菜单切到“底部两端对齐”，输入清空（确实重挂），三项仍然为 **1 / 1 / 0**。
- **为什么是问题**：Spec 验收 6 与计划要求用稳定身份及累计计数证明不卸载。现有 e2e 的 `identity()` 只读实例号与卸载数，前后总相等，根本不是重挂探针；输入和滚动断言仍有价值，但不能替代承诺的生命周期证据。组件 happy-dom 的独立挂载计数测试仍有效，本条不声称产品在正常切布局时一定重挂。
- **如何核实**：打开真实 `/lab?c=WorkbenchShellLayout&s=default&vp=1440x900`，填样例输入，读取 `data-shell-sample`、`data-created`、`data-unmounted` 得到 1/1/0；点击场景 combobox 选“底部两端对齐”，等场景为 `justify` 且输入为空，重新读三项仍为 1/1/0。使用真实场景卸载路径，没有直接调用组件生命周期。
- **建议改法**：把计数对象放到真正的模块 `<script lang="ts">` 中，或由不随被测内容卸载的 fixture 拥有，输出每次递增的身份与共享累计创建／卸载数。既有 e2e 同时核对身份、创建和卸载；用真实场景切换作为一次反例验证计数会变，再在同一场景的布局变更中确认不变。
