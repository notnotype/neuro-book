## 发现 01：移除旧保存会话后，没有接出“未保存”、重试与放弃，失败会卡住本代次的后续布局保存

- **严重程度**：重要。
- **类别**：正确性 / 失败恢复 / UI。
- **计划位置**：「3. 工作台 store 与布局记录」「4. 公开状态与面板命令」「5. 外壳组件」「验收映射」（plan.md:29–58、97–103）。
- **现象**：计划用三个 persist 字段替换旧会话，列出的 action 全是布局变更，没有 retry/discard/reopen；标题栏、面板与状态栏的 UI 清单没有保存反馈或恢复入口；命令只“调 store 的 action”，没有把 `CommitResult` 折算为命令结果的规则。验收只列坏记录回落，没列确定失败、未知结果或打开/订阅失败。
- **为什么是问题**：persist 字段的恢复方法只在 setup 闭包里可用，`store.state` 不带方法。第一次保存失败或未知结果会暂停队首，后面的布局动作继续改当前显示但不再发出；泛用 store 能保留意图，却不会替产品提供用户入口。`[INFERENCE]` 按计划可做出看起来能拖、刷新就丢改动、也无法恢复的外壳；命令包装若忽略结果，还会把未落盘报成成功。这是 accepted 设计已有的外壳一合同。
- **依据**：静态核实；泛用 store 的恢复行为已在真实内核/Storage 测试中运行通过，尚无 t65 产品 UI。设计稿 `docs/proposals/workbench-shell-abstractions.md:229–231` 要求读取失败可临时调整并显示“未保存”、失败保留意图并提供重试/放弃。`docs/specs/state/store.md:93、102–107、135–142` 规定字段只读视图、失败队列暂停、由 owner 调用恢复。真实实现 `src/shared/store/persisted.ts:294–303、312–331、344–354` 继续改 display/排队但失败不发，`:51–57` 恢复方法只在字段句柄；`src/shared/store/store.test.ts:363–407` 经真实写者冲突验证暂停、retry 接着保存和 discard 后继续。旧 `components/workbench/WorkbenchShellLayout.md:19–20` 明确原产品宿主负责失败重试/放弃。`docs/specs/workbench/commands.md:67、167` 要求结构化结果，并把未保存与已保存区分。
- **建议改法**：在已有工作台 store 增加按三个已知字段执行的恢复 action，直接复用 persist 的 reopen/retry/discard。在现有状态栏提供保存状态及重试/放弃入口，受保护原件保持明确只读状态。规定布局命令如何映射 `saved/failed/unknown/protected` 及同值结果；将确定失败、未知结果的反馈与恢复加入 S2 和产品界面验收。

## 发现 02：四条必填参数命令不能通过现有命令面板执行，S6 的入口承诺缺少实现

- **严重程度**：重要。
- **类别**：可实现性 / 命令合同 / 测试。
- **计划位置**：「4. 公开状态与面板命令」「验收映射」五条命令；「验证」（plan.md:41–47、101、110）。
- **现象**：位置、对齐、隐藏、标题头收起分别严格要求 `{position}`、`{alignment}`、`{hidden}`、`{collapsed}`，计划同时承诺 S6 经命令面板执行改变布局。现有面板对普通候选一律传 `{}`，没有通用参数编辑器；计划没有定义这四条命令如何取得用户选择。
- **为什么是问题**：按计划直接登记后，只要它们人类可见，候选可选却必然得到 `invalid-args`，不会调用 store action。按钮传完整参数能成功，不代表命令面板路径能成功；在 e2e 中直接调用服务也不能证明用户入口。
- **依据**：静态核实与真实组件运行探针。`src/plugins/workbench/web/components/WorkbenchCommandPalette.vue:120–149` 只对行号模式合成参数，普通命令在 :138 写 `args: {}`；`src/plugins/commands/shared/registry.ts:302–305` 在求 `when` 和执行前严格校验。`docs/specs/workbench/commands.md:73、156–160` 规定必填参数与严格校验。现有 `src/plugins/workbench/web/commands/theme-commands.ts:22–37、41–65` 单独实现“无参数则用户选择”，并非命令面板自动提供。本次临时探针挂载真实 `WorkbenchCommandPalette`、nb-ui QuickInput 与命令表，登记同形必填 position 命令，以输入框 Enter 选择；1 个测试通过，断言真实审计事件 `args: {}`、`invalid-args`、处理器执行次数为 0。没有直接伪发 accept/closed、mock/spy/假时钟；覆盖组件入口，未运行 Chrome e2e。
- **建议改法**：推荐保留必填参数合同，四条带参命令设 `expose.human: false`，通过面板标题控件与状态栏传完整参数，无参最大化命令保留命令面板执行；修正 S6 入口映射，S3 通过真实命令服务验证参数与不可用原因。若保留“命令面板执行全部动作”的目标，明确加入选择流程及可省参数合同，复用 quickPick 并同步 Spec；不能静默补默认值。

## 发现 03：布局 store 若随现有根入口创建，打开 Lab 也会读取产品布局记录

- **严重程度**：重要。
- **类别**：不变量 / 生命周期 / Lab 隔离。
- **计划位置**：「3. 工作台 store 与布局记录」「5. 外壳组件」「6. Lab 场景」（plan.md:34–36、52、59、64）。
- **现象**：计划把三个 persist 字段的 store 归工作台浏览器入口代次，又依赖“Lab 场景只用局部状态”维持隔离，没有限定真实 store 在哪条页面路径开始读取。现有工作台根入口在路由创建前就被窗口门禁激活，包括直接打开 `/lab` 的窗口。
- **为什么是问题**：`[INFERENCE]` 若在当前 `activate` 中创建 store，`defineStore.create` 会立即对三个字段执行 Storage open 与订阅；Lab 的 fixture 即使完全局部，也已在舞台挂载前读取产品布局。只把产品 `WorkbenchShell` 标为不可 Lab 挂载不能阻止该启动路径。现有 Lab 隔离合同要求页面与 fixture 不读取产品数据；此处须明确根入口的启动工作是否属于允许的共同引导，以及产品布局何时激活。尚无 t65 实现，未运行浏览器，不宣称已发生回归。
- **依据**：静态核实调用链。`src/web/host/window.ts:200–207、222–227` 先解析 `workbenchRootKey`；`src/web/mount.ts:43–47` 之后才建立并等路由。`src/plugins/workbench/web/plugin.ts:43–56` 当前根入口负责所有页面表。`src/shared/store/store.ts:211–212` 创建时逐字段 attach；`src/shared/store/persisted.ts:238、247` 立即 open/subscribe；`src/plugins/storage/shared/remote-route.ts:22–24、39–42` 转真实远程服务。`docs/specs/ui/component-lab.md:58、69、93、122` 规定 Lab 与 fixture 的数据隔离。现有 `e2e/lab.e2e.ts:55–79` 仅观察 HTTP `/api/` 与浏览器存储键，不能完整捕获新增 WebSocket Storage 调用。
- **建议改法**：推荐保留页面表与选择服务的原启动边界，把布局 store 的创建明确延迟到产品首页需要时，并仍归已定入口代次释放；可沿用现有服务/入口机制，在布局未激活时公开键保持未就绪值。S5/S6 用真实运行时验证 Lab 没有新增产品布局 open/订阅，观察 Storage 远程调用或真实订阅事实，不能只数 HTTP。若计划允许共同引导读取产品布局，则明确其与 Lab 隔离合同的边界并更新验收；不在通用 store 加 Lab 特例。

## 发现 04：首页切换没有同片迁移既有 e2e 的选择器、项目标记与根元素合同

- **严重程度**：重要。
- **类别**：回归 / 切片顺序 / 验收。
- **计划位置**：「5. 外壳组件」页面；「切片」S4、S6–S7；「验证」（plan.md:59、84、86–87、109）。
- **现象**：S4 替换 `createEmptyWorkbench` 的首页，仅列新组件测试与 typecheck；S6 新增 `workbench-shell.e2e.ts`，S7 才跑全量，没有列既有消费方的迁移。当前 `settings.e2e.ts` 测 `.nb-empty-workbench` 的计算底色；`projects.e2e.ts` 依赖唯一 `data-workbench-project`；宿主状态依赖页面单根 attrs 透传。
- **为什么是问题**：`[INFERENCE]` 删除旧 class 后，主题测试会找不到元素；保留旧 class 的中心对齐与 padding 等页面样式又会污染全屏 Grid。标题栏、欢迎文字和状态栏都显示项目名，若各自照搬旧项目标记，原项目测试会因多个匹配失败。新页面若多根且不显式绑定 attrs，窗口 ready/instance/rpc 标记会丢失。新增外壳用例不会自动迁移这些已有消费方。
- **依据**：静态核实，未运行新实现 e2e。`e2e/settings.e2e.ts:91–92、129–149` 依赖旧 class；`:102–119` 测欢迎文字，计划保留欢迎文字，所以文案断言本身不必然失败。`e2e/projects.e2e.ts:62、80–81、122` 依赖唯一项目标记；`src/plugins/workbench/web/empty-workbench.ts:27–33` 当前拥有单根与标记；`src/web/PageOutlet.vue:27–28` 将宿主状态 attrs 交给页面根。`src/web/styles.css:35–68、77–79` 旧 class 同时负责中心布局和 token 底色。`e2e/lab.e2e.ts:221–235` 要求离开 Lab 后新窗口实例与产品主题。`docs/testing/README.md:140–145` 要求随实现运行受影响既有测试。
- **建议改法**：首页接线同片迁移 settings 的底色测量到真实外壳根，保留窗口状态属性，为当前项目选一个唯一稳定语义标记。欢迎文字按计划保留。明确列出 settings/projects/browser-host/Lab 返回路径的受影响用例，在接线片跑聚焦 e2e；S7 全量用于收口。删除旧空首页的失效样式，不保留旧 class 作为兼容路径。

## 发现 05：把 DOM 几何、手势边界和编辑器跨布局生命周期交给了无法测量布局的层级

- **严重程度**：重要。
- **类别**：测试 / 验收可判定性。
- **计划位置**：「切片」S2、S4–S6；「验收映射」尺寸夹取、同值与手势、编辑器不卸载（plan.md:82–86、94、98、102）。
- **现象**：尺寸夹取与拖到零 1px 边界映射到 S4 组件测试；“手势结束只提交一次”“读取就绪前尺寸手势不可用”只映射到 S2 store；编辑器在最大化、换位置与紧凑切换时不卸载只映射到 S4 挂载计数与 S5 Lab，没有列入 S6 浏览器断言。
- **为什么是问题**：store 不接收真实 pointer/key/ResizeObserver，不能证明手势禁用与一次提交的产品接线；happy-dom 不计算盒布局。实际紧凑切换、零占用、1px sash 和 Teleport 落点变化需要真实尺寸。只有 Lab 场景没有明确断言也不构成验收。输入保留本身不能证明未卸载：重挂后从外部恢复输入会误通过。
- **依据**：静态核实与真实 happy-dom 探针。`packages/neuro-book/vitest.config.ts:1–4、19`、`docs/testing/README.md:114–116` 规定真实布局走 Playwright。本次对真实 happy-dom 元素设置 `width:1440px;height:900px`，client 与 rect 宽高四值均为 0。旧 `components/workbench/WorkbenchShellLayout.vue:307–318、360–367` 读取实际容器并由 ResizeObserver 重建；旧 `WorkbenchShellLayout.test.ts:54–76、132–143、450–457` 用 stub/spy、回调调用及组件伪事件，不能按本计划规则照搬。旧同名 `.md:57–62` 还承诺输入、滚动、焦点与挂载生命周期。
- **建议改法**：S1 测纯尺寸/补丁；S2 用真实 Storage 的值、revision、订阅验证 action；S4 happy-dom 测不需布局的 props/emits、名称、按钮状态。S6 测实际拖动、读前禁用、越界停住不弹回、1px 边界、紧凑往返与停放。一次手势按涉及的记录验证各一次提交，不把跨记录保存说成原子事务。保活在同一局部 Lab 场景连续转换：样例暴露实例身份及累计创建/卸载数，输入与滚动由样例内部持有；断言身份不变、创建 1、卸载 0，再验证输入/滚动/焦点。不能靠切换 Lab 场景验证，场景切换会重挂。

## 发现 06：键盘调整、取消和停放后的焦点没有进入验收映射

- **严重程度**：重要。
- **类别**：可访问性 / 回归 / 验收覆盖。
- **计划位置**：「5. 外壳组件」「6. Lab 场景」「验收映射」「验证」（plan.md:51–64、89–111）。
- **现象**：验收没有分隔线键盘路径、取消后零提交、隐藏/最大化时的焦点去向，也没有框架按钮名称、禁用与窄屏键盘可达判据。
- **为什么是问题**：复用真实 nb-ui 只保护原语自身；新宿主仍需提供 `disabled/contextKey/revision`、接受一次提交、提供焦点落点并保持停放区不可交互。接线遗漏能通过纯模型、store 和截图，却使键盘无法调整、Escape 仍保存或焦点留在隐藏内容。公开键 `focusedPart` 延期不影响保护既有焦点行为。
- **依据**：静态核实。`packages/nb-ui/src/components/layout/GridRenderer.md:17、68` 规定方向键 10px、Shift 1px、Home/End、Enter，以及 Escape/pointercancel/失焦/上下文失效取消；旧 `components/workbench/WorkbenchShellLayout.md:37、46–47、57–74` 规定禁用、焦点/滚动恢复、取消不保存；旧 `.vue:237–275、418–422、454` 依赖宿主的 `data-shell-focus-target`、revision/disabled 与 `inert/aria-hidden`。`packages/nb-ui/docs/ui-development-spec.md:342–345`、`docs/standards/code/components.md:175` 要求名称、禁用与 390px 核心操作可达。
- **建议改法**：S4 验证名称、禁用和命令结果反馈；S6 用真实键盘调整 sash、Enter 恢复、Escape 取消，并观察几何及提交。补拖动期间改变容器尺寸或上下文后零提交。隐藏后焦点到“显示面板”，最大化后到面板标题，可见内容换位置/紧凑往返保留焦点与滚动，停放内容不进入 Tab；外部浮层不被抢焦点。在 390px 和 260px 短容器实际完成恢复操作。

## 发现 08：四主题截图没有区分 Lab 与产品主题，截图本身也不能证明 token 与操作可达

- **严重程度**：重要。
- **类别**：UI 规范 / 验收可判定性。
- **计划位置**：「5. 外壳组件」「切片」S6；「验收映射」主题；「验证」（plan.md:59–60、86、104、110–111）。

## 发现 09：依赖风险只有笼统提醒，缺少搬入边界与浏览器产物的可复核检查

- **严重程度**：建议。
- **类别**：依赖 / 性能 / 可维护性。
- **计划位置**：「2. 外壳几何的纯模型」「5. 外壳组件」「风险」（plan.md:25–27、51–58、119）。
- **现象**：计划承诺搬纯模型与三个参照组件，风险仅写“旧 nb-ui 接口不符时查用法”，没有说明旧 Storage 常量、旧 tab/item 子组件的取舍，也没有浏览器 JS 增量或动态页面加载的检查。
- **为什么是问题**：旧 `layout.ts` 仍从旧 Storage 定义取两个默认宽度；旧面板、状态栏还导入本片未列出的 tab/item。原样复制会留下旧应用依赖，或顺带搬入尚未使用的容器标签层。当前没有证据支持“要新增 VueUse 才能搬布局”，也不能从包安装大小推断浏览器传输体积；应以最终可达产物为准。纯布局已有公开窄入口，产品插件保持懒加载也关系到 Bun 合同测试是否意外加载 `.vue`。
- **依据**：静态核实与内存 Vite 生产构建探针。旧 `layout.ts:44–47、143–145` 取旧 Storage 的 340/400 默认宽度；`WorkbenchPanelSurface.vue:13` 导入 `WorkbenchPanelTab`，`WorkbenchStatusBar.vue:12` 导入 `WorkbenchStatusBarItem`。当前 `packages/nb-ui/package.json:12、35` 已有 layout 导出与 VueUse 依赖，布局原语自己的运行导入只用 Vue 与内部模块；`packages/neuro-book/vite.config.ts:27–46` 已预构建 VueUse、Vue 与响应式库。探针用当前真实 Vite/vue/UnoCSS 配置，`write:false`，在浏览器入口显式保留 `GridRenderer/createGrid`：现有 JS 合计 480,029 B，引用后 534,382 B；逐 chunk gzip 合计 159,445 B → 177,330 B，增量 54,353 B / 17,885 B。两份产物都不含 Lab，VueUse 在基线已经可达。这个实验只覆盖原语强制保留的构建形态，未实现 t65 外壳，不能作为最终体积或首次加载量。
- **建议改法**：S1 把 340/400 等几何默认值归到新纯模型，再由记录初值引用，不导入旧 Storage；S4 对不需要的旧 tab/item 路径明确删掉或改用现有 nb-ui 控件，确需新零件才列入同名文档/Lab 登记。布局继续走 `@notnotype/nb-ui/layout`，普通控件用公开 components 入口；新应用源码只有直接使用 VueUse API 时才声明直接依赖。产品页面 `.vue` 沿用异步 loader，现有 Vue/reactivity 单份预构建规则保持。实施后在同配置下记录浏览器 JS raw/gzip 与关键加载 chunk 增量，不设无依据的体积阈值，也不为探针数字改 nb-ui 架构。
