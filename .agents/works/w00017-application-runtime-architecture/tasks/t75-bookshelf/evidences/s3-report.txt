2. 口径、顺序、事件、今天、最近编辑（输出 16）：src/plugins/projects/project/stats-tracker.ts
   - 口径：
     - 计入：非隐藏的 .md，扩展名不分大小写，与编辑器的判定一致。
     - 跳过：任一段以 . 开头的路径（含 .nbook/）。
     - 字数用 nbook/shared/word-count 的 countWords，frontmatter 不计。
     - files 是可读的计入文件数，unreadable 单独计数（读不出的不进 files，见偏离 1）。
     - 读不出的情况：权限不足、非 UTF-8 或含 NUL、超过 Files 的正文上限 TEXT_BUDGET_BYTES。
   - 读文件：直接读项目目录，打开时带 O_NOFOLLOW|O_NONBLOCK，再 fstat，只计普通文件；符号链接与 FIFO 不计，也不会卡住扫描。
   - 顺序：
     - 先订阅再扫描。订阅建立前到达的消息也进队列，首扫完成后按到达顺序结算。
     - 所有改状态的工作串行：一次整轮扫描，或一个事件的结算。
     - 扫描并发读至多 4 个文件，每批之后 await setImmediate 让出一次执行权（这一点没有用注入时钟）。
     - 正文读完只留字数；最后一段只在事件触发的重读里计算。
   - 事件分类：
     - 已知文件（可读或读不出）：按文件重读。
     - 已知文件的上级目录：标记重扫。用每级上级目录的引用计数表判定，O(深度)。
     - 都不是：lstat 一次，目录则重扫，.md 普通文件则重读。
     - resync 与目录事件只立一个重扫标记：至多一次扫描在跑，另外至多排一次。
     - 队列超过 2000 条时折成一次 resync，防止扫描期间队列无限增长。
   - 订阅结束：
     - 收到 ended 消息或 onEnd 后不再扫描（在跑的扫描作废），状态为 ended。
     - 此前已收到的单文件事件仍会结算，见偏离 6。
   - 今天：
     - 午夜按注入时钟定时；跨日先把基线换成当时的总数，每个事件结算前也核对一次日期。
     - 打开时，记录日期是今天就沿用基线，否则以记录的总字数作基线；没有记录时，首扫总数就是基线。
     - 本地日期用 backend/shelf.ts 的 localDate（同一插件内的相对导入，服务端与子进程写法相同）。
   - 最近编辑：
     - 由 changed 事件（经文件服务保存与外部修改）设置，created（新建与复制）只计数，见偏离 4。
     - 地址为 project://<相对路径>；片段名是文件名去掉扩展名；时间取注入时钟；片段是最后一个非空段落去掉行首标记后的前 120 个码点。
     - 文件改名跟到新地址；目录改名按前缀改写后再重扫。
     - 删除时清空。每次整轮扫描后核对它指的文件还在，不在就清空（含重开后的首扫）。
   - 停止：
     - 退订，取消午夜计时与扫描。
     - 首扫没完成、或停止时正有整轮扫描在跑或排着：返回 null，不写。
     - 否则按注入时钟至多等 STOP_DRAIN_MS（1 秒）让在途与已排队的单文件结算完，再返回快照。
     - 停止开始后不再通知写入方。

3. 写入（输出 16 的“持久化”）：src/plugins/projects/project/stats-writer.ts
   - 节奏：
     - 变化后最多每 30 秒写一次（注入时钟）。距上一轮写入已满 30 秒就立即写，所以首扫完成时马上写一次。
     - 排着的写入到点时取最新快照；写入串行。
   - 按 revision 条件保存：
     - conflict、unknown-outcome、protected：先重读。
     - 存着的 computedAt 更晚：放弃，记 projects.stats.superseded。
     - 存着的与要写的相同：算写成（结果未知的那次其实已落盘）。
     - 其余情况：以重读到的 revision 重写。一轮至多 3 次，之后留到下一轮。
   - 其他失败：
     - busy、io-error、unavailable：保留旧记录，记诊断，下一轮再写。
     - corrupt、unsupported-version：以条件 reset 覆盖（原件进原件区），记诊断。
     - originals-full：放弃并记诊断。
     - 其余失败码：记 error 并放弃。
   - 句柄打开失败时下一轮再打开。

4. 停止（输出 16 的“停止”）：在入口登记的资源释放里写最后一次。
   - 快照与已存的相同则不写；快照为 null 时只收口不写，并记 projects.stats.final-skipped。

三、与 Spec 或计划的偏离及原因（Spec 未改，按约定只写在这里）

1. files 只计可读的 .md，读不出的计入 unreadable，不重复计入 files。Spec 写的是“篇是计入的文件数”与“读不出的计入 unreadable、不按 0 字计”，这里按“读不出的不算一篇”理解。若要把读不出的也算进篇数，只需改 build() 里的 files。
2. 符号链接与特殊文件（FIFO、设备）不计。Spec 没写；跟随链接可能跳出项目或重复计数，读 FIFO 会卡住扫描。
3. “过大”取 Files 的正文上限 TEXT_BUDGET_BYTES（按原始字节数），不做 Files 读取里那次按 JSON 编码后再核对。
4. 最近编辑只由 changed 事件设置（经文件服务保存与外部修改）；created（文件服务新建空文件、复制）只计数。外部新建的文件在 Files 里报为 changed，所以也会被设为最近编辑。
5. “整轮扫描没完成就不写”按任意一次整轮扫描理解：首扫没完成、或停止时有重扫在跑或排着，都不写。在 1 秒的结算窗口里遇到目录事件同样不写。
6. 订阅 ended 后不再扫描，但 ended 之前已收到、排在队里的单文件事件仍会结算。原因：正常停止时 Files 入口可能先于统计入口收口，用户最后一次保存的事件会卡在队里，丢掉它会让最后一次写入缺这次修改。
7. 停止时的 1 秒窗口除了等“在途的单文件重读”，也覆盖已排在队里的单文件事件。窗口里不发起扫描。
8. 片段按码点截到 120（记录 schema 按字形簇计长度，码点数不少于字形簇数，所以一定合规）。段内换行换成空格，分隔线（--- *** ___）不算段落。
9. 扫描时读不出的子目录跳过并记 warn 诊断，其中的文件既不计字数也不计 unreadable。
10. 激活时先 await 读记录再起 tracker：provider 一可用就能给出记录里的快照，代价是打开时多一次到服务端的读（计入下面的打开耗时）。
11. 项目入口代码按任务说明放在 src/plugins/projects/project/。tsconfig.json 的 include 没有列这个目录（只列 src/plugins/*/backend），它经 src/project/plugins.ts 与测试的导入进入类型检查。tsconfig 不在允许修改的范围，没有改。
12. 首扫期间“扫描中有修改”这类用例靠文件量让首扫跨过几步操作，再在关键处断言 status 仍是 counting，不是严格确定的时序。用到这一做法的有：stats-tracker 用 800 个文件，子进程“没完成就停止”用 1500 个，projects.test.ts 用 400 个。stats-tracker 连跑 7 次、writer 连跑 8 次都通过；在负载很高的机器上前置断言可能失败（会明确失败，不会误报通过）。
13. projects.test.ts 原来经“没有提供方”覆盖的 shelf 分支（live 调用失败时退回记录、为 stale 并记 projects.shelf.live-unavailable）不再有用例：现在运行中的项目总有提供方，而任务只允许改那一条用例。可以补一个“项目目录被移走、状态 ended 后书架退回记录”的用例，那是 S2 的代码，留给主会话决定。

C. 首扫耗时归因：把同一份样本的正文单独交给 countWords，共 1232 ms（1853 万字符）。也就是说扫描时间几乎全部在 t74 的共享 countWords 上：它对每个汉字调用一次 replace 的回调。I/O 与并发度不是瓶颈，调并发与批量帮不上忙。每批 4 个文件只占事件循环约 1–2 ms 就让出，扫描期间远程调用照常响应。

与 Spec 输出 12 的 55 ms、49 MB 对照：那是 t54 时只有内核与 nbook.diagnostics 的数字。同一台机器今天测到的 S3 之前的产物已经是约 97 ms、66 MB，增量来自 S3 之前陆续加入项目实例的 storage、settings、files 入口；S3 再加约 15 ms、6 MB。计划“风险”一节的阈值是超出 20% 先调参：打开耗时增量约 15%，首扫耗时取决于 countWords 而不是并发。Spec 第 12 条需要按这些数字重写，那是文档改动，没有做。
