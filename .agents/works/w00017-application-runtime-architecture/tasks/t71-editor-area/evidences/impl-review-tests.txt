### F1：连续规范化区域的一处编辑会改写整片未编辑行

- **严重程度：重要；类别：正确性 / 测试。**
- **位置：** `packages/neuro-book/src/plugins/editor/web/markdown/source-merge.ts:176`（稳定点要求 base 的行同时精确出现在 ours 与 theirs；183–184 两侧有差异就整片取 theirs）；测试 `source-merge.test.ts:35`、`:54`；`e2e/editor-area.e2e.ts:209`。
- **现象：** 原文 `* 甲\r\n* 乙\r\n* 丙\r\n`，真实产品页打开 `list.md`，只在第二项末尾输入“改”并 Ctrl+S，磁盘变为 `- 甲\r\n- 乙改\r\n- 丙\r\n`。第一、三项并未编辑，列表标记也被改写。连续标准 ruby 同样会把未编辑行改成属性式。
- **为什么是问题 / 依据：** `docs/specs/workbench/editor.md:110` 输出 19、`:171` 验收 5 要求未编辑的行字节不变。已接受的行级取舍仅允许编辑过的行规范化，不能放宽到整片。当前三方合并在连续序列化差异中没有稳定点，把序列化规范化与真正编辑合并成一个区域。
- **如何核实：** `bun /tmp/claude-1000/-home-notnotype-CodeRepository-neuro-book/c38df555-3a36-49c9-bf4f-4027b5da6d32/scratchpad/t71-impl/tests/markdown-probe.ts`（真实编辑器扩展工厂 + MarkdownManager）；另在 `http://127.0.0.1:46371/?project=review` 走真实 Files 与浏览器，双击列表文件、点击第二项、End、输入“改”、Ctrl+S；磁盘前后字节见 `list-saved.json`。
- **为什么测试验不出：** 7 个 `source-merge.test.ts` 与现有 18 个方言往返用例全部通过。前者只编辑与规范化列表隔着空行的普通段落；e2e 同样只改最后一个普通段落。方言测试只验证 canonical 序列化，没有检查编辑某个规范化行后的邻行字节。
- **建议改法：** 将 base→theirs 的实际编辑 hunk 与 base→ours 的序列化对应关系分开，逐行映射可保留的原文；缺少完全相等稳定行时也不能把整个规范化片段当成用户编辑。补真实编辑器的连续列表、连续 ruby 中项编辑，以及删除/插入其中一项的字节断言。

### F2：删除末段时额外保留一个换行，删光时仍写出换行

- **严重程度：重要；类别：正确性 / 测试。**
- **位置：** `packages/neuro-book/src/plugins/editor/web/markdown/source-merge.ts:149`、`:187`、`:192`；覆盖缺口 `source-merge.test.ts:35`、`:47` 与 `e2e/editor-area.e2e.ts:209`。
- **现象：** 真实产品中原文 `甲\r\n\r\n乙\r\n`，选中末段“乙”，Backspace 删除文字，再 Backspace 合并空段，富文本只剩 `<p>甲</p>`；Ctrl+S 后磁盘为 `甲\r\n\r\n`，多一个 CRLF。纯函数的 `mergeSource("a\nb\nc\n", "a\nb\nc", "a\nb")` 得到 `a\nb\n\n`；`mergeSource("甲\n", "甲", "")` 得到 `\n`。
- **为什么是问题 / 依据：** editor 输出 19 要按编辑后的语义写回编辑行、保存未编辑行字节。实现同时保留最后一个稳定原文行的 EOL，并在末尾再加 `finalEol`，删除末段时尾换行被计了两遍；删除空文档的情况没有正文却仍加尾换行。
- **如何核实：** `markdown-probe.ts` 中 4 个末尾删除输入均不符合期待；另用真实 Tiptap、真实 Files 的页面操作重现，结果见 `delete-saved.json`（保存的 DOM 与磁盘）。
- **为什么测试验不出：** 现有删除用例删的是中间段落，尾部行保留；末尾换行测试只切换相同正文的末尾符号，没有删除最后一个块/最后一行；e2e 只追加。
- **建议改法：** 合并内部统一处理行分隔符，输出完成后只附加一次尾换行；正文为空时不要凭打开时的尾换行造一行。补真实编辑器删末段、删末项、全选删光、原文有/无尾换行与 CRLF 的断言。

### F3：外部删除后的文档仍可编辑，测试只检查提示

- **严重程度：重要；类别：正确性 / 测试。**
- **位置：** `packages/neuro-book/src/plugins/editor/web/documents/store.ts:345`；`EditorGroup.vue:113`；测试 `documents.test.ts:353`、`e2e/lab-editor.e2e.ts:78`。
- **现象：** 真实 Files 打开 `deleted.md` 后在磁盘删除文件；页面显示“文件已被删除”，但富文本 `contenteditable="true"`。继续输入成功，标签变 dirty（结果见 `deleted-editable.json`）。
- **为什么是问题 / 依据：** editor 输出 18（`docs/specs/workbench/editor.md:106`）要求外部删除后“标已删除并只读，正文保留”；输出 20 要求只读视图不接受输入。`writable` 把 `deleted` 与 `ready` 一同视作可编辑，导致控件不切只读。允许 dirty 文档保存重建不意味着允许删除后继续输入，保存与视图写入资格需要分开。
- **如何核实：** 生产构建、真实产品页、报告目录的隔离项目；打开文件→`unlink` 原路径→等待删除提示→检查 `contenteditable`→输入文字并失焦，文字与 dirty 变化可观察。
- **为什么测试验不出：** Bun 删除用例只断言状态、正文保留与重建保存；Lab e2e 删除后只断言 banner，没有检查输入是否被拒绝，之后立即切场景。只有订阅 ended 用例检查 `writable=false`。
- **建议改法：** `writable` 仅用于 ready 的可输入资格；保存重建单独检查 deleted + dirty，不借用 UI writable。补真实 Markdown/Monaco 的外部删除后键盘输入无效、正文保留和 dirty 保存重建场景。

### F4：800 ms 阈值测试用产品常量计算期望，400 ms 变异存活

- **严重程度：重要；类别：测试。**
- **位置：** `packages/neuro-book/src/plugins/editor/area.test.ts:20`、`:86`；计划 `plan.md:147`；实现 `web/area.ts:22`。

- **为什么是问题 / 依据：** editor 输出 6、验收 2 与 files-explorer 的“打开与切换”给定具体 799/800 ms 边界。`docs/testing/README.md:9` 禁止由被测逻辑生成期望的同义反复；当前测试按修改后的常量推进 399/400 ms，永远只能证明实现和自己一致。

- **建议改法：** 直接按合同推进 799、再 1 ms；不导入阈值常量作为期待。另用真实组件挂载与手动时钟验证空白内容、顶部进度条出现和消失，至少保持独立于产品阈值的行为断言。

### F5：方言验收没有覆盖真实编辑器追加的硬换行，丢换行变异存活

- **严重程度：重要；类别：测试。**
- **位置：** `packages/neuro-book/src/plugins/editor/web/markdown/markdown-dialect.test.ts:15`、`markdown-empty-document.dom.test.ts:16`、`source-merge.test.ts:55`；产品 `markdown-editor-extensions.ts:20`；e2e `editor-area.e2e.ts:18`、`:209`。
- **现象：** 临时把 `MarkdownHardBreak.renderMarkdown` 从 `"\n"` 改为 `""`：编辑器 Bun **61/0**、DOM **10/0**、重新构建后的产品 editor-area e2e **9/0**，全部通过。真实产品 Shift+Enter 插入的 `<br>` 在保存时丢失；`hardbreak-mutated.json` 的 DOM 有 `<br>`，磁盘没有对应换行。真实扩展工厂的显式 `hardBreak` 节点原本应序列化 `前\n后`，变异后为 `前后`（`mutation-hardbreak-probe.log`）。
- **为什么是问题 / 依据：** editor 输出 19 与验收 5 包括硬换行语义保持；测试只用方言核心 `createMarkdownDialectExtensions()`，其中禁用了 StarterKit 的 hardBreak/link，实际控件追加的 `MarkdownHardBreak`、`MarkdownLink` 不在这套测试 schema 中。e2e 的 DIALECT 也没有硬换行；不能据迁入往返测试声称全集已验。

- **建议改法：** 至少一组真实 Editor/MarkdownManager 使用与控件相同的 `createMarkdownEditorExtensions()`；从用户输入生成硬换行并按磁盘/重开后的行结构断言，同时覆盖工作区/领域链接。验收 5 的全方言 fixture 应真正包含每个声明的方言。

### F6：磁盘冲突阻止移动的分支没有测到，放行变异存活

- **位置：** `packages/neuro-book/src/plugins/editor/documents.test.ts:432`；`src/plugins/explorer/documents.test.ts:147`、`:160`；产品 `editor/web/documents/store.ts:509`。
- **现象：** 临时删除租约 blocked 谓词中的 `state === "conflict"`，保留 unresolved；运行文档模型与资源管理器结算两份 Bun 测试，**27 pass / 0 fail / 183 expect**。真实 Files 探针先创建实际磁盘基线冲突，再调用公开 `coordinator.begin`，得到 `leaseAllowed=true`，违反合同（`mutation-conflict-lease-probe.log`）。

### F7：内存 Files 的条件保存不是原子提交，契约测试只验串行

- **严重程度：重要；类别：测试 / 正确性。**
- **位置：** `packages/neuro-book/src/plugins/lab/web/fixtures/explorer-scene/memory-files.ts:425`；契约测试 `src/plugins/lab/memory-files.test.ts:167`。
- **现象：** 同一个旧 baseline 并发提交两个不同正文：真实 Files **一个成功、一个 conflict**；内存适配器 **两个都成功**，且两个回执的 `identity.before` 都是同一个旧令牌。实际磁盘/内存正文只有最后一次。日志 `memory-save-probe.log`。
- **为什么是问题 / 依据：** `workspace/files.md:60` 明定“比较基线、替换、确认”是一次原子提交，同一基线的两次并发保存恰好一次成功；`docs/testing/README.md:16` 要求 fake 与真实依赖契约一致。内存实现先抓住 node，再异步算 `hashOf(node.text)`，两个调用跨 await 持有同一旧节点；之后没有重验/串行边界，均通过条件。Lab 依赖此适配器验证编辑器保存与身份链，会掩盖错误的并发与回执语义。
- **如何核实：** `bun --tsconfig-override /home/notnotype/CodeRepository/neuro-book/.worktree/w00017-t71-impl-tests/packages/neuro-book/tsconfig.json /tmp/claude-1000/-home-notnotype-CodeRepository-neuro-book/c38df555-3a36-49c9-bf4f-4027b5da6d32/scratchpad/t71-impl/tests/memory-save-probe.ts`；两端执行完全相同公开 Files 调用，真实内核与真目录，不伪造私有状态。
- **为什么测试验不出：** memory-files 的正文用例串行 read/write/read，再用全零哈希构造冲突；没有同 baseline 并发写，也没核对保存事件与回执在异步时序下的身份链连续性。
- **建议改法：** 按地址串行化“当前节点→基线校验→替换→回执”，或预计算哈希后在无 await 区间重验实际节点/版本并落账；同一契约用例在真实与内存端都并发写，断言恰一成功、一冲突，前后身份可跟到实际结果。

### F8：拆分组使原组 Markdown 撤销历史丢失，现有拆分验收只看共享正文

- **严重程度：重要；类别：正确性 / 测试。**
- **位置：** `packages/neuro-book/src/plugins/editor/web/components/MarkdownControl.vue:48`、`:98`；`EditorArea.vue:65`；测试 `area.test.ts:110`、`e2e/editor-area.e2e.ts:156`、`:229`。
- **现象：** 同一真实产品页中，原组 `g2` 输入“甲”：正文 `基线甲`；拆分前 Ctrl+Z 得到 `基线`、Ctrl+Shift+Z 恢复 `基线甲`；Ctrl+\ 拆分后，两组均为 `基线甲`。准确定位回原组 `g2`，Ctrl+Z 不再改变正文。逐步 DOM 与组标识见 `history-split-trace.json`。
- **为什么是问题 / 依据：** editor 输出 2 要求拆分后各有自己的撤销历史；`:142` 明确视图的编辑状态与撤销历史保留到标签关闭，当前原标签仍打开且 dirty，不满足淘汰条件。Grid 从 leaf 改为 branch 时原组控件重挂；`rebuilt` 用 `EditorState.create` 重建文档与选区，未恢复旧 history 插件状态，已有历史因此消失。`MarkdownControl.md` 对丢历史的描述不属于已接受取舍，不能替代 Spec。
- **如何核实：** 生产构建、真实 Files 与真实 Ctrl+Z/重做/拆分键；同组拆分前成功、拆分后失败，排除了原组本来没有历史或焦点错误。源码均已恢复，不在变异构建上复现。
- **为什么测试验不出：** area 用例只放任意 `{caret: 1}` 对象到 slot 再断言对象复用；e2e 拆分场景只看组数和正文，撤销场景只在同组 A→B→A 间切换。计划 `plan.md:153` 的“两组同文档各自撤销”没有实际用例。
- **建议改法：** 拆分/关闭相邻组时保留原控件实例，或在控件之外持有可恢复的 schema 与 history 状态；补“输入→拆分→原组撤销与重做”、关闭相邻组后历史仍在，以及同文档双组各自撤销的真实用户行为断言。

### F9：另一组的正文同步清空本组已有撤销历史

- **严重程度：重要；类别：正确性 / 测试。**
- **位置：** `packages/neuro-book/src/plugins/editor/web/components/MarkdownControl.vue:123`、`:130`、`:82`；测试 `e2e/editor-area.e2e.ts:156`、`:229`。
- **现象：** 已拆分的同文档两组中，原组 `g2` 输入“左”、失焦结算，两组均显示 `基线甲左`；另一组 `g6` 输入“右”、失焦结算，两组均显示 `基线甲左右`。回到 `g2` Ctrl+Z，无法撤销自己的“左”；`g6` 此时仍可撤销自己的“右”，两组恢复 `基线甲左`。完整操作后文本见 `history-shared-trace.json`。
- **为什么是问题 / 依据：** editor 输出 2、12 与 `:142` 要求各组拥有并保留自己的撤销历史，另一组的更新不进入本组历史；当前收到别组修订时调用 `load()`，创建全新的 `EditorState`，把本组已有用户历史也清掉。现象在拆分后的新输入上重现，与 F8 的拆分重挂清空历史是两个触发边界。
- **如何核实：** 同一真实产品、真实控件与用户键盘；每次失焦结算后等待两组正文相等，再撤销并检查两组文本，不调用内部 editor/store 方法。未修改产品。
- **为什么测试验不出：** 双组用例只测一组输入、另一组同步；A→B→A 用例只测不同文档，未让另一组修改同一文档。计划中的“两组同文档各自撤销”未落到用户行为测试。
- **建议改法：** 将别组输入作为不进入本组历史的正文变换，并映射本组既有撤销步骤；不要借“外部内容不进历史”清空用户历史。补双组轮流输入后各自撤销/重做，断言另一组输入仍在。
