### 1. 重要：原样迁入的方言往返测试不会进入新应用 Vitest 的测试集合

- **类别**：测试；**核实状态**：从代码推断，已核对运行器配置。
- **位置**：计划 `plan.md:54,101,116`；`packages/neuro-book/vitest.config.ts:18-25`；旧测试 `packages/neuro-book-legacy/app/components/markdown-studio/tiptap/markdown-editor-extensions.test.ts:1-13`、`dialect-fallback-dom.test.ts:1`。
- **现象**：计划要求迁入旧包的往返测试并用 Vitest 验证，但新应用 Vitest 只 include `src/**/*.dom.test.ts`；旧文件是 `*.test.ts`，其中还直接导入 Vitest。原样迁入后，`test:vitest` 不收集；Bun 会把它们当普通测试收集，却不是 Vitest 运行时。

### 2. 阻断：计划没有给真实生产 e2e 制造“慢读 / 800 ms 前后”的可用接缝

- **类别**：测试；**核实状态**：从代码推断，辅以现有测试场地检查。
- **位置**：计划 `plan.md:14,45,79,99,111-123`；`packages/neuro-book/src/plugins/files/testing/scene.ts:80-105`；`packages/neuro-book/src/plugins/files/testing/tap.ts:24-35,46-83`；`packages/neuro-book/e2e/fixtures.ts:48-62,74-90`；`packages/neuro-book/src/web/host/window.ts:65-70,191-200`。
- **现象**：`LinkTap` 只能作为 `filesScene(..., {wrapLink})` 的窗口内链路包装器扣住真实 RPC 回复；它不接入 `startProductServer` 的生产进程。现有 e2e 生产启动器只给状态根、端口和静态产物，没有慢读注入、测试项目插件或浏览器时钟注入入口。浏览器窗口的 `clockKey` 默认由 `systemClock` 提供，产品启动路径没有传入可推进的时钟。
- **为什么是问题**：计划明确要求“真实 Chrome + 真实 build + Files 测试链路扣住慢读”，但按已定义接口没有把这三者接在一起：Bun 场地能扣 RPC 回复，生产页面却没有该包装与可推进时钟的测试入口。现有 e2e 测试外壳能加测试插件，`BrowserWindowOptions.clock` 也已经支持注入，说明无需重造内核；计划需要把连接与控制方式分配到 S4。假造 Files 结果、改全局计时器或固定等待不符合测试规范，Lab 不能替代真实产品链路。
- **依据**：`files-explorer.md:125-126` 要求 800 ms 前无提示、之后仍未就绪才显示进度条，且计划 `plan.md:122` 明确把它放在产品页 e2e；测试规范要求等待可观察状态或注入时钟，不用固定时长。
- **建议改法**：S4 明确复用 e2e 外壳、`BrowserWindowOptions.clock` 与真实 `RemoteLink` 回复包装，向测试暴露局部时钟推进和指定 read 回复释放。控制窗口时钟、扣住已实际读取的回复，在阈值前/后观察空白与进度条，释放后观察正确正文；迟到结果不得抢当前意图。若用可控真实组件/内核场景证明精确阈值，另用未加测试插件的生产构建证明打开结果，计划应明确两层证据责任。此阻断针对当前写定的验收路径，不表示产品行为无法实现。

### 8. 重要：A→B→A 的撤销恢复没有被真实编辑器场景覆盖，S4 的 textarea/DOM 测试不能证明该合同

- **类别**：测试 / 正确性；**核实状态**：从计划与旧测试推断覆盖缺口；已运行真实编辑器可行性实验，未运行尚不存在的新实现。
- **位置**：计划 `plan.md:40-45,57,99-105,111-116,132`；旧宿主测试 `packages/neuro-book-legacy/app/components/editor-workbench/EditorViewHost.test.ts:29-53,184-212`；旧宿主合同 `packages/neuro-book-legacy/app/components/editor-workbench/EditorViewHost.md:37-43`。
- **现象**：计划在 S4 用 `textarea` 占位贯通切换，并只把“A→B→A 期间旧回调到达”的 DOM 测试列在风险；设计却要求“撤销历史按文档 × 视图保存，A→B→A 回来时恢复”。S4 的 textarea 没有 Monaco/Tiptap 撤销栈，计划的 e2e 只写 A→B 快速切换不串正文、打开/输入/保存等，没有“在 A 输入 → B 输入 → 回 A → Ctrl+Z/Redo 观察 A 的历史”的真实旅程。旧宿主测试也明确使用 textarea 替身，且 `vi.fn` 只验证宿主回执，不是实际编辑器历史。
- **为什么是问题**：按现计划全部通过仍可能在真实 Monaco/Tiptap 绑定重建时丢 A 的 undo history，或把 B 的历史误套到 A；这正是本 Task 的跨文档/跨视图核心不变量，无法由正文显示和 token 迟到测试推出。
- **依据**：旧合同把“控件复用”与“文档/视图状态”分开，并要求每组独立宿主、隐藏前结算；测试规范要求公开合同、边界与恢复场景必须有行为测试，替身不能冒充真实依赖。

### 10. 建议：首屏分块应核对静态依赖闭包，不能只看动态 chunk 名称与体积表

- **类别**：测试 / 性能；**核实状态**：从配置推断计划缺少判定步骤；已运行仓库外 Vite 产物实验。
- **位置**：计划 `plan.md:48-50,99-105,121-132`，具体 `50,131`；`packages/neuro-book/vite.config.ts:16-49`；`packages/neuro-book/scripts/check-dist.ts:1-56`；`packages/neuro-book/package.json:18-23`。
- **现象**：Vite 正常 build 会输出各 chunk 原始/gzip 体积表，早期“没有输出报告”的表述不准确；但现有配置没有 manifest/模块归属报告，`check:dist` 只查 Lab 与本机路径。计划 `plan.md:131` 没有写清“首屏不含它”怎样从产物表判定。实际实验里动态 `editor.api` 入口仅 452 字节，真正主体在它依赖的另一个 2,557,259 字节 chunk，说明只看入口 chunk 会漏算。

- **如何核实**：命令 `node /tmp/claude-1000/-home-notnotype-CodeRepository-neuro-book/c38df555-3a36-49c9-bf4f-4027b5da6d32/scratchpad/t71-plan/testability/build-browser-probe.mjs` 使用 Vite `8.1.4` 构建真实旧 Monaco loader，输出全部在报告目录。`generateBundle` 捕获 chunk 模块归属与 imports，静态闭包未含 Monaco；浏览器点击前只请求主入口，点击后才请求 Monaco。详细数据见 `browser-chunk-summary.json`，不是新应用实际构建数据。
- **建议改法**：S5 的“构建报告核对”明确记录 HTML 初始 module 的静态闭包、相关模块归属与原始/gzip 字节，再用首次打开源码前后的请求核对无提前加载。manifest + `generateBundle` 可实现，或采用等价产物分析；不要新增未经批准的性能阈值，也不要求首版只有一个 Monaco chunk。

### 11. 重要：指定沿用的 frontmatter 拆分函数已违反“原样保留”，CRLF 和结尾换行会被改写

- **类别**：正确性 / 测试；**核实状态**：已运行实际旧函数实验；新实现尚不存在。
- **位置**：计划 `plan.md:54-56,116,130`；`packages/neuro-book-legacy/shared/editor-workbench.ts:118-140,148-149`；合同 `docs/specs/workspace/files.md:57`；待确认清单 `pending-confirmations.md:57`。
- **现象**：计划明确沿 `splitMarkdownFrontmatter` 拆分并原样保留前缀，但该函数先对全文件做 `content.replace(/\r\n/g, "\n")`，并在关闭分隔符位于 EOF 时人为补 `\n`。报告目录 `frontmatter-probe.ts` 直接调用实际函数，再用实际 `composeMarkdownFrontmatter` 拼回，命令 `bun run /tmp/claude-1000/-home-notnotype-CodeRepository-neuro-book/c38df555-3a36-49c9-bf4f-4027b5da6d32/scratchpad/t71-plan/testability/frontmatter-probe.ts` 退出码 0：LF 样本相同；`---\r\ntitle: 第一章\r\n---\r\n\r\n正文` 全变 LF；`---\ntitle: 第一章\n---` 被补末尾换行。原始与输出写在 `frontmatter-results.json`。
