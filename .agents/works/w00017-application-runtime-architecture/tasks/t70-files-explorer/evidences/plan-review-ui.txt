### UI-06｜重要｜交互时序：切换呈现时未规定取消旧菜单与拖动

- **计划位置**：`plan.md:30`、`:40–42`、`:49`、`:56`、`:91`、`:101`、`:120`。
- **现象**：工具栏和命令都能切换“显示清单文件”，行投影会立即变化；计划只写拖动中 Escape 取消、落在目录移入、两行之间排序和源取当时的选择，未定义冻结的源身份令牌、已显示落点的身份或投影变化后的取消规则。验收映射 4 也遗漏主 Spec 要求的“未提交菜单/拖动取消”。
- **为什么是问题**：菜单打开期间目标可能改名、删除或消失；拖动时新增/隐藏清单行会改变同一指针位置对应的资源及排序间隙。按旧行索引或实时选择结算可能把操作投向用户未确认的资源。此为计划中的时序缺口，实际错误操作为推断。
- **依据**：`docs/specs/workbench/files-explorer.md:99,139` 要求发起后的目标稳定、切换呈现取消未提交菜单/拖动；`packages/neuro-book/src/plugins/workbench/web/views/drag-session.ts:6–16,221–228,272–288,376–379` 已有可参照的冻结源、放下重验且与已展示动作相同才提交、`pointercancel`/失焦/隐藏/销毁取消合同。这里沿用已采用的两套拖动归属，不要求重做外壳拖动。
- **建议改法**：补一个会话状态与取消表：打开菜单/激活拖动时冻结逻辑源和目标；切换清单显示立即取消未提交菜单/拖动，已发请求不改目标。按地址和同层前后项表达落点，不按 DOM/行索引持有目标；放下时重判并核对最后展示的动作。定义 `pointercancel`、捕获丢失、窗口失焦/页面隐藏、视图销毁和源/目标失效时不提交，触摸超过容差先让给滚动，真正拖动结束吞掉尾随 click。将投影切换、滚动导致源 DOM 回收及取消后零写入列入 S4 浏览器场景。

### UI-07｜重要｜展开持久化：只提示一次没有处理保存暂停后的恢复

- **计划位置**：`plan.md:10`、`:29–30`、`:62–64`、`:89`、`:101`。
- **现象**：计划使用现有持久化字段保存偏好和展开状态，失败策略只有“记录写失败只在视图里提示一次，不阻塞浏览”，没有队首失败/未知后的重试或放弃策略，也没有首读失败、坏记录与不认识的版本的呈现合同。
- **为什么是问题**：既有字段的一次保存失败或结果未知会暂停整个字段的队列，后续展开/收起仍立即更新 `display` 并排队，却不再发送。仅提示一次不会让持久化恢复；重开后会丢失此次失败之后的展开与显示偏好，持续浏览还会累积未保存意图。保存暂停的机制已从代码核实，未来 t70 的丢失/积压表现为推断。
- **依据**：`docs/specs/state/store.md:97,101–108,140–145` 明确首读、暂停、`retry/discard/discardAll/reopen` 与受保护记录合同；`packages/neuro-book/src/shared/store/persisted.ts:298–307,317–325,397–409,430–468` 显示排队、队首非 queued 时不发和显式恢复逻辑。`docs/specs/storage/persistence.md:103–105,156` 区分 missing、corrupt、unsupported-version、读取失败且禁止错误时写默认值。此项只补消费者恢复策略，不改变已采用的 store/Storage 设计。
- **建议改法**：浏览继续，但保留一个“展开/显示偏好未保存”的可访问状态及明确恢复入口；确定失败调用字段 `retry`，打开失败/订阅终止先 `reopen`，结果未知沿字段已有核对流程，不把文件操作的未知结果禁重试规则套到偏好记录。说明暂停期间意图如何合并或限量；用户放弃则用 `discardAll` 并明确显示回落。首读失败提供内存浏览和重读，corrupt/unsupported-version 不自动覆盖。S2 增加失败后继续展开、恢复并重新打开、首读错误/坏记录的验收。

### UI-01｜重要｜无障碍、组件复用：计划依赖的 ContextMenu 没有完整键盘与焦点合同

- **计划位置**：`plan.md:12`、`:22–23`、`:36`、`:54`、`:90–91`。
- **现象**：计划把创建内容、转换、展示名和清单修正等动作放进固定右键菜单，键盘表没有 `Shift+F10` / Menu 键或可聚焦的菜单按钮；直接复用的 nb-ui `ContextMenu` 也不负责打开时聚焦菜单、上下键/Home/End 导航、关闭后归还焦点。仅给出组件名不能得到可用的键盘动作入口。
- **为什么是问题**：只用键盘的用户无法按计划完成这些基础操作；`role="menu"` 本身不产生键盘行为。这里是既有依赖能力不足，不是要求把所有动作重新命令化。
- **依据**：`packages/nb-ui/src/components/feedback/ContextMenu.md:7–15,60–64` 明确不管理触发器且不提供完整键盘导航；`ContextMenu.vue:41–45,47–58` 的键盘处理只有 Escape，没有聚焦/归还处理；`ContextMenuPanel.vue:30–46` 使用普通 `div[role=menu]`。`packages/nb-ui/docs/ui-development-spec.md:123–125,344` 要求完整方向键、Home/End、Enter/Space、关闭及焦点归还。核实方式：静态读取组件合同与实现，未运行 t70。
- **建议改法**：在计划中选定一个完整菜单入口：树焦点上的 `Shift+F10` / Menu 键定位到当前焦点行，复用同一动作集合；补齐公共 `ContextMenu` 的键盘/焦点合同，或选用已有完整菜单原语组合。菜单关闭再启动内联编辑/对话框，避免两层同时争焦点；取消返回树，外点关闭尊重用户落点。验收覆盖只用键盘执行创建内容、改展示名、修正清单。

### UI-02｜重要｜无障碍：只渲染视口与离屏焦点可读的承诺缺少实现规则

- **计划位置**：`plan.md:31–36`、`:41`、`:89`、`:119`。
- **现象**：同一句规定“只渲染视口内的行与上下各 10 行余量”，又承诺用 `aria-activedescendant` 让“滚出视口的焦点行仍可读”。没有规定保留焦点 DOM 节点或滚动后更新焦点；行属性仅列 `aria-level/expanded/selected`，没有虚拟树必需的逻辑同层位置和总数。
- **为什么是问题**：`aria-activedescendant` 是对现存、可访问后代 id 的引用，不能让已卸载的行继续出现在无障碍树。滚轮快速跨过余量、连续键盘移动、折叠焦点祖先后都会遇到这个边界。只按当前 DOM 推导集合会把几千项的一小段误报成完整列表。
- **依据**：计划 `:41` 的两条承诺；W3C [Tree View Pattern 的角色与属性要求](https://www.w3.org/WAI/ARIA/apg/patterns/treeview/#wai-aria-roles-states-and-properties) 明确动态加载/滚动导致节点不完整时每项须给 `aria-level`、`aria-setsize`、`aria-posinset`，树须有可访问名称。`ui-development-spec.md:55,344` 要求角色、状态、方向键与焦点合同。核实方式：计划与一手无障碍指南对照；尚无 t70 实现，运行表现为推断。
- **建议改法**：保留虚拟化，但把渲染集合改为“视口加余量，并额外保留当前焦点/编辑项”；每项用稳定 id，按完整逻辑兄弟集合计算 `posinset/setsize`，状态行不冒充资源。键盘移动先将目标滚入视口并确保挂载，再更新 active descendant；折叠/删除/过滤使焦点失效时，明确回父项或邻近可见项。补 Home/End 与树名称，并在真实浏览器验收快速滚动后的 id 引用、键盘跨窗口移动和祖先折叠。

### UI-03｜重要｜焦点管理：无触发器删除确认不会自行把焦点还给树

- **计划位置**：`plan.md:36`、`:44`、`:51–53`、`:90`。
- **现象**：删除既能由 Delete 键也能由菜单触发，计划只规定确认框默认焦点在取消，未规定关闭后的落点；内联新建/改名也未定义 Escape、失焦、提交完成后的焦点。默认的 nb-ui `AlertDialog` 在没有 trigger slot 时明确阻止自动归还焦点。
- **为什么是问题**：菜单触发器会先消失，删除成功后原资源行也消失，普通“回到触发器”不足以恢复工作位置；取消后如果 DOM focus 未回到列表，计划中“仅列表拥有焦点才处理”的全部树快捷键就失效。输入框被移除同样会丢失 DOM focus。
- **依据**：`packages/nb-ui/src/components/feedback/AlertDialog.md:13,44–45,62`；`AlertDialog.vue:48–59` 的 `preventTriggerlessCloseFocus`。`Dialog.md:30` 只承诺回打开前元素，不能保证消失的菜单项/树行仍有效。`docs/standards/code/components.md:47–48` 要求出现/消失时焦点去向；`ui-development-spec.md:55,344` 要求焦点归还。核实方式：静态读取公共合同与实现；最终 t70 焦点丢失为推断。
- **建议改法**：控制器保存逻辑焦点地址而非菜单项 DOM；在 `AlertDialog.closed` 后取消回原项，删除成功回下一个存活兄弟、否则前一个、否则父目录/根；对话框期间视图已隐藏时沿工作台框架落点处理，不能抢回不可见树。内联编辑 Enter 提交、Escape 取消且不冒泡、中文组合输入 Enter 不提交；完成/取消后聚焦树并校正 active descendant。把虚拟列表中的编辑项纳入保留集合，定义滚出视口时保留草稿的行为；在 DOM 与浏览器验收中检查真实 `activeElement`。

### UI-04｜重要｜无障碍、交互：内容文件夹排序只有拖动入口

- **计划位置**：`plan.md:22`、`:36`、`:54–56`、`:91`、`:101`。
- **现象**：键盘表、菜单和工具栏都没有调整顺序动作；唯一的排序入口是“同一父目录的两行之间”指针拖动。剪切粘贴只能表达移入目标目录，不能替代同层清单换序。
- **为什么是问题**：只用键盘或无法持续按住指针的用户无法完成已列为 t70 验收 4 的内容编排。移动已有复制/剪切/粘贴替代，缺口只在排序，不能把二者混为同一覆盖。
- **依据**：`docs/specs/workbench/files-explorer.md:48,139` 与 `docs/specs/workspace/folder-kinds.md:73–74,116` 明确排序只改清单；`packages/neuro-book/src/plugins/files/shared/contracts.ts:276–277` 已有完整 `reorder` 能力。`ui-development-spec.md:416–419` 与 `docs/standards/code/frontend.md:9,62` 要求键盘路径；W3C [键盘界面原则](https://www.w3.org/WAI/ARIA/apg/practices/keyboard-interface/)要求全部交互可键盘操作，[Dragging Movements](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html#relationship-to-keyboard-accessibility-requirements)说明键盘替代与无需拖动的单指针替代分别检查。核实方式：计划完整键表/菜单/工具栏与现有服务合同静态比对。
- **建议改法**：在同一固定动作集合里增加“上移 / 下移”（首末项禁用），菜单与可聚焦按钮都可触发，直接复用拖动排序的同一纯变换和 `reorder` 调用。定义多选相邻/非相邻项的保序规则以及未列入项、缺失条目的合法性；这样无需再造一套键盘拖放会话。验收用键盘和点击两条路径确认只改清单。

### UI-05｜重要｜界面规范、虚拟列表：22 px 固定行与现有内联输入尺寸不相容

- **计划位置**：`plan.md:33–34`、`:41–42`、`:51–52`、`:119`。
- **现象**：计划固定资源行 22 px，要求同一行装 nb-ui `FormInput` 并原位显示名字错误，还要显示标签、副标题和状态；没有给出 22 px 对应的密度 token、单行排版或错误提示的空间规则。现有 `FormInput` 最小 `sm` 在 nbook/macos 下高 26 px，在 editorial/aurora 下高 28 px。
- **为什么是问题**：现有输入已经比 22 px 行高多 4–6 px。按原计划实现，只能溢出/裁掉输入和焦点环、临时撑高行而使虚拟列表的索引与真实几何错位，或私自覆盖公共控件的尺寸合同。副标题与校验文字若另起一行会加重冲突，窄面板和大字号时尤其明显；后者的实际表现尚未运行，为推断。
- **依据**：`FormInput.vue:52–55,112–118` 使用 `nb-ui-control-h-sm/md`；`packages/nb-ui/src/styles.css:40–49` 直接取尺寸 token；`themes/nbook/vars.css:63–64`、`themes/macos/vars.css:40–41`、`themes/editorial/vars.css:26–27`、`themes/aurora/vars.css:24–25` 给出上述高度。`ui-development-spec.md:41,44–45,450` 要求标准控件尺寸、零布局位移、窄屏核心操作和焦点环不裁切；`FormField.md:11,19` 的默认错误文案会另占一行。核实方式：静态尺寸计算；未运行 t70。
- **建议改法**：保留统一固定行高，直接以能容纳输入的公共尺寸 token 定行高（最少 `--control-h-sm`），让 CSS 行高与虚拟窗口的 JS 行高来自同一解析值；主题/字号改变后重算窗口及滚动锚点。名字与真实路径采用单行主次信息，完整路径通过可访问描述/提示取得；错误使用不参与行布局的关联提示或预留的反馈位置，配 `aria-invalid/describedby`。避免仅编辑行临时变高，也不要为压进 22 px 改写公共输入高度。

### UI-08｜重要｜窄屏、结果反馈：长清单与结果区缺少尺寸和滚动边界

- **计划位置**：`plan.md:40–44`、`:57`、`:90–92`、`:113`。
- **现象**：删除确认要求列出受影响项，结果区要求逐项展示源、目标、原因和复制残留范围；计划未规定项目很多、路径很长时哪个区域限高/让位、如何滚动与如何确保操作按钮仍可见。390 px 只列为截图目标。列出的公共 `Dialog` 默认宽 420 px；`AlertDialog` 的内容没有最大高度或内滚合同。
- **为什么是问题**：大批量失败不能无限挤占底部而使虚拟树视口变成零高；删除确认也不能把取消/删除按钮推到屏外。直接套公共默认值并不能保证长路径、长逐项结果在 390×844 下可完成操作。最终页面的溢出/遮挡尚未实现，为推断。
- **依据**：`docs/standards/code/components.md:47,58` 要求声明固定/伸缩、内容变多时谁让位和 390×844 结构；`ui-development-spec.md:44–45,210–212` 要求明确 overflow 所有权、窄屏核心控件可达和避免嵌套滚动。`Dialog.md:13–26` 明确默认固定宽与窄屏用法；`AlertDialog.vue:76–109` 的确认内容/动作区没有 `max-height` 或滚动区。`Toolbar.md:11–13` 已解决工具栏内部横向滚动，缺口在结果和确认内容。
- **建议改法**：组件文档先定三段布局：工具栏固定、树 `minmax(0, 1fr)`、结果区限高可收起并独立滚动；长资源地址折行且保持完整可取得，动作不被挤出。确认框限制视口尺寸，只让受影响清单内部滚动，取消/确认保持可见；碰撞和展示名表单显式用响应式 Dialog 尺寸。用 390×844、长中英文路径、多选大量删除、大批量失败和四主题明暗验证实际几何及键盘可达，不只截默认树。

### UI-11｜建议｜虚拟列表、滚动：只说明自有滚动元素，未定义尺寸与停放恢复

- **计划位置**：`plan.md:21`、`:31`、`:41`、`:89`、`:112–113`。
- **现象**：虚拟窗口只有固定行高和上下余量，没有明确视口高度变化、深处折叠后 `scrollTop` 夹取、隐藏再显示/移动视图后的重测与滚动锚点。S2 只要求 DOM 测试“只渲染视口”，没有真实几何场景。
- **为什么是问题**：视图可被收起、移到 Panel 或停放；原实例不重建，停放时真实尺寸为零。只在挂载/滚动时算窗口，或用旧索引保留滚动位置，会在恢复尺寸、前方插入/删除、深处折叠时出现空白窗口或阅读位置跳动。实际表现为推断；DOM 测试器不提供足够的真实布局证据。
- **依据**：`docs/specs/workbench/views.md:81,93` 明确实例停放而不重建与 `ViewContext.visible`；`WorkbenchViewFrame.md:14` 明确 fill 自己滚动。`packages/neuro-book/src/plugins/workbench/web/shell/teleport-memory.ts:2–18,34–38,79–88` 说明搬动/零尺寸时浏览器会影响滚动且外壳已保留元素位置。`packages/nb-ui/src/composables/useLayoutExtent.ts:4–11,43–58` 已区分布局盒、真实零和未挂载，按尺寸变化重测。`docs/testing/README.md:116` 指明需要真实布局的交互走 Playwright。
- **建议改法**：补虚拟窗口合同：用自有 viewport 的布局尺寸与滚动偏移计算区间，尺寸变化和重新可见时重算；用稳定资源地址及行内偏移保留首个可见项，折叠/删除时夹取到合法区间并协调焦点，不用隐藏状态的零覆盖记忆。保留 `layout: fill`，原生滚动元素消费已有细滚动条样式并用 `scrollbar-gutter: stable`；不要额外包一层 ScrollArea 后依赖私有 viewport DOM（其公共合同没有滚动 expose/emits）。S5 在大目录中滚到底、折叠前方分支、缩放面板、隐藏/移动后恢复，断言首末行、滚动位置和真实行几何。

### UI-10｜建议｜展开恢复：2000 条淘汰规则没有考虑祖先依赖

- **计划位置**：`plan.md:29`、`:63`、`:89`、`:101`。
- **现象**：只恢复“仍展开且祖先都展开”的目录；同时记录超过 2000 条就“丢最早的”。未说明淘汰祖先时如何处理保留下来的后代，或暂未加载的保存路径如何确认仍存在。
- **为什么是问题**：祖先通常比后代更早展开。若 `a/` 被淘汰而 `a/b/` 等后代保留，下次打开不会恢复它们，虽只丢一条，用户可能看到整片子树收起；后代还占着上限名额。首次根列出时未出现深层路径也不能据此删掉记录，因为它们只是尚未加载。此为边界逻辑推断，未运行 t70。
- **依据**：计划 `:29,63` 的恢复条件与淘汰规则；`docs/specs/workbench/files-explorer.md:53` 的按需恢复。旧 `WorkspaceFileTree.vue:290–292` 与 `workspace-file-tree.ts:249–251` 按全量树清理展开路径的办法依赖旧应用拥有全部节点，新树不能在只加载根时直接沿用。
- **建议改法**：把上限定义为可恢复的分支集合：淘汰一条时处理其后代，或保留必要祖先并以分支为单位淘汰；区分未加载与已确认不存在。恢复逐层只列已展开的祖先，某一目录读取失败保留展开意图并提供重试。S2 验收含三层恢复、祖先折叠后重开、记录超过上限和中间目录读取失败；上限值本身不用重新讨论。

### UI-09｜建议｜nb-ui 复用：现有树组件被误记为不存在

- **计划位置**：`plan.md:12`、`:25–42`、`:56`。
- **现象**：已有底座写“nb-ui 没有树与虚拟列表”，但库已经提供 `Tree` 和 `FileTree`；拖动反馈也已有 `DropFeedbackOverlay`，计划只列 `DropIndicator`。
- **为什么是问题**：新建专用虚拟树有合理理由，但“没有树”会跳过已存在的键盘导航、行状态、图标/箭头和拖动反馈合同，容易形成第二套近似样式。不能把“现有树不能直接满足全部需求”写成“现有树不存在”。
- **依据**：`packages/nb-ui/src/components/navigation/Tree.md:7–13,34–37,53,70–75` 支持受控展开、多选和上游键盘，但没有行插槽、虚拟化/拖动；`FileTree.md:11–17,73–79,95` 有独立箭头、行插槽、文件图标、右键和 HTML 拖放，但单选、固定 32 px、没有虚拟化。`DropFeedbackOverlay.md:7,11–15,23–42` 可渲染目录高亮/插入线和去重礼貌播报。`docs/standards/code/frontend.md:8,17` 与 `ui-development-spec.md:419,450` 要求优先复用并保持同类状态表达。
- **建议改法**：纠正底座列表，增加短复用表：说明本片多选、内容节点的打开/展开拆分和虚拟化为何需要专用树，沿用现有焦点、选中和主题状态基座；拖动的命中/提交仍归资源管理器，反馈优先组合 `DropFeedbackOverlay`。只把确认缺少且有公共消费者的能力加到 nb-ui，不为复用硬套现有树的数据模型。
