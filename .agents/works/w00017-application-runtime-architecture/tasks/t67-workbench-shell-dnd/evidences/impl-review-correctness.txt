## C02 — 重要 — 被动容器重排回写 location，覆盖另一窗口的迁区

- **类别**：不变量。
- **位置**：`packages/neuro-book/src/plugins/workbench/web/views/intents.ts:139`；`views/patch.ts:109`。
- **现象**：Sidebar 的 A/B/C 都使用合法默认 order=0。窗口乙把 B 迁到 AuxiliaryBar；窗口甲仍显示旧布局，把 Panel 的 D 插到 A/B 之间。中点不存在，触发 rerank，甲生成的补丁给 A/B/C 全部写 `{location:"sidebar", order:10/20/30}`。保存后 B 被搬回 Sidebar，AuxiliaryBar 变空。
- **为什么是问题**：B 的区域没有被本次用户操作主动修改，违反只重放主动字段、重排只改顺序的合同。equal order 是合法且常见的声明输入，不需要浮点精度耗尽或恶意记录。问题同时影响 `detach-view`、`move-container` 调用的 `reorderContainers`。这是计划审查 M02 的实现修正未到位：视图已有独立 `reorder`，容器 rerank 仍回写旧区域。
- **如何核实**：在真实内核、真实 Storage/SQLite 双窗口场地，经公开 `LayoutStore.actions.applyView` 重现，未绕开保存运行时。仓库根运行 `NBOOK_AGENT_TEMP_ROOT=/tmp/claude-1000/-home-notnotype-CodeRepository-neuro-book/c38df555-3a36-49c9-bf4f-4027b5da6d32/scratchpad/t67-impl/correctness bun --tsconfig-override ./packages/neuro-book/tsconfig.json /tmp/claude-1000/-home-notnotype-CodeRepository-neuro-book/c38df555-3a36-49c9-bf4f-4027b5da6d32/scratchpad/t67-impl/correctness/storage-probe.ts`，`storage-probe.json` 的 `passive-container-rerank`：保存前 B.location=`auxiliarybar`，保存后=`sidebar`，fresh 窗口的右栏容器数从 1 变 0。
- **建议改法**：给容器被动重排采用与视图 `reorder` 同样的独立字段操作：只在最新值里仍处于原 Part 时修改 order，保留 location 与身份。不要让 passive rerank 复用主动迁区补丁。

## C07 — 重要 — 半区并入覆盖收起成员的展开尺寸记忆

- **类别**：不变量。
- **位置**：`packages/neuro-book/src/plugins/workbench/web/views/intents.ts:303`、`:163`；`views/drop.ts:242`。
- **现象**：通过“移动到”把乙并到甲，再收起乙，保持甲展开；拖动整个甲容器到 Panel 戊的后半区，乙仍保持收起，但其原本未记录的 width 被保存为 `4.643288996372431`，甲 width=`115.35671100362757`，戊 width=`120`。以后展开乙使用已被改小的权重，原展开记忆丢失。
- **为什么是问题**：Spec“副作用与数据”明确要求“收起成员的展开意图……不变”。实现把 `sourceSlice.views` 中所有可见成员都纳入 `visibleMovers`，其中包含 collapsed 的成员，`splitSizes` 不分收起与展开，给它们全部写当前轴尺寸；固定 32px 的细条几何还参与来源比例。
- **如何核实**：真实 Chromium、真实菜单点击与鼠标拖放，`collapsed-source.json` 记录移动前后的收起状态；随后只读查询真实 `browser-state/storage/user.sqlite`：`SELECT revision, json_extract(value, '$.views."test.sample-views.beta".width') AS beta_width, json_extract(value, '$.views."test.sample-views.beta".collapsed') AS beta_collapsed FROM records`，revision=`15`、beta_width=`4.643288996372431`、beta_collapsed=`1`。收起状态稳定后乙仍为 32px 细条，甲 291.125px、戊 302.859375px；再真实点击乙的展开按钮，`collapsed-source-expanded.json` 的稳定宽度为乙 64px（触及最小值）、甲 275.453125px、戊 286.53125px。预先通过普通菜单合并和收起，没有执行尺寸调整。第一次 JSON 的 before 几何采在收起动画中，不用它证明 32px 或比例。
- **建议改法**：在半区求解边界区分实际成员、可见成员与参与当前分配的展开成员；收起成员随归属/顺序迁移，但不覆盖其展开尺寸。复用同一个过滤结果求比例和写尺寸，不再增加一套尺寸状态。

## C01 — 重要 — 半区前提失败仍执行保存并推进 revision

- **类别**：正确性。
- **位置**：`packages/neuro-book/src/plugins/workbench/web/state/layout-store.ts:184`；`views/patch.ts:166`；`state/layout-store.test.ts:524`。
- **现象**：另一窗口将半区目标从 Panel 迁到 Sidebar 后，本窗口用旧显示提交半区并入。`applyPatch` 记“这次并入没有保存”并返回原记录值，但 `customizations.commit` 仍调用真实 Storage.save：revision 从 `"2"` 增到 `"3"`，queue=0、save.state=`idle`。实测 display 仍是并入后的本地值，磁盘 value 没有并入；从代码推断，刷新会恢复后者。
- **为什么是问题**：Spec 与本次重点要求前提失败时整条零写入；返回相同 JSON 不能表达“跳过保存”。当前接口把拒绝当作已保存消费掉，既造成一次不应发生的写入/订阅通知，也让屏幕上的并入结果处于无需重试的 idle 状态。现有测试只比较 value，漏检 revision。
- **如何核实**：同上 `storage-probe.ts`，真实内核/Storage/SQLite 场地的 `requires-failed` 记录保存前后快照、revision、display、queue 与 patchProblems。value 完全相同，revision 确实 +1；诊断与实际写入相矛盾。
- **建议改法**：在持久化修改结果中显式表达“本次不写”，让队列跳过 save 并按已定政策结束该意图；不要用“返回旧值”冒充零写入。现有两窗口用例增加 revision 不变与显示最终状态的断言。

## C03 — 重要 — 拖放会话与命令面板并存，面板的方向键和 Enter 被拖放吞掉

- **类别**：正确性。
- **位置**：`packages/neuro-book/src/plugins/workbench/web/views/drag-session.ts:236`、`:265`；`components/WorkbenchShell.vue:213`。
- **现象**：面板标签空格拿起、ArrowLeft 选到换序落点，然后按 `Ctrl+Shift+P`，命令面板已打开且 combobox 获得焦点，但拖放仍 active。ArrowDown 不改变命令候选；Enter 只结束拖放，命令面板仍开着；Escape 的第一次也只结束拖放，不能关闭命令面板。
- **为什么是问题**：会话在 window 捕获阶段按键，却不观察焦点是否已经进入外壳外的模态界面，也不与命令宿主共享手势所有权。用户面对已聚焦的命令面板，实际按键仍控制背后的布局手势；两层交互同时存活。
- **如何核实**：真实内置 Chromium `Chrome/151.0.0.0`，1440×900，生产 e2e 工作台 `http://127.0.0.1:5197/`，真实 `page.keyboard`。`modal-during-drag.json` 记录打开前后 `drag=true`；ArrowDown 前后 `aria-activedescendant` 都是 `nb-quick-input-v-2-0-listbox-option-nbook.project.open`；Enter 后 `drag=false` 而 combobox 仍存在。截图 `modal-during-drag.png`。未伪造键盘事件。
- **建议改法**：在外壳拥有会话与命令浮层互斥：焦点进入外壳外的菜单/对话框时取消拖放；会话按键处理前核对当前交互所有权。不要在每个浮层里补一份拖放键表。

## C04 — 重要 — 工具按钮区仍被最近祖先落点接收，释放会迁移容器

- **类别**：正确性。
- **位置**：`packages/neuro-book/src/plugins/workbench/web/views/drop-dom.ts:108`；`components/WorkbenchShell.vue:312`。
- **现象**：把 Sidebar 的“样例丙”容器拖到 Panel 标题行里的“移动到”按钮中心，会显示 `move-container` 插入线；松手后丙实际迁到 Panel 末尾。
- **为什么是问题**：行为表第九行明确工具按钮区不接收。`dropHitAt` 只找最上层元素的最近 `TARGET_SELECTOR`，Panel 导航槽把 Tabs 和 single 的管理按钮一起包在 `data-switcher-band` 内；它既没有过滤控件区，也没有核对 `data-no-drag`。从代码推断，同一机制也会把 multiple 分节的标题文字/收起按钮/动作区作为内容半区接收；本条运行证据只针对 Panel“移动到”按钮。
- **如何核实**：真实 Chromium，真实 `page.mouse`，1440×900。`tool-zone-drop.json`：释放点 `{x:872,y:694}`，最上层命中是“移动到”按钮的图标；释放前 kind=`move-container`，Sidebar 有 A/B/C、Panel 有 E/F；释放后 Sidebar 只剩 A/B、Panel 有 E/F/C。截图 `tool-zone-drop.png`。
- **建议改法**：DOM 命中在寻找落点前排除工具/标题禁投区，或收窄条目带标记的包裹范围，使管理按钮不属于 Switcher 落点。对源和落点用清楚的独立排除标记，避免仅加 `data-no-drag` 却仍不在命中时使用。

## C05 — 重要 — 指针拖动时方向键漏到 Tabs，活动内容变化后会话仍有效

- **类别**：不变量。
- **位置**：`packages/neuro-book/src/plugins/workbench/web/views/drag-session.ts:240`；`views/drop.ts:298`。
- **现象**：按住已选中的 Panel 标签“样例戊”并移过 6px，拖影出现；鼠标仍按着时按 ArrowRight，标签带立即选中“样例己”，活动内容换了，但拖影和会话保持 active。
- **为什么是问题**：按键拦截只覆盖 keyboard cursor，不覆盖指针会话；而 `layoutKeyOf` 又有意排除 selected，导致这条真实可达的活动内容变化既写入选择又不取消拖动。违反拖动期间标签方向键不切换容器、活动内容变化取消的合同。不是伪造 presentation 或内部时序。
- **如何核实**：真实 Chromium 与真实鼠标、键盘，`pointer-key-leak.json`：操作前 `drag=true` 且 E selected；ArrowRight 后 `drag=true` 且 F selected，`data-selected-container` 从 E 变 F。
- **建议改法**：同一会话无论从鼠标还是键盘开始，都独占会改变拖动上下文的键；冻结源与当前目标相关的选中/可见成员/轴状态并监听失效，不能只依赖包含实际成员的全局字符串。

## C06 — 建议 — Escape 取消未释放指针捕获，首个无关键盘点击被吞

- **类别**：正确性。
- **位置**：`packages/neuro-book/src/plugins/workbench/web/views/drag-session.ts:195`、`:319`、`:364`。
- **现象**：鼠标拖动过程中按 Escape 取消、保持鼠标按下，原标签仍 `hasPointerCapture(1)=true`。随后聚焦 Panel“收起为标题头”并按 Enter，第一次被 `swallowClick` 吞掉（collapsed 仍 false），第二次 Enter 才变 true。
- **为什么是问题**：取消已清掉 active 与全局样式，却没有清掉自己持有的指针捕获，吞点击布尔位也没有限定本手势的尾随 pointer click；它会拦截别的控件的键盘 click。结束时资源与输入所有权没有同次收口。
- **如何核实**：真实 Chromium，首次 `cancel-capture.json` 用 focus 辅助聚焦；随后 `cancel-capture-trusted.json` 改成全程真实鼠标按住与 Escape、3 次 Tab、Enter，结果仍为 `{capture:{captured:true,active:false},first:"false",second:"true"}`。未派发合成指针或键盘事件。
- **建议改法**：结束时显式释放当前 pointerId 的捕获；吞点击记录本次指针手势身份，只消费匹配的尾随 click，排除键盘 `detail=0` 的点击，不保留无期限的布尔位。
