### T07 — 重要 — 正确性：含不可移动成员的整组并入仍显示有效半区，松手却拒绝，预览与动作不一致

- **位置**：`packages/neuro-book/src/plugins/workbench/web/views/drop.ts:233-243`；`packages/neuro-book/src/plugins/workbench/web/views/intents.ts:285-286`；`packages/neuro-book/src/plugins/workbench/web/views/drop.test.ts:133-139`；`packages/neuro-book/src/plugins/lab/web/fixtures/shell-scene/ShellViewsScene.vue:47-53,255-265`。
- **现象**：仅在仓库外Lab场景输入中给资源管理器声明加 `movable:false`（其容器还有可移动的大纲），真实鼠标把整个容器拖到笔记后半区，仍显示 `merge-container`、count=2和有效接收半区。松手后源仍为资源管理器、大纲，目标仍只有笔记。即界面承诺并入2个视图，实际执行整组拒绝。
- **为什么是问题**：Spec验收19要求预览与动作一致、非法成员整组拒绝。判定只核对容器成员快照，没有检查并入成员的movable；写入层才检查。名为“不可移动的视图不能起拖”的纯测试只测试单View源，不测试含不可移动成员的容器源。计划要求Lab摆出不可移动成员，但5个Lab视图和6个产品测试视图全可移动，也没有相应开关，所以13例e2e没有触达此问题。
- **如何核实**：原样运行的Lab场景`views-merged`，只改实验副本catalog的一个输入字段，未改产品判定、会话或意图实现；内置Chromium真实指针两次复现同一结果。见实验目录 `lab-invalid-member-preview.json`、`lab-invalid-member-preview.png`。与纯内部调用不同，证据通过真实界面起拖、显示反馈、释放。
- **建议改法**：在内容区产生整组并入预览之前，对全部实际成员复用与意图层同一movable前提；不把检查扩大到无关的容器换序。给现有Lab场景增加不可移动成员开关，并在已有整组并入测试里覆盖“无有效接收半区且成员/记录全不变”。

### T04 — 重要 — 测试：移除放下时的已显示动作门禁，13个真实Chrome用例全部通过

- **位置**：`packages/neuro-book/src/plugins/workbench/web/views/drag-session.ts:214-221`；`packages/neuro-book/src/plugins/workbench/web/views/drop.test.ts:180-186`；`packages/neuro-book/e2e/workbench-dnd.e2e.ts:58-65`；`docs/specs/ui/workbench-shell.md:224,274`。

- **为什么是问题**：这条门禁防止最后一次指针移动尚未呈现就松手时，提交用户没看到的另一插入位/半区。现有 e2e 均先等待落点或分8步移动后才释放，覆盖不到最后一帧的分歧；即使该核心不变量整体删除仍绿。

### T01 — 建议 — 测试：以整个 user 分区的 MAX(revision) 代替写入计数，断言依赖 Storage 的非合同实现

- **位置**：`packages/neuro-book/e2e/workbench-dnd.e2e.ts:84-98,116-121,201-219,255-271`；`docs/specs/storage/persistence.md:33,129`。
- **现象**：`revisionOf` 查询全部 owner、key、client 的 `MAX(revision)`，随后以 `revision + 1` 断言一次写入；读取本页 client 的返回值被丢弃。Storage 只保证 revision 单调且不复用，明确不保证连续。`expect.poll(...).toBe(revision + 1)` 也只证明某个时刻达到该值，不能排除之后再写一次。
- **为什么是问题**：合法的 revision 分配策略改变会误报；其它记录或客户端写入会污染计数。首条用例到拖动预览之后才取基线，不能证明拖动期间没有写入。现有注释承认依赖，但没有把“只接纳一次结果”变成稳定的验收证据。
- **如何核实**：逐行对照上述 SQL、所有 `revisionOf` 调用及 Storage Spec；本项为已核实的测试合同缺陷，不据此声称当前产品重复写入。
- **建议改法**：在测试专用 SQLite 库中对 `records` 的 INSERT/UPDATE 建审计计数（触发器随事务回滚），按 `owner='nbook.workbench'`、`key='views-customizations'` 和本页 client 过滤；从拿起前记录基线，并在手势完成及持久化队列空后核对增量为 1。revision 仅作标识和条件保存使用。
