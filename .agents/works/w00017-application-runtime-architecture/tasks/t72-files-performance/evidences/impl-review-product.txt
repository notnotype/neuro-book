## 已核实发现

### 1. 重要：等待控件就绪的焦点意图不随用户离开编辑器失效，迟到的 Monaco 抢回焦点

- **类别**：正确性 / 不变量。
- **位置**：`packages/neuro-book/src/plugins/editor/web/area.ts:345-354,525-533`；`packages/neuro-book/src/plugins/editor/web/components/EditorArea.vue:45-47`。
- **现象**：同组保留 Markdown 标签 A 和正在首次加载的 JSON 标签 B；回 A，在正文里按 Ctrl+W 关闭 A，B 成为活动标签。Monaco 下载尚未完成时点击资源管理器并在树里操作，焦点已明确在树上；放行 Monaco 下载后，`registerHandle` 又聚焦 B，焦点从树移回编辑器。真实页面结果 `before={tree:true,tag:"DIV"}`，`after={tag:"DIV",group:"g0",tree:false}`，见本目录 `async-focus-result.json`。
- **为什么是问题**：`focusWhenReady` 只在成功登记活动句柄时清零。用户焦点移出、切组、换标签都不撤销或换代；检查 `activeHandle === handle` 只能挡住非活动组，挡不住活动组里已经失效的聚焦意图。用户在树上继续按键会突然作用于编辑器；这不满足 `editor.md` 输出 8 的“迟到结果不改变焦点”，也破坏 `files-explorer.md:59,61` 的键位按实际焦点隔离。
- **如何核实**：已运行生产构建与真实 Chromium。用浏览器请求拦截只扣住实际 `assets/editor.api-*.js` 下载，按上述真实点击与键盘路径操作，用户先移到树，再放行网络；未直接调用控制器、未伪造组件登记时序。正常 Markdown / Monaco 拆分和关闭组的焦点已另外验证通过。
- **建议改法**：把待聚焦意图绑定到目标组、标签/绑定代次，并在用户主动将焦点移出编辑区或改变目标时取消。布局重挂导致的临时失焦与用户的新焦点意图区分；就绪回调只有目标和意图代次仍一致时才聚焦。回归覆盖“尚未就绪 → 关闭/拆分请求聚焦 → 用户回树 → 控件就绪仍留在树”。
- **来源边界**：关闭路径的 `focusWhenReady` 标记在 `47e3b1fc` 已存在；本项是 t72 将重挂焦点交给 `area.ts` 后仍未覆盖的焦点意图失效边界，不声称它由新增 `refocusOnRemount` 单独引入。新增拆分逻辑也使用同一等待标记，但没有把“首次 Monaco 未就绪时拆分”作为复现前提：产品 `active` 命令门禁此时不允许拆分。

### 2. 重要：清空预取 Promise 不能清空浏览器的失败模块缓存，视图“重新加载”仍永久失败

- **类别**：正确性 / 失败与恢复。
- **位置**：`packages/neuro-book/src/plugins/explorer/web/plugin.ts:73-80`。
- **现象**：入口预取 `FilesExplorerView-*.js` 时发生一次暂时网络失败，资源管理器显示“视图加载失败”与“重新加载”。网络恢复后该模块地址用普通 `fetch` 已返回 HTTP 200、47526 字节；点“重新加载”仍立即显示同一失败，文件树没有出现。该次完整实验共两次模块地址请求：失败的 import 和验证恢复的 fetch；重试本身没有第三次网络请求，见本目录 `view-retry-result.json`。
- **为什么是问题**：`viewModule = null` 只清掉应用层 Promise；同一文档里对同一 URL 的动态 import 失败会留在模块映射里，重复 `importView()` 直接拒绝，不重新下载。预取把失败机会提前到了视图挂载之前，但实现注释与 Task 的“预取失败后下次 load 重试”保证没有成立；暂时网络故障后资源管理器无法经提供的原位恢复入口重新使用。
- **依据与核实**：已运行真实生产构建与 Chromium。首次请求在真实网络层 abort；随后解除失败、同址 fetch 为 200；真实点击“重新加载”后仍失败且没有新 import 请求。依据 `files-explorer.md:71` 的渲染重试仍接同一控制器、`:34` 的失败可见与恢复入口，以及 `plugin.ts:75` 明确承诺的重新下载行为。
- **建议改法**：使用实际支持重新取模块的装载入口，重试时变更模块请求的尝试标识并保证构建后的依赖路径可用，或在无法清除原生模块失败缓存时提供明确的页面重载恢复。需要覆盖“预取失败、网络恢复、点击重试、树可操作”，不能只断言缓存变量已置空。
