## 已核实发现

### 1. 重要：16 ms 达标结论没有按采纳的呈现口径判定，已有数据也不支持统一“达标”

- **类别**：测量有效性 / 验收结论。
- **位置**：`packages/neuro-book/scripts/perf/page-agent.ts:179-205`；`packages/neuro-book/scripts/perf/browser-runner.ts:475-515`；Task `README.md:28,41`；`evidences/final-3000/summary.json:111-132,322-343`。
- **现象**：计划明确用 `presented`、帧数与点击 Event Timing 验收 16 ms；最终 README 却用 committed 10–15 ms 判“达标”。正式 B1 的 presented p50/p95 为 31/31.2 ms；C2-md 连 committed p95 都是 25.7 ms、最大 35 ms。点击 Event Timing 虽在页面代理收集，却没有写进任何 B/C 场景输出。`feedbackFrames=2` 只是 pointerdown 后该代理 tick 被调用两次，并没有记录输入落在哪个显示帧、实际 Paint 或展示时刻。
- **为什么是问题**：Spec 要求选中和标签在下一帧、16 ms 内切换；现有实现只提供首次 rAF 观察与再后一帧的上界，不能把首次观察小于 16 ms 和回调计数直接换算成已呈现。即使选择 committed 为较弱判据，C2-md 的长尾也被总体“达标”结论遗漏。产品是否确实达标仍需进一步呈现证据，本条不将 presented 上界直接当作产品真实延迟。
- **依据**：`docs/specs/workbench/files-explorer.md:127,136,201`；t72 `plan.md:35-37,104`；已采纳的 `plan-review-method.txt:19-27,99-107`。
- **如何核实**：核对代码与已提交正式 JSON；本条是对现有测量证据和判定的直接核实，未重新运行正式 3000 文件测量。
- **建议改法**：保留 committed/presented 的观察值但明确它们是采样界限；逐次保留点击的 Event Timing 或 Chrome Paint/Presentation trace，按既定口径给出 p50/p95/最大值和未达项。证据补齐前把“16 ms 达标”改为未验证；不能用 committed 替代计划里的 presented 后继续声称同一标准已满足。

### 2. 重要：多数正文样本未经真实输入核验，属性判据可以产生假成功

- **类别**：测量正确性 / 验收覆盖。
- **位置**：`packages/neuro-book/scripts/perf/browser-runner.ts:274-286,475-486,500-539`；`packages/neuro-book/scripts/perf/page-agent.ts:142-151`。
- **现象**：B1/B2 只在全部冷打开完成后对最后一个文件调用一次 `verifyInput`，含控件代码的首次打开与中间样本没有核验；C1-md、C2-md、C1-code、C2-code 完全没有真实输入核验，双组也只有富文本场景末尾一次。`verifyInput` 只核对 DOM 出现记号、撤销后记号消失及 dirty 为 false，未要求输入曾令文档 dirty 为 true。
- **矩阵遗漏**：计划C1要富文本/源码 × 单/双组各30次，但代码只有 `C1-md-split`，没有 `C1-code-split`。结果只有15个已实现id（A1+A2合并），缺源码双组格；单凭README的“16”本身不算缺陷（拆算A1/A2时也有16个场景），问题是“富文本与源码、单组与双组”宣称超出了已测矩阵。
- **为什么是问题**：DOM 内文字可输入不代表输入已提交到当前文档；例如控件输入绑定失效时，DOM 修改与撤销仍能通过，dirty 始终为 false 也能通过。其它样本只读 contenteditable/textarea 属性，无法排除首次加载、切换绑定或活动组焦点尚未就绪的假快结果。Task README 与计划声称“每个正文样本”均通过真实输入核验，与实现不符。
- **依据**：`docs/specs/workbench/files-explorer.md:128,137,201`；`docs/specs/workbench/editor.md:92`；t72 `plan.md:40,57,114`；采纳的 `plan-review-method.txt:29-37`。
- **如何核实**：直接读取页面判据与 `verifyInput` 全部调用位置（`grep` 的 3 处：定义、冷场景末尾、富文本双组末尾）；本条缺陷影响属于**从代码推断**，未将未发生的输入绑定故障说成当前产品故障。当前 1000 文件小样本全场景通过，只证明现有弱核验能通过。
- **建议改法**：按计划对每个成功正文样本在计时外验证目标文档的真实输入，等待其 dirty 变 true 或可观察的文档提交，再撤销并等待正文与 dirty 恢复；失败样本不得进入成功统计。至少覆盖两个编辑器、单/双组及首次加载、热切换各路径。

### 3. 重要：展开目录的分布几乎全部测缓存重开，p50/p95 没覆盖真实列出成本

- **类别**：测量有效性 / 样本口径。
- **位置**：`packages/neuro-book/scripts/perf/browser-runner.ts:561-592`；`packages/neuro-book/src/plugins/explorer/web/tree/model.ts:155-174,259-271`；`evidences/final-3000/summary.json:641-699`。
- **现象**：D1/D2 在同一页、同一目录上收起再展开 10 次，收起保留 listing 缓存且后续未过期时不再 `list`。正式 D2 的 10 个成功样本合计只有 1 次 Files `list`。本次 1000 文件 smoke 同样 D2 `list ×1`，完成 presented p50/p95 60.4/76.6 ms。报告没有将首次真实列出与其余 9 次缓存展开分开，却把总体 p50/p95 当作“展开内容目录（每项探测 index.md、读 content.xml）”证据。
- **为什么是问题**：最近秩 p95 在 10 个样本里只是最大值；一条真实列出样本无法给出列出成本的分布，p50 基本只反映固定几帧的缓存 DOM 观察。服务端逐项 lstat、content.xml 读取或大目录列出变慢可以完全不改变 p50。D1 连请求数也不输出，无法从报告辨认冷热比例。
- **依据**：`docs/specs/workbench/files-explorer.md:138,201` 要逐项测展开几百个子项并记录 p50/p95、请求数；t72 `plan.md:59-60,65` 与采纳的计划审查对内容目录成本及冷/热状态分离的要求。
- **如何核实**：运行真实生产构建后的小样本命令 `env NBOOK_AGENT_TEMP_ROOT=<本报告目录> bun run perf:files -- --count 1000 --iterations 5 --opens 3 --skip-build --out <本报告目录>/smoke-1000`；输出见 `smoke-1000/report.md:22-23`、`summary.json`。同时核对树模型收起不丢 listing、ensureVisible 只列未缓存/过期目录的实现。上面命令中的实际完整路径见报告末尾验证记录。
- **建议改法**：把首次展开和缓存展开分组；真实列出格每次用新上下文或不同的等规模未列出目录，至少重复计划要求的次数。两组各自给 p50/p95、样本数与 list/Storage 请求数，不把一个 cold 样本混入九个 warm 样本后宣称已覆盖列出性能。

### 4. 重要：A4 在展开记录仍未恢复完时结束，未测到约 1300 行恢复态的启动成本

- **类别**：测量正确性 / 起止边界。
- **位置**：`packages/neuro-book/scripts/perf/page-agent.ts:118-127`；`packages/neuro-book/scripts/perf/browser-runner.ts:439-459`；`packages/neuro-book/src/plugins/explorer/web/tree/model.ts:134-152,167-174`。
- **现象**：A4 与 A1/A2 共用“根下四行存在”的 treeReadyAt，出现这些父目录时便停止计时、随后关闭页面，未等待恢复的子目录列出与树投影完成。真实生产探针恢复 10 卷与宽目录时，treeReadyAt=356.7 ms，DOM 仅有 6 条资源行、2 条 loading，树内容高度 860 px；loading 消失时已到 474.4 ms，高度变成 18642 px。计时漏掉约 117.7 ms 的恢复工作。
- **为什么是问题**：A4 专门补足计划审查指出的“恢复多目录、完整行数组投影”增长路径，当前数字只表示父目录先到，后续展开与投影不在测量窗口内。正式报告用 A4 360/376 ms 代表恢复多个展开目录不能支撑该结论。A4 也没有采集请求数、长动画帧或每轮恢复状态，因此不能区分成功恢复、仍加载、偏好未落盘。
- **同一终点的操作核验缺口**：A1/A2的ArrowDown核验只等待 `document.activeElement.closest("[data-explorer-tree]") !== null`（`browser-runner.ts:403-406`），点击目录行已经把焦点放在树上；没有比较按键前后的aria-activedescendant/目标行，故按键不生效也通过。A3/A4甚至没有该核验。页面存在代理但树不接受方向键的情况仍可被记为“可操作”（**从代码推断**）。
- **依据**：t72 `plan.md:54,65,107`；采纳的 `plan-review-product.txt:74-81`；`docs/specs/workbench/files-explorer.md:135,139,201`。
- **如何核实**：真实生产构建与 1000 文件隔离项目，执行 `node /tmp/claude-1000/-home-notnotype-CodeRepository-neuro-book/c38df555-3a36-49c9-bf4f-4027b5da6d32/scratchpad/t72-impl/harness/runtime-probe.mjs`。证据 `runtime-probe.json` 的 `restoredReady`、`restoredAfterLoading` 与 `restored-after.png`；没有伪造 RPC 或替换产品逻辑。
- **建议改法**：保留根 listing ready 为独立指标；A4另等预置展开集合真正恢复、相应目录listing完成及完整行数/树高度稳定，再结束窗口。准备阶段等待展开记录落盘；每轮核对恢复集合与最终规模，并保存期间LoAF、请求与实际行数。可操作核验须比较ArrowDown前后活动后代/焦点行确实移动，不能只核对焦点容器仍为树。

### 5. 重要：E1 用中文 `keyboard.type` 却只统计 key 事件，输入再慢也会被漏掉

- **类别**：测量正确性 / 假阴性。
- **位置**：`packages/neuro-book/scripts/perf/browser-runner.ts:662,666-670,683-685`；Task `README.md:30,45`；`evidences/final-3000/summary.json:727-754`。
- **现象**：E1 输入全是中文 `后台改写期间的输入`，随后只取 `event.name.startsWith("key")`。Playwright 对没有键盘布局映射的中文走文本插入，本次 Chrome 生产页实际只发可信 `beforeinput`/`input`，没有 keydown/keypress/keyup。加入页面级 60 ms beforeinput 工作后，代理确实采到 beforeinput 的 72–80 ms Event Timing 与约 64–74 ms LoAF，但 E1 的 key 过滤仍得到 0；同一页面输入 ASCII 则采到 keydown/keypress duration=64 ms。正式证据和本次 smoke 都为“键入事件共 0 个”。
- **为什么是问题**：报告把未测到键盘事件当成“键入事件都在 16 ms 以内”，没有输入延迟、处理时长与 next-paint 的有效样本。即使输入路径明显卡顿，该指标仍为空并且 E1 仍可 ok；这不是 durationThreshold 筛掉快事件，而是输入方式与筛选事件类型不匹配。
- **依据**：`docs/specs/workbench/files-explorer.md:139,201`；t72 `plan.md:37,62,107`；采纳的 `plan-review-method.txt:99-107` 要求观察器不产出时不能当作 0。
- **如何核实**：执行 `runtime-probe.mjs`，`runtime-probe.json` 的 `typingChinese` 与 `typingAscii` 保留可信 DOM 事件、完整 Event Timing 和 LoAF。仅在本报告目录探针中添加 beforeinput 工作，没有改产品代码；先用真实 Chrome 实证输入路径与过滤结果，不据实验负载声称产品本身卡顿。
- **建议改法**：用能产生真实键盘事件的固定输入协议（例如 ASCII 按键），或按 beforeinput/input 及其交互语义完整采集中文输入；不要只过滤 key。记录实际发出/观察事件数；没有有效事件时把指标记为不可用、不能给达标结论。更新正式结论并重测该单场景。

### 6. 重要：无效 `--only` 不执行任何场景却返回 0，未执行状态没有闭合

- **类别**：失败处理 / 验收假成功。

- **现象**：`--only` 只解析字符串，不校验场景名；wanted 不匹配时直接返回，results 没有 not-run 项。实际 `--only not-a-scenario` 执行后退出 0，`summary.json` 为 `results: []`、`problems: []`，Markdown 只有空结果表。使用计划中的 A1/A2/C1 等概念名而不是脚本内部组合 id 也有同类风险。
- **为什么是问题**：用户/自动化想运行的目标没有执行，却得到成功退出与报告，违背“任一未执行或缺样本非零”的验收合同。当前 `some(status !== ok)` 对空数组为 false，也没有核对请求场景集合与实际结果集合。TypeScript 的 not-run 联合分支从未被构造。
- **依据**：`docs/testing/README.md:148`；t72 `plan.md:26`；采纳的 `plan-review-feasibility.txt:36-43`。

### 7. 重要：逐次样本、操作起点和点击事件没有落盘，正式分位数与时间窗无法复核

- **类别**：证据完整性 / 可复现性。
- **位置**：`packages/neuro-book/scripts/perf/browser-runner.ts:309-322,475-492,500-515,698-699`；`packages/neuro-book/scripts/perf/files-perf.ts:132-143`。
- **现象**：所有 ArmResult 都立即拆成数字数组并汇总，返回时没有 `raw`；首次冷打开也只保留两个汇总值。页面代理的 start、逐次 committed/presented/帧数、点击 Event Timing、longtask 及进度条所属操作没有写进结果。外壳只写 summary.json 与 report.md，计划指定的 samples.json.gz 完全未生成；本次 smoke 输出目录也确实只有这两个文件。
- **为什么是问题**：统计函数测试通过不能证明输入数据、冷/热划分和归属窗口正确。已提交的正式证据无法重算 p50/p95、找出缺样本或判断异常值对应哪个文件/第一次加载；进度条只有 B–F 这样的大场景标签和页面绝对时间，没有操作 start 可对齐，无法核实是否在 800 ms 前出现。运行临时根默认删除后这些证据不可恢复，不能靠下次重跑补回当前正式结论。
- **依据**：t72 `plan.md:28,37,44`；采纳的 `plan-review-feasibility.txt:72-79` 明确要求可重算分位数及逐次压缩记录；`docs/testing/README.md:146-147`。

- **建议改法**：保存每次操作的场景/轮次、地址、start、全部 ArmResult、事件/进度条归属和失败信息，压缩写入独立 samples.json.gz；汇总从这份同源数据生成。明确哪些指标是不可用或缺采，不把接口中声明但从未输出的 events 当作已有证据。

### 8. 重要：合法的 `--only C1-code` 单场景无法独立运行，依赖被过滤掉的 B2

- **类别**：场景隔离 / 可复现性。
- **位置**：`packages/neuro-book/scripts/perf/browser-runner.ts:495-505,524-528,563,595-597`。
- **现象**：源码热切换的前置只双击 data 下的文件，却不展开 data；data 的展开放在 B2 的测量 body 中。`--only C1-code`、`--only C2-code` 时 B2 被跳过，reveal 扫描树后找不到源码行。同样，D3 对 notes 的展开依赖 D1，而 D3 只展开 notes/wide；单跑 D3 的父目录仍折叠。
- **为什么是问题**：用户需要在共享机器上只跑单场景复测，合法场景仍因前一个场景未执行而失败；全场景跑通掩盖了这种依赖。场景前置与“是否计入测量”必须分离，否则 --only 的入口不具备承诺的可复现性。
- **依据**：t72 `files-perf.ts:7` 的 `--only` 接口；计划场景矩阵与按单场景复测的 S3 流程。不是要求产品支持额外行为。
- **如何核实**：真实运行原始 Node runner：`node scripts/perf/browser-runner.ts /tmp/claude-1000/-home-notnotype-CodeRepository-neuro-book/c38df555-3a36-49c9-bf4f-4027b5da6d32/scratchpad/t72-impl/harness/single-code-config.json /tmp/claude-1000/-home-notnotype-CodeRepository-neuro-book/c38df555-3a36-49c9-bf4f-4027b5da6d32/scratchpad/t72-impl/harness/single-code-result.json`，仅 C1-code、iterations=5；退出 1，错误 `树里找不到 [data-explorer-row="project://data/source-059.json"]`。C2-code/D3 同类路径为**从代码推断**。
- **建议改法**：每个场景显式建立自己依赖的展开、控件与文档预热状态；共享 helper 可以复用，但必须由本场景无条件调用。--only 只选择要统计的场景，不应该跳过它的必需前置。

### 9. 重要：E1 正式样本实际只改写 340 个文件，却按 500 文件压力给结论

- **类别**：样本真实性 / 测量规模。
- **位置**：`packages/neuro-book/scripts/perf/browser-runner.ts:631-642,659-660`；`packages/neuro-book/scripts/files-sample.ts:72-75,92-94`；Task `README.md:30,45`。

### 13. 重要：A1/A2 失败后旧页面与服务留到整个runner结束，污染后续场景

- **类别**：失败收口 / 跨场景隔离。
- **位置**：`packages/neuro-book/scripts/perf/browser-runner.ts:353-363,390-413,695-699`。
- **现象**：A1/A2 在循环里创建server、context与session，没有每轮finally；只有操作全部成功才 closeSession 与 shut。`openPage`、ArrowDown等待或其它页面步骤失败时，run捕获异常并继续A3/A4/B–F，前面的context/页面仍开着、service仍在servers集合里，直到整个runner的finally才停止。
- **为什么是问题**：失败后的测量继续跑是设计要求，但旧页面仍持项目租约、持续WebSocket/观察器与后台任务，且本机多一个服务/项目子进程；后续“冷服务”“资源保留”“后台不冻住”不再具有承诺的隔离起点。总体退出非零不等于后续ok样本仍可信。最终清理能避免正常异常返回时长期泄漏，但无法修复中途跨场景污染。
- **依据**：t72 `plan.md:24-27`、采纳的 `plan-review-feasibility.txt:90-106`；`docs/testing/README.md:20`。
- **如何核实**：逐分支读取 run 的异常捕获、A1/A2资源拥有范围与最外层finally；这是**从代码推断**，本次真实A1/A2小样本均成功，未人为让实际产品页面失败。未声称观察到常驻进程泄漏。
- **建议改法**：每轮server与context分别用try/finally拥有；打开失败也关闭刚创建的context，然后停服务并核对退出码，再允许后续场景继续。清理失败保留句柄到最终兜底并记录problems。

### 14. 重要：spawn 的 error 未被接住，启动失败绕过runner的报告与finally

- **如何核实**：真实执行 `env PATH=/tmp/claude-1000/-home-notnotype-CodeRepository-neuro-book/c38df555-3a36-49c9-bf4f-4027b5da6d32/scratchpad/t72-impl/harness/empty-bin /usr/bin/node scripts/perf/browser-runner.ts /tmp/claude-1000/-home-notnotype-CodeRepository-neuro-book/c38df555-3a36-49c9-bf4f-4027b5da6d32/scratchpad/t72-impl/harness/spawn-failure-config.json /tmp/claude-1000/-home-notnotype-CodeRepository-neuro-book/c38df555-3a36-49c9-bf4f-4027b5da6d32/scratchpad/t72-impl/harness/spawn-failure-result.json`，退出1，原始Node错误如上，result文件不存在。PATH仅对该命令生效，没有更改全局环境。Bun外壳同类事件边界为**从代码推断**；该探针结束后进程列表未见本次残留Chrome或服务。
