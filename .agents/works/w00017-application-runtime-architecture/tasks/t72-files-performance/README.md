# NeuroBook v2 Files 竖切五：性能验收

## 目标与范围

第 6 步 Files 竖切的最后一片（分解见 [t68 的计划](../t68-files-resource-layer/plan.md#第-6-步分解)）：在生产构建、参考机器的本机浏览器上，用约 3000 个文件的隔离项目逐项测资源管理器与编辑器区的性能标准，按测量修正，给出可复现的测量脚本与证据。

实施计划：[plan.md](plan.md)。

行为合同：[`workbench/files-explorer.md`](../../../../../docs/specs/workbench/files-explorer.md) 的“打开与切换”（性能标准表）与验收 12；性能标准表的“第二次打开”按开发者 2026-10-10 的决定由约 300 毫秒改为约 400 毫秒，其余行为合同未变。

## 前置

Files 竖切四 [t71](../t71-editor-area/README.md)。

## 当前状态

- 2026-10-09 计划起草；三个 omp 计划审查（测量方法、产品性能结构、可实施性）共 39 条发现（阻断 4 条：300 文件样本生成不了、样本没有源码文件、同一浏览器上下文共享客户端身份会恢复会话、Bun 跑 Playwright 会卡），全部核实成立并入计划，报告见 `evidences/plan-review-*.txt`，取舍记入待确认清单。
- 2026-10-10 S1 测量脚本：`bun run perf:files`（`scripts/perf/files-perf.ts` 生成样本、构建、出报告与清理；浏览器部分由 Node 运行的 `browser-runner.ts`；页面代理 `page-agent.ts`；纯函数 `stats.ts` 有 Bun 测试）。样本生成器加了源码文件（`--sources`）与宽目录校验（`--wide` 放不下时报错）。小样本冒烟（600 个 Markdown、20 个源码文件、宽目录 100 项，每格 3 次）全部 16 个场景通过。
  - 冒烟发现并修正了三个产品缺陷（各自提交，变异检查都能杀死）：preview 连续替换超过保留上限后，换下的视图状态键回到最近列表、淘汰循环摘不掉它而卡死页面（`2db49dde`）；t71 的焦点修正让重挂的控件自己抢焦点，拆分后原组把活动组抢回去，从资源管理器打开的文件落进原组（同一提交，改为由编辑器区只把焦点交给活动视图，拆分把焦点交给新组）；窄组里新打开的标签被标签条裁掉、点不到（`8a9bf8ef`，活动标签换了时横向滚到完整可见）。另外 Monaco 的语言服务在模型释放后以它自己的取消错误拒绝在途请求，页面多一条未处理的拒绝，改为只忽略这一种。
  - 小样本上的参考数（不是正式结果）：打开项目约 410–550 ms，已打开过的切换 27–48 ms（presented），第一次打开富文本约 96 ms、源码约 409 ms（含 Monaco 加载），展开目录约 60–77 ms，滚动帧间隔约 16.6–18 ms，外部改写 500 个文件时没有长动画帧。
- 2026-10-10 S2 正式基线（3000 个 Markdown、60 个源码文件、宽目录 400 项，每格 30 次、打开项目 10 次，`evidences/baseline-3000/`）与规模扫描（1000、2000 个文件，每格 10 次，`evidences/scale-*/`）。全部场景通过，进度条从未出现。对照性能标准：
  - 打开项目（服务刚启动）p50/p95 563/655 ms，1 秒内达标；第二次打开（宽限期内）428/451 ms，**标准“约 300 ms”未达到**。
  - 选中与标签：点击后第一帧里状态就已改好（committed 10–15 ms），下一帧呈现（presented 27–31 ms，2 帧），达标。
  - 正文：已打开过的 27–44 ms（presented），未打开过的章节 48 ms，第一次打开富文本（含控件代码）98 ms，都达标；第一次打开源码文件 385 ms（含 Monaco 加载，标准只说章节）。
  - 展开 400 项目录 60–76 ms、内容目录 60–94 ms，滚动帧间隔 p95 17 ms，没有长动画帧；外部改写 500 个文件时连续键入只有一个 51 ms 的长动画帧，键入事件都在 16 ms 以内；资源保留 5 轮堆 31.5–32.1 MB、关闭后控件为 0。
  - 规模扫描：打开项目、未打开过、已打开过的耗时在 1000/2000/3000 个文件之间不变（第二次打开 417–428 ms），不随文件数增长。
- 2026-10-10 S3 第二次打开的归因与修正：页面里的时间线（RPC 帧与资源请求按导航对齐）与 CPU 采样（未压缩的构建）显示时间花在启动的固定成本上：脚本加载与执行到握手约 90 ms；命令声明的校验约 55 ms（插件宿主每次查询都重新校验，`runtime.plugins` 输出 23 规定不缓存，每次都跑 TypeBox 解释执行的 `Errors`）；工作台外壳挂载约 130 ms 的主线程工作（含第一次布局约 40 ms）；资源管理器到视图挂上之后才读偏好记录、下载视图代码、列根目录。
  - 修正：命令声明改用编译过的 TypeBox 检查器先放行合格的声明（校验从约 55 ms 降到约 15 ms）；资源管理器在入口激活时就打开偏好记录并开始下载视图代码，控制器仍在视图第一次挂上时才建（files-explorer 第 71 行的口径不变）。第二次打开降到 p50 393 ms（新的浏览器上下文）、379 ms（同一上下文）。
  - 剩下的差距（约 80–90 ms）在工作台外壳的挂载与资源管理器“视图挂上才建控制器、才列根目录”的串行上，记入待确认清单；开发者 2026-10-10 接受约 390 ms，files-explorer 的标准改为“约 400 毫秒”。
