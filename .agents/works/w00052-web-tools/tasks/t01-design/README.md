# 设计：搜索后端、读取的引擎与正文抽取、与浏览器插件的关系

## 目标与范围

定 `web_search` 的搜索后端（自建、托管服务、要不要用户自己填密钥）、`web_fetch` 的读取引擎与正文抽取（直连、退回浏览器；w00034 定了不做反检测伪装，jina reader 的伪装指纹请求同属此类）、输出格式与大小上限，以及与浏览器插件（w00034）的关系。

合同：只做设计，行为合同未变。

## 决定

| 编号 | 日期 | 决定 |
|---|---|---|
| 1 | 2026-11-19 | 先做本插件，再做 w00034 的浏览器插件（w00034 t01 决定 8） |
| 2 | 2026-11-19 | `web_search` 支持各大搜索 API（Exa、Tavily 等），优先用 [DeepSeek 的搜索接口](https://api-docs.deepseek.com/zh-cn/guides/search) |
| 3 | 2026-11-19 | 第一版只实现 DeepSeek 一家（搜索与读取）；Exa、Tavily 以后再加 |

## 设计审查

计划第 2 稿（`7e88e7717`），设置页派 Claude Sonnet，后端与计划整体派 omp。

Sonnet（9 条：重要 7、建议 2，[`evidences/design-review-sonnet.txt`](evidences/design-review-sonnet.txt)），主会话核对了它引用的 `forms.md` 输出 31、AI 分类现有的 order、`models-store.ts` 不翻译的约定；处理后成计划第 3 稿：

| 条 | 问题 | 处理 |
|---|---|---|
| 1 | 没有数据模块，填完直接点“检测”时写入与检测并发、得 `no-key` | 成立，要改：加 `web/search-store.ts`，同一家的检测等在途写入结束再发 |
| 2 | 检测由服务端出文字；密钥变了旧结果不失效；检测计费却没有进行中的处理 | 成立，要改：`check` 只交码与详情，浏览器按语言写；写入、清除后清结果；进行中停用按钮，旁边写“会发一次搜索” |
| 3 | 没写 `layout` 与 `order` | 成立，要改：单列、每家一节，`order: 22` |
| 4 | 与模型页的密钥分不清；`env:` 写法被当原文存 | 成立，要改：标题、说明、关键词避开模型页；说明写清分开存放；`env:` 开头原位提示、服务端拒收 |
| 5 | 照抄 `ProviderDetail` 的密钥草稿逻辑，与 `forms.md` 输出 31 的 `SecretInput` 重复 | 成立，接受取舍：插件内抽一个 `ApiKeyField` 给各家共用，不动已实现的模型页；与模型页、`SecretInput` 的合并记进 Work 的后续 |
| 6 | 漏了文字目录、分区 id、Lab 替身与场景登记 | 成立，要改：逐项写进计划 |
| 7 | 对照模型页漏写的行为（读取中、只读、写失败通知、草稿、检测各状态、无障碍），`pages.ts` 不能直接复用 | 成立，要改：逐条写进计划与设置页 Spec；新写包装 |
| 8 | 验证走不到真实合同；地址写死，检测成功路径没法在本机测；没断言不回显 | 成立，要改：DeepSeek 地址改成只在设置文件里的配置项 `nbook.web.deepseekBaseUrl`，测试与 e2e 指向本机假端点；数据模块的合同测试接真实服务端；新增 `web-settings.e2e.ts`；DOM 测试断言不回显 |
| 9 | 设置页合同塞进工具 Spec；密钥输入边界没写 | 成立，要改：另建 `web/settings-page.md`；去首尾空白、空串与 `env:` 拒收 |

omp（16 条：阻断 2、重要 14，[`evidences/design-review-omp.txt`](evidences/design-review-omp.txt)；第 7、16 条带真实运行的实验），主会话核对了第 2、3、4、8 条引用的 Spec 与代码；处理后成计划第 4 稿：

| 条 | 问题 | 处理 |
|---|---|---|
| 1 | 内容标记能被正文里的结束标记打断；结构值与存档没有来源规则 | 成立，要改：转义结束标记与网址属性；存档首行写来源与提示；Spec 写明标记只是提示 |
| 2（阻断） | 内置插件不能在插件管理里停用，计划却这样承诺 | 成立，要改：删掉这句（作者的错误说法，开发者确认的是“内置”）；Spec 写怎样用工具绑定或权限规则去掉 |
| 3（阻断） | 内置插件的入口在启动时激活，开凭据库失败会让整个应用起不来 | 成立，要改：密钥改存 JSON 文件，入口激活时不读不写，用到时才读，失败得 `credentials-unavailable` |
| 4 | 顶层调用也带全文结构值，会话里多存一份、绕过预览 | 成立，要改：同 `read`，只给 eval 里的调用；`markdown` 上限 20 万字 |
| 5 | 写入确认、工具取密钥与停止的先后没有合同 | 成立，要改：每次调用开头读一次密钥，写成功后才返回；JSON 文件没有要关的句柄 |
| 6 | `read` 读不回长行的后半截 | 成立，要改：存档里超过 1,800 字的行在标点或空白处断开 |
| 7 | OMP 凭据库的清除在锁竞争下报成功、重启后旧密钥回来（实测） | 成立：本插件改用 JSON 文件后不受影响；`nbook.models` 同样受影响，另记 |
| 8 | 只进产品清单不会装进两个宿主 | 成立，要改：登记服务端与浏览器的定义表、内置名称目录，加装配测试 |
| 9 | 远程合同没写提供方、调用方、读写与错误表；检测会计费却可能被重放 | 成立，要改：逐方法写表，检测按写处理、不重放 |
| 10 | 截止按单次还是整次没定；eval 单元 30 秒比读取的 45 秒短 | 成立，要改：一个总截止覆盖重试；说明写 `eval({timeout})` |
| 11 | 只在错误分支遮盖，先截后遮会漏掉密钥片段；异常文字进日志 | 成立，要改：先遮盖再截，只取 `error.message`；客户端与工具从不抛错；诊断只记码与状态 |
| 12 | 没有读响应体的上限 | 成立，要改：按读到的字节计，成功 4 MiB、错误 16 KiB，超过得 `too-large` |
| 13 | 读取接口的字段映射、缺字段与空正文、过滤强度没定 | 成立，要改：逐项写定；不按分数筛 |
| 14 | 403 不一定是“地址被拒”；5xx 重发可能重复计费 | 成立，要改：403 只说被拒；只有 429 重试一次 |
| 15 | 真实接口测试会把真密钥写进文件；夹具不能证明与真实接口同义 | 成立，要改：真实测试只在内存用密钥；冒烟用带内存密钥的测试插件变体；夹具只入脱敏样本 |
| 16 | 同名工具时 eval 与内核选中的不是同一个（实测） | 成立，但不在本 Task 改：Agent 插件原有的问题，现在没有别的 `web_search`，不触发；另记 |
