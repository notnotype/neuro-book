# 设计：搜索后端、读取的引擎与正文抽取、与浏览器插件的关系

## 目标与范围

定 `web_search` 的搜索后端（自建、托管服务、要不要用户自己填密钥）、`web_fetch` 的读取引擎与正文抽取（直连、退回浏览器；w00034 定了不做反检测伪装，jina reader 的伪装指纹请求同属此类）、输出格式与大小上限，以及与浏览器插件（w00034）的关系。

合同：只做设计，行为合同未变。

## 设计审查

计划第 2 稿（`7e88e7717`），设置页派 Claude Sonnet，后端与计划整体派 omp（进行中）。

Sonnet（9 条：重要 7、建议 2，[`evidences/design-review-sonnet.txt`](evidences/design-review-sonnet.txt)），主会话核对了它引用的 `forms.md` 输出 31、AI 分类现有的 order、`models-store.ts` 不翻译的约定；处理后成计划第 3 稿：

| 条 | 问题 | 处理 |
|---|---|---|
| 1 | 没有数据模块，填完直接点“检测”时写入与检测并发、得 `no-key` | 成立，要改：加 `web/search-store.ts`，同一家的检测等在途写入结束再发 |
| 2 | 检测由服务端出文字；密钥变了旧结果不失效；检测计费却没有进行中的处理 | 成立，要改：`check` 只交码与详情，浏览器按语言写；写入、清除后清结果；进行中停用按钮，旁边写“会发一次搜索” |
| 3 | 没写 `layout` 与 `order` | 成立，要改：单列、每家一节，`order: 22` |
| 4 | 与模型页的密钥分不清；`env:` 写法被当原文存 | 成立，要改：标题、说明、关键词避开模型页；说明写清分开存放；`env:` 开头原位提示、服务端拒收 |
| 5 | 照抄 `ProviderDetail` 的密钥草稿逻辑，与 `forms.md` 输出 31 的 `SecretInput` 重复 | 成立，接受取舍：插件内抽一个 `ApiKeyField` 给各家共用，不动已实现的模型页；与模型页、`SecretInput` 的合并记进 Work 的后续 |
| 6 | 漏了文字目录、分区 id、Lab 替身与场景登记 | 成立，要改：逐项写进计划 |
| 7 | 对照模型页漏写的行为（读取中、只读、写失败通知、草稿、检测各状态、无障碍），`pages.ts` 不能直接复用 | 成立，要改：逐条写进计划与设置页 Spec；新写包装 |
| 8 | 验证走不到真实合同；地址写死，检测成功路径没法在本机测；没断言不回显 | 成立，要改：DeepSeek 地址改成只在设置文件里的配置项 `nbook.web.deepseekBaseUrl`，测试与 e2e 指向本机假端点；数据模块的合同测试接真实服务端；新增 `web-settings.e2e.ts`；DOM 测试断言不回显 |
| 9 | 设置页合同塞进工具 Spec；密钥输入边界没写 | 成立，要改：另建 `web/settings-page.md`；去首尾空白、空串与 `env:` 拒收 |
