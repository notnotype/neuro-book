## 已从代码确认的缺口

1. `GridBranch.size` 被解释为“由子节点计算，不是输入”，快照也不保存分支分配。任务要求分支外部分配独立表达：
   列宽不能由其内层叶高度或当前存在的叶尺寸重新猜测。分支暂缺一个叶时也要保留其外部分配意图。
2. `settle` / `assignAxis` 直接改写叶的size，`serialize`又读取这些size；当前API没有明确容器宽高输入，
   无法证明viewport重排不改用户意图。需要分离持久化意图与计算后的呈现。输入当前容器宽高，布局输出供renderer使用；
   layout/measure不改变序列化意图。只主动提交改变意图。
3. 不可满足约束的比例降级随后调用 `assignAxis`，它又夹回min，实际仍溢出容器。
   必须在不可满足约束时明确降级但几何保持有限非负、总尺寸守恒（包含实际sash）；不能只报告issue就继续溢出。
4. 分支还需可由当前宿主声明本身约束，不能只从叶推导；运行约束不进快照。

## 必须先增加的可观察测试

- 1000×600容器：left宽300，right分支宽699（1px sash），right内部纵向分配400/199。
  调外层后，内层总高仍600；调内层后，外层right宽不变；两轴均计sash且守恒。
- 保存用户意图后，用更小容器layout，再回原容器。中间的serialize必须不变，原分配可恢复。
- 最小宽合计超过容器（包括容器比sash总量还小）：有诊断，所有输出有限非负且总量不超容器。
- 一个branch存在显式外部宽度及当前约束；过滤暂缺叶后不丢该宽度意图。新版快照必须能恢复它。
- 重复id、非法/高版本、深度/数量超限整体拒绝，原树与原意图不变。大小限制要限制工作量，不能只是遍历完任意大数组后报错。
