# 前端值适配器的接续边界

只读取证与下一增量的检查点；不是已交付能力，也不替代 Spec。

## 可以复用

- `app/utils/storage/host-context-client.ts` 负责稳定浏览器身份与 user 访问初始化/释放；
  `StorageHostRequest` 允许隔离 HTTP 宿主验收，不把路径/主体交给页面。
- 核心句柄的 read/save/remove/migrate/repair/reclaim 与订阅均已有结构化结果。
  前端对外应保留同一语义，HTTP DTO 不是新的状态 authority。
- 核心订阅允许合并中间值，是当前状态观察，不是审计日志；传输实现不必承诺每个 revision 都重放。

## 实现前须明确

1. **远程句柄与访问上下文不是同一对象。** t24 池按请求借用句柄，空闲时释放。
   后续若让浏览器持有长期 owner 句柄，不能每次 HTTP read 无声打开新代次，然后把墓碑回收后的新凭据
   交给旧句柄继续写。核心 open 会捕获该 owner 的 local/shared 分区代次，包括尚未读取的记录。
   前端取得句柄、失效与重建必须保留此行为；选择传输前先写回收后旧前端句柄失效的端到端用例。
2. **初始快照与观察顺序。** 订阅必须先交付初始快照，再发布后续更新；迟到读取不能覆盖新快照。
   只读重连可重新取得快照，但不能自动重放结果不明的写入，也不能替 owner 清除本地意图。
3. **每个工作台自己释放。** 使用相同浏览器身份的两个标签可以恢复同一个 local 地址，
   但某个标签的释放/超时不能取消另一个标签的请求。关闭先停止调度，排空已经接纳的操作。
4. **传输容量与背压。** 现有 `app/utils/http/read-sse.ts` 固定消费 Agent 的 128 KiB 上限，
   Storage 值允许 1 MiB，不能直接传大值而沿用原 parser。若选 SSE，需独立预算或发送小失效通知后重读，
   且 H3 stream 要先 send 再 await 首帧 push。若选轮询，需说明稳定代次、串行观察、退避与资源上限。
   两者都是可选实现，尚未决定，不能为传输先造无消费者的事件总线。
5. **失败公开投影。** 复用 t24 的 code/status/committed 与 read 分类，不把网络中断说成磁盘未保存；
   401、上下文失效、代次过期停止相应访问，不无限自动重新签发后继续旧意图。

## 验收建议

同一真实 HTTP 隔离宿主上验证：保存后另一个标签观察到确认值、订阅首帧期间提交、后端重启后显式重建恢复、
两客户端 local 隔离/shared 同主体可见、回收使旧句柄及未读键失效、释放与断网、近 1 MiB 值、
慢消费者有界资源。浏览器 adapter 保持与 Vue/Pinia 无关，再由后续工作台宿主建立显示/确认/意图三份状态。

## 可行的最小接续方案（实现时验证）

优先评估“取得 owner 的分区代次绑定 + 有界串行轮询”，避免为当前状态观察提前引入长连接层：

- 远程 open 由服务端打开受信 owner 句柄，返回其已捕获的 local/shared 分区代次；不返回物理路径或主体。
- 后续值动作携带这份固定绑定，服务端在本次临时句柄上核对原绑定，连 read 也不能无声采用新代次。
  墓碑回收后，尚未读取的键同样失效；重新取得绑定是调用方显式重新初始化。
- 浏览器每个订阅只有一条串行读取链，先返回初始快照，再按修订发布变化；读网络故障可退避，
  访问失效则终止。写操作禁止自动重放，按既有 code/committed 告诉 owner 决定后续意图。
- 后续换为 SSE 可替换传输实现而保留同一句柄、快照、代次及失效语义。

这是基于现有核心已捕获分区代次的实现建议，不是追加产品能力；须以跨 HTTP 的回收与未读键用例验证，
不能仅依赖浏览器自己比较最新读取结果后才发现代次变化。
