# 建立组件 Lab 骨架与它自己的第一批零件

## 目标

在主应用里建成 Component Lab 的三栏骨架，补上产物门禁使它从第一天起就不进发布包，并让**Lab 自己新写的零件**成为第一批展品。

选新零件而不是迁移旧组件，是为了让第一批展品的文档**真的写在实现之前**。旧组件的文档只能补写，补写出来的文档验证不了「先文档后实现」这条规矩是否成立。JsonViewer 作为对照组一起入驻——它的文档是补写的，两者摆在同一个 Lab 里，差别看得见。

## 顺序调整

清退 preview 已顺延为 [t06](../t06-preview-retirement/README.md)。本 Task 又比上一版收窄：旧组件入驻（文件树、编辑器工作台等）移出，等本 Task 做出结果后再按实际形态创建下一个 Task，不预建 Task 链。

当前顺序：本 Task（Lab 骨架 + 自己的零件）→ 旧组件入驻 → 补写 Lab 界面合同 → 主题切换 → 清退 preview → 渐进迁移剩余组件。

t04 的浏览器人工走查在本 Task 开工时仍未完成。两者不互相阻塞，但 t04 的完成门禁不因本 Task 开工而视为通过。

## 已核实的现状

以下几条是本 Task 的设计前提，来自开工前的代码阅读，除标注外未运行验证。

**一、nb-ui 已有一套 Lab，本 Task 不复用也不合并。**`packages/nb-ui/playground/app/component-lab/` 约 2500 行，覆盖 48 个组件。它跑在 nb-ui 自己的 playground 里，解析不到主应用的别名、i18n 与自动导入。开发者已拍板：它只服务 nb-ui 的纯组件，NeuroBook 的 Lab 自建且要更重。另一条技术理由是它的组件清单为手写的 1102 行登记表，与本仓库 Lab 规范「索引是派生产物、不保留第二份清单」直接冲突。

**二、主应用当前没有任何按环境排除页面的机制。**构建配置里找不到针对 preview 页面的过滤，也没有 `pages:extend` 之类的钩子。14 个 preview 页面是随产品一起发布的。产物门禁属于全新工程，不是抄现成做法。（从代码读出，未跑构建验证。）

**三、三栏骨架大部分能从 nb-ui 直接拼出来，真正要新写的只有两处。**

| 骨架部位 | 来源 |
|---|---|
| 左栏的组件树 | nb-ui `Tree` |
| 分栏与拖动 | nb-ui `Splitter` |
| 右栏的 tab 与面板容器 | nb-ui `Tabs`、`Panel`、`ScrollArea` |
| 顶部 header | nb-ui `Toolbar` |
| **可收起的侧栏** | **nb-ui 没有，新写** |
| **能调尺寸的画布** | **nb-ui 没有，新写** |

**四、nb-ui 的 `FileTree` 与主应用的 `WorkspaceFileTree` 形态接近，但不构成替换关系。**两者行数接近（283 与 265），合同也接近：节点分 file/directory、带 children、拖拽落点为 before/after/inside。但 nb-ui 的这棵树**不是 reka 提供的**，283 行全部手写，roving tabindex、键盘导航与 HTML5 拖拽都是自己实现的，因此它并不比 `WorkspaceFileTree` 更有来头。

`WorkspaceFileTree` 更领域化也更多功能：接受扁平的路径列表并自己建出层级（nb-ui 的要求传入已经嵌套好的数组）、有强制展开路径、有领域化的落点规则与尾部落点。**开发者已拍板两者共存**，先用 nb-ui 的 `FileTree` 搭 Lab 左栏，不动 `WorkspaceFileTree`。本 Task 只登记这个对比，替换与否留给后续判断。

**五、组件规范已收窄「开发工具不受约束」这一句。**原文把开发工具整体排除在外，会导致 Lab 自己的零件没有组件文档，而 Lab 的索引正是扫组件文档得来的——没文档就进不了清单，Lab 展示不了自己。现改为：开发工具的页面和整体外壳不受约束，**开发工具里的零件受约束**；分界是给一份 props 就能在别处渲染出来的是零件，必须待在特定位置、依赖整页上下文才成立的是外壳。

## Lab 的界面形态

由开发者给定，本 Task 按此实现：

- **顶部 header**：横贯三栏之上，放设置与主题、配色切换。
- **左栏**：组件的树状选择列表，可收起。
- **中栏**：画布，展示被选中的组件；**可以控制包着组件的那个盒子的形状和大小**。规范硬性要求的手机 `390×844` 与平板 `768×1024` 做成预设，自由调尺寸是预设之外的能力。
- **右栏**：多功能面板，按 tab 切换（状态、样式、事件、组件文档等）。

按前述分界，header 与三栏布局壳属于外壳，不受组件规范约束；可收起侧栏与画布属于零件，受约束、要先写文档。

## 第一批展品

三个，按入驻顺序：

1. **可收起侧栏**（新写）。左右两栏都要用，有两处真实消费者，不是为了凑数造的零件。
2. **能调尺寸的画布**（新写）。Lab 的核心，nb-ui 没有对应物。
3. **JsonViewer**（已有文档，对照组）。它的文档是实现完成后补写的，和前两个「文档写在实现之前」的放在一起，差别当场可见。

前两个的组件文档**必须写在实现之前**。这是本 Task 要验证的主要事情，写反了本 Task 就白做。

## 本轮做与不做的 Lab 能力

开发者已选定四项「重」的能力，加上规范硬性要求的三项。本轮做其中五项，另两项推迟——**推迟的原因是它们的验证样本都在旧组件那边，第一批三个展品提供不了**：

| 能力 | 本轮 | 说明 |
|---|---|---|
| 手机与平板固定容器 | 做 | 画布零件的核心功能 |
| 组件文档与实物并排 | 做 | 右栏一个 tab；索引链的一部分 |
| 假数据现场改 | 做 | JsonViewer 的 `value` 本身就是一份可编辑的 JSON，天然样本 |
| 事件日志 | 做 | 三个展品的事件都不多，能力建出来但样本偏弱 |
| 主题与配色切换 | 做 | 放 header |
| 预置状态快照 | **推迟** | 三个展品都不读 store，本轮没有能验证这条通路的样本 |
| 挂不上的组件显示原因 | **推迟** | 需要一个含写操作的组件当样本，旧组件入驻时一并做 |

两项推迟的能力在旧组件入驻那个 Task 里补齐，届时 `WorkspaceFilePanel` 是现成的「挂不上」样本。

## 索引与 fixture

**索引是派生的。**扫描 `app/**` 下的组件文档，读 frontmatter 的能力标签得到组件清单，并据标签推导每个组件能不能挂、需不需要状态快照。扫描范围要覆盖 Lab 自己的零件目录，因为它们现在也受组件规范约束。仓库里不留第二份手写组件清单。

这条链目前只覆盖到「有哪些组件、能不能挂」。**场景不来自组件文档**——文档里没有场景这个概念——场景由 fixture 提供，按组件名与索引对上。这个划分是本 Task 对规范的执行方式，形态稳定后写进 Lab 合同。

**fixture 集中放在开发专用目录**（t04 已定，随「不目录化」一起），按整目录排除，不散落进组件目录。

## 允许改动

- `docs/standards/code/components.md`：收窄「开发工具自身不受本规范约束」一句（已执行，见前述第五条）。
- 新增 `packages/neuro-book/app/component-lab/`：Lab 外壳、新零件、索引扫描与全部 fixture。整个目录只在源码开发环境存在。
- 新增 Lab 入口路由，位置与形式由实现确定；只在源码开发环境注册。
- `packages/neuro-book/nuxt.config.ts`：加入排除规则，使非开发环境下 Lab 目录与路由不进构建图。**排除必须发生在构建图与路由生成阶段**，不接受运行时守卫或环境变量隐藏一个实际已打包的 Lab。
- 新增两份组件文档：可收起侧栏与画布各一份，**都写在实现之前**。
- 骨架优先用 nb-ui 现成组件拼装，不在主应用里重造 nb-ui 已有的东西。
- `JsonViewer.vue` 与 `JsonViewer.md` 默认不改。入驻过程中发现文档与实现不符时按组件规范记入「已知偏差」，不顺手修实现。

## 批次顺序

每一批都是一个可以停下的边界，中途叫停不留半成品。

1. **两份新零件文档 → 按文档实现两个零件 → 用它们和 nb-ui 拼出三栏骨架与 header。**加索引扫描与产物门禁。这一批结束时 Lab 能打开、能选组件、画布能挂东西、能切三种容器，且构建产物里没有它。文档必须先于实现，顺序反了这一批不算完成。
2. **三个展品全部入驻 + 右栏的组件文档 tab。**
3. **事件日志 tab + 假数据现场改 tab。**
4. **header 的主题与配色切换。**

## 开发者参与

- **界面形态的细节仍由 Agent 定。**三栏加 header 的骨架已由开发者给定，但导航怎么组织、右栏有哪些 tab、画布怎么调尺寸这些没有合同。Lab 规范明写这些等原型建成后补写。原型出来后由开发者定形，看着不对就说，此时改的代价最小。
- 两份新零件的文档写完后由开发者过目，与 t04 的安排一致：写起来别扭就改组件规范，不将就着往下写。**这一次文档在实现之前，所以过目的时机也在实现之前**，看完再动手。
- 浏览器人工走查只有开发者能做。

## 验证

1. `bun run --cwd=packages/neuro-book typecheck`。
2. 与改动表面相关的聚焦测试。
3. **产物门禁**：用 `NODE_ENV=production bun x nuxt build` 跑真实生产构建——`package.json` 的 `build` 脚本只跑 prepare 与 tsc，不产生产物，拿它验门禁等于什么都没查。构建后检查路由、模块图、产物文本与清单中不存在 Lab 模块、fixture、开发绝对路径或识别标记。同一套检查方法要能在同一份产物里抓到已知存在的路由，否则「没找到」不成立。
4. 开发入口下 Lab 可打开；三个展品均可挂载、可切场景；画布的两个预设容器与自由调尺寸均生效。桌面按不低于 1440px、手机按 `390×844` 记录实际视口值。
5. 同一场景重复打开或重置后，初始输入与可观察状态一致。
6. 确认无新增 console error 或 warning。

## 完成门禁

- 三栏骨架与 header 可用，三个展品在 Lab 中可挂载、可交互。
- 两份新零件的文档在实现之前写成，且提交历史能证明这个顺序。
- 组件索引来自扫描组件文档，仓库中没有第二份手写组件清单。
- 产物中不含 Lab、fixture 或开发路径，且该结论来自实际构建输出而非静态阅读。
- 三份组件文档符合组件规范，frontmatter 能力标签与实现一致。
- fixture 不要求凭据、网络、真实 Project/Session、Provider/Model 或浏览器持久化状态。
- 骨架中没有重造 nb-ui 已有的组件。
- 未运行或未授权的项目标注为未验证，不以静态阅读代替执行结果。
