### 1. 色板预选“上次的颜色”后，点那个已选的色块什么都不发生：既不上色，也不收起色板
- **严重程度**：重要；**类别**：正确性
- **位置**：packages/neuro-book/src/plugins/markdown/web/components/menus/MarkdownColorButton.vue:44（`:model-value="last"`）；根因在 packages/nb-ui/src/components/form/ColorSwatches.vue 的 `choose()`（“与当前值相同时不发”）
- **现象**：base 上色板的 `model-value` 是 `null`，点任何色块都发 `update:modelValue`。现在改成 `last`（上次的颜色，第一次是红色文字、黄色高亮），而 `ColorSwatches.choose()` 对“与当前值相同”的点击直接不发事件，`pick()` 不被调用：`menus.run` 不执行、`open` 不置 false。所以打开箭头的色板后，点那个带选中标记的色块（第一次用时就是红色或黄色），没有任何反应，色板还开着。
- **为什么是问题**：用户打开色板、点中一个标着“已选”的颜色，期望是“用这个颜色”。选区当前是别的颜色（例如蓝）、上次用的是红时，点红色同样无效，只能先点别的再点回来，或者关色板用左半边。Spec 输出 1 写“在色板选了颜色就记住”，没有把“选中的是上次的颜色”当成不可点。e2e 新用例选的是 `#0ea5e9`、`#dbeafe`，都不是预选色，没覆盖。选色板的预选值是作者自己加的（.md“选中的是上次的颜色”），不是开发者决定 1–3 里的要求。
- **如何核实**（实测，happy-dom 挂真实 `ColorSwatches`）：`/tmp/review-t20-impl2/exp/swatch.vue.test.ts`，`modelValue="#ef4444"`，点 `[data-color-swatch="#ef4444"]` 后 `emitted("update:modelValue")` 为 `undefined`；再点 `#0ea5e9` 才发出 `[["#0ea5e9"]]`。命令：`cd /tmp/review-t20-impl2/exp && npx vitest run --config vitest.vue.config.ts --disable-console-intercept`。
- **建议改法**：二选一。(a) 色板的 `model-value` 仍传 `null`（不预选），“上次的颜色”只体现在色条上；(b) 保留预选，但在 `MarkdownColorButton` 里不依赖 `update:modelValue`，改成监听色块的选择自己执行（需要 nb-ui 配合发一个“再点已选也发”的事件，改上游）。(a) 最简单，也与 base 一致。同时补一条 e2e：第一次用时点开色板，点红色，文字变红且色板收起。

### 2. 焦点在“移除注音”按钮上按回车，被卡片的 keydown 当成“确定”处理，移除不会发生
- **严重程度**：重要；**类别**：正确性（键盘可访问性）
- **位置**：packages/neuro-book/src/plugins/markdown/web/components/menus/MarkdownTextPrompt.vue:42-52（`onKeydown` 挂在整张卡片的容器上，`Enter` 分支无条件 `preventDefault()` 再 `confirm()`）
- **现象**：base 的卡片里只有输入框，容器级的 Enter 处理没问题。本段在卡片里加了两个 `IconButton`（移除、确定）。Tab 到“移除注音”按钮按回车时，keydown 冒泡到容器，`event.key === "Enter"` 成立，`preventDefault()` 取消了按钮原生的点击激活，随后 `confirm()` 提交输入框里的文字（空则取消）。`remove` 事件不会发出。Space 键不受影响（只有 Enter 被截），所以同一个按钮 Space 能用、Enter 不能。
- **为什么是问题**：用户 Tab 到按钮、按回车，期望是这个按钮的动作；实际是把预填的注音原样写回（看起来什么都没发生，注音还在）。“移除”只能用鼠标或 Space。Spec 输出 9 写“回车或点确定写回”，没有说焦点在别的按钮上时回车也算确定；plan-2 也只说“回车、Esc、焦点离开的规则不变”，没想到卡片里有了按钮。
- **如何核实**（实测，happy-dom 挂真实 `MarkdownTextPrompt`）：`/tmp/review-t20-impl2/exp2/prompt.dom.test.ts`，在“移除注音”按钮上派发 `keydown Enter`：`defaultPrevented` 为 true，`emitted()` 只有 `cancel`（输入框为空时），没有 `remove`。命令：`cd /tmp/review-t20-impl2/exp2 && npx vitest run --config vitest.config.mts --disable-console-intercept`。
- **建议改法**：Enter 只在事件目标是输入框时处理（`event.target instanceof HTMLInputElement`），或把回车处理挂到 `Input` 上而不是容器。Esc 仍可留在容器上（任何一个子控件上按 Esc 都应取消）。补一个组件测试：焦点在移除按钮上回车触发 `remove`；e2e 现有用例只用鼠标点按钮。

### 3. 卡片开着时再打开另一段“同样读音”的注音，输入框里是上一段改了一半的文字，没有重来
- **严重程度**：建议；**类别**：正确性
- **位置**：packages/neuro-book/src/plugins/markdown/web/components/menus/MarkdownTextPrompt.vue:13-22（`watch(() => [props.open, props.initial] as const, …)`）与 MarkdownMenus.vue:36-49（`openPrompt` 的“已开着再打开”分支）
- **现象**：作者为“卡片开着时点另一段注音”加了 `props.initial` 作为触发条件，并在 MarkdownMenus 里手动 release+hold 换高亮。但 watch 只在 `open` 或 `initial` 的值变了才重跑；两段注音的原文相同（小说里同一个人名反复出现，读音一样，很常见）时，`promptInitial.value = 同一个字符串` 不触发，输入框保留用户在上一段里敲了一半的文字，焦点与光标也不重置，而高亮与确定的目标已经是新的一段。回车就把那半截文字写到新的一段上。
- **如何核实**（实测）：`/tmp/review-t20-impl2/exp2/stale.dom.test.ts`：`initial="lín xī"` 打开，把输入框改成“我改了一半”，再 `setProps({initial: "lín xī"})`：输入框仍是“我改了一半”；换成 `"zhù yīn"` 才重置。真实运行时 `openPrompt` 的赋值同样是对 ref 写同一个值，Vue 不会触发。这一步走的是“指针按下后卡片仍然开着”这条路；是否会因为浏览器把焦点移走而先触发 `focusout` 关闭卡片，我没法不跑 e2e 证实（推断：作者给 `openPrompt` 写了这个分支，应当是测过会保持打开）。
- **建议改法**：`openPrompt` 每次打开都递增一个计数（或传 `key`）给卡片，watch 以计数为触发条件，这样不依赖文字是否变化；顺带把“再点一次同一段”也算一次重来。同样的做法也解决“上一次取消后立刻再打开同一段”之外的任何同值情形。

### 5. 选区跨多段注音时，卡片预填第一段的读音，确定会把整个选区都改成这一个读音；“移除注音”的标签也只说一段

### 6. 记录损坏或版本不支持时，选了颜色后色条与左半边仍停在缺省色（选了不记）
- **严重程度**：建议；**类别**：正确性（从代码推断，加 store 自己的测试说明）
- **位置**：packages/neuro-book/src/plugins/markdown/web/colors.ts:46-52（`remember`）
- **现象**：`remember` 只处理 `save.state` 为 `failed`/`unknown` 的暂停，其余走 `colors.commit`。按 store 合同（shared/store/store.test.ts 的 `corrupt`、`unsupported-version` 两例：“commit 直接 protected、不改显示”），受保护的记录不接受修改，`#pump` 里 `settleFirst(head,"protected")` 后 `display` 回到 `#project()`，也就是缺省。用户在色板选了蓝色，文字变蓝，但色条与左半边仍是红色；每次左半边点下去都是红色。记录是什么时候会损坏：schema 只认小写 `#rrggbb`，另一个版本或手工改成大写 `#EF4444`，同样判为损坏并保护。
- **为什么是问题**：Spec 写了“记录读不出或已损坏时按缺省颜色”，没写损坏时选了颜色能不能记。作者对“保存失败、结果未知”做了只改显示的退路，却没对“受保护”做同样的处理，三种“存不下”里漏一种，行为不一致。偏好丢了无伤，但色条与刚用的颜色不符会让人以为选色没生效。
- **如何核实**：读 shared/store/persisted.ts `#pump` 的 protected 分支（约 330-340 行）与 store.test.ts 553-561；未写成用例实测（需要真实 Storage 世界），标“从代码推断”。
- **建议改法**：`remember` 在 `commit` 返回 `protected` 时也 `colors.show(next(colors.display))`（与另两种暂停一致），或者在 Spec 里写明“受保护的记录不记”。窄场景，选后者也可接受。另：缺少 `colors.ts` 的单元测试（失败、未知、保护、内存回退都无覆盖），只有 e2e 的好路径。

### 7. 插件入口改成 async 后，等存储服务期间被停止，`assets` 不会被释放
- **严重程度**：建议；**类别**：不变量（资源释放）
- **位置**：packages/neuro-book/src/plugins/markdown/web/plugin.ts:77-91
- **现象**：`activate` 在 `createAssetUrls(...)` 之后才 `await context.services.resolve(storageKey)`，而 `context.signal.addEventListener("abort", () => assets.dispose(), {once: true})` 在 await 之后才登记。base 里整段同步，没有这个窗口。若入口在等待期间被停止（`context.signal` 已 abort），监听器登记在“已 abort 的信号”上，不会再触发，`assets` 里创建的对象地址不被回收。`resolve` 也没传 `{signal: context.signal}`（canon 插件就是这样传的），停止时等待不会被取消。
- **为什么是问题**：违反“创建资源后立刻登记释放”的习惯，是改成 async 引入的新窗口；概率很低（存储服务本来在它之前就激活了）。
- **如何核实**：读代码；运行时的 `onStop` 登记（contracts.ts 里 `context.onStop`）是更合适的挂法，不依赖信号当前状态。
- **建议改法**：把 `context.onStop(() => assets.dispose())`（或把 abort 监听）放到 `createAssetUrls` 之后、`await` 之前，`resolve` 加 `{signal: context.signal}`。

### 9. 卡片里 Esc 不看输入法组字：组字中按 Esc 取消候选，同时整张卡片被取消（base 就有，不算本段回归）
- **严重程度**：建议；**类别**：正确性（base 既有）

- **现象**：注音正是要用拼音输入法写的文字。Linux、macOS 的中文输入法在组字时按 Esc，keydown 是 `key: "Escape"` 且 `isComposing: true`，卡片把它当成“取消”：候选没取消干净，整张卡片先关了，已敲的拼音与高亮一并丢失。Enter 已经对 `isComposing` 做了保护，Esc 漏了。

- **如何核实**：读代码对照 Enter 分支；输入法行为没法在 happy-dom 里复现，标“从事件语义推断”，需要作者在带输入法的真实浏览器里试。

- (a) **拆分按钮的箭头复制了 `IconButton` 的状态色**：MarkdownColorButton.vue 样式里手写 `color-mix(... 15%)` 与 `24%`，注释写“与旁边的 IconButton（default）同一组状态色”。`IconButton` 改了状态色，箭头会悄悄走样；没有链接回 IconButton.vue:61 的任何机制。可以让 nb-ui 给 `IconButton` 一个宽度或 `narrow` 形态，或至少在 IconButton.vue 那一行旁注明被谁复制。
- (b) **回退到内存颜色的逻辑写了两处且不一致**：MarkdownColorButton.vue 里 `inject(markdownColorsKey, null) ?? memoryColors()`，每个按钮实例各建一份内存状态，工具栏与选区菜单的两组按钮在没有注入时（组件测试）互不相通；MarkdownToolbar.vue 里 `inject(markdownColorsKey, null)` 回退到 null，“⋯”里选色什么也不记。建议抽一个 `useMarkdownColors()`，统一回退，由控件根一处提供。
- (c) **MarkdownMenus.openPrompt 的“已开着”分支先 `releaseSelection` 再 `holdSelection`**：`holdSelection` 对非空选区本来就会覆盖旧装饰，`release` 只在新选区为空时有意义；注释没说明，读者会以为两步都必需。留一个即可，或写明理由。
- (d) **两个窗口**：store 的 `#receive` 只在第一个快照时更新显示（persisted.ts:285 附近），另一个窗口改了颜色，本窗口的色条要等自己下一次选色才同步；没有丢数据（`change` 在 base 上重算，另一字段保留），只是显示陈旧。Spec 没提，记一笔，不用改。

## 未发现问题的方面（仔细检查后）
- 保持选区高亮的寿命：装饰只在 EditorState 的插件状态里，不写插件视图；`holdSelection`/`releaseSelection` 都带 `addToHistory: false` 且不改文档、不改选区（测试覆盖），`ruby-remove`/确定/取消/点外面/只读/换文档（卡片侧）的收起顺序都先 `prompting = null`（同步 watch 撤装饰）再执行命令，没有发现撤销历史被污染；外部改写时 `reload` 只替换不同的一段，装饰随映射移动或随被删文字消失，不会错位（但见第 4 条：换文档时的清除没有测试）。
