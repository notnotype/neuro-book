### 1. 回填后带过去的 storedMarks 是旧实例，属性（markdown）与回填后的文字不一致；注释“原样带过去仍对得上”只对选区成立
- **严重程度**：建议；**类别**：代码质量（注释与合同准确性）
- **位置**：packages/neuro-book/src/plugins/markdown/web/components/MarkdownControl.vue:163-169
- **现象**：`written.accept` 的 `restyle` 会对已写出的 mark 做 `removeMark`/`addMark`，把 `markdown` 属性从 null 改成读回的写法（如 bold 的 `"**"`）。`storedMarks` 里仍是旧实例 `bold{markdown:null}`。实验（/tmp/review-w00025-t17-impl/exp.dom.test.ts）：`看` 光标在末尾，Ctrl+B、打“粗”、Ctrl+I（stored=[bold(null), italic(null)]）、flushPendingChange、打“斜”。交出后 doc 是 `粗`=bold{"**"}，`斜`=bold{null}+italic，两段相邻的粗体属性不同；再次交出写回 `看**粗*斜***\n`，输出正确，没有可见回归。
- **为什么是问题**：目前恰好因为“回填写法=规范写法”，null 与回填值写出相同。若以后 restyle 回填出与规范写法不同的写法（如 `__`），带过去的旧 mark 会打出另一种写法的相邻粗体，写出时可能拆成两段。注释“回填只改属性、不动选区，原样带过去仍对得上光标”暗示一切都对得上，漏了 mark 属性这一层。
- **如何核实**：运行 exp.dom.test.ts 的用例 A（输出写在 /tmp/review-w00025-t17-impl/out.txt）。
- **建议改法**：不改代码也可以，但注释补一句“带过去的 mark 属性可能是回填前的值，写出时按规范写法，所以相同”；或带过去前用 `tr.doc.resolve(from).marks()` 里同类型的现值替换。收益小，注释补一句即可。

### 2. 同一类丢失仍存在于 reload 路径（作者已问，结论：分开合理，但边界要写明）
- **严重程度**：建议；**类别**：正确性（边角）/文档
- **位置**：MarkdownControl.vue:200-212（`reload`）、:274-282（watch revision）
- **现象**：reload 用 `codec.reload(tr, text)` 做替换步骤，`Transaction.addStep` 会清 storedMarks。同一文档两个控件时，别组输入被接受 → 本组 reload → 本组刚按下的格式切换丢掉。Spec 输出 62 只写“停手、保存把正文交给文档不改变它”，没有承诺“别处改了正文也不改变”，所以不算违反合同。
- **为什么要提**：用户行为上同样是“按了 Ctrl+B 还没打字，格式没了”，只是需要两组同文档并发输入（窄场景）。按“窄场景选简单改法”的偏好，建议不加机制，在 MarkdownControl.md 一句话写成已知限制。reload 的 doc 若与光标处无关（没有改到光标所在位置），其实不需要清 stored marks，但这是 Tiptap/ProseMirror 的通用行为。
- **分开合理性**：commitNow 带 stored 是因为回填只改属性、位置不变；reload 会替换内容、选区要映射，stored 对不对得上取决于光标处的内容，不能原样带，分开是对的。

## 未发现问题的方面
- commitNow 的 `stored !== null` 判断：空数组（用户关掉全部格式）不是 null，会被带过去，正确；非空选区时 storedMarks 本来为 null，不受影响。
- 回填是否动选区：`restyle` 只调用 `setNodeMarkup`（同大小的 ReplaceAroundStep）与 `removeMark`/`addMark`（Mark 步骤），位置不变，选区不需要映射；`setStoredMarks` 放在这些步骤之后，所以不会被 `addStep` 清掉。实验与 DOM 用例都证实。
- 输入法组字：commitNow 的调用方在组字期间不触发交出（见 .md 与 flush 条件），回填不会落在组字中。
- 同一文档几个控件：`stored` 取自本控件的 `current.state`，各控件各自带各自的，没有共享状态。
- 只读：commitNow 对只读照常结算，带 stored 无副作用。
- 新 DOM 用例经 keydown/textinput 的真实入口，变异检查（去掉带过去的两行）能抓住。
- Spec 输出 63：afterEach 删除的文件被标为“被其它来源删除”，不会被失焦自动保存重建。
