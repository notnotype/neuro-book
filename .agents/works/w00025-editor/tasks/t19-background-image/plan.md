# t19 实施计划：背景图片与护眼底色

## Context

- **为什么做**：开发者 2026-11-05 提出：需要背景图片（自定义壁纸）与护眼模式，也借此验证编辑器的可访问性。
- **开发者已定**（2026-11-05）：背景有多种，现在有两种：正文（编辑器区）与整个窗口；图片之外再给几个纯色底。
- **依据**：[插件的数据与状态](../../../../../docs/proposals/plugin-data-model.md)（图片是 `user://backgrounds/` 下的文件，配置记引用、透明度、填充方式）；[nb-ui 表面模型](../../../../../docs/proposals/nb-ui-surface-model.md)（面板叠在照片上读不了的教训）；`design-language.md` 的“六、无障碍”。
- **工作方式**：worktree `.worktree/w00025-t19-background-image`，从 master 拉。Spec 与记录在主工作区改。

## 关键设计

### 1. 设置：`workbench/shared/contracts.ts`

每种背景一个设置项，用户层，应用级，在设置窗口“外观”分区：

```ts
type Background =
    | {kind: "none"}
    | {kind: "color", color: string}                 // 只有正文
    | {kind: "image", image: string, fit: "cover" | "contain" | "repeat", scrim: number};  // image 是 user:// 地址

nbook.workbench/background.editor   // 正文（编辑器区）
nbook.workbench/background.window   // 整个窗口：只有 none 与 image
```

以后加别的种类（例如欢迎页）就加一个设置项，不改形状。两种可以同时开：正文的盖在窗口的上面。

### 2. 可读性下限（这件事的关键）

`scrim` 是盖在图片上的那层面色的不透明度，范围 75–100，缺省 85。

下限是算出来的，不是调出来的：图片最坏的情况是纯白（暗色）或纯黑（亮色）。nbook 暗色面 `rgb(45,41,37)` 盖在纯白上、文字 `rgb(239,233,223)`：60% 时对比度 3.32，70% 时 4.51，正好压线，75% 时 5.29；亮色面盖在纯黑上 75% 时 9.05。取 75，给别的主题留余量（`macos` 的取值实施时算）。这样**任何图片**都能保证正文对比度不低于 4.5，不用运行时量图。第 1 轮的实测（测试图 60% 时暗色最差 3.4）与此一致。次要文字（`--text-secondary`、`--text-muted`）的对比度实施时按四个主题配色实测，不够就抬下限或单独处理。

纯色底：文字颜色来自主题，所以预设按明暗分开：亮色有羊皮纸 `#f4ecd8`、豆沙绿 `#cce8cf`；暗色有深棕、墨绿。自定义颜色时算它和当前文字的对比度，低于 4.5 不应用，并说明原因。切换明暗时，只对当前明暗不合格的颜色退回主题的底。

无障碍偏好：`prefers-reduced-transparency`、`prefers-contrast: more` 与 `forced-colors` 下不画图片，退回主题的实心面（设计语言“六、无障碍”的义务）。

### 3. 怎么画

- **正文**：`MarkdownControl`、Monaco 的滚动容器之下画一层（背景与面色遮罩），编辑组读设置后写变量；工具栏与面包屑同样透出。Monaco 的底色要跟着透明，实施第一步先核实。
- **整个窗口**：`.workbench-shell-layout` 铺图，`--panel-surface`、`--sidebar-surface` 等改成“面色 + 遮罩”的半透明。只改这一层作用域的变量，主题包不动。浮层（菜单、对话框）不变：它们有自己的面。
- 窗口的背景要覆盖四个主题：`macos` 自带玻璃，叠上去要验。书架页、设置窗口这些独立页面不铺（第一版）。

### 4. 图片怎么进来：`files`

现在 Files 只有文本的 `write`，浏览器写不了二进制，这是要补的合同。新增写字节的路由，只允许 `user://backgrounds/`，限制图片类型与大小（上限 20 MB），内容按哈希命名，同一张不存两份；旧图不自动删，设置页列出已有的。显示用现成的 `/api/nbook.files/raw/user/…`。文件不见了：记诊断，退回没有背景，设置页显示原因。

### 5. 设置页：`settings.pages`

“外观”分区一页“背景”：两种背景各一块，每块选 无 / 纯色 / 图片，图片有填充方式与遮罩滑块，旁边实时预览（一段真实正文样式的文字在所选背景上）。没有说明文字；滑块到下限就停，不解释。

## 验证

- **可访问性**：e2e 用纯白图、纯黑图与杂色测试图，在 nbook、macos × 明暗下，隐藏文字后量正文、次要文字、面包屑与侧栏的背景，算最差对比度，全部不低于 4.5；量不到的如实写。
- 无障碍偏好用 Playwright 模拟 `reducedMotion` 之外的媒体特性，模拟不了的如实写未验证。

## 不做与风险

- 不做：按作品分别设置；书架页与独立页面的背景；视频或动图；模糊强度的设置。
- 风险：窗口背景让面板变半透明，其它会话正在做的布局与界面可能被影响；只动变量，范围收在外壳。
- 风险：大图解码拖慢首屏，图片不进主题变量的计算，按需加载，实施时量一次。
- 风险：Monaco 的主题底色写在它自己的主题里，透明可能要改主题定义；不行就只让 Markdown 编辑器透出，并告诉开发者。

## 开发者已确认（2026-11-05，全部按推荐）

1. **遮罩下限 75%**：滑块不能再低，保证任何图片都读得清。代价是壁纸不会很鲜艳。推荐。不想限制的话，低于下限时要提示，但 Spec 的可读性保证就没了。
2. **设置是应用级的**：所有作品共用一套。推荐。按作品分别设置以后能加。
3. **源码编辑器（Monaco）也透出**：正文背景连带它。推荐，否则切到源码时背景消失，很突兀。
