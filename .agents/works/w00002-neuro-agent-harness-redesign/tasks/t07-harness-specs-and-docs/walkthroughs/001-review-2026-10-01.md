# t07 审查记录：nb-session / nb-profile / nb-harness（2026-10-01）

开发者要求补 Spec 时顺带审查。方法：通读三包源码与测试，逐条核对准备写进 Spec 的行为；拿不准的行为用一次性脚本实测（脚本在会话临时目录，已删除），并用仓库根 `.env` 的凭据跑了一次真实 DeepSeek。本记录只列发现，**未修改任何产品源码**；修复需要另行授权。

各条也已作为“已知缺口”写进对应 Spec 的“边界与兼容”一节，修复后要同步删除那一条。

## 高

1. **文件工具没有访问边界，harness 中的 `edit` 不经确认就能写盘。**（[file-tools](../../../../../../docs/specs/harness/file-tools.md)）`read` 与 `edit` 都接受绝对路径和 `..`；`createHarness` 创建 `edit` 时没有传 `confirmWrite`。实测：`cwd` 为 `scratchpad/cwd` 时，`read ../outside/o.txt` 成功，随后 `edit` 把该文件第 2 行改成了 `BETA`，`isError: false`。接入产品前必须先定访问范围（cwd 或 Project 根）与审批接线。
2. **`turn` 分不清成功、失败和中止。**（[agent-turn](../../../../../../docs/specs/harness/agent-turn.md)）实测三种情况全部正常 resolve，`text` 为空串，日志多一条空文本的助手消息：`streamFn` 抛错、`apiKey` 返回 undefined、轮次中途 abort。OMP 的错误信息（`stopReason`、`errorMessage`）被丢弃，会话条目也没有对应字段。宿主无法给用户报错，也无法据日志判断某一轮是否失败。
3. **模型上下文不从会话日志恢复，Profile 渲染出的消息被丢弃。**（agent-turn）`turn` 只用 `renderProfile` 的 `systemPrompt`，`messages`（包括 `HistorySet` 展开的历史）没有交给 Agent；Agent 的历史只在内存里。实测：同一日志上新建句柄后，第一轮模型请求只有 1 条消息。append-only 日志目前只是“记账”，不能恢复对话；Profile 的 `HistorySet`/`Message`/`ToolResult` 在 harness 中都不起作用。

## 中

4. **并发 `turn` 留下没有回复的用户消息。** `turn` 先追加用户消息、再调用 `agent.prompt`；第二次调用被 OMP 以 `AgentBusyError` 拒绝时，消息已经落盘。实测日志：`user:one`、`user:two`、`assistant:ok`。
5. **轮次开始前已中止的 `signal` 不生效。** `addEventListener("abort")` 对已中止的 signal 不会触发；实测本轮照常跑完并返回回复。
6. **日志写入失败后句柄永久不可用且不报告。** 首个写入错误被记住，之后所有事件不再写入，每一轮都在结束时抛同一个错误；`close()` 不抛。
7. **工具重名不检测。** `definePlugin` 只查同一插件内部；harness 不调用它，也不检查插件与内置工具、插件之间的重名。实测 `use` 一个带 `read` 工具的插件后，工具列表为 `read, edit, read`。
8. **JSONL 日志把所有读文件错误当作空会话。** `readFile(...).catch(() => null)` 吞掉权限不足、路径是目录等错误，`read` 返回 `[]`，宿主会以为会话为空。
9. **TSX 句内插值被拆行。** `collectText` 用换行连接相邻字符串，`<System>回答使用{lang}。</System>` 渲染为 `"回答使用\n简体中文\n。"`。每个写 TSX Profile 的人都会踩到；示例已改用模板字符串规避。
10. **真实 LLM 用例在包目录下永远跳过。** `harness.e2e.test.ts` 在模块顶层读 `DEEPSEEK_API_KEY`；从包目录运行时 OMP 的 env 模块读的是当前目录的 `.env`，不是仓库根 `.env`，于是凭据存在也被跳过，且看起来像“通过”。`model.ts` 中“OMP 的 env 模块在 import 期已把仓库根 `.env` 注入”的注释与实测不符。临时做法：`bun --env-file=../../.env test`（已写入包 README 与 AGENTS.md）；CI 是否注入了 secret 未核实。

## 低

11. `read` 的行号显示：单行超过字节预算时输出 `1: `（像空行）加截断说明；以换行结尾的文件多出一个空的末行编号。真实 DeepSeek 运行中，模型据此把一行的 `note.txt` 描述为“两行，第二行为空”。
12. nb-profile 的小问题：`ToolCall` 与 `ToolResult` 语义相同；渲染输入的 `now` 无人使用；`HistorySet` 子节点被忽略（与产品 SDK 的写法不同）；`If` 只认严格 `true`。
13. harness 把 `tool_call` 条目转成 `role: "tool"`、文本为参数 JSON 的渲染消息，`HistorySet kind="tool-results"` 因而也会包含调用参数（第 3 条修复前没有实际影响）。
14. `Harness` 没有注销插件的方法；`PluginHost.unregister` 未暴露。这也与 [w00017 移交的插件启停问题](../../../research/2026-09-29-plugin-agent-tools-and-profiles.md)直接相关。
15. 图片读取没有大小上限，整文件 base64 返回。
16. t06 交付时 SSE 序列化与写出器没有任何测试；本 Task 已补 `tests/sse.test.ts`（7 例）。

## 与产品 Profile SDK 的差距（不是缺陷，供设计参考）

nb-profile 只有默认导出一棵节点树；产品 SDK 有 `defineAgentProfile`、manifest、`toolset` 工具声明、初始参数 schema、`context(ctx)` 函数和 `SkillCatalog` 等领域节点。产品 Profile 不能用 nb-profile 加载。将来产品接入（#117）前需要决定是扩展 nb-profile 还是迁移产品 SDK。

## 建议的处理顺序

第 1–3 条决定 harness 能否接入产品，建议在补设计（插件装配、审批、上下文恢复）时一并处理；第 4–10 条可以作为一个修复 Task；第 11–15 条随相关改动顺手修。
