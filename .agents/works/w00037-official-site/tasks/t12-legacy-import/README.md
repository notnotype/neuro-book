# 旧站数据导入与切换演练

## 目标与范围

一次性的导入命令与逐字段的去向表；在副本上演练并按主键与关系核对；写切换与退回的步骤。读生产快照要另取开发者授权。

合同：[`site.legacy-import`](../../../../../docs/specs/site/legacy-import.md)。

## 当前状态

未开工：开发者 2026-11-24 要求先把 ADR、Task 与文档写好，开工等他的指示。

范围：预检与导入两个命令、合成旧库的测试、在生产快照的副本上演练并按主键与关系核对、切换与退回的步骤。

前置：[t07](../t07-identity-core/README.md)、[t08](../t08-social-login-and-oauth-provider/README.md)（导入的 GitHub 身份要能登录）。要开发者授权的：取生产数据库与文件卷的快照。预检若报出不合规则的用户名，处理规则交开发者定。

从 t07 的计划接过来的（2026-11-24，[t07 的计划](../t07-identity-core/plan.md) 3.2、3.7 与“设计审查的处理”第 16 条）：

- 账号库第一条迁移里为导入留的列是照最宽的可能定的，没有对照旧库的结构（读快照要开发者授权）：邀请码表有可空的备注，主人可以为空；两张码表的停用存的是时间。旧库的“是否停用”若只有布尔，导入时停用时间取导入的时刻，写计划时把这一句补进 `site.legacy-import`。
- 旧站的密码格式（scrypt 的参数、盐按字符串用）取自 t01 的记录与 t02 的探针，没有对照旧站源码，也没用旧站真实生成的哈希验过。开工前用旧站的代码在本地造一个样本哈希，跑一次账号模块的校验；对不上只改那一个文件。
- 对外的用户名是小写的登录名；旧用户名原样的写法存着但不对外，显示由显示名承担（显示名为空时取旧用户名的原样写法）。
- 导入显式写入账号 id，之后新账号的 id 接着往上（探针验过）；占位邮箱的写法与创建管理员的命令相同。
