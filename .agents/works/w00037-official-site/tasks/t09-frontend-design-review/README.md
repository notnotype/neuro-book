# 前端设计评审：静态稿与评审板

## 目标与范围

按仓库的设计评审流程，为登录、注册、账号设置、同意条款页、授权确认页、管理面板、统计看板与三个公开页面出静态稿，开发者逐轮定外观与交互。

合同：只定外观与交互，行为合同未变；页面要调的接口见 [`site.accounts`](../../../../../docs/specs/site/accounts.md)、[`site.admin`](../../../../../docs/specs/site/admin.md)、[`site.oauth-provider`](../../../../../docs/specs/site/oauth-provider.md)、[`site.telemetry-dashboard`](../../../../../docs/specs/site/telemetry-dashboard.md)。

## 当前状态

开发者 2026-11-24 让设计与后端同时进行。注意力排序已定，下一步出第一轮静态稿。

已定（开发者 2026-11-24，会话里答复）：

1. **主页只做登录入口**，不做产品介绍页。主会话的处理：登录入口旁留一行产品说明与隐私政策、服务条款的链接，供 Google 审核 OAuth 应用时作“说明用途的公开主页”；这一行是主会话加的，待追认。
2. **管理员登录后先看统计看板**；用户、注册码与邀请码、OAuth 客户端、审计在导航里。
3. **普通用户登录后直接进账号页**。（原先写的“最上面是待办”已被第 8 条取代。）
4. **外观**：全站用 nb-ui 的默认主题；开发者想另看一种“官方站自己的品牌外观”的可能，第一轮静态稿里并排给出。
5. **手机**：登录、注册、同意条款、授权确认和三个公开页适配手机；账号页能用；管理面板只做桌面宽度。

6. **外观定为“默认配色，登录页画成稿纸”**（第 1 轮评审板，三个候选里选 C）：全站用 nb-ui 的默认主题与配色，不为官方站另做配色；只有登录页整页画成稿纸，产品名与说明一格一字写在格子里。印章里的字现在是临时的 NB，有正式标志时换。

第 1 轮评审板的另一题（看板首屏的内容与先后）没有答，按图上的排法继续：上面一条是今天的四个数，中间是活跃与在线两张趋势图，下面是版本、系统、留存。

第 2 轮评审板（2026-11-24）的决定：

7. **注册、同意条款、授权确认三页与登录页用同一张稿纸**，同意。但注册页的“登录方式三选一”不要：GitHub、Google 做成图标，放在表单下面，登录页与注册页同一种画法（开发者：“别人家的都是放图标到表单底下”）。
8. **账号页不同意照图做。** 顶上的“这个账号还没有邮箱”横幅（nb-ui 的 `Banner`）不要：开发者认为丑，并且它让同一页在“有邮箱”“没有邮箱”两种状态下版式不同，后面的表单整体下移，违反 [开发规范](../../../../../packages/nb-ui/docs/ui-development-spec.md) 第 3 节第 4 条“状态变化不推动周围内容”。改法：待办标在它所在的那一行（邮箱那一格与目录里对应的一项），各状态的版式相同。此前第 3 条“最上面是待办”随之作废。
9. **管理面板的用户页不同意照图做。** 表格连同筛选、搜索与翻页抽成一个通用组件，并且要有正式的分页。

没答、按主会话的推荐做（待追认）：第一版界面只有中文，文字的组织方式留好加英文的余地；条款与隐私政策先出中文一份。

旧站的页面只用来对照功能有没有漏，不照它的样子画；静态稿从 nb-ui 现有组件与应用里设置页的画法起步。

范围：登录、注册（含用 Google 或 GitHub 注册时先填注册码与用户名）、同意条款页、账号设置（资料、邮箱、密码、已关联的账号、会话、邀请码、给过的授权）、OAuth 授权确认页、管理面板（用户、注册码与邀请码、OAuth 客户端、审计）、统计看板、三个公开页面（主页、隐私政策、服务条款）。按 design-review 的流程出静态稿与评审板，逐轮记录开发者的决定。
