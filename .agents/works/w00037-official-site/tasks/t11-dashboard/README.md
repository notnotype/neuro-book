# 统计看板：查询接口与图表

## 目标与范围

统计模块给看板的查询接口（要管理员身份）与管理面板里的几张图：活跃与新增、按周留存、在线、版本与平台分布、同意率、错误码。

合同：[`site.telemetry-dashboard`](../../../../../docs/specs/site/telemetry-dashboard.md)。

## 当前状态

未开工：开发者 2026-11-24 要求先把 ADR、Task 与文档写好，开工等他的指示。

范围：看板的六个只读查询接口（活跃数的算法、新增与留存、在线、分维度与小格子、错误码）、它们在合同包里的 schema、把响应转成 t10 定的视图模型的适配器，并把看板接到真实数据。看板的页面、图表模块与视图模型归 [t10](../t10-frontend/README.md)（它的计划 3.5 与 D8，2026-11-24）。合同包要导出的东西见 t10 计划 3.2 的清单；同意门槛不管统计模块的接口（`site.accounts` 输出 10），看板接口只按管理员身份判。

前置：[t06](../t06-telemetry-ingest/README.md)（有聚合）、[t07](../t07-identity-core/README.md)（“问身份”）、[t09](../t09-frontend-design-review/README.md)（图的样子与图表库）。

写计划时要定的一处（t05 的计划查出）：看板接口按“问身份”的回答判权限，统计模块要用到这个回答的类型；ADR 0059 决策 2 照字面只许模块包依赖自己的合同包。两种做法：统计模块自己声明它要的那个函数的形状、由进程入口的适配器转接；或者另写一份 ADR 部分取代决策 2，允许依赖别的模块的合同包（仍禁止实现包）。

从 t06 的计划接过来的（2026-11-24，[t06 的计划](../t06-telemetry-ingest/plan.md) 3.2 与 3.8）：

- 每个查询读哪张聚合表的哪些列，见计划 3.2 的表；“系统”那个分维度含不含系统大版本、立即事件要不要一个查询，看板 Spec 没说，写计划时定。
- 活跃数查 400 天约 50 毫秒（规划时的探针，8 核桌面机），在事件循环上同步执行，写计划时看要不要限制范围或缓存。
- 三条要能从外面读聚合才验得了的验收，由本 Task 的合同测试补成黑盒：`site.telemetry-ingest` 验收 1 的“聚合数不变”、Smoke 的“记入后在聚合里看到”、`telemetry.protocol` 验收 1 的“聚合里只算一份”。
