### 1. 社交注册成功时草稿没人删，草稿只在读的时候才判过期（注册码在 sessionStorage 里留到登出或关标签页）
严重程度：重要　类别：不变量、合同（计划 3.9、审定 D5）
位置：src/pages/RegisterPage.vue:322-346（只在进 /register 时读或清）；src/session/sign-out.ts:21；src/host/storage.ts:110-129
现象：全仓库只有三处删草稿：密码注册成功（RegisterPage:253）、进 /register 不带 social_error（RegisterPage:326）、登出（sign-out.ts:21）。社交注册成功时上游把人带回 `/`（Spec 输出 23），守卫按分派送去 /account，这条路径上没有任何地方碰草稿；用户放弃后不回 /register（在上游页面直接改地址去 /login 或 /、关掉上游页面后另开页）也一样（点浏览器的返回会重新载入 /register，那条路径会清掉，bfcache 恢复时不会，见下一条）。草稿里有注册码（有次数的准入凭据）、用户名、邀请码，从发起那一刻起一直留在 sessionStorage，直到登出、关标签页，或再次打开 /register。
为什么是问题：计划 3.9 写“注册成功（落到 /）、登出、不带 social_error 进 /register 时删掉”，并且 D5 把“存注册码”的风险论证建立在“读一次就删、10 分钟过期”上（计划 3.9 注册码一条）。10 分钟只在 take 时判，没人 take 就没有过期这回事；放弃的流程里它是一个能在标签页里活几天的、仍然可用的注册码。社交注册成功的账号还在同一个标签页里一直登录着，草稿的 registrationCode 已被扣掉，危害小；放弃的流程里的才是真风险（可用的码）。
如何核实：`grep -rn "clearSocialRegisterDraft\|takeSocialRegisterDraft" src | grep -v test` 只有上述几处；RegisterPage.dom.test.ts 与 e2e/register.e2e.ts 里没有“社交注册成功后草稿被清掉”或“离开 /register 后草稿过期”的用例（有“不带 social_error 再进 /register 被清”）。
建议改法：让清理不依赖用户再进 /register。最小做法：startSite 启动时先 take 一次（或 `clearIfExpired`，过期的删掉），并在 `router.afterEach` 里目的地不是 /register 时清掉；或者在 `CurrentAccount` 变成 signed-in 的那一刻清掉（覆盖社交注册成功、密码注册成功、补同意）。补一条 dom 用例：发起 -> 草稿在 -> 以已登录身份落到 /account -> 草稿不在；以及“放弃后到 /login，草稿不在”。

### 2. 发起社交流程后点浏览器的返回，页面从 bfcache 恢复，卡在“发起中”：两枚图标与提交按钮永远不可用（已在真实 Chrome 复现）
严重程度：重要　类别：正确性、不变量
位置：src/pages/RegisterPage.vue:265-299（`starting` 成功后不放开）；src/pages/LoginPage.vue:90-101；src/pages/account/SecuritySection.vue:124-141（`busyProvider`）；src/pages/account/LinkDialog.vue:249-264（`starting`）；全站没有 `pageshow`
现象：三处都假设“`leave(url)` 之后页面随之卸载，所以成功时不再放开”（注释原文）。从上游授权页点浏览器的返回时，Chrome、Firefox、Safari 默认走 bfcache：页面连同 JS 状态原样恢复，`starting`、`busyProvider` 仍是 true，没有任何代码在恢复时重置。注册页整张表单的提交按钮也因 `busy` 不可用；账号页的 LinkDialog 打开着、页脚按钮不可用、`busy` 为真（对话框自己的取消路径也受影响）；SecuritySection 的所有“关联/解除关联”按钮不可用。只有刷新才恢复。
为什么是问题：“在上游页面点返回”是这个流程里最常见的放弃方式（选错了账号、不想授权了），上游的 `social_cancelled` 只在点了上游页面的取消按钮时才回站点。
如何核实：我在 /tmp/review-w00037-t10-b4/lab/bfcache.mjs 里用本机 Chrome（`ignoreDefaultArgs: --disable-back-forward-cache`，Playwright 默认把 bfcache 关掉所以 e2e 看不到）对 `vite preview` 的构建产物跑了：注册页填注册码与用户名、勾两项同意、点 GitHub 图标，等地址变成上游页，再 `goBack`。恢复后 `/register` 页上用户名仍是 bob、两枚图标 `disabled` 为 `[true,true]`、sessionStorage 里草稿还在（输出：`{"url":"/register","restored":"navigate","social":[true,true],"username":"bob","draft":true}`）。nb-site-server 计划 3.8 发的 index.html 是 `no-cache` 而不是 `no-store`，所以生产环境同样符合 bfcache 的条件（`no-store` 的主文档在 Chrome 里不进 bfcache，那是巧合不是设计）。
建议改法：收口成一处。`leave` 之后站点根（`startSite`）监听 `pageshow`，`event.persisted` 为真时把“发起中”放开——最干净的是让 `SiteContext.leave` 返回一个 `Promise`/给一个 `restored` 的 ref，页面在 `await leave()` 之后放开 `starting`；或者让各处的 `starting` 由一个共用的 `useLeaving()` 管理，`pageshow(persisted)` 时统一清。同时 bfcache 恢复时草稿还在、表单还在，行为是对的，只要放开按钮即可。补一条用 `ignoreDefaultArgs` 打开 bfcache 的 e2e 用例，或至少一条 dom 用例（派发 `pageshow` 事件，persisted: true）。

### 3. 目录“钉住”只被滚轮、触摸、按键放开：拖滚动条、自动滚动之后高亮留在被点的那一节
严重程度：建议　类别：正确性（目录滚动高亮）
位置：src/pages/account/AccountPage.vue:102-104、123-125、154-160
现象：`goTo` 与带锚点进入时把 `pinned` 设成那一节，只有 `wheel`、`touchstart`、`keydown` 三种事件会放开。拖拽滚动条、鼠标中键自动滚动、选文字拖到边缘触发的滚动、辅助技术触发的滚动、程序滚动都不放开：`current = pinned ?? spied`，高亮一直是被点的那一节，与看到的内容不符。
如何核实：/tmp/review-w00037-t10-b4/lab/lab.spec.ts 的 T1：1440 宽点“已登录的设备”（scrollY 711，高亮 sessions），再 `window.scrollTo(0,0)`（等价于拖滚动条回顶）；scrollY 为 0，高亮仍是 sessions（输出：`T1 after scrollTo(0,0): sessions scrollY 0`）。
建议改法：换一个不依赖输入设备的放开条件：记下 `goTo` 之后“目标位置”，滚动事件里只要 `scrollY` 离目标超过阈值且不是在向目标靠近（或滚动停下 `scrollend` 之后）就放开；或者干脆在 `scrollend`（Chrome 114+、Firefox 109+、Safari 26）之后放开 `pinned`，再由 `spy` 重新判。`spy` 本来在滚到底时已经特判了“最后一节”，钉住只是为了平滑滚动途中不跳，`scrollend` 之后放开即可。

### 8. “退出其它所有设备”遇到 `rate_limited` 等失败后仍把剩下的逐个发完，最后的文案丢掉倒数
严重程度：建议　类别：正确性、代码质量（注释与行为相反）
位置：src/pages/account/SessionsSection.vue:76-108，注释 6-8 行
现象：注释写“串行地发……一次失败（例如限流）不会连带后面一整批同时撞上”，但循环里失败只是 `failedCount += 1; lastFailure = ...; continue`，之后仍把剩下的会话一个个发完，每一个都再被限流拒绝。结果：6 个其它会话、`Retry-After: 600` 时发出 6 个 DELETE，状态行写“结束了 0 个，6 个没结束”（只有 `failedCount === 1` 才显示失败自己的文案），`rate_limited` 的倒数没有了，用户不知道要等多久；`overloaded`、`unavailable`、网络失败同理（连续对一个坏掉的服务发 N 次请求，每次等超时）。

建议改法：把“规则说明”收成 `useFormFeedback` 的一等操作：`feedback.setRule(field, textRef)`（写状态行并标红、不聚焦）与 `feedback.clearRule()`（只撤规则那一类），`reason` 里的前缀约定就不需要了；`social:` 那一类直接用固定的 `"social_error"`，不拼地址参数。`meta` 失败时给社交图标行一个重试（点一下重取，或进页 5 秒后自动重取一次）。

### 22. Google 的“G”图是 Figma 导出的 SVG：用 `foreignObject` 里的 CSS conic-gradient 加高斯模糊滤镜，只在 Chrome 实测过
严重程度：建议　类别：正确性（跨浏览器，未验证）
位置：src/assets/brands/google-light.svg、google-dark.svg（各约 10.8 KB，原样取自 Google 素材包）；SocialButtons.vue:70-71（用 `<img>` 引入）
现象：这份 SVG 的彩色部分是一个 `mask`（“G”的形状）下面的 `foreignObject`（里面是 `div` 的 `conic-gradient`）加七个 `filter` 的模糊椭圆。e2e 只在本机 Chrome 里量（`register.e2e.ts:210`：四色像素各 > 3）。`foreignObject` 放在作为图片引入的 SVG 里，在 Safari（WebKit）上历来有限制，我没有 WebKit 环境，没法验证：如果它不渲染，“G”会只剩白底的空按钮。Firefox 同样没验证。
为什么是问题：Google 的规范是“G 必须用标准的全彩版”，空按钮既违反规范，也让 Safari 与 iOS 用户没有 Google 登录入口的外观。
如何核实：用 Playwright 的 WebKit（本机没装，`~/.cache/ms-playwright` 不存在）或 Safari 打开 /login，看 Google 按钮里有没有四色“G”。
建议改法：先在 WebKit 与 Firefox 各看一次；若有问题，换成素材包里同一个“G”的纯路径版（四条圆弧的 `path`，没有 `foreignObject` 与滤镜；Google 的品牌页有这个“Logo”素材，不是整枚按钮的那份），按钮的底与描边仍由 `.social-face--google` 的 CSS 画，与 GitHub 一样；这样亮暗两份图可以合成一份，也少下载约 10 KB。README 同步写明换了素材。

### 未发现问题的方面（仔细检查后）
- 草稿内容与时序：草稿不含密码（保存点只传 provider、用户名、显示名、邀请码、注册码、同意）；写草稿在 `leave` 之前（dom 用例用 `left[].draft` 快照守着）；读一次就删；超过 10 分钟或存坏的不还原（`storage.dom.test.ts`）。问题只在“没人读时不清”（第 1 条）。
- 社交发起的门槛：`registrationOpen` 为假、`meta` 取不到、两项同意没勾、规则不合时都不发起；503/403/429 写状态行，429 倒数且按钮不可用（登录页、注册页有用例）。`social_error` 的文案只认合同包的码，其余显示 `social_failed`，不回显（`socialErrorText`）。
- 账号页流程：关联先要当前密码、没有密码的免；`last_login_method` 的文案与焦点（变异被抓到）；邀请码满 10 个禁用、`invite_code_limit` 重取；`endOthers` 串行、不碰当前会话（变异被抓到）；`CurrentAccount.update` 与进行中取数的先后正确（`generation` 换代，有单测）。
- 共用部分：`showSuccess` 用 `clock.every` 做一次性计时可以接受：到点第一次就停，被别的状态替换时不清别的，卸载时清理；缺点只是没有 `after`，不是缺陷。`FormStatus` 的 `tone` 与成功色没问题。`site-harness` 的三份列表默认回空：请求仍记进 `requests`，且只覆盖账号页一定会发的三个 GET，不会掩盖别的接口（别的没准备的请求仍进 `unexpected`）。`build.test.ts` 的 `sourcesOf` 对没有 sourcemap 注释的块返回空，不会让断言空过：入口块那一条有“必须认出 vue-router”的正向断言兜底，有注释而读不到 `.map` 仍然抛出。
- 密码一行写“已设置”：合同 `MeResponse` 没有密码修改时间，写“上次修改于”做不到，见第 12 条末。
- 有邮箱与没有邮箱的版式相同（e2e 量几何，主会话的运行与我读到的用例一致）；vitest `src/pages` 80 条全过（我重跑）。
- 图标：读屏名字与 `title` 按页面写“登录/注册”；GitHub 黑白、Google 全彩、底与描边与计划引的规范数值相同；暗色按根属性切换，不用脚本换图。GitHub 官方是否允许把 Invertocat 放进带描边的方块我没核实（README 也写了没核实）。
