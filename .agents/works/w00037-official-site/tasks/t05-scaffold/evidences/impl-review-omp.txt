# w00037 t05 第 1–3 片实现审查（3c4dc0466..49ab37bab）

### 1. 迁移可以换掉运行器的事务并被记为成功

- **严重程度**：阻断；**类别**：不变量。
- **位置**：`packages/nb-site-server/src/db/migrate.ts:79–87、149–167、217–235`；`db/migrate.test.ts:252–269`。
- **现象**：`db.inTransaction` 只证明有一个事务，不证明是运行器开启的那个。SQL 自行提交或回滚后再开始，`foreign_key_check` 与账本插入检查的是后一个事务；此前的数据可能已经提交，也可能已被撤销。
- **为什么是问题**：设计修订第 16 条接受的是“错误会被检测到，但首次 COMMIT 前的改动无法撤销”，不是接受漏检并发布。真实子进程中，`INSERT` 后提交、重开事务再插一行，退出 0 并记录 `0002_replace`，两行都在；先回滚再重开也退出 0，第一行消失但仍记成功；第二段改成写不存在的表则退出 1，第一行永久留在库里、账本没有第 2 条，重跑可再写一遍。
- **如何核实**：实验目录 `migration-entry.ts` 经未改的 `runCli` 起真实 `migrate` 子进程，分别选 `replace`、`rollbackReplace`、`replaceFail`，退出后用独立 SQLite 连接查询 `item`、`site_migrations`；现有测试只覆盖退出脚本时已经没有事务的情况。
- **建议改法**：在执行前按 SQLite 的语句边界拒绝事务控制，保留触发器与多行 CASE；优先复用 SQLite 的解析/授权机制（若 Bun 的公开接口支持），否则实现并测清 SQL 词法和语句边界。运行后的状态检查只作兜底，不能承担原子性保证。

### 2. SQLite 原始诊断能把库里的值写到标准错误

- **严重程度**：重要；**类别**：安全与性能。
- **位置**：`packages/nb-site-server/src/db/migrate.ts:66–69、181–189`；`commands/prepare.ts:28–34、47–52`。
- **现象**：迁移器直接输出 `SQLiteError.message`，理由是“说明里只有标识符与 SQL 片段”。SQLite 允许 `RAISE(ABORT, 表达式)`，说明可由数据库中的当前行产生，不由迁移文件中的字面量决定。打开库的失败也复用这个未经约束的出口。
- **为什么是问题**：违反不输出路径与数据的日志边界；真实运行中 `migration_failed` 的 `dbMessage` 等于库中的完整合成私有值。设计修订第 14 条允许错误说明的前提不成立。
- **如何核实**：实验目录 `migration-entry.ts`，先应用 `0001_items`，独立连接写入一条合成记录，再以 `dynamicError` 运行真实 `migrate`；stderr 为一行 JSON，`dbCode=SQLITE_CONSTRAINT_TRIGGER`，`dbMessage` 为合成记录原值；退出 1，原数据未改。
- **建议改法**：只对外投影模块名、合法迁移 ID、`reason` 与 SQLite 稳定错误码；需要可读说明就按码映射到固定文本，不筛原始消息。把合法迁移 ID 的约束同样用于输出账本中不合格的记录，不能把任意账本内容当日志字段。

### 3. 校验和忽略了实际写进数据库的换行差异

- **严重程度**：重要；**类别**：正确性。
- **位置**：`packages/nb-site-server/src/db/migrate.ts:90–97、158、210–214`；`db/migrate.test.ts:317–323`。
- **现象**：对归一化文本算哈希，却执行原始文本。引号内的 CRLF 不是 SQLite 的空白而是数据；因此同一个迁移 ID 及校验和能对应两个不同的数据库结果。
- **为什么是问题**：Windows 和 Linux 第一次迁移可落下不同的默认值或种子数据，之后对方版本读到账本也不会识别差异。BOM 只去 SQL 文件第一个字符，未遇到同类问题；不要把字符串中的换行与文件开头的标记混为一谈。
- **如何核实**：实验目录 `migration-entry.ts` 用真实 `migrate` 分别在两个空库应用 `crlf` 和 `lf`；`0002_lines` 校验和相同，`hex(item.value)` 分别为 `746F700D0A626F74746F6D` 与 `746F700A626F74746F6D`。
- **建议改法**：制定同一份字节既用于执行又用于校验的规则。最少部件的做法是把 `.sql` 固定为 LF 检出、对原始内容算哈希，真正写 CRLF 用 SQL 明示；若仍要求容忍外部文件检出差异，哈希只归一化字面量以外的换行，并加含多行字符串的行为用例。
