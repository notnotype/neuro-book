## 1. [重要] 新写 user-select: text 的内容根里，原生 button、summary 与 nb-ui 的 Tabs、CollapsibleCard、CollapsibleRow 触发器会变成可选
问题：用户选择是继承的，原生 `<button>`、`<summary>`、`<div role=button>` 不带 none 时继承内容根的 text。实测（headless Chrome，html 为 none、内容根为 text）：原生 button 的 computed user-select 是 text，对其文本节点 setBaseAndExtent 读出 "button label"。落点：
 - `.acv-stream`（packages/nb-agent-ui/src/vue/AgentConversationView.vue:631）里的工具调用与思维链标题：AgentChainSummary.vue:26 原生 button、AgentTurnBlock.vue:134（通知行）与 :151（分隔线开关）原生 button、nb-ui 的 CollapsibleCard/CollapsibleRow 触发器（packages/nb-ui/src/components/layout/CollapsibleCard.vue:48 与 CollapsibleRow.vue:42 用 `component :is="button"`，都没写 select-none）、AgentFileChanges.vue:56/68、AgentUserContent.vue:77/100 的 button。
 - `.ard`（AgentRequestDetail.vue:498）里的 nb-ui Tabs（Tabs.vue:158 原生 button 无 select-none）、`.ard__find-page`（:339/:340）、`.ard__item-head`（:350/358/375/393）。
 - `.acv-inspector`（AgentContextInspector.vue:94/99/108）里的 `<summary>`。
 后果：桌面里双击折叠标题会同时选中标题文字，拖选跨过标题时把“已执行 3 步”之类标签带进复制结果；与 Spec 输出 12 写的“界面框架的文字（…按钮、菜单…）不能选中”不符，也与新规范 4.7 自己写的“业务里自己写的原生 button 没有，要自己写”相矛盾。规范 4.7 第一条“nb-ui 的按钮、菜单项、徽标、气泡面板已经是”也说宽了：Tabs、CollapsibleCard/Row、Banner 的关闭按钮、InfoTip 触发器都不是。
 各处 e2e 都只做正向断言（内容可选），没有一条在内容根里断言框架控件不可选，所以不会红。
建议：在 nb-ui 的 CollapsibleCard、CollapsibleRow、Tabs（以及 Banner 关闭键、InfoTip）的触发器上写 select-none；nb-agent-ui 里这些原生 button/summary 逐个加（或各自 scoped 类里加一行）；Lab 用例补一条“消息流里工具标题（或思维链摘要）选不中”。不想逐个加的话，也可把规范与 Spec 的措辞收窄为“内容根里的可点击标题不保证不可选”，但这样与“像原生应用”的目标不符。

## 9. [一般] e2e 稳定性：浏览器用例没等会话面板文字就读；若干定位没带文案过滤
问题（packages/neuro-book/e2e/text-selection.e2e.ts）：
 - “浏览器”用例在 `openNote` 后立刻 `expectSelectable(sessionPanel(page), "没有会话")`；桌面用例却先 `await expect(sessionPanel(page)).toContainText("没有会话")`。会话面板由懒激活的 agent 插件渲染（plugins/agent/web/plugin.ts:449 `vueOnce` 动态导入），文字出现晚于 `data-rpc-state=online`。`copyable` 里 `evaluate` 只等元素存在，不等文字，找不到文本节点返回 null，`toContain` 一次失败、不重试。负载高时会偶发红（你的 memory 里已有多个负载相关的偶发）。`expectWorkbenchChrome` 里状态栏“显示面板”与面板头“资源管理器”同理。
 - `page.locator(".workbench-panel-head__label")` 与 `.settings-list-section__group-title`、`.settings-row__description` 都取 `.first()` 而没按文案过滤；面板头第一个未必是资源管理器（布局或插件顺序变化即失效），设置页第一个小组标题的文字被当作 needle 取 innerText，倒是自洽。
 - 一条通用做法：让 `copyable` 外面包 `expect.poll(...)`，或进入断言前先 `await expect(region).toContainText(needle)`（不可选的区域也能用，toContainText 读 textContent，与选区无关）。
建议：把 `expectSelectable` / `expectNotSelectable` 内部先 `await expect(region.first()).toContainText(needle)`，再读选区；面板头用 `locator(".workbench-panel-head__label", {hasText: "资源管理器"})`。
