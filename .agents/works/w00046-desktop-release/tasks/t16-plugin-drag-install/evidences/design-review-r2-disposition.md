# t16 设计审查第 2 轮（Opus，14 条：中 4、低 10）的处理

第 2 轮的中级问题大多出在“逐个文件 PUT”带来的状态（在途写入、封口、路径放 URL）。r3 改成一个请求传整个文件夹（自定分帧，流式），这些状态整体去掉；不再在 r2 上逐条打补丁。

| 条 | 级别 | 处理 |
|---|---|---|
| 1 window 上的监听接管整个工作台 | 中 | 成立。落点收窄到插件页的根元素，不挂 window；落在没有落点的地方归 t15 统一处理 |
| 2 在途 PUT 不在状态机里 | 中 | 成立，随设计消失：一个请求写完才交回 id，中途失败删掉已写的部分 |
| 3 确认安装后马上关窗，页面的删除让安装失败 | 中 | 成立。行为 5 写明发出安装后页面不再删，由服务端安装结束时删；dom 测试覆盖 |
| 4 临时名改名在 Windows 上易被打断；删除失败未定义 | 中 | 成立。`wx` 直接写，不改名；删除失败只记诊断、留给下次清空，清空失败不挡插件页 |
| 5 路径规则只在服务端逐个查 | 低 | 成立。规则放 `src/shared/plugin-upload.ts`，页面收集时先查 |
| 6 大小写冲突、文件与目录同名、NFC | 低 | 成立。写进路径规则 |
| 7 总量在并发下超、`bodyLimit` 整份读 | 低 | 成立。不用 `bodyLimit`，在流里计数；一个上传一个请求，没有并发写同一上传 |
| 8 `+` 被解码成空格 | 低 | 随设计消失：路径在分帧的 JSON 头里 |
| 9 被取代的旧上传没人删；“进行中”范围 | 低 | 成立。被新拖入取代时页面删；进行中含预览与确认框开着 |
| 10 `readDrop` 的形状太贴插件页 | 低 | 成立。交回条目列表，解释交给调用方 |
| 11 e2e 合成 drop 到不了文件分支 | 低 | 成立。文件分支放 dom 测试，e2e 只走“选择文件夹” |
| 12 读文件失败分不出原因；目录链接环 | 低 | 成立。提示写“读取或上传没有完成”；遍历深度至多 64 |
| 13 上传客户端怎么交给页面 | 低 | 成立。作为 prop 注入 |
| 14 同时存在的上传个数；清扫计时器；清空的时机 | 低 | 成立。至多 8 个；计时器用注入的时钟，随能力建立、随服务端停止撤销；清空写成“第一次用到暂存区时” |
