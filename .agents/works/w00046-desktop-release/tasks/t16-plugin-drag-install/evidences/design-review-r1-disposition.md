# t16 设计审查第 1 轮（Opus，17 条：中 7、低 10）的处理

| 条 | 级别 | 处理 |
|---|---|---|
| 1 上传 id 没规定校验，可借路径穿越写进安装目录 | 中 | 成立。id 是服务端签发的 UUID，先按格式查本次运行的内存表，查不到不拼路径 |
| 2 没有“写完”，并发与删除时序未定义 | 中 | 成立。加封口与状态机（写入中、已封口、使用中、已删除）；使用中的删除排队；安装由服务端结束时删，页面确认安装后不再删 |
| 3 相对路径放在 URL 路径里会被规范化与重复解码 | 中 | 成立。改放 `?path=`，只解码一次后校验 |
| 4 拖放事件处理缺口 | 中 | 成立。在 `window` 上处理 `dragenter`/`dragover`（`preventDefault`、`dropEffect`），按 `relatedTarget === null` 收起覆盖层，不计数；`drop` 的同步段里取条目；进行中再拖入给提示；“只收 Files 的拖动”与“拖入的不是文件夹给提示”不矛盾：前者筛掉页面内部的拖动，后者是 Files 拖动里的单个文件 |
| 5 桌面能否收到外部拖放排得太晚 | 中 | 部分成立。查了 Electrobun 2.0.6：没有改 WebView2 的 `AllowExternalDrop`（缺省允许）。Windows 现在不能构建，仍在切片 5 实测，结果给 t15；网页一侧按标准实现，桌面若收不到再加壳的处理 |
| 6 “选择文件夹”跳不过 node_modules、Chromium 先弹确认 | 中 | 成立，接受为已知限制（待确认清单）：按钮是键盘用户的入口，跳过在收集时做；桌面用壳的原生对话框拿路径要给页面加调用壳的接口，不在本 Task |
| 7 遍历应放共用层 | 中 | 成立。放 `src/ui/dropped-folder.ts`，t15 复用 |
| 8 整份读进内存 | 低 | 成立。流式写到临时名再改名，按实际字节累加 |
| 9 不能与 copy.ts 共用路径规则 | 低 | 成立。自己一份规则，一律按 Windows 也合法的查（待确认清单） |
| 10 路由在入口激活后才挂、要 `onError` | 低 | 成立。插件页先 `list()`，入口那时已激活；路由加 `onError(rethrowRouteError)` |
| 11 v2 没有鉴权，写不出 403 | 低 | 成立。去掉授权测试，现状写进计划 |
| 12 页面读文件失败没定义 | 低 | 成立。作废这次上传并指出文件 |
| 13 清理缺口 | 低 | 成立。预览失败也删；离开页面用 `keepalive`；删除不存在算成功 |
| 14 可只上传 `files` 用得到的部分 | 低 | 不做（写进“不做”）：服务端取舍已正确，先保持简单 |
| 15 可测性 | 低 | 成立。e2e 走“选择文件夹”（真实目录）；合成 `drop` 只验文件分支；遍历的替身按真实形状写 |
| 16 配套漏项 | 低 | 成立。补 Lab 夹具、`PluginsPage.md`、上传时的 `path-rejected` 文字、Spec 其它处、合同版本 6 |
| 17 体验补充 | 低 | 采纳：预览写文件数与大小、拖错上一层目录给提示、压缩包单独说明 |
