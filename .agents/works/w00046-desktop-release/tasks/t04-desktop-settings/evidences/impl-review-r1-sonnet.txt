[6] 建议 / 正确性（输入边界） / packages/neuro-book/src/plugins/desktop/web/zoom.ts:250-252、plugin.ts:161-167
`Numpad0` 在 NumLock 关闭时其实是 Ctrl+Insert（复制），被当成“复位缩放”吞掉；输入法组字期间的按键也没有排除。
- Numpad0：UI Events 里 `code` 是物理键位，NumLock 关闭时小键盘 0 键的 `key` 是 "Insert"、`code` 仍是 "Numpad0"。`zoomKeyAction` 的 `Numpad0` 分支只看 code，所以 Ctrl+小键盘 0（NumLock 关）= Ctrl+Insert 被 `preventDefault` 且 `stopPropagation`，复制被拦下并改成复位缩放。Windows 上 Ctrl+Insert 是保留的复制快捷键。（从规范推断，没有真键盘；用 `{code: "Numpad0", key: "Insert", ctrlKey: true}` 调 `zoomKeyAction` 会得到 "reset"，这是可验证的部分。）同理 `Digit0`/数字行不受影响，`NumpadAdd`/`NumpadSubtract` 不受 NumLock 影响。
- 输入法：keydown 在组字期间 `isComposing` 为 true（或 key 为 "Process"，keyCode 229），`code` 仍是物理位置。捕获阶段的监听直接 `preventDefault` 并停止传播，把输入法正在用的 Ctrl 组合键拦下。常见中文输入法对 Ctrl+= 之类的占用不多，但这是 brief 点名的冲突面，代价只是一行判断。
- 建议：处理前先 `if (event.isComposing || event.key === "Process") return null`；小键盘的 0 要求 `key === "0"`；小键盘加减的 `key` 也核一下。把这两种输入加进 `zoom.test.ts` 的按键判定那条里（现在测的 `ZoomKey` 没有 `key`、`isComposing` 两个字段，也要加）。
