### 1. 向导宿主逻辑（first-run.ts、first-run-entry.ts）没有任何单元测试，Spec 输出 34 的大半句子无测试
严重程度：重要　类别：测试缺口

没有任何测试覆盖的 Spec 句子：

### 2. 三处新增的 `waitForTimeout` 违反 fixed-wait 机检，`packages/neuro-book` 内违反即失败
严重程度：重要　类别：测试规范
位置：e2e/desktop-first-run.e2e.ts:98、:162；e2e/desktop-settings.e2e.ts:178
现象：用 `scripts/ci/test-conventions.ts` 的 `scanTestSource` 扫这三个文件，报 `fixed-wait` 共 3 处新增（desktop-settings.e2e.ts:56 是 master 上就有的 setTimeout，不算）：first-run 的“再看一阵子”1.5 秒、“浏览器里”1.5 秒，desktop-settings 的“坏的用户层不交值”1 秒。三处都没有 `// test-lint-allow fixed-wait: <理由>`。
为什么是问题：docs/testing/README.md 第 20 行写明断言“没有发生”要先排一个走同一条队列、结果看得见的动作，不按固定时长等；机检表里 `fixed-wait` 对 neuro-book 是失败不是警告。我在主工作区跑 `testConventionReport` 得到 master 现有 13 条失败，这次再加 3 条。仓库里已有的例外写法：editor-autosave.e2e.ts:151、markdown-comments.e2e.ts:105，都带理由。
更实质的一点：1.5 秒是“等到向导本该出现的时间”，不是信号。机器负载 30 时记录就绪可能晚于 1.5 秒，这条否定断言会假通过；作者说做过变异（出现条件不看记录），那是在安静负载下。
如何核实：`bun scripts/ci/...` 的扫描函数（我的脚本在 /tmp/claude-1000/review-t02-impl/scratch/scan.ts）；`grep -n waitForTimeout` 三个文件。
建议改法：给向导的出现条件一个可观察的信号，最小做法是向导宿主在“记录与用户层都已就绪、判定过一次”后在根元素上设一个 data 属性（或经公开状态），e2e 等这个属性再断言 count 为 0；做不到就按仓库先例加 `test-lint-allow fixed-wait` 并写明没有可等的信号，同时把等待放宽到不依赖本机速度。

### 3. 写配置失败时状态行不说原因，与 Spec 输出 34“底部说明原因”和计划“按码取文字”不符
严重程度：重要　类别：对照 Spec
位置：first-run.ts:177-203（write）、first-run-entry.ts:140-145（messageText）、locales 的 `firstRun.errors.notSaved`
现象：主题、明暗、语言、桌面三项写失败，`SettingsFailure` 有 denied、invalid-value、layer-invalid、write-failed、conflict、unavailable 等十来个码（settings/shared/contracts.ts:COMMAND_FAILURES 那张表），向导一律显示“{名字}没有改成，回到了原来的值。”；只有 `unknown-outcome` 另有一句。原因（码、detail）只进 `desktop.first-run.write-failed` 诊断，用户看不到。
为什么是问题：Spec：“写失败时控件回到配置服务里的值，底部说明原因”；计划第 64 行：“失败按码取文字放状态行”；ADR 0034 决策 2：界面按“拥有者命名空间加码”取文案。作品目录那一侧作者做到了按码（五条 reveal 文案），设置这一侧没做。典型场景：用户的 settings.json 被别的程序占着或只读（正是 e2e 用例 4 造出来的情形），向导只说“没改成”，用户不知道该去查什么；而同一情形下缩放（plugin.ts:75）至少把 `detail` 作为可复制的通知详情给出。
如何核实：e2e/desktop-first-run.e2e.ts:142 断言的文字就是那句通用话；把 write 里 `message` 的构造看一遍，没有任何分支用 `result.code` 区分（除 unknown-outcome）。
建议改法：二选一。(a) 按码分三四类给文案：`write-failed` 与 `layer-invalid`（设置文件写不进去、文件有问题，到设置里看）、`denied`、`unavailable`（连不上服务）、其余通用，目录里补键；(b) 保留通用句，状态行 title 属性或第二行附上 `detail`（Dialog 的 status 已有 `title` 与 `select-text`）。若判断“窄场景不值得”，至少在 Spec 把“说明原因”改成“说明没改成”，让合同与实现一致。

### 4. 作品目录“打开”遇到不认识的错误码时说成“连不上服务”，并丢掉码；作品目录读取失败时路径行悄悄为空
严重程度：建议　类别：失败说明（ADR 0034）
位置：first-run-entry.ts:113-126（library、revealLibrary）、locales `firstRun.errors.reveal.unavailable`
现象：`revealLibrary` 返回合同里五个码以外的失败（例如远程调用的 `denied`、输入校验类、服务端内部错）时，代码一律归为 `unavailable`，状态行显示“现在连不上 NeuroBook 的服务，稍后再试。”；`library()` 失败时只记诊断，第四步“新作品默认放在”那一行路径为空、“打开”照常可点，点了才得到另一条错误。
为什么是问题：ADR 0034 决策 2：“遇到不认识的码，显示通用说明并附上码”。这里的 `unavailable` 文案是“连接问题”的具体说法，用到非连接错误上会误导；用户报 bug 时也没有码可报。
如何核实：读 first-run-entry.ts:122-125；用一个返回 `{ok:false, code:"denied"}` 的 projects 替身即可复现。
建议改法：新增一条通用文案“没能打开作品目录（{{code}}）”给未知码，`unavailable` 只留给真正的传输失败（`RemoteCallError` 的 unavailable）；`library()` 失败时让第四步这一行显示“读不到”的中性提示，不留空。

### 5. `close()` 在记录已存在时也重写；一次写失败后同页再关向导会静默排在失败的意图后面
严重程度：建议　类别：不变量
位置：first-run.ts:229-240、shared/store/persisted.ts:#pump（读过）
现象：从命令面板打开向导（记录已 ok）再关，`remember` 照样 `commit(() => ({at}))`，`at` 变成新的时刻、revision 增加，`locality: "shared"` 的记录会广播给所有客户端的所有窗口。另外，`persisted.ts` 的队首失败或结果不确定时队列暂停（`#pump` 遇到 state 非 queued 的队首就 return），之后的 commit 排在它后面，Promise 永不结算：同一页里第一次关向导写失败后，再从面板打开、再关，第二次写既不发出也不记诊断。
为什么是问题：第一点是无谓写入与跨窗口事件，对 Spec 没有用处（Spec 只要求第一次写）。第二点符合 Spec“下次还会出现”，但同页的重复关闭会悄悄丢，诊断里也没有。两点都不严重，属于窄场景。
如何核实：读 persisted.ts #pump 与 first-run.ts:234；`unknown` 时 report 文案“下次还会出现”也不准确（写请求可能已落盘）。
建议改法：`close()` 里 `if (store.state.seen.base?.status === "ok") return;` 跳过写；失败的意图是否要 `retry` 或 `discardAll` 后重发，按“窄场景选简单改法”可以只在文档里记为已知限制。`unknown` 的诊断文案改成不断言“下次还会出现”。

### 6. 三条切换命令的 id 在本插件里复制成字面量，语言那条没有任何测试核对
严重程度：建议　类别：结构、上游选择
位置：first-run.ts:47-52
现象：`SWITCH_THEME`、`SWITCH_APPEARANCE`、`SWITCH_LOCALE` 是照抄的字符串，注释说“这三个常量在对方的 web/ 里，所以照抄字面量”。真实常量在 plugins/workbench/web/commands/theme-commands.ts:19-20 与 plugins/settings/web/plugin.ts:50，且都带 `export`。
为什么是问题：声明者改名（例如把 `nbook.settings.switch-theme` 迁到 `nbook.view.*`）时，向导的主题、明暗、语言会全部变成“没有改成”（命令 id 未知，`execute` 返回失败），编译期与大部分测试都不会红：theme 与 appearance 有 e2e，locale 没有（见第 1 条）。注释把“常量在对方 web/ 里”当成约束，但没有记录这条约束的理由（跨插件只引 `shared/contracts.ts` 是规则，把常量搬到 `shared` 不违反它）。
如何核实：`grep -rn "switch-locale" e2e` 无输出。
建议改法：把三个命令 id 常量移到各自声明者的 `shared/contracts.ts`（workbench 的 shared 已导出 `themeSetting`、`appearanceSetting`，settings 的 shared 已导出 `localeSetting`），向导按包名引用；代价是两个插件各多一个公开常量。不想动上游时，至少补一条 e2e 或单元测试让三条命令各被执行一次。

### 7. 几条测试断言空过或没测到它声称的判据
严重程度：建议　类别：测试质量
位置：src/plugins/desktop/web/components/FirstRunWizard.dom.test.ts:74-86、:151-157；e2e/desktop-first-run.e2e.ts
现象：
- “回车在开关上不前进”：组件里没有任何处理 Enter 或发 `next` 的代码，测试派发的 `KeyboardEvent` 在 jsdom 里也不会合成 click，所以这条断言无论怎么改实现都是绿的（除非有人以后新加 Enter 处理）。

如何核实：删掉对应属性或 `.is-hero` 的 transform 后跑 dom 测试，应全绿（我没改仓库，按代码推断，未实跑）。
建议改法：第一条删掉或改成真正按下 Enter 的 e2e；第二条断言 `request-close` 的 reason，或直接在 dom 测试里把 `close-on-request` 的保护视为必要而删这条；缩略图加一条 `naturalWidth` 断言；位移用 `boundingBox` 比较第一步与第二步 `.first-run__mood` 的 y 与宽；用例 4 加 root 跳过。

### 8. FirstRunWizard.md 与实现不一致：`state:local` 标签与“组件自己记住键盘焦点”不存在；“窄于 560px 两列”没有对应的样式

### 9. 样式没有消费字号与圆角 token，卡片焦点环靠浏览器默认 outline
严重程度：建议　类别：UI 规范

现象：字号手写 12、13、14、15、24、30px，圆角手写 10、8、28、2px；tokens.css 与 theme.css 里有 `--text-xs/sm/md`（12、13、14）与 `--radius-panel`（10）。两组卡片（`first-run__card`）是裸 `<button>`，`border:0; background:none`，自己没有 `:focus-visible` 样式，也没用 `.nb-ui-focus-ring`；选中态只在缩略图上画 `box-shadow`。

建议改法：12、13、14px 换 `--text-xs/sm/md`，10px 换 `--radius-panel`；卡片按钮加 `nb-ui-focus-ring`（注意 `.first-run__themes` 外层没有 overflow 裁切，余量够）。15px、24px、30px 没有对应 token，保持即可。

## 未发现问题的方面
- 出现条件：shouldOpen 对“读取失败、记录未就绪、用户层不可用、已 dismissed”都不开，与 Spec 表一致；`field.ready` 与 `base?.status` 的组合我对着 persisted.ts 与 RecordSnapshot 核对过，没找到漏洞。
- 值的写法：`settings.update` 在 resolve 前已 `apply` 快照，所以写完删在途值不会闪回旧值；在途值只在没有被更新点选覆盖时清（first-run.ts:199-200）这一处正确。三条命令的参数名（theme、appearance、locale）与声明一致。`commands.execute` 不抛（每次执行恰好一条审计事件，含异常），write 里没有 catch 不会产生未处理的拒绝。
- 浏览器路径：空浮层、命令 when 要求 inDesktop，e2e 同时核对不加载向导的请求；安装事实的监听在 boot.ts 里先于页面就绪消息注册，没有丢消息的时序；桥只收形状正确的 install-facts，`open-state-root` 不带路径，页面脚本不能借它让壳打开任意目录。
- Dialog 用法：`size`、`close-on-request`、`close-on-overlay`、`initial-focus`、页脚插槽与状态行都对着 Dialog.vue、DialogSurface.vue、dialog-close.ts 核对过；状态行是 `aria-live`，错误可选；Esc 经 `request-close("escape")`，输入法组字时不触发。
