# 浏览器入口登记后台任务与可续传上传

## 目标与范围

扩展 nbook.tasks：浏览器入口能登记任务（窗口断开记为已中断），服务端提供可续传的上传接口，让长时间的上传、导入能脱离单个窗口；第一个使用者是 t15 的批量拖入。t16 的上传先用页面里的进度

合同：改 [`workbench.background-tasks`](../../../../../docs/specs/workbench/background-tasks.md)（现在写明“浏览器入口登记任务”不承诺，要改成承诺并定语义）；可续传的上传接口另写 Spec（放在 `workspace.files` 还是新能力，开工时定）。

## 当前状态

2026-11-17 经 nbdev 新建，开发者同意分两步走（讨论见 w00046 会话）：t16 的插件文件夹上传先用页面里的进度、不接入 `nbook.tasks`；本 Task 在 t15（批量拖入）要用时开工，需求由真实使用来检验。未开工，排在 t15 之前或与它同时。

## 设计要点（讨论的结论，开工时重新核对）

- 现状：`nbook.tasks` 只让服务端入口登记任务，句柄带取消信号；窗口关了任务照跑。上传的字节在页面里，页面关掉上传就断，所以直接上传不是服务端任务。
- 要做的三件事：
  1. **浏览器入口登记任务**：远程合同加 `start`、`report`、`end`，任务作为清单里的一项，由登记它的窗口推进；窗口断开记为已中断。
  2. **可续传的上传接口**：分块上传，每块带偏移，服务端记下已收到多少；窗口关掉再打开能读到进度，用户重新选同一个文件夹后接着传。
  3. **脱离页面的上传（只在桌面）**：壳用原生对话框拿本机路径，服务端自己读文件；浏览器版做不到，两端不同的部分按 Work 的“按能力分、不建统一 facade”处理。
- 不做：把所有下载都改成任务（桌面更新的下载是壳的事，保持现状）。
