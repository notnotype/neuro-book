t10 计划设计审查第 1 轮（Sonnet，页面一侧）的处理。报告：design-review-r1-sonnet.txt。8 条有效（阻断 1、重要 6、建议 1），均成立、均改计划。

总的改法：提示从“壳推给页面的事件”改为“壳持有的状态”，每个阶段一个新 id，壳记持有窗口，只在持有窗口关掉、刷新、离开就绪时转交。

[1] 阻断 同一 id 用 update() 推进阶段与通知合同冲突：每个阶段一个新 id、一条新通知；页面记“壳 id → 句柄”，句柄失效不重发。
[2] 重要 何时发 end：“以后”不发 end（中心里的“下载”仍可点，壳仍接受这个 id 的 download）；end 只在提示被新阶段取代或转交时发，连中心记录一起删。
[3] 重要 没有选择的提示无“已处理”：加 update-hint-shown，一次性提示收到后清掉。
[4] 重要 就绪未定义：就绪 = ready 且页面挂好（不是启动失败页），每实例一次；加 page-gone；监听最早建立、就绪前缓冲。
[5] 重要 宿主拿不到通知服务：window.ts 加非必需启动门禁取 notificationsKey，BrowserWindow.notifications()；window.ts 列进切片 3。
[6] 重要 新开窗口与刷新分不清：持有窗口规则，新窗口只在没有持有者时接手，转交时对旧窗口发 end。
[7] 重要 种类到通知形状：计划加对照表；壳对不认识的 id、不符的选择写诊断后忽略，重复 download 幂等。
[8] 建议 测试：要点 3、4 补全审查列出的场景。
