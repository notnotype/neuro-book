t10 计划设计审查第 1 轮（omp，壳、更新器与安装级锁）的初步处理。报告：design-review-r1-omp.txt，17 条（阻断 3、重要 14，其中一条撤回、一条收窄）。

结论：阻断的三条都成立，而且指向同一个上游选择，主会话不在现有合同内硬补，停下交开发者定方向。

- [1] helper 换上失败会自己回滚并重启旧版本，计划的“正在更新”标记（5 分钟内有效）会把这个旧版本挡掉，5 分钟内每次打开都直接退出。
- [2] 旧壳退出后它持有的安装独占锁随之释放，Electrobun 的 helper 不认这把锁；两个旧壳交错时会二次换上，或在换文件期间运行旧程序。单靠标记过期也证明不了 helper 已经结束。
- [3] Electrobun 的 download 与 apply 不接收目标版本：下载的是更新器最近一次检查的全局清单，换上的是磁盘上的已准备记录，不一定是用户同意、壳校验过的那个版本。

三条的共同根源：desktop-update Spec 输出 8 与“安装的使用与换上”术语要求“独占一直保持到新版本开始运行”“换上进行中再打开不运行旧程序”。Electrobun 2.0.6 的换上由原生 helper 在旧进程退出之后做，壳在那段时间不存在，满足这条合同只能在 helper 之外另造一套跨进程、跨版本的交接协议（门禁进程或修改 helper），而且只能在 Windows 上验证。

其余 14 条（结果分类与一次性交付、已准备记录的完整校验、便携与安装隔离、严格版本解析、计时的停止收口、关闭后的中心动作、失败哈希与比较基线、A/B/C 构建的版本输入与补丁前提、before-quit 的阶段接缝、验收证据、正式 baseUrl、下载失败时旧更新未删）都成立，按方向定下后一并改进计划。

2026-11-14 开发者选方向 A 之后的处理（计划修订，交第二轮审查）：
- [1][2] 去掉“正在更新”标记与它的过期规则；独占只管“有人在用时不发起换上”，取到后重读状态；壳退出之后由更新器的换上程序与文件占用承担（Spec 已改）。
- [3] 下载前重新检查并绑定提示里的版本与哈希，变了回到判定；检查、下载串行。
- [4] 只用 check、download、apply 的返回值判断结果，不按 onStatusChange 的事件。
- [5] 换上结果由我们自己的状态文件对账（attempt + 本地版本），取桌面锁之后才对账，待显示的结果持久化到 shown 为止。
- [6] 不读更新器的私有文件；“有没有可换的”看自己的状态文件，能不能换由 applyUpdate 自己校验。
- [7] 便携版不建、不读安装级文件；环境变量启动的安装版仍持共享锁。
- [8] 严格解析 SemVer 后再比较；补测试。
- [9] 控制器挂在运行中区间，停止时取消计时、丢掉在途结果。
- [11] 结束的提示保留目标与合法动作（download、retry、open-page）。
- [12] 失败、被取代的不算基线；只提示模式只比本地。
- [13] build.ts 加 --version，三个独立检出副本交替构建与发布，测试应用标识。
- [14] before-quit 从一开始注册，按核心阶段放行；apply 只在取锁之前。
- [15] Windows 证据加状态文件、结果文件、version.json、日志与更新源请求日志。
- [16] GitHub latest/download 的核对写进 t11 的发布后核对。
- [17] 选下载更高版本前把旧的记为被取代，旧文件即使还在也不再换上（Spec 输出 7 已改）。
