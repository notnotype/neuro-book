# w00046 t01 提案第二轮设计审查的处理结果（2026-11-13）
# 审查对象：docs/proposals/desktop-distribution.md 在 6cba91d5c 的副本；只审修订
# 报告：design-review-r2-omp.txt（omp 默认模型，8 条：重要 7、建议 1；第一轮未完全解决 3 条）
# 8 条都归“成立要改”，没有涉及开发者已定决定的。

1 同一安装目录被两个状态根使用时，换文件会动别人在用的程序（第一轮 4 未解决）：4.6 加安装级排他，换文件前确认没有别的进程在用这份安装，有就推迟。
2 关闭前询问没有页面失联的结束路径：4.3 加代次、单窗口至多一个待决询问、截止后的原生对话框（继续等待、取消、强制关闭），不把超时当同意；无产品页的窗口壳直接关。
3 applyUpdate 换完会立刻重开应用：核实属实（Electrobun 2.0.6 没有只换不开的选项）。4.6 改为下次启动时、取锁与拉起服务端之前换上，由更新器打开新版本接着启动；与开发者定的“下次启动换上”一致，用户可见行为不变。
4 开窗转交绕过版本核对（第一轮 1 未解决）：4.3 改为先问持锁壳的版本，相同才请它开窗、收到成功应答才退出，不同就提示先关掉旧版；开窗请求不带地址；对方正在停止时等它退出再自己启动。
5 两窗关闭重叠会漏掉最后一窗的任务提示：4.3 改为壳串行提交关窗，真正关最后一个存活窗口前重新判断任务。
6 同版本摘要不符一律失败误伤源码包独立发布：4.8 改为只对本次冻结的待发集合（应用、SDK、本次没发过的源码包）核对；只被打进 bundle 的已发源码包沿用现有规则。
7 旧版本续发 npm 时隐式 latest 被拒（第一轮 13 未解决）：4.8 改为逐包读 npm 当前 latest，本次更高才走 latest，否则用不推进 latest 的历史标签；读不到就停。
8 端口变化的影响写反：4.3 改写为客户端身份与按它隔离的布局、标签页会换一份（旧的仍在），主题语言以 settings.json 为准会恢复；补开发服务与桌面版并行必有一方顺延，进验收。
