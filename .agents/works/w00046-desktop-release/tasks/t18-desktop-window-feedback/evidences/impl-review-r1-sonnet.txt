### 1. 标志盒子与测量层复本“宽度相同”的不变量没有任何断言
- 严重程度：建议；测试缺口
- 位置：packages/neuro-book/src/plugins/workbench/web/components/WorkbenchTitleBar.vue 的 .workbench-titlebar__brand-box--lockup / --mark 与 .workbench-titlebar__measure-lockup / -mark；e2e/workbench-titlebar.e2e.ts 只改了文件菜单的预期
- 现象：我核对了算术，目前一致：横排标志外边距 var(--space-1) + var(--space-2) = 2 + 4 = 6px，盒子内边距 calc((s1+s2)/2) 左右各 3px = 6px；图形标志外边距 2 + 2 = 4px，盒子内边距左右各 2px = 4px。但这个相等靠两处 CSS 手写保持，没有测试把它钉住。计划切片 2 的验证写了“workbench-titlebar.e2e.ts（让位切换点不变）”，提交里没有对应的新增断言；现有“逐级让位”e2e 只查各档位只增不减、关键按钮在视口内、放宽要多 40px，差 1 到 2px 看不出来。
- 为什么是问题：有人改 --space-1/--space-2 或某一处外边距时，盒子与复本不再等宽，让位的切换点悄悄漂移（先后挤出界或多留空），而没有测试失败。另外横排标志被改成内边距左右各 3px，视觉上标志相对原来右移 1px、与项目按钮的间距少 1px，计划里没提这一点。
- 如何核实：读 diff；git show 284ece566 -- packages/neuro-book/e2e/workbench-titlebar.e2e.ts 只有一行文件菜单预期的改动；我没有跑 e2e（按要求），像素差是从 CSS 推断。
- 建议改法：在 workbench-titlebar.e2e.ts（或 Lab 场景）里加一条：命令在与不在两种状态、level 0 与 level 1 两档，各量 [data-titlebar-brand] 的 getBoundingClientRect().width，与测量层对应复本的 outer 宽度（宽加外边距）相等，容差 0.5px。想避免右移 1px 就把盒子内边距写成与复本一致的不对称值（左 var(--space-1)，右 var(--space-2)）。
### 2. 窗口按钮组宽度 120px 由三处手算保持，原来的单一来源被反转，文档仍写“只在 styles.css 写一处”
- 严重程度：建议；设计/可维护性
- 位置：packages/neuro-book/src/web/styles.css 的 --nb-window-controls-width: 120px；src/web/DesktopFrame.vue 的 .desktop-frame__button { width: 34px } 与 .desktop-frame__divider { margin-inline: 8px 9px; width: var(--border-w, 1px) }；src/web/DesktopFrame.md 布局节第一条
- 现象：旧实现里按钮宽度是 calc(var(--nb-window-controls-width) / 3)，变量是单一来源。现在 .desktop-frame__controls 没有宽度，宽度是内容撑出来的 8 + 1 + 9 + 3 × 34 = 120，变量另写 120px，只靠一句注释“宽度在 styles.css 的 --nb-window-controls-width 里算过”对账。DesktopFrame.md 仍写“宽 --nb-window-controls-width（120px，只在 styles.css 写一处）”，与实现不符。分隔线宽度取 var(--border-w, 1px)，而 --border-w 是 nb-ui 登记的主题 token（nb-ui/src/theme/tokens.ts），主题改它时按钮组宽度就不是 120。启动页 index.html 里同样的数字另抄了一份，没有变量。
- 为什么是问题：标题栏右栏的留位（WorkbenchTitleBar 的 padding-inline-end、让位算 chrome、后备标题栏的右内边距、离线横幅的 inset-inline-end）全吃这个变量；按钮组真实宽度一旦与它不同，右栏的末尾按钮会压到窗口按钮下面或多出一截空白。e2e 只断言 lastEnd <= buttons.x，这在宽度偏大（留位小于实际）时才失败，偏小时不会。
- 如何核实：读 diff；grep -rn "window-controls-width" packages/neuro-book/src；.desktop-frame__controls 没有 width 声明。
- 建议改法：在 styles.css 里定 --nb-window-button-width: 34px，--nb-window-controls-width: calc(18px + 3 * var(--nb-window-button-width))，DesktopFrame.vue 的按钮宽、分隔线边距用同一组变量，分隔线宽度写定 1px；再在 desktop-frame.e2e.ts 里断言 controls 的 boundingBox().width 等于 CSS 变量解析值。同步改 DesktopFrame.md 的说法。
### 3. 与 nb-ui IconButton“同步”的状态值现在复制在三处以上，没有任何守卫
- 严重程度：建议；设计/重复（上游选择）

- 现象：26×26、radius-button-sm、15% / 24% 的 text-main 底色、scale(0.93)、motion-fast 与 ease-layout、图标 15px（text-xs 的 1.25em）这一整套值，在 IconButton 之外又手抄了三份（产品页窗口按钮、启动页、标志按钮），注释都只写“与 IconButton 同步，那边改了这里跟着改”。启动页里还换成了写死的 120ms 与 6px。
- 为什么是问题：靠注释同步的值迟早漂移；启动页是静态 HTML，连主题 token 都没有，更不会被改 IconButton 的人看到。这是 AGENTS.md 说的“调用方要为它写补丁、同一件事各写一份”的信号：根因是 IconButton 是定边长的方块，表达不了“命中区比芯大”和“标志加芯底色”。
- 如何核实：对照 IconButton.vue 的 sizeClass / variantClass 与上面三处的 CSS；git grep "0.93"。
- 建议改法：把“上游选择”作为候选交给开发者：在 nb-ui 里给 IconButton 一个命中区外扩的变体（或抽一个 .nb-ui-chip 状态类），产品页窗口按钮与标志按钮复用；启动页因为是静态页，至少在 DesktopFrame 的 dom 或 e2e 里加一条对照：同一页里量 IconButton sm 悬停态与 .desktop-frame__chip 悬停态的计算样式相同。不做的话，把“同步”的清单写进 IconButton.md，让改它的人看得见。
### 4. 高对比度下分隔线与标志按钮的悬停反馈会消失；新增的 e2e 只查静止态的描边
- 严重程度：建议；高对比度（从代码推断，未在真浏览器里核实）
- 位置：src/web/DesktopFrame.vue 的 .desktop-frame__divider（background: var(--divider, …)）与 @media (forced-colors: active) 块；desktop/src/views/shell/index.html 的 .divider；src/plugins/workbench/web/components/WorkbenchTitleBar.vue 的 .workbench-titlebar__brand-button:hover/:active；e2e/desktop-frame.e2e.ts 新增的“高对比度模式下……”用例
- 现象：forced-colors 下作者写的非系统色 background-color 会被强制成 Canvas。分隔线只靠 background-color 画，会整条看不见（标题栏里原有的短分隔也有同样问题，但那是旧的）；标志按钮悬停与按下只改背景色，高对比度下没有任何反馈，窗口按钮的芯却明确写了 Highlight。e2e 用例只在静止态量三个 svg 的 stroke 不等于 body 背景，没有量悬停态，也没有量分隔线。
- 为什么是问题：这次的目标之一就是“高对比度下仍看得见”，Spec browser-host 输出 12 也写了这句；分隔线的消失虽然不影响功能，但标志按钮悬停无反馈会让键盘外的用户不知道它可点。
- 如何核实：读 CSS；forced-colors 对 background-color 的强制规则见 CSS Color Adjust；没有跑浏览器。
- 建议改法：分隔线与标志按钮在 forced-colors 块里改用 border-inline-start: 1px solid ButtonText 或 CanvasText 的 outline，标志按钮悬停写 background: Highlight、color: HighlightText（标志是 svg，要确认它的墨色在高对比度下跟随 color）；e2e 里补一条悬停态与分隔线可见的断言。

### 7. commandTitle 只看“命令在不在”，不看可用性；计划写的是“在不在、可不可用”
- 严重程度：建议；设计/与计划不一致
