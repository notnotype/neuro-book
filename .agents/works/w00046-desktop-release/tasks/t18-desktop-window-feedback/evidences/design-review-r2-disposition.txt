w00046 t18 设计审查第 2 轮的处理（2026-11-16）。审查对象：plan.md r2 的“最小尺寸”一片。原定 omp（默认模型），一启动就撞上
Codex 的额度上限（429 usage_limit_reached），按规矩不逐家试，改派 Claude Opus。Opus 9 条：阻断 0、重要 3、建议 6；原文 design-review-r2-opus.txt。
处理后计划改为 r3。

1. 重要，初始尺寸拿外框和客户区最小值比、对话框也走 centered()：成立。r3：centered 加可选的外框下限（最小客户区 + 按有没有系统标题栏取的外框估计），
   只有产品窗口与启动页传，对话框不受影响；单元测试含工作区 1093×582 与对话框。
2. 重要，换过程失败的分支：成立。r3 写死安装序列：窗口已关直接返回；“已装好”看当前过程是不是我们的；属性写失败删掉再报；
   SetWindowLongPtrW 返回 0 时读回判断；旧过程不符时只用非 0 的旧过程换回、删属性、报问题。
3. 重要，运行时编译在用户机器上的前提：成立，并实测坐实一半。探针第 5 条：路径里有中文时 TinyCC 找不到源文件。探针第 6、7 条：
   改交相对当前目录的路径可行（壳的当前目录是安装里的 app\bin，与源文件同一棵树）；C 里不链接库、函数地址由 JS 经 GetProcAddress 交给它可行，
   干净机器上不依赖 TinyCC 找 user32。C 不写 #include。构建时交叉编译小 DLL 的候选没采用：本机与 CI 都没有 Windows 交叉编译链（没有 lld、zig、mingw），
   要加工具链与一个要签名的二进制；上面两点消掉了它要解决的前提。
4. 建议，最小化时外框差不可信：成立。r3 最大化与最小化时都不改，验收加最小化。
5. 建议，工作区比最小值小时最小跟踪尺寸大过工作区：成立。r3 在 C 里夹到窗口所在显示器的工作区；Spec 写“不超过工作区”。
6. 建议，缓存 cc 返回的对象、永不 close、失败也缓存：成立，照写，注释写明释放即崩。
7. 建议，取不到原过程时兜底：成立。为空时交 DefWindowProcW。
8. 建议，DPI 换算没有测试：成立。换算写成纯函数，用 NB_MIN_SIZE_PURE 只编它，在 Linux 上经 cc 跑单元测试；验收脚本用 SendMessageTimeoutW。
9. 建议，win32.ts 文件头的“一律不等待”与 GWL_STYLE 的同步消息不符：成立。r3 如实改写文件头，不改调用方式（只在窗口刚创建时调用）。
