## 发现 1（重要，不变量/键盘可达）展开后展开收起按钮 tabindex 留在 -1，Tab 进不了
位置：packages/neuro-book/src/plugins/workbench/web/components/WorkbenchToolStrip.vue 的 railItems/syncTabStops（约 248-275 行）与 MutationObserver（约 290 行，只看 childList）；packages/nb-agent-ui/src/vue/messages/AgentMessagesSegment.vue 模板里 toggle 的 `:data-rail-item="props.expanded ? undefined : ''"`。
现象：收着时按钮带 data-rail-item，侧轨的 syncTabStops 给它写 tabindex（按下的入口是 Tab 停靠点时，按钮是 "-1"）。展开时视图把 data-rail-item 摘掉，按钮不再是 railItems，syncTabStops 从此不碰它，先前写的 tabindex="-1" 留在元素上；展开时它是列表区里的普通按钮，计划要求“Tab 可达”，实际 Tab 跳过它，键盘用户展开后无法 Tab 到收起按钮。
为什么是问题：计划“展开时它不带，是列表区里的普通按钮，Tab 可达”；Spec 输出 50“焦点与读屏”。dom 测试 WorkbenchToolStrip.dom.test.ts 的“焦点交接”用例用的是手写的 `data-rail-toggle` 空按钮，没有 `data-rail-item` 的摘取，也没断言 tabindex，所以没拦住。
如何核实（真实组件）：在 /tmp/review-w00043-t20-impl2/probe/tabstop.dom.test.ts 里挂真实 WorkbenchToolStrip + 真实 AgentMessages（rail 位置、两者 expanded 同步翻 true）。结果：收着时 toggle 的 data-rail-item 在、tabindex="-1"（按下的入口 a 是停靠点）；展开后 data-rail-item 摘掉、tabindex 仍是 "-1"。运行：cd packages/neuro-book && npx vitest run --config /tmp/review-w00043-t20-impl2/probe/vitest.probe.config.mts <测试文件>，输出写在 probe/out.txt。
建议改法：二选一。(a) 视图段在 toggle 上展开时显式 `:tabindex="props.expanded ? 0 : undefined"`（收着时交回侧轨管；但从 -1 回到收着时 Vue 会把没有 tabindex 的属性摘掉，侧轨要靠 childList 重排，收起时 strip 换回会触发）；(b) 更稳：侧轨 syncTabStops 之外，对“曾经是 railItem、现在不是”的元素清掉 tabindex（记一个 Set），或让 MutationObserver 也看 `attributeFilter: ["data-rail-item"]`（只过滤这一个属性，不会因自己写 tabindex 而循环）并在重排里对失去标记的元素 removeAttribute("tabindex")。补一条 dom 用例：真实视图段展开后 toggle 的 tabindex 不是 "-1"。

## 发现 2（建议，性能/合同）placement 带上 width 后，拖轨宽与窗口缩放每帧让整个视图重渲染
位置：packages/neuro-book/src/plugins/workbench/web/components/WorkbenchShell.vue:216-217（watchEffect 里 `width: rail.width`）；packages/neuro-book/src/plugins/agent/web/MessagesHost.vue:65-70（ownHeadStyle 依赖整个 `placement.value`）、86-90；AgentMessagesSegment.vue:262 `listStyle`。
现象（从代码推断，未跑 layout-frames）：以前 rail 位置只在元素换了时才换引用；现在 `width`、`tooNarrow` 进了 placement，拖轨宽手柄、窗口缩放时 `rail.width` 每帧变，watchEffect 每帧写一个新 placement 对象（samePlacement 比 width 不同，放行）。链上：MessagesHost 的 `placement` computed 对 rail 直接返回 `current`（新引用）-> ownHeadStyle 重算并返回新对象（三个自定义属性每帧 setProperty 同值）-> AgentMessages 与 AgentMessagesSegment 每帧重渲染（slot 函数、列表 props 全部重新求值）-> `listStyle` 每帧写一次 width。float 窗的 edge 早已如此，但停靠右轨的拖宽是新增的每帧路径。AgentMessages.vue 的 `targets` 保持引用做对了，焦点与滚动放回不会触发；问题只在多余的重渲染。

如何核实：`bun run perf:layout-frames`（或脚本里拖右轨手柄的场景）对比 c41ff201e 与 7263ba27d 的每帧 DOM 写入与脚本时间。

## 发现 3（建议，不变量）连点与命令发起的展开收起：上一次的位移动画没取消；起点只靠 1 秒 TTL 判过期
位置：AgentMessagesSegment.vue:225-230（watch(expanded) 里 `return` 先于 `cancelMoves()`）、169（ORIGIN_TTL）、166 的注释。
现象：(1) `cancelMoves()` 排在三个提前 return 之后：`origins === null`（经命令、别处发起，规范允许“直接换”）、方向对不上、超 TTL、时长为 0 时都不取消。点按钮开始展开（toggle 与导航在位移中），1/3 的时候用命令（例如 nbook 的命令收起）收起，`start` 是 null，直接 return：toggle 上还在跑的 translate 动画不取消，元素换了位置后带着旧的偏移继续滑完，视觉上先跳再滑。(2) 起点失效只靠 1 秒 TTL：宿主拒绝（窗口太窄）时 expanded 不变，`origins` 留着 1 秒；这 1 秒内别处发起的一次成功展开（命令、窗口刚好变宽后点另一个入口等）会拿旧矩形做起点，toggle 与底段按钮从点击拒绝那一刻的位置滑过来。记录和宿主结果之间没有直接的联系。
为什么是问题：计划“连点时取消上一次动画”只在有起点的路径成立；TTL 是时间启发式，而宿主的结果（done、too-narrow、revoked）在 `MessagesHost.requestRail` 里是明确知道的。

建议改法：把 `cancelMoves()` 挪到 watch 回调的最前面（只要 expanded 变了就取消在途动画，再决定要不要做新的）；起点失效改成明确事件：视图段在 `tooNarrow` 变 true 时（props.tooNarrow watch）清 `origins`，TTL 可以留作兜底但不再承担这件事。

## 发现 4（建议，正确性/视觉；从代码推断，未在真实页面慢放）离场元素按 left 锚定，右轨朝左长，淡出的那一半会漂或被裁掉

现象：(1) 展开：收着的 strip 在窄列右侧（右轨，右缘贴窗口），before-leave 时量到 offsetLeft 约 0（main 当时还是 48 宽），之后 main 随轨宽朝左长，绝对定位的 strip 钉在 main 的左缘，于是淡出的这 120ms 里窄列图标从右缘滑/跳到卡片最左边再消失；设计是“右缘不动”。(2) 收起：状态一翻成 collapsed，侧轨的 `max-width: 48px` 立刻把 main 所在的 `.workbench-tool-strip__segment` 压成 48 宽（贴右、overflow-x hidden），此时离场的列表还是 `left:0; width:300px`，被裁成最左边 48px 一条（不是靠右那条）淡出，所以“列表淡出”几乎看不到完整的列表，是一片被切掉的左缘。展开时列表是靠右的（`flex-end`），收起时的残影却靠左，两个方向不对称。

- 同一个按钮两种位置：toggle 始终是 main 的第一个子元素、同一个 DOM 节点，收着/展开只换类与属性；浮动窗（Teleport disabled）里同样；dom 用例“同一个元素”已覆盖。视图段自己的焦点交接与侧轨的交接都落在 toggle 上，幂等，不互相打架（strip 的 nextTick 在 post 之后才读 activeElement）。
- `AgentMessages.vue` 的 `targets` 保持引用（computed 取 previous）做对了：拖轨宽每帧写 placement 不会触发 watch(targets) 的焦点与滚动放回。`samePlacement` 逻辑正确（none 分支、window/rail 分支、width 与 tooNarrow 比较）。
- `moving` 计数簿：after-leave 与 leave-cancelled 互斥、`_leaveCb` 强制完成走 afterLeave，连点、卸载（onBeforeUnmount 取消）都不漏减；减少动态效果时 holdInPlace 与 FLIP 两条都按令牌 0 不写 data-messages-moving。令牌用 `calc()` 写成时 motionMs 返回 0 会静默关掉过渡，目前 tokens.css 是字面量，不算问题。
- 列表页延后淡入的 `opening`：只在刚展开时为真；切页时在窗口内重放一次后清掉，切页在 animationend 之后不重放；动画被 display:none 取消时 opening 暂留，下一次 animationend 清，不会卡住。
- 会话面板过滤菜单：scope 为 null 时没有范围一组与多余分隔线；“全部作品”计入条数；清除回到当前作品；选中已选的单选项不发事件。`--acv-list-inset-end` 只在 `.acv-segment__list` 上声明，会话面板在下拉与左栏等别的宿主里读到缺省 0。
- 拖动的轴：layout-drag 读 `data-tool-band-axis`，`entriesIn`、`groupEnd` 按轴取；band 隐藏（单容器）时 `rectOf` 返回 null 被跳过；轨宽手柄的方向键 `stopPropagation`，不会与横排的左右键冲突。
- 旧 key 清理：shell.rail.expand/collapse/tooNarrow 在两份 JSON 与 locales.test 里一起删了，源码里没有残留引用（e2e 里的 `data-rail-expand` 属于迁移范围）。
