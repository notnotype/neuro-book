# t16 计划草稿 1 的设计审查：处理

审查：omp（默认模型），2026-11-22，[报告](design-review-omp.txt)，有效 17 条（阻断 4、重要 11、建议 2，第 7 条审查者自己撤回）。修订后的计划是 [plan.md](../plan.md) 草稿 2。

| 条 | 归类 | 处理 |
|---|---|---|
| 1 发布写失败不等于没发布（rename 之后目录同步失败、索引后写） | 成立 | 不改存储层，草稿 2 改成内核识别只有会话头的日志并补完（关键设计 4），“建会话时日志就在”的前提不变 |
| 2 `changeProfile` 在损坏句柄上卸载、重装扩展 | 成立，要改 | 收尾分两类：`committed`（受理批写下就做，只放叫醒等待者）与 `written`/`launch`/`after`（反应都写下才做）；补 `changeProfile` 一例 |
| 3 建会话在 `try` 之外抛错漏放锁 | 成立，要改（原有缺陷） | 失败收口从拿到存储句柄那一行开始；补“宿主资源抛错之后同 id 能再建” |
| 4 状态仍会被 `abort` 与阶段帧盖掉 | 成立，要改 | 状态只经一个入口发布，损坏后只接受 `broken`；`abort` 加损坏门 |
| 5 同一次 `waitRun` 两种结果 | 部分成立 | 损坏时已登记的 `waitRun` 先查日志里有没有这次的 `runEnded`；回退后复用 run id 那一半记已知限制 |
| 6 跨进程“没发布但 id 已占用” | 不再适用 | 存储层不改，不存在未发布状态 |
| 8 未发布目录可写附件 | 不再适用 | 同上 |
| 9 旧 fork 被打开过之后重发也报成功 | 成立，要改 | 补写判断改成按第一条事件对上来源、目标被开着时交回失败 |
| 10 未发布句柄的 append 与 close 竞态 | 不再适用 | 同 6 |
| 11 只读恢复的验收只看两条结算 | 成立，要改 | 验收补：工具结果、就绪的话转留着、门、异步提问保留、再开不重复、`rewind` 造的真暂停作反例、恢复批写失败 |
| 12 缺依赖的占位装配补上依赖后解除只读 | 成立，范围外 | 原有缺陷，与本 Task 的恢复无关；写进 runtime.md 已知限制、另建跟进 |
| 13 延迟序列化让会话头可变 | 不再适用 | 同 6 |
| 14 崩溃夹具的门闩不在新发布点 | 不再适用（部分） | 第 4 处不再有新发布点；只读恢复用现成的 `crash-session.ts` 夹具 |
| 15 损坏会话上撤回扩展不摘下 | 成立，要改 | 损坏时撤回照样摘下扩展、等清理完再放行，不写装配事件 |
| 16 只读重开后已提交的 `resolve` 重放被挡 | 成立，要改 | 只读门挪进 `resolve` 的判定，重放先于只读检查 |
| 17 首批完整不等于初始化做完 | 成立，接受取舍 | 承诺只到会话头与第一批，建会话的反应写成已知限制 |
| 18 验收证明不了坏句柄不开运行 | 成立，要改 | 加“空闲时回答异步提问、反应批失败、模型没收到新请求”一例；同步两例按 `ctx.ask` 的真实返回与日志分别断言 |

开发者定的三条行为（决定 1）不变；“以前留下的只有会话头的日志不迁移”在新方案里不需要了：旧日志走同一条补完路径。
