### 1. 公开状态 `nbook.agent/active` 被加进“有未读”，皮肤的“工作中场景”会在没人干活时一直亮着
- 严重程度：重要
- 类别：正确性 / 违反公开合同
- 位置：packages/neuro-book/src/plugins/agent/web/plugin.ts:808（`bindingsOf(agentState, {active: computed(() => activity.active.value || unreadTotal.value > 0)})`）；读取方 packages/neuro-book/src/plugins/workbench/web/plugin.ts:167-171（`agentWorking`）
- 现象：为了让状态栏条目在“只有 bot 新消息”时也显示（条目的 `when` 是 `nbook.agent/active`），作者把公开状态本身改成“有会话在跑或等用户，或者联系人有未读”。
- 为什么是问题：`nbook.agent/active` 是公开合同（conversation.md 输出 39、188），含义写在 theme/skins.md 输出 17：“Agent 工作中（有会话在运行或等用户处理）”，工作台据此换 `workingScene`。现在只要任一 bot 有一条未读，active 就为 true，皮肤一直停在“工作中”场景，直到用户把消息看掉；这与“状态栏‘Agent：1 运行中’的同一个信号”的定义不符。第三方插件也可能按这个键写 `when`。Spec 与测试都没有把这个键的含义改成含未读（grep docs/specs 只有上面三处）。
- 如何核实：读 plugin.ts:808 与 workbench/web/plugin.ts:167；让一个 bot 有未读、无会话在跑，`stateService.read("nbook.agent/active")` 为 true，`agentWorking()` 为 true。从代码推断，未跑。
- 建议改法：保持 `active` 的原义；状态栏条目的显隐另走（例如新增一个公开状态键 `nbook.agent/attention`，或让条目的 `when` 改成 `any` 两个键；若 `when` 不支持，就为条目单独发一个状态键）。同时给 e2e “窗口失焦的未读”那条加一个断言：未读时 `workingScene` 不生效，或至少对 `active` 键的单测。

### 2. 聊天区的盖层（没有模型、正在打开、打开失败）只在自己的点击里清除，宿主被别处打开会话时盖层不撤
- 严重程度：重要
- 类别：正确性 / 共享状态
- 位置：packages/neuro-book/src/plugins/agent/web/messages-model.ts:100-125（`openContact`）、`sessionOpened`（只被头像列和会话页的点击调用）；packages/neuro-book/src/plugins/agent/web/MessagesHost.vue 模板里的 `v-if="pending !== null || pickBot"` 盖层
- 现象：`pending` 只有 `openContact` 成功、`sessionOpened()` 两处清零。宿主的当前会话被别的路径换掉（状态栏“N 条新消息”或“等你处理”触发的 `focus-session`、请求页/子代理卡片的 `focus-session`、命令“新建 Agent 会话”走 `host.create`）时，`pending` 仍在：聊天区被“打不开和星璃的对话（code）/先添加一个模型服务商”盖住，`selected` 还高亮着那个联系人，`watchSeen` 因 `pending !== null` 一直不交“看到”。
- 为什么是问题：盖层与宿主真实状态脱钩。典型路径：没配模型时点联系人出现“去添加”盖层，用户再点状态栏的“1 条新消息”或新建会话，聊天区仍是盖层；点开失败的盖层后用状态栏跳转同理。未读也永远清不掉（`watchSeen` 被盖层挡住）。
- 如何核实：我在 scratch 里用真实的 `createMessagesModel` 与响应式替身宿主复现：`openContact` 失败后令 `host.sessionId` 变成 "other"，`pending` 仍是 `{step:"failed"}`，`selected` 仍是该联系人（/tmp/w43-t15-r2/scratch/pending.test.ts，bun test 通过）。真实宿主走的是同一个 `sessionId`/`open` 接口，从代码看路径一致；e2e 里没有任何用例经过这些盖层（grep `data-messages-cover|open-failed|add-provider` 在 e2e 与测试里零命中）。
- 建议改法：盖层只在“宿主的 `sessionId` 还是点联系人时那一个”时有效：在模型里 `watch(host.sessionId)`，不是自己 `host.open` 引起的变化就清 `pending`（或把 `pending` 存下点击时的 `sessionId`，渲染时比对）。补一个模型单测：打开失败后宿主换会话，盖层撤掉。

### 3. 窄版标题的 `aria-haspopup/aria-expanded`（`titlePopup`）只在抽屉开关时写，换版式时不跟着改
- 严重程度：重要
- 类别：正确性 / 可访问性
- 位置：packages/neuro-book/src/plugins/agent/web/MessagesHost.vue:80-86
- 现象：`watch(drawerOpen, (open) => { head.titlePopup.value = layout.value === "narrow" ? {expanded: open} : null }, {immediate: true})` 只监听 `drawerOpen`，不监听 `layout`。`layout` 初值取 `props.memory.layout`（视图重挂、换代时是上次的值）：记忆是 wide 时挂上，`immediate` 写成 null；随后量到窄版，`layout` 变 narrow、`claim` 变 true，面板头改由视图接管标题，但 `titlePopup` 仍是 null，直到用户第一次开关抽屉才补上。反方向（窄→宽）则把 `{expanded:false}` 留在宽版里，虽然 `claim=false` 时外壳不读它，再变回窄版时是旧值。
- 为什么是问题：views.md 输出 19 与 conversation.md 输出 44 要求标题按钮写 `aria-haspopup`、`aria-expanded` 并开抽屉；此处在“记忆为 wide 的重挂 → 缩到窄版”这条路径上标题按钮没有弹出语义，读屏用户不知道它开抽屉。agent-conversation e2e 只走“默认窄版挂上”的路径，覆盖不到。
- 如何核实：读代码即可确定；要复现：先把右栏拖宽到 600 以上再让视图换代重挂（或刷新），再缩到窄版，看标题按钮没有 `aria-expanded`。我没跑 e2e。
- 建议改法：把来源改成 `watch([drawerOpen, layout], …, {immediate: true})`；同时补一个 MessagesHost 的 dom 测试（见第 12 条）。

### 4. 在抽屉里用键盘选一项后抽屉关闭，焦点落在已隐藏的行上（掉到 body），没有回到开它的按钮
- 严重程度：重要
- 类别：可访问性 / 与 Spec 不符
- 位置：packages/nb-agent-ui/src/vue/messages/AgentMessages.vue:71-74（`openContact` 调 `closeDrawer(false)`）；packages/neuro-book/src/plugins/agent/web/MessagesHost.vue:98-105（`openSession`、`onSessionOpened` 直接 `drawerOpen.value = false`）
- 现象：conversation.md 输出 2 写“点视图里抽屉外、`Esc`、选了一项都关，焦点回到开它的按钮”，AgentMessages.md 写“关闭后焦点回到开它的按钮”。实现里只有 `Esc` 走 `closeDrawer(true)`；选联系人传 `false`，选会话（会话面板的 `opened`）与头像列里点最近会话完全不碰焦点。抽屉用 `v-show` 收起，焦点所在的行成了 `display:none`，浏览器把焦点丢回 body；用键盘开抽屉、方向到某行回车的人，之后要从页面开头重新 Tab。
- 如何核实：dom 测试“抽屉：点视图里的聊天区关…点了联系人关”只断言 `drawerOpen` 为 false，没断言 `document.activeElement`；加上断言会失败。
- 建议改法：选中项触发的关闭也走 `closeDrawer(true)`（点击触发的关闭，焦点本来在被点的行上，回到开它的按钮同样合理）；MessagesHost 的 `openSession`/`onSessionOpened` 不要自己写 `drawerOpen`，改成发给 AgentMessages 关（或暴露一个 `close(restoreFocus)`）。顺带：宽版里收起/展开列表栏（`update:listCollapsed`）也有同样的焦点丢失——被点的按钮随 `v-show` 隐藏（dom 测试“宽版收起列表栏”没看焦点），收起后应把焦点放到头像列顶上的展开按钮，展开后放到收起按钮。

### 5. 点已经打开着的联系人会把整个主对话重新打开（全屏“正在打开”盖层、重新订阅与加载）
- 严重程度：建议
- 类别：正确性 / 体验
- 位置：packages/neuro-book/src/plugins/agent/web/messages-model.ts:100-125；packages/neuro-book/src/plugins/agent/web/session-host.ts:1021-1070（`openHere` 没有“已经是这个会话”的短路）
- 现象：`openContact` 不看 `host.sessionId`。点当前选中的联系人（宽版列表栏里的选中行、窄版头像列里的当前头像，用户手滑或想“回到聊天”都会点）：先写 `pending={step:"opening"}`（盖层 + 转圈），`provider.open` 走一次 `ensureMain` RPC，再 `host.open(同一个 id)`，`openHere` 会 `closeCurrent()`、重新订阅、重取快照与路径，聊天区先闪成“加载中”，`shownSeq` 归 0，滚动位置丢失。
- 为什么是问题：一次无意义的全量重载；运行中的 bot 会话重载期间也会让“看到”短暂停发。
- 如何核实：读代码；`openHere` 里 `generation += 1; closeCurrent();` 无条件执行。
- 建议改法：`openContact` 开头判断 `host.sessionId.value === found.sessionId`（联系人里已有 `sessionId`）且 `host.owner` 对得上时，只清 `pending`、必要时关抽屉，不调 `provider.open`/`host.open`。

### 6. 读会话头失败写 `failed` 时不看已有的失败码，谁后到谁覆盖；恢复“最近的会话”据此决定要不要清记录，结果取决于两个请求的先后
- 严重程度：建议
- 类别：正确性（竞态）
- 位置：packages/neuro-book/src/plugins/agent/web/session-host.ts:1045-1053（`owners.ownerOf(id).then`）与 1100-1116（快照失败写 `target.failed`）、1165-1185（`restore` 的 `failureCode() !== "header-unreadable"`）
- 现象：会话头请求和订阅/快照/路径是并行的，两边失败都直接 `target.failed = {code}`，没有“已有失败就不覆盖”的判断。
  - 会话已被删除（最近的会话里那条不在了）：头读不到记 header-unreadable，快照也失败记 not-found 一类的码。头请求先回来时最终是快照的码，`restore` 清掉记录，行为同以前；头请求晚回来时最终是 header-unreadable，`restore` 保留记录——每次打开窗口都停在“打不开（header-unreadable）”加重试，而那个会话再也读不到，用户只能手动换会话；
  - 服务端重启期间两个请求都失败时同理，结果看谁后到。
- 为什么是问题：Spec（conversation.md 输出 52）要求的是“读不到会话头 ≠ 不在了，恢复时不清记录”，实现的判定依据是“最终的 failed 码”，不是“头读不读得到”，所以与请求完成顺序有关；错误提示里的码也不稳定。
- 如何核实：从代码推断。session-host.test.ts 的“读不到会话头”用例用 `failing` 集合让头读失败而快照成功，没有覆盖“头与快照都失败”的顺序；加一个让头请求晚于快照失败的用例即可复现。
- 建议改法：给 `Current` 记一个 `headerUnreadable: boolean`，`restore` 看它而不是 `failed.code`；`failed` 写入只在 `target.failed === null` 时才用 header-unreadable，快照失败等更具体的码优先。

### 7. 消息列表的“bot / 会话”标签是手写的 `role="tab"` 原生按钮，没有 roving tabindex、方向键，也没有 `aria-controls`，没用 nb-ui 的 `Tabs`
