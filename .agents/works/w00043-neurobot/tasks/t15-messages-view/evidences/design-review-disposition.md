# t15 阶段 ① 设计审查的处理（2026-11-19）

审查对象：计划草稿 1。前端、服务端分开，各一个 Claude Sonnet（服务端改动小、不碰并发与跨进程，按任务大小降级，没开 omp）。报告：[前端 13 条](design-review-front-sonnet.txt)（重要 10、建议 3），[服务端 10 条](design-review-back-sonnet.txt)（重要 6、建议 4），没有阻断。修订写在计划的“设计审查的修订”一节。

| 条 | 归类 | 处理 |
|---|---|---|
| 前端 1 转交放在 `open(id)` 里太晚，浏览器没有读会话头的方法 | 成立，改 | 远程合同加只读 `header`；转交提到打开会话的唯一入口，先读会话头再决定揭示哪个视图 |
| 前端 2 转交的竞态、恢复到有归属的会话 | 成立，改 | 每次打开记号，晚到的作废；`restore()` 不打开有归属的会话 |
| 前端 3 运行中插话走 `enqueue`、不带结算；重发丢字段 | 成立，改 | 固定模式一律 `send` 带 `mode` 与 `settlePending`；重发带上两项 |
| 前端 4 “发出会拒绝 N 项”与向导作废没列 | 成立，改 | 照提案第四节第 7 小节补上，N 不含异步与后代的事项 |
| 前端 5 没有模型时也建了主对话 | 成立，改 | bot 视图先看模型，没有就引导卡、不调 `ensureMain` |
| 前端 6 固定宿主的接口前后矛盾 | 成立，改 | 组件只收已取得的会话 id；取会话、失败、重试在 bot 视图里 |
| 前端 7 隐式建会话的路径没守全 | 成立，改 | 守在 `create()` 与 `open()` 两个窄点 |
| 前端 8 岗位 Profile 有模式扩展、模式选择器却不显示 | 成立，改 | 按 Profile 的工具集有没有 `switch-mode` 判断 |
| 前端 9 “看到”的可见信号、计数与视图实例的寿命 | 成立，改 | 视图可见信号加窗口焦点；入口启动即订阅 `botsChanged` 给 `badge()` |
| 前端 10 文案覆盖没有机制 | 成立，接受取舍 | 阶段 ① 只有压缩失败那一句带“开一个新会话”，照旧显示；阶段 ④ 再定 |
| 前端 11 组件工厂每次新类型、`identity` 定死、转交丢 `owner.id` | 成立，改 | 静态组件加属性；转交带 `owner` |
| 前端 12 停靠区答完焦点掉到 body、“本会话都批准”不传播 | 成立，改 | 照向导的现有规则 |
| 前端 13 转交测不到 | 成立，改 | 新 e2e 从状态栏活动条目点到主对话 |
| 服务端 1 “助手消息”没定义 | 成立，改 | 计数消息是不带工具调用的 `assistant` 事件，共用一个判定函数 |
| 服务端 2 只存个数时 `through` 落后算不对 | 成立，改 | 内存里留 seq 列表，只存“看到”的 seq |
| 服务端 3 订阅与补数的先后 | 成立，改 | 先订阅攒帧、再补数、按 seq 去重 |
| 服务端 4 `through` 没有上界；`latestSeq` 用 head 会频繁推送 | 成立，改 | 截到最新计数消息；`latestSeq` 是最新计数消息的 seq |
| 服务端 5 头像路由的安全 | 成立，改 | 照取图路由：记录为准、逐段 `lstat`、按字节判类型、安全头、ETag |
| 服务端 6 记录读不懂、存储打不开、补数前的状态 | 成立，改 | `unread` 可为 null；`markSeen` 有失败码；读不懂时 `reset` |
| 服务端 7 补数拖住 `ensureMain` | 成立，改 | 持有之后另起 |
| 服务端 8 订阅的取消与持有分开管 | 成立，改 | 放在一起 |
| 服务端 9 缺 `seenSeq`、最后一句话；按 seq 与提案的“按时间”不同 | 成立，改 | 加 `seenSeq`；最后一句话在阶段 ②；提案补决策记录 |
| 服务端 10 视图用 `latestSeq` 标看到会越过没画出的消息 | 成立，改 | 用组件已画出的最后一条计数消息的 seq |
