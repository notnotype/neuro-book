# t15 阶段 ④ 计划草稿 1 的设计审查：处理

审查：Claude Sonnet，2026-11-22，报告 [design-review-6-sonnet.txt](design-review-6-sonnet.txt)，9 条（阻断 2、重要 3、建议 4）。修订后的计划是 [plan-4.md](../plan-4.md) 草稿 2。

| 条 | 归类 | 处理 |
|---|---|---|
| 1 消息到日志 seq 在应用的适配器里不存在 | 成立，要改 | 核实：`createKernelTranscript` 的消息 id 取事件 `id`，`logSeqOf` 只对旧适配器有效。适配器加 `countedSeq(messageId)`，按事件类型（`assistant` 且不带工具调用）标，与后端 `countsAsMessage` 同口径；单测补半截文字、补的空回复、被改成停止的 |
| 2 基线只拍一次会让看着时到的回复也画线，计划前后矛盾 | 成立，要改 | 核实：草稿 1 每次按基线重算，看着时到的回复 seq 也大于基线。改成锁存：基线拍到、第一页路径读完后算一次，之后不再算。这正是决定 9 第 4 条开发者同意的行为（失焦期间来的回来后不画线），草稿 1 的算法与那句说明不一致，算法错了；e2e 重排成三条（切走时到的有线、看着时到的没有、书房面板重开后看过的线没了） |
| 3 文案变体在视图里没有统一的翻译拦截点，“退回内置”做不到 | 成立，要改 | 改在源头：适配器加 `pinned` 选项，压缩失败的系统条目与运行出错两处都出固定会话的键；删掉“退回内置”。归属读到之前就压缩失败时是普通档那句，记为已知限制 |
| 4 重拍的情形漏了重试，`reattach` 依赖 30 秒释放定时器 | 成立，要改 | 重试与 `reattach` 都沿用这次的线；“这次打开”只算宿主打开另一个会话与书房面板打开（`markOpened`）。这改了决定 9 第 4 条里“视图收起再展开会重拍”那半句：它原本取决于收起是否满 30 秒，结果不稳定，交付时向开发者说明 |
| 5 基线的读取机制没写，惰性读会读到已前进的值 | 成立，要改 | 写明 `watch(..., {flush: "sync"})` 拍到就停；验收加“`seenSeq` 前进的第二次推送不改基线”；补数失败时拍不到、角标也空，写进 Spec |
| 6 主动发来的回复落在很早的一轮里，线离得远 | 部分成立，接受取舍 | 日程以宿主身份发的话是用户消息、自成一轮（提案第 11 小节），不会并进上一轮；宿主提醒是系统条目，会留在上一轮。轮可能跨几天、按天的线只在轮前，记为已知限制，不拆进轮内 |
| 7 首屏指标的口径 | 成立，要改（部分） | 起点、终点都可见且期间没隐藏才记；加 `position`、`reattach` 字段；写明不含 `ensureMain`；`plugin.ts` 不引入 DOM 实现。“视图可见与没有盖层”不另判：盖层只在还没开会话（等模型、正在取、取失败）或找不到 bot 时出现，那时不走 `openHere` 的计时；`pages` 字段不加，`events` 与 `messages` 已能分开读得慢与画得慢的大概 |
| 8 日期线与组件的几处坑 | 成立，要改 | 全部落进计划：导出 `localDayIndex`；晚于 `now` 写今天；跳过 `timestamp` 为 0 的消息；`<template v-for :key>`；线是内容列的直接子元素；样式复制一份；属性用 `data-day-divider`、`data-unread-divider`；分页只在 Lab 与 dom 测试走得到 |
| 9 验收映射里写不出或会空过的 | 成立，要改 | e2e 加“看着时到的回复没有线”；不用等 30 秒的路径（切会话、书房面板 `markOpened`）；首屏指标 e2e 读不到诊断，不覆盖，只靠单测；未读线的单测走真实的 `createKernelTranscript` |

补上哪条依据能避免这次误判：草稿 1 的“适配器给日志合成的消息 id 是 `h<seq>`”是按 `harness.ts` 推断的，没有核对应用实际用哪个适配器。写计划时依赖的映射要追到调用点，不按同包里找到的第一个函数认。
