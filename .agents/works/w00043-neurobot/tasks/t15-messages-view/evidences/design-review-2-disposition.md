## 第二轮

审查者同上，对象是 plan-2 草稿 2，报告 [design-review-3-sonnet.txt](design-review-3-sonnet.txt)：重要 8、建议 6，审查者自己收窄了第 10、12 条各一处。全部成立；第 11 条（右栏收起时没有未读指示）交开发者，答复记为 t15 决定 7。改后的计划是草稿 3。

| 条目 | 处理（plan-2 草稿 3） |
|---|---|
| 1 “不建 current”与“记成打开失败”矛盾 | 照旧立刻建 `current`，`owner` 三态（未读到时是加载中、取最严一档）；读头失败 `header-unreadable` 走现有重试，`restore` 遇到它保留记录 |
| 2 点联系人到聊天出现之间没人持有状态 | 消息视图的选择（`no-model`、`opening`、`failed`、`ready`）与盖层；宿主加只读 `owner` 与 `close()` |
| 3 静态属性只搬了三个 | `canCreate` 为假时不画新建与第一屏；身份直接写进 `session.title`、`avatar`，不加 `identity`；第 3 片逐个对照两个宿主组件的属性 |
| 4 同插件多条贡献与“取最小那条”矛盾 | 每插件至多一条，接收器拒第二条并记诊断 |
| 5 提供者缺席时的孤儿、页面宿主 | 缺席时照样 bot 档、身份回落；编辑区页面遇到有归属的会话改走 `focus-session` |
| 6 `focus-session` 对 bot 的子会话、祖先根的身份 | 归属表提到插件级；按会话树的根判断；`AncestorItem` 加可选 `owner`（进第 2 片） |
| 7 `claim` 要并进 `headOfPanel` | 写明三处一起改、宽版点标题照常折叠；视图在 `setup` 同步写初值 |
| 8 抽屉的几处交互互相打架 | 点外面不算标题按钮与传送的浮层；`Esc` 只在抽屉内或触发按钮上、不管 `defaultPrevented`；内容常驻；焦点与读屏写明 |
| 9 服务端 `list` 已经不列有归属的树 | 删客户端过滤；刷新收进 store 按引用计数共用一个定时器；去掉按活动重取 |
| 10 `last` 存记录的合并与旧记录问题、摘要露标记 | 改成尾部有界读取（至多 201 条），不碰记录；文字用 `replyText`，表情写成“[表情]”，Markdown 标记留着记为已知限制 |
| 11 右栏收起时没有未读指示、可访问名称 | 决定 7：状态栏活动条目写“N 条新消息”；可访问名称统一“标题 + 数”；底部面板口径与理由写明 |
| 12 `replaces` 的校验、清理与布局形态 | 前缀用 `descriptor.plugin`；不经 SDK 公开；用 `removeTab` 清五种位置；隐式容器 id 的例外；不写回、降级会再出现 |
| 13 验收映射漏项 | 补 11 行，写明 dom 或 e2e；加档位条件的变异检查 |
| 14 不做与风险 | 写明阶段 ③ 复用宿主加对话视图的组合；风险点改写成失败通道、第一屏、提供者缺席 |

第二轮的发现都是计划层面的细节，审查给了改法、照改即可，方向没有新问题，所以不开第三轮设计审查。实现审查按切片 5 做，前端与后端分开。
