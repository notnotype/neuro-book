# 《Agent 内核的输入缓冲区》第二稿的审查处理（2026-11-18）

审查对象：第二稿，提交 `1e9c0cce4` 时的固定副本。两位审查者：Claude Opus 审内核与后端合同（[报告](buffer-proposal-review-r2-backend-opus.txt)，17 条：重要 10、建议 7），Claude Sonnet 审对话视图（[报告](buffer-proposal-review-r2-frontend-sonnet.txt)，12 条：重要 9、建议 3）。没有阻断。下表用 B、F 指两份报告的条目。

主 Agent 的核实：在主工作区用真实内核重跑了 B1 的复现（[end-race](buffer-proposal-review-r2-end-race.test.ts.txt)，`packages/nb-harness` 下 `bun test`，通过）：回复写下后、`runEnded` 之前受理的 `send` 交回“已排进当前运行”，会话却回到空闲、话留在缓冲区里。这也是现有内核的一处缺口。

## 判断

第二稿的骨架（回到空闲时剩下的留着、运行只取就绪的、放行由用户或排话的人做）两份报告都没有推翻；问题集中在合同还不够精确：状态的落点（由日志推出会让会话级归约读路径级事件，界面也要再推一遍）、收口判断与写 `runEnded` 之间的时间窗、停止的原因与谁停的不在同一个写入批、会把话放进缓冲区的入口没列全、几条新指令的失败码。第三稿按下表改：状态改成显式的会话级事件，在收口的同一个写入批里写下；不再由日志推出，旧日志没有这些事件就照现在的行为。

## 处理（第三稿）

| 条 | 归类 | 处理 |
|---|---|---|
| B1 收口判断与 `runEnded` 不在同一个队列项 | 成立（已复现） | 写成不变量：决定收口与写 `runEnded` 在同一个写入批，之前受理的话由这次运行取走，之后的按空闲处理；加验收 |
| B2 暂停的运行接着跑不写事件 | 成立 | 接着跑暂停的运行写 `runResumed{runId, by}`；暂停按空闲算，暂停时排的话留着 |
| B3 停止的原因与谁停的不在同一批 | 成立 | 停止受理时把发出者与是否留着交给运行循环，收口的同一个写入批写 `inputHeld` 或 `inputRemoved` |
| B4 NeuroBook 的 `watchSteer` 在内核外读缓冲区 | 成立 | 第六节加 `agent/jobs.md` 与 `jobs/steer.ts`：只认就绪的插话，放行出来的插话也算到达；写明读快照缓冲区的宿主代码都按状态过滤 |
| B5 放行的入口没列全 | 成立 | 放行改成“输入入口的属性”：凡以某发出者身份送进一条新输入的（`send`、`enqueue`、异步提问的回答、`rewind{resend}`）都放行这个发出者能放行的；`agent_send` 不带话时改走 `resume` |
| B6 权限表建在发出者可信上，而插件缺省就是用户 | 成立 | 前提写进提案：`agentKey` 按调用方盖章，插件的缺省身份是宿主，只有远程合同（用户界面）是用户；`startTask` 的发出者是调用方；“安全”一节写成以盖章为前提 |
| B7 用户压缩后的自动放行范围与执行者 | 成立 | 范围收窄到压缩期间进来、因这次压缩收口而留着的那几条；由内核做：`compact` 带选项，压完在回到空闲后按普通放行执行，不放在网页里 |
| B8 `send{replaces}` 不校验 | 成立 | 每项带 `{id, edits}`，任一项不在缓冲区、改过或不能移除时整条以 `input-stale` 失败、什么都不写 |
| B9 不带选项的 `send` 怎样放行 | 成立 | 内核缺省等同 `release: "keep"`；现行验收 2 的顺序随“留着的先跑”改写，列进行为变化 |
| B10 事件形状 | 成立 | `inputRemoved` 加 `by`，原因 `cancelled`、`aborted`、`replaced`（旧日志的 `user` 读作 `cancelled`），`replaced` 带 `replacedBy` |
| B11 由日志推出要让会话级归约读路径级事件 | 成立 | 同“判断”：改成显式的会话级 `inputHeld{ids, cause, heldBy?}` |
| B12 编辑后归谁；宿主能否 `start` 用户会话 | 成立 | 编辑只给原发出者，`by` 不变；宿主 `start` 的范围交开发者（第 2 项） |
| B13 停止缺省在哪一层；用户停止子会话后父 Agent 的话 | 成立 | 内核 `abort` 缺省不变（清空），界面照 2026-11-05 传留着；父 Agent 的话交开发者（第 1 项） |
| B14 旧日志的停止推不出谁停的 | 成立 | 不再由日志推出：旧日志没有 `inputHeld`，旧条目照现在的行为是就绪的 |
| B15 留着之后再经历收口，原因被改写 | 成立 | 原因只在从就绪变成留着时记下；“只有用户能放行”是条目上独立的 `heldBy: user` |
| B16 `resume`、`release` 的失败码 | 成立 | 加两张情形表与新码（`nothing-to-release`、`held-by-user`、`input-stale`）；`release` 进远程合同 |
| B17 运行不再取输入时放行 | 成立（与 F3 合并） | 运行不再取输入时（只压缩、正在中止、已决定收口）到达的放行与用户的新话，在回到空闲时生效：先把剩下的转成留着，再按这次用户的放行处理 |
| F1 乐观消息按 `inputId` 确认做不出来 | 成立 | `inputQueued`、`input`、`steer` 带受理它的 `commandId`，转录按 `commandId` 确认 |
| F2 合并的时间差与失败 | 成立 | 同 B8；结果未知的重发冻结参数 |
| F3 运行中与停止进行中打的话走 `enqueue` | 成立 | 同 B5、B17：用户的 `enqueue` 同样放行；停止进行中打的话在停止完成后按用户的放行处理 |
| F4 “已暂停 · 原因”没有实时来源 | 成立 | 同 B11：显式事件，转录直接读 |
| F5 “有留着的话”算进“等你处理”会误报 | 成立 | 只算只有用户能放行的（用户停止留下的、用户自己的话留着），其余在会话行上轻标 |
| F6 压缩后的自动放行 | 成立 | 同 B7 |
| F7 合并要的数据拿不到 | 成立 | 快照与远程合同的条目带完整输入（附件等）；合并出的是一条新输入，输入拦截照常经过它 |
| F8 “编辑”会把别人的话洗成用户的 | 成立 | 不是用户排的只能取消；用户自己的“编辑”是取出到输入框，重发是新话 |
| F9 单一入口的形状 | 成立 | 写出输入框的入口状态；中断与留着同时有时，“继续”先接着跑中断的那一轮，留着的随后 |
| F10 合并后新话看不见 | 成立 | 合并出的那一条作为乐观消息显示在末尾，前面还有宿主的话时标“前面还有 N 条” |
| F11 停止的第二个选项 | 成立 | 只数用户自己的话决定显不显示；清空时被清掉的非用户的话经 `inputRemoved{by}` 通知排话的人；停止进行中这个选项不可用 |
| F12 恢复方式设置 | 成立 | 写出设置声明（Agent 对话分区、用户层、三个取值、缺省合并）；内核不带模式时缺省 `keep` |
