## 二、逐条耦合（按对 bot 场景的影响排序）

### 1. 分轮只认“普通用户消息开头”，视图里没有任何注入点
类别：不推荐耦合
位置：CT:227-241（splitIntoTurnGroups）、CT:258-262（buildTurn 里 user 只在组首是 intent=normal 的用户消息时才有）、V:217（视图直接调用）；types.ts:120（SystemMessageSource 只有 prompt/reminder/compaction/branch_summary/custom）。
现象 [读码]：一条消息要自成一轮，只有“intent 为 normal 的 user 消息”这一条路。提醒、定时任务结果、别的 bot 的话这类没有用户开头的内容，会并进上一轮：上一轮的最终回复、轮末汇总、整轮收起、“已完成/已停止”状态都会算错（status 取组内最后一条，CT:552-578）。唯一的变通是把事件伪装成带 author 的 user 消息（types.ts:77，T:103-106 按 author 换头像与名称，Spec 末段也这么写）；伪装的代价 [读码]：它仍带“编辑/重试/分支”操作（vue/builtin-message-actions.ts 的 rewritable 不看 author）、仍是“用户”色调、不能是没有模型调用的轮、宿主的 recallOf 要自己滤掉（SH:102-111）。nb-story 为同一个缺口写了一整个“按轮分开的转录”（nb-story/src/web/qa/turn-transcripts.ts:1-8）。
挡住：bot 模式（提醒、任务结果、bot 之间讨论）；会话加 bot 模式里把子会话结果当作自成一轮的内容。
建议：消息加可选字段，例如 `startsTurn?: true` 加 `origin?: {label: Text; icon: string}`（user 与 system 消息都可带），splitIntoTurnGroups 认它，T 的角色行用 origin；字段缺省时行为不变。比往视图加 `turnSplitter` 回调好：回调不可 JSON 化，违反 ctx 必须能 JSON 化的合同（types.ts 头注释）。代价：小（types、CT 两处、T 的角色行、单测与一个 Lab 场景）。neurobot.md 第六节“由事件开启的轮次”已有同样设想，这里补充了 author 伪装的现状与副作用。

### 2. 等用户时审批向导一律替换输入框，没有开关
类别：不推荐耦合
位置：V:306-309（blockingInputs/dockedInputs 的划分）、V:522-531（输入框 v-show=!waitingForUser 且 inert）、wizard.ts:99（isDocked = 带 source 或 async）。
现象 [读码]：有阻塞事项时输入框被隐藏并失去焦点，用户不能说话；视图没有 prop 改这一点。停靠区是现成的“并存”形态（不替换输入框），但进入条件是事项自带的 `async` 或 `source`，语义是“异步提问/后代会话的事项”：把普通审批标成 async 能蹭到并存，但停靠区一次一个、各自单独提交、没有“全部拒绝”（Spec“停靠区”），与同步向导对一批审批的处理不同，且 async 的含义被改写。
挡住：bot 模式的“等用户时输入框与审批并存”（neurobot.md 第四节第 8 小节）；bot 常驻时主对话停在等批准，用户却想先说一句别的话。
建议：给 PendingInputCommon 加显式的 `placement?: "wizard" | "dock"`，isDocked 先看它，缺省沿用现在的规则；停靠区对批量审批的单项提交语义在 Spec 里写清。比加视图 prop 好：并存与否按事项定，宿主可以只让某类事项并存。代价：小到中（wizard.ts、V 两处、Spec 与停靠区对批量审批的验收；“记住”的收口见第 8 条）。

### 3. 整段历史一次取完：适配器只会“整份重建路径”，宿主没有用视图已有的分页
类别：不推荐耦合
位置：SH:400-415（loadPath 循环取完 `more`，最后一次 applyPath）；KT:679-690（applyPath 先 resetPath 再整份归约）；KT:158-183 与 426（压缩详情的 keptTurns 靠路径上全部 turnStarted 数“保留了几轮”）；V:178-250、283-292（视图已有 history.hasMore/loading/error 与 history.loadPrevious）；搜 SH 内没有给 ctx.history 赋值（createAgentContext 缺省 hasMore=false）。
现象 [读码]：视图侧已经会往前分页，适配器与宿主侧不会：没有“只应用路径后缀”“往前补一页”的入口，窗口化后 keptTurns 也会算错（数不到被窗口外的轮）。[推断]：消息流没有虚拟列表或 content-visibility（在 packages/nb-agent-ui/src 内搜 virtual、content-visibility、IntersectionObserver，只有分支树里一处），所有轮次都进 DOM；运行中宿主每秒换一次 ctx（SH:48,803-816），视图每次对全部消息跑 splitIntoTurnGroups 与 reuseTurnGroups（V:217，O(n)）。
挡住：bot 模式（一条不断的对话，几周后每次打开、重连都整条重取重画；neurobot.md 第四节第 8 小节“长流按窗口取”）；会话加 bot 模式里 bot 对话与大量子会话并存时的内存。
建议：KernelTranscript 加 `applyPath(events, {partial: true})` 与 `prependPath(events)`（保持引用稳定，已交出的消息对象不动）；keptTurns 在窗口内数不到时给 null（CompactionView 已允许 null）；宿主实现 loadPrevious。长流渲染开销另测，没证据前不加虚拟列表。代价：中（适配器两个入口与它的契约测试、keptTurns 兜底、宿主分页；视图基本不用动）。

### 4. 适配器对扩展事件一律跳过，没有“扩展事件到消息”的映射入口
类别：不推荐耦合
位置：KT:558（isExtensionEvent：type 含 "/" 或 record.kind 为 "ext"）、KT:685 与 707（跳过）；createKernelTranscript 的 options 只有 toolName 与 authorOf（KT:234）；harness.ts applyEvent 的 default 把不认识的事件记成 problem（旧适配器）。
现象 [读码]：扩展写进日志的事件（提醒、任务结果、bot 之间的消息、日程）不会变成任何视图消息；只会被 notePath 记进路径与锚点。认不出的非扩展事件会记进 problems()，但扩展事件连 problems 也不进。
挡住：bot 模式的事件消息；与第 1 条配套：映射出来的消息要能自成一轮。
建议：options 加 `extensionEvent?: (event: {type; data; id; at}) => MessageView | readonly MessageView[] | null`，在 reducePath 的跳过之前调用，返回的消息按路径顺序进 logged；映射函数由宿主给，核心不认扩展的具体形状。代价：小（一个选项、applyPath 与 applyEvent 两处调用、契约测试）。

### 5. 助手的名字、头像与模型徽章是整个视图一份，消息上没有说话者
类别：不推荐耦合
位置：T:98-109（assistant 角色取注册表里唯一一项，头像优先 ctx.session.profileIcon）、T:198-200（角色行总写 lastAssistant.model）；vue/builtin-roles.ts；types.ts:77（只有 UserMessageView 有 author）、types.ts:95-117（AssistantMessageView 没有）；types.ts:170 的 profileName 在 nb-agent-ui/src 内没有渲染处（搜到的只有类型与测试）。
现象 [读码]：bot 的名字只能靠“换掉 assistant 角色的静态 label”，头像靠 SessionView.profileIcon；同一对话里换了说话者（bot 之间讨论）画不出来。模型徽章不能关：模型按 bot 设置、用户不该关心时，每轮仍挂一个。
挡住：bot 模式的身份展示；以后 bot 之间讨论（至少两个助手说话者）。
建议：AssistantMessageView 加可选 `author?: {label: Text; icon: string}`（与 UserMessageView 同形），T 的助手角色行优先用它；加一个视图级开关或 ctx 字段隐藏模型徽章。代价：小到中（types、T、AgentRawView 显示、测试）。

### 6. 宿主的数据层（session-host.ts，1751 行）把“打开一个会话”的流程、内核协议、NeuroBook 概念和 ctx 装配揉在一起
类别：可以拆开（代价大，延后）
位置：SH:252-1751。装配 ctx 在 SH:1590-1700；打开/新建/恢复在 SH:922-1062（recent、drafts 都按“位置最近用过的会话”）；NeuroBook 概念：Profile 与主创（SH:36,1608-1655）、权限规则（rememberRules，SH:143-185）、Skill、Agent 模式 normal/discuss/plan（SH:94-98）、模型服务的角色（RoleOption）、作品 project；`nbook/…` 导入 3 处（localized-text、models/shared/contracts、shared/settings）；CH:109-135 与 plugin.ts:395-530 里装配 registry、renderers、services。
现象 [读码]：宿主一个“对话位置”对应一个 SessionHost，核心动作是 open(sessionId)；固定会话的 bot 位置要改成“打开固定 id、不显示 create/select”，会话列表、profile 选择、welcome 的最近对话、draftProfile 都用不上。作为 NeuroBook 内置插件时，复用 SessionHost 加一组关闭项即可；以后的 NeuroBot 不依赖 @notnotype/neuro-book（neurobot.md 第四节第 3 小节），要复制或重写这 1751 行里的纯逻辑。
挡住：NeuroBot 复用；bot 作为内置插件时只是多写一些“关掉”的配置。
建议：不现在拆。bot 先在 NeuroBook 内置插件里做，用 SessionHost 加参数（固定会话、关会话操作），验证“bot 需要哪些关”之后，再把已是纯函数的部分挪进 nb-agent-ui 核心：recallOf（SH:102）、pendingView 的映射（SH:1535-1590）、branchesOf/rewindTargetFor（SH:583-635）、用量与 availability 的装配（SH:1590-1700）。代价：大（NeuroBot 开工时才值得；窄场景先走简单做法）。

### 7. 内置登记一包拿走，命令缺省全开，还带着没有 v2 工具对应的旧名
类别：可以拆开
位置：vue/builtins.ts（四份登记合成一个 builtinContributions）；vue/builtin-composer.ts:30-35（命令的 when：interaction.commands 为 undefined 时全部显示，含 /new /fork /rename /clear /summarize /plan /mode）；builtin-tools.ts:172-201（request_user_input/ask、switch_mode、run_workflow、execute_sql、agent_collaboration 里的 create_agent、invoke_agent、detach_agent、report_result）。
现象 [读码]：会话式命令的缺省极性是“全开”，不是会话式的宿主忘了写 interaction.commands 就会列出发出去没人处理的死入口（nb-story 的做法是整个不装，QaPage.vue:54-63）。工具名：在 packages/ 内除 legacy、llmlint 外没搜到 create_agent、invoke_agent、detach_agent、report_result、execute_sql、run_workflow、request_user_input 这些名字的定义，v2 的子代理工具是 agent_spawn 等，由宿主自己登记（agent/web/subagent-renderers.ts:30-35）；switch_mode、/plan、模式向导是 NeuroBook 的概念，但 composer.modes 是通用列表，不算越界。
挡住：bot 模式不想要 /new /fork /clear；NeuroBot 想要一份不带旧名的工具登记。
建议：builtin-composer 拆成“输入框触发字符”与“会话式命令”两份，后者不进缺省的 builtinContributions，宿主明确加；builtin-tools.ts 删掉在 v2 里没有对应工具的旧名（先确认 nb-story 与 Lab 不用）。代价：小（两个文件、测试里的断言、README 一句）。

### 8. “本会话都批准/以后都允许”两个按钮与“会话”字样的界面文案
类别：可以拆开
位置：vue/wizard/AgentApprovalWizard.vue:115-116（两个按钮只受 item.remember !== false 控制）；types.ts:291；locales/zh-CN.ts 中的文案：352、355（本会话都批准）、195（只对这个会话生效）、213-214（当前会话不能添加图片/文件）、432（本会话命中率）、502（会话费用已达上限）、507（开一个新会话）等 [读码，共 32 处含“会话”，其中约 13 处是会话列表与会话面板自己的文案，这些正当]。
现象：neurobot.md 要求“两个记住收成一个按 bot 的范围”，现在不能只留一个或改文案；错误文案里的“开一个新会话”对“用户看不到会话”的 bot 是错的话。会话列表有 labels 覆盖（README 会话列表一节），视图文案没有。
建议：PendingApprovalView.remember 改成可带 `scopes`（或一个 `scope: {label: Text}`）决定画哪几个按钮与文案；视图里不属于会话列表的“会话”字样改成中性说法（“对话”），或给视图加 `labels` 覆盖。代价：小（向导一个组件加字段，文案改 10 来处，locales.test.ts 照常核对）。

### 9. 顶栏是一整块：关会话标题栏就连带关掉溢出菜单与宿主入口
类别：可以拆开
位置：V:47,408（header 为 false 则整块不渲染）；H:117（溢出菜单在顶栏右列里，且要求 session !== null）；H:62-80（左列：子会话是返回箭头，否则 newSession 时是新建）；H:48-49（标题是会话标题，空串写“未命名会话”，无会话写“新对话”）；V:140-146（溢出项：上下文、分支树、登记的顶栏动作、原始视图切换）。
现象 [读码]：Spec“顶栏”承认 header=false 后原始视图入口随之没有，宿主要用受控 viewMode。同样没有的还有：分支树入口（只在溢出菜单里）、登记的顶栏动作（常驻两个、其余溢出）、head-trailing 插槽。bot 想要“只显示 bot 名字与头像，不显示会话标题，但保留查看模型请求、上下文”时做不到。
挡住：bot 模式的顶栏；会话加 bot 模式里 bot 的头与会话的头样式不同。
建议：把 AgentConversationHead 作为受管组件导出（现在是内部零件，H 已经是自包含的，三列 Teleport），视图再加一个 `head` 插槽，缺省仍是现在的头；宿主要 bot 头就用自己的组件，溢出菜单的内容作为 ctx 或登记项的结果交给它（或把溢出菜单抽成一个可单独挂的组件）。代价：中（导出与 .md、一个插槽、溢出菜单抽组件；不必改已有宿主）。

## 三、三种用法下包应该是什么形状

推荐：保持“无界面的核心 加 一个编排好的视图”，把三种用法的差别做成数据字段、事项级字段和少数插槽；不拆成几种外壳，也不堆布尔开关。
理由：
- 核心已经是无界面的（types、conversation-turns、registry、kernel-transcript、wizard、composer-actions、status-line，boundary.test.ts 机检不引 Vue 运行时）；会话列表与面板也早已在视图外。差别大的“外壳”就是顶栏与会话导航，这两块要么已独立，要么按第 9 条抽出即可。
- 滚动跟随、分页、向导与输入框互斥是一团时序（第 14 条），拆成零件会让每个宿主各写一份。
- 实际要关的东西大多已经是数据驱动（canMutateHistory、canOpenTree、composer.models 为空、statusBar、header），缺的是：轮次起点、事项并存、说话者、事件映射、窗口化。这五样都是“消息或事项上加可选字段”，缺省行为不变，nb-story 与 NeuroBook 现有用法不受影响。
- 布尔开关越多组合越多；所以另外把组合写成“用法档”（第 12 条），每档有一个场景与挂载测试。

三档的约定（建议写进 Spec）：
1. 会话档（现状）：header 或 headTargets，sessions 插槽，newSession，statusBar，内置四份登记，canMutateHistory 与 canOpenTree 按会话，审批向导替换输入框。
2. bot 档：无会话标题（用第 9 条的 head 插槽放 bot 的头）、无 sessions 插槽、无 newSession；不装 builtinMessageActionsContribution（或 canMutateHistory 保持 false）；不给 canOpenTree；composer.models 为空（隐藏模型选择）；interaction.commands 只列宿主做了的；事项 placement 取 dock（第 2 条）；事件经适配器的 extensionEvent 映射成带 startsTurn/origin 的消息（第 1、4、13 条）；助手消息带 author（第 5 条）；历史由宿主按窗口取、视图按 history.loadPrevious 往前翻（第 3 条）；欢迎屏 welcome 为 null。
3. 会话加 bot 档：两个视图并排，宿主各给自己的 ctx（bot 的固定会话与被选中的子会话），中间或旁边挂 AgentSessionList，bot 的行带 icon 与 status；bot 派出的会话在 bot 的流里用宿主登记的工具卡片画（现有 SubagentCard 做法），子会话的待处理事项经 PendingInputCommon.source 进 bot 视图的停靠区，点“打开子会话”发 session.select；子会话视图保持会话档，顶栏返回箭头靠 ctx.session.path。这一档不需要视图支持“同时显示两个会话”。
