### 设计审查第一轮的处理

后端（B，Opus）与前端（F，Sonnet），编号同报告：

| 发现 | 结论 | 处理 |
|---|---|---|
| B1 新触发点没写方法，内核只压 `manual` | 成立 | 过期前用 `inplace`、空闲用 `summary`，失败不换方法；压缩指令带原因与方法顺序 |
| B2 缓存寿命与单价没有来源 | 成立（“订阅制不省钱”是审查者推断，提案照此标注） | 寿命配在模型设置并随请求发出；单价未知、订阅制、没配寿命不做 |
| B3 压缩前刷记忆插不进阈值与溢出，空闲时又花钱 | 成立 | 改为压缩后把摘要追加进日记文件，不多跑回合 |
| B4、F5 任务会话的审批无人应答 | 成立；“待你处理”入口改了已定的 web 范围 | 任务按清单放行、清单外拒绝并报告；入口交开发者（待定项 2） |
| B5、F1 自写的部分远大于提案所列 | 成立，核实了服务端宿主 3,952 行、对话宿主 1,459 行 | 第三节列全；复用规模交开发者（待定项 1） |
| B6、F17 宿主发起的压缩与用户消息竞争 | 成立 | 用户消息到达先中止压缩再发 |
| B7 计时归属与重启 | 成立 | 计时在句柄层或对话管理，截止时刻由持久数据算 |
| B8 会话轮换没有机制、会丢摘要 | 成立 | 去掉轮换，按 ADR 0035 以后加检查点快照 |
| B9、F14 原始记录与会话日志的先后与真相源 | 成立；原文与 ADR 0035 决策 1 冲突 | 入站以原始记录为准、出站以会话日志为准；流来自会话日志，群聊时重做记为取舍 |
| B10、F4 提醒与任务结果的表示；分轮会并进上一轮 | 成立 | 扩展写 bot 一侧的消息、不开运行；nb-agent-ui 加由事件开启的轮次 |
| B11 两个会话同时写记忆 | 成立 | 写锁、暂存后改名、改动记录 |
| B12 核心记忆每次请求重读会让缓存失效 | 成立 | 用 `opening` 在创建与压缩后取快照 |
| B13 只监听本机的安全靠三条来源核对 | 成立 | 写成第一版必须满足的不变量与验收 |
| B14 外部内容第一版就进来 | 成立 | 来源与信任级；任务不能写核心记忆；目录外读要批准 |
| B15 什么时候才省钱没写成条件 | 成立 | 下限、间隔、单价、寿命写成判断式；记录花费与节省 |
| B16 重启、错过的任务、数据目录单实例 | 成立 | 重启后系统输入接着处理；错过合并；启动认领数据目录 |
| B17 插话还是排队 | 成立 | 运行中插话，空闲连发合并 |
| B18 ADR 0030 的条件被改了原意 | 成立 | 交开发者（待定项 3） |

| F2、F3 跨会话拼流、轮换的显示 | 去掉轮换后不再成立 | 无 |
