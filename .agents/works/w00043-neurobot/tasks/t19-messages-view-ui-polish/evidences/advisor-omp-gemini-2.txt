一、完整列表：做一个「对话目录」视图，两页共用一个位置，不做弹窗。

默认放在主侧栏（缺省左边）的独立容器里，首次不自动显示，工作台照常打开「项目」。点开后目录暂替资源管理器，不遮聊天、不换掉正在写的文档。常查的人可挪到次侧栏、底部面板或应用内浮窗，入口跟着视图走；既要文件又要目录就放底部。不是恢复 t15 决定 5 取消的「项目」内会话分节；为目录用新视图 ID，消息继续沿用 `nbook.agent.conversation`，保留对旧 `nbook.agent.sessions` 的 `replaces`。

轨底「全部 Bot」「会话历史」都显示同一个目录并指定页、聚焦该页搜索；按两次只定位，不把视图关掉。不改用户停靠的位置，不清搜索、筛选和列表滚动。Bot 页按名字查，行显示头像、名字、最近一句或状态、未读数。会话页缺省当前作品，能切全部作品、筛 Profile、显示归档；标题下放说明，行尾是时间和状态，改名、归档、恢复留在行菜单。保留普通会话的子会话层级，Bot 主对话及其后代不混进历史。找旧会话不用弹窗：点「会话历史」直接打字，或从命令面板执行新命令「查找会话」到同一搜索框。只搜标题和说明，不搜聊天正文。现有「切到 Agent 会话」无参数时取活动或未读目标，不是搜索（`agent/web/plugin.ts` 的 `FOCUS_SESSION_COMMAND`）。

点 Bot 或会话行：在本窗口的「消息」打开，消息停靠在哪或已浮出就在哪，不另开编辑器标签，也不跟随上次用过的对话页面；目录不关闭、不自动换页，焦点留在列表，打开失败不改当前项。同一侧同一容器时默认推荐消息在上、目录在下，沿用分节的分隔线与收起；目录只滚自己的结果，选中能展开已收起的消息，不自动收目录。若用户特意把两者放同侧的不同容器，该区域只能显示一个：找时切到目录，选中切回消息；想同时看，就拖成同容器或分到两侧。不会为这种摆法临时盖一个抽屉。

窄：搜索独占一行，范围与筛选在下一行；每项两行，长标题截断、悬停显示全名。宽：筛选与搜索同排，行尾给作品／状态／时间固定列；仍是一列结果（内容列约 720px 封顶），不加聊天预览。

编辑区不是现成的停靠点：`ui/workbench-layout.md` 输出 26 拒收工具视图。推荐不放宽；若编辑区是硬需求，用 `editor.pages` 显式「在编辑区打开目录」，复用同一份目录状态与打开目标，不承诺直接跨类型拖拽。

二、侧轨展开：停靠时不加「显示名称」档；轨只负责快切，目录负责查找和浏览。

约 400px 的次侧栏，把原头像列的宽度换给外缘 48px 轨，不是在 400px 外再叠一列。聊天拿到约 352px 的排版预算，主题留缝和内边距另扣；这是算式，不是实测。假设带名字的轨要 144px，同一预算只剩 256px，低于现有双列宽版给聊天预留的 320px。盖上去会遮住正文或输入框，留在原宽会让长消息重排，自动加宽则会挤写作区，且小窗口未必有余量。三种都不做；用户手动拖宽聊天侧栏，增加的宽度给聊天，不自动长出另一份列表。

保留 48px 轨的三段：上段切容器；中段是新对话、Bot、最近会话；底段固定「全部 Bot」「会话历史」。头像／会话方块的悬停和键盘提示给全名，同名补来源或时间；容器只用浅按下态，当前会话用描边，未读仍用角标。短窗先收最近项，不挤走两个目录入口；未读数不撑宽。名字不值得占一列，能看全名、按名字筛、滚到旧条目的是同一个目录。

即使视图很宽，也不自动把轨换成全量列表。侧栏多节时，轨保留容器入口和宽度，不挂属于某一节的头像组；消息分节的标题动作仍有同名的目录命令，不在聊天区再画一条轨。停在底部面板也是这两个标题动作。这样从单节变两节不多扣一次聊天宽度，目录上下排用的是工作台原有分节，而不是第三种轨。

三、左右：支持一键交换主、次区域，不给每条轨单独选内外侧；换边另立工作台 Task。

默认「活动轨｜主侧栏｜编辑区｜次侧栏｜次轨」。切到主侧栏在右，则是「次轨｜次侧栏｜编辑区｜主侧栏｜活动轨」。会话可以移到左边；有了这个设置，不必逐一搬消息、项目及同容器分节，也不丢各自的宽度和收起记忆。账号、设置只在主轨底出现一次。若只想把某个视图搬到另一侧，已有「移动到」，不需要布局开关。不确定左右交换的使用频率；不为它承诺两条轨可各自放内侧，也不镜像编辑、底部面板、文案或系统窗控。

实现：`nbook.workbench/primarySide` 是建议的新用户设置，默认 `left`。保留规范文档顺序及 `sidebar` / `auxiliarybar` 锚与 ID；`state/default-tree.ts` 的 `fitsSkeleton` 不放宽。只在 `nb-workbench-layout/src/layout-project.ts` 的 `projectLayoutDoc` 对呈现体重排横向四块，重算相邻分隔线；次轨把现有次侧栏横入口换成只在呈现里的外缘叶。区域宽度包含次轨，分隔线仍拉整列，拖到零、隐藏或放不下时次轨随列收，靠标题栏复开。主轨自身的显隐不变。`state/layout-doc-store.ts`、`state/layout-constraints.ts` 的尺寸求解、拖动预览、落账共用该投影，宽度意图回写到原来的区域锚。

上述工作台文件均在 `packages/neuro-book/src/plugins/workbench/web/`。`components/WorkbenchShell.vue`、`WorkbenchToolStrip.vue` 与 `WorkbenchRegionStrip.vue` 共用侧轨渲染、键盘与溢出逻辑；底部仍用横条。`shared/contracts.ts`（插件目录下）只让视图给稳定 ID、名称、图标或头像、选中、未读、命令，以及主段／底段；不收 Teleport 的 DOM，不公开给第三方。`entry-drop.ts` / `layout-drag.ts` 从呈现取轨边和插入方向，只有容器入口可拖；`shell/adjacency.ts` 与 `WorkbenchSurface.vue` 的相连圆角、接缝、最大化避让从物理邻接算（现在写死为左）；`WorkbenchTitleBar.vue`、`titlebar/menu-items.ts` 和文案按物理左／右显示，命令参数仍用逻辑名。

要修的合同：`docs/specs/ui/workbench-layout.md` 输出 1、18–22、46–47（骨架、F6/读屏、接缝、入口与拖动），`ui/workbench-shell.md` 输出 28、32（开关），`workbench/views.md`（轨贡献）；同步 ADR 0044 的「一棵树」说明。代价主要是换边后两侧的拖拽、隐藏／拖到零／窄窗、最大化和圆角过渡都须验，不是改一条 CSS。切换时保持编辑器与消息实例、浮窗坐标和用户意图；拖动中中止手势再切，避免旧方向回写。

不移 ActivityBar。`layout-doc-validate.ts` 目前要求活动栏、状态栏各一个，`fitsSkeleton` 还校验位置。只移出文档、仍投影到同一几何树，可以统一两轨来源，但要付旧记录迁移、校验和 `hiddenBars` 兼容的代价，换边并不需要；连呈现树也移出，则宽度求解、落点和圆角要两头算，回到 ADR 0044 要消除的问题。当前收益不抵代价。

四、浮窗：窄、宽都用右侧快切轨加同一个目录，不保留宽浮窗的第二份全量列表。

单标签且消息就绪：保留 t18 的 40px 自绘头，聊天和轨通顶；轨顶不放头像，右上让给工作台的「回到停靠」等框架按钮，头按 `--workbench-own-head-inset-end` 留位。只让头的空白区域拖窗。轨没有工作台的容器入口或账号设置，复用同一组快切条目和底部命令。加载或失败用普通头；多标签用普通标签头，只在消息标签显示时从头下方画轨。目录自己浮出时用普通头，不借用消息头。

宽窗增加的是聊天宽度，不再按 600×360 门槛摆全量列表；撤掉消息内的旧抽屉、列表栏和分隔线。代价：原来一个宽浮窗可同时浏览完整列表和聊天；现在要把目录独立摆在旁边。不确定有多少人依赖原来的双列浮窗。两页内连续滚动、不设页码；查的是当前范围的全部结果，不只搜已画的行，沿用 `session-list.ts` 的 `list` 与本地搜索。

「全部 Bot」「会话历史」经 `nbook.view.open` 找目录的位置；浮着就提到前面，停靠就切到其容器。不要为露出目录偷偷移动消息窗；若浮窗盖住停靠目录，可把目录也浮出，或将两者并排。目录点选统一走面向「消息」的打开动作，不直接用 `nbook.agent.focus-session` 给无归属会话选去向（它会沿最近对话位置）。两者并排时保留列表焦点；点选导致目录被切走（同侧不同容器、同窗不同标签），或消息浮窗被提到前面时，焦点去消息标题，不留在遮住的列表里。退回停靠按布局输出 39 回声明容器，不承诺回浮出前的位置；停靠、浮动、缩放均不重建聊天实例或清空草稿。

待拍板（均为推荐，不当作已定）：
1. 完整列表的家：独立目录，默认主侧栏；接受找会话时暂替文件树，不用模态弹窗、抽屉或换聊天页。
2. 目录的去向：选中总在「消息」打开；不改变现有「切到 Agent 会话」对其它调用方的行为。目录继续用工具视图，不放开拖进编辑组。
3. 400px 的名字档：不做；给聊天保宽，完整名称交给提示和目录。
4. 左右摆法：支持主次整列交换，另立工作台 Task；不做单轨内外移动，ActivityBar 不出布局树。
5. 宽浮窗的双列：以独立目录替代内嵌全量列表；看重一窗双列胜过统一入口，才保留 t18 宽版，这两种不要同时做。
