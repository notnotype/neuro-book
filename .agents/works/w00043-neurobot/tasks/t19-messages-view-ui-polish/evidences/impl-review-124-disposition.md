# 片 1、2、4 快速审查的处理

审查对象：`5815d0a08`、`a88d156c4`（片 1），`53f747f69`（片 2），`e31150442`（片 4），固定在 `13364cb00`。Opus（[`impl-review-124-opus.txt`](impl-review-124-opus.txt)，重要 3、建议 6）与 omp `@review`（[`impl-review-124-omp.txt`](impl-review-124-omp.txt)，重要 8、建议 4）同审一份说明，报告到齐后一起归类。修正提交 `8c9efbd14`。

| 发现 | 谁报的 | 处理 |
|---|---|---|
| 读入归整在 computed 里用随机 id（新面板、分支每次重算换 id，放弃改动后当前面板失效） | Opus 1、omp 8 | 成立，改：`settlePlacements` 收一个按文档给确定 id 的策略，`reconcileViews` 用和补位同一套 `freeId`。用例：多标签浮窗的旧记录读入、再交一次目录，搬回的分节 id 不变；变异时失败 |
| 视图的“重置位置”把浮窗带回的意图留着 | Opus 2、omp 2 | 成立，改：`moveView` 把视图从别处放回它声明的容器时，同一次提交清掉那个容器的意图；浮窗归位（`dockFloat`）照旧带回。Spec 输出 50 把“重置位置”写清是视图回声明的容器与容器回声明的区域两种。用例在 store 的侧轨意图一组；变异时失败 |
| 命令面板第一步逐个试算全部目标（38 个视图 3.6 秒） | Opus 3、omp 9 | 成立，改：第一步只问有没有一个会被收下的目标（`some`），第二步才列全表 |
| 手势落账把预算覆盖的宽写进意图 | Opus 4、omp 4 | 成立，挪到片 5：预算覆盖要等片 5 才接进 store；计划片 5 加约束“手势回写跳过被覆盖的区域宽度”与真实手势往返用例 |
| 键盘拿起后 Tab 会停到全被拒的入口带 | Opus 5、omp 6 | 成立，改：入口条的停靠点按 `entryDrop`（和指针同一道关）筛，一个不剩的入口条不进 Tab 环。用 omp 的探针（真实 store 与键盘会话）在修正后重跑：Tab 只在右轨与浮动之间 |
| 测试缺口（拖放、菜单、命令面板一侧；浮窗读入；窗并窗的意图） | Opus 6 | 部分改：补命令面板与目标表的用例、浮窗读入用例；拖放一侧由段 A 的 e2e 覆盖，键盘一侧用探针核过；窗并窗没补（片 6 碰浮窗时补） |
| 关卡只比视图 id，已违反的视图再混进别的视图也放行 | Opus 7、omp 7 | 成立，改：关卡比违反的样子（位置、容器、混进来的视图）。纯函数用例：违反着时不相干的写入照收、混进别的视图被拒 |
| `setContainerRail`、`setFloatRail` 收零与非有限宽 | Opus 8、omp 11 | 成立，改：两处写入口和读入同一条判据，拒绝、零写入。用例给零、负数、NaN、无穷 |
| `recordRepairs` 在记录没被采用时照报 | Opus 8 | 成立，改：不合骨架的不报 |
| 模板读入修了坏值却不报 | omp 3 | 成立，改：按实际采用的来源（记录，没有时模板）算；用例与变异 |
| 预算没计右栏的有效最小宽，求解器转去压左侧栏 | omp 5 | 成立，改：基线加 `regionMinimum`，右栏只让到聊天下限与有效最小宽的较大者；Spec 输出 50 公式同步。用例两条 |
| `railBudget` 没考虑区域最小宽（同上） | Opus 8 | 同上 |
| 带自有 `toString` 键的坏值让读入抛错 | omp 1 | 成立，改：说明里不对值做字符串强制转换，只写原值或种类；校验里原有的 id、版本、区域名三处一起改。用例与变异 |
| 降级求解拿展开厚度算，会收走右栏而不是拒绝展开 | omp 12 | 成立，挪到片 5：片 5 接预算时，`presentationCollapse` 用收着的基线选项，计划片 5 加这一条与窄窗用例 |
| `confinedTo` 第三方也能写 | Opus 9、omp 10 | 接受取舍，交开发者：登记校验拿不到“是不是内置插件”（贡献描述里没有发布者是否保留的信息，`replaces` 同样只靠 SDK 不收）；第三方写了也只限制它自己的视图。要严格只给内置，得让内核把这个信息交给贡献点校验 |
| `setFloatRail` 没从包入口导出、没测 | Opus 8 | 留给片 6（浮窗展开第一次用到它时导出并补测）|
