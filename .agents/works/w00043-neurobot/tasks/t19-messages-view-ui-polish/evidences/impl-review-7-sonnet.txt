## 1. [重要][正确性] 收着时按高度截项少算 12 像素：每个“刚好放得下”的高度上，最后一项被裁掉一截
位置：/home/notnotype/CodeRepository/neuro-book/.worktree/w00043-neurobot/packages/nb-agent-ui/src/messages-segment-fit.ts:25-43（slots 的算式），AgentMessagesSegment.vue:56-62、.acv-segment__main 的样式（padding-block: 4px）
现象：fitSegment 把输入高度当“内容盒”，按 n 项需要 40n-4+9（SEGMENT_ITEM_STEP*n - 4 + SEGMENT_DIVIDER）算。实际有两处对不上：
 (a) useLayoutExtent 量的是 clientHeight，含 padding（它自己的 .md 写着“包含内边距、不含边框：拿它给自己的内容排版时，要扣掉内边距”），而 .acv-segment__main 有 padding-block: 4px，上下共 8；
 (b) 短线是 flex 的一个子项，它和相邻项之间多出一个 4px 的 gap，“最后一项后面没有 gap 所以补回 4”的前提不成立：n 个按钮加 1 条短线共 n+1 个子项、n 个 gap，总高 36n + 4n + 9 = 40n + 9，不是 40n + 5。
合计需要 40n + 17，函数在 height = 40n + 5 就判定能放 n 项，差 12px。
如何核实：我用 headless Chrome 把同样的 CSS（main 的 padding-block 4、gap 4、行高 36、短线 1px 加 margin-block 4）摆 n=3/5/8 项，量 clientHeight：137 / 217 / 337，而测试里的 heightFor(n) 给 125 / 205 / 325，各差 12。探针在 /tmp/review-t19-impl-7/probe/fit.html。也就是 fitSegment 单测里每一个“正好放得下”的用例（heightFor）在真实布局里都放不下，最后一项被 overflow-y 裁掉（scrollbar-width: none，用户看不到滚动条），只有 roving 聚焦到它时才滚出来。单测只对着自己的常量，没人对过真实布局，所以没发现。
为什么是问题：Spec 输出 57 写“随高度只在末尾增减”，用户看到的是最后一个会话方块半截；侧轨本来就在高度紧时才触发截项，这个误差恰好落在最常见的“刚好不够”区间。
建议：把 12 做成有名字的常量（padding 8 + 短线两侧 gap 4），或让 main 的 padding 改到外层、量内容盒；同时把 heightFor 换成从真实 DOM 量出来的数（e2e 里按 data-strip-* 数量对 main 的 clientHeight 做一次对照），避免常量与 CSS 各写一份。

## 2. [重要][正确性] 注释与 .md 写“换位置时 Vue 只搬节点，列表的滚动与搜索框的焦点不丢”，在浏览器里不成立
位置：AgentMessagesSegment.vue:4-6（文件头注释）、AgentMessages.vue:3-6、AgentMessages.md“rail 与 edge 之间换的是同一个视图段实例……展开着的列表、搜索词与滚动位置不丢”、AgentMessagesSegment.md 相应段
现象：Teleport 的 `to` 变了（侧轨换元素、rail 与 edge 之间切换会改 disabled 与 to）时 Vue 用 insertBefore 把子树移到新位置（Vue 3.5.39 的 runtime-dom 里没有 moveBefore）。浏览器里 insertBefore 一个已在文档里的节点等于先移除再插入：焦点丢，滚动位置归零。
如何核实：headless Chrome 探针 /tmp/review-t19-impl-7/probe/focus.html：input 聚焦后把它的父节点 append 到别处，document.activeElement 不再是 input（focusAfterMove=false）；滚动容器 scrollTop 100 的，被 append 到新父节点后变 0（scrollAfterMove=0）。结果：focusBefore=true focusAfterMove=false scrollBefore=100 scrollAfterMove=0。happy-dom 的 dom 测试不会重现这一点，所以测试没有暴露。
为什么是问题：Spec views.md 输出 21 写“视图负责列表内控件的身份、滚动与选中，换位置后自己恢复”——换位置后恢复是视图的责任，这里指望 Vue 搬节点就保住，实际两样都丢。触发路径：右轨换容器再切回（工作台给新的 main/foot 元素）、rail↔edge（浮成窗再停靠）。丢失的是展开着的列表的滚动与搜索框焦点（搜索词因为在宿主里保留了，列表还是原样画出来，但滚动回顶）。placement 经 none 回来时更彻底：v-if 的 aside 与 Segment 整个卸载重挂，Segment 自己的 pendingFocus、brokenAvatars 状态也一并没了。
建议：要么承认不保，改文档与注释（“搜索词保留，滚动与焦点不保”，并在换位置前后各记一次再恢复：换位置前记 listRef 的 scrollTop 与焦点所在页，nextTick 后恢复）；要么在 Teleport 位置变化的 watch 里做恢复。至少把注释里那句断言改掉，否则后来的人会信它。

## 3. [重要][正确性] 打开 bot 后“焦点交给聊天输入框”在盖层 inert 期间给不上，之后没人补（从代码推断，未在真实运行时复现）
位置：/home/notnotype/CodeRepository/neuro-book/.worktree/w00043-neurobot/packages/neuro-book/src/plugins/agent/web/MessagesHost.vue:117-142（revealAndFocus、openContact）、:177-189（模板里 :inert="cover !== null"）；contact-opener.ts 的 openContact
现象：openContact 在第一个 await 之前就把 pending 设上（盖层出现，聊天区 inert），随后 `await provider.open(id)`（远程）、`await host.open(sessionId)` 才清 pending。revealAndFocus 并行地 `await props.reveal()`，成功后 `focusComposer()`（nextTick 里调 conversationRef.focusComposer()）。reveal 只是一条命令执行，通常比取主对话的远程调用快，所以给焦点时盖层还在、输入框在 inert 子树里，focus() 无效；pending 清掉之后没有任何地方再给一次焦点。
为什么是问题：Spec 输出 57“打开”写“打开之后焦点交给聊天输入框”。点侧轨里的 bot 头像是这条路径的主入口（点一个当前没开着的 bot 必经 pending）；只有“当前已开着它的主对话”的早退路径才给得上。newSession 同理：`host.act({type:"session.create"})` 不等落定，sessionId 还是 null 且 tab 为 bot 时 pickBot 盖层把聊天区 inert。
如何核实：e2e 里点一个不是当前的 bot，等聊天出现后断言 document.activeElement 是输入框；或在 MessagesHost 的 dom 测试里把 provider.open 做成可控的 Promise，先 resolve reveal 再 resolve open，看焦点。目前 messages-model.test.ts 与 dom 测试都没覆盖这条宿主逻辑（见第 8 条）。
建议改法：揭示完成后把“要给焦点”记成宿主状态，等 cover 变 null（且是最后一次揭示）再 focusComposer；即 `pendingFocus = seq`，watch(cover, …) 里在 cover===null 且 seq===reveals 时给。

## 4. [重要][界面] 圆点的描边读了不存在的宿主变量 `--skin-activitybar-background`，真实变量是 `--skin-activitybar-surface`

建议改法：改成 `var(--skin-activitybar-surface, var(--panel-surface))`，hostVars 与 .md 同步改名。

## 6. [建议][界面] 状态变化的过渡有缺口：当前 bot 竖条与当前会话描边是瞬变；底段按下态用了强调色，与侧轨底段的约定不一致

建议改法：(a) 竖条常驻 DOM、用 opacity 或 transform 过渡（或把当前态改成每个头像行自带的伪元素、颜色/透明度过渡），描边加 box-shadow 到 transition 列表；(b) 改成 `var(--skin-activitybar-active, var(--text-main))`。
