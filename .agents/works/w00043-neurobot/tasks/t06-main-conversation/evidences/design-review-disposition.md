## 一次消掉几条的改法

- **只读会话头的原语**：会话头建后不变，内核加一个不取锁、不修复、只读第一行的 `header(id)`。用在三处：
  - `ensureMain` 与启动时的持有先核对归属，再打开；
  - 冷会话上的 `owned-session` 拒绝不先打开；
  - 已有会话先打开、没有才建，不先按记录里的 Profile 建。

  消掉第 3、20 条与第 22 条补充里的冷路径问题。
- **缺省 bot 用固定 id `lyra`，建 bot 先复制进暂存目录再改名**：消掉第 10、21 条，不从预设 id 推 bot id。
- **收窄主对话状态的合同**：状态只报持有的情况（`none`、`opening`、`held`、`failed{code}`），只读与损坏以会话自己的快照与状态帧为准，不在 bot 服务里另报一份。消掉第 15、27 条，第 18 条的验收随之改。
- **宿主接着跑有归属的会话里的运行，这次不实现**：自动接续搁置后它没有调用方。runtime 输出 4、108 的 planned 句子留着，第 14 条随之消失。
- **不另开 `restoreProfile`**：远程 `changeProfile` 已经带 `commandId`、码表齐全，界面直接用它，消掉第 22 条。
- **头像不在 t06**：t06 没有界面，头像的取法照表情包走 HTTP 路由，归 t15，消掉第 4 条。

## 记已知限制、建跟进的（不在 t06 改）

内核原有的三个窄窗口缺陷（第 2、6、7 条），都是 t06 之前就有，所有会话都受影响：

- 反应批写失败时，等待者的结果与日志不一致；
- 只读冷打开跳过中断恢复；
- 只有会话头的半成品日志被当成建好的会话。

另有关系表断链（第 8 条的一部分）。这四项写进 Spec 的已知限制，跟进待开发者定建在哪个 Work。
