### 1. `clone()` 从可变的原始选项重新读取配置
- **严重程度**：重要；**类别**：正确性；**Task**：w00026 t58。
- **位置**：`packages/nb-layout/src/grid.ts:168-173,755-756`。
- **现象**：`buildGrid` 为原网格捕获了归一后的 `sashSize` 与 `encodeRef`，但 `clone()` 把外部传入的 `options` 对象原样留存并再次传给 `buildGrid`。调用方创建网格后改写 `options.sashSize`，副本会使用新值；改写 `options.encodeRef`，副本序列化出的 ref 也会变化。原网格仍用创建时捕获的值，故副本不再保留原网格配置。
- **如何核实与结果**：第一条定向 smoke test 创建时设 `sashSize: 4`、之后改为 `12`，输出 `{"original":[4],"clone":[12]}`。第二条定向 smoke test 创建时用 `ref => "old:" + ref.id`，再把选项改为 `ref => "new:" + ref.id`；原网格序列化得到 `"old:x"`，clone 得到 `"new:x"`。
- **建议改法**：让 `clone()` 复用建网格时已捕获的规范化选项（数值 `sashSize`、原 `encodeRef`；函数型 `sashSize` 沿用同一函数），不要重新读取调用方可变的 options 对象。
