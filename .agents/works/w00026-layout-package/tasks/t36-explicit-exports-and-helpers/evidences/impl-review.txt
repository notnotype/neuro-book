### 1. “一行一个名字”检查对多行 `export {` 空转
**严重程度**:重要 **类别**:测试(错的分支上也通过)
**位置**:`packages/nb-layout/src/exports.test.ts:117-120`
**现象**:检查用的是 `/^export (?:type )?\{[^}]*,[^}]*\}/`,逐行匹配,要求同一行里出现完整的 `{…,…}`。入口自己用的多行写法 `export {\n    a, b,\n} from` 里,`export {` 这一行没有闭合花括号,`a, b,` 那一行不以 `export` 开头,所以都匹配不上。
**为什么是问题**:这条检查要拦的是评审时看不出加了哪个名字。它拦不住最常见的违规,也就是在多行清单里把两个名字写在同一行。同一行两条语句 `export {a} from "x"; export {b} from "y";` 同样漏过。
**如何核实**:`exp/me.ts` 里对 `export {\n    a, b,\n    c,\n} from "./x";` 跑这条正则,检出行数为 0。同文件里单行的 `export {c as d, e} from "./z"` 能检出,说明只有单行写法有效。
**建议改法**:改用语法树。用 `ts.createSourceFile` 遍历每个 `ExportDeclaration`,按每个 `element` 的起始行号判重,同一行出现两个 element 就报告。顺带可以要求每条 `export` 声明只含一个来源。

### 2. `hasDefaultExport` 漏掉 `export default function/class`
**严重程度**:重要 **类别**:测试(判据不全)
**位置**:`packages/neuro-book-test-support/src/module-exports.ts:1026-1030`
**现象**:判据只看 `ExportAssignment` 和名字为 `default` 的具名再导出。`export default function foo() {}` 和 `export default class Foo {}` 是声明语句,`moduleExports` 把它们记成名字 `foo`、`Foo`,不是 `default`;匿名的 `export default function () {}` 则什么都不返回。
**为什么是问题**:入口的“没有默认导出”断言在这三种写法下都会通过。自检里只测了 `export default 1`,正好是能被识别的那一种。
**如何核实**:`exp/me.ts` 的输出里,`defaultFn`、`defaultAnonFn`、`defaultClass` 三个用例都是 `default= false`,而 `defaultExpr`、`defaultAs`、`defaultFrom` 是 `true`。
**建议改法**:在 `hasDefaultExport` 里再检查带 `export` 与 `default` 两个修饰符的声明。自检补上 `export default function`、`export default class` 两条违规样例。

### 3. `moduleExports` 对几种写法静默漏报,重载还会重复计数
**严重程度**:建议 **类别**:正确性(助手的合同)
**位置**:`module-exports.ts:1004-1018`
**现象**:`export const {p, q} = obj`、`export namespace N {}`、`export import A = B.C` 都返回空数组。重载函数 `export function f(...)` 写三次会返回三个 `f`。
**为什么是问题**:头注释说它“只认得写在这个文件里的导出”,但漏报是静默的。`exports.test.ts` 的禁用词检查和文档导入检查依赖它的结果。`./text` 与 `./locales` 的入口文件本身就是声明文件,漏掉的名字既不会被检查,也不会出现在清单里。
**如何核实**:`exp/me.ts` 里 `destructure`、`namespace`、`importEq` 都输出 `[]`,`overload` 输出 `["f","f","f"]`。
**建议改法**:要么补上这三种写法,要么让它遇到不认识的带 `export` 修饰的语句时抛错。结果按名字去重。

### 4. 禁用词切分漏掉 `SideBar`,也不认复数
**严重程度**:建议 **类别**:测试(漏)
**位置**:`exports.test.ts:69-75`
**现象**:`words()` 只把 `status` 后接 `bar` 合并成 `statusbar`。`SideBar`、`sideBar` 会切成 `side`、`bar`,不命中禁用词 `sidebar`。`Regions`、`Containers`、`Editors` 这类复数也不命中。
**为什么是问题**:`AGENTS.md` 的规则写的是活动栏、状态栏、侧栏等概念,而不只是这几个固定拼写。
**如何核实**:从代码推断,我没有单独跑。按 `words()` 的两步正则,`SideBar` 先变成 `Side Bar`,再按空白切开,得到 `side`、`bar`。
**建议改法**:合并规则改成通用一点,例如对相邻两词拼接后也查一次禁用表。再对词尾 `s` 做一次去复数后比较。自检补一条 `SideBar`。

### 5. 文档导入检查的覆盖面偏窄
