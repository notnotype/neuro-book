# 右栏与底部面板的入口条与切换容器

## 目标与范围

从 [t27](../t27-region-entry-strips/README.md) 拆出来（2026-11-17，t27 计划第 3 稿的第二轮设计审查之后）。开发者 2026-11-16 的原话：“底部的面板应该也是类似 ActivityBar 的那种容器（类似 vscode），切换应该是左右滚动切换。右栏也应该是和 ActivityBar 一样能切换容器的”。

已定的（编号同 t27 README）：

- 8. `card-3`：右栏、底部面板一个容器一张卡片，卡片里几节之间是开放式分割线（t27 第 1 片已做）。
- 9. `strip-3` 甲：右栏、底部面板的入口条是卡片顶上一行，切换时不动；当前容器只有一节时，那一节的标题与动作并进这一行。
- t27 第 3 版“直接做”：底部面板、右栏的卡片与顶上一行不动，里面的内容左右滚；选中标记（右栏图标的按下底色、底部面板标题的下划线）和内容同时滑过去。
- 待确认清单 2026-11-16 一行：右栏、底部面板只要显示着分节就有入口条，只有一个容器时也有。

范围：入口条叶（呈现树里的一片叶，不进文档）、并成一行的头、点入口与菜单、左右滚动切换（用 t27 第 2 片的 `swap`，加 `window` 与静止的底）、选中标记滑动、入口条的拖放。

合同：[`ui/workbench-layout`](../../../../../docs/specs/ui/workbench-layout.md) 输出 6、11、13、20、36、42、44 到 47；[`ui/nested-grid`](../../../../../docs/specs/ui/nested-grid.md) 的“过渡”与投影；[ADR 0046](../../../../../docs/adr/0046-workbench-view-containers.md)。

## 输入

- t27 计划第 3 稿的“右栏、底部面板顶上一行（入口条叶）”“入口条的拖放”“切换容器时发 `swap`”里右栏、底部面板的部分（提交 `c56ab99a7` 的 `tasks/t27-region-entry-strips/plan.md`），以及它对 ADR 0046 六处冲突的逐条核对。
- t27 第二轮设计审查（[`design-review-r2.txt`](../t27-region-entry-strips/evidences/design-review-r2.txt)）转过来的，计划要逐条回答：
  - 第 1 条：最大化只有一节的分节后入口条被盖住，还原按钮不可达。审查给两条路：最大化的分节所在区域的入口条不算被盖住；或最大化的那一节自己画头。
  - 第 2 条：并进入口条的头跨两片叶，`panelOf`、悬停动作的范围、焦点记录、标题行上的落点、`layoutContents` 的 `insetTop` 都按叶认面板；“只有一节”按文档还是按呈现判要定。审查给的退路（每节保留自己的头）会推翻决定 9，不采纳。
  - 第 8 条：实时拖放的入口带（`DragGeometry`、`FrozenGeometry` 的入口带只有一条，`barAfterCollapse` 只认侧栏，`collapsed()` 的平移不认入口条叶），写进拖放那一片的文件清单。
  - 第 9 条：入口条让区域的最小高度从 80 变成 112（输出 6 写至少 80）。推荐：只有一节、头并进入口条时那一节的最小改成 48，区域合计仍 80；几节时每节照旧 80。
  - 第 12 条后半：`regionStrip` 的叶 `ref` 与包装分支 id 后缀要由库导出构造与反解函数；`regionAnchors` 的契约在带入口条的区域不再是“单节塌陷成叶”，注释与说明要改。
  - 第 14 条：入口条旁唯一的分节仍被分到收起策略（`assignByParent`），跳过；第 3 稿“区域隐藏时没有入口条”与“按拖到零画”的措辞冲突。
  - 交换的静止底（`swap-backdrop`）与 `window` 只在这里用；待确认清单里第二轮第 11 条的卡片层候选若被采纳，静止的底就不需要了。
