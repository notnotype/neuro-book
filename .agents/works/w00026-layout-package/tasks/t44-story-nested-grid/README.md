## 有意的差别

计划列的四条之外，探针多量出一条（第 5 条）。都记进了[待确认清单](../../pending-confirmations.md)：

1. 抽屉开合时内容整张跟着外框从右边滑进滑出（原来内容静止、外框像幕布擦开）。
2. 只在抽屉参与手势时写宽度偏好。
3. 平板档导航那条线停用。
4. 首次打开按窗口宽度定档。
5. 导航收起再展开回到收起之前的宽度（原来固定回到 188）；导航宽度不进偏好，刷新后仍是 188。

另有两处读屏的变化：主区与抽屉那条线的取值范围变成真实可达的范围；平板档多一条 0 宽、停用的分隔线。

## 接入记录（第一个外部使用方用 nb-layout 公开面的体验）

给 t47（发布）、t48（API 报告与稳定性标注）、t49（手感编排进库）看。宿主为下面几处写了补丁或接受了差别：

- **分隔线的读屏名称是节点 id**：`NestedGrid` 与 `Splitter` 都把相邻两块的 id 代进“调整 {before} 与 {after} 的宽度”，nb-story 读出来是“调整 nav 与 main 的宽度”，工作台是 `section:…`、`g0` 一类。公开面没有给叶或面板起显示名的口子，宿主只能把 id 起成人话，而 id 同时是身份（e2e 与持久化都靠它）。建议加可选的 `label`（叶与 `Splitter` 的面板配置）。
- **最右一栏的内容不能贴右**：库只对“左边不动、右边在动”的叶贴右（`grid-motion.ts` 的 `rightAnchored`），最右的详情栏开合时左边在动，内容跟着左边缘走，做不出“内容静止、外框擦开”。缺按叶的内容锚点。
- **“这一栏此刻不存在”没有状态**：平板档抽屉是浮层，栏只能收到 0 加停用，留下一条 0 宽、停用的分隔线，读屏会读到；或者增删叶，要走过渡与版本的先后。缺“叶隐藏但保留 id”，或“零宽邻居的分隔线不进读屏”。
- **过渡时长只有一档**：`NestedGrid` 只读 `--nb-layout-motion-layout`，宿主要“控件形变那一档”只能覆盖变量。
- **收起状态要宿主自己对账**：库推荐从网格读收起状态，但宿主有自己的模型（抽屉开没开），网格又能自己改收起（拖过阈值、Enter）。没有“收起状态变了”的事件，只有 `onApplied`（只管手势）与 `setCollapsed` 的返回值，对账只能宿主写。
- **正在关的叶的内容**：宿主要经模板 ref 读 `outgoingLeaves` 才能在关的过程中接着画；它写在 `NestedGrid.md`，不在 Spec 的“时序与寿命”里。更自然的是 `leaf` 插槽的作用域直接给 `outgoing`。
- 顺手的地方：`useGridHost` 整包绑定、`setCollapsed`、`sashDisabled`、`sashSize` 的函数形式都直接够用；减少动效、设备像素对齐、键盘都不用宿主管。
