F01  重要 | 事实错误 / 违反包边界 | tab-strip-geometry.ts 放在 nb-layout 核心里读 DOM
==================================================================
位置：plan.md:51（packages/nb-layout/src/tab-strip-geometry.ts）、plan.md:53；packages/nb-layout/tsconfig.json（lib 只有 ESNext）、packages/nb-layout/AGENTS.md“边界”第一条

现象：计划把 resolveStripInsertion 搬成“纯读 DOM”的 resolveTabStripInsertion(strip: Element, ...)，路径是 nb-layout 的 src/ 根，也就是核心（. 入口）。

为什么是问题：核心的合同是“不依赖任何包，不依赖 Vue 与 DOM”，tsconfig 的 lib 只有 ESNext，没有 DOM 类型。核心里写 Element、getBoundingClientRect 过不了 tsc。src/boundary.test.ts 只查 import，抓不到，但 typecheck 会红。

另外，现有 tab-drag.ts 本来就是两层：DOM 读取（linesOf、resolveStripInsertion）和纯算法 resolveListInsertion（已经在核心里，只吃矩形）。

建议改法：拆成两件。读 DOM 的部分（linesOf、visibleTabStops）放 src/vue/（或 TabStrip 的 expose），产出矩形和标签 id 的数据；核心里留一个纯函数，吃“行、成员矩形、点”，返回结果。核心的单元测试用矩形造数据，不需要 happy-dom。计划里“纯读 DOM”的说法要改，切片 1 的“nb-layout 单元”验证也要跟着改成两层。

F02  重要 | 接口 / 遗漏 | resolveTabStripInsertion 的返回值丢信息：index、partition 在单行固定标签、“收进更多”时都不对
==================================================================
位置：plan.md:45、53、55；packages/neuro-book/src/plugins/editor/web/tab-drag.ts:55-93；packages/neuro-book/src/plugins/workbench/web/layout-drag.ts:94-107、237-241；packages/nb-layout/src/layout-drop.ts:36

现象：计划让函数“只认 [data-tab-row]、[data-panel-tab]”，返回 {index, partition, indicator, inPlace}，partition 来自分区；单行（wrapTabs 关）时“一个分区”。

问题一，partition 在单行里没法从 DOM 得到。现在的实现（tab-drag.ts:71、77）在单行里用每个标签的 data-editor-tab-pinned 判断落点属于固定区还是普通区（Spec editor 50、55：落点跨过固定与普通的分界时随之固定或取消固定）。计划里单行只有一个分区、行上没有区别，函数无从知道插在固定标签前面还是后面，editor 拿到的 part 恒为同一个值，单行模式下拖动不再能固定或取消固定。

问题二，index 的参照系。现在编辑器的 index 是“这组全部标签在呈现顺序里、摘掉来源之前的位置”（tab-drag.ts:91），靠的是 DOM 里有全部标签（滚出视口的也在）。工具面板用 adapt 时，收进“更多”的标签不在 DOM 里，现在的 insertionIn（layout-drag.ts:94-107）要拿文档的 tabs 做映射，并且约定“收进更多的排在最后一个看得见的后面”。只吃 Element 的通用函数做不到，调用方只能拿到“看得见的标签里的第几个”。

问题三，LayoutDropPanelGeometry.insertionAt(point) => number（layout-drop.ts:36）只返回数字，没有 part、indicator、inPlace。计划只说“工作台直接量 [data-panel-strip=<面板>] [data-tab-strip]”，没有说编辑器路径现在由 editorStripDrop 带回的 part、indicator、inPlace（layout-drag.ts:237-241）在统一后从哪来，LayoutDragDrop.part 怎么给工具面板用。

如何核实：读上面三处；在 wrapTabs 关、有固定标签的组里，现有 e2e 的拖动固定用例就是这条路径。

建议改法：函数返回“前一个、后一个看得见的标签 id”（或 beforeId，null 表示最后一个看得见的之后）、所在行、插入线矩形，不返回 index 和 partition。宿主自己有完整的 items（含 partition、含收进更多的），由宿主把 beforeId 换成文档下标、把邻居的 partition 换成 part、判 inPlace。TabStripItem.partition 就是为此留的字段，单行时分区取每个 item 的 partition，不取行。LayoutDropPanelGeometry 的 insertionAt 返回值改成对象（index、part、indicator、inPlace），或者把 strip 的度量整体交给宿主回调。

F04  重要 | 时序 / 事实偏差 | 头高变化“立刻跟”的方案没有挡住过渡：真正的过渡来自 data-moving 的 CSS，不是 decideMotion
==================================================================
位置：plan.md:66；packages/nb-layout/src/grid-motion.ts:28-40（placementMoved）；packages/nb-layout/src/vue/useGridMotion.ts:59-73（decideMotion）；packages/nb-layout/src/vue/NestedGrid.vue:366-372、438-443；packages/nb-layout/src/vue/useContentLayer.ts:75-80

现象与证据：

(a) 计划写“decideMotion 把‘只有 inset 变了、叶矩形都没变’判成瞬时”，像是现成行为。实际 decideMotion 判“动不动”靠 placementMoved，而它对活动内容项比的是内容矩形（item.rect，= 叶矩形减 inset）。inset 变化使内容矩形高度差几十像素，超过 1px 容差，placementMoved 返回 true，decideMotion 返回 move。要做到计划说的行为，需要改 placementMoved（比较叶矩形与 inset 分开），这是库的合同变化，不是“表驱动补测试”。

(b) 更要紧的是，就算 decideMotion 返回 none，内容外框的过渡也不由它控制：NestedGrid 只要 moving 为真，所有 .nb-grid-content[data-moving] 都带 transform/width/height 的 470ms 过渡（NestedGrid.vue:438-443）。头高会变的典型时刻正是外框在过渡中：显示或隐藏侧栏、拆分、关闭编辑组，同一时间本组的宽度逐帧在变（内容 following，头在叶里是 100% 宽，跟着重排），多行标签的行数在过渡中途变一两次。头（在外框里）当帧就多出一行，内容层的上边却要用 470ms 滑过去：内容层的 z-index 比外框高（NestedGrid.vue:407-413），多出来的那一行标签会被内容盖住，直到过渡结束。

如何核实：读上面几处；在 happy-dom 之外要用真实浏览器：一个 3 行标签的编辑组，切换侧栏，观察头底与内容顶。（没有跑 e2e，从代码推断。）

(c) 同一处还有：首帧用 34、测到再改。编辑器未交付（editorArea 为 null）时头是空的，没有可观察的元素，inset 永远停在 34，欢迎文字上面留一条空带；计划没说这种状态的 inset 应是 0。

建议改法：不要把头高当 insetTop 经 transform/height 过渡。把头高作为一个不过渡的量：例如 Surface 把实测头高写成外框上的 CSS 变量，内容内层 body 用 margin-top/padding-top 吃掉它（NestedGrid 的外层矩形仍是整叶），或者保留 insetTop 但让它的变化在 style 上带 transition: none（按“只有 inset 变”的那一次更新）。还要给 placementMoved 写明：叶矩形、内容的 insetTop 分开比。Spec 要同步改（见 F13）。editorArea 为 null 时 insetTop 取 0。

F05  重要 | 事实错误 | “组矮时正文至少留一行字”：calc(100% - 44px) 的 44 对不上，头无法知道正文区自己需要多高
==================================================================
位置：plan.md:66；packages/neuro-book/src/plugins/editor/web/components/EditorGroup.vue:331-348、356；packages/neuro-book/src/plugins/editor/web/components/EditorBreadcrumbs.vue:248；docs/specs/workbench/editor.md 输出 54

现象：现在靠 flex 分配：头 flex: 0 1 auto（可收缩、min-height 34），面包屑行、进度条（2px）、横幅不收缩，正文 min-h-7（28px）。Spec 54 的要求是先给正文留一行字、再给提示条与面包屑它们本来的高度，余下才给标签区。头搬到外框以后，头不知道内容层里面包屑和横幅有多高，计划用常数 44 顶替。

为什么是问题：面包屑行 26px + 进度条 2px + 正文最小 28px = 56px，有文件标签且面包屑设置开着时 44 不够，少 12px，正文被内容层的 overflow: hidden 裁掉一截（e2e 现有用例量的是 [data-editor-content] 的盒高 >= 28，盒高由 min-h-7 保证，被裁掉了量不出来，所以它不会红）。页面标签、关面包屑时又多留了。横幅（冲突、已删除等）出现时更不够。这个数是由内容层的状态（设置、活动标签种类、横幅）决定的，常数不对。

如何核实：EditorBreadcrumbs.vue:248 高 26px；EditorGroup.vue:346 进度条 h-0.5；:356 min-h-7。把组拆到最小高度 120px，开面包屑、打开 4 个以上标签使标签区多行，量正文区可见高度。

建议改法：insetTop 不由头独占。Surface 取 min(头的自然高度, 叶高 - 内容区的最小需要)，内容区的最小需要由内容自己报（例如内容层根上 min-content 高度，或编辑器区把“面包屑行 + 进度条 + 横幅 + 28”作为 CSS 变量/回调交给 Surface）。至少在计划里写明 44 是怎么来的，并改成上面的和；e2e 用例要真的量正文可见高度。

F10  重要 | 接口 | 键盘停靠点：stripCount 只给个数，“只算看得见的”之后下标对不上；滚出视口的从“算错”变成“够不到”

位置：plan.md:53、101；packages/neuro-book/src/plugins/workbench/web/layout-drag.ts:283-291、367；packages/nb-layout/src/layout-drop.ts:211-236（enumerateDropCandidates）

F13  建议 | 别扭 / 遗漏 | adapt 的测量层渲染 tab 插槽：盒子样式、只留图标的宽度、可访问名称、重复实例都没有交代

位置：plan.md:24-30、40、49；Tabs.vue:92-96、113-118、226-234

现象与问题：

1. Tabs 的测量层是和真实按钮共用 tabBoxClass 的“同款盒子”，所以量出来的宽度才对得上。TabStrip 的按钮和测量盒在库里，样式在宿主（F09），测量盒怎么拿到宿主给按钮的内边距、字号、间距，计划没说；对不上就是 adapt 的临界点错位，e2e 会在“依次经过四档”（workbench-views 的 15 号验收）时红。
2. Tabs 用一个只含图标的占位量“只留图标”的宽度（data-measure-icon）。TabStrip 的内容在宿主插槽里，库不知道只留图标长什么样，要把 level 2 的插槽渲染一遍才量得到。计划只说“测量层也渲染 tab 插槽”，没有说渲染几遍。

4. 每个标签渲染两遍（真实 + 测量），插槽里有会注册副作用的组件（Tooltip、会订阅的组件）时会实例化两次，测量层如果带了 id 或 data-panel-tab，layout-drag 的 root.querySelector(`[data-panel-tab=...]`)（layout-drag.ts:119）可能先命中测量层的副本。当前只有工具面板用 adapt，插槽里只有图标和文字，风险小，但库的合同应写明“测量层的内容不带 id、data-* 与交互”。

建议改法：把“测量层怎么得到盒子样式”写进 TabStrip 的合同：测量盒和真实按钮用同一组类（库给 frame/button 类，宿主 :deep 或 itemClass 同时作用在两处）；插槽收到 level 与 measuring 两个参数，测量层以 level 2 再渲一个样本；iconOnly 时库写 aria-label=item.title。
