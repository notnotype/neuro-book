### 1. 同一棵离开的子树里，没有留着内容的叶，面板头没有冻结
- 严重程度：重要（静态推断，未实跑）。
- 类别：正确性、对照合同。
- 位置：`NestedGrid.vue:167`（`frozenLeaves`），`grid-motion.ts:300` 前后（`mounted` 与 `leaves.some(mounted)`）。
- 现象：`leavingPlacements` 按组判断，组里任何一块叶有挂着的内容，整组叶都留着。这次 `mounted` 又加入了“宿主去掉、标了留住的活动内容项”，所以关一列时，只要其中一块叶带着留住的内容，同列另一块叶也会被留着缩回去。`frozenLeaves` 只冻“有留着的内容”的叶（`leavingContents` 与 `leavingLeaves` 的交集）。同列另一块叶的情形有：没有内容项，内容没标 `retain`，或内容不活动。它的面板头插槽照常被调用，传入的是已离开的 node，而宿主在同一个同步段里已经删掉了它的数据。
- 为什么是问题：在这次改动之前，这样一组只有宿主保留着挂着的内容时才会被留，数据也还在。现在宿主删光数据的组也会被留，插槽会读到没了的数据，例如 `heads[node.id]!.title` 抛 TypeError。Spec 156 写“别的离开的叶照常渲染”，针对的是区域隐藏和交换里滑出去（数据都在），没有考虑这条新来源。
- 如何核实：用 `LeavingHost` 夹具再加一个竖分支，里面两块叶，只有一块有标 `retain` 的内容。同步删分支、两块叶的 `heads` 和那一项内容，再看错误处理收到什么。
- 建议改法：把这组里因留住的内容而留着的叶都冻住。例如 `leavingContents` 非空时，不在交换带上的 `leavingLeaves`（`move.leaving` 里非 `plan.leaving` 的）一起冻。或者 Spec 156 明确写出“同组没有留着内容的叶，宿主要自己保留面板头的数据”，并给用例。

### 4. 说明报错对任何后代错误都说“渲染失败”，生产环境也输出
- 严重程度：建议。
- 类别：代码质量。
- 位置：`frozen-slot.ts:28-35`。
- 现象：`onErrorCaptured` 会收到后代的所有错误，包括事件处理、watcher、定时器、生命周期，不只是渲染。冻住期间任一错误都会输出“something inside failed to render … read data the host has already removed”。例如留着的组件里一个 `setInterval` 每次抛错，过渡期间每次都输出一条，而原因可能与宿主删数据无关。`console.error` 也没有只在开发期输出的判断。
- 建议改法：只在错误是渲染期抛出的时候补说明，或把措辞改成“可能是”。同一项冻住期间只报一次，或者限定在开发构建。

### 5. 宿主在叶仍在缩回去时补回同一个内容 key，`leavingContents` 不会被修剪
- 严重程度：建议（静态）。
- 类别：不变量。
- 位置：`useGridMotion.ts` 的 `update`，`decision.kind === "none"` 时不动 `leavingContentItems`；`useContentLayer.ts` 的 `placements` 去重。
- 现象：补回的是内容、叶仍离开，布局没变时，这一轮 `placementMoved` 为假，走 `none`，旧的 `leavingContents` 留着。内容层靠 `placements` 的 `present.has(key)` 去重，所以不叠两份。但 `frozenLeaves` 读的是没修剪的 `leavingContents`，这块叶的面板头继续冻着，直到下一次布局变化或 `stop`。
- 影响：窗口小，只在叶仍离开时补回内容，面板头多冻一段过渡时间。

### 6. 留着的内容没有 `data-leaving` 时不吃 `pointer-events: none`
- 严重程度：建议（静态，影响不确定）。
- 类别：一致性。
- 位置：`NestedGrid.vue:900` 的样式（`.nb-grid-content[data-leaving]`）与第 733 行的模板。
- 现象：`data-leaving` 只在叶是离开的叶时才有。内容的叶是“降到零但还在树里”时（`collapseAndDrop` 那种），留着的内容只有 `data-content-leaving` 和 `inert`，没有 `pointer-events: none`。样式注释说这样做是为了命中判定看到底下。`inert` 是否等价取决于宿主的命中实现，我没验证。
- 建议改法：把 `.nb-grid-content[data-content-leaving]` 加进同一条选择器，或在 e2e 里用 `elementFromPoint` 断言。

### 7. 每块叶、每个内容项多一个组件实例，并依赖 Vue 3.5 的内部行为
- 严重程度：建议。
- 类别：代码质量。
- 位置：`frozen-slot.ts`、`NestedGrid.vue:717、742`。
- 现象：
  - 每块叶、每个内容项各多一层 `FrozenSlot` 组件实例，插槽的依赖现在记在它身上，不再记在 `NestedGrid` 的渲染上。这是行为变化：宿主数据变了只重渲染那一个 `FrozenSlot`，不再带动 `NestedGrid`。
  - 它依赖 `withMemo` 的记号、已挂载的 VNode 不克隆、`patch(n1 === n2)` 早返回。文件头已写明这点，也说“插槽没再被调”的断言会先红。但 `peerDependencies` 是 `vue ^3.5.24`，放开了后续 3.x。
- 建议改法：保持现状，但在 Vue 升级的清单里单列这一条。
