### 1. `policy-refused` 的 `tab-limit` 在代码里不存在：757 是骨架规则
- **严重程度**：重要；**类别**：正确性
- **位置**：计划“L2”的 `policy-refused` 一行；`layout-doc.ts:627-629`、`:756-757`
- **现象**：计划把 757 归 `policy-refused`、`by: "tab-limit"`（“标签数上限”）。读 `insertTab`：757 的 `refusal` 来自 `refusesMoreTabs`，它只返回“区域的锚不放标签”或“分节只有一个标签”。代码里没有任何“标签数上限”，也没有宿主规则参与（`insertTab` 没有 `policy` 参数，源码注释自己写了“这里没有 policy”）。
- **为什么是问题**：照字面实施，实施者要么发明一个不存在的 `tab-limit`，要么把一条骨架规则错归成宿主规则。`policy-refused` 的意思是“宿主给的规则拒绝”，应用以后据此区分“我的规则拒了”与“库的骨架拒了”，归错了就是错的合同。同一原因在 817、845 又归 `not-allowed`（`anchor-holds-no-tabs`），同一原因两个码。
- **如何核实**：读 `layout-doc.ts:627`、`:754-758`、`:817`、`:845`。
- **建议改法**：757 归 `not-allowed`，`rule` 为 `anchor-holds-no-tabs` 或 `single-section`（`refusesMoreTabs` 改返回 `rule` 而不是文字）；`policy-refused` 的 `by` 只留 `accepts`、`can-insert`。计划里“`rule`……一处一个”改成“一种规则一个名字”：815、844 与 1030、1067 本来同文，应同名，不然测试按 `rule` 区分不出来源处。

### 3. “`issues` 只发新增”没有定义，按字面实施仍会逐帧重复发
- **严重程度**：重要；**类别**：正确性
- **位置**：计划“`issues` 只发新增”“测试迁移规则”；`useSashGesture.ts:321-330`、`useGridLayout.ts:76-78`
- **现象**：`flush`（每个 rAF）都 `pushIssues(current.session.issues)`，而 `session.issues` 是上一次求解的状态（`grid-gesture.ts:224`、`:321`），指针不动时也是同一批；`not-collapsible`、`no-room-to-restore`、`over-constrained`（sash-drag 247）在整场拖动里每帧都在。今天是累积进 8 条的窗口，新做法是每帧把同一批当一批发出。`useGridLayout.recompute` 每次重算也把 `next.issues` 整个再发一遍，窄窗口里就是“每次布局都发”——提案体验 10 要治的就是这个，计划只合成了“一次里几条”，没解决“每次都发”。
- **为什么是问题**：“新增”的判据（同一场手势内、同一布局世代内同 `code` 加同 `params` 算不算新）没写。计划的验收只有“连续两次被拒的提交，第二次事件只带第二条”，覆盖不到这两处。
- **如何核实**：读 `useSashGesture.ts:321-330`；在 Lab 里窄窗口拖一根线数 `issues` 事件（不跑 e2e，写进报告）。
- **建议改法**：Spec 139 写明去重键（`code` + 规范化的 `params`）与作用域（一场手势、一个布局世代），实现里 scope 与 `useGridLayout` 各留一个“上次已发”的键集；补两条用例：同一场拖动里同一诊断只发一次、窄窗口连续 resize 只发一次。

### 12. `params` 的取值形状有几处隐患
- **严重程度**：建议；**类别**：正确性
- **位置**：计划“共同形状”第 3 条
- **现象**：`ids` 用逗号连成字符串，而 L0 的 id 是“任意合法字符串”（`grid-types.ts` 的注释写“任意合法字符串 id 都可安全索引”），含逗号的 id 就拆不回来；`swap-skipped` 的 `ids` 今天用“、”连（`grid-swap.ts:132`）。`number` 里的 `NaN`、`Infinity` 序列化进 JSON 日志会变成 `null`，计划写的“可以直接序列化进诊断日志”不成立（`invalid-argument` 的 `value?` 正是这类值）。
- **建议改法**：值允许 `string | number | readonly string[]`，与 nb-ui 的 `TextParams`（`Readonly<Record<string, string | number>>`）的差异写明；或者 `ids` 用 `\n` 等不可能出现在 id 里的分隔，并把非有限数写成字符串。
