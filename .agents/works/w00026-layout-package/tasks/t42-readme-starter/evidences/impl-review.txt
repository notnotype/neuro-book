### 1. 约定第 1 条没说快照不存 sizing、最小尺寸、收起策略，恢复后左栏不再是固定宽、也收不起来
**严重程度**：重要　**类别**：准确　**位置**：`packages/nb-layout/README.md:118`（起步例子 `:46` 的 `saved`）

**现象**：
- 起步例子的左栏是 `sizing: "fixed"`、`minimumSize` 160，带 `collapse`。
- 实验 `exp/a.ts`、`exp/b.ts`：`serialize()` 里的叶只有 `id`、`ref`、`size`。
- 用 `createGrid(null)` 加 `restore(snap, ref => ({ref}))` 恢复，返回 `ok` 且 `dropped` 为空，但 `files` 变成 `sizing: "weight"`、最小 0、没有 `collapse`。
- 800 宽下 `files` 是 227.4（原 240）；拖到收起后再存、恢复，是 173.8。
- 此时 `setCollapsed("files", true)` 返回 `not-collapsible`。
- 只有解析函数返回 `{ref, sizing, minimumSize, collapse}` 才回到 240。
- README 只写“可以顺带给约束与收起策略”，读起来像可选项。

**为什么是问题**：
- 体验审查第 7 条明确要求把“收起状态不进快照”和约束表示例放进 README。
- Spec 实现合同也写了“快照 v2 不存运行约束”。
- 现在的措辞让人以为只返回 `{ref}` 就够。
- 退化是静默的：恢复成功、没有诊断，要等到左栏收不起来才发现。

**建议改法**：
- 改成“快照只存结构、ref 与两轴尺寸意图；sizing、最小/最大尺寸、收起策略（含 collapsed）都不存，解析函数要按 ref 重新给”。
- 加一个三行的解析表例子，直接用 `files`。

### 2. 起步例子最外层 `height: 100%` 依赖 README 没写的祖先高度，复制到新项目里可能塌成 0 高（推断）
**严重程度**：重要　**类别**：可用　**位置**：`README.md:69`（`StarterScene.vue` 同处）

**现象**：
- 例子最外层是 `height:100%`，里面是 `flex:1; min-height:240px` 的框，再里面是 NestedGrid 根（`width:100%; height:100%`，`NestedGrid.vue:733`）。

- 复制到普通 Vite 项目时，`html`、`body`、`#app` 都没设高度，最外层的 100% 会解析成 auto。
- 按 flexbox 规则，高度不定的列容器里，flex 项的子元素百分比高度也是不定的。
- NestedGrid 根很可能是 0 高，`extent` 高为 0，布局为空、分隔条停用，页面空白。`min-height` 只保证外盒 240px，不保证里面的 100% 能解析。

**为什么是问题**：
- README 自己说“承载盒要有确定的高度”，例子本身却没给出确定高度。
- `readme.test.ts` 与 e2e 都在 Lab 的定高祖先里跑，“复制就能跑”没被验证。
- 高为 0 本来就合法，读者看到空白页却没有任何诊断。

**建议改法**：
- 例子最外层改成显式高度，例如 `height: 480px`；或在例子前写明“放进有确定高度的父元素，`html`、`body`、`#app` 设 `height:100%`”。
- 加一次“祖先无定高、外层 480px”的探针。
