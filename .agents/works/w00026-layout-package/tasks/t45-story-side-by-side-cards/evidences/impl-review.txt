### 1. 开会话时的地址与存下状态的合并规则，没有任何自动化验证
- 严重程度：重要
- 类别：测试
- 位置：`src/web/host/book.ts:218-250`；`e2e/side-by-side.e2e.ts:271-278`
- 现象：这段新逻辑包括四个参数按组取、`fromUrl` 判定、两张并行核对、去重、“某张没出现就提示并把留下的放左边”。`host/` 下没有 `book.test.ts`，`openBookSession` 没有单测。e2e 里只有“地址带 `entity2`、`tab2`，刷新后仍并排”这一条。

### 3. 运行中的“同一内容”按原始 id 比较，规范化只在开会话时做一次
- 严重程度：建议
- 类别：正确性
- 位置：`src/web/host/details.ts:447-458`（`sameContent`）；`src/web/host/book.ts:240-250`
- 现象：`entityCard` 返回的 `id` 是同一身份分组的代表（`core/queries/entities.ts:83`），原始 id 和它可以不同。开会话时按规范化后的 `id` 去重，运行时点出来的人只比原始字符串。
- 为什么是问题：
  - 左边开着 A，从别处点到 A 的另一个成员 id（例如名册、关系图、问答的 `@`），或者阅读位置往后拨、两个身份合并后，会出现两张显示同一个人的卡。
  - 地址里是 `entity=A&entity2=A'`，刷新后按输出 69 只剩一张。状态与刷新后的结果不一致，也没有提示。
- 如何核实：`bun -e` 对 `openBeside` 先后传 `"a"` 与 `"a-alias"`，得到两张（我跑过，`toView` 也写出 `entity2=a-alias`）。要看真实数据，需要一本有身份合并的书。
- 建议改法：窄场景，按“窄边角倾向简单”的约定，在 Spec 输出 69 或 README 记为已知限制即可。不要为此在运行时再调 `entity.card`。

### 6. 提示顺序取决于请求完成顺序；空串参数会让存下的状态整组被丢掉

### 7. 窄档关浮层后放宽，两张不会回来
- 严重程度：建议
- 类别：需求对照
- 位置：`src/web/host/book.ts:526`（`closeDrawer`）；Spec 66
- 现象：平板或手机上点遮罩、按 Escape 调的是 `closeDrawer()`，等于整块收起（`open=false`）。放宽回宽屏时详情仍是收起的，要点顶栏开关才回来。Spec 66 写“回到宽屏两张回来”，e2e 的平板用例（第 307-317 行）先点遮罩、再 Ctrl 点，才放宽，这条路径被绕开了。
- 为什么是问题：这条规则没有被明确。你们可能认为“用户关了就关了”，但 Spec 没有写。
- 建议改法：要么在 Spec 66 写明“在窄档里关掉浮层就是整块收起，放宽后要用顶栏开关展开”，要么让窄档的关浮层只记“浮层不显示”。我倾向前者，复杂度低。
