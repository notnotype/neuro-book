## 阻断

**1. `swap.node` 没有稳定的 id 可填**（类别：接口 / 遗漏；位置：计划“交换过渡”“切换容器时发 swap”；`packages/nb-layout/src/layout-project.ts:131-134`）
- 现象：计划写“`node` 是区域在呈现树里的节点（投影已登记）”。但投影里单子分支会塌陷成幸存的叶（`{...survivor}`）。区域有两节以上时节点是分支 id（文档树的区域节点），只有一节时它就是那一节的叶 id。
- 为什么是问题：切换容器常见的几种情况，新旧两侧都没有同一个节点 id。2 节换 1 节，是分支 id 换叶 id。1 节换 1 节，是两个不同的叶 id。`nodeRectsOf` 只能按当前帧或上一帧各自的叶与 path 求矩形，一个 `node` 字符串在两帧里对不上，裁切窗也就无从定义。
- 如何核实：构造“项目”2 节、“大纲”1 节的侧栏，打印切换前后 `projection.regionAnchors` 的键。
- 建议：`swap` 不要用节点 id。改成 `{leaving: string[], entering: string[]}` 这类叶 id 列表，窗口取两侧并集或宿主直接给矩形（见第 5 条）。

**2. 相连叶之间的那 1px 分隔条没有任何一张卡片去画，“一张卡片”会有缝**（类别：正确性 / 视觉；位置：计划“一个容器一张卡片”；`adjacency.ts:118-119`、`layout-project.ts:136`、`SashHandle.vue:351-368`）
- 现象：同一区域两节之间的分隔条仍占 `SASH_PX = 1` 的流内空间。计划里 `joined` 的内缩是 `0px`，两张叶卡片各自贴到外框边，中间是这 1px 的分隔条。分隔条只在长轴两端各缩进 10px 的中间段画线（`.sash-seam` 的 `top/bottom: var(--nb-splitter-seam-inset)`），两头各 10px 没有背景。
- 为什么是问题：线的两端各露出 1px × 10px 的窗体底色，浅色的淡投影和深色的 1px 外框也在这里断开。这正好违反开发者要的“不碰卡片边”和“一个容器一张卡片”。现有的活动栏与侧栏相连处没有这个问题，因为条两侧的缝宽恒为 0（`layout-project.ts:136`）。
- 如何核实：nbook 浅色、深色各截一张两节侧栏，放大线的两端；再读分隔条在端点处的计算背景。
- 建议：给相连的 `panes` 分隔条整条画卡片底色，并让它自己带上外框或投影在这 1px 上的那一段。或者让相连的叶沿分隔条向对方伸出半个缝宽。计划的验收映射里没有对应的像素用例，要补。

## 重要

**3. “角接过去”的条件会把交换里离开的叶当成“缩回去”，每次切换都触发活动栏的 cap 画法**（类别：被破坏的既有约定；位置：`WorkbenchSurface.vue:255、258-262、277-282、549-561`；计划“角接过去扩到整列”）
- 现象：`capLeaf` 的条件是“在 `shapedLeaves` 里、左边相连，且 `drawnAsBefore(id)`（离开的叶也算）或 `freshlyJoined`”。现在切换容器时旧叶是被顶替、不留着，所以不会命中。计划让旧叶留着并进 `keptSize`，它们就成了 `outgoingLeaves`，`capLeaf` 非空。
- 为什么是问题：活动栏会换成断开的右边，面板形状往左伸出去，短线淡出。这违反 Spec 输出 19 的“切换容器时……活动栏前后都相连，不换画法”。计划只处理了 `freshlyJoined`（“切换容器不算刚连上”），没处理离开这一侧。
- 建议：`capLeaf` 的“缩回去”改成“宽度降到零”这一种，不含交换中离开的叶。补一条 e2e：切换容器的整个 470ms 里，活动栏的 `data-shell-cap` 和短线不透明度始终不变。

**4. 反向重定向时，仍在滑出的旧块和新进的块会穿过彼此**（类别：正确性；位置：计划“滚到一半又换”）
- 现象：入口顺序为 C、A、B。点 A 切到 B，B 从下进、A 向上出。滚到一半点 C，B 改成向下出，C 从上进，A 还在向上排空。
- 为什么是问题：计划写“新的接在这一刻看得见的最外面那一块后面，不跳、不叠”。按这个规则，C 的起点在 A 当前位置之上，A 的终点是 `-(L+缝)`，C 的终点是 0。C 向下、A 向上，两张不透明卡片在途中必然相互穿过。同向重定向没问题。
- 如何核实：写个纯函数用例，算 A、C 的区间在 `t ∈ [0,1]` 是否相交。
- 建议：改成“胶片”模型：所有块按入口顺序摆在一条带上，只有一个滚动偏移量在过渡。重定向只换目标偏移，不会穿叠，也不会跳。或者方向翻转时把仍在排空的块一起折返。

**5. `swap` 接口表达不了本计划自己需要的裁切窗和缝**（类别：接口；位置：计划“交换过渡”“切换容器时发 swap”；决定 8）
- 现象：`{node, axis, direction, token}` 里没有窗口，也没有缝宽。但右栏、底部面板要“裁在卡片里顶上一行以下”，侧栏要裁在卡片这一级。
- 为什么是问题：
  - 帧矩形比卡片大：外缘有整缝、相邻有半缝（`cardInset`）。窗口取节点矩形，卡片会进到缝里才被裁。
  - 行程“节点长度加一条缝”也没算清。两侧叶各自带 `outer` 缝，已经有约两条缝宽。再加一条缝，卡片间距约三条，开发者要的是一条。
  - 这是决定 8（通用工具、以后发 npm）要的接口，不能靠宿主去假装改 `leafShape` 来凑。
- 建议：`swap` 加 `window`（相对节点矩形的四边内缩）和 `travel`（相邻两块之间的偏移）。由宿主给，nb-layout 只管平移和裁切。
- 附带：新容器的最小宽度比当前大时，区域本身会在同一次布局里变宽。计划没说窗口、旧叶终点按新还是旧的区域矩形。

**6. 滑出的旧内容和旧分隔线在 470ms 里是活的**（类别：可达性 / 焦点；位置：`useLeafParking.ts:25-30`、`useContentLayer.ts:78-81`、`NestedGrid.vue:531`）
- 现象：现有的“留着缩回去”靠终点宽度为零来停放。交换里旧叶终点非零，不会被停放。旧叶外框有 `inert`，但内容项没有。`isParked` 只看停放集合，旧内容仍可聚焦、可读屏。离开的分隔线（计划说要留着）也还是 `role=separator`，`aria-controls` 指向旧叶。
- 为什么是问题：焦点在旧分节里时，`content-parked` 要等到过渡结束才发，焦点交接晚 470ms。违反输出 42“焦点原来在被切走的分节里时，交给新容器的第一个分节”。
- 建议：交换中离开的叶、内容、分隔线一律加入停放集合，同时保持可见（沿用 `outgoingLeaves` 的“可见但不可交互”分支）。焦点在切换提交时就交接。

**7. `token` 的消费规则会漏或误用**（类别：边界；位置：计划“交换过渡”第一条）
- 现象：计划写“token 变了才算一次新的交换，之后第一次布局变化消费它，没有变化就作废”，但没写谁来判断“没变化”。
- 失败场景：
  - 点入口时命令结果与现状相同（输出 42 的零写入）、提交被拒，或布局变化只有减少动效。那么这个 token 一直留在 prop 里，会被之后无关的第一次布局变化消费，比如拖一下分隔条或改窗口大小，播出一次错误的滚动。
  - `useGridMotion.update` 里 `duration <= 0` 走 `stop()`，没有消费 token。
  - 同一轮里有别的布局变化先到（`presented` 的第二次发布）。
- 建议：交换只在“这次变化里 `leaving`、`entering` 两侧确实互换”时生效。宿主在 nextTick 后清 `swap`，或把 token 与布局版本号绑定，不靠“下一次变化”。

**8. 顶上一行多让的 32px 没进几何账**（类别：不变量；位置：`layout-project.ts:91`、`layout-present.ts:44`、`layout-constraints.ts:80-81`、`SHELL_PANEL_MIN_HEIGHT = 80`；计划“几何：不进布局树”）
- 现象：计划只改 `layoutContents` 的 `insetTop`。但：
  - 投影里分节收成标题行的 `collapsedSize` 来自全局 `headHeight = 32`。右栏最上面一节收起后只有 32px，要放“行 + 自己的头”共 64px，放不下，自己的标题和展开入口被行盖住。
  - `hasRoom` 用 `height > PANEL_HEAD_HEIGHT` 判可见。64px 头的叶高 40px 时算“有地方”，内容却是零高、被停放，`visibleTabs` 与实际不一致。
  - 最小高度 80 减去 64 只剩 16px 正文。
  - 区域只剩一个容器、行消失时头高 64→32，浮动窗回停靠时同样跳变。
- 建议：头高按叶的位置进约束与投影（`collapsedSize`、`hasRoom`、最小高度），不只改内容项。补验收：右栏顶节收起、40px 高的底部面板。

**9. 顶上一行没有可实现的层位和 DOM 位置**（类别：结构 / 键盘 / 可达性；位置：计划“顶上一行”；`NestedGrid.vue` 的插槽与 z 序）
- 现象：计划写这一行“在外框之上、内容之下”。NestedGrid 的插槽只有 `leaf`（在外框内）、`content`、`overlay`（z 900、`pointer-events: none`）和 `float-chrome`，没有“外框与内容之间、可交互”的位置。放在 NestedGrid 外面，行会盖住 sash 手柄（z 4）。
- 失败场景：
  - 最大化时，最大化的面板盖住区域，行还在上面。计划没写“最大化时行隐藏”。
  - 行在叶外，`panelOf` 找不到所属叶，焦点进入行会触发 `focus-panel(null)`，宿主丢掉当前面板（输出 36）。
  - F6（`moveGridFocus`）按网格内的叶走，行不在链里。
  - 行的读屏结构（`aria-pressed` 按钮组还是 tab）没定。
- 建议：先定行放在 NestedGrid 外、surface 之内，列出：最大化时隐藏、`pointer-events` 只给条目、焦点归属、F6 停靠点、可达性角色。

**10. “区域里有两个以上的容器才有这一行”是计划自己加的，没有出现在开发者的决定里，而且让落点不可达**（类别：需求核对；位置：计划“顶上一行”第一条）
- 现象：单容器的右栏、底部面板没有入口条，也就没有入口右键菜单（输出 44）、没有拖放落点（输出 45、46）。
- 为什么是问题：
  - 想把一个含多视图的容器拖进只有一个容器的区域，输出 46 说它“只能落在入口条上”，但这条不存在。
  - 默认布局里右栏本来就是单容器，用户没法靠拖放建出第二个容器。
  - 活动栏即使只有一个入口也画条。
- 建议：交给开发者决定，写清取舍（总画行 vs 单容器不画），不要作为已定写进计划。

**11. “静止的底”缺少挂载位置，过渡中区域尺寸变化也没法同步**（类别：结构；位置：计划“右栏、底部面板”第 3 条）
- 现象：NestedGrid 没有“外框下面”的插槽，底只能放在 NestedGrid 外面、根之前。宿主拿不到区域矩形，`placeGrid` 的结果不对外。底不走 `useGridMotion`，区域在交换中同时变宽（用户同时拖了侧栏）时，底和滑动的外框不同步。
- 另：深色外框是 `0 0 0 1px`，底、外框对接的那一帧（`data-swap` 摘掉）要同一次渲染换，否则有一帧双层或无层。
- 建议：通过 NestedGrid 暴露区域矩形，并让底的位置过渡走同一条 `left/top/width/height`。

**12. 把投影改成伪元素画，既没有必要，计划写法也画不出来**（类别：上游选择；位置：计划“投影与外框”；`WorkbenchSurface.vue:503-513`）
- 现象：现在的投影和外框是画在 `.workbench-surface__card` 上，外面套着 `overflow: hidden` 的 `.workbench-surface__slot` 和 `overflow: clip` 的 `.nb-grid-frame`。内缩为 0 的一边，阴影和 1px 外框自然被裁掉。这正是活动栏与侧栏相连处现在的做法。
- 为什么是问题：
  - 相连的边本来就没有投影，不需要“伪元素、四边各自伸出去”。
  - 计划写的伪元素放在卡片内部，会被卡片自己的 `overflow: hidden` 裁掉；要画就得放在 slot 上，仍受 slot 的 `overflow: hidden` 限制。
  - 它还会改动所有卡片（编辑组、浮动窗），风险大。
  - 真正要补的是第 2 条的 1px 缝。
- 建议：保留现有机制，删掉伪元素这一项，只修分隔条那 1px。理由是第 2 条的根因在分隔条，不在投影。

## 建议

**13. 其他遗漏**（类别：遗漏 / 验收；位置：计划“入口的选中标记”“入口条的拖放”“验收映射”）
- 选中标记做成独立的块，位置从“当前入口的量取”来。但活动栏的入口列表有 `TransitionGroup` 换位（拖动中滑动）、“更多”收进、窗口大小变化、侧栏隐藏淡出后再显示，块的位置在这些时刻怎么跟，计划没写。
- `layout-drag.ts` 的 `geometryOf`（374-381 行）用 `[data-panel-head]` 作 `strip`、叶卡片作 `frame`。顶上一行在叶卡片里却不在 `strip` 里，落在行上的点既不是 `strip` 也不是 `body`；只有一节并成一行后，`[data-panel-head]` 在行里而不是叶里。风险一节只说“要区分”，没说怎么改量取。
- 并成一行后，标题、视图动作、框架按钮、容器入口在窄宽度（区域最小 160px）下的让位顺序没定。
- 验收映射缺少：重定向穿叠、焦点交接、减少动效下 token、最大化时行隐藏、顶节收起、1px 缝的像素用例。

## 末尾风险逐条判断

1. **顶上一行不进布局树**：低估了。风险不只是拖放落点，还有第 8、9、10、13 条的几何账、层位、F6、最大化、单容器可达性。需要先把这些定下来再动手。
2. **静止的底和外框对接那一帧**：判断对，但漏了底的挂载位置和区域尺寸同步（第 11 条），不只是变量要对上。
3. **`clip-path` 过渡每帧重绘**：帧时间次要。更要紧的是窗口怎么定（第 5 条）；`left/top` 加 `clip-path` 用同一个时长和曲线，终点线性插值，我没发现重定向时跳变的问题。
4. **投影改伪元素**：判断为不必要，而且按写法画不出来（第 12 条）。建议删掉这项。

## 没发现问题的方面

- `left/top` 加 `clip-path` 同步过渡：沿用 t25 的位置写法，从当前计算值重定向时没有跳变。
- `groupOf`（宿主给区域）：不同区域相邻按组区分，编辑组为 null 恒不相连，浮动窗为 null，设计自洽。
- 每个角按“两侧的边都不相连才圆”：对区域内单轴线性排列成立。
- 减少动态效果直接换、拖动中（`holding`）不交换：与现有 `decideMotion` 的分支一致。
- 隐藏或拖到零时点别的入口按显示长出来、不发 `swap`：与 `hiddenRegionsAtZero` 的现有呈现一致。
- `adjacency.ts` 的 `sideOf` 在邻居是分支时返回分支 id、`groupOf` 取 null，保守不相连，不会误连。
