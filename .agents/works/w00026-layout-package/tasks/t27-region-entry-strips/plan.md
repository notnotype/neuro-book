# t27 计划：一个容器一张卡片、切换容器滚过去、右栏与底部面板的入口条

第 3 稿（2026-11-16，按第 2 稿的设计审查改；审查与处理见 [README](README.md) 与 [`evidences/design-review.txt`](evidences/design-review.txt)）。第 1 稿按“一节一张卡片、几节各自连在活动栏上”写，开发者在评审页第 2 版上否了，作废；第 2 稿的“投影改由单独一层画”“顶上一行不进布局树”“交换按节点 id”三处被审查推翻，本稿改掉。

## Context

开发者 2026-11-16 试用 t25 后要的：活动栏切换容器做成上下滚动；底部面板、右栏也像活动栏一样切换容器、左右滚动；侧栏和活动栏连在一起。三版评审页（[`container-switch`](artifacts/container-switch/index.html)）定下的，编号同 [README](README.md)：

1. `switch-1` 甲：切换时整个容器滚过去，470ms、布局曲线（`--motion-layout`、`--ease-layout`）；滚到一半又点，从这一刻接着滚。
2. `indicator-1`：入口的选中标记和内容同时滑过去。
3. `join-2` 否：几节各自连在活动栏上的画法不要。
4. 底部面板的一个标签（容器）下面可以有几节，左右并排（现有合同，输出 25 第 7 行）。
5. `card-3`：侧栏、底部面板、右栏一个容器一张卡片，卡片之间照旧是缝；卡片里几节之间是开放式分割线（1px，沿长轴两端各缩进 10px，不碰卡片边，旧外壳 [`ui/workbench-shell`](../../../../../docs/specs/ui/workbench-shell.md) 输出 38 的画法）。编辑组照旧一组一张卡片。
6. `strip-3` 甲：右栏、底部面板的入口条是卡片顶上一行，切换时不动；当前容器只有一节时，那一节的标题与动作并进这一行。
7. 第 3 版“直接做”：侧栏整张卡片一直和活动栏相连，切换时整张卡片上下滚；底部面板、右栏的卡片与顶上一行不动，里面的内容左右滚；方向跟着入口条；点当前容器的入口是隐藏区域；区域隐藏或拖到零时点别的入口按显示长出来、不滚；减少动态效果直接换；平铺主题没有缝和圆角、线照旧；隐藏显示同 t25 的丙。
8. 开发者 2026-11-16 看过第 2 稿要点后同意，要求按 autonomous-delivery 推进。

滚动的样子照评审页上的演示（`regionScroller`）：侧栏的裁切范围是整列（含上下的缝），一次滚“区域长度加一条缝”；底部面板、右栏裁在卡片里顶上一行以下，只有内容在动。

合同：[`ui/workbench-layout`](../../../../../docs/specs/ui/workbench-layout.md) 输出 11、19、20、22、36、42、44 到 47；[`ui/nested-grid`](../../../../../docs/specs/ui/nested-grid.md) 的“过渡”；[ADR 0046](../../../../../docs/adr/0046-workbench-view-containers.md)。

约束：开发者 2026-11-16 定 nb-layout 要做成可复用的通用布局工具、以后发 npm（t26）。这次往 nb-layout 里加的三样都是通用的、由宿主驱动：交换过渡（`swap` 与插槽 `swap-backdrop`）、分隔线的样式钩子（`sashStyle`）、带容器的区域在呈现里的入口条叶（投影选项 `regionStrip`，和已有的容器模型同在 `layout-project.ts`，t26 拆通用层时一起处理）。区域怎么分组、卡片怎么拼、入口条里画什么都在工作台。

## 技术选型

无。滚动用现有的过渡机制（CSS 过渡，`left`/`top` 加 `clip-path`），选中标记是一个元素的 `transform` 过渡。

## 关键设计

### 一个容器一张卡片：`web/shell/adjacency.ts`、`web/components/WorkbenchSurface.vue`

- 卡片仍按叶画（扁平渲染器一块叶一个外框），几块叶拼成一张：`CardInput` 加 `groupOf(id): string | null`，宿主给工具面板（含入口条叶）所在的区域；同组、相邻的两块叶之间的边是相连（`joined`：不留缝、两角不圆）。不同区域的工具面板挨着（底部面板与右栏）照旧是两张卡片。
- 活动栏与侧栏：贴着活动栏、在侧栏组里、宽度大于零的每一块叶都相连（整列）。条件从“同一个分支的兄弟”改为“左邻是活动栏、在侧栏组里、宽度大于零”。
- 圆角按角算：一个角圆当且仅当它两侧的边都不相连。`shapeOf`、卡片、内容外层（`content-clip` 的下面两个角）从“左右两侧相连”改为四个角各自给（卡片上四个 CSS 变量）。
- 投影与外框照旧画在卡片上：相连的一边内边距为 0，外面一层（`workbench-surface__slot`）的 `overflow: hidden` 正好在这条边上把投影裁掉，活动栏与侧栏相连处现在就是这样。第 1 片先在 e2e 环境截一张深色的活动栏与侧栏相连处，确认相连的一边没有外框，再推到几块叶上。
- 分隔线：`sashKindOf` 只把同组两块之间的线算作 `panes`；nbook 的 `--shell-pane-divider` 从透明改回 `var(--divider)`（t25 第 4 条改成透明的理由是一节一张卡片，现在不成立）；不同组之间的线照旧取 `--shell-seam`（卡片主题透明）。
- 相连两块之间那 1px 的分隔线占位：两张卡片贴到外框边，中间这 1px 没有卡片，线两端各 10px 露出窗体底，深色的外框也在这里断开。NestedGrid 加 `sashStyle(sash)`（返回写在分隔线元素上的内联样式，同 `leafShape` 由宿主给）；工作台给同组的分隔线写上两侧卡片在长轴方向的内缩（`--shell-sash-fill-start`、`--shell-sash-fill-end`，取 `before` 那块的；同一列、同一排的两块这两边贴着同样的东西），分隔线的 `::before` 在这段里画卡片底色、带卡片投影，投影沿主轴裁掉（只留长轴两端那两小段，接上两张卡片的外框），开放式的线（`.sash-seam`）画在上面。平铺主题缝为 0，结果就是一条贯通的线，和现在一样。
- 活动栏与侧栏之间的短线（`data-shell-join-seam`）照旧画在活动栏上，一条，两端离顶底 10px。

### “角接过去”扩到整列：同上

- `capLeaf` 换成一组：这一刻按形状裁、和活动栏相连、而且正在降到零（`shrinking`）、留着缩回去但不在交换里、或刚连上的那几块（整列）。交换里滑出去的叶不算（切换容器时活动栏前后都相连，不换画法）。每块都往左伸过活动栏的一个圆角加半缝，伸出去的部分是活动栏的底色（`GridLeafShape.fill`）；最上面一块的右上角、最下面一块的右下角是圆的，其余的角在组内本来就是直的。组内没有缝，伸出去的部分连成一条，和只有一节时一样。
- `freshlyJoined` 同样换成一组；切换容器（整列换成另一列）不算刚连上。

### 交换过渡：`packages/nb-layout/src/grid-motion.ts`、`vue/useGridMotion.ts`、`vue/NestedGrid.vue`

- 新属性 `swap`（宿主驱动，通用）：

  ```ts
  interface GridSwap {
      /** 变了才算一次新的交换。 */
      readonly token: number;
      /** 这次变化里离开的叶与换上来的叶（叶 id）。 */
      readonly leaving: ReadonlyArray<string>;
      readonly entering: ReadonlyArray<string>;
      readonly axis: GridAxis;
      /** 1：新的从终点那边（右、下）进来，旧的往起点那边出去。 */
      readonly direction: 1 | -1;
      /** 相邻两组之间多隔的距离（CSS px）。 */
      readonly gap: number;
      /** 裁切窗：相对两组外接矩形的四边内缩与四角，CSS 长度（同 `GridLeafShape`）；不给就是外接矩形本身。 */
      readonly window?: GridLeafShape;
  }
  ```

  不用节点 id：区域在呈现树里的节点随分节数变（两节是分支 id，一节塌陷成那一节的叶 id），新旧两帧对不上（审查第 1 条）。
- 生效条件：`token` 变了之后的第一次布局变化里，`entering` 都是新出现的、`leaving` 都离开了，才按交换过渡；不是就照常过渡、这次交换作废。`token` 变化所在的那一轮刷新结束后（`nextTick`）不管用没用都作废，所以零写入的点击、提交被拒、减少动态效果都不会把它留给后面不相干的布局变化（审查第 7 条）。拖动中（`holding`）不交换。
- 窗口：`entering` 的终点矩形与 `leaving` 的上一帧矩形的外接矩形（区域在同一次变化里变宽变窄时两者都算进去），按 `window` 内缩、圆角。每个外框、内容外层、分隔线的 `clip-path` 是窗口在它自己坐标里的位置，和 `left`/`top` 同一个时长与曲线，所以窗口在网格里不动。已有 `leafShape` 裁切的项按两者的交（每边取内缩大的、裁到的那边圆角取窗口的）。
- 胶片（评审页 `regionScroller` 的模型，审查第 4 条）：参与交换的几组排成沿 `axis` 的一条带，相邻两组相距“窗口长度加 `gap`”，整条带一起平移。新的交换来时：上一轮还在动的那几组（滑出去的、刚滑进来的）先读出这一刻的位置（`getComputedStyle` 的 `left`/`top`，每次重定向读一次），新的一组接在 `direction` 那头最外面那组的后面，所有组的终点都平移同一个量（让新的一组落到终点矩形），所以只会同向一起走，不穿过彼此、不跳；平移之后整个在窗口外的组摘掉。`decideMotion` 里留着的离开项（`still`）每轮按带的位置重新给终点，不再沿用上一轮的终点。
- 离开的一组：提交那一刻就停放（不可交互，焦点在里面时这一刻发 `content-parked`，宿主把焦点交给新容器的第一节，输出 42），过渡结束前看得见；它们之间的分隔线留着、不可交互、跟着滑（审查第 6 条）。
- 外框、内容外层、分隔线写 `data-swap="in" | "out"`。新插槽 `swap-backdrop`：交换进行时在窗口矩形上画一块宿主给的底（在外框下面，位置跟着窗口，同一套过渡）。暴露 `swappingLeaves`。
- 减少动态效果直接换，不用交换。

### 切换容器时发 `swap`：`web/components/WorkbenchShell.vue`、`WorkbenchSurface.vue`

- 点入口切换（输出 22、47 的点击），区域这一刻可见、没在长出来时，提交前给 `swap`：`leaving`、`entering` 是切换前后区域里显示着的分节（入口条叶前后都在，不在里面）；侧栏 `axis: "height"`，右栏、底部面板 `axis: "width"`；`direction` 按入口顺序，新的在后面是 1；`gap` 是主题的缝宽（`card-gap`）。区域隐藏或拖到零时不发，按显示长出来（已有）。拖动落进入口、“移动到”、当前容器空了这些结构变化不发，照旧。
- 侧栏：不给 `window`，裁在整列（含上下的缝，评审页的 `sideClip`）；外框带着卡片的样子滚，活动栏、短线不动，“角接过去”不触发。
- 右栏、底部面板：`window` 是卡片里入口条以下那块（上边 0，其余三边按区域外沿的整缝、半缝换成 px，下面两个角圆）；`swap-backdrop` 里画这块卡片（底色、下面两个圆角、投影，变量同卡片）；交换中的外框不画底色、投影、圆角，只带着头与内容滑。入口条叶不动，它和底一起就是一张不动的卡片。

### 入口的选中标记：`web/components/WorkbenchToolStrip.vue`、入口条

- 活动栏的按下底色从每个按钮自己的底换成条里一个独立的块，位置是当前入口（渲染后量当前入口的 `offsetTop`、`offsetLeft`；条的尺寸变了用 `ResizeObserver` 重量），`transform` 过渡只在当前入口变了的那一次带（写一个标记），所以窗口缩放、入口收进“更多”时直接到位；拖动中入口换位（`TransitionGroup`）时块直接到终点的位置，和按钮的滑动差这一段，接受；区域隐藏时淡出（`aria-pressed` 的规则不变）。底部面板标题的下划线、右栏图标的按下底色同样。当前入口总在外面（输出 22）。

### 右栏、底部面板顶上一行（入口条叶）：`packages/nb-layout/src/layout-project.ts`、`web/state/layout-constraints.ts`、`layout-present.ts`、`WorkbenchSurface.vue`、`WorkbenchPanelHead.vue`、`WorkbenchShell.vue`

- 几何：入口条是呈现树里一片只在呈现里的叶（不进文档），第 2 稿的“不进布局树、给顶上的叶多让一行头”作废（审查第 8、9、11 条：收成标题行的尺寸、最小高度、`hasRoom`、层位、焦点、F6、最大化都要另补）。投影选项 `regionStrip?(region): number`（入口条的高度，0 是没有）；工作台给右栏、底部面板 32。区域呈现出至少一节时，区域在呈现树里的节点是一个纵向分支，id 是文档里区域节点的 id：右栏是 `[入口条, 分节……]`（只有一节时也不塌陷），底部面板是 `[入口条, 横向分支（id 加后缀 `:sections`）[分节……]]`。入口条叶 id `strip:<区域>`，高度固定，挨着它的那条缝宽 0、不可拖。`regionAnchors` 登记这个纵向分支，拖到零、隐藏按拖到零画都在它上面，入口条跟着整个区域缩到零。`rebaseIntents` 只按文档节点 id 取尺寸，区域节点取到的是含入口条的整个高度，和现在一样；入口条叶和 `:sections` 分支不在文档里，不写。只剩一节的区域里那一节不配收成标题行（输出 11：区域只显示一个分节时它不收）。
- ADR 0046 留下的“入口条作树上的条节点”的六处冲突（t24 设计审查第二轮 R3），这样放的结果：
  1. 条两侧的缝宽 0、不可拖：只有入口条与分节之间那条是 0；区域外沿那条缝（编辑区与底部面板、编辑区与右栏）挨着的是区域的纵向分支，不是条，照旧 1px、可拖。
  2. 区域拖不到零：收起策略配在区域的纵向分支上，入口条在里面一起缩到零。
  3. 放不下时只收面板不收条：入口条只在区域呈现出至少一节时才有，分节都被收走、区域隐藏时没有。
  4. 校验写死两个条：入口条不进文档，不涉及。
  5. 默认右栏多一行重复的标题：只有一节时那一节没有自己的头，标题与动作并进入口条，高度和现在一样。
  6. 底部面板的区域不是一棵子树：在呈现里包成一个分支；文档不变，`regionOf`、骨架判定照旧按文档。
- 什么时候有：右栏、底部面板呈现出至少一节就有，只有一个容器时也有（第 2 稿的“两个以上的容器才有”是我加的，没给开发者看过；没有入口条时，含几个视图的容器拖不进只有一个容器的区域，输出 46 说它只能落在入口条上。按推荐做，记进待确认清单）。
- 内容：右栏是容器图标（按下底色滑动），底部面板是容器标题（下划线滑动）。当前容器只有一节时，后面接那一节的头（标签带或只写标题）与它的视图动作，再接框架按钮，那一节自己没有头（`layoutContents` 给它的上边是 0，`hasRoom` 按这块叶的头高判）；几节时入口条是入口加框架按钮，每节照旧有自己的头。放不下时：当前入口总在外面，先截断并进来的标题，再把动作收进“⋯”，再把排在后面的入口收进“更多”。
- 交互同活动栏：点入口不是当前容器就切换（发 `swap`），是当前容器就隐藏区域；右键与菜单键开容器的菜单（输出 44）；名称与悬停文字按输出 41；方向键在入口之间走。入口条叶在网格里，F6 照常停在它上面；焦点进入口条时当前面板记为没有（和活动栏一样）；最大化时它和别的叶一样被盖住；读屏结构同活动栏（一组带 `aria-pressed` 的按钮）。
- `layout-present.ts` 的 `containerEntries`、`toolEntryIntent` 推广到三个区域（`regionEntries(doc, region, …)`、`regionEntryIntent`），活动栏照旧用侧栏的。

### 入口条的拖放：同上，加 `web/layout-drag.ts`、`web/live-drag.ts`

- 右栏、底部面板的入口条和活动栏上段一样是拖动源（输出 46）与落点（输出 45）：横着排，插入线是竖线，落在入口上是并入的高亮；复用活动栏的判定（`measureTabStrip` 按方向量）。入口条叶有自己的外框，矩形随布局走，来源收起后的平移同别的叶。并进入口条的那一节的头仍是那一节的头（元素带那一节的 `data-panel-head`，`geometryOf` 按面板 id 找头，不只在叶外框里找）。

### 一叶一张卡片的假设要盘点的地方

实施第 1 片时逐个过，结果写进 Task 记录：实时布局拿起一节（拿起的卡片四角都圆、带投影，剩下的几节重新拼成一张）、收成标题行的节（标题行一样拼进卡片）、显示隐藏时露出来的形状（`leafShape`，组内的边不留缝不圆）、落点分区与盖层（画在一节上，盖层的四角按这一节在卡片里的位置）、拖到零、最大化（最大化的一节自己一张卡片）、浮动窗（自己一张卡片，回停靠后拼进去）。

## 不做与风险

- 不做：标签切换的动画（开发者没提）；拖动落进入口、“移动到”、当前容器空了引起的换容器不滚；编辑组的卡片画法。
- 风险：入口条叶让区域在呈现里多一层分支，按呈现节点 id 认区域的地方（`regionAnchors` 的消费者、实时布局里按叶找区域、落点分区）要逐个核对；第 3 片先跑 `layout-project`、`layout-drag` 相关的单元测试与 `workbench-live-drag`。
- 风险：交换时右栏、底部面板的底是 `swap-backdrop` 里另画的一张，交换结束摘掉 `data-swap`、外框换回自己画卡片的那一帧要和底同一次渲染换（同一套四角与投影变量），第 3 片逐帧看。
- 风险：裁切用 `clip-path` 过渡，每帧重绘滑动的那几块；先在开发服务上量帧时间，超了再考虑合成层的做法。
- 风险：胶片重定向读一次 DOM（`getComputedStyle`）；只在交换进行中又来一次交换时读，不在平常的过渡里。
- 已知限制：拖动中入口换位时，选中标记直接到终点，和按钮的滑动差一段（约 200ms）。
