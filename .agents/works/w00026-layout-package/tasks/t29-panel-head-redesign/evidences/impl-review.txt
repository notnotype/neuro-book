### 1. 「最大化着还原按钮一直在」的 e2e 断言不依赖被测的 CSS 豁免
- **严重程度：** 重要　**类别：** 测试
- **位置：** `packages/neuro-book/e2e/workbench-containers.e2e.ts:238-242`，对应 `hover-actions.css:14` 的 `:not([data-hover-actions="frame"]:has([aria-pressed="true"]))`
- **现象：** 用例先点最大化，再点 (900,500) 并把指针移到 (900,500)，断言 opacity 为 "1"。视口 1440×900，最大化后这块面板盖住活动栏以外的整个表面，这一点落在它的卡片里。
- **为什么是问题：** 卡片带范围属性，指针在上面 `:hover` 成立，`data-hover-actions-active` 也写上，点击还把焦点放进面板。规则里 `:not(:hover):not(:focus-within):not([data-hover-actions-active])` 先就不成立，opacity 本来就是 1。删掉新加的豁免，这条用例照样过。它是 plan 第二轮第 9 条、Spec 输出 20 的唯一验收，判据没被测到。
- **如何核实：** 删掉该 `:not(...)` 重跑这条用例（由作者跑），预期仍通过。
- **建议改法：** 最大化后把指针移出面板（状态栏、标题栏），焦点放到面板外，再断言 "1"。加一条还原后同样位置 opacity 为 "0" 的对照，并做变异检查：删掉豁免必须失败。

### 2. Lab 夹具没跟着改，还留着旧的“收起”框架按钮
- **严重程度：** 重要　**类别：** 不变量、测试
- **位置：** `src/plugins/lab/web/fixtures/WorkbenchSurfaceFixture.vue:81`、`:136-140`、`:236`；`src/plugins/lab/web/fixtures/index.ts:399-421`
- **现象：** 夹具的 `frameActions` 仍列 `collapse`（chevrons-down，`pressed` 为是否收起），传给头时没有 `fold`、`foldLabel`。`effectiveVisibleTabs` 的调用没传 `fillers`。`WorkbenchPanelHead` 的 Lab 场景也没有带 `fold` 的场景，`named` 里还有 `collapse`。
- **后果：**
  - Lab 里看不到新头（标记、整行开关）。
  - Lab 的“收起”按钮收起时 `aria-pressed="true"`，被新的 CSS 豁免命中，收起的分节框架按钮一直显示，这在产品里不会发生。
  - Lab 的 `data-visible-tabs` 在全部收起且别的分隔线预览时，会把垫底那节算成拉出来。
  - plan 说“截图给开发者”，Lab 里没有对应场景。
- **建议改法：**
  - 夹具改成给 `fold`、`foldLabel`，拿掉 `collapse` 按钮，点标题走 Shell 同一个判定。
  - `effectiveVisibleTabs` 传 `projection.value.fillers`。
  - `WorkbenchPanelHead` 加“展开、收着、接管标题区、英文长标题”四个场景（UI 专属检查第 5 条）。

### 3. 接管标题区时，标题按钮的可访问描述说 Enter 切换收起，实际是开弹层
- **严重程度：** 建议　**类别：** 正确性（可访问性）
- **位置：** `WorkbenchShell.vue:824`（`message(foldOf(panelId) === null ? 'shell.drag.hint' : 'shell.drag.hintFold')`）；`WorkbenchPanelHead.vue:178`
- **现象：** 接管模式下展开标记是单独的按钮，标题按钮是视图的弹层开关，但 `dragHint` 照样传“按 Enter 展开或收起，按空格拿起并拖动”，写进接管标题按钮的 `aria-description`。
- **为什么是问题：** 对话视图的标题上读屏会说 Enter 展开或收起，实际 Enter 开会话列表。
- **建议改法：** 接管时（`panelViewHead(panelId) !== null`）仍用 `shell.drag.hint`，hintFold 只给非接管的标题按钮。

### 4. `headReserved` 给展开标记留的宽度比实际少
- **严重程度：** 建议　**类别：** 正确性
- **位置：** `WorkbenchShell.vue:197`（`FOLD_MARK_PX = 20`）
- **现象：** 非接管头里标记实际占 9px 外边距 + 14px + 5px 间距 = 28px；接管头里是 24px 按钮 + 2px 间距 = 26px。
- **为什么是问题：** 按钮预算（`buttonBudget`）多放按钮，临界宽度下标题被压到约 88px 而不是 Spec 说的“总给标签带留一个截断标签”。标题可收缩，不会溢出，但 plan 要求“`headReserved` 改成两个框架按钮加标记的宽度”。
- **建议改法：** 非接管 28、接管 26，或在组件里导出标记宽度并和 CSS 共用。

### 5. 标题 h2 改成 flex 并撑满，波及没有标记的头
- **严重程度：** 建议　**类别：** 不变量（既有约定）
- **位置：** `WorkbenchPanelHead.vue:350-363`（`.workbench-panel-head__title` 加了 `display:flex; align-self:stretch`）、`:406-417`（`.workbench-panel-head__handle` 改成 `display:flex`）
- **现象：**
  - 模板里 `<h2 v-else class="...__title">{{ label }}</h2>`（没有标签时只写名称）现在是 32px 高的 flex 容器，文字落进匿名 flex 项，贴在顶部。原来是 block，被 `.band` 的 `align-items:center` 居中。Lab 的 “empty” 场景会命中。
  - 没有标记的标题按钮（底部面板分节、区域唯一分节）在 flex 的 h2 里被拉成 32px 高，焦点环从文字高变成整行高。
- **为什么是问题：** plan 与 Spec 写“没有标记的头照旧”。
- **建议改法：**
  - 把 `display:flex; align-self:stretch` 只给带标记的标题（例如 `.workbench-panel-head__title:has(> .workbench-panel-head__handle > [data-panel-fold])`）。
  - 或给文字 h2 单独补 `align-items:center`，并给没标记的按钮补 `align-self:center`。
  - 看一眼 Lab 的 `empty` 与 `anonymous` 场景。

### 8. `fold` 没和 `titleOnly` 绑定，可收起但不画标记的头会丢掉收起入口
- **严重程度：** 建议　**类别：** 不变量
- **位置：** `WorkbenchShell.vue:192-195`；`WorkbenchPanelHead.vue:191`
- **现象：** `foldOf` 只看 `collapsibleIn`，标记与 `aria-expanded` 只在 `titleOnly` 且有 `activeTab` 的分支画；同时 `frameActionsOf` 已拿掉收起按钮。
- **影响：** 目前只有浮动窗有多标签，浮动窗不可收起，当前不可达。以后若出现竖排里的多标签或零标签的工具面板，它们既没有标记也没有按钮，收起只能走命令；`headReserved` 还会白留 20px。
- **建议改法：** `foldOf` 加 `titleOnlyPanelIds.has(panelId)`。

### 9. 每次渲染里 `foldOf` 与 `foldLabel` 被重复求值
- **严重程度：** 建议　**类别：** 性能
- **位置：** `WorkbenchShell.vue:824-830`
- **现象：** 每块头在模板里调 `foldOf` 三到四次，每次走 `findTreeNode` 与 `sectionCollapseBlock`（遍历树），`foldLabel` 对没有 `fold` 的头也算 `message(... text(panelTitle(...)))`。
- **建议改法：** 像 `titleOnlyPanelIds` 一样做一个按面板的 computed 表，`foldLabel` 只在 `fold` 非空时算。

## 未发现问题的方面

- 垫底：
  - `layout-project.ts` 的 `assignByParent`、`fillers` 的判定与 Spec 的“按呈现数”一致，视图声明的最大高度被去掉，包装分支与区域内左右拆开的子列都能处理。
  - `sashDisabled` 只命中带垫底的那一列（`fillerColumns` 按分支 id 认），线照画（seam 保留），同一次渲染内翻转无状态残留。
- 悬停与按钮：
  - `hover-actions.css` 的修改只作用于 `data-hover-actions="frame"` 的容器，视图动作与编辑组头（`EditorGroupHead.vue` 的 `data-hover-actions`）不受影响。
  - `[aria-expanded="true"] > .workbench-panel-head__chevron` 只会命中直接子的标记，接管头的标题按钮里没有 chevron，不会误中。
- 点标题：
  - 键盘拖动期间 Enter 与 Space 都由会话吞掉；指针拖动后的 click 被 `takeClick` 吞掉；右键不触发 click。
  - 最大化着不给 `fold`，`control === null` 与 `key === active` 的条件与计划一致。
  - 命令的拒绝条件（底部分节、唯一分节、浮动窗、编辑组）与 `collapsibleIn` 一致，不会出现点了没反应而 `aria-expanded` 不变的情形。
- 对齐：e2e 量到的 9px、5px 与资源管理器根行一致，但只对着第一行（根行，无图标）。第一层目录项有 `FileIcon`，文字会更靠右，标题只与根行文字对齐。
