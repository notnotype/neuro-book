# 面板头与分节全部收起的样子

## 目标与范围

开发者 2026-11-17：侧栏一个容器里的视图全部收起时样式不对，要重新设计；面板头有点丑，收起后更丑。出静态稿逐轮评审，定了再写 Spec 与计划。

合同：[`ui/workbench-layout`](../../../../../docs/specs/ui/workbench-layout.md) 输出 11（收成标题行、一列全部收起时“标题行排在上面，下面留空”）、输出 20（工具面板的面板头）；[`workbench/views`](../../../../../docs/specs/workbench/views.md) 输出 10、12（视图动作随鼠标显示）。定稿后按决定改。

和 [t28](../t28-panel-entry-strips/README.md) 的关系：t28 并成一行的头用的就是这个面板头，所以 t28 第 2 片（画出入口条与并成一行）排在本 Task 定稿之后；t28 第 1 片（nb-layout 的入口条叶与交换规则）不受影响。

- 开发者 2026-11-17 在第 1 轮评审板上答（都按推荐）：
  1. `all-collapsed` 甲：一个容器的分节全部收起时，卡片和活动栏照旧连成满高的一列，收起的标题行排在上面，下面是卡片自己的底。
  2. `head-style` 甲：展开标记在标题左边，浮动、最大化与视图动作悬停才出，收起按钮拿掉（由标记与点标题行代替），收起的行标题退成次要字色。开发者附言：“记得细节检查一下，看看对齐了没”。
  3. `title-click` 甲：点分节的标题行在展开、收起之间来回切；键盘在标题上按 Enter 同样切换，空格照旧拿起拖动。

- 计划 [`plan.md`](plan.md) 第 1 稿：两片（nb-layout 的分支选项 `collapsedRest`，全部收起时最后一行拉到底；工作台的头：展开标记、点标题切换、框架按钮悬停才出、拿掉收起按钮、字色、对齐）。

- 第一轮设计审查（Claude Sonnet，2026-11-17，[`evidences/design-review.txt`](evidences/design-review.txt)）：11 条，阻断 1、重要 7、建议 3。逐条核实，改成第 2 稿：

  | 条 | 内容 | 处理 |
  |---|---|---|
  | 1 | 只改网格分配，收起的叶会被夹回收起尺寸，t28 的包装分支还出诊断；夹取、约束、快照都要改 | 成立，换做法：不给网格加选项，在投影里让全部收起时最后一节垫底（第 10 条的候选） |
  | 2 | 拉长后拖缝会被求解器拒绝 | 换做法后不成立：垫底的那一节按比例分，和“收起的分节在展开的上面”同一情形，已有路径 |
  | 3 | 任何手势的预览都把拉长的收起分节判成“拉出来”，内容露出 | 成立，改：预览里排除垫底的那一节（由文档算得出） |
  | 4 | 拉长后收起分节的正文有了面积，指针与键盘的落点不一致 | 成立，改：`geometryOf` 对收起的分节只取标题行，保持旧约定，垫底的那一节下面不是落点 |
  | 5 | 只有标题文字可点，不是整行 | 成立，改：标题按钮铺满标题那一格，标记放进按钮，加 `aria-expanded`、`aria-controls` |
  | 6 | 发两个事件有顺序问题；双击、空格、点标题聚焦没写 | 成立，改：头只发 `activate`，Shell 一处决定；双击、空格写进 Spec |
  | 7 | 接管标题区时标记放哪、aria、对齐都没落地 | 成立，改：标记是左列最前面一个单独的按钮，算进等宽，这个模式不按左缘对齐判 |
  | 8 | 框架按钮不在悬停范围里；最大化后还原按钮会随悬停淡出；`headReserved` 常数要改；拉长的卡片空白处也算悬停 | 成立，改：框架按钮容器加 `data-hover-actions`，按下的一直显示，`headReserved` 改算，收起的分节悬停范围放在头上 |
  | 9 | 对齐判据量不出来、漏了几处 | 成立，改：判据改成能量的几条（标记离卡片左缘 8px、两种状态横坐标相同、字形竖直中心差不超过 1px、收起行之间的线），加深色与平铺主题 |
  | 10 | 质疑上游：是不是该在投影里做 | 成立，采纳（见第 1 条） |
  | 11 | 展开上面一行时“上面几行不动”不成立 | 成立，改写：卡片上下边不动，行之间的边界照常过渡；补用例 |
