### 1. “意图为正”的平均份额谓词让全 0 意图的分支变成“新叶独占”

- **如何核实**：`bun /tmp/t52-r2/p1.ts` 的 A 节。

### 4. `setSize` 的两种新参数形状与现有形状同 `field`，破坏“按 `field` 判别”，形状数也少数了一种
- **严重程度**：重要
- **类别**：接口与合同
- **位置**：`plan.md:40-41、68`；`grid-failure.ts:6、20-27`；`grid.ts:307-314`；`grid-types.ts:209-220`；Spec 288-289 行
- **现象**：

  - `grid-failure.ts:6` 的头注释写明“一个码有几种形状的写成按 `field` 判别的联合”。同 `field` 两种形状判别不了。
  - 不带 `side` 的是带 `side` 的超类型，所以 `planBranchResize`（`grid.ts:309、311`）将来漏写 `side` 也能编译，“漏字段在编译期报错”的保护没了。使用方读 `params.side` 得先 `"side" in params`。
  - Spec 288 行写“尺寸另加 `side`”，与计划的形状冲突，计划没列这行怎么改。

- **如何核实**：读 `grid-failure.ts:20-27` 与 `grid.ts:307-314`。“删掉 `side` 后仍能编译”是推断，没有改仓库跑 `tsc`。

  - 新形状用不同的 `field` 值，例如 `not-finite` 的 `field:"px"`、`invalid-argument` 的 `field:"px-negative"`，都带 `id`。
  - Spec 288、289 行逐行改，形状数写成三种，`GridFailureCode` 加 `wrong-sizing`。
