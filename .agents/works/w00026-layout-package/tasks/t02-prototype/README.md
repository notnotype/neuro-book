# 一次性原型：扁平渲染与一棵树的手感

## 目标与范围

交开发者亲手试：扁平渲染的一棵树、落点指示与实时布局两种拖动手感、一个应用内浮动窗、一个手机呈现。回答三个问题：手感够不够，Tab 与读屏顺序怎么办，重内容（真实编辑器）的帧率与起拖时的停顿。手感不够或 Tab 顺序解决不了就回到开发者重新讨论。代码不合入。依据 [t01](../t01-requirements/README.md) 的决定 1、2、3。

## 怎么试

在 worktree 里 `nbdev dev start`，打开 `/lab?c=LayoutTreeDraft&s=default`，占满整个窗口。窗口窄于 600 时变成手机呈现；也可以用 `&s=phone&vp=phone`。切换手感在标题栏，其余选项在标题栏的“设置”里。状态栏显示落点、上一场拖动的帧率和内容加载耗时；每个视图右下角写着实例被创建了几次，搬动后应该一直是 1。

## 原型做了什么

- **模型**：一棵树（分支与带标签的面板）加浮动列表，编辑区是树里标了 `stage` 的子树；标题栏和状态栏在树外。尺寸按权重分，拖动手势用 nb-ui 现有的求解器，没有快照。
- **渲染**：面板外框、分隔线、视图内容都是同一个父元素下的绝对定位元素，用 transform 加宽高摆放。视图内容按视图 id 建一次，不换父元素。每个标签自己一个内容实例（Trellis 的做法），不是现在的每个编辑组一个控件。
- **判定**：拿起时算好“摘掉来源之后”的树和几何，整场拖动都按这份固定几何判定，预览只影响显示；否则让位会把落点从指针下挪走，来回抖。

## 实测

原始结果见 [`evidences/measurements.txt`](evidences/measurements.txt)。

- **结构可行**：主流程 22 项全过。跨面板搬动后滚动、输入、光标和一直在跑的动画都还在，没有实例被重建。
- **Tab 顺序有解**：`reading-flow` 加 `reading-order` 让 Tab 跟视觉顺序走，不搬节点。读屏顺序要另加 `aria-owns`。只在 Chrome 上试过。
- **每标签一实例可以接受**：普通章节的 JS 堆增量在噪声内，第二个 Monaco 约 6MB（DOM 占用没有计入）。起拖时新建 TipTap 最长帧 33 到 50ms；Monaco 第一次要等库加载，这期间卡片是空的。
- **帧率说不准**：无头软件渲染，同条件各轮差到 35 到 59 帧，负载影响大于条件本身。过渡时内容只排一次版对 TipTap 有小幅改善，对 Monaco 看不出差别。真实手感只能靠开发者在真窗口里试。
- **`moveBefore` 不能代替不换父元素**：焦点在，滚动还是丢。

## 开发者第一轮反馈（2026-11-05）与处理

1. **标签条内拖动不要变成卡片**：改成只有标签跟手、其余标签滑开、内容留在面板里；离开标签条才撕成卡片，回到标签条卡片消失。单标签面板也一样。开发者问库要不要支持标签：我建议要，待确认（见当前状态）。
2. **VS Code 模式落成浮动的预览不跟手**：原因是 `DropFeedbackOverlay` 的几何带过渡。浮动预览改成单独的元素，不带过渡，实测两帧内跟上指针。
3. **动画曲线照 Trellis**：逐帧采样拟合出缓出 5 次幂、约 470ms，证据见 [`evidences/trellis-easing.txt`](evidences/trellis-easing.txt)。设置里可以切回 `--ease-standard` 对比。
4. **补上漏掉的两个功能**：十字交汇处同时调宽高、拖动收起与展开。这两个产品里本来就有，原型自己写分隔线时丢了。改成直接用 nb-ui 的 `collectSashHits` 和 `solveSashDrag`，没有改它们：说明现有求解器可以原样接到新渲染层上。上下方向收成标题行，左右方向拖到零；点收起面板的标签也能展开。
5. **新增落点分区（开关，缺省开）**：拖到面板正文上时画出上下左右中五块，形状与判定一致（四角按对角线分），当前那块高亮。两种模式都有。

主流程 22 项与这一轮 33 项全部通过。

## 开发者第二轮反馈（2026-11-05）与处理

开发者说其它地方没问题：手感、无落点就浮动、标签条的分工都认可。编辑器标签能出编辑区、工具视图不能进编辑区这组缺省没有异议，开放范围到 t03 写定。

1. **不要最外层落点**：做成开关，缺省关。
2. **模式改名**：“实时布局”和“落点指示”，按行为命名。
3. **落点分区按模式打磨**：实时布局下放到卡片后面，只留淡线，不写字，当前那块轻轻提亮，看点留给卡片。落点指示下压暗视图内容（72% 底色加轻微模糊），线和文字都加重，当前那块的文字用强调色底。有分区时不再重复覆盖层的文字，拖影放到分区上面。

主流程 22 项与反馈相关的 37 项全部通过。第三轮去掉了压暗里的 `backdrop-filter`。

## 开发者第三轮反馈（2026-11-05）与处理

1. **压暗不用模糊**：改成不透明度加调暗，两个参数都能调。
2. **实时布局默认不用蓝色遮罩**：空位是一块空面板加一圈边框，当前分区也不填色。
3. **`(A | B) | C` 放到 B、C 之间的走法**：开发者判断属实。原来有三种：B 右缘取 B 的一半，缝按比例从全部兄弟取，C 左缘取 C 的一半；落点指示又按面板的一半估算，缝只画一条线，所以和结果对不上。改成同一区域的共享边与缝是同一个落点，新块只从相邻两块取；指示画提交后的矩形。缝的命中带从两侧各 6px 收到 2px，否则紧贴缝的面板边缘也算接缝。跨编辑区边界的两边仍然不同，见 t01 决定 16。
4. **样式提供可调接口**：设置里的“反馈样式”按模式调，落到 CSS 变量，下面显示当前值的 JSON。

三组测试全过：主流程 22 项、反馈相关 37 项、这一轮 12 项。这一轮逐个核对了共享边、编辑区下缘、右上面板上缘、并入标签四种落点：指示外扩覆盖层规定的 6px 内缩后，与提交后的矩形相差不超过 1.5px。新块多一条缝要多占 4px，由同一层的块分摊，所以其它块约少 2px。

## 开发者第四轮反馈（2026-11-05）与处理

开发者指出 `(A | B) | C` 还是有两种结果：“拆到右侧”和“放到两块之间”。复现属实，第三轮只修了同一层兄弟。沿 B、C 之间那条线扫描，原来有三种结果，拖工具视图还会依次变成浮动、无落点、拆到左侧。修法：

1. 缝不再是单独的落点，指针在缝里归最近的那块；整段插入做成开关，缺省关。
2. 编辑区边界两侧共用同一条线时只算一个落点：编辑器进编辑区，工具留在外面。

字面的 `row(左 *row(A B) C)` 上，整条线现在只有一个结果，两种模式下指针在 C 一侧时指示都等于结果。默认布局里 C 只占右栏上半，与 B 不等长，所以按指针在哪一块分成“拆到右侧”“拆到左侧”，放下去高度不同，这条留着。四组测试全过：22、37、12、7 项。
