决定（主会话，2026-11-06）：下面“缺口”都已写进 `ui/workbench-layout.md`。活动栏条目仍是拖动源（等于拖视图的标签），不是落点，不能重排：表里按“不是拖动源”写的 `dnd:119`、`dnd:236`、`dnd:667` 按此调整，改动更小。内容项指回叶的标记定为 `data-content`、`data-content-leaf`。

范围：`packages/neuro-book/e2e/workbench-shell.e2e.ts`（16 条）、`workbench-views.e2e.ts`（27 条）、`workbench-dnd.e2e.ts`（30 条），共 73 条，数量与 `grep -cE '^\s*test\('` 三个文件之和一致。`workbench-dnd.e2e.ts:289` 的用例在源码里是一条（里面循环开 12 个上下文），按一条算。

对照依据：新合同 [`ui/workbench-layout.md`](../../../../../docs/specs/ui/workbench-layout.md)（下称新 Spec，“输出 N”“验收 N”都指它），旧合同 [`ui/workbench-shell.md`](../../../../../docs/specs/ui/workbench-shell.md)（“现行输出 N”指它），以及新 Spec 末尾的“现行合同的去向”表（下称去向表）。会话类手势的细则在 [`ui/layout-drag.md`](../../../../../docs/specs/ui/layout-drag.md)，写作“layout-drag 输出 N”。

去向的四种定义照任务说明：保留（行为不变，最多改一两个标记）、改写（行为还在，操作路径或断言按新模型重写）、删除（行为随设计取消，写依据）、Lab 取代（组件级 Lab 用例覆盖更合适，写由哪条覆盖，不存在写“待补”）。

## 通用改动

各行说明里写“助手”，指下面这几处在三个文件里各有一份的辅助函数，改一次管整个文件。

| 项 | 现在 | 新模型下 |
|---|---|---|
| 记录 | `customizations()`、`revisions()`、`writesOf()`、`hideSidebarInRecord()` 读写 `views-customizations`、`layout-sizes-side`、`layout-sizes-panel` | 只有 `workbench.layout`（以及 `workbench.layout-template`、`editor.tabs`）；一次手势一次写入，不再有“只写涉及的记录”（状态与转换） |
| “移动到”入口 | 面板头与分节标题里的按钮 `[data-move-view]`，`moveVia()` 点它 | 标签的右键菜单，键盘用菜单键（输出 23）；`moveVia()` 重写，目标名从“样例甲”这类容器名换成面板名、“新面板（挨着 X）”、“重置位置” |
| 活动栏条目 | `[data-activity-container="view:X"]`，选中互斥 | 每个工具视图一个条目，按下态等于有效可见，可同时按下几个（输出 22）；条目标记由实现定 |
| 叶与内容 | 视图和编辑器内容在 `[data-leaf]` 里面 | 内容项与叶外框是兄弟元素（输出 14），`closest("[data-leaf]")` 失效；`data-tool-part`、`data-container-host`、`data-view-section`、`data-switcher-*`、`data-shell-slot`、`data-shell-parking`、`data-shell-card` 都随旧组件消失 |
| 落点反馈词表 | `data-drop-kind` 取 `move-container`、`merge-container`、`detach-view`、`move-view`、`noop` | 容器类取消，结果类型随 `resolveLayoutDrop` 重定；断言这些值的用例都要改词表 |
| 边界名 | `调整 sidebar 与 panel-stack 的宽度`、`调整 editor 与 panel 的高度`、`data-sash="body:0"` | 来自新树的叶 id 与节点 id，`sidebar`、`panel` 这类具名面板的叶 id 不变（输出 1 与“边界与兼容”） |
| 面板头按钮 | 五个框架按钮：位置、对齐、收起、最大化、隐藏 | 三个：收起、最大化、隐藏（输出 20）；`data-panel-action` 是否沿用由实现定 |

## 缺口

现行有、新 Spec 没写去向的行为。每条写出处、新 Spec 的现状、受影响的行。是否补写、怎么定由开发者决定，下面不替开发者选。

1. **纵向分支里往最小尺寸以下拖、边界上按 Enter 的结果。** 现行输出 4、7、8：面板（纵向）能拖到零、Enter 拖到零、拖到顶最大化。新 Spec 输出 11 把“拖到零”限定在横向分支，“收成标题行”限定在纵向分支，输出 6 又写“停在边界不弹回”，没有写手势怎么进入这两种状态，也没写纵向边界上 Enter 的结果。影响：shell:277、shell:297、views:124（现用例都在纵向的面板上做）。
2. **活动栏条目是否仍是拖动源，以及条目的顺序与重排。** 现行外壳三 19、23：容器项可拖、可聚焦、键盘拿起，同一 Switcher 内可换序。新 Spec 输出 24 的来源只有视图标签、编辑器标签、整个面板，输出 31 只说标签与面板头可聚焦拖动，输出 22 没写上段条目按什么排序、能不能拖动重排。影响：dnd:119、dnd:236、dnd:667（本表按“不是拖动源”改写；若保留则这几条改动更小）。
3. **拖放放进收起成标题行的面板时是否展开。** 现行输出 39 末句写明同一次写入清掉收起；去向表把输出 39 指向输出 1、4、29，那里没有这一句。输出 11 的“收成标题行”只写了“点标签、面板头按钮、拖开”三种回来的办法。影响：dnd:442。
4. **活动栏与侧栏相连按拖动中的几何变化。** 现行输出 38 写明从零拉出、往零拖时不等松手就相连或分开。新 Spec 输出 12 只规定可见性（`ViewContext.visible`）跟拖动中的几何，输出 19 只说按矩形邻接算，没有说邻接用提交前还是拖动中的矩形。影响：views:151。
5. **公开状态 `panelVisible` 等对隐藏、收起、拖到零、被最大化挤走的求值。** 现行输出 32 写明“可见指未隐藏且未拖到零”。新 Spec 输出 36 只写“按名字求值”；输出 17 的有效可见是视图的概念。影响：状态栏“显示面板／隐藏面板”按钮的文字与标题栏布局按钮的按下态（shell:172、shell:277，另有 `workbench-titlebar.e2e.ts`）。
6. **外观里没有转写的几条。** 现行输出 38 的“部件自己不画外框与圆角；工具区、视图、面板标题行与编辑器标签栏都不画底线；工具区、视图、面板的当前标签用加粗的正文色；工作台页占满视口、页面根不预留滚动条位置”。去向表只把“卡片”指向输出 19，输出 19 没有这几条。影响：shell:500、views:594。
7. **标题动作与滚动条随鼠标显示的范围。** 现行范围按容器模式写（multiple 是视图窗格，single 是整个侧栏或右栏，面板是整个面板），在 `workbench/views.md` 输出 10 与验收 9。新 Spec 输出 20 只排了面板头里的顺序，views.md 的文字还在讲容器。影响：views:177、views:935。
8. **命令 `nbook.view.open` 没进输出 35 的命令表。** 它在 `workbench/views.md` 输出 14：选中视图所在容器、显示区域、展开收起的视图。容器取消后“选中容器”要换成“激活标签并显示面板”，输出 22 对活动栏点击写了同样的语义，但命令没写。影响：views:361。
9. **“移动到”菜单的关闭条件缺交付状态与视图代际。** 现行输出 24 列的是视图、来源容器、容器模式、交付状态、视图代际，任一变化即关闭。输出 23 只写“视图与所在面板”，视图渲染出错后重试换代时菜单关不关没写。影响：views:901。
10. **无名面板的显示名。** 输出 23 的目标“别的工具面板”、输出 35 的 `target`、命令面板的“移动到”选项都要给面板起名；面板记录只有具名面板有 `name`，没有标题字段。现行输出 24 的目标标题与图标与 Switcher 同源。影响：views:309、views:343、views:698、dnd:698。
11. **恢复时合法文档里的尺寸越界。** 现行状态表“恢复尺寸越界：夹取到该叶的最小或最大值加诊断，不改写记录”，去向表把验收 7 指向验收 12，验收 12 只列了损坏内容与不支持的版本。输出 8、10 说夹取不写文档，但没写读取时要给诊断。没有现行 e2e 覆盖，来自去向表对照。
