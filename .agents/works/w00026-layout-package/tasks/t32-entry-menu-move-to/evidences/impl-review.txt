### 1. “移到底部面板”之后，那个容器的入口菜单多半只剩视图的“移动到”，搬回去没有整容器的路
**严重程度**：重要　**类别**：不变量 / 与相邻功能的交互
**位置**：`WorkbenchShell.vue:580-588`（`openStripMenu`）；`e2e/workbench-views.e2e.ts:740-746`
**现象**：容器搬进底部面板时被切成当前容器。它只有一个分节（隐式容器都是这样）就并进入口条，`openStripMenu` 对“底部面板、并成一行、入口是当前容器”这种情况开视图的“移动到”（`openMoveMenu`），不开容器的菜单。所以刚用“移到底部面板”搬过去的单视图容器，右键它在面板里的入口得不到“移到侧栏”“移到右栏”，也没有“重置”。要用整容器的菜单，得先把面板里别的容器切成当前。面板里只有它一个容器时，菜单只能走视图的“移动到”（新建用户容器或并进别的容器）。搬回去之后容器已成 `custom:`，永远没有“重置”。
**为什么是问题**：Spec 输出 47 确实写了“并成一行时右键开视图的‘移动到’，不开容器的菜单”，所以不是实现偏离 Spec。但本 Task 让“进底部面板”变成一步操作，却没有对应的整容器“出来”，输出 44 “入口的右键菜单：移到另外两个区域”在这个状态下不成立。计划只写了“不变”，没有评估这个组合。
**如何核实**：从代码推断，未运行。`openStripMenu` 里 `region === "panel" && section?.container === container && key !== null` 对刚搬进来的当前单分节容器成立。`e2e:730` 搬 A 进面板后 A 就处于这个状态，用例没有去右键它的面板入口。
**建议改法**：交开发者定。A）并成一行时，视图的“移动到”菜单后面追加容器的“移到”项；B）接受，在 Spec 输出 44 或 47 写明例外。无论哪种，e2e 补一步：搬进面板后右键它的入口，断言菜单内容。

### 2. 选“移到”之后的焦点落点没有任何断言
**严重程度**：建议　**类别**：测试
**位置**：`e2e/workbench-views.e2e.ts:699-705`、`730-760`
**现象**：只有“重置”那一步断言了焦点（`:727`）。三次实际执行“移到”都没有断言焦点：`:700` 侧栏到右栏，`:703` 右栏到侧栏，`:740` 侧栏到底部面板。`:730` 另一半只看菜单项、没有执行。右栏到底部面板、从底部面板出发的路径完全没测。
**为什么是问题**：重点 2 与 Spec 输出 16 关心的是焦点不落到页面上。从代码推断逻辑是对的：`closeContainerMenu` 在 nextTick 里按容器 id 找 `data-tool-entry` 或 `data-region-entry`，找不到再去它第一个分节的标题。三条路径都由同一个函数处理，与“重置”一致。但这条推断没有测试守着。活动栏隐藏时搬到侧栏会落到分节标题，也没有覆盖。
**如何核实**：读 e2e 即可。
**建议改法**：在 `:701`、`:704`、`:742` 之后各加一行 `toBeFocused()`，断言目标区域入口条或活动栏上那个容器的入口。

### 3. `:730` 里“入口排在最后”的断言在功能坏掉时仍会通过
**严重程度**：建议　**类别**：测试
**位置**：`e2e/workbench-views.e2e.ts:750-753`
**现象**：搬之前底部面板入口顺序里没有 A 的 id（A 从没去过面板）。`settleContainers` 会把有成员而不在入口顺序里的容器追加到最后。所以删掉 `moveContainerTo` 里的 `setContainerEntries` 那一步，`entries.at(-1) === A` 照样成立。这条断言没有测到计划写的“排在最后”。
**为什么是问题**：计划的验收映射把它列为 e2e 新用例的判据。单元测试 `containers.test.ts:226` 已覆盖该排序，所以实际风险小。真正测到“排在最后”的是 `:725`：A 先在 `[D, A]` 里，D 搬回后变 `[A, D]`，这点是好的。
**如何核实**：读 `moveContainerTo` 的 `entries` 步骤与 `settleContainers` 的 `listed`。未跑变异。
**建议改法**：在 `:730` 里先让 A 去过面板、再搬回侧栏、再搬一次，才会有“已在列表里、位置不在最后”的情形。或删掉这条断言，注释写明由单元测试覆盖。

### 4. `MENU_REGIONS` 重复了 `VIEW_LOCATIONS`
**严重程度**：建议　**类别**：代码质量
**位置**：`web/state/containers.ts:150-157`
**现象**：同一文件第 11 行已导入 `VIEW_LOCATIONS`（`["sidebar","auxiliarybar","panel"]`，`containerRegion` 也用它）。新增的 `MENU_REGIONS` 是同一列表的手写副本，类型还放宽成 `PanelName`。
**为什么是问题**：两处先后会各自改。“按侧栏、右栏、底部面板的先后”正是 `VIEW_LOCATIONS` 的定义。
**如何核实**：读文件。
**建议改法**：改成 `VIEW_LOCATIONS.filter((region) => region !== here)`，删掉常量。

### 5. 几处注释还停在旧行为
**严重程度**：建议　**类别**：代码质量
**位置**：`WorkbenchShell.vue:590、595、600`

### 6. 菜单动作丢掉了 `LayoutResult`
**严重程度**：建议（原有做法，收益小，可不改）　**类别**：错误路径
**位置**：`WorkbenchShell.vue:567、571`
**现象**：`moveContainer` 返回 `LayoutResult`，菜单动作不看。`limit-exceeded` 由 store 记成 `structureFailure` 会显示，`rejected`（`fitsSkeleton`）、`not-found` 则静默。“重置”原来就这样。视图的“移动到”走命令，会报“这个视图不能放到那里”。
**为什么是问题**：多了两个入口，同一类失败在两处表现不一致。但这些失败近乎不可能发生，按“收益小的不改”处理也合理。
**如何核实**：读 `apply`（`layout-doc-store.ts:219`）。
**建议改法**：不改，或让菜单动作也走命令。
