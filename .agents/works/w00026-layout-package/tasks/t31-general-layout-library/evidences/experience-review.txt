### 6. 收起策略里的 restoreSize 谁来更新，没说；我的代码就踩了

- 在哪一步：model.ts syncDocks 与 setDock。
- 建议：要么 Grid 在收起那一刻自己记下收起前的尺寸写进 restoreSize（谁收起谁记），要么提供 `updateCollapse(id, patch)`；README 写明“restoreSize 由谁维护”。

### 9. 同向拆分会产生同向嵌套分支，树越拖越深，没有扁平化
- 碰到了什么：splitLeaf 总是造一个新分支，即使新分支方向和父分支相同。bun 里实测：editor（横）里把 g1 再向右拆，得到 editor → b6（横）→ g1、g5，一层多余的横向分支。连续拆就一路嵌套，Grid 有 16 层、256 节点上限（失败码 limit-exceeded）。addLeaf 能避免，但没有“比例”参数，新叶权重要自己算。另外 splitLeaf 新建的分支 sizing 固定为 weight，拆一个 fixed 的叶会丢掉它的 fixed。
- 在哪一步：model.ts applyTabDrop；drop 到组边缘拆分。
- 建议：splitLeaf 在方向与父分支相同时自动走“插到父分支里”并带 ratio；或提供 `normalize()`。README 写明 16 层上限对“拖拽拆分”的实际影响。同时 findParent 要自己写（没有 parentOf），9 行。

### 10. “窗口变窄守住最小尺寸”：库不守，是按比例降级；issues 是中文字符串、一次七条

和 dockview、golden-layout 比（凭记忆，没有重新核实）
- dockview：给整套停靠模型（面板、组、拖到边缘拆分、序列化、浮动窗），接入基本是创建、注册组件、addPanel，几十行；第三方拿到的“拖标签拆组”开箱即用。nb-layout 按提案只给网格与手感，面板模型、落点规则、标签条都要自己写：我这个玩具约 440 行起，难度明显更高。优势：没有停靠时搬 DOM 的问题，有 dockview 没有的收起/吸附/过渡，和 Vue 的接合更直。
- golden-layout：配置对象驱动，接入是写一份 config，再把组件挂进去；框架适配要自己做。nb-layout 在 Vue 里的接入更顺（slot、响应式），但同样没有“配置一份就出布局”的路径。
- 总体判断：如果 README 与官方示例（第 20 条）到位，nb-layout 对“想要 VS Code 手感的分栏与吸附”的第三方很有吸引力；对“要一个现成的标签停靠布局”的第三方，今天与按提案发布之后都比 dockview 难接入得多，这是提案选择的结果，但要在 README 第一句就说清，免得被拿去和 dockview 比。
