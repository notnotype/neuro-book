### 1. 依赖方向的两处文字没跟着加上 nb-layout
**严重程度**：建议　**类别**：文档
**位置**：`packages/nb-story/AGENTS.md:10`、`docs/specs/story/viewer.md:201`，次要的是 `packages/dev-panel/AGENTS.md:28`
**现象**：nb-story 的网页现在导入 `@notnotype/nb-layout/vue`。AGENTS.md 的“依赖方向：只依赖……”清单没有 nb-layout。Spec `story/viewer` 的“owner 与依赖方向”逐个列了网页的依赖（Vue 3、nb-ui、Sigma.js、nb-agent-ui、nb-markdown、nb-form），也没有它。dev-panel 的 AGENTS.md 写“组件来自 nb-ui”。
**为什么是问题**：计划说“没有 Spec 写两个宿主用哪个包的分栏”，这只对分栏行为成立。viewer.md 把网页依赖逐个列成了依赖方向合同。新依赖不登记，下次按清单审依赖的人会把 nb-layout 当成越界。
**如何核实**：`rg nb-layout packages/nb-story/AGENTS.md docs/specs/story/viewer.md` 没有结果。`viewer.md:201` 列着 nb-form 但没有 nb-layout。
**建议改法**：两处各加“分栏用 nb-layout（只进前端构建，devDependencies）”。dev-panel 那句改成“组件来自 nb-ui、分栏来自 nb-layout”。

### 2. 迁移说明说“只有两处不同”，实际不止
**严重程度**：建议　**类别**：文档、公开面
**位置**：`packages/nb-ui/docs/migration-0.4.md`，新增小节第一段
**现象**：说明写“属性、插槽与事件不变，只有两处不同”，指 `branchId`、`sashLineEnds` 没有了，以及收到 0 的一侧不再画静止接缝。同一 Task 的 `evidences/drift.txt` 还记了另外几处，说明里都没写：
- 分隔线的 `aria-label` 和 `aria-valuetext` 原来走 nb-ui 的文字端口。目录键 `splitter.resizeWidth`、`resizeHeight`、`collapsed`、`pixels` 这次从 nb-ui 的 zh-CN 和 en-US 目录里删了。现在用 nb-layout 自带的中文目录，宿主要多语言得注入 `@notnotype/nb-layout/text` 的 `LAYOUT_TEXT_KEY`。原来靠 nb-ui 端口拿到英文或自定义文字的外部宿主，迁移后会静默变回中文。
- 相邻面板吸收不了让出的空间时，新版拒绝收起（`no-room-to-collapse`），旧版不检查。
- 焦点在 `aria-disabled` 的分隔线上时，按键被忽略。

**为什么是问题**：迁移说明是 nb-ui 外部使用者改导入的唯一依据，“只有两处”不实。仓库内两个宿主不受影响，它们都没注入文字、语言都是中文，所以只是文档问题。
**如何核实**：对照 `drift.txt` 的“行为差别”一节，再看 `git show caed94657:packages/nb-ui/src/locales/en-US.ts` 里的 `splitter` 块。
**建议改法**：去掉“只有两处”的断言。补一行文字来源变化和 `splitter.*` 键的删除，写明 `LAYOUT_TEXT_KEY` 怎么接，或指到 nb-layout 的 `Splitter.md`。再补一句收起被拒绝的差别。

### 3. 构建输入的清单靠手写，新测试只钉住“清单里现在有谁”
**严重程度**：建议　**类别**：测试
**位置**：`packages/dev-panel/src/server/build.ts:20`、`packages/dev-panel/tests/panel-server.test.ts` 新增的“编进网页的工作区包”用例、`tests/web-build.test.ts`
**现象**：覆盖面本身是对的，也确实能抓到漏掉 nb-layout 的情况。
- 网页源码只导入 nb-ui 和 nb-layout 两个工作区包（`rg "@notnotype/" src/web` 核过）。
- nb-layout 没有工作区依赖，只有外部依赖 `tabbable`，由根 `node_modules` 和 `bun.lock` 管着。
- `computeBuildHash` 与 `CODE_PATHS` 由同一份 `PANEL_SOURCE_PACKAGES` 生成。
- 清单少了 nb-layout 时，我从代码推演新用例会失败：walk 不到它，哈希不变，`changed:true` 的断言不成立。没有改仓库做变异。
- 新用例和 `web-build.test.ts` 我都跑了，通过。

缺口有两处：
- 新用例里的 `["nb-ui", "nb-layout"]` 是照抄常量的字面量。网页以后再导入第三个工作区包而没人改清单时，没有测试会失败。面板就会不重建、不提示“代码已更新”，正是本 Task 要消除的那类漏。
- `web-build.test.ts` 只核 `backdrop-filter`，没有断言构建产物里带了 nb-layout 的 Splitter 样式。验收映射里“开发者面板的分栏照旧”这一格，构建通过并不能说明 nb-layout 的组件被编进去了。

**如何核实**：读 `build.ts:20` 和新用例，`web-build.test.ts` 全文只有 35 行。
**建议改法**：加一条测试，扫 `src/web` 里 `from "@notnotype/<名>"` 的工作区包名，断言都在 `PANEL_SOURCE_PACKAGES` 里。或者直接由 dev-panel `package.json` 里 `workspace:` 的依赖生成清单。
