## 1. 隐藏的侧栏被活动栏的预览展开后，指针一进展开的侧栏，判定按拿起时的几何落到别的面板，侧栏又收回去
- 严重程度：重要；类别：正确性
- 位置：packages/neuro-book/src/plugins/workbench/web/layout-drag.ts:232-240（measureGeometry 只量拿起时可见的叶）、:367-376（freeze）、:274-293（barDrop 对隐藏侧栏给 reveal）；live-drag.ts:165（reveal 也算吸收）
- 现象：本次新加“侧栏隐藏时放到活动栏，预览同样展开它”（Spec 输出 38“标签条上”最后一句）。实时布局的几何在拿起时冻结（freeze → measureGeometry），隐藏的 sidebar 那时 geometryOf 返回 null，不在 frozen.geometry.panels 里，frozen.strips 里也没有它。等够 150ms 预览把侧栏展开之后，用户自然会把指针往右移进刚展开的侧栏（想放进去或看清位置）；这时 resolveLayoutDrop 用的是拿起时的矩形，那块区域属于原来紧挨活动栏的面板（缺省布局是编辑组的左缘或中央），候选变成那块面板的 edge/center（或被拒绝 → null），再过 150ms 预览换走，展开的侧栏收回、编辑组被分开或来源收起。画面上是“侧栏弹出来，一碰它就缩回去”。
- 为什么是问题：base 上 barDrop 带 noPreview，侧栏在拖动中从不展开，这个不一致是本次引入的。预览是“放下的真实结果”，但它展开出来的那块面板却不能作为落点，指针在它上面得到的判定和画面完全对不上；plan 的“不做与风险”只写了“来源是唯一标签时邻居会动，差一点”，没覆盖这种整块面板从无到有的情况。
- 如何核实：真实运行时复现（主 Agent 跑，我没跑 e2e）：1440×900，先隐藏 sidebar，把 auxiliarybar 的视图拖到活动栏上段，等 surface 的 data-live-preview 变成 reveal 的键、sidebar 叶宽度 > 0；再把指针移到 sidebar 叶的中心，等 300ms，读 data-live-preview 与 sidebar 叶宽度：预期会变成编辑组的 edge/center 或 source-removed，sidebar 宽度回到 0。代码层面：frozen 只在 dropAt 首次判定和 nextTick 各量一次，此后没有任何路径把预览展开的面板补进 geometry。
- 建议改法：两条可选，优先第一条（部件少）：(a) reveal 的落点不预览展开，回到 base 的样子（只吸收进条目，侧栏保持隐藏，放下才展开），Spec 那句改成“侧栏隐藏时放到活动栏，条目让位，侧栏放下才展开”；(b) 保留展开，但吸收期间对 reveal 出来的面板区域判为“仍在活动栏的吸收”（sticky，类似 insideShownSlot），离开侧栏区域才换候选。无论哪条都补一条 e2e 盯住（plan 验收映射里本来就列了“隐藏的侧栏等够才展开”，现在 e2e 与单元测试都没有这条，见第 3 条）。

## 5. 落点指示下一次判定把整份几何量两遍；每次判定还整份 JSON 序列化落点
- 严重程度：建议；类别：安全与性能
- 位置：layout-drag.ts:401-406（floatDrop 里 `geometry(doc)`）、:320（previewOf 的 edge 分支为取 origin 调 `geometry(doc)`）、:354（stripDrop 原位分支 `geometry(doc).panels`）、:613-619（stableDrop 的 `JSON.stringify(next)`）
- 现象：`geometry(doc)` 在没冻结时就是 measureGeometry：每块叶 3 次 querySelector 加至多 3 次 getBoundingClientRect，再加条、标题栏、活动栏、surface。dropAt 已经量过一份 `seen`，走到 floatDrop（指针在状态栏、窗外等无落点处，落点指示每帧都走）又整份重量一次，只为了 `origin`；previewOf(edge) 与 stripDrop(原位) 同样。base 在这几处只读 surface 一个矩形。stableDrop 每次 resolve（每帧）把整个落点（含 sectors 的每块矩形与动作）JSON.stringify 一次，candidateOf 的 keyOf、actionKey 又各序列化一次动作。
- 为什么是问题：都是读，读在写前，不会多算样式，所以帧开销测量看不出来；但这是“几何一个入口”重构带来的回退（每帧多几十次 DOM 查询与分配），而且三处都只需要调用方手里已有的 `seen`。
- 如何核实：读 layout-drag.ts:232-240 的 measureGeometry 与上面三处调用；在落点指示下把指针停在状态栏上移动，DevTools 的 JS 采样里 measureGeometry 每帧出现两次（主 Agent 可选做）。
- 建议改法：floatDrop、previewOf、stripDrop 改为接收 `seen: DragGeometry`（dropAt、windowDrop、fileDrop 都已有），不再自己调 `geometry(doc)`；stableDrop 的键可以只序列化 `[actionKey, inPlace, part, sectors.active, preview.indicator, preview.areaRect]` 这几个会影响画面的字段，或者让 dropFor 的缓存命中时直接比身份。

## 7. 活动栏放满时吸收一个视图：占位可能被收进“更多”，或者把别的条目挤进“更多”，判定却还按拿起时的条目位置
- 严重程度：建议；类别：正确性（从代码推断，未在运行时复现）
- 位置：packages/neuro-book/src/plugins/workbench/web/components/WorkbenchShell.vue:299-302（toolEntries 改读 renderedDoc，pressed 仍按已提交的 visibleViews）；WorkbenchToolStrip.vue:86-91（strip/layoutStrip）；items/item-strip.ts:33-48
- 现象：toolEntries 现在跟着预览变。别处的视图被活动栏吸收时条目多一个，它的 pressed 按已提交的可见性算（为假，优先级 0）。活动栏刚好放满时，layoutStrip 进入溢出分支：要给“更多”按钮让出一格，按 rank 保留，排在后面的收起。结果是 (a) 占位插在靠后的位置时它自己进了“更多”，看不到留位，别的条目也不滑；或 (b) 占位插在前面时最后一两个条目被挤进新出现的“更多”。判定用的是拿起时冻结的条目（frozen.bar，只含当时在 DOM 里的条目），和此刻画面差一到两格。base 的活动栏读已提交的文档，拖动中不会出现这种变化。
- 为什么是问题：plan 规则三写“工具面板的头放不下时活动标签总在外面，所以被吸收的标签不会进‘更多’”，这条理由对面板头成立（活动标签优先），对活动栏不成立：活动栏的优先级是“有效可见”，被吸收的条目不是。plan 的风险只登记了“这一列有多个面板时占位差几格”。
- 如何核实：layoutStrip 的 byRank 先按 priority 再按 order；构造一个刚好放满的活动栏（矮窗口或多个侧栏视图），实时布局把 auxiliarybar 的视图拖到活动栏最下面，读 `[data-tool-band] [data-tool-entry]` 与 `[data-tool-more]`。
- 建议改法：拖动中给占位条目 priority 1（和“有效可见”同级），与面板头“活动标签总在外面”的规则对齐；或者拖动中 strip 的 hidden 集合按拿起时冻结，不随预览重算。至少把这条写进 plan 的风险。

## 未发现问题的方面
- flush 与帧顺序：LiveDrag 的 tick 在上一帧注册，先于本帧 pointermove 排的手势 rAF；flush → publish 里 clearFrame 取消手势那一帧，判定（elementsFromPoint）先于 placeCard、moveGhost、placeFloat 的写；放下中（dropping）不抢发布。drag-gesture.test.ts 两条用例盯住了。
- placeLifted / frameStyle 抢元素：Vue 3.5.39 的 patchStyle 对 next 的每个键无条件 setStyle（node_modules/@vue/runtime-dom/dist/runtime-dom.esm-bundler.js:510-548），frameStyle 在模板里直接调用、不进 computed，所以重渲染写回的就是 liftedRect 的最新值；刚拿起时元素还没 data-lifted，这次渲染从变量取；放下时 Vue 按叶的矩形写回三个键，land 的过渡照常启动。“只写变了的键”比的是上一次的 liftedRect，跨场次、吸收后再拿起都先经过一次渲染，不会漏写。
- translate 残留：placeFloat(null) 在 onActiveChange(false) 里，放下、取消、结构变化、dispose 都经过它，且先于 commit；Vue 的 style 对象里从不含 translate，不会被清也不会被覆盖。编辑器窗停靠走异步 dropPanel 时窗先回原位再停靠，与 base 的 previewFloat(null) 时机相同，不是回归。
- 反馈拆分：dragPlaceholder、dragSlotPanel、mergeTarget、feedback*、liveSectorsRaw 全部从同一个 dragView 派生；liftedCard 与 presentDrag 的 lifted 都只读 live.card；dragView 只在 computed 里读，模板与插槽里没有（grep 第 467-509 行之外无引用）。stableDrop 让 dragDrop 身份稳定，浮动落点每帧变的矩形只让 dragView 重算，下游的字符串与 null 值不变，不触发渲染。
- 落点指示行为：stripSnapshot 未冻结时 `measureTabStrip(strip)` + `tabStripInsertionIn` 就是 base 的 `resolveTabStripInsertion`（tab-strip-geometry.ts:86-88），编辑组 ownPartition 从 snapshot.members 取，与 base 读 DOM 属性等价；geometry、barEntries 未冻结时每次现量，与 base 一致。

- 活动栏的点击、右键、键盘、data-tool-entry 拖动源判定：IconButton 与它的属性、事件没变，外层 div 只给 TransitionGroup；捕获挂在根上，条目在预览里卸载不丢捕获（从代码推断，见第 3 条）。
- 跨包深导入、静默 catch、放宽断言、删除任务外代码：本次范围（master...HEAD 三点 diff）内没有发现。
