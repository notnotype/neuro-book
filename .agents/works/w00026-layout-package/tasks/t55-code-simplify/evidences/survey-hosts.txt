## 内部候选（按收益排序）

### 1. 效率：`drag-session.ts:252` 每次判定都无条件做 `elementsFromPoint`
- **现在**：`resolve: ({source, point, region}) => options.resolve({source, point, region, top: topElementAt(document, point)})`，每次 `evaluate` 都做一次整页命中测试。
- 引擎的头注释花了很大篇幅让帧里“先读后写”，免得判定里的 `elementsFromPoint` 强制重算样式。
- 但 BookFrame 的换边判定和 LivePanelsScene 的 `resolve` 都不读 `top`。这两个宿主每帧白做一次命中测试。
- **改成**：把 `DragQuery.top` 做成惰性的 `get top()`，带一次缓存，只在宿主读它时才测。类型与签名不变。
- **省多少**：不读 `top` 的宿主每次判定省 1 次 `elementsFromPoint`，指针移动时约 60 次/秒。
- **风险**：低。
  - 宿主解构 `({top})` 时才会触发读取。
  - 要查有没有宿主 `{...query}` 展开，展开会把惰性取值提前触发。我只确认了本模块的两处没有展开。
  - 工作台的 `fileDrop` 用 `top`，读一次，行为不变。
- **公开面 / 持久化**：公开类型不变，不碰持久化。
- **测试**：`drag-session.dom.test.ts`、`useDragSession.dom.test.ts`、`live-drag-session.dom.test.ts`。
  - 加一条断言：不读 `top` 就不调用 `elementsFromPoint`。
  - 还要跑 `e2e/workbench-drag-cost.e2e.ts` 看每帧上限，以及 `lab-drag-session.e2e.ts`。

### 7. 简化：`LivePanelsScene.vue` 里几处多余，约 -8 行

## 顺便发现的问题（正确性，不算简化）
1. **LivePanelsScene 的 `homeRect` 在 `settleMotion` 之前量**。
   - `live-drag-session.ts:101` 先调宿主的 `activate`，`109` 才 `settleMotion`；`LivePanelsScene.vue:167` 的 `measured()` 因此可能量到过渡中间的矩形。
   - 拿起后那一次同步判定（`start()` 里的 `publish()`）用这个旧矩形判“原位”。
   - 影响很小：候选要稳定 150ms 才换预览，第一帧 `measure`（117 行）又会纠正它。
   - 但 `live-drag-session.md` 与头注释都没说宿主的 `activate` 先于 `settleMotion`，宿主读 DOM 时不知道会量到过渡中间。
   - 建议在 `LiveDragSessionOptions.activate` 的注释或 md 里写一句。
2. **`NestedGridAcceptanceFixture.vue` 里 `unknown-ref` 与 `malformed` 场景的快照版本是字面量 `2`**（247 与 282 行）。
   - `GridSnapshot` 这一个有类型约束，版本升了会报编译错误。
   - 不带类型的 `malformedSnapshot` 没有约束，`GRID_SNAPSHOT_VERSION` 升到 3 时，它会因为版本不符而被拒，不再因为重复 id 被拒，场景悄悄测错东西。
   - 建议改用 `GRID_SNAPSHOT_VERSION`。
3. **没有发现文档与代码不一致**。
   - `live-drag-session.md` 的宿主表（`facts`、`show`、`measure`、`collapsed`、`staysWithoutSource`、`card`、`follow`）与 `live-drag.ts` 的 `LiveDragHost` 逐项一致。
   - “约定”里键盘、减少动效、`grid()` 为 null 时不问 `live` 的描述与 `live-drag-session.ts:103-106` 一致。
   - 头注释的先后（`activate` → `offer` → `end` 先于 `onActiveChange(false)` → `commitsUnderPointer` → `sampled`）与代码一致。
   - README 第 131 行与 CHANGELOG 第 18 行的措辞和导出一致。
