## 二、效率（热路径）

**9. 效率：`sashProps` 为每条分隔线建整支分支的面板配置**
- 位置：`NestedGrid.vue:412`，`buildGridBranchPanels(sash.branch.children, …)[sash.index]`。
- 现在：只用 `[sash.index]` 一项，却为每条分隔线 map 整个 `children`。一支有 k+1 个孩子、k 条线时，每次渲染分配 k×(k+1) 个对象。分隔线拖动期间每帧都渲染。
- 改成：只为那一个孩子建一项（先取 `children[sash.index]` 再交给 `buildGridBranchPanels`）。
- 省下：每帧从 k×(k+1) 次分配降到 k 次。k=5 时约 30 降到 5，绝对值很小。
- 风险：低。测试：`NestedGrid.dom.test.ts`（aria 值）、`grid-splitter.dom.test.ts`。

**10. 效率：`sashLookOf` 每条线每次渲染最多被调 3 次**
- 位置：`NestedGrid.vue:355`。调用点：`sashAriaLabel`（经 `sashProps`）、模板里 `data-sash-kind`（`:758`）、`sashBoxStyle`（`:365`）。
- 现在：宿主的 `sashKind`、`sashStyle`、`paneLabel` 回调每条线每次渲染各被调 2 到 3 次，`sashStyle` 每次还新建一个对象；并且 `sashLooks.set(...)` 写在渲染函数里，渲染有副作用。
- 改成：每条线每次渲染只算一次，再统一用。例如用 `sashAttrs(item)` 返回合并后的属性对象，`v-bind` 一次。`NestedGrid.md` 已经声明过"paneLabel 一次渲染可能问几次"，改成一次是兼容的。
- 省下：宿主回调每帧省 2/3。
- 风险：低到中，要保住"离开的线沿用离开前最后一次的值"。
- 测试：`NestedGrid.dom.test.ts` 里 `paneLabel`、`sashKind`、`sashStyle` 和交换的用例。

**11. 效率：悬停命中每次 pointermove 都读所有分隔线的矩形**
- 位置：`useSashGesture.ts:157-179`（`hitTargets`）经 `onPointerMove` 的 `winningScope`（`:81-97`）。
- 现在：非拖动时的每个 pointermove，对路径上每个 scope 做 N 次 `getBoundingClientRect` 加 N 个对象分配，再加一次 `composedPath()` 数组；没有按帧合并。N 取 10 到 20 时，鼠标在工作台上扫过去每秒几十到上百次。
- 改成（可选）：把 hover 的命中判定按 rAF 合并，或者按布局版本缓存矩形。
- 风险：中。光标和命中带的更新会晚一帧，`useSashGesture.dom.test.ts` 的光标和显现计时断言多是同步的。建议先量再定，收益不确定，我不推荐直接动。

**12. 效率：`placeFloat` 每帧扫网格根的全部子元素**
- 位置：`NestedGrid.vue:692-698`。
- 现在：拖浮动窗时每帧遍历根的所有子元素并读 `dataset`。子元素数 = 叶 + 分隔线 + 每个标签的内容项，几十个量级。
- 改成：手势开始（`offset` 第一次非 null）时按 id 取一次元素集合缓存，`null` 时清掉。
- 风险：中，换叶或新标签挂上后缓存会漏，要在 layers 变化时失效。收益小，列出备选。

**13. 效率：`useSortable` 每个拖动帧量两次布局**
- 位置：`useSortable.ts:121-133`（`measure`）在 `resolve`（`:268`）与 `watch(state, …, {flush: "post"})`（`:198`）各调一次。后者只为了取 `extent` 夹住被拖行。
- 改成：`resolve` 里记下 `extent`，post 的 watch 复用。
- 省下：每帧一次 `querySelectorAll` 加 N 次 `offsetTop` 链遍历。
- 风险：中。行高不等时，换序后 `extent` 的并集理论上不变，但这是推断，没验证。收益小，列出备选。

## 六、顺便发现的问题（不是简化）

- `NestedGrid.vue:282-298` 的 `layerContents` computed 在读取时写 `previousContents` 与 `heldLifted`。如果同一轮里有别的代码读它（例如 `useContentLayer` 里 `options.contents()` 以外的调用），或者 Vue 把它读两次，"上一轮的 contents"就会被覆盖，拿起项的留住就丢了。目前每轮只被 `useContentLayer` 的 `placements` 读一次，所以没问题，但这是个只靠"调用方恰好只读一次"撑着的不变量，在第 14 条里一起收掉最稳。
- `Splitter.vue:53` 起的 `sashSizes` computed 里有 `console.warn`，每次重算都可能再警告一次，不像 NestedGrid 那样每种只报一次（`layoutDevWarning`）。这是风格和噪声问题，不影响功能。
- `useSashGesture.ts:341` 的 `settle(source, source !== "pointer" || reason === ... ? "reset" : "refresh")` 一条三元里塞了五个条件，我没找到错误，但阅读上很难核对；改写成表驱动的小函数更好，可当可读性候选。
