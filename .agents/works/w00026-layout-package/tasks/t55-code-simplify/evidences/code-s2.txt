## 行为表（Grid 会话 grid-gesture.ts / Splitter 会话 splitter-session.ts）
| 项 | Grid 会话 | Splitter 会话 |
|---|---|---|
| 折叠没有真实变化（求解返回 collapsed 为空，带诊断） | `applyCollapse` 返回 applied:false；诊断先进本帧 issues，然后**回退再跑一次拖动求解**（位移用 `deltaOverride ?? delta`），owner.issues = 折叠诊断 + 去掉同键后的拖动诊断；若拖动求解也无结果则 owner.issues 不变 | `collapseOn` 把 `issues = result.issues`（覆盖）后直接返回 null，**不再跑拖动求解**，状态、预览、尺寸不动 |
| 折叠求解返回 null（索引越界、基线非法） | 同上：issues 不动，也回退跑拖动求解 | 返回 null，issues 不动 |
| 折叠成功 | owner.issues = result.issues；snapState 累积收起覆盖；sizes/collapsed(合并)/active=收起的 id/compensated=[] | 同左（逐行相同） |
| 拖动成功后的 issues | 折叠诊断在前、拖动诊断去重（按 `issueKey`，同键只留折叠那条）；跨支 `session.issues` 是各支 flatMap | 直接 `issues = result.issues`，不去重，不保留之前折叠的诊断 |
| 拖动结果为 null（非法输入） | 该支 `continue`，该支状态保持上一帧 | `applySolve(null)` 返回 null，状态保持 |
| collapsed 的存储 | `{...result.collapsed}` 拷贝 | `collapsed = result.collapsed` 共用引用（只读用，无可观察差别） |
| cancel 后的尺寸 | sizes 置 null，读取处按 `sizes ?? baseline`，效果是基线 | sizes = baselinePx；效果相同。其余重置相同（collapsed、active、compensated、snapState）；两边都不清 issues；Grid 另清 `pending`、`changed`；Splitter 另清 `state` |
| `jump` 的位移覆盖 | 写在 owner.deltaOverride，持续到**下一次 `update`** 才清；中间任何一次求解（包括折叠无变化后的回退拖动求解）都用它；`jump` 对每个 owner 各自求解一遍整帧 | 一次性：算出绝对位移直接 `drag(target)`，之后没有记忆 |
| `update` | 先清全部 deltaOverride，再整帧求解（所有轴一起投影） | 直接按主轴取位移求解 |
| `changed` | 每次整帧求解重算：任一支 active/compensated/collapsed 非空即 true；cancel 置 false | `state !== null`；拖动无变化时 state 置 null；折叠无变化不动 state |
| 预览产物 | `{layout, tree, changes, issues}`：对克隆树写预览意图再整体布局；`issues` 是本帧快照 | 只给 `SplitterGestureState`（含 `sash` id、sizesPx 等），几何由组件持有 |
| 提交 changes 形状 | 含 `extent`、`active`、`compensated`、`collapsed`；baseline/target 缺值回退 `owner.baseline[index]` | 只含 `branchId/axis/baseline/target/collapsed`；缺值回退 `baselinePx[index] ?? 0` |
| 多轴 | 同一棵树最多两根轴（交叉处）；`pending` 折叠只作用于发起轴 | 单轴 |
| 显式 API | `update/jump/setCollapsed/toggleCollapsed/finish/cancel` | `update/jump/toggleCollapsed/finish/cancel`（无 `setCollapsed`） |
| 相同的部分 | `collapsibleIndex`（前侧优先、`toggleable:false` 跳过）、折叠当前状态判定（`collapsed[id] ?? panel.collapse.collapsed`）、折叠成功后的状态写入（sizes/collapsed 合并/active/compensated/snapState 累积）、`jump` 的绝对位移 `sashLineOffset + sashEdgeDelta`、`withCollapseOverrides(panels, snapState?.collapsed)` 传给 `solveSashCollapse`、baseline/target 记录循环（回退值不同，见上）、cancel 里的重置 | 同左 |

读出来的其它差别：Grid 的 `applyOn` 在没有预览时把 `pending` 清掉再返回 null；Grid 会话的 `sizes: null` 与 Splitter 的 `sizes = baselinePx` 在所有读取处等价，可统一而不改行为。
