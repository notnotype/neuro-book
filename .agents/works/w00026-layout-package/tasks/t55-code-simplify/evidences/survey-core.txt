- 这个模块没有大块的无用逻辑，也没有大量没人用的分支。能删的主要是少量没有生产调用方的代码，加上几处同形重复。

- 现状：它们被 `createLiveDrag`（不从入口导出）和 `NestedGrid` 的手势会话间接使用，真正的公开入口是 `./vue` 的 `createLiveDragSession`、`useSashGesture`。
- 做法：开发者判断这些是不是要作为“通用库的可组合积木”继续发布。不发的话，`index.ts` 能少约 14 个名字、约 30 行。
- 影响：改 `index.ts` 和 `index.api.txt`；这些现在都是 `@experimental`。

## 三、顺便发现的问题（不是简化候选）

1. **`moveLeaf` 没有规模守卫。** `grid.ts:727` 起的移动不检查深度和节点数，`addLeaf`、`splitLeaf` 都检查。
   - 场景：目标是一个空分支（`children: []`，`createGrid` 能建出来），而树的最大深度正好是 `GRID_MAX_DEPTH`。叶子移进去后深度变成 17，超限，且 `serialize` 之后 `restore` 会被 `limit-exceeded` 拒绝。
   - 这是从代码推断，没复现。
2. **`planBranchResize` 的注释和实现不符。** `grid.ts:305-309` 写“计划不修改任何节点”，但 `:372` 会改子节点的 `collapse`。`resizeBranches` 是在候选树上调的所以无害；`resizeBranch`（单分支）没有 `collapsed` 参数，走不到这一行。注释需要改，或者把这一步挪出计划函数。
3. **`sash-drag.ts:322` 的循环变量 `round` 遮住了导入的 `round`。** 现在循环体里没用 `round()`，诊断阶段在循环之外，所以没出错；以后在循环里加诊断文案就会踩。
4. **两个手势会话对“折叠没变化”的处理不一致（从代码推断，未验证）。**
   - `splitter-session.ts:125` 的 `collapseOn` 在没有真实变化时仍写 `issues = result.issues`。
   - `grid-gesture.ts:313-315` 的 `applyCollapse` 在同样情况下不碰 `owner.issues`，诊断改由 `solve()` 合并后统一写入。
   - 所以同一个键盘折叠被拒的场景，`session.issues` 的内容可能不同。第 10 条要合并两者时，得先定口径。
5. **`grid-gesture.ts:182-183` 里 `projectGridGesture` 在 `children.length !== sizesPx.length` 时静默 `continue`。** 这种情况理论上不该出现，出现了说明会话基线和树对不上，现在没有任何诊断。

## 四、看过、没发现可简化的部分

- `drag-gesture.ts`（572 行）：状态机的顺序都有对应的 Spec 条目和测试守着，没有死分支；`release` 里的 `swallowClick` 和 `finish` 里的重复设置，是为了覆盖“松手后等一帧再放下”期间被取消的情形，保留。
- `frame-loop.ts`、`drag-card.ts`：已经很紧。`drag-card.ts` 每帧约 5 个小对象，没有值得省的地方。
- `live-drop.ts`、`live-drag.ts` 的整体结构：除第 13 条的 `followAt` 外，没有可合并的路径；每帧的顺序（先读、判定、再写）是为了避免强制重算样式，有注释说明理由。
- `grid-drop.ts` 的 `resolveGridInsertion` 与 `resolveListInsertion`：成员过滤循环看起来重复，但列表版故意不为落在间隙里的成员分配几何（`:285-287` 的注释）。合并会在标签条每次指针移动时多分配，不建议统一。`edgeArea` 和 `halfArea` 的重复很小，可以不动。
- `grid-rects.ts` 的 `placeGrid`：`childEdges` 里的 `slice` 和 `[...path, step]` 每次布局有少量分配，但节点数最多 256，不构成问题。
- `grid-swap.ts` 的 `planSwap`：逻辑复杂但每一步有注释，没有重复。
- `sortable.ts`、`theme-vars.ts`、`sash-hit-area.ts`（类型别名以外）、`issue-gate.ts`、`grid-failure.ts`：已经很简洁，没有死导出。`issue-gate.ts` 的 `take` 和 `replace` 分别服务手势与布局重算，不能合并。
- `scripts/api-surface.ts`、`api-report.ts`（除入口清单外）、`pack.ts`、`pack-check.ts`、`component-tags.ts`：各自职责清楚，没有多余分支；`pack.ts` 里选 `vue-tsc` 出声明而不用 `rolldown-plugin-dts` 的 `vue: true`，是有实测依据的（见文件头注释）。
- 测试文件（`grid.test.ts` 1879 行、`drag-gesture.test.ts` 926 行等）没有逐条审，只看了和上面候选相关的引用。
