## 发现

### 1. 建议｜文档｜packages/nb-layout/src/vue/NestedGrid.md（“滑出去的分隔线不再问宿主”下新增的一条）
- 现象：新增句写“回调里读的响应式状态变了、或属性里的回调换了，这张表才重算”。实际上 `useSashPresentation` 的 `looks` computed 还读 `options.layers()`，布局变化、过渡每次改 `layers` 也会重算（重问一遍宿主回调）。
- 为什么是问题：句子读起来像“其它情况都不重问”，会让宿主作者误以为布局动画期间回调不会被再问；实际与 base 一样，每次 `layers` 变（过渡中逐帧）都问。base 是每次渲染问，现在是每次 `layers` 或回调依赖变问；两者在 NestedGrid 的真实渲染触发里几乎重合，差别只在“与表无关的渲染原因”（例如 `moving`、`growing` 变化）不再重问。
- 核实：读 useSashPresentation.ts 的 `looks`（第 62 行起）与 NestedGrid.vue 传入的 `layers: () => layers.value`。
- 建议：把句子改成“`layers` 变化、回调里读的响应式状态变化、属性里的回调换了，这张表才重算；与这些无关的渲染不再重问”。

### 2. 建议｜说明与实际不符（非回归）｜packages/neuro-book/src/plugins/lab/web/fixtures/nb-layout/LivePanelsScene.vue:174

- 影响：这个 Lab 场景用 `useGridHost` 的 `host.bindings`（带 `onGestureCommit`），所以拖分隔线会走 `resizeBranches`。但同一文件的 `layout` computed（175 行）在 extent 不变时也不重算，所以 base 里拖完分隔线后布局本来就没更新，第二次拖在 base 里同样因基线与树不一致被 `stale-baseline` 拒绝。结论：不是新增的可观察回归，只是 S2 报告的核对结论说小了。
- 核实：读 LivePanelsScene.vue 36、37、174、175、206 行；`NestedGrid.vue` 的 `renderTree = preview?.tree ?? props.node`。未跑 Lab（不跑 e2e）。
- 建议：不改也行；要改就让 `node` 读一下 `host.revision.value`，与 `useGridLayout.node` 同样的写法。

### 3. 建议｜一致性（可不改）｜packages/nb-layout/src/grid.ts:468-476
- 现象：新的收起收尾用 `find(entry.id, candidate)`（整棵树按 id 找）。base 是 `find(entry.branchId)` 再在该分支的孩子里按 id 找。我删掉了 `branchId` 字段，所以不能再分支内查。
- 为什么：id 在树里唯一时两者等价；`addLeaf`、`splitLeaf` 会拒重复 id，`createGrid` 初始树不校验重复。有重复 id 的初始树里，新写法可能把 `restoreSize` 写到另一个同 id 节点。同一函数上面 `intents` 一段本来就用整树 `find(id, candidate)`，所以这是与现有写法一致，不是新引入的假设。
- 建议：不改（窄场景、已有同样假设）。

## 未发现问题的方面（逐项对照 base，读代码加跑测试）
- 重点 1 useSashPresentation：渲染里的 `sashLooks` 与新 `looks` computed 在离开的线上等价（上一张表只在这个 computed 里读写；非离开→离开→仍离开的重算值恒等；线不在 `layers` 里时新表自然不含它，等于 base 的 layers watcher 清除）。模板渲染的 sash 项全部来自 `order.items`（同一份 `layers.value` 的 key 重排），表里一定有键，`!` 不会取到 undefined。真实宿主：WorkbenchSurface 的 `sashKind` 只读 props（projection、doc、slotPanel）；`sashStyleOf` 另读 `capLeaves`、`cardOf` 等 computed，以及非响应式的 `lastPresented.cards` 与 `separatedBarRight`。逐条看后没有可达的旧结果场景：`lastPresented.cards` 只在 `presented` 里有尺寸的叶上被同步 watcher 改写，而缩回去的叶（`drawnAsBefore` 为真）此时尺寸为零被跳过；`separatedBarRight` 与读 `cards.value` 的同一依赖一起变，同步 watcher 先于惰性重算。唯一理论边缘是 post watcher 删记录，但那时叶与它的线已不在 layers（从代码推断，没有可达场景）。BookFrame 的 `paneLabel` 读 `book.details.value.items.length` 与 `tier`，都是 ref。`sashDisabled` 仍在渲染里问，没改。
