[F01 重要] S2 合并两个手势会话：两边的差别不止 issues 一处，计划对 Grid 做法的描述也不准
位置：plan.md「两个手势会话 —— 切片 S2」第 2 条；splitter-session.ts:109-134 对 grid-gesture.ts:208-225、307-330
现象：

建议改法：S2 前先写一页“两边行为表”（上面 1 到 3 的每一项各取哪边）再动手；核心只抽两边已经逐字相同的求解流程，折叠失败后的处理保留成会话各自的一小段，不强求统一；验证补用例：Enter 折叠失败后 Splitter 的 gesture-update/gesture-end 载荷与提交内容，不只看 issues。

[F04 建议] S1 moveLeaf：回滚确实不可达，但“只删 nextTree/originalTree”还会留下重复查找，守卫的位置与不变式没写
位置：plan.md「S1」第 3 条；grid.ts:766-805、:198-210（collapse）、:626-631（addLeaf 守卫）
核实结果：对着 collapse() 逐种推演——来源 S 与目标 T 不同（同分支走前面早返回）；S 删叶后只可能：(a) 剩 1 个孩子 X，X 顶替 S（T 要么就是 X，要么在 X 里）；(b) 剩 0 个孩子，S 被摘掉（S 只有 L 一个孩子，T 不可能在 S 内）；(c) S 是根且被顶替，tree=X。三种下 T 都还在。根叶没有分支，早在 not-found 返回。所以两处回滚不可达，克隆没有用；没有“改了一半”的失败路径。
仍有的问题：
 1) 去掉克隆后，前面已经找到的 hit / target 就是活树节点，stagedHit、stagedTarget、destination 三次重新 find 都成了冗余；计划只说删 nextTree 与回滚，编码者为通过类型检查（find 返回可空）多半保留 destination 的 null 检查或加 `!`。要写明用 target.node（同一对象，collapse 里 survivor.size 只改属性、不换对象）。
 2) 新增的守卫必须放在第一次修改之前（含 fixed 跨轴那条之后、filter 之前），因为失败路径没有回滚了；计划的用例“树不变”能抓到放错位置，但计划没写位置。公式要与 addLeaf 对齐：scaleIssue(scale.nodes, Math.max(scale.depth, (depthOf(parentId) ?? 1) + 1))（节点数不增加，不要照抄 +1）。
 3) 守卫按移动前的深度算，会误拒一种极端情形：T 是 S 的另一孩子 X 内的空分支，且 T 在深度 MAX；S 塌陷后 T 上移一层，移入本来合法。属于 Spec 之外的新失败条件，要么接受并在 grid.md 写一句，要么先算塌陷后的深度。
 4) 行为上有一个可见差别：成功的跨分支 moveLeaf 之前整棵树换成克隆（所有节点引用换新），之后节点引用保持。useGridLayout 已按 revision 而不是引用判变化（useGridLayout.ts:70-75 注释），生产里只有 Lab 的 GridStructureScene 调 moveLeaf，且 e2e 用的 "move-to-end"（GridStructureScene.vue:47）是同分支重排，不走克隆路径；跨分支那条只有 grid.test.ts 覆盖，e2e 覆盖不到。
如何核实：见上面行号；rg -n "\.moveLeaf\(" packages --glob '!*.test.ts' 只有 GridStructureScene.vue:47。
建议改法：计划里写明用 target.node、守卫前置与公式；用例补“已在 MAX 深度时移入空分支失败且 serialize 前后相等”之外再加一条“塌陷后变浅的合法移动”或把第 3 点记为已知保守。
