### 1. 示例缺 `flush`，与它自己的文字要求矛盾
- **严重程度**：建议　**类别**：文档
- **位置**：`packages/nb-layout/src/drag-card.md:23-45、64-66`
- **现象**：“和拖动会话一起用”一节要求“在你的 `frame` 里先调 `session.flush()`”，但开头的示例里没有 `session`，也没有 `flush`。示例里 `sourceRect()` 是在 `frame` 里读 DOM，同样没放在 `flush` 之前。`pointer` 初值是 `{x: 0, y: 0}`。
- **为什么是问题**：
  - 照抄示例、按下文挂好监听，卡片能跟手。但帧里先写卡片，会话发布的那一帧排在后面，它在判定里读 DOM，读在写后面，就是下文自己说的“每帧多一次强制的样式重算”。
  - 我确认过这一节的次序说法本身是对的：会话先排的话，它在判定里写 `data-drop-rejected`、拖影，帧循环的帧再读 `getBoundingClientRect`，同样强制重算。
  - 示例的 `start()` 排出第一帧时，如果还没有任何 `pointermove`，就用 `{0,0}` 拿起。
- **如何核实**：读文档，比对示例与下文。
- **建议改法**：示例里加一个 `session` 并在 `frame` 开头 `session.flush()`，`sourceRect()` 的读放在它之前。`start()` 前用按下点给 `pointer` 赋值，或写一句“拿起时先把 `pointer` 设成按下点”。

### 2. `start()` 撤掉已排帧的路径没有用例
- **严重程度**：建议　**类别**：测试
- **位置**：`packages/nb-layout/src/frame-loop.test.ts`
- **现象**：Spec 输出 21 写“`start()` 撤掉排着的帧并排第一帧”。实现里是 `frame-loop.ts:477` 的 `if (pending !== null) options.cancelFrame(pending)`。`frame-loop.test.ts` 里每一次 `start()` 发生时 `pending` 都是 null：首次启动、`stop` 之后、帧里 `stop` 之后。这行删掉，现有 7 条用例应当照样通过。
- **为什么是问题**：`live-drag.begin` 在上一场没收场时再 `start`，靠的就是这条。旧实现没有这条，是新增的行为，却没被测到。
- **如何核实**：读 7 条用例，找 `start` 调用时 `pending` 的值。
- **建议改法**：补一条“`start` 两次，只剩一个排着的帧，且被撤掉的那个不再跑”。

### 3. `drag-geometry.test.ts` 的几处判据没被断言
- **严重程度**：建议　**类别**：测试
- **位置**：`drag-geometry.test.ts`，对应 `drag-geometry.ts:119-129`（`bandsAfterCollapse` 的横向入口条）、`:160-170`（`windowRect`、`keepVisible`、`wholeInTree`）、`:187-203`（`sortedOffset`）
- **现象**：
  - **横向入口条**：`bandsAfterCollapse` 里 `groupEnd + move.left - shift` 与入口的 `start/end + move.left` 没有非零用例。右栏那条用例里容器还在，`shift` 为 0，入口条叶的 `move.left` 也为 0。底部面板那条用例里整条入口条消失。你问的“入口条组末端的平移”确实没测到。
  - **`windowRect`**：只测了 x 方向的夹取，y 夹取没测。`extent` 为 null 时不夹也没测。
  - **`keepVisible`、`wholeInTree`**：本身没有用例；`wholeInTree` 是新开窗在状态栏上松手时整个夹回的那一步。
  - **`sortedOffset`**：条比标签短时的 `Math.max(start, end - size)` 没测。抓点夹到 0 与 1、`size` 为 0 时取 0.5 也没测。
  - **布局一致性用例**：“测试用的布局和计算一致”这条只比较叶的 id，不比较矩形，名字说过头了。默认布局或约束常量变了，硬编码的 `LEAVES` 与投影不一致，失败会落在各条几何期望上，错误信息指向的是几何，不是常量。
- **为什么是问题**：这几处是第 3 片“只搬不改”要守住的内容。现在搬动时改坏它们，测试不会失败。
- **如何核实**：读测试，找每个分支的输入。变异检查没跑，上面“没有断言”是读出来的。
- **建议改法**：补横向入口条（比如右栏容器唯一视图被摘，`shift` 与 `move.left` 都非零）、`windowRect` 的 y 夹取与 `extent` 为 null、`sortedOffset` 的两个夹取。一致性用例改成比较每块叶的矩形，或者改名。

### 4. `drag-card.test.ts` 的覆盖与期望的独立性
- **严重程度**：建议　**类别**：测试
- **位置**：`packages/nb-layout/src/drag-card.test.ts:109-123`
- **现象**：
  - **期望不独立**：“逐帧缩向目标”的期望是 `380 + 220·e^(−n·dt/90)`，和实现是同一个指数式，只比较头 4 帧，之后只看终态。这一条不是手算常数，与 `drag-geometry.test.ts` 的期望做法不同。
