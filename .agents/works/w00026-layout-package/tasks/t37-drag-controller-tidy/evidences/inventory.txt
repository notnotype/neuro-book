二、复位点与结束顺序

1. 一场的调用顺序（行号）
- 拿起：`activate` 回调在 983 起。它由 drag-session.ts 的 `activate` 选项（238 行转给手势）调用；手势何时调用未读，不确定。
- 每次判定：drag-session.ts 241 行的 resolve 调 layout-drag.ts 1024 行的 resolve 回调。
- 第一次落到别处：live-drag.ts 234-238 调 collapseSource（layout-drag 278-288）。
- 回到原处：live-drag.ts 240-243 调 expandSource（layout-drag 289-297）。
- 结束：drag-gesture.ts 253-275 的 finish。它的调用顺序是：
  (a) drag-gesture.ts 260：host.released()，对应 drag-session.ts 260-265，拆指针与会话监听、释放捕获；
  (b) drag-gesture.ts 261：host.publish(null)，对应 drag-session.ts 244-246，state.value 置 null；
  (c) drag-gesture.ts 262：host.activeChanged?.(false)，对应 drag-session.ts 248，即 layout-drag.ts 1049-1060 的 onActiveChange(false)；
  (d) drag-gesture.ts 263：host.ended?.(end, current.last)，对应 drag-session.ts 247，即 layout-drag.ts 1042-1047 的 onEnd；
  (e) drag-gesture.ts 264：host.commit(dropped, current.source, keyboard)，对应 drag-session.ts 243，即 layout-drag.ts 1040 的 commit；
  (f) drag-gesture.ts 265-274：焦点恢复（经 requestFrame 或直接调 restoreFocus）。
- 要点：onEnd 在 commit 之前，不在之后。onActiveChange(false) 先于两者。`dropped` 从哪里来（释放路径里调 finish 的地方）没有读，不确定。

2. 各复位点清了什么
- activate（983-1021）清：sortGrab（985）、pressedAt（986，改为按下点或 null）、held（987）、editorRefusal（988）、shownDrop（989）、shownDropKey（990）、frozen（991）、beforeCollapse（992）、sourceCollapsed（993）、windowDrag（994）；newContainer 重新生成（995）；previews 缓存（Map，984）清空。
  不清：previewsOf（214）、overRejected（242）、sorting（338）。sorting 只在 live.end 里经 placeSorted(null) 释放。
- resolve 回调（1024-1037）：每次判定开头清 overRejected（1025）、editorRefusal（1026）。
- onActiveChange(false)（1049-1060）：setRejected(false)（1052）、live.end()（1054）、frozen（1055）、beforeCollapse（1056）、windowDrag（1057 先撤窗的 placeFloat，1058 再置 null）、markFloatMove(null)（1059）。
  不清：editorRefusal、held、sorting、sortGrab、pressedAt、shownDrop、shownDropKey、newContainer、sourceCollapsed、previewsOf。
  live.end() 内部（live-drag.ts 364-380）先调 host.placeSorted(null)()（378），由它读 sorting（layout-drag 369）并置 null（370）；再调 host.show(null)（379）。
- onEnd（1042-1047）：读 editorRefusal（1043）后置 null（1044）。
- collapseSource（278-288）与 expandSource（289-297）：写 frozen、beforeCollapse、sourceCollapsed、held，清 previews。

3. onActiveChange(false) 之后仍被读的绑定
- editorRefusal：onEnd 在 1043 读它。它不被 onActiveChange(false) 清，这是 onEnd 能拿到值的前提。
- sorting：onActiveChange(false) 经 live.end 间接读它（369）。这依赖 live.end 在 1054 行先于 frozen 清空（1055），但 sorting 本身不依赖 frozen。
- windowDrag：1057 行在 onActiveChange 内仍读 `.panel`，之后才在 1058 置 null。
- commit（1040）只读参数 drop、source、keyboard，以及 options.commit；本文件的 let 一个都不读。
- held、overRejected、shownDrop、shownDropKey、newContainer：onActiveChange(false) 之后没有读者（在本文件内；options.commit 的实现不在本文件，不确定它是否读）。

4. 时序注意
- freeze 在 1017 行经 nextTick 异步调用，以 live.active.value 为条件。它可能晚于一场的结束；读 live.active 那一判定是挡住这种情况的唯一条件（推断，未在更细的时序上验证）。

四、live-drag.ts 与 layout-drag.ts 之间往返的状态

不确定：host 回调里的 session.state 读取，依赖 session 是 980 行创建的 const，在 host 首次调用前已存在（推断：live 的回调都在拿起之后才跑）。
