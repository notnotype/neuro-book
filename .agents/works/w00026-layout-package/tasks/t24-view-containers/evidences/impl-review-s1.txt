F5　重要（从代码推断，未在浏览器里验证）　区域级收起 / 键盘与指针　区域拖到零之后，区域里分节之间的分隔线还在：长度为 0、粗细 1px，仍可聚焦、仍有命中带
位置：packages/nb-layout/src/grid-rects.ts:258-275（分隔线条目不看长度）、vue/SashHandle.vue:62-63（只有粗细为 0 才 inert）、sash-hit-area.ts:51-55（命中带是矩形四周各扩 5/15px）；
  触发它的是本提交的 layout-project.ts:74-79（把收起配给分支）。
现象（探针复现到“条目存在”这一步，probe4.ts）：侧栏三个分节、拖到零。placeGrid 的结果里 s1|s2、s2|s3 两条分隔线还在：
  rect {x:48,y:192,width:0,height:1}、{x:48,y:385,width:0,height:1}，size（粗细）为 1。叶的矩形是 0×192，useLeafParking 按矩形判（任一轴为 0），所以叶与内容是停放的（交付报告第七节没核实的那一项：成立）。
  分隔线这边：SashHandle 的 inert = disabled || size === 0，size 是粗细不是长度，所以这两条是 tabindex=0 的可聚焦分隔线；命中带是它的矩形四周各扩 5px（触摸 15px），
  也就是在区域那条 1px 外边界上、y=192 与 y=385 附近各有一块约 10×11（触摸 30×31）的区域同时命中“外边界（宽）”与“分节之间（高）”两条线。
为什么是问题（推断的后果）：
  - 键盘：Tab 会停在看不见的分隔线上（N 个分节就多 N-1 站），方向键与 Enter 会改停放着的分节的高度与收成标题行，用户看不到在改什么；
  - 指针：在那两小块按下，按“十字交汇同时调两轴”的规则是双轴手势，把侧栏拉开的同时改了分节高度。
  旧模型没有这个状态：拖到零的只会是一片叶，里面没有分隔线。nested-grid.md 的“分支的收起”只写了叶按停放处理，没写里面的分隔线。
如何核实：bun run /tmp/review-w00026-t24-s1/probe4.ts 看条目；可聚焦与命中要在切片 2 接上工作台后用浏览器看（侧栏放两个分节、拖到零、按 Tab；在边界上分节交界的高度按下拖动）。
建议改法：分隔线沿自己长度方向的尺寸为 0 时按 inert 处理、不进命中集合（grid-rects.ts 给条目带上长度，或 placeGrid 直接不产出长度为 0 的分隔线），
  Spec 的“分支的收起”补一句“收起为零的分支里的分隔线不可聚焦、不可拖”。加一条 NestedGrid.dom 测试。这是 nb-layout 的事，不该留给工作台。

如果要加，两条约束（都核对过代码）：

  不加缓存也能白捡的一点：anchorOf 的 Object.entries(doc.panels) 每次调用都新建一个数组，换成 for…in 即可。

F9　建议　区域级收起 / 放不下时的收走　拖到零的区域在另一根轴上仍按分节的最小尺寸算，窗口矮时会把看不见的分节“收走”并给诊断
