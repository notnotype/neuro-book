### 3. `{container: "view:X"}` 在 X 声明了别的容器时也算“有声明”：凭空建出一个不属于任何视图的隐式容器，落在 X 的 `location` 而不是 X 的容器所在的区域
- **严重程度**：建议；**类别**：正确性
- **位置**：packages/neuro-book/src/plugins/workbench/web/state/containers.ts:144-148（`containerHomeRegion` 的隐式分支）；layout-doc-store.ts:495（`moveView` 用它判“有没有声明”）
- **现象**：`containerHomeRegion("view:x")` 只看 `views.get("x").location`，不看 x 是否写了 `container`。实验 `/home/notnotype/.claude/jobs/03f32b6c/tmp/review-t24-final/exp/implicit-target.test.ts`（packages/neuro-book 下 `bun test` 通过；纯函数，不涉及运行时）：x 声明 `container: "acme.group"`（侧栏）、`location: "auxiliarybar"`，`viewHome(x)` 是 `acme.group/sidebar`，`containerHomeRegion("view:x")` 却给 `auxiliarybar`。于是 `move-view {viewId: y, container: "view:x"}` 不报 `stale-target`，而是在右栏建出 id 为 `view:x`、成员只有 y 的容器，标题取 y 的；它不是 `custom:`，空了以后 id 也一直留在锚的 `entries` 里（`settleContainers` 只删 `custom:`）。
- **为什么是问题**：输出 41 说三类 id 互不重叠，隐式容器只属于“没写 `container` 的视图”；x 写了容器，`view:x` 就既没有成员也没有声明，按 commands.md 应是 `stale-target`。之后若 x 的插件去掉 `container`，x 的“重置位置”会并进 y 所在的这个容器。只有直接带参数调用才走得到（菜单与命令面板不列没有成员的容器），所以记建议。
- **如何核实**：上面的实验；或在 view-commands.test.ts 的场地里给某个视图声明一个容器，再以 `{viewId: 别的视图, container: "view:<它>"}` 执行，看到 `ok: true` 与新建的 `view:<它>` 容器。
