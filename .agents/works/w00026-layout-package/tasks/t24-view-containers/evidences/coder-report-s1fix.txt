2. F9 的 grid 规则按“节点”做，不只按“分支”。Spec 原句（nested-grid.md“分支的收起”）：“为零的分支在两根轴上的最小尺寸都按零算，窗口放不下时不把它里面的叶算作要收走的。”
   说明第 7 条写的是“收起且 `collapsedSize` 为 0 的节点两根轴都返回 0”，我照说明做到了叶：旧模型里横向分支中拖到零的面板，也不再把所在那一行的高度下限撑高（一行全是零宽面板时这一行的高度下限变 0）。
   如果只想管分支，`collapsedToZero` 与 `minimumOf` 各加一个 `kind === "branch"` 条件即可，带容器的区域单分节时代表区域的是叶，那种情形就又回到审查报告 F9 的现象，所以没这样做。
3. “唯一显示的分节”按文档数，不看呈现。Spec 原句（输出 11）：“区域此刻只显示一个分节时它不收成标题行，没有收起按钮，`collapsed` 留在记录里，区域里又显示两个以上分节时才起作用。”
   窗口矮、别的分节放不下被收走时，文档里仍是两个分节，剩下那个照旧能收、有按钮；区域里被左右拆开的分节也按分节数算。投影给不给标题行的策略本来也是按文档结构定的，两边一致；要按呈现算的话判定得吃 `presentationCollapse` 的结果，没做。
4. 底部面板分节的命令：展开与切换也返回 `unavailable`。命令表原句：“缺省当前面板；底部面板的分节不折叠，`unavailable`。”库的 `setPanelCollapsed(…, false)` 仍然允许（说明写了“展开总是允许”），
   只是命令这一层按表的字面整条不可用；记录里残留 `collapsed` 的底部分节不算收起，呈现与没带时相同，所以不需要经命令清它。主 Agent 觉得展开应当可用的话，把 panel-commands.ts:97 的判断挪到 `collapsed` 求值之后、只拦收起即可。
5. 只剩锚的区域，往锚的交叉方向外缘放也拒绝（说明第 1 条的字面：目标是锚且不同轴就拒绝）。例：右栏的容器全空、只剩锚时，`split auxiliarybar left` 被拒绝。
   这种落点会把锚包进交叉方向的分支，区域从此认不出来，所以我认为拒绝是对的；空区域要接收新块得走锚沿区域方向的外缘。活动栏、落点解析那一层（切片 4）给空区域出落点时要用这个方向。
6. `moveView(…, {newPanelNextTo})`（W/web/state/layout-doc-store.ts:488–492）在“beside 有 container 且 `regionOf` 非 null”时点名容器。beside 所在区域的具名面板不是锚（残留记录）时，现在会从库里拿到“落点不在带容器的区域里”的拒绝，原来是成功并清掉归属。
   正常文档里遇不到（F3 的校验与读取回落之后，带 container 的面板都在带容器的区域里），没改 store；要彻底的话把那里的 `regionOf` 换成 `containerAnchorOf`。
7. `revealView`（layout-doc-store.ts:439）仍然无条件展开：对区域唯一显示、记录里残留 `collapsed` 的分节，它会把残留清掉，之后区域再有第二个分节时它是展开的。
   Spec 没说揭示视图时残留的收起记录怎么办；“揭示就是要看见它”，清掉更符合直觉，所以没改，列在这里。
8. 两句界面文案待审（zh-CN 里底部那个部件的名字是“面板”，我写了“底部面板”以免和面板头的“面板”混）：
