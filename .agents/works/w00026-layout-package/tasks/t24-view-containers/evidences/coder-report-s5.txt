三、拿不准的地方
- 没有成员的隐式容器（例如 view:乙，乙搬走后）算不算“有声明”。Spec 原句：“目标容器既没有成员也没有声明时为 stale-target”。我按“有声明的区域”算：隐式容器的区域取视图声明的 location（输出 4“隐式容器看视图的 location”），所以 {container: "view:乙"} 会把视图放回乙声明的区域并重建这个容器，不报 stale-target。“重置位置”回到没有成员的容器也依赖这一点。菜单与命令面板不会列出没有成员的容器，只有直接带参数调用才会走到这里。
- 目标就是视图自己所在的容器：已经是最后一个分节时只让容器看得见（看得见时零写入）；不是最后一个分节时移到最后。菜单不列它自己的容器，只有直接调用会这样。
- 三个“新容器”无条件都列出（在只有自己一个分节的容器里，“新容器（同区域）”效果是换一个 id）。Spec 原句：“目标是别的容器，或‘新容器（侧栏）’‘新容器（右栏）’‘新容器（底部面板）’”，没有排除条件，按字面列。
- 浮动着的视图不在任何容器里：别的容器全部列出，声明的容器有成员时既出现在容器项里，也会有“重置位置”。
- 菜单里沿用了“浮动”一组（Spec 输出 23 没列它，原菜单就有）。
- 没有 e2e 直接测“菜单开着时视图换了容器、面板 id 不变 → 菜单关闭”这一条（身份里加了容器，代码层面成立）；现有的 e2e 只测了换代。
