# 视图容器：活动栏、右栏、底部面板的一个图标是一整个容器

## 目标与范围

开发者 2026-11-09：活动栏一个图标切换侧栏的一整块内容（例：图标一是会话加资源管理器，记住位置与展开收起），右栏、底部面板也做；容器既有插件声明的也能由用户拖出来。先写提案

合同：先写提案 [工作台的视图容器](../../../../../docs/proposals/workbench-view-containers.md)，接受后改 [workbench-layout](../../../../../docs/specs/ui/workbench-layout.md)、[views](../../../../../docs/specs/workbench/views.md) 等。

## 当前状态

开发者 2026-11-09 定：右栏、底部面板也做；容器既有插件声明的，也能由用户拖出来。2026-11-10 待定项“都先按推荐”：容器里是分节，用户拖出来的容器用第一个视图的图标，旧记录不迁移、回落默认树，右栏、底部面板的入口在各自的头上。

提案 [工作台的视图容器](../../../../../docs/proposals/workbench-view-containers.md) 已提交（`reviewing`），设计审查进行中。

第一轮设计审查（都派 Opus：环境里 `sonnet` 解析到不可用的模型，两份都没起来）：逐项审查 [`evidences/design-review.txt`](evidences/design-review.txt) 18 条（阻断 2、重要 12、建议 4），拉远看 [`evidences/zoomout-review.txt`](evidences/zoomout-review.txt) 11 条。两份都指出第一稿的“容器是一次显示一个子节点的分支”会被规范形吃掉（单子分支塌陷、分支上存不了身份），已核实成立。改稿换了模型，下表按改动归类（D 是逐项审查，Z 是拉远看）：

| 发现 | 判定 | 改稿 |
|---|---|---|
| D2、Z1、Z3、D18 容器作分支会被规范形吃掉；有更省的路；备选没并排比 | 成立，改 | 容器是记录里的清单，树上只有普通面板；备选三行并排 |
| D3 没有“不活动”的通道，十几处直接读 `hidden` | 成立，改 | 可见判定收到 `isNodeShown`，切片 0 先做，容器条件只加一处 |
| D4、Z8 按具名面板名字挂的规则无处安放；宽度约束归谁 | 成立，改 | `regionOf` 取代面板名；约束来自区域与当前容器视图声明的并，切换不改尺寸意图（待定项 3） |
| D1 加版本号后旧记录走“损坏”路，窗口不再保存 | 成立，改 | 不加版本号，加字段；旧记录走“合法但不合骨架”：默认布局、下次保存覆盖 |
| D6、Z9 实时布局预览切容器与冻结几何冲突；切容器不在结构键 | 成立，改 | 不预览切容器，放下才切；当前容器进结构键与文档比较 |
| D7、Z4 分节中央放下是什么；一个分节一个标签谁保证；浮动窗停靠 | 成立，改 | 前后两半插入；文档操作保证；多标签浮动窗停靠时每个标签成一节 |
| D10、Z5 底部面板左右排不能收成标题行 | 成立，改 | 底部面板的分节只调宽、不折叠 |
| D8 右栏、底部面板的头没有几何来源 | 成立，改 | 入口条是树上的条节点（同活动栏、状态栏） |
| D5 侧栏拖到零时点当前容器 | 成立，改 | 可见就隐藏，拖到零或隐藏就展开 |
| Z10 活动栏隐藏时没有入口 | 成立，接受 | 只能用命令切换，写进已知限制（待定项 2） |
| D9 入口的拖动源、右键、键盘、两种落点的几何 | 成立，改 | 入口条是标签条：之间新建、之上并入；入口可在条里换序、搬到别的区域 |
| D11、D12、D15、Z6、Z11 声明的空白、空容器、标题图标该存还是算；没引用已有的身份设计 | 成立，改 | 沿用外壳抽象第 3 节：三类 id、按实际成员出现、标题图标按顺序求、不存 |
| D13 公开命令的新参数 | 成立，改 | 第 7 节：`move-view` 目标是容器，打开视图切到它的容器，`focusedPart` 按区域 |
| D14 容器里隐藏单个视图 | 成立，不做 | 写进非目标 |
| D16 入口条溢出、切容器的过渡、缺静态稿 | 部分成立 | 溢出同活动栏的“更多”；外观等实施计划时出静态稿 |
| D17 没有验收场景 | 成立，改 | 加 6 条验收场景 |
| Z2 推翻 ADR 0044 决策 3 没登记 | 成立，改 | 接受时另写 ADR 部分取代决策 3；Spec 改动表加一行 |
| Z7 现在只有 3 个视图，右栏、底部面板的容器是提前做 | 部分成立 | 开发者已定要做；分两步，先侧栏 |

改稿后待定项三条：默认怎么排（照例子把会话、资源管理器放进一个侧栏容器，对话留在右栏）、活动栏隐藏时只用命令、切换容器不改尺寸意图。
