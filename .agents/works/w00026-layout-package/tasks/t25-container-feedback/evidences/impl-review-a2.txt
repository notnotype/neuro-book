### 1. 过渡中反向时，元素先跳到布局终点再动
- 严重程度：重要
- 类别：正确性
- 位置：`packages/nb-layout/src/grid-motion.ts:292`（`keptSizeStarts`）、`:161`（`enteringRects` 的 `known`）、`packages/nb-layout/src/vue/useGridMotion.ts:159-176`、`packages/nb-layout/src/vue/NestedGrid.vue:256`（`structureMoving`）
- 现象：
  - 长到一半又隐藏：第二轮里这块叶是“离开”，`keptSizeStarts` 给它的起点是 `before.get(key)`，也就是上一帧布局里的完整矩形。
  - 第一次渲染 `growing` 里有它，`structureMoving` 为假，不带过渡，样式一次写成完整宽度。元素本来在过渡中途，这样写会取消过渡并一下子变成全宽，下一个 tick 才从全宽缩回去。
  - 缩到一半又显示：`decideMotion` 前后帧都滤掉了 `leaving`，所以这块叶对 `enteringRects` 是“新叶”，起点是压成零的矩形。DOM 元素同 key 复用，于是从半宽跳到零宽再长出来。
  - 内容外层的起点用的是 `leaf:X` 这个键，同样会跳。
- 为什么是问题：快速连点两下活动栏入口是常见操作，起点矩形本来是为“元素已经画在那儿”设计的，进行中的轮次里元素的实际位置不等于布局模型的矩形。
- 如何核实：
  - 在 `useGridMotion.dom.test.ts` 里让 `start` 连发两次，第二次的 `entering` 里会有 `leaf:X`。
  - e2e 的“长到一半又隐藏、缩到一半又显示”只检查最终状态和宽度，测不到中间帧。
  - 可以在逐帧录屏里量外框宽度，应该会看到一帧突变。
- 建议改法：
  - 轮次进行中（`inRound`），已经有元素的叶不写起点：`start()` 里丢弃 `move.entering` 中已画着的叶的键，让 CSS 过渡从当前计算值重新定向。内容外层换摆法那一帧要的起点，仍给上一轮没有换过摆法的。
  - 把当前 `leaving` 的 key 并进 `enteringRects` 的 `known`，这样重新显示的叶不当新叶。
  - 补一条逐帧用例，断言每帧外框宽度和上一帧的差不超过一帧该走的量。

### 2. 留着的叶被下一次变化整个丢掉；`leaving` 与 `keptSize`、`anchoredRight` 的跨轮规则不一致
- 严重程度：建议
- 类别：正确性、代码质量
- 位置：`useGridMotion.ts:172`（`leaving.value = move.leaving`）和它上面“要么回到树里，要么已经缩到了头”的注释；`NestedGrid.vue:132`（`placement`）
- 现象：
  - 隐藏侧栏后，过渡中又隐藏底部面板或做别的布局变化，第二轮的 `previous` 已经滤掉了 `leaving`，新的 `move.leaving` 里没有侧栏。
  - 赋值把侧栏整个丢掉，它在缩到一半时瞬间消失。注释说的“已经缩到了头”不成立。
  - `keptSize` 和 `anchoredRight` 是用 `carried()` 跨轮保留的，唯独 `leaving` 是替换。已丢掉的叶的键还留在 `keptSize` 里，直到 `stop`。
  - 还有一条出口：`duration <= 0` 时 `update()` 不调用 `start`。过渡中切到“减少动效”再显示同一块叶，`leavers` 还留着旧的，树里又有同 key 的叶，出现重复 key。
- 建议改法：
  - `start()` 里把上一轮 `leaving` 中这一轮树里没有的叶继续保留，只替换这一轮判出来的。
  - `placement` 里过滤掉树里已有同 key 的 `leavers`，作为保险。

### 3. 留着的外框成了“被隐藏面板的几何”，指示器式拖动在 470ms 内会量到它
- 严重程度：建议
- 类别：隐含耦合
- 位置：`packages/neuro-book/src/plugins/workbench/web/layout-drag.ts:347`（`geometryOf`）、`:358`（`measureGeometry`）、`:857-858`（只有实时分支调 `settleMotion`）
- 现象：
  - `geometryOf` 靠 `querySelector('[data-leaf=id]')` 是否存在来排除隐藏面板，此前隐藏的面板没有 DOM。

  - `measureGeometry` 只按 `doc.panels[leaf.id]` 过滤，没看面板是否显示。
- 为什么是问题：窗口很窄（约 470ms），但依赖的是“隐藏即无 DOM”这个隐含前提，现在被打破。
- 如何核实：从代码推断，未验证。
- 建议改法：`geometryOf` 或 `measureGeometry` 显式排除 `isPanelShown` 为假的面板，或排除带 `data-leaving` 的外框。
