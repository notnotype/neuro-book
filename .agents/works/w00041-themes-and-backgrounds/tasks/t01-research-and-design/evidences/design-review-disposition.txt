t01 计划设计审查（Sonnet，16 条）的处理。全部核实后改进计划，没有不改的。

[1] 内置 id 与存量设置冲突：内置保留裸 id nbook、macos，贡献点 validate 规定无点 id 只许 nbook.workbench，其余要带插件 id 前缀。不用迁移。
[2] 内置素材的 URL：声明里一律相对路径，描述文件不 import 图片；浏览器侧的内置解析表沿用 web/plugins.ts 登记消息目录的做法。
[3] 第三方素材的 URL：加窗口能力，插件 id 加相对路径得到 URL，内置与第三方走同一个函数。
[4] 声明偏离静态稿：改成每个明暗一张场景图，各位置给裁切，与开发者看过的一致。
[5] choices 与命令的波及面：S2 展开：工作台浏览器入口贡献提供者，schema 改字符串，分段控件变下拉，命令参数不再列枚举、运行时核对，Lab 场景补提供者。
[6] 配色缺键：缺的键取 base 的缺省配色合并；整份声明统一“先明暗再键”，把类型写清楚。
[7] 欢迎页的场景：editor.pages 的声明加可选 scene 字段，EditorGroup 只在没开文件或活动页声明了 scene 时画；contentX 定义单位，由容器的内边距实现。
[8] 300 KB 没有执行者：删掉硬限制，写成作者建议；内置用测试核对；补验收场景表。
[9] 服务端不认识贡献点：贡献点定义放 shared，三个位置都带。
[10] 首屏风险说法不准：第 4 步登记早于激活，不是风险；真正的差别是图片晚到，接受。热插拔未实现，验收写成重启后；目录用 receiver。
[11] prose 字体没人读：MarkdownControl 读 --font-prose，缺省回落界面字体；只给系统字体栈是已接受的限制。
[12] 侧栏下角的归属：只在 sidebar 这个 Part 画，挂在 Part 上不挂视图；高度不足不画。
[13] 无障碍偏好：消费处用 CSS @media 关掉，不加 JS 分支；“没有遮罩”改写成“不压暗、不磨砂，边缘渐变淡出”。
[14] 回退顺序：项目层未知退到用户层，再退到缺省；诊断按 id 只记一次。
[15] 变量合同的位置：src/ui/theme/skin-vars.ts 放变量名；productTheme 收解析好的主题作参数，不 import 工作台。
[16] 文档一致性：改决定编号；SDK 预设对零入口插件带素材目录要在 S5 核实。
