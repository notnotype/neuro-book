# 主题编辑器：用界面做出声明式主题

## 目标与范围

做一个相对完整的主题编辑器，绝大部分声明式主题（配色、字体、活动栏、画框、场景图与裁切）都能用它做出来，并能导出为插件、导入

合同：新增。定稿后写 `docs/specs/theme/` 下的主题编辑器 Spec，并改 [`theme/skins.md`](../../../../../docs/specs/theme/skins.md)（用户主题进同一个主题列表）。

## 开发者的决定

1. （2026-11-06）要做一个相对完整的主题编辑器：绝大部分声明式主题都能用它做出来。

2. （2026-11-06，`r1-home`）用户做的主题存在用户数据里的“我的主题”库，改完即时生效，和插件主题在同一个主题列表。
3. （2026-11-06，`r2-entry`）编辑器放在编辑区页签，也可以是独立的浮动窗口；开发者的话：“我感觉都可以。等一下好像都可以支持，新的布局包支持”。我的理解：编辑器是一个视图，页签与浮动窗口两种放法都支持，不是二选一。设置窗口里的一页不做。浮动窗口可以拖开，能解决设置窗口遮挡预览的问题。要核实：新布局包（nb-layout）能不能把同一个视图放进页签与浮动窗口。
4. （2026-11-06，`r3-palette`）配色先选主色一键推导整套，再逐项微调。
5. （2026-11-06，`r4-crop`）场景取景在原图上拖取景框，数值输入框保留并保持一致。
6. （2026-11-06，`r5-share`）导出成可安装的主题插件（zip），也能把插件里的主题导入后编辑。

## 当前状态（早先的说明，已被上面的决定取代）

结构评审板第 1 轮已发布（`review`，5 道选择题加留言），等开发者答复：用户主题存在哪里、编辑器放在哪里、配色怎么编、场景取景怎么编、分享与导入。还没写 Spec 和计划，没改代码。

我的推荐都已写在板上：用户数据里的“我的主题”库（改完即时生效）、编辑区页签（两侧真实工作台实时预览）、主色推导加逐项微调、在原图上拖取景框、导出成可安装的主题插件。

已查清的现状（决定编辑器范围）：声明里能写标题、主题包、亮暗各 33 个配色变量与 10 个角色变量、活动栏、画框线色、字体、场景图与五个位置的取景；图标集、按状态换场景、代码提供的场景声明里还没有，编辑器也做不了。不写代码的主题插件可以装（有示例 `theme-dusk`），但要重启才生效，所以实时预览不能走插件。
