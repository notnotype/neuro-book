# 主题编辑器：用界面做出声明式主题

## 目标与范围

做一个相对完整的主题编辑器，绝大部分声明式主题（配色、字体、活动栏、画框、场景图与裁切）都能用它做出来，并能导出为插件、导入

合同：新增。定稿后写 `docs/specs/theme/` 下的主题编辑器 Spec，并改 [`theme/skins.md`](../../../../../docs/specs/theme/skins.md)（用户主题进同一个主题列表）。

## 开发者的决定

1. （2026-11-06）要做一个相对完整的主题编辑器：绝大部分声明式主题都能用它做出来。

2. （2026-11-06，`r1-home`）用户做的主题存在用户数据里的“我的主题”库，改完即时生效，和插件主题在同一个主题列表。
3. （2026-11-06，`r2-entry`）编辑器放在编辑区页签，也可以是独立的浮动窗口；开发者的话：“我感觉都可以。等一下好像都可以支持，新的布局包支持”。我的理解：编辑器是一个视图，页签与浮动窗口两种放法都支持，不是二选一。设置窗口里的一页不做。浮动窗口可以拖开，能解决设置窗口遮挡预览的问题。核实结果（2026-11-06）：布局包的应用内浮动（w00026 t09）还是 `planned`，视图现在不能浮动；现有的只有 nb-ui 的 `FloatingWindow`（设置窗口在用，对话框那一档）。所以现在的做法：编辑器主体做成一个组件，页签里放一份，浮动窗口里放一份（和设置窗口同样的承载方式）；等 t09 做完，浮动改走布局包，编辑器主体不用改。
4. （2026-11-06，`r3-palette`）配色先选主色一键推导整套，再逐项微调。
5. （2026-11-06，`r4-crop`）场景取景在原图上拖取景框，数值输入框保留并保持一致。
6. （2026-11-06，`r5-share`）导出成可安装的主题插件（zip），也能把插件里的主题导入后编辑。

7. （2026-11-06，`r2-organise`）左边竖向分区导航，右边一次看一个分区；分区：基本信息、配色、字体、活动栏与画框、场景与取景、对比度检查。
8. （2026-11-06，`r2-lightdark`）顶部一个亮/暗切换，编辑区与真实工作台都跟着切；提供“从亮色派生暗色（或反过来）”。
9. （2026-11-06，`r2-contrast`）每个颜色项旁实时显示对比度，低于 4.5 标红；另有汇总分区；导出时有不合格项只提示，不阻止。
10. （2026-11-06，`r2-crop`）五个取景框叠在同一张原图上，选中的实线、其余淡显；右边列表选框、改数值，拖框与数值互相同步。

## 偏离与遗留

- 设置窗口的“主题”项旁没有“编辑…”按钮（设置行还不能放操作按钮）：入口是命令 `nbook.settings.open-theme-editor`、`…-floating` 与标题栏“视图”菜单。
- 素材不整理：被替换或移除后没人引用的素材留在 `user://theme-assets/`（需要文件服务的删除，留给以后）。
- 导入是“包里全部主题一起导入”，没有“列出后选一个”的界面。
- 页签切走时预览暂停（编辑区只挂载当前页签），切回来恢复，编辑状态不丢。
- 拖框每 120ms 保存一次（给 store 加只改显示的 `show` 能更省，收益小，没做）。
- Lab 里没有带真实场景图的场景（Lab 没有字节读取路由），取景编辑只能在真实页面或 e2e 里看。
- 取景框的位置用“参照盒”（默认布局下各位置的大致尺寸）换算，是示意；真实尺寸随窗口变。
- 已知别人的失败：`architecture.test.ts` 的跨插件导入、`AgentCompactionDetail` 缺 Lab 场景、`nb-story` 类型检查、`lab-scenes.e2e.ts` 里 `AgentConversationView` 的基线；`themes.e2e.ts` 的“书房 light”可读性用例在机器忙时偶发超时，单独重跑都过。
