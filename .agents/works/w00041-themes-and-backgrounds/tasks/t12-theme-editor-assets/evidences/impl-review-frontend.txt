审查对象：detached worktree `/tmp/review-w00041-t12-impl/wt`（c6166f61c），范围 t12 的四个提交（576a6cf2a 之后）。`master..c6166f61c` 的 diff 混入了 master 之后的别的改动（layout-drag 等），本报告只看 t12 的前端部分。

## F1 重要 / 异步状态：上传的 busy、note、failure 是组件本地状态，不跟目标走，切主题或明暗后残留到别的目标上
位置：`SceneImageSlot.vue:20-22, 40-42, 52-58, 68`；`ThemeEditorIcons.vue:129-130, 163-177`；`ThemeEditorScene.vue:66, 83`（两处 `SceneImageSlot` 都没有 `:key`）
现象：
1. 上传期间切明暗或换主题：写入目标是冻结对了，但 `busy`（按钮转圈、“移除”停用、“正在处理图片”）、结束后的 `note`（“123 KB”或“超过建议的 300 KB”）、`failure`（上传失败原因）都挂在没换的组件实例上，所以新的主题或明暗下会看到别的主题的上传状态与失败原因，且在上传结束前被停用。
2. 不用上传也有：上传成功后 `note` 一直留着，直到下一次上传才清。换明暗、换主题，或点“移除”之后，“123 KB”还在，旁边的图已经没有了。`remove` 路径（第 68 行）不清 `note`/`failure`。
3. `ThemeEditorIcons` 同理：`failure` 与 `busy` 跨主题残留，`busy` 把新主题的“更换”“移除”“复制到另一套”一并停用到上传结束。
为什么是问题：冻结目标的设计目的是“图落到发起时的那套”，界面反馈却落在当前那套，用户看到的是错的主题上有一条与它无关的成功或失败提示。Spec 编辑器输出 21 与计划都把“上传期间切走”当作正式场景。
如何核实：读代码即可（`note/failure/busy` 不在任何 watch 里，也不含目标信息；两个 `SceneImageSlot` 与 `ThemeEditorIcons` 无按 `model.selectedId + appearance` 的 key）。未跑页面。
建议改法：反馈带上目标标识，只在目标等于当前时显示：保存 `{id, appearance}` 与消息一起，渲染时比较；或者让 `watch([() => model.selectedId.value, () => model.appearance.value])` 清 `note/failure`，`busy` 用“当前目标有没有在途上传”（按目标集合记）而不是一个布尔。“移除”时清 `note`。

## F2 重要 / 正确性：写声明被拒绝或提交失败时仍显示成功，输入框照样清空
位置：`SceneImageSlot.vue:50-53`；`ThemeEditorIcons.vue:171-172`；根因在 `theme-editor-model.ts:203-214`（`#update` 被拒绝返回 `undefined`、提交失败返回 `result`，两种都不抛）
现象：`await write(...)` / `await model.setIcon(...)` 的返回值被丢弃。`#update` 在 `userThemeProblem` 拒绝（例如图标数超 64、名字不合规）、目标主题已被删（`current === undefined`）、或 `#settle` 判失败时，声明没变，原因只写进 `model.rejected`（显示在操作条下方）。但调用方接着：
- `SceneImageSlot` 照样 `note = “123 KB”`，用户看到“已存”，图却没换；
- `ThemeEditorIcons` 照样 `draft.value = ""`，用户输入的名字丢了，而这个名字根本没保存。
为什么是问题：同一屏上出现“成功提示”和“保存失败”两种互相矛盾的信号；清空输入框让用户要重新打字。上传成功但声明没写，素材文件已经留在用户素材目录里，用户却被告知成功。
如何核实：读 `#update`（返回值语义）与两处调用；model 层没有返回“是否真的写进去”的布尔值，所以调用方想判断也判断不了。
建议改法：让 `setScene/setWorkingScene/setIcon` 返回 `boolean`（写进去才为真），界面只在为真时写 note、清 draft、发 `stored`；`stored` 目前在 `write` 之前发出（`SceneImageSlot.vue:50`），也该挪到成功之后。

## F3 建议 / 正确性：输入框回车绕过 busy 守卫，上传期间能再开一个文件选择；两次上传共用一个 busy 布尔
位置：`ThemeEditorIcons.vue:143-150, 190, 192`
现象：“添加”按钮 `loading` 时被 Button 停用，但输入框的 `@keydown.enter="add"` 直接走 `add → pick → input.click()`，没有 `busy` 判断。上传进行中按回车，会再弹出文件选择，选了就并发第二个 `onFile`；先结束的那个在 `finally` 把共用的 `busy` 置 false，第二个还在飞，按钮与“复制到另一套”“更换”“移除”提前恢复可用。
为什么是问题：计划里“连续两次上传，后完成覆盖”是被接受的场景，但 busy 的含义被破坏；“复制到另一套明暗”在第二次上传没完成时点击，第二次落地后另一套与这一套不再一致，用户以为已经复制了整份。
如何核实：读代码：`add` 没有 `if (busy.value) return`。未跑页面。
建议改法：`add` 开头 `if (busy.value) return`；busy 改成计数或按目标记。

附带核实（不是问题）：brief 问的“取消文件选择后 `pendingName` 残留是否被后来的 `onFile` 误用”——`input` 只有 `pick()` 一个入口（元素 `display:none`，不可能被用户直接点到），每次 `pick` 先写 `pendingName` 再 `click()`，所以取消后残留的值不会被用到；`element.value = ""` 保证同一文件可重选；`name === ""` 那行（第 162 行）是不可达的防御，可删。

## F5 重要 / 与文档不一致且外观差：工作态场景缩略图加载失败时，既有错误行又留着破图标

## F10 建议 / 测试：图标与工作态场景用例里，注释声称的行为没有断言；几处否定断言时机太早
位置：`e2e/theme-editor.e2e.ts:211-269`
现象：
1. 名字不合规则那一步，注释写“行内给原因，不打开文件选择、不写声明”，只断言了行内原因可见；没有点“添加”并断言 `filechooser` 没触发、也没断言列表仍空。回车路径（`@keydown.enter`）整个没测，它是 F3 的入口。
2. “移除：这一套没有了，样式表也随之去掉（亮色那一套还在）”：暗色那次移除后没有断言样式表还在，“亮色还在”无证据。
3. 工作态用例里 `expect(await sceneVar(page)).toBe(idle)`（上传工作态场景后立即读一次）不是 poll，读的是“还没变”的瞬间，错误实现（上传工作态图就把空闲的 `--skin-scene` 换掉）如果在渲染一两帧之后才生效，这条会过；至少要先 `await expect(thumb).toBeVisible()` 之后再等一个稳定条件，如 poll 一段时间保持不变。
4. 结尾 `expect.poll(() => sceneVar(page)).not.toBe(working)` 只断言“不是工作中的图”，空字符串（场景丢了）也过；应 `toBe(idle)`。
5. 关闭编辑器用 `page.locator("[data-editor-tab-close]").last().click({force: true})`：`force` 与 `.last()` 都是“按位置猜”，页签多于一个时会关错，`force` 会绕过“按钮被遮住”的可操作性检查。
6. 没有固定等待（未发现 `waitForTimeout`），选择器都是 `data-*` 或角色，这方面是好的。
“读 `--svg` 计算值能否区分换与没换”：能。`iconOf` 要求计算值含 `<sha256>.svg` 这个由上传内容算出来的文件名，内置图标的 `--svg` 是内联 data URI，不会含它，所以是有效的正向判据；只是没有在上传前读一次基线（可以加一句 `not.toContain` 作对照，成本很小）。
建议改法：按上面逐条补；或承认这些注释说的是意图，把注释改成实际断言的内容。

## F11 建议 / 测试：“冻结目标”只在 model 层有单测，两个组件把冻结用对了没有任何测试
位置：`theme-editor.test.ts:341-386`（model 层）；`SceneImageSlot.vue:37-39`、`ThemeEditorIcons.vue:157-162`
现象：计划表“图标上传的异步目标：上传期间切主题、切明暗、改名、连续两次上传”登记在 `theme-editor.test.ts`，实际测的是 `model.setIcon(name, asset, target)` 带 target 能写对位置（第 365-371 行）。组件有没有传 target、传的是不是“发起时”的值，没有测试；`SceneImageSlot` 的两条路径（场景、工作态）与 `ThemeEditorIcons` 的 `pendingName` 也没有。e2e 里没有“上传期间切明暗”的用例（Spec 验收 16 明文要求“When 上传期间切了明暗；Then 图标落在发起时的那套”）。

## F12 建议 / 代码质量：两个上传组件的流程重复，建议抽一个小的 composable，而不是合并组件
位置：`SceneImageSlot.vue:30-59`、`ThemeEditorIcons.vue:138-178`；样式 `.…__file`、`.…__error` 在三个组件里各抄一份（`SceneImageSlot`、`ThemeEditorIcons`、`ThemeEditorScene`）
现象：两者都有：隐藏 `<input type=file>` 与 `click()`、`element.value = ""`、发起时冻结 `{id, appearance}`、`busy/failure` 与 `try/catch/finally`、`error instanceof Error ? error.message : String(error)`、`role=alert` 的错误行。不同的只有“上传前加工”（图要 `prepareImage`，SVG 原样）、写进声明的动作、成功后的提示。
为什么是问题：F1、F2、F3 都是这段流程里的同一类缺陷，两处各改一遍；以后第三种素材（比如声音）会拷第三份。不建议把两个组件合并（界面形态差很多）。
建议改法：抽 `useFrozenUpload(model, {prepare?, upload, write})`，返回 `{busy, failure, note, pick(el)}`，状态按冻结目标存（顺带修 F1），成功与否由 `write` 返回的布尔决定（修 F2）。同时：`SceneImageSlot` 里 `mark(part)` 动态拼 `data-scene-*`/`data-working-*` 属性名，grep 找不到、改名时测试才报，用静态的 `data-scene-upload` 等写出来更好找。
另：`ThemeEditorIcons.remove` 只是 `model.removeIcon(name)`；`removeIcon` 带的可选 `target` 参数没有任何调用方传（`theme-editor.test.ts:366` 外）；同步点击确实不需要，但留着一个没人用的参数会让人以为“移除”也要冻结。

## F13 建议 / 代码质量：`$event as string` 强转与 `NO_PROVIDER` 的来源注释
位置：`ThemeEditorScene.vue:105`；`ThemeEditorScene.vue:39-40`
现象：`SegmentedControl` 的值类型是 `string | number | boolean | null`，这里用 `$event as string` 抹平，`setPreview(value: string)` 再对字符串字面量比较。只有三个固定选项时不会错，但强转会让以后加一个非字符串选项时静默出错。可以改成 `setPreview(value: SegmentedControlValue)` 里 `String(value)`，或直接把 `previewOptions` 的值收成联合类型并用类型守卫。
`NO_PROVIDER = "none"` 的注释“贡献 id 都带点”我核对过：`shared/themes.ts:121` 用 `SCENE_PROVIDER_ID` 要求点分小写，`sceneProvider` 值不可能是 `"none"`，哨兵安全；注释可以顺手写出这个校验出处，免得改校验时漏掉。

## F14 建议 / 交互：当前提供者没发布时，只有展开下拉才看得到“未发布”，触发器上只显示一个 id
位置：`ThemeEditorScene.vue:49, 93-99`；截图 `ThemeEditor__scene-full__1400x900__light.png`
现象：`description: "未发布"` 只在下拉列表里那一项下面显示。收起时触发器写 `acme.sky.clock`，与一个已发布且生效的提供者看起来一样。用户不展开就不知道这个提供者现在没有在画图（实际是回退到静态图）。Spec 输出 20 只要求“下拉里保留它并标未发布”，所以这是满足 Spec 的，只是界面上最该告诉用户的状态被藏起来了。
建议改法：触发器的 label 本身带上“（未发布）”，或在下面的说明行下方出一行 `role=status` 的提示；至少让选中项的 label 为 `${id}（未发布）`。
另外：场景图一块没有小标题，“工作态场景”“场景提供者”“预览状态”都有小标题，同一屏上标题层次不均（看截图）；`ThemeEditorChrome` 的块标题是 `--text-muted` xs，这里是 `--text-main` sm，与既有分区不一致。

## F15 建议 / 一致性：标签与既有规范；预览 mask 的注释与实际画法不一致；预览没有加载失败的兜底
位置：`SceneImageSlot.md`、`ThemeEditorIcons.md` frontmatter；`ThemeEditorIcons.vue:274-282`
1. `docs/standards/code/components.md`（“禁止规则”档位 A）：“非宿主组件声明 `io:mutate`”被禁止，`io:mutate` 的定义是“自己发起写请求”。`ThemeEditorIcons` 与 `SceneImageSlot` 自己不发请求，请求都在 `transfer.uploadIcon/uploadScene`（Holder 注入）里，写声明经 `model`。`SceneImageSlot` 的 `io:mutate` 是 t12 之前就有的；`ThemeEditorIcons` 是新抄的。`governance:check` 过了，但标签与规范的定义对不上。拿不准处：规范“机械比对工具尚未建立，当前靠评审核对”，所以这里留给开发者判断，不一定要改，只是新增一例会让这个偏差扩大。
2. `ThemeEditorScene.md` 标签没变（`state:local, state:inject`）。它画 `<img :src>`（读素材）和持有 `previewWorking`（写模型，不是 shared-write？），标签的取舍没有问题，列出来只是为了表明我看过了。
3. `.theme-editor-icons__preview` 的注释写“和工作台里的图标同一种画法”，但工作台（`nb-ui/src/tailwind.css:89-98`）是 `mask-image: var(--svg)` 加 `mask-size: 100% 100%`，预览用 `mask: … center / contain no-repeat`。方形 viewBox 的 SVG 两者没有差别；非方形的 SVG（路由允许）在预览里按比例缩小居中，在工作台里被拉成 100% 100%，所以预览不等于真实效果。要么改注释，要么预览用 `100% 100%` 与工作台一致（预览的目的就是看实际效果）。
4. 预览是 `<span>` 的 mask，素材取不到（404、被拒）时是一块空白，没有任何提示，用户分不出“这个 SVG 是空的”“没加载出来”。缩略图那边有 `@error`，这里没有。
5. `-webkit-mask` 简写后紧跟标准 `mask`，写法与 `tailwind.css` 一致，没问题；`--icon-url` 是 `url("…")` 字符串，素材名来自 `^[0-9a-f]{64}\.svg$` 校验，不会破坏引号。

## F16 建议 / 文案与读屏：文案细节

1. 中文说明“保存不等于产品里有这个图标：没用到的名字不会报错，也看不到效果”，“产品里有这个图标”指的是“产品里用了这个图标名”，读起来像“产品里有没有这个图标这件事”。建议：“保存的名字如果产品里没用到，不会报错，也看不到效果。”英文版没有这个歧义。

## F18 建议 / 代码质量：图标名规则在组件里复制了一份，且“与声明校验同一条规则”只靠注释保证
位置：`ThemeEditorIcons.vue:123-124`；原规则 `shared/themes.ts:75`（未导出的 `const ICON_NAME`）
现象：组件写 `const ICON_NAME = /^[a-z0-9]+(?:-[a-z0-9]+)*$/u` 并注释“与声明校验同一条规则”。服务端/声明校验的那条没有导出，两份各自演化。另外，图标至多 64 个（`MAX_ICONS`，Spec 输出 21 明文），界面既不显示数量也不在第 65 个前提示，用户在第 65 个时会走到 F2 的“被拒绝却显示成功/清空输入”路径，只能在操作条下面看到被拒原因。
