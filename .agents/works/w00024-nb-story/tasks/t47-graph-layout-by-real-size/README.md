# 关系图排版按真实画布与名字的尺寸算

## 目标与范围

开发者 2026-10-31 的想法：关系图密密麻麻是因为图的尺寸太小，排版时要考虑点的大小和线的粗细。先查清“太小”是怎么来的，再改排版。**不改点与线的画法**（点一样大、线一样粗仍是 t01 评审定下的样子；点按出场数分档、线按强弱分粗细要推翻那个决定，没有做，见“待开发者定”）。

合同：[`story.viewer`](../../../../docs/specs/story/viewer.md) 输出 25（改写）、验收 3。

## 核对（2026-10-31，量出来的）

在示例《西游记》上，按 Sigma 的取景算屏幕像素（脚本在会话里，数字见 [对照页](artifacts/report/index.html)）：

- 排版出来的外框近似正方形，而 Sigma 默认镜头把外框的长边放进画布的短边，所以在 1411×745 的画布上图只占约 565×557 像素，**占画布 27% 到 30%**，左右两侧各空出一大片。
- 去重叠（noverlap）按画布宽度算每个点占多少图坐标，实际取景却受画布短边限制，两者差约两倍：它以为有 1500 像素，屏幕上只有 700 像素。再加上它把每个点的名字当成以点为中心的圆（名字其实在点的右边，又宽又扁），三轮到上限仍有重叠，只记一条诊断。
- 关系图里每个点都强制出名字，225 个点就有 225 个名字框挤在一起：第 57 回名字框互相重叠 463 对，第 100 回 2101 对。

## 做法

- 排版（`web/graph/sigma-kit.ts`）：力导向和应力排版推开重叠的那一步换掉。先把外框仿射拉伸成画布的宽高比（至多 3 倍，点的相对次序和线的交叉数不变），再按“铺满时一个图坐标占几个像素”把每个点的“圆圈加右边的名字”当矩形，沿重叠少的方向两两推开；推开让外框变大、比例变小，所以每一轮先拉回画布的比例再推，至多四轮。没有随机数。去掉了 `graphology-layout-noverlap` 依赖。
- 强制出名字（`chooseForcedLabels`）：主要人物一定出，其余按权重从大到小，名字框面积合计到画布的三成为止。点少时全出，点多时只出主要的，其余的悬停、选中（`Focus` 本来就强制出邻居的名字）或放大后出。
- 取景（`fitAll`）：按外框的宽高比铺满画布，替换 Sigma 的 `animatedReset`；首次显示、重新排版、“铺满”按钮都用它。容器变宽变窄时，镜头还在上次铺满的位置（用户没缩放平移过）就重新铺满。
- `StoryNetwork.vue` 排版前取容器的宽高（减去取景的边）传给排版；`.md` 与 Spec 同步。

## 开发者的决定（2026-10-31）

点的大小与线的粗细不动；点多时只出主要名字、三成面积的预算同意。下面是当时列出的待定项。

- **点的大小、线的粗细要不要变**：这次只改了排版，点还是一样大、线还是一样粗。想让点按出场次数分档、线按强弱分粗细，要推翻 t01 评审“点一样大、线一样粗，多少写在线上的字里”这条；排版现在已按像素算尺寸，换成不同大小时只要把 `size` 传进去（`footprint` 读的就是点的 `size`），不用再改排版。
- **点多时只出主要的名字**是新行为：之前 225 个名字全部强制出（叠成一片）。三成的面积比例是我定的，想多出或少出改 `LABEL_BUDGET`。
- 线上的字（关系词、“可能是同一人”）没有参与排版去重叠，第 57 回仍有叠在一起的线字。

## 没覆盖的

- 手机宽度、1280 以下的窗口；点多到画布放不下时（第 100 回）仍有重叠。
- 应力排版只有单测，没有在浏览器里看；同心、环形排版没动（它们是规则的圆圈，只换了取景）。
- 拖动一个点后不重新去重叠；点在“铺满”之外被用户拖出去后不处理。
