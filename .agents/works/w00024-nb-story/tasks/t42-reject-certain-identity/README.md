# issue 266：驳回确定的身份说法

## 目标与范围

`revisions.reject` 放宽到确定的身份说法，驳回后这条身份连线消失，可撤销；网页人物卡“同一身份”一栏给断开入口；命令行人物卡带说法编号。不做“拆开对象”：不新增修订种类。

合同：[`story.revisions`](../../../../docs/specs/story/revisions.md) 输出 3（改写）、输出 8、失败码 R2、验收 2；[`story.viewer`](../../../../docs/specs/story/viewer.md) 新增输出 64；[`story.queries`](../../../../docs/specs/story/queries.md) 的 `entity.card` 的 `identities` 多一个 `statement`。来源：[issue 266](https://github.com/notnotype/neuro-book/issues/266)。

## 核对（2026-10-30）

issue 把玄奘、法明、取经使命并在一起，判断为“对象一级的合并”，没有可驳回的说法。示例图里不是这样：e8-11、e9-8、e9-9 是三个对象，用两条确定的身份说法连着（`s9-16` 在 9.17、`s9-38` 在 9.32），都是 #264 的“取法名”“认定取经人”类错误。限制只在 `ops.ts` 的入口：`reject` 只收候选。套用层（`apply.ts` 的 `identity.reject`）本来就是按编号把说法去掉，不看确定性。

## 做法

- `isRejectableIdentity`（`core/overlay/items.ts`）：身份类、非否定、连两个不同对象，确定性不限；`reject` 用它，`confirm` 仍只收候选。
- 列表：有决定的确定说法也列入（已驳回，可撤销），没有决定的确定说法不是待确认项；被驳回的确定说法不再使候选“后文已确认”（`closed`），候选重新待确认。
- `entity.card.identities[].statement` 给出把对象连进来的说法编号；命令行人物卡写“（对象编号，说法 sN-M）”；错误提示改写。
- 人物卡“同一身份”每项后面一个断开按钮（“你加的”连接除外），点了驳回，下面出“已断开：名字”和撤销。

## 验证

- 新增单测：驳回确定说法后人物卡连线换成另一条、点数不变、`closed` 不变；两条都驳回后拆开、点数加一、候选 `s21-2` 重新待确认；撤销全部还原；驳回非身份说法得 `revision_not_candidate`。变异检查：入口改回只收候选，该测试失败；去掉“被驳回不算已确认”，两条测试失败。
- nb-story 单测 643 条通过，类型检查（含 web、e2e）通过；`revisions.e2e.ts` 10 条通过，其中新增 1 条走真实浏览器点断开、再点第二次、撤销。
- 示例《西游记》上没有实跑：issue 里的 `s9-16`、`s9-38` 在示例图里存在，机制与样例书相同；示例图还会被重抽替换。

## 当前状态

已完成并合入 master，没有单独的实现审查。issue 266 没有回复也没有改标签。

## 没覆盖的

- 一对对象被多条确定说法连着时要逐条断开（样例书里 e1-1 与 e6-2 有 s6-25、s8-11 两条）：人物卡每次只给当前连着的那一条的按钮。要“一键拆开这两个对象”需要新增修订种类，另起 Task。
- 由确定的身份说法派生出的“本人知道”等记录随说法消失，但此前依赖它的秘密显示是否合理没有逐个看。
- 断开按钮的外观没有截图复核。
