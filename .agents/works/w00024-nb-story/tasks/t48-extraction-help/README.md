# 抽取时向外求助：书外知识先查再问

## 目标与范围

抽取遇到看不懂的书外知识（梗、网络用语、典故、游戏或同人术语、真实地名）时能提问：先派能联网搜索、读网页的 agent 查，查不到再问用户；按答案会改哪类记录决定停不停。先做 20 章实验，用数字定分级再写 Spec。

合同：会改 [`story.ingest`](../../../../../docs/specs/story/ingest.md)（新的求助出口、等回答的状态、书外词条进请求），可能牵动 [`story.revisions`](../../../../../docs/specs/story/revisions.md)（它写明第一版不做“有待确认就暂停抽取”，留了位）。实验之后再写。

## 起因

开发者 2026-11-09 提出：让 agent 看书时会遇到梗或它知识里没有的东西，nb-story 的抽取没有考虑这一点，应该给抽取程序一个提问的出口；问开发者是否阻塞后续抽取、能否分级，回答者是用户或一个能联网的 agent。同日开发者定“按推荐”，即下文的分法与先做实验。

现状（2026-11-09 查的代码与 Spec）：

- 抽取逐章往后，一章的请求只有截至上一章已提交的记录与本章原文（ingest 输出 4）；一章理解错了，错的记录会被后面每章当已有记录接着用。事后能改的只有修订覆盖层管的身份、对象种类、称呼三类，说法本身不改，也不重抽。
- 抽取里已有的 `questions` 是书里的悬念，不是抽取程序自己不懂的东西；新出口要另起名字，暂叫“求助”。
- 在 nb-story 的 `src` 里没搜到联网搜索的配置。

## 定下的做法（2026-11-09 开发者按推荐）

按问题的来源分，再决定停不停：

| 问题 | 谁回答 | 停不停 |
|---|---|---|
| 书外的知识 | 当场派能联网的 agent 查，答案带出处 | 本章等它查完，不等人 |
| 书外的知识，agent 查不到 | 用户 | 答案决定“这是不是一个人或一样东西的名字”时，停在这一章提交前等回答；只影响一两句意思的，先按最可能的理解写、标“待核”，接着抽 |
| 书里的歧义（反讽还是真心、新名字是不是某人的外号） | 不联网；先写候选，后文交代了再更新，进待确认页 | 不停 |

- 停不停由程序按“答案会改哪类记录”判断，不让模型自报轻重：会改对象（新建、合并、算作谁的外号）的才停。
- 联网的 agent 只查书外的东西，不查这本书本身（百科、书评、同人维基）：那里有后文，会把剧透写进前面章节的记录，破坏按阅读位置不剧透与“谁在什么时候知道什么”。
- 查到的答案存成每本书的“书外词条”，后面章节遇到同一个词直接带进请求，不重复查、不重复问。
- 等回答时停下的任务和现在的“已停止”一样能接着抽；另给一个开关“全部先猜后核、不停”，给挂一夜跑的场合。
