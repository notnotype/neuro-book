# issue 264：西游记示例的三类抽取错误（身份乱并、本人身份当成本人知道、同名化身串事）

## 目标与范围

按 issue 264 修规则和编译：本人自己的身份不再默认成本人知道、规则写明取名拜师认出不算同一个体与同称呼的不同次化身各建秘密、示例 README 补已知的不足；重抽另待授权

合同：[`story.ingest`](../../../../docs/specs/story/ingest.md) 的行为合同没有变；改的是发给模型的抽取规则文字（`rules.md`）与示例说明。来源：[issue 264](https://github.com/notnotype/neuro-book/issues/264)。

## 核对（2026-10-30）

对着示例图 `xiyouji-graph.json.gz` 与代码逐条核对，三条都成立，原因不同：

| 条 | 成因 | 处理 |
|---|---|---|
| 1 身份乱并 | 示例里对象没有被合并；`knows` 的别名来自模型写的“确定”身份说法：s1-30（须菩提祖师授名）、s9-16（法明和尚给江流取名）、s79-3（国丈认出和尚是孙大圣，`about` 带了国丈）、s72-5 与 s80-3（妖精“其实是”妖精，`about` 带了玄奘）。规则本来就写了取名拜师不算，是模型没守，且没有被认出的人、被捆的人也不能进 `about` 这一层 | `rules.md` 写明 identity 两头只能是“被说成同一个个体”的两头，认出者、说破者、被捆者不在其中，给三个反例；常见错误加一条 |
| 2 本人身份当成本人知道 | `compile.ts` 约 600–614 行：确定的身份说法连着一个马甲和一个非马甲，就替非马甲一方补“知道，这是本人自己的身份”。变身、化名成立，前世、转世不成立（金蝉子，示例里这类程序补的记录共 29 条）。漏掉的知情人（白骨精等）是抽取覆盖不足，没有核原文 | `rules.md` 知情一节写明例外：转世、失忆、被蒙蔽的身份，由模型自己为本人写一条 `unaware`（`inferred`），程序看到本人已有记录就不补；补编译测试（手写记录压住程序补的，其余不变） |
| 3 同称呼两次化身 | 第 84 回的揭晓（k84-1、k84-2）被挂在第 14 回的秘密 x14-1 上，规则里没有话告诉模型两次化身要各建各的 | `rules.md` 秘密一节写明：同称呼可先后指不同的一次，后文揭晓先对照已有秘密，不是同一次就新建，看不出时宁可新建；常见错误加一条 |

没有走程序判据的两条路，原因：

- 用“马甲是否出场（`as`、说话人）”区分前世身份与真变身：在示例的 29 条上不成立（金蝉子在草稿里也有出场记录）；
- 编译警告“两端都是普通人物的确定身份说法”：示例里这类 25 条（共 75 条确定的身份事实），多数是合理的变身，会淹没真问题。
