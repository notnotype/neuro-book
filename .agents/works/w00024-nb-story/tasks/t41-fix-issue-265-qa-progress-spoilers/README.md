# issue 265：设了阅读位置时，问答过程里不显示阅读位置之前搜不到的搜索词

## 目标与范围

命令行进度与网页的工具步骤，对阅读位置之前没有命中的搜索词和对象名不显示原词；思维链实测；改 story.qa 输出 12、story.viewer 输出 42

合同：[`story.qa`](../../../../docs/specs/story/qa.md) 新增输出 43、[`story.viewer`](../../../../docs/specs/story/viewer.md) 新增输出 63。来源：[issue 265](https://github.com/notnotype/neuro-book/issues/265)。

## 核对与做法（2026-10-30）

issue 复现属实：示例导入后 `search 六耳猕猴 --at 57` 0 条、`--at 58` 命中 58.29。泄漏点有四处：命令行进度（`describeTool`）、网页推送的运行事件（`message_update` 带整条半截消息）、推送的日志帧、`qa.get` 返回的日志。

做法（[`qa/spoiler.ts`](../../../../packages/nb-story/src/qa/spoiler.ts)）：参数里 `query`、`entity`、`other`、`track`、`perspective` 的词，在阅读位置之前 `search` 不到就整个值显示成“（阅读位置之前没有结果）”；工具结果文字回显了被隐藏的词，换成“（…）”；设了阅读位置时思考块不给网页；位置就是最后一段时一律原样。引擎里进度、日志条目、事件排在同一条队列，保持先后，一轮结束前等队列走完；存下的日志与交给模型的内容不变。`qa.get` 按对话现在的位置处理。

实施中发现并修的一处：流式的半截工具调用还带一份原始参数文字（`partialArgs`），只替换 `arguments` 时它照样泄漏；改为只留 `type`、`id`、`name`、`arguments`。这一处由服务级的测试（真实服务进程与本机端点）发现，脚本化模型的引擎测试看不到。变异检查：关掉屏蔽，引擎测试两条失败；去掉对 `partialArgs` 的处理，服务测试失败。

## 没覆盖的

- 模型在过程中写给人看的普通文字（不是工具调用与思考）里可能直接说出后文的词：它与回答正文是同一类内容，没法靠“搜得到”判断；
- 阅读位置落在未抽取的尾部时，原文里读过的词图里搜不到，会被多隐藏。
