# 设计：核心包与插件的接口、快照与控件名、动作、截图、高亮、光标

## 目标与范围

按 Work README 的“已定的事”出设计：nb-page-agent 的公开接口（快照格式与引用规则、动作、截图、高亮、光标）、Vue 指令、内置插件的入口与远程服务、`nbook` 全局对象的接口与文档生成、审批档位；对照调研做 Playwright 子集名与自造名的小实验。

合同：只做设计，行为合同未变。

## 当前状态

2026-10-30 经 nbdev 新建。2026-11-26 开工：两个只读子代理查了服务端到窗口的通路与前端现有部件，另请一个只拿到目标的子代理独立出了一版方案（大方向一致，本稿取了它的几处细节），主会话核实了 driver.js 1.14 的能力，写出[设计稿](design.md)第一稿，开发者当天确认（决定 1 到 9）。

## 决定

| 编号 | 日期 | 决定 |
|---|---|---|
| 1 | 2026-11-26 | 全局对象叫 `ui`，方法平铺；不叫 `nbook`（eval 的对象与方法必须属于同一个插件），以后设置、命令各由拥有它的插件出自己的对象 |
| 2 | 2026-11-26 | 分两批交付：先快照、截图、高亮、目标窗口与稳定名；再点击填写等动作、Agent 光标、提示条与停止按钮 |
| 3 | 2026-11-26 | 用户中途切窗口 Agent 不跟：选中的窗口用到它断开、转后台或 2 分钟没调用；换了窗口旧引用作废，重新快照 |
| 4 | 2026-11-26 | 截图的同意走现有审批（`exec` 档，可“本会话都允许”）；密码框与标了不公开的控件总是遮住 |
| 5 | 2026-11-26 | 点击、填写等动作算 `write` 档（与浏览器插件对外部网站按执行档不同） |
| 6 | 2026-11-26 | 引导可以等用户点击（`highlight` 的 `until: "click"`），nb-harness 加“正在等用户”的标记，等待不计入 eval 时限 |
| 7 | 2026-11-26 | 不做命名对照实验，动词直接用 Playwright 的 |
| 8 | 2026-11-26 | 设置的读写接口与窗口状态的只读面移出本 Task，以后要时另开 |
| 9 | 2026-11-26 | 不做页面内执行任意脚本（`evaluate`） |
| 10 | 2026-11-26 | 安全边界先不做（第二稿的“安全区与不公开的内容”整节，以及高亮说明框的来源标记）：开发者原话“有点耗费时间，没有安全需求的话收益也不大” |
| 11 | 2026-11-26 | 高亮自写，不用 driver.js（第二稿“待开发者定”第 3 条，开发者答“同意”） |
| 12 | 2026-11-26 | 删除、清空一类后果大的点击要确认，第二批做（第二稿“待开发者定”第 6 条，开发者答“同意”） |
| 13 | 2026-11-26 | eval 的两层审批保持现状（代码一层、代码里调的每个工具再按各自档位一层）；想让 eval 只当“组合工具”的用户可以给 `nbook.agent.eval` 写放行规则，现有规则页就能写。开发者原话：“第二层感觉并不多余……eval 内调用的工具其实和 eval 外调用的工具一样的，只是 eval 可以把工具组合起来” |
| 14 | 2026-11-26 | 不做 `v-nb-target` 指令，名字分自动与手写两层（第二稿“待开发者定”第 2 条，开发者答“同意”）；`ui` 在 Profile 页按对象一行开关，第一批做 |
| 15 | 2026-11-26 | 高亮加“下一步”（`until: "next"`）、进度（第几步，共几步）与“跳过引导” |
| 16 | 2026-11-26 | 拖拽不做真的拖，第二批做“拖拽指引”（起点到终点的箭头，用户自己拖，Agent 用 `waitFor` 等结果）；逐字打字看实验 2 再定（能做就给 `fill` 加选项）；保留 `check`（同 Playwright 的 `setChecked`）；说明框加“提问”，以 `asked` 结束并带问题；第一批加 `missed`（用户点到了别处）；可复用的“引导脚本”以后另开 Task。开发者原话：“这几点都同意” |

开发者对决定 1 到 9 的原话：“可以”（推荐见设计稿“待开发者定”）。
