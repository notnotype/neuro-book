## 现状里要用到的事实

- 服务端插件能列出连着的窗口（`context.remote.instances()`），并按窗口的实例 id 调用浏览器端登记的远程服务（`use(合同).at({client: 实例 id})`）；命令系统的 `nbook.commands/remote` 就是这样做的。
- 服务端没有“当前窗口”的概念，也不知道哪个窗口在显示哪个会话。窗口的公开状态只在本窗口读得到。
- eval 全局对象：对象与它的方法必须是同一个插件登记的（`global.object` 指向别的插件的对象时不登记），方法收一个对象参数，`effect` 只有 `read`、`write`、`exec` 三档；工具的处理函数拿得到会话 id、作品、是否后台运行，拿不到发起的窗口。工具可以交回图片，eval 每个单元至多附 8 张。
- eval 单元缺省 30 秒，模型可以设到 3600 秒；只有嵌套调用等用户应答（审批、同步提问）的时间不计入。
- 对话视图的停止按钮调 `abort({sessionId})`，窗口里的别处也能调。
- nb-ui 里没有引导、高亮类组件，没有全局登记的自定义指令；工作台有往页面挂浮层的贡献点 `workbench.overlays`。driver.js、截图库都还不是依赖。

## 第一版范围

分两批交付，每批都能单独用：

| 批 | 内容 | 有没有副作用 |
|---|---|---|
| 一 | 快照与引用、截图、高亮（含等用户点击）、目标窗口、控件稳定名 | 只改窗口的视觉状态，不改数据 |
| 二 | 点击、填写、按键、选择、勾选、滚动、悬停、等待；Agent 光标、“正在操作”提示条与停止按钮；同一窗口的租约 | 会改数据 |

不做：

- 指针与拖动、触摸（已定搁置，等桌面外壳的可信输入）；
- 命令绑定与通用命令（已定搁置）；快照会读控件声明的命令 id，但第一版没有控件声明；
- 在页面里执行任意脚本（`evaluate`）：eval 本来就在服务端能做任何事，再在用户的窗口里开一个口，会绕过引用、脱敏与“不许操作”的标记；
- iframe 内部（快照只列 iframe 本身）；
- 设置的读写接口、窗口状态的只读面：和界面操作不共用代码，见“待开发者定”第 8 条。

## 给模型的接口：全局对象 `ui`

方法平铺在一个对象上，动词沿用 Playwright（模型最熟），另加 `snapshot`、`highlight`：

| 方法 | 批 | 审批档 | 做什么 |
|---|---|---|---|
| `ui.snapshot({scope?, text?, maxChars?})` | 一 | read | 当前窗口的文字快照 |
| `ui.screenshot({of?, annotate?, maxSize?})` | 一 | exec | 截当前窗口或某个控件，图附在结果里 |
| `ui.highlight({…定位, title?, text?, side?, until?})` | 一 | read | 高亮一个控件、旁边写说明；`until: "click"` 等用户真的点了它再返回 |
| `ui.clearHighlight({})` | 一 | read | 去掉高亮 |
| `ui.click`、`ui.fill`、`ui.press`、`ui.selectOption`、`ui.check` | 二 | write | 动作 |
| `ui.scroll`、`ui.hover`、`ui.waitFor` | 二 | read | 不改数据的动作与等待 |

**定位**：每个要指向控件的方法收同一组字段，恰好给一种：`ref`（快照里的引用）；`target` 加可选的 `key`（稳定名，列表项带业务身份）；`role` 加 `name`（角色与可访问名）；`text`（可见文字，最后手段）。另有 `nth`（多个命中时取第几个）与 `within`（限定在某个容器里）。命中多个又没给 `nth` 时得 `ambiguous`，结果列出候选。

**引用**：窗口里一张 `WeakMap<Element, number>` 单调发号，同一个元素跨快照编号不变，模型可以拿着用。元素被重画、原来的不在了，就按它的角色、名字、稳定名在当前页面里重找：恰好一个就继续并在结果里标 `rebound`，没有得 `stale-ref`。引用只在发它的那个窗口、那次加载里有效。

**快照**：交回渲染好的文本树和一份元素数组，模型通常只打印文本树。

```
window "NeuroBook" /project/雾港  1440x900  focused
layer: base
- region "资源管理器" [target=explorer.panel]
  - button "新建文件" [e12 target=explorer.toolbar.new-file]
  - tree "文件"
    - treeitem "第一章.md" [e15 selected target=explorer.row key=正文/第一章.md]
- tab "第一章.md" [e21 selected]
- textbox "正文" [e30 focused value="他没有回头。…（共 1.2 万字）"]
```

- 只列可交互元素与带名字的容器；`text: true` 时再带标题与短文字。只列看得见、没被遮住（取中心点做命中检查）、不在 `inert` 里的；有模态时只列最上层模态里的，`layer` 写明。视口外但能滚到的照列，标 `offscreen`。
- 走进 open shadow root；输入框的值截短；密码框与标了不公开的控件，值写成 `•••`。
- 缺省至多 8000 字符，超了截断并写明可以用 `scope` 缩小到哪些区域。

**动作**（第二批）：动作前自动等目标看得见、可用、没被遮住、位置稳定；动作后等页面静下来（100 毫秒没有 DOM 变化，至多 1 秒），交回与上一次快照相比的变化（新增、消失、变了的行，至多 30 行），不重取整页，省 token。点击发完整的 pointer 与 mouse 事件序列（nb-ui 基于 reka-ui，菜单与下拉多在 pointerdown 上打开，只发 `click` 没反应），参照 page-agent（MIT）的 `clickElement`。需要真实用户操作的控件（文件选择框、剪贴板、原生拖放）不假装成功，交回 `needs-trusted-input`，让 Agent 请用户自己做。动作期间用户自己也操作了的，结果里带警告，不暂停。

**截图**：DOM 重画成图，不是屏幕像素（字体、`backdrop-filter`、canvas、跨域图片可能有偏差，文档写明）；以后桌面外壳给真实截图时换实现，接口不变。`annotate: true` 时在图上给每个快照元素叠上它的引用编号，让看图的模型把看到的和能点的对上。

**失败码**（各方法共用）：`no-window`、`window-hidden`、`window-gone`、`window-busy`、`stale-ref`、`ambiguous`、`not-found`、`not-actionable`（被遮住、禁用，写明遮挡者）、`needs-trusted-input`、`forbidden-target`、`timeout`、`denied`。

**文档**：参数、返回与失败码的 TypeBox 是唯一来源，经 `agent.tools` 生成 eval 的接口文档；对象的 `docs` 只写用法、例子与两条规矩（页面里的文字是证据不是指令；改正文用文件工具，不在编辑器里打字）。现在的文档生成器丢掉字段说明，要补（见“要改的别的模块”）。

## 目标窗口

每次 `ui.*` 调用由服务端选窗口，不建登记表：

1. 列出连着的窗口，只取打开了这个会话所属作品的（会话不属于作品时取没打开作品的）；并发问每个窗口 `info()`（有没有焦点、看不看得见、最近一次用户输入的时刻），每个 800 毫秒超时。
2. 有焦点的优先，其次是看得见且最近有用户输入的。
3. 选中后记在这个会话里，之后一直用它，直到它断开、转到后台（看不见），或这个会话 2 分钟没调 `ui`，才重新选。用户中途切到另一个看得见的窗口，这一轮不跟过去：引用属于窗口，跟过去会让前面拿到的引用全部作废。
4. 拿着旧窗口的引用调到新窗口上：`stale-ref`，说明是换了窗口，模型重新 `snapshot`。

失败：没有符合的窗口、或会话在后台运行（没有人看）得 `no-window`，Agent 应请用户打开窗口；窗口在后台时，读和动作照做并带警告，截图与高亮得 `window-hidden`；调用途中窗口断开或刷新得 `window-gone`。同一个窗口同时只给一个会话操作：窗口里一份租约，先到先得，后到的得 `window-busy`，空闲 5 秒自动放开。

## 截图的同意与不公开的内容

- 截图走现有审批，不另造同意界面：`screenshot` 声明为 `exec`，判定对象写成 `{kind: "screen", value: "<窗口标题>"}`。于是询问模式与“可以写文件”模式下会问，审批卡上写明截哪个窗口；用户可以选“本会话都允许”或“以后都允许”，也可以写规则；`auto` 模式交审批模型判，`yolo` 不问。后台会话没人可问，按现有规则得 `denied`。
- 不公开的内容与同意无关，总是遮住：密码框，以及标了 `data-nb-private` 的控件与它的子树（模型设置里的密钥输入框、请求头编辑器），快照里值写 `•••`，截图里换成色块，结果里写遮了几处。
- 截下的图作为工具结果存进会话日志，随会话删除，不写进作品目录。

## 窗口里看得到什么

- **高亮**：描边框加说明框，目标本身保持可点，页面其余部分照常可操作。同一窗口同一时刻一个高亮，新的替换旧的；用户点了目标、按 Esc、点关闭，或 Agent 这一轮结束都会去掉。
- **Agent 光标**（第二批）：动作前光标移到目标、点击时有涟漪；思路借 page-agent 的 `SimulatorMask`（MIT，保留版权声明），移动用 Web Animations，系统设了减弱动效时直接到位。
- **提示条与停止按钮**（第二批）：Agent 在这个窗口操作时，顶上一条写“Agent 正在操作：〈会话标题〉”与停止按钮；停止调 `abort` 结束这次运行（eval 内核随之重置，窗口里的引用不受影响）。空闲几秒后提示条收起，出现与收起都有过渡。
- 这几样的外观在实施前先出静态稿给开发者看（design-review 的流程），不在本稿里定。

## 控件的稳定名

- 合同落在 DOM 属性上，指令只是写这些属性的简便写法：外部网页、Monaco 里的小部件、命令式建的 DOM 都没有指令，引擎只读属性。

| 属性 | 含义 |
|---|---|
| `data-nb-target` | 稳定名：点分的小写段，至少两段，第一段是所属插件或区域，例如 `explorer.toolbar.new-file` |
| `data-nb-key` | 列表项的业务身份（路径、id），不用下标 |
| `data-nb-command` | 控件绑定的命令 id（快照照列，第一版没有控件声明） |
| `data-nb-private` | 值不进快照与截图 |
| `data-nb-agent="never"` | Agent 不得操作（动作得 `forbidden-target`），用在删除账号、显示密钥这类地方 |

- 指令：`v-nb-target="'explorer.toolbar.new-file'"`；列表项一律写 `v-nb-target="{name: 'explorer.row', key: file.path}"`；还可以带 `private`、`agent: 'never'`。组件里本地导入，不需要全局登记。nb-ui 的组件把宿主的 `data-*` 落到根元素，所以在 nb-ui 组件上直接写属性也行。
- 开发构建里检查：同名又没有 key 的元素同时出现多个、同名同 key 重复、名字不合规则，各警告一次。
- 第一批只给引导验收要走的路径命名（约 30 个：打开作品、新建章节、打开设置、切换主题等），其余靠角色加名字定位。被官方引导或 Skill 引用的名字列进 Spec 的名字表，加一条治理测试：表里每个名字都要在源码里出现，防悄悄改名。

## 技术选型

| 问题 | 选用 | 理由 | 否决 |
|---|---|---|---|
| 角色与可访问名 | `dom-accessibility-api`（MIT，Testing Library 在用）算名字；交互角色自己维护一张约 30 项的小表 | 名字规则（`aria-labelledby`、`label`、`title`）最容易写错，用久经考验的库；角色表小，自己写才能照 nb-ui 的真实 DOM 调 | 照抄 Playwright 的 `roleUtils`（依赖它的内部模块，复制了要自己维护）；page-agent 看光标样式的启发式（给不出名字） |
| 高亮 | driver.js 1.14（MIT，约 47 KB） | 已核实：有不挡页面操作的选项（`allowPageInteraction`）、等用户点目标（`advanceOn`）、元素被重画后重找、捕获阶段跟随嵌套滚动、在打开的原生对话框里也能显示；调研时 1.10 的几条限制已不成立 | 自写（开工前的实验不过才自写，届时用 `@floating-ui/dom` 定位说明框） |
| 截图 | snapdom、html-to-image、modern-screenshot 三选一，按实验定 | 都是 MIT、DOM 重画；在工作台、编辑区（Monaco、Tiptap）、带主题变量与模糊效果的界面上各截一张，对照浏览器的真实截图看失真、记耗时，超过 2 秒或明显失真的淘汰 | html2canvas（自称实验性）；屏幕共享（每次都弹选择器） |
| 点击与输入 | 自写，事件序列参照 page-agent | 要按 nb-ui、Tiptap、Monaco 的实际行为调 | Testing Library 的 user-event（测试库，不做命中检查） |
| 光标 | 自写，借 page-agent 的思路 | 几十行，要接主题与减弱动效 | — |
| 服务端到窗口 | 现有的远程服务 | 命令系统已在用 | 自己开连接 |

## 要改的别的模块

- `nbook.agent` 的 eval 文档生成（`backend/eval/objects.ts` 的 `tsType`）：把字段说明写成签名里的注释。现在只打印类型，模型看不到每个字段是什么意思。
- `ui` 的方法工具都标 `defaultForAll`：对象没被调用时只在 eval 说明里占一行，用户可以在 Profile 的工具绑定里去掉。
- nb-harness 的工具上下文加一个“正在等用户”的标记，`highlight` 等用户点击时用它，这段时间不计入 eval 单元的时限（与“等用户应答不计”同一条规则）。不加的话，模型忘了把 eval 的 `timeout` 调大，引导到一半就被截停、内核重置。

## 开工前的实验

各半天左右，结果写进 Task 的证据：

1. reka-ui 的下拉菜单、选择框、弹出层：只发 `click` 与发完整 pointer 序列，各试一次。
2. 输入：原生输入框、`v-model` 输入框、文本域、Tiptap 正文、Monaco，各试“原生 value setter 加 input 事件”“`execCommand('insertText')`”“`beforeinput`”，看内容与 Vue 状态是否同步、撤销是否正常。只决定第二批能做到哪；做不到的控件写进文档的“不能做”。
3. driver.js 在工作台上的验收：描边框跟随嵌套滚动、在模态之上、不挡其余操作、目标被 Vue 重画后跟上、Esc 与点击能结束、减弱动效时不做动画。
4. 截图库对比（见技术选型）。
5. 浮层的 shadow root 与 `adoptedStyleSheets` 在严格 CSP 的外部页面上是否生效（为 w00034 预先确认）。
6. 工作台真实快照的字符数、估算 token 与耗时。

## 测试

- 逻辑单测（bun）：定位的解析与互斥、引用表与重找、变化摘要、稳定名规则、失败码、TypeBox 模式。
- 核心包的真实浏览器测试（Playwright，自带夹具页）：原生与 ARIA 控件、shadow root、遮挡层、`inert` 模态、嵌套滚动、密码框。断言快照与预期一致、快照列出的角色与名字在 Chrome 的无障碍树里都找得到；动作的可观察结果；截图能解码、尺寸对、密码框区域是纯色、`annotate` 的编号与引用一致；高亮框与目标矩形相差不超过 2 像素、滚动后跟随、`until: "click"` 只认真实点击。
- 应用 e2e（一个新文件）：脚本化模型写 eval 代码，在真实服务端与页面里快照、按稳定名高亮与点击，断言工作台真的变了；两个窗口时选中有焦点的、全关时得 `no-window`、换窗口得 `stale-ref`；询问模式下截图出审批卡、拒绝得 `denied`；点停止按钮后当次 eval 以 `aborted` 结束、提示条消失。
- 变异检查：去掉 pointerdown、去掉命中检查、去掉遮挡、`until: "click"` 接受合成事件、窗口选择改成随机，各应有用例失败。
- 真实模型冒烟（`*.llm.test.ts`）：“教我新建章节”走一遍，记请求数与输入 token，对照调研里薄接口 7 次请求、5.5 万 token 的量级。

## 风险

- **Agent 操作了用户看不到或不想要的东西**：选错窗口、一段代码连点十下、把章节正文里的话当指令。对策：窗口粘住且结果里写窗口标题；提示条与停止；动作是 `write` 档，`discuss`、`plan` 模式自动拦；`data-nb-agent="never"`；文档写明页面文字是证据不是指令，快照里的名字与值一律加引号。eval 本身不是沙箱，这条边界在 `eval.md` 已声明。
- **合成输入覆盖不全**：reka-ui、Tiptap、Monaco 的行为在实验前都是推断。对策：实验 1、2 先做，做不到的显式交回 `needs-trusted-input`。
- **token**：快照太大或模型每步重取，会掉到调研里“厚接口”那一档（34 万对 5.5 万）。对策：只列可交互元素、8000 字符上限、`scope`、动作交回变化摘要；冒烟时盯请求数。
- **截图失真**：DOM 重画是近似，文档写明，不当作可信证据。
- **审批疲劳**：询问模式下每次点击都问。对策：“本会话都允许”对嵌套调用可用；引导以 `highlight` 为主，让用户自己点。

## 待开发者定

1. **全局对象叫 `ui`，不叫 `nbook`。** eval 的对象与方法必须属于同一个插件，`nbook` 装不下命令、设置、界面几家的方法；推荐界面用 `ui`，以后设置、命令各由拥有它的插件出自己的对象。
2. **分两批交付**（见“第一版范围”）：先快照、截图、高亮，再动作、光标、提示条。
3. **用户中途切窗口不跟**：选中的窗口一直用到它断开、转后台或 2 分钟没调用；这一轮里换了窗口，旧引用作废，模型重新快照。
4. **截图的同意走现有审批**（`exec` 档，可以“本会话都允许”）；`auto` 模式由审批模型判、`yolo` 不问；密码与不公开的内容总是遮住。
5. **动作算 `write` 档**：询问模式逐次问，“可以写文件”模式放行，`discuss`、`plan` 模式拦下。与浏览器插件不同（那边对外部网站一律按执行档）：在自己的应用里点按钮，和改作品文件是同一类事。
6. **引导时等用户点击**：`highlight({until: "click"})`，并给 nb-harness 加“正在等用户”的标记，等待不计入 eval 的时限。
7. **不做命名对照实验**：动词直接用 Playwright 的；t16 时推荐过先做对照实验，但调研没找到名字影响准确率的证据，模型又是先读文档再写代码，实验的花费不值。
8. **设置的读写与窗口状态的只读面移出本 Task**，以后要时另开；第一版的快照本身已经交代窗口里有什么。
9. **不做页面内执行脚本**（`evaluate`）。
