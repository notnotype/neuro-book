主会话亲自核实过的事实：
- 服务端插件调 context.remote.instances() 得 target-gone：路由给服务端自己装的上游对 server 目标一律拒绝（nb-runtime/src/remote/router.ts 的 upstream.request 与 #refusal 的 hub 分支），只有窗口发来的查询才在 handle 里答（INSTANCES_CONTRACT 分支）。G2 对，O 的“未发现问题”里“instances() 由服务端路由直接回答”只对窗口发起的查询成立。plugin-channel.md 输出 8 承诺插件能列实例，是现成缺口。
- 单条消息上限 1 MiB（nb-host/src/shared/socket.ts），Spec 要求二进制经 HTTP 资源地址；有插件自带 PUT 路由收原始字节的先例（workspace/files.md 的主题素材与 upload）。
- eval 的询问不能记（agent/backend/permissions/index.ts 的 rememberable）；缺省审批模式是 ask（web/session-host.ts）。
- 应用与组件库里没有一处检查 isTrusted。
- 工具声明里没有按后台会话排除的办法（agent/shared/points.ts、nb-harness tool.ts 都没有 background 相关字段）。
- 通道 Spec 的非目标：不把等用户回答的长交互挂在一次调用上（plugin-channel.md 第 22 行）。

一、成立，要改：安全边界（第二稿“安全区与不公开的内容”）

1. Agent 能点自己的审批卡、模式开关、权限规则、对话输入框（O1、G3）。改：定不变量“Agent 的动作改变不了它自己的权限与身份”。安全区 data-nb-agent="never" 改成按子树继承，必须标的区域列成清单（审批与提问向导、模式与审批模式、权限规则页、Profile 工具绑定、对话输入框与发送、Agent 自己的对话视图、凭据输入），治理测试防漏标；这些区域的处理函数另外只认 isTrusted（网页下的第二道防线；以后桌面外壳的可信输入也经引擎，边界仍是引擎的安全区检查）。
2. 不公开的内容只遮了值（O10、G4、S16）。改：窗口里一层统一的私有投影，快照、元素数组、名字计算、文字定位、候选、遮挡者、变化摘要、错误、截图与编号标注都从投影取；私有子树不参与文字匹配与名字计算；兜底规则（password、autocomplete 的密码与一次性码、名字或 name/id/label 像凭据）缺省私有，data-nb-private="false" 才退出；测试用合成假值覆盖全部出口。
3. 快照文字能伪造结构（O11）。改：名字与值按 JSON 字符串转义（含换行、控制字符与双向控制字符），先截断再转义；动作结果回显实际点到的元素。
4. 高亮说明经 driver.js 的 innerHTML 进页面（S19、G15）。改：说明只作纯文本（textContent），合同与测试写明；随第 17 条自写高亮。
5. 高亮能在应用界面里冒充官方引导（O23）。改：说明框固定带来源（Agent 标记与会话标题），安全区与私有控件不许高亮；静态稿把来源标记列为必看。
6. 窗口远程服务的调用方（O19、G1）。改：callers 限 server；每个方法声明 read 或 write、输出 schema 写长度与条数上限；写明信任边界是“本机所有插件受信、只有一个使用主体”，多使用主体出现前选窗口不区分用户。G1 后半（防本机不受信客户端要宿主签发授权）超出现有拓扑的信任模型（ADR 0022），记为已知前提，不做。

二、成立，要改：窗口、引用与寿命（第二稿“目标窗口”“引用”）

7. 服务端列不出窗口（G2，已核实）。改：nb-runtime 让服务端插件的 instances() 由路由本地回答，兑现 plugin-channel.md 输出 8，补 routing.test.ts；页面插件区分“目录查询失败”与“没有合格窗口”。
8. 引用是裸数字（O2、G9、S5）。改：引用带本次加载的前缀；存发号时的身份（角色、主名、稳定名、key、命令、所在层），每次使用先重算核对；身份变了按“不在了”处理。
9. 重找后照做会点错（O3、S6）。改：动作一律不重找，身份不符得 stale-ref 并附候选；只读的方法可在同一层内、稳定名与 key 都相同时重找并标 rebound。
10. 选窗口按作品近似不对（O9、G7）。改：info() 交回窗口正显示着哪些会话；次序是“显示本会话且有焦点 > 显示本会话且可见 > 有焦点 > 可见且最近有真实输入”；只问提供了窗口合同的实例；写成表。t16 决定 2 的“窗口上报焦点”改为每次拉取，理由写进设计。
11. 转后台的两条规则矛盾（O13、G7）。改：只留一条：粘住的窗口转后台时读照做，动作、截图、高亮得 window-hidden，不重选。
12. 远程调用没有超时、每次问所有窗口（O13）。改：读 3 秒、动作 10 秒、超时得 window-unresponsive；粘住期间只问那一个窗口，可见性与焦点随结果带回。
13. 断开不等于没做（O7、G8）。改：动作方法声明 write；未派发得 window-gone，已派发结果未知得 outcome-unknown，文字写明先快照核对，不自动重试。
14. 租约与粘住、引用没有共同寿命（O12、G9、O18）。改：选窗口与基线由插件后端一张以会话为键的表持有，所有 ui 方法共用；租约在窗口，绑定 {sessionId, runId}，同一次运行续租，运行结束或 2 分钟没调用才放开；第一批就有（高亮有状态）；断线、刷新、回退、fork、换 Profile、会话关闭、服务重启各状态留与失效列表；子会话继承父会话选中的窗口。
15. 停止要绑定那次运行（G14）。改：提示条拿到 {sessionId, runId, 租约代次}，停止调 abort({sessionId, runId, keepQueue: true})，迟到的清理不撤下一次运行的提示条。
16. 后台会话要在审批之前就拒绝（G13、O14 后半）。改：上游加“只给有用户在看的会话”的工具标记，后台会话的工具表与 eval 对象里都没有 ui；不靠审批模式推出。

三、成立，要改：截图、等用户点击与时限（第二稿“截图”“高亮”）

17. 截图走远程结果会超 1 MiB 断线（O4、G6，已核实）。改：服务端每次签发一次性上传凭证（绑定这次调用与窗口、30 秒有效），窗口把已排除私有内容、缩到长边至多 1280、编码为 JPEG 或 WebP、至多 512 KB 的图经插件的 PUT 路由上传；服务端校验类型、尺寸与字节；远程调用只交小结果。快照、元素数组也设硬上限。
18. 判定对象算不出窗口标题（O6、G5）。改：判定对象只用参数 {kind: "screen", value: of ?? "window"}；结果里写明截的是哪个窗口；执行时目标窗口转后台得 window-hidden。批准不绑定到具体窗口，含义是“截你正在用的那个窗口”，写进设计（接受，见第五组第 31 条）。
19. 等用户点击不能挂在一次长调用上（G10，已核实通道非目标）。改：短调用装上高亮、交回等待身份；窗口经服务端提供的合同（callers 限 client）发“已结束”消息，服务端在本地等，按身份结算；结局 clicked、dismissed、replaced、timeout、gone、cancelled；只认真实点击；迟到的消息不结算后来的高亮。
20. 等待标记没有上限、暂停哪段时间没定（O8、G11）。改：高亮的 timeout 缺省 300 秒、至多 3600 秒；“正在等用户”从窗口确认装上之后开始、结算即收回，随调用取消自动收回；装载、查找、清理照常计时；写明等待期间按整单元暂停的取舍与上限；注入时钟测重叠、取消早于或晚于装上。
21. 截图“随会话删除”不成立（G17）。改：写明截图是会话的持久数据，归档不删、fork 复制，删除等会话删除的合同。

四、成立，要改：接口形状、文档与页面里的规则（第二稿“给模型的接口”“控件的名字”）

22. 失败码与 eval 的失败通道对不上（O14、G12）。改：业务失败一律抛（status error 加码），候选、遮挡者等结构放进 details，上游让 ToolCallError 带 details（agent 插件小改）；表里删掉 denied、timeout 等审批与通道保留码，改引用各自 Spec；成功结果的警告进 returns 的 warnings。
23. 定位的类型打不出来（O15、G12）。改：定位是一个扁平对象（字段都可选，运行时校验恰好一种主定位），within 只收引用或稳定名，不递归；上游 tsType 打印字段说明、可选、单位与缺省；远程合同的输入从同一份业务 schema 派生成对象形状，效果与错误映射另写。
24. text 一名三用（O16）。改：高亮的说明叫 message，快照的开关叫 includeText，定位里的文字仍叫 text。
25. 文档与实际可用的方法不是同一份清单（G16）。改：上游让 eval 的对象文档按会话的方法清单生成，版本把方法清单算进去。
26. 稳定名的指令接口（S1、S2、S21，t16 决定 8 要求先审）。改：不做指令（多根组件上不生效，最该命名的控件没有模板可写）；名字分三层：渲染方自动写（命令按钮与菜单项写 data-nb-command，设置行写设置键，对话框按标题），手写层用属性或 nbTarget(name, key) 帮助函数，保护层（私有与安全区）；要改 nb-ui 的菜单项透传标识、工作台 TitleActions 写命令 id、设置行写键；与现有 data-explorer-* 等 e2e 标记的关系写明（不迁移）。这条改动交开发者确认（第六组）。
27. 名字的唯一性范围（S15）。改：容器带名字与 key 时，后代的名字只要求在最近的带 key 容器里唯一；within 缺省取容器声明的“当前活动的那一个”；开发期检查放进引擎的 DOM 扫描。
28. 看得见没有定义（S3）。改：沿祖先链取有效不透明度、visibility、display、被裁成零面积；低于阈值的标 faint 仍可定位，高亮与动作前先聚焦让它出现（工作台的悬停动作有 focus-within 规则）。
29. 模态在 DOM 里没有统一信号（S4）。改：层由命中检查反推，层根按 dialog、alertdialog、menu、listbox 等角色认；过滤补 aria-hidden；命中到 html 或 body 且页面禁了指针时点名说明。
30. 虚拟列表、预算与名字匹配（S12、S14）。改：列表类容器写一行摘要（总数、已渲染范围、可滚动），行上带 posinset，过量渲染的视口外行折叠；没渲染的行 not-found 时文档提示先用定位命令或搜索；预算按估算 token 并给截断优先级（最上层 > 焦点所在区域 > 其余）；scope 收引用或稳定名；名字匹配缺省不分大小写、折叠空白的子串，exact 为精确；内容命名的角色另算主名（跳过 role=img 的状态标记）。
31. Agent 自己的对话视图在被快照的窗口里（S20）。改：对话视图属于安全区（不进快照、不进变化摘要、不能操作），它的内容按不可信处理。
32. 等页面静下来（S13）。改：100 毫秒没有 DOM 变化且没有在跑的有限动画（getAnimations），至多 1.5 秒，超时带 settling；变化摘要在静下来后再取；测试另开不减弱动效的配置。
33. 自己的提示条在模态下点不了、盖住自己的命中检查（S11）。改：提示条与停止按钮用 workbench.overlays 挂 nb-ui 组件，显式 pointer-events: auto，不遮标题栏控件，停止有键盘路径；光标在核心里且不接收事件；引擎自己的节点带标记，命中检查与快照忽略。
34. 合成事件的字段（S18）、目标不是可交互元素（S1 第 3 点）、需要用户激活的处理函数（S8）、输入实验的范围（S7）。改：写全事件字段（pointerId 1、isPrimary、buttons、view）；目标不可交互时落到它唯一的可交互后代；动作期间收 NotAllowedError 进警告，data-nb-agent="trusted" 的控件直接 needs-trusted-input；实验 2 加 Monaco 的 EditContext 开与关、日期段、组合框，写明判据，fill 读回核对，引擎认得的不可 fill 控件清单。
35. 测试计划（O17、S17）。改：选窗口用真实输入的时刻区分、三个窗口；询问模式的用例先批 eval 再见截图卡、拒绝看 status；应用侧一个真实组件的 Lab 场景（Dialog 套 Select、右键菜单、确认框、虚拟树、悬停动作、拆组编辑器）给核心与应用测试共用；无障碍对照用 CDP 的 Accessibility.getFullAXTree；变异清单补引用身份、跨层重找、等动画、忽略自己的层、私有投影、模态下停止、不抢焦点；快照的耗时预算与大文档用例。
36. 层级（S22）。改：自写高亮与光标的层登记进 nb-ui 层级表的例外并加层级测试（Lab 检查框在高亮期间仍可点）。
37. Profile（O20）。改：不用 defaultForAll；ui 的方法与 eval 一样作主创与临时帮手的可选工具，bot 的岗位 Profile 不带（交开发者确认，第六组）。

五、成立，但接受取舍

38. 截图的批准不绑定具体窗口（G5 前半）。绑定要给 subjects 加会话上下文与异步、并定义判定后到执行前窗口变了怎么办，属审批的公开合同变更；改为执行时只截粘住的那个窗口、转后台就不截，结果写明窗口。记为已知取舍。
39. “以后都允许”记整个工具（O22）。按现有记忆规则，截图选一次“以后都允许”就对所有会话与窗口生效；这是用户的明确选择，不另加按工具收窄记忆的上游机制，设计写明范围。
40. 等待期间整单元暂停（O8 第二点、G11）：模型可以借未 await 的高亮让别的代码不计时；上限是高亮自己的 timeout，写明取舍，不做按调用暂停（要改 eval 的计时模型）。

六、交开发者定

41. eval 本身是执行档且询问不能记（O5）：询问与“可以写文件”模式下每段 eval 都要批一次，discuss、plan 模式下连快照也用不了。推荐接受（引导写在一段代码里只批一次，文档提示要流畅体验用 auto）；备选是给 eval 加只读静态分析或允许为 eval 写放行规则。
42. 不做 v-nb-target 指令、名字分三层（第 26 条）。
43. 高亮改为自写，不用 driver.js（S9、S10、S19；t16 决定 3“先看 driver.js 够不够，不行就自写”）：它会抢焦点、按 innerHTML 写说明、给目标的父滚动容器加 overflow:hidden、改页面 class 与全局样式、缺省压暗页面、Esc 被 nb-ui 对话框先吃掉；自写只要矩形跟随加 @floating-ui/dom 定位说明框。
44. 安全区的清单（第 1 条）：Agent 不能操作、也不读这些区域。
45. 后台会话不能用 ui（第 16 条）。
46. 删除一类后果大的点击在“可以写文件”模式下也要问（O21）：data-nb-agent="confirm" 的目标要模型带 confirm: true 重发，这一次按执行档审批；放在第二批。
47. ui 进哪些 Profile（第 37 条）。

七、对第一批范围的影响

第一批要先补的上游：nb-runtime 的服务端实例查询；nb-harness 的等待标记与“只给有用户在看的会话”的工具标记；agent 插件的 ToolCallError details、文档生成（字段说明、按会话的方法清单与版本）、审批相关界面只认真实输入并标安全区；nb-ui 菜单项透传标识、工作台 TitleActions 写命令 id、设置行写键。外加本插件自己的截图上传路由。
