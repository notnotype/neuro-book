# 引导的等待条件与控件名：until 等出现，编辑器、资源管理器、对话输入框的稳定名

## 目标与范围

模型在没看过页面时写不出整段引导，原因有两个：页面里的控件没有稳定名、不在界面目录里；有的步骤不是“点一下”（打字、选中文字、拖动），`until` 只有 `click` 与 `next`，判不出这一步做完了。本 Task 补这两样：

1. **`until` 等某个东西出现**：例如 `until: {appears: <定位>}`，用户怎么做到的都算（点、打字、快捷键、拖动）。`ui.find` 的路径每一步本来就带 `appears`，可以直接接上。[t01 决定 16](../t01-design/README.md#决定) 里第二批的 `waitFor` 提前到这里；要不要同时做“等它消失”、这类步骤里点到别处算不算 `missed`，设计时定。
2. **稳定名扩到四处**（由控件的拥有者写，[`agent/page-agent.md`](../../../../../docs/specs/agent/page-agent.md) 输出 6）：
   - 编辑器的工具栏与选区菜单，按命令 id（例如插入表情的 `nbook.edit.sticker`、批注）；
   - 资源管理器的行，key 用文件的资源地址（行上写的是展示名，不一定是文件名）；
   - 对话输入框与 `@` 文件菜单。
3. **界面目录收编辑器工具栏上的命令**（输出 7 的“命令”现在只收活动栏与视图标题栏）。

用来验收的例子见 [t04](../t04-guide-one-eval/README.md) 的评测场景：编辑器里插入表情、给某段话加批注、把文件发给 Agent、先在资源管理器找到指定文件再发。

## 已知的事（2026-11-27 核对）

- 编辑器插表情有三个入口：工具栏“表情”（窄时收进“⋯”）、斜杠菜单“块”组的“表情”、正文里打 `:` 补全；批注是选中文字后选区菜单的“批注”、右键“添加批注”或 Ctrl+Alt+M（`markdown/web/components/menus/MarkdownMenus.md`）。
- 新应用里把文件发给 Agent 只有输入框的 `@` 引用（`agent/web/mentions.ts`，[`agent/conversation.md`](../../../../../docs/specs/agent/conversation.md) 输出 28）；没搜到从资源管理器拖进输入框或右键“发给 Agent”。
- 资源管理器的树是虚拟列表（`explorer/web/tree/window.ts`），没渲染的行定位不到；展开上级文件夹可以由引导脚本按快照元素的展开状态判断、跳过已展开的。
- 现在只有工作台与设置窗口写稳定名。

## 待开发者定

- 资源管理器要不要加“发给 Agent”的动作（产品功能，不属于 `ui`）。
- 没渲染的行：要不要给资源管理器一个“定位到这个文件”的命令，让引导先把它滚出来。
