# 演示稿与 spike：标签写法与富文本编辑的体验

## 目标与范围

在写实施计划之前，先用演示稿和能上手的 spike 让开发者体验标签写法与富文本编辑，按反馈一轮轮改，直到需求对齐、稳定（开发者 2026-11-26）。

要拿出来体验、对齐的：

- 标签写法：取值、条件、条目引用、图片怎么写；源文字与给 Agent 的带值写法并排对照；样本书（星瑕）里现有的 `{}`（7 种取值、1 个条件、2 处跨条目引用，各在 11 份草稿里重复）换成标签后是什么样。
- 富文本里的标签：取值显示成什么（当前的值、字段名、来历），怎么插入、怎么改指向、怎么删；条件块怎么显示与编辑。
- 源文字与富文本的切换：两边来回切的效果，富文本表达不了的写法怎么处理。
- 与章节编辑器的关系：同一套工具栏与排版，哪些章节方言的写法条目里不能用、编辑器怎么挡。

非目标：不改内核、不合入产品代码；spike 的分支不合并。标签登记表与沙箱块不做（见 [Work 的范围](../../README.md#范围)）。

合同：本 Task 不改行为合同。要改的 Spec 在需求对齐后的实施 Task 里定：[`canon/rendering.md`](../../../../../docs/specs/canon/rendering.md)、[`canon/author-ui.md`](../../../../../docs/specs/canon/author-ui.md)，以及取代 [ADR 0038](../../../../../docs/adr/0038-world-engine-entry-text-is-whitelisted-mdx.md) 决策 1 与 3 的新 ADR。

## 当前状态

2026-11-26 新建。已定的几条见 [Work 的决定](../../README.md#决定)。

第 1 轮[评审板](artifacts/review/index.html)（写法，v1）开发者已答，两题都按推荐（决定见 Work 的决定表）：

2. `agent-value`：给 Agent 的值写在标签中间、用 JSON；开发者问好处坏处，主会话在会话里答。

搭稿时实测（章节方言的编解码器，`defaultMarkdownLanguage`）：`V`、`If`、`Else` 这些标签现在全部读成原样内容。独占一行的 `<V />` 是原样块；跨段的 `<If>` 连同里面的 `<V>` 整段是原样块；自闭合的标签方言不认。所以不管选哪种写法，都要给条目另加一个语法模块。

开发者 2026-11-26 又提出一个方向：给 Agent 的主文字不带值，原文就是标签，Agent 只通过工具改值；要主会话比较它与“值写在标签中间（JSON）”的优缺点，到时候做一个简单的评测。主会话查到：内核的带值回写（`writeBack`）现在只经远程接口暴露，Agent 工具与作者界面都没有调用，Agent 改主文字用的是 `canon_write` 的 `set`、`replace`。所以开发者提的方向和 Agent 现在实际的改法很接近，评测的设计在会话里给出。

开发者同时问到条目文字的表达力：现在能不能做可交互的生成式视图或角色状态栏、外部组件怎么注入、能不能直接写 JSX、React 里能不能混用 Vue 组件。主会话在会话里答复，开发者同意在本 Task 里做演示。

2026-11-26 评测跑完（[结果](evidences/agent-value-eval.txt)，设计见 [eval.md](eval.md)）：198 次运行，三组成功率没有可区分的差别；和带值写法有关的报错只出现在“带值、可以就地改”的甲组（luna 6 次，其中一次弄丢了一个取值），乙、丙两组都没有。评测时查到的两个现有缺陷记在 w00039 t20。

富文本 spike 并进 master（Lab 的 `EntryRichDraft`，草稿区 `drafts/w00055-t01/`，分支 `w00055-t01/drafts`）：取值小块、条件（只画生效的一支，可打开全部分支）、条目引用、`{` 与 `@` 插入、点开小块的浮层、源文字切换与写坏标签的拦截。Gemini 顾问的意见（[说明](evidences/designer-r1-brief.txt)、[意见](evidences/designer-r1.txt)）多数已采纳，没采纳的列在评审板上。
