== 别的观察 ==
- 三组的模型都几乎总是读 fields 与 text 两样（乙组的说明里提示了可以一起读），读懂题三组都对，说明“值不在文字里”在这些题上没有让它读错或编造。
- 甲、丙组的 rewrite 只用了 4 次（flash 甲 2、丙 2）；模型大多数时候选择 set 整块源文字。甲组的说明说“带值写法可以就地改”，luna 因此照带值文字去 replace，摩擦全在这一组；丙组说明写“值只给看”，没有出现。
- 费用：198 次合计约 1.34 元（按 deepseek-flash 低谷价折算）。

== 能推到多远 ==
- 世界很小（两个条目、两块主文字），题目单一，两个模型都较强；长条目、很多跨条目引用、弱模型没有测。
- 带值写法的外壳是 {地址 = 值}，不是将来的 <V of>值</V>；“读懂”的结论能推过去，改写时的出错方式不一定。
- 甲组的 rewrite 在评测台里拆成两步（内核的 writeBack 改数不补依据，见 eval.md）。

== 结论 ==
两个模型、三组的成功率没有可区分的差别（每组 33 次，差 1 次不显著）。差别在摩擦：只有“带值、可以就地改”的甲组出现了和格式有关的报错与一次弄丢表达式；不带值的乙组与只给看的丙组都没有。
