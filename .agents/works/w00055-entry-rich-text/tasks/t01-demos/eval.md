# 评测：主文字给 Agent 时带不带值

开发者 2026-11-26 提出“值不进原文，原文就是标签，只让 Agent 通过工具改值”，要求比较它与“值写在标签中间（JSON）”，做一个简单的评测；主会话推荐现在就跑，开发者同意。

## 要回答的问题

Agent 读条目的主文字时，值写不写在文字里、能不能在文字里改值，对两件事的影响：

1. **读懂**：问到主文字里提到的值，答得对不对，会不会编造。
2. **改对**：改值、改文字、两样一起改、改条件，最后的世界对不对，有没有把表达式换成写死的数，有没有改到无关的地方。

## 三组

三组都用产品的 `canon_lookup`、`canon_read`、`canon_write`（真实的服务端、项目子进程与世界服务），工具说明用产品原文，每组只在下面列的地方不同。三组实际给模型的说明原文存进证据。

| | 甲：带值、可以就地改 | 乙：不带值（开发者提的） | 丙：带值、只给看 |
|---|---|---|---|
| `canon_read` 的 `text` | 产品现在的带值写法：`{panel.魔力 = 1200}`、`{表达式 -> "结果"}` | 源文字：`{panel.魔力}`，不带值；值只在 `fields` 里（`show` 照产品，缺省只给 `fields`，要文字得自己加 `text`） | 同甲 |
| 多出的写法 | `canon_write` 多一个 `rewrite`（`entry`、`block`、`text`）：交回读到的那一块，`=` 右边的值改了就改字段，别的字改了就改文字（内核的 `writeBack`） | 无 | 同甲的 `rewrite`，但交回的值改了就拒收，提示用 `set` 改字段 |
| 说明里多的几行 | 带值写法的读法；`->` 的结果不能改；改主文字用 `rewrite` | 主文字里的 `{地址}` 是取值，值在 `fields`；改值用 `set` | 带值写法的读法；值只给看；改主文字用 `rewrite`，改值用 `set` |

`set`、`replace` 改主文字照产品（按源文字匹配），三组都留着。

**现在的产品不在三组里**：它是“带值、只给看、没有 `rewrite`、说明里不讲带值写法”。探针已证实它的缺陷：读到 `{panel.存款 = 300}` 后照抄去 `replace`，得到 `replace-not-found`，回话没提读到的文字与源文字不同。这条记为 w00039 的后续，与评测结论分开。

## 替身与能推到多远

用现在的内核与 `{}` 写法（开发者同意）。带值写法的外壳是 `{地址 = 值}`，不是将来的 `<V of>值</V>`：

- “读懂”的结论能推到标签写法（值在不在文字里是同一个问题）。
- “改对”里的出错率不一定能推过去：模型改 `{a = 1}` 与改 `<V of="a">1</V>` 的出错方式可能不同。报告里写明。

## 世界

每次运行新起一个场地（实测约 1 秒），用 `canon_write` 建条目、作者身份填数（数要依据，Agent 的初值写不进去），三章，位置是第 3 章末尾。

- 星瑕（人物、面板）：面板 魔力 1200、魔力上限 3000、存款 300、回溯 3；人物的性格。主文字两块：
  - `b1`：`## 现在` 一段，魔力、上限、存款、回溯四个取值，加一个条件 `{panel.魔力 >= 1000 ? "还能变身。" : "魔力不够变身。"}`。
  - `b2`：`## 哥哥` 一段，引用星瑾的身份与好感度，加一个跨条目的条件 `{ref("e2").panel.好感度 >= 50 ? "哥哥站在她这边。" : "哥哥还在怀疑她。"}`。
- 星瑾（人物、面板）：身份“联邦调查员”，好感度 40。

## 题目与判据

| 题 | 类别 | 要它做的 | 程序判据 |
|---|---|---|---|
| R1 | 读懂 | 星瑕现在还能变身吗？魔力多少？ | 答“能”，提到 1200 |
| R2 | 读懂 | 星瑕今天还能回溯几次，存款多少？ | 3、300 |
| R3 | 读懂 | 哥哥现在站在她这边吗？对她的好感度多少？ | 否、40 |
| W1 | 改值 | 星瑕的魔力改成 800 | 魔力 800 |
| W2 | 改值 | 星瑾对她的好感度改成 60 | 好感度 60 |
| T1 | 改文字 | 星瑕“现在”那段末尾加一句“她把钱都藏在床底。” | `b1` 含这句 |
| T2 | 改文字 | 把“魔力不够变身。”改成“魔力不足，只能维持原身。” | 条件里的那一支换成新句，判断不变 |
| M1 | 两样 | 魔力改成 800，并在“现在”末尾加一句“她把钱都藏在床底。” | W1 与 T1 都成立 |
| M2 | 两样 | 存款改成 5000，并把“联邦币”改成“星币” | 存款 5000，`b1` 里是“星币” |
| C1 | 改条件 | 变身的门槛从 1000 改成 900 | 条件写 `>= 900` |
| C2 | 改条件 | “现在”那段加一句：回溯次数用完时写“今天不能再回溯了。”，没用完不写 | 新条件读 `panel.回溯`、在 0 时给出这句；回溯 3 时渲染里没有它 |

每道写题另查三条，任何一条不成立算失败：

- 原有的每个表达式都还在（题目要改的那个除外），没有被换成写死的数或字；
- 题目没让改的字段都没变，没有多建、删除条目；
- 主文字过得了写入检查（能渲染、没有出错块）。

读懂题另查编造：答案里出现的与题目相关的数，不是世界里的值就记一次编造。

## 指标

每组每题：成功率；编造；被拒收与重试的次数；调用工具的次数；输入与输出 token；费用按 deepseek-flash 低谷价折算。按题、按组列表，不只给总数；每条失败都打开对话看过再归因（模型、说明、工具回话、判据写错）。

## 规模与做法

- 模型：gpt-6-luna（`.env` 的 `JIJI_LUNA_*`）、deepseek-flash（`DEEPSEEK_API_KEY`）。
- 每组每题每个模型 3 遍：11 题 × 3 组 × 2 模型 × 3 遍 = 198 次。一次运行最多 12 轮工具调用。
- 系统提示三组相同：写作助手，用 canon 工具读写这部作品的设定，改设定用 `intent: "setting"`。
- 先冒烟（一个模型、三组、各 3 题、各 1 遍），逐条读对话，确认判据与归因；再正式跑。正式运行放后台，每跑完一次追加一行 JSONL，断了能续，中转出错自动重试。
- 代码在 spike 分支 `spike/w00055-t01-eval`（`.worktree/w00055-t01-spike`），不合并。结论与汇总进本 Task 的 `evidences/`，完整对话留在本机 `.local/agent/works/w00055-entry-rich-text/tasks/t01-demos/eval/`。
