== 3. 三道新题实际走的路径 ==
LONG（两遍相同）：lookup → canon_read show text（回话 b3 一行：“[b3] 这一块共 14856 字，这里放不下：用 field: "text[b3]" 读”）→ canon_read field=text[b3]（第一页 8111 字，末尾“……（这一块共 14856 字，后面还有 6856 字：cursor "8000" 续读。这么长的块用 replace 改局部）”）→ cursor 8000 读第二页 → replace find=整句“她七岁那年在码头边捡到一只会发光的贝壳。”→ 成功。回话把它引到了分页读与 replace，整个路径没走弯路。
  限制：模型两遍都没有试整段 set，所以“set 被拒、回话请它用 replace”这一支没有在模型对话里出现。我在探针里直接调产品验证了回话原文：“第 1 项（set）：这一块有 14856 字，canon_read 一页读不全；整段写回会丢掉没读到的部分。改局部用 replace（find 写要换掉的那几句）。”（模型已被第一页末尾那行“用 replace 改局部”先引到 replace，所以用不到。）另外目标句其实不在读取的必要范围内：prompt 里已给出新句“……一只会发光的海螺。”，题面给了新句，旧句可以推出来，存档里它读完两页才 replace，分不清 find 是读到的还是推出来的；干扰句（只写“贝壳”）没有被误改。如果要强迫“不读就改不了”，需要更隐蔽的题面，这次没做。
KEY（两遍相同）：lookup 两个名字（星瑕的猫“没有这个名字的条目”）→ read text → 一次 canon_write：create(key:"cat", name 星瑕的猫, kind 物品, summary) + set text[b1] 整块，里面写 <Ref id="$cat" />。回话：“已写入：修订 r6，版本 6。新建：cat → e3（没有设定组）”，带来的变化里是 <Ref id="e3" />总蹲在她肩上。落盘正式 id，没有残留 $。用的是“同一次 canon_write 里 $代号”。说明里的“同一批 create 的条目在 entry、id、ref('…') 里写 $代号”它读到了。
STALE（两遍相同）：lookup → read text →（评测台：作者改 b1）→ replace（find 是 If 整段）→ 回话“stale-read：你读过之后世界变了。之间的修订：“作者改星瑕的主文字”（作者）。用 canon_read 重读，再带新的 version 写。”→ 重读（读到作者那句）→ replace find=作者那句“她睡觉时一定要开着灯。”、with=作者那句+换行+“她把钱都藏在床底。”→ 成功。它没有把 stale 当成“抄错了”，两句都在。回话引对了。

== 4. 观察到的产品问题（按重要性）==
(1) replace 的 find 要不要带装饰，说明与回话含混（3 例去装饰：T1.1、C2.2、STALE.1；与 t01 的差别：t01 里 replace 按源文字匹配、评测台还补了一行“set、replace 时不要带上”，现在 find 按带值写法匹配而产品说明没有分开讲，这是它的来历）。canon_write 说明写：“它们只给你看，写回时去掉：改文字照抄带值的写法就行，文字里改了值不会写进字段”，模型把“写回时去掉”读成 find 里也要去掉（T1.1、C2.2 走到了找不到，STALE.1 被 stale-read 先挡住，find 都去掉了 value="true"，规范规则其实是 find 按带值写法匹配）。此时回话只有泛泛的“第 1 项（replace）：这一块里找不到 find，原样抄读到的文字。”，没说“find 要带着你读到的 value=… 这类装饰”，也没提可以不带标签只抄纯文字。T1.1 因此改用整块 set 重写（风险大：自己重敲所有标签），C2.2 靠第二次照读到的原文抄成功。建议：说明里分开写“write 的 value/with 去掉装饰、replace 的 find 要与读到的完全一致（带装饰）”；find 找不到而去掉装饰后能对上时，回话点名“find 里的标签要带上读到的 value 等属性，或只抄不含标签的文字”。存档：luna.product.T1.1.json、luna.product.C2.2.json（第 1 次 canon_write 的回话）、luna.product.STALE.1.json（第 1 次 canon_write）、luna.product.M1.1.json（带值变了的回话）。M1.1 的回话（find 带值、值变了）已经说清，是好的样子。
(2) 写入成功的回话只写“版本 6”，没有像读取那样带“6·a9c3dce44320”。模型下一步：M1.1 用 "6" 成功（只比版本号）；M2.2 沿用最早读到的 "5·8a4cafb7a949" 写文字 → “stale-read：你读过之后世界变了。之间的修订：“星瑕获得奖金”（Agent）。”，是它自己刚写的那条修订，多一次重读（luna.product.M2.2.json 第 4 轮）。M2.1 则在两步之间补读了一次。建议回话里带完整版本串，或说明里写“写入后要继续写，用回话里的新版本或重读”。
(3) 长块分页在句中截断：第一页末尾停在“……她”，第二页以“[b3] 把这一天悄悄折起来…”开头（块 id 前缀重复出现，看起来像新块，且前一页的半句断在中间）。LONG 两遍都没出问题（模型直接按整句 replace，不依赖页边界），但如果目标句正好跨页，模型自己抄就抄不全；回话已经说了“用 replace 改局部”，只是页边界对模型不友好。优先级低。存档 luna.product.LONG.1.json、luna.product.LONG.2.json 的两次 canon_read(text[b3])。
(4) 写入成功的“带来的变化”把整块去值后的 before→after 全文回出来：长块被截断到 650 字左右，短块几乎重复整块，token 浪费；没发现错误。优先级低。存档 luna.product.LONG.1.json 末次 canon_write 回话（652 字）、luna.product.T1.1.json（短块整块回出）。
(5) 没有发现明显缺陷：作者渲染的值表、去值、$代号换 id、stale-read 都按规范工作；写回的块没有出错块（每次判题都查了），没有残留装饰（C2.2 里模型自己写的 value="false" 被去掉）。
(6) 评测台自己的盲点（不是产品问题）：判题只读了 character 的性格与身份、panel 的几个数，W2.1 的多余 note（人物.现在的状态，story 意图）没被抓到；KEY 的判据要求“总蹲在她肩上。”紧跟 Ref。LONG 的整句猜测见上。没有改判据去迁就结果。
