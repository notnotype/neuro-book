# w00055 t02 只读设计审查

审查对象：`13a8ff591` 与固定的 `plan.md` 第 2 稿。运行时证据来自实现 worktree `451d94623` 的现有代码；新合同的反例不冒充新实现已经跑出的结果。

### 1. `replace` 同时在两个不兼容的文本坐标系里找字
- **严重程度**：阻断；**类别**：正确性。
- **位置**：`plan.md:54,82`；`docs/specs/canon/agent-tools.md:90`；`docs/specs/canon/rendering.md:94–101`。
- **现象**：令源文是 `旧称 <V of="panel.魔力" />`，读取结果是 `旧称 <V of="panel.魔力">3110</V>`。Agent 以读出的整个片段为 `find`、只把“旧称”换成“新称”，按合同“先去值”的 `find` 是 `旧称 <V of="panel.魔力" />`，在带值块里出现 0 次，而原 `find` 恰好 1 次。去掉第一步仍不够：只匹配 `3110` 并把它换成跨标签的普通段落，可以把用户要改的文字落进随后整段丢弃的值区，也可能令闭标签脱离其开标签。计划没有写半个开闭标签、引号被改坏、或匹配只落在生成值时分别怎样处理。
- **为什么是问题**：普通改字会被误拒；仅在成功后跑源文白名单，分不清“值修改被丢弃”与“文本被意外吞掉”。批准的“改值忽略并提示”不是“任意半标签都可以无损回写”。
- **如何核实**：把输出 8、10 的规定字符串代入输出 6 的 `replace` 两步（同时要求去值后找、在带值文中找，结果分别为 0、1）；对照现有 `replace` 的源文基线和 `value-conflict`。
- **建议改法**：定义 `find` 只在读取戳对应的带值投影里匹配，不先把它去值。使用渲染时的源文/生成区间映射把编辑投回源文：完整标签可作为编辑单位，纯值修改忽略并提示，半个结构或跨越生成边界且不能唯一投影的修改回具名失败；下层仍用旧源文做条件写。整块 `set`/`create`/`addBlock` 的去值另定，不共用片段规则。

2. [重要／不变量] 同用 marked 仍会把代码里的标签认成活标签
文件：plan.md:47–53；docs/specs/canon/rendering.md:74,120,124；packages/nb-markdown/src/language/codec/source.ts（`splitFrontmatter`）、codec/read.ts:184–188。
现象及影响：计划给内核补 frontmatter 拒收和换行归一化，没规定 BOM 怎么消耗、源文坐标怎么回映。源文 `\uFEFF    <V of="panel.魔力" />`（开头是真 BOM）没有 frontmatter：直接分词看到段落和活 V，编辑器先剥 BOM，同一段变成缩进代码，标签只应照原样显示；作者、Agent 的显示、值表位置及去值因此可能分叉。只共享 marked 选项或遮罩扩展不够；编解码器另有 `blockTokens`／`inlineTokens` 入口，不能只罩 `lexer.lex`。
核实：在实现 worktree 用 marked 17.0.6 与真实 `codecFor(...).read` 跑 `lab/codec.ts`，同一 E2 标签词法：直接 `paragraph`／`live`，真实 codec `codeBlock`／`literal:code`。这是共享前处理未定义的反例，不是新内核已上线的结果。
改法：定义两端共享的正文前处理及坐标映射，明确 BOM 是去掉、拒收还是保留在正文外；覆盖写出校验使用的分词入口。在真实 codec 逐个比正文、代码与表格落点，不只比 `Lexer.lex` 的 token。

3. [重要／正确性] 条件配对不能先于字面标签判定
位置：plan.md:45–50,114；docs/specs/canon/rendering.md:50,120,169。
现象及影响：`<If test="panel.魔力 > 0">写 \`</If>\` 后面<Else />普通</If>`（反引号表示行内代码）、或真支里写 `\<Else />`，都应只有真正的闭标签与一个分支分隔符。E2 延续到计划的“先找配对和切分、再对分支 inlineTokens 分类”却先消费里面的字面哨兵：前者误闭合，真 Else 和闭标签成孤立；后者把转义的 Else 也当分隔。写入会拒掉合法文档，或预览截断并把错支当正文。
核实：`lab/codec.ts` 用 E2 扩展、真实 marked 17.0.6 与 `codecFor`，两条在直接词法和真实 codec 中同样把字面分隔符标为 live；第一条剩余两处为 orphan。替身只提供候选扩展，不代表新内核已实现。
改法：先让 Markdown 确认各个原子的去处，再只用活的标记配对和分支切分（或在切分前以同一词法检查跳过字面区间）；用真实 codec 把条件中的代码、奇偶反斜线与链接标题加到 S3，断言分支文字、节点与内核校验均一致。

4. [重要／不变量] 表格对同一个条件标签做了两次不同的判定
位置：plan.md:35–38,53,114；docs/specs/canon/rendering.md:120,124,169；packages/nb-markdown/src/language/syntax/core/index.ts:349–359；codec/render/inline.ts:177–179,203–207。
现象及影响：遮罩让 marked 不按 `test` 里的 `||` 切单元格，但还原后 core 的 table reader 又数一次 `table.raw` 中的管道字符。按当前计划把已还原的 token 给 core，场景 4 中完全合法的条件会连整张表一起读成原样块，实际没有可编辑的条件节点。写侧又会统一把自定义行内节点输出里的 `|` 变成 `\|`；若标签在 marked 解表格转义前就被整个遮罩，再还原时得到的就不是原来的 `||`。
核实：`lab/codec.ts` 用场景 4 跑真实 `codecFor`（E2 标签扩展、marked 17.0.6）：marked 给 2 列，三个条件标签都为 live，codec 却给一个 `rawBlock`、零条目节点且无诊断；对照同表中的 `<V of="panel.魔力" />` 得到正常表格与原子节点。原样块也能通过“原文未丢”，不足以验收。
改法：让表格读法的溢出检查和写法共享同一套原子边界；只转义 Markdown 正文的管道字符，或明确原子中管道的分层解码。真实 codec 测试须断言表格与条目节点、表达式保持不变，并强制重写而非复用原文。

5. [重要／正确性] `replace` 的带值基线缺少读取模式，版本相同也会找错文字
位置：docs/specs/canon/agent-tools.md:53,64–69,70–90,98–101；docs/specs/canon/rendering.md:94,103；plan.md:82；packages/nb-canon/src/world/entry-edits.ts:109–114。
现象及影响：`canon_read` 可选 `mode=planned`；`canon_write` 没有读取模式或绑定读取位置的令牌，版本串只标世界/输入，不标模式。旧回写明定读取模式并拒绝 planned；删除值回写是已定决定，但现在文本匹配依赖投影，同一个版本、位置、块在两种模式的投影仍会不同。默认用实际模式重算，会把按计划读到、恰好出现一次的 `find` 报找不到；默认用计划模式则反过来。若两版碰巧在别处有同一串，还可能改错位置。
核实：`lab/world.ts` 用真实 World/read view 发布计划，版本 5 的同一块在实际模式读到“原样”、按计划读到“计划值”；原文相同，版本检查不能区分。当前底层 `set` 仍以 `actual` 路由。
改法：钉住带值查找的读取位置、线、模式和输入戳（或明确只支持实际模式生成的投影并让调用方能据此重读）；区分投影所读的源文与实际写入的目标，计划覆盖了同一块时禁止把计划源文写成实际。补同戳不同模式、只改章讲的线而世界版本不动的工具合同用例。

6. [重要／正确性] 程序生成的属性没有可往返的编码
位置：docs/specs/canon/rendering.md:55,95–101；plan.md:45,54,62–66；packages/nb-canon/src/render/render.ts:361–363。
现象及影响：输出 8 为 V 的 JSON 正文规定了 `\u003c`，因此值中原有 `</V>` 不会提前闭合；但 `Ref.name`、`V.label`／`unavailable`、`Image.path` 的属性值没定义转义。旧世界允许名字 `代号 "灰袍"\n队长`（实际换行）；直接放入属性打断引号和标签行。沿用旧 `JSON.stringify` 也不行，计划的 `名="值"` 扫描仍在 `\"` 的 `"` 处结束。Agent 即使原样交回，也可能报错或找不到去值边界，违背输出 10。
核实：`lab/world.ts` 在真实 World 发布了该名字、从 read view 原样读到它；旧 Agent 渲染确实用 JSON 的反斜线写出名字，而新词法没有这种引号规则。E5 的名字固定为“星瑾”，未覆盖这一域。
改法：规定每个生成属性的可逆单行编码与解码次序，明确它与源文属性的关系；用真实读写覆盖引号、换行、反斜线、`&`、`>`、`|` 和紧邻字面标签及 If 内的 V。保留 V 正文的 JSON 转义，并把 plan.md:64 的“JSON 的 `<`”改成明确的 `\u003c`。

7. [重要／不变量] 静态读取不能替代对实际输出值的 `mentions` 收集
位置：plan.md:68,87,129；docs/specs/canon/rendering.md:113–118,122；docs/specs/plot/brief.md:67–70；packages/nb-canon/src/render/render.ts:273–296,321–339；packages/neuro-book/src/plugins/plot/core/brief/gate.ts:334–345。
现象及影响：计划说 `reads` 与 `mentions` 都按词法静态算。但 `<V of="rel.对象" />` 的地址只读本条目，`reads` 为空；当值是绝密知识点的引用时，该 id 不在任何标签/属性中，只在运行时值里。若按计划只扫标签，关卡收到空集，名字回调虽会换成“一件绝密设定”，外围整句仍会放行，失去旧合同的扣整块保护。以引用为键的整表也不能只扫路径。输出 15 仍要求记录实际引用值，和计划不一致。
核实：`lab/world.ts` 用真实 `composeBrief`、World 和旧渲染：字面地址 `rel.对象` 没有 `reads`，实际值提供 `mentions=[e3]`，含这句话的块被扣，同条目的普通块仍给。新写法更换外壳，不应丢这条依赖。
改法：静态集合补齐全部标签及各支的显式引用/行键，并与实际输出时从引用值、列表行得到的 `mentions` 取并集；t04 描述也走同一收集，另并入插件声明的读取（含无地址属性的读法）。用真实简报断言扣整块，而不只断言绝密名字没出现。

8. [重要／不变量] 旧花括号防线漏掉旧内核实际接收的引用，又不给字面示例转义出口
位置：docs/specs/canon/rendering.md:80,115,123,160；plan.md:60,68；docs/specs/plot/brief.md:68–73。
现象及影响：`{ ref ("e3").entry.name }` 是旧合同的字段表达式，但不含 `{ref(`，`{` 后也不紧跟字段根。新合同不再解析花括号，防线漏掉它，简报能放行含条目 id 与旧语法的原文，而旧版按 `reads` 扣块。反向，作者用反引号或 `\{panel.魔力}` 讲旧写法，已不可能被求值，输出 20 却仍拒写且“换成标签”会把说明变成活引用。
核实：`lab/world.ts` 通过真实 World 发布带空格旧引用、转义正文及代码样例，三者旧 parser 均通过。旧 `composeBrief` 只扣含保密引用的那一块；按新合同的两个字面前缀检查，前者不中、后两者反而命中。
改法：区分遗留数据识别和新正文的字面规则，覆盖旧语法允许的空白/注释，或按明确的源格式判定旧块。在简报路径对不能安全解释的旧语法失败关闭；新写入给字面示例一个明确可用的转义，补旧式空格、代码、转义与未迁移块的真实简报测试。不要靠等待一段时间后删除子串防线。

9. [重要／不变量] 简报给得出的字面标签仍会写出条目 id，残缺候选没有失败语义
位置：docs/specs/canon/rendering.md:29,113–118,170；plan.md:45,68,129；docs/specs/plot/brief.md:68,70；`independent-design.txt:139–145`。
现象及影响：对非保密条目的字面示例 `` `<Ref id="e2" />` ``，输出 15 同时要求 `mentions` 记 e2 和照原文输出。关卡因 e2 的名字可给而放行，于是修改后仍给写手条目 id 与原语法，违反简报输出 16。残缺的 `` `<V entry="e2" of=` `` 则是允许存的字面文字，但计划与 Spec 没保留独立设计的“属性读不全，纯文字报 syntax”；不能用扫描到了几个 id 来证明其余原文干净。
核实：`lab/world.ts` 走真实 `composeBrief`：非保密字面 Ref 随其余正文原样进入涉及条目的样子；设计只加公开条目的 `mentions`，不改变 `gate.ts:339–345` 的放行条件。这条原样输出在旧版也有，新增场景 5 把它写成了新合同。
改法：分开作者／Agent 的字面显示和交给写手的纯文字。后者完整字面标签应去掉 id／语法或标问题扣块；对任何不能完整解析的候选也标问题。验收同时断言公开引用与秘密引用的结果不出现原始 id，而不是只断言 `reads` 或 `mentions`。

10. [重要／不变量] 值表只靠顺序，缺少配对失败与换版边界
位置：docs/specs/canon/rendering.md:93,119–124；plan.md:61,83–84,127,154；packages/neuro-book/src/plugins/canon/shared/contracts.ts:96,225–230,311；docs/specs/runtime/plugin-channel.md:54–55,118。
现象及影响：输出 7 按“活的标签”排值表；计划的标签序号来自词法（含字面、`Else` 和闭标签）。同一块含字面 V、If 真支 V、ElseIf 假支 V 时，没有约定索引域、无值的结构标记或未选分支占不占条目。漏掉前一个 V 后，下一项仍可能是 V，光看种类不能发现值挂错地址；也未规定缺项、额外项、文法不同或错误块走哪条路径。计划以“连接两端同版本”为前提，但握手不比较插件/文法版本，路由按合同整数版本核对；现有 `render`/`renderSource` 输出是 `Unknown`，计划改形状、删方法却没升合同版本，旧客户端会把没有 `tree` 的块送入 `children(block.tree)`（`EntryText.vue:50–51,137`）。
核实：对照输出 7 与 plan.md 的两个序号域，核对上述 wire 规则、`version: 1` 与旧消费者。BOM 与表格用例已在真实 codec 证明共享词法不等于共享落点。
改法：用原文坐标或明确的标签身份对齐，写清未选支、字面、结构标记的参与规则；不匹配时整块回退源文与诊断，不能继续取下一项。升远程合同版本；用两个相邻的同类 V 测漏项、重复、版本不同，不能只测 happy path。

11. [重要／不变量] 白名单分不清 core 识别的 HTML 与条目标签
位置：plan.md:35,45,59,114；docs/specs/canon/rendering.md:47,55,75–76,120,124；packages/nb-markdown/src/language/syntax/core/index.ts:135–151,323–337。
现象及影响：章节能把 `<STRONG>甲</STRONG>` 读成并重写为原大小写的粗体；“所有大写名先遮罩”的计划把它变成两个条目候选，按未登记标签拒收。独占一行的 `<br>` 则相反：marked 给 `html`，core 的块 reader 给 `hardBreak`；若按计划的词法单元名单先拒其他 HTML，编辑器自己写的空行也会被拒。这里共享 marked 扩展不等于共享白名单语义。
核实：`lab/codec.ts` 在真实 `codecFor` 上观察到原 core 的 `<STRONG>` 是 `htmlMark` 并保留大小写；套 E2 遮罩后 `STRONG` 落到条目词法。独行 `<br>` 的两个结果是 `html` 与 `paragraph/hardBreak`。
改法：先把 core 已有的 HTML 强调／换行形态保留给 core，并共享其大小写、块位置和属性判定；白名单区分 core 能解释的节点与其余原样 HTML。断言独行 `<br>`、大小写混排的强调、空任务项的节点和写出，不把“读写未丢字”当作接收了合法结构。

12. [重要／正确性] 双引号属性内的字面 `<V` 与外层标签重叠，遮罩不再等长
位置：plan.md:45–51；docs/specs/canon/rendering.md:50,55,64,78,113,120；独立实验 `entry-grammar.ts:33–61,69–80`。
现象及影响：`<If test="panel.名字 == '<V of=bad />'">有<Else />无</If>` 的 test 是合法的字符串比较；`<V` 位于属性字符串内，不是 Markdown 标签。E2 在全源上查候选，不跳过已消费的属性区间，给出外层 If 的 `[0,38)` 和内层 V 的 `[23,25)`。等长遮罩的非重叠前提失效，后续闭合、诊断列和静态收集失去确定性。
核实：`lab/limits.ts` 用 E2 得到源长 53、遮罩长 68；`lab/codec.ts` 同一输入走真实 marked 与 codec 得 `rawBlock`、零条目节点、无诊断。不是对新实现的运行结论。
改法：消费完整标签时游标跳过经确认的属性区间；出现结构错误只报外层候选，别在其中挖出新的活标签。原子接口验证范围有序且不重叠；覆盖属性含 `<`、`>`、标签形字符串与坏标签，核对列号和静态依赖。

13. [重要／正确性] 按块承诺的标签配额会被整篇编辑器用尽，错误指引也无法执行
位置：docs/specs/canon/rendering.md:81,85,119,145；docs/specs/canon/author-ui.md:261,273；plan.md:45–46,53；packages/neuro-book/src/plugins/canon/web/text-whole.ts:29–38,52–68。
现象及影响：表里保证每个存储块 256 个以内不因标签数被拒，方案按所有词法候选编号，连行内代码里的 3 字 `<V>` 都吃最窄的号位。两块各含 129 处这种代码示例时，分别完全合法；现作者入口把两块拼为一篇，预览按一块解析，修改一个普通字后保存也写成一块。宽度不足从第 257 个候选开始；用户只能删合法文字，不能照 `too-many-tags` 的“拆成几块”操作。
