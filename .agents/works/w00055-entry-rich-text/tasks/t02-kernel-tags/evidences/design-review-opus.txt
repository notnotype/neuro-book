## 1. 编辑器重写写出的“<大写字母 + 空白”不转义，内核按 tag-malformed 拒收；计划没有给条目语法加转义规则的地方
- 严重程度：重要；类别：正确性
- 位置：rendering.md 输出 1 的 tag-malformed 一条（第 78 行）与输出 21（第 124 行）；plan.md 关键设计第 2 节“编辑器侧的条目语法模块”（第 53 行）；nb-markdown packages/nb-markdown/src/language/codec/render/escape.ts:267-269（`<` 只在后面有 `>`、组得成 HTML 时才转义）
- 现象：编辑器的写法对文字里的 `<` 只按“会不会读成 HTML 标签或自动链接”判断转义。实验 e1-escape.ts（core 语言 + 真实 codecFor，段落文字整篇重写）：
  "评级 <A 级" => "评级 <A 级"；"x <If 后面" => "x <If 后面"；"表 <Foo/ 坏" => "表 <Foo/ 坏"；只有后面带 `>` 的 "评级 <A 级>" 才写成 "评级 \<A 级>"。
  新 Spec 输出 1 规定这类“<加大写名字、不成标签、不在代码里也没转义”的写法拒收（tag-malformed），场景 4 明写“评级 <A 级 被拒”。
- 为什么是问题：输出 21 承诺“编辑器原样写回或整篇重写写出的文字过得了输出 1”，计划 S3 的性质测试也照这个写。可是 MarkdownSyntax 没有给语法模块贡献转义规则的字段（syntax/types.ts 里 escape 只是 WriteContext 上的函数，由 codec/render/escape.ts 统一实现），计划第 1 节给 nb-markdown 只加 `atoms`。读回校验也拦不住：按计划“写不完整的候选只遮名字、还原后仍是文字”，读回的文档与编辑器里的一致，第一级（minimal）就通过，写出的文字到内核被拒。作者在富文本里打“评级 <A 级”这种普通句子，保存失败，且错误指向作者看不到的源文写法。
- 如何核实：cd 实现 worktree；bun /tmp/review-w00055-t02-design/lab/e1-escape.ts。
- 建议改法：二选一并写进计划与 markdown-syntaxes.md 的 atoms 合同：(a) atoms 钩子同时声明“原子候选”，escapeText 对落在候选起点的 `<` 一律转义（相当于把“候选”的定义交给语法模块）；(b) 条目语法把不完整候选读成一个不可编辑的特殊节点，使读回与编辑器文档不等，迫使阶梯升到 full（会把整块的 ASCII 标点都转义，不推荐）。S3 的性质测试生成器要显式包含“<大写字母+空白、无 >”的纯文字。

## 2. 值表的“序号”在 Spec 与计划里是两种口径，If 的各部分与没生效分支里的标签有没有项都没定；对不上时前端静默显示错值
- 严重程度：重要；类别：不变量
- 位置：rendering.md 输出 7（第 93 行：“按活的标签在源文里出现的顺序排的值表”）与输出 8 的条件一条（第 96 行：“各支的文字照源文给”）；plan.md 第 58、61 行（“`values` 按标签序号”，序号来自 lexTags，含字面的与不完整的候选）、第 65 行（“没生效的分支照原文给”）
- 现象：
  1. Spec 说按“活的标签”排；计划的序号是 lexTags 给的全部候选的序号（字面的、代码里的也占号）。两种口径在块里有字面标签时序号不同。
  2. 一个 If 在词法里是 `<If>`、各 `<ElseIf />`、`<Else />`、`</If>` 几个标签。值表给 If 与各 ElseIf 项，`<Else />`、`</If>` 占不占号没写。
  3. 没生效的分支里的 `V`：给 Agent 时 Spec 说“各支的文字照源文给”（读起来是所有分支都不带值，连生效的那支也不带），计划说“没生效的分支照原文给”。给作者的值表里这些 V 有没有项、是不是要求值，也没写。按“生效的才求值”实现，前端按全部活的标签数序号，后面的值整体错位一格。
  4. 值表只靠序号对应，项里没有标签名与起点。前后端文法版本不一致（计划风险一节承认的前提：远程连接两端同版本；开发模式下浏览器缓存旧包与后端热重载也会出现）时，前端拿第 i 项去画第 i 个标签，显示的是别的字段的值，没有任何报错。
- 为什么是问题：值表是 Spec“边界与兼容”列出的公开接口，t03 的富文本要照它实现；输出 8 的写法还决定 Agent 能不能看到生效分支里的值（读不到就要另调工具，与决定“带值、只给看”相悖）。
- 如何核实：读 rendering.md 第 93、96 行与 plan.md 第 58、61、65 行对照；没有可跑的实现。
- 建议改法：输出 7 写死：值表每项带 `{tag: 标签名, from: 在源文里的起点}`，只给活的标签，If 的 `<Else />`、`</If>` 不占项（或明确占），没生效分支里的 V 也有项（照样求值，或给 `skipped: true`）；前端按 `from` 与名字对上再取值，对不上整块按出错显示并报诊断。输出 8 改成“生效的那支里的标签照常带值，没生效的支照源文给”，与计划一致。

## 3. 装饰属性的值来自作者数据（条目名、字段显示名、读不到的原因），里面有 `"` 或换行时带值写法自己就不成标签，往返与 Agent 写入都断
- 严重程度：重要；类别：正确性
- 位置：rendering.md 输出 8、9（第 95-100 行）、输出 10 末句“对任何一块源文，先按输出 8 渲染再去值，得到的文字与源文逐字相同”（第 101 行）、标签写法一段“值里不能有 `"` 与换行”（第 55 行）；plan.md 第 45、63-66 行
- 现象：`label` 是字段显示名（components.md 第 62-63 行，实例字段的显示名由作者或 Agent 起，Spec 没限制字符），`name` 是条目当时的名字（作者起），`unavailable` 里拼着命名空间的 label（现实现 packages/nb-canon/src/render/render.ts:75 `${label}第 N 章起生效`）。新的标签词法只认 `名="值"`、值里不能有 `"` 与换行，而 Spec 与计划都没写程序生成这些属性时怎样处理这两种字。现实现写 Ref 用 `name=${JSON.stringify(name)}`（render.ts:363），照搬就是 `name="说\"不\""`，新词法在 `\"` 处断开。
- 为什么是问题：一个名字带 ASCII 双引号的条目（例如外号写成 `"黑鸦"`），所有 `<Ref id=它 />` 所在的块在带值文字里都不再是一个活的标签，而是 tag-malformed 的候选。之后：
  1. 输出 10 的往返不变量对这块不成立（去值只动活的标签）；
  2. Agent 对这块做任何 replace（计划第 82 行：整块渲染、替换、整块去值、写回）都会被写入检查以 tag-malformed 拒收，Agent 改不了这块的任何一个字，错误还指向它没写过的位置；
  3. 计划的“程序属性写进源文报 unknown-tag”兜底在这里不起作用，因为根本没解析成标签。
- 如何核实：读 render.ts:363 与 components.md 第 62-63 行；对照 rendering.md 第 55 行的属性写法。
- 建议改法：输出 9 规定装饰属性值的写法：程序生成时把 `"` 换成 `”`（或 `&quot;`，去值时整段丢掉，不必解码）、换行换成空格；或者把显示名、名字这类人写的文字从属性挪到开闭标签中间（`<Ref id="e12">"说\"不\""</Ref>`，用 JSON，和 V 的值同一种做法，`<` 写成 <）。S3 的往返性质测试的生成器要包含带 `"`、换行、`>`、`<` 的名字与显示名。

## 4. replace 的 find、with 同时被写成“先各自去值”和“在带值文字里找”，两种读法互相矛盾；按序号比对“改了值”在增删标签后错位
- 严重程度：重要；类别：正确性
- 位置：agent-tools.md 新增的“写主文字（planned）”一条（commit 13a8ff591 的 agent-tools.md 第 2 处加行）；plan.md 第 82 行；independent-design.txt 第 5 节“入口”（“五处要用……replace 的 find、with”与下一条“replace 改成在带值文字的空间里做”）
- 现象：两处都写“`replace` 写到 `text[块]` 的 `find` 与 `with`，都先按输出 10 去值再写”，紧接着又写“`replace` 在这一块按读取位置的带值写法里找：`find` 恰好出现一次”。照第一句实现：Agent 照读到的抄 `find="魔力 <V of=\"panel.魔力\">3110</V>"`，先去值成 `魔力 <V of="panel.魔力" />`，在带值文字里找不到，Agent 每次照抄都失败。而且对片段单独去值本身没有定义：`find="3110</V>，"` 这种半个标签的片段里 `</V>` 是孤立的闭标签，去值要么报错要么原样，结果取决于实现。
  另外“文字里改了值”的检测（独立设计写的是“去值以后重新渲染，带值 V 的内容按序号逐个对照”，计划只写了回话）在 Agent 同一次替换里删掉或加了一个 V 时按序号错位，回话里的“现在是 X”会报成别的字段的值。
- 为什么是问题：后续切片照字面实现会二选一，而只有“find、with 原样用于带值文字，替换后整块去值”是对的；写错的那种在 agent-tools.test 里只有用带值片段做 find 才测得出来。
- 如何核实：读 agent-tools.md 与 plan.md 第 82 行这两句；对照 rendering.md 输出 10（去值的对象是“交回的文字”，即整块）。
- 建议改法：agent-tools.md 与计划改成：create、addBlock 的 text 与 set 的整块值先去值；replace 的 find、with 不单独去值，原样在带值文字里替换，替换后整块去值再检查。“改了值”的比对按（标签名、地址或 expr）配对，对不上的不报，只报配得上且值不同的。补两条测试：find 为带值的整个 V；find 为半个带值标签（`3110</V>，`）。另写明不带 `</V>` 的 `<V of="…">3110`（Agent 只抄了开标签）不当带值的 V 去值，而是按 unknown-tag 拒收，免得 `3110` 作为普通文字留进源文。

## 5. “没登记的标签上一版这一块里有就放行”的例外，碰上作者界面“整篇写进第一块、其余删掉”就失效；比较的是原文还是规范写法也没定
- 严重程度：重要；类别：正确性
- 位置：rendering.md 输出 19（第 122 行）；plan.md 第 59 行；author-ui.md 输出 39（“提交时整篇写进第一块、其余的块删掉”）
- 现象：例外只看“这一块原来的源文”。作者界面第一版把整篇主文字当一篇编辑，提交时写进第一块、删掉其余的块。插件卸了以后，第二块里的 `<StatBar … />` 随整篇写进第一块，第一块的上一版没有这段文字，按输出 19 拒收（unknown-tag）。结果是：只要没登记的标签不在第一块，作者改主文字的任何一个字都提交不了，正是决定 4（“没装插件时标签原样保留”）要避免的情形。
  另外，存下来的是规范写法（输出 18），作者在源文字里手写或改动过空格的同一个标签（`<StatBar of="x"/>`）与上一版“一模一样”的比较是比原文还是比规范写法没写；比原文时只差一个空格也会被拒。
- 为什么是问题：决定 4 是开发者定的，Spec 的写法让它在现有的唯一作者入口上不成立；t04 才做登记表，但这条规则本 Task 就要实现（计划第 59 行）。
- 如何核实：对照 rendering.md 第 122 行与 author-ui.md 输出 39 的提交规则。
- 建议改法：例外改成“这个条目当前的主文字（任一块）里已经有规范写法相同的这个标签”，按规范写法比较；或者按名字放行“这个条目当前主文字里出现过的没登记的标签名”，属性不再检查。本 Task 写一条测试：两块、第二块有没登记的标签，按 author-ui 输出 39 的方式提交改过的整篇，能写入。

## 6. replace 在“读取位置的带值写法”里找，没写按哪种模式渲染；Agent 按计划模式读到的值抄进 find 时找不到
- 严重程度：建议；类别：正确性
- 位置：agent-tools.md 新增的“写主文字（planned）”一条；plan.md 第 82 行（“按读取位置渲染这一块”）；packages/neuro-book/src/plugins/canon/backend/agent-tools.ts:73、369-385（canon_read 收 `mode: actual|planned`，写入一侧按 context.position 读、mode 写死 actual，见第 199、216 行）
- 现象：旧合同用 planned-not-writable、line-required 两个码把“按计划模式读的、位置没写线的”挡在回写之外（旧输出 12）。新合同删掉了这两个码，理由是值不再写回，这一点成立；但 replace 现在要在带值文字里逐字匹配 find，带值文字取决于模式（计划模式下值不同，If 的 `value=` 也可能不同）。Spec 只写“按读取位置”，计划同样，没写模式。
- 为什么是问题：Agent 用 canon_read 的 planned 模式读一块（工具允许），抄一句含 `<V …>值</V>` 或 `value="true"` 的话做 find，写入按实际模式渲染，找不到，Agent 只会得到“find 没有出现”，看不出原因；反过来不含值的 find 正常。行为取决于 Agent 抄了哪一段，难以从报错里学会。
- 如何核实：读 agent-tools.ts:73、199、216、369-385 与 agent-tools.md 新增那条。
- 建议改法：Spec 写明 replace 的匹配不受值影响：先在带值文字里找，找不到时把 find 与带值文字里每个活标签的装饰都去掉再找一次（去装饰的比较按活标签逐个做，不对片段单独解析）；或者写明 replace 按实际模式渲染，找不到且 find 里带装饰时回话提示“按实际模式重读这一块”。补一条测试：planned 模式读、抄带值的 find、replace 能成或得到明确的提示。

## 7. 写入检查按词法单元类型放行，但编辑器写出的独占一行的 `<br>` 在 marked 里是块级 `html` 单元；大写的 `<B>`、`<BR>` 在章节里是强调与换行、在条目里成了没登记的标签
- 严重程度：建议；类别：正确性
- 位置：rendering.md 白名单表 Markdown 一行（第 47 行）与输出 1 第一项（第 75 行）、“读法变化”（第 161 行）；plan.md 第 59 行；nb-markdown packages/nb-markdown/src/language/syntax/core/index.ts:126-128（HTML_MARKS、HTML_MARK_OPEN、HTML_BREAK 都带 i 标志）、:322-330（`ONLY_BREAKS`：块级 html 单元只有 `<br>` 时读成只有换行的段落）
- 现象：实验 e2-lex.ts（core 语言的真实词法器与 codecFor）：
  `<br>` => [{type:"html", raw:"<br>"}]；`- 项\n  <br>` 的列表项里也是 html 单元；`> <br>` 同样。编辑器把它们读成只有硬换行的段落，写回时也这样写（core/write.ts:169-186）。只有和文字同一行的 `<br>` 才是行内的 htmlBreak。
  `<B>粗</B>` 在 core 里是 htmlMark（tag:"b"，写法记成 "B"），`<BR>` 是块级 html 并读成换行。按新的标签词法，`<B>`、`<BR>`、`<Em>` 都是“< 加大写名”的候选，遮罩后 core 的 htmlInline 看不到它们，条目里成了没登记的标签（unknown-tag）。
- 为什么是问题：计划第 59 行按单元类型列放行名单（段落、标题……加“core 自己读写的 `<strong>`…`<br>`”），照字面会写成放行 htmlMark、htmlBreak 两种类型，块级 html 一律拒收，编辑器写出的空段落（作者在富文本里敲两次回车）就会被拒；要正确放行，内核得照抄 `ONLY_BREAKS` 的判断，两份正则日后会分叉。大写 HTML 一条与白名单表“与章节编辑器相同的读法”的说法不符，“读法变化”里也没登记。
- 如何核实：cd 实现 worktree；bun /tmp/review-w00055-t02-design/lab/e2-lex.ts '<br>' '- 项\n  <br>' '> <br>' '<B>粗</B>' '<BR>'。
- 建议改法：`./marked` 导出“这个块级 html 单元是不是只有换行”的判断（core 的读法与内核共用同一个函数），白名单写成“块级 html 只放行只有 `<br>` 的”；S3 的编解码器对照用例加上列表项里、引用里独占一行的 `<br>`。“读法变化”补一条：HTML 形式的强调与换行只认小写，大写开头的 `<B>`、`<BR>` 按标签读、没登记即拒收（或者把这六个 HTML 名与 br 不区分大小写地排除出标签候选，并写进保留名）。

## 8. 旧写法防线：Spec 与计划的判据不同，计划那种会误拒代码里的 `${user.name}`，两种都漏 `{ panel.魔力 }` 与 `{/* 注释 */}`
- 严重程度：建议；类别：正确性
- 位置：rendering.md 输出 20（第 123 行：“`{ref(` 或 `{` 紧跟字段引用的根（例如 `{panel.`）……代码里的也算”）；plan.md 第 60 行（“`{ref(` 或 `{名字.`”）
- 现象：
  1. 判据不一致：Spec 是“字段引用的根”（entry、text、本条目的命名空间），计划是任意“名字加点”。按计划实现，代码块里的 `${user.name}`、`{console.log(x)}`、`{this.state}` 都命中，整块写入被拒、已存的块渲染成出错的块；Spec 又规定“代码里的也算”，作者没法用转义或代码绕开。
  2. 两种判据都要求 `{` 后紧跟名字。旧 MDX 允许花括号里有空白：`{ panel.魔力 }`、`{ ref("e9").panel.秘密 }` 不命中，这样的旧块在新内核里是普通文字，纯文字照原文写出地址与条目 id，`reads` 为空，简报照常放行（只泄出地址与 id，不泄值）。
  3. `{/* 注释 */}` 不命中。旧合同里只含注释的表达式不显示给任何人（作者常把备注写在这里，样本里有 `{/* 待补 */}`）；没迁到的旧块在新内核里把注释原文显示给作者、Agent 与写手的简报。转换器会去掉，但防线的目的就是兜住没迁到的块。
  4. `{text[b1]}` 是根后接 `[`，Spec 的“例如 `{panel.`”与计划的“`{名字.`”都不明确是否算。
- 为什么是问题：开发者已确认没有真实作品要迁（11-26），防线只守样本、测试与分享来的旧世界观；现在的判据在正常文字上有误拒、在它要守的旧块上有漏网，两头都不好。
- 如何核实：grep 实现 worktree 的 canon 与 plot 测试数据，能看到 `{/* 待补 */`、`{/* 以后补 */` 这类注释；`${user.name}` 一类误拒按计划判据可直接推出。
- 建议改法：判据写成“`{` 后跳过空白，接 `ref`、`/*`，或接一个字段引用的根再接 `.` 或 `[`”，只在代码之外判（遮罩后的 marked 单元里能分出代码，`{` 不需要偏移也能按单元判在不在代码里）；或者既然没有真实作品，干脆不要这道防线，改成转换器在 S5 对全部样本跑完、断言没有残留，省掉一个要在以后删的失败码。

## 10. 遮罩的两条限制写成了作者可见的拒收：整个私用区的字都拒收，“标签”的计数口径不含代码里的与不完整的候选
- 严重程度：建议；类别：正确性
- 位置：rendering.md 输出 1 最后一项（第 81 行）、失败表 reserved-char、too-many-tags（第 144-145 行）；plan.md 第 46 行；independent-design.txt 第 2 节第 2 条（首位字 U+E000-E0FF，数字 U+E100 起，4 个字的标签能区分 256×6143 个，即用到 U+F8FE）
- 现象：
  1. reserved-char 拒收“Unicode 私用区的字”。私用区在中文文字里并不罕见：GB18030-2000 与港台旧编码转来的文本把一些生僻字、部首放在 U+E000-F8FF（例如 GB18030-2000 映射到 U+E81E 一带的字），苹果的标志 U+F8FF、图标字体也在这里。作者从旧电子书、网页贴进来的设定原文会被整块拒收，提示“去掉这些字”，而这些字在编辑器里常显示成方框或看不见。章节编辑器不拒收它们，所以这也是一条“读法变化”，Spec 第 161 行没有登记。
  2. 计数口径：编码按全部候选（含代码里的、转义的、不完整的 `<A`）分配序号，3 个字的候选（`<V>`、`<T>`）只有 1 个身份字、只能表示 256 个序号。Spec 写“一块里的标签多得超过上限（256 个以内总是放行）”，读者会理解成活的标签；代码块里贴一段带大量 `Array<T>`、`List<String>` 的泛型代码，活标签为 0 也可能被拒。
- 为什么是问题：两条都是实现手段（等长哨兵）漏到了合同里，拒收的是与条目写法无关的正常文字；作者无从理解。
- 如何核实：读 independent-design.txt 第 2 节第 2 条的编码说明，与 rendering.md 第 81 行对照。
- 建议改法：(a) 遮罩前把原文里已有的私用区字也当作原子（每个这样的字记位置，用同一套哨兵编码），这样不必拒收，reserved-char 整个去掉；做不到时至少只拒收与哨兵编码冲突的那一段范围，并登记进读法变化。(b) Spec 写明上限按“< 加大写名字的写法，含代码里的与不完整的”计数，或者让序号分配先给活的候选、再给字面的，保证活的 256 个以内放行。

## 11. 每一块都按“开头的 frontmatter”拒收，把以分隔线开头、后面还有分隔线的普通块也拒了；BOM 没有规定
- 严重程度：建议；类别：正确性
- 位置：rendering.md 输出 1 第一项（第 75 行“开头的 frontmatter”）；plan.md 第 47 行（“内核用 nb-markdown 同一个 splitFrontmatter：主文字开头有 frontmatter 的拒收”）；nb-markdown codec/source.ts:22-39
- 现象：splitFrontmatter 只要开头是 `---` 行、后面任意一行又是 `---`，就把中间整段当 frontmatter。实验 e3-fm.ts：`"---\n第一节 魔力 <V of=\"panel.魔力\" />\n\n---\n\n第二节"` => frontmatter 是前四行。这是一块用分隔线分节的普通文字，Agent 很常这样写。计划说的是“主文字开头”，Spec 写的是“开头的 frontmatter”，内核实际按块检查（输出 1 的对象是“一块”），所以第二块、第三块这样写也被拒；而作者界面（author-ui 输出 39）把各块用空行连成一篇，只有第一块在文首，编辑器只会把第一块的开头读成 frontmatter。
  另外 splitFrontmatter 先剥 BOM（`﻿`），编辑器把 BOM 存在 map 里写回；内核只说换 LF，BOM 留在块里交给 marked 当正文字符，两边读出的第一个单元不同（编辑器没有这个字）。
- 为什么是问题：为了与编辑器读法一致的规则，拒收范围比编辑器会误读的范围大；错误码 unsupported-markdown 也不提示“开头的 --- 被当成了文件头”。
- 如何核实：cd 实现 worktree；bun /tmp/review-w00055-t02-design/lab/e3-fm.ts。
- 建议改法：只对条目的第一块（排序上的第一块）检查 frontmatter，或者干脆规定写入时块开头的 `---` 行之前补一个空行不行就拒收并给专门的提示（例如 `leading-frontmatter`，“开头的 `---` 改成 `***` 或在前面加一个空行”）；写入时去掉开头的 BOM（与去 CR 同一步）。

## 12. 判断未知的 If 给作者画什么没定：纯文字写“未知”，作者界面“只画生效的那一支”而未知时没有生效的支，照字面就什么都不画
- 严重程度：建议；类别：正确性
- 位置：rendering.md 输出 7（第 93 行“判断未知时没有生效的支”）、输出 15 条件一条（第 118 行“判断未知时写‘未知’”）；author-ui.md 输出 10 新加的“条件只画生效的那一支（planned）”；independent-design.txt 第 6 节“未知的判断……给作者的显示另定”

- 为什么是问题：旧合同里作者能看到的“未知”丢了（审查维度 5：旧合同有、新合同没有）；同一块在纯文字与作者视图里表现不同，S0 快照里“给作者的显示文字序列”的对照也会在这里出差异。

## 13. `atoms` 钩子只“返回起止”，可条目语法的 marked 扩展在分词时要知道每个哨兵背后是哪个标签（If、Else、V），这个查询接口与它的作用域没有设计
- 严重程度：重要；类别：代码质量（接口与合同）
- 位置：plan.md 第 37 行（“`MarkdownSyntax` 加可选字段 `atoms`：在原文上找出原子的函数（返回起止）”）、第 48 行（行内扩展 `entryTag` 在一段里配对 `<If>`…`</If>`、按 ElseIf、Else 切分支）；workspace/markdown-syntaxes.md 新加的“可选的原子”一句；independent-design.txt 第 2 节第 3 条（“标签表挂在词法器实例上（实验里是模块级变量；嵌套的 lex 会互相覆盖）”）
- 现象：遮罩以后 marked 看到的只是 `<`+私用区字+`>`。行内扩展要在这串字上判断“这是 If 开标签、那是 Else、这是 `</If>`”，必须能从哨兵查回原子的原文或种类与属性。计划给 nb-markdown 的合同只有“语法模块返回起止、语言负责遮罩与还原”，没有“分词期间按哨兵查原子”的入口。独立设计的实验用的是模块级变量，并已注明嵌套的 lex 会互相覆盖；而 nb-markdown 里嵌套分词是常态：写回校验在 write.ts:208、343 各自新建词法器再 lex，comment 语法的 prepareWrite 经 `tools.lex` 再分一次（syntax/comment/index.ts:473），这些都可能发生在外层 lex 未结束或另一份文本上。
- 为什么是问题：S2 按计划只做“起止”，S3 写 entryTag 时才发现缺口，要么回头改 S2 的公开合同（nb-markdown 是已发布的包，`MarkdownSyntax` 是宿主插件照着写的公开类型，markdown-syntaxes.md 第 1 段），要么在 nb-canon 里用模块级状态，正好是独立设计警告过的并发与嵌套问题。
- 如何核实：读 plan.md 第 37、48 行与 independent-design.txt 第 2 节第 3 条；grep 上述 write.ts、comment/index.ts 行号。
- 建议改法：S2 一并设计并写进 markdown-syntaxes.md：`atoms(source)` 返回 `{from, to, kind?}[]`；语言在每个词法器实例上挂只读的原子表，扩展经 `this.lexer` 拿到（例如导出 `atomAt(lexer, sentinel) → {index, source}`），表随 `lex()` 进入与结束设置、按实例隔离，嵌套的 `lexer().lex` 各有各的表。S2 的测试加一条：外层 lex 期间对另一段文字再 lex，两边的原子互不串。

## 14. 标签词法没规定“已认出的标签里面不再找候选”；独立设计的原型在属性值里含 `<大写` 时重叠认领，遮罩不再等长、文字被复制
- 严重程度：重要；类别：正确性
- 位置：plan.md 第 45-46 行（标签词法与遮罩的说明）；rendering.md 第 55 行（标签写法）与输出 17；原型 /tmp/w00055-t02-indep/entry-grammar.ts:29-63（`source.matchAll(CANDIDATE)` 在整段原文上找候选，不跳过已认出的标签）、:66-84（mask 按候选依次拼接）
- 现象：实验 e4-proto.ts、e5-overlap.ts（用独立设计留下的原型，计划说 S3 要把它的例子写成测试）：
  `<Image src="a.png" alt="见 <V 标签" /> 后文`：长度 38，遮罩后 47，Image 与属性里的 `<V` 都被认领，遮罩结果是 `<#…#><# 标签" /> 后文`，“ 标签" />”被复制了一遍。
  `<Ref id="e1" name="<Boss> 老大" /> 后文`：长度 35，遮罩后 48，同样重叠。
  `<Ref id="e1" name="说"不"" />`：整个 Ref 变成不完整的候选（literal:text），即第 3 条的情形。
- 为什么是问题：等长是整套做法的前提（偏移、行列、还原都靠它），计划第 46 行写了“等长”但第 45 行的词法说明没写候选不能重叠。触发它的输入并不罕见：Image 的 `alt` 是作者写的说明；给 Agent 的 `name`（条目名）、`label`（显示名）、`unavailable` 是程序把作者数据放进属性，名字里有 `<Boss>` 这类写法就会进来。结果在内核里是行列错、分类错，在编辑器里（同一个 atoms 钩子）可能把复制出来的文字写回原文。
- 如何核实：cd 实现 worktree；bun /tmp/review-w00055-t02-design/lab/e5-overlap.ts 与 e4-proto.ts（依赖原型，不是计划的实现；计划的实现还没写，结论是“计划的说明没有排除原型的这个行为”）。
- 建议改法：Spec 输出 17 与计划第 45 行写明：从左到右扫描，认出一个完整的标签后从它的结尾继续，属性值里的 `<` 不是候选；不完整的候选只占 `<名` 那几个字，之后从名字后面继续。S3 的性质测试生成器在属性值里放 `<大写名`、`<V of="x" />`；遮罩函数断言输出与输入等长，不等就抛出（失败关闭）。第 3 条的建议同时适用：程序生成的属性值里把 `<` 也换掉。

## 15. “核对整段属性值都被读完”没定义：acorn 的 parseExpressionAt 会跳过开头的注释，只比 end 时 `/* … */ panel.a` 能通过
- 严重程度：建议；类别：正确性
- 位置：plan.md 第 51 行（“acorn 的 `parseExpressionAt`，核对整段属性值都被读完”）；rendering.md 第 57 行（“式子只许下面这些语法节点……别的一律拒收”）
- 现象：实验 e6-acorn.ts、e7-acorn.ts（worktree 的 acorn 8.17.0）：
  `"/* ref('e9').panel.秘密 */ panel.a"` => start 25, end 32, len 32（只比 end === 长度时通过，注释被当空白吞掉）；
  `"<!-- x\npanel.a"` => start 7, end 14（acorn 在脚本模式下把 `<!--` 当单行注释；属性值不能有换行，所以这一种进不来）；
  `" panel.a > 1 "` => end 12, len 13（尾部空格：只比 end 时误拒）；
  `"panel.a /* x */"`、`"panel.a // x"` => end 7（尾部注释：比 end 时拒收，比“剩下的 trim 后为空”时也拒收）。
  另 `panel.a ?? 1` 解析成 LogicalExpression，白名单写的是 `&&` `||`，要按运算符核对，不能只按节点类型。
- 为什么是问题：注释不是语法节点，按 Spec 应拒收；开头的注释能通过只比 end 的实现，静态的 reads 看不到注释里的 `ref('e9')`（不求值，所以不泄值），但写进源文的注释会原样给 Agent 与写手的简报看，等于又开了一个旧 `{/* */}` 那样的备注通道，与“HTML 注释拒收”的取舍相反。尾部空格误拒则是作者常见的手误。
- 如何核实：cd 实现 worktree；bun /tmp/review-w00055-t02-design/lab/e6-acorn.ts 与 e7-acorn.ts。
- 建议改法：计划写明判据：用 acorn 的 `onComment` 收集，有任何注释即 forbidden-syntax；属性值去掉首尾空白后要求 `node.start === 0 && node.end === 长度`；LogicalExpression 只放 `&&`、`||`。S3 的表驱动测试加上这几例。

## 16. 三元式还在式子的白名单里，计划的式子清单与转换器却当它已经没有了
- 严重程度：建议；类别：文档
- 位置：rendering.md 第 68 行（`ConditionalExpression` `?:` 照旧放行）、输出 5 第 3 小条（“条件的判断是未知时，整个条件表达式的结果是未知”）；plan.md 第 9 行（式子能写的东西里没有 `?:`）、第 76 行（“运算里面的三元式报错”、顶层三元式转成 If）
- 现象：开发者 11-26 第 1 轮定的是“沿用现在的表达式白名单”，所以 Spec 保留 `?:` 与决定一致；但计划第 9 行列举 `test`、`expr` 能写的内容时漏了它，转换器又把“运算里面的三元式”当成转不了、要人工改的情形。既然 `<V expr="(panel.a > 1 ? 1 : 2) + 3" />` 是合法的，转换器直接写成 expr 即可；分支是字符串的顶层三元式写成 `<V expr="c ? '有' : '无'" />` 也合法，只是“不做文字拼接与格式化”的边界上，选一个字符串算不算格式化没有写。
- 为什么是问题：S3 照计划第 9 行实现节点表会漏掉 ConditionalExpression，S5 的快照对照才会发现；转换器多出一类不必要的人工处理。
- 如何核实：对照 rendering.md 第 68 行与 plan.md 第 9、76 行。
- 建议改法：计划第 9 行补上 `?:`；转换器对运算里的三元式写成 expr，不报错；Spec 输出 5 或白名单旁写一句“三元式可以选出字符串（这不算格式化）”，或明确只许数与真假，二选一。

## 19. 脚注与数学从“普通文字”变成“拒收”是一次收紧，读法变化与“白名单只增不减”的例外里都没登记；`$钱$` 这类正文会被拒
- 严重程度：建议；类别：文档

- 现象：实验 e2-lex.ts（core 语言）：`正文[^1]\n\n[^1]: 注` => footnoteRef、footnoteDef；`公式 $a<b$ 与 $$x$$` => 两个 mathInline；`他说 $钱$ 不是问题` => mathInline。价格写法 `$20 和 $50`、`$5，会员价$3` 不受影响（Pandoc 的规则，仍是文字）。旧 MDX（micromark 不带脚注与数学）里这些都是普通文字。新 Spec 输出 1 拒收脚注与数学，“边界与兼容”第 2 条说白名单只增不减、只把花括号列为例外，第 3 条的读法变化清单列了 `a < b`、自动链接、缩进代码等，没有脚注与数学。
