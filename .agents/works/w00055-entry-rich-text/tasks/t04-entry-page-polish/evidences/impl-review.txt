## F1 [重要][正确性/版式] 右栏 max-height 24rem 封顶，展开“位置与出场”后右下又留出大块空白，收起时左下留空；与“高度跟左栏走”不符
位置：NewEntryDialog.vue 的 `.new-entry__groups { max-height: 24rem }`（style 段，约 L255），以及文件头注释“左栏展开变高时右栏跟着拉长”。
现象：grid 默认 stretch，但 max-height 会封住拉伸。我在 /tmp/review-w00055-t04-impl/exp/grid.html 用同样的 grid + flex 结构（右栏列表内容 900px 高）在 headless Chrome 里量：
  - 左栏收起 280px：行高 384，左栏 280、右栏 384（行高被右栏的封顶值撑起，不是“跟左栏走”，左栏下方空 104px，主会话自己的截图 s1b/NewEntryDialog__customized 里能看到）。
  - 左栏展开 520px：行高 520，左栏 520、右栏仍 384（右栏下方空 136px）。这正是开发者在评审板第 2 轮指出的“右下角有很多空白”，展开“位置与出场”（四个字段）时原样回来。
  - 右栏内容少（100px）时：左右都 280，正常。
为什么是问题：计划写的是“maxHeight 取左栏收起时的高度，展开时跟着变高”，实现是写死 24rem，两个方向都不跟；代码注释说右栏会跟着拉长，实际被同一条规则挡住，注释与行为相反。
核实：上面的探针；或 Lab 里展开“位置与出场”量 `.new-entry__groups` 与 `.new-entry__self` 的高度差。
建议改法：让右栏不参与撑高又跟左栏等高。常用做法：`.new-entry__groups { position: relative }`，内层 `.new-entry__groups-inner { position: absolute; inset: 0 }`（右栏不贡献内容高度，行高只由左栏决定，右栏恰好等于左栏高度，列表在里面滚），再给左栏一个 `min-height`（例如 20rem）保证收起时右栏列表还看得下几行；窄时（上下排）把 absolute 去掉、给列表固定 max-height。不要再用 max-height 封顶。

## F5 [重要][正确性/联动] 标题栏“新建条目”预填的分组被标成“作者动过”：选中任何有分组的条目后，换种类时分组不再跟着种类走，新条目会悄悄落进被选中条目的分组
位置：new-entry.ts `emptyDraft`：`folderTouched: folder !== ""`；entries-view.ts `near` 的 `folder: found.item.folder`；NewEntryDialog.vue 里 `shownFolder = folderTouched ? folder : kind`、`patch({kind, ...(folderTouched ? {} : {folder: value})})`、`withKind` 的 `...(draft.folderTouched ? {} : {folder: kind})`。
现象：条目的 folder 缺省就等于它的种类（newEntryOp 里 `folder: folderTouched ? folder : kind`）。选中“星瑕”（folder “人物”）后点标题栏“新建条目”：草稿 folder=“人物”、folderTouched=true。作者接着点种类“物品”：withKind 因 folderTouched 不改 folder，新条目被建进“人物”分组；段头摘要折叠着、第一段写的是“人物 · 一开始就在”，不展开看不出（展开看分组一栏才知道）。以前的新建（无预填）分组总是跟着种类走。
为什么是问题：Spec 输出 4 写的是“分组与上级预先填成它的（新建在它同一层）”，意图是同层；但选中项的分组多数只是它种类的默认，不是作者选的。把一个默认值当成“作者动过”，等于让“选中了什么”决定新条目的分组，而作者此时选的是另一个种类。plan 与 Spec 都没有写“预填的分组要不要跟着种类”，这是没写出来的假设。tests（entries-view.dom.test 新增用例）只断言了预填值本身（folder “组织”、folderTouched true），没有断言之后换种类会怎样。
如何核实：dom 测试里选中一个 folder 与 type 相同的条目，startNewEntry(state,null)，再在对话框点另一个种类按钮，读 state.creating.value.folder。
建议改法（二选一，请开发者定）：① 预填的分组只在它不等于被选中条目的种类时才标 folderTouched（等于种类就是默认，留给种类跟）——near 里加 `kind`（EntryTreeItem 没有 type，需宿主从 known/列表项取）；② 不预填分组，只预填上级。无论哪种，补一条“预填后换种类”的断言。

## F8 [重要][正确性/输入法] 名字框回车新建只判 event.isComposing，WebKit 上选词那一次 Enter 会直接建条目
位置：NewEntryDialog.vue `onNameEnter`：`if (event.isComposing || !ready.value) return;`。
现象：同仓库的做法是 `event.isComposing || event.keyCode === 229`（ComponentChecklist.vue L96-97 注释写明：WebKit 在组字结束后才发选词的那次 Enter，此时 isComposing 已为假；nb-ui SearchSelect 同）。桌面壳是 electrobun（macOS 上是系统 WebKit），名字几乎都是中文，用拼音输入法在名字框里按 Enter 选词，会被当成“新建”，把拼音刚上屏的名字（可能还没改完）直接建出来；条目建出来就是写入一次修订，不是随手能撤的小事。
为什么是问题：这是本次新增的唯一“回车即提交”入口，恰好落在输入法最常用的框上；dom 测试只测了 `isComposing: true`（Chrome 的行为），没有 keyCode 229 的用例，等于没测 WebKit 路径。
如何核实：模板里发 `new KeyboardEvent("keydown", {key: "Enter", keyCode: 229})`，当前代码会 emit confirm（从代码推断，我没在 WebKit 上跑）。
建议改法：抽成同一个判断（`event.isComposing || event.keyCode === 229`），并在测试里加 keyCode 229 的一条；测试里先断言 confirm 没发，再做变异（删掉 229）看它失败。

## F14 [建议][可达性/反馈] 放头像时，简介按钮的 title 被换成简介全文，页面只读（blockedReason 非空）时看不到“不能改的原因”
位置：EntryPage.vue 简介按钮 `:title="portraitShown && props.summary !== '' ? props.summary : blockedReason"`。
现象：有头像且简介非空时，按钮的 title 恒为简介全文（为了截断时悬停看全文）；这时如果因为世界只读或有未提交的主文字而 `disabled`，悬停读到的是简介而不是原因。设计语言“反馈与等待”要求停用的控件说得出原因；名字按钮、别名按钮、两个种类出场按钮都保持 `title = blockedReason`，只有简介例外。
如何核实：mount EntryPage 带 portrait、editable、editReason，读 [data-edit="entry.summary"] 的 title（从代码推断）。
建议改法：停用时 title 优先原因（`blockedReason ?? (portraitShown ? summary : undefined)`），或把“全文”放在 aria-label 里（已有）与 tooltip 之外的位置，不占 title。

## F18 [建议][正确性/信息准确] 页头“出场”对 prehistory、unscheduled 与章已被删的情况都写“一开始就在”

## F19 [建议][文档/动效清单] EntryPage.md 的“状态”没写新增的状态过渡；Lab 里没有“展开位置与出场”的场景

## F20 [重要][版式/需在 Lab 复核] “在看”挪进 219px 的右栏后，“这时还没出场”的标记几乎没有位置；英文的“在看”也放不下
位置：EntryPage.vue `.entry-head__where`（width: 240px，border-box，padding-left 20 + 发丝线 1 → 内容宽 219px）里放 `ViewPointPicker`；ViewPointPicker.vue 根是 `flex min-w-0 max-w-full items-center gap-1`（不折行），`.view-point__mark` 是 `min-width:0; white-space:nowrap; padding:0 10px` 的 pill，内部文字 `truncate`。
现象：主会话自己的截图 /tmp/w55-t04/s2/EntryPage__portrait__1180x400__light.png 里“‹ 在看 第 2 章末尾 ›”这一组量出来约 185–190px；219 − 190 − gap 4 ≈ 25px，留给“这时还没出场”（12px 字，6 个字约 72px + 内边距 20px）的只有 25px，pill 会被压成只剩几像素的“…”。以前“在看”是在别名行靠右、整行都能用，标记可以并排放下。Spec 输出 8 明写“‘在看’左边的标记写‘这时还没出场’（不另起一行）”。英文界面的 390 截图（EntryPage__editable-english）里 “‹ Viewing End of chapter 2 ›” 本身约 235px，已经大于 219px；第 12 章以上更长。lab 里 entry-page.scenes.ts 的 `same-as` 场景同时带了 notAppeared 与 positionGone，但没有主会话的截图记录，plan 要求的“1440、760、390”也没有 notAppeared 的图。
为什么是问题：新布局把一个宽度有弹性的控件放进了定宽列；“还没出场”是 Spec 要求读得出来的状态，不能只靠 truncate 的 title。
如何核实：Lab 的 EntryPage `same-as` 场景在 1180 与英文下截图，看标记与“在看”是否被挤、右缘是否溢出页头的 32px 内边距。我没渲染，上面是按截图量出来的估算。

## F21 [重要][正确性/接口] startNewEntry(state, null) 同时代表“标题栏的新建（跟着选中项）”与“右键空白处/分组行的新建（最上面一层）”，后者现在也被选中项预填
位置：entries-view.ts `startNewEntry`：`parent !== null ? emptyDraft({parent…}) : emptyDraft(state.near.value ?? {})`；EntryTree.vue `menuItems`：`emit("create", menu.value?.parent ?? null)`，`rowIdOf` 对分组行、“再显示”、读取中行与空白处都返回 null（注释写明“按空白处算”）；plugin.ts L352 命令 `newEntry: (parent) => startNewEntry(state, parent)`（命令参数可省）。
现象：在设定树的空白处或某个分组标题上右键 →“新建”，之前建在最上面一层、分组跟着种类；现在 parent 为 null 走进 near 分支：上级与分组被预填成“树里当前选中的那一项”的（这个选中项可能在屏幕外、是别的分组里的、别的父下面的）。作者右键的是 A 分组标题，对话框却预填了选中项 B 的分组与上级。
为什么是问题：一个 null 承担两种意图；右键空白/分组本来的意思是“根”，Spec 输出 4 只规定了标题栏的“新建条目”才跟着选中项（“视图标题栏的‘新建条目’在树里选中了一个条目时…”），右键菜单只写了“在它下面新建”（条目行）。dom 测试里没有“右键空白处不预填”的用例（只测了标题栏路径）。
如何核实：state.selected 设成某个有分组的条目，从 EntryTree 空白处右键选“新建”，读 state.creating.value.folder（我从代码推断，没跑）。
建议改法：区分入口：给 startNewEntry 一个显式的 `{from: "header" | "row", parent}` 或第二参数 `nearSelected: boolean`；标题栏的按钮才传 true，EntryTree 的右键一律 false；命令的缺省取标题栏语义。补一条“右键空白处不预填”的用例。

## F22 [建议][可达性] 种类按钮与预设按钮的“按下/已选”只靠颜色区分（浅灰底 vs 强调色浅底），没有第二个标记
位置：NewEntryDialog.vue `.new-entry__kind[aria-pressed="true"]`；ComponentChecklist.vue `.component-checklist__preset[aria-pressed="true"]:disabled`。
现象：选中与未选中只差一个 14% 强调色底加蓝字（对比度见 F2）。主会话自己的 390 截图（s1b/NewEntryDialog__person__390x760）里“人物”“基本”两个选中项与同排灰按钮靠目测才分得出，色弱或强光下分不出。aria-pressed 给了读屏，但视觉上没有勾、边框或字重的变化。
为什么是问题：固定检查第 9 条“状态不只靠颜色”，设计语言六、无障碍。
建议改法：选中的那个加一个 `i-lucide-check` 小图标或 1px 强调色描边；同一个组件库里 nb-ui 的 ToggleGroup/Chips 若已有选中画法，直接复用。

## F23 [建议][四态] 登记的类型还没读到（或读失败）时，横版对话框的右半边整块是空的；以前列表只是不出现
位置：NewEntryDialog.vue 模板 `v-if="props.items.length > 0"` 包右栏，但 `.new-entry` 的 `grid-template-columns: minmax(0,1fr) minmax(0,1fr)` 恒为两列。
现象：对话框一打开 `components` 还没读到（entries-view.ts 是对话框开了才读，`items` 先是 []），或读取失败、一个类型也没登记时，左栏只占左半，右半空着，读到后右栏才出现，整个对话框内容的布局跟着一跳；失败时右半永远空。开发者评审板第 2 轮点名的就是“右下角空白”，这里右半整块都空了。
为什么是问题：Lab 的场景都给了 items，没有场景覆盖“没读到”；设计语言/开发规范 4.1 要求自己显示加载、空、失败的组件覆盖四态。
如何核实：Lab 里给 NewEntryDialog 的 items 传 []。
建议改法：items 为空时给右栏一个占位（“正在读取设定组…”/失败原因，用 role="status"），或让 `.new-entry` 在没有右栏时退成单列（`:class` 加 `new-entry--single`）；补一个场景。

## F24 [建议][零碎，合并报告] 三处小问题
