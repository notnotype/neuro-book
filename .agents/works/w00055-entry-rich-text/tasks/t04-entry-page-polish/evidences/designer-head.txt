# omp @designer（Gemini）顾问意见，2026-11-27；说明见同目录 designer-head-brief.md
**核心结论**：现在页头显空，不是因为条目缺数据，而是**单列左堆 + 960px 宽容器两极拉伸 + 条目级元信息缺席页头**共同造成的。推荐采用**方案 1（左身份 + 右坐标的双栏紧凑页头）**，同时把宽屏下过宽的页头跨度收住；若愿意在宽屏断点做更大胆的版式升级，**方案 2（宽屏左置档案侧栏）**在阅读感和空间利用率上最好。

---

## 1. 为什么现在看起来空（版式诊断）

1. **左堆三行 + 左右两极撕裂**：名字、简介、别名全挤在最左侧约 25%–30% 的窄带里，`…` 与 `在看` 被推到最右端。图 1、图 2（590px 编辑区）中右空掉约 60%；图 3（960px 内容列）中间直接拉出一条 450px+ 宽、100px+ 高的空白带，视觉完全断成两截。
2. **宽屏页头与下方两栏脱节**：图 3 主体已切成“左竖导航（~180px）+ 右主内容区（~740px）”，页头却仍横跨 960px 居中铺开，左列文字刚盖过导航栏一点点，右侧主内容区正上方几乎整片空置。
3. **条目自身的元信息全没进页头**：种类、分组、上级条目、马甲归属、首次出场与出场统计、已启用的设定组，全部缺席页头（只零星出现在面包屑或藏进 `…`）。页头只剩“名字 + 两个浅灰占位”，新建条目天然像未完成的草稿。
4. **过度垂直折行放大了空白面积**：空面积 ≈ 页头高度 × 右侧剩余宽度。名字、简介、别名各占一整行，每行只有几个字；别名空态还白白占一行（且 `+ 添加别名` 的按钮内边距让 `+` 略向右缩，与标题、简介左边缘未齐平，显得更松散）。
5. **右侧条件控件缺席时直接留洞**：`在看` 仅在作品有章节时出现。图 1、图 2 无章节时，整个右半区只剩顶角一个 `…`；即便图 3 有 `在看`，它也孤悬在右下角，与右上 `…` 之间空出一整行，无法撑起右栏重心。
6. **画布层级扁平，缺少锚点**：图 1、图 2 页头与主体同底，标题字号偏保守，往下连着三行灰字（`一句话简介`、`+ 添加别名`、`还没有主文字`），反倒被正文中那枚高饱和蓝底 `开始写` 按钮抢走全部注意力，更衬出上半区的空薄。

## 2. 页头方案（3 个）

三个方案共用同一套**三层空态策略**（避免堆满空表单，同时满足“零废话”和“不推高正文”）：
- **文本字段（名字、简介）**：就地轻占位（`一句话简介`），点击直接输入。
- **高频分类/集合入口（种类、分组、别名、设定组）**：静息态为极淡的内联文字触发器，悬停显浅底，既是信息也是操作入口。
- **稀疏关系与状态（上级条目、马甲、已删除）**：**空时完全隐藏**（经 `…` 设置），有值时**同行内联**出现，绝不新增一整行把下面内容推下去。

---

### 方案 1：左身份 + 右坐标的双栏紧凑页头（最推荐）

把页头做成左右分工明确的“条目档案头”，内容列封顶从 960px 收紧到约 **840px**，左区锁定 3 行高（名字行 / 简介行 / 别名行），右区定宽约 220–260px 且总高不超过左区 3 行——**因此 `在看`、统计等条件信息出现与否，都不会改变页头总高**。

**空条目（刚新建普通条目，无种类、无章节、无立绘）**：
```text
新条目甲  [+ 种类]                                   分组 未分组   …
一句话简介                                           + 添加设定组
+ 别名
──────────────────────────────────────────────────────────────────────
[ 文字 ]  +
```

**填满的人物条目（有立绘、别名、马甲/上级、章节与剧情统计）**：
```text
┌────┐  星霞  [人物]  ↳ 本尊：星月             < 在看 第 2 章末尾 v >  …
│立绘│  第三魔法学院一年级，靠打工交学费        分组 人物 · 上级 星月议会
│头像│  [小瑕 ×] [夜王 ×] + 别名               第 1 章起 · 出场 8 章 · 情节 4
└────┘
──────────────────────────────────────────────────────────────────────
```

- **用到的已有数据**：名字、简介、别名、种类、马甲（`↳ 本尊`）、分组、上级条目、立绘（仅作 52–56px 方形头像，代表条目）、首次出场章、出场章数、情节条数（`最近出场` 放悬停 tooltip，避免过长）、已启用设定组入口、`在看`、`…`；已删除时在标题同行加 `已删除` 徽章。
- **宽窄屏排法**：
  - **窄屏（~590px 编辑区）**：左右仍可并排（左约 340px + 右约 200px，右区属性自动收紧为 2 行，超长分组/上级单行省略，悬停看全）；仅极窄分屏（<460px）时右区折到左区下方。
  - **宽屏（侧栏关闭）**：整体内容列封顶收至 ~840px（左身份区弹性至 ~540px，右坐标区定宽 ~260px，左右之间可加一条极淡 1px 竖线或仅靠留白形成双列），彻底消除 450px 空白带。
- **空字段出现方式**：
  - `种类`：空态在标题旁放低对比 `+ 种类` 轻入口（点击下拉选），选定后转为柔和标签，同行淡入不位移。
  - `立绘头像`：仅在**已有立绘**时于名字左侧水平展开（不推高正文）；或者仅对含“形象”组的人物条目在无图时显示极淡 52px 图标槽作上传入口（见第 3 节联动，避免和人物分页重复）。非人物条目不占头像位。
  - `别名`：左边缘对齐标题首字（去掉多余左 padding），空态仅显示紧凑的 `+ 别名`。
  - `右区`：无章节时隐藏 `在看`，同位置不占位推高；空条目未挂设定组时，右区第二行显示 `+ 添加设定组` 轻入口（给刚新建条目的下一步动作提供自然抓手）；有章节后显示 `第 N 章起 · 出场 M 章 · 情节 K`（异步统计算完用 opacity 淡入，不触发位移动效）。

---

### 方案 2：宽屏左置“条目档案侧栏” + 窄屏紧凑双栏头

顺着图 3 已经出现的“左竖导航 + 右主内容”两栏结构彻底往前走一步：**宽屏不再画横跨全宽的大页头**，把条目身份卡并入左侧定宽栏（~240–260px）放在分页列表上方；右侧主内容区（封顶 ~680–720px，最佳长文行宽）顶部只保留一条 44px 单行栏，放当前分页名、`在看` 与 `…`。窄屏（无左侧导航时）退回方案 1 的双栏紧凑顶头。

**宽屏 — 空条目**：
```text
新条目甲                   │  文字                                 …
[+ 种类] · 分组 未分组     │ ────────────────────────────────────────
一句话简介                 │  输入正文……（直接就地书写，无空态按钮）
+ 别名                     │
                           │
─────────────────────────  │
[ 文字 ]                   │
+ 添加设定组               │
```

**宽屏 — 填满的人物条目**：
```text
┌────┐ 星霞                │  人物         < 在看 第 2 章末尾 v >  …
│头像│ [人物]  ↳ 星月      │ ────────────────────────────────────────
└────┘                     │  [人物分页主体，首屏直接顶到最上方]
第三魔法学院一年级，靠打工  │
交学费                     │
[小瑕 ×] [夜王 ×] + 别名   │
                           │
分组  人物 / 星月议会       │
出场  第 1 章起 · 共 8 章   │
─────────────────────────  │
[ 人物 ]                   │
  文字                     │
  数值                     │
─────────────────────────  │
  情节                  4  │
```

- **用到的已有数据**：与方案 1 相同（名字、种类、马甲、头像、简介、别名、分组、上级、首次出场/出场章数、情节条数在导航项保留、`在看`、`…`）。
- **宽窄屏排法**：
  - **宽屏（≥ ~820px，触发左导航断点）**：左栏 240–260px 独立垂直滚动或吸顶，右栏 680–720px 专注主体内容；页头荒漠彻底消失，且首屏给正文/卡片多赚出 100px+ 垂直高度。
  - **窄屏（~590px）**：切回方案 1 的紧凑双栏顶头 + 横向分页条。
- **空字段出现方式**：同方案 1；因左栏独立于右侧内容流，简介折行、别名换行、新增上级/马甲都不会推低右侧正文顶部。
- **代价**：宽窄屏切换断点时标题位置会在“顶部 ↔ 左栏”间跳变；240px 宽度下较长的简介会折 2–3 行；开发改造成本高于方案 1。

### 方案 3：压行单轴头 + 固定单行事实带（最小改动）

不引入右栏也不改宽屏两栏框架，只通过**把 `在看` 提上标题行 + 压缩行高 + 合并元数据到固定单行事实带 + 收紧页头宽度**来消空。

**空条目**：
```text
新条目甲  [+ 种类]                                                …
一句话简介
未分组  ·  + 别名  ·  + 添加设定组
────────────────────────────────────────────────────────────────────
[ 文字 ]  +
```

**填满的人物条目**：
```text
┌──┐ 星霞  [人物]  ↳ 星月                < 在看 第 2 章末尾 v >   …
└──┘ 第三魔法学院一年级，靠打工交学费
     分组 人物 / 星月议会 · [小瑕 ×] [夜王 ×] + 别名 · 第 1 章起(8章)
────────────────────────────────────────────────────────────────────
```

- **用到的已有数据**：名字、种类、马甲、小头像（36–40px，仅已有立绘时显示）、简介、分组、上级、别名、首次出场与出场章数、`在看`、`…`。
- **宽窄屏排法**：
  - **窄屏（~590px）**：总高从现在 ~150px 压到 ~105px；事实带超宽时优先收折出场统计进 tooltip 或 `+N`。
  - **宽屏（侧栏关闭）**：方案 3 必须**把页头对齐并封顶在右侧主内容列宽（~720–760px）**，或整页最大宽收至 780px，否则第 2 行简介右侧依然会拉出大块空白。
- **空字段出现方式**：全部压缩进第 1 行与第 3 行固定槽位，不增行；`在看` 提至第 1 行右侧后，无章节时仅留 `…`，不再形成右侧第二行空洞。
- **代价**：条目数据全填满时，第 3 行单行事实带容易拥挤（需要截断/收折别名或统计）；空条目在宽屏下仍比方案 1、2 素净一些。

### 推荐结论

**首选方案 1（左身份 + 右坐标的双栏紧凑页头）**，理由：
1. **同时治好窄屏与宽屏的中间空白**，且宽窄屏心理模型一致，拖动分栏跨断点时标题不跳位置。
2. **严守“状态出现不推高正文”**：右区高度被左区固定 3 行兜住，`在看`、出场统计、马甲、种类、头像任意组合切换，下方分割线 0px 纵向位移。
3. **开发成本与信息回报比最高**：无需重做宽屏壳层，用现有 nb-ui 标签、轻按钮、选择器即可拼出，安静克制，只在“条目名”一处视觉用力。

若团队愿意借此次优化同步升级宽屏阅读体验（让正文首屏更高、彻底去掉通栏页头），**方案 2** 是天花板更高的长期形态。

## 3. 页头下面两个空态的改法

1. **“文字”分页去掉空态拦截，直接进入可写正文**：删掉说明句“还没有主文字”和刺眼的实心蓝按钮 `开始写`。进入分页直接落进就地可写的编辑器画布，首行仅放极淡占位（如 `开始记录……` 或当前编辑器默认占位），点击空白即直接打字；若底层需惰性创建文档，视觉上仍做成“点击即原地聚焦输入的轻占位行”，绝不用主按钮把空页面衬得更空。
2. **人物分页去掉竖排 6 个重复的“填写”**：静息态把 `填写` 换成极淡的短横线 `—`（或仅在悬停/聚焦当前行时亮出微弱底色与输入提示），立刻消除“机械空表单墙”的压迫感，让“已填内容”和“未填槽位”有清晰的视觉区分。
3. **空立绘不再霸占半幅宽度，短字段改为双列网格**：图 2 里未传图时那块约 160×210px 的大虚线 `添加立绘` 框挤占了快一半宽度，不仅自身是一大块死白，还把右侧 `现在的状态` 占位挤出换行孤字“境”。改法：无立绘时不铺这块大虚线框（上传入口收进页头小头像槽或“形象”分页，或在卡片右上角留一个紧凑入口）；6 个短字段（性别、年龄、身份、所属、现在在哪、生死）排成 **2 列 × 3 行**的紧凑键值网格，下面 `现在的状态` 拉通整卡全宽；已有立绘时再在左侧展开立绘区（或固定在“形象”分页主看、人物页缩成轻巧挂图）。
4. **给人物短属性区和下方长文本区做克制的材质区分**：将上方结构化短字段（6 项 + 现在的状态 + `+ 添加一项资料`）包进一块极淡暖灰底或极细描边卡片里，收紧行高，与下方自由书写的“性格 / 说话方式 / 背景”区分节奏；宽屏下两者同享 ~680–720px 的舒适列宽，避免散在 960px 白纸上。

---

## 4. 不该做的（看起来热闹但没信息）

- **不加纯装饰封面图 / 彩色渐变横幅（Notion Cover 风格）**：白占 150–200px 首屏，空条目挂一个“添加封面”只会更喧宾夺主，违背安静克制。
- **不放“设定完成度进度条 / 完善度 20% / 新手引导卡片”**：小说里的配角、地点不需要填满所有字段，进度条既制造无效焦虑，又不提供创作信息。
- **不加解释性说明句与引导废话**：如“在这里补充角色设定”“创建章节后可在此切换时间点”“别名可用于检索与识别”——占版面且违背不写解释句的约束。
- **不在空态铺一堆“0”和“无”的占位标签**：如同时摆出 `无上级`、`非马甲`、`出场 0 章`、`情节 0 条`、`暂无章节`。满排零值比留白更显寒酸；稀疏字段空时必须彻底隐藏。
- **不把设定组内部字段（性别、年龄、身份、生死）挪进页头凑数**：破坏“页头只属于条目对象”的模型边界，而且普通非人物条目依然会空，还会混淆“在看”随章节变化的数据归属。
- **不用高饱和大按钮、彩色标签雨或后台统计大数字卡片（Dashboard 风格）来撑场面**：全页只应在主标题与当前激活态两处克制用力，其余回归低对比中性文字与细线。
