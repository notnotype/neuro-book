## 关键设计

### 编辑器一侧的条目语法：`packages/neuro-book/src/plugins/canon/web/entry-syntax.ts`

节点只存能从源文推出的东西，节点的原文就是源文的切片，写回原样：

- 条件要成一个整体（作者拆不坏），但在哪一层成组 S1 先做探针再定（第二轮审查第 6 条）：（甲）词法层，语法模块把一行之内配好对的 `<If …>…</If>` 整段给成一个原子——第二轮实测原子范围在片段上算（表格单元格、行内另分词），`If` 的配对却依赖整篇的 Markdown 上下文，表格里 `| <If test="t">x | y</If> | z |` 片段上配成一对、整篇里是 `cross-block`，会让表格的格数数错；嵌套的 `If` 会让遮罩报范围重叠；每次分词多一遍整篇解析。（乙，倾向）词法层照 t02 每个活标签一个原子（与内核逐字一致，rendering 输出 17 把原子放在词法层就是为了这一点），读出之后在语法模块的 `resolve`（整篇读完的钩子）里把同一段里开、分、闭之间的节点合成一个 `entryIf`，它的原文取整篇源文的切片（按 t02 已证明的“原子与活标签一一对应”的先后找开闭标签的位置）；codec 写回时的读回校验也走同一个 `resolve`，两边一致。探针用真实编解码器跑：表格、列表、引用、标题里的条件，各支含强调、链接、行内代码、`<V>`、`<Ref>`，嵌套与写坏的；对不上内核配对的一律不成组（各标签一个、画成 `entryRaw`）。进编辑时另做一道运行时比较：编辑器读出的条件与内核 `parseEntryText` 的 `entryIf` 对不上，就整篇落在源文字（写原因），不在富文本里猜。跨行的 `If` 不成组（已知限制，Spec 写明）。
- 节点：`entryValue`（`V`）、`entryIf`（整段条件）、`entryRef`、`entryImage`、`entryRaw`（没登记的标签、跨行条件的零件、写坏但被认成标签的）。属性：`source`（原文）。各项（`of`、`entry`、`expr`、`test`、各支的原文）在节点视图与浮层里按需用 `lexTags`、`parseEntryText` 从 `source` 读，不另存。
- 改一个小块 = 换掉它的 `source`。新原文用 `tagText` 拼（条件：开标签、各支原文、分支标签、闭标签，写成一行；各支原文里有换行的不收），然后做**写入前的检查**：在事务的草稿上 `codec.write` 整篇（编解码器写改过的块时自带读回校验：读回的节点与文档不同就写不出，这就是“这一处仍读成同一种节点”的判定，第二轮第 7 条），再 `checkEntryText(parseEntryText(整篇))`（带下面的基线）没有新问题，才把事务提交；只在“应用”时做一次（第二轮实测 7.5 万字约 0.4 到 1 秒，负载 25 以上；整篇上限 5 万字），做的时候按钮显示进行中；否则不改文档，浮层里写原因、留着作者打的字（审查第 4 条）。浮层里的输入先存在浮层自己的状态里，按“应用”、回车或关浮层时检查一次，合成一个撤销步。
- 读回一致的性质测试改写（审查第 11 条（c））：t02 的“节点里的标签等于内核的活标签”改成“把 `entryIf` 展开成里面的活标签后等于内核的活标签”，重做一次变异检查。另加表驱动：表格单元格里的条件（含 `\|`）、列表项里的条件、标题里的条件、跨行的条件、各支里有强调、链接、行内代码、`<V>`、`<Ref>`。

### 写入失败、受控值与光标：新组件 `web/components/EntryRichInput.vue`

与 `PlainSourceInput` 同一个合同，逐项对照写进 `EntryRichInput.md`（S3 前半先写，审查第 6 条建议）：

| 合同 | 富文本里怎样做 |
|---|---|
| `update:modelValue` | 每次文档变化后整篇写出（`codec.write`），成功就交出并 `accept(tr)` 登记新来源（同章节编辑器）。写不出（不应发生：小块的改动都过了检查）：不交出，输入框下面写“这一处写不出，撤销上一步”，暂存留着最后一次交出的文字。 |
| `modelValue` 从外面变（“换成那边的”、冲突里选“现在的”、重连后读到的暂存） | 与最近一次交出的比，不同才 `codec.reload(tr, source)`（只换不同的那一段，保撤销历史）；相同是回声，不动。 |
| `focus(caret?)` | 照做。 |
| `cursorOffset()` 与切换模式时的光标 | 编解码器不给节点到偏移的对照，降为“同一个顶层块、块内按纯文字的偏移”：富文本切源文字，光标落在对应块的开头加块内偏移；反过来按源文字光标所在的块。写进组件文档与 Spec。 |
| `insert(text)` | 收一段源文，按条目语法读成节点插在光标处，过写入前的检查；`readonly` 时返回 false。光标在行内代码、代码块里时“插入”菜单与 `{`、`@` 不可用（菜单项写原因）；在链接文字里照插（标签在链接文字里是活的，内核放行的才落）；条件的模板写成一行。 |
| `readonly` | 关掉编辑、`{`、`@` 与浮层里的改动；浮层只能看。 |

另收：`values`（见下一节）、`fields`（本条目各设定组的字段，带此刻的值）、`find`（`EntryFind`）、`baseline`（存下的那一版主文字里没登记的标签，见“源文字模式”）、`showBranches`。

### 值怎么到小块上：`web/text-preview.ts` 改名为 `web/text-values.ts`

- 仍按停顿约四分之一秒请求 `renderSource`（rendering 输出 16），世界变了、重连时重读（沿用现在的 `stamp`）。超过 5 万个字符不请求。
- 对上值的做法与阅读视图同一段逻辑：把 `layoutBlock` 里“按标签名与起点把值表对回活标签、对不上整块不用”抽成共用函数（rendering 输出 7，不按位置猜），得到请求时那份源文里每个活标签的“原文 → 值”。再按原文把它们与文档里此刻的小块对齐（最长公共子序列：作者在别处打字、小块原文没变的照样换上新值；新插的、改过的小块对不上，等下一次）。这样作者连续打字时值也会更新（审查第 5 条（c））。
- 对齐的粒度是活标签（第二轮第 8 条）：文档一侧把整段条件展开成里面的活标签再排，条件小块里的 `V`、`Ref`、`ElseIf` 都对得上值。
- 值用 `Decoration.node` 挂在小块上（带值的 `spec`，随事务自动映射位置），节点视图从 `decorations` 读，不进文档、不进撤销历史；不用“节点视图每次数自己是第几个”（几千个小块时是平方级）。S3 的第一条 dom 测试确认 Vue 节点视图拿得到 `decorations` 与 `useCanonText()`。输入法组字时（`view.composing`）不换，组完再换。
- 初值里读不出的块（出错的块、对不上的）没有值，这些块里的小块画“没有算”，不画“计算中”。“计算中”的小块按字段显示名或式子原文的宽度画，值到了宽度会变、所在那一行回流（作者刚在附近打过字，已知取舍）。
- 进编辑时稿与存下的文字相同（刚点“编辑”）：直接用阅读视图手里的值表当初值，不先画“计算中”（审查第 5 条（d））。
- 本条目的字段在 `fields` 里有此刻的值：新插的取值小块马上显示它（`@designer` 第 3 条）；别的条目的字段、计算、条件在对上值之前画“计算中”的弱样子。超过 5 万字不请求时，计算与别的条目的值画“没有算”的样子（与“计算中”分开，审查第 7 条（e））。

### 小块浮层与编辑器的状态（第二轮第 5、11 条）

- 浮层里没应用的字只存在浮层里。下面几种情况关上浮层、丢掉没应用的字：开始提交（`phase` 离开 `idle`）、输入框变只读、外面换了整篇（`codec.reload`，“换成那边的”、冲突里选“现在的”）、撤销或别处的改动让锚着的小块不在了（按节点位置映射，映射后不是同一个节点就算不在）。丢掉之前有没应用的字时，状态行写一句“没应用的改动已丢弃”。
- 小块的浮层同样用 nb-ui `Popover` 的锚点用法（第二轮第 11 条：`AnchoredPopover` 会吃掉非输入元素的按下）。焦点：浮层打开时焦点进第一个输入框；Tab 在输入框、“应用”“换一个”“删掉”之间走；Esc 关上、焦点回编辑器且小块仍是节点选区；“应用”成功后同样回编辑器。用 nb-ui `Popover` 的锚点用法（见下节），焦点与 Esc 由原语管。

### 条件小块怎么画

- 正文里只画生效的那一支：各支原文用阅读视图的行内画法画出来（把 `EntryText.vue` 里画行内单元的部分抽成 `EntryInline`，阅读视图与节点视图共用），里面的 `V`、`Ref` 的值来自同一张值表；没有一支生效时画淡的占位，判断未知时写“未知”。
- “显示全部分支”（状态行左区的开关，只在有条件时出）：每个条件画成条件式加各支，没生效的变淡。开关翻转时以光标所在的段落为锚点保持它在视口里的位置，展开收起有过渡；开关记在标签状态里。
- 复制粘贴：小块的 `renderHTML`/`parseHTML` 带 `source`（dom 测试：富文本里复制一个条件小块粘到另一段，写出的源文里是同样的原文；粘进含 `<V` 的纯文字，写成 `\<V`），在富文本之内复制粘贴原样；从外面粘进含标签的纯文字时按现在的转义写成字面（`\<If`），写进 Spec 的“不支持”，提示作者在源文字里粘。

### 阅读视图里的来历浮层：`EntryText.vue`、`OriginList.vue` 与宿主

现在点值，来历（`OriginList`，输出 11）画在含这个值的整块后面；整篇编辑以后整个主文字是一块，开头的值来历画在几十段之外。改成贴着值弹浮层（开发者选乙）：

- 用 nb-ui `Popover` 的“锚在外部元素上”（`anchor` 是被点的值按钮）：打开时焦点进面板、Tab 在面板里走（面板传送到 body，由原语管焦点），Esc 关上并把焦点还给值按钮，点外面关上（焦点留在点的地方），在锚点上再按一次是关。不用 `AnchoredPopover`：它的合同是不抢焦点、不管 Esc 与点外面（第二轮第 1 条）。值按钮自己写 `aria-haspopup="dialog"`、`aria-expanded`；面板 `role="dialog"`，名字是“某某的来历”。
- 开着的是“哪一处”，不是“哪个地址”：同一个字段在正文里出现几次时只按下被点的那一个（第二轮第 2 条）。标签状态里的 `origin` 从地址改成“块 id 加这个标签在块源文里的起点”，地址照旧另记（来历按地址读）。
- 换到别的条目页再回来、刷新后：照 Spec 验收场景 2（“各有各的展开的来历”）还原，按记下的那一处重新锚上打开；那一处不在了（块被改了）就不开并清掉记录。
- 尺寸定死，不随内容抖（第二轮第 3 条）：宽度 440 像素，窄于它加两边 16 像素时占满视口宽度减 32 像素；高度上限是视口的六成，`OriginList` 在面板里自己滚动；读取中先给一个固定高度的占位（三行）；打开时选定上方或下方，之后内容变高（再显示更早的、重读）不换边。“再显示更早的”之后焦点留在那个按钮的位置（新的一行），读屏照 `OriginList` 现在的播报。
- “改这一笔”打开变更详情页时浮层关上。世界变了（别处的写入）时照现在的做法重读；那一处不在了就关上。

- `EntryText` 去掉“来历画在哪一块后面”（`originBlock`、块后的 `origin` 插槽），改成值按钮上锚一个浮层，插槽是浮层里的内容；`EntryText.md`、`OriginList.md`、Lab 场景（`EntryText` 的“展开着存款”）跟着改。

### 小块的样子与键盘：`web/components/EntryValueChip.vue`

- 一个组件两种样子（`variant`：阅读、编辑），阅读视图的值按钮与编辑器的节点视图共用，值、未知、不完整、改过、“计算中”、“没有算”、已删除、字段没了的写法只写一处（`@designer` 第 2、11 条）。阅读里是虚线下划线的文字按钮，指着时浮出浅底；编辑里是浅底小块；编辑里的条件用极淡底色，不用虚线。S3 先用一条 dom 测试确认节点视图里拿得到翻译端口（`useCanonText()`）。
- 长值：编辑里最多两行，超出截掉、末尾省略号，浮层看全文；先在 Lab 用真实长值量 `line-clamp` 对行高与基线的影响再定写法（审查第 10 条（c））。
- 键盘与读屏（审查第 10 条（a））：左右方向键越过小块时先选中它（节点选区），Enter 开浮层，Esc 关浮层、焦点回编辑器且小块仍选中；小块带 `aria-label`（种类、字段名、值、状态）。
- 动效：小块从“计算中”换成值、条件换支、显示全部分支的展开收起、模式切换两种输入框的交换、输入框下面原因的出现，时长与缓动取令牌；值的宽度变化不加动画（行内回流）。

## 不做与风险

- 不做：块级条件；跨行条件在富文本里的编辑（只能在源文字里改）；登记的标签的界面（t04）；在小块里直接改字段的值（改值在数据分页，t01 已定）；条件各支里的富文本（各支在浮层里按源文字改）；源文字模式的波浪线（要改编辑器插件的 `CodeInput` 合同，另记后续）；从外面粘进来的标签按写法读入。
- `@designer` 没采纳的：状态行吸顶；页头另标求值的章节（页头的“在看”已写位置，编辑时锁在那里）；有暂存时“保留暂存退回阅读”（现在的合同是有稿就直接进编辑，输出 45）。
- 风险：
  - 编解码器重写作者改过的块时写法变成规范写法（列表记号等）：只发生在作者改过的块；“改回一样就不算有改动”按整篇比，改过的块写法变了就算有改动（已知限制）。
  - 单行条件整段一个原子与内核按标签分原子的读法是否处处一致：由 S1 的性质测试与表驱动守（见上），对不上的情形退回各标签一个原子。
  - 整篇每次按键写出：S3 量过再定。
