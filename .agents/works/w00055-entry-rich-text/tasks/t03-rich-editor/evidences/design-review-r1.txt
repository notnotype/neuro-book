# w00055 t03 计划第 1 稿 设计审查报告
（审查者：Claude Sonnet 5.5，只读；实验文件在 /tmp/review-w00055-t03-design/exp/）

## 1. 值回来后“只改小块的属性”会让没动过的块被重写，甚至整篇写不出（阻断；合同违反；计划“值怎么到小块上”“小块的样子”末条）
现象：计划让值表回来后把值写进小块节点的属性（“值回来以后只改小块的属性，不重建段落”）。但编解码器按节点对象的身份认“没编辑过的块”（`packages/nb-markdown/src/language/codec/write.ts` 的 `itemsOf`/`originsOf`，来源登记在 `map.origins` 这张按节点对象查的表上），改小块属性的事务会让含它的段落、列表项成为新节点，整块失去来源。
实测（/tmp/review-w00055-t03-design/exp/attr.test.ts，用 entryLexing 加一个带额外属性 `value` 的行内原子，真实编解码器）：
- 不把 `value` 登记进 `derivedAttrs`：对每个块里的小块改一次 `value` 后 `codec.write` 返回失败“各级写法都读不回来”（读回校验 `compare.ts` 的 `sameAttrs` 对编辑器节点与读回节点的全部属性取并集比较，读回没有 `value`）。7 个样例 7 个都失败，也就是整篇写不出，输入框的 `update:modelValue` 没有东西可交。
- 登记进 `derivedAttrs` 后能写出，但含小块的块被规范化重写：`|名|值|\n|:--|--:|\n|甲   |<V…/>|` 变成 `| 名 | 值 |\n| :-- | --: |\n| 甲 | <V…/> |`；`行一 <V/>\\\n行二 &amp; &copy; \\* x` 变成 `…& © * x`（实体被解码，源文字语义都变了）；`- a <V/>\n\n\n\n- b` 变成 `- a <V/>\n- b`；`*  甲` 变成 `* 甲`；缩进四格的行变成 `&#x20;   缩进`。
为什么是问题：计划技术选型把“进编辑什么都没改时整篇逐字不变”当作选 Tiptap 加编解码器的理由，S1 的性质测试也只测“读后直接写回”。但真实路径是：进编辑 → 小块先画“计算中”→ 250 ms 后值回来 → 属性更新 → 下一次 `update:modelValue` 就带出被重写的文字。作者什么都没打，状态行就出现“有未提交的修改”，提交会把 Agent 或旧版写的块原样规范化掉，还可能解码实体。每个有小块的条目都会中，不是边角。同样，值属性更新进撤销历史（多一步没有可见差别的撤销）。
如何核实：`cd /tmp/review-w00055-t03-design/exp && bun test attr.test.ts`（node_modules 是指向 worktree 的软链）。
建议改法：值不放进文档节点的属性，放在节点外：一个 ProseMirror 插件状态或组件里的响应式表，小块的 NodeView 按“第几个小块”读它（或用 Decoration 把值画上去）；节点属性只放能从源文字推出的东西（源文、解析出的各项）。同时把“值回来后整篇逐字不变”写成 S1/S3 的测试（读入、等一次值回填、写出，与原文逐字比较，样本取表格、实体、多余空行、非标准列表记号）。若坚持放属性，必须登记 `derivedAttrs` 并接受上面的重写，那就要回答“作者没动却变脏”怎么办。

## 2. `searchEntries` 与已有的 `findEntries` 重复，计划“现在只有 lookup 与 tree”不成立（阻断；依赖的机制与事实；计划“找条目”、“要开发者定的”第 3 题、切片 S2）
现象：计划说“现在只有按名字完全匹配的 `lookup` 与按层读的 `tree`”，要新加 `searchEntries({query, position, limit})`，放进 `service/views.ts` 与 `shared/contracts.ts` 并升远程合同版本；第 3 题还说不加就“只能从设定树里已经展开过的条目里选（新建条目对话框现在就是这样）”。
事实：世界服务早有 `findEntries`（`packages/nb-canon/src/service/service.ts:1227-1260`；合同 `packages/neuro-book/src/plugins/canon/shared/contracts.ts:127-135`；后端 `backend/remote.ts:113`；Spec 在主工作区 `docs/specs/canon/project.md` 方法表 `findEntries`）：名字或别名不分大小写地包含搜索词，可选种类与类型、读取位置、游标与条数；排序全等、前缀、包含，同档按树序；不列删除的；带视图令牌一律拒。`EntryPicker` 已用它（`EntryPicker.md`；`EntryPageHost.vue:514-520` 的 `finderFor` 传 `position`、`limit: 20`；`entry-picker.ts` 的 `useEntryFind` 做去抖与丢晚到结果；Agent 工具 `agent-tools.ts:207、321` 也用）。所以新建条目对话框并不是“只能从展开过的里选”，第 3 题的“不加的话”那一支的描述是错的，开发者按这个描述答，会拍在一个错的前提上。
为什么是问题：重复一个读取意味着第二套排序、位置与视图令牌规则、第二个远程合同版本、两份 Spec；`@` 的候选与 `EntryPicker` 同一件事却排得不一样。保密方面：`findEntries` 对视图令牌一律拒（防剧透视图不许枚举名字），作者界面没有令牌，所以富文本里的 `@` 直接可用；新写的 `searchEntries` 若要“按视图令牌处理”还得自己再设计一遍，计划只字未提。
计划里新增的两个要求 `findEntries` 确实没有：`query` 为空时给“最近改过的”（它的搜索词空时行为需要查实现，计划未提），结果带“是否已删除”（它不列删除的）。前者可用于 `@` 刚打下去还没输字的候选，但应当用 `tree` 或扩展 `findEntries` 的空搜索词语义，不要另起方法；后者对 `@` 无用（已删除的不该被选），对小块的“已删除”标记来自值表的 `ref.deleted`、不需要搜索。
如何核实：`grep -rn findEntries packages/neuro-book/src packages/nb-canon/src`；读 `EntryPageHost.vue:514-520`。
建议改法：删掉 S2 与第 3 题；富文本的 `entries` 属性直接是 `finderFor(kinds)` 同形的函数（复用 `useEntryFind`）；若“空搜索词给最近改过的”确实要，作为 `findEntries` 的小扩展单列，并在 Spec 的 `findEntries` 行补一句。顺带：`findEntries` 在 Spec 里仍标 `（planned）`，但代码与调用方都在，晋升状态与计划的 Spec 改动表一起核一下。

## 3. 读入时“整个 If 一个原子节点”的机制不存在：编解码器读的是自己的词法单元，没有 `entryIf`（重要；依赖的机制；计划“编辑器一侧的条目语法”）
现象：计划写“`entryIf`：整个 `<If …>…</If>` 一个行内原子……读时用 `parseEntryText` 的 `entryIf` 单元（它已经配好对、给出各支）”。但 `entryIf` 单元只出自 nb-canon 自己的 `parseEntryText`（`packages/nb-canon/src/grammar/parse.ts:229-254`，`groupConditions` 在分完词后就地改 `lexAtoms(lexing, source)` 的结果）。章节编辑器的编解码器读入走自己的 `language.lexer()`（`packages/nb-markdown/src/language/codec/read.ts:readBody`），语法模块的读法表只有 `readInline: {entryTag: …}`，按单个词法单元调用（`ReadContext.inline(tokens)` 是 `tokens.flatMap(readToken)`），读法拿不到兄弟单元，也没有“读完一层行内单元后分组”的钩子。`MarkdownSyntax.resolve`（`ReadResolver`）能在整篇读完后改 JSON，但那时各支的内容已经读成文字与标记节点，要还原成“各支存原文”的字符串得再写一遍。
为什么是问题：计划把整个第二层设计（原子、浮层按源文字改、`cross-block` 不会被作者拆坏）建在这个单元上，却没说它从哪来。可选的做法各有代价：（a）给 nb-markdown 加一个通用的“行内单元分组”钩子，要改共享包与方言 Spec（`workspace/markdown-dialect.md`），也要过它自己的语料与性质测试；（b）在 `marked` 里加一个 `entryIf` 行内分词规则，在遮罩后的文字上自己配对，但那样绕过 `groupConditions` 里“被强调、链接切开的分支落在别的层、配不上”的判断，同一个文字内核判 `cross-block`、编辑器读成一个原子（上面实测 `<If test=\"panel.a\">**甲<Else />乙**</If>` 内核报 `cross-block`）；（c）用 `resolve` 再写一遍。三种都要在计划里选定并列进切片与 Spec/文档改动表，S1 现在只写“四种节点、属性的写回与检查”。
另一个连带问题：读入的原子里存的“原文”不是源文字的切片。实测（/tmp/review-w00055-t03-design/exp/ifraw.test.ts）表格单元格里的 `<If test="panel.a">甲 \| 乙<Else />丙</If>` 的 `entryIf.raw` 是 `甲 | 乙`（`\|` 已被 marked 还原）；列表项里续行的缩进也被去掉（`甲\n续行`）。所以写回时原子的写法必须按所在位置重新转义（表格单元格里非标签部分的 `|`、换行写成 `<br>` 或拒绝；列表与引用里的缩进由块写法补），而 t02 只有标签自己是原子，标签外的字走普通文字的转义，没有这个问题。新模型把一大段正文挪进原子里，等于把 nb-markdown 对这些位置的转义与读回校验责任挪进了 canon 的原子写法，S1 的性质测试没有覆盖“If 在表格单元格里、含 `|`、含换行”。
如何核实：读 `read.ts:readBlock` 与 `syntax/types.ts` 的 `ReadContext`；运行 `exp/ifraw.test.ts`。
建议改法：S1 之前先做一个小探针选定（a）或（c），写进计划；写法的转义用 `entryAtomSpans` 保护标签、对其余部分按位置转义；把“表格单元格里的 If、含 `|` 的分支、列表项里多行的分支、标题里的 If”加进 S1 的表驱动与性质测试（t02 的随机文法 `word` 里没有 `|`，加上）。

## 4. 浮层里改各支文字没有校验与失败出口：一次坏的按键能让整篇再也写不出（阻断；合同；计划“关键设计”的 `entryIf`、“属性值的检查”）
现象：计划只对 `test`、`expr`、地址做“写成标签后用 `lexTags` 读回、与写的不同就不写进节点”的检查。各支的内容（任意行内 Markdown 加标签）在浮层的文本框里直接改，t01 的 spike 就是每次按键 `setNodeMarkup`（`EntryRichDraft.vue:355-356` 的 `updateBranch`），也就是每个字符一个事务、一次整篇写出。
为什么是问题：内核对 `If` 的拒收条件全落在各支的内容上：`**甲<Else />乙**` 报 `cross-block`（强调切开分支，实测），支里写了空行（`a <If …>甲\n\n乙</If>` 实测 `cross-block` 加 `tag-malformed`），支里写 `<If` 报“不能套着”，`[链](<V … />)` 报 `tag-not-live`。作者在文本框里打 `**` 的中途就是这些状态。节点属性写成这样以后，编解码器的读回校验读到的是别的结构（标签散成几个小块），与编辑器里的节点对不上，`codec.write` 返回失败（实测同类：属性对不上时是“各级写法都读不回来”），整篇从这一次按键起写不出。计划对“写失败时 `update:modelValue` 怎么办、给不给文字、状态行写什么”没有任何规定；若停止交出，暂存里留着旧文字而界面上是新的，作者关页面就丢。重点 1 问“这种节点模型能不能保证写回的文字过检查”：属性值能，各支内容不能，因为各支内容恰恰是原子里最自由的部分。
如何核实：运行 /tmp/review-w00055-t03-design/exp/ifraw.test.ts 看上面几个文字的 `cross-block` 等；读 spike 的 `updateBranch`。
建议改法：浮层里的文字先留在浮层自己的状态里，只在 `checkEntryText(parseEntryText(拼出的 If 原文))` 通过且拼出的是恰好一个 `entryIf` 单元时才 `setNodeMarkup`，不通过就在浮层里写原因（与 `data-mode-problem` 同一种位置）并保留上一个好的值；失焦或关浮层时仍不通过就还原或留着浮层不关。再规定整篇写失败的出口：不交出、状态行写“这一处写不出”并给撤销，且在 S3 的测试里造一个写失败的文档验证 `update:modelValue` 与暂存的行为。撤销的粒度也要写：浮层里打的字合成一次撤销步，而不是每键一步。

## 5. 值表“按先后配对”改了 Spec 写明的做法，又丢掉了现有的校验；“源文相同才换值”在慢请求加持续打字下会长期不更新（重要；与已定设计不一致；计划“值怎么到小块上”）
现象与依据：
（a）rendering 输出 7 写“按标签名与起点对上每一项；对不上的块整块按出错显示，不按位置猜”。阅读视图的 `layoutBlock`（`components/entry-text.ts:66-85`）正是这样做的：对源文逐个活标签按 `名字@起点` 取值，多一项少一项都报 `mismatch`。计划另起“写出的源文里第 k 个该有项的活标签对应文档里第 k 个”，只数个数，不核每一项的标签名与起点。前后端不同版、或 `entryIf` 里面的标签数错一个，k 之后的所有小块就拿到别人的值，而且没有任何报错（值表项有名字，是现成的校验）。
（b）改法：先对请求时的源文 S0 用 `parseEntryText` 按 `名字@起点` 取值（与 `layoutBlock` 同一段逻辑，抽出来共用，不要抄），得到“S0 的第 k 个活标签 → 值”；再按先后对文档里的小块，并对每个 k 核对小块自己的原文等于 S0 第 k 个标签的原文，不等就整批不换。`entryIf` 里面的标签用对分支原文单独 `parseEntryText` 的结果数，但分支原文脱离上下文单独分析与整篇里的落点不一定相同（引用式链接的定义在别处、表格单元格里被还原了 `\|`），要么对 `entryIf` 用整篇 S0 里该 `If` 区间内的标签，要么在 S1 加性质测试证明“单独分析等于整篇里的子集”。
（c）“请求时发的源文必须等于此刻写出的源文才换”：`text-preview.ts` 的节奏是停顿 250 ms 才发、响应要 `renderSource` 一遍（计划自己说结果是源文的十几到四十倍，长文按 5 万字封顶）。作者每 300 ms 打一个字、响应要 400 ms 时，每个响应回来时源文都已经变了，值永远不换；而这正是作者边打字边看“魔力”值的场景。按小块各自的原文核对（上面 b 的逐项核对）而不是整篇源文相等，作者在别处打的字就不会让这批值作废。
（d）进编辑那一刻阅读视图手里已有这篇存下的文字的值表（宿主的 `blocks` 带 `values`，来自 `render`）；草稿文字与存下的文字相同时（刚点“编辑”）直接用它给小块定初值，不必先画一遍“计算中”再等 250 ms：计划的“计算中弱样子”会让进编辑后整页的值同时换宽度、行重排一次。

## 6. “与 `PlainSourceInput` 同一合同”在富文本里有三处没法照字面实现（重要；合同；计划“富文本输入框”、“编辑视图”的切换模式一条）
（a）`cursorOffset()` 返回“光标前写出的源文长度”，以及切换时“光标按 `cursorOffset` 放到对应位置”：编解码器只给整篇写出（`codec.write(doc, map)`），不给节点到偏移的对照（计划自己在“值怎么到小块上”里也说了这一点）。没改过的块写原文、改过的块重写，光标落在加粗、链接里时前缀的写法还要补出尚未闭合的符号，所以“截到光标处的文档写一遍取长度”既不等于整篇写出文字里的偏移，也会把块重写成规范写法。反方向（源文字切回富文本，要把偏移变成文档位置）计划只有 `focus(caret?: "start" | "end")`，没有这条路。要么降级成“落在同一块（顶层块序号）里，块内按纯文字偏移”，写进组件文档与 Spec 输出 48；要么列出为此给 nb-markdown 加的对照，并列进改动表。
（b）受控值从外面变：条目页有“换成那边的”“用这里的”、冲突里选“现在的”、重新连上后读到别处的暂存，这些都会让 `modelValue` 在作者没打字时变成另一篇。`PlainSourceInput` 靠文本框的受控值天然处理；Tiptap 要自己做：与最近交出的文字比较，不同才用 `codec.reload(tr, source)` 换（它只换不同的那一段、保撤销历史），相同的回声不动文档。计划没有这一条，S3 的 dom 测试也没有；漏了会表现为选了“换成那边的”界面毫无变化，而暂存已经换了。
（c）写出失败的出口（见第 4 条）、只读（提交在途时 `readonly`、条目已删除时稿只读）要同时关掉 `{`、`@` 触发与浮层里的改动，不止 contenteditable。`insert(text)` 在 `readonly` 时返回假的约定要保留。此外编解码器要求写出被接受后调用 `record`／`accept(tr)`（`codec/write.ts:623-663`、`WriteResult.accept`）登记新来源，计划没写谁调用、什么时候调用；不调用的话撤销回到打开时的文字无法写回原来的字节。
建议：在 S3 之前先写一份“富文本输入框与 `PlainSourceInput` 逐项对照表”（每个暴露的方法、每个事件，以及外部改 `modelValue`、只读、写失败各一行），放进 `EntryRichInput.md` 草稿，再审一次。

## 7. 模式与各种状态的组合没有定义：存下的稿读不出、稿在源文字里写坏、已删除条目、只读稿、模式记在哪（重要；遗漏；计划“编辑视图”第 2 条）
计划写“进编辑默认富文本。存下的文字富文本读不出（内核说这一版写得不对、`frozen`）时落在源文字”。两处问题：
（a）`frozen` 在现有代码里不是这个意思：`text-tab.ts:212` `frozen = state.draft !== null && state.read === null`，指“开始编辑时读到的块已经不在了”，编辑区只读、只能放弃（Spec 输出 46）。此时落在“源文字”是只读的源文字吗？还是富文本只读？计划没说，而 `EntryTextEditor.md` 规定 `frozen` 时不出“插入”与模式控件。
（b）真正会出现的是：作者在源文字里写了暂时过不了检查的文字，输入停顿后暂存了（暂存按任何文字存，Spec 输出 45），刷新后“直接进编辑并带着暂存”。默认富文本读它，`checkEntryText` 不过。计划只写了“从源文字切回富文本前查，有问题不切”，没写“进编辑时同样查、不过就落在源文字”，也没写落下来以后分段控件上“写原因”是什么字样、什么时候能重试。
（c）模式存在哪没写：条目页的标签状态（`entry-page.ts`，`preview` 就记在那里）、会话、还是每次默认？Spec 输出 45 要求刷新后直接回到编辑；模式若不记，作者在源文字里改到一半刷新就被扔回富文本，（b）的情形又来一次。建议记在标签状态里，并规定“读不出时的自动落点不覆盖作者选的模式”。
（d）条目已删除时稿列在“已删除”页下面（`EntryPageHost.vue` 的 `#deleted` 插槽，第二个 `EntryTextEditor`）：只读、能复制。富文本输入框是否也挂在这里、用 `readonly` 渲染小块（没有值表，因为 `previewing` 对已删除条目不读）？计划没提；两个 `EntryTextEditor` 的实例都要接模式。
（e）整篇 5 万字以上不请求值（计划已写），超过 `RENDER_SOURCE_MAX` 时 S3“小块显示显示名”：`V of` 的显示名是“字段的显示名”，需要 `fields`，别的条目的字段与计算式显示什么？写成“式子原文”要与“计算中”的样子区分，否则作者分不出“没算”与“出错”。

## 8. `If` 整体做原子以后，“正文里画生效的一支”“显示全部分支”“复制粘贴”没有机制（重要；遗漏；计划“关键设计”、“小块的样子”、“编辑视图”的“显示全部分支”）
（a）画法：各支内容是“行内的 Markdown 加标签”的字符串，存在原子的属性里。要在正文里“只画生效的一支”，节点视图必须自己把这段字符串读成行内内容（强调、链接、行内代码、`<V>` 的值、`<Ref>` 的名字、`<br>`），并给里面的 `V` 配值（上一条第 5 条（b）的单独分析问题）。计划没说用什么渲染：t01 的 spike 只替换 `<V` 的文字（`branchText`），不是 Markdown。可选：用 nb-markdown 的 `display/` 里的行内显示（要看它能不能只画行内、能不能让标签小块嵌进去）、或把各支读成真正的子文档。无论哪种，这是一块新的渲染代码，需要自己的 Lab 场景与 dom 测试，计划的切片 S3 只写“组件、浮层、`{`、`@`”。
（b）“显示全部分支”：开关一翻，所有 `If` 原子的高度与宽度同时变，整页回流；计划对模式切换写了“页面的滚动位置不变”，对这个开关没有。设计语言要求状态变化不推动周围内容、有过渡，需要写明锚点（保持光标或视口顶部的块不动）与过渡。开关的状态记在哪里（标签状态？每次进编辑重置？）与失效情形（没有 `If` 时是否显示开关）也没写。
（c）复制粘贴与拖动：节点的 `renderHTML`/`parseHTML` 要把 `branches` 与各支文字带进剪贴板（t01 spike 若没带，生产不能照搬）。粘进别处没问题：原子在一个段落里，不会跨段。但粘进标题、表格单元格、链接文字、代码标记里时，原文里的换行会破坏那个位置的写法：标题与表格单元格不能有换行。编解码器的写回会抛 `Unrepresentable` 或读回对不上（第 4 条的整篇写失败）。要有一条规则：原子带换行的各支只允许在能放换行的块里（`ProseMirror` 的 `filterTransaction` 或节点的 `allowedIn`），或写出时统一写成 `<br>`（与“表格单元格的 `<br>`”读回规则一致，需要查 `isBreakOnlyHtml` 与读法）。
（d）从外部把一段含 `<If>…</If>` 的文字粘进富文本（作者从源文字模式复制、或从聊天里复制），按现在的转义规则会被写成 `\<If …>` 的字面文字（t02 的 `atomEscape`），没有任何提示：作者以为粘进了条件。至少给出“粘贴的文字里含活标签时问是否按写法读入”或明确写进 Spec 输出 48 的不支持清单。
（e）“跨段粘贴”：只要原子不跨段，选区跨段删除也不会留下半个 `If`，这是新模型的好处；但选区从 `If` 原子里的“文字”开始是不可能的（原子内没有光标），所以“在条件中间回车”变成“光标在条件前后回车”，写进验收更好。
建议：把（a）与（c）作为 S1/S3 的明确子项并配测试：“含强调、链接、行内代码、`<V>`、`<Ref>`、换行的各支在正文里画成什么”“原子含换行时粘进标题 / 表格单元格被拒还是改写”。
