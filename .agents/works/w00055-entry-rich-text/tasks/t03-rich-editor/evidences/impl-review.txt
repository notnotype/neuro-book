【1】重要 / 正确性
位置：text/EntryText.vue 的 collapsed（约 227 行）、valueNode 的 onClick（163 行）与 aria-expanded（158 行）；宿主 entry-page/EntryPageHost.vue:301 的 toggleValue。
现象：点到条目页外面（标签条、设定树）时浮层只收起，`collapsed=true`，但宿主记下的 `open` 还是那一处。这时作者再点同一个值：onClick 照常发 `value(place)`，宿主的 toggleValue 看到 `state.origin === place` 把它置空，结果什么也没出现（浮层本来就没开）；要点第二下才打开。同时 `aria-expanded` 与 `canon-value-open` 高亮按 `props.open === place` 算，收起期间仍是“展开”，读屏和样式都与实际不符。
为什么是问题：Spec 输出 11 写“点到页外只收起、记着的那一处留着”，没写要点两下；按钮状态与可见状态不一致。
核实：dom 测试里 mount EntryText 带 open=place，向页外元素发 pointerdown 等浮层消失，再点该值按钮，断言 emitted("value")，再看宿主收到后 open 变成 undefined、浮层仍不在。现有用例（EntryText.dom.test.ts:89 起）只测了“重新挂上才重开”，没点同一个值。
建议改法：值按钮的状态用 `open && !collapsed` 算 aria-expanded 与高亮；onClick 里 `if (collapsed.value && props.open === place) { collapsed.value = false; return; }`（把收起的重新展开，不发 value）。补一条上面的 dom 用例，变异：删掉这行判断应当失败。

【3】重要 / 正确性
位置：text/EntryRichInput.vue 的 offsetBefore（650 行起，尤其 `$pos.parentOffset === 0` 那个分支）、cursorOffset（668）、positionAt（678）。
现象（已在真实编解码器上跑过，脚本思路：用 entrySyntax 加 coreSyntax 的语言读一篇源文，复刻 offsetBefore 对每个位置求值；没用编辑器与 DOM）：
 a. 不单调。`parentOffset === 0` 时无论嵌多深都算“最外层块的起点”。列表、引用里第二项起的段首（parentOffset 为 0）返回整个列表的起点，比它前面一项末尾的值小。源文 "- 甲甲\n- 乙乙\n- 丙丙\n- 丁丁"：位置 8、9、14、15 返回 0，而位置 5 到 7 返回 4，位置 11 到 13 返回 9。列表是首块时 `$pos.index(0) === 0` 直接返回 0，光标在第 N 项开头（敲完 Enter 的常见位置）切到源文字就落在全文开头。
 b. 二分靠单调：positionAt 把这些 0 当“<= 目标”，把 low 推过头。实测 "前文\n\n- 甲甲\n- 乙乙\n- 丙丙\n- 丁丁\n\n后文"，源文偏移 16（丙丙）切回富文本落在位置 19（丁丁的段首），再读回偏移是 4；列表为首块、偏移 17（丁丁）落在位置 21，读回 0。
 c. 表格里 `doc.cut` 出来的半截表写不出：位置 17 到 19、29 到 31 返回 null（实测）。cursorOffset 返回 null 时 EntryTextEditor.switchMode 退成不放光标；但 positionAt 只要二分里碰到一个 null 就整个返回 null，`commands.focus(null)` 等于保留旧选区，源文字里光标在表格或表格之后的人切回富文本，光标留在旧位置，没有任何提示。
为什么是问题：Spec 输出 48“切换模式时光标落在同一段的大致位置”；列表与表格在条目主文字里是常见写法；现有两条 dom 用例（EntryRichInput.dom.test.ts:96、105）只含段落与小块。
建议改法：嵌套的段首不要走“最外层块起点”的特例，只在 `$pos.depth === 1` 时用（或统一用 `doc.cut(0,pos)` 写出后剥掉末尾的空列表记号）；二分前把写不出的位置当作“沿用上一个能写出的值”而不是整体放弃（或改成按块边界二分，再在块内按纯文字偏移走）。补用例：首块与非首块的列表、引用、表格各来回一次（offset -> pos -> offset 差不超过同一块）。变异：把特例改成不分深度应当被这些用例抓住。
开销：positionAt 是 1 次整篇写出加约 log2(文档大小) 次前缀写出；5 万字文档大小约 5 万，约 16 次，按 README 的 7.5 毫秒中位数估计一百多毫秒，只在切换时发生，可接受（推算，未在浏览器量）。

【4】重要 / 正确性
位置：text/EntryRichInput.vue 的 focusChip（268）与 onPopoverOpen（280）。
现象：focusChip(pos) 在 `doc.nodeAt(pos)` 是小块时把它选成节点选区。“新插入”（`{` 选“条件”“计算”，或“插入”菜单）的浮层，at.from 是插入点而不是某个小块；若插入点紧挨着后面有一个已有小块（例如在两个小块之间、或段首小块前面打 `{`），按 Esc 取消时 nodeAt(插入点) 就是那个邻居，它被选中，接着打的字把它替换掉。应用成功那条路没问题（插入点就是新小块）。
为什么是问题：Esc 取消一次插入不该动别的小块；替换后只能靠撤销。
核实：dom 用例：文档 `甲<V of="…"/>`，光标放在“甲”与小块之间，按 `{` 选“计算”，浮层里按 Esc，断言选区不是 NodeSelection（现在是）。
建议改法：focusChip 只在 `current.node !== null`（改的是已有小块）时选节点；新插入的 Esc 只 `editor.view.focus()` 回到原光标。onPopoverOpen 里按 `current.node === null` 分开调用。

【7】建议 / 正确性
位置：text/EntryRichInput.vue:482 到 489（menuKey 的 Escape、空格分支），closeMenu（约 453 行）。
现象：a. `{` 后立刻按空格会 closeMenu(true) 把 `{` 补回正文，但空格被 preventDefault 吞掉，作者想写的“{ ”变成“{”。想写文字里的花括号加空格的人每次要多打一个空格。b. Escape 与空格分支没有判 `event.isComposing`（Enter 分支有）。在 Firefox、Safari 里输入法组字时 keydown 的 key 可能就是 " " 或 "Escape"，组字被打断并关掉列表；Chrome 里组字时 key 是 "Process"，不受影响，桌面版（Chromium）下基本不触发，所以只是建议。
核实：a. dom 用例：按 `{`、再在搜索框按空格，断言正文是 "{ "（现状是 "{"）。现有“{ 后按 Esc 补回一个 {”（EntryRichInput.dom.test.ts:409）只覆盖 Esc。
建议改法：补回时按触发键加空格：空格分支调用 closeMenu 时带上要补的文字（`closeMenu(true, " ")`）；两个分支都加 `!event.isComposing`。

【8】建议 / Spec 偏离（页面滚动）
位置：text/EntryRichInput.vue:700、703（defineExpose.focus 里的 `editor?.commands.focus(pos)`、`focus(caret ?? null)`）。
现象：Tiptap 的 `commands.focus` 默认 `scrollIntoView: true`（node_modules/@tiptap/core/src/commands/focus.ts：在下一帧调 `editor.commands.scrollIntoView()`）。Spec 输出 48 写“切换模式时光标落在同一段的大致位置，页面不滚动”。从源文字切到富文本时（switchMode 后新输入框挂上，flushFocus 调 focus(偏移)），页面会滚到光标处；两种输入框排版高度不同，光标在视口外时页面会跳。Monaco 一侧的 placeCaret 不滚动，两边不一致。同一个入口也用在“点编辑后焦点进输入框”，那里滚动无妨。
核实：e2e：长条目里把页面滚到离光标很远处，点分段控件切模式，断言 scrollTop 不变。
建议改法：带偏移或来自切换的 focus 传 `{scrollIntoView: false}`（`commands.focus(pos, {scrollIntoView: false})`）。

【9】建议 / 界面与无障碍
位置：text/EntryRichInput.vue:237 到 249（openNew 的 `anchor: view.dom`）与 260（closeChip 的 `aria-expanded`）。
现象：a. 新插入的浮层把 view.dom 当锚点，nb-ui Popover 的 onInteractOutside 会把落在锚点里的按下与焦点移动都拦掉（Popover.vue 里 `anchor.contains(target)` 就 preventDefault），所以浮层开着时点编辑区别处不会收起（已有小块的浮层锚在小块上，点编辑区别处会收起，两种行为不一致）；光标换了位置而浮层还在，应用时仍插在旧位置。b. closeChip 对所有浮层执行 `current.anchor.setAttribute("aria-expanded","false")`，新插入的锚点是编辑区根节点（contenteditable 的 div），于是编辑区被写上 aria-expanded=false，读屏会读成“已折叠”。已有小块锚是无 role 的 span，aria-haspopup、aria-expanded 在无 role 的 span 上不成立，读屏多半忽略（建议给小块壳 role="button"）。
核实：a. dom 用例：`{` 选“计算”后对编辑区别处发 pointerdown，断言浮层关上。b. 看 `[contenteditable]` 的属性。
建议改法：新插入的用 `anchor: null` 加 `reference`（虚拟矩形）；Popover 只在 `anchor` 给了才拦，不给时点编辑区会收起，Esc 后的焦点回编辑区本来就由 focusChip 做。aria-expanded 只对 node 不为空的（已有小块）写。

【10】建议 / 界面
位置：text/EntryRichInput.vue 模板里 Popover 的 `<form v-if="editing !== null">`（约 797 行）与 `:anchor="editing?.anchor ?? null"`；text/EntryText.vue 的 `<section v-if="anchor !== null && openAddress() !== null">`；entry-chip-views.ts 的 paintChip（约 109 行）。
现象（从代码推断，未在浏览器看）：

【14】建议 / 性能（推算，未量）
位置：text/EntryRichInput.vue 的 writeOut（约 128 行）与 `created.on("update")`。
现象：每次文档变化整篇 `codec.write`，写出被接受后再发一个程序事务回填写法（`quietly(accept)`）。README 量过 5 万字、50 段（happy-dom，负载 13）：中位 7.5 毫秒、九成 16.7 毫秒，已经贴着一帧。Spec 输出 47 的上限是约 1 MiB（条目页能读出的最大主文字），富文本没有对 5 万字以上的文字退化：按线性推算 30 万字每键约 45 毫秒、1 MiB 约 150 毫秒，在浏览器里还要加上浏览器自己的布局。值表在超过 5 万字时已经不请求，但写出照旧每键一次。
建议：要么在计划“不做与风险”里写明“超过 N 字时富文本不保证流畅”，要么把 writeOut 改成停顿时交出（plan S3 写了这个后备）并在超过阈值（例如 10 万字）时自动落在源文字、写原因。需要的话由主 Agent 在真实浏览器里造 30 万字的条目量一次按键耗时。

== 未发现问题的方面（仔细检查后没有发现）==
 - EntryText 的 `renderingBlock`：它不是模块变量，是 `<script setup>` 里的闭包变量，每个组件实例一份；Block 的渲染函数同步执行、在 finally 里复位，位置键取块 id 加标签起点没有串块的路径。
 - 宿主 richContext 的各字段引用：fields、marks、baseline 各是独立的 computed，每次按键重算的只有外层对象与 computing 这个原始值，EntryRichInput 里 `watch([...])` 的触发条件是五个 prop 真的变了才触发，不会每键整篇重对值；richValues 兜底只在第一次请求回来之前新建对象，且 EntryRichInput 对 null 保留上一份。
 - applyChip 里先关浮层再发事务、followChip 把“锚着的小块换了”当作丢弃的顺序，与注释一致；id 守卫能挡住等待期间被换掉的那一个（缺的是测试，见第 12 条）。
 - Popover 的 Esc 顺序：form 上的 keydown（markEscape）在冒泡阶段先于 reka 挂在 window 上的 Esc 监听，`closedByEscape` 的读写顺序正确；Button 的默认 type 是 "button"，浮层里“换一个”“删掉”不会提交表单。
 - 来历浮层与值按钮：锚点按钮上的按下被 Popover 拦掉（onInteractOutside），点另一个值是先 close 再 value，能换过去；`pressed` 在 document 捕获阶段记，页内页外的分辨在“按下后关闭”这条主路径上正确（边缘：键盘关闭沿用上一次指针位置，只影响“清掉还是收起”，两种都可接受）。
 - 监听与计时器的释放：document 上两个 pointerdown 监听（EntryRichInput 的 menuOutside、EntryText 的 press）都在 beforeUnmount 移除；源文字检查的计时器在卸载与模式变化时清；编辑器在 beforeUnmount 销毁并置空，之后 focusChip 的定时器有判空。
 - 去掉预览：grep 预览、interactive、data-source-line、lineOf、text-preview、wide 在 canon 下的非测试代码里没有残留（页头自己的 `wide` 属性与 reads-service 里的透传是别的页面在用，EntryPage 已不传）；文案键 textEdit.preview* 在两份 locale 里都已删除；代码里 `text("…")` 的字面键在 zh-CN 与 en-US 里都能查到。
