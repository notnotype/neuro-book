# 条目主文字的富文本编辑器

## 目标

条目的主文字改用标签写法，内核与编辑器共用一个解析器（marked），作者用富文本编辑器写条目。先出演示稿与 spike 给开发者体验，需求对齐、稳定以后再实施（开发者 2026-11-26：“不用那么急着快速做。多做点演示稿，spike 让我体验后，等需求对齐了稳定了你再开始实施”）。

从 [w00039](../w00039-novel-writing-plugins/README.md) 分出来。那边的 [t38](../w00039-novel-writing-plugins/tasks/t38-kernel-shared-parser/README.md)（内核改用与章节相同的解析器）搁置的条件是“用过整篇编辑器与人物设定组”，现在已经满足（t39、t40、t41、t42 都已合入）。t38 列的难点、t39 的设计审查与 11-24 的讨论都是本 Work 的起点：

- [t38 的来由与已知的难点](../w00039-novel-writing-plugins/tasks/t38-kernel-shared-parser/README.md#来由与已知的难点)：定位、写入合同、保密关卡、带值回写、读法变化的清单。
- [t39 的设计审查](../w00039-novel-writing-plugins/tasks/t39-entry-text-editor/README.md)：富文本建在章节的解析器上、内核却用另一套解析器把关，要补的东西是原计划的两到三倍。
- [条目主文字的方向（2026-11-24 的讨论）](../w00039-novel-writing-plugins/research/2026-11-24-entry-text-direction.md)：去掉 `{}` 改用标签、标签登记表、沙箱块等提议与主会话的看法。
- t28 的 spike（分支 `spike/w00039-t28-entry-editor`）：富文本编辑条目的一次性演示，只作 Tiptap 接法的参考。

## 决定

| 日期 | 决定 |
|---|---|
| 2026-11-23 | （w00039）解析器只留一个：扩展章节编辑器现有的解析器（marked），内核也改用它 |
| 2026-11-26 | 开发者：取值与条件**换成标签**（例如 `<V of="panel.魔力" />`），不再用 `{}`。代价开发者知悉：内核先换、编辑器跟在后面；渲染、白名单、带值回写、样本与 Agent 工具说明返工；另写 ADR 取代 [ADR 0038](../../../docs/adr/0038-world-engine-entry-text-is-whitelisted-mdx.md) 的决策 1 与 3；已有的 `{}` 要迁移 |
| 2026-11-26 | 开发者：**富文本为主，保留源文字**。点“编辑”默认进富文本，可以切到源文字（t39、t40 的 Monaco 加高亮）；分屏预览去掉 |
| 2026-11-26 | 开发者：新开本 Work，不急着做；先多出演示稿与 spike 给开发者体验，需求对齐、稳定以后再写实施计划 |
| 2026-11-26 | 开发者在 [t01 第 1 轮评审板](tasks/t01-demos/artifacts/review/index.html)：条件**写成 `test` 表达式**（`<If test="panel.魔力 >= 1000">…<Else />…</If>`，另有 `<ElseIf test>`；沿用现在的表达式白名单，边界由引号定，简单比较由编辑器的小表单写出）；给 Agent 的值**写在标签中间、用 JSON**（`<V of="panel.魔力">1200</V>`，与现在带值写法里的值相同）。开发者另问 JSON 的好处坏处，主会话在会话里答 |
| 2026-11-26 | 开发者另提一个方向：给 Agent 的主文字不带值、原文就是标签，值只用工具改；要主会话比较优缺点并做一个简单的评测。主会话比较了三种（甲：值写进标签可以就地改；乙：不带值；丙：带值只给看），推荐**现在就跑评测**，开发者同意。评测用现在的内核与 `{}` 写法当替身、真实的 canon 工具（[t01 的评测设计](tasks/t01-demos/eval.md)） |
| 2026-11-26 | 开发者同意：条目文字的表达力（插件登记的标签、沙箱里的 JSX、可交互的状态栏）在 t01 里**做演示、不实施**，实施另开 Work |
| 2026-11-26 | 开发者看过 [t01 第 2 轮评审板](tasks/t01-demos/artifacts/review/index.html) 与评测结果（[记录](tasks/t01-demos/evidences/agent-value-eval.txt)）后，在会话里定：Agent 读主文字时**带值、只给看**（丙：`<V of="panel.魔力">1200</V>`，值不能在文字里改，改值用工具；交回时程序去掉值），没按主会话推荐的“不带值”。第 1 轮定的“值写在标签中间、用 JSON”照用。spike 试用的反馈：值的小块与周围文字留空隙、光标不要落在值的末位（看起来像会打进值里）；问“加一支”是什么、条件能不能经 `{` 插入 |
| 2026-11-26 | 开发者问条件能不能更强、能不能直接写表达式。主会话说明条件里本来就能写比较、并且或者不是、跨条目与分档，写不了的是算术、函数与条件以外的计算结果；建议加“计算值” `<V expr="…" />`（富文本里是带“＝”的小块，给 Agent 时带值只给看），白名单补四则运算与取整、向下取整、向上取整、最大、最小、绝对值、百分比几个确定的函数，仍然只解释、不执行代码；循环、状态栏、任意代码走沙箱里的 `<jsx>`。开发者“同意”（三档里的第 2 档，不含文字拼接与格式化） |
| 2026-11-26 | 开发者看过表达力演示与补上的“模型能用的标签”后，在会话里同意主会话的提议（“可以”），取代 [t01 第 3 轮](tasks/t01-demos/artifacts/review/index.html)的题：**插件的展示组件都登记成标签**（作者在主文字里摆、模型读得到），设定组的分页改成作者能改的默认模板，设置页、对话框这类不属于条目内容的界面仍用 Vue，**这些进本 Work**；标签登记给四样：作者看到的界面、读哪些字段（不带属性的也要报）、给模型的描述文字、给模型的用法说明；模型靠按需调的标签列表与用法、默认模板里的例子、写入检查被拒时附带的用法学会用。**沙箱 JSX 另开 Work**。开发者同时指出富文本里不能直接插入标签，演示已补上 |
| 2026-11-26 | 开发者试过演示里插入标签后：“可以了，感觉没问题了”。实施时界面请 omp 的 `@designer`（Gemini）当顾问审查，例如富文本里标签卡片的排版 |
| 2026-11-27 | 开发者提出设定组的分页也要能像主文字那样编辑。先对齐术语（开发者同意）：界面与讨论里叫“设定组”，“Component”只留在代码与 Spec 的类型名里；“MDX”不再用，写法叫标签写法（[ADR 0064](../../../docs/adr/0064-entry-text-uses-tags-and-the-chapter-parser.md)）；设定组分页里可改的那段文字叫“设定组模板”。开发者定：设定组只是一组预设，**只在创建（加到条目上）时填进字段与模板，之后归条目自己**，作者也可以从零搭出一样的条目（没按主会话推荐的“作品里每种设定组一份模板”）；一个设定组分页有三种看法：用户视图是模板渲染出的界面，AI视图是模板渲染出的带值文字，原始视图是原始数据（Agent 用工具查、作者在界面看）；先后同意主会话的提议：先做标签登记表、再做设定组模板，各自先出演示稿 |
| 2026-11-27 | 开发者看过 t04 后改定叫法（“都同意”），取代上一行的“设定组”：界面上**不要“组”的概念**，条目有种类、有勾上的几个 Component 就够了；Component 在界面叫**模块**，种类的预设叫**模板**（例如从“主角”模板新建，自动勾上外貌等模块，作者新建时也能自己增减），模块分页里可改的那段文字叫**版式**（原“设定组模板”，避免与新建用的模板撞名），种类不改名。条目上本来就不记用了哪个模板，行为不变，只改叫法（t05） |

## 范围

- 标签写法：取值、条件、条目引用、图片各用什么标签，属性怎么写，给 Agent 的带值写法。
- 解析器：内核换成 marked、共用的文法放在哪里，读法变化的清单。
- 富文本编辑器：标签在编辑器里的样子与改法，插入入口，与源文字的切换，提交与暂存沿用 t39。
- 已有数据的迁移（样本书与作品里的 `{}`）。

- 标签登记表：插件登记展示用的标签（界面、读哪些字段、给模型的描述与用法），富文本里能插入、点开改属性；模型用的标签列表与用法工具、写入检查的回话；设定组分页改成默认模板（开发者 2026-11-26）。

`<html>`、`<jsx>` 沙箱块（数据通道、写入授权、JSX 运行时）在 t01 里做过演示，实施另开 Work。
