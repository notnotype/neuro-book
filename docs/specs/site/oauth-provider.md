# 官方站：对外 OAuth 服务

## 目标与非目标

让别的应用用官方站的账号登录：管理员登记客户端，客户端走授权码加 PKCE 的流程拿到令牌，再取用户的基本资料。账号本身见 [`site.accounts`](accounts.md)。

不承诺：

- 不支持隐式流程、密码流程、动态客户端注册。
- 不支持设备码流程（等 NeuroBook 应用要接登录时另加）。
- 不发 id_token，不支持 `openid` 范围；发现文档里不出现公钥地址。
- 不支持刷新令牌：访问令牌到期后重新走授权。

## 术语与参与者

- **客户端**：管理员登记的一个外部应用，分机密的（有密钥）与公开的（没有密钥）。
- **资源所有者**：在授权确认页上点同意的用户。
- **签发者**：站点地址本身，不带路径。

## 输入与前置条件

标准端点（地址由发现文档给出）：授权、令牌、用户信息、撤销、`/.well-known/oauth-authorization-server`。

自家接口，都在 `/api/identity/v1/` 下：

| 接口 | 谁能调 | 作用 |
|---|---|---|
| `GET oauth/authorization` | 用户 | 读一次待确认的授权请求：客户端的名字、要的范围 |
| `POST oauth/authorization` | 用户 | 同意或拒绝这次授权 |
| `GET me/grants`、`DELETE me/grants/:id` | 用户 | 列出、撤销自己给过的授权 |
| `GET admin/oauth-clients`、`POST admin/oauth-clients`、`PATCH admin/oauth-clients/:id`、`POST admin/oauth-clients/:id/rotate-secret` | 管理员 | 列出、登记、改动客户端，换密钥 |

客户端的属性：名字、回调地址（一到五个，精确匹配，除本机回环外必须是 HTTPS）、种类（机密或公开）、是否免确认（只用于自家的应用）、是否停用。范围只有 `profile` 与 `email`。

## 输出与可观察行为

1. **只有列出的端点可达。** 从外部能到达的身份相关地址只有：[`site.accounts`](accounts.md) 与 [`site.admin`](admin.md) 列出的接口、本 Spec 列出的自家接口与标准端点、Google 与 GitHub 的回调。身份库自带的任何其它地址，任何方法，回 404。
2. **发现文档。** `/.well-known/oauth-authorization-server` 回的 `issuer` 等于站点地址；里面列的每个端点地址都可达，并只列本 Spec 支持的能力（授权码、PKCE 的 `S256`、`client_secret_basic` 与 `none`）。
3. **授权请求。** 请求必须带已登记且没停用的客户端、与登记值精确相等的回调地址、`response_type=code`、`S256` 的 PKCE、范围在允许之内。客户端或回调地址不对时不跳转，显示错误页；其它不合格的跳回客户端并带标准的错误码。
4. **先登录。** 资源所有者没有会话时被带到登录页，登录后回到这次授权请求继续，请求的参数不变；被篡改或超过 10 分钟的请求不继续，显示错误页。
5. **确认。** 客户端不免确认、且这个用户没有对它给过覆盖本次范围的授权时，显示确认页；同意后带授权码跳回客户端，拒绝时带 `access_denied` 跳回。跳回的地址里带 `state`（原样）与 `iss`。
6. **换令牌。** 机密客户端用 `client_secret_basic` 认证，公开客户端不带密钥；都要带与授权请求对应的 PKCE 校验值。成功时回一个不透明的访问令牌与它的有效期（1 小时）。授权码 1 分钟内有效，只能换一次；重复使用回 `invalid_grant`。
7. **用户信息。** 带有效访问令牌调用户信息端点，回 `sub`（账号的数字 id 的字符串形式）；有 `profile` 范围时另有用户名与显示名；有 `email` 范围时另有邮箱与“是否待补”。
8. **令牌随账号失效。** 账号被封禁、密码被改或被重置、用户撤销了对这个客户端的授权、客户端被停用之后，此前发出的访问令牌调用户信息端点得 401，没用掉的授权码换不出令牌。
9. **登记客户端。** 只有管理员能登记；响应里给出客户端 id，机密客户端另给一次密钥，之后不能再读出。换密钥后旧密钥立即不能用。
10. **撤销端点。** 客户端可以撤销自己拿到的令牌；撤销不存在的令牌也回成功。

## 状态与转换

授权请求：待登录 → 待确认 → 已同意（发出授权码）或已拒绝；授权码：未用 → 已用或过期；访问令牌：有效 → 过期或被撤销。

时序与寿命：

- 一次授权请求从发起到同意至多 10 分钟。
- 同一个授权码被并发换两次时至多一次成功。
- 重启服务不影响已发出的令牌与待用的授权码。

## 副作用与数据

- 客户端、授权记录、授权码与令牌落在账号模块的库里；密钥与令牌只存摘要。
- 登记与改动客户端各写一条审计记录（[`site.admin`](admin.md) 输出 8）。

## 失败与恢复

标准端点用 OAuth 规定的错误码（`invalid_request`、`invalid_client`、`invalid_grant`、`access_denied`、`unsupported_grant_type`、`invalid_scope`）。自家接口的码：

| 码 | HTTP | 含义 | 调用方怎么办 |
|---|---|---|---|
| `authorization_expired` | 410 | 这次授权请求过期或被篡改 | 回到客户端重新发起 |
| `client_not_found` | 404 | 没有这个客户端 | 无 |
| `redirect_uri_invalid` | 400 | 回调地址不合规则 | 改地址 |

其余码同 [`site.accounts`](accounts.md)。

## 边界与兼容

- 签发者地址与端点地址一经对外公布不再改变。
- 标准端点的行为按 RFC 6749、RFC 7636、RFC 8414、RFC 7009、RFC 9207；本 Spec 只写选了哪些与本站特有的规则。
- 浏览器在授权流程里只和授权端点、登录页、`oauth/authorization` 打交道；身份库自己的续接协议不出现在浏览器与本合同里。

## 验收与 Smoke

1. 测试客户端走完整流程：授权 → 登录 → 确认 → 换令牌 → 取用户信息；同一个授权码再换一次被拒。
2. 普通用户调登记客户端的接口被拒；对身份库自带、不在清单里的地址逐个请求都得 404。
3. 拿到令牌后封禁该账号：用户信息端点得 401。
4. 改掉授权请求里的回调地址再继续：不跳转，显示错误页。

Smoke：合同测试包里的完整授权流程用例。
