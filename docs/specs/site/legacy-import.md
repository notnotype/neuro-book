# 官方站：旧站数据导入

## 目标与非目标

给部署的人：把旧官方站（`neuro-book-site`）数据库快照里的账号类数据一次性导入新站的空库，并给出可以核对的报告。导入之后账号的行为见 [`site.accounts`](accounts.md)。

不承诺：

- 不导入会话、设备码与它的令牌、旧的 OAuth 客户端与令牌、工坊、备份；它们留在旧站的快照里。
- 不做增量导入、不做双向同步：只在空库上跑一次。
- 不改旧站的快照。
- 不替不合规则的用户名自动改名。

## 术语与参与者

- **快照**：旧站停止写入后取的数据库文件。
- **预检**：只读快照、不写新库的一遍检查。
- **报告**：导入或预检写出的 JSON，供人核对。

## 输入与前置条件

命令由进程入口包提供，两个：预检、导入。参数：快照的路径、报告的输出路径；导入另要求配置里的数据目录是空的（账号模块的库里没有任何账号）。服务没有在这个数据目录上运行。

旧库到新库的去向：

| 旧数据 | 去向 |
|---|---|
| 用户的 id、角色、状态、创建时间、最后登录时间 | 原样；状态“停用”对应封禁 |
| 用户名 | 登录用的用户名取小写；原样的写法保留为“用户名的显示写法” |
| 显示名、头像、网站、签名 | 原样；显示名为空时取用户名 |
| 邮箱 | 旧库没有；填 `u<id>@placeholder.invalid`，并标记“邮箱待补” |
| 密码哈希 | 原样；没有密码的账号仍没有密码 |
| 会话版本号 | 不迁：所有人重新登录 |
| GitHub 身份 | 上游身份的 id 取旧库存的 GitHub 数字 id；展示用的 GitHub 用户名原样，作为 [`site.accounts`](accounts.md) 输出 24 的上游账号名字，关联时间取导入时刻 |
| 注册码、邀请码 | 码、可用次数、已用次数、过期时间、是否停用、备注、创建者，原样 |
| 用户用了哪个注册码、是谁邀请的 | 原样 |
| 同意记录 | 旧库没有；导入的账号都没有同意记录 |

## 输出与可观察行为

1. **预检。** 预检不写新库，报告里列出：各类数据的条数；不合 [`site.accounts`](accounts.md) 用户名规则的用户（过短、过长、含不允许的字符）；转小写后重名的用户；指向不存在用户的 GitHub 身份与码的使用关系。有上述任一项时以非零码退出。
2. **导入的前提。** 数据目录不是空的、预检有问题、快照读不了时，导入不写任何东西，以非零码退出并说明原因。
3. **全有或全无。** 导入要么全部写入，要么新库保持空：中途失败之后数据目录里没有半份数据，可以直接重跑。
4. **账号可登录。** 导入之后，每个有密码的旧账号用原用户名（不分大小写）与原密码能登录；每个有 GitHub 身份的旧账号用那个 GitHub 账号能登录。登录后它们受同意门槛约束（[`site.accounts`](accounts.md) 输出 10），资料里“邮箱待补”为真。
5. **状态原样。** 旧站里停用的账号导入后不能登录；管理员仍是管理员。
6. **码的状态原样。** 用完的、停用的、过期的注册码导入后仍不能用；还有剩余次数的码剩余次数不变。
7. **id 不变并接着发。** 每个账号的 id 等于旧 id；导入之后新注册的账号 id 大于所有旧 id。
8. **占位邮箱不参与认人。** 占位邮箱不能用来登录，也不与任何上游给的邮箱相撞；用户补填真实邮箱之后标记消失。
9. **报告。** 导入成功的报告含各类数据的导入条数、与快照条数的逐类对比、快照文件的摘要值；条数不等时导入算失败（按输出 3）。报告里没有密码哈希与码的明文。

## 状态与转换

数据目录：空 → 已导入。没有中间状态对外可见。

时序与寿命：

- 导入期间与导入之前，服务不在这个数据目录上运行；导入成功之后才启动服务。
- 同一个快照重跑预检，报告相同。

## 副作用与数据

- 只写配置里的数据目录与报告文件；快照以只读方式打开。

## 失败与恢复

| 码 | 含义 | 部署的人怎么办 |
|---|---|---|
| `snapshot_unreadable` | 快照打不开或不是旧站的库 | 重新取快照 |
| `precheck_failed` | 预检发现问题 | 按报告处理旧数据或定处理规则后重跑 |
| `target_not_empty` | 数据目录里已有账号 | 换一个空的数据目录 |
| `count_mismatch` | 导入条数与快照不等 | 新库保持空；看报告 |

## 边界与兼容

- 只认旧站最后一个版本的库结构；结构对不上按 `snapshot_unreadable` 处理。
- 快照里的密码哈希与码是敏感数据：命令不把它们写进报告、日志与标准输出。

## 验收与 Smoke

1. 合成一个旧库：有密码的用户、只有 GitHub 身份的用户、停用的用户、id 有空洞、一个用完的注册码与一个还剩两次的注册码。导入后逐项符合输出 4 到 7。
2. 合成的旧库里有 `Bob` 与 `bob`：预检失败并在报告里列出这两个用户，导入不写入。
3. 导入到一半时结束进程：数据目录里没有账号，重跑成功。

Smoke：合同测试包里用合成旧库导入后登录的用例。
