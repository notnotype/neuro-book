# 官方站：账号

## 目标与非目标

给访问官方站的人：凭注册码注册、用用户名或邮箱加密码登录、用 Google 或 GitHub 登录、管理自己的资料与登录方式。给站内别的模块：一个“问身份”的端点。管理员对别人账号的操作见 [`site.admin`](admin.md)，本站作为 OAuth 服务方见 [`site.oauth-provider`](oauth-provider.md)。

不承诺：

- 不验证邮箱、不发邮件，没有自助找回密码。
- 不按邮箱自动合并账号。
- 没有两步验证、通行密钥。
- 用户名注册后不能改；不能自助注销账号（由管理员处理）。
- 已知限制：邮箱不验证，持有注册码的人可以先占用别人的邮箱。

## 术语与参与者

- **访客**：没有会话的请求方。**用户**：有有效会话的账号持有者。
- **注册码**：管理员发的准入凭据，有可用次数。**邀请码**：用户发的码，只记“谁邀请的”，不能代替注册码。
- **上游**：Google 或 GitHub。**上游身份**：上游名加上游给的稳定 id。**上游账号的名字**：GitHub 的登录名、Google 的邮箱，只用来让本人认出关联的是哪个账号。
- **公开资料**：账号的 id、用户名（小写的登录名）、显示名、头像、网站、签名、角色与注册时间。
- **同意记录**：账号同意了哪个版本的条款、是否同意数据存放在境外、时间。
- **当前条款版本**：站点配置里的条款版本号。

## 输入与前置条件

接口都在 `/api/identity/v1/` 下，请求与响应是 JSON；改状态的请求要带与站点地址相同的来源头，否则回 `forbidden_origin`。

| 接口 | 谁能调 | 作用 |
|---|---|---|
| `POST register` | 访客 | 密码注册 |
| `POST login`、`POST logout` | 访客、用户 | 登录、结束当前会话 |
| `GET whoami` | 任何人 | 问身份 |
| `GET me`、`PATCH me` | 用户 | 读、改自己的资料 |
| `POST me/password` | 用户 | 改密码或给没有密码的账号设密码 |
| `POST me/consent` | 用户 | 补交同意 |
| `GET me/sessions`、`DELETE me/sessions/:id` | 用户 | 列出、结束自己的会话 |
| `GET me/identities`、`DELETE me/identities/:id` | 用户 | 列出、解绑上游身份 |
| `GET me/invite-codes`、`POST me/invite-codes`、`PATCH me/invite-codes/:id` | 用户 | 列出、生成、停用自己的邀请码 |
| `POST social/:provider/start` | 访客、用户 | 发起上游登录、注册或关联 |
| `GET meta` | 任何人 | 当前条款版本、注册与各上游是否开放 |

字段规则。长度按 Unicode 码点计；输入不去首尾空白（注册码与邀请码除外）：

| 字段 | 规则 |
|---|---|
| 用户名 | 3 到 30 个字符，只含小写字母、数字、下划线、点；输入只收 ASCII 的字母、数字、下划线、点，其中的大写字母按小写处理；全站唯一 |
| 显示名 | 1 到 50 个字符，可改 |
| 邮箱 | 合法的邮箱地址，至多 254 个字符，按小写比较，全站唯一；不收以 `.invalid` 结尾的地址（这个后缀留给占位邮箱） |
| 密码 | 8 到 128 个字符；登录时只查上限，不查下限：旧站导入的密码可能更短 |
| 头像与网站 | 只收 `http` 或 `https` 地址，至多 500 个字符；签名至多 200 个字符 |

配置：当前条款版本 `NB_SITE_IDENTITY_TERMS_VERSION`（必填；形如 `2026-11-20` 的真实存在的日期，服务条款与隐私政策共用一个版本）、注册是否开放 `NB_SITE_IDENTITY_REGISTRATION_OPEN`（`true` 或 `false`，缺省 `true`）、会话时长 `NB_SITE_IDENTITY_SESSION_DAYS`（2 到 365 的整数，缺省 30）、同时算密码哈希的个数 `NB_SITE_IDENTITY_HASH_CONCURRENCY`（1 到 16 的整数，缺省 2）、排队等着算哈希的请求数上限 `NB_SITE_IDENTITY_HASH_QUEUE`（0 到 10000 的整数，缺省 64）、Google 与 GitHub 各自是否开放。不合格时的问题词见 [`site.operations`](operations.md)。

定时任务（名字给 [`site.operations`](operations.md) 输出 11 的测试控制入口用）：`purge` 每 10 分钟跑一次、服务启动后先跑一次，清掉已到期的会话与过去的限流时间窗。

## 输出与可观察行为

1. **密码注册。** 请求带用户名、可选的显示名（省略时取用户名）、邮箱、密码、注册码、可选的邀请码、同意的条款版本、对境外存放的同意。全部合格时创建账号、记下同意记录、扣注册码一次、记邀请归属，并当场建立会话；响应是账号的公开资料。
2. **注册的原子性。** 注册码的扣减、账号、同意记录要么都发生要么都不发生：因用户名或邮箱重复等原因没建成账号时，注册码不被扣。同一个只剩一次的注册码被并发使用时，至多一个请求成功。
3. **注册的拒绝。** 注册关闭回 `registration_closed`；注册码不存在、停用、过期或用完回 `registration_code_invalid`；邀请码不存在、停用、过期或用完回 `invite_code_invalid`；条款版本不是当前版本、或没有同意境外存放回 `consent_required`；用户名、邮箱被占用分别回 `username_taken`、`email_taken`；字段不合规则回 `validation_failed` 并列出字段。
4. **登录。** 请求带“用户名或邮箱”与密码；含 `@` 的按邮箱找，否则按用户名找；邮箱待补的账号不能用邮箱登录。凭据对、账号没被封禁时建立会话并回公开资料。凭据不对、账号不存在、账号没有密码都回同一个 `invalid_credentials`，响应时间不因账号是否存在而有可分辨的差别。被封禁的账号回 `account_banned`。
5. **会话。** 会话由名为 `__Secure-nbsite.session_token` 的 HttpOnly、Secure、SameSite=Lax 的 Cookie 携带，作用域是站点地址；名字在版本之间不变（变了等于让所有人登出）。有效期为配置的会话时长，使用中会延长，每天至多延长一次。同一个账号可以同时有多个会话。登出只结束当前会话。
6. **会话失效。** 账号被封禁、角色被改、密码被改或被重置之后，这个账号在此之前建立的全部会话立即无效：带着它们的请求得到 `unauthenticated`。用户自己改密码时当前这一个会话保留。
7. **问身份。** `whoami` 回三种之一：`{"state":"anonymous"}`；`{"state":"authenticated","user":{"id":数字,"username":…,"role":"user"|"admin"}}`；账号库不可读时回 503 与 `unavailable`。它不延长会话。
8. **读改资料。** `me` 回公开资料加邮箱、是否有密码、邮箱是否待补、是否还缺同意（同意记录不是当前条款版本，或没有对境外存放的同意，即输出 10 的门槛）。`PATCH me` 可改显示名、邮箱、头像、网站、签名；邮箱改成别人的回 `email_taken`。
9. **改密码。** 有密码的账号要带对的旧密码，否则回 `invalid_credentials`；没有密码的账号可以直接设。成功后按输出 6 失效其它会话。
10. **同意门槛。** 同意记录不是当前条款版本、或没有对境外存放的同意时，这个账号的会话只能调 `whoami`、`GET me`、`me/consent`、`logout`，账号模块的其它接口（含 [`site.admin`](admin.md) 与 [`site.oauth-provider`](oauth-provider.md) 的）回 `consent_required`；别的模块的接口不在此列。`me/consent` 交齐之后恢复；它带的条款版本不是当前版本、或没有对境外存放的同意时回 `consent_required`。
11. **社交登录的发起。** `social/:provider/start` 带意图：登录、注册、关联。响应是要跳转去的上游地址。上游没开放回 `provider_disabled`。
12. **社交登录。** 意图为登录、上游身份已关联某个账号时，回调后建立会话并跳回站点；上游身份没有关联任何账号时不建账号，跳回站点并带 `social_not_registered`。认人只按上游身份，不按邮箱。
13. **社交注册。** 意图为注册时，发起请求要先带齐注册所需的全部内容（用户名、可选的显示名、注册码、可选邀请码、两项同意），在跳去上游之前按输出 3 校验；不合格就不跳转。回调后邮箱取上游给的地址，上游没给邮箱时跳回站点并带 `social_email_missing`。注册的原子性同输出 2。建成的账号没有密码。
14. **邮箱撞号。** 社交注册时上游给的邮箱已被别的账号占用：不建账号、不关联，跳回站点并带 `email_taken`。
15. **关联。** 意图为关联时，发起请求要有会话并带对的当前密码（没有密码的账号免）；回调只把上游身份关联到发起这次请求的那个账号。那个上游身份已关联别的账号回 `identity_taken`；这个账号在该上游已有身份回 `identity_exists`。发起之后那次会话已失效的，回调不关联。
16. **解绑。** 解绑后账号至少还剩一种登录方式（密码或另一个上游身份），否则回 `last_login_method`。
17. **会话列表。** 列出自己每个会话的建立时间、最后使用时间（精确到一小时以内）、浏览器标识的概要（浏览器名与系统名，认不出时为空；不给原始的浏览器标识）、是否当前会话；可以结束其中任意一个。
18. **邀请码。** 用户可以生成邀请码，同时有效的至多 10 个，可以停用；已有 10 个有效的码时再生成回 `invite_code_limit`。新生成的码不限次数、不过期；从旧站导入的码保留原来的可用次数与过期时间。列表里每个码有：码、建立时间、已用次数、可用次数与过期时间（没有时为空）、是否还能用。注册页接受 `/register?invite=<码>` 预填邀请码。
19. **限流。** 登录按三个键计：来源地址（每 5 分钟 30 次）、来源地址加用户名（每 5 分钟 10 次）、同一个用户名的失败次数（每小时 20 次，超过后每次登录先等 2 秒，不锁死）。注册按来源地址每小时 5 次，改密码按账号每小时 5 次。超限回 `rate_limited` 与 `Retry-After`。来源地址只从可信代理的转发头取；取不到时请求回 `forbidden_origin`，不与别的请求合并计数。计数按对齐的时间窗算：窗从整点起按窗长切，所以跨过边界的一个窗长里可以到两倍。IPv6 来源按前 64 位算一个，另按前 48 位合计，额度是单个来源的 16 倍。每次尝试都计入；在哪个键上被限流拒绝，那一次就不计入哪个键。这里的“用户名”是规范化后的登录名：转成小写，是邮箱时就是那个邮箱。成功的登录不清零失败计数。每个计数的键超过 10 万个时，窗口内新出现的键共用一份溢出额度，为该计数上限的 10 倍；失败计数的键超过 10 万个时，新出现的用户名一律先等 2 秒。
20. **过载。** 同时在算的密码哈希有上限，个数与排队的长度分别由 `NB_SITE_IDENTITY_HASH_CONCURRENCY` 与 `NB_SITE_IDENTITY_HASH_QUEUE` 定；排队的请求超过上限或等待超过 5 秒时回 `overloaded`，不无限排队。登录、注册、改密码与管理员重置密码（[`site.admin`](admin.md) 输出 4）都要算哈希，都可能回 `overloaded`。
21. **旧密码格式。** 以旧站格式存着的密码能照常登录；登录成功后它被换成新格式，之后仍能用同一个密码登录。换格式不会覆盖在这次登录期间被改掉或重置的密码。
22. **错误形状。** 失败的响应体是 `{"error":{"code":…,"fields":[…]?}}`，`code` 是下文失败表里的稳定值；`fields` 只在 `validation_failed` 时有，是不合规则的字段名的数组，字段名就是请求体里的键名；不带给人看的文字、堆栈与内部路径。请求体超过 16 KiB、不是 JSON 或不是对象时回 `validation_failed`，`fields` 为空数组。不需要参数的写接口（登出、结束会话、生成邀请码，以及 [`site.admin`](admin.md) 里的封禁、解封、结束全部会话、重置密码）请求体可以为空；给了请求体时必须是没有键的 JSON 对象，否则同样回 `validation_failed`、`fields` 为空数组。成功而没有内容可回的接口（登出、改密码、结束会话）回 `{}`。
23. **社交流程的落点。** 上游回调处理完后，浏览器被带回站点的一个页面。登录或注册成功到 `/`，关联成功到 `/account`。没完成时带查询参数 `social_error=<码>`：登录意图回 `/login`，注册意图回 `/register`，关联意图回 `/account`；码是失败表里标“跳转参数”的三个，以及 `email_taken`、`identity_taken`、`identity_exists`、`account_banned`。由 [`site.oauth-provider`](oauth-provider.md) 输出 4 带到登录页的人，登录成功后回到那次授权请求，不到 `/`。
24. **上游身份列表。** `me/identities` 的每项有 id、上游名、上游账号的名字与关联时间。上游账号的名字在注册或关联时记下，之后不随上游更新，只给本人看。

## 状态与转换

账号：`active` ⇄ `banned`（由管理员改）。会话：有效 → 失效（登出、被结束、到期、输出 6 的四种变更）。

时序与寿命：

- 注册成功的响应返回时会话已经可用。
- 登出的响应回 200 时，这个会话已经失效；账号库不可用而没能结束会话时，登出回 503 `unavailable`、不清 Cookie，会话仍然有效。
- 发起社交流程得到的跳转地址在 10 分钟内有效，只能用一次；过期或重复使用时回调跳回站点并带 `social_state_invalid`。
- 封禁与登录并发时：封禁完成之后到达的登录被拒；封禁完成之前已经建立的会话按输出 6 失效。
- 改密码或重置密码与登录并发时：改动完成之后才建成的会话，即使它的密码校验发生在改动之前，也无效；这次登录回 `invalid_credentials`。
- 重启服务不影响已有会话；限流的计数在重启后清零。

## 副作用与数据

- 账号、会话、上游身份（连同上游账号的名字）、注册码与邀请码的使用、同意记录都落在账号模块的库里。密码只存哈希。注册码与邀请码存原文（管理员要能看到）。
- 会话不存来源地址；浏览器标识只存概要（浏览器名与系统名），不存原始的写法。
- 账号的数字 id 一经分配不变、不重用。

## 失败与恢复

| 码 | HTTP | 含义 | 调用方怎么办 |
|---|---|---|---|
| `validation_failed` | 400 | 字段不合规则 | 按 `fields` 改 |
| `unauthenticated` | 401 | 没有有效会话 | 登录 |
| `invalid_credentials` | 401 | 凭据不对 | 重试 |
| `account_banned` | 403 | 账号被封禁 | 联系管理员 |
| `forbidden_origin` | 403 | 来源头不对或取不到来源地址 | 从站点页面发起 |
| `consent_required` | 403 | 缺当前版本的同意 | 走同意页 |
| `registration_closed`、`provider_disabled` | 403 | 功能没开放 | 无 |
| `registration_code_invalid`、`invite_code_invalid` | 422 | 码不可用 | 换码 |
| `username_taken`、`email_taken`、`identity_taken`、`identity_exists` | 409 | 已被占用 | 换一个或先登录再关联 |
| `last_login_method` | 409 | 解绑后没有登录方式 | 先设密码 |
| `invite_code_limit` | 409 | 有效的邀请码已有 10 个 | 先停用一个 |
| `social_not_registered`、`social_email_missing`、`social_state_invalid` | 跳转参数 `social_error`（输出 23） | 社交流程没完成 | 按页面提示重来或先注册 |
| `rate_limited` | 429 | 超限 | 等 `Retry-After` 秒 |
| `overloaded`、`unavailable` | 503 | 过载或账号库不可用 | 稍后重试 |
| `not_found` | 404 | 没有这个接口，或会话、邀请码不是自己的、不存在 | 无 |
| `internal` | 500 | 程序自身的错误 | 稍后重试，仍失败就报告缺陷 |

同时有几处不合格时，回下面先后里的第一个。字段不合格的请求不计入限流。

- 注册：`forbidden_origin`、`registration_closed`、`validation_failed`、`rate_limited`、`consent_required`、`registration_code_invalid`、`invite_code_invalid`、`username_taken`、`email_taken`。码在占用之前查，没有可用注册码的人试不出哪些用户名与邮箱已被注册。
- 登录：`forbidden_origin`、`validation_failed`、`rate_limited`、`overloaded`、`invalid_credentials`、`account_banned`。封禁在密码之后查，不知道密码的人试不出谁被封了。

## 边界与兼容

- 公开接口是上表的路径、字段规则与失败码；只追加，不改已有码的含义。
- 浏览器只和上表的接口、标准 OAuth 端点、上游回调打交道；身份库自带的其它端点从外部不可到达（见 [`site.oauth-provider`](oauth-provider.md) 输出 1）。
- 信任边界：请求体、来源头、随社交流程带回的内容都当不可信输入校验。

## 验收与 Smoke

1. 只剩一次的注册码，8 个并发注册：恰好 1 个成功，码显示用了 1 次。
2. 用重复的用户名注册：失败，同一个注册码随后仍可用于另一个用户名。
3. 登录后由管理员封禁：原 Cookie 调 `me` 得 `unauthenticated`，再登录得 `account_banned`。
4. 仿真上游走社交注册：缺注册码时不跳转；带齐后回调建出账号并有会话；同一个上游身份再次以登录意图回来直接登录。
5. 已有密码账号的邮箱与上游给的邮箱相同：社交注册被拒，原账号仍只有密码一种登录方式。
6. 条款版本提高后：旧会话调 `me/invite-codes` 得 `consent_required`，补交同意后恢复。
7. 用旧密码的登录在密码校验通过之后、会话建成之前，管理员重置了这个账号的密码：这次登录得 `invalid_credentials`，没有留下可用的会话。

Smoke：合同测试包里账号的注册、登录、问身份用例。
