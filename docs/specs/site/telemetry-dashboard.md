# 官方站：统计看板

## 目标与非目标

给管理员：从 [`site.telemetry-ingest`](telemetry-ingest.md) 的聚合里读出几组固定的数，画成管理面板里的图。

不承诺：

- 没有自定义查询，没有导出。
- 数的是上报份数与心跳次数，不是人数；重装算新的安装，一人多台各算一份。
- 数字可以被伪造的上报抬高，只作趋势参考。
- 使用档的数只代表打开了使用统计的安装。

## 术语与参与者

- **活跃数**：某个日期窗口里“窗口内第一次上报”的份数，见输出 2。
- **新增**：`daysSinceLast` 为 `first` 的份数。
- **开启比例**：每日上报里 `usageEnabled` 为真的占比。

## 输入与前置条件

接口都在站点地址的 `/api/telemetry/v1/` 下，只读，要求管理员身份：身份由账号模块的“问身份”端点（[`site.accounts`](../site/accounts.md) 输出 7）判定。

| 接口 | 参数 | 作用 |
|---|---|---|
| `GET overview` | 截止日期 | 当天、近 7 天、近 28 天的活跃数与新增，开启比例 |
| `GET series/active` | 起止日期（至多 400 天） | 每天的日活跃、7 日活跃、28 日活跃、新增 |
| `GET series/retention` | 起止的安装周 | 每个安装周在其后第 1、2、4、8 周的活跃份数与当周新增 |
| `GET series/online` | 起止时间（至多 14 天） | 每个心跳段的心跳次数 |
| `GET breakdown` | 日期、维度 | 那一天按一个维度（版本、渠道、运行形态、系统、架构、语言、大区、`noticeSeen`）分的份数 |
| `GET errors` | 起止日期、可选的应用版本 | 按拥有者加错误码（`owner` 与 `code` 一对）的份数与分档分布，崩溃与升级结果 |

## 输出与可观察行为

1. **权限。** “问身份”回匿名时得 `unauthenticated`；不是管理员得 `forbidden`；账号模块不可用时得 `unavailable`，不当作匿名放行。
2. **活跃数的算法。** 截至日期 D 的 N 日活跃数（N 为 1、7、28），是窗口 `[D-N+1, D]` 内满足下面条件的每日上报的份数：设它在窗口内的第 k 天（k 从 1 起），它的 `daysSinceLast` 是 `first`、`more`，或者数值不小于 k。
3. **新增与留存。** 新增是 `first` 的份数。留存接口对每个安装周给出：那一周的新增份数，与之后第 1、2、4、8 周里带这个安装周的每日上报的 7 日活跃数。安装周为 `older` 的上报不进留存。
4. **在线。** 每个心跳段的心跳次数，另给出按运行形态分的次数。
5. **小格子。** 分维度的结果里，份数小于 5 的格子不给出取值，合并成一行“少于 5”的合计。
6. **版本分段。** 清单版本不同的聚合分开返回，每段带它的清单版本；接口不把它们相加。
7. **没有数据与零。** 某天没有任何上报时那天不出现在序列里；有上报而某一项为零时给出 0。
8. **口径标注。** 每个接口的响应带固定的说明字段：数的单位（份数或心跳次数）、开启比例的分母（每日上报的份数）。

## 状态与转换

无状态。

时序与寿命：

- 读到的是聚合任务最近一次算出的结果，可能比写入晚一个聚合间隔。
- 聚合任务运行期间的读不被阻塞。同一次读到的各个维度出自同一批算完的上报，彼此对得上；还在保留期内的日子，最近记入的上报可能还没算进去。

## 副作用与数据

无；只读。

## 失败与恢复

| 码 | HTTP | 含义 | 调用方怎么办 |
|---|---|---|---|
| `unauthenticated` | 401 | 没有登录 | 登录 |
| `forbidden` | 403 | 不是管理员 | 无 |
| `validation_failed` | 400 | 日期范围或维度不合规则 | 改参数 |
| `unavailable` | 503 | 账号模块或统计模块的库不可用 | 稍后重试 |

## 边界与兼容

- 公开接口是上表的路径、参数与响应里的数的含义；只追加。
- 本能力只经“问身份”端点依赖账号模块，不读账号模块的库。

## 验收与 Smoke

1. 构造三份上报：第 1 天 `first`、第 2 天 `daysSinceLast` 为 1、第 9 天为 7。第 2 天的 7 日活跃是 1；第 9 天的 7 日活跃是 1；第 9 天的 28 日活跃是 1。
2. 两份不同“安装”的上报在同一天：日活跃是 2。
3. 某个系统当天只有 2 份上报：分系统的结果里它不单列，进“少于 5”。
4. 普通用户调任一接口得 `forbidden`。

Smoke：合同测试包里“记入若干上报后读出活跃数”的用例。
