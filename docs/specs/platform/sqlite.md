# 受管 SQLite 连接与事务能力

## 目标与非目标

目标：提供受管 SQLite 机制：由数据 owner 声明的具名数据库资源、受控的打开与借用、事务、参数化执行、并发借用与关闭。物理数据库资源由精确 owner 在具体资源作用域内管理，全部驱动连接与未完成获取先登记再交付；关闭、重开与失败语义明确，提交结果未知时不重放。

覆盖范围：

- 具名数据库资源的声明、打开、借用与归还；每个物理文件与其驱动连接的 owner 登记。
- 单数据库事务、只读或读写权限、参数化的语句执行。
- 并发借用、忙碌/锁定错误、关闭与重开边界，以及由宿主解析后交付的数据库定位。

非目标：

- 不拥有领域 schema、表与迁移含义；World、Plot、Storage、History、RAG 各自拥有。不实现迁移引擎，也不在打开或启动时自动迁移、悄悄建表；域 schema 的显式 DDL/迁移可在本机制上执行，其版本与门禁语义归领域 owner。
- 不是“提供者是进程级，所以所有库都归进程级 owner”：提供者只提供机制；每个物理文件的 owner 是拥有该资源作用域的一方，可以是应用/进程级（应用库）也可以是代次级（Project 库）。
- 不发明 SQL 沙箱或语句白名单；受信代码边界内不隔离恶意 SQL，`agent-sql` 等语句限制仍属对应领域与工具合同。
- 不提供跨数据库、跨文件事务，不引入 `ATTACH` 联邦；需要另一个库的消费者注册另一个具名资源。
- 不改变既有数据库位置、格式与迁移策略；本切片不启动 Project、Agent、模型或 UI。

## 术语与参与者

- 具名数据库资源：数据 owner 声明的资源身份，包含名称、定位、访问模式与 schema/迁移归属；不是请求里任意传入的绝对路径。
- 物理资源 owner：唯一拥有某个物理数据库文件及其伴随文件（`-wal`、`-shm` 等，按驱动语义）以及该文件上全部驱动连接生命周期的 owner。owner 的作用域随资源语义选择：应用库可由应用/进程作用域拥有，Project 库由 Project 代次拥有；应用库、Project 库、历史库与 RAG 库各有独立 owner，不合并成一个数据库。
- 借用（borrow）：带精确资源/代次/权限的受限使用面，只提供执行、事务与归还；不授予物理连接close/disconnect或转移owner的能力。原始驱动连接仅由owner与其受管adapter持有；Prisma/libsql差异在该边界适配，不直接交给任意消费者。归还借用不等于关闭数据库。
- 未完成获取：连接或资源打开在创建之前先登记的获取记录，保证失败、取消或关闭时能够收口。
- 结果未知（outcome unknown）：无法判定是否已经提交（提交应答丢失、提交期间连接断开）。判定以证据为准：驱动明确报告提交前的失败（忙碌/锁定、约束、权限等）是已知失败，不属于结果未知；结果未知不得当作成功或失败处理。
- 权限：资源声明的访问模式（只读、读写、是否允许创建）与借用者身份范围。
- 代次：关闭重开后可区分的新身份；同路径重开不是同一代次。

## 输入与前置条件

- 宿主提供驱动能力与已解析的数据库定位：定位解析与其优先级裁决（进程环境与 Boot Config 的先后关系等）属于应用 adapter/配置解析职责，通用 SQLite 机制不实现第二套解析、也不从请求参数构造定位。机制只接收已解析定位并校验其形态：拒绝 UNC 与非法 URL、越过 State Root 的相对 URL，只读门禁不因解析配置创建目录或文件。
- owner 注册具名资源：名称、定位、访问模式、schema/迁移归属与所属作用域（例如 Project 代次）。同一作用域内同名资源唯一，重复注册是冲突而非覆盖。
- 宿主交付可判等的文件定位身份：等价URL/绝对路径写法、目标文件系统的大小写语义及链接解析不能制造第二owner；同实例两个具名声明映射同一实际文件时拒绝冲突。不存在的目标以已确认父目录与目标名预留，创建完成后核实身份；身份变化或无法安全判等则拒绝，不默默视为新库。此处不指定解析算法，不声称跨进程强互斥或抵御恶意文件替换。
- 借用前置：资源已经打开且可用；借用声明访问模式上界，不得高于资源声明；只读借用不得执行写，也不改变库的逻辑数据（驱动可能有伴随文件或元数据动作，见副作用与数据）。消费者只能取得所有者授予的具名资源，不能凭路径打开任意数据库文件。
- SQL 参数：执行接口必须支持参数绑定；平台自身语句只允许固定文本；不提供把未绑定值拼进 SQL 文本的便利路径，标识符不做值插值。
- 事务：显式事务（BEGIN/COMMIT/ROLLBACK）由借用者控制；没有显式 BEGIN 的语句按 SQLite autocommit 语义立即生效，这不是平台替调用方提交。平台不隐式开启事务、不替借用者提交显式事务、不提供跨文件事务；连接关闭时未提交的显式事务按 SQLite 语义回滚。
- 并发：同一文件可以有多个借用（读可并发、SQLite 写串行）；由 owner 决定连接复用或及时关闭；忙碌/锁定以明确错误暴露，平台不隐藏、不无限重试。
- 取消：取消等待中的打开或借用请求是请求而不是终止确认；未完成获取保持登记，直到结算与收口成功。

## 输出与可观察行为

- 打开：成功 → 资源可用、借用可发出；失败 → 明确错误（未知资源、只读时文件缺失、权限不足、定位非法），且不产生越界文件。
- 执行：参数化语句返回结果集或影响行数；显式事务中的写以提交为对其他连接可见的界，autocommit 语句按 SQLite 语义立即生效；未提交内容在回滚或断开后不可见。
- 持久读回：提交后的数据在关闭全部连接并以新实例重新打开同一文件后可见；只读借用不改变库的逻辑数据（表与行内容），但不承诺物理文件字节不变——驱动可能创建或修改伴随文件、更新访问元数据。
- 权限：越权写（只读借用上的写、未声明资源的访问）被明确拒绝，不静默降级、不落库。
- 忙碌/锁定：返回明确错误；是否有限重试由调用方显式策略决定，平台不隐藏、不无限重试。
- 结果未知：仅在无法判定是否已提交时标注为结果未知（提交应答丢失、提交期间断开）。提交前的已知失败（忙碌/锁定、约束、权限、只读拒绝）按明确失败返回，不归入结果未知；结果未知不自动重放写操作，由领域通过重新读取或恢复流程判定。
- 关闭：owner 先拒绝新借用、收口消费者，再关闭登记连接；借用归还后关闭成功。关闭不删除数据库文件；重开同一文件产生新代次，旧代次的迟到调用返回明确错误，不得被静默路由到新代次的连接。

## 状态与转换

| 状态 | 进入事件 | 允许做的事 | 离开条件 |
| --- | --- | --- | --- |
| 创建中 | 运行实例创建提供者 | 校验驱动与定位能力 | 成功 → 可用；失败 → 进入停止中收口，收口成功才报告已关闭 |
| 可用 | 初始化完成 | 注册具名资源、打开、借用、执行与归还 | 显式关闭 → 停止中 |
| 停止中 | 关闭请求 | 拒绝新注册与新借用；已接纳消费者的清理路径仍可归还借用、提交或回滚；取消或放弃等待不证明操作已终止 | 借用全部归还、连接关闭且清理成功 → 已关闭；收口失败或超时 → 阶段仍是停止中并报告“关闭未完成”，保留占用、失败 owner 与原因，不报已关闭 |
| 已关闭 | 收口完成 | 无；迟到调用返回明确错误，不复活连接 | — |

- 管理阶段只有创建中、可用、停止中、已关闭四种；“关闭未完成”不是第五阶段，而是停止中在收口失败或超时时的结果与报告，实例留在停止中并保留失败 owner。
- 具名资源与数据库：未登记 → 已登记并打开中（未完成获取先登记）→ 可用 → 停止中（拒绝新借用、收口消费者）→ 已关闭（文件与数据保留）。打开失败先收口本轮部分资源；收口失败保留失败 owner 与原因，阶段仍在停止中并报告“关闭未完成”。只有显式恢复操作才另起一次关闭尝试，只重试失败收口，不得与仍 pending（超时但未结束）的清理重入或并发重跑，不自动循环重试。
- 借用：借用中 → 已归还（归还幂等）；owner 关闭前必须收口借用，未归还导致的关闭失败必须可见，不静默强关正在使用的连接。
- 代次：Project 关闭重开或同路径重开产生新代次，旧代次的句柄、借用与迟到回调一律失效，不得作用于新代次。
- 并发：并发首次打开共享一次初始化；并发借用相互独立；错误借用或重复归还有明确结果。
- 提供者与 owner：同一服务键在同一解析作用域最多一个 SQLite 提供者；同一物理文件在同一运行实例内只有一个物理资源 owner 登记（协作登记），不允许第二套 owner 体系并行管理。该唯一性不跨进程强制：其它进程或运行实例不受本登记约束，物理层并发由 SQLite 文件锁与驱动语义决定。

## 副作用与数据

- 文件：`<定位>.sqlite` 及其伴随文件由物理资源 owner 拥有；非 owner 不得删除或替换（该排他性是本运行实例内的协作登记，不跨进程强制）。关闭时按驱动语义完成 flush 或 checkpoint；只读打开不承诺物理文件字节不变（驱动可能创建或修改伴随文件、更新元数据）。备份与恢复不归本能力。
- 数据：schema、表与迁移含义由领域 owner 拥有。既有资源与位置保持不变：应用库位于 State Root 工作区 `.nbook` 下的默认位置，Project 库为项目内 `.nbook/project.sqlite`，历史库与 RAG 库保持各自既有位置；这不是格式变更，也不授权迁移。应用库的 owner 通常是应用/进程作用域，Project 库的 owner 随 Project 代次。
- 本能力不在打开或启动时自动建表或迁移；域 schema 只由 owner 显式执行 DDL/迁移语句（走同一借用与事务通道），不改变已有数据格式之外的内容，不写 Storage 或配置，不发起网络。
- 运行数据只使用隔离的临时根；验收真实文件不接触用户日常数据库。

## 失败与恢复

- 定位非法、权限不足或未知资源：在打开前拒绝，不创建文件；只读打开缺失文件报错，且不创建空库文件。定位由宿主/应用 adapter 解析后交付，机制不重复解析。
- 打开失败：关闭已创建的连接、清理未完成获取登记，保留失败 owner 与原因；显式恢复操作可重试。
- 事务失败：回滚成功则明确失败且数据不可见；回滚无法确认时按结果未知处理。
- 提交失败：驱动明确报告提交前失败（忙碌/锁定、约束、权限）按已知失败处理，事务未提交；只有无法判定是否已提交（提交应答丢失、提交期间断连）才是结果未知——不重放、不声称成功或失败，由领域通过重新读取或恢复流程判定，再次写入需要新的显式操作。
- 忙碌或锁定：明确错误；有限重试只能来自调用方显式策略。
- 关闭失败（借用未归还、flush 或 checkpoint 失败）：阶段保留在停止中并报告“关闭未完成”，保留占用与 owner，不假报已关闭，也不提前把文件所有权交给新 owner；只有显式恢复操作才另起一次关闭尝试，且不与仍 pending 的收口重入。
- 借用失效或驱动连接被外部销毁时，禁止继续使用并记录受影响owner/借用与原因。失效不等于完整关闭；只有确认在途操作结束且所有受管连接已收口才可closed，否则保持停止中。不要求对已确认释放的资源永久保留虚假占用。
- 崩溃或强杀：可能残留锁文件与未提交事务；恢复遵循 SQLite 与领域合同，本能力不自动删除用户数据库或伴随文件。
- 无自动迁移：打开资源不得触发 schema 迁移或建表；域 schema 由 owner 在既有检查与授权门禁下通过显式 DDL/迁移语句执行（复用本机制的借用与事务通道）；未迁移的库对需要新 schema 的消费者返回明确错误，不由平台悄悄建表。

## 边界与兼容

- 受信代码边界：参数化与权限模式是防误用边界，不是 SQL 沙箱；不隔离恶意 SQL，也不承诺对任意 SQL 的语义限制。
- 依赖方向：SQLite 提供者不依赖 Project、配置、身份数据库或工作台；领域与 Project 依赖它。等待其激活的消费者是同一依赖与激活等待图中的边，不得形成环。
- 物理资源归属：每个物理文件在运行实例内恰有一个 owner 登记；owner 作用域随资源语义选择——应用库可随应用/进程生命周期，Project 库随 Project 代次——提供者是进程级不等于提供者拥有所有库。应用库、历史库与 RAG 库各有独立 owner。Project 关闭先拒绝新借用并收口消费者，再关闭登记连接，失败保留 owner 与占用；World 的操作级连接、Plot 的长寿命连接与 `agent-sql` 写连接都从该 owner 借用，归还后由 owner 决定复用或关闭。该唯一性是本运行实例内的协作登记，不跨进程强制互斥。
- 驱动并存：不同驱动连接同一文件时都必须登记到该文件的 owner，借用与归还顺序、关闭责任统一。
- 兼容：定位解析与优先级裁决（进程环境优先于 Boot Config、相对 URL 不越 State Root、拒绝 UNC 与非法 URL、只读门禁不创建目录）由应用 adapter/宿主解析侧继续承担并保持兼容；通用机制只消费已解析定位，不重复实现解析。不改变表结构与迁移策略。本切片只提供机制并用真实文件验证，Project 库 owner 随后续切片按本合同接入。

## 验收与 Smoke

本 Spec 为 planned：以下场景是实施必须提供并记录结果的执行序列，当前没有运行证据；具体命令入口由实施计划登记，本文不预设脚本名。所有运行数据使用系统临时根下的真实 SQLite 文件，不使用 mock 回显作为持久性证据。

1. 参数绑定：打开具名资源 → 由 owner 显式建表（机制不自动迁移）→ 参数化插入包含 `'); DROP TABLE` 与引号、换行的文本 → 读回完全一致且表仍存在，证明值未被当作语句执行。
2. 回滚：打开具名资源并显式建表 → 开启事务 → 插入 → 回滚 → 关闭 → 重开同一真实文件：行不存在。
3. 持久读回与关闭重开：提交 → 关闭全部连接 → 新实例重开同一文件：行存在；关闭不删除文件，伴随文件按驱动语义处理（只读打开也可能产生驱动级伴随文件或元数据动作，不承诺物理字节不变）。
4. 权限与定位：只读借用上的写被拒绝；只读借用读回内容一致，逻辑数据不变；未登记资源或非法已解析定位（UNC、非法 URL、越过 State Root 的相对 URL）被拒绝且不创建文件；只读打开缺失文件报错且不创建空库。
5. 并发写事务竞争与归还：两个并发写事务在同一文件上竞争（显式写事务）→ 至少一个得到明确的忙碌/锁定错误，或按调用方显式 busy timeout 序列化；不静默丢写、不无限重试，读借用不被错误地当作写失败。owner 关闭前借用未归还 → 关闭可见失败；归还后关闭成功；重复关闭共享同一结果。
6. 已知失败与结果未知的区分：驱动明确报告提交前失败（例如写入被忙碌/锁定拒绝）→ 按已知失败返回、事务未提交、数据不可见；以故障注入（测试专用受控驱动适配器或在提交期间断开连接）使提交应答丢失 → 才返回结果未知且不重放，由重新读取判定实际状态。持久性证据取真实 SQLite 文件，故障注入只验证错误路径。
7. 无自动迁移与显式 DDL：打开一个不含业务表的真实库文件 → 不产生建表或迁移副作用；需要该 schema 的消费者得到明确错误；owner 显式执行 DDL/迁移语句时可在同一借用与事务通道上生效。
8. 跨库拒绝：请求在同一个事务中操作两个物理文件 → 明确不支持；两个库分别以独立具名资源与独立 owner 打开。
9. 代次：关闭重开同一路径后，旧代次的借用与迟到回调返回明确错误，不作用于新代次的数据。
10. 同文件身份冲突：用两份不同具名声明及等价路径/URL定位同一真实临时库，第二owner登记被拒绝；支持的平台上另覆盖大小写/链接别名，身份不明时明确拒绝。两个不同真实文件仍能独立登记与关闭。
11. 借用权边界：取得借用只能执行/事务/归还，不能关闭或转交共享连接；另一个借用不因它归还而失效。故障注入驱动失效后停止后续调用并显式报告，未结算操作仍计入关闭门禁。
