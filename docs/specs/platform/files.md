# 平台文件能力：受根约束的托管 I/O

## 目标与非目标

目标：为受信的服务插件与领域模块提供共同的、受根约束的文件机制：宿主签发的根能力与读写权限、根内相对路径寻址与包含校验、读/写、变更订阅（watch）、协作锁，以及句柄、订阅与锁的登记与释放。所有资源在使用前登记到拥有它的作用域，使部分初始化失败与作用域关闭都能收口。

覆盖范围：

- 受根约束的读写、目录项操作与明确的权限授予；只接受可信入口签发的资源约束。
- 句柄、变更订阅与协作锁的所有权、取消与释放语义。
- 路径穿越与 symlink/junction/reparse point 的包含校验边界：拒绝可检测的根外链接与身份变化，不能证明位于根内的操作拒绝。

非目标：

- 不做业务文件服务：作品目录结构、文件树、刷新与展开语义、领域格式解析与业务写入门禁归 workspace-files 及对应领域 owner；Project、配置、会话与 Storage 各自拥有自己的根与写入策略。
- 不提供多文件或多步操作的事务；与外部修改之间不承诺事务或合并。
- 不承诺恶意代码隔离：内置同进程代码是受信代码，包含校验与权限是防误用边界，不是恶意插件沙箱。
- 不承诺抵御恶意外部进程的并发目录替换：校验与操作之间的竞争属于 OS/文件系统边界，不在本能力的沙箱承诺内；根在维护者语义下可信且稳定，不作为并发恶意替换对象建模。
- 不因作用域关闭、消费者退出或卸载删除任何用户数据。
- 本切片不启动 Project、Agent、模型或 UI；后续 workspace-files、Storage、Project、配置与租约等按本合同接入。

## 术语与参与者

- 根能力（root capability）：可信owner签发给特定消费者的操作授予，携带稳定根身份、独立授予身份、允许操作集合与寿命；不能仅凭公开根身份获得它。根本身可信且稳定，不建模为并发恶意替换对象。涵盖State/Workspace/Cache等根，后续Project/用户资产根由对应owner签发。
- 资源约束：本次请求的相对路径与操作意图；只能缩小已签发授予，不能靠请求自报访问模式扩大权限。同一物理根的只读与读写消费者持不同授予身份。
- 受管句柄：读/写句柄、目录句柄、变更订阅（watcher）与协作锁的统称；每个受管句柄有唯一申请者作用域。
- 包含校验：判定操作目标（目录项操作为其父目录）在解析可检测的链接（symlink/junction/reparse point）之后仍位于已签发根内。本规范不规定实现所用的解析算法、调用次序或具体 API；只要求结果语义：可检测到的根外链接、根外目标或身份变化必须拒绝，无法证明位于根内的操作必须拒绝。
- 外部修改：不由本能力发起、但发生在同一文件系统上的其他进程或用户改动。
- 取消：调用方撤销尚未结算的操作的请求；取消是请求而不是终止确认，取消不等于回滚，也不代表操作已终止，未结算的操作仍须登记到结算与收口。
- owner：签发根能力的一方拥有根；申请者拥有自己的受管句柄；platform-files 拥有平台自身的登记与释放机制。

## 输入与前置条件

- 宿主在启动阶段提供经过校验的根能力及读写权限。文件能力不能自行发现、扩大或提升根，也不能从请求参数直接构造根；不直接服务任意 HTTP 路径。
- 寻址输入统一为根内相对路径：消费者只传相对路径；绝对路径只用于宿主签发根能力与内部校验，不作为操作入参。任何路径形态（绝对路径、`..`、UNC、可检测的根外链接）经包含校验判定越界或无法证明位于根内时拒绝。
- 权限按最小授予：只读、读写（写含创建与替换）、删除单独声明。借用者不能把只读升级为写；同一根对不同消费者可有不同授予。rename/移动同时移除源目录项并创建目标，因此需要写与删除权限一并授予，任一缺失即整体拒绝，不做部分移动。
- 每类操作携带实际签发的根能力（含授予身份）、相对路径与取消信号；校验请求操作属于授予集合且未超出根owner上界。失效或未签发授予拒绝；写操作只在授予允许时创建父目录，不得在根外创建。
- 并发：同一路径的并发写不序列化（按 OS 语义）；需要互斥时使用协作锁；读取方可能读到旧或新内容，除非操作为整文件替换语义。
- 依赖方向：文件能力不依赖 Project、配置、身份数据库或工作台；等待本能力激活的消费者是同一依赖与激活等待图中的边，不得形成“文件能力等待 Project、Project 等待文件能力”的环。

## 输出与可观察行为

- 读：返回内容，或以明确错误返回不存在或被拒绝；包含校验失败时不返回部分内容。
- 写：成功表示数据已写入目标且调用方要求的 flush 已完成；不承诺断电或崩溃后的持久性，除非操作显式要求并完成持久化同步。整文件替换要么发布完整新内容、要么保留旧内容，不向读取方暴露截断的半文件；追加与流式写入不作此承诺。
- 删除：只在显式删除操作下发生，并返回明确结果（成功/不存在/被拒绝）；删除目录项只作用于目录项自身——删除链接项不删除链接目标，递归删除不跨越链接边界，目录项操作不得跟随链接删除根外目标。
- 变更订阅：事件包含根身份、相对路径和类别；尽力投递、可合并、不保证OS事件逐条有序。消费者须重读内容。释放后不得开始新的消费者回调，包括此前排队但尚未开始的通知；已经开始执行的回调可完成，仍计入在途工作且不得复活旧代次。底层OS回调到达不等于允许继续向已释放消费者投递。
- 协作锁：advisory 且基于既有锁文件语义，只在协作参与者之间生效；获取返回成功、被占用或失效。持有者负责释放，或随其作用域关闭释放。锁不提供 fencing 或跨进程强制互斥，也不保证持有者即时察觉失效：被 stale 接管或外部破坏只能在后续操作或显式探测时被发现，探测到后必须报告失效并停止依赖，不得继续假装持有。
- 取消：取消是请求而不是终止确认；已接纳的操作尽力取消，调用方放弃等待不证明操作已结束，相关资源仍须登记到结算与收口为止。能中断的返回取消结果，不能中断的按完成或结果未知结算；取消不承诺回滚已写入的字节。
- 释放：句柄、订阅与锁的释放幂等，重复释放无额外副作用；释放失败保留失败 owner 与原因，不静默当作已释放。

## 状态与转换

| 状态 | 进入事件 | 允许做的事 | 离开条件 |
| --- | --- | --- | --- |
| 创建中 | 运行实例创建提供者 | 登记根能力与内部登记表 | 成功 → 可用；失败 → 进入停止中收口，收口成功才报告已关闭 |
| 可用 | 初始化完成 | 签发受管句柄；接受取消与释放 | 显式关闭 → 停止中 |
| 停止中 | 关闭请求 | 拒绝新句柄、新订阅与新锁；已接纳消费者的清理路径仍可使用既有句柄（flush、写回、释放）；取消或放弃等待不证明操作已终止 | 消费者先关闭、提供者最后收口且全部清理成功 → 已关闭；收口失败或超时 → 阶段仍是停止中并报告“关闭未完成”，保留失败句柄、owner 与原因，不报已关闭 |
| 已关闭 | 收口完成 | 无；迟到回调不得复活句柄或静默重建订阅 | — |

- 管理阶段只有创建中、可用、停止中、已关闭四种；“关闭未完成”不是第五阶段，而是停止中在收口失败或超时时的结果与报告，实例留在停止中并保留失败 owner。
- 受管句柄：获取中（未完成获取也须先登记）→ 使用中 → 释放中 → 已释放。失败或取消的获取必须收口，不能泄漏句柄；释放失败保留失败 owner 与原因，不自动循环重试。取消请求不使未结算的获取消失：登记持续到清理成功或收口失败留痕。
- 重复正常关闭共享本次结果，不重复副作用；只有显式恢复操作才另起一次关闭尝试，重试失败收口；上一次收口仍处于 pending（超时但未结束）时不得与之重入或并发重跑同一清理。运行实例隔离：不同运行实例各自拥有独立实例与登记表，不跨实例共享。
- 同一服务键在同一解析作用域最多一个提供者；重复提供是冲突而非覆盖。

## 副作用与数据

- 只在授予的根内读写；整文件替换使用的临时文件位于同一根内，失败时清理，不在根外留下残留。
- 关闭、卸载或退出不删除文件与目录；Cache Root 的内务清理也只能由显式维护操作触发。
- 不写数据库、Storage 或配置，不解释内容格式；领域格式与写入门禁归对应领域 owner。
- 变更订阅与协作锁是进程内资源，附带操作系统句柄或锁文件；关闭必须释放监听与句柄；锁的物理残留按既有锁合同清理，绝不删除用户内容。残留锁文件只对协作参与者有意义，不构成对第三方进程的强制约束。
- 不发起网络副作用。

## 失败与恢复

- 校验失败（越界、链接越界、UNC、权限不足）：明确拒绝，且不得先在根外创建文件或目录。
- 校验与操作之间的替换（TOCTOU）：机制降低校验与实际操作之间的替换窗口（受控根内操作、操作前后复核目标身份、使用平台可用的原子手段），检测到目标被替换或身份变化时失败，绝不把校验过的路径名交给会跟随已替换链接的后续操作。可移植 Node 文件 API 不具备等价 openat/O_NOFOLLOW 的原子能力，因此本能力不对抗恶意外部进程的并发目录替换给出绝对保证：该竞争处于 OS/文件系统边界，不在本能力的沙箱承诺内。
- symlink/reparse：读、写、stat 等目标型操作在解析可检测链接后做包含校验；rename、unlink、rm 等目录项操作校验父目录包含性，且不跟随目标链接（删除只作用于链接项）。
- 取消与超时：结果必须明确（完成/取消/未知），不把取消伪造成成功，取消后不重新执行。
- 外部修改冲突：不承诺事务与合并；并发写按 OS 语义处理，调用方用锁与重新读取应对；检测到目标身份或类型变化（例如目录被替换）时失败，而不是写入错误目标。
- 锁失效或被接管：advisory 锁的失效探测有延迟窗口，不承诺即时发现；一旦探测到失效即报告并停止依赖，不自动抢回、不无限轮询。
- 关闭与释放的失败：部分失败可诊断、保留失败 owner；收口失败时阶段保留在停止中并报告“关闭未完成”，只有显式恢复操作才另起一次关闭尝试且不与仍 pending 的收口重入，不自动循环，不假报已关闭。

## 边界与兼容

- 所有权：platform-files 提供机制；作品路径、事件与索引归 workspace-files；各根的业务含义归签发它的 owner；业务写入边界由领域合同定义。
- 依赖方向单向：Project、配置、会话租约、Storage 与领域可以消费平台文件能力；平台文件能力不反向依赖它们，也不依赖工作台或 UI。
- 受信代码：包含校验与权限用于防止误用与意外越界，不是恶意代码隔离；本能力不提供恶意插件沙箱，也不承诺抵御恶意外部进程的并发目录替换（见失败与恢复）。
- 与既有持久策略兼容：State Root、Workspace Root、Cache Root 的既有布局与链接语义不变；既有包含校验工具在词法与真实路径检查（目标与父目录分别处理）下覆盖的拒绝集合必须保持等价或更严格，本规范不规定实现算法，实现可调整解析方式，只要不放宽拒绝集合；不强制改变已有目录结构，不迁移数据。
- 本切片用真实临时根验证机制，不启动 Project、Agent、模型或 UI；后续消费者按借用与登记语义接入，不建立第二套文件访问正文。

## 验收与 Smoke

本 Spec 为 planned：以下场景是实施必须提供并记录结果的执行序列，当前没有运行证据；具体命令入口由实施计划登记，本文不预设脚本名。所有运行数据使用系统临时根，遵守测试与临时根合同，不使用仓库或用户数据根。

1. 真实临时文件持久读回：在临时根内以根能力写入文本 → 释放句柄 → 由新的运行实例或新句柄读回同一文件且字节一致；关闭不删除文件。
2. 越界与非法输入拒绝：`..` 相对路径、绝对路径、UNC，以及根内指向根外的 symlink/junction → 全部拒绝（绝对路径不作为合法寻址输入），且根外无任何创建；删除该链接时只删除链接本身，链接目标不受影响；无法证明位于根内的目标（例如解析失败或身份变化）同样拒绝。
3. 授予隔离：同一根签发只读与读写两份授予，只读授予读成功但写/删除/rename拒绝；不能以公开根身份或自报模式取得写权。rename缺写或删除任一授予时源目录项保持不变。
4. 变更订阅：外部进程修改文件后收到相对路径事件，重新读取得到新内容；在已有通知排队时释放，尚未开始的消费者通知不再执行，已开始回调可完成且在途资源不被提前释放。
5. 协作锁：两个参与者竞争同一目标 → 一个成功、一个被占用；正常释放后可重新获取；探测到 stale 接管或外部破坏（探测存在延迟窗口）时报告失效，而不是继续假装持有。
6. 取消：取消尚未开始的写操作 → 无副作用；取消与写入竞争时结果明确（完成/取消/未知），不伪报成功，调用方放弃等待不被当作已终止证据。
7. 关闭顺序：消费者作用域先释放句柄 → 提供者关闭成功；提供者仍有借用句柄时关闭 → 可见失败或诊断而非静默失效；重复关闭共享同一结果；收口失败时阶段保留在停止中并报告“关闭未完成”，显式恢复操作另起一次关闭尝试且不与仍 pending 的收口重入。
8. 外部修改并发：两个写入者并发修改同一文件 → 结果为所采用写入之一或明确错误，不产生被当作完整内容的半文件（整文件替换语义下）。
