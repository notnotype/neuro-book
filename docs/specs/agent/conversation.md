# Agent 的对话界面

## 目标与非目标

把纯受控的对话视图（[`ui/agent-conversation-view.md`](../ui/agent-conversation-view.md)）接到新内核，在工作台里用起来：作者在右栏和 Agent 对话、切换会话、批准写入、回答提问、看上下文和费用。

不承诺：

- 横屏方案、一键切换布局、布局预设：等布局包，开发者体验后再定。这里只保证对话能放到编辑区；
- Agent 模式另做；就地编辑时加新图；
- 按块采纳改动、收件箱：随历史接入；
- 搜对话内容：只搜标题和说明；
- 刷新页面时正在生成的那条从头补发：刷新后从下一个增量接着显示，这条写完时换成日志里的全文；

## 术语与参与者

- **宿主**：`nbook.agent` 的浏览器入口。持有当前窗口的当前会话，把日志与帧合成视图要的 `ctx`，把视图的 action 换成远程指令。
- **当前会话**：一个对话位置（右栏的视图或编辑区的页面）正在显示的会话。运行期间每个窗口各选各的，两个窗口开同一会话看到同一份；刷新后回到这个位置最近切到的会话（两个窗口共用这份记录）。
- **向导**：审批向导与提问向导，等用户时替换输入框的位置。
- **中断的会话**：当前路径的最后一次运行以 `interrupted` 结束，之后还没有新一轮。

## 输出与可观察行为

### 会话

1. 新建会话用 `nbook.agent.main`，目录里不隐藏、可用的 Profile 多于一个时先选。会话归属当前打开的作品。没有当前会话时第一次发送自动新建。
2. 会话面板是同一个组件，放在消息视图的“会话”一页与编辑区页面头里的下拉里。每行是 Profile 图标（`agent.profiles` 声明的 `icon`，没写用缺省，名字在悬停提示）、标题、时间、说明、状态（运行中、等你处理、已中断），按最近活动排，不按日分组（planned）。列表不含有归属的会话及其后代（[`sessions.md`](sessions.md) 输出 25）。

   （planned：消息视图的版式改为输出 57：宽窄两版、可拖的列表栏、头像列里的“≡”与抽屉去掉，完整列表在展开的视图段里。下面一段在它实现前是当前行为。）

   **消息视图**（开发者 2026-11-18 定）：右栏的视图里一个列表、一个聊天区。列表顶上“Bot”“会话”两个标签（planned：标题式，没有底线，当前页用主字色与粗一档的字重，Bot 后面跟未读合计；一组 `tablist`，方向键换页）：bot 一页列各归属插件（输出 53）的联系人（[`bots/view.md`](../bots/view.md)），会话一页是会话面板；标签只决定列表看哪一页，宿主打开会话时按它有没有归属切换。（planned）视图根宽不小于 600、高不小于 360 像素是宽版：左边的列表栏（缺省 260 像素；可收起，收起后换成头像列）、右边聊天区，对话的头画在聊天区上方。（planned）列表栏与聊天区之间的线可拖：列表栏宽 200 到 420 像素，聊天区至少留 320 像素；拖到 200 像素以内再过 40 像素收成头像列，收着时往外拖过 40 像素展开；焦点在线上时左右方向键每次 10 像素、`Enter` 收起或展开。宽度与收起只在内存里记，同一个窗口里视图重新挂上时接着用，重开窗口回到缺省。其余是窄版：左边一列头像（开列表的按钮、各联系人的头像与未读点、最近 5 个根会话），右边聊天区，对话的头接管面板头（输出 44），列表在抽屉里（点视图里抽屉外、`Esc`、选了联系人都关，`Esc` 与选了联系人之后焦点回到开它的按钮；（planned）抽屉从头像列右边拉出、非模态，选了会话一页的一项也关）。换版式时聊天区不重挂。（planned）视图浮成只有它一个标签的窗时自绘头（[`workbench/views.md`](../workbench/views.md) 输出 19 的“自绘头”），宽窄两版都是：没有“消息”那一行，列表栏（或头像列）通到窗口顶，列表的切换行与对话头同高 40 像素、在同一行；对话头在聊天区上方，右端给“回到停靠”等按钮留出位置；切换行的空白、头像列顶上那一行的空白与对话头的空白可以拖动窗口；窄版的抽屉从对话头下面拉出，抽屉只由头像列顶上的按钮开。没有打开会话、停在 bot 一页时写“选一个 bot 开始聊天”，盖住聊天区（第一屏在盖层下面，看不到也点不到）。（planned）视图的计数是各归属插件联系人的未读合计（[`workbench/views.md`](../workbench/views.md) 输出 17）。
3. 面板顶部是搜索（只查标题和说明）、作品范围（当前作品、全部作品）、过滤按钮。过滤菜单选 Profile、显示已归档；选了的条件是过滤按钮上的条数，菜单里能一次清除；有没有选，面板高度都不变。改名、归档、恢复在每行悬停的菜单里。
4. 切换会话只换这个对话位置的当前会话，不影响别的窗口。当前会话被归档时位置还显示它，输入框只读，可以恢复。

### 对话

5. 打开会话：先订阅 `frames` 并缓存；取 `snapshot`，得 `head`、`leaf` 与会话级基线；固定这个 `leaf` 分页取 `path`；处理缓存，seq 不大于 `head` 的日志帧丢掉，`snapshot` 返回之前的状态帧丢掉。内联放不下的事件经 `eventChunk` 拼回，按 seq 保序。收到 `leafChanged` 按新叶子重取路径，不把各分支的日志接在一起。重连后（`onResync`）按现在的快照与路径整份重建：比按 seq 用 `log` 补（[`sessions.md`](sessions.md) 输出 8）多读一次路径，但回退、切分支不用另外处理。
6. 发送走 `send`，运行中走 `enqueue`（回车插话，Ctrl/⌘ 加回车排队）；排队中的消息显示在待处理区，能删，能取出到输入框改了再发。用户消息先乐观显示；明确被拒时撤掉，文字放回输入框并说明原因；连接断开、结果未知时标出来，可以重发或移除。停止走 `abort{keepQueue: true}`，排队的消息留着；状态栏显示“正在停止”和用时，超过 10 秒提示工具没有响应，以快照的状态收口。停止的第二个选项与乐观消息见输出 49。
7. 模型与推理档选的是这个会话的设置（`changeSettings` 的 `core.model`、`core.effort`）。选择器（[`ui/agent-conversation-view.md`](../ui/agent-conversation-view.md) 的“带角色的选择器”）列“跟随默认”（`core.model: null`）、模型角色（`core.model: "role:<id>"`，[`models/service.md`](../models/service.md) 输出 8）与启用、可用、有凭据的模型；当前选中的不合格也列出并标“不可用”。实际模型、窗口、推理档来自快照的 `model`（会话没选档时，角色的默认档就是实际档，来源标“角色”，规则见 [`models/service.md`](../models/service.md) 输出 18）。模型服务不在时选择器隐藏。
8. 审批模式菜单：每次询问（默认）、放行写入、自动判断、全部放行，写 `core.approvalMode`。
9. 中断的会话不单独提醒：输入框占位文字变成“上次运行已中断。按回车继续，或输入内容后继续”，发送按钮换成继续。空着按回车走 `start`，写了字走 `send`。发出之后恢复原样。有留着的话时的继续见输出 50。

### 审批与提问

10. 运行等用户时向导替换输入框的位置：贴在消息流底部，往上滚时浮在内容上；贴底时不盖最后一条。最高占视图的 60%，内容内部滚动，内容区最少 8 行高，放不下时整体滚动。表面和其它浮层相同（磨砂）。输入框隐藏但不卸载，草稿还在。
11. 模型一条回复发起多个要审批的调用时，向导一步一个，标“第 1 / 3 个”，和提问一样作答：每步选批准、本会话都批准或拒绝（可带附言），能来回改，全部选完才能提交。“全部拒绝”随时可点，可带一段附言。可以收起成一条小条，写等什么、第几个，没有批准按钮；这时不能发新消息，要先处理它。出现时焦点到向导容器（不落到批准按钮），有读屏播报，没有焦点陷阱；收起后焦点到展开按钮，答完回输入框；Esc 只收起。
12. 审批显示工具与目标。`edit`、`write` 用只读查询 `approvalPreview` 取改前改后，用 `DiffView` 显示，一次改多个文件时按文件分节，过大或读不了的写明原因；命令显示等宽代码块，工作目录与超时一行小字；别的工具列出参数的键与值（这里只有参数，没有 schema，nb-form 的展示态也只能画成 JSON 框）。“本会话都批准”的按钮写明要记住什么（`git diff *`），不能记的没有这个按钮（[`agent/permissions.md`](permissions.md) 输出 18）。按钮：批准（`allow`）、本会话都批准（`allow-session`）、拒绝（`deny`）。附言框写了字就是拒绝，这段话交给模型，这时批准不可点。“本会话都批准”同时选中这批里同一个工具的其余调用。一批审批是一起问的，还没执行：同一个文件前面有别的调用、预览算不出来时写明，并显示参数。
13. 提问一次 1 到 4 题，单选或多选，总带“其它”；带表单的题用 nb-form 的编辑态。提交走 `resolve{answer}`（`text` 是拼好的人话，`data` 是逐题的回答），“停止这一轮”走 `abort`。已答的答案在提交前可以来回改，切走标签再回来还在，未提交的只在这一批里保留。
14. 别的窗口先答了，这个窗口的向导跟着消失；答复撞上 `already-answered` 时不报错。

### 状态栏

15. 输入框下面一行小字。左边先是数据项（缺省只有上下文圆环与百分比：90% 起变红，分母是快照 `model` 的窗口，不知道时只显示绝对数），后面是提醒：运行阶段与用时（请求中、生成中、执行工具、正在压缩、正在停止）；等重发（第几次、还等多久）；等你批准或回答；费用告警；断线时的连接状态。右边是数据项，缺省是累计 tokens、输入、输出、缓存命中、费用，图标与轮末用量相同，明细在悬停。数据项可以由用户开关、排序、换边（输出 45）。窄时先收右边、从前往后，右边收完再收左边的数据项、从后往前，都收进右边最前面的“…”，悬停写它们的文字；提醒不收，都收完还放不下才截断。Agent 模式与审批模式不在状态栏标出，看输入框工具栏的控件（[modes.md](modes.md) 输出 11）。单价未知时不显示费用，为 0 显示“免费”。
16. 上下文占用是最近一次模型回复的输入、缓存读取与缓存写入之和，即下一次请求至少要带的量。压缩后到下一次回复之前，取压缩后的估算加放回的量（估算不含系统提示与工具，所以比真实值低，下一次回复后会跳回）。
17. 累计费用到告警线（快照的费用与设置 `warnCost` 算）时费用那一项变色，左边写“超过告警线”；有没有单价的请求时费用项的悬停写“这个模型没有单价，费用上限对它不起作用”。累计跨回退，含失败与后台用途。
18. 运行结束的码显示成人话：`cost-limit`、`tool-call-loop`、`empty-reply`、`thinking-loop`、`first-event-timeout`。等重发时收到带 `retry` 的 `modelFailed`，丢掉那次的半截文字。

### 工作台状态栏条目

19. 空闲时不显示。有运行中或等用户的前台会话时显示“Agent：1 运行中 · 1 等你处理”，等用户时用警告色；点击打开对话位置并切到那个会话，优先切到等用户的。“运行中”数有会话在跑的根会话——根自己或它的任一后代在跑都算一个；“等你处理”数在等用户的会话，含子会话；按 `activity` 条目的 `root` 算。点击时等用户的是子会话就切到它。

### 压缩

20. `/compact [要求]` 走 `compact`。没有会话时不新建，说明还没有对话。被拒时文字放回输入框并说明原因：`nothing-to-compact`、`no-compaction-model`（文字提示到设置里给“压缩”角色绑定模型）、`read-only`。运行中受理（`next-boundary`）时说明“将在这一步结束后压缩”，运行结束时清掉。结果未知只说明，不重发。对话模型不可用时输入框只读，这时不能手动压缩。
21. 只压缩的运行不算上一轮的一部分：上一轮不展开、不转圈；停止显示“压缩已停止”，失败显示压缩没成功、对话没动、可以换压缩模型或开新会话，都不改上一轮回复的状态。
22. 解析到的模型跟着变：模型库变了（绑定角色、设密钥、改模型）或会话的 `core.model`、`core.effort` 变了，不用重开会话，状态、窗口与推理档就跟上：未绑定的说明消失、能发送。运行中也一样，运行状态、队列与正在生成的那条都不动。
23. 缓存命中率是累计的缓存读取除以输入、缓存读取、缓存写入之和；读写都是 0 时不显示，不写 0%：有的服务商不报缓存。
24. 上下文详情：点状态栏的圆环或缓存命中、或顶栏菜单打开，内容见 [`ui/agent-conversation-view.md`](../ui/agent-conversation-view.md) 的“上下文检查器”。数据来自 `preview`，打开与刷新时才取，不调模型；算不出（`preview-unavailable` 等）时写原因。开着时不跟着运行自动刷新。
25. 改写历史（可写、没归档、空闲时才有入口，运行中不可点）：按消息在树上的位置精确选回退目标，不按文字猜。重试助手的回复：退到那次模型请求之前（`after-step`）再 `start`；重试用户的话：退到这一轮第一次请求之前。编辑：用户消息就地变成编辑器（补充说明不能编辑），发送走这一轮 `before-turn` 的 `rewind{resend}`。从此处分支：只退不发；用户的话退到它之后，回复退到它之后（下一步之前或这一轮结束处）。原来的路径都还在。选不到目标或被拒时说明原因，对话不动。
26. 分支切换：`branchPoints` 查到的分叉里，当前路径走的那个孩子之后第一条消息上有“‹ 2/3 ›”，几处分叉落在同一条消息上时取最近的那处；切换走 `switchBranch`，运行中不可点。打开、切分支、运行结束时重新取。
27. 分支树：顶栏菜单打开，内容见 [`ui/agent-conversation-view.md`](../ui/agent-conversation-view.md) 的“分支树”。数据经 `treeNodes` 分页读，读的时候不挡对话；选中后切换走 `switchBranch`（落到那条分支最近写入的末端）。
28. `@` 引用：列项目里的文件（`find`，内容文件夹里的条目显示标题），选中后插入 `[名字](project://路径)`，模型按地址读。没有打开作品、查不到、查失败时菜单上说明。就地编辑里也能用。`$` 列这个会话的 Profile 能用的 Skill，选未初始化的先问要不要初始化，点标签打开它的 `SKILL.md`（[`skills.md`](skills.md) 输出 26–28）。
29. 草稿按会话存在浏览器本地，至多 10 条、30 天过期，打字时攒 0.5 秒写一次，切会话前先写；切到别的会话不带过去，切回来还在，发送后清。读回来之前用户已经打了字时不盖掉。另一个窗口看不到（接受）。还没有会话时打的字留在输入框，第一次发送才建会话。上方向键翻的是当前路径上用户说的话，最新在前，去重，至多 50 条；补充说明与命令不算，回退掉的分支不在路径上也不算。
30. 斜杠命令：`/new` 新会话，没发的字不带过去；`/fork` 复制当前路径成新会话并打开，运行中被拒时说明、字放回输入框，结果未知时说明，再执行一次用同一个指令 id，不多建；`/rename 标题` 改标题，没写标题时说明；`/model [文字]` 打开选择器，有文字时打开模型库并填进搜索；`/compact` 见输出 20。`/plan`、`/mode` 另做。
31. 附件：选择、粘贴、拖入图片与文件，没有会话时第一次加附件就建会话（几个一起加只建一个；正在新建（新建命令、第一次发送）时等它、传到它建出的会话里，不另建；建好之前用户去了别的会话时不抢界面，空会话留着；建不成时这个附件标失败，不重试）。不限张数，单个 25 MB，超了在附件条上写原因，失败的能重试。切会话时草稿的附件清掉（包括从没有会话的草稿打开已有会话），迟到的上传结果不算。发送时只带文字里还有标签的附件，一个标签一项，并算好范围（[`harness/runtime.md`](../harness/runtime.md) 输出 82）；代码片段、转义与围栏里的地址不是标签。明确被拒时附件随文字放回输入框；结果未知时重发带上原来的附件。模型不支持图片时也能加，发送时换一行字。编辑重发带上原来的附件。兜底标题去掉附件的标签。

### 子代理与后台任务

33. 子代理卡片：`agent_spawn`、`agent_send`、`agent_answer` 的调用各画一张卡，是常显的节点（`node`，与提问、任务清单一样切开思维链）：卡头是 Profile 图标、子代理名、工具次数与用时（等宽数字，进行中每秒走）、状态、打开子会话；放不下时先截子代理名，数字与按钮不动；下面一行是状态的说明。`agent_spawn` 的卡片按调用的 `invocation` 认子会话（不认 fork 出来的）；`agent_send`、`agent_answer` 的卡片按参数里的子会话 id 认，运行按结果的 `runId` 认，还没有结果时认 `tree` 项里 `runInvocation` 是这次调用的那次运行。找不到子会话时（例如 fork 出来的父会话里复制过来的卡片）按调用自己的结果画，没有终态的写“状态未知，打开子会话核对”。状态与那一行按调用与子代理两方面定：参数还在生成写“正在准备”；派发失败（图标与名字取参数里的 Profile）写失败原因，打开按钮不可用；调用被拒写“没有派出”；参数不合 schema 写“参数不对，没有派出”；调用 `unknown` 且按运行找不到时，找不到子会话写“不知道派没派出”，找得到写“状态未知，打开子会话核对”；子代理运行中写正在做什么（最近一次工具调用的动作名与对象，例如“读取 第二章.md”；还没有工具调用时写“正在思考”）；等用户写“等你批准：动作名”“等你回答：…”或“等你切换模式”。动作名是对话视图里这个工具的名称（与思维链那一行相同），视图没有登记这个工具时写工具名；对象是地址时只写最后一段。等父 Agent 写“在问：问题”（`tree` 项的 `question.text`）；完成写结果第一句，没有结果句时写“已完成”；出错写“出错：原因”；中止、中断写“已停止”“已中断”；数据还没到写“正在启动”。终态依次取：调用自己的结果是终态时用它；父会话里后来的工具结果（`wait`、`agent_send` 等，形状见 [`jobs.md`](jobs.md) 的“边界与兼容”）中同一次运行的终态，宿主按 `runId` 建索引；`tree` 项 `runs` 里同一次运行的收口原因；`runs` 里那次运行带着回复首句（`line`）时，完成写这句首句（同调用自己的结果），没有时写“已完成”；都没有时取 `tree` 的现况（[`subagents.md`](subagents.md) 输出 21）。卡片高度不随文字与状态变：那一行放不下截断；不自动展开；点这一行看结果全文，全文区限高、区内滚动。还有进行中的卡片（子代理运行中、等用户、等父 Agent）的那一轮不自动收起，用户手动收起照常。
34. 后代的待处理事项：后代会话等用户的审批、提问与模式切换请求停在输入框上方的停靠区（输出 37），不进本会话的向导、不替换输入框、不抢焦点；出现时经视图常驻的读屏播报区报出，文字带来源。每个事项用与审批、提问、模式切换向导相同的内容，标题写“子代理「名字」要……”，图标换成子代理 Profile 的，标题行有打开子会话的按钮；标题放不下时省略号截断，计数与按钮固定在右边。每个事项单独提交，发给它所在的会话；预览、“本会话都批准”“以后都允许”的规则都按它所在的会话。另一处先答了，这里跟着消失；没答成功时在会话的提示里写原因，所选保留。已选、已写的只在确认已答时清掉（应答成功、收到它已结算、或一份完整的 `tree` 里这个后代在而事项不在），数据重取中、订阅重建时保留。
35. 子会话的顶栏与作者：子会话的顶栏左边是返回，只有图标，切到父会话；中间是子代理的图标与子会话标题，仍是会话下拉的触发（[ui.agent-conversation-view](../ui/agent-conversation-view.md) 的“顶栏”）。路径上的 `input`、`steer` 带 `by` 是会话的，那条话标成那个会话的 Profile 名与图标，用户在子会话里说的仍是“你”；重载后照样。
36. 后台命令卡片：`shell` 带 `async` 的调用画一张卡（参数生成完才定成这种卡）：卡头是命令、任务 id 与用时、状态，在跑时有“停止”（远程 `killJob`）；下面一行，运行中是输出的最后一行，结束后是退出码与行数，右边是输出文件的地址（点了打开）。点这一行展开看输出的最后若干行（`jobTail`），运行中跟着更新；限高、区内滚动。还没有任务 id 时按调用的状态写：等审批或正在登记写“等待开始”，被拒写“没有执行”，参数不对写“参数不对，没有执行”，没登记成就出错写错误。卡片按结果的 `details.jobId` 认任务；数据来自 `jobs`，任务已不在任务中心时（取过、重启后）来自 `jobStatuses` 读的 `status.json`，一个会话打开时一次读齐（[`jobs.md`](jobs.md) 输出 9、10）；展开时才取 `jobTail`，运行中至多每秒一次；运行中的卡片同输出 33 不随整轮收起。跑过门槛自动转到后台的 `shell`（结果带 `details.autoBackground`，[`builtin-tools.md`](builtin-tools.md) 输出 31）也画这张卡，转之前是普通的命令卡；（planned）卡头注明“自动转到后台”。`wait`、`kill`、`jobs` 是过程里的一行；`ask` 带 `async` 的调用也是过程里的一行（“提问”加题干），在停靠区回答。
37. 停靠区：消息流与输入框之间的一块，放异步提问与后代的待处理事项（输出 34）：用与同步向导同一套内容（多题、单选多选、“其它”、表单、审批的预览），不替换输入框，输入框照常能发；一次显示一个事项，标题行有“第 n / m 个”与上一个、下一个；没有“全部拒绝”“终止本轮”。能收起成一条，写有几个、第一个的前半句。最高为整个对话视图高度的 40%，内容区内滚动。在排队消息与可用性提示的上面。本会话的同步向导出现时（它在消息流里贴底、替换输入框），停靠区收成一条，排在向导下面；向导消失后停靠区回到用户原来的展开或收起。阴影与圆角按停靠的面（nb-ui 设计语言“停靠的面不用浮层的阴影档”），收起与展开、亮色与暗色都一样处理。停靠区与同步向导的界面状态各存一份、按会话存，切走再回来还在。
38. 会话面板里的子会话：子会话嵌在父会话下：父会话第二行右边“N 个子代理”是折叠开关（与打开会话的按钮并列，不嵌套）；收起时有子会话等用户，父会话行写“子代理等你处理”；个数与提醒按全部子会话算，不受过滤影响。子会话每个一行（图标、名字、说明、状态），挂在父会话标题下面，跟父会话在同一个日期组；父会话按自己与后代中最近的活动排序。展开记录由宿主持有，面板关掉再打开还在。展开有三种来源：用户手动展开或收起；当前会话的祖先、有子会话等用户的、搜索或过滤命中子会话的祖先会自动展开，自动只在这些条件变化时生效一次，之后用户手动的优先。命中子会话时它的祖先照样列出（弱化，读屏说明它只是上级）。父会话被归档或不在当前范围时，它的子会话不在顶层列出。

47. 恢复方式：用户设置 `nbook.agent/resumeMode`（用户层，`"merge" | "keep" | "followups"`，缺省 `"merge"`），在设置的“运行可靠性”分区，点继续时现读，三项写作“合并一起发”“保留原插话与排队”“按排队顺序”。合并时各条按入队顺序、之间空一行，附件随各自的文字保留；合并出的一条是普通的新消息，显示在消息流末尾，前面有宿主的话先跑时标“前面还有 N 条”。
48. 排队区（[ui.agent-conversation-view](../ui/agent-conversation-view.md) 的“输入框与待处理区”）的数据来自快照与日志的缓冲区条目（[`agent/sessions.md`](sessions.md) 输出 22）：每条带发出者，会话、宿主排的只能取消（`remove`），用户自己的能编辑（取出到输入框，`remove` 之后放进草稿，重发是新话）；留着的显示“已暂停”与原因，原因按 `cause` 与 `heldBy` 取文案：`end` 是 `completed` 写“上一轮已结束”，`finished` 写“交出结果之后”，`error` 写“上一轮出错”，`aborted` 按停的人写“你停止了这一轮”“派它的 Agent 停止了”“<来源名>停止了”，`interrupted` 写“上次运行被中断”；`queued` 写“空闲时排的”，带码时写“运行没开起来：<码的说明>”；认不出的写“上一轮没有正常结束”。状态栏的活动只把只有用户能放行的留着的话算作等你处理（`heldBy` 是用户，或用户自己的话留着），会话列表的行在这时也标出来；只看打开着的会话，服务端重启后没打开过的会话里留着的话要打开它才看到（已知限制）。
49. 停止的第二个选项：缓冲区里有用户自己的话（就绪或留着）时，停止键右边接一段下拉箭头，菜单里“停止并清空排队（N 条）”走不带 `keepQueue` 的 `abort`，N 是缓冲区里的全部条数（用户的停止清空全部）；停止进行中这一项不可用。空闲时 Ctrl/⌘ 加回车排的话等于发送。乐观消息按受理它的 `commandId` 确认，不按先后。
50. 有留着的话时的继续。占位文字与发送键见 [ui.agent-conversation-view](../ui/agent-conversation-view.md) 的“输入框与待处理区”；排队区头上的“继续”与空着按回车是同一个动作。宿主按恢复方式（输出 47）调用内核：

    | 情形 | 合并 | 保留原插话与排队、按排队顺序 |
    |---|---|---|
    | 空闲，只有留着的话，空着继续 | 用户留着的话不少于两条时，合成一条走 `send{replaces}`；少于两条走 `resume{mode: "keep"}` | `resume{mode}` |
    | 空闲，留着的话加中断的运行（`interrupted`，被停止与出错的不算），空着继续 | 先 `start` 接着跑，再在这次运行里照上一行合并发出 | `resume{mode}`（内核先接着跑） |
    | 空闲，写了字 | 用户留着的话与这句合成一条走 `send{replaces}`（没有用户留着的话时走 `send`）；有中断的运行时同上一行，先 `start` 接着跑 | `send{release: mode}` |
    | 运行中，点头行的“继续” | 同第一行（`send` 进在跑的运行） | `resume{mode}` |
    | 运行中，写了字回车（插话）或 Ctrl/⌘ 加回车（排队） | 不合并：`enqueue` 照常发，内核放行用户留着的话、保持原模式 | 同左 |

    继续是一个操作：进行中（含两步之间）头行的“继续”与发送键不可用；`start` 失败（含结果未知）时停下、说明原因，不再发；第二步之前这次运行已被停止或已收口时不再发 `send{replaces}`，说明原因；`send{replaces}` 得 `input-stale` 时只重读快照、重新合成、再发一次 `send`，不重做 `start`；再失败时说明原因；合成的那一条结果未知时，“重新发送”沿用它的 `commandId` 与参数（含 `replaces`）。被拒或失败时只把用户这次写的字放回输入框，空着继续时不放回合成的文字。停止进行中“继续”不可用。合成：用户留着的条目按入队顺序，之间空一行，附件与粘贴块的 `#N` 按文字写法整体重新编号；宿主、会话的话不合并，由内核在合成的那一条前面放行，乐观消息的“前面还有 N 条”就是它们的条数。

51. 提醒。排队区（输出 48）在缓冲区的话之后列出待发的提醒：标签“提醒”加来源名（宿主写它的 `label`），正文是摘要；只能取消（走 `removeNotice`），只有发送方能撤回的（快照里带 `senderOnly`，例如后台任务的回执，[`jobs.md`](jobs.md) 输出 13）连取消也没有。门开着、或有运行（下一次请求就带上它们）时这几行是普通的就绪行；门关着又没有运行时它们按留着画，原因写“你继续时一起送出”，计进头行的“已暂停 N 条”，“继续”与空着回车走 `resume`（只有提醒时也开一次运行，[`harness/runtime.md`](../harness/runtime.md) 输出 114）。提醒取走之后在消息流里是一条系统消息（`source: "reminder"`），标签“提醒 · <来源名>”，正文折叠、点开看全文。会话发的提醒，来源名写那个会话的 Profile 名，同输出 35 里会话发的话（planned）。

## 状态与转换

| 向导状态 | 进入 | 离开 |
|---|---|---|
| 无 | 没有等用户的事项 | 收到 `interactionRequested` |
| 展开 | 有等用户的事项 | 全部提交，或运行结束 |
| 收起 | 用户收起 | 用户展开，或全部答完 |

时序与寿命：

- 宿主按位置放在插件级，组件借用并计数，归零后 30 秒取消订阅：编辑区页面切标签就卸载，也没有关闭信号。未提交的答案、收起状态放在宿主里。
- 切换会话时，正在生成的内容丢弃，进来时按输出 5 重新取。
- 插件停止时对话位置显示停止原因，刷新后回到原来的会话。
- 服务端换进程后浏览器节点是终态（[`runtime/plugin-channel.md`](../runtime/plugin-channel.md)），走现有的重新加载页面，加载后从存储恢复当前会话，会话显示中断的样子。
- 最近用过的会话按位置存在 `nbook.storage` 的本地记录，作品范围按作品分区；会话不在了就显示未选择会话。

## 副作用与数据

只经 `agent.sessions` 的远程指令改会话。界面状态（当前会话、向导收起、面板的过滤）在浏览器本地，不进会话日志。

## 失败与恢复

| 情况 | 显示 | 恢复 |
|---|---|---|
| 会话打不开 | 位置里显示原因 | 重试、选别的会话 |
| 没有模型、没有凭据、角色未绑定 | 输入框上方显示原因，发送不可用；提示卡写明哪个角色或服务商（输出 42） | 卡上的按钮去对应的设置：添加服务商、绑定角色、设置密钥，其余“打开设置”跳到模型服务 |
| 服务端换进程 | 重新加载页面，不丢已写下的内容 | 点重新加载 |
| `already-answered` | 向导跟着服务端的状态 | 自动 |
| 发送被拒 | 撤掉乐观消息，文字放回输入框，上方说明原因 | 改了再发 |
| 发送结果未知 | 消息标“未确认” | 重发（同一个指令 id）或移除 |
| 预览查询失败 | 向导写“预览不可用”，显示参数 | 审批照常 |
| 活动订阅失败 | 条目不显示，写诊断 | 刷新 |

## 边界与兼容

- `nb-agent-ui` 仍是纯受控视图，不依赖内核；新内核的适配器在它的核心里，输入是 JSON。nb-story 迁移之前旧适配器留着。
- 公开状态键 `nbook.agent/active`（有会话在跑或等你处理，主题据此换场景，不含新消息）、`nbook.agent/attention`（planned，状态栏条目的显隐：再加上有新消息）、命令 `nbook.agent.open`、`nbook.agent.open-in-editor`、`nbook.agent.new-session`、`nbook.agent.focus-session` 是公开合同。

## 验收与 Smoke

1. 真实浏览器、真实服务端、本机端点：右栏打开视图、发一条、看到流式与最终回复、状态栏变化；刷新后回到同一会话。
2. Agent 改文件：向导浮动显示 diff，收起再展开，批准后文件变了；拒绝并附言，模型收到这段话。
3. Agent 用 `ask`：单选加其它、多选、表单各答一次，结果回到模型。
4. 两个窗口开同一会话，一个批准，另一个的向导消失。
5. 服务端在运行中重启：重新加载后回到这个会话，显示中断的样子，回车继续（排着的话显示已暂停，回车先接着跑中断的那一轮，再发出排着的话）。
6. 把对话打开到编辑区页面，文件视图拖到右栏：都能用。
7. Smoke：真实模型跑主创改一个文件，经批准。
8. 运行中排两条话，点停止：两条显示已暂停；写一句回车（恢复方式为合并）：消息流末尾出现合成的一条，先跑它；用停止键旁的箭头选“停止并清空排队”时排着的话都消失。
9. 后台的宿主消息开的运行里，用户停止时留下的两条话一直显示已暂停；点头行的“继续”后它们进在跑的这次运行。
10. 书房：点看板娘，右边滑出星璃的主对话、书房不压暗；看着时到的回复不算未读，失焦时到的算，关上后看板娘带计数与那句话，拿回焦点再打开清零；面板里发附件、@ 菜单压在面板上、文字能拖选；桌面窗口外框下面板头的“关闭”在标题行之下（[bots.view](../bots/view.md) 验收 4）。
11. 消息视图里开着星璃、窗口失焦时她回了一句：计数为 1，这次不画线。拿回焦点、切到别的会话再点回她：那句所在的一轮之前是“以下是新消息”，第一轮之前有“今天”，计数清零；看着时她再回一句，不多出线，线还在原处。

## 实现合同

- **公开入口**：贡献（视图、编辑区页面、活动条目）的 id，公开状态键与命令（见“边界与兼容”）；宿主与组件不对外导出。
- **owner 与依赖方向**：`nbook.agent` 的浏览器入口。依赖 `nb-agent-ui`（纯受控视图，新内核的适配器在它的核心里）与 `agent.sessions` 的远程指令；`nbook.models` 不在时选择器隐藏。
- **关键不变量**：
  - 打开会话先订阅再取快照，日志帧按 `head` 去重；`leafChanged` 与重连都按新路径整份重建，不把分支接在一起（输出 5，`session-host.test.ts`“打开过程中”“回退”）。
  - 乐观消息只由实时帧确认；结果未知时重发用同一个指令 id，服务端其实受理了也只有一条（输出 6，`session-host.test.ts`“结果未知”）。
  - 宿主按位置放在插件级，组件借用并计数，归零后 30 秒才取消订阅；向导的界面状态在宿主里，这一批答完就清（`session-host.test.ts`“组件都还回去之后”“向导的界面状态”）。
  - 活动条目先订阅后取快照，只数前台会话（输出 19，`session-host.test.ts`“活动条目”）。
