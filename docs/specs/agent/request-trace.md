# 模型请求记录

## 目标与非目标

Agent 每发一次模型请求，都记下发出去的内容、回来的结果、用时与用量；用户在编辑区的“模型请求”页按会话与轮查看、筛选、全文查找，并和上一次请求比较。用来回答：模型看到了什么，token 和钱花在哪，缓存为什么没命中，请求为什么失败。

不承诺：

- 不经新内核的模型调用不记：nb-story 的问答（迁到新内核之前）。
- 不重发、不改写请求，也不从记录里恢复会话。
- 不导出、不进诊断包、不同步到别的机器。
- 原始请求体里的图片只记类型与字节数。
- 记录关着时发出的请求，打开之后补不回来。
- 会话删除还没有（[`sessions.md`](sessions.md)）；加的时候，删会话一并删它的记录。

## 术语与参与者

- **记录**：一次模型请求的一份记录，由请求、回复、结果三部分组成：请求是交给模型适配器的那一份（系统提示词、消息、工具声明、参数）；回复是内容块与工具调用；结果是状态、用量、用时、HTTP 状态与响应头、错误，以及可选的原始请求体。
- **用途**：对话、压缩、审批、后台，同 [`harness/runtime.md`](../harness/runtime.md) 的请求用途。
- **相同前缀**：一次请求的消息从第一条起，与同一会话里前一次请求的消息逐条相同的那一段。
- **重发**：同一会话里，请求内容与紧挨着的前一次完全相同的请求。

## 输入与前置条件

设置（用户层，设置窗口里 Agent 下的“模型请求记录”一节）：

| 键 | 缺省 | 含义 |
|---|---|---|
| `nbook.agent.requestTrace` | `true` | 记不记 |
| `nbook.agent.requestTracePayload` | `true` | 存不存原始请求体 |
| `nbook.agent.requestTraceDays` | `14` | 保留几天，1 到 365 |
| `nbook.agent.requestTraceHeaders` | `false` | 记不记请求头 |

入口：

| 入口 | 打开后 |
|---|---|
| 命令 `nbook.agent.open-requests`，命令面板标题“查看模型请求”，参数 `sessionId?`、`request?` | 见输出 25 |
| 对话顶栏菜单的“查看模型请求” | 只看这个会话 |
| 助手回复的操作“查看这次请求” | 只看这个会话，选中这条回复对应的请求 |

## 输出与可观察行为

### 记录

1. 经新内核发出的每一次模型请求都有一条记录：会话的对话、压缩、审批请求，后台会话（会话标题）与子代理的请求都算。记录在请求发给适配器之前出现，状态是“进行中”，结束时变成“成功”“失败”或“已中止”。被模型拦截链直接给出回复、没有发给适配器的请求没有记录。
2. 记录写明会话、请求序号（与会话日志 `modelStarted` 的 `request` 相同）、用途、所在的轮（轮的序号与那一轮用户的话）、改过这次请求的扩展；不属于任何会话的请求（单次请求 `complete()`）没有会话与序号。
3. 回复：成功时是内容块与工具调用；失败或中止时是已经产生的部分内容与错误（类别、码、HTTP 状态、遮盖过密钥的文字，同 [`harness/models.md`](../harness/models.md)）。
4. 用时：开始时间、收到第一个内容事件的时间、总时长。用量：输入、输出、缓存读、缓存写，以及费用（价格未知时没有费用）。
5. 响应的 HTTP 状态与响应头；`requestTraceHeaders` 开着时另记发出的请求头（含适配器加上的鉴权头）。两边的头里，下面这些只记名字、值换成 `***`：`set-cookie`、`cookie`、`authorization`、`proxy-authorization`、`www-authenticate`，以及名字去掉 `-`、`_` 之后含 `token`、`secret`、`apikey` 的；名字含 `ratelimit` 的照记原值。`requestTraceHeaders` 关着时请求头一个都不记。
6. `requestTracePayload` 开着时另存服务商收到的原始请求体，其中的图片换成类型与字节数。适配器拿不到请求体时没有这一项。
7. 进程在请求进行中退出：下次启动时这些记录变成“已中断”。
8. 重发的请求标“重发”与这是第几次发送。
9. 记录写不进去（磁盘满、没有权限）时请求照常进行，写一条诊断 `agent.requests.write-failed`。
10. 关掉 `requestTrace` 之后的请求不记；已有的记录照样能看，照样按天数清理。
11. 超过 `requestTraceDays` 天的记录在启动时与之后每天清理一次；清理不动进行中的记录。

### 查看器

12. 查看器是编辑区里的一页，标题“模型请求”。同一时间只有一页；从入口再打开时用已经开着的那一页，换成入口要的筛选与选中。
13. 列表新的在上，相邻的、同一会话同一轮的请求合成一组：组头写会话标题（只看一个会话时不写）、“第 N 轮”与那一轮用户的话；后台会话的请求写所属会话与“后台”。每条两行，同一列表里行高相同：
    - 第一行：状态、用途、模型、会话里的序号、时间；重发的标“重发”和第几次，工具声明与上一次不同的标出；
    - 第二行：输入、输出、缓存命中、总时长、费用，各条对齐成列；没命中缓存的标出；进行中的写“进行中”与已经等了多久；失败的写 HTTP 状态与错误类别。
14. 页面开着时，新的请求出现在列表顶部，选中的那条与滚动位置不变；进行中的请求结束时原地更新。
15. 筛选条常驻一行：会话、用途、状态（成功、失败、重发过、已中止、已中断、缓存没命中）、模型、时间（最近一小时、今天、全部）。选了的条件高亮、带一个清除按钮。排序：时间、总时长、输入 token、费用，缺省按时间；不按时间排时不分组。列表头写筛选后的条数、输入 token 合计、缓存命中、费用合计。
16. 全文查找：查请求与回复的正文、系统提示词、工具声明、工具调用的参数、错误文字，不分大小写，与筛选同时生效。列表只留有命中的请求，第二行换成第一处命中：在哪一条消息、前后的字、这次请求里另外还有几处。输入 `#N` 时选中当前会话里序号为 N 的请求（列表里有不止一个会话时，没有当前会话，不跳）。
17. 详情顶部常驻概览：状态、用途、序号、时间、重发；会话、轮与 Profile；模型与推理档、输入、输出、缓存命中与读到的量、首个内容事件、总时长、费用、HTTP 状态与停止原因；改过这次请求的扩展；失败时一条错误。概览右边：新一次、旧一次、打开会话、复制请求（JSON）。下面六页：消息（缺省）、系统提示词、工具、和上一次比较、原始请求体、响应。换一条记录时停在原来那一页。
18. 消息页一条消息一行：序号、角色、一行预览、token 条与 token 数（按这次请求里最大的一条算长度）。助手调用工具写成工具名与对象，工具结果写明是哪一条调用的结果；按轮分段；回复放在最后。与上一次请求相同的前缀缺省收成一行“第 1–N 条和 #M 相同”，点开逐条列出；这次新加的前面一条分隔线。点一行在原地展开全文，长的先露前几行，“看全文”看完。可以按角色筛选（用户、助手、工具结果、提醒）。
19. 从查找打开详情时带上查找词：详情上方一条查找条，写第几处、共几处、上一处与下一处、各页的命中数；消息页多一个“有命中”的筛选。
20. 和上一次比较：缺省和同一会话里前一次请求比，可以换成同一会话的别的一次。摘要写系统提示词、工具、消息、参数各自是相同还是怎样变了，写两次的缓存命中与最早一处变化的位置；下面是变了的部分的逐行差异与末尾多出的消息。
21. 原始请求体与响应两页原样显示 JSON，带行号，可以复制。没有原始请求体时写原因：设置关着，或这次请求的适配器拿不到。
22. 页面窄到放不下左右两栏时，列表与详情来回切换：点一条进详情，详情顶上“请求列表”返回；新一次、旧一次照样能用。宽到放得下时回到左右两栏。
23. 没有记录时写“还没有模型请求”；`requestTrace` 关着且没有记录时写“没有在记录模型请求”和“打开记录”按钮，点了打开设置。
24. “更多”菜单：“记录设置…”打开设置窗口的那一节；“清空这个会话的记录”（筛选了一个会话时才有）与“清空全部记录”，都要先确认，进行中的记录不清。
25. 命令带 `sessionId` 时筛选那个会话；带 `request` 时选中那一次。那一次已经清掉了时写“这次请求的记录已经清掉了”，列表照常显示。回复上的“查看这次请求”只在这条回复有请求序号时出现。

## 状态与转换

| 状态 | 怎么到 | 之后 |
|---|---|---|
| 进行中 | 请求发给适配器之前 | 成功、失败、已中止、已中断 |
| 成功、失败、已中止 | 适配器交回 | 不再变 |
| 已中断 | 进行中的时候进程退出，下次启动时 | 不再变 |

时序与寿命：

- 记录在请求发给适配器之前已经存在；列表看到的进行中的记录，结束后原地变状态，不换位置。
- 关掉页面不影响记录。设置在下一次请求生效。
- 清空与进行中的请求同时发生时，进行中的那条不清，结束时照常写完。
- 两个会话同时发请求，各自的记录互不覆盖；同一会话的记录按请求序号排。

## 副作用与数据

- 记录放在状态根下的 `agent/requests/`，不随作品走，只有本机看得到。相同的内容（一条消息、一段系统提示词、一个工具声明、一份回复）只存一份。
- 格式版本 1：读到不认识的版本时那条不显示，也不改写、不清理。
- 清理按天数（输出 11）与清空（输出 24），之后没有记录用到的内容一并删掉。

## 失败与恢复

| 码 | 含义 | 调用方怎么办 |
|---|---|---|
| `request-not-found` | 这次请求没有记录，或已经清掉 | 页面写输出 25 的说明，刷新列表 |
| `payload-not-found` | 这次请求没有原始请求体 | 页面写输出 21 的原因 |
| `trace-unavailable` | 记录目录读不了（权限、损坏） | 页面整块写原因与重试 |

诊断：`agent.requests.write-failed`（输出 9）、`agent.requests.unreadable`（某条记录或内容读不出，跳过它）。

## 边界与兼容

- 远程服务 `nbook.agent/requests`（服务端提供，浏览器调用）：列出与查找、读一条、读原始请求体、清空，事件“记录变了”。
- `@notnotype/nb-agent-ui/vue` 导出受管组件 `AgentRequestTrace`；数据由宿主给，操作经事件交回，同对话视图。
- 信任边界：记录里有提示词、作品正文与工具输出的全文，只经本机的同源接口给页面。

## 验收与 Smoke

1. 本机起一个 OpenAI 兼容端点：发一轮带一次工具调用的对话，页面里同一组出现两条记录，第二条的消息页“第 1–N 条和 #1 相同”收成一行，回复在最后；回复上的“查看这次请求”选中第二条。
2. 端点对第一次请求回 429、第二次成功：列表里两条，第一条失败、第二条标“重发”，第二次；响应页有限流头的原值；打开 `requestTraceHeaders` 再发一次，这次的请求头里有 `authorization`，值是 `***`，关着时发的那几次没有请求头。
3. 请求进行中结束服务进程，再起：那条记录是“已中断”。
4. 全文查找第一轮用户的一个词：列表只剩含它的请求，详情查找条的总数与各页命中数一致。
5. 把编辑区拖窄到放不下两栏：列表与详情来回切换；拖宽后回到两栏，选中不变。

Smoke：`packages/neuro-book/e2e/agent-request-trace.e2e.ts`（实施时新建）。
