# 本机统计

## 目标与非目标

给用户：在本机看到自己的字数、模型用量与每天的写作情况。给别的插件：一个记数的服务，声明了指标就能往里记。给遥测插件：一个只读接口。数据只在本机，统计插件自己从不联网；哪些数会被上报由 [`telemetry.client`](../telemetry/client.md) 与 [`telemetry.protocol`](../telemetry/protocol.md) 决定。

不承诺：

- 不是审计或计费的账本：进程崩溃、断线时可能少计一小批。
- 项目没有打开的日子没有那个项目的字数数据。
- 第一版没有让别的插件往仪表盘加自定义卡片的贡献点；声明了的指标只进数据，不自动出图。
- 不挡同进程的插件自己联网；“不联网”说的是统计插件自己。

## 术语与参与者

- **指标**：一个有 id、类型与说明的数。类型四种：计数、带标签的计数、耗时分布、里程碑；另有“每日数值”（一天一个值，由拥有数据的插件交出）。
- **声明者**：声明某个指标的插件；指标的 id 以它的插件 id 加点开头。
- **本机日**：这台机器的本地日期。
- **缺测**：某一天某个指标没有数据，区别于数值为零。

## 输入与前置条件

- 指标经贡献点声明：id、类型、名称与说明（文字引用）；带标签的计数（含按标签的每日数值）另写标签的取值：要么列出允许的取值（至多 50 个），要么声明为开放（取值事先列不全，例如模型名、“拥有者:错误码”、项目）。声明写在插件描述的顶层贡献里（三个运行位置都要认得它）；标签是本机标识（项目的内部标识、服务商与模型名）的指标另标“本机”，以后的上报清单不收这类指标。
- 记数服务（服务端实例提供，项目子进程与窗口经内核的远程服务调用）：
  - 计数加若干；带标签的计数加若干并指定标签；
  - 记一次耗时（毫秒）；
  - 标记一个里程碑已达成；
  - 交出某个本机日的每日数值，可以带一个标签。
  - 取值：增量是 1 到十亿的整数（缺省 1），每日数值是非负整数，日期是真实存在、在“今天前 400 天”到“今天后 1 天”之间的本机日，标签 1 到 128 个字符。
- 只读接口：按日期范围与指标读；读某一个本机日的全部指标。
- 诊断的本机观察（[`runtime.diagnostics`](../runtime/diagnostics.md)）：统计插件在每个运行位置观察本实例的诊断记录。

## 输出与可观察行为

1. **声明。** id 不以声明者的插件 id 开头、类型不认识、标签取值超过上限的声明不生效；同一个 id 声明两次时后一个不生效。
2. **只收声明过的。** 对没声明的指标记数、由不是声明者的插件记数、用没列出的标签记数：前两种被丢弃，第三种记到标签 `other` 上。开放标签的指标，每个本机日至多收 50 个不同的取值，之后新出现的取值记到保留标签 `$overflow` 上（与 `other` 不同：它说明当天取值太多，不说明取值不在名单里）。取值不合格的记数被丢弃。记数的调用不因此失败。
3. **归日。** 每次记数算在它发生时的本机日；经远程服务送来的记数带着发生时的日期，不按送达的时间算。
4. **计数与标签。** 同一天同一指标同一标签的计数相加。
5. **耗时分布（planned）。** 存的是固定几档各自的次数与总次数、总时长，不存每一次的值。
6. **里程碑（planned）。** 第一次标记时记下达成的本机日；之后再标记不改变它。
7. **每日数值。** 同一天同一指标同一标签交出多次时留最后一次；没有交出的日子是缺测。
8. **字数。** 项目插件在一个项目的“今天”换到新的一天时，交出刚结束那一天的净增字数与当时的总字数；项目关闭时交出当天到此刻为止的值；项目打开时若上次打开的那一天还没交过（关闭时没送出、进程崩溃、隔天才重开），按存下的统计补交那一天。跨过不止一个午夜（例如休眠）时，中间各天净增为零、总字数是当时的值。两个数都以项目为标签（项目的内部标识，不是项目名）；仪表盘的每天净增与总字数都只把当天交过数的项目相加，不把别的日子的总数往后带。项目整天没打开的那一天缺测。
9. **模型用量。** 模型服务在每一次模型调用结束时记：请求数（内核的重试各算一次，与服务商的账单一致）、失败数、输入与输出与缓存的 token、有定价时的费用，以及用量不全与单价未知的请求数，标签是模型（带提供方前缀）；按提供方类别分的标签（planned）。凡经模型服务的调用都计入（Agent 与别的插件），不取决于请求记录是否开着，会话分叉不重复计入此前的请求。
10. **错误码。** 统计插件把观察到的诊断记录里级别为错误、带错误码的，按“拥有者加错误码”计数；不读取、不保存记录里的消息与数据。
11. **软依赖。** 统计的存储不可用或写入失败时，记数的调用照常返回，声明者的业务不受影响；统计的可用状态（可用或降级，以及丢弃与少计的次数）在只读接口上查询。
12. **结果不明不重放。** 经远程服务的记数在连接中断、结果不明时不重发；这一小批记为少计。
13. **仪表盘。** 统计视图显示：每天的净增字数与总字数、按模型的请求数与 token 与费用、一张日历热力图（每格一个本机日，深浅按当天净增字数；缺测与零用不同的样子）。时间范围可选近 30 天、近一年、全部。
14. **清除。** 设置里可以清除全部统计数据；清除后仪表盘为空，里程碑回到未达成。
15. **不联网。** 统计插件在任何运行位置都不发起网络请求；在禁止出网的环境里行为相同。
16. **只读接口。** 读到的是已经落到本机的数；正在攒的一小批可能还没出现。读一个没有任何数据的日子得到空集合。

## 状态与转换

统计服务：可用 ⇄ 降级（存储不可用）。

时序与寿命：

- 指标在声明者的贡献被登记之后才能记数；之前的记数按输出 2 被丢弃。
- 声明者被停用（被关掉或卸载、不在当前插件清单里）后，它的指标不再接受记数，已有的数据保留、仍可读。
- 应用正常退出前，已经攒着的记数被写入；项目子进程与窗口里的送数端在收口时先送出最后一批再结束（整个应用退出时，项目子进程的最后一批是否赶得上由实现确认，赶不上时计为少计）。异常退出时最后一小批（至多 5 秒内的）可能丢失。
- 降级期间攒着的那一批写不进去就丢弃，不无限攒；之后写入成功即回到可用。
- 两个窗口与一个项目子进程同时记同一个指标，结果是三者之和。
- 清除时已经在项目子进程与窗口里攒着、随后才送到的那一小批（至多 5 秒内的）会留下。

## 副作用与数据

- 数据落在用户层的本机存储里，按“本机日、指标、标签”一行；长期保留，直到用户清除。
- 存的只有数、日期、指标 id 与标签；不存项目名、文件名、正文与模型服务的地址。

## 失败与恢复

| 码 | 含义 | 调用方怎么办 |
|---|---|---|
| `stats_unavailable` | 存储不可用，只读接口读不到数 | 稍后再读；记数不需要处理 |
| `metric_unknown` | 只读接口被问到没声明的指标 | 改指标 id |

记数的调用没有失败码。

## 边界与兼容

- 公开接口是指标的声明形状、记数服务、只读接口。指标 id 一经使用不改含义；含义变了用新的 id。
- 第三方插件可以声明指标并记数；它们的数只在本机。
- 信任边界：同进程的插件互信，owner 检查防的是误用，不是恶意插件。

## 验收与 Smoke

1. 23:59 在项目子进程里记一次保存、00:00 之后才送达：它算在前一天。
2. 关掉模型请求记录后发几次请求：模型用量照常增加。
3. 项目一整天没打开：热力图上那一天是缺测的样子，前后两天的数不受影响。
4. 让统计的存储不可写：保存项目、发模型请求都成功，统计的可用状态为降级。
5. 在禁止出网的环境里跑完上面各项：没有对外的连接尝试。

Smoke：应用的合同测试里“记数后在只读接口读到”的用例。
