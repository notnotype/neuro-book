# 世界引擎：作者界面（设定侧）

## 目标与非目标

作者在工作台里看到并改动这部作品的世界：左边一棵条目树，编辑区里每个条目一页，可以换到任意一章的开头或末尾看它当时的样子，点一个值看它是怎么来的，就地改、记一笔、新建与删除条目；每次写入都有回执，可以还原；要作者处理的事在底部面板，状态栏显示条数。本能力只定界面；读写世界的规则在 [`canon.project`](project.md)、[`canon.model`](model.md)、[`canon.revisions`](revisions.md)、[`canon.rendering`](rendering.md)、[`canon.components`](components.md)。

不承诺：

- 剧情侧的界面（剧情线、章的工作单、谁知道什么、伏笔账本、目标表、时间线）与决定、正文建议两个面板视图。
- 待处理与改动记录两个视图跟窗口在看的线（输出 34）：它们仍按缺省位置读。
- 主文字的所见即所得编辑：作者改的是整篇源文字（输出 39，planned），渲染结果在旁边的预览里看（输出 48，planned）。预览只能看：不能在预览里改，点预览里的内容不会跳到源文字，两栏不同步滚动（只在打字时跟到光标那一段）。
- 主文字分节与主文字的剧情变化：第一版界面把主文字当一整篇（输出 39，planned）。
- 新建剧情变更与计划，改变更的文字、安放与参与者（只能改已有变更里的值、把待定的改成生效、记一笔）。
- 待处理的一键处理（“按正文改设定”这一类）。
- 人物、面板以外的 Component 类型的专门界面；内置类型的完整字段清单。
- 语义档归纳以后的显示（产品里还没有接归纳用的模型；只保证“还没归纳”的写法）。
- 在编辑区里选中正文的某一句（只打开那一章）。
- 页面标签的拆分、固定与预览。
- 区分同名条目的标签：两个同名条目的标签标题相同。
- 没有绑定项目的窗口里不出现这三个视图：现在视图的声明没有条件，它们照常在，各写一句“打开作品后可用”。

## 术语与参与者

- **位置**：[`canon.model`](model.md) 的读取位置；界面上写成“最初”（模型里的初值：什么都没套，前史也没套）“第 N 章开头”“第 N 章末尾”。**缺省位置**见同一 Spec 输出 21。
- **按计划**：按计划模式读（同一 Spec 输出 5）；界面上叫“算上计划中的情节”。
- **条目页、回执页、变更详情页**：编辑区的三种带参数的页面标签（[`workbench.editor`](../workbench/editor.md) 输出 33）。
- **数据分页**：条目页里一个启用的命名空间对应的分页。

别的词按 [`canon.model`](model.md) 的术语。界面文字里不出现记录 id、Component、命名空间、字段路径、补丁这些词。

**数据分页的贡献点** `canon.component-views`：只接受浏览器入口，必须交实现（`implementation: "required"`），贡献 id 是 Component 类型 id（[`canon.components`](components.md) 输出 1）并按插件 id 的前缀校验（`idPrefix: "plugin"`），所以第三方插件只能给自己的类型交界面；内置插件之间靠约定，同一个类型后交的被拒。`title` 不写时补界面文字的约定键 `componentViews.<本地 id>.title`（本地 id 是类型 id 去掉插件 id 的前缀，同视图与页面的约定键）。

```ts
interface ComponentViewDeclaration {
    /** 分页的名字。 */
    title?: Text;
    /** 分页的图标：lucide 图标的类名（`i-lucide-` 开头）；不写时用通用的“一组设定”图标（输出 9）。 */
    icon?: string;
    /** 这个界面会用到的、同一条目上别的设定组（类型 id）。只是依赖的声明，不是权限：设定的读取对作者这一侧本来就全开。 */
    uses?: string[];
}
interface ComponentViewImplementation {
    /** 只取得组件定义；条目页创建实例，组件收到 `{context: ComponentViewContext}`。 */
    load(): Promise<Component>;
}
/** 都是响应式读取：条目页换位置、世界发布新修订以后，同一个 context 给出新的值。 */
interface ComponentViewContext {
    readonly entry: string;
    readonly namespace: string;
    readonly position: ReadPosition;
    readonly mode: "actual" | "planned";
    /** 世界版本。界面自己另读别处的数据（例如别的插件的远程方法）时，按它变了重读。 */
    readonly version: number;
    /** 这个命名空间在所选位置上的字段状态（canon.model 输出 5；含最近一次改动，canon.project 输出 32）。 */
    readonly fields: Readonly<Record<string, FieldState>>;
    /** 这个类型的字段声明（canon.components 输出 21），含条目上实例声明的。 */
    readonly declarations: readonly FieldDeclaration[];
    /** 这个分页在标签上的状态（例如面板选中的值卡）：界面组件随标签卸载，要跨“切走再回来”保留的放在这里，寿命同输出 7。 */
    readonly state: Record<string, unknown>;
    /** 写入入口不可用时的原因（输出 28 的只读、独占，输出 27 的断开）；可以写时为 null。 */
    readonly blocked: Text | null;
    /** 把一次安放写成界面上的“第 N 章”“前史”（同条目页，按章表的序号）。 */
    place(at: Placement): string;
    /** 一个地址的来历的一页（canon.model 输出 37），从最近一步往前；`path` 是这个命名空间里的路径。 */
    origins(path: string, cursor?: string): Promise<OriginsPage>;
    /** 对这个地址记一笔（输出 17）；语义档只给 `text`。成功与失败都交回，失败的原因由界面自己显示。 */
    record(path: string, input: {readonly text: string; readonly delta?: number}): Promise<{readonly ok: true} | {readonly ok: false; readonly reason: Text}>;
    /** 打开一个条目、一条剧情变更的页面。 */
    open(ref: {readonly kind: "entry" | "change"; readonly id: string}): void;
    /** 这一页的通用字段表（输出 12），专门界面嵌进自己的内容里；`fields` 只列其中几个字段（按字段名），不传列全部（planned）。 */
    readonly FieldTable: Component<{readonly fields?: readonly string[]}>;
    /** 列表字段（`path` 是这个命名空间里的字段名）的加一项、改一项、去掉一项：条目页打开元素对话框或确认（输出 40，planned）。条目页之外的宿主可以不给。 */
    listAdd?(path: string): void;
    listEdit?(path: string, element: string): void;
    listRemove?(path: string, element: string): void;
    /**
     * 以下都可以不给：条目页给全；别的宿主缺哪一项，界面就退到没有它时的做法（planned）。
     * 同一条目上另一组设定此刻的情况；只对声明里 `uses` 列了的类型有意义，没列的一律是 `absent`（不报错，界面按“没有”画）。
     * 在渲染或计算属性里读；`peer` 只能读（命名空间、字段状态、字段声明），改它的字段要到它自己的分页去。
     */
    other?(type: string):
        | {status: "present"; peer: ComponentPeer}
        | {status: "absent"}                 // 没加过
        | {status: "removed"}                // 去掉过，可以恢复
        | {status: "later"; from: string}    // 加了，所选位置上还没启用；`from` 是“第 N 章”这样的写法（planned）
        | {status: "unavailable"};           // 类型没登记或不可用
    /** 给这个条目加上（去掉过的是恢复）`uses` 里的一组设定；写不了时的原因在 `blocked` 里。 */
    addComponent?(type: string): Promise<{readonly ok: true} | {readonly ok: false; readonly reason: Text}>;
    /** 切到那一组的分页；没有这个分页时什么也不做。 */
    showTab?(type: string): void;
    /** 在这个条目的这一组上新增一个字段、改显示名、去掉、恢复（canon.components 输出 4）；类型不允许实例字段时写入被拒，原因在 `reason` 里。 */
    fieldAdd?(field: FieldDraft): Promise<{readonly ok: true} | {readonly ok: false; readonly reason: Text}>;
    fieldRename?(path: string, label: string): Promise<{readonly ok: true} | {readonly ok: false; readonly reason: Text}>;
    fieldRemove?(path: string): Promise<{readonly ok: true} | {readonly ok: false; readonly reason: Text}>;
    fieldRestore?(path: string): Promise<{readonly ok: true} | {readonly ok: false; readonly reason: Text}>;
    /** 这一组上去掉过的字段（canon.components 输出 4 的 `removedFields`），给“恢复”用。 */
    readonly removedFields?: readonly {readonly id: string; readonly label: string}[];
    /** 这个类型的预设字段（canon.components 输出 24），“添加一项资料”里列。 */
    readonly presets?: readonly FieldDeclaration[];
    /**
     * 专门界面里的就地改（输出 51）：`edit` 的第二个参数，`inline` 为真、并且此刻挂着这条路径的 `FieldEditor` 时不出确认条，由它画；
     * `value`、`intent` 预先填好。`FieldEditor` 放在值的旁边、和值一起挂着，这个字段正在就地改时画输入、意图、预览与保存取消，
     * 别的时候不画；`layout` 是 `"popover"`（锚在 `anchor` 上的浮层，短项）或 `"block"`（浮在原处、向下长，成段的文字）。
     * `FieldDetail` 画一个值的细节：语义档的起点与各句、记一句；值的来历（planned）。`editing`、`detail` 是本组里正在就地改、正在看细节的
     * 字段，没有时为 null。
     */
    edit(path: string, options?: {readonly inline?: boolean; readonly value?: unknown; readonly intent?: "creative" | "story"}): void;
    readonly FieldEditor?: Component<{readonly path: string; readonly layout?: "popover" | "block"; readonly anchor?: HTMLElement | null}>;
    readonly FieldDetail?: Component<{readonly path: string}>;
    readonly editing?: string | null;
    readonly detail?: string | null;
    showDetail?(path: string | null): void;
}
```

**条目种类的贡献点** `canon.entry-kinds`：登记一个种类默认带哪几组设定。声明在插件清单里，不交实现，贡献 id 按插件 id 的前缀校验。种类仍然只是条目上的一个词，世界里不存这张表。

```ts
interface EntryKindDeclaration {
    /** 存进条目的那个词，例如“人物”。 */
    kind: string;
    /** 新建这个种类的条目时默认带的设定组（类型 id）。 */
    components?: string[];
    /** 新建对话框里的先后，小的在前。 */
    order?: number;
    /** 这个种类的条目页在标签上的图标（lucide 类名，[`workbench.editor`](../workbench/editor.md) 输出 33）；不写时用书签。 */
    icon?: string;
}
```

同一个词可以有几条登记（别的插件可以给“人物”追加默认的设定组）：默认的设定组先是内置的、再是别的插件的，并起来、去重，`order` 取最小的，`icon` 取第一条写了的；别的插件之间按贡献 id 排（planned）。默认里写到没登记或不可用的类型时，那一项当作没写，另写一条诊断。默认只在“没说要哪几组”时用：新建对话框见输出 4；Agent 的新建见 [`canon.agent-tools`](agent-tools.md) 输出 7。内置登记人物（人物、形象两组）、组织、地点、物品，各有图标。

## 输出与可观察行为

### 条目树

1. **设定视图。** 侧栏视图“设定”显示条目树，在活动栏有它的入口，排在文件资源管理器之后。窗口没有绑定项目时，视图里只有一句“打开作品后可用”。
2. **树的内容。** 一层一层显示：根下按分组列出条目，同组按顺序；有子条目的可以展开，展开时才读那一层。每项显示条目在缺省位置上的名字（[`canon.project`](project.md) 输出 30）；在缺省位置上尚未出场的用次级色并在名字后写“未出场”；已删除的条目只有在它还有没删除的子孙时才列出，名字后写“已删除”，不能打开写入入口。一层读不完时末尾有一行“再显示（还有 N 项）”，N 是这一层还会列出的条数，点了接着读。马甲条目按它的父条目显示（新建时缺省放在本体下面，见输出 4）。
3. **树跟着世界变。** 世界发布了新的修订（本窗口或别处）以后，已展开的各层重读并原地更新：展开状态与滚动位置保留，选中的条目还在就保持选中，不在了就没有选中项。
4. **新建条目。** 视图标题栏的“新建条目”与树项右键菜单的“在它下面新建”打开一个对话框：名字（必填）；种类（人物、地点这类词，从已有条目用过的里选，也可以新写）；分组（缺省与种类相同）；放在谁下面（缺省是右键的那一项，否则是根）；启用哪些数据（已登记的类型里选零个或多个）；它是谁的另一个身份（选填，选了以后“放在谁下面”缺省变成那个条目）；“放在谁下面”“另一个身份”的候选与“种类”用过的词都只来自树里已经读到的条目（展开过的层），要选的不在其中时先在树里展开它；从哪里出场（缺省“一开始就在”，否则选一章的开头）。顺序排在同层最后。名字为空时确认按钮不可用。确认后发布一次写入；成功后树里出现这一项、打开它的条目页，并按输出 18 给提示。种类的候选另有登记的种类（输入的 `canon.entry-kinds`），排在用过的词前面；点一个种类的按钮、或种类的输入框失焦时，作者还没动过“启用哪些数据”的勾选，就把勾选整组换成这个种类的默认（没登记的种类是空的）；作者动过以后不再跟着种类换。
5. **打开条目。** 单击树项打开它的条目页；这个条目的页已经开着就切过去，不开第二个。条目页成为所在组的活动标签时，树里选中它的条目；树里还没读到这一项时不展开去找；编辑区拆成几组时，选中的是最后成为活动标签的那一页，在组之间换焦点不改选中。键盘：方向键在树里移动与展开收起，Enter 打开，菜单键或 Shift+F10 打开右键菜单。

### 条目页

6. **页头与面包屑。** 页头依次是名字、一句话简介、别名（输出 38），别名那一行靠右是“在看”（输出 7），名字那一行靠右是条目的“更多”。标签条下面有面包屑（[`workbench.editor`](../workbench/editor.md) 输出 33）：“设定 › 分组 › 各级上级 › 名字”，上级从最上面一级到直接上级（[`canon.project`](project.md) 输出 33）；点“设定”显示设定视图（`nbook.view.open`，[`workbench.views`](../workbench/views.md) 输出 14），点一级上级打开它的条目页，分组与名字不可点。面包屑写的是这个条目在哪，不随从哪里点过来而变。马甲条目在名字后面有“是谁：某某”，某某是到那个条目的条目页的链接。标签标题是条目在缺省位置上的名字：页面在前台时名字变了标题跟着变，不在前台的标签回到前台时更新；刷新后恢复的标签先显示编辑器记下的标题（[`workbench.editor`](../workbench/editor.md) 输出 33）；从没读到过名字时标题是“条目”。
7. **在看（位置与故事线）。** 页头的“在看”是一个按钮，写这一页的值是哪一刻的：“在看 第 3 章末尾 · 主线”。不止一条线时才写线（按章节自动时写这一页实际读的线，固定看一条线时写那条线，按钮换强调色浅底、带分支图标）；算上计划时加“· 含计划”。按钮两边各一个按钮往前、往后一处：一处是“最初”与每章的开头、末尾排成一列里的一项，到头了不可用，悬停写要去哪（“往前一处：第 3 章开头”）或“已经是最初”“已经是最后”。点按钮打开菜单，分两段，各有一个小标题与说明图标（悬停看这一段管什么）：“故事线”（不止一条线时）列“按章节自动”（旁边写“当前：线名”）与可选的线（输出 34）；“剧情进度”先是“最初”（旁边写“起始设定”），然后按章序一章一行，写章的序号与标题（[`canon.project`](project.md) 输出 28），行尾是“开头”“末尾”两个按钮，当前位置那个是强调色实底。多于 12 章时剧情进度顶上有搜索框（纯数字只认章号，别的按“第 N 章”与标题里的字筛，不分大小写、不管空格；搜不到写“没有对得上的章”），章表约 8 行高、在里面滚，打开时当前章在中间。作品里有计划中的情节时最下面另有开关“算上计划中的情节”（按计划）。选位置或选线以后菜单关上、焦点回到按钮；拨开关不关。菜单比窗口高时在里面滚。键盘：打开时焦点在搜索框（章多时）或当前位置上，上下键换章、左右键换开头末尾，回车选中；故事线一段上下键换线；Escape 关上、焦点回到按钮。没有章、没有计划又只有主线时（空作品）不出“在看”。按钮左边一格写这一页此刻的标记，同时只写一样：“原来选的那一章已经不在了”，或“这时还没出场”（输出 8）。标记出没时按钮不动。打开页面时选缺省位置。位置、“按计划”开关、当前分页、展开的来历、面板里选中的值卡，以及填了一半的就地改与记一笔（在改哪个值、填的内容、选的意图、写的“发生了什么”），是这个标签自己的状态：切到别的标签再回来保持不变；关掉标签或刷新窗口以后回到缺省。同时开着的两个条目页各有各的状态。选着的那一章被删掉时，位置回到缺省位置，标记写“原来选的那一章已经不在了”。
8. **未出场、已删除与找不到。** 所选位置上条目尚未出场时，“在看”左边的标记写“这时还没出场”（位置就在旁边的按钮上；不另起一行），各分页照常显示它的初值。条目已删除时，页面只显示原来的名字与“这个条目已删除”，没有别的写入入口（planned：有“恢复这个条目”，输出 38）。参数里的条目不存在时，页面写“找不到这个条目”。
9. **分页。** 每页是图标、名字与条数（没有或为 0 时不写）。依次是“文字”、每个启用的命名空间一个数据分页（分页名与图标见输入的贡献点，没声明图标的用通用的“一组设定”图标；顺序同条目读取结果里命名空间的顺序）、附加分页（输出 36）、“情节”；数据分页与“文字”是一段，附加分页与“情节”这些不对应设定组的看法是另一段，两段之间有分隔。作品里还没有剧情变更时不出“情节”与声明了 `needsChanges` 的附加分页（空着没用）。竖排时分页的增减（加上、去掉一组设定，“情节”第一次出现）有过渡：新的一页淡入，去掉的淡出，其余的滑到新位置。条目的种类登记了默认的设定组（输入一节的 `canon.entry-kinds`）时，这些设定组的数据分页排到“文字”前面，其余数据分页照旧在“文字”后面；所以人物条目打开时选中人物分页；这个条目有没提交的主文字稿时打开页面选“文字”（直接进编辑，输出 45）。排到前面的几个分页之间，次序仍同命名空间的顺序（planned）。一个启用的命名空间也没有时不出数据分页。条目页的滚动区不窄于 1040 像素时分页在内容左边竖排、吸在页头下面，窄于 1024 像素时在页头下面横排，两个宽度之间保持原样（免得在临界处来回切）；要排写正文的两栏预览（输出 48）而放不下“两栏加竖排分页”时横排。两种排法选中同一页，直接换、不做过渡；焦点原本在分页上的，换完在新那套的选中项上。横排放不下时（窄窗口、设定组多）分页条在自己里面横向滑动，每页照旧写图标与名字（触屏上没有悬停提示，只剩图标认不出是哪一页）；分页条不画滚动条（放不下与放得下时一样高），某一头还有看不见的分页时那一头渐隐，鼠标滚轮在上面竖着滚时横着滑；选中的一页总在看得见的范围里：打开页面、分页条变窄、换了选中（例如刚加上的一组）时滑到露出它，作者自己滑到别处时不被拽回来。打开页面时选第一个分页。没删除的条目总有“文字”分页，没有主文字时写“还没有主文字”（输出 39）；这时打开页面选第一个数据分页，没有数据分页才选“文字”（planned；之前没有主文字时不出“文字”分页）。
10. **文字分页。** 显示给作者的渲染（[`canon.rendering`](rendering.md) 输出 7），内容列宽度封顶。文字里的每个值是一个按钮，读屏读出字段的显示名与值，点了展开来历（输出 11）；值的“改”在数据分页，文字分页里改的是整篇主文字的源文字（输出 39，planned）。条件只画生效的那一支（planned）。值未知时写“未知”，不完整时写“不完整”并用警告色；所选位置之前被改过的值（[`canon.project`](project.md) 输出 32），后面用次级色写“第 N 章改过”，前史里改的写“前史改过”，核对点定下的写“第 N 章核对过”。出错的块显示它的纯文本与一句原因，别的块照常。
11. **来历。** 点一个值，在它下面展开它的来历（[`canon.model`](model.md) 输出 15、37），展开时才读：一行一步，最近的在上，先读最近的 20 步，末尾有“再显示更早的（还有 N 步）”，初值那一步总在最后一行。每行写位置、发生了什么（剧情变更的文字、“最初”、“核对：正文写 X”加对上或对不上）、依据（原文引用、估计、作者给的）、变化量与结果；估计的依据用警告色并带“估计”两字。由剧情变更给出的步，行尾有“改这一笔”，打开那条变更的详情页。再点同一个值收起；同一时间只展开一个。来历读取失败时，展开处写原因与“重试”。
12. **数据分页用哪个界面。** 这个类型在 `canon.component-views` 有交付的界面就用它；没有、界面的贡献方已停止或组件加载失败时，用通用的字段表，加载失败时另在分页顶上写原因。专门界面可以经 `FieldTable` 在自己的内容里嵌一节通用字段，这一节的值、来历与“改”同通用字段表。通用字段表：一行一个字段，写显示名、值与单位、输出 10 的“改过”标记，值可以点开来历，值旁有“改”（输出 16）；列表字段一行一个元素，下面另列各元素的“改”“去掉”与“添加一项”（输出 40，planned）。展开着的字段是数或语义档时，来历下面有“记一笔”的输入（输出 17，planned）。
13. **人物的界面**（类型 `nbook.canon.person`）。一行一个字段，同通用字段表；语义档的字段在值下面依次列出起点与之后记下的每一句（带位置），未归纳时最后写“还没归纳”。
14. **面板的界面**（类型 `nbook.canon.panel`）。一列值卡，每个字段一张：显示名、当前值与单位、输出 10 的“改过”标记；列表字段一张卡，列出各元素的名字。选中一张值卡，旁边是这个字段的流水：就是它的来历（同输出 11 的分页与“最初”一行），列为“位置、发生了什么、变化、结果”，由剧情变更给出的行有“改这一笔”，核对点一行写对没对上；流水上面是“记一笔”的输入（输出 17）。打开分页时选中第一张值卡；没有字段时写“这个面板还没有内容”。
15. **情节分页。** 列出涉及这个条目、在所选位置上已经算进去的剧情变更（[`canon.project`](project.md) 输出 31；按计划时含计划），从新到旧；每行写位置、文字，以及它对这个条目的改动（“存款 −300”“样子 → 哥哥”）；计划、待定、已撤销的各带一个文字标记。分页名后写总条数（0 条时不写）。一页读不完时末尾有“再显示（还有 N 项）”。点一行打开变更详情页。

### 写入

16. **就地改。** 数据分页里每个值旁有一个“改”按钮（常显，与值按钮并列，键盘可达）。点了以后，分页顶上出现确认条（内容滚动时它不动，同一时间只有一条），写明在改哪个字段（planned：确认条在页头之下、分页之上，各分页共用这一条）；页头的名字、简介不用确认条，见输出 38：
    - 输入控件按字段的声明（数、文字、选项），焦点进它。planned：是否是开关；引用是条目选择器，按名字或别名找、只列声明的 `targets` 种类的条目，可以清空（写成未知）；图片是作品内路径与说明两个输入，路径不合规则时写原因。语义档的“改设定”改的是起点，输入里预填起点，不是显示的归纳文字。
    - 意图二选一（改设定、剧情里变了）写成落点（确认条里在输入下面，前面写“这次改的是”；编辑卡里在取消、保存那一行的左边，输出 51）：改设定写“从<来源>起”，来源是这个值最近一次定下的地方（“从最初起”“从第 2 章起”“从前史起”；来源只在计划里、或是语义档的核对点时写“改设定”，核对点定下的值按改设定写不回去）；剧情里变了写“从<所选位置那一章>起”。来源就是所选的那一章时两项写“改第 3 章那一笔”“第 3 章里又变了”。缺省是改设定；所选位置是最初时只有改设定、不出这一行；值不完整时只有剧情里变了。
    - 选着剧情里变了时，输入下面多一行选填的“发生了什么”：它是这次修订的标题，也是记下的那一条剧情变更的文字；不填时写“<字段>变成 <新值>”（例如“年龄变成 18 岁”；值长于 20 字、成段的文字、引用、图片与是否写“<字段>变了”）。改设定的标题是“改<字段>”，不问理由。
    - 填了新值以后取预览（[`canon.revisions`](revisions.md) 输出 22）。确认条写这次会写回哪里（“改最初的值”“改第 2 章‘订了蛋糕’那一笔”“在第 3 章末尾记一条变更”），预览没回来时写“正在预览…”，带来的变化（多了、少了哪些待处理，哪些值跟着变）逐条列出。编辑卡（输出 51）不单写写回哪里（在二选一里）：没有别的变化时不写，有别的变化时写一条警告色浅底的提示；“保存”是这一处唯一的主色，旁边写快捷键（单行“↵”，成段的文字“Ctrl ↵”，Mac 上是“⌘ ↵”），读屏名只是“保存”。预览没回来、或预览返回失败时“保存”不可用，失败时写原因；原因优先于变化。
    - “保存”发布（同一 Spec 输出 8）；成功后确认条消失，焦点回到那个“改”按钮。“取消”与 Escape 放弃，焦点同样回到“改”按钮。
    - 几笔累出来的数，“改设定”的预览返回 `accumulated-value`：确认条写“这个数是几笔累出来的”，并展开它的来历（输出 11），由作者改其中一笔（输出 21）或记一笔。
    - 只在实际模式下可用；“按计划”开着时“改”不可用，按钮的说明是“先不算计划”。条目已删除、命名空间没启用或只读时没有“改”。
17. **记一笔。** 面板的界面里，对选中的字段（planned：通用字段表与人物的界面里，对展开着的数或语义档字段，同样的输入在来历下面）：精确档填变化量（可正可负）与一句发生了什么（[`canon.revisions`](revisions.md) 输出 9），语义档只填一句发生了什么（同一 Spec 输出 23）；落在条目页所选的位置，所选位置是最初时不可用（说明“先选一章”），“按计划”开着时不可用。确认即发布；成功后输入清空，失败时输入留着、原因写在输入下面（输出 29）。
18. **保存后的提示。** 每次本窗口发布成功都给一条提示：这次修订的标题、“查看详情”（打开回执页）、“还原”（还原这次修订，按输出 22）、关闭。就地改与记一笔在标题后面弱一档写这次记在哪：“记在最初”“记在第 3 章”“记在前史”（就地改按确认条预览的写回处，改第 2 章那一笔的写“记在第 2 章”；记一笔是所选位置的那一章）；改条目本身（删除、加一组设定、别名）与主文字不写。编辑区里有条目页、回执页或变更详情页挂着（是某一组的活动标签）时，提示浮在这个页面下方、盖在内容上，出现与收起都不推开内容（页面末尾常留一段空白，至少一条提示高，几条同时在、窄了折行时跟着提示的实际高度，最后几行能滚到提示上方）：同一时间只有一条，新的顶掉旧的；切到这三种页面的另一个标签时它跟过去。提示出现 6 秒后自己收起；指针停在提示上、焦点在提示里、还原的确认框开着时停表，都离开以后接着计剩下的时间、至少再留 0.8 秒（停表期间换了新的提示，从头计 6 秒）；计时是窗口里一份，几个页面同时挂着时共用。点“还原”时提示先留着，还原成功后换成还原的那一条，取消则不变；确认框关上时焦点回到提示里的“还原”，焦点离开以后接着计时。提示收起时淡出，同时在的别的提示行滑到它让出的位置。没有这三种页面挂着时（例如在改动记录里还原，编辑区开着章节正文），提示是一条工作台通知（[`workbench.notifications`](../workbench/notifications.md)，正文是标题，有位置时后面带“（记在某处）”），只有“查看详情”一个动作（一条通知只有一个动作），还原从回执页做；它按工作台通知自己的时长收起。页面自己的写入失败（页头的名字、简介、别名与恢复，加一组设定）同样浮在页面下方，写原因与关闭，不自己收起，读屏念出（`role="alert"`）。已知限制：键盘用户在 6 秒里不一定到得了提示，还原另有改动记录这条路；读屏靠常驻的 `role="status"` 念到新提示。
19. **删除条目。** 条目页页头的“更多”里有“删除条目”：确认对话框写“删除以后，引用它的地方会显示‘已删除的条目’；可以在改动记录里还原”；确认后发布，标签留着并按输出 8 显示已删除，按输出 18 给提示。

### 回执与变更详情

20. **回执页。** 一次修订的回执（[`canon.project`](project.md) 输出 29），任何一次写入都是同一种页面。依次是：标题、谁、什么时候、种类；“改了什么”（新建、修改、删除的对象，一类一节；修改的列出每个字段的显示名与改前、改后；写不出值的改动（启用的数据、初值的依据、认不出的键）只写“改了”，条目自己的字段声明的改动写成“添加了一项：某某”“去掉了一项：某某”“恢复了一项：某某”“一项改名：旧名 → 新名”（几项一起改的连在同一行），同一个字段改了几处（列表的几个元素、主文字的几块）合成一行“改了几处”，结构化的值写“（一组值）”；章序调整的修订只有一节“章序”，列出调整前后的章序，调整前没有章时只写调整后的）；“带来的变化”（发布时存下的那一份，[`canon.revisions`](revisions.md) 输出 6：新出现与消失的待处理、跟着变的值）。条目与剧情变更的名字是到它的页面的链接。页头有“还原这次修订”（输出 22）；它是一次还原时写明还原的是哪一次，并链接过去。参数里的修订不存在时写“找不到这次改动”。回执页不能改别的东西。面包屑是“设定 › 改动记录 › 这次修订的标题”，点“改动记录”显示改动记录视图（同样经 `nbook.view.open`）。
21. **变更详情页。** 一条剧情变更：文字、安放的位置、是已写还是计划、生效状态、讲到它的原句（每句写出处；出处是章节正文的有“打开这一章”）、涉及的条目（链接）、它的每一处改动（“星瑕的存款 −300，依据：估计”）。数的改动旁有“改”：页面顶上出现同输出 16 的确认条，没有意图一项，“会写回哪里”就是这条变更；它改的是这条变更本身（[`canon.revisions`](revisions.md) 输出 8 表里的“改其中某一笔”：读出这条变更、换掉那一处的值，照普通写入预览与发布），读出以后这条变更被别处改过时按输出 29 的 `version-conflict`。变更待定时页头写明原因（与设定冲突，或写入者没把握），并有“改成生效”：同样先预览再发布（同一 Spec 输出 17），校验不过时写第一条原因。“按计划”与位置不影响这一页。参数里的变更不存在时写“找不到这条情节”。面包屑是“设定 › 安放的位置 › 这条情节的文字”（文字太长时截断），只有“设定”可点。

### 底部面板与状态栏

22. **还原。** 改动记录里每条修订、回执页与保存后的提示都能还原。点了先预览（[`canon.revisions`](revisions.md) 输出 11、12）：没有依赖时确认对话框写带来的变化；有依赖时从新到旧列出依赖它的后续修订，给“连同这些一起还原”与“取消”；预览说不能还原时（章序调整 `not-revertable`；补偿里有对决定的修改、需要作者来源 `author-source-required`），对话框只写原因，没有确认按钮。确认后发布一次补偿修订；结果回来之前对话框不关、按钮不可用，失败时原因写在对话框里，成功后关掉并按输出 18 给提示。待处理视图的“强行解除”同样。
23. **待处理视图。** 列表与选中那一条的详情并排（窄于 640 像素时上下排）。列表分三组：“待处理”“只是提示”“已处理”，后两组默认收起，组名后写条数；组内按 [`canon.model`](model.md) 输出 16 的顺序，一页读不完时末尾有“再显示更多”。每条写一句是什么与它的位置。打开视图时选中“待处理”的第一条；选中的那一条在世界变了以后消失时，选中它原来位置上的下一条，没有就不选。详情按种类：
    - 核对点不符：正文写的原句（有“打开这一章”）、算出来的数、嫌疑区间里的每一笔（估计的在前），每笔一个“改这一笔”，打开那条变更的详情页。
    - 待定的剧情变更：原句与原因，链接到它的详情页。
    - 套不上：套不上的那条变更与原因，链接到它的详情页；同一个根因让几条变更套不上时合成一条，写还有几条；根因是让它们套不上的那次修订（[`canon.model`](model.md) 输出 16）时写它的标题，链接到它的回执页。
    - 别的种类（章已删除、世界线与时间的几种、插件的诊断）与“只是提示”“已处理”两组里的：一句说明与它指向的对象的链接；已处理的另写作者当时的决定。插件的诊断写它声明的显示名（[`canon.project`](project.md) 方法表的 `pending`），声明已经不在时写“插件的一项检查”。
    一页最多为 50 个对象另读文字与位置，选中那一条的详情要的排在最前；超出的行只写种类（“一条情节套不上了”），不写位置。详情里世界线的几种不写线（线没有给作者看的名字），时间的几种只写一句与变更的链接，插件的发现只写显示名与相关对象、不写它的参数。
    结果不完整时（同上），列表顶上写哪些检查没算出来、被截断、因插件停用没有算，写显示名。别人正在独占写入时，列表顶上写是谁，并有“强行解除”，要二次确认。
24. **改动记录视图。** 按版本从新到旧列出修订（[`canon.revisions`](revisions.md) 输出 14）：标题、谁、什么时候、带来的变化的一句摘要；每条有“查看详情”与“还原”（章序调整与有依赖的，列表里已经知道，按钮旁写原因）。可以按章、按写入者筛。一页读不完时末尾有“再显示更多”；世界变了以后，已经读出来的条数原样重读，滚动位置不变。
25. **状态栏条目。** `nbook.canon/hasPending` 为真时显示“待处理 N”，警告状态，点了执行 `nbook.canon.show-pending`；为假、窗口没有绑定项目、世界还没读到时不显示。N 是缺省位置、实际模式下“待处理”一组的条数，与待处理视图里那一组名后的数相同；底部面板入口条上的“待处理”入口与面板头写同一个数（视图的 `badge`，[`workbench.views`](../workbench/views.md) 输出 17），为 0 时不写。

### 读取、失败与可达

26. **新鲜度。** 世界发布新修订（本窗口或别处）以后，前台可见的内容重读并原地替换：重读期间保留旧内容，不出现空白或加载占位；不可见的标签与视图回到前台时先显示上次读到的内容，同时重读。本窗口的一次写入成功返回时，界面已经按它的版本重读，不等事件。短时间里接连几次发布，可见的内容只重读到最后那一版。第一次读取期间显示加载占位。章节正文变了、语义档的归纳补算完成、章表或登记的类型变了（[`canon.project`](project.md) 输出 34）以后，受影响的内容同样重读。
27. **断开与重连。** 与项目实例的连接中断后重连成功时，内容按当前版本重读。订阅被提供方结束（项目实例停止）以后，三种页面与三个视图顶上都有一条横幅“世界已断开”与“重试”；这期间写入入口全部不可用，已显示的内容留着；“重试”成功后横幅消失、内容重读。
28. **写不了的时候。** 世界只读时（`world-read-only`、`write-unknown`），三种页面顶上有一条横幅写原因，所有写入入口不可用。别人正在独占写入时（`busy`），写入入口不可用，说明里写是谁在写（它申请独占时给的那句），独占结束后自动恢复。
29. **写入失败。** 发布被拒收时，确认条或对话框留在原处、写出原因，作者填的内容不丢：`value-conflict` 写“这个值刚刚变了”并把读到的值换成新的，要作者再点一次“保存”；`version-conflict` 写“这个对象刚被改过”，重读并重新预览后要作者再点一次；`validation-failed` 写第一条校验不过的原因（服务给的说明，原样）；`result-mismatch` 写“写完的结果对不上”与读回的值（读不回时写“未知”）；`write-failed` 写“没有写进去，可以再试一次”；`world-locked` 写“另一个 NeuroBook 正在用这部作品，稍后再试”；`too-large` 写“这次改动太大，分开改”。断线使写入结局不明时（`unknown-outcome`），界面按请求 id 查结局（[`canon.project`](project.md) 的 `outcome`）后再报成功或失败，查不到时写“不确定这次改动有没有写进去”，并给“再查一次”；重试用同一个请求 id（[`canon.revisions`](revisions.md) 输出 24）。别的失败写“这次改动没有成功”与服务给的说明，不把码给作者看。
30. **键盘与读屏。** 树、列表、分页、值、确认条、对话框都能只用键盘操作：分页用左右方向键切换；待处理与改动记录的列表用上下方向键移动，移到哪条详情就显示哪条；值按钮与“改”按钮各是一个 Tab 停靠点，值在前；Enter 或空格展开、收起来历。确认条出现时焦点进输入控件，保存或取消后回到“改”按钮（输出 16）。横幅与保存后的提示用 `role="status"`，写入失败的原因用 `role="alert"`。只有图标的按钮有可读的名字。
31. **界面文字。** 界面文字都经界面文字机制给出（[`ui.i18n`](../ui/i18n.md)）；条目的名字、剧情变更的文字、原句是作品内容，原样显示。
32. **宽度。** 条目页、回执页、变更详情页的内容列都封顶；条目页的页头、分页与内容同一个上限、左边对齐，内容净宽 760 像素（竖排分页另占 200）。宽度 390 像素时：页头换行，“在看”换到标题与简介下面、占满一行；人物分页立绘在上、短资料一行一项；面板的界面上下排（值卡在上、流水在下）；三种页面与待处理、改动记录两个视图都没有横向滚动（横排的分页条在自己里面滑动，输出 9，不算）。设定视图在侧栏里，390 宽时工作台把侧栏让给编辑区，它不显示。
33. **底部面板默认不显示。** 第一次生成布局时，底部面板不因为“待处理”“改动记录”这两个视图而显示（两个视图声明 `revealRegion: false`，[`workbench.views`](../workbench/views.md) 输出 18）。两个视图各是底部面板里的一个隐式容器，底部面板的入口条（[`ui.workbench-layout`](../ui/workbench-layout.md) 输出 47）上各是一个入口，排在后台任务与通知前面；也经状态栏条目、`show-pending`、`show-revisions`、回执页的面包屑与“打开视图”到达。

### 线、读取服务与附加分页（planned）

34. **窗口在看的线。** 一个窗口有一条在看的线：公开状态 `nbook.canon/line`，值是线的 id，空串是“按章节自动”（读取位置不写线，按 [`canon.worldlines`](worldlines.md) 输出 12 取那一章讲的线）。缺省按章节自动，不存盘，刷新以后回到按章节自动。可选的线：主线，加实际模式下存在而且可建的线（`lines` 不列主线，界面补上），按线的树缩进。
    - 状态栏条目 `nbook.canon.line`（右侧，`nbook.canon/lineReady` 为真时显示）：只有主线时写“故事线：主线”；有两条以上线时，按章节自动写“故事线：按章节自动”，选了线写“故事线：线名”。它是窗口一份，不写各页自己的时间点。点了执行 `nbook.canon.pick-line`：快速选择里第一项“按章节自动”，其后是可选的线；选了改公开状态。
    - 条目页与剧情侧的页面（[`plot.author-ui`](../plot/author-ui.md)）的读取位置都带上窗口的线（按章节自动时不带）。页头的“在看”（输出 7）里有“故事线”一段（不止一条线时），改的是窗口的那一个；按钮上写的线名在按章节自动时取章表里这一章讲的线（已知限制：章讲的是还只是计划的线时，实际读的是它最近的实际祖先，这里仍写主线）。只有主线时“在看”不提线。
    - 换线不改页面的位置：在子线上读切口之前的章，读到的是共同的过去（同 `canon.worldlines` 输出 12）。前台可见的内容按新线重读，重读期间保留旧内容（同输出 26）。
    - 本入口一直读着线表：选着的线不在了（不存在、不可建、只剩计划线）时回到按章节自动；下一次打开快速选择时标题写“原来看的那条线已经不在了”。回到按章节自动之前的那一轮读取可能得到 `line-not-found`：有旧内容的页面留着旧内容；没有旧内容时，剧情的页面写“这条线读不到”，条目页写通用的读取失败。
    - 条目页的标签标题固定按缺省位置、不带窗口的线读。
35. **读取服务。** 本入口给别的浏览器入口交 `canonReadsKey`（整个窗口一份；窗口没有绑定项目时它的连接是 `no-project`、组合函数都给 null，调用方写“打开作品后可用”）。它交出：
    - 读世界的组合函数（同本能力自己用的：读、列表；换输入时旧内容接着显示，新的读到才换）；章表也经它读（同一个读取在几处用只读一次）；
    - 外部读取：调用方把自己的远程读取（一次性的，或分页的列表）挂进同一份读取层。键是调用方插件 id、方法名与输入，取数只由输入决定。外部读取与世界读取同一代失效、同一轮重读与换上；连接断开、订阅结束与 `retry()` 也是同一份（输出 26、27）：连接在线时 `retry()` 把读失败了的读取（世界的与外部的）再读一次，不等世界下一次变化。插件的诊断数据版本变了（`inputChanged` 的 `diagnostics`）同样整代失效。取数抛错时这个读取得到失败 `external-failed`，不影响同一轮别的读取；结果带的世界版本比本入口已知的旧时，下一轮再读。外部列表一页最多 200 条；重读时按真实页长从头翻到已读的条数，翻的过程中读取输入变了就从头再来，同一份读取输入的各页齐了才换上。
    - 窗口的线（只读）与改它的入口、可选的线；
    - 页头组件：标题、“在看”（同输出 7：故事线、位置与“算上计划中的情节”，出现的条件与标记都同条目页）与断开、只读的横幅（输出 27、28）；本能力的条目页有自己的页头，与它共用“在看”与横幅。
36. **附加分页。** 贡献点 `canon.entry-tabs` 给条目页加不对应命名空间的分页：只接受浏览器入口，必须交实现，贡献 id 按插件 id 的前缀校验（同 `canon.component-views`；`requires` 可以指向别的插件的类型）。声明 `{title?: Text; requires: string; order?: number; icon?: string; needsChanges?: true}`（`icon` 是分页的图标，写法同 `canon.component-views`，不写时用通用的看法图标；`needsChanges` 见输出 9）：条目在所选位置上启用了 `requires` 那个 Component 类型（条目读取结果里的启用类型）时出这个分页，换到还没启用的位置时分页消失、选着它的标签回到第一个分页；附加分页排在数据分页之后、“情节”之前，按 `order` 再按贡献 id。实现 `load()` 交组件，组件收到 `{context: EntryTabContext}`：`entry`、`position`（带窗口的线）、`mode`、`version`、`state`（按贡献 id 存在标签上，寿命同输出 7）、`place(at)`、`open(ref)`；没有写入入口。贡献方停止后这个分页消失，选着它的标签回到第一个分页。

45. **暂存。**（planned）编辑中的内容自动暂存在这部作品的本机记录里（[`storage.persistence`](../storage/persistence.md)），一个条目一份：输入停顿、输入框失焦、页面转入后台时写。刷新、关掉标签或窗口以后再打开这个条目，直接进编辑并带着暂存的内容。暂存不是修订：不进改动记录，别的读取（含 Agent 的工具）看不到。那一行写“已暂存”（存下去的就是页面上现在的内容时才写）；存不下或写不进去时写“没有暂存”，内容留在页面上，这时关掉会丢；写不进去的（连接断着）在输入框失焦、页面转入后台与重新连上时再存。“放弃”先确认，确认后删掉暂存、回到阅读视图；放弃以后迟到的写入不会把它写回来。暂存删不掉（连接断着）时不离开编辑，写明暂存没有删掉、连上以后再放弃：否则重开以后它又回来。放弃还没完成（等存储删掉）时不提交、不确认。同一个条目在这个窗口的两个编辑组里各开一页时是同一份稿，两处同时点“编辑”只开一份。打开条目时连接断着、没读到暂存的，不当成没有稿：连上以后再读，这之前不能开始编辑。改回与读到的一样就不算有未提交的内容，暂存随之删掉。同一个条目在另一个窗口里也在编辑、并且那边先写了暂存时，这个窗口停止自动暂存、写明“另一个窗口也在改这个条目的文字”，由作者选“用这里的”或“换成那边的”，两边都不自动丢。选了“用这里的”以后重读一遍；那边有一次提交还在等结果（输出 46）时不覆盖它，写明先换成那边的。最后一次输入到关窗不足一秒时可能来不及暂存。
46. **有未提交的主文字时。**（planned）这个条目的标签显示未保存的圆点，不在前台时也显示（[`workbench.editor`](../workbench/editor.md) 输出 68）。条目页的“在看”（位置、线与“算上计划中的情节”）锁在开始编辑时的位置上（内核解析后的位置，写明线；菜单开着时关上），要换先提交或放弃。世界变了（别处的写入）不动编辑中的内容、也不提示，提交时按输出 44 处理。世界只读、别人独占写入、连接断开、条目已删除时“提交”不可用，原因写在那一行，暂存留着；这时用 Ctrl+S 提交不发，原因照提交被拒的说明显示（同一句不写两遍），原因没了就收起。条目已删除时页面写“这个条目已删除”，稿列在它下面：能看、能复制、能放弃。开始编辑时的位置读不出来了（那一章被删、那条线不在）：编辑区只读地显示稿（能复制），只能放弃；条目页别的内容回到这一页自己的位置上读，刷新、重开以后也是这样。提交发出后没收到结果的（断开、刷新）：那一行写“正在确认上一次提交”，输入框只读，连上以后把同一个请求原样再发一次（[`canon.revisions`](revisions.md) 输出 16：已经发布过就拿回那一次的结果，不会多出一条修订）；在得到确定的结果之前不发别的请求，这期间再按提交等于再确认一次，可以放弃（只丢本机的稿）。“确定的结果”是：已经发布；或内核判过这个请求以后的拒收（世界变了、原文没过校验这些）、日志明确没有写进去，这时稿还在、可以再提交（“没有发布”要先记进暂存；记不进去时仍按等着结果处理，存储好了再确认）。查到“没发布”、被别人的独占或世界只读拦下、连不上都不算，仍然等着。请求发出之前要先连同稿一起写进暂存（冻结）并确认写下去了：没写成的不发、稿照常能改；写下去而回执丢了的，按没收到结果处理，再确认时先核对暂存里有它、没有就补上，补不上不发。刷新、重开以后读到等着结果的稿，自己去确认（不用页面开着）；确认出没有发布时稿回到能改的样子，那一行写明上一次提交没有发布或失败的原因。提交在途时不能放弃、不能改。

49. **人物分页。** 内置人物（`nbook.canon.person`）的数据分页：左边是立绘，右边一行一项的短资料（性别、年龄、身份、所属、现在在哪、生死，再是这个条目上自己加的各项与“添加一项资料”），下面是现在的状态，再下面是性格、说话方式、背景三段文字（planned）。立绘读自同一条目上的形象这一组（`nbook.canon.look`）：有立绘时是图，点了切到形象分页；有形象、没有立绘时是“添加立绘”：切到形象分页并打开立绘的选择；没加过形象同样写“添加立绘”，去掉过是“恢复形象”：先给这个条目加上那一组（输出 38 的同一次写入），成功后同样切过去、打开立绘的选择；类型不可用时这一格空着。形象在所选位置上还没启用时写“第 N 章起有形象”（planned）。加上形象被拒时原因写在立绘下面（planned）。立绘的来历到形象分页看。自己加的列表（Agent 能加别的种类）卡片画不成一行，在下面嵌一节通用字段表（输出 12），不从这一页消失。宽度不够时立绘在上、资料排成一列；宽窗口里内容列封顶，立绘按比例裁切、不随窗口变大（planned）。刚新建的人物短资料每一项写“填写”，成段的文字写一句说明这一段写什么的提示。

51. **专门界面里的就地改。** 人物、形象两个分页里，值本身是按钮，点了就改（写不了时按钮不可用、悬停写原因，同输出 16 的“改”），不出页面顶上的确认条，输入在这一项上：短的（短文字、有建议值的文字、图片）在锚在这一项上的浮层里，引用也是（planned）；成段的文字在原处展开同一张编辑卡（原文藏起来，后面的内容往下让，不被盖住；收起时原文立刻回来接住焦点）；打开时整个滚进可见范围（在页面下方打开时保存不在窗口外）。浮层不越出条目页（编辑区）。编辑卡里的东西同输出 16：输入、选着剧情里变了时的“发生了什么”、有别的变化时一条提示（多于一条时收成“还有 N 项”，整句在悬停提示里）或原因、最下面一行是意图二选一与取消、保存；浮层用玻璃的面。浮层里的短项是单行的输入框，回车就是保存：预览还没回来时等它回来，除了这一项没有别的变化（没有多出、少了的待处理，没有跟着变的值，没有套不上的）就直接保存，有就停在预览上给作者看、不保存。有建议值的文字是一个输入框，建议值嵌在编辑卡里、列在输入框下面（不另弹一层）：打开时列出全部、当前值打勾，打了字才筛；点一条是把它填进输入框，也可以直接写别的；引用是条目选择器（planned）。短项的浮层：点浮层外面、按 Escape、点“取消”都是放弃这次填写，草稿不留。成段的文字按 Escape 或“取消”放弃，Ctrl（或 ⌘）加回车保存；点编辑层外面不收起，填了一半切到别的分页、别的标签再回来还在（同输出 7）。保存请求在途、Escape 落在输入法组字里时不算放弃；图片上传在途时也不算（planned）。保存或放弃以后焦点回到这个值。保存失败回来时这次填写已经放弃（作者点了外面或换了别的字段）就不写回（planned）。值在所选位置之前被剧情改过时旁边有“第 N 章改过”，它也是按钮；点了在浮层里看来历，只有初值的值没有这个入口（planned）。语义档的项点了展开细节：起点与之后记下的各句、“记一句”（输出 17）与改起点。别的数据分页照旧用确认条；专门界面还在加载、加载失败或贡献方停了时也用确认条（planned）。
52. **添加一项资料。** 人物分页的短资料里有“添加一项资料”（人物这一组允许实例字段，[`canon.components`](components.md) 输出 4），排在各项之后（planned）：浮层里列类型的预设里这个条目还没加的各项、去掉过的各项（写“恢复‘某某’”），另有一栏自己写名字（本期只加文字的项）；选了或写了就加上。新的一项是未知、排在自己加的各项最后（planned）。被拒时原因写在那一栏下面（例如名字与已有的一项相同）。自己加的项行尾有常显的“更多”：改名、去掉；去掉时确认里写“数据会保留，可以恢复”（planned）。
53. **图片的显示、选与上传。** 图片按作品内路径显示，懒加载；文件不在时画“图片找不到”的占位（[`canon.components`](components.md) 输出 15）。选图片的地方（确认条、元素对话框、专门界面的浮层）是同一个版式：作品的图片文件夹（作品设置里的那一项，缺省“插图”）里按名字倒序的前 12 张缩略图（这一页刚上传的排在最前；每处选图片的地方打开时重列，上一处的原因不带过来）、“上传”、说明一栏，另可手填作品内路径。上传只收 PNG、JPEG、GIF、WebP，不超过 32 MiB，存进那个图片文件夹，重名时用实际存下的名字；可以按 Escape 取消（取消以后写一句“图可能已经写进作品”，不算失败）。失败分三种：类型或大小不合；网络失败或结果不明（图可能已经写进作品）；别的。原因写在选图片的地方，结果不明时写完重列一次（planned）。上传进作品的文件放弃填写、撤销修订都不删（planned）。窗口里没有文件服务时没有缩略图与上传，只剩手填路径与说明。图片文件在别处被换掉以后，重新打开页面才看到新图。

## 状态与转换

页面标签（条目页、回执页、变更详情页）的状态：

| 状态 | 条件 | 表现 |
|---|---|---|
| 加载中 | 第一次读取还没回来 | 加载占位 |
| 正常 | 读到了对象 | 输出 6 到 21 |
| 找不到 | 参数指向的条目、修订或变更不存在 | 一句“找不到……”，没有写入入口 |
| 已删除 | 条目已删除 | 输出 8 |
| 断开 | 订阅被提供方结束 | 输出 27 的横幅，内容留着 |

时序与寿命：

- 一次写入从点“保存”到结果回来之间，触发它的确认条或对话框的按钮不可用，别的写入入口照常；结果回来以后才给输出 18 的提示。
- 预览只对它基于的版本有效。确认条开着时世界版本变了：这个值没变，预览自动重取，重取回来之前“保存”不可用；这个值变了，按输出 29 的 `value-conflict` 处理，不等作者点“保存”。
- 页面标签的状态（输出 7）随标签：切走再回来不变（页面不在前台时组件已经卸载，状态在标签上），关闭后丢弃；刷新后恢复的标签只恢复“是哪个对象”与标题。
- 贡献 `canon.component-views` 的插件停止后，用它界面的数据分页立刻换成通用字段表；它重新激活后换回（运行时没有单独停一个插件再激活的接口，停用与启用插件要重启）。
- 本能力的入口停止后，三种页面的标签显示编辑器的“这个页面已经不在了”，三个视图按 [`workbench.views`](../workbench/views.md) 的声明消失处理。

## 副作用与数据

本能力不存自己的数据。写入都经世界服务发布成修订（[`canon.revisions`](revisions.md)）。开着哪些页面标签由编辑器记（[`workbench.editor`](../workbench/editor.md) 输出 5、33）；面板显不显示、视图在哪由工作台的布局文档记。

## 失败与恢复

界面自己不产生失败码；世界服务的失败码（[`canon.project`](project.md) 与 [`canon.revisions`](revisions.md) 的失败表）按下表呈现。

| 码 | 界面上 |
|---|---|
| `no-project` | 视图里“打开作品后可用” |
| `world-read-only`、`write-unknown`、`busy` | 输出 28 |
| `value-conflict`、`version-conflict`、`validation-failed`、`result-mismatch`、`write-failed`、`world-locked`、`too-large`、`unknown-outcome` | 输出 29 |
| `accumulated-value`、`incomplete-field`、`intent-not-allowed`、`field-unavailable` | 输出 16、17：界面按字段的状态不给出会得到它们的入口；仍然得到时按输出 29 的“别的失败” |
| `has-dependents`、`not-revertable`、`author-source-required` | 输出 22 |
| `cursor-stale` | 按已读的条数重读（输出 24） |
| `request-id-reused` | 界面每次写入用新的请求 id、重试用原来的，不该出现；出现时按输出 29 的“别的失败” |
| `chapter-not-found` | 输出 7 |
| `stopping`、订阅结束 | 输出 27 |

## 边界与兼容

- 公开接口：上表的视图、页面、状态栏条目、公开状态与命令的 id 与参数；贡献点 `canon.component-views` 的声明、实现与 `ComponentViewContext`。组件的名字与内部状态不是公开接口。
- 界面只经世界服务读写世界，不直接读世界日志的文件。

## 验收与 Smoke

1. **星瑕的一周。** Given 脚本生成的星瑕样本项目，When 打开作品，Then 侧栏有“设定”，树里“哥哥”在“星瑕”下面；When 点“星瑕”，Then 开出条目页，位置是最新一章末尾，标签标题是“星瑕”，面包屑是“设定 › 人物 › 星瑕”；When 打开“哥哥”，Then 面包屑是“设定 › 人物 › 星瑕 › 哥哥”，点其中的“星瑕”切到星瑕的条目页；When 在“在看”的菜单里选第 1 章的“末尾”，Then 菜单关上、按钮写“第 1 章末尾”，文字里的值与面板的值卡换成那时的；When 点“往后一处”，Then 按钮写“第 2 章开头”；When 点存款，Then 来历列出“最初”与每一笔，估计的那笔是警告色并带“估计”。
2. **两个条目页各有各的状态。** Given 星瑕的条目页在“第 1 章末尾”、展开着存款的来历，When 打开星瑾的条目页再切回来，Then 星瑕的页还在“第 1 章末尾”、来历还展开着，星瑾的页在缺省位置；When 在星瑕的页点一个值的“改”、填一个数但不保存，切到星瑾的页再切回来，Then 确认条与填的数还在；When 刷新窗口，Then 两个标签都还在、标题是两个人的名字（没有点开的那个也是），位置都回到缺省。
3. **就地改与回执。** Given 条目页在最新一章末尾，When 改一个只在初值设过的字段，Then 二选一写“从最初起”“从第 3 章起”、缺省是前者，没有别的变化时不写预览；When 保存，Then 值变了，页面下方浮出提示、写着“改<字段>”与“记在最初”，页面内容不动；When 指着提示点“还原”并确认，Then 值回到原样，提示换成还原的那一次；When 指着它点“查看详情”，Then 回执页列出这个字段的改前改后，改动记录里多了两条。
4. **累出来的数。** Given 存款是初值加几笔加减，When 点它的“改”并填一个数，Then 确认条写“这个数是几笔累出来的”、展开来历、“保存”不可用；When 在面板里记一笔 −200，Then 流水末尾多一行、值卡的数少 200。
5. **待处理。** Given 样本里第 2 章正文写的余额与算出来的不同，Then 状态栏有“待处理 1”；When 点它，Then 底部面板显示、选中那一条，详情里有原句与嫌疑的几笔；When 点“改这一笔”，Then 开出那条变更的详情页；When 点那处改动旁的“改”、填成对得上的数并保存，Then 这一条从“待处理”消失，状态栏条目消失。
6. **有依赖的还原。** Given 修订 A 之后修订 B 改过同一个字段，When 还原 A，Then 对话框列出 B，选“连同这些一起还原”后两处都回到 A 之前。
7. **别处的写入。** Given 条目页开着，When 另一个进程发布一次改了这个条目的修订，Then 页面上的值原地更新，没有出现加载占位；位置、分页不变。
8. **只读与独占。** Given 世界只读，Then 页面顶上有横幅、“改”“记一笔”“还原”都不可用；Given 另一个调用方持有独占写入，Then 写入入口不可用并写出它申请时给的那句，它释放后自动恢复。
9. **专门界面的回退。** Given 一个测试插件给它登记的类型交了界面，When 它停止，Then 那个数据分页换成通用字段表；When 它重新激活，Then 换回。
10. **新建与删除。** When 在“星瑕”下面新建一个种类是“物品”、启用面板的条目，Then 树里出现它、开出它的条目页、有提示；When 删除它，Then 它的页显示“这个条目已删除”，树里不再列出；When 在改动记录里还原删除，Then 它回到树里。

11. **只用键盘改一个值。** Given 条目页的数据分页，When 用 Tab 走到一个值的“改”、按 Enter、填新值、Tab 到“保存”按 Enter，Then 值变了，焦点回到那个“改”按钮；When 再按 Enter 后按 Escape，Then 确认条消失、焦点还在“改”按钮。
12. **没有页面在前台时的还原。** Given 编辑区前台是一个章节文件，When 在改动记录里还原一次修订并确认，Then 对话框在结果回来后关掉，出现一条通知，带“查看详情”；Given 这次还原被拒收，Then 对话框不关、写出原因。
13. **来历很长。** Given 一个有 50 步来历的数，When 点它，Then 展开处先列最近 20 步与“最初”一行，末尾写“再显示更早的（还有 29 步）”；When 点它，Then 接着列出。
14. **窄屏。** Given 宽度 390 像素，Then 条目页的页头换行、“在看”换到标题下面，分页横排、每页写名字，放不下时在分页条里滑动，在宽屏上选了最后一页再变窄时它仍看得见，面板的界面值卡在上、流水在下，三种页面与待处理、改动记录两个视图都没有横向滚动。
15. **从空作品起步，作者与 Agent 都能改（planned）。** Given 一部空作品，Then 设定视图是空状态；When 点“新建人物”、填名字并新建，Then 开出它的条目页；When 改外观、在文字分页加一段、加一个别名，Then 页上都看得到。When Agent 经 `canon_write` 建一个组织与挂在它下面的人物（带外观与一段主文字）并被批准，Then 树里有它们、条目页读得到初值；Given 一个条目页开着，When Agent 再写一次，Then 页上出 Agent 提示；When 从提示还原，Then 那次写入建的条目从树里消失。
16. **整篇编辑主文字（planned）。** Given 空作品里新建的一个启用面板、声明了字段“魔力”并填了值的条目，When 在文字分页点“开始写”、写两段、从“插入”里选“魔力”，Then 旁边的预览里出现这两段与魔力当时的值；When 点“提交”，Then 阅读视图里是这两段与魔力当时的值，改动记录多一条，这个条目的主文字是一块；When 点“编辑”、改一句但不提交、刷新窗口，Then 这个条目的标签带圆点，打开它直接在编辑里、改的字还在；Given 这时另一处把主文字改成了别的，When 点“提交”，Then 问一次、并排两份整篇，选“现在的”以后阅读视图里是别处的那一版、圆点没了；Given 另一处改的是这个条目的一个字段，When 点“编辑”、改一句并提交，Then 不问，直接发布。Given 一个条目的主文字里有一块在第 3 章被剧情改过，When 点“编辑”，Then 留在阅读视图，页头下面写着这个条目的文字里有随剧情变的段落。

## 实现合同

- **公开入口**：插件 `nbook.canon` 的浏览器入口（上表的视图、页面、状态栏条目、公开状态与命令）；数据分页的贡献点 `nbook/plugins/canon/shared/component-views`（`CANON_COMPONENT_VIEWS_POINT`、声明的校验），实现与 `ComponentViewContext` 的类型在 `nbook/plugins/canon/web/component-views`。
- **owner 与依赖方向**：界面属于 canon 插件的浏览器入口，经它自己的世界客户端（`nbook.canon/world` 远程合同）读写；依赖工作台、编辑器、文件、命令与通知各插件的公开合同；浏览器代码在运行时只引 nb-canon 的 `./schema` 子路径（主入口带着渲染链，在 Vite 开发模式下加载不了）。树键盘与右键菜单由 nb-ui 的 `Tree`、`ContextMenu` 提供，分页切换由 nb-ui 的 `Tabs` 提供。
- **关键不变量**：
  - 窗口里一份读取层：同一个读取在同一读取输入上只发一次，世界换代整代作废、只重读在用的，重读期间保留旧内容（输出 26）：[`world.dom.test.ts`](../../../packages/neuro-book/src/plugins/canon/web/world.dom.test.ts)“同一个读取在两处用只发一次；连续几次发布以后停在最后那一版，重读次数不多于发布次数”。
