# 世界引擎：修订、发布与还原

## 目标与非目标

作者与 Agent 都能改世界，所以每一次写入（作者在界面上保存、Agent 的一次写入、一章的记账、后台任务的结果、章序调整）都是一次修订：原子发布、版本加一、过期报冲突、存改前与改后的值、发布时算好“带来的变化”、能还原。本能力定义写入请求、校验、预览与发布、冲突、就地改、改动记录与还原。对象与计算见 [`canon.model`](model.md)；写入怎样排队、落盘、独占见 [`canon.project`](project.md)。

不承诺：

- 经文件改设定（导出、旁车、块标记、导入）：第一版没有这条路（[ADR 0039](../../adr/0039-world-engine-segmented-revision-log.md)）。
- 按任意历史版本重新计算；还原只承诺“恢复成改前的值”。
- 多人协作与分支合并。
- 恢复的旧值按 schema 版本升级：第一版没有升级函数（[`canon.components`](components.md) 输出 11）。
- 还原时检查后面的修订是否“读过”被还原的值：依赖只按写入的地址算（输出 12）；还原后重算，后面因此套不上的进待处理。

## 术语与参与者

- **修订**：一次发布的写入，改动记录里的一条。
- **写入请求**：要发布的内容：一组对象的新值，加上谁、为什么、基于哪个版本。
- **版本**：世界的整数版本号，空世界是 0，每次发布加一。
- **预览**：对写入请求做发布时的全部计算，不发布。
- **带来的变化**：一次修订让世界有了哪些可见的变化：待处理的增减、相关值的改前改后、让后面哪些记录套不上。发布时算好、存进修订。
- **创作修改与剧情变化**：创作修改改的是设定本身（初值或给出这个值的那条记录），所有位置都跟着变；剧情变化是在某个位置上新记一条剧情变更，只影响之后。
- **就地改**：在某个读取位置上看到的值上直接改，由程序按来历决定写回哪条记录。
- **补偿修订**：还原时发布的修订，把被还原的修订改过的东西恢复成改前的值。
- **依赖**：后面的修订建立在被还原的修订之上（输出 12）。
- **请求 id**：调用方给一次写入请求取的稳定 id，用来在断线后查结果、防止重复发布。

## 输入与前置条件

**写入请求**

| 项 | 意思 |
|---|---|
| `requestId` | 调用方生成的稳定 id（输出 16） |
| `by` | 作者、Agent 会话（带会话 id）、后台任务（带任务名）或系统 |
| `what` | 种类：`opening`（开局）、`plan`（提计划）、`bookkeeping`（记账）、`edit`（作者保存）、`creative`（Agent 的创作修改）、`resolve`（处理待处理）、`suggest`（给正文建议）、`revert`（还原）、`reorder`（章序调整） |
| `title`、`why` | 一句标题；可选的原因 |
| `chapter` | 可选，这次写入关于哪一章 |
| `baseVersion` | 写入者读到的版本 |
| `puts` | 一组 `{ref: {kind, id}, after}`：对象的新值，`after` 为空表示删除（哪些对象能删见输出 20）；新建对象的 id 由程序生成，请求里用临时 id，发布后给出对照 |
| `reads` | 就地改、记一笔与回写必须给（输出 19）：读到的 `{地址, 读取位置, 值, 来历}` |
| `notes` | 可选，附注（例如记账时“没建条目”的名字） |

**存下来的修订**（世界日志的持久化格式，见 [`canon.project`](project.md)）：`{id, version, requestId, time, by, what, title, why?, chapter?, baseVersion, ops, notes?, reverts?, impact}`。

- `ops` 的每项是 `{ref, kind: "create", after}`、`{ref, kind: "modify", fields}`、`{ref, kind: "delete", before}`，或章序调整的 `{kind: "chapters", before, after}`（两份章 id 的列表）。
- `fields` 的每项是 `{path, before?, after?}`：没有 `before` 表示改之前这个字段不存在，没有 `after` 表示改之后不存在；JSON 的 `null` 是“未知”，与“不存在”不同。
- 路径的写法：对象的键用 `.键`；有 id 的列表（主 MDX 的块、列表字段的元素）用 `[id]`，不用下标；没有 id 的数组（别名、讲述、补丁、连接、提示）整体是一个叶子。
- 修改只存变了的叶子。`impact` 是带来的变化（输出 6）。

**由程序转成写入请求的几种写法**：就地改（输出 8）、记一笔（输出 9）、文字替换（输出 10）、Agent 交回改过的一块（[`canon.rendering`](rendering.md) 输出 12）、还原（输出 11）、章序调整（输出 13）。

## 输出与可观察行为

1. **原子发布。** 一个写入请求要么整个发布、版本加一，要么整个拒收、世界不变。跨条目的修改（转账两边）在同一次修订里。
2. **存改前与改后。** 新建存整份新值，删除存整份旧值，修改只存变了的叶子的改前与改后；命名空间里的值带类型版本。
3. **写入时校验。** 发布前在当前世界上检查，任何一项不过就整次拒收（`validation-failed`），详情逐条列出（码、对象、路径、说明）：
   - 引用的条目存在、没删除，在剧情变更的安放上已出场；剧情变更对命名空间的数据字段打补丁时，它在安放上已启用、没去掉（`启用` 字段本身、初值与创作修改不受限）；
   - 字段在声明里、值的类型与范围对得上（[`canon.components`](components.md) 输出 14、15）；新 id 不与已有的重复；
   - 条目树与身份同一的约束（[`canon.model`](model.md) 输出 23）；`lines` 指向剧情线条目；
   - 连接与种类对得上：`fulfills` 只能从已写变更指向计划；`replaces`、`splitFrom` 只能从计划指向计划，`splitFrom` 的 `by` 是一条指向同一计划的 `fulfills` 变更；不能指向自己；`replaces` 不成环，一个计划同时最多被一个生效的计划替代；
   - 新写、改过、或从待定转为生效的生效剧情变更，在它的安放上能套上（含约束，在一条变更的补丁全部套完之后检查）；
   - 来源为正文的讲述（含条目的 `retold`），原句确实在那一章的正文里（正文由宿主提供，[`canon.project`](project.md) 的输入）；
   - 每个数有依据：讲述里的原文（原句存在，且按中文与阿拉伯数字的常规读法能从原文里读出这个数，加减取绝对值）、由某个核对点推出的差额（程序复算相等）、作者给的，或补丁上标“估计”；都没有就拒收；
   - 主 MDX 的每一块过白名单，块的规则成立（[`canon.rendering`](rendering.md) 输出 1 到 3）。
4. **对后面的影响。** 这次写入让后面已有的剧情变更套不上的，不拒收，列进预览与带来的变化（“这次修改会让第 7 章的 2 条套不上”），这些问题记在这次修订名下（它们的根因，[`canon.model`](model.md) 输出 22），可以直接还原它。
5. **预览。** 对写入请求做输出 3、4、6 的全部计算，不发布：返回校验结果、带来的变化，以及受影响的条目在这次写入所在章末尾（没有章时在缺省读取位置）的样子。预览只对它基于的版本有效。在同一版本、同样的章序、正文与已登记的类型上，预览算出的带来的变化与随后发布存下的逐字相同（语义档的归纳文字除外）；中间有别的修订发布或这些输入变了，以发布时算出并存下的为准。
6. **带来的变化。** 发布时计算并存进修订：在哪（位置的说法）；这次让哪些待处理消失、新出现了哪些；相关地址在这次写入所在位置的改前与改后（显示名与值；语义档写当时的值，含“未归纳”的写法）；让后面哪些记录套不上。回执、保存后的提示、改动记录都读存下来的这一份，不重算。
7. **版本冲突。** `puts` 里的对象在 `baseVersion` 之后被别的修订改过（新建、修改或删除），整次拒收（`version-conflict`），详情列出这次请求涉及的全部对象，标出哪些被改过、它们现在的值。没被改过的对象不算冲突，即使世界版本已经前进了。
8. **就地改。** 调用方给出读取位置、地址、新值、读到的值与来历，以及意图（缺省为创作修改）。发布前重算这个位置的值，与读到的不同就拒收（`value-conflict`）。按来历的形状路由：

   | 这个值来自 | 创作修改写回 | 剧情变化 |
   |---|---|---|
   | 只有初值 | 改初值 | 在这个位置新记一条变更 |
   | 某条变更的赋值、整段替换、增元素、增块（之后没有加减、事件） | 改那条变更里的那个补丁（增元素、增块改的是它带的值） | 同上 |
   | 初值或赋值之后又有加减（几笔累出来的数） | 拒收（`accumulated-value`），详情给出来历；改其中某一笔，或记一笔 | 记一条加减（新值减读到的值） |
   | 语义档（起点加事件） | 改起点（初值、那次赋值或那个核对点给的起点）；有事件时拒收（`accumulated-value`） | 记一条赋值，成为新的起点 |
   | 值不完整 | 拒收（`incomplete-field`） | 只接受赋值 |
   | 命名空间没启用、已去掉、只读或类型不在 | 拒收（`field-unavailable`） | 同左 |

   - 剧情变化落在读取位置：开头位置落在本章最前，末尾位置落在本章最后；读取位置是初值或按计划模式时不接受剧情变化（`intent-not-allowed`）。
   - 发布后的值不等于调用方给的新值时整次拒收并说明原因（`result-mismatch`，例如“你改的那一笔是 +10，差额是 −800”）。
   - 结果另外列出：被改的那段文字在初值或别的变更里也原样出现的地方（由调用方决定要不要一起改），以及后面改过同一地址的记录（加减的会跟着变，赋值与整段替换的不会，要看一眼）。
9. **记一笔。** 给出读取位置、数值字段、增减、原因与读到的值：等于意图为剧情变化的一次加减，落在这个位置。
10. **文字替换。** 写入时可以把长文本或一块写成“把 A 换成 B”：A 在当时的值里必须恰好出现一次，程序替换后存全文；没找到得 `replace-not-found`，出现多次得 `replace-not-unique`。
11. **还原。** 还原一次修订，是发布一次补偿修订：把它改过的对象与字段恢复成改前的值；它新建的对象真正删除；没有 id 的数组里它新加的元素，只移除这些元素（改之后的数组以改之前的为开头，多出来的就是它加的），别的元素保持现状。补偿修订本身也能还原（等于重做）。还原后重算，后面因此套不上的进待处理，根因是这次补偿修订。整章撤销就是还原那一章的记账修订；作者在本章自己记的一笔是别的修订，不在内。
12. **依赖。** 后面的修订满足任一条，就依赖被还原的修订：改过同一个地址，或其中一个地址是另一个的前缀（状态到字段、列表元素与子键，记录到字段）；引用了它新建的条目或列表元素；与它的记录属于同一组兑现（[`canon.model`](model.md) 输出 13）。只往没有 id 的数组里加元素的修改互不依赖。依赖取传递闭包。有依赖时不单独还原，拒收（`has-dependents`），详情从新到旧列出依赖的修订；调用方可以请求把它们连同这次一起还原，程序从后往前算补偿，作为一次修订发布。不会覆盖后面的修改。
13. **章序调整。** 宿主给出的章序与世界里最近一次记下的不同时，世界发布一次 `reorder` 修订，操作是 `{kind: "chapters", before, after}`。打开时重放到它，记下这份章序；计算按宿主当前给的章序。它不能单独还原（`not-revertable`）：章序的真相在活页夹，改章序在活页夹里改。
14. **改动记录。** 按版本从新到旧列出修订：谁、种类、标题、时间、带来的变化的摘要、能不能还原（不能的给原因：有依赖、章序调整）。能按章、按条目、按写入者筛。
15. **修订不可变。** 发布后的修订不再改；改错了用新的修订改，或还原它。
16. **请求 id。** 同一个世界里，带同一个 `requestId` 的写入请求最多发布一次：再次提交时不重复发布，返回第一次的结果（修订 id、版本、id 对照）；内容与第一次不同时拒收（`request-id-reused`）。调用方可以按 `requestId` 查这次写入有没有发布、发布成了哪次修订（[`canon.project`](project.md) 的 `outcome`）。
17. **待定转生效。** 处理待处理时把一条待定的剧情变更改成生效，按新写的生效变更完整校验（输出 3）；不过就整次拒收。同一次修订可以同时改它的补丁与 `held` 说明。
18. **排序键。** 写入请求没给排序键时，程序按第一条正文讲述的原句在本章第一次出现的位置算；没有正文讲述的，排在本章最前（剧情变化落在开头位置时）或最后。给已有记录补上第一条正文讲述时，排序键改为这处讲述的位置，并写进带来的变化。
19. **必须带读到的值。** 就地改、记一笔与回写必须带 `reads`；缺了拒收（`reads-required`）。直接给对象新值的写入（`puts`）只按输出 7 判冲突。
20. **删除。** 条目不真正删除：删除是给它加墓碑标记的一次修改，其余字段原样保留，还原就去掉标记。剧情变更不删除，只撤销。核对点、未决问题、正文建议可以删除。还原新建对象的修订时，那些对象真正删除（因为有依赖时不能单独还原，删的时候没有别的记录引用它们）。对条目或剧情变更给 `after` 为空时拒收（`not-deletable`）。

## 状态与转换

- 写入请求的结局只有两种：发布（得到修订 id 与版本、新建对象的 id 对照）或拒收（得到失败码与详情）。拒收不改世界、不占版本号。断线时结局未知，按 `requestId` 查（输出 16）。
- 发布按 [`canon.project`](project.md) 的单写者排队；同一时刻只有一次发布在算。预览不排队，读的是它基于的版本。
- 一个预览结果、一个读取结果，都只对它的版本有效；拿旧版本的读取结果去写，按输出 7、8 判冲突。

## 副作用与数据

- 每次发布在世界日志末尾追加一行（[`canon.project`](project.md)）；改动记录就是日志本身，不另存。
- 删除的对象与被覆盖的旧值留在日志里，还原要用。彻底清除不在第一版。

## 失败与恢复

| 码 | 含义 | 调用方怎么办 |
|---|---|---|
| `validation-failed` | 校验不过，详情逐条列出（`entry-missing`、`not-appeared`、`component-disabled`、`unknown-field`、`type-mismatch`、`constraint-violated`、`number-out-of-range`、`invalid-asset-path`、`element-missing`、`quote-not-found`、`number-without-basis`、`basis-mismatch`、`invalid-line`、`invalid-link`、`invalid-tree`、`id-taken`、`ambiguous-field`，以及 [`canon.rendering`](rendering.md) 的 MDX 问题） | 按详情改请求 |
| `version-conflict` | 要改的对象在读取之后被改过 | 重读，看过当前值后再写 |
| `value-conflict` | 就地改或回写时，读到的值已经不是现在算出的值 | 重读再改 |
| `accumulated-value` | 就地改了一个几笔累出来的数，或有事件的语义档 | 改其中一笔，或记一笔 |
| `incomplete-field` | 以创作修改改不完整的字段 | 先处理根因，或以剧情变化赋值 |
| `field-unavailable` | 改的字段在这个位置没启用、已去掉、只读或类型不在 | 先启用、加回或换回插件 |
| `intent-not-allowed` | 在初值或按计划的位置上记剧情变化 | 改成创作修改，或换位置 |
| `result-mismatch` | 发布后的值不等于调用方要的值 | 看说明，换一条记录改 |
| `replace-not-found`、`replace-not-unique` | 文字替换的 A 没找到或不唯一 | 给更长、唯一的 A |
| `has-dependents` | 还原的修订有依赖 | 连同依赖一起还原，或不还原 |
| `not-revertable` | 章序调整不能还原 | 在活页夹里改章序 |
| `request-id-reused` | 同一个请求 id 带了不同的内容 | 换一个请求 id |
| `reads-required` | 就地改、记一笔或回写没带读到的值 | 补上 |
| `not-deletable` | 删除条目或剧情变更 | 条目加墓碑，剧情变更撤销 |

## 边界与兼容

- 公开接口：写入请求与修订的形状（修订存进世界日志）、失败码与详情的形状（码、对象、路径、说明）。
- 修订里未知的字段原样保留。新增的 `what` 种类对旧读者显示为“其它”。

## 验收与 Smoke

1. **两人同时改。** 作者与 Agent 都在版本 10 读了星瑕。Agent 先改了星瑕的外观（版本 11）；作者接着保存星瑕的存款（基于 10）：存款这次只改星瑕，星瑕在 11 被改过，作者得到 `version-conflict`，详情给出外观的当前值。作者若改的是星瑾，不冲突，正常发布为版本 12。
2. **就地改。** 第 45 章“染成黑色”设了发色。作者在第 50 章末尾把发色改成“深棕”：改的是第 45 章那条变更的补丁，初值不动，第 44 章末尾仍是银白。作者在第 50 章把存款从 41800 改成 41000：存款初值之后有几笔加减，得到 `accumulated-value` 与来历；勾“剧情变化”后在第 50 章末尾记一条 −800。
3. **还原与依赖。** 第 3 章的记账（修订 A）新建了“守护之星”，第 4 章的记账（修订 B）给它加了一条持有记录。还原 A 得到 `has-dependents`，列出 B；请求连同 B 一起还原：一次补偿修订，B 的记录与 A 的条目一起消失；再还原这次补偿，两者都回来。
4. **预览就是回执。** 记账先预览再发布，中间没有别的修订：预览里的“带来的变化”与发布后修订里存的逐字相同。
5. **数的依据。** Agent 记“花了两千”，补丁 −2000，讲述原句含“两千”：通过。原句写“三千五”、补丁 −3500：通过。原句里没有这个数、也没标估计：`validation-failed`，`number-without-basis`。
6. **断线重试。** 发布时连接断了，调用方不知道成没成：按请求 id 查，已发布就拿到那次修订；再提交同一个请求不会多出一次修订。

Smoke：不适用——本能力没有独立的运行入口，由 [`canon.project`](project.md) 的 Smoke 一并覆盖。
