# 世界引擎：条目、剧情变更与状态

## 目标与非目标

作者需要在任意一章的开头或末尾看到每个设定当时的样子，每一处变化都有描述和出处。本能力定义世界里存的六种对象（条目、剧情变更、核对点、未决问题、正文建议、修订）中前五种的形状，以及怎样从它们算出任意位置上的状态、来历、诊断与待处理。修订、发布与还原在 [`canon.revisions`](revisions.md)；字段的种类与约束在 [`canon.components`](components.md)。

计算是确定的：同一份世界（同一版本）、同一章序、同一组已登记的 Component 类型，算出的结果逐字相同；计算不调用模型。唯一的例外是语义档的归纳文字：它来自归纳缓存，缓存补上以后同一版本的读取会从“未归纳”的写法变成归纳的那句（输出 9）。

不承诺：

- 细到天和时段的故事时间、世界线与回档：第一版的位置只精确到章（章内按排序键），另加前史。同一章里的补叙按排序键排，不按故事时间。
- 知情与秘密、按某个角色的视角读取。
- 剧情变更之间的因果连接。
- 出处失联与“细纲已变”的检测（正文、细纲改了以后原句还在不在）：由改稿后的重新记账另行定义。
- 按任意历史版本重新计算：只算当前版本。

## 术语与参与者

- **条目**：设定的单位（人物、组织、地点、物品、概念、剧情线……），有稳定 id，在条目树里有一个位置。
- **条目树**：作者整理条目的目录，由父条目、分组与顺序组成；只用来组织，不表示包含、从属或身份同一。
- **主 MDX**：条目的文字，按块存，每块有稳定 id。块怎样解析与渲染见 [`canon.rendering`](rendering.md)。
- **状态**：条目上随剧情变化的数据：名字、别名、一句话描述、主 MDX 的各块，以及各命名空间的字段。
- **地址**：条目 id 加路径。路径的根是 `entry`（`entry.name`、`entry.aliases`、`entry.summary`）、`text`（`text[<块 id>]`）或一个命名空间（`<命名空间>.<字段 id>`）；列表元素写 `[元素 id]`，元素的子字段写 `.<子字段 id>`。存下来的路径只用 id。
- **剧情变更**：故事里发生的一件事。**已写**的来自正文；**计划**是还没写的。
- **生效状态**：剧情变更持久的状态：生效、待定（处理前不生效）、已撤销（保留，不生效，带原因）。只由修订改变。
- **套上、不适用、套不上**：一次计算里一个补丁的结果（输出 7）。与生效状态无关。
- **讲述**：一件事或一个设定在哪里被讲到，每处一条：来源（正文、细纲、故事种子、作者消息、界面、手记）、章、原句。
- **依据**：一个数从哪来：讲述里的原文、由核对点推出的差额、作者给的，或“估计”。
- **核对点**：正文写明的一个数，独立的对象，在自己的位置上与算出来的值比较。
- **位置**：故事里的一点。存在对象上的叫**安放**：前史（带先后）、某一章加章内排序键、未排章（只有计划）。读取用的叫**读取位置**：初值、第 N 章开头、第 N 章末尾。
- **模式**：实际（只用已写的）或按计划（再加上那时还没兑现的计划）。
- **来历**：一个地址在某个位置上的值是怎样一步步得出的。
- **不完整**：因为前面有补丁套不上，这个地址的值不可信。
- **待处理**：要作者拍板的事，由计算得出（输出 16）。
- **剧情线**：种类为“剧情线”的条目；剧情变更用它标所属的线。

## 输入与前置条件

- **章**：宿主给出章的稳定 id 与先后（来自活页夹）。章 id 不复用。可以没有章。
- **Component 类型**：由 [`canon.components`](components.md) 登记。

存下来的对象（属于世界日志的持久化格式，见 [`canon.project`](project.md)）：

**条目**

| 字段 | 意思 |
|---|---|
| `id` | 程序生成，不复用 |
| `type` | 种类，一段短文字；`剧情线` 有专门含义 |
| `parent`、`folder`、`order` | 条目树：父条目（或无）、分组、同级顺序 |
| `sameAs` | 可选，身份同一的本体条目 id（马甲指向本体） |
| `appears` | 可选，出场位置（一个安放）；没有时从头就有 |
| `init` | 初值：`name`、`aliases`、`summary`、`text`（块的列表，每块 `{id, source}`）、`data`（每个命名空间 `{type, version, enabled, removed?, fields, declared?}`：所属类型的 id、类型版本、初值里是否启用、是否已去掉、字段初值、实例字段声明）、`components`（只做查询的类型） |
| `initBasis` | 可选，初值里各个数的依据，按路径 |
| `retold` | 可选，正文重述设定的讲述，按路径（外观写在哪几句）；不论这个字段的值来自初值还是某条变更 |
| `deleted` | 可选，删除后的墓碑标记；条目的其余字段原样保留 |

**剧情变更**

| 字段 | 意思 |
|---|---|
| `id`、`kind` | 程序生成；`written` 或 `plan` |
| `text` | 描述，一句或一段 |
| `at` | 安放 |
| `told` | 这件事的讲述的列表 |
| `involves`、`lines` | 涉及的条目；所属的剧情线（剧情线条目的 id） |
| `links` | 连接：`{kind: fulfills, plan}`（已写指向计划）、`{kind: replaces, plan}`（新计划指向旧计划）、`{kind: splitFrom, plan, by}`（拆出的计划指向原计划，`by` 是那次兑现的已写变更） |
| `patches` | 补丁的列表，可以为空 |
| `status` | `active`、`held`、`undone`；`held` 带 `{reason: conflict|unsure, note, against?}`（`against` 是冲突的地址）；`undone` 带原因 |
| `by` | 谁写的：作者，或某个 Agent 会话、某个后台任务 |

**补丁**：`{op, at: 地址, value, basis?, version?}`，`version` 是命名空间字段所属类型的版本。`op` 见输出 6。

**核对点**：`{id, at: 地址, value: 数, told: 一条讲述, place: 安放, anchor?: {change, side: before|after}}`。

**未决问题**：`{id, text, quote?, about?, status: open|answered|dropped, answer?, hints}`；`about` 可以是条目、剧情变更、地址或没有；`hints` 是“正文里可能的答案”（章加原句）。

**正文建议**：`{id, cause: 修订 id, target, group, before, after, reason, judgment: sure|ask|notThisOne, found: linked|agent, status: open|applied|declined}`；`target` 是某章正文、某章细纲或某个条目的某一块；`after` 为空表示建议不改。

## 输出与可观察行为

1. **只存六种。** 世界只存条目、剧情变更、核对点、未决问题、正文建议与修订。位置上的状态、来历、诊断、不完整标记、计划进展、待处理、本章涉及的条目都在读取时算出，不存。
2. **先后。** 所有安放有一个全序：前史按自己的先后，之后是各章按宿主给的章序，章内按排序键；排序键相同时，按写入它的修订的版本先后，再按 id 的数值部分（`c9` 在 `c10` 之前），不按字符串比较。未排章的计划不在序里。读取位置的含义：初值是什么都不套；第 N 章开头是套完前史与第 N 章之前的所有章；第 N 章末尾是再套完第 N 章。初值与“第 1 章开头”不同，前史夹在两者之间。
3. **章序变化。** 宿主给的章序与世界里最近一次记下的不同（插章、挪章、删章，包括世界没打开时改的），世界记一次“章序调整”修订（[`canon.revisions`](revisions.md) 输出 13），之后按新章序算。章被删掉时，安放在它上面的剧情变更与核对点在任何位置都不套用，各成一条待处理“章已删除”，等作者重新安放。
4. **章内排序键。** 剧情变更与核对点共用一种存下来的排序键，写入时给定（[`canon.revisions`](revisions.md) 输出 18），之后只由修订改变，正文改稿不移动它。
5. **某个位置上的条目。** 实际模式下 = 初值 + 所有已写、生效、安放在这个位置之前的剧情变更，按先后依次打补丁。按计划模式再加上：安放在这个位置之前、生效、在这个位置上尚未兑现（输出 13）的计划；安放在已写章节（这一章上有生效的已写剧情变更）上的计划，从下一章开头起才算“之前”；未排章的计划不进任何位置；已取消、被替代的计划不进任何模式。
6. **补丁的执行。**

   | `op` | 用在 | 结果 |
   |---|---|---|
   | `set` | 任何字段、元素的子字段、名字、一句话描述、`启用` | 值变成 `value` |
   | `add` | 精确档的数值字段与数值子字段 | 加上 `value`；当前值是未知时套不上 |
   | `note` | 语义档字段 | 值不变，把一句事件记进这个字段的归纳输入（输出 9） |
   | `listAdd`、`listRemove` | 列表字段 | 按元素 id 增、删；增一个已有的 id 或删一个不存在的元素，套不上 |
   | `aliasAdd`、`aliasRemove` | 别名 | 增、删一个别名 |
   | `replaceBlock` | 主 MDX 的一块、精确档的长文本字段 | 整段替换，存全文 |
   | `addBlock`、`removeBlock` | 主 MDX | 在指定块之后增一块、删一块 |

   随剧情变化的文字整段替换，不做文本 diff 与合并。
7. **套不上。** 每个补丁的结果是：套上；不适用（命名空间在这个位置上已去掉或没启用，[`canon.components`](components.md) 输出 5、7）；套不上（条目不存在或已删除、元素不存在、类型不符、未知值不能加减、约束不满足、数超出范围）。一条剧情变更里有一个补丁套不上，整条在这个位置上都不算数，其余补丁也不套（转账不会只记一边）；不适用的补丁只跳过它自己。一条变更套没套上只取决于它之前的状态，与从哪个位置读无关。这是这次计算的诊断，不改变生效状态；前面修好以后再算，诊断自然消失。读取结果对每条剧情变更同时给出生效状态与这次套没套上。
8. **不完整。** 一条剧情变更套不上时，它的补丁本来要改的地址，从它的位置起标“不完整”，带原因（哪条变更、为什么）。不完整沿依赖往后传：之后对这个地址的加减、事件仍不完整，遇到不依赖旧值的赋值或整段替换就截止；给元素的子字段赋值只解除它覆盖的那个子地址。跨字段约束（`max` 引用另一个字段）不满足时，标的是被约束的字段。
9. **语义档。** 语义档字段的值由“起点”与之后的事件决定：起点是初值、最近一次 `set`，或最近一个比较位置不晚于它的核对点（正文写明的数是新的起点，不拿来比较）；之后的 `note` 按先后排成事件列表。没有事件时，值就是起点。有事件时，值是小模型对“起点加事件”的归纳，从归纳缓存里取；缓存里没有时，值是“起点；之后：事件一；事件二……”，并标“未归纳”。归纳怎样补进缓存见 [`canon.project`](project.md) 输出 11。
10. **未知。** 任何字段的值都可以是未知。未知的数不能加减（输出 6）；精确档字段第一次在正文里出现的数，由写入者记成初值并带依据或“估计”，本能力不替它猜。
11. **核对点。** 精确档字段的核对点在比较时点上与那一刻算出的值比较：
    - 挂在一条剧情变更上（`anchor`）、而那条变更在这次计算里套上了：`before` 比那条变更的补丁之前的值，`after` 比之后的值；
    - 没挂，或挂靠的变更待定、已撤销或套不上：在 `place` 上比较，即排在 `place` 之前的变更都套完之后的值。

    相等就对得上；不相等，成一条待处理“核对点不符”，读取结果在这个值旁边给出“正文写的是 Y”，值本身仍是算出来的。地址在比较时点不完整时不比较，只在诊断里记“无法核对”，不成待处理；核对点所在的条目已删除时不比较，也不成待处理。核对点不改变精确档的值。语义档字段的核对点不比较，在 `place` 上成为新的起点（输出 9），`anchor` 对它不起作用。
12. **嫌疑区间。** “核对点不符”列出嫌疑记录：同一地址上，从“上一个比较过的核对点”（对得上、对不上都算；无法核对的不算）与“最后一次赋值”中较晚的一个起，到这个核对点为止的所有剧情变更；两者都没有时从初值起，初值本身也列入；套不上的记录也列入。上一个核对点也对不上时，它之前的记录在它自己那条里列出，这条不再重复列。带“估计”依据的排在前面。
13. **计划进展。** 计划的进展是算出来的，按实际模式的计算结果判定，与按计划模式无关：
    - 在某个读取位置上，有一条安放在这个位置之前、生效、且套上了的已写变更用 `fulfills` 指向它，它在这个位置“已兑现”；否则“未兑现”；
    - 它自己 `undone`，是“已取消”；有生效的计划用 `replaces` 指向它，是“被替代”；这两种与位置无关；
    - 兑现它的那条已写变更被撤销或套不上，计划回到未兑现；
    - `splitFrom` 指向它、`by` 是某条兑现变更的拆出计划，与那条兑现变更是一组：那条兑现变更不生效或套不上时，这些拆出的计划在计算里一起不生效（存下来的状态不变）。

    “全书的当前进展”指在最新一章末尾的进展（没有章时在初值）；列表与筛选缺省用它。
14. **出场与删除。** 条目有 `appears` 时，早于出场位置的读取位置上，它标“尚未出场”，按名字找条目不返回它（按计划模式与跨时期的查询除外）。删除的条目留墓碑：读取它得到“已删除”与原来的名字，引用它的地方显示“已删除的条目”；对它的补丁套不上。
15. **来历。** 读取一个地址时可以要来历：按先后列出初值（带依据）、每一步赋值、加减、增删元素或整段替换（哪条变更、结果、依据）、核对点（对没对上）、语义档的事件与归纳（是否来自缓存）。就地改按来历决定写回哪条记录（[`canon.revisions`](revisions.md) 输出 8）。
16. **待处理。** 在给定的读取位置（缺省见输出 21）算出：核对点不符（每个核对点一条）；套不上（按根因合并，见输出 22）；待定的剧情变更（与设定冲突、没把握，各一条）；章已删除（输出 3）。未决问题与正文建议不算待处理，各自单独计数。排序：按位置从前到后，同一位置按种类（核对点不符、套不上、待定、章已删除），再按 id。
17. **未决问题与正文建议。** 两者都是存下来的对象，状态只由修订改变。未决问题可以挂在条目、剧情变更、地址上，也可以不挂；正文建议记着是哪次修订引起的、改哪里、改前改后、理由、把握与怎么找到的。
18. **剧情线。** 剧情变更的 `lines` 只能指向种类为 `剧情线` 的条目。剧情线条目与别的条目一样有状态，可以带 Component。
19. **重述设定的讲述。** 条目上的 `retold`、剧情变更的 `told` 都只是讲述，不产生补丁；重讲一件已经记过的事，只给原记录补一条讲述。改设定以后找正文旧写法时，`retold` 里链到这个字段、且所在章在这个值有效的范围里的讲述，是第一批候选。
20. **本章涉及的条目。** 某一章涉及的条目 = 安放在这一章、生效的剧情变更的 `involves` 与补丁地址里的条目，加上比较时点在这一章的核对点的条目。
21. **缺省的读取位置。** 有章时是最新一章的末尾；没有章时是初值。
22. **根因。** 一条变更套不上的根因，是让它从套上变成套不上的那次修订（发布时记在那次修订“带来的变化”里，[`canon.revisions`](revisions.md) 输出 6）；没有这样的修订时，根因是它自己。同一根因的几条套不上合成一条待处理，列出受影响的记录数与范围。
23. **条目树与身份同一的约束。** `parent` 指向存在、未删除的条目，不是自己，不成环；`sameAs` 指向存在的另一个条目，被指向的条目自己没有 `sameAs`（马甲不嵌套）。写入时校验（[`canon.revisions`](revisions.md) 输出 3）。父条目被删除后，子条目照常存在，在树里显示在原父条目的墓碑下。

## 状态与转换

剧情变更的生效状态（只由修订改变）：

| 从 | 到 | 由什么 |
|---|---|---|
| 新建 | `active` 或 `held` | 写入时给定；Agent 没把握或与设定冲突的写成 `held` |
| `held` | `active` | 作者处理待处理时采纳（按新建的生效变更重新校验，[`canon.revisions`](revisions.md) 输出 3） |
| `active`、`held` | `undone` | 撤销（带原因） |
| `undone` | `active` | 还原撤销它的修订 |

条目：存在 →（删除）→ 墓碑 →（还原删除它的修订）→ 存在。

- 计划进展、套上与否、不完整、待处理都随每次计算重新得出，没有自己的转换。
- 读取总是针对世界的某一个版本；同一版本上的读取结果不变（语义档归纳的例外见“目标与非目标”）。

## 副作用与数据

- 本能力是计算，没有副作用。对象怎样写进世界日志见 [`canon.project`](project.md)；归纳缓存的读写见同一 Spec 输出 11。

## 失败与恢复

读取不失败：算不下去的情况都成为诊断与待处理，不让整次读取失败。读取位置指向不存在或已删除的章时，读取得到 `chapter-not-found`（[`canon.project`](project.md)）。写入时的校验失败见 [`canon.revisions`](revisions.md)。

| 诊断 | 含义 | 作者或 Agent 怎么办 |
|---|---|---|
| `cannot-apply` | 一条剧情变更在这个位置套不上，带原因（`entry-missing`、`element-missing`、`type-mismatch`、`unknown-value`、`constraint-violated`、`number-out-of-range`）与根因 | 改前面的记录，或改这条 |
| `check-mismatch` | 核对点不符，带算出的值、正文的值与嫌疑记录 | 改或撤某条记录、插一条校正、或改正文 |
| `check-skipped` | 比较时点上地址不完整，没有比较 | 先处理不完整的根因 |
| `incomplete` | 地址的值不完整，带原因 | 先处理根因 |
| `chapter-deleted` | 安放在已删除章上的记录 | 重新安放 |
| `not-reduced` | 语义档的值还没归纳 | 等归纳补上，或手动给起点 |

## 验收与 Smoke

1. **转账。** 第 3 章“星瑕给星瑾转了两千”是一条变更，两个补丁：星瑕存款 −2000、星瑾存款 +2000。把初值的星瑕存款改成 1000（有下限 0）：这条变更在第 3 章套不上，两人的存款都不变；待处理里一条“套不上”，根因是那次改初值；星瑕存款从第 3 章起不完整，到第 5 章一条“存款定为 500”的赋值后恢复完整。把初值改回四万，诊断消失。
2. **核对点与嫌疑区间。** 初值存款 40000（依据：“卡里还有四万”），第 2 章 −300（估计）、第 3 章 +2000，第 3 章末尾的核对点写 41800。核对点不符，嫌疑记录是第 2、3 章两条，带估计的第 2 章排第一；第 2 章改成 −200 后对得上，待处理消失。第 3 章另一个核对点挂在 +2000 那条变更之前（`before`）写 39800，对得上；那条变更改成待定以后，这个核对点回到 `place` 上比较。
3. **计划的部分兑现。** 第 4 章计划“花 300 买药、救下风信子”；第 4 章还没有已写变更时，第 4 章末尾按计划读含这条计划；第 4 章有了第一条已写变更之后，第 4 章末尾按计划读不含它、第 5 章开头含它。之后记账写“花 50 买药”兑现它，拆出“救下风信子”（`by` 是这条记账变更）排到第 5 章开头。按计划读第 5 章开头，有“救下风信子”；撤销那条兑现记录后，原计划回到未兑现，拆出的计划在计算里一起不生效。第 3 章开头按计划读，原计划还不在（它安放在第 4 章）；兑现若改到第 6 章，第 5 章开头按计划读时原计划在、第 6 章末尾不在。
4. **前史与初值。** 一条前史“6 岁那年父母失踪”把父母的状态设成“失踪”：读初值是原来的值，读第 1 章开头是“失踪”。
5. **语义档。** 星瑾“现在的态度”是语义档，初值“冷淡”，第 1、2 章各一句事件。缓存里有这组输入的归纳时，第 2 章末尾读到归纳的那句；没有时读到“冷淡；之后：……；……”并标“未归纳”。第 3 章正文写明“她终于肯叫哥哥了”记成新的起点后，第 3 章末尾的值从这里重新开始。
6. **删章。** 删掉第 2 章：安放在第 2 章的变更不再套用，各成一条“章已删除”；第 3 章以后的值相应变化。把它们挪到第 3 章后，待处理消失。读第 2 章开头得到 `chapter-not-found`。
