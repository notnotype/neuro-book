# 世界引擎：条目、剧情变更与状态

## 目标与非目标

作者需要在任意一章的开头或末尾看到每个设定当时的样子，每一处变化都有描述和出处。本能力定义世界里存的六种对象（条目、剧情变更、核对点、决策、正文建议、修订）中前五种的形状，以及怎样从它们算出任意位置上的状态、来历、诊断、待处理与提示；剧情插件用到的讲述发生点、标注、在场、决策与诊断贡献点也在这里。修订、发布与还原在 [`canon.revisions`](revisions.md)；字段的种类与约束在 [`canon.components`](components.md)。

计算是确定的：同一份读取输入（输出 36：世界版本、章序与各章讲的线、正文快照、已登记的 Component 类型、标注种类与诊断、历法与模糊词表），算出的结果逐字相同；计算不调用模型（插件的诊断另见输出 34）。唯一的例外是语义档的归纳文字：它来自归纳缓存，缓存补上以后同一版本的读取会从“未归纳”的写法变成归纳的那句（输出 9）。

不承诺：

- 细到天和时段的故事时间、世界线与回档：本能力的位置只精确到章（章内按排序键），另加前史。同一章里的补叙按排序键排，不按故事时间。故事时间的说法与计算见 [`canon.time`](time.md)，世界线见 [`canon.worldlines`](worldlines.md)。
- 知情、伏笔、目标、态度的语义，决策的守卫与检查，按某个角色的视角读取：由剧情插件定义（[`plot/knowledge.md`](../plot/knowledge.md) 等）。本能力只提供它们用到的讲述、标注、在场、决策的存储与诊断贡献点。
- 剧情变更之间的因果连接。
- “细纲已变”的检测（细纲改了以后它上面的讲述还对不对）：由改稿后的重新记账另行定义。正文讲述的失联由本能力算出（输出 26）。
- 按任意历史版本重新计算：只算当前版本。

## 术语与参与者

- **条目**：设定的单位（人物、组织、地点、物品、概念、剧情线……），有稳定 id，在条目树里有一个位置。
- **条目树**：作者整理条目的目录，由父条目、分组与顺序组成；只用来组织，不表示包含、从属或身份同一。
- **主 MDX**：条目的文字，按块存，每块有稳定 id。块怎样解析与渲染见 [`canon.rendering`](rendering.md)。
- **状态**：条目上随剧情变化的数据：名字、别名、一句话描述、主 MDX 的各块，以及各命名空间的字段。
- **地址**：条目 id 加路径。路径的根是 `entry`（`entry.name`、`entry.aliases`、`entry.summary`）、`text`（`text[<块 id>]`）或一个命名空间（`<命名空间>.<字段 id>`）；列表元素写 `[元素 id]`，元素的子字段写 `.<子字段 id>`。存下来的路径只用 id。
- **剧情变更**：故事里发生的一件事。**已写**的来自正文；**计划**是还没写的。
- **生效状态**：剧情变更持久的状态：生效、待定（处理前不生效）、已撤销（保留，不生效，带原因）。只由修订改变。
- **套上、不适用、套不上**：一次计算里一个补丁的结果（输出 7）。与生效状态无关。
- **讲述**：一件事或一个设定在哪里被讲到，每处一条，有稳定 id：来源（正文、细纲、故事种子、作者消息、界面、手记）；正文的讲述带章与原句，其余来源带各自的锚点（输出 24）。
- **依据**：一个数从哪来：讲述里的原文、由核对点推出的差额、作者给的，或“估计”。
- **核对点**：正文写明的一个数，独立的对象，在自己的位置上与算出来的值比较。
- **位置**：故事里的一点。存在对象上的叫**安放**：前史（带先后）、某一章加章内排序键、未排章（只有计划），另带世界线 `line`（剧情变更的 `at` 与核对点的 `place` 都是安放）。读取用的叫**读取位置**：初值、第 N 章开头、第 N 章末尾，另带世界线 `line`。不写线时是主线；线怎样影响读取见 [`canon.worldlines`](worldlines.md)，同一条线的视图里安放的全序按输出 2。
- **模式**：实际（只用已写的）或按计划（再加上那时还没兑现的计划）。
- **来历**：一个地址在某个位置上的值是怎样一步步得出的。
- **不完整**：因为前面有补丁套不上，这个地址的值不可信。
- **待处理**：要作者拍板的事，由计算得出（输出 16）。
- **剧情线**：种类为“剧情线”的条目；剧情变更用它标所属的线。与世界线（[`canon.worldlines`](worldlines.md)）无关。
- **段**：一章正文按换行切开后，去掉首尾空白仍不为空的行，从 1 起数。
- **发生点**：正文讲述在当前正文里的位置：章、段、段内偏移（输出 24）。
- **失联**：正文讲述的原句在那一章的当前正文里找不到，或那一章已不在活页夹里（输出 26）。
- **生效的讲述**：能定位到发生点的正文讲述（输出 26）。读者读到了什么、伏笔到了哪一步，都只按生效的讲述算。
- **讲述位置**：读者读到哪里：某一章的某一段之后，或某一章的开头、末尾（输出 27）。
- **标注**：讲述、剧情变更或决策上的一条带种类的数据 `{kind, version, …}`，种类由插件登记（[`canon.components`](components.md) 的标注种类），本能力只存、校验与在还原时查依赖（输出 28）。
- **参与者**：剧情变更里出现的人，在场或被提到（输出 29）。
- **性质**：剧情变更是事件（缺省）、叙述（只是讲到，世界没变，输出 30）还是分叉（[`canon.worldlines`](worldlines.md)）。
- **决策**：要作者定的事，与作者定下的结论、理由与约束（输出 31 到 33）；原来的“未决问题”是待定的决策。
- **作者来源**：作者原话或界面确认的出处，由宿主签发（[`canon.revisions`](revisions.md) 输出 21）。
- **诊断**：插件登记、在读取时算出的检查结果，进待处理或提示（输出 34、35）。

## 输入与前置条件

- **章**：宿主给出章的稳定 id 与先后（来自活页夹）。章 id 不复用。可以没有章。
- **正文**：宿主按章 id 给出那一章的当前正文（[`canon.project`](project.md) 的输入），用来定位讲述（输出 24、26）。
- **Component 类型**：由 [`canon.components`](components.md) 登记；标注种类同样由那里登记。
- **诊断**：插件经贡献点 `canon.diagnostics` 登记（下表），计算由插件在项目实例里的入口提供。

**诊断的登记**（插件清单里的声明，插件不激活也能读）

| 项 | 必填 | 规则 |
|---|---|---|
| `id` | 是 | `<插件 id>.<名>`，前缀必须是声明它的插件的 id，不是的那条不登记、写诊断 `diagnostic-declaration-invalid`，不参与重复判定；剩下的里同一个 id 出现不止一次的，全部不登记（同一诊断） |
| `version` | 是 | 正整数；规则或稳定键的组成变了就加一 |
| `level` | 是 | `pending`（进待处理）或 `hint`（进提示） |
| `label` | 是 | 给作者看的名字 |
| `key` | 是 | 稳定键除诊断 id 以外的组成部分，从 `objects`、`line`、`telling`、`range`、`detail` 里选，至少一项（形状见下） |
| `inputs` | 否 | 读哪些视图的说明，文字，给作者与审查者看 |

**诊断的计算**：`(world: 只读世界, at: 读取位置, mode: 实际或按计划) => 发现[]`，同步，不调用模型，不写世界。它可以读世界与它自己插件的项目数据（例如剧情插件存下的窄问题答案）；对同一份读取输入与同一份插件数据给出相同的结果。插件的项目入口启动后经 canon 的项目内接口登记它声明的诊断的计算，同时给出它的数据版本（一段不透明的文字）；数据变了，插件经同一接口报告新的数据版本，之后的读取按新数据算。入口停止时登记随之失效。

- **稳定键**：一个对象，只含登记里声明的组成部分，每部分的形状固定：`objects` 是对象引用的有序列表（`{kind: entry | change | check | decision, id}`，顺序有意义，不去重）；`line` 是世界线 id；`telling` 是讲述 id；`range` 是 `{from: 章 id, to: 章 id}`；`detail` 是一段文字，给按内容区分的发现用（例如原句的 SHA-256、规则项的 id）。声明了的部分必须有值。比较与存储用规范的 JSON。稳定键里的对象引用是发现的指纹，不是引用位置：不做存在校验；写入请求里它们的临时 id 照样换成生成的 id。
- **发现**：`{key, at?, objects, params}`。`at` 是安放或讲述的发生点；`objects` 是给作者看的相关对象；`params` 是说明的参数（键值都是文字或数）。
- **规范的 JSON**：本组 Spec 里说“规范的 JSON”的地方（稳定键、作者来源的摘要、读取输入的摘要），都按 RFC 8785（JSON Canonicalization Scheme）序列化：对象的键按 UTF-16 码元排序，数按 ECMAScript 的写法，不带空白。

存下来的对象（属于世界日志的持久化格式，见 [`canon.project`](project.md)）：

**条目**

| 字段 | 意思 |
|---|---|
| `id` | 程序生成，不复用 |
| `type` | 种类，一段短文字；`剧情线` 有专门含义 |
| `parent`、`folder`、`order` | 条目树：父条目（或无）、分组、同级顺序 |
| `sameAs` | 可选，身份同一的本体条目 id（马甲指向本体） |
| `appears` | 可选，出场位置（一个安放）；没有时从头就有 |
| `init` | 初值：`name`、`aliases`、`summary`、`text`（块的列表，每块 `{id, source}`）、`data`（每个命名空间 `{type, version, enabled, removed?, fields, declared?}`：所属类型的 id、类型版本、初值里是否启用、是否已去掉、字段初值、实例字段声明）、`components`（只做查询的类型） |
| `initBasis` | 可选，初值里各个数的依据，按路径 |
| `retold` | 可选，正文重述设定的讲述，按路径（外观写在哪几句）；不论这个字段的值来自初值还是某条变更 |
| `deleted` | 可选，删除后的墓碑标记；条目的其余字段原样保留 |

**剧情变更**

| 字段 | 意思 |
|---|---|
| `id`、`kind` | 程序生成；`written` 或 `plan` |
| `nature` | 可选，性质：`event`（缺省）、`narration`（输出 30）、`fork`（[`canon.worldlines`](worldlines.md)，另有 `fork` 字段） |
| `when` | 可选，时间说法的列表（[`canon.time`](time.md)） |
| `text` | 描述，一句或一段 |
| `at` | 安放 |
| `told` | 这件事的讲述的列表（形状见下） |
| `involves`、`lines` | 涉及的条目；所属的剧情线（剧情线条目的 id） |
| `marks` | 可选，标注的列表（输出 28），例如剧情插件的“揭示给在场的人” |
| `cast` | 可选，参与者的列表，每项 `{who?: 条目 id, label?: 文字, role: present|mentioned, as?: 条目 id}`（输出 29）。没有这个字段表示“没记参与者”，空列表表示“记了，没有人” |
| `links` | 连接：`{kind: fulfills, plan}`（已写指向计划）、`{kind: replaces, plan}`（新计划指向旧计划）、`{kind: splitFrom, plan, by}`（拆出的计划指向原计划，`by` 是那次兑现的已写变更） |
| `patches` | 补丁的列表，可以为空 |
| `status` | `active`、`held`、`undone`；`held` 带 `{reason: conflict|unsure, note, against?}`（`against` 是冲突的地址）；`undone` 带原因 |
| `by` | 谁写的：作者，或某个 Agent 会话、某个后台任务 |

**补丁**：`{op, at: 地址, value, basis?, version?}`，`version` 是命名空间字段所属类型的版本。`op` 见输出 6。

**讲述**（剧情变更的 `told`、核对点的 `told`、条目的 `retold` 里都是这个形状）

| 字段 | 意思 |
|---|---|
| `id` | 程序生成，不复用；写入请求里新的讲述不带 id |
| `source` | `chapter`（正文）、`outline`（细纲）、`seed`（故事种子）、`message`（作者消息）、`ui`（界面）、`note`（手记） |
| `chapter` | 正文与细纲必有 |
| `quote` | 原句。正文必有：非空、不含换行；其余来源可以有 |
| `nth` | 可选，只用于正文：原句在这一章出现几次时，取第几处（从 1 起，按正文的先后） |
| `anchor` | 正文以外的来源用，由写入者给出，本能力不解析：细纲（`outline`）必有，是细纲的块 id；作者消息（`message`）必有，是消息 id；界面（`ui`）必有，是确认 id；故事种子与手记可以有。正文以外的讲述不会失联，也不进读者读过的讲述（输出 26、27） |
| `marks` | 可选，标注的列表（输出 28） |

**核对点**：`{id, at: 地址, value: 数, told: 一条讲述, place: 安放, anchor?: {change, side: before|after}}`。

**决策**（原“未决问题”）

| 字段 | 意思 |
|---|---|
| `id` | 程序生成 |
| `text` | 要定的事，一句话 |
| `status` | `pending`（待定）、`decided`（已定）、`superseded`（被取代）、`dropped`（放弃）；各状态必有的字段与允许的转换见“状态与转换” |
| `about` | 挂的对象的列表，可以为空：`{kind: entry, id}`、`{kind: change, id}`、`{kind: address, at}`、`{kind: chapter, id}`、`{kind: decision, id}`、`{kind: diagnostic, id, key, version}`（输出 33） |
| `scope` | 可选，适用的章的范围 `{from?: 章 id, to?: 章 id}`，两端都含 |
| `due` | 可选，待定时最晚在哪一章写正文之前要定（章 id） |
| `candidates` | 可选，待定时的候选，文字的列表 |
| `suggestion` | 可选，作者未确认的建议结论 `{conclusion, reason?, by}`（输出 32） |
| `conclusion`、`reason`、`risks`、`constraints` | 已定的结论、理由、风险（文字），约束（文字的列表） |
| `marks` | 可选，标注的列表（例如剧情插件的守卫，输出 28） |
| `supersededBy` | 被取代时，取代它的决策 id |
| `source` | 出处：最近一次带授权的普通写入里那项授权的来源，只由本能力写；还原把它恢复成那时的出处，还原用的授权只存在补偿修订里（[`canon.revisions`](revisions.md) 输出 21） |
| `quote` | 可选，提出这件事的原话 |
| `hints` | “正文里可能的答案”的列表，每项 `{chapter, quote}` |

**正文建议**：`{id, cause: 修订 id, target, group, before, after, reason, judgment: sure|ask|notThisOne, found: linked|agent, status: open|applied|declined}`；`target` 是某章正文、某章细纲或某个条目的某一块；`after` 为空表示建议不改。

## 输出与可观察行为

1. **只存六种。** 世界只存条目、剧情变更、核对点、决策、正文建议与修订。位置上的状态、来历、诊断、不完整标记、计划进展、待处理与提示、本章涉及的条目、讲述的发生点与失联、在场都在读取时算出，不存。
2. **先后。** 所有安放有一个全序：前史按自己的先后，之后是各章按宿主给的章序，章内按排序键；排序键相同时，按写入它的修订的版本先后，再按 id 的数值部分（`c9` 在 `c10` 之前），不按字符串比较。未排章的计划不在序里。读取位置的含义：初值是什么都不套；第 N 章开头是套完前史与第 N 章之前的所有章；第 N 章末尾是再套完第 N 章。初值与“第 1 章开头”不同，前史夹在两者之间。
3. **章序变化。** 宿主给的章序与世界里最近一次记下的不同（插章、挪章、删章，包括世界没打开时改的），世界记一次“章序调整”修订（[`canon.revisions`](revisions.md) 输出 13），之后按新章序算。章被删掉时，安放在它上面的剧情变更与核对点在任何位置都不套用，各成一条待处理“章已删除”，等作者重新安放。
4. **章内排序键。** 剧情变更与核对点共用一种存下来的排序键，写入时给定（[`canon.revisions`](revisions.md) 输出 18），之后只由修订改变，正文改稿不移动它。
5. **某个位置上的条目。** 实际模式下 = 初值 + 所有已写、生效、安放在这个位置之前的剧情变更，按先后依次打补丁。按计划模式再加上：安放在这个位置之前、生效、在这个位置上尚未兑现（输出 13）的计划；安放在已写章节（这一章上有生效的已写剧情变更）上的计划，从下一章开头起才算“之前”；未排章的计划不进任何位置；已取消、被替代的计划不进任何模式。
6. **补丁的执行。**

   | `op` | 用在 | 结果 |
   |---|---|---|
   | `set` | 任何字段、元素的子字段、名字、一句话描述、`启用` | 值变成 `value` |
   | `add` | 精确档的数值字段与数值子字段 | 加上 `value`；当前值是未知时套不上 |
   | `note` | 语义档字段 | 值不变，把一句事件记进这个字段的归纳输入（输出 9） |
   | `listAdd`、`listRemove` | 列表字段 | 按元素 id 增、删；增一个已有的 id 或删一个不存在的元素，套不上 |
   | `aliasAdd`、`aliasRemove` | 别名 | 增、删一个别名 |
   | `replaceBlock` | 主 MDX 的一块、精确档的长文本字段 | 整段替换，存全文 |
   | `addBlock`、`removeBlock` | 主 MDX | 在指定块之后增一块、删一块 |

   随剧情变化的文字整段替换，不做文本 diff 与合并。
7. **套不上。** 每个补丁的结果是：套上；不适用（命名空间在这个位置上已去掉或没启用，[`canon.components`](components.md) 输出 5、7）；套不上（条目不存在或已删除、元素不存在、类型不符、未知值不能加减、约束不满足、数超出范围）。一条剧情变更里有一个补丁套不上，整条在这个位置上都不算数，其余补丁也不套（转账不会只记一边）；不适用的补丁只跳过它自己。一条变更套没套上只取决于它之前的状态，与从哪个位置读无关。这是这次计算的诊断，不改变生效状态；前面修好以后再算，诊断自然消失。读取结果对每条剧情变更同时给出生效状态与这次套没套上。
8. **不完整。** 一条剧情变更套不上时，它的补丁本来要改的地址，从它的位置起标“不完整”，带原因（哪条变更、为什么）。不完整沿依赖往后传：之后对这个地址的加减、事件仍不完整，遇到不依赖旧值的赋值或整段替换就截止；给元素的子字段赋值只解除它覆盖的那个子地址。跨字段约束（`max` 引用另一个字段）不满足时，标的是被约束的字段。
9. **语义档。** 语义档字段的值由“起点”与之后的事件决定：起点是初值、最近一次 `set`，或最近一个比较位置不晚于它的核对点（正文写明的数是新的起点，不拿来比较）；之后的 `note` 按先后排成事件列表。没有事件时，值就是起点。有事件时，值是小模型对“起点加事件”的归纳，从归纳缓存里取；缓存里没有时，值是“起点；之后：事件一；事件二……”，并标“未归纳”。归纳怎样补进缓存见 [`canon.project`](project.md) 输出 11。
10. **未知。** 任何字段的值都可以是未知。未知的数不能加减（输出 6）；精确档字段第一次在正文里出现的数，由写入者记成初值并带依据或“估计”，本能力不替它猜。
11. **核对点。** 精确档字段的核对点在比较时点上与那一刻算出的值比较：
    - 挂在一条剧情变更上（`anchor`）、而那条变更在这次计算里套上了：`before` 比那条变更的补丁之前的值，`after` 比之后的值；
    - 没挂，或挂靠的变更待定、已撤销或套不上：在 `place` 上比较，即排在 `place` 之前的变更都套完之后的值。

    相等就对得上；不相等，成一条待处理“核对点不符”，读取结果在这个值旁边给出“正文写的是 Y”，值本身仍是算出来的。地址在比较时点不完整时不比较，只在诊断里记“无法核对”，不成待处理；核对点所在的条目已删除时不比较，也不成待处理。核对点不改变精确档的值。语义档字段的核对点不比较，在 `place` 上成为新的起点（输出 9），`anchor` 对它不起作用。
12. **嫌疑区间。** “核对点不符”列出嫌疑记录：同一地址上，从“上一个比较过的核对点”（对得上、对不上都算；无法核对的不算）与“最后一次赋值”中较晚的一个起，到这个核对点为止的所有剧情变更；两者都没有时从初值起，初值本身也列入；套不上的记录也列入。上一个核对点也对不上时，它之前的记录在它自己那条里列出，这条不再重复列。带“估计”依据的排在前面。
13. **计划进展。** 计划的进展是算出来的，按实际模式的计算结果判定，与按计划模式无关：
    - 在某个读取位置上，有一条安放在这个位置之前、生效、且套上了的已写变更用 `fulfills` 指向它，它在这个位置“已兑现”；否则“未兑现”；
    - 它自己 `undone`，是“已取消”；有生效的计划用 `replaces` 指向它，是“被替代”；这两种与位置无关；
    - 兑现它的那条已写变更被撤销或套不上，计划回到未兑现；
    - `splitFrom` 指向它、`by` 是某条兑现变更的拆出计划，与那条兑现变更是一组：那条兑现变更不生效或套不上时，这些拆出的计划在计算里一起不生效（存下来的状态不变）。

    “全书的当前进展”指在最新一章末尾的进展（没有章时在初值）；列表与筛选缺省用它。
14. **出场与删除。** 条目有 `appears` 时，早于出场位置的读取位置上，它标“尚未出场”，按名字找条目不返回它（按计划模式与跨时期的查询除外）。删除的条目留墓碑：读取它得到“已删除”与原来的名字，引用它的地方显示“已删除的条目”；对它的补丁套不上。
15. **来历。** 读取一个地址时可以要来历：按先后列出初值（带依据）、每一步赋值、加减、增删元素或整段替换（哪条变更、结果、依据）、核对点（对没对上）、语义档的事件与归纳（是否来自缓存）。就地改按来历决定写回哪条记录（[`canon.revisions`](revisions.md) 输出 8）。
16. **待处理。** 在给定的读取位置（缺省见输出 21）与模式（缺省实际模式）上算出：核对点不符（每个核对点一条）；套不上（按根因合并，见输出 22）；待定的剧情变更（与设定冲突、没把握，各一条）；章已删除（输出 3）；世界线的“子线记录越界”“线不存在”（[`canon.worldlines`](worldlines.md) 输出 1、3）与时间的几种（[`canon.time`](time.md) 输出 2、3、5、6）；以及插件登记的级别为 `pending` 的诊断（输出 34）。决策与正文建议不算待处理，各自单独计数。待处理按读取位置的线算：线视图里的记录产生的进这条线；越界的记录进它所在的线；安放在两种模式下都不存在的线上的记录（“线不存在”）在任何线的待处理里都列出；计划线上的记录在实际模式下不进任何视图，也不算“线不存在”。排序是全序：先按项的排序位置——前史在前，再按章序；同一章里，带安放的项按排序键在前，带讲述发生点的项按段与偏移在后——没有排序位置的项排在最后；同一位置按种类（待处理：核对点不符、套不上、待定、章已删除、世界线、时间、插件的诊断；提示：讲述失联、原句重复、标注与 Component 的版本与类型不在（`mark-*`、`component-version-unsupported`、`component-unknown`）、世界线的提示、时间的提示、插件的诊断），再按项的排序 id，最后按整项的规范 JSON。项的排序位置：只涉及一件事的项取它的安放（核对点取比较时点）；涉及几件事的项（打架的环、安放与时间对不上、回溯的时间对不上）取其中最早的安放；按根因合并的“套不上”取最早那条的安放；章已删除、安放在未排章与不存在的线上的项没有排序位置。项的排序 id：有对象 id 的取它（按根因合并的取根因修订的 id），插件的诊断取诊断 id 加稳定键的规范 JSON，其余取涉及对象引用的有序列表的规范 JSON。没有安放的提示（活页夹一段的提示）以那一段所在章的开头为排序位置。
17. **决策与正文建议。** 两者都是存下来的对象，状态只由修订改变。决策见输出 31 到 33；正文建议记着是哪次修订引起的、改哪里、改前改后、理由、把握与怎么找到的。
18. **剧情线。** 剧情变更的 `lines` 只能指向种类为 `剧情线` 的条目。剧情线条目与别的条目一样有状态，可以带 Component。
19. **重述设定的讲述。** 条目上的 `retold`、剧情变更的 `told` 都只是讲述，不产生补丁；重讲一件已经记过的事，只给原记录补一条讲述。改设定以后找正文旧写法时，`retold` 里链到这个字段、且所在章在这个值有效的范围里的讲述，是第一批候选。
20. **本章涉及的条目。** 某一章涉及的条目 = 安放在这一章、生效的剧情变更的 `involves`、参与者（`cast` 的 `who` 与 `as`）与补丁地址里的条目，加上比较时点在这一章的核对点的条目。按计划模式读时，再并上安放在这一章、这条线上看得到的生效计划（`plan`）的同类条目：未写的章只有计划时，“涉及本章”靠它。读取视图另给这一章活页夹分的段（`chapterLines`，没有分段时是章开头那条线一段）和条目给 Agent 的渲染（`render`），供剧情插件取读者读过的讲述与简报里的条目样子。
21. **缺省的读取位置。** 有章时是最新一章的末尾；没有章时是初值。
22. **根因。** 一条变更套不上的根因，是让它从套上变成套不上的那次修订（发布时记在那次修订“带来的变化”里，[`canon.revisions`](revisions.md) 输出 6）；没有这样的修订时，根因是它自己。同一根因的几条套不上合成一条待处理，列出受影响的记录数与范围。
23. **条目树与身份同一的约束。** `parent` 指向存在、未删除的条目，不是自己，不成环；`sameAs` 指向存在的另一个条目，被指向的条目自己没有 `sameAs`（马甲不嵌套）。写入时校验（[`canon.revisions`](revisions.md) 输出 3）。父条目被删除后，子条目照常存在，在树里显示在原父条目的墓碑下。
24. **讲述的发生点。** 正文讲述在读取时按那一章的当前正文定位：在每一段里按字面找原句（不做任何归一化），从段首往后找，下一次从上一处的末尾之后接着找，按段、再按段内的先后数第几处。原句在这一章只出现一次时就是那一处；出现几次时取 `nth` 指的那一处；没给 `nth` 时取第一处，并给这条讲述一条提示 `duplicate-quote`（出现了几次、没指定是哪一处）。发生点是 `{chapter, paragraph, offset}`，`offset` 是这一段里原句之前的字符数（按 UTF-16 码元）。正文以外的讲述没有发生点。发生点不存，正文变了，下一次读取按新的正文算。
25. **讲述的 id。** 讲述的 id 在写入时生成，之后不变：改原句、改 `nth`、改标注都是改这条讲述，不换 id；删掉一条讲述再写一条是新的 id。同一请求里要引用新写的讲述（时间说法的依据，[`canon.time`](time.md) 输入表）时，按它在这条变更 `told` 里的下标写，存下时换成生成的 id。
26. **失联与生效。** 正文讲述在下列情况下失联：原句在那一章的当前正文里一次也找不到；`nth` 大于出现的次数；那一章不在宿主当前给的章序里；宿主取不到那一章的正文。失联的讲述与它的标注照常存着，读取结果里标“失联”并带原因，进提示（`telling-lost`），不进待处理。能定位到的正文讲述是生效的讲述；失联的原句重新出现在正文里，或者一次修订改了它的原句、`nth` 让它能定位，它重新生效。
27. **讲述位置与先后。** 讲述位置写成 `{chapter, paragraph}`（读到这一章的第 `paragraph` 段，含这一段）、`{chapter, edge: "start"}`（这一章还没读）或 `{chapter, edge: "end"}`（读完这一章）。生效的讲述按发生点排先后：先按宿主给的章序，再按段、段内偏移，同一点上按讲述 id 的数值部分。在某个讲述位置上读过的讲述 = 发生点不晚于它的生效讲述。这一章讲的是哪条世界线见 [`canon.worldlines`](worldlines.md)。
28. **标注。** 讲述、剧情变更与决策可以带标注 `{kind, version, …载荷}`。新加或改过的标注写入时要求：种类已登记且可用、允许挂在这类对象上，`version` 等于登记的版本，载荷过登记的 schema，载荷里声明为引用的路径按它声明的种类（条目、剧情变更、世界线、决策）指向存在的对象，条目还要未删除、种类对得上（[`canon.components`](components.md) 输出 17、18）；不过就整次拒收（[`canon.revisions`](revisions.md) 输出 3）。种类不在或版本对不上时，存下来的标注只读：读取结果照常给出存下的载荷，并带诊断 `mark-kind-unknown` 或 `mark-version-unsupported`；写入时它可以原样留着，新加或改它被拒收（同一码）。本能力不解释载荷的意思。
29. **参与者与在场。** `cast` 的每一项有 `who`（条目）或 `label`（没建条目的临时人物，例如“守门的卫兵”）二者之一；`role` 是 `present`（在场）或 `mentioned`（被提到）；`as` 是这一场他用的马甲，`sameAs` 指向 `who`。写入时 `who` 写成马甲的，存成本体加 `as`。`who` 与 `as` 的校验同 `involves`（存在、没删除、在安放上已出场）。某人在一条剧情变更里在场，是这条变更的 `cast` 里有他、`role` 为 `present`。“某人在一段安放里在场的变更”按输出 5 的规则取：实际模式只取已写、生效、这次计算里套上的变更（没有补丁的变更算套上），按计划模式再加上按输出 5 进来的计划。没有 `cast` 的变更不算任何人在场；结果另给出这段里这样的变更有几条，调用方据此降级处理，不当作没人在场。
30. **叙述。** `nature` 为 `narration` 的剧情变更只是讲到（一句预言、一处意象），世界没变：不能有补丁（写入时拒收，`narration-with-patches`），至少有一处讲述（`narration-without-telling`）；可以有参与者、标注、剧情线，可以是计划。它不进时间的说法与计算（[`canon.time`](time.md)）。剧情变更的列表可以按性质筛选。
31. **决策的状态。** 必有的字段与允许的转换见“状态与转换”。表里标了“要作者来源”的转换与修改，写入请求里必须带宿主签发、校验通过的作者授权（[`canon.revisions`](revisions.md) 输出 21），否则整次拒收；授权的来源成为决策的出处 `source`，较早的出处留在改动记录里。已定的决策的结论、理由、风险、约束、标注、范围与挂的对象，只能带作者来源改。理由没给时，读取结果写“作者没说理由”，程序不补。
32. **作者未确认的建议。** 不带作者来源的写入者（包括 Agent）可以新建待定的决策（不能带结论、理由、风险、约束与标注：这几项读取时列在“重新打开前定下的”下面，新建时带上等于不带来源写出作者定过的历史，`invalid-transition`）、改待定决策的要定的事、候选、到期章与挂的对象，或者写 `suggestion`（建议的结论、理由与提议者）。建议不改变状态，读取与渲染时标“作者未确认”。转成已定时结论可以照用建议，也可以不同；`suggestion` 在这次转换里清空。
33. **挂的对象。** `about` 里的引用写入时校验：条目存在且没删除，剧情变更与决策存在，地址的条目存在、字段已声明，章在当前章序里，诊断的 `id` 合乎 `<插件 id>.<名>`、`version` 是正整数、`key` 合乎稳定键的形状，`version` 等于这个诊断现在登记的版本时，`key` 的组成部分与声明的完全相同（不多不少）；版本不同或插件停用时，只查稳定键的通用形状；不过拒收（`invalid-about`）。被挂的条目后来删除时，决策照常存在，读取时那一项显示“已删除的条目”。`scope` 的 `from` 不晚于 `to`。挂在诊断上的已定决策是作者对这条诊断的处理（输出 35）。
34. **诊断。** 插件登记的诊断在读取待处理与提示时算出，不落盘：世界服务调用插件登记的计算，传入这次读取的只读世界、读取位置与模式；级别为 `pending` 的发现进待处理（输出 16），`hint` 的进提示。一次计算的结果按这个顺序处理：按计算返回的先后去重（同一稳定键只留第一条，其余丢弃，并给提示 `diagnostic-duplicate-key`）；去重后最多留前 1000 条，多的丢弃，结果标“不完整”并带 `diagnostic-truncated`；再按输出 35 分出已处理的；最后按输出 16 排序。启用了的插件这一次没算出（还没登记计算、计算抛错）时，这个诊断没有结果，别的诊断照常算，读取照常返回，结果里带 `diagnostic-unavailable`（诊断 id 与原因），并标“不完整”。插件停用时，它的诊断不算，结果另列“因插件停用而未计算的诊断”，不因此标不完整。计算的耗时不进读取结果，记在 `status` 的诊断里（[`canon.project`](project.md) 输出 26）。提示与待处理一样在给定的读取位置算出、排序规则相同，不要求作者处理；本能力自己的提示是 `telling-lost`、`duplicate-quote`、`mark-kind-unknown`、`mark-version-unsupported`。
35. **作者对诊断的处理与版本。** 稳定键按登记声明的组成部分序列化成规范的 JSON 比较。一条发现有一条已定的决策挂在 `{kind: diagnostic, id, key, version}` 上，且诊断 id、稳定键、版本都与这条发现相同时，它不进待处理与提示，列在“已处理”里并带那条决策；那条决策重新打开、放弃或被取代以后，发现照常报出。版本不同的决策不起作用：发现照常报出，并带上旧决策的 id，作者可以一键沿用（带作者来源新建一条挂在当前版本上、结论相同的决策）。插件停用期间，作者的这些决策照常保留。
36. **读取的输入。** 一次读取的输入是：世界版本、章序与各章讲的线、正文快照（宿主最近一次给出的各章正文）、已登记的 Component 类型、标注种类与诊断（各带版本）、各插件报告的诊断数据版本、历法与模糊词表的内容。一次读取从头到尾用同一份输入；读取结果给出世界版本、正文快照的摘要与整份读取输入的摘要。正文快照的摘要：各章正文按 UTF-8 取 SHA-256（宿主取不到正文的章记 `null`），对按章序排的 `[[章 id, 摘要], …]` 取规范的 JSON，再取 SHA-256。读取输入的摘要：对 `{version, chapters: [[章 id, 讲的线或分段]], text: 正文快照的摘要, registry: {components: [[id, version]], marks: [[id, version]], diagnostics: [[id, version]]}, pluginData: [[插件 id, 数据版本]], calendar: 生效的历法（[`canon.time`](time.md) 输出 16）的规范 JSON 的 SHA-256 或 null, fuzzy: 模糊词表的规范 JSON 的 SHA-256 或 null}（历法按内容取摘要，不只看它的版本号：作者改了历法没加版本时，缓存与游标照样作废）` 取规范的 JSON，再取 SHA-256；`chapters` 按章序，其余列表按 id 排序（UTF-16 码元）。别的 Spec 说“读取输入”时都指这一份，不另列。读取结果总等于在这份输入上从头计算的结果，缓存与增量更新不改变结果。

## 状态与转换

剧情变更的生效状态（只由修订改变）：

| 从 | 到 | 由什么 |
|---|---|---|
| 新建 | `active` 或 `held` | 写入时给定；Agent 没把握或与设定冲突的写成 `held` |
| `held` | `active` | 作者处理待处理时采纳（按新建的生效变更重新校验，[`canon.revisions`](revisions.md) 输出 3） |
| `active`、`held` | `undone` | 撤销（带原因） |
| `undone` | `active` | 还原撤销它的修订 |

条目：存在 →（删除）→ 墓碑 →（还原删除它的修订）→ 存在。

决策（只由修订改变）：

| 状态 | 必有的字段 |
|---|---|
| `pending` | `text` |
| `decided` | `text`、`conclusion`、`source` |
| `superseded` | `text`、`supersededBy`（指向一条已定的决策）、`source` |
| `dropped` | `text`、`source` |

| 从 | 到 | 要作者来源 |
|---|---|---|
| 新建 | `pending` | 不要 |
| 新建 | `decided` | 要 |
| `pending` | `decided`、`dropped` | 要 |
| `decided` | `pending`（重新打开） | 要 |
| `dropped` | `pending`（重新打开） | 要 |
| `decided` | `superseded` | 要；`supersededBy` 指向的决策同时或更早已定 |
| `pending` 里改要定的事、候选、到期章、挂的对象、建议 | — | 不要 |
| `decided` 里改结论、理由、风险、约束、标注、范围、挂的对象 | — | 要 |

不在表里的转换拒收（`invalid-transition`）。决策不删除，不再要的转成放弃。

- 转换时字段的去留：不是目标状态必有的字段可以留着，但只在 `decided` 时起作用。重新打开以后，结论、理由、风险、约束、标注照存，读取时列在“重新打开前定下的”下面，守卫与约束不再检查；再转成已定时以这次请求给的为准，没给的沿用。转成已定时 `suggestion` 清空，候选与到期章照存。
- `supersededBy` 可以指向同一请求里新建的决策（临时 id）：一个请求里的对象都写好以后再按这张表校验，取代它的那条在这次请求的结果里必须是已定的。一个请求里每一条需要作者来源的转换或修改，各带绑定它的来源（[`canon.revisions`](revisions.md) 输出 21）。

- 计划进展、套上与否、不完整、待处理都随每次计算重新得出，没有自己的转换。
- 读取总是针对一份读取输入（输出 36）；同一份输入上的读取结果不变，例外是语义档的归纳（见“目标与非目标”）。

## 副作用与数据

- 本能力是计算，没有副作用。对象怎样写进世界日志见 [`canon.project`](project.md)；归纳缓存的读写见同一 Spec 输出 11。

## 失败与恢复

读取不失败：算不下去的情况都成为诊断与待处理，不让整次读取失败。读取位置指向不存在或已删除的章时，读取得到 `chapter-not-found`（[`canon.project`](project.md)）。写入时的校验失败见 [`canon.revisions`](revisions.md)。

| 诊断 | 含义 | 作者或 Agent 怎么办 |
|---|---|---|
| `cannot-apply` | 一条剧情变更在这个位置套不上，带原因（`entry-missing`、`element-missing`、`type-mismatch`、`unknown-value`、`constraint-violated`、`number-out-of-range`）与根因 | 改前面的记录，或改这条 |
| `check-mismatch` | 核对点不符，带算出的值、正文的值与嫌疑记录 | 改或撤某条记录、插一条校正、或改正文 |
| `check-skipped` | 比较时点上地址不完整，没有比较 | 先处理不完整的根因 |
| `incomplete` | 地址的值不完整，带原因 | 先处理根因 |
| `chapter-deleted` | 安放在已删除章上的记录 | 重新安放 |
| `not-reduced` | 语义档的值还没归纳 | 等归纳补上，或手动给起点 |
| `telling-lost` | 正文讲述失联，带原因（原句找不到、`nth` 超出、章不在章序里、取不到正文）；提示 | 改回正文，或改这条讲述的原句、`nth` |
| `duplicate-quote` | 原句在这一章出现几次、没给 `nth`，取了第一处；提示 | 给 `nth`，或给更长的原句 |
| `mark-kind-unknown` | 标注的种类没有登记（插件停用、卸载）；标注只读 | 启用提供它的插件；标注不会丢 |
| `mark-version-unsupported` | 标注的版本与登记的种类版本不同；标注只读 | 换回对应版本的插件 |
| `diagnostic-unavailable` | 启用了的插件登记的诊断这一次没有算出（没登记计算、计算抛错），带原因；结果标“不完整”（插件停用时不报这个码，另列，输出 34） | 看插件的诊断 |
| `diagnostic-truncated` | 一个诊断的发现超过 1000 条，多的丢了；结果标“不完整” | 插件作者收窄诊断 |
| `diagnostic-duplicate-key` | 提示：一个诊断返回了稳定键相同的几条发现，只留了第一条 | 插件作者改键的组成 |
| `diagnostic-declaration-invalid` | 诊断的声明不合规则：id 的前缀不是声明者、同一 id 被声明不止一次（诊断，不是调用失败） | 插件作者改声明 |

## 边界与兼容

- 公开接口：上表的对象形状与地址写法（存进世界日志），读取位置、讲述位置与模式，读取结果里的生效状态、套上与否、不完整、来历、诊断与提示；贡献点 `canon.diagnostics` 的声明形状与计算的签名。
- 对象里未知的字段原样保留，不丢弃，不报错。
- 诊断的计算只读世界：它拿到的只读世界不提供写入；同一版本的世界被几个诊断共用。

## 验收与 Smoke

1. **转账。** 第 3 章“星瑕给星瑾转了两千”是一条变更，两个补丁：星瑕存款 −2000、星瑾存款 +2000。把初值的星瑕存款改成 1000（有下限 0）：这条变更在第 3 章套不上，两人的存款都不变；待处理里一条“套不上”，根因是那次改初值；星瑕存款从第 3 章起不完整，到第 5 章一条“存款定为 500”的赋值后恢复完整。把初值改回四万，诊断消失。
2. **核对点与嫌疑区间。** 初值存款 40000（依据：“卡里还有四万”），第 2 章 −300（估计）、第 3 章 +2000，第 3 章末尾的核对点写 41800。核对点不符，嫌疑记录是第 2、3 章两条，带估计的第 2 章排第一；第 2 章改成 −200 后对得上，待处理消失。第 3 章另一个核对点挂在 +2000 那条变更之前（`before`）写 39800，对得上；那条变更改成待定以后，这个核对点回到 `place` 上比较。
3. **计划的部分兑现。** 第 4 章计划“花 300 买药、救下风信子”；第 4 章还没有已写变更时，第 4 章末尾按计划读含这条计划；第 4 章有了第一条已写变更之后，第 4 章末尾按计划读不含它、第 5 章开头含它。之后记账写“花 50 买药”兑现它，拆出“救下风信子”（`by` 是这条记账变更）排到第 5 章开头。按计划读第 5 章开头，有“救下风信子”；撤销那条兑现记录后，原计划回到未兑现，拆出的计划在计算里一起不生效。第 3 章开头按计划读，原计划还不在（它安放在第 4 章）；兑现若改到第 6 章，第 5 章开头按计划读时原计划在、第 6 章末尾不在。
4. **前史与初值。** 一条前史“6 岁那年父母失踪”把父母的状态设成“失踪”：读初值是原来的值，读第 1 章开头是“失踪”。
5. **语义档。** 星瑾“现在的态度”是语义档，初值“冷淡”，第 1、2 章各一句事件。缓存里有这组输入的归纳时，第 2 章末尾读到归纳的那句；没有时读到“冷淡；之后：……；……”并标“未归纳”。第 3 章正文写明“她终于肯叫哥哥了”记成新的起点后，第 3 章末尾的值从这里重新开始。
6. **删章。** 删掉第 2 章：安放在第 2 章的变更不再套用，各成一条“章已删除”；第 3 章以后的值相应变化。把它们挪到第 3 章后，待处理消失。读第 2 章开头得到 `chapter-not-found`。
7. **改稿与失联。** 第 5 章的讲述“她把钟拨慢了一刻”带一条标注。读者位置第 5 章末尾读过的讲述里有它，发生点是它所在的段。作者改稿删掉这句：它失联，提示里有 `telling-lost`，标注照常存着，第 5 章末尾读过的讲述里不再有它；改回这句，它重新生效，发生点按新正文算。第 6 章的原句“好”出现三次、没给 `nth`：取第一处，提示 `duplicate-quote`；给了 `nth: 2`，取第二处，提示消失。
8. **在场。** 第 3 章“卫兵盘问星瑾”的参与者：星瑾在场、`label` 为“守门的卫兵”的临时人物在场、哥哥被提到；第 4 章有一条没记参与者的变更。问星瑾在第 1 到 4 章在场的变更：得到第 3 章那条，另给出“没记参与者的 1 条”。参与者写成星瑾的马甲：存成星瑾加 `as`。第 3 章涉及的条目里有哥哥。
9. **决策。** Agent 新建待定的决策“哥哥的秘密在哪一章揭开”，并写建议“第 20 章”：读取时标“作者未确认”。Agent 不带作者来源把它转成已定：拒收（[`canon.revisions`](revisions.md) 的 `author-source-required`）。作者在对话里说“定在第 20 章，前面只给暗示”，宿主签发来源后转成已定，结论、来源存下。之后 Agent 改它的约束：拒收；作者带来源重新打开：回到待定，`source` 是这次的来源。
10. **诊断与作者的处理。** 一个插件登记的诊断 X（版本 1，级别 `pending`）在第 8 章末尾报出一条发现。作者标“有意为之”：带来源新建一条挂在 `{X, 这条发现的键, 1}` 上的已定决策，发现移到“已处理”。插件升级、X 的版本改成 2：发现重新进待处理，带上那条旧决策的 id；一键沿用后又移到“已处理”。停用插件：读待处理照常返回、结果完整，X 列在“因插件停用而未计算的诊断”里；两条决策照常存着。

Smoke：不适用——本能力没有独立的运行入口，由 [`canon.project`](project.md) 的 Smoke 一并覆盖。
