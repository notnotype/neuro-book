# 世界引擎：作品里的世界

## 目标与非目标

每部作品有一个世界。本能力定义世界存在哪、怎样打开与恢复、写入怎样排队与落盘、多个进程怎样不互相覆盖、读写接口与事件、后台任务怎样独占写入、语义档的归纳怎样补算，以及在大书上要达到的速度。取舍见 [ADR 0039](../../adr/0039-world-engine-segmented-revision-log.md)。

不承诺：

- Agent 工具、自动预查、记账与写正文的任务：另行定义，它们经本能力的接口读写。
- 作者界面。
- 关键词与语义检索；给 Agent 读的只读文件视图（做不做由检索实验决定）。
- Git 分支合并：两个分支的日志合在一起出现重号时只读打开（输出 4）。
- 同一时刻在两台设备上写同一部作品（例如经同步盘）：第一版只支持同一时刻一台设备写；同步工具留下的冲突副本不读（输出 20）。
- 彻底清除删掉的内容（重写日志的工具）。
- 系列作品、跨作品共享设定。

## 术语与参与者

- **世界日志**：`<项目>/.nbook/world/log/` 下的 JSONL 文件，一行一次修订，只追加，是世界唯一的真相源。
- **段**：世界日志的一个文件。写满就开新的一段，旧段不再写。
- **世界服务**：canon 插件在 `project` 位置（[`runtime.projects`](../runtime/projects.md)）提供的服务，打开这个项目的世界，经远程服务给浏览器与服务端用（[远程服务与 RPC 协议](../runtime/plugin-channel.md)）。项目实例里只有一份世界，各调用方的远程门面都转到它。
- **独占写入**：一个持有者（例如一章的记账）在一段时间里是唯一能发布的写入者；是一份有期限、要续的租约。
- **归纳缓存**：语义档的归纳结果（[`canon.model`](model.md) 输出 9），按输入的摘要存。
- **小模型**：宿主提供的归纳函数：给字段的显示名、起点与事件，返回一句话；带一个版本标识。

## 输入与前置条件

**宿主提供**（canon 插件在项目实例里接好）：

| 输入 | 用途 |
|---|---|
| 章序 | 活页夹里章的 id 与先后；打开时给一次，之后每次变化再给。清单不存在时是“没有章”；清单读不出或不合法时不给新章序（输出 23） |
| 正文 | 按章 id 取当前正文，用于校验讲述的原句（[`canon.revisions`](revisions.md) 输出 3） |
| 小模型 | 可选；没有时语义档一直显示“未归纳”的写法 |
| Component 类型 | [`canon.components`](components.md) 的登记 |

**世界服务的方法**（远程调用；读取结果都带版本）：

| 方法 | 种类 | 主要参数 | 结果 |
|---|---|---|---|
| `status` | 读 | — | 版本、可写或只读（带原因）、独占写入的持有者、诊断（含最近一次打开与发布的重算量与耗时） |
| `entry` | 读 | 条目 id、读取位置、模式、是否要来历 | 条目在这个位置的样子（[`canon.model`](model.md) 输出 5、14、15） |
| `tree` | 读 | 父条目或分组、游标 | 条目树的一层 |
| `lookup` | 读 | 名字或别名的列表、读取位置 | 每个词：匹配到的条目（按这个位置上有效的名字），或没找到 |
| `changes` | 读 | 筛选（章、涉及的条目、剧情线、已写或计划、生效状态、计划进展）、游标、条数 | 剧情变更，每条带生效状态与这次套没套上 |
| `object` | 读 | 对象的种类与 id | 存下来的那个对象（条目、剧情变更、核对点、未决问题、正文建议），没有时为空；改它的写入请求从这里取原样 |
| `pending` | 读 | 读取位置（缺省见 [`canon.model`](model.md) 输出 21） | 待处理（同一 Spec 输出 16） |
| `questions`、`suggestions` | 读 | 状态筛选、游标 | 未决问题、正文建议 |
| `revisions` | 读 | 筛选（章、条目、写入者）、游标 | 改动记录（[`canon.revisions`](revisions.md) 输出 14） |
| `render` | 读 | 条目、读取位置、模式、给作者或 Agent | [`canon.rendering`](rendering.md) 输出 7、8；结果带版本、位置与模式，回写时照带 |
| `preview` | 读 | 写入请求 | [`canon.revisions`](revisions.md) 输出 5 |
| `outcome` | 读 | 请求 id | 这次写入有没有发布、发布成了哪次修订（[`canon.revisions`](revisions.md) 输出 16） |
| `publish` | 写 | 写入请求，可选独占令牌 | 修订 id、版本、新对象的 id 对照，或失败 |
| `editInPlace`、`recordDelta`、`writeBack` | 写 | 见 [`canon.revisions`](revisions.md) 输出 8、9 与 [`canon.rendering`](rendering.md) 输出 12；可选独占令牌 | 同 `publish` |
| `revert` | 写 | 修订 id、是否连同依赖、请求 id；可选独占令牌 | 同 `publish` |
| `acquireExclusive` | 写 | 一句说明（“第 5 章记账”） | 令牌与到期时间，或 `busy` |
| `renewExclusive` | 写 | 令牌 | 新的到期时间，或 `exclusive-lost` |
| `releaseExclusive` | 写 | 令牌 | — |
| `breakExclusive` | 写 | — | 作者强行解除当前的独占写入 |

**事件**：`changed`（每次世界版本前进后：`{version, revision, by, what, title}`；一次读进别的进程写的几行时，每行一个）、`exclusive`（独占写入开始或结束：持有者的说明）、`reduced`（补上了归纳，版本不变）。

## 输出与可观察行为

1. **一个项目一个世界。** 世界服务在项目实例启动时打开这个项目的世界；同一项目实例里的所有调用方（所有窗口、服务端插件、经它们来的 Agent 与后台任务）共用它。浏览器里的插件经 canon 插件的浏览器入口，以自己的身份转到本窗口绑定的项目实例；窗口没有绑定项目时调用得到 `no-project`。
2. **日志的格式。** 每行一个 JSON 对象，是一次修订（[`canon.revisions`](revisions.md) 的形状），另带 `"format": 1`；UTF-8，以换行结尾。版本号从 1 起，每行比上一行大一，跨段也一样。段的文件名是这一段第一行的版本号，左补零到至少 6 位，扩展名 `.jsonl`；打开时按数值排序。
3. **分段。** 追加前，当前这一段已有 256 KiB 或更多时，新开一段；一行不跨段。一行本身超过 256 KiB 时，它独占一段。一行最大 4 MiB，超过的写入拒收（`too-large`）。旧段此后不再写。
4. **打开。** 持日志的跨进程锁，依次读各段、逐行解析、按顺序重放：
   - 目录不存在：空世界，版本 0；
   - 最后一段的末尾有一截没有换行结尾的字节（写了一半）：把这截字节另存到 `.nbook/world/` 下带时间的旁存文件，从段里截掉，写诊断 `torn-tail`，照常可写；
   - 任何一行（包括最后一行）以换行结尾却解析不了、版本号不连续、或不认识的 `format`：只重放到这一行之前，世界只读（`world-read-only`），诊断指出段与行；不改写任何文件。
5. **读的是某一个版本。** 每个读取结果带版本，同一次读取内部看到的是同一个版本；发布进行中、或正在读进别的进程写的行时，读取看到的是之前的完整版本，完成后的读取看到新版本，不会看到一半。
6. **单写者。** 一个项目实例里所有写入排队、一次一个：在当前版本上校验与计算（[`canon.revisions`](revisions.md)），写进日志，写入确定落盘后才更新内存里的世界、发 `changed`。成功返回之后，即使进程崩溃或断电，重开后也看得到这次修订。预览不排队。
7. **写盘失败。** 写入日志失败、且能确定没有落盘（写之前就失败，或已写的部分已截回并落盘）时，这次写入失败（`write-failed`），内存里的世界不变。不能确定有没有落盘时，世界转为只读（`write-unknown`），这次写入的结局按 `outcome` 查：重开项目后，日志里有这次的请求 id 就是已发布。
8. **两个进程。** 写入时持日志的跨进程锁，核对日志的尾部（最后一段的文件名与长度）还是本实例上次读写后的样子；不是（别的 NeuroBook 进程写过），先把新增的行读进来（输出 17），再按 [`canon.revisions`](revisions.md) 输出 7 判这次请求冲不冲突；写完后再核对一次尾部，发现重号就转为只读并写诊断；然后释放锁。
9. **章序。** 打开后与每次宿主给出新章序时，章序与世界里最近一次记下的不同，就发布一次章序调整修订（[`canon.model`](model.md) 输出 3）。章序调整是系统写入，不受独占写入限制；发布前在持锁、读进别的进程写的行之后再比一次，相同就不发。世界只读时不发布，只按宿主给的章序计算并写诊断。
10. **独占写入。** 申请独占的调用方同时持有一个租约订阅；`acquireExclusive` 成功后得到令牌与到期时间（60 秒后）；带这张令牌的写入或 `renewExclusive` 把到期时间往后推 60 秒。持有期间，不带这张令牌的写入都得到 `busy`（详情是持有者的说明与开始时间），读取不受影响；同一时刻只有一个持有者，第二次申请得到 `busy`。持有者 `releaseExclusive`、到期没续、租约订阅结束（所经的连接断开、调用方实例失效或入口停止）、作者 `breakExclusive`，都结束独占并发 `exclusive` 事件；结束后，旧令牌的写入与续期得到 `exclusive-lost`。独占只在这个项目实例里有效：另一个 NeuroBook 进程打开同一部作品时不受它限制，那边的写入按 [`canon.revisions`](revisions.md) 输出 7 判冲突。
11. **补归纳。** 读取遇到缓存里没有的归纳时，结果先标“未归纳”（[`canon.model`](model.md) 输出 9），并把这个输入排进补算；每次发布后，把最新一章末尾缺的归纳也排进去。补算在写入队列之外调用小模型，成功后追加进归纳缓存，发 `reduced`；失败的写诊断、下次遇到再排。同一个项目实例里，同一输入同一时刻只算一次。补算不改版本，也不挡发布。
12. **归纳缓存。** 在 `<项目>/.nbook/cache/reductions.jsonl`，一行一条，只追加，每行一次写完。键是这些输入的 SHA-256：字段所属类型与字段 id、种类与单位、起点、事件列表、小模型的版本标识。同一个键有几行时，取文件里最早的那条有效的；坏行跳过并写诊断。删掉它只会让值暂时回到“未归纳”并重新调小模型。
13. **不经文件服务。** 世界日志与缓存在控制目录 `.nbook/` 下，由世界服务直接读写，不经 nbook.files，不进 nb-history（[`workspace/files.md`](../workspace/files.md)）。
14. **速度。** 在参考机器（项目文件底座定的 i5-1035G1）上，系统负载低于 1，在项目进程里直接调用（不经远程），用三百万字的模拟世界（约 1000 章，每章 5 个计划、15 条已写变更、2 个核对点，约 520 个条目，日志约 19 MB，形状同“证据”里的规模测量）：
    - 打开到可以读（日志文件已在系统缓存里；从开始打开到第一次读取可以返回，含重放与首次计算）：2 秒以内；
    - 打开之后，在随机的读取位置读随机的一个条目（实际模式，不要来历）：50 次的中位数在 20 毫秒以内；按计划模式第一次读取 1 秒以内，之后同样 20 毫秒以内；
    - 在最新一章发布一次记账（15 条变更、2 个核对点，含校验、计算、写入落盘，不算小模型）：10 次的中位数在 100 毫秒以内；
    - 改一个常出场条目的初值（影响从第 1 章起）：5 次的中位数在 1 秒以内。
15. **停止。** 项目实例停止时：正在进行的那次发布做完或失败；排着的写入得到 `stopping`；独占写入结束；补算中的归纳丢弃。
16. **按请求 id 查结局。** `outcome` 按请求 id 回答：已发布（修订 id 与版本）、没有这个请求、或世界只读期间无法确定（`write-unknown`）。
17. **别的进程写的行。** 别的 NeuroBook 进程追加到日志的行，在本实例下一次写入前（输出 8）或日志目录变化时读进来。读入一律在持锁时做（目录变化只是提示），只读以换行结尾的完整行；尾部比记下的短时视为日志被外部改动，转为只读并写诊断。读进来的行在一份新的世界上重放、整体换上，再按每行发 `changed`；与本实例的有重号时转为只读。
18. **大小上限。** 写入请求与读取结果的预算是远程消息的上限（1 MiB）减去 64 KiB：请求超过预算时在调用方一侧就得到 `too-large`，不发出；结果超过预算时世界服务回 `too-large`；列表类的方法用游标分页，单页不超过预算。
19. **游标。** 游标记着它所属的版本；拿着旧版本的游标继续读，得到 `cursor-stale`，从头再读。
20. **日志目录里的其它文件。** 文件名不符合输出 2 的文件（例如同步工具留下的冲突副本）不读，写诊断 `foreign-file`，列出文件名。
21. **目录。** 第一次写入前（含打开时修复写了一半的末行），先建好 `.nbook/world/log/` 与 `.nbook/locks/`。
22. **等锁。** 跨进程锁约 3 秒内拿不到（与项目里别的跨进程写入同一把锁的等法），这次写入或打开时的修复失败（`world-locked`），世界不变；正常关闭时锁随即释放，进程崩溃留下的锁最迟 10 秒后可被接管。
23. **活页夹清单坏了。** 宿主读活页夹清单失败或清单不合法时，世界不改章序，继续按上一次的章序计算，写诊断 `binder-invalid`；清单恢复后照常。清单里没有的章节文件不算章。

## 状态与转换

| 世界状态 | 怎样进入 | 读 | 写 |
|---|---|---|---|
| 打开中 | 项目实例启动 | 等打开完成 | 等打开完成 |
| 可写 | 打开成功 | 可以 | 排队 |
| 独占中 | `acquireExclusive` | 可以 | 只有持令牌的；其余 `busy` |
| 只读 | 坏行、版本不连续、不认识的格式、重号、写入结局不确定 | 可以（到坏行之前，或到最后确定的版本） | `world-read-only` 或 `write-unknown` |
| 已停止 | 项目实例停止 | — | `stopping` |

时序与寿命：

- 方法在世界打开完成后才处理，之前到达的调用等待打开完成；打开后只读时读取照常、写入失败。
- `changed` 事件在写入落盘、内存换上新版本之后发出；收到事件后再读，一定读到不早于事件里版本的世界。
- 独占令牌的寿命不超过它的到期时间，也不超过申请它的调用方实例；调用方断开即失效。
- 同一个窗口重连后（[远程服务与 RPC 协议](../runtime/plugin-channel.md)）重新订阅事件，先读一次 `status` 拿当前版本。

## 副作用与数据

- `<项目>/.nbook/world/log/*.jsonl`：世界日志，属于作品，要备份；作者用 Git 时应提交。
- `<项目>/.nbook/world/` 下的旁存文件：写一半的末行（输出 4），作者确认无用后可以删。
- `<项目>/.nbook/cache/reductions.jsonl`：归纳缓存，可以删。
- `<项目>/.nbook/locks/` 下的锁：跨进程锁（输出 22）。
- 内存：世界的全部对象与修订都在项目实例的内存里。

## 失败与恢复

| 码 | 含义 | 调用方怎么办 |
|---|---|---|
| `world-read-only` | 日志有坏行、版本不连续、重号、格式不认识 | 读诊断，修好日志文件后重开项目 |
| `write-unknown` | 上一次写入有没有落盘不确定，世界转为只读 | 重开项目，按请求 id 查结局 |
| `busy` | 别人正在独占写入 | 等 `exclusive` 事件；作者可以强行解除 |
| `exclusive-lost` | 独占已结束（到期、断开或被强行解除），旧令牌作废 | 停止这次任务 |
| `world-locked` | 跨进程锁约 3 秒内拿不到 | 稍后重试；查别的 NeuroBook 进程 |
| `write-failed` | 写盘失败，确定没有写进去，世界没变 | 看诊断（磁盘、权限）后重试 |
| `too-large` | 请求、结果或一行日志超过上限 | 拆小；列表用游标 |
| `cursor-stale` | 游标所属的版本已经过去 | 从头再读 |
| `chapter-not-found` | 读取位置指向不存在或已删除的章 | 换位置 |
| `stopping` | 项目实例正在停止 | 重开项目后重试 |
| `not-found` | 条目、修订或块不存在 | 重读 |
| `no-project` | 浏览器窗口没有绑定项目 | 打开作品后再调 |
| 路由层的失败（`unknown-outcome`、`unavailable`、`timeout`、`target-gone` 等，[远程服务与 RPC 协议](../runtime/plugin-channel.md)） | 链路或目标实例的问题，不是世界的 | 写方法得到 `unknown-outcome` 时按请求 id 调 `outcome` 查结局（场景 7）；其余按那份 Spec 处理 |
| 其余 | 校验、冲突、渲染与回写的失败 | 见 [`canon.revisions`](revisions.md)、[`canon.rendering`](rendering.md) |

## 边界与兼容

- 公开接口：世界服务的方法、事件与失败码；世界日志的行格式与分段规则（持久化格式，`format: 1`）；归纳缓存的行格式。
- 日志格式只加字段：读到不认识的字段原样保留；`format` 变了的行只读打开，不改写。
- 世界服务只对同一项目实例里的调用方与经远程服务绑定这个项目的客户端开放；日志里的 MDX 是项目数据，按 [`canon.rendering`](rendering.md) 的白名单解释。

## 验收与 Smoke

1. **星瑕的一周。** 把作者界面原型里的星瑕样本（开局、两章记账、作者改设定、还原、补记）作为写入请求依次发布到一个临时项目：每个读取位置上的条目状态、待处理与回执，与原型算出的相比，只在事先列好的差异清单（原型与本组 Spec 不同的地方，逐条注明依据）里有出入；关掉项目再打开，结果逐字相同。
2. **写一半。** 发布第 20 次时在写入落盘之前杀掉项目子进程，并在最后一段末尾留半行：重开后版本是 19，旁存文件里是那半行，诊断 `torn-tail`，再发布得到版本 20。
3. **坏在中间。** 手改第一段中间一行成非法 JSON：重开后只读，诊断指出段与行，读取到坏行之前的版本，写入得到 `world-read-only`，文件没被改写。最后一行以换行结尾但被改坏，同样只读，不截掉。
4. **两个进程。** 两个 NeuroBook 进程开同一个项目，交替发布，包括其中一个在段边界开新段之后：版本连续、没有重号；一边改了星瑕的存款后，另一边先收到 `changed`，基于旧版本改星瑕得到 `version-conflict`，改星瑾正常发布。
5. **独占写入。** 后台任务“第 5 章记账”申请独占：作者在条目页保存得到 `busy`（说明是“第 5 章记账”），读取照常；任务发布后释放，作者再保存成功。作者强行解除时，任务的下一次发布得到 `exclusive-lost`；任务不续期、过了 60 秒，独占自动结束。
6. **分段与速度。** 按输出 14 的形状生成三百万字的模拟世界：除了独占一段的超长行，段大小都不超过 256 KiB 加一行；输出 14 的各项都达标。
7. **断线重试。** 发布时远程连接断了：调用方按请求 id 调 `outcome`，得到已发布的修订；重发同一个请求得到同一次修订，日志里只有一行。

Smoke：场景 1 跑 nb-canon 包目录的 `bun test tests/sample.test.ts`；场景 2、3 是同目录的 `tests/node-log.test.ts`（写一半由注入失败的文件操作造出，不杀进程）；场景 4 是应用包的 `src/plugins/canon/two-process.test.ts`；场景 6 在应用包目录跑 `bun scripts/perf/canon-scale.ts`。
