# 世界引擎：作品里的世界

## 目标与非目标

每部作品有一个世界。本能力定义世界存在哪、怎样打开与恢复、写入怎样排队与落盘、多个进程怎样不互相覆盖、读写接口与事件、后台任务怎样独占写入、语义档的归纳怎样补算，以及在大书上要达到的速度。取舍见 [ADR 0039](../../adr/0039-world-engine-segmented-revision-log.md)。

不承诺：

- Agent 工具、自动预查、记账与写正文的任务：另行定义，它们经本能力的接口读写。
- 作者界面。
- 关键词与语义检索；给 Agent 读的只读文件视图（做不做由检索实验决定）。
- Git 分支合并：两个分支的日志合在一起出现重号时只读打开（输出 4）。
- 彻底清除删掉的内容（重写日志的工具）。
- 系列作品、跨作品共享设定。

## 术语与参与者

- **世界日志**：`<项目>/.nbook/world/log/` 下的 JSONL 文件，一行一次修订，只追加，是世界唯一的真相源。
- **段**：世界日志的一个文件。写满就开新的一段，旧段不再写。
- **世界服务**：canon 插件在 `project` 位置（[`runtime.projects`](../runtime/projects.md)）提供的服务，打开这个项目的世界，经远程服务给浏览器与服务端用（[远程服务与 RPC 协议](../runtime/plugin-channel.md)）。
- **独占写入**：一个持有者（例如一章的记账）在一段时间里是唯一能发布的写入者。
- **归纳缓存**：语义档的归纳结果（[`canon.model`](model.md) 输出 9），按输入的摘要存。
- **小模型**：宿主提供的归纳函数：给字段的显示名、起点与事件，返回一句话。

## 输入与前置条件

**宿主提供**（canon 插件在项目实例里接好）：

| 输入 | 用途 |
|---|---|
| 章序 | 活页夹里章的 id 与先后；打开时给一次，之后每次变化再给 |
| 正文 | 按章 id 取当前正文，用于校验讲述的原句（[`canon.revisions`](revisions.md) 输出 3） |
| 小模型 | 可选；没有时语义档一直显示“未归纳”的写法 |
| Component 类型 | [`canon.components`](components.md) 的登记 |

**世界服务的方法**（远程调用；读取结果都带版本）：

| 方法 | 种类 | 主要参数 | 结果 |
|---|---|---|---|
| `status` | 读 | — | 版本、可写或只读（带原因）、独占写入的持有者、诊断 |
| `entry` | 读 | 条目 id、读取位置、模式、是否要来历 | 条目在这个位置的样子（[`canon.model`](model.md) 输出 5、14、15） |
| `tree` | 读 | 父条目或分组、游标 | 条目树的一层 |
| `lookup` | 读 | 名字或别名的列表、读取位置 | 每个词：匹配到的条目（按这个位置上有效的名字），或没找到 |
| `changes` | 读 | 筛选（章、涉及的条目、剧情线、已写或计划、生效状态、计划进展）、游标、条数 | 剧情变更，每条带生效状态与这次套没套上 |
| `pending` | 读 | 读取位置（缺省最新一章末尾） | 待处理（[`canon.model`](model.md) 输出 16） |
| `questions`、`suggestions` | 读 | 状态筛选 | 未决问题、正文建议 |
| `revisions` | 读 | 筛选（章、条目、写入者）、游标 | 改动记录（[`canon.revisions`](revisions.md) 输出 14） |
| `render` | 读 | 条目、读取位置、模式、给作者或 Agent | [`canon.rendering`](rendering.md) 输出 7、8 |
| `preview` | 读 | 写入请求 | [`canon.revisions`](revisions.md) 输出 5 |
| `publish` | 写 | 写入请求，可选独占令牌 | 修订 id、版本、新对象的 id 对照，或失败 |
| `editInPlace`、`recordDelta`、`writeBack` | 写 | 见 [`canon.revisions`](revisions.md) 输出 8、9 与 [`canon.rendering`](rendering.md) 输出 12；可选独占令牌 | 同 `publish` |
| `revert` | 写 | 修订 id、是否连同依赖；可选独占令牌 | 同 `publish` |
| `acquireExclusive` | 写 | 一句说明（“第 5 章记账”） | 令牌，或 `busy` |
| `releaseExclusive` | 写 | 令牌 | — |
| `breakExclusive` | 写 | — | 作者强行解除当前的独占写入 |

**事件**：`changed`（每次发布后：新版本与修订摘要）、`exclusive`（独占写入开始或结束：持有者的说明）、`reduced`（补上了归纳，版本不变）。

## 输出与可观察行为

1. **一个项目一个世界。** 世界服务在项目实例启动时打开这个项目的世界；同一项目实例里的所有调用方（所有窗口、Agent、后台任务）共用它。
2. **日志的格式。** 每行一个 JSON 对象，是一次修订（[`canon.revisions`](revisions.md) 的形状），另带 `"format": 1`；UTF-8，以换行结尾。版本号从 1 起，每行比上一行大一，跨段也一样。段的文件名是这一段第一行的版本号，左补零到至少 6 位，扩展名 `.jsonl`；打开时按数值排序。
3. **分段。** 追加前，当前这一段已有 256 KiB 或更多时，新开一段；一行不跨段。旧段此后不再写。
4. **打开。** 依次读各段、逐行解析、按顺序重放：
   - 目录不存在：空世界，版本 0；第一次发布时建目录；
   - 最后一段的最后一行写了一半（没有换行结尾，或解析不了）：把这段字节另存到 `.nbook/world/` 下带时间的旁存文件，从段里截掉，写诊断 `torn-tail`，照常可写；
   - 别处有解析不了的行、版本号不连续、或不认识的 `format`：只重放到这一行之前，世界只读（`world-read-only`），诊断指出段与行；不改写任何文件。
5. **读的是某一个版本。** 每个读取结果带版本，同一次读取内部看到的是同一个版本；发布进行中的读取看到的是发布前的版本，发布完成后的读取看到新版本。
6. **单写者。** 一个项目实例里所有写入排队、一次一个：在当前版本上校验与计算（[`canon.revisions`](revisions.md)），追加一行并 fsync 成功后，才更新内存里的世界、发 `changed`。预览不排队。
7. **写盘失败。** 追加或 fsync 失败（磁盘满、没有权限、被占用），这次写入失败（`write-failed`），内存里的世界不变；已写进段里的半行截回原来的长度。截不回时世界转为只读，写诊断。
8. **两个进程。** 追加前持跨进程锁（项目的 `.nbook/locks/` 下），核对最后一段的长度还是本实例上次读写后的长度；不是（别的 NeuroBook 进程写过），先把新增的行读进来，再按 [`canon.revisions`](revisions.md) 输出 7 判这次请求冲不冲突；fsync 后释放锁。
9. **章序。** 打开后与每次宿主给出新章序时，章序与世界里最近一次记下的不同，就发布一次章序调整修订（[`canon.model`](model.md) 输出 3）；世界只读时不发布，只按宿主给的章序计算并写诊断。
10. **独占写入。** `acquireExclusive` 成功后，不带这张令牌的写入都得到 `busy`（详情是持有者的说明与开始时间），读取不受影响；同一时刻只有一个持有者，第二次申请得到 `busy`。持有者 `releaseExclusive`、持有者所在的调用方断开或停止、作者 `breakExclusive`，都结束独占并发 `exclusive` 事件；被强行解除后，旧令牌的写入得到 `exclusive-lost`。
11. **补归纳。** 读取遇到缓存里没有的归纳时，结果先标“未归纳”（[`canon.model`](model.md) 输出 9），并把这个输入排进补算；每次发布后，把最新一章末尾缺的归纳也排进去。补算在写入队列之外调用小模型，成功后追加进归纳缓存，发 `reduced`；失败的写诊断、下次遇到再排。同一输入同一时刻只算一次。补算不改版本，也不挡发布。
12. **归纳缓存。** 在 `<项目>/.nbook/cache/reductions.jsonl`，一行一条，只追加。删掉它只会让值暂时回到“未归纳”并重新调小模型；坏行跳过并写诊断。
13. **不经文件服务。** 世界日志与缓存在控制目录 `.nbook/` 下，由世界服务直接读写，不经 nbook.files，不进 nb-history（[`workspace/files.md`](../workspace/files.md)）。
14. **速度。** 在参考机器（项目文件底座定的 i5-1035G1）上，三百万字的规模（约 1000 章，每章 15 条剧情变更、2 个核对点，日志约 19 MB）：
    - 打开到可以读：2 秒以内；
    - 打开之后，在任意一个读取位置读一个条目：20 毫秒以内；
    - 在最新一章发布一次（不算小模型）：100 毫秒以内；
    - 在第 1 章发布一次：1 秒以内。
15. **停止。** 项目实例停止时：正在进行的那次发布做完或失败；排着的写入得到 `stopping`；独占写入结束；补算中的归纳丢弃。

## 状态与转换

| 世界状态 | 怎样进入 | 读 | 写 |
|---|---|---|---|
| 打开中 | 项目实例启动 | 等打开完成 | 等打开完成 |
| 可写 | 打开成功 | 可以 | 排队 |
| 独占中 | `acquireExclusive` | 可以 | 只有持令牌的；其余 `busy` |
| 只读 | 坏行、版本不连续、不认识的格式、写盘后截不回 | 可以（到坏行之前） | `world-read-only` |
| 已停止 | 项目实例停止 | — | `stopping` |

时序与寿命：

- 方法在世界打开完成后才处理，之前到达的调用等待打开完成；打开失败（只读）时读取照常、写入失败。
- `changed` 事件在 fsync 成功、内存更新之后发出；收到事件后再读，一定读到不早于事件里版本的世界。
- 独占令牌的寿命不超过申请它的调用方（窗口、会话或后台任务）；调用方断开即失效。
- 同一个窗口重连后（[远程服务与 RPC 协议](../runtime/plugin-channel.md)）重新订阅事件，先读一次 `status` 拿当前版本。

## 副作用与数据

- `<项目>/.nbook/world/log/*.jsonl`：世界日志，属于作品，要备份；作者用 Git 时应提交。
- `<项目>/.nbook/world/` 下的旁存文件：写一半的末行（输出 4），作者确认无用后可以删。
- `<项目>/.nbook/cache/reductions.jsonl`：归纳缓存，可以删。
- `<项目>/.nbook/locks/` 下的锁：跨进程锁，进程退出即释放。
- 内存：世界的全部对象与修订都在项目实例的内存里。

## 失败与恢复

| 码 | 含义 | 调用方怎么办 |
|---|---|---|
| `world-read-only` | 日志有坏行、版本不连续、格式不认识，或写盘后截不回 | 读诊断，修好日志文件后重开项目 |
| `busy` | 别人正在独占写入 | 等 `exclusive` 事件；作者可以强行解除 |
| `exclusive-lost` | 独占被强行解除，旧令牌作废 | 停止这次任务 |
| `write-failed` | 写盘失败，世界没变 | 看诊断（磁盘、权限）后重试 |
| `stopping` | 项目实例正在停止 | 重开项目后重试 |
| `not-found` | 条目、修订或块不存在 | 重读 |
| 其余 | 校验、冲突、渲染与回写的失败 | 见 [`canon.revisions`](revisions.md)、[`canon.rendering`](rendering.md) |

## 边界与兼容

- 公开接口：世界服务的方法、事件与失败码；世界日志的行格式与分段规则（持久化格式，`format: 1`）。
- 日志格式只加字段：读到不认识的字段原样保留；`format` 变了的行只读打开，不改写。
- 世界服务只对同一项目实例里的调用方与经远程服务绑定这个项目的客户端开放；日志里的 MDX 是项目数据，按 [`canon.rendering`](rendering.md) 的白名单解释。

## 验收与 Smoke

1. **星瑕的一周。** 把作者界面原型里的星瑕样本（开局、两章记账、作者改设定、还原、补记）作为写入请求依次发布到一个临时项目：每个读取位置上的条目状态、待处理与回执，与原型算出的相同；关掉项目再打开，结果逐字相同。
2. **写一半。** 发布第 20 次时在 fsync 之前杀掉项目子进程，并在最后一段末尾留半行：重开后版本是 19，旁存文件里是那半行，诊断 `torn-tail`，再发布得到版本 20。
3. **坏在中间。** 手改第一段中间一行成非法 JSON：重开后只读，诊断指出段与行，读取到坏行之前的版本，写入得到 `world-read-only`，文件没被改写。
4. **两个进程。** 两个 NeuroBook 进程开同一个项目，交替发布：版本连续、没有重号；一边改了星瑕的存款后，另一边基于旧版本改星瑕得到 `version-conflict`，改星瑾正常发布。
5. **独占写入。** 后台任务“第 5 章记账”申请独占：作者在条目页保存得到 `busy`（说明是“第 5 章记账”），读取照常；任务发布后释放，作者再保存成功。作者强行解除时，任务的下一次发布得到 `exclusive-lost`。
6. **分段与速度。** 按输出 14 的形状生成三百万字的模拟世界：段大小都不超过 256 KiB 加一行，输出 14 的四项都达标。

Smoke：（planned）在临时项目里跑场景 1、2、6 的脚本，实现时补路径。
