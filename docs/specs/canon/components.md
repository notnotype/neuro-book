# 世界引擎：Component 类型与字段声明

## 目标与非目标

条目上的数据按 Component 分块：一个带数据的 Component 类型在条目的状态里占一个命名空间，用字段声明说清每个字段是什么、怎么变、怎么约束。本能力定义类型怎样登记、字段怎样声明、条目上的实例怎样加上、去掉、启用，以及类型对不上时数据怎样保留；另定义引用（字段、列表的键、标注里指向条目的值）怎样声明与统一处理，以及标注种类怎样登记。内置类型与第三方类型走同一个贡献点（[ADR 0027](../../adr/0027-builtin-and-third-party-plugins-are-equal.md)）。

不承诺：

- **schema 升级函数**：类型声明带版本号，状态值、补丁与修订里的值都记着版本；第一版没有升级，版本对不上的命名空间只读（输出 11）。
- **数值溢出“截到上限”**：第一版只做拒绝。
- 作者界面（各类型的 Tab）、查询视图、记账说明与用法说明的用法：本能力只登记与转交它们，界面与说明怎么给 Agent 另行定义。
- 第一版内置类型（人物、面板、情节）的字段清单：另行定义；本能力只定它们共用的声明写法。
- 关系、地点与地图 Component。

## 术语与参与者

- **Component 类型**：一种可以加在条目上的能力，由插件声明。带数据的类型有一个**命名空间**（例如 `panel`）与一组字段声明；只做查询的类型没有命名空间。
- **实例**：某个条目上的一个 Component。一个条目上同一类型最多一个实例。
- **字段声明**：一个字段的 id、显示名、种类、档、约束等（输入与前置条件的表）。
- **字段 id**：补丁、核对点、MDX 里的引用用的稳定标识，合法标识符，登记后不变。
- **档**：精确档的值由程序按补丁计算；语义档的值是一段文字，由小模型从最近一个确定的起点与之后的事件归纳（[`canon.model`](model.md) 输出 9）。
- **启用**：每个实例的保留控制字段，地址 `<命名空间>.启用`，表示这个位置上该命名空间可不可见、可不可被剧情变更写。
- **去掉**：创作修改把实例从条目上拿掉；数据保留，与“这个位置没启用”是两回事。
- **类型版本**：类型声明的整数版本号。
- **引用**：指向一个条目的值，写成 `{ref: 条目 id}`；哪些位置是引用由声明给出（输出 18）。
- **以引用为键的列表**：元素 id 就是它指向的条目 id 的列表，一个条目最多一行（输出 19），例如人物的知情（一行一个知识点）。
- **标注种类**：插件登记的一种标注（[`canon.model`](model.md) 输出 28），声明载荷的 schema 与载荷里哪些路径是引用。

## 输入与前置条件

类型经 canon 插件的贡献点 `canon.components` 登记。声明在插件清单里，插件不激活也能读；插件登记且启用期间类型可用，与它的入口是否激活无关：

| 项 | 必填 | 规则 |
|---|---|---|
| `id` | 是 | `<插件 id>.<名>` |
| `label` | 是 | 给作者看的名字（“面板”） |
| `namespace` | 带数据时 | 合法标识符；不能是 `entry`、`text`、`ref` 与保留名（[`canon.rendering`](rendering.md) 输出 2） |
| `version` | 带数据时 | 正整数 |
| `fields` | 否 | 类型固定的字段声明，每个必须给出 `id` |
| `instanceFields` | 否 | 为真时，实例可以在自己身上再声明字段（面板这类每个条目字段不同的） |
| `agentView` | 否 | 给 Agent 的文字视图，MDX，按 [`canon.rendering`](rendering.md) 的白名单解释，地址的根是本命名空间 |
| `bookkeepingNotes`、`usageNotes` | 否 | 记账说明、用法说明，文字 |

字段声明：

| 项 | 规则 |
|---|---|
| `id` | 合法标识符，在命名空间里不重复，不叫 `启用`。类型固定的字段由类型作者给出；实例字段新建时由 `label` 生成（`label` 本身合法且没被占用就用它，否则加序号），生成结果随声明存下。改 `label` 不改 id |
| `label` | 显示名 |
| `kind` | `number`、`text`、`enum`、`boolean`、`list`、`image`、`ref` |
| `precision` | `exact`（缺省）或 `semantic`，只用于 `number` 与 `text`（列表元素的子字段也可以用，输出 20） |
| `targets` | 可选，只用于 `ref` 与 `keyedBy`：允许指向的条目种类（条目的 `type`）的列表；没有时任何种类都行 |
| `keyedBy` | 可选，只用于 `list`：为 `"ref"` 时这是以引用为键的列表（输出 19），可以带 `targets` |
| `unit` | 可选，数值的单位 |
| `min`、`max` | 可选，只用于精确档的 `number`；`max` 可以是同一命名空间里另一个精确档数值字段的 id（“魔力上限”） |
| `options` | `enum` 的选项 |
| `item` | `list` 的元素字段声明（种类限 `number`、`text`、`enum`、`boolean`、`image`、`ref`，不嵌套列表） |
| `retold` | 可选，为真表示这个文字字段会在正文里被重述（外观、性格），改设定以后要找正文旧写法 |
| `carry` | 可选，为真表示回溯时随回溯者保留（回溯次数、魔力这类用掉就不回来的），回溯分叉缺省把它带过去（[`canon.worldlines`](worldlines.md) 输出 7） |

各种类的值与可用补丁（补丁的执行规则见 [`canon.model`](model.md) 输出 6）。所有种类的值都可以是未知：

| 种类与档 | 值 | 可用的补丁 |
|---|---|---|
| `number` 精确档 | 数（输出 14） | 赋值、加减 |
| `text` 精确档 | 文字 | 赋值（整值替换，可以写成“把 A 换成 B”） |
| `number`、`text` 语义档 | 文字（当前的样子） | 赋值（新的起点：数或文字；数按十进制写成文字，声明了单位的后面加单位）、事件（一句发生了什么） |
| `enum` | 选项之一 | 赋值 |
| `boolean` | 真或假 | 赋值 |
| `list` | 元素列表；元素有程序生成的 id、`label` 与 `item` 声明的子字段 | 增加元素、去掉元素、给元素的子字段赋值或加减 |
| `image` | `{"图片": 作品内路径, "说明": 文字}`（输出 15） | 整值赋值 |
| `ref` | 引用 `{ref: 条目 id}`（输出 18） | 赋值 |

地址只能指到声明过的叶子：字段、列表元素、元素的子字段。`image` 只能整值写，不能单写它的“说明”。

**标注种类的登记**（贡献点 `canon.marks`，声明在插件清单里，插件不激活也能读）：

| 项 | 必填 | 规则 |
|---|---|---|
| `id` | 是 | `<插件 id>.<名>`；存下来的标注的 `kind` 就是它 |
| `version` | 是 | 正整数；载荷的形状或意思变了就加一 |
| `label` | 是 | 给作者看的名字（“揭示”“伏笔节点”） |
| `attachTo` | 是 | 能挂在哪类对象上：`telling`、`decision` 的非空子集 |
| `schema` | 是 | 载荷的 JSON Schema（不含 `kind`、`version` 两个键） |
| `refs` | 否 | 载荷里是引用的路径与允许的条目种类，`[{path, targets?}]`；路径用 `.键` 逐级写，`[]` 表示数组的每个元素（`nodes[].foreshadow`） |

## 输出与可观察行为

1. **登记。** `canon.components` 的每条声明在载入时校验：`namespace` 合法且不是保留名；固定字段都有 id，id 合法、在命名空间里不重复、不叫 `启用`；`max` 指向同一命名空间里的精确档数值字段；`enum` 有选项。不过的整条不登记，写诊断 `component-declaration-invalid`，指出哪一项。
2. **命名空间撞名。** 两个已登记的类型声明了同一个 `namespace` 时，两个都不可用，写诊断 `component-namespace-conflict`，列出两个类型的 id；世界里这个命名空间的数据保留，按输出 12 处理。不按登记先后决定谁赢。
3. **加实例。** 给条目加一个带数据的类型是一次创作修改：在条目的初值里加上这个命名空间，字段的初值都是未知，`启用` 为真。条目上已有这个类型、且没被去掉时，拒收（`component-exists`）；已被去掉的，按输出 7 恢复。只做查询的类型加上后只记“有这个 Component”，不占命名空间。
4. **实例字段。** 类型允许 `instanceFields` 时，作者或 Agent 可以在实例上新增、改显示名、删除字段声明，都是创作修改；新增字段的 id 按“输入”的规则生成并存下，与类型固定的字段一起不重复。删除一个字段声明时，这个字段的初值与所有补丁保留，读取时看不到它；再声明同一个 id 时恢复（种类与档的要求见输出 16）。
5. **启用。** `启用` 是内核随时可写的控制字段：初值里不启用、再由某一章的剧情变更启用，表示“从这一章起有这个 Component”。一个位置上没启用的命名空间，在这个位置读不到（读取结果里没有它）；剧情变更对它的数据字段打补丁，写入时拒收，已存的在计算时按“不适用”跳过（[`canon.model`](model.md) 输出 7）。初值与创作修改不受启用限制。同一条剧情变更里先处理启用，再处理数据字段，整条一起校验。
6. **启用前的位置。** 作者在启用前的位置上看这个命名空间时，读取结果标明“第 N 章起生效”，给出的是它在启用那一刻的起始值。
7. **去掉实例。** 去掉是一次创作修改：实例标为“已去掉”，数据隐藏、保留；读取、渲染都看不到它，对它的补丁在计算时按“不适用”跳过。“已去掉”与“没启用”分开记，互不影响。再加回同一类型时去掉这个标记，原来的数据与各位置的启用照旧，不重新从未知开始。
8. **字段 id 与显示名。** 补丁、核对点、MDX 里的引用都用字段 id，改显示名不影响它们。给 Agent 的带值写法与查询结果里，显示名与 id 不同时两者都给（[`canon.rendering`](rendering.md) 输出 9）。写入请求里的字段可以写 id 或显示名，按当前声明解析成 id 后存下；显示名在命名空间里不唯一时拒收（`ambiguous-field`）。
9. **约束。** 精确档数值字段的 `min`、`max` 在一条剧情变更的补丁全部套完之后检查；`max` 引用的字段取同一时刻的值。不满足时，写入拒收（`constraint-violated`），计算时这条变更套不上（[`canon.model`](model.md) 输出 7）。值或 `max` 引用的值是未知时，这一项不检查；语义档不检查约束。
10. **版本随值记录。** 每个命名空间的数据、对它的补丁、修订里它的改前与改后，都记着写入时的类型版本。
11. **版本对不上。** 世界里某个命名空间的数据记的版本与当前登记的类型版本不同（第一版没有升级函数）：这个命名空间只读，读取与渲染照常给出存下来的值，并带诊断 `component-version-unsupported`；对它的写入拒收（同一码）。
12. **类型不在。** 数据所属的类型没有登记（插件停用、卸载，或撞名）：数据保留，读取结果里给出原始值并带诊断 `component-unknown`，渲染这个命名空间的字段显示占位；对它的写入拒收（同一码）。类型重新可用后恢复正常，不丢数据。
13. **只做查询的类型。** 没有命名空间的类型不能被补丁写，读取结果里只列出“有这个 Component”。
14. **精确档的数。** 精确档的数是有限的十进制数，绝对值小于一千亿（10¹¹），最多 4 位小数（这样的数在 JSON 里读写不失真）；加减按十进制精确计算，不出现二进制浮点的误差（0.1 加 0.2 等于 0.3）。写入的数或算出的结果超出这个范围，写入拒收（`number-out-of-range`），计算时这条变更套不上。
15. **作品内路径。** 图片的路径是相对作品根目录的路径：不带协议、不以 `/` 开头、没有 `..` 段、不在 `.nbook/` 下。不合规则的写入拒收（`invalid-asset-path`）。文件不存在时照样存，渲染显示“图片找不到”的占位。
16. **重新声明同一个 id。** 实例上重新声明一个删除过的字段 id 时，种类与档必须与原来的相同，否则拒收（`field-redeclare-mismatch`）；显示名、单位、约束可以不同。
17. **标注种类。** `canon.marks` 的每条声明在载入时校验：`id` 的写法，`attachTo` 非空，`schema` 是合法的 JSON Schema，`refs` 的每条路径在 schema 里存在、是字符串。不过的整条不登记，写诊断 `mark-declaration-invalid`，指出哪一项。种类可用的条件与 Component 类型相同（插件登记且启用）；不可用、或存下的版本与登记的不同时，已存的标注按 [`canon.model`](model.md) 输出 28 只读。
18. **引用。** 引用位置有：`ref` 种类的字段与元素子字段；以引用为键的列表的元素 id（输出 19）；标注种类声明的 `refs` 路径；内核自己的引用位置（剧情变更的 `involves`、`lines`、`cast` 的 `who` 与 `as`、`links` 指向的计划，决策的 `about`，条目的 `parent`、`sameAs`）。对所有引用位置，内核统一做：
    - 写入时，新写或改过的引用指向的条目存在、没删除、种类在 `targets` 里；不过拒收，详情给出路径与原因（`ref-invalid`：`entry-missing`、`entry-deleted`、`ref-type-mismatch`）；
    - 写入请求里的临时 id（`tmp:` 开头）在引用位置上换成程序生成的 id（[`canon.revisions`](revisions.md) 输入）；不在引用位置上的 `tmp:` 文字原样存下；
    - 指向的条目后来删除时，存下来的引用照常给出，读取与渲染标“已删除的条目”并带它原来的名字；对它的补丁照常套上（引用值本身不因条目删除而失效）；
    - 改动记录按条目筛选时，新写或改过指向这个条目的引用的修订也算（[`canon.revisions`](revisions.md) 输出 14）；
    - 还原的依赖：新写了指向被还原的修订所建条目的引用的修订，依赖它（[`canon.revisions`](revisions.md) 输出 12）。
19. **以引用为键的列表。** `keyedBy` 为 `ref` 的列表，增元素时给的元素 id 是一个条目 id（或同一请求里的临时 id），校验同输出 18；同一条目在列表里最多一行，增一个已有的 id 套不上（[`canon.model`](model.md) 输出 6）。元素的 `label` 不存，读取时取被引用条目在这个位置上的名字；条目已删除时显示“已删除的条目”。地址照常写 `[元素 id]`（`know.知情[k12].程度`）。
20. **列表元素的语义档。** 列表元素的子字段可以声明 `precision: semantic`（只用于 `number`、`text`）：起点、事件、归纳与归纳缓存都按元素子字段的地址记，规则同字段的语义档（[`canon.model`](model.md) 输出 9）；去掉元素后它的事件不再参与归纳。

## 状态与转换

| 实例状态 | 怎样进入 | 读取 | 剧情变更的补丁 |
|---|---|---|---|
| 不存在 | 初始 | 没有 | 写入拒收 |
| 存在、在这个位置启用 | 加上；启用 | 有 | 正常 |
| 存在、在这个位置未启用 | 初值里不启用，或被剧情变更停用 | 没有（作者在启用前的位置上看到输出 6） | 写入拒收；已存的按“不适用” |
| 已去掉 | 去掉（输出 7） | 没有 | 写入拒收；已存的按“不适用” |
| 只读 | 版本对不上（输出 11）、类型不在（输出 12） | 有原始值与诊断 | 写入拒收 |

- 类型随插件的登记与启用可用、随停用与卸载不可用；变化在下一次读取时生效，不改写世界里的数据。
- 实例的加、去、启用都是修订（[`canon.revisions`](revisions.md)），能还原。

## 副作用与数据

- 类型声明在插件清单里，不写进世界。
- 实例（含“已去掉”的标记与类型版本）、实例字段声明、各命名空间的初值都存在条目的初值里，随修订写进世界日志（[`canon.project`](project.md)）；去掉的实例与删除的字段声明不删数据。

## 失败与恢复

| 码 | 含义 | 调用方怎么办 |
|---|---|---|
| `component-declaration-invalid` | 类型声明不合规则（诊断，不是调用失败） | 插件作者改声明 |
| `component-namespace-conflict` | 两个类型声明了同一个命名空间（诊断） | 停用其中一个插件 |
| `component-unknown` | 数据所属的类型没有登记 | 启用提供它的插件；数据不会丢 |
| `component-version-unsupported` | 数据的版本与登记的类型版本不同，第一版不升级 | 换回对应版本的插件 |
| `component-exists` | 条目上已有这个类型的实例 | 不再加 |
| `component-disabled` | 剧情变更写了生效位置上没启用或已去掉的命名空间 | 先启用或加回，或改成创作修改 |
| `ambiguous-field` | 写入里的显示名对应多个字段 | 改用字段 id |
| `unknown-field` | 地址指到没声明的字段、子键，或单写了图片的一部分 | 改地址 |
| `constraint-violated` | 补丁套完后不满足 `min`、`max` | 改补丁；详情给出字段、约束与算出的值 |
| `number-out-of-range` | 数超出精确档的范围或小数位数 | 改数 |
| `invalid-asset-path` | 图片路径不是作品内的相对路径 | 改路径 |
| `field-redeclare-mismatch` | 重新声明的字段 id 种类或档与原来不同 | 换一个新字段 |
| `mark-declaration-invalid` | 标注种类的声明不合规则（诊断，不是调用失败） | 插件作者改声明 |
| `ref-invalid` | 引用指向的条目不存在、已删除或种类不对，详情给出路径与原因 | 改引用，或先建那个条目 |

## 边界与兼容

- 公开接口：贡献点 `canon.components` 与 `canon.marks` 的声明形状（输入与前置条件里的各张表）、字段 id 规则、各种类的值形状与引用值的写法（存进世界日志，属于持久化格式）。
- 标注种类与 Component 类型一样没有升级函数：载荷的形状变了只能升版本，旧版本的标注只读。
- 字段 id 一经登记不变；类型改字段种类、拆字段要升级函数，第一版不支持，只能新增字段。
- 第三方类型与内置类型同一套规则，没有内部登记表。

## 验收与 Smoke

1. **从第 3 章起有面板。** 星瑕加面板时选“从第 3 章起”：初值里不启用，第 3 章一条剧情变更启用。第 2 章末尾读星瑕，结果里没有 `panel`；作者在第 2 章看面板，标“第 3 章起生效”并给出起始值；第 2 章的一条剧情变更给 `panel.存款` 加减被拒收（`component-disabled`）；第 3 章末尾读到面板。去掉面板再加回来，各章读到的值与启用情况都与去掉之前相同。
2. **版本对不上。** 面板类型的声明版本从 1 改成 2（没有升级函数）后打开作品：星瑕的面板照常读到、带诊断 `component-version-unsupported`，给它记一笔被拒收；改回版本 1，可以写，数据没变。
3. **撞名。** 两个插件都声明命名空间 `panel`：两个都不可用，诊断列出两者；停用一个后，另一个可用，数据完整。
4. **数。** 存款初值 0.1，记一笔 +0.2，读到 0.3；记一笔 +0.00001 被拒收（`number-out-of-range`）。
5. **引用与以引用为键的列表。** 一个类型的“知情”是以引用为键的列表，`targets` 为“知识点”，元素有语义档的子字段“他以为的”。一次写入新建知识点“哥哥能回溯”（临时 id `tmp:k`），同一请求给星瑾的知情加一行 `[tmp:k]`：发布后行的 id 是生成的知识点 id。给知情加一行指向一个人物：拒收（`ref-invalid`，`ref-type-mismatch`）。删除这个知识点：星瑾的那一行照常存在，显示“已删除的条目”；还原新建它的修订得到 `has-dependents`，列出加这一行的修订。按条目筛改动记录时，加这一行的修订出现在这个知识点下面。
6. **标注种类的版本。** 插件登记标注种类“揭示”（版本 1，`refs` 是 `point`，`targets` 为“知识点”）。给一处讲述加一条载荷缺字段的揭示：拒收。停用插件：已存的揭示照常读到、带 `mark-kind-unknown`，给它再加一条揭示被拒收，改这处讲述的原句照常可以；插件以版本 2 回来：已存的揭示带 `mark-version-unsupported`、只读。

Smoke：不适用——本能力没有独立的运行入口，由 [`canon.project`](project.md) 的 Smoke 一并覆盖。
