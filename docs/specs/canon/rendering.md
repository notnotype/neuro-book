# 世界引擎：渲染与带值写法

## 目标与非目标

条目的主文字是带标签的 Markdown，可以引用本条目与别的条目的字段（`<V of="panel.魔力" />`）。同一份数据给作者看界面、给 Agent 读文字。本能力定义主文字的写法与白名单、按块解析、给作者的渲染结果、给 Agent 的带值写法与交回时的去值、给不回写的读者（例如写手的简报）的纯文字。只解释白名单，不执行代码；Markdown 的读法与章节编辑器相同（[`workspace.markdown-dialect`](../workspace/markdown-dialect.md) 的 core，[ADR 0064](../../adr/0064-entry-text-uses-tags-and-the-chapter-parser.md)）；同样的输入在浏览器里与在项目进程里算出的结果逐字相同。

带（planned）的条目与表是换成标签写法以后的合同（[ADR 0064](../../adr/0064-entry-text-uses-tags-and-the-chapter-parser.md)）；标“（planned：删除）”的条目在它们实现时去掉。

不承诺：

- 作者在界面里编辑主文字的方式：见 [`canon.author-ui`](author-ui.md)。
- 跨段的条件：`If` 只在一段之内（planned）。
- 文字拼接与格式化：式子只算数、比较与逻辑（planned）。
- 按任意历史版本渲染：只渲染当前版本。

## 术语与参与者

- **块**：主文字的存储与解析单位，有稳定 id；一块是闭合的语法单元。
- **标签**：主文字里 `<` 加大写字母开头的名字写成的一处，例如 `<V of="panel.魔力" />`（planned）。
- **活的标签与字面的标签**：落在正文里、按它的意思解释的是活的；落在行内代码、代码块里或前面有转义（`\<V`）的是字面的，照原文显示（planned）。
- **式子**：`V` 的 `expr` 与 `If`、`ElseIf` 的 `test` 写的内容（planned）。
- **字段引用**：式子里指到一个地址的部分：从 `entry`、`text`、本条目的命名空间，或 `ref('条目 id')` 开始的成员访问链；`V` 的 `of`（加 `entry`）是一个字段引用。
- **带值写法**：给 Agent 的渲染：源文里活的标签带上当时的值与说明（planned）。
- **装饰**：带值写法里由程序加的属性与内容（输出 9），交回时去掉（planned）。
- **去值**：把 Agent 交回的文字里的装饰去掉、换回源文的写法（输出 22，planned）。
- **登记的标签**：插件登记了名字、属性与给模型的描述的标签（planned）。

## 输入与前置条件

- **渲染**的输入：条目、读取位置、模式（实际或按计划）、给谁看（作者或 Agent）、世界版本。也用于 Component 的 `agentView`（[`canon.components`](components.md)），这时地址的根是那个命名空间（planned）。
- **回写**的输入（planned：删除）：条目、块 id、读取时的版本与读取位置、改过的带值写法文字；意图（创作修改或剧情变化，缺省创作修改）。
- **写入**主文字的一块（新建、整段替换、增块）时按输出 1 检查；Agent 写入的文字先按输出 22 去值（planned）。

**白名单**（planned）

| 类别 | 放行 |
|---|---|
| Markdown | 与章节编辑器相同的读法：CommonMark，GFM 的表格、删除线（只认 `~~`）与任务列表；中文标点旁的强调按 CJK 友好的规则解析（`**“走吧。”**然后` 成粗体）；HTML 形式的强调与换行（小写的 `<strong>`、`<b>`、`<em>`、`<i>`、`<del>`、`<s>` 成对，`<br>`，包括独占一行、只有换行的 `<br>`） |
| 取值 | `<V of="地址" />`；别的条目的字段 `<V entry="条目 id" of="地址" />` |
| 计算值 | `<V expr="式子" />` |
| 条件 | `<If test="式子">…<ElseIf test="式子" />…<Else />…</If>`：`ElseIf` 可以有几个，`Else` 至多一个且在最后；整个条件在一段之内，各支是行内的文字，可以带强调、链接与别的标签（不能再套 `If`） |
| 条目引用 | `<Ref id="条目 id" />` |
| 图片 | `<Image src="作品内路径" alt="说明" />`；图片字段 `<Image of="地址" alt="说明" />`（`alt` 可省） |
| 登记的标签 | `<名字 属性="…" />`，名字与属性按登记（输出 19） |

标签的写法：名字区分大小写；属性只有 `名="值"` 一种写法，值里不能有 `"` 与换行；一个标签不跨行；除 `If` 外都自闭合。从左到右认，认出一个标签以后从它的结尾接着认，属性值里的 `<` 不另算标签。`B`、`BR`、`EM`、`I`、`DEL`、`S`、`STRONG`（不分大小写）是 HTML 的强调与换行，不是标签名。式子里的字符串用单引号（`test="character.身份 == '学生'"`）；三元式可以选出数、真假或文字（`expr="panel.魔力 >= 1000 ? '能' : '不能'"`），选出文字不算格式化。地址的写法同字段引用、不带 `ref`：`panel.魔力`、`att.态度[e1].称呼`、`entry.name`、`text[块 id]`；存下来的地址照原样认（元素 id 是 `true`、`default` 这类 JS 的字面量与关键字时，式子里要写成 `['true']`，`of` 里直接写 `panel.list[true]`）。

式子只许下面这些语法节点（ESTree 的名字），别的一律拒收：

| 节点 | 限制 |
|---|---|
| `Identifier` | 只能作为字段引用的根：`entry`、`text`、本条目的命名空间；或作为函数名 |
| `MemberExpression` | 非计算的 `.键`；计算的 `[常量]` 只许字符串字面量或标识符写法的元素 id（`[t3]` 与 `['t3']` 等价），数字下标与动态下标拒收 |
| `CallExpression` | `ref('条目 id')`（一个字符串字面量参数，只能作为成员访问链的开头）；内置函数（输出 2）（planned） |
| `Literal` | 字符串、数、真假、`null` |
| `BinaryExpression` | `==` `!=` `===` `!==` `<` `<=` `>` `>=`；`+` `-` `*` `/` `%`（planned） |
| `LogicalExpression` | `&&` `||` |
| `UnaryExpression` | `!`；`-`（planned：作用于任意操作数） |
| `ConditionalExpression` | `?:` |

- 根名字的解析顺序：`entry`、`text`、`ref`、本条目的命名空间（Component 视图里是那个命名空间的字段）。`entry`、`text`、`ref` 是保留名，命名空间不能用；内置函数名只在调用的位置认（`round(x)` 是函数，`round.计数` 仍是名叫 `round` 的命名空间的地址），不占命名空间的名字（planned）（[`canon.components`](components.md) 输入与前置条件）。

## 输出与可观察行为

1. **写入时检查。**（planned）写入主文字的一块（新建、整段替换、增块）时检查，不过就拒收，指出块、行与列（[`canon.revisions`](revisions.md) 的 `validation-failed`）。检查之前先去掉开头的 BOM、把换行规范成 LF；存下来的是规范后的原文，活的标签写成规范写法（输出 18）。拒收的情形：
   - 白名单以外的 Markdown：别的原样 HTML、HTML 注释、脚注、数学（`unsupported-markdown`）；嵌套深到读不出结构的（几万层引用或列表，只会来自粘贴）同样拒收（`unsupported-markdown`），存下来的旧数据里有这样的块时照输出 4 按出错显示；
   - 活的标签名字不认、属性不认或缺了必填的属性、`V` 与登记的标签不是自闭合的，或带着装饰（输出 9 的属性与内容）（`unknown-tag`；没登记的标签见输出 19）；
   - 式子写错、带注释、用了白名单以外的节点或运算符，地址写错（`forbidden-syntax`，行列落在属性值里）；`expr` 一个字段引用都没有（`no-field-expression`）；
   - `If` 没闭合、跨段、被强调切开或套在另一个 `If` 里（`cross-block`）；孤立的 `ElseIf`、`Else`、`</If>`，或内置与登记的标签名后面写了属性却不成标签（例如少了收尾的 `<V of="panel.魔力"`、属性用了单引号或没加引号、`=` 两边有空格），又不在代码里、没转义（`tag-malformed`；落在链接与图片说明里的同样这样判）。别的 `<` 加大写名字（`评级 <A 级`）是文字；
   - 标签落在链接地址、链接标题或图片说明里（前面有转义的也算），或落在 Markdown 会丢掉的地方（例如表格里多出来的单元格）（`tag-not-live`）；表格的某一行比表头多出单元格（`unsupported-markdown`：多出的单元格 Markdown 会丢掉，编辑器把整张表当原样保留）；
   - 一块里 `<` 加大写名字的写法（活的、字面的、不成标签的都算）与标签以外的 U+E000 到 U+F8FF 里不同的字合计超过 6000 个（`too-many-tags`；同一个字出现几次算一个）。

   块内没有定义的引用式链接按普通文字显示，不拒收。
2. **保留名与内置函数。**（planned）写成函数调用的有 `ref` 与七个内置函数：`round(x)`、`round(x, 位数)`（位数只许整数字面量，可以是负的：`round(x, -2)` 舍到百位）、`floor(x)`、`ceil(x)`、`min(a, b, …)`、`max(a, b, …)`、`abs(x)`、`percent(部分, 整体)`（结果是文字，例如 `"40%"`，四舍五入到整数）。四舍五入的 .5 远离 0（`round(-2.5)` 得 -3），舍入前先去掉乘出来的二进制尾差（`round(1.005, 2)` 得 1.01）。保留名的列表随版本只增不减。
3. **块由写入方给出。** 主文字的块怎么分由写入方（作者的界面、Agent 的工具）决定，系统不替它切：新建条目时给的每段主文字、增块与整段替换给的原文各是一块。一块是闭合的语法单元（输出 1），里面可以有几段。块的边界只由增块、删块、整段替换一块改变，不重新切；标题只是块里的普通内容，不是解析的边界。公开函数 `splitBlocks`（把一段文字按顶层的语法节点切成块）留给要整段导入文字的调用方，产品里没有调用方。
4. **按块解析。** 渲染时每块单独解析与求值。某一块出错（存下来的旧数据过不了当前白名单），这一块显示成纯文本并带诊断（块 id、行、列、原因），其余块照常。
5. **求值。** 表达式在给定的版本、位置与模式上取值；结果只取决于输入。引用别的条目，取它在同一版本、同一位置、同一模式上的状态。未知按三值逻辑传：
   - 比较的任一边是未知，结果是未知；`<` `<=` `>` `>=` 两边不同是数或不同是文字时，结果是未知；
   - `!未知` 是未知；`假 && 未知` 是假，`真 && 未知` 是未知；`真 || 未知` 是真，`假 || 未知` 是未知；
   - 条件的判断是未知时，整个条件表达式的结果是未知，不当成假。
   - 运算与函数（planned）：任一操作数或参数是未知，结果是未知；`+ - * / %` 与 `round`、`floor`、`ceil`、`min`、`max`、`abs` 只对数有定义，别的类型得未知（不拼接文字）；除以 0、`percent` 的整体是 0 时得未知。结果不是有限数（溢出）、`%` 的除数是 0 时也得未知；式子里数的字面量要是有限数（`1e309` 拒收，`forbidden-syntax`）。
6. **读不到的值。** 引用的条目尚未出场、已删除、没有这个字段、命名空间没启用、已去掉或类型不可用时，不让整块失败：作者看到带说明的占位，Agent 看到值为 `null` 并带装饰 `不可用：原因`（planned：写成 `unavailable="原因"`，输出 9）。
7. **给作者的渲染。**（planned）结果是按块的源文与值表：每块给块 id、源文与值表；值表每项对应一个活的标签，按它在源文里的起点排，项里写标签名与起点（`If` 与各个 `ElseIf` 各一项，`Else`、`</If>` 没有项；没生效的支里的标签照样有项、照样求值）。调用方按本能力的白名单与输出 17 读源文，按标签名与起点对上每一项；对不上的块整块按出错显示并报诊断，不按位置猜。值表每项按标签的种类给：`V` 给地址、条目、显示名、原始值、显示文字，以及未知、不完整的标记，读不到时给原因（输出 6）；`V` 的 `expr` 给原始值与显示文字；`If` 与各个 `ElseIf` 给判断的结果（真、假、未知）与生效的那一支，判断未知时没有生效的支，作者看到“未知”（同值未知的样子）；`Ref` 给当时的名字（删除的写“已删除的条目”）；`Image` 给路径与说明；登记的标签给它的描述（输出 19），没登记的给“需要插件”。值是引用的，显示文字是被引条目当时的名字；值是图片的，给路径与说明。出错的块给纯文本与诊断。显示文字里数加千位分隔，未知显示“未知”；路径与 id 不出现在显示文字里。
8. **给 Agent 的渲染（带值写法）。**（planned）结果是按块的文字，每块带块 id，整体带版本与读取位置。每块的文字就是这一块的源文，只给活的标签带上装饰（输出 9）：
   - 取值写成 `<V of="panel.魔力">3110</V>`：值写成 JSON（文字带引号、换行写成 `\n`，数不带，未知是 `null`，图片是 `{"图片": 路径, "说明": 文字}`），值里的 `<` 写成 `\u003c`；计算值写成 `<V expr="…">"40%"</V>`；
   - 条件写成 `<If test="…" value="true">…<ElseIf test="…" value="false" />…<Else />…</If>`：每个判断带结果（`true`、`false`，未知是 `null`）；各支里的标签照常带装饰，别的字照源文给；
   - `<Ref id="e12" />` 写成 `<Ref id="e12" name="星瑾" />`，`name` 是这个位置上的名字；图片字段写成 `<Image of="…" alt="…" path="作品内路径" />`；
   - 登记的标签在开闭标签中间写它的描述（输出 19）；
   - 装饰以外的字与源文逐字相同：字面的标签、转义与代码原样输出。
9. **装饰。**（planned）程序加在活的标签上的属性与内容：`V` 的值（开闭标签中间）与属性 `label`（字段的显示名与 id 不同时给，列表元素的地址不给）、`incomplete`（地址不完整：`变更 id 原因码`，`expr` 的值依赖不完整的字段时也给）、`unavailable`（读不到的原因）；`If`、`ElseIf` 的 `value`；`Ref` 的 `name`；`Image` 的 `path`；登记的标签开闭之间的描述。例：`<V of="panel.m2" label="魔力" incomplete="c7 constraint-violated">3110</V>`。这些属性名只由程序生成，写进源文的拒收（输出 1）。属性值与描述来自作者的数据（名字、显示名、原因）时，其中的 `&`、`"`、`<`、`>` 写成 `&amp;`、`&quot;`、`&lt;`、`&gt;`，换行写成空格，带值写法因此总能按标签读出来。
10. **带值写法的文法。**（planned：删除，由输出 22 取代） 注记从 `{` 开始；`=` 形式的左边只许地址，`=` 只有一个；`->` 形式的左边按 JS 的词法（字符串、注释）扫描到顶层的 `->` 为止；右边的值按 JSON 解析出边界；之后可以有 ` # ` 加装饰（装饰里没有 `}`），最后是 `}`。不按第一个 `}` 或 `->` 切。
11. **结果确定。** 同样的输入，渲染结果逐字相同。
12. **回写。**（planned：删除，由输出 22 与 [`canon.agent-tools`](agent-tools.md) 的写入取代） 交回的一块要说明它读自哪种模式；只有按实际模式读到的块能回写，按计划模式读到的拒收（`planned-not-writable`）：计划里的值不是现在的值，原样交回也会被当成改动。渲染的结果带着版本、位置（写明读的线）与模式，交回时照带；位置没写明线的拒收（`line-required`）：章讲的线换了不加世界版本，按现在的线读会把旧线的值当成改动。程序按这个顺序处理交回的一块：
    1. 解析注记（输出 10）；装饰与 `<Ref>` 的 `name` 属性在回写时忽略，有没有、改没改都不影响结果；
    2. 注记按出现的顺序与源文里的表达式一一对应，核对地址相同；
    3. 拆成字段操作（`=` 右边的值变了）与文字操作（注记以外的字变了）；
    4. 文字操作：把注记换回源文的表达式，得到这一块的新源文，按输出 1 检查；新源文按 [`canon.revisions`](revisions.md) 输出 8 的路由写：创作修改写回给出这一块当前文字的记录（初值的块，或那条整段替换、增块的变更），剧情变化在读取位置新记一条整段替换；
    5. 字段操作：按 [`canon.revisions`](revisions.md) 输出 8 的就地改处理，用请求里的意图；
    6. 两者作为一次修订发布；回写的预览（planned）。Agent 的回写不需要作者确认，改动记录与可撤销的提示照常给作者。
13. **回写拒收。**（planned：删除） 以下情况整次拒收，不发布：`->` 的部分被改（`computed-edited`）；注记被删、重排、复制或新增（`annotation-mismatch`，要加新的引用请改源文）；同一字段出现两处、被改成两个不同的新值（`conflicting-values`；只改了其中一处的，按改了的那处）；改了不完整、不可用的字段，或几笔累出来的数（[`canon.revisions`](revisions.md) 输出 8 的 `incomplete-field`、`field-unavailable`、`accumulated-value`）；来源不止一个而请求没给处理方式（`needs-handling`，详情给出来历）（planned，现在是 `accumulated-value`）；读取之后世界版本前进过，而交回的文字与现在的世界有差别：差别是值的得 `value-conflict`，别的得 `version-conflict`，重读再改（没有差别算没有改动，不发布）。
14. **出错的块。** 给 Agent 的渲染里，出错的块给出原样的源文（不换注记）并标“出错”，带诊断。（planned：删除这一句）回写这样的块时，交回的文字整体当作这一块的新源文（不做注记对应），按输出 1 检查，通过就整段替换。
15. **纯文字的渲染。** 给不回写的读者（例如写手的简报，[`plot.brief`](../plot/brief.md) 输出 8、13）：读取视图的 `renderPlain(条目, 位置, 模式, {entryName?})` 按块给出文字，每块带三样，由调用方据此决定这段文字能不能给：
    - `reads`：读了谁的数据：明写了条目的字段引用指到的条目（含本条目自己），加上地址里以引用为键的列表的行键（`att.态度[e1].称呼` 读的是关于 e1 的数据，本条目自己字段里的行键也算）；不写条目的本条目字段不算。（planned）按块里全部的标签算，活的与字面的都算，`If` 的判断与各支都算；明写条目是 `V` 的 `entry` 与式子里的 `ref('…')`。
    - `mentions`：文字里写了谁的名字：`<Ref>`、值是引用的、以引用为键的列表的行（planned：字面的 `<Ref>` 也算）。
    - `problems`：这一块有写不干净的地方：`syntax`（块出错，文字是原样源文）、`raw-value`（结果没有纯文字的写法，例如取出的单个列表行）、`quoted-block`（读到另一块的原文，`text[...]`）、`unavailable`（读不到值，输出 6）；`unknown-tag`（块里有没登记的标签，不知道它读了谁，输出 19，planned）；块里有内置或登记的标签名写成的、不成标签的写法（代码里的、转义的也算）时报 `syntax`（读不全它的属性，planned）。有问题的那一处不写文字。
    - 值的写法：字符串、数（千位分隔）、真假（是、否）、未知（“未知”）同输出 7；引用写条目当时的名字；以引用为键的列表写各行条目的名字，用顿号连；作者写的列表写各行的 `label`；字符串列表用顿号连；图片写说明。名字由调用方的 `entryName` 给，不给时用条目当时的名字，删除的、不存在的写“已删除的条目”；读取时给以引用为键的行补的 `label` 不用（调用方可能要改写这个名字）。
    - `<Image>` 标签整个写成它的说明（`alt`，没有就不写）。
    - 条件（planned）写生效的那一支；判断未知时写“未知”。登记的标签写它的描述（输出 19）。块里有字面的标签（代码里的、转义的）时报 `syntax`（planned）：照原文写会把条目 id 与写法给读者。
16. **按给的源文字渲染。**（planned）给作者界面在提交之前看结果用（[`canon.author-ui`](author-ui.md) 输出 48）：把调用方给的一段源文字当作这个条目的主文字，在给定的位置与模式上渲染成一块（块 id 固定为 `source`），结构与输出 7 相同（planned：源文与值表）。求值与渲染存下来的块用同一个上下文：不写条目的字段读的是这个条目此刻的数据，引用的名字是当时的名字。不写入、不留痕迹，世界的版本不变；解析的结果也不留（存下来的块的解析结果是留着复用的，这里的源文字每次都不一样）。源文字超过 5 万个字符（按 UTF-16 码元计，即 `String.length`）时不渲染，调用方得到 `too-large`；嵌套深到渲染不了的（几万层引用这类）照出错的块给。源文字过不了写入时的检查（输出 1）时，这一块照输出 4 给纯文本与诊断（行、列按给的源文字算）。条目不存在、那一章或那条线读不到时的结果与渲染存下来的块相同。
17. **标签的落点。**（planned）正文里（段落、标题、列表、引用、表格的单元格里）的标签是活的；行内代码与代码块里的、前面有转义的是字面的，作者与 Agent 都看到原文。标签的属性值里有 `|` 时不把表格的单元格切开；一行以标签开头时这一行不算 HTML 块；原文里 Unicode 私用区的字照常是文字。
18. **规范写法。**（planned）存下来的活的标签是规范写法：`<名字 属性="值" … />`，属性顺序照写的、之间一个空格，自闭合写 ` />`；`If` 写成 `<If test="…">…<ElseIf test="…" />…<Else />…</If>`。写入时不是规范写法的按规范写法存。
19. **登记的标签与没登记的标签。**（planned）插件登记的标签有名字、属性表（哪些是地址、哪些必填）与给模型的描述；作者看到插件画的样子，Agent 看到开闭标签中间的描述，纯文字写描述，`reads` 记属性里的地址与描述读到的字段。没登记的大写名字标签：写入时拒收（`unknown-tag`），除非这个条目当前的主文字里（任一块）已经有规范写法相同的这个标签（插件卸了以后，作者整篇提交、Agent 改别处都还能写）；作者看到“需要插件”的占位，Agent 看到原样的标签，纯文字报 `unknown-tag`。
20. （已删除）
21. **与章节编辑器读法一致。**（planned）同一段主文字，经章节编辑器的 Markdown 读法（加上条目的标签）读出的活的标签与落点，与本能力相同；编辑器原样写回或整篇重写写出的文字过得了输出 1。
22. **去值。**（planned）Agent 交回的文字（[`canon.agent-tools`](agent-tools.md) 的写入）在写入之前去掉装饰：带值的 `V` 换回自闭合并去掉 `label`、`incomplete`、`unavailable`；`If`、`ElseIf` 去掉 `value`；`Ref` 去掉 `name`；`Image` 去掉 `path`；登记的标签去掉开闭之间的描述、换回自闭合。只动活的标签，字面的原样保留。去值以后照输出 1 检查。值写在文字里不改字段：交回的值与当时的不同，字段照旧（改值另用写入工具）。对任何一块源文，先按输出 8 渲染再去值，得到的文字与源文逐字相同。

## 状态与转换

无。渲染是纯计算；回写的结局与写入请求相同（发布或拒收，[`canon.revisions`](revisions.md#状态与转换)）。

## 副作用与数据

- 渲染没有副作用。
- 回写成功时发布一次修订；块的源文、块 id 与块的顺序存在条目的状态里（[`canon.model`](model.md)）。

## 失败与恢复

| 码 | 含义 | 调用方怎么办 |
|---|---|---|
| `mdx-invalid` | MDX 解析失败，带行列（planned：删除） | 改源文 |
| `unsupported-markdown` | 用了白名单以外的 Markdown（原样 HTML、注释、脚注、数学）（planned） | 改成白名单里的写法 |
| `tag-malformed` | 内置或登记的标签名后面写了属性却不成标签，或 `ElseIf`、`Else`、`</If>` 孤立（planned） | 写完整，或写成 `\<` |
| `tag-not-live` | 标签落在链接地址、标题或图片说明里，或落在 Markdown 会丢掉的地方（planned） | 移到正文里；要在链接标题里写这几个字，写成 `&lt;` |
| `too-many-tags` | 一块里 `<` 加大写名字的写法与私用区里不同的字合计超过 6000 个（planned） | 拆成几块 |
| `forbidden-syntax` | 用了白名单以外的语法 | 改成引用字段，或转义 |
| `unknown-tag` | 用了内置以外的标签或属性 | 去掉 |
| `no-field-expression` | 表达式不引用任何字段（planned：`expr` 不引用任何字段） | 多半是正文里的花括号，写成 `\{`（planned：不引用字段的直接写成文字） |
| `cross-block` | 块不闭合或跨块；`If` 没闭合、跨段（planned） | 把那段写进同一块；条件写在一段之内 |
| `computed-edited` | 回写改了 `->` 的部分（planned：删除） | 改它依赖的字段 |
| `annotation-mismatch` | 回写时注记被删、重排、复制或新增（planned：删除） | 照原样保留注记；新增引用改源文 |
| `conflicting-values` | 同一字段被改成两个不同的值（planned：删除） | 只留一个 |
| `needs-handling`（planned） | 来源不止一个而没给处理方式 | 补上处理方式，或转给作者 |
| `planned-not-writable` | 交回的块是按计划模式读到的（planned：删除） | 按实际模式重读那一块再改 |
| `line-required` | 交回的位置没写明读的线（planned：删除） | 照带渲染结果给的位置 |

## 边界与兼容

- 公开接口：白名单与式子的节点表、保留名与内置函数、内置标签与它们的属性、带值写法与装饰、去值、规范写法、纯文字渲染的三样与值的写法、给作者的值表、失败码。
- 白名单与保留名只增不减；收紧白名单会让已存的块在渲染时成为出错块（输出 4），不会丢数据。换成标签写法（[ADR 0064](../../adr/0064-entry-text-uses-tags-and-the-chapter-parser.md)）是一次例外：旧的花括号写法在新写法里是普通文字，样本与测试数据随之换写法；脚注（`[^1]`）与数学（`$…$`、`$$…$$`）原来是文字，现在拒收，要写成 `\[^1]`、`\$`。
- 读法变化（planned）：换成章节编辑器的读法以后，`a < b` 与 `1<2` 是文字（原来拒收）；`<https://…>` 是自动链接；行首缩进四格是代码块（原来是段落）；单个 `~` 是文字（原来是删除线）；`- [ ] 待办` 是任务项；中文强调的边角按 marked 的 CJK 友好规则；一行以标签开头时不算 HTML 块；`<B>`、`<BR>` 这类大写的 HTML 名字照小写的读。
- 条目的主文字是项目数据，可能来自模板或别人分享的世界观：只解释白名单，不执行代码，不需要隔离环境。Component 的 `agentView` 随插件发布，和插件代码同样受信任，但仍按同一个白名单解释。

## 实现合同

- **公开入口**：`@notnotype/nb-canon`：`parseBlock`、`blockProblem`、`renderEntryForAuthor`、`renderEntryForAgent`、`renderBlockForAuthor`、`renderBlockForAgent`、`splitBlocks`、`evaluate`、`scanAnnotations`、`writeBack`；读取视图 `CanonReadView.renderPlain` 与类型 `PlainBlock`、`PlainProblem`、`PlainOptions`（`@notnotype/nb-canon/schema`）；应用侧 `canonWorldContract` 的 `render`、`writeBack`。
