# 世界引擎：渲染与带值写法

## 目标与非目标

条目的主文字用 MDX 写，可以引用本条目与别的条目的字段（`{panel.魔力}`）。同一份数据给作者看界面、给 Agent 读文字。本能力定义 MDX 的白名单与按块解析、给作者的渲染结果、给 Agent 的带值写法，以及 Agent 交回改过的一块时怎样拆成修订。只解释白名单里的语法树，不执行代码（[ADR 0038](../../adr/0038-world-engine-entry-text-is-whitelisted-mdx.md)）；同样的输入在浏览器里与在项目进程里算出的结果逐字相同。

不承诺：

- 作者在界面里编辑主 MDX 的方式：另行定义；本能力只给出渲染结果与回写。
- 复用项目的 Markdown 方言。
- 内置函数：第一版没有，名字先保留（输出 2）。
- 按任意历史版本渲染：只渲染当前版本。

## 术语与参与者

- **块**：主 MDX 的存储与解析单位，有稳定 id；一块是闭合的语法单元。
- **表达式**：MDX 里 `{…}` 的内容。
- **字段引用**：表达式里指到一个地址的部分：从 `entry`、`text`、本条目的命名空间，或 `ref("条目 id")` 开始的成员访问链。
- **注记**：带值写法里的 `{地址 = 值}`（可改的字段）或 `{表达式原文 -> 值}`（算出来的，只读），值之后可以带装饰。
- **装饰**：注记里 `#` 之后由程序生成的说明：`不完整：原因`、`不可用：原因`、`显示名：名字`，几项用 `；` 分开。
- **回写**：Agent 把带值写法的一块改过后交回。

## 输入与前置条件

- **渲染**的输入：条目、读取位置、模式（实际或按计划）、给谁看（作者或 Agent）、世界版本。也用于 Component 的 `agentView`（[`canon.components`](components.md)），这时地址的根是那个命名空间。
- **回写**的输入：条目、块 id、读取时的版本与读取位置、改过的带值写法文字；意图（创作修改或剧情变化，缺省创作修改）；来源不止一个时的处理（改基准、改某条记录并给 id、补一笔并给位置），可选。

**白名单**

| 类别 | 放行 |
|---|---|
| Markdown | CommonMark，加 GFM 的表格与删除线；中文标点旁的强调按 CJK 友好的规则解析（`**“走吧。”**然后` 成粗体） |
| 只含注释的表达式 | `{/* … */}` |
| 标签 | `<Ref id="…" />`（条目引用，`id` 是字面量）、`<Image src="作品内路径" alt="…" />`（图片）；属性的值是字面量或白名单里的表达式 |

表达式只许下面这些语法节点（ESTree 的名字），别的一律拒收：

| 节点 | 限制 |
|---|---|
| `Identifier` | 只能作为字段引用的根：`entry`、`text`、本条目的命名空间 |
| `MemberExpression` | 非计算的 `.键`；计算的 `[常量]` 只许字符串字面量或标识符写法的元素 id（`[t3]` 与 `["t3"]` 等价），数字下标与动态下标拒收 |
| `CallExpression` | 只许 `ref("条目 id")`，一个字符串字面量参数，且只能作为成员访问链的开头 |
| `Literal` | 字符串、数、真假、`null` |
| `BinaryExpression` | `==` `!=` `===` `!==` `<` `<=` `>` `>=` |
| `LogicalExpression` | `&&` `||` |
| `UnaryExpression` | `!`；`-` 只许直接作用于数字字面量（负数） |
| `ConditionalExpression` | `?:` |

- 根名字的解析顺序：`entry`、`text`、`ref`、本条目的命名空间（Component 视图里是那个命名空间的字段）。`entry`、`text`、`ref` 与以后的内置函数名是保留名，命名空间不能用（[`canon.components`](components.md) 输入与前置条件）。

## 输出与可观察行为

1. **写入时检查。** 写入主 MDX 的一块（新建、整段替换、增块）时检查，不过就拒收，指出块、行与列（[`canon.revisions`](revisions.md) 的 `validation-failed`）：
   - 不许 `import`、`export`，表达式里不许白名单以外的节点（`forbidden-syntax`）；
   - 白名单以外的标签，或 `<Ref>` 带了 `id`、`<Image>` 带了 `src`、`alt` 以外的属性，拒收（`unknown-tag`）；
   - 一个字段引用都没有的表达式拒收，提示可能是正文里的花括号、要转义（`no-field-expression`）；只含注释的表达式除外；
   - 块不是闭合的语法单元（块级标签没闭合、跨块）拒收（`cross-block`）；
   - MDX 解析失败拒收（`mdx-invalid`）。

   块内没有定义的引用式链接按普通文字显示，不拒收。
2. **保留名与内置函数。** 第一版没有内置函数；写成函数调用的只有 `ref`。保留名的列表随版本只增不减。
3. **切块。** 一段文字整体写入（新建条目、整篇替换）时，按顶层的语法节点切成块，每块得到新的 id；之后块的边界只由增块、删块、整段替换一块改变，不重新切。标题只是普通的块，不是解析的边界。
4. **按块解析。** 渲染时每块单独解析与求值。某一块出错（存下来的旧数据过不了当前白名单），这一块显示成纯文本并带诊断（块 id、行、列、原因），其余块照常。
5. **求值。** 表达式在给定的版本、位置与模式上取值；结果只取决于输入。引用别的条目，取它在同一版本、同一位置、同一模式上的状态。未知按三值逻辑传：
   - 比较的任一边是未知，结果是未知；`<` `<=` `>` `>=` 两边不同是数或不同是文字时，结果是未知；
   - `!未知` 是未知；`假 && 未知` 是假，`真 && 未知` 是未知；`真 || 未知` 是真，`假 || 未知` 是未知；
   - 条件的判断是未知时，整个条件表达式的结果是未知，不当成假。
6. **读不到的值。** 引用的条目尚未出场、已删除、没有这个字段、命名空间没启用、已去掉或类型不可用时，不让整块失败：作者看到带说明的占位，Agent 看到值为 `null` 并带装饰 `不可用：原因`。
7. **给作者的渲染。** 结果是按块的结构：Markdown 节点、值（地址、显示名、原始值、显示文字，以及未知、不完整的标记）、算出来的结果、图片（路径与说明）、条目引用（当时的名字，或“已删除的条目”）、占位、出错块的纯文本与诊断。显示文字里数加千位分隔，未知显示“未知”；路径与 id 不出现在显示文字里。
8. **给 Agent 的渲染（带值写法）。** 结果是按块的文字，每块带块 id，整体带版本与读取位置。每块的文字就是这一块的源文，只把表达式换成注记：
   - 只有一个字段引用、没有别的运算的表达式写成 `{地址 = JSON}`；其余表达式写成 `{表达式原文 -> JSON}`；
   - 值统一写成 JSON：文字带引号（换行写成 `\n`），数不带，未知是 `null`，图片是 `{"图片": 路径, "说明": 文字}`；
   - 属性里的表达式同样写成注记（`src={character.立绘[原身].图片 = "assets/星瑕/原身.png"}`）；
   - `<Ref id="e12" />` 输出成 `<Ref id="e12" name="星瑾" />`，`name` 是这个位置上的名字，由程序生成；
   - 注记以外的字与源文逐字相同：转义的 `\{`、行内代码与代码块里的花括号原样输出，不当注记。
9. **装饰。** 装饰写在注记的花括号里、JSON 值之后，用 ` # ` 隔开：地址不完整加 `不完整：原因`（`->` 的值依赖不完整的字段时也加）；读不到加 `不可用：原因`；字段的显示名与 id 不同加 `显示名：名字`。例：`{panel.m2 = 3110 # 显示名：魔力；不完整：第 5 章的转账套不上}`。
10. **带值写法的文法。** 注记从 `{` 开始；`=` 形式的左边只许地址，`=` 只有一个；`->` 形式的左边按 JS 的词法（字符串、注释）扫描到顶层的 `->` 为止；右边的值按 JSON 解析出边界；之后可以有 ` # ` 加装饰（装饰里没有 `}`），最后是 `}`。不按第一个 `}` 或 `->` 切。
11. **结果确定。** 同样的输入，渲染结果逐字相同。
12. **回写。** 程序按这个顺序处理交回的一块：
    1. 解析注记（输出 10）；装饰与 `<Ref>` 的 `name` 属性在回写时忽略，有没有、改没改都不影响结果；
    2. 注记按出现的顺序与源文里的表达式一一对应，核对地址相同；
    3. 拆成字段操作（`=` 右边的值变了）与文字操作（注记以外的字变了）；
    4. 文字操作：把注记换回源文的表达式，得到这一块的新源文，按输出 1 检查；新源文按 [`canon.revisions`](revisions.md) 输出 8 的路由写：创作修改写回给出这一块当前文字的记录（初值的块，或那条整段替换、增块的变更），剧情变化在读取位置新记一条整段替换；
    5. 字段操作：按 [`canon.revisions`](revisions.md) 输出 8 的就地改处理，用请求里的意图与多来源的处理；
    6. 两者作为一次修订发布（可以先预览）。Agent 的回写不需要作者确认，改动记录与可撤销的提示照常给作者。
13. **回写拒收。** 以下情况整次拒收，不发布：`->` 的部分被改（`computed-edited`）；注记被删、重排、复制或新增（`annotation-mismatch`，要加新的引用请改源文）；同一字段出现两处、被改成两个不同的新值（`conflicting-values`；只改了其中一处的，按改了的那处）；改了不完整、不可用的字段，或几笔累出来的数（[`canon.revisions`](revisions.md) 输出 8 的 `incomplete-field`、`field-unavailable`、`accumulated-value`）；来源不止一个而请求没给处理方式（`needs-handling`，详情给出来历）；读取时的版本或值已经过期（`version-conflict`、`value-conflict`）。
14. **出错的块。** 给 Agent 的渲染里，出错的块给出原样的源文（不换注记）并标“出错”，带诊断。回写这样的块时，交回的文字整体当作这一块的新源文（不做注记对应），按输出 1 检查，通过就整段替换。

## 状态与转换

无。渲染是纯计算；回写的结局与写入请求相同（发布或拒收，[`canon.revisions`](revisions.md#状态与转换)）。

## 副作用与数据

- 渲染没有副作用。
- 回写成功时发布一次修订；块的源文、块 id 与块的顺序存在条目的状态里（[`canon.model`](model.md)）。

## 失败与恢复

| 码 | 含义 | 调用方怎么办 |
|---|---|---|
| `mdx-invalid` | MDX 解析失败，带行列 | 改源文 |
| `forbidden-syntax` | 用了白名单以外的语法 | 改成引用字段，或转义 |
| `unknown-tag` | 用了内置以外的标签或属性 | 去掉 |
| `no-field-expression` | 表达式不引用任何字段 | 多半是正文里的花括号，写成 `\{` |
| `cross-block` | 块不闭合或跨块 | 把那段写进同一块 |
| `computed-edited` | 回写改了 `->` 的部分 | 改它依赖的字段 |
| `annotation-mismatch` | 回写时注记被删、重排、复制或新增 | 照原样保留注记；新增引用改源文 |
| `conflicting-values` | 同一字段被改成两个不同的值 | 只留一个 |
| `needs-handling` | 来源不止一个而没给处理方式 | 补上处理方式，或转给作者 |

## 边界与兼容

- 公开接口：白名单与表达式的节点表、保留名、两个内置标签、带值写法的文法与装饰、回写请求的参数与失败码。
- 白名单与保留名只增不减；收紧白名单会让已存的块在渲染时成为出错块（输出 4），不会丢数据。
- 条目里的 MDX 是项目数据，可能来自模板或别人分享的世界观：只解释白名单，不执行代码，不需要隔离环境。Component 的 `agentView` 随插件发布，和插件代码同样受信任，但仍按同一个白名单解释。

## 验收与 Smoke

1. **两种渲染。** 星瑕的一块写着 `魔力 {panel.魔力}/{panel.魔力上限}，{panel.魔力 >= 1000 ? "能变身" : "变不了身"}`。第 5 章末尾：作者看到“魔力 3,110/12,000，能变身”，悬停能看到中文字段名；Agent 读到 `魔力 {panel.魔力 = 3110}/{panel.魔力上限 = 12000}，{panel.魔力 >= 1000 ? "能变身" : "变不了身" -> "能变身"}`。第 1 章面板还没启用时，作者看到占位，Agent 读到 `{panel.魔力 = null # 不可用：面板第 3 章起生效}`，条件那一处是 `-> null`。
2. **回写。** Agent 把上一块里的 `3110` 改成 `3000`、把“魔力”改成“魔法力”，意图为剧情变化：一次修订里，第 5 章末尾记一条 −110，并记一条这一块的整段替换，新源文是 `魔法力 {panel.魔力}/…`。改了 `->` 后面的 `"能变身"`：`computed-edited`。
3. **一块坏了。** 存下来的三块里第二块含白名单以外的标签（旧数据）：渲染时第一、三块照常，第二块显示纯文本与诊断；Agent 读到它的原样源文与“出错”标记，交回一段合法的文字后，这一块被整段替换。
4. **花括号与括注。** 写入一块“他说{+5}”被拒（`no-field-expression`）；写成 `他说\{+5}` 通过，作者看到“他说{+5}”，Agent 读到 `他说\{+5}`。源文 `{panel.存款}（未知）` 里作者自己写的括注，在 Agent 读到的 `{panel.存款 = null}（未知）` 里是注记以外的字，回写时照原样保留。

Smoke：不适用——本能力没有独立的运行入口，由 [`canon.project`](project.md) 的 Smoke 一并覆盖。
