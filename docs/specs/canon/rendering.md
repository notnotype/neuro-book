# 世界引擎：渲染与带值写法

## 目标与非目标

条目的主文字是带标签的 Markdown，可以引用本条目与别的条目的字段（`<V of="panel.魔力" />`）。同一份数据给作者看界面、给 Agent 读文字。本能力定义主文字的写法与白名单、按块解析、给作者的渲染结果、给 Agent 的带值写法与交回时的去值、给不回写的读者（例如写手的简报）的纯文字。只解释白名单，不执行代码；Markdown 的读法与章节编辑器相同（[`workspace.markdown-dialect`](../workspace/markdown-dialect.md) 的 core，[ADR 0064](../../adr/0064-entry-text-uses-tags-and-the-chapter-parser.md)）；同样的输入在浏览器里与在项目进程里算出的结果逐字相同。

主文字是标签写法（[ADR 0064](../../adr/0064-entry-text-uses-tags-and-the-chapter-parser.md)）。带（planned）的句子是还没实现的合同：插件登记的标签（登记表、属性表与描述），Component 的 `agentView` 按主文字的写法解释，以及跨段的条件（块级 `If`）。

不承诺：

- 作者在界面里编辑主文字的方式：见 [`canon.author-ui`](author-ui.md)。
- 跨段的条件：`If` 只在一段之内（planned）。
- 文字拼接与格式化：式子只算数、比较与逻辑。
- 按任意历史版本渲染：只渲染当前版本。

## 术语与参与者

- **块**：主文字的存储与解析单位，有稳定 id；一块是闭合的语法单元。
- **标签**：主文字里 `<` 加大写字母开头的名字写成的一处，例如 `<V of="panel.魔力" />`。
- **活的标签与字面的标签**：落在正文里、按它的意思解释的是活的；落在行内代码、代码块里或前面有转义（`\<V`）的是字面的，照原文显示。
- **式子**：`V` 的 `expr` 与 `If`、`ElseIf` 的 `test` 写的内容。
- **字段引用**：式子里指到一个地址的部分：从 `entry`、`text`、本条目的命名空间，或 `ref('条目 id')` 开始的成员访问链；`V` 的 `of`（加 `entry`）是一个字段引用。
- **带值写法**：给 Agent 的渲染：源文里活的标签带上当时的值与说明。
- **装饰**：带值写法里由程序加的属性与内容（输出 9），交回时去掉。
- **去值**：把 Agent 交回的文字里的装饰去掉、换回源文的写法（输出 22）。
- **登记的标签**：插件登记了名字、属性与给模型的描述的标签（planned）。

## 输入与前置条件

- **渲染**的输入：条目、读取位置、模式（实际或按计划）、给谁看（作者或 Agent）、世界版本。也用于 Component 的 `agentView`（[`canon.components`](components.md)），这时地址的根是那个命名空间（planned）。
- **写入**主文字的一块（新建、整段替换、增块）时按输出 1 检查；Agent 写入的文字先按输出 22 去值。

**白名单**

| 类别 | 放行 |
|---|---|
| Markdown | 与章节编辑器相同的读法：CommonMark，GFM 的表格、删除线（只认 `~~`）与任务列表；中文标点旁的强调按 CJK 友好的规则解析（`**“走吧。”**然后` 成粗体）；HTML 形式的强调与换行（小写的 `<strong>`、`<b>`、`<em>`、`<i>`、`<del>`、`<s>` 成对，`<br>`，包括独占一行、只有换行的 `<br>`） |
| 取值 | `<V of="地址" />`；别的条目的字段 `<V entry="条目 id" of="地址" />` |
| 计算值 | `<V expr="式子" />` |
| 条件 | `<If test="式子">…<ElseIf test="式子" />…<Else />…</If>`：`ElseIf` 可以有几个，`Else` 至多一个且在最后；整个条件在一段之内，各支是行内的文字，可以带强调、链接与别的标签（不能再套 `If`） |
| 条目引用 | `<Ref id="条目 id" />` |
| 图片 | `<Image src="作品内路径" alt="说明" />`；图片字段 `<Image of="地址" alt="说明" />`（`alt` 可省） |
| 登记的标签 | `<名字 属性="…" />`，名字与属性按登记（输出 19）（planned） |

标签的写法：名字区分大小写；属性只有 `名="值"` 一种写法，值里不能有 `"` 与换行；一个标签不跨行；除 `If` 外都自闭合。从左到右认，认出一个标签以后从它的结尾接着认，属性值里的 `<` 不另算标签。`B`、`BR`、`EM`、`I`、`DEL`、`S`、`STRONG`（不分大小写）是 HTML 的强调与换行，不是标签名。式子里的字符串用单引号（`test="character.身份 == '学生'"`）；三元式可以选出数、真假或文字（`expr="panel.魔力 >= 1000 ? '能' : '不能'"`），选出文字不算格式化。地址的写法同字段引用、不带 `ref`：`panel.魔力`、`att.态度[e1].称呼`、`entry.name`、`text[块 id]`；存下来的地址照原样认（元素 id 是 `true`、`default` 这类 JS 的字面量与关键字时，式子里要写成 `['true']`，`of` 里直接写 `panel.list[true]`）。

式子只许下面这些语法节点（ESTree 的名字），别的一律拒收：

| 节点 | 限制 |
|---|---|
| `Identifier` | 只能作为字段引用的根：`entry`、`text`、本条目的命名空间；或作为函数名 |
| `MemberExpression` | 非计算的 `.键`；计算的 `[常量]` 只许字符串字面量或标识符写法的元素 id（`[t3]` 与 `['t3']` 等价），数字下标与动态下标拒收 |
| `CallExpression` | `ref('条目 id')`（一个字符串字面量参数，只能作为成员访问链的开头）；内置函数（输出 2） |
| `Literal` | 字符串、数、真假、`null` |
| `BinaryExpression` | `==` `!=` `===` `!==` `<` `<=` `>` `>=`；`+` `-` `*` `/` `%` |
| `LogicalExpression` | `&&` `||` |
| `UnaryExpression` | `!`；`-`（作用于任意操作数） |
| `ConditionalExpression` | `?:` |

- 根名字的解析顺序：`entry`、`text`、`ref`、本条目的命名空间（Component 视图里是那个命名空间的字段）。`entry`、`text`、`ref` 是保留名，命名空间不能用；内置函数名只在调用的位置认（`round(x)` 是函数，`round.计数` 仍是名叫 `round` 的命名空间的地址），不占命名空间的名字（[`canon.components`](components.md) 输入与前置条件）。

## 输出与可观察行为

1. **写入时检查。** 写入主文字的一块（新建、整段替换、增块）时检查，不过就拒收，指出块、行与列（[`canon.revisions`](revisions.md) 的 `validation-failed`）。检查之前先去掉开头的 BOM（几个都去掉）、把换行规范成 LF；存下来的是规范后的原文，活的标签写成规范写法（输出 18）。拒收的情形：
   - 白名单以外的 Markdown：别的原样 HTML、HTML 注释、脚注、数学（`unsupported-markdown`）；语法单元树超过 100 层的（一层引用、一层强调各算一层，一级列表算两层：列表与列表项；段落与里面的文字也各占一层，所以约是 98 层引用或 49 级列表）同样拒收（`unsupported-markdown`），存下来的这种旧块渲染时照输出 4 给出错的块：分词与阅读视图都按层递归，界线与运行时的栈深无关；
   - 一块超过 5 万个字符（按 UTF-16 码元计，即 `String.length`；`block-too-large`）：Markdown 的解析在少数写法上随长度大致按平方变慢（最坏一块约 50 秒），写入排在单写者队列里。上限只管一块，一次请求的块数不设上限：经远程调用时受消息预算约束，刻意构造的最坏请求能占住项目进程十几分钟（已知限制）。作者界面整篇编辑时整篇写进一块，所以这也是作者改过的条目整篇的上限，与输出 16 一次肯渲染的长度相同。只管写入：超过的不解析、直接拒收；渲染不看它，存下来的旧数据照常渲染；
   - 活的标签名字不认；属性不认、写了两次或缺了必填的（`V` 要有 `of` 或 `expr` 之一、`entry` 要与 `of` 同写，`Image` 要有 `src` 或 `of` 之一，`If`、`ElseIf` 要有 `test`，`Ref` 要有 `id`）；`entry`、`id` 是空的；除 `If` 外的标签与登记的标签不是自闭合的、`V` 带着内容，或写了装饰属性（输出 9）（`unknown-tag`；没登记的标签见输出 19）；
   - 式子写错、带注释、用了白名单以外的节点或运算符、超过 1000 个字符（按 UTF-16 码元计），地址写错（`forbidden-syntax`，行列落在属性值里）；`expr` 一个字段引用都没有（`no-field-expression`）；
   - `If` 没闭合、跨段、被强调切开或套在另一个 `If` 里（`cross-block`）；孤立的 `ElseIf`、`Else`、`</If>`，`Else` 之后还有 `ElseIf` 或第二个 `Else`，或内置与登记的标签名后面写了属性却不成标签（例如少了收尾的 `<V of="panel.魔力"`、属性用了单引号或没加引号、`=` 两边有空格），又不在代码里、没转义（`tag-malformed`；落在链接与图片说明里的同样这样判）。别的 `<` 加大写名字（`评级 <A 级`）是文字；
   - 活的标签落在链接地址、链接标题或图片说明里，或链接标题里前面有转义的完整标签（图片说明里转义的是字面的，不拒），或落在 Markdown 会丢掉的地方（`tag-not-live`；表格某一行多出来的单元格里的标签不算，这一行先按下一条报整张表）；表格的某一行比表头多出单元格（`unsupported-markdown`：多出的单元格 Markdown 会丢掉，编辑器把整张表当原样保留）；
   - 一块里 `<` 加大写名字的写法（活的、字面的、不成标签的都算）与标签以外的 U+E000 到 U+F8FF 里不同的字合计超过 6000 个（`too-many-tags`；同一个字出现几次算一个）。

   块内没有定义的引用式链接按普通文字显示，不拒收。
2. **保留名与内置函数。** 写成函数调用的有 `ref` 与七个内置函数：`round(x)`、`round(x, 位数)`（位数只许整数字面量，可以是负的：`round(x, -2)` 舍到百位）、`floor(x)`、`ceil(x)`、`min(a, b, …)`、`max(a, b, …)`、`abs(x)`、`percent(部分, 整体)`（结果是文字，例如 `"40%"`，四舍五入到整数）。四舍五入的 .5 远离 0（`round(-2.5)` 得 -3），舍入前先去掉乘出来的二进制尾差（`round(1.005, 2)` 得 1.01）。保留名的列表随版本只增不减。
3. **块由写入方给出。** 主文字的块怎么分由写入方（作者的界面、Agent 的工具）决定，系统不替它切：新建条目时给的每段主文字、增块与整段替换给的原文各是一块。一块是闭合的语法单元（输出 1），里面可以有几段。块的边界只由增块、删块、整段替换一块改变，不重新切；标题只是块里的普通内容，不是解析的边界。公开函数 `splitBlocks`（把一段文字按顶层的语法节点切成块）留给要整段导入文字的调用方，产品里没有调用方。
4. **按块解析。** 渲染时每块单独解析与求值。某一块出错（存下来的旧数据过不了当前白名单），这一块显示成纯文本并带诊断（块 id、行、列、原因），其余块照常。
5. **求值。** 表达式在给定的版本、位置与模式上取值；结果只取决于输入。引用别的条目，取它在同一版本、同一位置、同一模式上的状态。未知按三值逻辑传：
   - 比较的任一边是未知，结果是未知；`<` `<=` `>` `>=` 两边不同是数或不同是文字时，结果是未知；
   - `!未知` 是未知；`假 && 未知` 是假，`真 && 未知` 是未知；`真 || 未知` 是真，`假 || 未知` 是未知；
   - 条件的判断是未知时，整个条件表达式的结果是未知，不当成假。
   - 运算与函数：任一操作数或参数是未知，结果是未知；`+ - * / %` 与 `round`、`floor`、`ceil`、`min`、`max`、`abs` 只对数有定义，别的类型得未知（不拼接文字）；除以 0、`percent` 的整体是 0 时得未知。结果不是有限数（溢出）、`%` 的除数是 0 时也得未知；式子里数的字面量要是有限数（`1e309` 拒收，`forbidden-syntax`）。
6. **读不到的值。** 引用的条目尚未出场、已删除、没有这个字段、命名空间没启用、已去掉或类型不可用时，不让整块失败：作者看到带说明的占位，Agent 看到值为 `null` 并带装饰 `unavailable="原因"`（输出 9）。`expr` 与判断的结果按三值逻辑已经确定时（例如 `false && 读不到的`），不标读不到。
7. **给作者的渲染。** 结果是按块的源文与值表：每块给块 id、源文与值表；值表每项对应一个活的标签，按它在源文里的起点排，项里写标签名与起点（`If` 与各个 `ElseIf` 各一项，`Else`、`</If>` 没有项；没生效的支里的标签照样有项、照样求值）。调用方按本能力的白名单与输出 17 读源文，按标签名与起点对上每一项；对不上的块整块按出错显示，不按位置猜（作者界面与世界服务同版发布，对不上只出现在升级中开着的旧窗口里，不另报诊断）。值表每项按标签的种类给：`V` 给地址、条目、显示名、原始值、显示文字，以及未知、不完整的标记，读不到时给原因（输出 6）；`V` 的 `expr` 给原始值与显示文字；`If` 与各个 `ElseIf` 给判断的结果（真、假、未知），生效的那一支写在 `If` 那一项上，判断未知时没有生效的支，作者看到“未知”（同值未知的样子）；`Ref` 给当时的名字（删除的写“已删除的条目”）；`Image` 给路径与说明；登记的标签给它的描述（输出 19）（planned）；没登记的给“需要插件”。值是引用的，显示文字是被引条目当时的名字；值是图片的，给路径与说明。出错的块给纯文本与诊断。显示文字里数加千位分隔，未知显示“未知”；路径与 id 不出现在显示文字里。
8. **给 Agent 的渲染（带值写法）。** 结果是按块的文字，每块带块 id，整体带版本与读取位置。每块的文字就是这一块的源文，只给活的标签带上装饰（输出 9）：
   - 取值写成 `<V of="panel.魔力">3110</V>`：值写成 JSON（文字带引号、换行写成 `\n`，数不带，未知是 `null`，图片是 `{"图片": 路径, "说明": 文字}`），值里的 `<` 与反引号写成 JSON 的转义（`\u003c`、`\u0060`）；计算值写成 `<V expr="…">"40%"</V>`；
   - 条件写成 `<If test="…" value="true">…<ElseIf test="…" value="false" />…<Else />…</If>`：每个判断带结果（`true`、`false`，未知是 `null`）；各支里的标签照常带装饰，别的字照源文给；
   - `<Ref id="e12" />` 写成 `<Ref id="e12" name="星瑾" />`，`name` 是这个位置上的名字；图片字段写成 `<Image of="…" alt="…" path="作品内路径" />`；
   - 登记的标签在开闭标签中间写它的描述（输出 19）（planned）；
   - 源文是规范写法（输出 18）时，装饰以外的字与源文逐字相同；活的标签本身不是规范写法的，写成规范写法。字面的标签、转义与代码原样输出。
9. **装饰。** 程序加在活的标签上的属性与内容：`V` 的值（开闭标签中间）与属性 `label`（字段的显示名与 id 不同时给，列表元素的地址不给）、`incomplete`（地址不完整：`变更 id 原因码`，`expr` 的值依赖不完整的字段时也给）、`unavailable`（读不到的原因）；`If`、`ElseIf` 的 `value`；`Ref` 的 `name`；`Image` 的 `path`；登记的标签开闭之间的描述（planned）。例：`<V of="panel.m2" label="魔力" incomplete="c7 constraint-violated">3110</V>`。这些属性名只由程序生成，写进源文的拒收（输出 1）。属性值与描述来自作者的数据（名字、显示名、原因）时，其中的 `&`、`"`、`<`、`>` 与反引号写成 `&amp;`、`&quot;`、`&lt;`、`&gt;`、`&#96;`，换行写成空格，带值写法因此总能按标签读出来。
10. （已删除）
11. **结果确定。** 同样的输入，渲染结果逐字相同。
12. （已删除）
13. （已删除）
14. **出错的块。** 给 Agent 的渲染里，出错的块给出原样的源文并标“出错”，带诊断。
15. **纯文字的渲染。** 给不回写的读者（例如写手的简报，[`plot.brief`](../plot/brief.md) 输出 8、13）：读取视图的 `renderPlain(条目, 位置, 模式, {entryName?})` 按块给出文字，每块带三样，由调用方据此决定这段文字能不能给：
    - `reads`：读了谁的数据：明写了条目的字段引用指到的条目（含本条目自己），加上地址里以引用为键的列表的行键（`att.态度[e1].称呼` 读的是关于 e1 的数据，本条目自己字段里的行键也算）；不写条目的本条目字段不算。按块里全部的标签算，活的与字面的都算，`If` 的判断与各支都算；明写条目是 `V` 的 `entry` 与式子里的 `ref('…')`。出错的块（`syntax`）的 `reads`、`mentions` 是空的。
    - `mentions`：文字里写了谁的名字：`<Ref>`、值是引用的、以引用为键的列表的行、字面的 `<Ref>`。
    - `problems`：这一块有写不干净的地方：`syntax`（块出错，文字是原样源文）、`raw-value`（结果没有纯文字的写法，例如取出的单个列表行）、`quoted-block`（块里有引另一块原文的写法，`text[...]`，不看它在不在生效的支里或代码里）、`unavailable`（读不到值，输出 6）；`unknown-tag`（块里有没登记的标签，不知道它读了谁，输出 19）；块里有内置标签名写成的、不成标签的写法（代码里的、转义的也算）时报 `syntax`（读不全它的属性；登记的标签名同内置的（planned））。不成标签、名字也不是内置的（`评级 \<A 级`）只是文字，不报。有问题的那一处不写文字；字面的标签是例外，照原文写进文字、报 `syntax`，由调用方扣下。
    - 值的写法：字符串、数（千位分隔）、真假（是、否）、未知（“未知”）同输出 7；引用写条目当时的名字；以引用为键的列表写各行条目的名字，用顿号连；作者写的列表写各行的 `label`；字符串列表用顿号连；图片写说明。名字由调用方的 `entryName` 给，不给时用条目当时的名字，删除的、不存在的写“已删除的条目”；读取时给以引用为键的行补的 `label` 不用（调用方可能要改写这个名字）。
    - `<Image>` 标签整个写成它的说明（`alt`，没有就不写）。
    - 条件写生效的那一支；判断未知时写“未知”，判断未知是因为读不到值（输出 6）时同取值一样报 `unavailable`、不写文字。登记的标签写它的描述（输出 19）（planned）。块里有字面的标签（代码里的、转义的完整标签）时报 `syntax`：照原文写会把条目 id 与写法给读者。
16. **按给的源文字渲染。** 给作者界面在提交之前看结果用（[`canon.author-ui`](author-ui.md) 输出 48）：把调用方给的一段源文字当作这个条目的主文字，在给定的位置与模式上渲染成一块（块 id 固定为 `source`），结构与输出 7 相同（源文与值表）。求值与渲染存下来的块用同一个上下文：不写条目的字段读的是这个条目此刻的数据，引用的名字是当时的名字。不写入、不留痕迹，世界的版本不变；解析的结果也不留（存下来的块的解析结果是留着复用的，这里的源文字每次都不一样）。源文字超过 5 万个字符（按 UTF-16 码元计，即 `String.length`）时不渲染，调用方得到 `too-large`；嵌套深到渲染不了的（几万层引用这类）照出错的块给。源文字过不了写入时的检查（输出 1，没登记的标签按输出 19 的基线查：条目的主文字里没有的照样拒收）时，这一块照输出 4 给纯文本与诊断（行、列按给的源文字算）。按块长拒收的 `block-too-large` 不在这里报：预览一次肯渲染的长度由上面的 `too-large` 管。条目不存在、那一章或那条线读不到时的结果与渲染存下来的块相同。
17. **标签的落点。** 正文里（段落、标题、列表、引用、表格的单元格里）的标签是活的；行内代码与代码块里的、前面有转义的是字面的，作者与 Agent 都看到原文。标签的属性值里有 `|` 时不把表格的单元格切开；一行以标签开头时这一行不算 HTML 块；原文里 Unicode 私用区的字照常是文字。
18. **规范写法。** 存下来的活的标签是规范写法：`<名字 属性="值" … />`，属性顺序照写的、之间一个空格，自闭合写 ` />`；`If` 写成 `<If test="…">…<ElseIf test="…" />…<Else />…</If>`。写入时不是规范写法的按规范写法存。
19. **登记的标签与没登记的标签。** 插件登记的标签有名字、属性表（哪些是地址、哪些必填）与给模型的描述；作者看到插件画的样子，Agent 看到开闭标签中间的描述，纯文字写描述，`reads` 记属性里的地址与描述读到的字段（planned）。没登记的大写名字标签：写入时拒收（`unknown-tag`），除非这个条目的主文字里（初值的任一块，或生效的变更里改它主文字的补丁；不分线）已经有规范写法相同的、自闭合的这个标签（插件卸了以后，作者整篇提交、Agent 改别处都还能写；带内容的写法不放行）；作者看到“需要插件”的占位，Agent 看到原样的标签，纯文字报 `unknown-tag`。
20. （已删除）
21. **与章节编辑器读法一致。** 同一段主文字，经章节编辑器的 Markdown 读法（加上条目的标签）读出的活的标签与落点，与本能力相同；编辑器原样写回或整篇重写写出的文字过得了输出 1。
22. **去值。** Agent 交回的文字（[`canon.agent-tools`](agent-tools.md) 的写入）在写入之前去掉装饰：带值的 `V` 换回自闭合并去掉 `label`、`incomplete`、`unavailable`；`If`、`ElseIf` 去掉 `value`；`Ref` 去掉 `name`；`Image` 去掉 `path`；登记的标签去掉开闭之间的描述、换回自闭合（planned）。只动活的标签，字面的原样保留。去值以后照输出 1 检查。值写在文字里不改字段：交回的值与当时的不同，字段照旧（改值另用写入工具）。对规范写法的源文，先按输出 8 渲染再去值，得到的文字与源文逐字相同；不是规范写法的旧块（补偿修订会原样恢复改前的文字），去值后是它的规范写法。

## 状态与转换

无。渲染是纯计算。

## 副作用与数据

- 渲染没有副作用。
- 块的源文、块 id 与块的顺序存在条目的状态里（[`canon.model`](model.md)）。

## 失败与恢复

| 码 | 含义 | 调用方怎么办 |
|---|---|---|
| `unsupported-markdown` | 用了白名单以外的 Markdown（原样 HTML、注释、脚注、数学） | 改成白名单里的写法 |
| `tag-malformed` | 内置或登记的标签名后面写了属性却不成标签，或 `ElseIf`、`Else`、`</If>` 孤立，`Else` 之后还有 `ElseIf` 或第二个 `Else` | 写完整，或写成 `\<` |
| `tag-not-live` | 标签落在链接地址、标题或图片说明里，或落在 Markdown 会丢掉的地方 | 移到正文里；要在链接标题里写这几个字，写成 `&lt;` |
| `block-too-large` | 一块主文字超过 5 万个字符 | 拆成几块 |
| `too-many-tags` | 一块里 `<` 加大写名字的写法与私用区里不同的字合计超过 6000 个 | 拆成几块 |
| `forbidden-syntax` | 用了白名单以外的语法 | 改成引用字段，或转义 |
| `unknown-tag` | 标签名不认；属性不认、重复或缺必填；`entry`、`id` 是空的；不自闭合、`V` 带内容或写了装饰属性（输出 1） | 照白名单改，或去掉 |
| `no-field-expression` | `expr` 不引用任何字段 | 不引用字段的直接写成文字 |
| `cross-block` | `If` 没闭合、跨段、被强调切开或套在另一个 `If` 里 | 把那段写进同一块；条件写在一段之内 |

## 边界与兼容

- 公开接口：白名单与式子的节点表、保留名与内置函数、内置标签与它们的属性、带值写法与装饰、去值、规范写法、纯文字渲染的三样与值的写法、给作者的值表、失败码。
- 白名单与保留名只增不减；收紧白名单会让已存的块在渲染时成为出错块（输出 4），不会丢数据。换成标签写法（[ADR 0064](../../adr/0064-entry-text-uses-tags-and-the-chapter-parser.md)）是一次例外：旧的花括号写法分两种：`{panel.x}` 在新写法里是普通文字；`<Image src={…} />` 这类旧属性写法像写坏的标签，是出错的块。样本与测试数据随之换写法；脚注（`[^1]`）与数学（`$…$`、`$$…$$`）原来是文字，现在拒收，要写成 `\[^1]`、`\$`。
- 读法变化：换成章节编辑器的读法以后，`a < b` 与 `1<2` 是文字（原来拒收）；`<https://…>` 是自动链接；行首缩进四格是代码块（原来是段落）；单个 `~` 是文字（原来是删除线）；`- [ ] 待办` 是任务项；中文强调的边角按 marked 的 CJK 友好规则；一行以标签开头时不算 HTML 块；`<B>`、`<BR>` 这类大写的 HTML 名字照小写的读。
- 条目的主文字是项目数据，可能来自模板或别人分享的世界观：只解释白名单，不执行代码，不需要隔离环境。Component 的 `agentView` 随插件发布，和插件代码同样受信任，但仍按同一个白名单解释（planned）。
