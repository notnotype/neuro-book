# 图像配方：节、预设、风格组合与片段

## 目标与非目标

一份配方说明一张图“要生成什么”。本 Spec 规定这几件事：
- 配方、预设、片段、风格组合四种文件的格式；
- 配方怎样分节，角色框怎样组织；
- 预设怎样以“引用加差异”挂在节上，更新预设时谁跟着变；
- 一组预设怎样一次套上，新配方从哪一组开始；
- 片段怎样引用、怎样展开；
- 本书、我的预设库与官方预设之间怎样复制；
- 配方怎样展开成与后端无关的生成请求；
- 每一批生成怎样存下配方当时的样子，又怎样从快照恢复；
- 怎样按 id 找到这些文件，复制出重复的 id 时怎么办。

提示词本身的表示与写法见 [`images/prompt`](prompt.md)。

不承诺：

- 生成、排队、费用、后端的能力声明：归 `images/generation`。参数有哪些字段、取值范围，由那里的能力声明给出。
- 生成记录、仓库、快照文件的存放与对账：归 `images/library`。本 Spec 只规定快照里有什么、哈希怎么算。
- 要用词库的检查与粘贴拆分：归 `images/checks`。
- 工作台怎样画这些东西：归 `images/workbench`。
- 角色框的内容来自角色设定；底图字段只预留形状，没有行为。

已知限制：
- 两台机器各自给同一份复制出来的文件换了不同的新 id，经 Git 合并时这一行会冲突，由作者选一个。
- 恢复时拆开随机项里的片段引用（输出 28），先把引用的权重乘进各项并量化一次，再在展开时乘随机项的权重。极端的权重下（例如 0.0001 乘 0.0001），结果和当时一次量化的结果不同。

## 术语与参与者

- **配方**：一张图“要生成什么”，由有序的节、角色框、参数、尺寸、张数、种子与底图组成。
- **节**：文字提示词按用途分的格子，有种类与可选的名字。
- **角色框**：一个角色（或一个物体、一格分镜）自己的正面与负面提示词。
- **预设**：一种节或参数的一份有名字的内容。
- **差异**：配方里一节相对它所引用的预设改了什么，由若干条改动组成。
- **锚点**：“加一项”记着加在哪一项后面，记那一项的键。
- **作废的改动**：对现在的预设内容已经做不了的改动（输出 10）。
- **风格组合**：一组“节的种类与名字，对应一个预设”，外加一个参数预设。
- **本书默认**：新建配方时套上的那个风格组合。
- **片段**：有名字的一小组词，分核心词与陪衬词，可以有主提示词与各角色框几部分。
- **本书、我的预设库、官方预设**：本书指作品目录里的文件；我的预设库是 `user://image-presets/` 里跨书的文件；官方预设随插件提供，只读。
- **展开**：把配方变成与后端无关的生成请求。
- **用得了的引用**：引用的文件找得到、只有一个原件（输出 4）、是要的那种、能按 `schema` 读、版本插件认识。
- **内容快照**：某一时刻配方、预设或片段的完整内容，按哈希认。
- **id 索引**：本书里每个 id 当前在哪个文件。
- **键、项、一段提示词**：见 [`images/prompt`](prompt.md)。

## 输入与前置条件

四种文件，都是 UTF-8 的 JSON，并且满足 I-JSON（[RFC 7493](https://www.rfc-editor.org/rfc/rfc7493)）：没有重复的字段名，字符串里没有落单的代理项，数的量级与精度不超出双精度浮点数。数按双精度浮点数解析后的值认，例如 `0.8` 就是解析后的那个值。快照的哈希（输出 27）靠这一条才算得出来。

| 文件 | 扩展名 | `schema` |
|---|---|---|
| 配方 | `.recipe.json` | `nbook.image-recipe/v1` |
| 预设 | `.preset.json` | `nbook.image-preset/v1` |
| 片段 | `.fragment.json` | `nbook.image-fragment/v1` |
| 风格组合 | `.style.json` | `nbook.image-style/v1` |

文件 id 的规则：
- 每个文件都有 `schema` 与 `id`。
- 文件 id 在本书里唯一，由插件生成，12 个以上字符，取自小写字母与数字。
- 官方预设的 id 以 `official:` 开头。

配方：

```ts
{
  schema: "nbook.image-recipe/v1",
  id: string,
  model: string,                       // 后端的模型 id
  sections: Section[],                 // 有序
  characters: Character[],             // 有序，先后决定人物大致的左右站位
  params: {preset: ParamsRef} | {values: Record<string, unknown>},
  size: {width: number; height: number},   // 正整数
  count: number,                           // 一批几张，正整数
  seed: number | null,                     // 不小于 0 的整数；null 表示每批随机
  base?: unknown,                          // 预留：源图、遮罩、强度
}
type Section = {
  id: string,                          // 在这份配方里唯一
  kind: "subject" | "style" | "quality" | "content" | "language" | "general" | "negative",
  name?: string,
  disabled?: true,
} & ({prompt: Prompt} | {preset: PresetRef})
type PresetRef = {id: string; diff: Change[]}
type Change =
  | {op: "add"; item: Item; after: Key | null}             // after：锚点的键；null 表示加在最前
  | {op: "remove"; key: Key}
  | {op: "set"; key: Key; fields: Record<string, unknown>; drop?: string[]}   // fields：要设的字段与新值（可以是 null）；drop：要去掉的字段
type ParamsRef = {id: string; diff: ({op: "set"; field: string; value: unknown} | {op: "unset"; field: string})[]}
type Character = {id: string; title: string; positive: Prompt; negative: Prompt; disabled?: true}   // id 在这份配方里唯一
```

- 节与角色框的 id 由插件生成，6 个以上字符，取自小写字母与数字。它们只在这份配方里唯一；在别处引用时连同配方 id 一起写。
- 复制配方时，节与角色框的 id 保留。

节的种类：

| `kind` | 名称 | 去处 | 能套的预设 |
|---|---|---|---|
| `subject` | 主体 | 主提示词 | 无 |
| `style` | 画风 | 主提示词 | 画风 |
| `quality` | 质量 | 主提示词 | 质量 |
| `content` | 内容 | 主提示词 | 无 |
| `language` | 自然语言 | 主提示词 | 无 |
| `general` | 通用 | 主提示词 | 无 |
| `negative` | 负面 | 负面提示词 | 负面 |

预设：

```ts
{
  schema: "nbook.image-preset/v1",
  id: string, name: string,
  kind: "style" | "quality" | "negative" | "params",
  model?: string,                      // 在哪个模型上调的
  prompt?: Prompt,                     // kind 不是 params 时必有
  values?: Record<string, unknown>,    // kind 是 params 时必有；不含尺寸、张数、种子
  sample?: {image: string; from?: string},  // 样图：WebP 的 data URL，不超过 64 KiB；from 是原图的哈希
  origin?: {from: "library" | "official"; id: string; at: string},  // 复制自哪里，at 是 ISO 时间
}
```

风格组合：

```ts
{
  schema: "nbook.image-style/v1",
  id: string, name: string,
  entries: {kind: "style" | "quality" | "negative"; name?: string; preset: string}[],
  params?: string,                     // 参数预设的 id
  origin?: {from: "library" | "official"; id: string; at: string},
}
```

片段：

```ts
{
  schema: "nbook.image-fragment/v1",
  id: string, name: string,
  use: "appearance" | "outfit" | "action" | "expression" | "interaction" | "scene" | "composition",
  main?: {core: Item[]; support: Item[]},
  characters?: {core: Item[]; support: Item[]}[],
  note?: string,
  origin?: {from: "library" | "official"; id: string; at: string},
}
```

- 片段的七种用途，依次是外貌、服装、动作、表情、互动、场景、构图。
- 片段里的项只能是词与句子。

其它输入：

- **本书默认：**配置项 `nbook.images/defaultStyle`，由本插件声明，只允许写在项目层（[`settings/configuration`](../settings/configuration.md)）。值是一个风格组合的 id，缺省是 `null`。
- **文件的位置：**四种文件放在本书的哪个目录都行。插件按扩展名在全书里找，不看 `.nbook/`、`.git/`，以及文件服务排除的目录。新建时的缺省位置：
  - 配方放 `插图/配方/`；
  - 预设与风格组合放 `插图/预设/`；
  - 片段放 `插图/片段/`。
- **我的预设库：**在 `user://image-presets/`，文件格式与本书里的相同。
- **官方预设：**随插件提供，每本书都能直接用。

## 输出与可观察行为

**文件与 id**

1. **读文件与写文件。**
   - 读文件时按 `schema` 校验。版本比插件认识的新，就只读打开，给出 `unsupported-version`，插件不改写它。
   - 插件改写文件时，原样保留不认识的字段。
   - 插件写出的 JSON 用两个空格缩进，字段按本 Spec 的顺序排，末尾有换行。
   - 插件写预设、片段、风格组合，以及换 id（输出 4），都经文件服务按期望写入；期望不符（文件被别处改过）时给出 `conflict`。开着这份文件的编辑器照它自己的规则处理磁盘变化（[`workbench/editor`](../workbench/editor.md) 输出 16）：没有未保存的修改就换成新内容，有就标“磁盘已变化”。
2. **新 id。**
   - 这些情况给新的文件 id：新建；“复制”配方、预设、片段或风格组合；从我的预设库或官方预设拿进书里。从别处拿进来的，记下 `origin`。
   - 新建的节与角色框，给配方里没有用过的 id。
3. **id 索引。**
   - **建立：**项目入口激活时扫描全书，建立 id 到文件路径的索引，之后跟着文件的变化更新。
   - **可用：**第一次扫描结束，索引就可用；按 id 查找要等到这时。
   - **读不了的目录：**不让扫描失败，给出诊断，那里的文件不在索引里。这一次扫描不改记录，也不按输出 4 换 id。
   - **记录：**每个 id 上次所在的路径记在 `.nbook/images/ids.json`。每次扫描结束、每批文件变化处理完时更新。读不了或坏了，就当没有记录。
4. **重复的 id。**
   - 只有一个文件的 id 是 x：它就是 x，路径和记录不同（例如被移动过）时，记录随之更新。
   - 几个文件的 id 都是 x，而记录里 x 所在的路径上正好是其中一个：它是原件。
   - 几个文件的 id 都是 x，记录没有或对不上：判不出原件，按 x 的引用给出 `duplicate-id`，直到作者打开其中一个、选定哪个是原件。
   - 记录里 x 所在的路径在这一次读不了的目录下：同样判不出原件，按 x 的引用给出 `duplicate-id`，看得见的那几份都不当作原件，直到那个目录能读，或者作者选定原件。
   - 原件确定以后，按 x 的引用都指向原件，其余各份由插件换新 id（输出 1）。
   - 版本比插件新或只读的文件不换，提示一句；它不影响按 x 的引用指向原件，也不让展开失败。
   - 换好新 id 的文件，等它写到磁盘上，索引才按新 id 收录它。

**节与角色框**

5. **新建配方。**
   - 先建这些节：主体、画风、质量、内容、自然语言，再加三个负面节，依次名为“官方段”“我的负面”“要避开的画师”。
   - 然后套上本书默认的风格组合（输出 17）。
   - 本书默认没设或找不到时，各节为空，并提示一句。
6. **节的操作。**可以加一个任意种类的节（可起名）、改名、调顺序、删除、停用。同一种节可以有几个。停用的节不参与展开。
7. **角色框的操作。**可以加、删、调顺序、改标题、停用。每个角色框有正面与负面两段提示词。
8. **主体数量自动补。**
   - 时机：按张展开（输出 25）时，每张在角色框已经展开、抽过签、去掉停用的项以后，看最终结果。
   - 条件：主体节里没有主体数量的词（`1girl` 到 `6+girls`、`1boy` 到 `6+boys`、`1other` 到 `6+others`、`no humans`），而又有没停用的角色框。
   - 计数：按每个角色框正面第一项的键是 `girl`、`boy`、`other`，各数几个，补成 `2girls`、`1boy` 这样的词。
   - 位置：补在第一个没停用的主体节的最前面；没有这样的节，就补在主提示词的最前面。
   - 已经有这些词就不动。

**预设与差异**

9. **套用预设。**
   - 只能给能套这种预设的节套（见“节的种类”表），参数预设只能套在参数上。种类对不上时给出 `kind-mismatch`，不套。
   - 套上以后，节的内容就是预设的内容，差异为空。
10. **节的实际内容。**从预设当前的内容出发，按差异依次做：
    - 先做全部“去”，再做全部“改”，最后按差异里的顺序做“加”。
    - “去”与“改”按键找项；“改”把 `fields` 里的字段设成新值（`null` 也是一个值），再去掉 `drop` 里的字段。
    - “加”放在锚点那一项后面，锚点可以是前面加进来的项；锚点不在了，就加到末尾。

    下面几种改动作废，不做，给出 `diff-void`，不写任何文件：
    - 找不到对应项的“去”与“改”；
    - 改完以后这一项的键变了，或者它不再是合法的项（[`images/prompt`](prompt.md) 的 `invalid-prompt`）；
    - 要去掉的字段，这一项本来就没有；
    - 要加的项的键，这时的内容里已经有了：做完“去”以后剩下的项里有（这一项已经并进预设），或者前面加进来的项里有。

    预设的内容是按原文保存的一段（`raw`）时，差异里的改动全部作废。
11. **差异怎么算。**作者在一个引用了预设的节里编辑以后，差异由预设的内容 P 与节的实际内容 S 算出。P 与 S 先按输出 30 并掉重复的键。
    - P 或 S 是按原文保存的一段时，差异表达不了：S 与 P 相同，差异为空；不同，这一节改成普通的一段提示词，内容是 S，并提示一句。
    - 两边按键取最长公共子序列；子序列有几种取法时，取在 P 里最靠前的那种。
    - P 里不在子序列中的项，记为“去”。
    - 子序列里，两边除键以外有字段不同的项，记为“改”，`fields` 是 S 里那些不同字段的值；P 里有、S 里没有的字段（例如重新启用后没了 `disabled`）记进 `drop`。
    - S 里不在子序列中的项，按 S 的顺序记为“加”，锚点是它在 S 里前面紧挨的那一项。

    按输出 10 把这份差异套回 P，得到的结果与 S 逐项相同。调换顺序会记成一去一加，没有“挪位置”这种改动。
12. **节上的三个动作。**
    - **还原：**清空差异。
    - **另存为新预设：**用节的实际内容新建一个预设，节改为引用它，差异为空。
    - **更新预设：**把节的实际内容写回预设（输出 13）。写成功以后，这一节如果还引用这个预设，差异按输出 11 对预设的新内容重算：写回期间没再改过这一节，差异就是空的；改过，就只剩写回以后的那些改动。重算是对打开着的这份配方的一次编辑，配方因此变成未保存，保存照编辑器的规则。写入失败（例如 `conflict`）时，差异不动。
13. **更新预设。**
    - 写回前，列出本书里引用这个预设的全部配方，每份写明哪些项会跟着变、哪些项保持它自己的值。
    - 确认后只写预设文件（输出 1），不写任何配方文件。
    - 写回以后，各配方的实际内容按输出 10 重新算。作者没保存那次重算就关掉配方时，旧差异里的“加”与预设里已有的项重复，按输出 10 作废，所以内容不会多出一份。
14. **换预设。**给一节换成另一个同种的预设，差异保留，按输出 10 对新预设重新算；作废的改动给出 `diff-void`。
15. **模型对不上。**预设的 `model` 与配方的 `model` 不同时，那一节给出 `model-mismatch`，不阻止生成。
16. **参数。**
    - 配方的参数要么引用一个参数预设，要么直接写 `values`，二者取一。
    - 引用预设时，实际值就是预设的 `values`，再按差异做 `set` 与 `unset`。
    - `unset` 一个预设里没有的字段，按输出 10 作废。
    - 换参数预设时，差异保留，对新预设重新算。
    - 预设里出现尺寸、张数或种子时，给出 `invalid-file`。

**风格组合与本书默认**

17. **套用风格组合。**一次套用里，配方的每一节最多接一条，按下面的顺序给组合的各条找节：
    1. 带名字的条目，找同种、同名、还没接条目的节；同名的有几个，取靠前的。
    2. 剩下的条目，按组合里的顺序，找同种、还没接条目的第一节。
    3. 还没找到的，新建一节，名字取条目的名字。

    挂上的规则同输出 14：节原来引用了别的预设，差异保留并重新算；原来没引用，就按输出 9 套上。组合里有参数预设时，同样换掉参数的预设。
18. **本书默认。**`nbook.images/defaultStyle` 指向的组合，只在新建配方时用一次；以后改了它，已有的配方不变。

**片段**

19. **插入片段。**
    - 在一节里插入片段，那一节得到一个指向片段主提示词部分的片段引用。
    - 片段有角色框部分时，第 i 部分插进第 i 个角色框的正面，没有的就新建角色框，各是一个带 `part` 的片段引用。
20. **展开片段。**
    - 一个片段引用展开成：所指部分的核心词，加上没被关掉的陪衬词。
    - 片段找不到时，给出 `fragment-missing`。
    - 找得到、但没有所指的部分，或者引用的文件不是片段，给出 `invalid-reference`。
21. **拆开成普通词。**把片段引用换成它展开以后的项，每一项的权重乘上引用的权重，按 [`images/prompt`](prompt.md) 输出 20 量化。乘出来超出范围时不拆，给出 `weight-out-of-range`。

**本书、我的预设库与官方预设**

22. **复制进出预设库。**
    - “放进我的预设库”与“拿进书里”都是复制一份、给新 id、记 `origin`。
    - 复制时连同它引用的东西一起复制：风格组合连同它的预设，预设连同它引用的片段，并把复制品之间的引用一起改成新的 id。引用官方预设的照旧引用，不复制。
    - 先写被引用的文件，最后写被复制的那一个。中途失败时，已经写出的文件留着，并在结果里列出。
23. **官方预设。**官方预设只读，配方可以直接引用；“复制到本书”得到一份可以改的副本。

**展开**

24. **展开结果。**每张一份，每份既有逐节的内容，也有拼好的主提示词与负面：

    ```ts
    type Expanded = {
      model: string;
      params: Record<string, unknown>;
      size: {width: number; height: number};
      count: number;
      seed: number | null;
      images: {                        // 一张一份，共 count 份
        sections: {                    // 没停用的节，按配方里的顺序
          id: string; kind: string; name?: string;
          items: Weighted[];           // 补上的主体数量在它补进去的那一节里
          text?: string;               // 这一节的图中文字
        }[];
        main: Weighted[];              // 不是负面的节依次拼接，含补上的主体数量
        text?: string;                 // 主提示词的图中文字
        negative: Weighted[];          // 负面节依次拼接
        characters: {id: string; title: string; positive: Weighted[]; negative: Weighted[]; text?: string}[];
        picks: number[];               // 抽签结果，按随机项在配方里出现的顺序
      }[];
      snapshots: {recipe: string; presets: Record<string, string>; fragments: Record<string, string>};
    };
    type Weighted = {kind: "tag" | "sentence"; text: string; weight: number} | {kind: "raw"; text: string};
    ```
25. **展开的步骤。**
    1. **去掉停用的。**每拿到一层内容，先去掉其中停用的，再解析剩下的引用。这些都算一层：配方的节与角色框；一节或一段提示词里的项；预设按输出 10 套完差异以后的项；片段所指部分展开出来的项；随机项的每个选项。停用的东西里的引用不解析，找不到也不算失败。
    2. **解析引用。**每一节的预设按输出 10 算出实际内容；片段按输出 20 展开。随机项每个选项里的引用都要解析，没抽中的也一样。
    3. **抽签。**按张数逐张抽签（[`images/prompt`](prompt.md) 输出 16）。
    4. **实际权重。**每项的实际权重，是它所在各层权重的乘积：随机项、片段引用与它自己。全部乘完以后，按 [`images/prompt`](prompt.md) 输出 20 量化一次。
    5. **主体数量。**每张按输出 8 补。
    6. **拼接。**不是负面的节，依次接成主提示词；负面节，依次接成负面提示词；角色框各自展开。
    7. **图中文字。**主提示词各节的图中文字，按节的顺序用一个空行连起来，放进 `text`；角色框正面的图中文字放进那个角色框的 `text`。
26. **展开会失败的情况。**有任何一个失败时，展开失败，交回全部问题，不交回部分结果。失败有这些：
    - `preset-missing`、`fragment-missing`、`duplicate-id`、`invalid-reference`；
    - 配方本身或引用的文件 `invalid-file`、`unsupported-version`；
    - 按原文保存的一段里有随机写法或图中文字，或者它不自成一段（`raw-unsupported`）：随机写法抽不了签，图中文字拆不出来，开着的权重会带到下一节；要先改成拆得开的写法；
    - 负面节或角色框的负面里有图中文字（`misplaced-text`）；
    - 有不认识的项（`unknown-item`）；
    - 实际权重的绝对值超过 10000（`weight-out-of-range`）；
    - 随机项的一个选项去掉停用的、展开片段以后什么也不剩（`empty-option`）。

    这些只看第 1 步去掉停用的以后剩下的内容。`diff-void` 与 `model-mismatch` 不让展开失败。其余按原文保存的段，按 `raw` 交给后端适配器。

**快照与恢复**

27. **内容快照。**
    - 快照是一个对象的完整内容：配方用展开那一刻编辑器里的内容（包括没保存的修改），预设与片段用当时解析到的内容。
    - 哈希是快照的规范 JSON 的 SHA-256，规范 JSON 照 [RFC 8785](https://www.rfc-editor.org/rfc/rfc8785)（JSON Canonicalization Scheme）。
    - 展开结果的 `snapshots` 记下配方快照的哈希，以及展开时解析过的每个预设与片段的快照哈希（按 id），包括随机项里没抽中的选项引用的。停用的东西里的引用不解析，也不记。
28. **从快照恢复。**
    - 输入是一组快照，得到一份配方内容，不写文件；怎样交给编辑器，见 `images/workbench`。
    - 恢复要做到：每一节、每个角色框、参数的实际内容，都和快照那时一样。拆开片段时权重的量化差，见“已知限制”。
    - **停用的节、角色框与项：**照配方快照原样保留，里面的引用不要快照。
    - **片段引用：**片段现在的内容和快照相同，就保留引用；不同、不在了或用不了，就按快照里的内容拆开成普通词（输出 21），并提示一句。拆开时乘出来超出范围的，不拆，保留引用并提示一句。
    - **引用了预设的节：**先按上一条处理片段引用，得到那时的实际内容。下面两条都成立时，仍引用这个预设，差异按输出 11 对预设现在的内容重新算：
      - 这个预设现在用得了；
      - 那时的实际内容与预设现在的内容都不是按原文保存的，那时的实际内容里也没有重复的键。

      否则那一节改成普通的一段提示词，内容是那时的实际内容，并提示一句。
    - **参数：**参数预设现在用得了，就仍引用它，差异按现在的预设重新算；否则改成直接写 `values`，值是那时的实际值，并提示一句。
    - **快照缺了、坏了，或版本不认识：**恢复失败，给出 `snapshot-missing`。
29. **引用不见了的修法。**一节给出 `preset-missing` 或 `fragment-missing` 时，有两个修法：
    - 从最近一批的快照，把这一节恢复成普通词，规则同输出 28；
    - 另选一个预设或片段，差异按输出 14 处理。

**键不重复**

30. **一段里键不重复。**
    - 预设的内容，以及引用了预设的节的实际内容，同一段里每个键最多出现一次。差异（输出 10、11）靠这一条按键找项。
    - 读入或编辑时得到重复的键，就并成一项：位置取最先出现的那一次，内容取最后出现的那一次。并完提示一句。读入时的合并不改写文件。
    - 没有引用预设的节不受这条限制，重复的键由 [`images/prompt`](prompt.md) 的诊断 `duplicate-item` 提示。

## 状态与转换

- 配方文件在工作台里编辑，保存、未保存标记、外部改动照编辑器的规则（[`workbench/editor`](../workbench/editor.md)）。
- 预设、片段、风格组合文件，在词库的管理动作与“更新预设”里写，写法见输出 1。期望不符时给出 `conflict`，重读后再请作者确认。
- 预设或片段文件变了，打开着的配方按新内容重算实际内容，不写配方文件，也不动它的未保存修改。
- 时序与寿命：
  - id 索引在项目入口激活后的第一次扫描完成时可用，之前的按 id 查找要等它。项目代次结束，索引随之作废。
  - 同一个预设被两处同时“更新”，后写的那处得到 `conflict`，它那一节的差异不动。
  - 展开拿的是那一刻的内容。之后预设或配方再改，不影响已经展开的结果，也不影响它的快照。
  - 换 id（输出 4）的文件正开在编辑器里、又有未保存的修改时，编辑器标“磁盘已变化”，保存时得到磁盘冲突。作者选“覆盖磁盘版本”，旧 id 写回磁盘，下次扫描再按输出 4 处理。

## 副作用与数据

- **四种文件：**放在作品目录里与 `user://image-presets/`，是作者的数据，跟着书走，建议进 Git。
- **id 索引的记录：**`.nbook/images/ids.json`，由项目入口直接写。删掉以后下次扫描重建，只是在这之前判不出原件（输出 4）。
- **本书默认：**存在项目层配置里，归配置插件管。
- **快照：**本 Spec 只定内容与哈希；存放、去重与清理归 `images/library`。
- **大小：**样图不超过 64 KiB；配方文件要能装进作品文件的正文上限（[`workspace/files`](../workspace/files.md)）；一段提示词读入时的长度上限见 [`images/prompt`](prompt.md)。

## 失败与恢复

| 编号 | 码 | 含义 | 调用方怎么办 |
|---|---|---|---|
| F1 | `invalid-file` | 不是合法的 JSON，或者形状不对。例如：不满足 I-JSON（重复的字段名、落单的代理项、超出双精度范围的数）；缺字段；种类不认识；提示词数据不对；节或角色框的 id 重复；数值不在规定的范围（尺寸、张数不是正整数，种子不是不小于 0 的整数）；参数既有预设又有 `values`；参数预设里有尺寸、张数或种子；样图超过 64 KiB | 工作台显示错误，可以用源码编辑器打开修改；这份文件不参与展开 |
| F2 | `unsupported-version` | 文件的版本比插件新 | 只读打开，不改写；被引用时展开失败 |
| F3 | `preset-missing` | 引用的预设找不到 | 展开失败；按输出 29 修 |
| F4 | `fragment-missing` | 引用的片段找不到 | 展开失败；按输出 29 修 |
| F5 | `duplicate-id` | 判不出原件：书里几个文件 id 相同又对不上记录，或者记录里的原件在读不了的目录下 | 展开失败；作者打开其中一个，选定原件 |
| F6 | `kind-mismatch` | 套预设时，预设的种类和节对不上 | 不套 |
| F7 | `diff-void` | 差异里有作废的改动 | 提示；展开时忽略这几条 |
| F8 | `model-mismatch` | 预设记的模型和配方的不同 | 提示，不拦 |
| F9 | `conflict` | 写预设、片段、风格组合，或换 id 时，文件已被别处改过 | 重读后再确认 |
| F10 | `read-only` | 改官方预设，或改版本更新的文件 | 只能复制一份再改 |
| F11 | `invalid-reference` | 引用的东西找得到但用不了：节引用了别的种类的预设，片段没有所指的部分，或者引用的文件不是要的那种 | 展开失败；改引用 |
| F12 | `raw-unsupported` | 按原文保存的一段里有随机写法（`\|\|`）或图中文字（`Text:`，不分大小写），或者它不自成一段（[`images/prompt`](prompt.md) 的术语） | 展开失败；改成拆得开的写法 |
| F13 | `misplaced-text` | 负面节或角色框负面里有图中文字 | 展开失败；删掉或挪到正面 |
| F14 | `snapshot-missing` | 恢复要的快照缺了、坏了，或版本不认识 | 恢复失败 |
| F15 | `unknown-item` | 没停用的内容里有插件不认识的项 | 展开失败；升级插件，或者删掉、停用这一项 |
| F16 | `weight-out-of-range` | 片段引用、随机项与项自己的权重乘出来，绝对值超过 10000 | 展开或拆开失败；调小引用或随机项的权重 |
| F17 | `empty-option` | 随机项的一个选项展开以后什么也不剩 | 展开失败；给片段补上词，或者删掉这个选项 |

## 边界与兼容

- 四种文件的格式是公开的：作者、Agent 与别的工具都可以直接读写。插件每次读都校验，不合法的按 `invalid-file` 处理。
- 版本：只增加可选字段时版本不变，旧插件保留不认识的字段；改变已有字段的含义时版本加 1，旧插件只读。
- 官方预设随插件的版本走。插件的新版本去掉了某个官方预设，引用它的配方得到 `preset-missing`。
- 展开结果是给后端适配器与生成记录的公开接口（`images/generation`、`images/library`）。
- 失败码只在本能力里有意义；和别的能力的结果放在一起时，按“能力加码”区分。

## 验收与 Smoke

1. **预设更新的传播。**
   - 前提：配方 A、B 都引用画风预设 P，A 把 P 里一位画师的权重改成 0.8。
   - 操作：从 B 更新 P，加一位画师、改一个年份。
   - 结果：A 的实际内容多了这位画师、年份跟着变，那位画师仍是 0.8；A 的文件逐字节不变。B 变成未保存、差异为空。不保存 B 就关掉再打开，B 的实际内容和保存了一样。
   - P 正开在源码编辑器里、没有未保存的修改时，编辑器里的 P 换成新内容；P 有未保存的修改时，编辑器标“磁盘已变化”，B 的差异照样重算为空。
   - 写回在途时作者又在 B 加了一个词：写成功以后，B 的差异只剩这个词。
2. **作废的改动。**接场景 1，再从 B 把 A 改过权重的那位画师从 P 里去掉、更新 P。打开 A 时给出 `diff-void`；展开 A 成功，结果里没有这位画师。
3. **套用风格组合。**
   - 配方有两个内容节，名为“服装”“光照”，只有一个负面节，名为“个人”。
   - 套上一个组合：一个画风预设、一个质量预设、三个带名字的负面预设、一个参数预设。
   - 结果：画风与质量各挂到自己种类的第一节。第一个负面预设挂到“个人”；另外两个负面预设新建两节，名字取各自条目的名字。两个内容节不变。
4. **带角色框部分的片段。**配方只有一个角色框，插入一个有主提示词部分与两个角色框部分的片段：多出第二个角色框；展开后两个角色框各得到对应的词。
5. **复制出来的重复 id。**在资源管理器里复制一份配方：下次扫描时原件保留 id，副本换了新 id；生成记录里引用原 id 的批次仍然指向原件。
6. **恢复。**
   - 生成一批以后先改了预设 P，再恢复这一批的配方：画风节仍引用 P，实际内容和当时一样。
   - 删掉 P 再恢复一次：那一节成了普通的一段提示词，内容和当时一样。
   - 再改了一个被引用的片段，恢复：那个片段引用被拆成当时的普通词。
   - 节里有一个停用的、指向已删片段的引用：展开成功，`snapshots` 里没有这个片段；恢复后这个停用的引用原样还在。
7. **多机重启。**项目重启后，id 索引照常重建；删掉 `.nbook/images/ids.json` 以后，再遇到重复 id 时给出 `duplicate-id`，而不是挑一个。
8. **跨书复制。**一个风格组合的画风预设里引用了片段 F。把组合放进我的预设库，再拿进另一本书：另一本书里多了组合、预设与 F 的副本，引用都指向副本，展开成功。
9. **按张补主体数量。**主体节为空，一个角色框的第一项是随机项（girl 或 boy），张数为 2。两张各按抽中的结果补上 `1girl` 或 `1boy`。
10. **差异的往返。**对下面每对 P 与 S，按输出 11 算差异、按输出 10 套回 P，结果与 S 相同：
    - 调换两项的顺序；
    - 删去第一项、改最后一项的权重；
    - 在一项后面连加两项；
    - 停用一项，再把另一项重新启用；
    - 把一项不认识的字段设成 `null`，再去掉另一项的这个字段；
    - 只改一个词的大小写；
    - 改片段引用关掉的陪衬词；
    - 改随机项一个选项里的权重。

    另外，S 里同一个词出现两次时，先并成一项再算；S 是按原文保存的一段时，这一节改成普通的一段提示词。
11. **记录对不上。**
    - 关掉应用，把原件移走，再复制一份：两份都对不上记录，按 x 的引用给出 `duplicate-id`，直到作者选定原件。
    - 原件所在的目录暂时读不了，只看得见一份副本：按 x 的引用给出 `duplicate-id`，不改记录；目录恢复以后，引用仍指向原件。

Smoke：随实现补。
