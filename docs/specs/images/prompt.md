# 图像提示词：项、权重与写法

## 目标与非目标

给图像插件一套与后端无关的提示词表示。一段提示词是一串带数值权重的项。这套表示要能做到：
- 读入 NovelAI 与 SD 两种写法；
- 写出 NovelAI 的规范写法；
- 对随机项抽签；
- 按空行把一整段原文切成几段，并保住每个词的实际权重；
- 做只靠语法就能查出的检查。

配方（[`images/recipes`](recipes.md)）、体检与粘贴拆分（`images/checks`）、后端适配器（`images/generation`）与工作台都用它。

不承诺：

- 一个词收没收录、属于哪一类、放没放错节，归 `images/checks` 与 `images/tags`。读入时调用方可以提供“已知标签”的判断，但本 Spec 不自带词库。
- 写成 NovelAI 以外的写法，归各后端的适配器。
- `@{名字}` 解析到哪个片段，归 [`images/recipes`](recipes.md)。
- 词的先后对生成效果的影响。

已知限制：

- **词与句子的分法是启发式的**（输出 2）。全大写开头、三个词以上的标签会被读成句子；句子里的缩写与小数点，以及句子中间的数值权重、随机项、片段引用，都会让句子提前结束。读成哪种可以事后改：改项的 `kind`。
- **连写的数值权重。**`1.6::甲, -1::乙`（前一个没结束就写下一个）的语义，NovelAI 没有公开。读入时按“后一个替换前一个”处理，并给出诊断 `chained-weight`。
- **随机项外面包着数值权重、选项里又有数值权重时**（例如 `2::||rain|3::snow ::||::`），本 Spec 按相乘读；NovelAI 是先替换选项再按连写的语义算，结果可能不同。
- **权重为 0 的项。**`0::词 ::` 读成权重为 0 的项。它是不是等于没写，NovelAI 没有公开。

## 术语与参与者

- **项**：提示词的最小单位，种类见“输入与前置条件”。
- **一段提示词**：有序的一串项。节的内容、角色框的正面与负面、片段的各部分，都是一段提示词。
- **逗号段**：原文里两个分隔符之间的一截文字。
- **段落**：原文里两个空行之间的一截文字。
- **实际权重**：一项最终发给模型时乘上的倍数。
- **原文**：一段提示词从文字读进来时的那段文字。
- **自成一段**：一段文字读完时，没有开着的花括号、方括号或数值权重，开头也不依赖前文开着的权重。
- **规范写法**：本 Spec 写出 NovelAI 文字时唯一的写法（输出 10）。
- **键**：判断两项是不是同一项时比较的值（输出 13）。
- **读法**：`novelai` 或 `sd`。
- **诊断**：只靠语法查出的问题，带码、位置，以及能不能一键改。

## 输入与前置条件

一段提示词的数据形状。它写在配方、预设、片段文件与内容快照里，所以本身就是持久格式：

```ts
type Prompt =
  | {items: Item[]; source?: string}   // source：NovelAI 原文，只在输出 12 的条件下保留
  | {raw: string};                     // 拆不开的原文，整段保存（输出 11）

type Item =
  | {kind: "tag"; text: string; weight: number; disabled?: true}
  | {kind: "sentence"; text: string; weight: number; disabled?: true}
  | {kind: "fragment"; ref: string; part?: number; weight: number; off?: string[]; disabled?: true}
  | {kind: "choice"; options: Item[][]; weight: number; disabled?: true}
  | {kind: "text"; text: string; disabled?: true}
  | {kind: string; [field: string]: unknown};   // 不认识的种类，原样保留

type Key = string | unknown[];   // 项的键（输出 13）：词与句子是字符串，别的种类是数组
```

- **`weight`：**有限的数，可以为负，绝对值不超过 10000，最多四位小数（按数的最短十进制写法算），缺省是 1，存的时候总是写出来。
- **词与句子的文字：**下面这些写法在 NovelAI 里另有含义，写进文字会改变别的项的权重或种类，所以不许出现：
  - 词：分隔符（`,`、`，`、换行）、花括号、方括号、`||`、`::`、`Text:`（不分大小写），也不以 `@{` 开头；
  - 句子：`||`、`::`、`@{`、`Text:`（不分大小写）；花括号的 `{` 与 `}` 个数相同，方括号的 `[` 与 `]` 个数相同。
  - 按 NovelAI 读法读入得到的词与句子总是满足这一条；按 SD 读法读出的不满足时，见输出 8。
- **`fragment`：**
  - `ref` 是片段的 id。
  - `part` 指片段的哪一部分：不写是主提示词那部分，写从 0 起的整数是第几个角色框那部分。
  - `off` 是关掉的陪衬词，记它们的键。
- **`choice`（随机项）：**至少两个选项；每个选项是一串非空的项，里面不再有随机项与图中文字。
- **`text`（图中文字）：**没有权重；一段提示词里最多一个，而且总在最后。
- **`disabled`（停用）：**展开时跳过。

读入的输入有三样：
- 一段文字，最多 65536 个字符；
- 一个可选的读法，不给就按输出 9 自动判断；
- 一个可选的“是不是已知标签”的判断，调用方用词库提供，判断时传入一个逗号段的键。

NovelAI 写法的读入规则：

| 写法 | 含义 |
|---|---|
| `,`、`，`、换行 | 分隔逗号段 |
| 空行 | 分隔段落；句子不跨段落 |
| `{`、`}` | 给它右边的全部内容乘、除 1.05，不要求配对 |
| `[`、`]` | 给它右边的全部内容除、乘 1.05，不要求配对 |
| 逗号段开头的 `数值::` | 开始一段数值权重，和开着的括号相乘。数值的写法是可选的负号、数字、可选的小数部分，不认指数写法 |
| 其余位置的 `::` | 结束数值权重，并把开着的花括号、方括号都清掉 |
| `\|\|甲\|乙\|\|` | 随机项 |
| `Text:` | 图中文字，从这里到全文末尾都算 |
| `@{名字}` | 片段引用，`名字` 是本书里片段的名字 |
| 圆括号 | 普通字符 |

例如 `1.2::year 2025::` 里，`2025::` 不在逗号段开头，所以是结束，`year 2025` 的权重是 1.2。

SD 写法的读入规则：

| 写法 | 含义 |
|---|---|
| `(甲)` | 每套一层乘 1.1 |
| `(甲:数值)` | 权重就是这个数值 |
| `[甲]` | 每套一层除以 1.1 |
| `\(`、`\)` | 字面的圆括号 |
| `BREAK`、`<…>`（例如 `<lora:名字:0.8>`） | 照原样读成词，给出诊断 `sd-only` |

## 输出与可观察行为

1. **按 NovelAI 读法读入。**
   - 每一项的实际权重，等于它左边全部花括号、方括号的乘除之积，再乘上包住它的数值权重，按输出 20 量化。
   - 一个逗号段里，实际权重中途变了（例如 `beautiful {detailed} eyes`），就在变化的地方切成几项，给出诊断 `split-in-item`；写出时这几项之间按规范写法加逗号。
   - 句子不在这里切，见输出 2。
2. **词与句子。**按下面的顺序决定：
   - 段落之间先切开。
   - 在一个段落里，一个逗号段如果以大写字母开头、至少有三个词，而且调用方的“已知标签”判断没有认出它，就是一个句子的开头。句子一直延续到 `.`、`!`、`?`、`。`（含）或者段落末尾，中间的逗号不切；遇到别的写法时，在它前面结束：数值权重的开始与结束、随机项、片段引用、`Text:`。
   - 含中文的逗号段也读成句子。
   - 其余的逗号段读成词；空的逗号段丢掉，给出诊断 `empty-item`。
   - 句子里的花括号与方括号照原样留在句子的文字里，不按输出 1 切。整个句子的权重，是句子开头所在位置的实际权重。
   - 句子里的 `{` 与 `}`、`[` 与 `]` 个数要相同，这样句子结束时开着的括号和开头时一样。不相同时，整段提示词按原文保存（输出 11），给出诊断 `unparsed-sentence`。
3. **图中文字。**
   - `Text:`（不分大小写）读成一个 `text` 项，冒号后面紧跟的一个空格是写法的一部分，不算内容。
   - 之后的全部字符，包括多出来的空格、换行与空行，原样是内容。
   - `Text:` 前面的内容照常读。
4. **随机项。**
   - 随机项要独占一个逗号段：同一个逗号段里，`||…||` 前后只能有空白与权重写法。
   - `||` 与 `||` 之间按 `|` 分成选项，其中的逗号只在选项里分隔，不分隔外面的逗号段。每个选项从权重 1 开始独立读成一串项，读法同输出 1、2。
   - 随机项本身的权重，是它所在位置的实际权重。
   - 随机项和别的文字连在同一个逗号段里（例如 `||red|blue|| hair`），或者任何一个选项不自成一段、读不成项，就按输出 11 处理。
5. **片段引用。**`@{名字}` 读成一个 `fragment` 项，权重是它所在位置的实际权重。在这一层只记名字，名字换成 id 由调用方做（[`images/recipes`](recipes.md)）。
6. **全角逗号与下划线。**全角逗号当逗号读，给出诊断 `fullwidth-comma`。下划线照原样保留在文字里，给出诊断 `underscore`。
7. **数值权重没有结束。**
   - 到全文末尾还开着的数值权重或括号，照 NovelAI 的规则一直作用到末尾，给出诊断 `unclosed-weight`。
   - 前一个数值权重没结束，就在逗号段开头开始下一个：后一个替换前一个，给出诊断 `chained-weight`。
8. **按 SD 读法读入。**照“SD 写法”的表算实际权重，其余同输出 2 到 6。读出来的词或句子里有不许出现的写法（例如 SD 里当普通字符的花括号），整段提示词按原文保存（输出 11），给出诊断 `reserved-text`。
9. **自动判断读法。**
   - 文字里出现 `(词:数值)` 这种写法，就按 SD 读，其余按 NovelAI 读。
   - 读入的结果里写明用的是哪种读法，调用方可以指定另一种读法重读。
   - 按 NovelAI 读的文字里出现 `(词:数值)` 时，给出诊断 `sd-syntax`。
10. **规范写法。**写出一段提示词时：
    - 项之间用 `, ` 隔开；
    - 权重为 1 的项不加包裹；
    - 权重不为 1、相邻且权重相同的几项合成一段，写成 `数值::甲, 乙 ::`：数值去掉末尾的 0，结束的 `::` 前面空一格；
    - 句子照原样写；
    - 随机项不加外层包裹：把随机项的权重乘进每个选项里每一项的权重，再把选项按同样的规则写成 `||甲|乙||`；
    - 片段引用写成 `@{名字}`，名字由调用方给出；
    - 停用的项照样写出；
    - 图中文字写在最后，和前面隔一个换行，写成 `Text: ` 加上内容。

    规范写法的结果总是自成一段，不出现连写的数值权重，不认识的项跳过（输出 19）。
11. **按原文保存。**下面几种情况，整段提示词存成 `{raw: 原文}`，并给出对应的诊断：
    - 随机项没有独占一个逗号段，或者选项读不成项、不自成一段：`unparsed-choice`；
    - 句子里的花括号或方括号个数不配对：`unparsed-sentence`；
    - 实际权重超出范围：`weight-out-of-range`；
    - 按 SD 读法读出的词或句子里有不许出现的写法：`reserved-text`。

    `raw` 写出时照原样，不能抽签、不能切段。
12. **原文的保留与写回。**
    - 只有按 NovelAI 读法读入、读入的文字自成一段、而且里面没有片段引用时，结果里才保留 `source`。片段引用在原文里只有名字，存的是 id，两边比不了。之后只要有任何一项改了（增删、改字、改种类、改权重、停用、一键改），`source` 就丢掉。
    - 写出时，有 `source` 就照原样写出，没有就用规范写法。
    - 从文件里拿到一段带 `source` 的提示词时，先把 `source` 按 NovelAI 读法重读一遍，和 `items` 比较。不一致，就丢掉 `source`，给出诊断 `source-stale`。
13. **键。**
    - 词与句子的键是规范化文字，是一个字符串：转小写、下划线换成空格、连续的空白合成一个空格、去掉首尾空白。
    - 别的种类的键是一个数组，第一个元素是种类，所以不会和词的键相同：
      - 片段引用：`["fragment", ref]`，有 `part` 时是 `["fragment", ref, part]`；
      - 随机项：`["choice", 选项]`。选项是一个二维数组，按选项排，每个选项是里面各项的键；随机项自己的权重、选项里各项的权重与别的字段不进键；
      - 图中文字：`["text"]`；
      - 不认识的项：`["item", 整项]`。
    - 两项的键写成 JSON（[RFC 8785](https://www.rfc-editor.org/rfc/rfc8785)）以后相同，就是同一项。
14. **往返不变。**一段没有 `source` 的提示词，如果满足下面的条件，按规范写法写出、再按 NovelAI 读法读回来，得到的项、种类、顺序与实际权重都和原来一样：
    - 没有停用的项，也没有不认识的项；
    - 没有片段引用：读回来只得到名字，`part` 与 `off` 也写不出来；
    - 词的文字里没有 `|`；
    - 句子的文字里没有花括号与方括号；
    - 每一项按输出 2 单独读，种类和它现在的种类相同；
    - 句子以 `.`、`!`、`?`、`。` 结尾，或者是最后一项；
    - 随机项的权重是 1。权重不为 1 的随机项，往返后它的权重乘进了各选项，抽签得到的实际权重不变。

    不满足的提示词，只保证经 JSON 存取不变。
15. **切段。**把一整段文字按段落切成几段，用于粘贴拆分：
    - 先对全文按读法算出每一项的实际权重，再按段落切开。句子不跨段落，所以每一项都只属于一个段落。一个权重跨了几段时，切开以后每一项的实际权重不变。
    - 图中文字单独作为最后一项，不参与切段。
    - 切出来的每一段都是一段提示词。只有当这一段的文字自成一段、而且单独读入得到的项与切出来的相同时，才保留 `source`。
16. **抽签。**
    - 给一段提示词和一个随机源，对每个没有停用的随机项，独立、等概率地选一个选项。结果是不含随机项的一串项，以及选了哪几个选项（按随机项出现的顺序记下标）。
    - 同一个随机源给出同样的结果。
    - 选中的选项里每一项的实际权重，是它自己的权重乘上随机项的权重，乘完按输出 20 量化。
17. **检查。**给一段提示词，交回一组诊断。诊断是可序列化的数据：码、位置（第几项，或原文里的字符范围）、能不能一键改。码见“失败与恢复”的诊断表。
18. **一键改。**
    - `underscore` 把下划线换成空格。
    - `fullwidth-comma` 与 `empty-item` 改成规范写法。
    - `duplicate-item` 在两项除键以外都相同时，删掉后出现的那一项。
    - 改完 `source` 丢掉。
19. **不认识的项。**数据里不认识的种类，存回去时原样保留；写出 NovelAI 文字时跳过它，给出诊断 `unwritable-item`。
20. **权重的量化与范围。**
    - 实际权重按四舍五入（0.5 远离 0）保留四位小数，`-0` 记为 0。
    - 读入时算出来的实际权重不是有限的数，或者绝对值超过 10000，整段提示词按原文保存（输出 11），给出诊断 `weight-out-of-range`。随机项里的项，实际权重算上随机项的权重。
    - 数据里随机项的权重乘上它选项里任何一项的权重，绝对值也不超过 10000（F2），所以抽签与规范写法乘出来的权重总在范围里。

## 状态与转换

- 读入、写出、切段、抽签、检查、一键改都不持有隐含的状态，也不读写文件，浏览器与服务端都能用。同样的输入总是得到同样的结果；抽签另要同一个随机源。
- `source` 是数据的一部分，随一段提示词一起传递。它在读入时按输出 12 得到，任何改动都让它失效，失效以后不会恢复。

## 副作用与数据

- 没有副作用。
- 数据形状写进别的文件，版本跟着所在文件的格式走（[`images/recipes`](recipes.md)）。
- 存回去时，不认识的字段与项原样保留。
- 权重存的时候按输出 20 量化。

## 失败与恢复

失败：

| 编号 | 码 | 含义 | 调用方怎么办 |
|---|---|---|---|
| F1 | `too-long` | 要读入的文字超过 65536 个字符 | 不解析，提示作者分开粘贴 |
| F2 | `invalid-prompt` | 数据形状不对。例如：权重不是有限的数、超出范围或多于四位小数；随机项的权重乘上它选项里一项的权重，绝对值超过 10000；词或句子的文字里有不许出现的写法；随机项少于两个选项，或者有空选项；图中文字不在最后，或者不止一个；`part` 不是从 0 起的整数 | 所在文件按 [`images/recipes`](recipes.md) 的 `invalid-file` 处理 |

除了 `too-long`，读入文字不会失败，问题都以诊断交回。

诊断：

| 编号 | 码 | 含义 | 能一键改 |
|---|---|---|---|
| D1 | `unclosed-weight` | 到末尾还开着的数值权重或括号 | 否 |
| D2 | `chained-weight` | 前一个数值权重没结束就开始下一个 | 否 |
| D3 | `empty-item` | 连续的分隔符 | 是 |
| D4 | `fullwidth-comma` | 全角逗号 | 是 |
| D5 | `underscore` | 词里有下划线 | 是 |
| D6 | `duplicate-item` | 同一段里两项的键相同 | 除键以外都相同时是 |
| D7 | `sd-syntax` | 按 NovelAI 读的文字里出现 SD 的 `(词:数值)` | 否（改用 SD 读法重读） |
| D8 | `sd-only` | `BREAK`、`<…>` 这类 SD 专用写法 | 否 |
| D9 | `unparsed-choice` | 随机项没有独占一个逗号段，或者选项读不成项、不自成一段，整段按原文保存 | 否 |
| D10 | `unwritable-item` | 不认识的项，写不成 NovelAI 文字 | 否 |
| D11 | `cjk` | 含中文的逗号段 | 否 |
| D12 | `split-in-item` | 一个逗号段里权重中途变了，切成了几项，写出时会多出逗号 | 否 |
| D13 | `unparsed-sentence` | 句子里的花括号或方括号个数不配对，整段按原文保存 | 否 |
| D14 | `weight-out-of-range` | 实际权重不是有限的数或超出范围，整段按原文保存 | 否 |
| D15 | `source-stale` | 文件里的 `source` 和 `items` 对不上，已丢掉 | 否 |
| D16 | `reserved-text` | 按 SD 读法读出的词或句子里有 NovelAI 另有含义的写法，整段按原文保存 | 否 |

## 边界与兼容

- 公开的有两样：数据形状，以及读入、写出、切段、抽签、检查、一键改这几种运算。数据形状是配方、预设、片段文件与快照格式的一部分，Agent 用文件工具读到的就是它。
- 诊断码只在本能力里有意义。和别的能力的结果放在一起时，调用方按“能力加码”区分。
- NovelAI 对连写数值权重的语义一旦实测清楚，输出 7 的读入规则会随之修改。规范写法不写连写的数值权重，所以写出不受影响。
- 片段引用的写法 `@{名字}` 只用于“原文”这个视图与粘贴；存的时候存 id。

## 验收与 Smoke

1. **跨段的权重。**
   - 输入：`{{a, b` 空一行 `c}}, d`。
   - 整体读入后，a、b、c 的实际权重是 1.1025，d 是 1。
   - 按段落切成两段，各自写出为 `1.1025::a, b ::` 与 `1.1025::c ::, d`；两段各自读回，权重不变。
2. **带括号与数字的标签。**
   - `saber (fate), 1girl` 自动判断为 NovelAI 读法，读成两个词，权重都是 1。同一串指定按 SD 读时，`fate` 读成权重 1.1 的一项，并给出 `split-in-item`。
   - 权重 1.2 的 `year 2025` 写出为 `1.2::year 2025 ::`，读回得到同一项；`1.2::year 2025::` 读入也得到同一项。
3. **随机项与图中文字。**
   - 输入：`1girl, 2::||rain|3::snow ::||::, night, Text: Hello` 空一行 `World`。
   - 读成：词、随机项、词、图中文字。随机项的权重是 2，两个选项分别是 rain@1 与 snow@3；图中文字是 `Hello`、空一行、`World`。
   - 用同一个随机源抽签两次，结果相同；抽中 snow 时，它的实际权重是 6。
   - 写出为 `1girl, ||2::rain ::|6::snow ::||, night`，换行，再 `Text: Hello`、空一行、`World`。读回后抽中 snow 的实际权重仍是 6。
4. **原文的保留。**
   - 读入一段自成一段的 NovelAI 原文，不改就写出，与原文逐字相同。
   - 改一项的权重再写出，得到规范写法，按 NovelAI 读法读回来与改后的项一致。
   - 按 SD 读法读入的文字不保留 `source`。
5. **按原文保存。**
   - `||red|blue|| hair` 存成 `raw`，写出与原文相同，并给出 `unparsed-choice`；`||red|blue||, hair` 读成一个随机项和一个词。
   - 15000 个 `{` 接一个词，给出 `weight-out-of-range` 并存成 `raw`。
6. **句子与段落。**
   - `A girl stands` 空一行 `near a tree.`，读成两项：第一项是句子，第二项是词。切段得到两段，每段一项。
   - `1.2::A girl in a red dress ::, rain` 读成权重 1.2 的句子与权重 1 的词，句子的文字里没有 `::`。

Smoke：随实现补；本能力是纯运算，合同测试覆盖全部输出条目。
