# 功能名称

> 本模板中的说明在填写后删除。`planned` 与 `implemented` 使用同一文件；实现完成后原地更新状态和证据。

## 目标与非目标

说明用户或调用方得到的能力，以及明确不承诺的行为。

## 术语与参与者

定义本规范使用的对象、角色和容易混淆的词。

## 输入与前置条件

列出触发方式、输入形状、权限、有效范围和前置状态。

## 输出与可观察行为

按输入类别说明返回值、界面反馈和调用方能观察到的结果。

## 状态与转换

用表格或状态图说明初始状态、触发事件、下一状态、拒绝条件、幂等与并发语义。没有持久状态时明确写“本能力不引入持久状态”。

## 副作用与数据

说明持久化、文件、事件、网络、缓存、外部进程及其 owner、生命周期和清理责任。没有副作用时明确写“无副作用”。

## 失败与恢复

说明校验失败、部分失败、重试、回滚、超时、取消和 fail-closed 行为。

## 边界与兼容

说明模块所有权、权限、安全、公开接口、版本兼容和迁移影响。

## 验收与 Smoke

使用 Given / When / Then 或同等清晰格式，覆盖主路径、边界、状态转换、副作用和恢复。写实际可执行或可观察的 smoke 入口，不用“测试通过”代替场景。

## 实现合同

`planned` 阶段删除本节或只写“尚未实现”。`implemented` 阶段记录 owner、公开接口、数据/事务边界、关键内部不变量和稳定命令或模块入口；物理文件拆分不需要更新入口，入口符号变化时同步更新。不写逐函数控制流或文件改动过程。

## 证据

`planned` 阶段链接批准该目标的 Proposal/ADR。Task 只作为实现 provenance，不作为行为依据。

`implemented` 阶段改用三条固定标签，每条至少链接一个仓库内存在的文件，类型必须对应（`bun run docs:check` 校验）：

- 实现入口：源码文件，不能是 `.md`
- 合同测试：`*.test.ts` / `*.spec.ts` 等测试文件
- Smoke：可执行 smoke 脚本或测试；确实没有时写「不适用——<理由>」
