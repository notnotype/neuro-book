# 剧情：写完以后的检查

## 目标与非目标

一章写完以后，要查出穿帮（不该知道的人说出、做出了这件事）、视角越界、提前泄底、违反写作指示与决策、正文里冒出来的没记录的事。要判断文字的，由程序先圈候选，再让记账 Agent 回答窄问题（引原句）；泄底另开一次不知道真相的“试读”。本能力定义候选怎样圈、各层问什么、预算与优先、试读的材料、答案的校验与保存、结果怎样成为待处理，以及几个账本视图。程序能确定的检查在各自的 Spec 里（[`plot.knowledge`](knowledge.md)、[`plot.foreshadowing`](foreshadowing.md)、[`plot.goals`](goals.md)、[`plot.decisions`](decisions.md)），不在这里。

不承诺：

- 自动改正文。
- 提示词的措辞与用哪个模型：本能力定问题的结构与给模型的材料；措辞是领域提示词，随实现改。
- 检查在写作流程里什么时候跑、谁来跑：随写作流程与 Agent 工具另行定义；本能力给出“对第 N 章跑一次检查”的入口与它的结果。
- 缺省上限的最终数字：本 Spec 给的是缺省值，用样章量过以后再定。

## 术语与参与者

- **窄问题**：只问一件事、要求引原句的问题，由记账 Agent 回答。
- **层**：窄问题按查什么分的几类（输出 2）。
- **试读**：另开一次便宜模型的调用，只给与问题有关的原文、不给真相，问读者会怎么猜（输出 4）。
- **一次检查**：对某条线上的第 N 章跑一遍各层与试读，结果存成一条检查记录（输出 7）。
- **记账 Agent、试读模型**：宿主提供的两个模型调用：给问题与材料，返回结构化的答案。

## 输入与前置条件

- 世界（某个版本）、第 N 章与它讲的线、第 N 章的当前正文与上一章的正文、写作指示快照、写手上下文的记录与写手的自陈（[`plot.brief`](brief.md) 输出 11、15）。
- 宿主提供记账 Agent 与试读模型的调用；没有时不能检查（`plot-check-unavailable`）。
- 检查记录存在插件的项目记录里（[`storage.persistence`](../storage/persistence.md)，`scope: project`）。

## 输出与可观察行为

1. **本章涉及的知识点（写完以后）。** 知识点 K 在第 N 章有信号，当：它出现在第 N 章的计划、节点或细纲讲述的标注里；第 N 章安放的一条变更改了某人对 K 的知情行；或者第 N 章正文里出现了 K 的主体或 `揭穿` 指向的马甲的名字或别名（按内核的 `lookup`）。至少有一个信号才圈；没有信号的不问，由新事实层兜底。
2. **各层的候选与问法。** 候选由程序圈出，每个候选一个窄问题；每个问题写明要引原句（段与原文），答不出就答“看不出”：
   - **在场层**：涉及本章、保密档以上的 K × 本章已写变更里在场、对 K 的有效知情是 `unaware`、`suspects`、`forgot`、`misbelieves` 或没有行的人。问“某某有没有说出或做出把这件事当真的言行（包括试探、质问、回避、施压）”；误信的另问“有没有与他的误信矛盾的言行”，题面写明误信的来源（知情行的“谁告诉的”“怎么知道”）。
   - **叙述层**：视角方式是第一人称或有限视角时，涉及本章、保密以上、视角人物不知道或误信的 K。问“叙述有没有写出视角人物不知道、看不到的这件事”。
   - **伏笔物件层**：本章已写变更涉及、或正文里出现了某个已埋未回收伏笔的物件时，每个物件一问，只问事实：动了没有、原句、动之前与之后是什么样（正文没写清就答“没写清”）、谁动的；题面写明伏笔当前的阶段、读者在本章之前见没见过这个物件。前提还成不成立由程序判断（[`plot.foreshadowing`](foreshadowing.md) 输出 7）。
   - **时间层**：每章固定一问：本章有没有时间倒回或跳回。
   - **读者层**：见输出 4。
3. **固定的一次调用。** 写作指示层与新事实层每章合成一次调用，不占输出 5 的配额：叙述有没有写出视角人物不可能知道的内心、别人的心理；结尾有没有停在写作指示的 `ending`；“不写的”每一项有没有写；涉及本章的已定决策的文字约束有没有被违反、待定决策的事有没有被写死（[`plot.decisions`](decisions.md) 输出 4）；正文里有没有人说出或按一件世界里没有记录的事行动；有没有新的名字、数值、设定，既不在自陈里，也不在世界里。输出最多 30 条，超出的记“未列：N 条”，这一次检查标“不完整”。
4. **试读。** 只对涉及本章、保密以上、在本章之后有揭示计划（带 `explicit` 的 `plot.reveal` 的计划）、读者在上一章末尾还没到 `knows` 的 K 做：
   - 材料按问题选、不按答案选：K 是某个悬念的答案（[`plot.foreshadowing`](foreshadowing.md) 输出 3）时，取这个悬念从第一章起所有生效节点所在的段（包括误导与呼应），加上一章与本章的全文，按活页夹章序、到本章为止；K 没有悬念连着时，只给上一章与本章的全文，结果标“材料只有前后两章”，并给提示 `plot.check.noSuspense`（建议建一个悬念）。
   - 题面是悬念的名字（读者要猜的那个问题）；没有悬念时由程序从 K 的主体写成“关于某某，你有什么猜测”。题面、材料里都不出现 K 的命题、条目 id 与世界里的真相。
   - 问“你觉得是谁（是什么）、有多确定（确定、强烈倾向、有点怀疑、看不出）、哪几句让你这样想”。
   - 试读的答案再交记账 Agent 判一个窄问题：这个答案与 K 的命题一致、部分一致、还是不一致。一致或部分一致、而确定程度是“确定”或“强烈倾向”时，报提前泄底（输出 8）。
   - 每章最多 3 次试读（缺省），按输出 5 的价值排。
5. **预算与优先。** 窄问题每章最多 20 个（缺省，不含试读与固定的一次调用），按价值排：读者层（绝密）、读者层（保密）、叙述层、在场层（绝密）、在场层（保密）、伏笔物件层、时间层；同一层按知识点、人的 id。超出的不合并，记成“未问：N 条”并列出；作者要求时，或下一章检查时，可以补问。
6. **答案的校验。** 每个答案的引文由程序核对：原文必须在本章正文里（试读的引文在给它的材料里）；对不上的，这个答案按“看不出”处理，并给提示 `plot.check.badQuote`。
7. **检查记录。** 一次检查存一条记录，键是线与章：用的世界版本、写作指示快照的版本、本章正文的摘要（SHA-256）、写手上下文的记录、各层的问题与答案、未问与未列的条目、试读的材料清单与答案。同一章再跑一次，新记录替换旧的。诊断只读本章正文摘要与当前正文相同的那条记录；正文变了以后，这一章的检查结果不再报，给提示 `plot.check.stale`（“本章正文变了，检查要重跑”）。
8. **结果成为待处理**（诊断，级别 `pending`，读检查记录算出）：
   - `plot.check.possibleSlip`：在场层或叙述层答“有”；同一章、同一知识点的几条合成一项，列出各层、人与原句；键是章与知识点；
   - `plot.check.earlyReveal`：试读报出提前泄底；附上挂在 K 上的读者守卫与决策（[`plot.decisions`](decisions.md) 输出 3、7）；键是章与知识点；
   - `plot.check.unrecordedKnowing`：新事实层报出有人按没有记录的事行动；键是章与原句的摘要；
   - `plot.check.unreportedInvention`：新事实层报出不在自陈、也不在世界里的新名字、数值、设定；键是章与原句的摘要；
   - `plot.check.instructionViolated`：写作指示层报出视角越界、结尾没停住、写了“不写的”；键是章与那一项；
   - `plot.check.forkSuspected`：时间层答“有”，而本章没有分叉；键是章；
   - 决策的两项（`plot.decision.constraintViolated`、`plot.decision.decidedInText`）在 [`plot.decisions`](decisions.md) 里，读同一份记录。
   只提示的：`plot.check.unasked`（未问、未列的条数）、`plot.check.noSuspense`、`plot.check.badQuote`、`plot.check.stale`。作者对这些诊断的处理按内核的规则落成决策、绑定诊断的版本（[`canon.model`](../canon/model.md) 输出 35）。
9. **账本视图。** 读取：
   - 保密账本：每个保密以上的知识点，在给定的线与位置上谁知道、谁误信、谁怀疑，读者从哪一段起怀疑、知道；
   - 读者现在知道什么：最新一章末尾读者的程度不是 `unaware` 的知识点；
   - 改揭晓章的依赖：对知识点 K，哪些计划带指向 K 的揭示、哪些悬念以 K 为答案（连同它们的节点）、哪些决策挂在 K 上（含读者守卫）、哪些章的写作指示快照的文字里出现了 K 的名字。
10. **费用的记录。** 一次检查记下模型调用的次数（窄问题、固定的一次、试读、判一致）与用量，回执读这一份。

## 状态与转换

| 检查记录 | 怎样进入 | 诊断 |
|---|---|---|
| 没有 | 本章没跑过检查 | 不报本 Spec 的诊断 |
| 有效 | 跑完一次，正文摘要与当前正文相同 | 按输出 8 报 |
| 过期 | 本章正文变了 | 只报 `plot.check.stale` |

- 一次检查用开始时的世界版本与正文；检查进行中世界或正文变了，记录照存，按输出 7 判过期。

## 副作用与数据

- 检查记录存在插件的项目记录里；同一章只留最新一条。模型调用的输入输出不另存。

## 失败与恢复

| 码 | 含义 | 调用方怎么办 |
|---|---|---|
| `plot-check-unavailable` | 宿主没提供记账 Agent 或试读模型的调用 | 配好模型角色后再跑 |
| `plot-check-failed` | 模型调用失败或答案的结构不对，这次检查没有存 | 重跑；多次失败看模型角色的配置 |
| 输出 8 的各项 | 待处理与提示 | 改正文或记录，或标“有意为之” |

## 边界与兼容

- 公开接口：“对第 N 章跑一次检查”的入口与它的结果、检查记录的形状（插件的项目记录，带版本）、诊断的 id 与键、账本视图的结果形状。
- 检查记录的形状变了时升版本；旧版本的记录不读，按“没有”处理。
- 插件停用时，检查记录照常存着，诊断不可用（[`canon.model`](../canon/model.md) 输出 34）。

## 验收与 Smoke

1. **卫兵认出勇者。** 第 4 章卫兵（对“勇者左手有星形的疤”没有知情）在场，正文里卫兵盯着旅人的左手说“你是勇者吧”：在场层问到，答“有”并引原句，进一条 `plot.check.possibleSlip`。正文改成卫兵只是例行盘问：重跑以后消失；改了正文没重跑时，只有 `plot.check.stale`。
2. **试读与泄底。** 悬念“谁杀了男爵”以“管家是凶手”为答案，揭示计划在第 20 章。第 12 章写了管家擦拭沾血的手套：试读拿到悬念的全部节点（含指向园丁的误导）与第 11、12 章全文，题面是“谁杀了男爵”，材料里没有答案的命题；它答“管家，强烈倾向”，判一致，进一条 `plot.check.earlyReveal`，附上第 20 章之前的读者守卫。
3. **预算。** 第 7 章有 25 个候选：问 20 个，按价值排，其余 5 个记“未问：5 条”；固定的一次调用照跑。
4. **新事实。** 正文里小梅说“十一点在桥头见”，而世界里没有这个约定、自陈里也没写：`plot.check.unrecordedKnowing`；写手的自陈里写了这一条时，不报。
5. **引文对不上。** 一个答案引的原句不在正文里：按“看不出”处理，提示 `plot.check.badQuote`。

Smoke：不适用——由剧情插件的包测试（记账 Agent 与试读模型用按合同对过的替身）与真实模型的评测覆盖。
