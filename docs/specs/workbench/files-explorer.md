# 文件资源管理器

## 目标与非目标

随 [ui.workbench-layout](../ui/workbench-layout.md)（planned）：`data-editor-group` 改放在编辑组内容项的根上，文件拖到编辑组的行为不变。切换之前下文仍是现行合同。

在 NeuroBook 主页面左侧提供基础文件管理，按文件夹类型呈现（普通文件夹、内容文件夹、活页夹，见 [workspace.folder-kinds](../workspace/folder-kinds.md)），显示项目与用户资产两个根。支持浏览、新建、打开、重命名、删除、拖动移动、多选及复制/剪切/粘贴；打开后进入真实编辑与保存链，而不止展示文件树。用起来要和本地 IDE 一样流畅，见[打开与切换](#打开与切换)的性能标准。

2026-09-26 开发者确认首版意图，并以“可以，就这么做，收口”批准 [Files 与资源管理器首版设计](../../../packages/neuro-book-legacy/docs/proposals/files-explorer.md#决策记录)中的 F1–F9。本文固定面板展示、交互、确认与反馈；实际文件写入、服务端校验和逐项结果归 [workspace.files](../workspace/files.md)。2026-10-02 开发者接受 [项目文件底座与 Files 竖切](../../proposals/project-file-foundation.md)：全局的普通/内容节点双模式由文件夹类型取代，新增用户资产根、按需加载、乐观切换与性能标准。

非目标：角色/世界书等领域模板、明细和专用操作，两个独立并排文件树，第二套内容组织数据，Git、全文搜索、远程文件系统提供者、外部插件安装/公开 SDK/动态 API/沙箱/热卸载。首版不含回收站或文件操作全局撤销；Lab 仅作辅助验证，不能替代主页面真实链路。

已知限制：跨机器访问的基础操作（浏览、新建、重命名、删除、拖动、复制/剪切/粘贴）尚未在隔离的第二宿主上验证，当前验证只在本机完成；排他改名等底层文件原语在非 Windows 平台上的验证状态见 [workspace.files](../workspace/files.md) 的已知限制。

## 术语与参与者

- **文件夹类型呈现**：普通文件夹显示真实文件名，`index.md` 是普通文件项；内容文件夹中的子目录是内容节点，隐藏其 `index.md` 文件行，由节点行打开对应正文，展示名与顺序来自清单；活页夹由剧情插件呈现。
- **根**：项目根（`project://`，标题是作品的显示名：书名，没有时是目录原名，[`runtime.projects`](../runtime/projects.md)；没有绑定项目时为“项目”）与用户资产根（`user://`，标题“用户资产”，默认折叠）。
- **节点行**：可选择的 UI 呈现，不是第二份文件数据或文档身份。
- **选择/焦点**：资源操作的目标集合与当前键盘位置；不等于编辑器已打开的文档。
- **展开**：显示子项；**打开**：请求编辑器显示资源正文；**创建内容**：明确请求创建目录的 `index.md`。
- **面板宿主**：提供 Files 客户端、文档打开、命令、状态记录、确认/反馈与环境能力的工作台。
- **资源管理器**：这些能力的消费者；不持有文件、正文或共享 Project 的最终所有权。

## 输入与前置条件

- 主页面具备有效项目绑定和可用 [workspace.files](../workspace/files.md) 接口，面板从明确依赖取得文件状态，不从组件内隐式创建产品会话。
- 用户可通过界面切换是否显示清单文件、选择一项或多项资源并发起操作；文件目标使用真实资源标识，不以显示标题定位文件。
- 打开正文需要文档/编辑器能力，文件操作需要相应授权；失败或能力不可用必须可见，不伪造成功。
- 读取失败、没有打开项目、空目录不是同一前置状态；不能拿旧项目残留树作为新项目的有效数据。

## 输出与可观察行为

### 文件夹类型呈现

| 行为 | 普通文件夹 | 内容文件夹 |
|---|---|---|
| 子项标签 | 真实文件名，不读 frontmatter | 清单中的展示名，缺省真实名字；路径保持可辨。改展示名只改清单，不改路径或文件字节 |
| 顺序 | 目录在前，按名字排序（[workspace.folder-kinds](../workspace/folder-kinds.md)） | 清单顺序；未列入项按名字排序排在末尾，缺失条目标出 |
| `index.md` | 正常显示，可作为文件打开 | 子目录节点不单列 `index.md`，点节点打开其正文 |
| 子目录 | 仅作为文件夹展开/收起，不解释成正文 | 既可展开，也可打开已有 `index.md`；节点行的资源操作作用整个目录 |
| 没有 `index.md` 的节点 | 不适用 | 可展开但无正文；提供明确“创建内容”动作，不把缺失当读取错误，不自动写文件 |
| 拖动排序 | 不适用（按名字排序） | 只改清单顺序，不移动、不改名文件 |

- 活页夹由剧情插件注册的渲染者呈现；剧情插件未启用时按普通文件夹显示并提示。
- 清单文件（`content.xml`、`binder.xml`）默认隐藏，可在视图的标题动作里切换显示；切换显示只改变呈现，不修改磁盘、正文与 dirty，选择与展开保留。
- 根行可展开、新建子项；根本身不可在本面板重命名、移动、删除。用户资产根默认折叠，Agent 对它默认只读（见 [workspace.resources](../workspace/resources.md)）。
- 打开项目只列出根目录（与上次展开的路径），展开目录时才列出该目录，遇到内容文件夹或活页夹读一次清单；大目录的列表虚拟滚动；已展开部分由文件监视增量更新。

### 基础文件操作

- 新建文件/文件夹、重命名、移动和删除通过同一 Files 能力操作实际资源；菜单与拖动移动同义，展示过滤不改变服务端授权。
- 支持多选并对明确集合操作：Ctrl/Meta 切换选择，Shift 选择当前可见行连续范围，修饰选择不打开；右键已选行保留集合、未选行先单选。树内 Ctrl/Meta+A 只选可见资源，不把被隐藏的正文自动纳入单独选择。
- 箭头仅展开/收起；普通文件夹的目录行单击切展开，内容文件夹中无正文的节点行只选择。普通文件和有正文入口的节点行无修饰单击 preview、双击/Enter permanent；节点行的展开控件与打开区域分开。上下键移动焦点，左右键处理目录层级，Space 切换选择；输入框/编辑器有焦点时树不劫持键位。右键根仅呈现合法根级动作。
- 目录行的重命名、复制、移动、删除作用整个目录（含隐藏正文及附件），“打开”仅打开其 `index.md`；创建内容只在缺失时排他创建空 Markdown `index.md`，已有时冲突，不生成领域模板。在内容文件夹内，这些操作同步更新清单；修改展示名只改清单，文件↔目录转换不是路径改名的隐式副作用。
- 剪贴板只在当前窗口同一有效项目绑定内保存资源引用与复制/剪切意图，不存文件字节，不与系统文件剪贴板互通。复制可重复粘贴；剪切粘贴每成功一个源才从意图中移除该源，失败源保留；Escape 清除剪切标记，项目换代清空旧引用。Ctrl/Meta+C/X/V 仅在文件树聚焦时操作文件，不抢编辑器或输入框的正文剪贴板；源消失或身份变化时拒绝旧意图。
- 粘贴目标固定：右键目录用该目录，选中文件用其父目录，无选择用当前根；多个候选目录不猜测，先明确目标。用户确认前显示实际源与目标；父子同时选中只取最外层，重复源去重，同目标移动无操作，移动到自身后代拒绝。
- 碰撞时不自动覆盖或合并：对同名文件/目录选择改名、跳过或取消；同目录复制也须显式改名，可提示候选名但提交仍排他重验。操作结果反馈逐项成功、失败、跳过、未执行或未知及目录复制残留范围；部分成功不报整批完成。
- 文件操作不以乐观树更新等同于写盘成功。普通单项错误后继续独立项，授权/绑定失效后停止；取消不回滚已完成项，未知先核对实际文件再重试，不盲目重复已成功项。
- 本面板不再贡献角色、世界书等领域专用模板/明细/动作；这些已有文件仍可作为普通资源浏览和访问，不能因隐藏领域 UI 而删除或改写数据。

### 新应用的插件、命令与界面

本节是新应用里资源管理器的接入方式与细化规则；上文的呈现与操作规则不变。

**插件与视图**：资源管理器是浏览器插件 `nbook.explorer`，只消费 `nbook.files` 的客户端；视图 id `nbook.explorer`，在侧栏，`layout: "fill"`（视图自己滚动）。入口在视图第一次挂上时建一个控制器，它活到入口停止：视图停放、移动、渲染重试只解绑再绑定，树、选择、剪贴板与进行中的操作不随视图实例消失。

**标题动作**：新建文件、新建文件夹、刷新、全部收起、显示清单文件五个按钮是视图声明的标题动作（[workbench.views](views.md) 输出 10），由外壳画在标题行里；视图自己不画工具栏。“显示清单文件”读公开键 `nbook.explorer/showManifests` 作按下态，“刷新”带本视图实例的 `{viewId, generation}`。

**行的样子**：选中不描边，按树有没有焦点分两种：焦点在树里时用强调色浅底与强调色文字；焦点不在树里（例如在编辑区）时用灰底与普通字色，灰底比悬停深一档。关掉编辑器里的文件不清除选中，焦点在编辑区时那一项是灰底。悬停与选中的底色是圆角块，左右各离视图边 6px。键盘焦点所在的行画 1.5px 的内嵌焦点线，只在树是键盘带来的焦点时画（鼠标点行不画）。展开与收起时新出现的行从上方滑下一行高并淡入、下面的行随之移动，收起反向，时长取主题的 `--motion-base`；滚动时窗口两端进出的行不动画；系统减少动画时不动。以下几条是 2026-10-14 的修订：

- **图标**：文件按扩展名、目录按种类（普通文件夹、内容文件夹、活页夹，展开与收起各一个）与少数常见目录名用 [catppuccin](https://github.com/catppuccin/vscode-icons) 的彩色图标（MIT）；节点行有正文用 Markdown 图标，没有用内容文件夹图标。亮色取 catppuccin 的 Latte 配色，暗色取 Macchiato，随明暗切换即时变。根行用自己的图标规则（见“根”）。
- **根**：根行是分节标题：比资源行小一号、加粗、弱化色、不缩进、没有图标，仍是树里的一行（键盘、选择与右键照常）。
- **类型后缀**：内容文件夹与活页夹自己的行显示去掉 `.content`、`.binder` 后缀的名字，后缀作淡色副标题（与节点“展示名 + 真实名字”同一写法）；改名框里是完整名字。
- **状态挂在行上**：目录的状态不单独占一行。正在列出：展开箭头换成转圈；读取失败：名字用危险色、行尾一个错误标记，点标记或执行 `nbook.files.retry-list` 重新列出；清单不合法：名字用警告色、行尾一个警告标记，子项照常按普通文件夹显示；空目录：展开后什么也不显示。原因经悬停提示与行的可访问描述给出。
- **状态图标**：无正文、缺失、未列入、需要剧情插件、剪切中是行尾弱化色的小图标，悬停显示文字，可访问描述里有同样的文字；缺失与剪切中的行仍淡化。几个同时出现时并排。真实名字的副标题仍是文字。
- **叶子节点**：列出结果标为叶子的节点（[workspace.folder-kinds](../workspace/folder-kinds.md) 的“正文入口”）没有展开控件、不能展开，点它只选择或打开正文。空的普通文件夹仍可展开。
- **缩进参考线**：每层一条竖线，对齐上级展开箭头的中线；焦点行（没有焦点时取第一个选中行）所在那一段同层兄弟的线加深。设置 `nbook.explorer/indentGuides` 三档：`none` 不画；`hover`（缺省）在鼠标位于树上或树有焦点时画；`always` 一直画。
- **内联输入**：新建与改名时这一行铺选中底色，输入框收在行里：比行矮 4px、与行块同一套圆角、1px 焦点色描边，没有外扩的光环与投影。名字不合法或同名时，输入框描边换成危险色，原因是贴在输入框下沿、左右与它对齐的一条浅危险色底提示（2026-10-14 修订）。
- **滚动条**：树的滚动条是叠在行上的悬停滚动条，规则见 [workbench.views](views.md) 输出 12。
- **隐藏 Markdown 扩展名**：设置 `nbook.explorer/hideMarkdownExtension`（缺省关）打开时，`.md` 文件的行不显示 `.md`（清单给了展示名的照旧显示展示名）；改名框里仍是完整名字，悬停提示仍是完整路径。两个设置项在设置的“资源管理器”分节，改了即时生效。

**打开作品时揭示活动文件**：绑定项目的窗口里，资源管理器与编辑器区都建好后，读那一刻编辑器的活动标签（公开键 `nbook.editor/ready`、`nbook.editor/activeDocument`，继续写作打开的文件也算）：展开它所在的各级目录，列出后选中它、焦点行给它，树滚到它可见，不移动页面焦点。只做这一次：那一刻没有活动标签就不做，之后切换标签也不跟着揭示（免得树跟着乱跳）；行出现之前用户自己选了别的行，揭示作废。

**命令**：资源管理器的具名动作都是命令，标题动作、右键菜单项与树内按键只执行命令 id；焦点移动、展开收起与范围选择是高频交互，不进命令。

| 命令 | `effect` | 树内按键 |
|---|---|---|
| `nbook.files.new-file`、`nbook.files.new-folder` | write | — |
| `nbook.files.collapse-all` | read | — |
| `nbook.files.toggle-manifests` | write（只写显示偏好） | — |
| `nbook.files.rename` | write | F2 |
| `nbook.files.delete` | write，`destructive` | Delete |
| `nbook.files.copy`、`nbook.files.cut` | read | Ctrl/Meta+C、Ctrl/Meta+X |
| `nbook.files.paste` | write | Ctrl/Meta+V |
| `nbook.files.move-up`、`nbook.files.move-down` | write | Alt+↑、Alt+↓ |
| `nbook.files.create-content`、`nbook.files.convert`、`nbook.files.set-display`、`nbook.files.include`、`nbook.files.drop-entry` | write | — |
| `nbook.files.clear-cut` | read | Escape |
| `nbook.files.reveal` | read | — |
| `nbook.files.open`、`nbook.files.open-to-side` | read | Enter、Ctrl/Meta+Enter |
| `nbook.files.copy-path`、`nbook.files.copy-relative-path` | read | — |
| `nbook.files.retry-list` | read | — |
| `nbook.view.refresh-files`（[命令目录](commands.md#命令目录第二批--外壳与-view-标题)） | read | — |

- 除 `refresh-files` 与 `reveal` 外参数一律为 `{}`，作用于本窗口资源管理器的选择；Agent 暴露一律 `never`。`refresh-files` 由标题动作带本实例的视图 id 与代次调用。`reveal {address, expand?}` 按“打开作品时揭示活动文件”同一套揭示地址，`expand` 时连它自己一起展开；Agent `auto`，不进命令面板，欢迎页的快捷入口用它（[workbench.bookshelf](bookshelf.md) 输出 19）。
- 树内按键由树在自己的列表元素拥有焦点时处理，执行同一条命令；命令声明里不写键位：宿主的键位分发是全局的，树没有焦点时 Delete 不能删文件，而右键菜单执行命令时焦点在菜单上。内联输入、对话框与编辑器有焦点时树不处理这些键。
- `when` 读 `nbook.explorer` 的公开布尔键：`ready`（控制器已建、偏好首读完成）、`canCreate`、`hasSelection`、`canPaste`、`canReorder`、`canCreateContent`、`canConvert`、`canEditManifest`。`when` 只说明有没有可作用的选择，执行时再按选择核对，不合格返回 `unavailable` 与原因；从命令面板执行时作用于当前选择，不要求树有焦点。
- 没有控制器时命令为 `unavailable`（资源管理器尚未打开）；需要界面输入的命令（新建、改名、展示名、带碰撞的粘贴、删除）还要求视图已挂上且可见。内联输入与确认框的状态在控制器里：视图停放或重建后在新的实例里接着显示，提交的仍是发起时冻结的对象。
- `open` 以常驻方式打开能打开的选中项（文件与有正文的节点），`open-to-side` 带 `group: "side"`（[workbench.editor](editor.md) 输出 35）；目录行没有这两项。`copy-path` 把选中项在服务端机器上的绝对路径（Files 的 `realPath`）、`copy-relative-path` 把相对所在根的路径写进系统剪贴板，多项按树里的顺序每行一个。`retry-list` 重新列出焦点所在的读取失败的目录。
- **右键菜单**：先是资源管理器自己的固定动作，按被右键的那一行与此刻的可用性给出；之后是别的插件经贡献点 `explorer.context` 贡献的菜单项（共同规则见 [`workbench.menus`](menus.md)），与固定动作之间画一条分隔线。贡献项的当前文件是这次右键作用的选择（右键已选行时是整个选择、未选行时是这一行，同上面的选择规则），`context: "selection"` 的项执行时收到 `{addresses}`（这些资源的地址，按树里的顺序）。根行只有合法的根级动作，没有贡献项。

**当前根与目标**：当前根取焦点行的方案（焦点在根行上时取该根），没有焦点时取第一个可用的根。新建与无选择的粘贴以选中的目录、选中文件的父目录或当前根为目标（叶子节点不能展开，按选中文件算，目标是它所在的文件夹；要往叶子节点里放东西就拖进去）；选中多项时不猜，动作不可用。内容文件夹里新建的项插到选中项之前。

**内容文件夹的呈现条件**：一层目录按内容文件夹呈现，条件是它的列出结果带内容根且清单状态为 `ok`；不只看目录自身的文件夹类型（内容树里的子目录也是普通目录类型）。清单不是 `ok` 时按普通目录显示真实名称、`index.md` 成行、点击只展开，清单错误挂在这一层的目录行上（见“行的样子”的“状态挂在行上”；清单缺失不提示）。活页夹按普通目录显示并带“需要剧情插件”状态图标，其 `binder.xml` 按普通文件显示。

**增量刷新的依赖**：一条事件要重列哪些已加载或正在列出的目录：

- 普通变化：事件路径的父目录；改名取新旧父目录。
- 清单 `content.xml`：同一内容根下的所有目录（嵌套层的标题、顺序、缺失与未列入都来自这份清单）。
- 节点正文 `index.md` 的增删与替换：节点目录本身，以及列出该节点的上一层（有无正文在上一层算出）。
- 目录改名、删除、类型转换：作废它与子树的缓存和在途列出，迟到的旧结果丢弃；改名时展开、选择与焦点按段边界改写到新地址。
- 正在列出的目录被标脏时，结果到达后再列一次。

**剪贴板与冻结的意图**：粘贴、拖动与删除先冻结为一份意图（逐项的源地址与身份令牌、实际目标），批量结果按意图里的下标结算；之后的选择、刷新与地址改写都不影响结算。剪贴板与已冻结的意图**不跟随改名改写地址**：源被改名或移走后旧意图失效，粘贴得到“源已被替换或移走”，用户重新复制。剪切粘贴按意图逐项从剪贴板移除成功的源；剪贴板在此期间被换掉时，迟到的结果不动新剪贴板。

**结果未知**：批量结果未知时，在用户明确“放弃”之前，复制、剪切、粘贴、拖动与删除都不可用；“重新列出”只核对，不解除。放弃时说明不会取消可能仍在后台执行的操作，并清掉这份意图与它的剪贴板。单项新建与改名照常。

**拖动**：激活门槛与外壳一致（鼠标与笔 6 px、触摸按住 200 ms，超过容差先让给滚动）。激活时冻结源并取得身份令牌，令牌未齐不能提交；落点按地址与同层前后项表达。放下时重新判定，只提交与最后显示相同的动作。手势按 [ui.layout-drag](../ui/layout-drag.md)：Escape、指针取消、失去捕获、窗口失焦、页面隐藏、焦点移到树之外、视图卸载、切换显示清单文件、源或落点失效都取消且不写，已提交的批量不因此改目标；拖动中方向键等归拖动，树不响应。内容文件夹的排序另有“上移 / 下移”，与拖动排序同一变换，多选时整体移动一位并保持相对顺序。以下几条是 2026-10-14 的修订：

- **落点**：目录行（含根、叶子节点与收起的目录）中段移入该目录；其余位置都是两行之间的缝。缝在上一行 A 与下一行 B 之间：A 是展开且有子行的目录时，缝只属于一层（A 的第一个子项之前）；否则可属于从 B 的层（没有 B 时为第 1 层）到 A 的层之间的任一层，按指针相对行左边的横向位置选（指针在名字上时取最深的一层，往左移变浅），不能到根这一层；层 d 的接收目录是 A 在第 d-1 层的祖先，位置是“A 在第 d 层的祖先之后”。接收目录在内容树里时：源都在这一层就调整顺序（只改清单），否则移动并放到这个位置（[workspace.files](../workspace/files.md) 的“移动到指定位置”，多选按树里的先后连成一串）；在内容树里移入目录放在最后。接收目录是普通文件夹时移入它（按名字排序，没有位置）。树里最后一行之下的空白移入项目根（源都在用户资产根时移入用户资产根）。源已都在目标文件夹里（移入时）、落在自己或后代上时没有落点。
- **反馈**：反馈画在树里，跟着行滚动，左右与行对齐。调整顺序与放到某个位置：2 px 强调色实线压在缝的正中，起点缩进到落点那一层，左端一个空心圆；接收目录的整段（目录行到最后一个展开的子孙行）铺很浅的底。移入：目标目录的整段铺浅底、目录行再深一档，不描边、不画插入线。说明动作的标签（“放到 X 之后”“放到 X 之前”，换了接收目录时加“移入 P”；“移入 P”，内容树里加“放在最后”）写在拖影里；拖影的左上角在指针右侧 12 px、下方 4 px，写被拖的名字，多项时写“N 项”。被拖的行淡化图标与文字，缩进参考线不淡。
- **停留展开**：指针停在收起的目录行中段 600 毫秒自动展开；移开或落点换了重新计时。
- **边缘滚动**：指针进入树上下边缘 24 px 内时逐帧滚动，越靠边越快；滚动后按新位置重新判定落点（同上，指针没动而行变了先撤下落点）。滚动中松手时放下生效，落到松手时指针下的位置。
- **拖到编辑区**：指针在编辑组（经落点登记查到，[workbench.editor](editor.md) 输出 35）上时，落点是“在这一组打开”，编辑组画整块浅底；放下时对源里能打开的项依次执行 `nbook.editor.open {address, mode: "permanent", group}`，目录跳过，最多 10 项（多出的不打开，标签说明）。这不是文件操作，放下时不用拿起时冻结的身份令牌；起拖的条件照常（结果未知期间不能起拖）。
- **动画**：时长取主题的 `--motion-fast` 与 `--motion-base`，系统减少动态效果时为 0、不放；只对渲染着的行做。放下后（移动、放到某个位置、调整顺序）被拖的行从原位置滑到新位置并短暂亮一下，其余行让位；新位置所在目录收起而看不见时，最近的可见上级目录行闪一下。粘贴与新建的行从上方滑入并短暂亮一下，删除的行收起淡出，其余行让位。取消（Escape、指针取消、放在没有落点处）时拖影回到第一个源行再淡出。停留展开计时中，目录行的箭头在 600 毫秒里匀速转到朝下，计时取消时转回。起拖时拖影从略小放大并淡入，源行渐淡。动画只跟着本窗口提交的操作出现：提交后一秒内的刷新里认不出对应的行就不放，其它原因的刷新（外部改动、别的窗口）没有动画。

**焦点**：对话框关闭后，取消回原焦点行；删除成功到下一个存活的同层项，没有则上一个，再没有则父目录或根。内联编辑 Enter 提交、Escape 取消、输入法组字中的 Enter 不提交，完成后焦点回树。焦点行被折叠、删除或隐藏时回最近的存活祖先。Shift+F10 与 ContextMenu 键在焦点行打开右键菜单，菜单支持方向键、Home/End 与 Enter/Space。虚拟列表里焦点行与正在编辑的行即使滚出视口也保持挂载；行带完整同层集合的位置与总数。

**打开**：执行 `nbook.editor.open {address, mode}`，单击 `preview`，双击与 Enter `permanent`；命令未登记时显示“编辑器尚未接入”，不伪装成功。

**未保存的文档**：复制、移动、拖动、改名与删除前经编辑器的文档协调服务结算，行为见 [workbench.editor](editor.md) 输出 23–25：复制在冻结源之前三选；移动类取租约、冻结的源身份经 `translate` 换成本窗口保存后的身份；删除确认列出将丢失的修改。编辑器没有加载时直接放行。

**持久化**：记录归 `nbook.explorer`。“显示清单文件”`explorer.preferences`（user/local，`{showManifests}`，缺失为隐藏）；项目树的展开 `explorer.expanded`（project/local，`{paths}`），用户资产树的展开 `explorer.user-expanded`（user/local，同形，没打开项目也保存）；每份最多 2000 条，按分支淘汰（连同记录里的后代）。展开记录里的路径在父目录列出、确认不存在时才删。首读完成前不挂树；首读失败时照常浏览、给“重新读取”，坏记录与不认识的版本不覆盖。保存暂停时视图给“展开与显示偏好未保存”，带重试与放弃（放弃后显示回落到已保存的值）。

### 文档与体验

打开映射到唯一真实文档入口；从节点行与从文件行打开同一 `index.md` 不产生互不一致的正文。选择变化、树刷新或切换显示不丢未保存内容。编辑组、标签、dirty、冲突和保存归 [workbench.editor](editor.md)，不由面板自行维护第二套副本。复制 dirty 文件时让用户选“先保存再复制”“复制已保存的磁盘版本”或“取消”，绝不暗中复制未保存输入或误称副本含最新正文。移动前结算当前输入并等待相关在途保存；成功后保留未保存正文、按实际目标重绑定文档身份，失败不得把旧正文误标新路径。删除前列出受影响范围与不可恢复风险，dirty/未决冲突须明确结算，默认取消；编辑器 Ctrl+Z 不代表文件可恢复。

### 打开与切换

- 点击文件后，资源管理器选中状态与标签页在下一帧切换，不等正文；编辑区先保持空白，800 毫秒内不显示任何加载提示，超过 800 毫秒仍未就绪才显示顶部进度条（正常打开在此之前完成，提前显示只会闪一下）；不保留旧文件正文，避免输入落到旧文件。
- 打开成功以正确正文可编辑为完成点；选中与标签先切换只是反馈，不能代替打开成功，失败时在编辑区显示原因。
- 同组同类编辑器复用控件，文档模型按打开引用保留（沿[首版切换设计](../../../packages/neuro-book-legacy/docs/proposals/files-explorer.md#切换性能分开文件模型和控件的寿命)）；外部修改经变更事件同步到已打开的编辑器。预读留扩展口，策略在实际体验后另定。

性能标准（生产构建，参考机器上的本机浏览器，约 3000 个 Markdown 文件、3–5 层目录、单章 5–30 KB）。参考机器为 Intel Core i5-1035G1（4 核 8 线程，基础频率 1.0 GHz）、16 GB 内存，选较慢的机器以暴露性能问题；桌面版加载同一本机服务页面，不单独测：

| 场景 | 标准 |
|---|---|
| 打开项目 | 1 秒内看到可操作的文件树；第二次打开（关闭页面后、项目宽限期内再打开）约 400 毫秒 |
| 点击文件 | 选中状态与标签页 16 毫秒内切换 |
| 正文出现 | 已打开过的文件 100 毫秒内；未打开过的普通章节 200 毫秒内 |
| 展开目录 | 几百个子项不卡，滚动流畅 |
| 任何时候 | 界面不被后台扫描、解析或同步冻住 |

跨机器访问仍可完成相同基础链路，但上述毫秒标准只针对本机。

## 状态与转换

| 状态/事件 | 可观察结果 |
|---|---|
| 未打开项目 | 说明尚无工作区，不显示假空项目或发起文件写入 |
| 初次加载 | 根目录列出即可操作；正在列出的目录在自己的行上显示转圈；读取错误挂在目录行上，与真正的空目录（展开后没有行）分开 |
| 就绪 → 切换显示清单文件 | 只改变树投影；原打开文档与 dirty 不受影响 |
| 就绪 → 打开资源 | 选中与标签当帧切换，编辑区等待正确文档就绪或显示失败；迟到结果不能抢占新的打开意图 |
| 无正文目录 → 展开/尝试打开 | 可浏览子项、说明无正文，磁盘不变 |
| 无正文目录 → 明确创建内容 | 排他创建空白 Markdown `index.md`，成功后可打开；已存在返回冲突，失败不显示虚假正文 |
| 已选择 → 文件操作中 | 操作保留明确源/目标与反馈；随后改变选择不能改写已发起操作目标 |
| 批量完成/部分完成/失败或未知 | 逐项反馈实际结果、目录复制残留和未执行项；未知先核对磁盘，不以一个成功项代替整批成功 |
| Project 失效/切换 | 撤销旧目标资格并清理本窗口文件剪贴板；旧树、意图或迟到回调不能改投新项目 |
| View 移动/关闭 | 沿工作台实例合同；关闭释放自己的依赖与监听，不关闭共享 Project 或其它窗口 |

读取、浏览、展开与切换显示无业务写入副作用。复制/移动等不是仅凭相同界面动作就能安全重放的幂等操作。

## 副作用与数据

- 文件副作用归 [workspace.files](../workspace/files.md)，正文与磁盘基线归文档域，视图展开与显示偏好归既有 [Storage 边界](../storage/boundaries.md)。不把正文或文件复制进 UI 偏好。
- 呈现不创建另一套目录关系或内容节点数据库；内容文件夹的编排只写在其清单里（[workspace.folder-kinds](../workspace/folder-kinds.md)），不为呈现执行数据迁移。
- 新应用并排重建，不迁移旧应用的视图与状态记录（[插件的数据与状态](../../proposals/plugin-data-model.md)）；原普通/内容节点模式偏好退役。“显示清单文件”与展开的记录见[新应用的插件、命令与界面](#新应用的插件命令与界面)。偏好不存正文、选中资源副本或剪贴板跨窗口数据。
- 产品组件消费明确客户端能力，不直接持有网络协议、后端文件系统或默认全局产品 store；主页面提供真实依赖，Lab 只替换受控接缝。
- 面板离开释放自己的事件、快捷键与句柄；数据和文档持久寿命不跟随面板销毁。

## 失败与恢复

- 无权限、只读、路径失效、读取失败、空目录有不同含义；不给用户造成“失败等于文件消失”的假象。
- 打开失败不能把旧正文改标成新文件，不能用空白编辑器冒充打开成功；快速连续打开的旧结果不得覆盖当前目标。
- 操作失败或结果未知必须可见；不能盲目重试可能已经发生的移动/复制/删除，也不能仅恢复旧树就声称磁盘已回滚。
- dirty、保存冲突和在途输入由文档 owner 协调；复制先选磁盘基线/先保存/取消，移动确认真实重绑定，删除默认取消且不静默丢弃未保存内容。
- 呈现与切换显示不触发数据修复；清单不合法时按 [workspace.folder-kinds](../workspace/folder-kinds.md) 退回普通显示并提示。创建正文遇到失败时保留目录与已有文件，不因 UI 状态补写或覆盖内容；内容格式诊断不自动等同写入禁止，服务端路径/权限保护不放宽。
- 不承诺回收站、跨文件事务或文件操作撤销；不能将编辑器撤销命令用于暗示已删除文件可恢复。

## 边界与兼容

- 文件数据与访问合同归 `workspace.files`，文件夹类型与清单归 `workspace.folder-kinds`；本能力只拥有用户呈现、操作发起与反馈。
- 文档/编辑器继续拥有打开、输入和保存；[工作台外壳](../ui/workbench-shell.md)拥有布局/实例，[命令系统](commands.md)拥有统一分发与执行策略，本能力不复制这些合同。
- 内容格式继续引用 [Content Reference](../../../packages/neuro-book-legacy/assets/reference/content/README.md)；内容文件夹的持久格式是其清单，归 `workspace.folder-kinds`。
- 内置 Files/资源管理器通过显式接口接入主页面，经 [插件通道](../runtime/plugin-channel.md) 通信（迁移完成前沿用 HTTP 与 SSE），组件不绑定协议；以视图与命令贡献给 workbench，打开文件执行 `nbook.editor.open`；右键菜单的贡献点 `explorer.context` 见 [workbench.menus](menus.md)。不支持外部可执行插件安装和动态 API 注册不妨碍主页面真实使用。
- 领域功能移除仅限本资源管理器适配及其专用入口，不授权清理独立领域模块或用户数据。实现切换时同步真实组件文档与能力标签，不提前把文档目标写成当前实现。
- [Component Lab](../ui/component-lab.md)的无默认产品宿主/真实数据请求约束不变；同一组件在 Lab 可替换依赖不代表生产磁盘、鉴权、SSE 或性能验收已完成。

## 验收与 Smoke

浏览、操作、拖放、UI 细节、命令化、持久化与编辑器结算均已用真实内核、真实磁盘与真实 Chrome 验证；下列完整合同还要求跨机器基础操作，在未取得隔离第二宿主前仍是已知限制（见“目标与非目标”）。

1. 准备普通文件夹、带清单的 `*.content/`（展示名与真实名不同、含嵌套节点、缺少 `index.md` 的节点）与 `*.binder/`：普通文件夹显示真实名称与 `index.md`、不读任何文件内容；内容文件夹按清单显示展示名与顺序且始终能辨路径，隐藏节点的 `index.md` 并从节点行打开同一正文；剧情插件未启用时活页夹按普通文件夹显示并提示；根不提供改名/移动/删除，用户资产根默认折叠。
2. 普通文件夹的目录单击只展开；节点行拆分展开与打开区域，无正文节点行只选择，明确创建空白正文后可编辑保存，已有正文拒绝覆盖，浏览/展开不写磁盘。
3. 在树内用上下/左右、Space、Ctrl/Meta、Shift、Ctrl/Meta+A、单击 preview、双击/Enter permanent 和右键选择操作；仅可见资源入选，修饰选择不打开；编辑器/输入框聚焦时按键不被树拦截。
4. 缺失偏好时清单文件默认隐藏，切换显示后重新加载在同一 user/local 记录恢复；项目树与用户资产树的展开各自恢复。切换显示时可见资源选择与展开保留，未提交菜单/拖动取消，已提交目标不变；dirty 正文不受影响。在内容文件夹内拖动排序与修改展示名只改清单。
5. 同窗口同项目复制两个资源并重复粘贴；剪切逐成功项清除，失败项保留，Escape 清除标记；项目换代/源身份变化拒绝旧引用，另一窗口、系统剪贴板与正文快捷键不被文件树剪贴板挟持。
6. 右键目录、选中文件及无选择分别验证目标为目录、父目录、根；多目录歧义须显式选目标。父子重叠、重复源不重复操作，内容目录复制含隐藏正文与附件；自身后代移动拒绝，同目标移动无操作。
7. 对同名文件和目录选择改名/跳过/取消，确认同目录复制不能覆盖源，预检后目标被占用仍冲突；菜单与拖动的权限/冲突语义相同。
8. 目录复制中途失败可见残留范围，普通单项失败仍继续独立项，绑定/授权失效停止；取消不假回滚，在途结果未知先核对磁盘再重试，绝不将部分成功显示成全部完成。
9. dirty 文件复制分别选择先保存、磁盘版本和取消；在途保存期间移动继续输入后正文随成功目标重绑定、失败仍属原文档；删除 dirty/冲突目录时展示影响范围及不可恢复风险，默认取消，编辑器撤销不承诺恢复文件。
10. 分别验证未开项目、加载、空目录、读取错误、只读及绑定失效；旧结果不串到新项目，失败不会伪造成空树。
11. 移除面板中的角色/世界书适配后，原有相关文件和 frontmatter 字节不因启动/切换显示被删除或改写，基本文件与编辑链不依赖领域服务。
12. 在生产构建、参考机器的本机浏览器上，用约 3000 个文件的隔离项目逐项测[性能标准](#打开与切换)：打开项目到可操作、第二次打开、点击到选中切换、已打开与未打开文件的正文出现、展开几百个子项的目录；记录 p50/p95、请求数、模型/控件创建与资源保留。加载期间编辑区不显示旧正文，800 毫秒内不出现加载提示，超过 800 毫秒才出现进度条；后台工作期间界面不冻结。不能用 Lab 内存路径或单纯高亮代替证据。
13. Lab 用同一面板、客户端核心和控制逻辑验证三类文件夹呈现、错误与局部操作；不发产品 API 请求，切场景释放。主页面另证实实际磁盘、API 与事件同步，跨机器至少验证基础操作可用。
14. 资源管理器的具名动作都能从命令面板执行，菜单、标题动作、树内按键走同一命令；只用键盘完成创建内容、修改展示名、加入清单与上移下移；内联输入或编辑器聚焦时树内按键不触发；资源管理器未打开或未显示时需要输入的命令为 `unavailable`。
15. 批量结果未知后再按粘贴不发第二批，放弃后才恢复；剪贴板里的源被另一窗口改名后粘贴为“源已被替换或移走”；拖动中切换显示清单文件、滚动或源被替换后放下不写。
16. 展开记录超过上限时按分支淘汰；偏好首读失败时照常浏览并可重新读取；保存暂停时可见并能重试或放弃。
17. Given 打开过 `notes/b.md`、`notes/c.md`（活动的是 c）并收起了 `notes` 的窗口，When 刷新，Then `notes` 展开、c 被选中，b 没有选中；When 切到 b 的标签，Then 资源管理器的选择不变。行出现之前用户选了别的行时揭示作废。

## 实现合同

- 公开入口：浏览器插件 `nbook.explorer`（[`explorer/plugin.ts`](../../../packages/neuro-book/src/plugins/explorer/plugin.ts)、[`explorer/web/`](../../../packages/neuro-book/src/plugins/explorer/web/)）；命令表见 `explorer/web/commands.ts`；右键菜单贡献点 `explorer.context`、剪贴板与拖动模型、持久化记录 `explorer.preferences`/`explorer.expanded`/`explorer.user-expanded` 见 `explorer/shared/contracts.ts`。
- owner 与依赖方向：`files-view`（资源管理器呈现）依赖 `workspace-files`（`nbook.files` 客户端，[`workspace.files`](../workspace/files.md)）与 `nbook.editor` 的文档协调服务（可选依赖，[`workbench.editor`](editor.md)）；资源管理器不持有文件字节或磁盘基线，只持有树投影、选择与剪贴板意图。
- 不变量：
  - 剪贴板与冻结的拖动/粘贴意图不跟随改名改写地址，源被改名或移走后旧意图失效（`transfer.test.ts` 的“冻结的意图”）；
  - 批量结果未知时复制/剪切/粘贴/拖动/删除全部不可用，直到用户明确放弃（`transfer.test.ts` 的“验收 8、15：结果未知”）；
  - 内容文件夹内的新建、改名、拖动排序只改清单、不移动或改名文件（`actions.test.ts` 的“内容文件夹的动作只改清单或排他创建”）；
  - 控制器活到入口停止，视图停放/重建只解绑再绑定，不丢树、选择与进行中的操作（`view-host.ts` 的寿命规则，`browse.test.ts`）。
