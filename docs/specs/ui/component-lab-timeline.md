# Component Lab 时间线回放

## 目标与非目标

目标：让 fixture 为场景声明一条或多条时间线，由 Lab 提供统一的播放控件，按虚拟时间逐步改变组件输入，用来观察流式生成、运行状态切换、断线重连这类随时间变化的界面行为。任意时刻的界面只由“场景初始输入 + 时间线 + 播放位置”决定，因此可以复现、可以截图对比。

非目标：

- 不访问网络，不模拟服务端协议，不运行真实会话模型；时间线只改变 fixture 交给组件的输入。
- 不改变 [Component Lab](component-lab.md) 已有的场景、分层输入、事件记录与偏好合同。
- 不持久化播放位置。

## 术语与参与者

- **时间线**：一组按虚拟时间排列的步骤，属于某个场景，由 fixture 声明。
- **步骤**：`{at, label?, op, args}`。`at` 是相对时间线开头的虚拟毫秒数，`op` 是 fixture 定义的操作名，`args` 是可 JSON 化的参数。
- **归约函数**：fixture 提供的纯函数，输入当前状态和一个步骤，返回新状态。
- **时间线状态**：场景初始输入经过若干步骤归约后的结果，fixture 用它绑定组件。
- **播放位置**：当前虚拟时间 `t`。
- **虚拟时钟**：Lab 维护的 `t`，播放时按倍速推进，暂停时静止；fixture 可以把它作为“当前时间”传给组件。

## 输入与前置条件

- fixture 在场景登记中声明时间线：`id`、名称、步骤列表，以及该场景使用的归约函数。步骤列表是仓库内的固定数据，可以放在独立文件中。
- 步骤的 `at` 不递减；`op` 必须是该 fixture 归约函数支持的操作；`args` 必须能无损 JSON 往返。
- 归约函数必须是纯函数：不访问网络、存储、定时器或随机数，同样的输入总是得到同样的输出。
- 可选：fixture 可以声明“当组件发出某个事件时切换到另一条时间线并从头播放”，新时间线以触发时刻的时间线状态作为初始状态。
- Lab 页面地址可以带 `tl`（时间线 id）和 `at`（虚拟毫秒数），打开后直接定位到该位置并暂停，供自动化截图使用。

## 输出与可观察行为

- 场景声明了时间线时，画布下方的场景控制区显示时间线控件：时间线选择、播放与暂停、上一步、下一步、倍速（0.5×、1×、2×、4×）、带步骤刻度的进度条、重置；并显示“第 n / N 步 · 虚拟时间 · 当前步骤名称”。
- **定位规则**：播放位置为 `t` 时，时间线状态等于场景初始输入依次应用全部 `at ≤ t` 的步骤的结果，虚拟时钟为 `t`。
- 播放时虚拟时钟按倍速连续推进，每越过一个步骤就应用它；到达最后一步后自动暂停。
- 下一步：定位到下一个步骤的 `at`。上一步：定位到上一个步骤的 `at`（按定位规则从头重算）。拖动进度条：定位到拖到的时间。
- 数据 tab 的“内部状态”显示当前时间线状态（只读）与播放位置。
- 播放期间组件照常可交互，组件发出的事件照常进入事件日志。
- 切换场景、切换时间线、点击“还原输入”或在数据 tab 修改场景输入，都会重置到 `t = 0` 并暂停；修改输入后以新输入作为初始状态。

## 状态与转换

本能力不引入持久状态。播放状态只存在于当前页面。

| 当前 | 事件 | 结果 |
|---|---|---|
| 暂停 | 播放 | 播放，从当前 `t` 推进 |
| 播放 | 暂停，或到达最后一步 | 暂停 |
| 任意 | 上一步、下一步、拖动 | 暂停并定位 |
| 任意 | 重置、切换时间线、切换场景、还原输入、修改输入 | 暂停并定位到 `t = 0` |
| 任意 | 组件事件命中 fixture 声明的切换规则 | 切换到目标时间线，以当前状态为初始状态，从 `t = 0` 播放 |

## 副作用与数据

无副作用。时间线数据是仓库内的固定输入；播放位置、倍速与所选时间线不写入 Lab 偏好或任何浏览器存储。

## 失败与恢复

- 步骤的 `at` 递减、`op` 不受支持或 `args` 无法 JSON 往返：由 `fixtures/index.test.ts` 的登记门禁拦截；运行时遇到同样问题时，时间线控件显示错误并禁止播放，场景其余部分照常显示初始状态。
- 归约函数在第 k 步抛错：停在第 k − 1 步的状态并暂停，显示出错的步骤序号与错误信息。
- `tl` 或 `at` 参数无效：忽略该参数，按默认从 `t = 0` 暂停开始，并给出开发诊断。

## 边界与兼容

- 本能力属于 Component Lab，owner 与 [Component Lab 规范](component-lab.md)相同；fixture 的其他规则不变。
- 符合 Lab “固定输入、不访问网络、不伪造业务成功结果”的要求：时间线只重放仓库内的固定数据。
- 可分发产物不包含时间线控件与时间线数据，沿用 Lab 的产物排除机制。
- 服务端事件回放不在本规范内；等新的会话数据层存在后另行扩展。

## 验收与 Smoke

1. Given 一个声明了时间线的场景，When 打开该场景，Then 控制区显示时间线控件，位置为第 0 步并暂停。
2. Given 同一时间线，When 从头播放到第 k 步暂停，与直接拖动到第 k 步的 `at`，Then 两者的组件 DOM 与时间线状态完全一致。
3. Given 倍速 4×，When 播放，Then 虚拟时间的推进速度为 1× 的 4 倍，步骤按 `at` 顺序应用。
4. Given 播放中，When 切换场景或点击还原输入，Then 回到 `t = 0` 并暂停，事件日志按 Lab 既有规则清空。
5. Given 地址带 `tl=<id>&at=<毫秒>`，When 打开 Lab，Then 直接定位到该位置并暂停。
6. Given 一条 `at` 递减的时间线，When 运行 `fixtures/index.test.ts`，Then 登记门禁报出组件、场景与步骤序号。
7. Given 归约函数在第 k 步抛错，When 播放，Then 停在第 k − 1 步并显示错误。
8. Given fixture 声明了事件触发的时间线切换，When 组件发出该事件，Then 切换到目标时间线，并以当时的状态为初始状态开始播放。

Smoke：尚未实现。实现时扩展现有 `smoke:component-lab` 系列入口，覆盖第 2 条与第 5 条。
