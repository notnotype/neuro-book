# 工作台布局：一棵树

## 目标与非目标

除标题栏外，工作台是一棵布局树：工具视图和编辑组都是树上的面板，活动栏和状态栏是树上的条。骨架固定：`活动栏 | 侧栏 | 编辑区 | 右栏`，面板在编辑区下面（输出 1）。面板在骨架内换位置时，它的内容不重建，并从旧位置滑到新位置。工作台是这棵树的唯一写者，插件只提交意图。

侧栏、右栏、底部面板三个区域各一次显示一个视图容器：容器里的几个视图同时可见，各占一个分节，位置、大小、展开收起由容器记住；点入口切换的是整个容器，切走再切回来是原样（输出 40 到 47；输出 44 入口菜单里的“移到”除外）。

本 Spec 取代了 [ui.workbench-shell](workbench-shell.md) 的外壳一到三与输出 39。标题栏、状态栏的条目、无项目首页、活动栏底部条目、页面浮层与主题变量表（输出 38）留在那里。设计理由见[布局提案](../../proposals/workbench-single-tree-layout.md)与 [ADR 0044](../../adr/0044-workbench-single-layout-tree.md)；视图容器的见[视图容器提案](../../proposals/workbench-view-containers.md)与 [ADR 0046](../../adr/0046-workbench-view-containers.md)。

不承诺：

- **操作系统级窗口**：只有应用内浮动（输出 39）；拖出窗口也是应用内浮动，夹回树区域。
- **资源树拖出树外**：文件拖到编辑组的行为见 [workbench.files-explorer](../workbench/files-explorer.md)，这里不变。
- **手机呈现**：窄于 600 时只有这棵树，界面会很挤，放不下按输出 10 降级。
- **条移到四边**：条在树里，位置固定。
- **改变骨架**：面板移到编辑器旁边、工具视图夹在编辑组之间、编辑器标签拆到工具面板旁边、整块拖动面板，都没有入口（开发者 2026-11-06）。编辑器标签想离开编辑区用应用内浮动（输出 39）。
- **面板横跨左右侧栏**这类摆法没有拖动入口。
- **容器的其它形态**：容器里隐藏单个视图、容器嵌套容器、插件开新的入口条、编辑组进容器，都没有。浮动窗不是容器，浮动的单位仍是带标签的组。
- **活动栏隐藏时切换侧栏的容器**：没有界面入口，只能经命令（`nbook.view.open`，输出 35），是已知限制。

## 术语与参与者

```text
Workbench（每个窗口一个，nbook.workbench 拥有）
├─ TitleBar ──── 树外，固定在最上面
└─ LayoutDoc（布局文档）
   ├─ tree ───── 文档树：结构、id、ref、两轴尺寸意图
   ├─ panels ─── 面板 id → 角色、名字、标签、活动标签、隐藏、收起；分节的归属，锚上的入口顺序与当前容器
   └─ floats ─── 浮动的面板与矩形，后面的压在前面的上面
```

- **面板**：带标签的组，树的叶子。工具面板（`role: "tool"`）装工具视图，编辑组（`role: "editor"`）装编辑器标签。
- **具名面板**：名叫 `sidebar`、`auxiliarybar`、`panel` 的工具面板。面板 id 等于名字。标题栏开关、命令、视图与容器声明的 `location` 都认这个名字。它是所在区域的**锚**：没有标签，不属于任何容器；区域里有分节时不进呈现树，区域打开着、一个分节都没有时它就是这块空区域（输出 40、48）。
- **条**：活动栏、状态栏。固定厚度，不可调、不可收起。
- **骨架**：见输出 1。**侧栏这一列**是 `sidebar` 和与它上下分开的工具面板，**右栏这一列**同理；**面板这一排**是 `panel` 和与它左右分开的工具面板；**编辑区**是全部编辑组。
- **区域**：侧栏这一列、右栏这一列、面板这一排，名字是 `sidebar`、`auxiliarybar`、`panel`，正文里也叫侧栏、右栏、底部面板。一块面板属于哪个区域，看它和哪片锚同一列（底部面板是同一排）；编辑组与浮动窗不属于任何区域。区域的隐藏、拖到零、入口顺序、当前容器都记在锚的记录上。
- **分节**：区域里除锚以外的工具面板。恰有一个标签，属于一个容器（输出 40）。
- **容器**：一组一起显示、一起切走的分节，用 id 指认（输出 41）。区域此刻显示的那个是它的**当前容器**。
- **入口**：区域里一个有成员的容器在入口条上的一项。侧栏的入口条是活动栏上段（输出 22）。
- **文档树**：用户的布局，会保存。隐藏的面板也在里面；不在当前容器里的分节也在里面。
- **呈现树**：这一刻交给 grid 求解的树，由文档树和呈现事实算出，不保存。隐藏的、放不下被收走的面板不在里面；区域里有分节时，锚与不在当前容器里的分节也不在里面；区域打开着、一个分节都没有时，锚就是那块空面板（输出 48），它在里面。
- **呈现事实**：实测容器尺寸、最大化、焦点。可能让呈现和文档不同，不写回文档。
- **内容项**：一个视图或一个编辑器标签的内容（没有标签的编辑组也有一个，画空态），和叶外框是同一父元素的子元素，从建到销毁不换父元素（[ui.nested-grid](nested-grid.md) 输出 82）。
- **当前面板**：最近获得焦点的面板。焦点移到外壳之外时保持原值。焦点在右栏、底部面板的入口条里时，当前面板是头并在这一行里的那一节，没有并进来的就不变；在入口条里切了容器，焦点没动，当前面板跟着换。
- **活动编辑组**：工作台记着的 `currentEditor`；编辑器的“活动组”就是它。
- **有效可见**：见输出 17。

## 输入与前置条件

- 触发：打开或刷新窗口、容器尺寸变化、用户操作（拖动边界、面板头按钮、状态栏、命令、活动栏、拖动标签）、插件打开或关闭标签、视图声明变化。
- 输入：记录 `workbench.layout`（可缺失、损坏、版本不支持）；实测的外壳容器尺寸；视图目录；窗口是否绑定项目。
- 前置：工作台浏览器入口已激活。Storage 不可用时按默认树渲染，只是不能保存。

文档的形状（`@notnotype/nb-workbench-layout` 导出，校验函数 `validateLayoutDoc` 是唯一权威）：

```ts
interface LayoutDoc {
    version: 1;
    tree: GridSnapshot;                     // 叶的 ref：`panel:<id>` 或 `bar:activitybar`、`bar:statusbar`
    panels: Record<string, PanelRecord>;     // 树里的面板和浮动的面板都在这里
    floats: ReadonlyArray<{panel: string; rect: {x: number; y: number; width: number; height: number}}>;  // CSS px，相对树区域，写入时取整；至多 16 个
    hiddenBars: ReadonlyArray<"activitybar" | "statusbar">;
    currentEditor: string | null;
}
interface PanelRecord {
    role: "tool" | "editor";
    name?: "sidebar" | "auxiliarybar" | "panel";
    tabs: ReadonlyArray<TabRef>;            // 顺序就是显示顺序
    active: string | null;
    hidden?: boolean;                       // 只有具名面板会隐藏；隐藏的是它的整个区域
    collapsed?: boolean;                    // 分节：收成标题行；锚：它这个区域拖到零（同名不同义，见输出 11 的表）
    container?: string;                     // 分节所属容器的 id（输出 41）；只有区域里的分节有
}
type TabRef =
    | {kind: "view"; viewId: string}                  // 工具视图，每个视图只有一个实例
    | {kind: "tab"; type: string; tabId: string};     // 动态标签，例如 type 为 nbook.editor
```

校验：每个面板恰被树引用一次；`TabRef` 全局唯一；`active` 属于 `tabs`；条恰各一个；具名面板名唯一；至少一个编辑组；节点不超过 256 个、深度不超过 16 层；id 不能是 `__proto__`、`constructor` 这类键。

锚的记录另存它这个区域的入口顺序（容器 id 的列表）、当前容器、区域是否拖到零；这几项与 `container` 都是内部合同，记录的 `version` 不变（见“副作用与数据”）。

## 输出与可观察行为

### 模型

1. **默认树与骨架**：默认树是 `V[H[活动栏, sidebar, V[编辑组, panel], auxiliarybar], 状态栏]` 加上按声明建的分节：每个有成员的容器放进它的区域（输出 4），容器里一个视图一个分节，分节与区域的锚同一列（底部面板是同一排）；同一份声明算出同一棵树。内置声明下，侧栏是容器“项目”的会话与资源管理器两个分节，右栏是对话一个分节，底部面板是后台任务与通知（planned）。第一次生成文档时，有容器的区域显示，没有容器的隐藏；区域里的视图都声明了 `revealRegion: false` 时同样隐藏（[workbench.views](../workbench/views.md) 输出 18），所以内置声明下底部面板隐藏。任何操作之后树都合这个骨架：状态栏在最下；活动栏、侧栏这一列、中间、右栏这一列从左到右；中间是编辑区在上、面板这一排在下。侧栏与右栏这一列只上下分，面板这一排只左右分，编辑区里只有编辑组、可以任意分。骨架按锚的位置判，并要求锚没有标签、区域里别的工具面板都是分节（恰一个标签、写着归属）；合法但不满足的记录按“状态与转换”读。（planned：投影在 `body` 横向分支里、右栏一列外侧另插一片右轨叶，只在呈现里，文档与骨架不变，见输出 50。）
2. **规范形**：每次结构操作之后，同轴嵌套展平，单子分支塌陷。所以 `(A | B) | C` 只会存成 `H[A, B, C]`。展平前后每个叶的尺寸不变（差不到 1px）。
3. **不变量**：树里至少有一个编辑组，可以是空的。分节的标签被拖走或关掉后，分节移除。锚一直留在树里，不移动；区域被拖空时隐藏，用户打开的空区域不隐藏（输出 43、48）。编辑组拖空后移除，最后一个除外。结构操作失败时整批不改，文档保持原样。
4. **视图放哪**：视图属于它声明的容器，没写的属于自己的隐式容器（输出 41）。第一次生成文档时，容器里分节的先后、区域里入口的先后都按 `order`（[workbench.views](../workbench/views.md) 输出 13）。文档已经有了之后才出现的视图，成为它的容器最后一个分节：容器已经有成员时就加在容器此刻所在的区域；还没有成员时，容器放进声明的区域（声明的容器看容器的 `location`，隐式容器看视图的 `location`），入口排在这个区域入口顺序的最后；同时出现的几个之间按 `order`。区域隐藏着就保持隐藏，当前容器也不换，直到用户打开；区域原来没有容器时它成为当前容器。之后它在哪由文档决定。声明消失的视图（插件暂时缺失）留在树上显示占位，写明原因，可以关闭；文档就是所见的样子，别的操作写回时不丢。被别的视图声明取代的旧视图例外，直接拿掉（[workbench.views](../workbench/views.md) 输出 20）。

### 尺寸

5. **固定尺寸**：标题栏 36px，状态栏 22px，活动栏 48px，都不可调。条两侧的缝宽为 0，其余缝占 1px，命中区向两侧扩展。（planned：侧轨的卡片宽收着 48、展开时按视图段声明，叶厚按活动栏的算法加缝，见输出 50。）
6. **约束**（CSS px）：

    | 面板 | 宽 | 高 |
    |---|---|---|
    | `sidebar` | 160 到 560，默认 340 | 至少 80 |
    | `auxiliarybar` | 160 到 max(360, 视口宽 × 0.45)，默认 400 | 至少 80 |
    | `panel` | 至少 160，默认 320 | 至少 80，默认 200 |
    | 其它工具面板 | 至少 160，默认 320 | 至少 80，默认 200 |
    | 编辑组 | 至少 220 | 至少 120 |

    右栏、底部面板顶上的入口条（输出 47）占 32px（planned）：当前容器只有一节、它的头并进入口条时，区域的最小、最大高度和只有一节时一样；几节时多一行入口条，底部面板至少 112（planned）。

    视图声明的最小最大尺寸，面板取所有标签的并（最大的最小值），切标签不改布局。拖过最小或最大值时停在边界，不弹回。
    前三行是区域的约束，区域里的分节都用所在区域那一行；“其它工具面板”只剩浮动窗。区域实际的约束是这一行与当前容器里各视图声明的并；切换容器不改尺寸意图，新容器的约束更紧时只在呈现时夹，切回来回到原来的尺寸。
7. **谁吸收余量**：一个子节点按比例分配（`weight`），当且仅当它含编辑组，或它的兄弟都不含编辑组；其余保留像素（`fixed`）。所以侧栏、右栏、面板和编辑区并排时保留宽度，编辑组吸收余量；全是工具面板的一列按比例分，不留白。（planned：侧轨展开多出的宽度由编辑组吸收，必要时这次呈现压右栏，见输出 50 的预算。）
8. **尺寸意图**：保存的是 CSS px，只从呈现尺寸写回：手势落账后、结构操作之前各一次。呈现为零的轴和收起的面板不写，那就是展开时的尺寸。全是工具面板的分支里有收起或隐藏的兄弟时，其余的只更新彼此的比例，总量保持原来的份额，所以展开后回到原来的尺寸。测量、夹取、放不下时的压缩、拖动期间都不写文档。不在当前容器里的分节不写，切换容器也不改任何尺寸意图，所以切走再切回来各分节的大小原样。写回经输出 49 的两个入口。
9. **手势**：边界的手势按 [ui.nested-grid](nested-grid.md) 输出 7 到 10、26，键位与步长按 [NestedGrid](../../../packages/nb-layout/src/vue/NestedGrid.md) 的“交互”：十字交汇同时调两轴、方向键 10px、Shift 1px、Home、End、Enter，一次手势只落账一次；Escape、指针取消、失焦、容器尺寸或结构变化取消整场，不提交。
10. **放不下时只改呈现**：先把工具面板压到最小；还放不下时，按右栏、底部面板、侧栏的顺序把区域里显示着的分节、打开着的空区域（输出 48）从呈现树里收走（planned），焦点所在的面板最后收；放得下之后，没帮上忙的放回来（窄的时候收走纵向的那块不省宽度）；再放不下才压编辑组。每种降级给诊断，不写文档。窗口变大时自动回来。所有几何非负且在容器内。（planned：降级前先按收着算展开的侧轨；右栏被收走时有成员的右轨留收着的 48，见输出 50。）
11. **面板的几种状态**互不等价，只有隐藏与拖到零画得一样、只差记录：

    | 状态 | 文档 | 呈现 | 怎么回来 |
    |---|---|---|---|
    | 隐藏 | 锚的 `hidden`：隐藏的是整个区域 | 同拖到零：区域在挨着编辑区的那条边界的方向上为 0，保留 1px 边界，这条边界和挨着它的边界照常有交汇处（输出 9 的十字交汇）；内容停放；焦点与键盘落点照旧按隐藏算，不落到零宽的面板上（planned） | “显示”清掉区域的隐藏与拖到零，按意图回来；或拉开边界，同时清掉隐藏 |
    | 收成标题行 | 分节的 `collapsed` | 侧栏、右栏的分节高度等于面板头，内容停放；底部面板的分节不折叠；区域此刻只显示一个分节时（隐藏的区域按拖到零算）它不收成标题行，没有收起按钮，`collapsed` 留在记录里，区域里又显示两个以上分节时才起作用 | 点标题，或面板头的按钮，或拖开 |
    | 拖到零 | 记在锚上，是整个区域的状态 | 区域在挨着编辑区的那条边界的方向上为 0（侧栏、右栏是宽，底部面板是高），保留 1px 边界（能从它拉开；这一侧是零，边界上不画接缝的线，平铺主题里不多出一条线）；区域里有几个分节都一样，内容停放（planned） | 拉开边界，或点活动栏的入口，或“显示” |
    | 不在当前容器 | 分节的 `container` 不是区域的当前容器 | 不在呈现树里，不占空间；内容停放，不卸载 | 切到它的容器（输出 42） |
    | 被最大化盖住 | 无 | 还在原来的矩形，被盖住；内容停放 | 退出最大化 |
    | 放不下被收走 | 无 | 不在呈现树里；内容停放；有诊断 | 窗口够大时自动回来 |

    “显示”指标题栏的区域开关、活动栏的入口、命令 `nbook.view.set-part-hidden`。区域里一个分节都没有时“显示”照样打开它，是一块空面板（输出 48）。区域的隐藏与拖到零同时为真时，“显示”把两个都清掉；分节收成标题行的不动。
    一列的面板全部收成标题行时，标题行排在上面；带容器的区域里最后一节垫底：外框拉到这一列的底，卡片满高，它仍是收起的（内容不显示、不可交互、尺寸意图不写回，手势预览里也不算拉开），这一列的分隔线不能拖，展开靠点标题或命令。这一列和同一行的编辑区高度不变。
12. **拖过最小尺寸**：区域挨着编辑区的那条边界往最小尺寸以下拖，越过 24px 时整个区域拖到零（planned）；侧栏、右栏里分节之间的边界这样拖是收成标题行，底部面板里分节之间的边界停在最小宽度（planned）；边界上的 Enter 是同一个切换。编辑组不可收起。**从零拉回**：用指针拉回时在合法展开区跟随指针（按下边界加累计位移）；按钮、命令与 Enter 恢复意图尺寸。区域是隐藏的（按拖到零画）时，拉开就是显示，同一次落账清掉隐藏。拉回的过程中内容就出现，不等松手：里面的视图没加载过时在拖动中加载，`ViewContext.visible` 跟着拖动中的几何；按着拖回零时内容回到停放。拖动中不写文档，落账时才写。
13. **最大化**：对任意面板，它盖住树除条以外的区域，只在内存，不落盘。其余面板原地不动：矩形不变，内容马上不可交互，过渡结束后隐藏；还原时最大化的面板缩回去露出它们，它们不重新长出来。入口是面板头的按钮和命令，没有拖动手势；期间没有分隔线可拖。隐藏或收起这个面板（包括标签被搬空）、显示被它盖住的面板、结构操作、放不下时退出，刷新不复活。区域里最大化的是一个分节，切走它所在的容器时退出。头并在入口条里的那一节（输出 47）最大化时，提交那一刻它就在自己的叶里画头（入口条被盖住）；还原时头留在叶里，过渡结束才搬回入口条，这一刻正文上移一行、不随过渡（planned）。头换了地方时焦点在头里的，交给新头里同一个元素（标题、同一条命令的框架按钮），没有就给标题（planned）。（planned：最大化不盖侧轨，期间轨宽手柄不可用；在侧轨上打开对话或展开先退出最大化，见输出 50。）

### 渲染

14. **按矩形摆放**：面板外框、分隔线、内容项、条是同一父元素的子元素（[ui.nested-grid](nested-grid.md) 输出 27、31、80、82）。结构变化不重建还在的实例，内容的输入、滚动与焦点保留。三层 Teleport 与滚动焦点记忆都不再需要。
15. **位移**：程序引起的布局变化都有过渡（[ui.nested-grid](nested-grid.md) 输出 35、59、88、92）。面板移到别处时外框从旧矩形滑到新矩形；标签并入已有面板时，内容从旧面板滑到新面板，即使两块面板都没动。飞行中的内容压在别的面板上面，不被它们裁切。容器尺寸变化与手势不过渡。系统减少动态效果时直接到终点。
16. **停放与焦点**：内容停放时不可交互，不进读屏与 Tab 顺序，保持最后的非零尺寸，不卸载。焦点所在的内容被停放、或焦点所在的面板头随面板隐藏时，焦点移到同一面板可见的标签；面板不可见时移到活动栏里它所在容器的入口（只有侧栏的容器有），都没有时移到外壳根；编辑组移到活动编辑组。焦点在外壳之外（菜单、对话框）时不抢。切换容器时的焦点见输出 42。
17. **有效可见**（`ViewContext.visible`）：在已提交的文档里，面板不隐藏、不收起、不是零尺寸，是活动标签，不被放不下收走，不被最大化盖住；分节另要所在容器是区域的当前容器，区域没隐藏、没拖到零；浮动窗的活动标签总算可见，被别的窗盖住、树里的面板最大化时也算。手势预览不改可见性；从零拉回时按拖动中的几何算。第一次有效可见才加载（[workbench.views](../workbench/views.md)）。
18. **Tab 与读屏顺序**：面板内按 DOM 顺序走；走出一块时按树的先后跳到下一块（标签条、内容、下一个面板）。F6、Shift+F6 在面板之间循环；活动栏与右栏、底部面板的入口条也各是一站，入口条在它区域的分节之前。读屏顺序按树序（`aria-owns`）。从外面 Tab 进来时落在树序的首或尾。（planned：侧轨与区域按从左到右排：左轨在左侧栏之前，右轨在右栏之后，见输出 50。）
19. **外观**：卡片还是平铺由主题决定，变量沿用 [ui.workbench-shell](workbench-shell.md) 输出 38 的那组。缝、圆角、整缝与半缝、相连，都按矩形邻接算：贴着窗体、标题栏或状态栏的一边留整缝，挨着别的卡片的一边留半缝，相连的一边不留缝；相连与否按拖动中的几何算。**一个容器一张卡片**：侧栏、右栏、底部面板里同一区域相邻的两块（分节，以及右栏、底部面板的入口条，输出 47）相连，所以一个容器的几节拼成一张卡片；几节之间画开放式分割线：`--shell-pane-divider`，1px，沿长轴两端各缩进 `--shell-pane-divider-inset`，不碰卡片边，线两端那一小段仍是卡片，卡片的外框与投影在分割线处不断开。不同区域的卡片挨着（底部面板与右栏）照旧留缝。编辑组一组一张卡片，卡片主题里组与组之间是缝、不画线，平铺主题里的线贯通整个高度（planned）。一个角圆当且仅当它两侧的边都不相连，相连的边上没有投影与外框。**活动栏与侧栏相连**：侧栏里贴着活动栏、宽度大于零的每一块都和活动栏相连，侧栏几节时整列相连；两者之间画一条两端不碰顶底的短线。侧栏隐藏、在过渡里留着缩回去时（[ui/nested-grid](nested-grid.md) 输出 45 到 48），以及显示时从零宽长出来时（输出 41、42），活动栏和侧栏画成一张：侧栏右边的两个圆角（几节时是最上面一节的右上角、最下面一节的右下角，planned）跟着它的右沿走，缩到零时正好落在活动栏右边、成了活动栏的两个角，长出来时把它们带出去；活动栏的角与两张卡片之间的缝这期间被盖着，中间不露缝，角一直是同一对圆角、不变形；中间那条短线隐藏时淡出、显示时淡入（`--motion-layout`、`--ease-layout`，和面板的过渡同时走完）。切换容器时活动栏前后都相连，不换画法（切换的动画见输出 42）。系统减少动态效果时直接到位（planned）。状态栏不是卡片。面板自己不画外框与圆角；面板头与编辑器标签栏不画底线；工具面板的当前标签是下划线加正文色，编辑组的当前标签是与正文同色的一块（[workbench.editor](../workbench/editor.md) 输出 53）（planned）。工作台页占满视口，自己不滚动，页面根不预留滚动条位置（planned）。悬停线两端的连接按邻接算（planned）。（planned：相连、圆角、接缝与最大化避让按侧轨列表与左右两侧算，右栏卡片与右轨相连的两个角不圆、接缝短线在内侧，见输出 50。）

    | 工具视图 | 接受，成为新分节：侧栏、右栏这一列只有上下，面板这一排只有左右 | 接受 | 拒绝 | 接受 |
    | 编辑器标签、文件 | 拒绝 | 拒绝 | 接受 | 拒绝 |

    缝只有两边同类才是落点：编辑组之间，同一列或同一排的工具面板之间。活动栏、侧栏、编辑区、右栏之间，编辑区与面板之间都没有缝落点。所以骨架不变（输出 1）：编辑组下面挨着面板时，放到编辑组下缘是分这一组，面板的高度不变；放到侧栏与编辑组之间的缝上，视图归侧栏，编辑器标签归编辑组。限制是去掉落点，不改道。接受矩阵在提交时再验一次。
27. **往一个方向分**（设置 `nbook.workbench/dropSplit`，缺省 `half`，只有用户层）：`half` 只分本窗口，新块取这一块的一半，别的块不动。`shared` 同方向的窗口一起分：这条边和所在分支同方向时，新块占分支里可分配总量的 1/(n+1)，可分配的 n 块按原比例缩，不占份额的（隐藏、收起）和保留像素的（输出 7）不动；不同方向时和 `half` 一样。所以编辑区分屏不分走侧栏、右栏、面板的空间。**移动的单位**：只有一个标签的面板移到外缘时是同一块面板移动，面板 id 不变，内容不重建。分节在区域里、区域之间换位置都是这样移动，归属按输出 40 改写。锚不移动（输出 3）。放回挨着来源那块的边上是原位（输出 28）。移动时面板的收起清掉：放到别的方向，收成标题行会变成零宽。多标签面板的一个标签移到外缘时拆出新面板，继承来源的角色；内容都不重建（编辑器标签见 [workbench.editor](../workbench/editor.md) 输出 49）。浮动窗的一个视图标签放进区域时成为新分节。
28. **放回原处**：结果的结构、顺序、标签集合、活动标签都和现在相同时，什么都不提交，尺寸意图也不动；分节的归属、各区域的入口顺序与当前容器也在比较之内，只切换容器的操作照常提交。预览画来源自己所在的位置，提示“原位”。标签放回它自己那块面板的中央不算原位，按输出 25 第 6 行画成添加为标签；它本来就是活动标签时结果不变，同样什么都不提交。只有一个标签的面板，放到它自己或紧挨着它的那块朝向它的那条边、那条缝，都是原处。分节放到自己的任一半、紧挨着它的分节朝向它的那一半、它们之间的缝，都是原处。
29. （删除，开发者 2026-11-07。）隐藏的、拖到零的面板不是落点，拖动时不浮出任何东西。要放进隐藏的区域见输出 23 的“移动到”，侧栏放到活动栏见输出 45。
30. **反馈**：拖影是“图标加文字”。指示画真实结果：区域矩形用提交时的同一个函数算，不估算；标签条的插入只画一条线。同区两半切换时高亮连续过渡。放下时高亮立刻消失，不留在原处，也不滑向结果，内容自己滑过去（输出 15）。落点文字走 `aria-live`，只在语义变化时更新。这一条说的是落点指示；实时布局的反馈见输出 38。
31. **键盘**：与指针同一套规则：空格拿起，Tab 在落点区域之间循环（活动栏、右栏与底部面板的入口条（planned）、工具面板、编辑组、浮动窗，最后是“浮动”：没有指针可以指，无落点要明确选），方向键逐个位置移动（缝也是位置），Enter 放下，Escape 取消，焦点回到拿起时的来源。分节上是前、后两个位置，活动栏与入口条上每个入口与入口之间的空位各是一个位置。拿起时停在原位，直接 Enter 不移动。标签、分节的标题、活动栏与入口条的入口是可聚焦的拖动源（planned），可访问描述说明“按空格拿起并拖动”。
32. **结构变化取消**：拿起时记下结构键（树的拓扑、浮动窗的集合、标签集合、来源是否还在），只比已提交的文档。结构变了（插件撤回视图、文件被删关掉标签）整场取消。各区域的当前容器也在结构键里：拖动中容器被命令切走，这一场取消，零写入。只是尺寸或滚动变了时按当前位置重算落点；实时布局下容器尺寸变了也整场取消（输出 38）。

### 编辑器的接缝

33. **谁拥有什么**：工作台持有树、面板、标签顺序、活动标签、活动编辑组；编辑器持有地址、编辑器、语言、preview、固定、光标、dirty、文档。编辑器经服务 `editorPanelsKey` 改结构（`PanelTabs`：插入、替换、拿掉、激活、移动、移到外缘；`PanelTree`：活动编辑组、拆一块、右侧相邻），两边靠 `tabId` 对上。preview 替换一次写完。固定分区的插入限制归编辑器，放下时先过它。`"side"` 是活动编辑组右侧相邻的编辑组，只在编辑组里找，工具面板跳过，没有就拆一个。
34. **恢复**：工作台先读文档；文档和 `editor.tabs` 都读完、编辑器入口交付后才渲染编辑组。`editor.tabs` 里没有的 `tabId` 显示原因并可以关闭；文档里没有的 `tabId` 由编辑器丢弃。页面标签不恢复：`editor.tabs` 里留一个记号，恢复时从文档里拿掉。编辑器入口未交付或撤回时编辑组里写着不可用的原因，文档里的标签不动，再次交付后恢复。

36. **公开状态**：`layoutReady`、`sidebarVisible`、`auxiliaryBarVisible`、`activityBarVisible`、`panelVisible` 保留，按区域求值：区域隐藏、拖到零、被最大化盖住、放不下被收走都不算可见，收成标题行算，打开着的空区域也算（输出 48）。新增 `hasCurrentPanel`、`nonPhone`（手机呈现之前恒为真）、`maximized`，后两个取代 `nonCompact`、`panelMaximized`。`focusedPart` 取当前面板所在区域的名字，编辑组是 `editor`。`panelPosition`、`panelAlignment`、`panelHorizontal`、`panelMaximizable` 删除，不留别名。 当前面板浮动时是 `float`。
37. **落点分区**（设置 `nbook.workbench/dropSectors`，缺省开，只有用户层；只在落点指示下画，实时布局不画，见输出 38）：拖动经过能接收的面板的正文时，把这块面板能往哪放画出来：编辑组上下左右中五块；分节是前后两块，侧栏、右栏这一列是上下，面板这一排是左右，没有中央；进不了中央时没有中央，空面板整块是中央；打开着的空区域整块一块，写“放在这里”（输出 48）。形状就是输出 25 的判定：指针在哪块，放下就是哪块。正文压暗（不透明度加调暗，不模糊），线与每块的字都显眼；指针所在的那块线更粗、底更深，它自己不写字：输出 28 的提示还在说这次落点（“放到两块之间”“原位”）。放不下字的块不写。指针在编辑组的标签条、活动栏上，或这块面板不接收、被菜单挡住时没有分区；侧栏、右栏分节的标题行算前半，底部面板分节的标题行和正文按同一条竖线分（输出 25 第 7 行），分区照画。指针在缝上时没有分区。拖动结束即消失。设置关掉时落点不变，只是不画。
38. **实时布局**（设置 `nbook.workbench/dragFeel`：`live` 或 `indicator`，缺省 `live`，只有用户层）：拖动中布局真的变，反馈就是布局本身。键盘拖动、系统减少动效、有面板最大化、容器还没量到时这一场是落点指示；拖的是含几个视图的入口时也是（输出 46）；拿起时定一次，整场不变。下面几条里什么时候换预览、收起与展开来源、换判定的几何、拿起与收回卡片，是 [ui.layout-drag](layout-drag.md) 输出 22 的编排，这里写的是工作台给它的规则（哪里算自己的标签条、预览摆成什么、几何怎么量、卡片的设置）。
    - **判定**：规则同输出 25，文档用已提交的，矩形用拿起时的（进行中的过渡先到终点再量）。容器尺寸变了整场取消：基准没了，也没法从预览里量回来。
    - **预览**：候选连续 150ms 不变才按它摆，邻居真实让位，缓出约 470ms（`--motion-layout`、`--ease-layout`）；来源自己那条标签条、已经吸收它的那条不等。预览过又没有候选了（同样等 150ms）：来源收起，留下的填满它的位置。
    - **判定的布局**：拿起时量一份；第一次摆到别处的落点（不是自己的标签条、不是放回原处）时来源收起；来源那块面板摘掉它还在（还有别的标签，或是最后一个编辑组留成空组）时，拿起卡片就收起，不等落点（撕下标签：那一块接着显示下一个标签，矩形不变）；之后按收起后的布局判（每块面板按收起前后的矩形差挪，标签条与活动栏的入口跟着挪），收起后不在的面板不是落点。回到原处（放下去是原样：它原来那一节的位置、自己的标签条或活动栏上自己的空位）时来源展开回原位，邻居让回原来的位置，预览就是已提交的样子，判定换回拿起时的那份；再摆到别处又收起。收起、展开那一刻指针下的落点留着，指针再动才按换过的布局重判，松手放到的就是屏幕上那个。预览怎么摆都不改判定。预览只给渲染：不写记录，不改可见性（输出 17），预览里露出来的、没打开过的视图不加载，没读过的编辑器标签不读文档，都是空白；已提交的文档、活动组、命令都不变。编辑器标签的落点先问编辑器放下会怎样（[workbench.editor](../workbench/editor.md) 输出 55）：并入目标组已开着的同一文件时落点换成那一组的中央（标签条上也是），按并入画；放不下时按被拒绝画（输出 39）。预览不切换任何区域的当前容器：来源是当前容器唯一的分节时，来源收起后预览里这个区域是空的，放下才切到相邻的容器（输出 43）。
    - **卡片**：离开标签条就拿起：那个标签的内容离开它的面板跟手，是同一个实例，按卡片的大小排版（卡片缩放时跟着重排，不是缩略图），上面一条头写图标、标题与落点文字。盖在别的面板与分隔线上，不接指针，抓住的点一直在指针下。从此刻显示着它的那块面板的大小开始缩，缩到 380×260（不大于来源面板）。缩小的时机是设置 `nbook.workbench/dragCardShrink`（只有用户层）：`strip`（缺省）一拿起就缩；`panel` 指针还在来源面板里时是面板原大小，离开才缩。来源面板是这一场拿起时它所在的面板，被别的标签条吸收过也不变。卡片的尺寸多久写一次是设置 `nbook.workbench/dragCardRefresh`（只有用户层）：`display`（缺省）每一帧，`60`、`30` 每秒至多这么多次，缩放到终点的那一次马上写；尺寸按整像素写，位置照旧每帧跟手。它只管拖动的卡片，开关面板等布局过渡不受影响。拿起的是来源面板唯一的标签时，那块面板在来源收起之前是空位（同“空位”，头也不画），不把标题留在原地。头只写标题的面板没有标签条，一拖就是卡片。原位（放下去是原样，输出 28）也拿着卡片，只有自己标签条里的原位是排序（见“标签条上”）。离开标签条重新拿起，从吸收它的那块面板的大小开始缩；指针这时已经在那块面板外面时，卡片从面板的位置按缩放的快慢追到指针下，不跳。拿起的标签没有实例（不活动的工具视图没打开过、编辑器标签没读过）时卡片的内容是空白，同预览。缩放与追赶的逐帧步进见 [ui.layout-drag](layout-drag.md) 输出 20。
    - **标签条上**：指针落在任何标签条上（自己的、别人的、活动栏上两个入口之间：活动栏是侧栏的入口条，空位按标签条的插入位算），来源就被它吸收：预览是放下的真实结果，卡片收回，没有拖影：被拖的标签（活动栏是入口）就在它留着的位置上显示出来，沿标签条跟着指针（活动栏是竖着），抓住的点（按下的那一点）在指针下，夹在条的两端之间不出去，盖在邻居上时底是不透明的（不活动的编辑器标签是悬停的样子），邻居的字不透上来；别的标签或入口按预览滑开（`--motion-move`），它自己不参与换位过渡。标签条里插到哪按这个标签此刻的位置判，不按指针：它的左沿过了左边邻居的中线，邻居就让到它后面；往右时右沿过了右边邻居画出来的中线才换，盖过邻居一半它就让开，和抓在标签的哪一点无关，条的两端都到得了；邻居的位置按拿起时量的、摘掉来源并补上它空位的那份（输出 25）。活动栏照旧按指针判：指针在入口上是并入（见下文）。该成为活动标签的照样成为活动标签，内容是同一个实例，落进这块面板；原来的活动内容停放。离开标签条重新拿起卡片，预览换走之后目标恢复。别人的标签条、活动栏第一次进去也要等 150ms，路过不变；在吸收它的这条标签条里换位马上预览。编辑器标签并入已开着的同一文件时不吸收：落点是那一组的中央（见“判定的布局”），卡片留着。浮动窗只写标题的头没有插入位，算中央；分节的标题行按输出 25 第 7 行，不吸收（planned）。活动栏放不进侧栏的（编辑器标签、有面板最大化）不吸收。活动栏上的预览只动入口：入口滑开留出位置，被拖的视图在空位上显示成一个入口，侧栏显示的还是原来的当前容器，隐藏着也不展开，放下才切换、才展开。指针在一个入口上时不吸收：这个入口高亮，样子同并入的盖层，侧栏同样不切。来源是侧栏里一个容器唯一的视图时，活动栏是它自己的入口条（输出 45）：指针停在别的入口上也不收起来源，入口不动，只高亮那个入口；收起来源的话它的入口跟着没了，下面的入口上移，高亮的入口就滑离了指针。
    - **空位**：长出新块的落点（外缘、缝），让出的位置什么都不画，露出窗体底：没有卡片的底与投影，不画头、没有内容。主题要画可以给 `--layout-slot-border`、`--layout-slot-fill`，缺省都透明。头、底和内容放下才有。指针在已显示的空位内（含 8px 边距）候选不变；并入没有空位，也没有粘滞。
    - **并入**（中央）：布局只因来源收起而动，目标的头与活动标签都不变；放回来源自己那块时，目标就是它收起后的样子。目标整块盖一层（`--layout-merge-fill` 的底，`--layout-merge-border-width` 宽的 `--layout-merge-border` 内描边），不写字（落点文字在卡片头上），跟着目标过渡。分节不是并入的目标，落在它上面按前后两半（输出 25）。
    - **分区**：不画输出 37 的分区：预览本身就是反馈，分区画在判定用的布局上，预览一摆目标就挪了，对不上。
    - **松手**：提交指针下的候选，不等预览稳定（放回原处不提交）；内容从卡片飞到结果，内容体一次到终点尺寸；并进已有的面板时，那块面板原来显示着的内容留在卡片下面、不可交互，卡片长满之后才停放，飞的一路面板不空。**取消**：布局回原样，内容飞回，零写入。
    - **读屏**：落点文字经常驻的 `role="status"` 节点，只在语义变化时更新。
    - **开销**：跟手的东西（卡片、拖影、拖动中的窗）不走渲染。候选不变、预览的过渡与卡片的缩放结束之后，移动中每帧至多一次样式重算、不布局，指针不动一次也没有。判据按帧，不按秒：每秒的次数等于它乘以刷新率。按需排帧见 [ui.layout-drag](layout-drag.md) 输出 21。
39. **应用内浮动**：浮动窗是一块不在树里的面板，带标签，工具视图和编辑器标签都能浮动。浮出来、回到树里，内容都不换父元素、不重建。分节浮出来是只有一个标签的窗，归属清掉（输出 40）。整窗拖动经过打开着的空区域不停靠，多标签的窗要先撕下标签（输出 48）（planned）。（planned：声明了视图段的视图浮动时，窗里的视图段、矩形、夹取与顶格见输出 51。）
    - **无落点就浮动**：松手时指针不在任何面板上（输出 25 第 1 行、窗口外），这个东西又允许浮动，就在松手处开一个窗，指针落在头上，大小 460×340（不小于最小尺寸，不大于树区域）；靠边时整个窗夹回树区域，不开到屏幕外。拖动中反馈画这个矩形，提示“浮动打开”；实时布局下来源收起，卡片头写同样的字，松手时窗的外框、头与内容一起从卡片的矩形长到窗的矩形，不先画在终点。到 16 个窗之后不再开。
    - **被拒绝**：指针在面板上但放不进去（编辑器标签在工具面板上、工具视图在编辑组上、浮动窗不接收、两块都不接收的缝，编辑器标签放进的组有未裁决输入，[workbench.editor](../workbench/editor.md) 输出 55）：光标是禁止，读屏写“不能放在这里”，松手取消，不开窗（开发者 2026-11-07）；编辑器标签放不下时，松手由编辑器在组顶部写为什么。实时布局下来源收起之后指针没动，被拒绝照样留着。
    - **不浮动**：视图声明 `floatable: false`（[workbench.views](../workbench/views.md)）；指针在 `data-no-drag` 的按钮区；被菜单、对话框挡住；活动栏上段放不进（编辑器标签、有面板最大化）：拖到活动栏是想放进侧栏，放不进不该开窗。这些松手就是取消。Esc 照旧取消。
    - **整窗移动**：拖头的空白处（标签条空白），或只有一个标签的窗的那个标签；（planned）视图自绘头时，拖视图标出的可拖元素（[workbench.views](../workbench/views.md) 输出 19 的“自绘头”）。多标签时拖标签是撕下，走普通的标签拖动。窗一直跟手，没有拖影，不走实时布局，不写记录，放下写一次。
    - **回到停靠**：拖窗经过别的面板时，只有标签条、缝和 14% 的外缘窄带能停靠，经过中央继续浮着；窗不接收时不穿透。全部标签一起并入。工具视图的窗停靠进区域时每个标签成一个分节，按原来的先后，归区域的当前容器；分节上能停靠的是缝与沿区域方向两端 14% 的窄带（planned）。落点按输出 30 画，窗继续跟手。框架按钮“回到停靠”：工具视图各回它声明的容器（没声明的是它的隐式容器），成为最后一个分节，编辑器标签回树序最后一个编辑组。
    - **缩放**：四边四角的手柄，到了最小尺寸（角色与视图声明，同输出 5）、最大尺寸（再加树区域）时对边不动；拖动中不写记录，放下写一次；Esc 取消。
    - **键盘**：右下角手柄与一个聚焦时才露出来的移动把手能聚焦，方向键 10px，Shift 1px，每次写一次。“移动到”与编辑器标签的右键菜单都有“浮动”。F6、Tab 经过浮动窗，排在树之后。
    - **叠放**：后面的压在前面的上面。点击或焦点进入提到最前，已在最前不写。浮动窗在分隔线、最大化的面板之上，在下拉菜单之下。
    - **夹取**：呈现时窗至少留 80px 宽与头的高度在树区域里，夹取不写回：窗口变小再变大，窗回到原处。拖窗从呈现的位置开始。
    - **记住矩形**（planned）：工具视图从浮动窗回到树里（框架按钮“回到停靠”、拖回树里停靠或并进树里的面板）时，窗的记录矩形按视图记在文档上（`floatRects?: {["view:<视图 id>"]: 矩形}`，文档的正式可选字段，进形状比较）；之后经“浮动”（命令 `nbook.view.float`、“移动到”菜单）再浮出这个视图，窗用记下的矩形，不按树区域居中错开，呈现照常夹取（上一条），侧轨展开的差值照常加（输出 51）。松手没有落点开的窗照旧开在松手处、不用它。窗里有几个标签时每个工具视图都记同一个矩形。视图从文档里没了（插件停用、卸载），它的项在同一次提交里清掉；读入时矩形不合法、键不是工具视图的项丢掉并给诊断，其余照用。编辑器标签不记。
    - **资源树的文件**：出树后同一份规则与反馈（输出 25、26、30、37），是编辑器标签的来源：外壳根登记落点（`WORKBENCH_FILE_DROP`），资源树的手势在树外问它。不在面板上时一个窗里开多个标签；被拒绝时松手取消，光标归资源树的会话，没有禁止样式（[workbench.files-explorer](../workbench/files-explorer.md)“拖出树”）。
    - **不可**：最大化、收起（命令 `unavailable`），隐藏只有区域。树里至少一个编辑组：最后一个组的标签都浮出来，它留着、是空的。浮动的编辑组空了移除，活动组换到树序最后一个编辑组。

### 区域与容器

40. **锚、分节与归属**：三片具名面板是三个区域的锚：没有标签，不属于任何容器，不移动；区域里有分节时不进呈现树，打开着又没有分节时画成一块空面板（输出 48）。区域里别的工具面板都是分节：恰有一个标签，属于一个容器，归属写在分节自己的记录上（`container`）。往区域里放视图只新建分节，不并进已有的分节。容器里分节的先后就是它们在树里的先后。分节搬出区域（浮出来）时归属清掉；搬进区域时写上目标容器：放到分节的前后或缝上，是那个区域的当前容器；放到入口上或经“移动到”，是指定的那个容器。
41. **容器的身份、标题与图标**：容器的 id 有三类，互不重叠：没写 `container` 的视图属于自己的隐式容器 `view:<视图 id>`；声明的容器用插件给的 id（贡献点 `workbench.viewContainers`，[workbench.views](../workbench/views.md) 输出 15）；用户拖出来的是 `custom:<UUID>`（planned）。容器出不出现只看此刻的成员：没有成员的容器没有入口。声明的容器空了入口消失，有视图回来入口回来；用户拖出来的容器空了就不再存在，它的 id 从入口顺序里删掉。入口顺序是一个区域里各容器的先后，记在锚上：容器第一次出现时排进去（输出 4），之后只随用户的操作变（输出 23、44 到 46）。标题与图标不保存，每次按同一个顺序求，活动栏、“移动到”菜单读的是同一个结果：声明的容器用声明的；隐式容器与用户拖出来的容器取第一个成员视图的（按分节的先后，跳过声明不在的视图），成员的声明都不在时写第一个成员的视图 id；声明的容器自己的声明不在了（插件被禁用）时同隐式容器。入口的悬停文字写出容器里的各个视图。
42. **切换容器**：一个区域只显示当前容器的分节。别的容器的分节留在文档里，内容停放、不卸载；它们的先后、大小、收成标题行都不变，切回来是原样。切换是一次提交：换掉当前容器，同时清掉区域的拖到零，不改任何尺寸意图（输出 6、8）。切换本身不改区域的隐藏：隐藏着的区域要不要显示，由引起切换的那个动作定（输出 22、23、35、44、45 各自写明）。焦点留在原处；焦点原来在被切走的分节里时，交给新容器的第一个分节。结果与现在相同时零写入（输出 28）。侧栏切换的样子（planned）：侧栏这一刻显示着、宽度大于零、里面没有最大化的分节时，点活动栏的入口切换，卡片不动（位置、外框、投影与右上、右下的圆角都在原处），里面的内容竖着滚过去：新容器的分节从入口顺序的那一头进来（排在后面的从下面进来），旧的往另一头出去，两者之间隔一条缝；裁在卡片里，卡片外不画；活动栏、它和侧栏之间的短线不动，活动栏与侧栏一直相连，角的画法不换；时长与曲线同布局过渡（`--motion-layout`、`--ease-layout`）。旧容器的分节在切换那一刻就不可交互（焦点按上一句交出），滚出去之前还画着。滚到一半又点：从这一刻接着滚，不跳，两张卡片不叠；点回正在滚出去的容器，它从这一刻往回滚。侧栏隐藏或拖到零时按显示长出来，不滚；里面有最大化的分节时（切换会退出最大化）照常过渡；系统减少动态效果时直接换（planned）。命令打开视图（输出 35）、拖动落进入口、“移动到”、当前容器空了引起的换容器不滚（planned）。右栏切换的样子同侧栏（planned）：右栏的入口竖排在右轨上（输出 50），点右轨的入口切换，内容竖着滚，排在后面的从下面进来；右轨、它和右栏之间的短线不动，右轨与右栏一直相连。底部面板切换的样子（planned）：点入口条的入口切换，条件同侧栏（区域显示着、宽度大于零、里面没有最大化的分节）；卡片与顶上的入口条不动，入口条以下的内容在卡片里横着滚过去：新容器的分节从入口顺序的那一头进来（排在后面的从右边进来），旧的往另一头出去，两者之间隔一条缝；裁在卡片里入口条以下那块，卡片外不画。入口条里并进来的头在点的那一刻换成新容器的，新容器有几节时这一段空出来、新的头随内容滑进来；旧容器里头并在入口条里的那一节，滑出去时也没有头，内容不下移。入口的按下底色、下划线和内容同时滑过去，别的途径换了容器时直接到位（planned）。时长与曲线、滚到一半又点、隐藏或拖到零时、减少动态效果时、哪些途径不滚，都同侧栏（planned）。几个区域前后脚切换（侧栏还在滚时点右栏的入口）时，前一个直接到终点，这一刻整个工作台进行中的过渡一起到终点；滚的过程中别的区域显示、隐藏时，裁切窗与静止的卡片停在开始时的位置，滚完才对上（已知限制，[ui/nested-grid](nested-grid.md) 输出 73、74）（planned）。
43. **当前容器空了**：当前容器的最后一个分节被拿走或关掉，提交之后区域切到入口顺序里它前面的那个容器，前面没有就切到后面的；这一次把区域拖空了（拿走了它最后一个分节）时锚隐藏，用户打开的空区域不隐藏（输出 48），其余布局不变，照常保存。这样切过去不改区域的隐藏：区域隐藏着就还隐藏着。拖动的预览里不切（输出 38）。
44. **入口的右键菜单**：菜单是容器的。“移到”另外两个区域各一项（侧栏的入口是“移到右栏”“移到底部面板”），排在最前。“移到”把整个容器搬过去，搬法同输出 46，入口排在目标区域入口顺序的最后，目标区域切到它，隐藏或拖到零时同一次写入展开；选完焦点去这个容器在新区域里的入口。底部面板并成一行的入口开的是视图的“移动到”，末尾接上这里的“移到”（输出 47）。“重置”把容器搬回它声明的区域（声明的容器看容器的 `location`，隐式容器看视图的 `location`），容器已经在那里时没有这一项；用户拖出来的容器没有声明的区域，也没有这一项。
45. **入口条上的落点**：工具视图能放到入口条上：活动栏上段（侧栏的入口条），以及右栏、底部面板的入口条（输出 47，入口那一段）。落在两个入口之间（含第一个之前、最后一个之后，入口条上入口之后的空白也是“最后”）：入口滑开留出位置，落点指示是一条和入口条垂直的线（活动栏是横线，入口条是竖线），放下在这里新建一个只含它的用户容器（planned）。落在一个入口上：这个入口高亮，放下成为那个容器最后一个分节。两种放下都把这个区域切到这个容器，区域隐藏或拖到零时同一次写入展开；预览里都不切（输出 38）。来源是这个区域里一个容器唯一的视图时，落在入口之间只是给这个容器的入口换位置：容器不变，区域的显隐与当前容器也不变；落在它自己的入口上、紧挨着它的两个空位上是原处（输出 28）。来源是别的区域里一个容器唯一的视图时，落在入口之间是整个容器搬过来、id 不变（搬法同输出 46，位置是落下的那个空位），预览里入口让开、不切。有面板最大化时不接收；编辑器标签、文件不接收；底段不接收（planned）。（planned：右轨的入口带同活动栏上段，沿纵轴量；视图段与底段是拒绝区，见输出 50。）
46. **拖入口**：只含一个视图的入口，拖它就是拖这个视图（输出 24），视图能去的地方它都能去。含几个视图的入口只能落在入口条上：在自己的入口条里换序，显隐与当前容器不变；落到另一个区域的入口条上，整个容器搬过去，位置是落下的那个空位。**搬整个容器**：分节的先后不变；侧栏与右栏之间搬时分节之间的比例不变，搬进或搬出底部面板时分节平分；收成标题行的照旧收着，搬进底部面板的展开（底部面板的分节不折叠，输出 11）。别处没有落点，松手取消，不开浮动窗。这一场是落点指示，不走实时布局（输出 38）。（planned：右轨入口的拖动同活动栏入口。）
47. **右栏、底部面板的入口条**：右栏、底部面板显示着分节时，卡片顶上一行（32px）是入口条：一个容器一个入口，按入口顺序（输出 41），切换时不动；只有一个容器时也有（planned）。右栏的入口是图标，按下是底色；底部面板的入口是容器的标题，按下是下划线；按下态是“当前容器且区域可见”，至多一项。当前容器在布局文档里恰有一节时，那一节的头并进这一行，接在入口后面占剩下的宽度，不多占高度；按被呈现的那份文档的结构判，区域隐藏、拖到零、放不下收走时不变，拖动的预览里摘掉来源后只剩一节的容器也并（planned）。底部面板并进来的头不写看得见的标题，只接视图动作与框架按钮（planned）：按下的入口写着它的标题，就当它的标题用：焦点要落到这一节的标题时落到这个入口，右键与菜单键开这个视图的“移动到”（输出 23），末尾接上容器的“移到”另外两个区域（输出 44），不开容器的菜单：容器只有这一节，它的“重置”就是视图的“重置位置”；视图不让移动时开容器的菜单。读屏的区域名称照旧是这一节的标题。入口条和区域的分节拼成一张卡片，和下面之间不画线（planned）。点入口、Enter：不是当前容器就切到它，区域隐藏或拖到零时同一次写入显示；是当前容器且区域可见就隐藏区域。右键与菜单键开这个容器的菜单（输出 44）（planned）。每个入口一个 Tab 停靠，读屏是一组带按下态的按钮；底部面板的文字入口也是这样（planned）。对齐：右栏第一个入口的图标、侧栏与右栏分节头的展开标记、资源管理器树第一层的箭头离卡片左缘相同；底部面板第一个入口的文字和底部面板分节头的标题文字离卡片左缘相同。放不下时先截断并进来的头的标题，再把排在后面的入口收进末尾的“更多”（当前容器的入口总在外面），再把视图动作收进“⋯”，框架按钮最后（planned）。入口是拖动源，入口条上的落点见输出 45、46；切换时内容怎样滚过去见输出 42。（planned：右栏的入口条改为右轨，本条只对底部面板，见输出 50。）
48. **空区域**：区域里一个分节都没有、又打开着（标题栏开关、命令的“显示”照样能打开它）时，它的锚就是这块区域，画成一块空面板：没有头，正中写“把视图拖到这里”，不接收焦点（F6 跳过）（planned）。区域拖到零、放不下时的收走同有分节的区域（planned）。整块是一个落点（指针、键盘、落点分区都是这一个，提示“放在这里”）：放下去成为这个区域里一个容器唯一的分节，区域的当前容器就是它——来源是它容器唯一的视图时整个容器搬过去，id 不变（搬法同输出 46）；否则新建一个只含它的用户容器。这不算切换当前容器：区域本来没有当前容器，预览里也这样显示（planned）。编辑器标签、文件不接收（在面板上却没有落点，算被拒绝）；整窗拖动不停靠（planned）。区域在被拖空的那一次结构操作里隐藏（拿走、移走、浮出它最后一个分节，预览里同样收起），用户打开的空区域不隐藏，刷新后还在；布局模板里存着打开的空区域时，新项目照它显示（planned）。
49. **意图回写的两个入口**：`@notnotype/nb-workbench-layout` 写回意图导出 `applyGestureCommit`、`rebaseForOperation`，`rebaseIntents`、`fixedNodesOf` 不导出。`applyGestureCommit(doc, projection, {before, after, collapsed})` 在手势落账后用：收起与展开记到区域的锚上（输出 11），从边界拉开隐藏的区域时清掉隐藏，`before` 与 `after` 里没动的保留像素节点不写，其余按输出 8 写回；收起被文档拒绝的项跳过、照常写回尺寸，逐项交回 `rejected`。`rebaseForOperation(doc, projection, presented)` 在结构操作之前用：按输出 8 写回，保留像素的节点不写（它们的呈现只可能是被压缩了）。
50. **侧轨**（planned，[侧栏的侧轨](../../proposals/workbench-side-rails.md)）：左右侧区域贴窗口外缘的竖条。左轨就是活动栏；右轨是投影时在 `body` 横向分支里、右栏一列外侧插入的呈现专属叶（id `rail:auxiliarybar`，保留名单同时覆盖树节点 id 与 `panels` 的键，读入撞名的记录按不合法），形状同活动栏：`fixed`、厚度由宿主给、两侧缝 0，参加过滤、单子塌陷与缝的计算，不进文档与意图回写。
    - **在不在**：右栏有成员容器时右轨在，右栏隐藏、拖到零、放不下被收走时也在（收着的 48）；右栏一个成员都没有时不在，跟着右栏收走。用户显式打开的空右栏照常呈现、可落入，没有右轨。左轨的显隐照旧只看 `hiddenBars`。
    - **三段**：入口带（区域里有成员的容器，一个一项，按入口顺序，点击、拖动、右键同输出 22 的上段）；视图段（当前容器唯一那个视图借来的一段，[workbench.views](../workbench/views.md) 输出 21）；底段（视图段的固定项，主侧再加全局项，最下面是展开按钮，当前容器有视图段时才有）。底段与当前容器的入口总在，视图段在中间独立滚动；连入口与底段都放不下时整条侧轨作为一个滚动区，焦点走到的项先滚进可见处。
    - **落点**：只有入口带是落点（入口之间新建容器、入口上并入），沿纵轴量；视图段与底段是拒绝区，松手是取消，不开新窗；键盘拿起的候选只停入口带。拖动期间侧轨的有效几何冻结到手势结束。
    - **相连与外观**：右栏卡片与右轨相连时相连的两个角不圆、不留缝，接缝短线（`--shell-join-divider`）在内侧、上下缩进；右栏隐藏或拖到零时右轨自己一张圆角卡片，当前容器的入口不按下。卡片宽 48；所有宽度（48、展开宽度、手柄数值、浮动窗的差值）是卡片宽，叶厚按活动栏的算法换算。
    - **展开**：展开状态与宽度按容器记在锚上：`rail?: {[containerId]: {expanded?: true; width?: number}}`，是锚记录的正式可选字段，进形状比较；模板、放弃恢复、动态标签去留、浮出（带到浮动窗记录）、归位（带回锚上）、重置位置（视图从别处回到声明的容器、容器回到声明的区域，清掉这一项）都保留或清掉它。读入时 `expanded` 只认 `true`，`width` 只认有限正数、呈现时按视图段声明的范围夹取，不认的值局部当缺省并给诊断。当前容器没有视图段（别的容器、加载失败、渲染出错、交付撤回）时按收着呈现、记录不改；加载中保留骨架、厚度不变。
    - **预算**：在求解前按所有侧轨收着求出基线（编辑组宽 `E`、最小 `Emin`，右栏宽 `R`）。展开多出 `D = 请求宽 − 48`；`Se = E − Emin`，`Sr = max(0, R − max(视图段声明的聊天下限, 右栏此刻的有效最小宽))`（聊天下限消息视图是 320，只在这次预算里用；有效最小宽是求解器对右栏执行的那个，区域那一行与当前容器里各视图声明的并）。`D ≤ Se` 编辑组让出 `D`；`Se < D ≤ Se + Sr` 编辑组让出 `Se`、右栏这次呈现成 `R − (D − Se)`（不写意图）；`D > Se + Sr` 时能给的宽 `48 + Se + Sr` 不小于下限就按它展开，否则不展开。被拒时按钮 `aria-expanded=false`，悬停与读屏给“窗口太窄”，用户意图不改，窗口变化时重算。只有高度不足时不收轨。别的面板最大化时，在侧轨上展开、打开或新建对话先退出最大化；最大化期间轨宽手柄不可用、不进 Tab。
    - **轨宽手柄**：展开时侧轨内侧边是专用手柄（不复用网格分隔线）：只改这个容器的轨宽，只由编辑组补偿（同上预算），触界即停，不触发区域的收起阈值；`role=separator`、可聚焦、`aria-valuenow/min/max`，方向键每次 10 像素，Home 与双击回缺省；跟手、松手不回弹；一帧至多一次预览求解；一次原子提交只写轨宽；Esc、失去指针捕获、布局版本在手势中变化时整场取消、零写入。收着时没有手柄。
    - **切换容器**：两端有效轨宽相同时照输出 42 原地滚动；不同时整次切换走一次布局过渡，入口的按下底块照常滑。
    - **焦点与读屏**：侧轨整条是一个地标（`navigation`，名称写区域），F6 一站，按从左到右排在左侧栏之前（左轨）或右栏之后（右轨）。收着时入口、视图段各项、底段是纵向工具条（roving tabindex）；展开的列表是视图段自己的区域。焦点在被收起或搬走的视图段里时，交给展开按钮或当前容器的入口。
51. **浮动窗里的视图段**（planned）：声明了视图段的视图在单标签浮动窗里，由视图把视图段画在窗的右边缘（[workbench.views](../workbench/views.md) 输出 21 的 `window`）。
    - **顶格**：窗右上角那一格只放“回到停靠”，由宿主画在视图段顶格；自绘头（输出 39、[workbench.views](../workbench/views.md) 输出 19）的右端不再为框架按钮留位，视图声明的与贡献的标题动作排在聊天头右端，按聊天头实际宽度预算，放不下进“⋯”。“回到停靠”的悬停写出去向。
    - **矩形**：记录矩形是收着的；呈现矩形是记录矩形加展开差值：按视图段声明的缺省宽展开的那段往右长，轨宽比缺省多出（少）的那段往左长（缩），所以拖轨的内侧手柄时窗的右边不动、手柄跟着指针。窗的手柄只结算用户动的边与轴，轨的内侧手柄只结算轨宽，两种预览共用坐标换算与夹取。夹取保证展开后的视图段与“回到停靠”可达：靠屏幕右边时呈现位置往左挪、记录位置不改；宽度不够时按收着呈现，展开请求回报“窗口太窄”。浮动窗记录加正式可选字段 `rail?: {expanded?: true; width?: number}`，规则同输出 50。浮动窗的轨宽拖动是网格里的一种手势事务：拿起时冻结基线与布局版本，连续预览，Esc、失去捕获或版本变了整场取消，松手一次原子提交。
    - **过渡**：窗的飞行沿用布局过渡，视图段在窗的内容里随窗整块飞，只有一份可访问的列表。右轨跟着右栏：右栏随之收走时右轨与右栏的卡片一起摘掉（[ui.nested-grid](nested-grid.md) 输出 45，两侧兄弟没有合拢），编辑区带过渡变宽；右栏还有别的容器时右轨留着。浮动窗只改宽度有布局过渡：展开、收起时窗的宽度过渡到位，过渡中视图段以外的内容（聊天区）宽度不变，视图段按新宽停在最终位置、由窗的右边露出或盖住；轨宽手柄的拖动、键盘与双击回缺省不过渡，窗与视图段同一次到位。中断与减少动态效果复用同一个收口。

## 状态与转换

| 层级 | 内容 | 记录与分区 |
|---|---|---|
| 布局 | `LayoutDoc` | `workbench.layout`：绑定项目时 project / local，否则 user / local |
| 新项目的初始布局 | 去掉动态标签的 `LayoutDoc` | `workbench.layout-template`：user / local |
| 编辑器标签 | `tabId` → 地址、编辑器、语言、preview、固定、光标 | `editor.tabs`：project / local，未绑定只在内存 |
| 只在内存 | 最大化、放不下被收走、拖动预览、当前面板 | 不保存 |

| 初始状态 | 事件 | 下一状态 | 拒绝条件 |
|---|---|---|---|
| 记录未读完 | 打开外壳 | 默认树显示，尺寸手势与依赖就绪的命令不可用 | 无 |
| 无记录 | 读取完成 | 有模板用模板，没有用默认树 | 无 |
| 记录损坏或版本不支持 | 读取完成 | 默认树加诊断，原件保留，普通保存不覆盖 | 不做部分恢复 |
| 记录或模板合法但不合骨架（2026-11-06 以前存的） | 读取完成 | 记录不合：默认树，不读模板，外壳根写一条诊断，下次保存覆盖它；模板不合：当作没有模板。第一次保存也会清掉 `editor.tabs` 里已经不在文档里的标签，开着的标签不恢复 | 不做部分恢复 |
| 记录合法，但锚上有标签、区域里有多标签的面板或分节没有归属（有容器之前存的） | 读取完成 | 默认布局，开着的编辑器标签带进它的编辑组；外壳根写一条诊断，下次保存覆盖这条记录。不迁移。模板这样时当作没有模板 | 不做部分恢复 |
| 恢复尺寸越界 | 读取完成 | 呈现时夹取到最小或最大值并诊断 | 不改写记录 |
| 已恢复 | 结构操作、手势结束、打开、关闭、切标签 | 整棵文档提交，确认后更新已确认值 | 同值不保存 |
| 另一窗口保存了同一记录 | 收到订阅 | 只更新已确认值，本窗口显示不被强改 | 无 |
| 保存冲突 | 条件保存被拒 | 重读 revision，用本窗口的文档覆盖，不合并 | 再失败时保留显示，提供重试与放弃 |

时序与寿命：

- 文档变了或呈现事实变了，呈现树才重算；算出的结果和上一次相同时不重建。重建会取消进行中的边界手势（[ui.nested-grid](nested-grid.md) 输出 9），所以容器尺寸连续变化时只有被收走的集合变了才重建。
- 外层过渡中，叶里嵌的内容尺寸逐帧变化。视图不要把过渡中的尺寸当事实记下来；最终尺寸在过渡结束后稳定。
- 放下后内容的飞行由文档变化触发，提交是同步的；飞行中开始新的手势，飞行直接到终点。
- 一次打开先写 `editor.tabs`，它确认后再写 `workbench.layout`；前者失败后者不写。崩在两次之间只多一条无主的标签项，恢复时丢弃，不会出现引用不存在的标签。属性变化（光标、固定）随时写，删除只在布局存盘前一起写：标签关掉到布局落盘之间刷新，不会把已经关掉的标签恢复成占位。布局记录被保护或读不了时不删。
- `tabId` 是随机不透明串，跨窗口不撞；`editor.tabs` 按键合并，`change` 在最新值上重放。
- 结构键变了时，进行中的拖动在下一次判定前取消；已经开始的飞行照常结束。
- 区域的当前容器只在提交时变：点入口、命令、放下之后（输出 42、43）。拖动的预览、放不下、最大化都不改它。

## 副作用与数据

- 只写上表的三条记录，都显式取 1MiB 上限。16 组、每组 200 标签时 `workbench.layout` 约 250KB。打开、关闭、切标签合并着写（至多 150 毫秒一次，只合并一连串的动作：等得再久，刚打开标签就刷新时这个标签就丢了）；手势结束立刻写。
- **未绑定项目的窗口**：`editor.tabs` 不落盘，所以 `workbench.layout` 存盘前去掉动态标签，只留工具面板与空编辑组。
- **行为变化**：工具视图的摆放从跨项目共享变成每个项目一份。新项目的初始布局取模板，没有就用默认树。
- **切换**：都是新 key，旧的 `layout-sizes-side`、`layout-sizes-panel`、`views-customizations`、`editor.session` 不读、不写、不删。首次启动用默认树，已有用户的布局、尺寸和打开的标签丢一次。回到旧版本读到的是升级前的旧记录，新版本里的调整不会带回去。
- 多窗口整棵树后写胜出，不做按节点合并。
- 视图容器不改记录的版本（`version` 仍是 1）：锚的记录多了入口顺序、当前容器与区域的拖到零，分节的记录多了 `container`。用户拖出来的容器只以 id 出现在入口顺序与分节的归属里，标题与图标不保存（输出 41）（planned）。有容器之前存的记录不迁移，按“状态与转换”回落默认布局。退回没有容器的版本之前要清掉布局记录：那个版本读得进新记录，会把所有容器的分节一起摊开显示（planned）。
- 浮动窗记住的矩形（输出 39 的“记住矩形”，planned）同样不改版本：没有它的旧版本校验不看文档上多出来的字段，照常读入、不用它。
- 视图只发出结构化意图；视图自己的状态由所属插件保存。

## 失败与恢复

结构操作失败时返回 `{ok: false, code, message}`，文档不变（`message` 是英文，只给日志看，和 [`ui/nested-grid`](nested-grid.md) 失败 5 同一个形状）；不合骨架的结果在提交前被拒绝（`rejected`），不管来自哪个入口：

| 码 | 含义 | 调用方怎么办 |
|---|---|---|
| `not-found` | 面板或标签已不存在 | 命令返回 `unavailable`（目标面板或视图中途不在了是 `stale-target`；`move-view` 的目标容器既没有成员也没有声明时同样是 `stale-target`）；拖动整场取消 |
| `rejected` | 接受矩阵拒绝 | 没有落点，不提交 |
| `limit-exceeded` | 超过 256 节点或 16 层 | 给诊断，不提交 |

- 记录损坏、版本不支持：回落默认树并诊断，不阻塞外壳打开；原件保留。
- 保存失败（写入失败、结果未知）：当前显示保留，状态栏“布局未保存”给出原因与重试、放弃；放弃回到已确认值，开着的编辑器标签不算在内（关掉的不回来，开着的留着，它们背后是打开的文档）。`editor.tabs` 保存失败同样显示，不自动重试，点重试才再试。
- 呈现降级：只影响当前呈现，诊断写在外壳根上，不保存。
- 网格的诊断与被拒的提交（[ui/nested-grid](nested-grid.md) 输出 139）记进窗口的诊断，事件 `workbench.grid`，消息里带码。放不下、空间没人吸收、收起或恢复没有空间、交换不成立，这几种是可以预期的降级，记 `debug`；落账之后通知抛出（`notify-failed`）记 `error`；被拒的提交与别的码记 `warn`。同一个问题持续时不重复记（nested-grid 输出 140）。
- 视图加载失败、入口停止：按 [workbench.views](../workbench/views.md)，不拖垮外壳。
- Escape、指针取消、失去捕获、失焦、页面隐藏或目标失效：结束拖放并清除反馈，不提交。

## 边界与兼容

- **归属**：`nbook.workbench`。树、尺寸求解、落点规则、内容层是 `@notnotype/nb-layout` 的能力，接受矩阵、约束、默认树由工作台经策略对象给。
- **公开合同**：命令与公开状态（输出 35、36）、`ViewContext`、贡献点是对插件与 Agent 的合同。视图声明的 `location` 只决定它的隐式容器第一次放在哪个区域，`ViewContext.location` 是视图此刻所在的区域，不在区域里时是 `null`；视图声明另有 `container?`，容器由贡献点 `workbench.viewContainers` 声明（[workbench.views](../workbench/views.md)）；`move-view` 的参数随输出 35 改。删除的命令与状态键不留别名，写进 SDK 作者文档。记录字段是内部合同，靠版本演进。
- **贡献点**：`workbench.editor-area` 给一个区级组件（关闭询问、标签的拖动；属性 `attachTabDrag`）、每个编辑器标签一个的内容组件（属性 `panelId`、`tabId`、`context`；空的编辑组也有一个，`tabId` 是 null；标签换组时不重建，`panelId` 跟着变）与可选的头（属性 `panelId`；不给时没有头，内容占满）；动态标签类型只给内置插件，不进 SDK。
- **标记**：`data-editor-group`、`data-editor-group-active` 在编辑组此刻显示的内容项的根上（每组一个），头的根写 `data-editor-group-head`、`data-editor-group-head-active`。标签写 `data-panel-tab`（标签键，工具视图与编辑器标签都是），标签条那一行写 `data-panel-strip`（面板 id）；`data-no-drag-start` 只是不起拖（标签上的关闭按钮），拖动经过时还算标签条。区域里有分节时锚不进呈现树，`[data-leaf="sidebar"]` 这类按具名面板名字的选择器不再选得到东西；区域打开着、一个分节都没有时，锚就是那块空面板（输出 48），选得到。内容项的根带 `data-content`（它的 key）与 `data-content-leaf`（所属叶 id）。
- **窄屏**：`390 × 844` 无页面级横向滚动，关键按钮可达；不保证好用。
- **Lab**：外壳的 Lab 场景用局部状态，不读写产品布局记录。

## 实现合同

- **公开入口**：`@notnotype/nb-workbench-layout` 的布局文档操作、落点判定与投影、意图回写的两个入口 `applyGestureCommit`、`rebaseForOperation`（`rebaseIntents`、`fixedNodesOf` 不导出，输出 49），`@notnotype/nb-workbench-layout/vue` 的 `TabStrip`，`@notnotype/nb-layout/vue` 的 `NestedGrid`；对插件与 Agent 是命令、公开状态与贡献点（输出 35、36，“边界与兼容”），对编辑器是服务键 `editorPanelsKey`。
- **owner 与依赖方向**：`nbook.workbench` 是树的唯一写者。`nb-layout` 不认识工作台；`nb-workbench-layout` 只经 `nb-layout` 的公开入口用它（[ADR 0054](../../adr/0054-nb-layout-general-library.md)），也不知道角色与骨架的含义，规则经 `LayoutPolicy` 由工作台给。编辑器只经 `editorPanelsKey` 改结构。
- **骨架靠几处守住**：落点只给合骨架的目标（`layoutEdgeTarget`）；具名面板不移动（`moveTabToEdge`）；store 的 `apply` 出口过 `fitsSkeleton`；读记录时有容器之前存的布局回落默认树（`predatesContainers`，“状态与转换”里读记录的回落规则，验收 30）。`default-tree.test.ts` 的随机操作性质测试钉住。
- **文档只在内存里有一份**：打开时从记录读一次，之后记录只管存，别的窗口保存不改本窗口的显示。
- **内容项不换父元素**：这是内容不重建、滚动不丢的唯一保证（[ui.nested-grid](nested-grid.md) 输出 82）。
- **当前容器只在提交时变**：预览不切容器（输出 38），切换是一次提交（输出 42）；当前容器空了由 `settleContainers` 统一换到相邻的容器（输出 43）。`layout-present.test.ts`、`entry-drop.test.ts`、`containers.test.ts` 钉住。
- **切换容器不改尺寸意图**：新容器的约束更紧时只在呈现时夹，切回来回到原来的尺寸（输出 6、42）。`workbench-containers.e2e.ts` 钉住。
