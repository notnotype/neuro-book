# 工作台与插件的嵌套 grid

## 目标与非目标

主工作台和插件能复用与领域无关的 grid，构造左右分栏中嵌套上下分栏的布局，独立调整、恢复和保存自己的尺寸。
本能力补齐最小嵌套样例暴露的尺寸与恢复边界，不提前重构 World Engine 页面。
任意跨窗口移动、多编辑组的产品能力（组会话与布局存储）、第三方插件运行时及任意结构编辑不在本期范围。

已知限制：

- 交换进行中别的布局变化来了时，带照旧走完，裁切窗与静止的底停在开始时的位置，滚完才对上（输出 74）。
- 两根轴交汇处按 Enter：一根轴另一侧吸收不了时，会改去收另一根轴上的面板，前一根的 `no-room-to-collapse` 不再报（恢复方向本来也这样改道）（输出 20）。
- 窄窗口里拖分隔线落账时，被压缩、这次没动的保留像素节点的意图会被写成压缩后的值，放宽后回不到原宽。显式收起与展开不受影响，它们落账不改意图（输出 167）。
- 一个分支里只有保留像素的孩子、还有没人吸收的留白时，分隔条上 Enter 展开的预览按这个分支此刻呈现的总量重排（手势提交要守恒，用不到留白），比松手之后的布局小；落账不改意图，松手后回到意图。

不承诺：

- 别的布局过渡还没走完时开浮动窗，起点是布局里那块叶的矩形，不是它此刻画着的位置，外框与内容一路错开、随过渡收拢（输出 107）。
- 一个分支的子节点经 `setCollapsed` 全部收起时整行留白、没有诊断（输出 147）。

## 术语与参与者

- grid 实例：一个宿主持有的布局树；其节点身份在该实例内唯一。
- 分支：沿横向或纵向分配空间的一组子节点；分支在父布局中的分配尺寸与内部子布局尺寸分别表达。
- 叶：一个内容槽位，具有当前宿主声明的尺寸约束和稳定引用。
- sash：可通过鼠标或键盘操作的分隔条。
- 原语：拥有几何与快照解析的 nb-layout 能力；宿主负责节点引用、持久化地址、版本兼容和恢复投影。
- 外框：网格为每块叶画的盒，矩形由布局结果算出，裁切里面的东西。
- 内容项：宿主经 `contents` 交给网格的一块内容，属于一块叶，不在叶外框里（输出 80）。
- 停放：内容保持最后一个非零尺寸、隐藏、不可交互、不进 Tab 顺序与读屏，但不卸载（输出 116）。
- 带：交换里一串整块平移的组（输出 61）。

## 输入与前置条件

输入为当前容器宽高、分支方向、叶与分支约束、稳定节点引用及可选版本化快照。
持久化能力由宿主显式传入，依赖 [storage.persistence](../storage/persistence.md)；原语本身不读文件或浏览器存储。
同一插件有多个 grid 时，宿主明确它们共享或独立的恢复地址，不能根据叶子名称隐式合并。
Grid 的承载盒没有 padding 与 border：测量按它的内容盒算，宿主要留白时加在外层元素上。
公开接口（属性、插槽、事件、组合函数与签名）见 [NestedGrid](../../../packages/nb-layout/src/vue/NestedGrid.md) 与 [grid API](../../../packages/nb-layout/src/grid.md)。

## 输出与可观察行为

标题以“过渡：”开头的各条合称“过渡”，其余组同理（两轴、调整、手势、悬停、拖动、scope、摆放、取整、交换、分隔线、内容层、最大化、浮动窗、停放、Tab、移动焦点、读屏顺序、分支的收起）。旧的小标题“按矩形摆放”即“摆放”组，“Tab 顺序”即“Tab”组，“分隔线的宿主样式”即“分隔线”组。按组名引用时指这一整组，要指一条写编号。
编号在第一次排定后只在末尾追加。

1. **两轴：每轴独立**：外层左右分栏的分配不使用内层上下叶的高度总和作为该列宽度；每一轴分别计算尺寸和约束。
2. **调整：兄弟吸收**：调整叶与分支相邻的 sash 时，可调整分支的外部分配尺寸；兄弟吸收相应空间，容器总尺寸守恒，包含实际分隔条占用。
3. **调整：内层不改外层**：内层上下调整不改变外层列宽。
4. **调整：外层变窄**：外层变窄后内部布局按当前约束重算。
5. **调整：触界**：尺寸触界时只消耗可用空间，不制造负值、非有限数值或超出父容器的累积尺寸。
6. **调整：降级**：约束无法同时满足时返回可诊断降级结果。
7. **手势：边界与提交**：鼠标和键盘调整具有开始、更新和结束边界；结束携带主动改变的节点/字段。
8. **手势：键盘连发**：按键连发不逐帧持久化，释放结束。
9. **手势：取消**：失焦、Escape、pointercancel、卸载和上下文失效取消；取消手势不提交新的保存意图。
10. **手势：程序变化不提交**：测量、挂载、视口变化、快照恢复与临时显隐不被报告为用户提交。
11. **悬停：几何**：静止时可见的接缝保持 1 CSS px，与分隔线的占用（`sashSize`）无关；可见线为居中的覆盖层，不挤压内容；命中带的外扩距离与线的粗细见 [Splitter](../../../packages/nb-layout/src/vue/Splitter.md)。
12. **悬停：光标**：有效悬停立即显示光标：宽度轴为 `ew-resize`，高度轴为 `ns-resize`，同 scope 双轴为 `move`。
13. **悬停：线的显现**：连续命中同一获胜 scope 满停留时长（见 [Splitter](../../../packages/nb-layout/src/vue/Splitter.md)）后，线的 opacity 渐显；交汇处增减命中不重置计时、不闪烁。系统减少动态效果时不渐显，停留时长照旧。
14. **悬停：按下与聚焦**：pointerdown 成功和键盘 focus-visible 立即全亮；active 离开线盒仍保持。
15. **悬停：不抢光标**：非 active 时只有 `buttons=0` 才能占 hover 与光标；别处正在进行的拖动（拖放别的元素、选择文本）经过热区不得抢光标。
16. **悬停：清理**：退出、失焦、禁用、卸载时清掉临时设置的页面级光标与停留计时。
17. **拖动：绝对边界**：pointer 按原始基线边界加累计位移求绝对边界；收起、展开只改约束，不以记忆尺寸重锚；边界位置与收起状态只看原始基线与累计位移。
18. **拖动：收起与展开的阈值**：低于最小尺寸再往里一个阈值（缺省值见 [Splitter](../../../packages/nb-layout/src/vue/Splitter.md)）时收起，回到 `max(最小尺寸, collapsedSize + 恢复阈值)` 且容量允许时展开。
19. **拖动：展开后的线与指针**：在可行的展开区里，线与指针（减去按下时抓取的偏移）的误差不超过 1 CSS px。
20. **拖动：显式收起与展开**：按钮、分隔条上 Enter 的显式收起与展开，能翻时结果和 `setCollapsed` 翻这块面板的标记相同（输出 147）：按比例分的兄弟按份额吸收或让出，保留像素的兄弟不变，展开回到意图（输出 166）。翻了之后最小尺寸之和放不下时保持收起，给 `no-room-to-restore`；翻了之后让出的空间没有兄弟能吸收（兄弟都到上限、都已收起或都保留像素）时保持展开，给 `no-room-to-collapse`；这两种这场手势都没有提交。锁住的面板（输出 168）不参与显式切换。这两种拒绝与锁住的跳过是和 `setCollapsed` 仅有的不同：`setCollapsed` 照样翻，放不下时报 `over-constrained`，没人吸收时留白。
21. **拖动：兄弟的分配**：上一帧解出的尺寸（首帧是原始基线）在当前边界内逐兄弟夹取，再按两侧目标总量由近到远补偿，整体守恒：掉头往回拖时先动挨着 sash 的叶，已被推开的兄弟留在被推到的地方，和拖一段松手再拖一样。
22. **拖动：显式折叠**：显式折叠只改目标兄弟的 `collapsed`，其他保持原状态。
23. **拖动：收起不写成意图**：收起结束不把收起尺寸（0 或 32 一类）写成展开意图，主动合法展开的尺寸可更新意图。
24. **scope：独占**：每个公共 `NestedGrid` 独占一个 scope；不跨独立 scope 拼事务。
25. **scope：命中赢家**：hover 与 capture 按 `composedPath` 由内向外共用有效命中赢家；最内无命中或禁用才让外层。
26. **scope：双轴一场**：同 scope 最多双轴一场。
27. **摆放：矩形**：叶与分隔线是同一父元素的子元素，矩形由布局结果算出，用 `left`、`top` 加宽高摆放（只有跟手的拿起内容用 `transform`，见输出 89）。
28. **摆放：包含块**：外框、内容与浮动窗手柄是里面 `position: fixed` 元素的包含块，各自成层叠上下文。
29. **摆放：交叉轴**：交叉轴拉满父分支，与主轴放不满时留空。
30. **摆放：分支的交叉轴上限**：分支在交叉轴上的上限是子节点里最大的那个：一列全部收起时它放不满，下面留空，不压住同一行的兄弟。
31. **摆放：结构变化不重建**：树的结构变化（拆分、关闭、换位置）不移动、不重建还在的叶：内容的滚动、输入与焦点保留。
32. **摆放：新叶的 DOM 位置**：新叶在 DOM 里紧接在树序的前一块之后，已有的叶不换相对次序。
33. **取整：累加**：沿主轴按设备像素累加：叶的终点取整，缝宽按设备像素取整（至少 1 个设备像素），下一块从上一块的终点加缝宽开始。
34. **取整：缝宽一致**：任意容器宽度、任意设备像素比下，同一占用的缝宽度相同，不随位置跳动。
35. **过渡：判定**：不是手势、也不是容器尺寸变化引起的布局变化（程序开关面板、拆分与关闭叶）时，外框与分隔线用 `--motion-layout`、`--ease-layout` 过渡到新矩形；拖动分隔线、松手落账和容器尺寸变化不过渡。（planned：宿主自己的尺寸手势——网格之外的手柄改了约束或固定尺寸，例如[工作台侧轨的轨宽手柄](workbench-layout.md)输出 50——用 `NestedGrid` 的 `gesturing` 告诉网格，期间的布局变化与它变回假的那一次同分隔线的手势，不过渡。）
36. **过渡：四条边**：每一帧一块的四条边一起到位，不动的那条边一帧也不挪（主线程繁忙、掉帧时也一样）。
37. **过渡：有尺寸的叶**：前后都有尺寸的叶，内容跟着外框逐帧变化，叶里不露空白，结束时等于新矩形。
38. **过渡：新叶的内容**：新叶与从零尺寸出来的叶，内容一开始就是最终尺寸，过渡中不跟外框变化（这期间又有变化时取新的最终尺寸，仍不跟）。
39. **过渡：贴边**：横向贴着外框在动的那条边：外框只有右边在动时（从左边长出来），面板头与内容贴着右边整块平移进来，不像幕布那样被外框拉开；左边在动时（从右边长出来）贴左边，本来就跟着它走；纵向贴上边（从上边长出来时照旧从上往下露出来）。输出 38、48、49 里的“横向贴边”都指这一条。
40. **过渡：嵌套的 grid**：叶里嵌的 grid，容器跟着外层逐帧变化，按容器尺寸变化处理：自己不另外过渡；经 `useGridHost` 接线时，进行中的手势取消（报 `context-changed`）。
41. **过渡：新叶**：新叶的主轴宽度从零长到终点，一条边不动，另一条边跟着让位的兄弟走，中间不露空白；内容按输出 38，贴边按输出 39。
42. **过渡：整棵子树新开**：一整棵子树新开出来时（上一帧没有这个节点，下面也没有一块旧叶，也不是顶替上一帧同一位置上的别的节点；例如一整列新开出来，一节换成一列是顶替、不算）作为一块长：沿它在父分支里的主轴，从上一帧它前后两个兄弟之间的缝长出来（没有这道缝时从不动的那条边），里面的叶、分隔线与内容在另一个方向一开始就是终点，不各自沿自己的分支长。
43. **过渡：新分隔线**：新出现的分隔线跟着外框的边走。
44. **过渡：离开的叶**：离开的叶立即消失，只有一种例外（输出 45）。
45. **过渡：留着的叶：条件**：离开的叶要在过渡里留着，四个条件要同时成立：一整棵子树离开（这一帧没有这个节点，下面也没有留下的叶，也没有被别的节点顶替）；它前后的兄弟这一帧相接，或它在分支一头而挨着的兄弟这一帧伸到了它原来的那一头（它所在的分支因此被摊平、兄弟换了分支也算）；它下面还有挂着的内容（隐藏，不是关掉），或有这一轮被宿主去掉、标了留住的活动内容项（输出 155）；又不在拖动中（没有拿起的内容，宿主也没说拖动在进行）。
46. **过渡：留着的叶：缩回**：留着的叶在过渡里作为一块沿父分支的主轴缩回那道缝（在一头时缩向那一头），过渡结束才摘掉。
47. **过渡：留着的叶：又有变化**：缩回期间又有别的布局变化时接着缩完（又显示回来的除外）。
48. **过渡：留着的叶：状态**：留着的这段时间它算降到零的叶（停放、不可交互、不接指针，焦点照常交出去），只是还画着，内容保持最后的尺寸，横向同样贴着外框在动的那条边整块平移出去（输出 39）。
49. **过渡：降到零的叶**：还在树里、这一轮降到零的叶（宿主把它收起为零）也一样：停放、不可交互，过渡结束前面板头与内容还画着、保持最后的尺寸，横向贴着在动的那条边平移出去，不是先成了一张空卡片再缩回去。
50. **过渡：降到零的叶：接着画**：这期间又有布局变化、它仍为零时接着画到结束，又长出来的照常显示。
51. **过渡：卡片形状：裁切**：宿主给出叶在外框里画成的卡片形状（`leafShape`：相对外框四边的内缩与四个角的圆角）时，内容不跟外框的这些叶在过渡中按这个形状裁，外框与内容外层都裁（内容外层另外裁掉面板头那一条，只圆下面两个角）：露出来的一截始终是一张完整的卡片，不动的那边也留着缝、角是圆的，不是在外框边上被直着切掉。
52. **过渡：卡片形状：投影**：卡片的投影在形状外面，过渡中不画，结束才出现。
53. **过渡：卡片形状：伸出外框**：形状可以伸出外框（某一边的内缩为负），这时宿主给出伸出去那部分的颜色（`fill`）：外框里的东西照旧裁在外框里，伸出去的部分只画这个颜色。
54. **过渡：卡片形状：伸出部分的叠放**：这块外框画在别的外框下面，伸到邻居那里的部分被邻居盖住、只在邻居的空处露出来。
55. **过渡：卡片形状：浮动窗**：浮动窗不按卡片形状裁。
56. **过渡：shapedLeaves**：宿主可以读这一刻按形状裁的叶（`shapedLeaves`），只在这段时间换形状。读到的是这一轮的（见“时序与寿命”）。
57. **过渡：打断**：过渡中开始手势或容器尺寸变化时，进行中的过渡直接到终点。
58. **过渡：重新计时**：连续的变化以最后一次为准重新计时。
59. **过渡：减少动态效果**：系统减少动态效果时没有过渡。
60. **过渡：moving**：宿主可以读这一刻有没有过渡在走（`moving`）；减少动态效果时它一直为假。读到的是这一轮的（见“时序与寿命”）。
61. **交换：整块平移**：宿主可以在一次布局变化之前给出交换（`swap`：离开的叶与换上来的叶、轴、方向、间距，可选的裁切窗），这次变化里离开的一组与换上来的一组不按“过渡”的长出来、消失，而是像胶片一样沿轴整块平移。
62. **交换：方向与间距**：换上来的一组从方向那头滑进来，离开的一组往另一头滑出去，相邻两组相距裁切窗沿轴的长度加间距。
63. **交换：裁切窗**：裁切窗是两组外接矩形按给的四边内缩（px）与四角，在网格里不动，窗外的部分不画，第一帧也不画。
64. **交换：组内一起平移**：外框、内容与组里的分隔线一起平移，尺寸不变。
65. **交换：离开的一组**：离开的一组提交那一刻就停放（不可交互、不接指针，焦点在里面时的处理见“时序与寿命”），过渡结束前还画着。
66. **交换：离开的一组的分隔线**：离开的一组里的分隔线留着、跟着滑、不能拖。
67. **交换：认哪些叶**：离开的叶只认上一帧呈现着、有尺寸、这一帧不在的，换上来的只认这一帧在、上一帧不在的，其余的 id 忽略。
68. **交换：不成立时**：忽略之后有一边为空，或离开的叶还在别的过渡里（长出来、缩回去），这次照常过渡，并经 `issues` 交回原因（`swap-skipped`，输出 139）。
69. **交换：不交换的时候**：拖动中、系统减少动态效果时不交换。
70. **交换：进行中又来一次**：交换还在进行时又来一次（滑到一半又点）：从每一组此刻的位置接着走，所有组同向平移同一段、要换上的那组落到终点，各组不穿过彼此、不跳，每次重新开始都是完整的过渡时长。
71. **交换：要换上的那组已在带上**：要换上的那组已经在带上（正在滑出去又被点回来）时从它此刻的位置往回走，否则接在方向那头最外面那组的后面。
72. **交换：窗外的组摘掉**：此刻与终点都在裁切窗外的组摘掉。
73. **交换：同时只有一条带**：网格同时只有一条带：新给的交换和进行中的带不相交（离开、换上来的叶都不在带上）时，进行中的过渡全部送到终点，这一次当作静止时开始。
74. **交换：交换中的普通布局变化**：交换中来了不带交换的布局变化，带照旧走完（已知限制：裁切窗与静止的底不跟着变，见“目标与非目标”）。
75. **交换：data-swap**：外框、内容与分隔线带 `data-swap`（`in` 是换上来的，`out` 是离开的）。
76. **交换：swappingLeaves**：宿主可以读这一刻在交换里的叶（`swappingLeaves`）。读到的是这一轮的（见“时序与寿命”）。
77. **交换：静止的底**：宿主可以给静止的底（`swap-backdrop`）：交换进行中在所有外框下面、两组外框的外接矩形上画一层宿主的东西（例如一张卡片），拿到裁切窗在这一层里的内缩与四角，交换结束和滑出去的项同一次渲染摘掉。
78. **分隔线：宿主样式**：宿主可以按分隔线（所在分支与两侧节点的 id）给分隔线元素写内联样式（多半是 CSS 变量），在线所占的那一条里画东西，例如两张拼起来的卡片之间那一条的底色；位置与尺寸由网格写，同名的以网格的为准。两侧节点是分支时，宿主拿到的是分支的 id，由宿主取它沿长轴两端的叶。
79. **分隔线：sashDisabled**：宿主可以让某条分隔线此刻不能拖（`sashDisabled`）：指针、键盘都不行，线照画，例如宿主要把它暂时固定。宿主拿到的两侧节点同输出 78，可能是分支的 id；它读的响应式状态变了，结果跟着变。
80. **内容层：摆放**：宿主可以传内容项（`contents`），每项属于一块叶，和叶外框、分隔线是同一父元素的子元素，矩形是叶减去面板头（面板头高度先按设备像素取整）。
81. **内容层：面板头高度变化**：面板头的高度可以变（`insetTop`，例如标签折行）：只有它变了不算布局变化，内容的上边立刻跟，不过渡。
82. **内容层：不换父元素**：内容项从建到销毁不换父元素，所以换叶不重建。
83. **内容层：两层结构**：结构是两层：外层按矩形摆放、裁切、带过渡，它不是叶外框，飞过别的叶时不被它们裁。
84. **内容层：内层尺寸**：内层的尺寸规则同输出 37（前后都有尺寸的叶，内层跟外框）与输出 38（新叶，内层一开始就是最终尺寸）。
85. **内容层：新叶里的内容项**：新叶里的内容项，新建的和停放过的（例如宿主把一组被停放的内容换回来、把收起的整块叶展开）一样：外层从新叶的起点跟着外框长，内层一开始就是最终尺寸，露出来的部分不超出外框。
86. **内容层：紧贴面板头**：叶从零长出来、缩到零（新叶、从零出来的叶、留着缩回去的叶）的过渡中，每一帧内容的上边都是外框的上边加面板头：内容紧贴面板头下面，不落后、不压住它。
87. **内容层：叠放**：叠放固定：外框、内容、分隔线；分隔线之上还有宿主的盖层（`overlay` 插槽，不接指针），再上面是拿起的内容（`lifted`）。
88. **内容层：飞过别的面板**：飞过别的面板的外框与内容抬到分隔线之下、别的内容之上，飞的内容在飞的外框上面（同不飞时）。
89. **内容层：拿起的内容：矩形**：拿起的内容不按叶摆放，矩形由宿主经 `placeLifted(rect)` 给（相对网格根）：跟手的东西直接写元素，不走属性，不引起这个组件重渲染。
90. **内容层：拿起的内容：呈现**：拿起的内容不带过渡，内层占满外层里 `lifted-head` 下面的部分，外层的尺寸一变就跟着重排，不算停放，不接指针。
91. **内容层：拿起的内容：放下**：`lifted` 变成 null 时从那个矩形滑到叶的矩形，内层一次到终点尺寸，不跟外框变化。
92. **内容层：换叶**：内容项换叶时从旧矩形滑到新矩形，即使两块叶都没动。
93. **内容层：停放**：不活动、叶为零、叶暂时找不到的内容项都按停放处理（输出 116），不卸载。
94. **内容层：一站**：一块叶的一站是外框加它活动的内容，Tab、`moveGridFocus`、上次焦点都按这个并集。
95. **内容层：aria-controls**：分隔线的 `aria-controls` 列外框与活动内容。
96. **内容层：兼容**：不传内容项的宿主行为不变。
97. **最大化：盖住**：宿主可以指定一块叶盖住除条（宿主指定要留出的叶）以外全部叶的外接矩形。条落在这个矩形之外才露出来；夹在别的叶之间的条照样被盖住。
98. **最大化：别的叶不变**：别的叶与分隔线的矩形不变、树不变，所以最大化和还原时它们什么都不变。
99. **最大化：被盖住的**：被盖住的叶与内容马上不可交互，内容在过渡结束后隐藏，分隔线不画也不能拖。
100. **最大化：叠放**：这块叶和它的内容压在上面，直到还原的过渡结束。
101. **浮动窗：形状**：宿主可以传浮动窗（`floats`，`{id, rect, gesture?}`；planned：加 `animate?`，见输出 105）：不在树里的叶，矩形由宿主给，排在树的后面（Tab 与读屏也是）。
102. **浮动窗：内容项**：内容项照常归属它，所以进出浮动窗内容不换父元素、不重建。
103. **浮动窗：层叠次序**：后面的压在前面的上面，换次序只改层级，不搬节点。（planned：手柄层同样不搬节点，抬升不让手柄里的焦点与指针捕获丢掉。）
104. **浮动窗：与别的层**：浮动窗都在分隔线、飞行内容之上，在盖层与拿起的内容之下。
105. **浮动窗：矩形变化**：只有矩形变了不算布局变化，不过渡（移动、缩放是手势）。（planned：宿主给这扇窗标 `animate: true` 时，它的矩形变化算布局变化、走布局过渡，例如最大化与还原、窗里的视图段展开与收起（[workbench-layout.md](workbench-layout.md) 输出 51）；这一次或上一次渲染里它带着 `gesture`，或这次变化是松手放开（输出 172）时，照旧不过渡、跟手。）
106. **浮动窗：出现与消失**：出现、消失，内容进出照常过渡。
107. **浮动窗：新开的窗**：新开的窗（上一帧没有这块窗，它的活动内容上一帧活动着、有尺寸，在另一块叶里）从那块叶上一帧的矩形出发：外框、手柄与内容同一个起点、同一个终点，整张卡片从原处拿起来飞到窗的位置，面板头随外框逐帧重排，投影与圆角第一帧就有；不按新叶从零长，否则窗第一帧就在终点、内容单独飞过去。
108. **浮动窗：新开的窗的例外**：实时布局拖动落下开的窗不按输出 107，从拿起的卡片出发（落地，见 [工作台布局](workbench-layout.md) 输出 38、39）。
109. **浮动窗：回到树里**：窗回到树里、叶的 id 不变时，外框照常从窗的位置过渡回去，压在别的面板上面（窗盖在它要回去的位置上也是）。
110. **浮动窗：回到树里：淡去**：窗的投影、底色与圆角随过渡淡去，用加速的曲线，到快落地才没，看得出是一张卡片飞回去落下。
111. **浮动窗：最大化**：最大化时浮动窗不算被盖住，还在上面。
112. **浮动窗：投影与圆角**：投影与圆角在外框自身（`--layout-card-*`）。
113. **浮动窗：手柄**：插槽 `float-chrome` 是手柄：网格根的直接子元素，矩形同窗，叠在它的内容上面，外层不接指针。
114. **浮动窗：手势中不接指针**：`gesture` 为 `move` 时外框与内容不接指针，判定才看得到底下。
115. **浮动窗：整窗拖动**：整窗拖动时宿主经 `placeFloat(id, offset)` 给相对记录矩形挪了多少：外框、内容、手柄一起挪，直接写元素，`floats` 不变；`null` 回到原处。
116. **停放：条件**：已发布的布局里叶曾有过非零尺寸、现在在任一轴上为零时，内容保持最后一个非零尺寸、`visibility: hidden` 且 `inert`，不进 Tab 顺序与读屏。
117. **停放：重新有尺寸**：重新有尺寸时不重新排版。
118. **停放：手势预览**：手势预览不会把内容停放，拖过阈值又拖回来内容不闪。
119. **停放：从零拉出**：从零往外拉时内容在拖动中就解除停放。
120. **停放：第一帧**：第一帧还没有尺寸时不算停放。输出 116 的“曾有过非零尺寸”只对 `leaf` 插槽的内容容器成立：载入时就为零的叶，内容容器不停放；内容层的项按输出 93，量到容器之后叶为零就停放。
121. **Tab：叶内与走出**：焦点在 grid 里时，叶里按 DOM 顺序走；走出一块时按树的先后跳到下一项（叶、分隔线交替，跳过没有可聚焦元素的），与 DOM 顺序无关。
122. **Tab：内容自己处理**：内容自己处理了 Tab（`preventDefault`）或输入法正在组字时不接管。
123. **Tab：走出最后一项**：走出最后一项时离开这个 grid。
124. **Tab：DOM 序等于树序**：DOM 序等于树序时全是浏览器的原生行为。
125. **Tab：从外面进来**：DOM 序与树序不一致时，从 grid 外面按 Tab 进来落在树序的首或尾。
126. **Tab：点击之后**：DOM 序与树序不一致时，点击不可聚焦的地方之后按 Tab 从点的那一块按树序走。
127. **Tab：不改落点**：DOM 序与树序不一致时，程序聚焦与点击不改落点。
128. **Tab：外框与内容不接焦点**：外框和内容都不接焦点，点空白不打断内部滚动区的键盘滚动。
129. **移动焦点：落点**：`moveGridFocus(from, direction)` 在叶之间按树的先后移动，回到这块上次的焦点，没有就是第一个可聚焦的元素。
130. **移动焦点：跳过**：没有可聚焦元素的叶跳过。
131. **移动焦点：嵌套**：嵌套时内层先走，走到头交给外层，最外层绕回。
132. **读屏顺序**：DOM 序与树序不一致时，根元素的 `aria-owns` 按树的先后列出叶、分隔线与没停放的内容项，无障碍树的顺序与视觉一致。
133. **分支的收起：配给**：收起策略可以配给叶，也可以配给分支。
134. **分支的收起：收起时的尺寸**：分支收起时，它在父分支主轴上的尺寸是 `collapsedSize`，里面的叶在这一轴上都取这个尺寸，为零时按停放处理（输出 116）。
135. **分支的收起：展开后**：分支内部沿自己那一轴的分配不变，展开后各叶回到收起前的尺寸。
136. **分支的收起：长度为零的分隔线**：收起为零的分支里，叶之间的分隔线长度为零：不可聚焦、不进指针命中、不能拖，展开后恢复。
137. **分支的收起：最小尺寸**：收起为零的节点（叶或分支）在两根轴上的最小尺寸都按零算，窗口放不下时不把它和它里面的叶算作要收走的。
138. **分支的收起：阈值与恢复**：收起的阈值、从零拉回、Enter 与显式恢复同叶（输出 18、20）。
139. **诊断：形状与码**：诊断是 `{code, message, params?}`，和失败 5 同形少一个 `ok`：`code` 给程序分支，`message` 是英文、只给日志看，`params` 的值只有字符串与数字。`params` 里 `cause`（为什么）、`axis`、`id`（诊断所在的分支、叶或面板）三个名字在所有诊断里意思相同，其余是度量（取两位小数）。码集合开放，`cause` 是码之下的细分，宿主不认识的 `cause` 按码处理。诊断码与失败 5 到 7 的码不相交。

    | 码 | `cause` | 什么时候 | 度量 |
    |---|---|---|---|
    | `over-constrained` | `min-total` | 分支的最小值合计超过主轴空间，按最小值比例降级 | `available`、`required` |
    | | `fixed-overflow` | 固定尺寸面板装不下留给它们的预算，压到最小值 | `available`、`required` |
    | | `leaf-min` | 叶在某根轴上的空间小于它的最小值 | `available`、`required` |
    | | `sash-overflow` | 分隔条合计超过主轴空间，分隔条与子节点一起压缩 | `available`、`required` |
    | | `cross-min` | 分支在交叉轴上的空间小于它的最小值 | `available`、`required` |
    | | `range-overflow` | 拖动时这根轴的有效范围装不下分支总量，这次不改几何 | `total`、`min`；所有面板都有上限时还有 `max` |

    | `no-collapse-policy` | | 要折叠的面板没有收起策略；只出现在直接求解收起的结果里，手势不会发 | |
    | `swap-skipped` | `no-leaving`、`no-entering`、`busy` | 交换不成立（输出 68） | |
    | `not-published` | | 宿主接纳了提交但没有发布匹配的布局 | |

    诊断从两条路来：`NestedGrid` 的 `issues` 事件（手势的诊断、被拒的提交、`not-published`、`swap-skipped`）与布局重算（布局重算的诊断、`notify-failed`）。用 `useGridHost` 的宿主从它的 `onIssues` 一个出口收两条路（输出 145）。事件里带 `ok` 的元素（`"ok" in issue`）是被拒的提交，就是失败 6 的那个失败，已经回滚；它的码可能是宿主自己的。
140. **诊断：结果是快照，通知只发新出现的**：
    - 求解与预览的结果（`layout().issues`；`gesture-update` 载荷的 `issues` 与 `layout.issues`）是这一次求解的全部诊断，逐条、参数完整。要知道现在有哪些问题、数是多少，读它们；通知不说诊断什么时候消失。
    - 两条路都只发新出现的：键是码、`cause`、`axis`、`id`，同一次求解里同一个键最多一条。布局重算这一路，这次有、上一次重算没有的才发，消失再出现会再发；`contextKey` 变了算重新开始；发布空布局（承载盒隐藏、没有网格）不算消失，再显示时持续的诊断不重发；`grid` 换实例不算重新开始。手势这一路，一场手势里同一个键只发一次，下一场重新算；键盘每按一次键是一场手势，按住不放算一场。预览布局自己的诊断不经通知，松手落账后的布局重算照常发。
    - 被拒的提交、`not-published`、`swap-skipped`、`notify-failed` 每发生一次发一条。一个失败只发一条。
    - 松手、取消与卸载时宿主的回调（`issues`、`gesture-update`、`gesture-cancel` 的监听，`onIssues`）抛出，手势已经结束、高亮与光标已经复原，异常照常冒出去；拖动途中某一帧里抛出，手势照常进行。只有落账之后的通知抛出时库接住它（交 `reportError`，没有时 `console.error`），提交照样算落账。

141. **主题变量**：Vue 层读的 CSS 变量都是 `--nb-layout-*`；除组件自己写在行内的几何外，每处 `var()` 都带清单（`NB_LAYOUT_THEME_VARS`）里的回退；装了 nb-ui 的宿主经它的桥接取主题的值（[`theme/system`](../theme/system.md) 的“变量体系”）；不装时用回退。输出 35、112 与组件文档里写的 `--motion-layout`、`--layout-card-*` 这类名字是主题写的旧名，库读的是对应的 `--nb-layout-*`。宿主旋钮（`--nb-layout-splitter-seam` 这类主题不写的）由宿主直接设新名，不经桥接。
142. **过渡：缺省时长**：宿主没给 `--nb-layout-motion-layout` 时（不装 nb-ui、也没自己设），布局过渡按缺省时长走：CSS 的回退与库里等过渡收尾时读到的缺省取清单里的同一个值。时长要写成 `ms` 或 `s` 的字面值；写成别的（`none`、`calc()`）时库的计时当 0。系统减少动态效果时 nb-layout 读的时长在根上全部归零，宿主在根上设的时长也压不过（输出 59）；设在子树元素上的时长不在这个保证之内。
143. **文案**：组件的读屏名称与提示（分隔条、可排序列表、浮动窗把手）经 `LAYOUT_TEXT_KEY` 注入的翻译函数取；没有注入时用库自带的 `en-US` 目录（源语言），参数照旧代入。只有一种语言的宿主用 `./text` 的 `layoutCatalogTranslate(语言)` 注入自带目录里的那一种（`en-US` 或 `zh-CN`），传别的语言时抛 `RangeError`（[`ui/i18n`](i18n.md) 输出 8 的例外）。
144. **承载盒的尺寸**：`NestedGrid` 量自己的根盒的布局尺寸（`clientWidth`、`clientHeight`，不随祖先的变换缩放），挂载后量到就发 `extent` 事件，两轴变了才再发；同步发，监听在同一个调用栈里拿到。卸载前发 `null`，`NestedGrid` 被条件渲染摘掉时父组件的监听收得到；宿主自己整个卸载时，宿主作用域里的侦听已经停了，收不到。
145. **宿主接线**：`useGridHost` 交回一包 `bindings`（树、布局、版本、上下文键、停用、提交处理、接 `extent`、`issues` 与 `gesture-start` 的处理），整包绑到 `NestedGrid` 上就能接手势；尺寸取自 `NestedGrid` 发的 `extent`，没量到可用尺寸（null，或宽、高为 0）时布局为空、`disabled` 为真。布局重算的诊断与 `NestedGrid` 的 `issues` 事件都交给 `useGridHost` 的 `onIssues` 一个出口。
146. **承载盒为零**：量到的宽或高为 0 时布局为空、分隔条停用（`aria-disabled`，不在 Tab 序里）；叶照常挂着，只是没有尺寸。
147. **收起与展开的入口**：`grid.setCollapsed(id, collapsed, options?)` 只翻这个节点的收起标记，尺寸意图不动；之后的 `layout()` 与把同一棵树的标记翻了再建相同：按比例分的兄弟吸收差额，保留像素的兄弟不变，展开回到它的意图（输出 166）。不读布局，不要容器尺寸。`toggleable: false` 不影响它。分隔条上的 Enter 能翻时结果相同；放不下或没人吸收时 Enter 拒绝、锁住的 Enter 跳过，`setCollapsed` 照样翻（输出 20、168）。`options.locked` 同时改锁（输出 168），不给时锁不变。返回 `{ok: true, changed, collapse}`：`changed` 是收起标记或锁有没有变，都没变时为 false、树不变；`collapse` 是调用之后这个节点的收起策略。失败：`id` 不存在 `not-found`；`id` 是根 `invalid-argument`（`field: "root"`）；没有收起策略 `not-collapsible`。
148. （已删除：网格的节点没有恢复尺寸，展开回到意图，见输出 166。）
149. **宿主的收起入口**：`useGridHost` 的 `setCollapsed(id, collapsed, options?)` 调 `grid.setCollapsed`（第三个参数同输出 147），标记或锁变了时版本递增、布局重发（诊断照常经 `onIssues`）并通知 `onApplied`（输出 170），没变时版本不变；没有网格时返回 `not-ready`（`missing: "grid"`）、版本不变。
150. **落账前的布局**：`onApplied(change, before)` 的 `before` 是这次落账之前发布的布局：手势是手势开始时呈现的那份，`host.setCollapsed`、`host.setSize` 是调用之前的那份；`onApplied` 被调时宿主的 `layout` 已经是落账之后的。
151. **开发模式的配置检查**：`setLayoutDevChecks(true)` 打开之后（缺省关），下面几种接线错误在浏览器控制台警告；同一个 `NestedGrid`（或同一个 `useGridHost` 宿主）的同一种只警告一次，警告里带 `contextKey`（没给时写明没有）。开关关着时都不警告。警告不改变失败与 `issues` 事件。
    - `NestedGrid` 接了提交处理、没有停用，有两侧都能调（主轴上最小与最大尺寸不同）的边界，而这些边界的分隔条全是 0 宽（`createGrid` 的 `sashSize` 缺省 0）；挨着固定尺寸节点的缝不算；
    - 要提交时没有提交处理；提交处理不是函数（例如整包绑定之后又写了 `@gesture-commit`，两者合成数组）；提交处理的返回值不是 `{ok: …}` 的形状（例如返回 `undefined`、Promise、布尔值）。三种是三条警告；
    - 整包绑定的宿主：手势开始时 `NestedGrid` 用的 `contextKey` 与宿主此刻的不同（模板里另写了 `context-key`）；`revision` 与宿主此刻的不同（模板里另写了 `:revision`）。
152. **分隔线的显示名**：`NestedGrid` 的 `paneLabel(id)` 返回的显示名代进分隔线的读屏名称（输出 143 的“调整 {before} 与 {after} 的宽度”），挨着分支时问分支 id，一次渲染里可能问几次（同 `sashKind`）；没给、返回空或空串时用节点 id。交换里滑出去的分隔线用它离开前最后一次的显示名。独立 `Splitter` 的面板配置 `label` 同样代进读屏名称，没给时用面板 id。显示名由宿主翻译好再给。
153. **结构操作不改兄弟的意图**：`addLeaf`、`removeLeaf`、`moveLeaf` 不改兄弟的尺寸意图（保留像素的、按比例分的、收起中的都不改）。布局时按比例分的份额按比例重分，保留像素的兄弟呈现不变（约束与容器放不下时照常压缩）；空出或多出的空间由按比例分且没收起的兄弟吸收，没有这样的兄弟就留白并给 `unabsorbed-space`。
    - 按比例分的新叶没给主轴意图（省略或为 0）时，取这一支里不是保留像素的兄弟（收起中的也算）的正意图的平均；这些兄弟的意图全是 0 时取 0；没有这样的兄弟时取 1。
    - 按比例分的节点移到别的分支时，同样按新叶重取目标分支的平均；保留像素的节点移到同向的分支时意图不变，移到方向不同的分支返回 `invalid-argument`（`field: "fixed-cross-axis"`），树不变。
154. **设一块保留像素的尺寸**：`grid.setSize(id, px)` 把保留像素的节点（叶或分支）沿父分支主轴的意图设成 `px`，夹进它自己在这根轴上的最小与最大（收起中也按展开时的约束夹）；兄弟不动，不读布局。收起中的节点也只改意图，展开时回到它（输出 166）；刚性的节点同样可设，夹进声明的主轴最小与最大（输出 169）。返回 `{ok: true, changed, size}`：`size` 是存下的意图；`changed` 是意图有没有变，没变时树不变；有收起策略时另带 `collapse`（同输出 147）。失败依次判：`id` 不存在 `not-found`；`id` 是根 `invalid-argument`（`field: "root"`）；按比例分的节点 `wrong-sizing`；`px` 不是有限数 `not-finite`（`field: "px"`）；`px` 为负 `invalid-argument`（`field: "px-negative"`）。
155. **关掉的内容留到过渡结束**：内容项的 `leave` 缺省 `"unmount"`，宿主把它从 `contents` 去掉就卸载（同以前）。标了 `"retain"` 的活动内容项被去掉、而它的叶这一轮在缩回去（按输出 45 留着缩回的离开的叶，或这一轮降到零的叶）时，库用它最后一次的渲染留到过渡结束：不再调宿主的 `content` 插槽，带 `data-content-leaving`、`inert`、看得见、跟着叶缩回去，不进 F6 与 Tab 的站点、不进 `aria-owns`，过渡结束（含容器尺寸变化把过渡送到终点）才卸载。
    - 不留的情形：叶不动、只是内容被换掉或去掉；不活动的；拖动中；它的叶在交换里滑出去；减少动态效果。过渡中又来一次布局变化时，叶还在缩回去的接着留，叶回到了树里的摘掉。
    - 过渡中宿主又给了同一个 key：以宿主的为准，沿用同一个元素，回到照常渲染。
    - 焦点在里面时照样发 `content-parked`，key 是宿主刚去掉的那个。
    - 冻住的只是这一项插槽的调用：里面的组件照常按自己的响应式依赖更新，交给子组件的插槽在子组件的渲染里调，那里面按 key 查宿主已删的数据会抛错；这时库补一条报错说明原因，原错误照常交给应用的错误处理。删数据与改 `contents`、改树要在同一次刷新里。
156. **带着留着的内容离开的叶**：有输出 155 留着的内容项时，按输出 45 留着缩回的离开的叶，面板头（`leaf` 插槽）都停在最后一次渲染，不再调宿主的插槽，限制同输出 155；离开的叶按子树整组留，同一棵离开的子树里没有留着内容的叶也是。交换里滑出去的叶、没有留着的内容时的离开的叶（区域隐藏）照常渲染，插槽读到的仍是这一轮的（“时序与寿命”）。
157. **内容层：拿起的内容：留住**：拿起的内容项这一轮不在 `contents` 里时（宿主的预览把来源摘掉了），网格留住它：实例不卸载，叶是拿起那一刻它所在的叶（之后的预览把它摆到别的叶上也不改），不活动，矩形照旧由 `placeLifted` 写；`lifted` 变成 null 之后按那时的 `contents` 处理，不在了就卸载。宿主要在摘掉它的那一次渲染里（或更早）给出 `lifted`：先摘掉、下一轮才给 `lifted` 的，网格没有可沿用的那一项，实例照常卸载。
158. **开发模式：诊断没有出口**：开关同输出 151。`useGridHost` 没给 `onIssues` 的宿主在建立时警告一次：布局重算的诊断与被拒的提交会被丢掉。有意不收诊断的宿主给一个什么都不做的 `onIssues`。只看 `useGridHost` 的选项：直接用 `NestedGrid` 的宿主不在这一条里。库不把诊断本身打到控制台，开关开与关时 `onIssues` 收到的都一样。
159. **开发模式：起拖时过渡还在走**：开关同输出 151。`NestedGrid` 的 `dragging` 从假变真的那一刻，布局过渡还在走时，警告一次：宿主的拖动会话起拖时没有调 `settleMotion()`，判定量到的是过渡中间的矩形。同一个 `NestedGrid` 只报一次。下面几种不算：宿主在 `dragging` 变真的同一次更新里改了布局、过渡是这次才开始的；系统减少动态效果（没有过渡）。实时布局的会话自己调 `settleMotion()`（[layout-drag](layout-drag.md) 输出 23）。
160. **拆分：同向并入**：`splitLeaf` 的方向与目标叶的父分支相同时，新叶插进这个父分支、挨着目标（`before` 在前、`after` 在后），不新建分支；`branchId` 照样要合法、不重复，只是没用上。目标是根叶或方向不同时照旧新建分支（验收 7）。并入时新叶与目标分掉目标在父分支主轴上的意图：底数是目标的意图，为 0 时取这一支的平均一份（输出 153 的规则）；新叶得底数乘 `ratio`，目标留下其余；这一支的意图全是 0 时两块都取 0，和兄弟一起均分。兄弟的意图不动（输出 153）。并入不加深，只加一个节点。
161. **拆分：平分**：`ratio` 可以是 `"even"`：并入时新叶取这一支的平均一份（同输出 153 的“按比例分的新叶”），目标的意图不动；新建分支时等于 0.5。
162. **拆分：保留像素的目标**：目标叶保留像素时 `splitLeaf` 返回 `wrong-sizing`（`expected: "weight"`），树不变：它的意图是像素，新叶与目标都分不到有意义的份额。
163. **根不展平成保留像素或可收起的节点**：增删或移动之后根分支只剩一个孩子、它保留像素或带收起策略时，根分支留着；布局照常（保留像素的照旧呈现，余下留白并给 `unabsorbed-space`）。其余只剩一个孩子的分支照旧换成这个孩子。
164. **复制网格**：`grid.clone()` 交回一份独立的网格：树、意图、约束、`sizing`、收起策略与状态，连同建网格时的选项（`sashSize`、`encodeRef`）。之后改其中一份，另一份的树、快照与布局都不变；叶的 `ref` 是同一个宿主对象。
165. **从快照建网格**：`restoreGrid(snapshot, resolveRef, options)` 按失败 7 校验快照，成功时交回 `{ok: true, grid, dropped, clamped}`，失败时是失败 7 的形状、没有 `grid`。约束、`sizing`、刚性与收起策略只来自 `resolveRef`。原地的 `grid.restore` 照旧：解析结果没给的约束、`sizing`、刚性与收起策略回落到当前树里同 id 的节点。这些都是运行期策略，不写快照。
166. **展开回到意图**：网格的节点只有一份展开尺寸，就是它的意图（`size` 在父分支主轴上的分量）：保留像素的回到意图的像素，按比例分的回到它的份额。收起不改意图；`setCollapsed(false)`、按钮与分隔条上的 Enter 都回到它，拖动展开跟随指针、松手时按呈现写回（输出 23）。网格的收起策略里没有恢复尺寸（独立 `Splitter` 没有意图，它的 `restoreSize` 照旧）。宿主要跨会话保存收起状态，存意图（快照或自己的记录）与 `collapsed` 就够了。
167. **落账保住意图**：`resizeBranches` 里一个分支应用了本场的收起变化之后，用现有意图布局就得出目标时，这个分支的意图一个也不改：显式收起与展开都这样落账，窄窗口里被压缩的保留像素兄弟不会被写成压缩值。否则照输出 2 反解；反解之后这个分支里还有收起着的按比例分的孩子时，展开着的按比例分的孩子的新意图按同一个倍数缩放，使它们的和等于落账前的和。呈现不变，收起着的那块展开时拿回收起前的份额。例：两块按比例分各 500、拖到把 b 收起，a 呈现 1000、意图仍是 500，展开 b 回到 500。三块意图各 300、呈现各 400，拖 b｜c 把 c 收起（呈现 `[400,800,0]`）：a、b 的意图写成 200、400，和仍是 600；展开 c 得 `[266.67,533.33,400]`，c 回到收起前的 400。
168. **锁住收起状态**：收起策略带 `locked: true` 时，拖动不越过阈值收起它，也拉不开收着的它；分隔条上的 Enter 跳过它（同 `toggleable: false`，作用于另一侧）；`resizeBranches` 要翻它的标记时整批失败，给 `collapse-locked`（失败 5）。宿主的 `setCollapsed` 照常翻它；锁经 `setCollapsed` 的 `options.locked` 改，或建树、恢复时在策略里给。独立 `Splitter` 同样遵守。
169. **刚性的节点**：保留像素的节点标 `rigid: true` 时，它在父分支主轴上的最小与最大尺寸都是它的意图（先夹进声明的主轴最小与最大），拖动的级联补偿不改它。最小尺寸之和放不下时先按比例压别的节点，刚性的最后才让：刚性的之和也放不下时只在刚性的之间按比例压，别的为 0；诊断照旧是 `over-constrained`（`min-total`）。交叉轴不受影响；按比例分的节点标了不起作用。`rigid` 和 `sizing` 一样是运行期约束，不写快照。
170. **宿主的落账通知**：`useGridHost` 的 `onApplied(change, before)` 在三种落账之后各调一次：手势提交（`kind: "gesture"`，带 `commit`、`result`），`host.setCollapsed`（`kind: "collapse"`，带 `id`、`result`），`host.setSize`（`kind: "size"`，带 `id`、`result`）；后两种只在 `changed` 时调。三种都带 `collapsed`：这次翻了收起标记的节点（id → 是否收起）。宿主直接调 `grid.*` 再 `invalidate()` 的不通知。`onApplied` 抛出时同手势：库接住、报 `notify-failed`，落账照样算数（输出 140）。
171. **宿主的设尺寸入口**：`useGridHost` 的 `setSize(id, px)` 调 `grid.setSize`，`changed` 时版本递增、布局重发并通知 `onApplied`（输出 170），没变时版本不变；没有网格时返回 `not-ready`（`missing: "grid"`）、版本不变。
172. **浮动窗：松手的起点**：宿主拖动中用 `placeFloat(id, offset)` 挪过这扇窗。`placeFloat(id, null)` 之后、下一帧之前发布的变化里，它要过渡的部分（回到树里或离开的外框、它的内容）从松手时画着的位置出发，即记录矩形加最后一次的偏移；这次它仍是浮动窗、矩形就是拖到的位置时不过渡（输出 105）。下一帧之后才发布的，照旧从记录矩形出发。（planned）
173. **浮动窗：抬升的请求**：指针在一扇浮动窗上按下（外框、内容、手柄层，含其中嵌的网格；在捕获阶段判，手柄阻止冒泡也收得到），或焦点进入它时，它不是 `floats` 的最后一个就发 `float-raise`（窗的 id）；已在最上面不发。网格不改次序，宿主把它挪到 `floats` 末尾。（planned）
174. **摆放：叶此刻的矩形**：expose 的 `leafRect(id)` 交回树里这块叶此刻的矩形（相对网格根，CSS px）。它与网格渲染用的是同一份摆放：手势预览中是预览的，最大化时最大化的那块是盖住的外接矩形，取整与网格相同。不在树里的（浮动窗、离开中的叶、不存在的 id）交回 null；不给过渡的中间帧。在计算属性里调用，摆放变了会重算。（planned）
175. **浮动窗：夹取**：`clampFloatRect(rect, area, keep?)` 把窗夹进区域。`area` 是带原点的矩形（相对网格根），或只有宽高（原点为 0）。窗比区域宽或高时缩到区域。`keep` 是至少留在区域里的宽与高：不给时是整扇窗，给了也不超过窗缩后的尺寸。窗的上边总在区域里。结果只用于呈现，宿主不写回记录。（planned）
176. **浮动窗：缩放的边界**：`resizeFloatRect` 的 `bounds.area`（矩形）给出时，跟着指针的边不越过它；起点就在区域外的边不再往外，也不往里跳；不动的边不变；最小尺寸优先。`max` 可以不给（不限）。`FloatWindowHandles` 的 `area` 属性同义，指针与键盘缩放都按它。（planned）
177. **浮动窗：手柄的结算**：`FloatWindowHandles` 松手时，在同一个同步段里先发 `preview(null)`，再发 `commit(rect, direction)`（没动不发 `commit`）；Esc 与失去捕获只发 `preview(null)`。`direction` 是这次动的边（形状同 `LayoutFloatResize`，0 是这一轴没动；键盘缩放是右下角）。`rect` 从已夹取的呈现矩形算起，没动的那一轴是夹过的值；要保住记录的宿主只取 `direction` 不为 0 的轴。（planned）

## 状态与转换

| 状态 | 事件 | 结果 |
|---|---|---|
| 未挂载 / 无快照 | 获得容器尺寸 | 默认布局；不保存 |
| 静止布局 | 用户开始调整 | 捕获当前实例、节点与基线；进入调整中 |
| 调整中 | 用户继续调整 | 更新内存几何与主动改变字段，未结束不持久化 |
| 调整中 | 正常结束 | 提交一次最终意图；保存由宿主负责 |
| 调整中 | 取消、节点撤销或上下文失效 | 停止手势；已产生的提交由原宿主收口，不改写新实例 |
| 任意布局 | 容器 resize / 临时隐藏 | 重新呈现，保留用户已保存的尺寸与偏好 |
| 静止布局 | 恢复兼容快照 | 校验完成后一次发布有效布局；失败不留下半棵树 |
| 键盘Enter按下 | 显式折叠/恢复 | 一次求解、keyup一次commit；重复Enter忽略，本场不混方向/Home/End |
| 键盘方向/Home/End | 同场连续调整 | 冻结baseline，未结束不混Enter；Escape回滚，下一场从发布几何开始 |

时序与寿命（宿主可以依赖）：

- 手势：一次按下命中的最多两根轴属于同一场手势；拖动中发布预览布局，松手把一次提交交给宿主，由宿主一次原子落账，同步验证手势、成功之后才通知（输出 7、26）。提交与预览的数据形状见 [NestedGrid](../../../packages/nb-layout/src/vue/NestedGrid.md)。
- 手势中途容器尺寸、结构、context 变化取消手势，报 `context-changed`（输出 9）；设备像素比变化时也取消（planned）。通知异常只报 `issues`、不反悔几何（宿主的回调抛出时手势照样收尾，见输出 140），自身提交不造成预览自取消；缺 grid 或容器尺寸时不接受提交。
- `content-parked`：内容层的项从没停放变成停放、而焦点还在这一项里时发出，焦点去哪由宿主决定。交换里离开的一组在提交那一刻停放，焦点在里面时同样在这一刻发出。焦点不在这一项里（例如在面板头的按钮上）、内容放在 `leaf` 插槽里、内容被卸载或换了叶时都不发。
- `swap`：和那次布局变化（新的 `node`、`layout`）在同一个同步段里给；`token` 变了才算一次新的交换。它被这之后的第一次布局变化用掉，不管那次按不按交换走（拖动中、手势预览中、减少动态效果、矩形没变时静默放弃）；这一轮刷新里没有布局变化就作废。
- `moving`、`shapedLeaves`、`swappingLeaves`：在插槽渲染时读到的都是这一轮的。

## 副作用与数据

原语只改变所属实例的内存状态并报告交互意图（不创建业务树、不保存），无网络、文件或跨实例副作用。
快照包含恢复所需的稳定引用、结构和用户分配意图，不包含组件实例、DOM、运行代次或存储句柄。
运行期约束来自当前宿主；旧快照中的 min/max 不能覆盖新版宿主约束。
快照格式是版本 2；版本 1 与不认识的版本拒绝恢复，原件不改写（失败 2）。
容器尺寸的测量：`null` 表示未挂载，0 是真实零。命中用 client rect，指针位移按冻结的根 rect 与 layout 的比例转换成 CSS 布局 px，不乘设备像素比。
落点几何（插入位置、指示线、边缘落点）的规则见 [DropFeedbackOverlay](../../../packages/nb-layout/src/vue/DropFeedbackOverlay.md)。

## 失败与恢复

失败项编号为失败 1 到 7，只在末尾追加。

1. 畸形 children、重复节点身份、非法方向与非有限尺寸必须返回诊断，不抛出未处理异常或污染已发布布局。
2. 未知高版本拒绝恢复并保留原布局或安全默认；宿主禁止普通保存覆盖原件（planned）。
3. 暂时缺少引用时可过滤当前呈现，但宿主保留原始记录，后续调整已知节点不能抹掉未知部分（planned）。
4. 部分引用过滤与整体格式非法分别报告；重复身份无法可靠定位时整体拒绝，不任意覆盖同名节点。
5. **结构操作的失败形状**：改尺寸、设尺寸、按分支调整、插入、拆分、移除、移动失败时返回 `{ok: false, code, message, params?}`，树不变；失败 1 说的“返回诊断”在结构操作上就是这个形状。`code` 给程序分支；`message` 是英文，只给日志看，宿主不按它分支；`params` 的值只有字符串与数字，宿主可以直接交给 [`ui/i18n`](i18n.md) 的翻译端口拼自己的文字。

    | 码 | 什么时候 | `params` |
    |---|---|---|
    | `not-found` | 节点、分支或父节点不在 | `id` |
    | `wrong-node-kind` | 要叶给了分支，或要分支给了叶 | `id`、`expected`（`leaf` 或 `branch`） |
    | `wrong-axis` | 不沿主轴调整 | `id`、`orientation`；调整的是节点时加父分支 `parent` |
    | `not-finite` | 调整量、尺寸、尺寸意图或设的尺寸不是有限数；比例不是有限数也不是 `"even"` | `field`，加 `value` 或 `id`（尺寸另加 `side`：`baseline` 或 `target`；设的尺寸是 `field: "px"` 加 `id`） |
    | `invalid-argument` | 根节点没有可调整的父分支、手势尺寸没有覆盖全部直接子节点、尺寸为负、方向或插入侧不认识、比例不在 0 与 1 之间、保留像素的节点移到方向不同的分支、设的尺寸为负 | `field`（`root`、`sizes-cover`、`size-negative`、`orientation`、`side`、`ratio-range`、`fixed-cross-axis`、`px-negative`），加 `id`、`side` 或 `value`（后两种只加 `id`） |
    | `limit-exceeded` | 这次操作会让节点数超过 256，或让新加、移动的叶落到第 16 层之下（根算第 1 层） | `limit`（`nodes` 或 `depth`）、`max` |
    | `duplicate-id` | id 已被占用 | `id`、`with`（`existing`：树里已有；`new-leaf`：新分支与新叶同 id） |
    | `into-own-subtree` | 把节点移进它自己的子树 | `id`、`parent` |
    | `not-conserved` | 手势目标的总量与基线不等 | `id`、`target`、`baseline` |
    | `stale-baseline` | 手势的基线已经失效 | `id` |
    | `not-collapsible` | 要收起的面板没有收起策略 | `id`、`branch` |
    | `wrong-sizing` | 要保留像素的节点给了按比例分的；拆分的目标叶保留像素 | `id`、`expected`（`fixed` 或 `weight`） |
    | `collapse-locked` | 按分支调整要翻一块锁住的面板的收起标记（输出 168） | `id`、`branch` |

    同一个子节点基线与目标都不合法时报基线那一侧。传进来的非法值在 `value` 里写成字符串（`NaN` 写作 `"NaN"`）。
6. **提交的返回**：`onGestureCommit` 返回 `{ok: true}` 或失败 5 的形状；拒绝时回滚预览并给诊断（“状态与转换”）。宿主自己写这个回调时可以用自己的码拒绝（写法见“边界与兼容”）。`useGridHost` 接提交时，落账时结构操作的失败原样转交失败 5 的码，提交自己的码是：

    | 码 | 什么时候 | `params` |
    |---|---|---|
    | `not-ready` | 网格或承载盒尺寸还没有 | `missing`（`grid` 或 `host-size`） |
    | `stale-context` | 提交带来的工作面与宿主此刻的不同 | `expected`（宿主此刻的）、`actual`（提交带来的） |
    | `stale-revision` | 提交带来的版本与宿主此刻的不同 | `expected`、`actual` |
    | `stale-size` | 容器尺寸在手势里变了 | 无 |
    | `handler-missing` | 宿主没有接 `onGestureCommit` | 无 |
    | `handler-threw` | 宿主的提交回调抛出 | 无（`message` 带异常的文字） |
7. **恢复的结果**：快照恢复返回 `{ok: true, dropped, clamped}`，或失败 5 的形状加 `dropped`、`clamped`。`dropped` 每项是 `{ref, code: "unknown-ref"}`（失败 3）。恢复的码：

    | 码 | 什么时候 | `params` |
    |---|---|---|
    | `invalid-snapshot` | 格式不对（失败 1、4） | `field`；某个节点的问题加 `id` |
    | `unsupported-version` | 版本不支持（失败 2） | `version` |
    | `unresolved-root` | 格式没问题，但根的引用解析不了，整体恢复不出来；`dropped` 里有那条引用 | 无 |
    | `duplicate-id` | 节点身份重复（失败 4） | `id`、`with: "existing"` |
    | `limit-exceeded` | 超过 256 个节点或 16 层（根算第 1 层） | `limit`、`max` |

    `unresolved-root` 与 `invalid-snapshot` 分开：前者是引用暂时缺（宿主保留原件，等引用回来），后者是原件坏了。

## 边界与兼容

本能力补充 [工作台布局](workbench-layout.md) 的布局消费合同。
nb-layout 拥有领域无关的类型、算法和交互边界；主应用与插件拥有约束、快照解释与 Storage 地址。
原语不引用主工作台 Part 名，不依赖 Pinia，不开启 Splitter `autoSaveId` 旁路。
嵌套 sash 的旧限制由本能力覆盖的场景逐项解除；其它未覆盖结构操作继续保留已有限制，不能据一个样例宣称任意布局均已支持。
外框、内容与浮动窗手柄是里面 `position: fixed` 元素的包含块（输出 28）：要盖住整个窗口的东西（对话框、拖影、菜单）宿主要 Teleport 到 `body`。
公开的标记：`data-swap`（输出 75）、`data-leaf`、`data-grid-scope` 等的取值与含义见 [NestedGrid](../../../packages/nb-layout/src/vue/NestedGrid.md) 的“公开的标记与变量”。
公开面：`package.json` 里每个子路径的入口（`./lab-sources` 只给应用的 Component Lab，不算）是一行一个名字的显式清单，入口里的名字就是公开面；文件里别的导出不是公开面，不承诺。`gesture-start`、`gesture-cancel` 的载荷类型是 `GridGestureStart` 与 `GridGestureCancellation`，字段见 [NestedGrid](../../../packages/nb-layout/src/vue/NestedGrid.md)；手势来源与取消原因的类型是 `SashGestureSource`、`SashGestureCancelReason`。
开发模式：根入口的 `setLayoutDevChecks` 打开配置检查（输出 151、158、159）；它不读 `import.meta.env`，宿主在自己的开发构建里调。
CSS 变量：`NB_LAYOUT_THEME_VARS`（根入口）列出库读的全部 `--nb-layout-*` 与各自的回退；README 的变量表只承诺其中主题级的一小批（颜色、圆角、阴影、时长、焦点），其余是内部名字，可以改名（输出 141）。
工作台的用法：用分支的收起表达整个区域拖到零（[工作台布局](workbench-layout.md) 输出 11、12）；把 `moveGridFocus` 登记成命令，缺省键位 F6、Shift+F6（[workbench.commands](../workbench/commands.md)）。
失败的码集合开放：新增码不算破坏，调用方按码分支时要有默认分支；码的写法同 [`ui/i18n`](i18n.md) 输出 13 的开放错误域（小写短横线，不含 `:`、`.`、空白，不超过 64 个字符），宿主可以拿码查自己目录里的文字。

## 验收与 Smoke

1. Given 左列与右侧上下分栏，When 调整外层 sash，Then 分支和叶均可吸收空间，外层总宽守恒；调整内层 sash 不改变外层宽度。
2. Given 两轴约束与窄容器，When 拖过边界、缩放容器并恢复，Then 几何有限、符合约束或报告明确降级；视口夹取不写回。
3. Given 同名叶分别位于主 grid 与插件 grid，When 调整其中一个并重新挂载，Then 两份记录和恢复尺寸互不影响（planned）。
4. Given 鼠标、键盘连发、失焦与取消，When 完成或取消调整，Then 主动提交次数和字段符合合同，程序布局不产生提交。
5. Given 畸形/高版本快照、未知引用、重复身份，When 恢复再保存合法修改，Then 无未捕获异常，当前布局不半更新。宿主保留原件与未涉及的未知部分（planned）。
6. Given 同项目双标签订阅，When 一个窗口拖动而另一个保存，Then 当前手势不断开，冲突由宿主处理（planned）。
7. Given 任一侧的叶，When 沿与父分支不同的方向拆分并调整新 sash，Then 新分支继承原外部分配、两个子叶按比例分掉原意图，外层另一侧尺寸不变；When 沿父分支的方向拆分，Then 新叶并进父分支、与目标按比例分掉目标的意图，兄弟不变、树不加深；重复身份、非法比例、保留像素的目标与节点、深度上限被拒绝且树不变。
8. Given 叶里有输入框、滚动内容和实例编号，When 在它左边拆分、关闭兄弟、把它换到树的另一处，Then 实例编号不变，输入、滚动与焦点保留；拆分与关闭后 DOM 序仍等于树序；换位之后焦点在 grid 里时 Tab 与 `moveGridFocus` 按新的树序走，浏览器的无障碍树也按新的树序。
9. Given 缝 1、4、7 px 与设备像素比 1、1.25、1.5，When 枚举容器宽度量三块等分的缝，Then 同一占用的缝宽度相同；Given 程序调整一块，When 过渡中量它的内容，Then 内容与外框同宽，结束时等于新矩形；Given 拆出新叶，When 过渡中量新叶的内容，Then 一开始就是最终尺寸，`ResizeObserver` 只报一次；拖分隔线与改窗口尺寸没有过渡。
10. Given 三块叶、每块带内容项，When 内容项换到另一块叶，两块叶都不动，Then 内容从旧矩形滑到新矩形，实例不变，输入与滚动保留；结束后点它命中内容；Tab 与 `moveGridFocus` 按树序。Given 拆出新叶，When 过渡中量新叶的内容，Then 一开始就是最终尺寸，`ResizeObserver` 只报一次。Given 设备像素比 1、1.1、1.25、1.5、1.75、2，When 读内容顶与面板头底，Then 没有缝也不重叠。
11. Given 一列里两组叶、每块带内容项，放慢过渡，When 给交换并换组、停在过渡中几个时刻，Then 两组都整块平移、尺寸不变，裁切窗外没有像素（第一帧也没有），组里的分隔线跟着滑；给了静止的底时它在外框下面、只在交换中；滑到一半反向，两组的区间不相交、回到原处；滑到一半点回正在滑出去的那组，它从此刻的位置往回走；滑到一半点另一列的交换，前一列直接到终点、后一列从静止开始完整的一段；给了交换但没有布局变化、之后改一次尺寸，什么都不滑。

Smoke 入口：[`e2e/lab-nested-grid.e2e.ts`](../../../packages/neuro-book/e2e/lab-nested-grid.e2e.ts)、[`e2e/lab-grid-structure.e2e.ts`](../../../packages/neuro-book/e2e/lab-grid-structure.e2e.ts)、[`e2e/lab-grid-panels.e2e.ts`](../../../packages/neuro-book/e2e/lab-grid-panels.e2e.ts)、[`e2e/lab-grid-swap.e2e.ts`](../../../packages/neuro-book/e2e/lab-grid-swap.e2e.ts)。

- 公开入口：`@notnotype/nb-layout`、`./vue`、`./text`、`./locales` 四个入口里写出的名字（一行一个名字的显式清单，[`exports.test.ts`](../../../packages/nb-layout/src/exports.test.ts) 守着）。网格这一面常用的是 `createGrid` 与结构操作（含 `splitLeaf`）、`grid.clone()`、快照（含从快照建网格的 `restoreGrid`）、`resizeBranches`、`setCollapsed` 与 `setSize`，`./vue` 的 `NestedGrid`、`useGridHost`、`useLayoutExtent`、`moveGridFocus`（`useGridLayout` 是 `useGridHost` 用的内部模块，不从入口导出）。签名见 [NestedGrid](../../../packages/nb-layout/src/vue/NestedGrid.md) 与 [grid API](../../../packages/nb-layout/src/grid.md)；接入的起步例子与“我要做 X 用哪个导出”见包的 [README](../../../packages/nb-layout/README.md)，宿主接线见 [useGridHost](../../../packages/nb-layout/src/vue/useGridHost.md)。
