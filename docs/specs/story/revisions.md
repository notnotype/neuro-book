# 剧情图谱：图的修订（覆盖层与待确认）

## 目标与非目标

抽取出来的图会有错和没定下来的地方：马甲核对只能写“可能是同一人”的候选，抽取会把人名建成马甲、把一个人的昵称挂在别人名下。本能力给用户一层可审阅、可撤销的修订：确认或驳回抽取留下的候选身份，手动连两个对象，改对象的种类，把一个称呼挪给另一个对象。修订按书单独保存，不改抽取数据；套用之后，查询、查看器、问答看到的都是改过的图。

明确不承诺：

- 第一版只有身份连接（确认、驳回、手动连）、改对象种类、挪称呼三类。合并对象、改说法的类别或挂靠不做。
- 不做事后扫描（让模型通读图找问题）：它是以后另起的修订来源。本 Spec 的数据与状态为它留了位（来源 `scan`、状态 `pending` 的存储项），第一版没有人写这类项。
- 不做自动采纳（核对结果不经确认直接生效）与“有待确认就暂停抽取”。状态里留“自动采纳”一档（`by: "auto"`），以后加配置不改数据格式。
- 不改抽取数据与导入的数据文件；不重新抽取。
- 单用户、本机，不做多人协作与冲突合并。

## 术语与参与者

- **修订**：一次对图的改动或一个决定。存放在书目录的修订文件里。
- **待确认项**：还需要用户决定的修订。第一版只有一种来源：数据里没有决定、也没被后文确认的**候选身份说法**（确定性为候选的身份类说法，见 [`story.queries`](queries.md#术语与参与者)的“身份连接”）。
- **来源**：待确认项由谁提出：`persona-check`（抽取时的马甲核对，见 [`story.ingest`](ingest.md) 输出 20）、`extraction`（抽取模型自己写的候选）、`user`（用户手动改）、`scan`（预留）。
- **依据位置**（`evidence`）：一条修订所依据的原文段，记作 `章.段`。修订从这一段起生效，阅读位置早于它时看不到。
- **状态**：`pending`（待确认）、`adopted`（已采纳）、`rejected`（已驳回）、`closed`（后文已明说，自动关闭）、`withdrawn`（用户撤销了自己的修订）、`stale`（对不上，已不套用）。
- **采纳方式**（`by`）：`user`（用户确认）或 `auto`（预留）。

## 输入与前置条件

- 书级方法的通用规则（`book`、`at`、`perspective`、`cursor` 与 `limit`）同 [`story.queries`](queries.md#方法清单)。写入类方法的 `evidence` 参数就是依据位置，不用 `at`。
- 书的数据是导入的或抽取得来的都能修订；书库格式不认识时只读，写入类方法得到 `unsupported_format`。

| 方法 | 种类 | 主要参数 | 结果里必须有的字段 |
|---|---|---|---|
| `revisions.list` | 读 | 可选 `state`（五种状态之一，或 `processed`：已采纳、已驳回、后文已确认三类）、`source`、`entity`（只要涉及这个对象的项，人物卡用）；长列表 | 每项：`id`、`op`、`state`、`source`、`by`、`summary`（一句话）、`entities`（涉及的对象编号）、`evidence`、`quote`（依据那一段原文，截到 120 字）、`refs`（出处）、`decidedAt`、`undoable`；`counts`（各状态条数，全书的，不受筛选影响） |
| `revisions.confirm` | 写 | `statement`（候选身份说法的 id） | `revision`（修订项）、`version` |
| `revisions.reject` | 写 | `statement`、可选 `reason` | 同上 |
| `revisions.link` | 写 | `a`、`b`（对象 id 或名字）、`evidence`、`certainty`（`candidate` 或 `certain`） | 同上 |
| `revisions.kind` | 写 | `entity`、`kind`（对象种类）、`evidence` | 同上 |
| `revisions.moveName` | 写 | `text`（称呼）、`from`、`to`（对象）、`evidence` | 同上 |
| `revisions.undo` | 写 | `revision`（修订项的 `id`） | 同上 |
| `revisions.evidence` | 读 | `entity`、可选 `text`（称呼）；长列表 | 每项：`ref`（章.段）、`text`（段原文）、`names`（这一段里该对象的称呼） |

- `book.info` 另给 `revisions: {pending, stale}`；它不带阅读位置，是全书的数，给命令行与脚本看。查看器的角标用 `revisions.list` 的 `counts`（按阅读位置算）。
- 写入类方法的结果里的 `version` 是修订文件的版本号，每次成功写入加 1。

## 输出与可观察行为

1. **套用。** 书级查询（含搜索、原文、图、问答用的工具）看到的是套用修订后的数据；套用发生在阅读位置的可见性之前，所以每条修订自带依据位置时，晚于阅读位置的修订看不出来。没有修订的书，所有结果与没有本能力时逐字相同。
2. **确认候选。** `revisions.confirm` 把一条候选身份说法变成确定：说法的位置、文字与持有人不变，只有确定性变为确定。确认之后，身份连接的状态、秘密里依据它的那些身份、人物卡的“同一身份”、关系图上的线都按确定的算。说法在记录里带标记 `revision`（显示“你确认的”）。只能确认候选：已经是确定的、不是身份说法的，得到 `revision_not_candidate`。
3. **驳回身份说法。** `revisions.reject` 收任何连两个不同对象的身份说法（不含否定），候选的与确定的都行（issue 266：抽取常把“取法名”“认出”写成确定的身份，用户要能撤掉这条连线）。驳回之后，这条说法在所有查询里不存在（记录、身份连接、搜索、人物卡都没有它，由它派生的“本人知道”也随之没有），它的 id 不再被列为待确认项。驳回的项在“已驳回”里还能看到，可以撤销。驳回只撤这一条说法：两个对象之间或同一身份组内还有别的连线时，它们仍在同一身份里，要把这些连线都驳回才拆开（每条说法的编号在人物卡 `entity.card` 的 `identities[].statement` 里）。确定的说法被驳回后，不再使候选“后文已确认”（输出 8）。不是身份说法、否定的或连的不是两个对象，得到 `revision_not_candidate`。
4. **手动连两个对象。** `revisions.link` 新写一条身份说法：`family` 为身份，对象是 `a`、`b`，位置是 `evidence`，`kind` 为 fact，说法文字是“{a 的显示名}就是（可能就是）{b 的显示名}。”，显示名取依据位置上的（规则同 [`story.ingest`](ingest.md) 输出 20，不泄漏之后才出现的称呼）。带 `revision` 标记（显示“你加的”）。用户自己写的说法记为已采纳，不进待确认。`a` 与 `b` 必须在依据位置之前已经出现，且是两个不同的对象。
5. **改对象种类。** `revisions.kind` 让对象的种类从依据位置起变成给定的种类；依据位置之前仍是原来的种类。所有按种类分的结果（`entities.list` 的 `kind`、人物卡、关系图的点、出场与同场的统计、无名对象的判断）按阅读位置上生效的种类给。给的种类与那一处原本的相同，得到 `revision_conflict`。
6. **挪称呼。** `revisions.moveName` 把 `from` 对象名下的一个称呼从依据位置起属于 `to`：
   - 依据位置及之后，原文里这个称呼的出现、阅读页的链接、出场与同场的统计、按称呼找对象，都指向 `to`；依据位置之前的出现不变（不改过去，也不剧透）；
   - `from` 的称呼表里，成立位置在依据位置及之后的该称呼记录被去掉，之前成立的保留；`to` 的称呼表在依据位置多一条这个称呼（非主名，说明写“由修订挪入”）；`to` 在依据位置已经有同文字的称呼时不重复添加；
   - 称呼表、原文里的称呼出现与按称呼找对象由同一套规则一起算出，三处不会各自为政。
   称呼必须在 `from` 名下出现过，`to` 必须在依据位置之前出现过，否则得到 `revision_target_not_found`。
   - 依据位置及之后，原文里这个称呼的出现、阅读页的链接、出场与同场的统计、按称呼找对象，都指向 `to`；
   - 依据位置之前的出现不变（不改过去，也不剧透）；
   - `from` 的称呼表里，依据位置之后才成立的该称呼记录被去掉，之前成立的保留。
   称呼必须在 `from` 名下出现过，`to` 必须在依据位置之前出现过，否则得到 `revision_target_not_found`。
7. **待确认列表。** `revisions.list` 的 `state=pending` 列出阅读位置 P 可见（说法的位置不晚于 P）的待确认项：没有决定的候选身份说法，且不是后文已被确认的。按依据位置、再按 id 排序。项的 `summary` 与 `refs` 只用 P 之前的称呼与出处。
8. **后文明说自动关闭。** 候选身份说法所连的两个对象之间，在 P 处已经有一条确定的身份说法（被驳回的不算）时，这条候选的状态是 `closed`：不在待确认里，在“已处理”里写“后文已确认”。这是现算的，不写存储，不需要用户操作，也不能撤销。
9. **撤销。** `revisions.undo` 对确认或驳回的项：回到待确认；对用户自己的修订（手动连、改种类、挪称呼）：状态变为 `withdrawn`，改动不再套用；对 `stale` 的项：丢弃（状态变为 `withdrawn`），用户可以在当前的图上重新做一遍。撤销本身留在这条修订的历史里。对 `closed`、`pending` 的项撤销得到 `revision_conflict`。
10. **同一目标的决定。** 对同一条候选说法再次决定：与现有决定相同的是空操作且成功；不同的以后一个为准，先前的决定留在历史里。
11. **保留与对应。** 追加新章与接着抽不改变已有的修订，抽取又提交一章后修订照样套用。抽取的整理会把建重的对象并成一个（被并入的编号记在留下的对象的 `mergedFrom` 里），修订所指的对象因此换了编号时按 `mergedFrom` 跟过去。每条修订记它所指目标的“锚”（对象：id、首次出现位置与最早的称呼；说法：id、位置与文字）。目标按 id 与位置、文字对得上，或按 `mergedFrom`、按位置与最早的称呼唯一对上时照常套用；对不上时状态变为 `stale`：不套用，出现在待确认里并写“对不上，已不套用”，保留原来的文字与依据，用户可以丢弃（输出 9）；锚后来又对上时自动恢复，不丢决定。`stale` 是现算的，不写回文件。书重新导入或删除后重抽是新的一代，不继承修订（见“时序与寿命”）。
12. **汇总提示。** 抽取完成时命令行汇总里，有待确认的候选就写“N 条待确认”，N 按全书算（阅读位置在尾部）；网页里待确认的数目是导航“待确认”的角标（[`story.viewer`](viewer.md) 输出 58）。
13. **命令行。** `nbstory revisions list|confirm|reject|link|kind|move-name|undo`，参数与上面的方法一一对应，默认文字输出，`--json` 给方法的结果；退出码与错误码同 [`story.cli`](cli-skill.md)。
14. **抽取侧。** 抽取记录里记下马甲核对写下的说法编号；编出的书里这些说法带 `origin: "persona-check"`，抽取模型自己写的候选不带，列表据此区分来源 `persona-check` 与 `extraction`；这个字段不影响任何查询的结果。
15. **依据段。** `revisions.evidence` 列出阅读位置 P 之前、给定对象（可再限定一个称呼）出现的段落（`章.段`、原文、里面的称呼），按位置从近到远分页；写入类对话框用它选依据，列表只含 P 之前的段。
16. **状态的优先级。** 待确认列表与“已处理”从抽取得来的原始记录与修订文件算出，不从套用后的图算（套用后候选已经变确定或已经不存在）。同一项状态冲突时的优先级：`stale`，然后是已有的决定（`adopted`、`rejected`），然后是 `closed`，最后是 `pending`。

## 状态与转换

| 从 | 到 | 条件 |
|---|---|---|
| （候选说法，无决定） | `pending` | 现算：说法可见，没有决定，没有被后文确认 |
| `pending` | `adopted` | `revisions.confirm` |
| `pending` | `rejected` | `revisions.reject` |
| `pending` | `closed` | 后文出现了所连两个对象之间确定的身份说法（现算） |
| `adopted`、`rejected` | `pending` | `revisions.undo`（对确认、驳回的项） |
| （无） | `adopted` | `link`、`kind`、`moveName` 成功 |
| `adopted`（用户的修订） | `withdrawn` | `revisions.undo` |
| 任一（待确认、已采纳、已驳回） | `stale` | 目标对不上锚（例如整理合并后找不到、数据被替换） |
| `stale` | 丢弃（`withdrawn`） | `revisions.undo` |
| `stale` | 原状态 | 锚又对上 |

时序与寿命：

- 一次查询固定在开始时的那一代、抽取进度与修订版本上；查询进行中写入修订，不影响它，也不让它读到之后的数据。分页游标还绑定修订版本，修订变了得到 `cursor_invalid`。
- 同一本书的修订写入之间没有丢失：每次写入都建立在写入时最新的修订之上，两次并发的写入（含不同进程，例如命令行与独立服务）都成功、都保留。
- 写入成功返回时修订已经落盘并对之后开始的查询可见。
- 书被删除时修订随书删除；同 id 重新导入或抽取是新的一代，不继承旧修订；写入进行中书被删除并换代，也不会让旧代的修订出现在新一代里（文件带代号，读者认代号）。
- 抽取在运行中提交一章时不改修订文件，修订写入不改抽取数据与阅读状态。

## 副作用与数据

- 修订文件 `<书库>/<书 id>/revisions-<版本>.json`：`{format: 1, generation, version, items: [...]}`，`generation` 是它所属的书的一代的代号。读写只认 `generation` 与当前一代相同的文件，当前的是其中版本最大且读得出来的那一份；读不出来的（内容损坏）跳过并回退到更早的完整版本；没有文件等于没有修订。书被删除后同 id 换了一代，旧代遗留的文件因为代号不符不会被读到，也不会被继承。每项记：`id`（`r1`、`r2`……，同一本书内不复用）、`op`（`identity.confirm`、`identity.reject`、`identity.link`、`kind.set`、`name.move`）、`state`、`source`、`by`、操作的参数、依据位置、锚、`reason`、创建与决定的时间、状态变化的历史。
- 写入：读到当前版本 n，在它的基础上算出新内容，先写完整的临时文件，再用硬链接发布为 `revisions-<n+1>.json`（目标已存在时失败，所以读者看到的总是完整的文件）；别的进程抢先发布了 n+1 时失败，重读后在新内容上重算再写（所以并发写入不丢）；成功后只删最近 50 个版本之外的旧文件（版本号不马上空出来：否则读到旧版本的写入者晚到时会把已回收的版本号当空位再发布，覆盖别人的写入）；写入前与发布之后各核对一次书目录仍是这一代（换了代就撤掉自己刚发布的文件并报 `book_not_found`）；代号不符的遗留文件按它占住的版本号处理：发布撞上它时、书目录确实还是这一代才删掉它再发布。沿用书库的原子性约定（[`story.queries`](queries.md#副作用与数据)）；文件里的格式版本不认识时只读，不写。
- 数据集的可选字段：说法的 `origin`、`revision`（由哪条修订产生）；这是对象类 schema 允许多出的字段（[`story.queries`](queries.md#边界与兼容)），旧的程序照常读。
- 原文、图与修订都只在本机书库里。

## 失败与恢复

| 编号 | 码 | HTTP | 含义 | 调用方怎么办 |
|---|---|---|---|---|
| R1 | `revision_target_not_found` | 404 | 说法、对象、称呼或依据位置在这本书里不存在，或在依据位置之前还没出现 | 用 `revisions.list` 与 `entities.list` 查正确的目标 |
| R2 | `revision_not_candidate` | 409 | 要确认的说法不是候选身份说法，或要驳回的说法不是连两个对象的身份说法 | 换一条说法 |
| R3 | `revision_conflict` | 409 | 改动没有意义或不允许：`a` 与 `b` 是同一个对象、种类没变、称呼已经属于目标、撤销一个不能撤销的项 | 按错误里写的原因改参数 |
| R4 | `revision_not_found` | 404 | `undo` 的修订编号不存在 | 用 `revisions.list` 查 |
| R5 | `evidence_invalid` | 400 | 依据位置不是已抽取的原文段 | 改成已抽取的一段 |
| R6 | `unsupported_format` | 415 | 书库或修订文件的格式版本不认识 | 升级程序 |

同时沿用 [`story.queries`](queries.md#失败与恢复) 的 F1、F2、F7、F9、F10。

## 边界与兼容

- **公开接口**：本 Spec 的方法表、结果字段与失败码；新增方法与可选字段不算破坏兼容。
- 修订文件的格式是内部格式，不承诺跨版本读写之外的兼容；用户不应手改。
- 问答的“没核实的出处”与回归基准读的是套用后的图，所以修订会改变问答答案；回归基准按没有修订的书算。

## 验收与 Smoke

1. **确认不剧透。** 样例书里有一条第 5 章的候选身份说法：阅读位置在第 4 章时待确认列表与人物卡里都没有它；到第 5 章出现；确认之后第 4 章的结果与确认前逐字相同，第 5 章的身份连接变确定。
2. **驳回与撤销。** 驳回一条候选后，它从列表与所有记录里消失，出现在“已驳回”；撤销后回到待确认，所有结果与驳回前逐字相同。驳回一条确定的身份说法同样如此，只是撤销后回到原来的确定状态，不进待确认。
3. **后文自动关闭。** 候选说法所连的两个对象在后一章有确定的身份说法：阅读位置在后一章时该候选在“已处理”写“后文已确认”，不在待确认里；在前一章时仍在待确认里。
4. **手动连接。** 连两个对象并带一句依据：说法的文字用依据位置上的称呼；依据之前的阅读位置看不到；`a` 与 `b` 相同得到 `revision_conflict`；依据在对象出现之前得到 `revision_target_not_found`。
5. **改种类。** 把一个马甲在依据位置改成人物：依据之前 `entities.list` 里仍是马甲，依据及之后是人物；出场统计按阅读位置上生效的种类算。
6. **挪称呼。** 把“小萱萱”从银色闪光挪给洛萱：依据位置之前的出现仍属于银色闪光，之后的出现、阅读页的链接与按称呼找对象指向洛萱；银色闪光在依据位置之前的称呼表不变。
7. **追加与整理。** 有修订的书追加新章后，修订照样套用、版本不变；抽取的整理把被修订的对象并进另一个对象后，修订跟到留下的对象上；目标在数据里确实没有了的，该项为 `stale`，出现在待确认里，原文字保留，丢弃后消失。
8. **并发与持久。** 两次并发的 `revisions.confirm`（不同的说法）都成功，之后两条都已确认；服务重启后修订仍在；删书后修订随之消失，同 id 重新导入没有旧修订。 写入中途进程被杀，读者仍读到上一个完整版本；写入检查之后书被删除并用同 id 重新导入，新书没有旧修订。
9. **没有修订。** 样例书不写任何修订，所有查询的结果与没有本能力时逐字相同。

Smoke：真实独立服务与 Chromium，用小抽取（样例书前 10 章）确认“十万水星可能就是苏天晴”、再撤销；用魔女学院的小抽取（20 章）把“银色闪光”改成人物、把“小萱萱”挪给洛萱，看人物卡与阅读页的链接。
