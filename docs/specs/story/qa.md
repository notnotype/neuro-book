# 剧情图谱：内置问答

## 目标与非目标

用户问书库里某本小说的问题，nb-story 自己调用模型回答：按“读到哪里”不剧透，答案带结论类型与出处，出处都是这个对话读过的原文。问答是一次对话：第一问开始一个对话，之后可以在同一个会话里追问，Agent 看得到前几轮。每一问由同一个 Agent 答：它用 [`story.queries`](queries.md) 的查询当工具查图、搜索、读原文；小说的问题用作答工具交结构化答案，程序校验、不合格就退回让它改；寒暄、澄清这类不需要查书的话，Agent 直接用文字回复。引擎跑在 [`agent.harness`](../agent/harness.md) 上；第一个入口是命令行 `nbstory ask`，以后的网页问答页与 NeuroBook 插件共用同一个引擎与同一份问答记录。

明确不承诺：

- 没有网页问答页：留给后续 Task，那时再改 [`story.viewer`](viewer.md) 的“不做问答”。
- 不保证答对：图是自动抽取的，模型也会错；答对率只由“验收与 Smoke”的回归门槛约束。
- 不限制一问的步数与退回次数（[`agent.harness`](../agent/harness.md) 不设步数上限）；只限制读原文的章数（输出 5）。没交答案的 Agent 不会被提醒（输出 10）。
- 文字回复不经校验、不被退回：里面写的出处只检查、标出没核实的（输出 24），不保证它们都读过。
- 对话中途不能改做法；图当目录的对话可以改阅读位置（输出 41），全读对话的位置不能改，要换就开新对话。改位置之后，对话历史里已经出现过的、晚于新位置的内容无法撤回：程序只保证之后的工具与结构化交卷的出处按新位置裁剪（输出 41）。
- 从两处同时追问同一个对话时，保存前的核对挡住绝大多数覆盖（输出 25），但核对与写入之间还有极短的窗口，不保证一定不丢一轮。
- 对话之前的一问一条的旧记录可以列出、显示与删除，不能续问（F8）。
- 不做中文分词与按相关度的检索排序：`search` 只按词拆开、按命中词数排序（[`story.queries`](queries.md) 输出 15）。
- 不接 NeuroBook 的模型角色与密钥接口：单独使用时读自己的配置文件。
- 外部 Agent 的用法（[`story.cli`](cli-skill.md) 的 Skill）不变，Skill 不引导外部 Agent 调 `nbstory ask`。

## 术语与参与者

- **阅读位置**（P）、**出处**、**一代**：见 [`story.queries`](queries.md#术语与参与者)。
- **一问**：一个问题在一本书、一个阅读位置、一种做法下的一次回答，是对话的一轮。
- **对话**：同一本书、同一代、同一种做法下的若干轮问答，共用一个会话；每一轮用的阅读位置记在这一轮里，中途可以改（输出 41）；对应一条问答记录，记录 id 就是对话 id。
- **文字回复**：Agent 没调作答工具、直接用文字说完的一轮回答。
- **作答 Agent**：一问里调用模型的那个 Agent，用 Profile `story-qa` 运行。
- **做法**：**图当目录**（`graph`，默认）由 Agent 自己查图、搜索、读原文；**全读**（`full`）第一条消息就带上 P 以前的全部原文。
- **读过的原文**：这个对话里经 `read` 工具返回过的段落（前几轮读过的也算）；全读时是 P 以前的全部段落。
- **退回**：作答工具校验不通过，以工具错误结果告诉 Agent 哪里不对，这一问继续。

## 输入与前置条件

### 命令

| 命令 | 用途 |
|---|---|
| `nbstory ask <问题> [--at <章或章.段>] [--mode graph\|full] [--book <书>] [--config <文件>] [--json]` | 问一个问题 |
| `nbstory ask <问题> --continue <对话 id> [--at <章或章.段>] [--book <书>] [--config <文件>] [--json]` | 在这个对话里追问；`--at` 先改这个对话的阅读位置（全读对话不行）；不能同时写 `--mode` |
| `nbstory qa [<记录 id>] [--book <书>] [--json]` | 不给 id：列出这本书的问答记录，新的在前；给 id：显示这条记录 |
| `nbstory qa rm <记录 id> [--book <书>]` | 删除一条问答记录 |
| `nbstory config init\|show\|set <字段> <值>\|unset <字段>\|test [--config <文件>] [--json]` | 写、看、改配置并检查它能不能用，见输出 18 到 22 |

- 不给 `--at` 时读到全书已抽取的最后位置，同 [`story.queries`](queries.md#阅读位置的规则)；`--book` 的省略规则相同。
- 三条命令都接受 `--library <目录>`。

### 配置

配置文件默认在 `$XDG_CONFIG_HOME/nbstory/config.json`（未设置时为 `~/.config/nbstory/config.json`），`--config` 可另指定。`ask` 读它，`nbstory config` 维护它（也可以手编，字段规则相同）。

```ts
type Effort = "minimal" | "low" | "medium" | "high" | "xhigh" | "max";
type QaConfig = {
    providers?: Record<string, {     // 自定义服务商；键是 id：小写字母、数字、连字符，不能与 OMP 目录里的服务商重名
        name?: string;
        api: "openai-completions" | "openai-responses" | "anthropic-messages" | "google-generative-ai";
        baseUrl: string;
        apiKeyEnv: string;           // 存密钥的环境变量名；密钥本身不写进配置
        models: {
            id: string;
            name?: string;
            contextWindow?: number;  // 没写的上下文、最大输出、推理与图片，运行时按模型名从 OMP 目录补；最大输出目录里也查不到时取 32768（OpenAI 系请求发往远端时夹到 64000；本机回环地址的端点按模型写的上限，OMP 18.14 起），不是不发上限
            maxTokens?: number;
            reasoning?: boolean;
            images?: boolean;
            price?: {input: number; output: number; cacheRead?: number; currency: string}; // 每百万 token；不补，不写时费用未知
        }[];
    }>;
    models: string[];                // 候选模型，写成 "服务商/模型名"（自定义服务商的，或 OMP 目录的）
    model: {
        use: string;                 // 默认模型
        thinking?: Effort;           // 默认模型的推理档；不写时请求不带推理档，由服务端的默认档决定
    };
    qa?: {
        maxChapters?: number;        // 图当目录一问最多读几个不同的章：1 到 20 的整数，默认 20
        fullReadMaxChars?: number;   // 全读的原文上限（字数），默认 300000
        answer?: "markdown" | "structured"; // 新对话的作答方式，默认 markdown
    };
    ingest?: …;                      // 抽取的模型，见 story.ingest 的“抽取模型”
};
```

- 全读的上限按字数算，不按 token。字数在上限内不保证放得进模型的上下文窗口：放不进时这一问以 `model_failed`（`context_overflow`）失败。
- 字段类型不对、`maxChapters` 不是 1 到 20 的整数、`fullReadMaxChars` 不是正整数，都按缺少必填字段处理（`qa_unconfigured`）。
- 字段之间的约束同样按 `qa_unconfigured` 处理：候选至少一个、不重复；默认模型在候选里；每个候选指向的服务商与模型都存在（自定义服务商里有，或 OMP 目录里有）；自定义服务商的 id 写法合法、不与目录重名。
- 目录里的模型密钥按 OMP 的取法从环境变量取（见 [`agent.harness`](../agent/harness.md#模型目录)）；单价按目录，目录单价全为 0 时当未知。
- **密钥只认启动环境**（[ADR 0032](../../adr/0032-nb-story-keys-from-startup-env.md)）：自定义服务商的 `apiKeyEnv`、目录服务商登记的变量，“有没有值”与取值都以进程启动时的环境为准（shell 导出的，加上 Bun 在启动时加载的当前目录 `.env`）；OMP 导入时额外读进来的家目录等 `.env` 不算。同一个变量在 `config show`、`config test`、`ask`、`ingest`、`serve` 与网页配置页里结论一致。已知限制：目录模型的取值仍由 OMP 决定，启动环境有一个登记的变量、别处 `.env` 里有优先级更高的另一个时，OMP 会选后者。
- 推理档不在模型支持的档里时往下夹到支持的档；模型不支持推理时不发。`config show` 写出实际发的档。
- **第 1 版。** 早先的配置（`model` 是 `{baseUrl, id, apiKeyEnv, api?, contextWindow?, maxTokens?, thinking?, price?}`）读的时候升级成第 2 版：建自定义服务商 `custom`（`api` 不写或 `chat` 是 `openai-completions`，`responses` 是 `openai-responses`；写了推理档的模型标成支持推理），候选与默认都是 `custom/<id>`，其余字段跟过去。命令行与网页写回的一律是第 2 版。

## 输出与可观察行为

### 一问

1. **一个对话一个 Agent。** `ask` 为新对话新建一个会话（Profile `story-qa`、生效工具集见输出 3），把问题作为第一条用户消息运行；追问时恢复同一个会话，把新问题作为下一条用户消息运行（输出 26）。一轮运行到作答工具交出通过校验的答案（输出 8）、以文字回复停下、失败或被取消，结束方式见输出 10。
2. **阅读位置由程序固定。** P 在每一问开始时定下（取这个对话当前的位置，输出 41），所有工具都按 P 与这本书的同一代查询；工具参数里没有 `book` 与 `at`，模型改不了。支持视角的工具可以带 `perspective`。
3. **查询工具。** 工具与 [`story.cli`](cli-skill.md#输入与前置条件) 的查询命令同名，参数是对应查询方法（[`story.queries`](queries.md#方法清单)）的参数去掉 `book` 与 `at`（例如 `read` 的 `from`、`to` 是 `{chapter, paragraph}`），结果是该命令给人读的文字输出（不附查看器地址；续页提示写成 `cursor` 参数）：

   | 工具 | 对应命令 |
   |---|---|
   | `info`、`chapter` | 目录、某一章的变化 |
   | `find`、`card`、`knowledge`、`statements`、`appearances` | 对象与人物卡 |
   | `ties`、`between`、`relations` | 关系 |
   | `knows` | 秘密矩阵 |
   | `ledger`、`track`、`questions`、`timeline`、`episodes`、`arcs` | 数值、悬念、时间线、情节 |
   | `search`、`read`、`para` | 搜索、原文、引用某段的记录 |

   书在新建时关掉了秘密时没有 `knows`，关掉了数值时没有 `ledger`、`track`（[`story.ingest`](ingest.md) 输出 18）：这一问的会话里不声明它们，模型调用它们得到工具错误；系统提示词里列举图里有什么时也不提数值。

   查询失败（例如 `entity_ambiguous`、`entity_not_found`）以工具错误结果返回错误码、说明与候选，这一问继续。

   记录等级（[`story.queries`](queries.md) 输出 23 到 27）不进问答：工具参数里没有 `maxTier`，写了是工具错误；结果文字不写等级，与不分级时相同。没有 `why` 工具。
4. **原文只到 P。** `read` 只返回 P 以前（含 P）的段落：P 所在章里 P 之后的段落不返回（比 [`story.queries`](queries.md) 输出 14 严，那条例外不适用于问答）；请求的范围整个在 P 之后时是工具错误。
5. **图当目录读原文的章数上限。** 一轮里新读、而前几轮没读过的不同章，至多 `maxChapters` 个（对话开始时的值，见输出 26）；前几轮读过的章再读不计数。已经读过的章可以再读；一次调用裁到 P 以后涉及的新章会让总数超过上限时，整次调用不读：返回正常的工具结果（不是工具错误），以“没有读：”开头，写明上限、已读的章与可以重读已读的章，不返回任何段落，也不计入已读。其余拒绝（章不存在、段数越界、范围倒置、在 P 之后）照旧是工具错误。同一条模型消息里的几次 `read` 依次处理，合起来同样不超过上限。全读时没有这条上限。
6. **全读。** 第一条用户消息先给 P 以前的全部原文（每行“章.段 正文”），再给问题；工具照样可用。P 以前的原文超过 `fullReadMaxChars` 时，`--mode full` 在发出任何模型请求之前失败（`full_read_unavailable`）。
7. **作答工具 `answer`。** 只在结构化作答的对话里有（作答方式见输出 38）；Markdown 作答的对话里模型看不到它。它是这一问的收尾工具（[`agent.harness`](../agent/harness.md) 的收尾工具），可选：Agent 也可以不调它、直接用文字回复（输出 10）。参数：

   ```ts
   type Answer = {
       conclusion: string;                                  // 先给的结论
       conclusionType: "明说" | "推断" | "解读" | "无法确定";
       knowledge?: {                                        // “谁知道什么”的题：一行一人
           who: string;
           state: "知道" | "怀疑" | "不知道" | "原文没有表明";
           how: string;                                     // 怎么知道的
           refs: Ref[];
       }[];
       points?: {text: string; refs: Ref[]}[];              // 其他题：分点
       explanation: string;                                 // 展开说明
       evidence: Ref[];                                     // 依据出处
       coverage: string;                                    // 覆盖了哪些范围、可能漏了什么
   };
   ```

8. **校验与退回。** 程序校验 `answer` 的参数，全部通过才算交卷，这一问以答案结束；有一条不通过就退回，工具错误结果逐条写出问题，Agent 改了再交。校验项：
   1. 参数符合上面的形状，`conclusion` 不为空；
   2. 每个出处写法正确（“章.段”或“章.段—章.段”），在全书范围内，且不晚于 P。出处包括 `evidence`、`knowledge[].refs`、`points[].refs`，以及各段文字（`conclusion`、`how`、`text`、`explanation`、`coverage`）里写成“章.段”或“章.段—章.段”形状的内容；文字里的数字碰巧是这个形状时同样校验，退回理由会说明，Agent 可以改写；
   3. 每个出处的段落都是读过的原文（范围出处要求范围内每一段都读过）；
   4. `knowledge` 里 `state` 为“知道”或“怀疑”的行至少有一个出处；
   5. `conclusionType` 不是“无法确定”时，`evidence` 至少有一个出处。
9. **作答规则。** Profile 的系统提示词包含作答规则 v5，另按作答方式加一组。Markdown 作答：查完书后直接用 Markdown 写回答（先结论再分点，可以用小标题、列表、表格，不写成 JSON），“谁知道什么”的题逐个角色写出状态、怎么知道的与依据段落，每个出处都要是读过的段落，写完逐条核对；不需要查书的话直接回复。结构化作答：回答小说的问题用 `answer` 交卷，按它的结构写（先结论，“谁知道什么”的题给一行一人的表）；角色靠自己猜测、或按当时情境能推出的，写成“推断他知道”并给出段落；交卷前逐条核对每个“知道”都指得出段落；不需要查书就能回答的话（寒暄、问能做什么、问题不清楚要先问回去）直接用文字回复；追问可以引用前几轮读过的段落；文字回复里写的出处同样要是读过的段落。
10. **一轮怎么结束。** 不提醒，一轮就是一次运行，按运行的结束方式定结果：

    | 运行的结束方式 | 这一轮 |
    |---|---|
    | `answer` 通过校验（`finished`） | 已答，带答案 |
    | 停止，最后一条助手消息的文字去掉首尾空白后不为空 | 已答，带文字回复 |
    | 输出到上限，文字同上不为空 | 已答，带文字回复，标明被截断（OpenAI 兼容的流以 `[DONE]` 收尾却始终没给结束原因，也按输出到上限记：网关耗尽预算时常这样，半句话不是正常结束） |
    | 停止或输出到上限，没有文字（空、只有空白，或只有推理、工具调用） | 失败（`no_answer`） |
    | 出错 | 失败（F2） |
    | 取消 | 中断（输出 13） |

    Markdown 作答的回复有没核实的出处时，这一轮还要经过一次出处复查（输出 39），复查之后才结束。
11. **结果。** 一轮结束时给出这一轮的结果：答案（输出 7 的结构）或文字回复（输出 24）二者之一、这一轮新读的章（按章号排序）、用量（输入、输出、缓存读写的 token；配置了单价时给费用，否则费用为空；用量不完整时标为不完整）、用时、模型（`服务商/模型名`）、做法、P、对话 id（即记录 id）与这是第几轮，复查过的轮另有复查的结局（输出 39）。

### 命令行

12. **`ask` 的输出。** 进度逐条写到标准错误：调用了哪个工具（例如“查人物卡：苏天晴”“读 37.1—37.96”）、作答被退回（附原因）、出处检查（哪些出处没读过、已让模型重写）、交卷。成功时标准输出给人读的回答：交卷的给结论与结论类型、表或分点、展开说明、依据出处；文字回复给回复正文，有没核实的出处就在后面列出；之后是读过的章、用量与费用、用时，最后一行写对话 id、第几轮与追问的命令（`nbstory ask <问题> --continue <id>`）。`--json` 时标准输出只有 `{"ok": true, "data": <结果>}` 或 `{"ok": false, "error": {"code", "message", "kind"?}}`（`kind` 只在 `model_failed` 时给出），进度仍写到标准错误；结果保留对话之前的字段名（`id` 是对话 id），另有 `turn`（第几轮，从 1 起）、`reply`（`{text, truncated, unverifiedRefs}`，用 `answer` 交卷时为 null；文字回复时 `answer` 为 null）与复查过的轮的 `recheck`（`{unverified, outcome}`）。`--model <服务商/模型名>` 与 `--thinking <档>` 只对这一问：模型不在候选里、推理档不是六档之一是用法错误；`--structured` 让新对话用结构化作答，与 `--continue` 同时写是用法错误。
13. **取消。** `ask` 运行中收到中断信号（Ctrl-C）时取消这一问：停止模型请求与工具调用，写下状态为“中断”的记录，退出码 130。
14. **退出码。** 在 [`story.cli`](cli-skill.md#输出与可观察行为) 的 0、1、2 之外：问答失败（失败码 F1 到 F4）为 4；取消为 130。查询类失败（书不存在、阅读位置不合法）在调用模型之前报出，退出码 1；`qa` 命令的 `qa_record_not_found`、`qa_record_broken`（F5、F6）也是 1。用法错误（未知选项、`qa` 的位置参数组合不对）一律为 2，不随书库内容变化。

### 问答记录

15. **每个对话一条记录。** 记录有书、这一代的代号、P、做法、作答方式（之前的记录没有这一项，按结构化读）、开始时间、对话开始时的章数上限（全读为空）、读过的段、它对应的会话日志（文件名与内容摘要），与按顺序的各轮（问题、状态、答案或文字回复、失败码与错误归类、这一轮新读的章、退回次数、用量、用时、模型、开始时间、这一轮在会话日志里的第一条的序号 `logFrom`，复查过的轮另有 `recheck`）。`logFrom` 从网页问答起写下，之前的记录没有它，照常读、照常续问。每一轮结束时（交卷、文字回复、失败或中断）写一份新的会话日志，再整条重写记录指向它：读者看到的记录与它指向的日志总是成对的，保存失败时旧的一对原样保留。中断与失败的那一轮没有答案与文字回复，不留半条答案。
16. **查看与删除。** `nbstory qa` 列出这本书当前一代的对话，一行一个：id、时间、最后一轮的状态、轮数、第一轮的问题、P，新的在前；`nbstory qa <id>` 按轮显示整个对话；`nbstory qa rm <id>` 删除整个对话。别的一代的记录不列出、不能显示（`qa_record_not_found`）。读不成记录的文件（损坏）列在最后、标为损坏，不影响其余记录；显示它得到 `qa_record_broken`，可以用 `qa rm` 删除。对话之前的一问一条的记录按一轮的对话列出与显示。
17. **密钥不落地。** 密钥只从配置指定的环境变量读出交给 HTTP 客户端，不出现在记录、会话日志、标准输出与标准错误里，也不出现在网页接口的任何响应与推送的任何一帧里；模型服务的错误正文回显了密钥时也一样（错误归类与状态码照常保留）。
18. **配置命令。** `nbstory config` 的 `show` 显示配置文件路径、默认模型与实际发的推理档、候选模型、用到的服务商（自定义的写接口与地址），并说明各服务商的密钥环境变量设没设置，不打印密钥；`set <字段> <值>` 改一个字段，`unset <字段>` 去掉一个可选字段（默认模型、候选、自定义服务商的接口、地址、密钥变量与模型列表不能去掉）。字段用点路径：`model.use`、`model.thinking`、`models`（值写 JSON 数组）、`providers.<id>`（整个服务商，值写 JSON）、`providers.<id>.name|api|baseUrl|apiKeyEnv|models`、`qa.maxChapters`、`qa.fullReadMaxChars`、`qa.answer`。改完字段之间的约束不成立（例如默认模型不在候选里、服务商 id 与目录重名）是用法错误。第 1 版的路径（`model.baseUrl`、`model.id`、`model.apiKeyEnv`、`model.api`、`model.contextWindow`、`model.maxTokens`、`model.price`）是用法错误，错误里写出第 2 版里对应的路径。配置文件不存在时 `show`、`set`、`unset` 以 `qa_unconfigured` 失败，下一步指向 `config init`。所有动作都接受 `--config` 与 `--json`。
19. **init。** 两种写法：用 OMP 目录里的模型，`--model <服务商/模型名>`；用自定义地址，`--base-url`、`--model <模型名>`、`--api-key-env` 三项（写进自定义服务商 `custom`，已有它时没给的地址与密钥变量沿用）。都可加 `--thinking`。选的模型加进候选并设为默认。给齐就直接写；缺的在终端里交互问：先问用目录里的模型还是自定义地址，已有配置的值作默认，选项里给了的不再问。目录里没有的模型不收。密钥环境变量名这一项只收环境变量名的写法，把密钥本身贴进来会被拒绝并说明。已有配置文件时：交互里先确认覆盖（默认不覆盖），非交互需要 `--force`；覆盖时没给的字段保留原值。不在终端里（或加了 `--json`）而缺必填项：用法错误，不等待输入。交互中取消：退出码 130，不写盘。
20. **写入规则。** 写之前整份配置过校验，不通过就不写、原文件不变（`qa_unconfigured`，写明哪个字段，说明里不带字段的值）；不认识的字段一律不收。各处密钥环境变量名（自定义服务商、`ingest.model`、`ingest.recall.model` 的 `apiKeyEnv`）只收变量名的写法，另外拒绝像密钥的写法（常见密钥前缀、32 个字符以上没有下划线的一整串）：这只挡得住已知形状，随机得像变量名的密钥仍会被当作变量名。通过的写同目录临时文件（名字随机）再改名，正在读它的 `ask` 读到的要么是旧的整份、要么是新的整份；写不进去报 `qa_config_write_failed`（F7）。配置里只有环境变量名，密钥值不出现在配置文件、输出与错误里。
    程序的写入（命令行的 `init`、`set`、`unset` 与网页设置页）共用一把跨进程锁（同目录常驻的 `.config.json.lock`，等别的写入最多 5 秒），锁内重读文件、比对读取时的摘要（文件原字节的 SHA-256，文件不在时是 `absent`；读不出来时不当作不在，报 `qa_config_write_failed`）、校验、写入。摘要对不上（别处在这之间改过）就不写，报 `config_conflict`（F10）。命令行在开始改之前（`init` 在提问之前）读下摘要。手改文件不走锁，只能靠摘要尽力发现；摘要按原字节算，只改了空白也算改过。
21. **test。** 用配置的默认模型、推理档和密钥，经与问答相同的路径向模型发一个最小请求（其余候选不测）：通过时输出模型引用、用时、用量，以及实际发的推理档；失败按 `ask` 的归类以 `model_failed` 失败，退出码 4；取消 130。请求带推理档当且仅当配置写了且模型支持推理。输出只报告发了什么档，不声称服务端已按该档思考。
22. **config 的退出码。** 0 成功；1 配置不合格、写失败或别处改过（`qa_unconfigured`、`qa_config_write_failed`、`config_conflict`）；2 用法错误（未知动作、参数个数不对、字段名或值的写法不对、缺必填项又不在终端、已有配置而没有 `--force`）；`test` 失败为 4，取消为 130。
23. **抽取模型。** `show` 另显示抽取用的模型（[`story.ingest`](ingest.md#抽取模型) 的 `ingest.model`）。没有它时回落到问答的默认模型，只在默认模型是 `openai-completions` 接口的自定义服务商时成立（抽取只会 OpenAI Chat 协议，也不加载 OMP 目录）；不成立时 `show` 写明“抽取要单独写模型”与原因，`ingest` 开始时以 `qa_unconfigured` 失败。`config set ingest.model '<JSON>'` 整节写入（必须一次给齐 `baseUrl`、`id`、`apiKeyEnv`，不收 `thinking`），之后 `ingest.model.<字段>` 可以逐个改；`config unset ingest.model` 整节去掉，抽取回到问答的默认模型（按上面的条件）。`config test --ingest` 用抽取实际用的模型，按抽取固定的两档（`minimal`、`medium`）各发一个最小请求，分别报告通过或失败；网关严格转发推理档、返回 400 并列出合法档位时，改发其中最接近的启用档（`minimal` 优先 `low`，不选 `none`，因为它是关闭推理）并重发一次，输出写明“网关不接受 minimal 档，改发了 low 档”；没有可改发的启用档、或 400 没列出档位时报 `model_failed`（`provider`）。`ingest.model` 与 `ingest.recall.model` 也可以不写 JSON：`config set ingest.model --base-url <地址> --model <模型名> --api-key-env <变量名>`，只给其中一项时其余沿用已有的值（已有的价格、上限原样保留），还没有这一组时三项要给齐；这三个选项给在别的字段或别的动作上是用法错误。挑相关说法（[`story.ingest`](ingest.md#抽取模型) 的 `ingest.recall`）：`show` 写明开没开、用哪个模型；`config set ingest.recall.enabled true|false` 开关；`ingest.recall.model` 的写法同 `ingest.model`（整节写入后才能逐个改，`unset` 整节去掉后回到抽取模型）；`ingest.recall` 里没有字段了整节去掉。开着时 `config test --ingest` 再用挑选的模型发一个 `minimal` 的请求，单独报告。马甲核对（[`story.ingest`](ingest.md#马甲核对) 输出 20 的 `ingest.personaCheck`）：`show` 写明开没开（默认开）；`config set ingest.personaCheck.enabled true|false` 开关，`unset` 回到默认开；用抽取的模型，`config test --ingest` 不另发请求。

### 对话

24. **文字回复里的出处。** 文字回复里写成“章.段”或“章.段—章.段”形状的内容逐个按输出 8 第 2、3 项检查（对照读过的原文与 P），不合格的列为这一轮的“没核实的出处”，回复照常算已答、不退回。回复里一个出处也没有、这一轮也没读过原文时，`ungrounded` 为 true：回答没有可核对的依据，记录与界面要标出来（输出 12、[`story.viewer`](viewer.md) 的问答页）。
25. **保存时核对轮数。** 一轮结束保存时，记录已经被别人改过（磁盘上的轮数不是这一轮开始时读到的轮数）就不保存：这一轮的结果照常输出，说明记录没保存、原因是对话被同时追问了；磁盘上的记录不变。
26. **追问。** `ask --continue <对话 id>` 读出这条记录与会话日志，用会话日志恢复会话（[`agent.harness`](../agent/harness.md) 输出 4），书、这一代、P、做法、作答方式与章数上限都取记录里的（改配置只影响新对话；模型可以每轮换，没指定时接着用最近一轮的，它不在候选里了就用默认模型），把问题作为下一条用户消息运行；模型收到的历史与上一轮结束时相同（同上输出 8）。前几轮读过的段落在这一轮里都算读过的原文。上一轮失败或中断的对话也可以追问。记录不存在、属于别的一代或损坏时报 F5、F6；会话恢复不了（会话日志的快照是早先版本的 Profile，记录写下之后工具改了，或会话日志不在、读不成、内容与记录里的摘要对不上）时报 F8；`qa.get` 按同一条检查给出能不能续问，页面在提交之前就知道。这几种失败都在发出模型请求之前报出，不改记录。与 `--mode`、`--structured` 同时写是用法错误；带 `--at` 是同时改阅读位置（输出 41），位置改动跟着这一轮一起保存，所以这一问在开始前失败或被放弃时记录与会话日志都不变。

### 网页

`nbstory serve` 的网页问答页与设置页（[`story.viewer`](viewer.md) 的问答页、设置页）经下面这些接口用同一个引擎与同一份配置。

27. **一轮跑在服务里。** 网页开始的一轮在服务进程里运行，不绑在页面的连接上：页面关掉、刷新、断网都不影响它，回来时接上。一个对话同一时间只有一轮：这个对话已有一轮在准备或运行时再开始得到 `qa_busy`（F9）；不同对话可以同时跑。每次开始都重新读配置，设置页改了下一轮生效。命令行与网页同时续问同一个对话时照输出 25 判冲突。
28. **开始前的错误在返回前报出。** `qa.start` 先做完开始前的全部检查（配置、书、P、全读上限、续问的记录、会话日志与会话恢复），失败时作为这次请求的错误（F1、F3、F5、F6、F8 与查询类的码），不留下运行、不改记录；通过后才受理，返回对话 id、这一轮的 `runId` 与第几轮。新对话的 id 由服务在受理前定下。
29. **接口。** 都是 `POST /api/rpc/<方法名>`，参数与结果见 [`contract.ts`](../../../packages/nb-story/src/contract/contract.ts) 的 `QA_METHODS`：
    - `qa.list {book}`：这一代的对话一行一个（id、第一问、记录里的轮数、最后一轮的状态、P、做法、开始与更新时间、服务里运行中或刚结束的那一轮），合并只在服务内存里的首轮（还在跑或没保存，轮数为 0）；读不成的记录另列（id 与原因）；新的在前。
    - `qa.get {book, id}`：记录（带作答方式；首轮还没保存时为空）、会话日志（读不成时给原因，页面只按记录显示）、能不能续问（不能时给原因：旧形状的记录、早先版本的 Profile、日志读不成、首轮没保存）、服务里的那一轮（带这一轮的模型）。
    - `qa.start {book, question, conversation?, mode?, at?, answer?, model?, thinking?}`：`conversation` 不给是新对话；`mode`、`answer` 只在新对话时用，续问时给了是 `invalid_params`；续问时的 `at` 是改阅读位置（输出 41）。`model` 必须在配置的候选里；`thinking` 必须是 `model` 支持的推理档，给它就要同时给 `model`。这几项不对都在登记运行之前报 `invalid_params`，不发请求、不留运行。
    - `qa.stop {book, conversation}`：停下运行中的那一轮，按输出 10 记为中断；准备中的一轮还没有停止的入口。
    - `qa.remove {book, id}`：见输出 31。
30. **推送。** `GET /api/qa/events?book=&conversation=` 是一个对话运行的推送（SSE，`data` 是 `QaFrame` 的 JSON）：第一帧是快照（服务里的那一轮与它已写下的会话日志条目；没有时为空），没有运行或运行已结束时随即结束；运行中按发生顺序推日志条目与事件，最后一帧是结束（这一轮的结果与有没有保存）。事件只有页面用得到的几种，工具结果只留开头 500 字；同一条消息生成中的快照每 100 毫秒最多推一次，别的帧之前先推积着的那一次。连接每 20 秒有一条心跳；一个连接积压超过 2 MiB 还没发出去时服务断开它，页面重读补齐。
31. **删除。** `qa.remove` 先关上这个对话的门（之后的开始得到 `qa_busy`），停下并等完这个对话准备中、运行中与保存中的那一轮，再删记录与它的全部会话日志；只在服务内存里的首轮也算这个对话，删掉就是删除成功；记录与运行都没有时是 `qa_record_not_found`。损坏的记录同样能删。删除书时同样先关上这本书的门、停下并等完这本书的全部轮次，再删书。
32. **结束后的那一轮。** 服务里结束的一轮保留到这个对话下一轮开始、对话或书被删除、或服务停止：保存失败时（输出 25 的冲突、书被删、写盘失败）它是这一轮结果唯一的来源，`qa.get` 与推送都给出它与没保存的原因。
33. **停止服务。** `serve` 收到 SIGINT、SIGTERM 或 SIGHUP 时先停下全部运行中的轮次、等它们按“中断”保存完，再撤销登记、停止监听（[`story.cli`](cli-skill.md) 输出 5）。服务被强行结束时，运行中的那一轮丢失（同“时序与寿命”）。
34. **全读的原文不进网页。** 网页拿到的会话日志（`qa.get`、推送的快照与日志条目）里，全读对话的第一条用户消息只有问题与“已附阅读位置以前的全部原文，共 N 段”；存下的会话日志照旧带原文（续问要交回模型）。
35. **设置页的配置接口。**
    - `config.get`：配置文件的路径、此刻的摘要、配置里写到的每个密钥环境变量名在服务进程的环境里有没有值，以及三种状态之一：没有文件（给一份起始配置）、合格（给配置）、读不成或不合格（只给原因，不回传文件内容：里面可能有贴错位置的密钥）。
    - `config.set {config, expect}`：整份写入，`expect` 是读取时的摘要（`absent` 表示只新建），按输出 20 校验与比对；校验不过是 `invalid_params`（说明不带原值），摘要对不上是 `config_conflict`。
    - `config.test`：用保存下来的配置按输出 21 发一个最小请求（只测默认模型），最多等 60 秒；结果给模型引用、实际发的推理档、用时与失败的归类和说明（已遮盖），不给模型回的正文。
    - `models.catalog`：OMP 目录的全部服务商加配置里的自定义服务商（自定义的在前；配置读不成时只有目录）。每家给 id、名称、来源、能不能用（[`agent.harness`](../agent/harness.md#模型目录) 的 `access`；自定义服务商是 `key`）、可以设的密钥变量与有没有值，以及模型（接口、上下文、最大输出、推理与能选的推理档、图片、单价，未知为空）。目录服务商有没有值是服务启动时按 OMP 的取法看的；自定义服务商按此刻的服务环境。自定义模型没写的参数按模型名从目录补上后给出。
    - `models.discover {api, baseUrl, apiKeyEnv}`：用这几个值（设置页对话框里正在编辑的，不读配置文件）读这个服务的 `/models`，只认 `openai-completions`、`openai-responses`；密钥取服务环境里这个变量的值，变量名同样只收变量名的写法。结果是读到（模型名与按模型名在目录里找到的参照，只是建议）、空、服务没有这个接口（404）、密钥被拒（401、403）、连不上、其它失败之一，另给这个变量有没有值。密钥不出现在结果里。

36. **接口与思考内容。** 模型走它的服务商的接口（自定义服务商的 `api`，或目录里模型的接口）。Responses 接口在发推理档时要思考摘要；不发推理档时不要摘要，过程里没有思考（`config show` 写明）。同一个对话中途换了接口时，之前几轮的思考按文字交给模型。`ask`、网页的一轮与 `test` 都走配置的接口。模型回的思考内容（Responses 的思考摘要，或 Chat Completions 服务回的 `reasoning_content`）作为思考写进会话日志，网页的过程里显示；GPT 系列经 Chat Completions 不回思考内容，过程里就没有思考。抽取的模型不受这一项影响。
37. **问题里的引用。** 问题里可以带 `[名称](entity://<对象 id>)`、`[章.段](paragraph://章.段)`、`[第 N 章](chapter://N)` 三种引用（网页的 `@` 菜单插入它们，命令行可以照样手写），原样交给模型；问答规则（Profile 版本 3）告诉模型：对象的引用按 id 查（查询工具的 `entity`、`perspective` 直接写这个 id），段与章的引用要看原文时按它读，答案里的出处照常写“章.段”。引用不改变防剧透与出处校验：晚于 P 的段照样读不到、不能引用。Profile 版本 2 时开的对话续问得到 F8 `qa_not_continuable`（输出 26），照常可以查看。

### 作答方式与模型

38. **作答方式。** 新对话开始时定下作答方式，之后这个对话一直用它：`markdown`（默认）直接用 Markdown 文字回答，`structured` 用 `answer` 交结构化的卷（输出 7、8）。不指定时按配置的 `qa.answer`；命令行用 `--structured`，网页用 `qa.start` 的 `answer`。作答方式记进会话快照（Profile 版本 4 的 `initial`）与对话记录。Profile 版本 3 及更早开始的对话（包括全部结构化的旧对话）只能查看、不能续问（F8）。
39. **出处复查。** Markdown 作答的一轮以文字回复结束（停止或输出到上限），而回复里有没核实的出处（输出 24）时，在同一个会话里再运行一次：先在会话日志里写一条元数据（`nb-story.reply-check`，带这些出处；不交给模型），再把“这些出处没读过，先读来核对、读不了的换掉或删掉，然后重写整份回答”作为下一条用户消息。只复查一次，结局：
    - 第二次以文字结束：它是这一轮的回复（截断按第二次），仍没核实的照旧列出；`recheck.outcome` 为 `rewritten`；
    - 第二次出错、被取消或没有文字：保留第一次的回复，这一轮仍是已答，`recheck.outcome` 为 `failed` 或 `aborted`；
    - 用量是两次之和，两次都完整才算完整；退回次数不变。
    结构化作答不复查（它已有校验与退回）。网页把复查的那条用户消息显示成这一轮过程里的一行，不显示成新的提问（[`story.viewer`](viewer.md) 的问答页）。
40. **每一轮的模型。** 一轮用的模型是配置的候选之一：`ask --model`、网页 `qa.start` 的 `model` 指定；不指定时新对话用默认模型，续问用最近一轮的（见输出 26）。推理档不指定时，用的是默认模型就用配置的推理档，否则不发；指定了就按模型往下夹（[`agent.harness`](../agent/harness.md#模型目录)）。同一个对话换了服务商或接口时，日志不改，之前几轮的思考由 OMP 按目标接口转换后交给模型（同输出 36）。
41. **对话中途改阅读位置。** 图当目录的对话可以改阅读位置：网页 `qa.position`、命令行 `ask --continue <id> --at <位置>`（后者改完接着运行这一问），全读对话是 `qa_position_fixed`（全读的第一条消息已带着原文，网页退出码 409，命令行是用法错误退出 2），对话在运行或准备时网页是 `qa_busy`。改位置不发模型请求、不产生费用：向会话日志追加两条——一条完整形状的用户消息，文字是程序生成的提醒（往后调：`<system-reminder>`\n阅读位置从第 27 章改为第 40 章。你可以访问第 40 章及之前的内容了。\n`</system-reminder>`；往回调：说新位置之后的内容现在不能访问或引用，即使前面的对话里出现过也不要再用；位置停在一章最后一段写“第 N 章”，否则写“N.M”），以及紧跟其后的 `meta` 条目（键 `qa.position`，值是新位置与“从”哪里改），再照追问的方式复制新日志发布记录。位置没变不写。记录里：`currentAt` 是下一问用的位置，`positionChanges` 是改了几次，每一轮的 `at` 是这一轮用的位置（旧记录没有这三项，当前位置按 `currentAt`、最后一轮的 `at`、开始时的 `at` 的先后取）。会话里提醒是独立的一条消息，网页靠紧跟的 `meta` 认出它（不看文字：用户可以把同样的标签当问题提交），显示成一条可展开的系统提醒，不开新的一轮。发给模型的请求里相邻的用户消息合并成一条（有的端点不收连续的 user 消息）；日志与页面仍是两条。下一问的工具、读原文与交卷的出处都按新位置：往回调时晚于新位置的已读范围不再算读过，已有的答案不改。系统提示词写着开始时的位置，另说明以最近一条 system-reminder 为准。限制：硬边界只有工具查询、读原文与结构化交卷的出处校验；Markdown 作答的越界出处只标注、复查一次，没写出处的剧情程序认不出；往回调时对话历史里早先出现的内容无法撤回。两处同时改或改与追问交错时，保存前核对轮数与位置改动次数，后保存的得到 `qa_conflict`（对话原样保留）。
42. **没抽完的书（w00024 t30）。** 书还在抽取或停在半路时，已提交的章之后那些已经切好、还没进图的章（抽取记录 `source.json` 里的，称尾部）可以读：阅读位置（新对话的 `--at`、网页的位置控件、中途改位置）可以落在尾部章里，只给章取该章最后一段，章不在已提交加尾部的范围里是 `position_out_of_range`；没有抽取记录、记录不是这一代的书（已提交各章的段数与这一代逐章对不上）或记录结构不对时没有尾部，行为同以前。位置在尾部时：`read` 读尾部章的原文，范围可以跨过抽取进度，尾部的段没有称呼标记、概要与记录，读过的段照常登记，出处校验照常；其余查询工具按抽取进度（图位置，不是阅读位置）回答，每个工具的结果（成功和出错）末尾有一行“图只抽到第 N 章；第 N+1 章到第 P 章的内容只能用 read 读原文”，`chapter`、`para` 的章号落在尾部时不查询、直接说图里还没有记录、只能用 read（普通结果，不是错误）；位置在抽取进度之内时没有这一行。位置提醒（输出 41）的目标在尾部时多一句“图只抽到第 N 章，第 N+1 章之后只能用 read 读原文”，章末仍写“第 N 章”。系统提示词只写固定的一句“工具结果末尾写了‘图只抽到第 N 章’时……”，不写具体章号，所以抽取进度增长后不会陈旧。全读对话的第一条消息同样包含尾部的原文。续问时阅读位置所在的尾部章读不到了（抽取记录没了或换了书）是 `qa_not_continuable`，不改成别的位置。
43. **过程里不剧透（issue 265）。** 阅读位置在能到达的最后一段之前时，给人看的过程不显示阅读位置之前搜不到的词：工具参数里的 `query`、`entity`、`other`、`track`、`perspective`，按空白与标点拆词（同 [`story.queries`](queries.md) 输出 15）后，有任何一个词在阅读位置之前搜不到（`search` 对象、说法、原文都算；对象编号与数字不是词，原样），这个参数显示为“（阅读位置之前没有结果）”。命令行进度（输出 12）、网页推送的运行事件与日志帧、`qa.get` 返回的日志都照此处理；工具结果文字里回显了被隐藏的词，换成“（…）”；设了阅读位置时思考块不给网页，工具调用只留名字、编号与参数（不带流式的原始参数文字）。只改给人看的那一份：存下的会话日志、续问交回模型的内容与模型收到的工具结果不变。`qa.get` 按对话现在的位置处理，往回调之后旧回合里原本能看的词也跟着收起；位置落不到这本书里时按第 1 章第 1 段算。位置就是最后一段（没设位置的默认）时没有可剧透的内容，一律原样。已知不覆盖：模型在过程中写给人看的普通文字（不是工具调用与思考）里可能直接说出后文的词。

## 状态与转换

一问的状态：

| 状态 | 进入 | 记录 |
|---|---|---|
| 运行中 | 读完配置、解析书与 P、全读检查通过之后 | 还没有记录，`nbstory qa` 不列出 |
| 已答 | `answer` 通过校验，或以文字回复结束（输出 10） | 写下，带答案或文字回复 |
| 失败 | 模型请求失败、`no_answer`、本机错误 | 写下，带失败码 |
| 中断 | 收到中断信号 | 写下，不带答案 |

表里的状态是一轮的状态；对话的状态取最后一轮的。追问时这一轮“运行中”，记录保持上一轮结束时的样子。

时序与寿命：

- 记录与会话日志在一轮结束时成对写成，对其他读者原子可见：`nbstory qa` 要么看不到这一轮，要么看到完整的一轮与它的日志。运行期间书库里没有这一轮的任何文件；进程被强行结束（不经中断信号）时，这一轮什么都不留下，对话停在上一轮。
- 续问读到一条记录之后，别处发布了下一轮、删掉了这条记录指向的旧日志：续问按新的一对重读，不报 F8。保存期间这个对话被删除：这一轮不保存（按冲突说明），不留下没有日志的记录。
- 同一本书上可以同时跑几问（几个 `ask` 进程，或网页上的几个对话），各自写各自的记录，互不影响。
- 网页的一轮在服务进程里：准备（输出 28）通过后才进入“运行中”；服务正常停止时运行中的那一轮记为中断并保存（输出 33）。
- 一问固定在开始时的那一代与抽取进度（[`story.queries`](queries.md#术语与参与者)）上回答：期间这本书又提交了一章，这一问的全部工具、分页与作答校验仍用开始时的数据。运行中这本书被删除、或删除后又以同 id 导入时，这一问照常答完、输出答案，但记录不保存（结果里说明），不会重新造出书目录，也不会出现在新一代的列表里。
- 记录写盘失败（例如没有写权限、磁盘满）时，这一问的结果不变：已答的照常输出答案，结果里说明记录没有保存与原因。
- 读过的原文在一个对话之内有效，随记录保存；章数上限按轮计（输出 5）。

## 副作用与数据

- **落点**：`<书库>/<书 id>/qa/<对话 id>.json` 是记录；`<书库>/<书 id>/qa/<对话 id>.<第几轮>-<随机>.session.jsonl` 是会话日志（[`agent.harness`](../agent/harness.md) 的日志格式），记录写明用哪一份；每轮写一份新的，上一份在新记录写下后删除。对话之前的一问一条的记录，会话日志是 `<记录 id>.session.jsonl`。删除对话时删除这个 id 的全部会话日志。
- 问答记录随书的这一代：删除书时一起删除。书库格式版本不变（版本 1 的读者忽略 `qa/`）。
- 写入只经 `qa/` 目录；不改书的信息、图与阅读状态。`qa/` 只在书目录已存在时创建，不会凭空造出一个书目录。
- 书库或这本书的格式版本不认识时，按 [`story.queries`](queries.md#副作用与数据) 只读不写：`ask` 照常回答但记录不保存（结果里说明），`qa rm` 得到 `unsupported_format`，`qa` 列出与显示照常。
- 模型请求只发往配置里的服务地址，内容是 Profile 渲染出的系统提示词、问题、工具结果与（全读时）P 以前的原文。

## 失败与恢复

| 编号 | 码 | 含义 | 调用方怎么办 |
|---|---|---|---|
| F1 | `qa_unconfigured` | 没有配置文件，或缺少必填字段（服务地址、模型名、密钥环境变量名），或字段值不合格 | 用 `nbstory config init` 写好，或按“配置”手编 |
| F2 | `model_failed` | 模型请求失败；`kind` 取 [`agent.harness`](../agent/harness.md#失败与恢复) 的错误归类（`auth` 含密钥环境变量没有设置，另有 `quota`、`rate_limit`、`network`、`context_overflow`、`provider`、`local`） | 按 `kind`：设好密钥、等额度或限流恢复、重试；`context_overflow` 时改用图当目录或调小上限 |
| F3 | `full_read_unavailable` | P 以前的原文超过全读上限 | 改用图当目录，或调大 `fullReadMaxChars` |
| F4 | `no_answer` | 一轮停下时既没交答案也没有文字（对话之前的旧记录里是“提醒两次后仍没有交卷”） | 重问 |
| F5 | `qa_record_not_found` | 记录不存在、已删除，或属于别的一代 | 用 `nbstory qa` 查 |
| F6 | `qa_record_broken` | 记录文件损坏，读不成一条记录 | 用 `nbstory qa rm <id>` 删除 |
| F7 | `qa_config_write_failed` | `nbstory config` 写不了配置文件（目录不可写、路径被文件占着等） | 换 `--config` 指定的位置，或修好目录权限 |
| F8 | `qa_not_continuable` | 这个对话不能续问：会话快照是早先版本的作答 Profile、记录写下之后工具改了（包括对话之前的旧记录），或会话日志不在、读不成、被改过 | 开新对话 |
| F9 | `qa_busy` | 网页问答：这个对话已有一轮在准备或运行，或这个对话、这本书正在删除，或服务正在停止 | 等这一轮结束，或先停下它 |
| F10 | `config_conflict` | 写配置时文件已经在别处改过（摘要对不上） | 重新读取（设置页“重新载入”，命令行重跑），再改 |
| F11 | `qa_position_fixed` | 全读对话的阅读位置不能改 | 开新对话（图当目录的对话可以改） |
| F12 | `qa_conflict` | 改阅读位置时对话在这期间被别处追问、改位置或删除了（保存前核对不过） | 重新读这个对话再改 |

查询类失败（`book_not_found`、`book_ambiguous`、`position_out_of_range` 等）沿用 [`story.queries`](queries.md#失败与恢复) 的码，在调用模型之前报出。

## 边界与兼容

- **公开接口**：`ask`、`qa`、`config` 命令与参数、`--json` 的输出形状、退出码、配置文件格式、问答记录的字段。新增可选字段不算破坏兼容。
- **引擎**：`ask`、网页问答页与以后的 NeuroBook 插件调用同一个问答引擎；Profile `story-qa` 与工具随包提供。
- **网页接口**：`qa.*`、`config.*` 与推送只在独立服务里有，不进查询合同（`storyContract`），核心库的 api 不认它们。
- **信任边界（设置页）**：设置页能改服务地址，密钥会发往新地址；权限与在终端里改配置相同：服务只听本机、要登录。
- **信任边界**：模型只经工具读书库，工具只读；模型的输出在作答工具处校验，不经校验的内容不进记录的答案。

## 验收与 Smoke

“确定性”的场景在 100 章样例书上跑，不调用真实模型；“回归”用真实模型。

1. **防剧透（确定性）。** P = 38.57：模型调 `read 38.50-38.81`，只得到 38.50—38.57；调 `read 39.1` 得到工具错误；交卷引用 38.60 被退回，理由是晚于阅读位置。
2. **章数上限（确定性）。** `maxChapters` 设为 2：读第 3 个新章得到“没有读：”开头的正常工具结果、不给段落、不计入已读，反复超限也读不到；再读已读的章照常返回。已读 1 章时，同一条模型消息里同时读两个新章：恰有一次成功，总数为 2。跨章请求 `37.90-39.1`（P = 38.57）在已读 1 章时整次不读、不计入已读。
3. **退回后交卷（确定性）。** 第一次交卷引用了没读过的段落、`explanation` 里写了一个晚于 P 的出处、且“知道”的一行没有出处，工具错误逐条列出这三处；Agent 读了那一段、改掉正文、补上出处再交，这一问以答案结束，记录状态为已答。分两次读完 `38.1-38.20` 与 `38.21-38.40` 后引用 `38.1—38.40` 通过；少读其中一段则被退回。
4. **提醒。** 已删除：问答不再提醒（输出 10），由场景 13 取代；编号保留。
5. **全读（确定性）。** P = 100 时把 `fullReadMaxChars` 设得小于原文字数，`--mode full` 在没有任何模型请求的情况下以 `full_read_unavailable` 失败；设得足够大时第一条用户消息含 P 以前每一段原文，交卷引用任何 P 以前的段落都不因“没读过”被退回。
6. **取消（确定性）。** 模型请求进行中向 `ask` 进程发中断信号：进程以 130 退出，`nbstory qa` 列出一条状态为“中断”、没有答案的记录。
7. **记录与一代（确定性）。** 问一问 → 删除这本书 → 同 id 重新导入：`nbstory qa` 不列出那条记录，`nbstory qa <id>` 得到 `qa_record_not_found`。一问运行期间：只删除书；删除后同 id 重新导入；重新导入后另一问先在新一代写下记录。三种情况下这一问都照常交卷，记录都不保存，书库里没有这本书时也不会多出书目录，新一代只列出另一问的记录。
8. **密钥（确定性）。** 用一个可辨认的假密钥跑场景 3（请求发往本机的 OpenAI 兼容端点）：端点收到这个密钥，而记录、会话日志、标准输出与标准错误里都没有它。端点回 401、错误正文里带着这个密钥时：以 `model_failed`（`auth`）失败，记录、会话日志与输出里仍没有它。
9. **回归（真实模型）。** 作答模型 gpt-6-luna、推理档 `xhigh`，判分用判分器 v2 的一审，题与标准答案用两步法评测时的版本，每题按它要求的阅读位置提问，前两批做法为图当目录：
   1. 第 21 到 100 章的 56 题各答 3 次，共 168 份，一审答错不超过 33 份（基线 33/168，约 19.6%）；
   2. 知情、身份 16 题各答 3 次，一审答错不超过 11/48；
   3. 全读答知情、身份 16 题各一次，只记录结果，不设门槛；
   4. 每题记下读过的章数、被退回的次数、用量与费用；
   5. 三批都要完整：任何一份没答、没判分，或答案没有出处、提到阅读位置之后的内容，这次回归不算通过。

10. **配置命令（确定性）。** `config init` 选项给齐写出的文件，`show` 读得回、`ask` 读得进；缺必填项又不在终端、已有配置而没有 `--force`、字段名不认识、值写法不对、去掉必填字段都是退出码 2，文件不变；`qa.maxChapters` 设 21 是 `qa_unconfigured`（退出码 1），文件不变；写不进去是 `qa_config_write_failed`。
11. **init 的交互（确定性）。** 在带按键输入的终端里依次问地址、模型名、密钥环境变量名、推理档，返回的配置与按键一致；贴进密钥形状的值被拒绝，改填变量名后通过；已有配置时默认不覆盖，选“不写”推理档会去掉原来的；中途取消不写盘。
12. **test（确定性）。** 对本机端点：通过时端点收到的请求带配置里的推理档（配置没写则请求里没有推理档字段）和密钥；端点回 401 且正文回显密钥：退出码 4、归类 `auth`，输出里没有密钥；密钥环境变量没设置：退出码 4，不向端点发请求。
13. **文字回复（确定性）。** 模型不调 `answer`、以一段文字停止：这一轮已答、带文字回复，退出码 0，没有提醒；文字里写了一个没读过的段与一个晚于 P 的出处，两个都列为没核实的出处。以输出到上限结束：已答、标明截断。停止时没有文字：`no_answer`，退出码 4。
14. **两轮追问（确定性）。** `maxChapters` 为 1 建对话，第一轮读第 26 章并交卷；之后把配置改成 2。`--continue` 问第二轮：第二轮第一次模型请求里有第一轮的问题、工具调用与答案。分三种走法：（1）第二轮不读原文，直接交卷引用第 26 章的段落，通过；（2）第二轮先再读第 26 章、再读第 25 章，都照常返回，再读第 24 章得到没读的正常结果（上限仍是建对话时的 1），最后交卷通过；（3）第二轮取消：退出码 130，记录有两轮、第二轮为中断，之后还能第三轮追问。`nbstory qa <id>` 按轮显示。
15. **不能续问（确定性）。** 对话之前形状的记录与会话日志（Profile 版本 1）：`qa` 照常列出与显示为一轮；`--continue` 得到 `qa_not_continuable`，退出码 4，端点没有收到请求，记录不变。新形状的对话把会话日志改动一个字节、或删掉它：同样得到 `qa_not_continuable`，没有请求，文件不变。`--continue` 与 `--mode` 同时写：退出码 2。
16. **同时追问（确定性）。** 从同一个一轮的对话出发先后跑两次追问、都在保存前开始：先保存的写成两轮；后保存的输出答案、说明没保存，磁盘上的记录仍是先保存的那两轮。
17. **读过的段跨轮（确定性）。** 图当目录：第一轮只读 38.1 与 38.3 并交卷；第二轮交卷引用 38.2 被退回，引用 38.1、38.3 通过。全读：第二轮不读原文，引用 P 以前任意段通过，引用晚于 P 的段被退回。
18. **成对保存（确定性）。** 场景 16 里没保存的那一次留下的新会话日志被删掉；每次保存成功后，这个对话只剩记录指向的那一份会话日志；`qa rm` 之后这个 id 的记录与会话日志都不在。
19. **网页的一轮（确定性，真实服务与本机端点）。** `qa.start` 后订阅：第一帧快照，之后的日志条目接上快照里的，正好是存下的会话日志；最后一帧是结束、已保存。模型 12 秒才回时推送照样送到结束帧。没有运行时订阅只有一帧空快照。同一个对话运行中再开始得到 `qa_busy`；`qa.stop` 后这一轮记为中断，之后能续问，续问那一轮的 `logFrom` 与服务给的一致。没配置、续问的对话不存在、位置超出都在返回前报错，不留运行、端点没有收到请求。每一帧与每个响应里都没有假密钥。
20. **网页的删除与停服（确定性）。** 首轮运行中 `qa.remove`：成功，列表里没有它，磁盘上没有它的文件，再删得到 `qa_record_not_found`。运行中删书：这一轮先停下保存，书再删掉。损坏的记录在 `qa.list` 里单列，可以删除。运行中向 `serve` 发 SIGTERM 或 SIGINT：这一轮保存为中断、登记撤销、退出码 0。
21. **网页的全读与积压（确定性）。** 全读对话：`qa.get`、快照与日志帧里都没有原文、有问题与段数，存下的会话日志带原文。一个不读的推送连接积压超过上限被断开，同时另一个订阅者照常收到。
22. **设置页的配置接口（确定性）。** 没有文件：`config.get` 给起始配置与 `absent`；`config.set` 带 `absent` 新建，再带 `absent` 得到 `config_conflict`；贴进密钥的变量名得到 `invalid_params`，说明与文件里都没有它；文件坏了只给原因、可以整份覆盖；`config.test` 通过时给模型名，401 时失败且没有密钥。并发写入（带摘要与不带摘要）都不交错，摘要对不上的那一个报冲突。
23. **Responses 接口（确定性）。** `api` 设为 `responses`、推理档 `xhigh`：本机端点收到的两次请求都是 Responses 的形状，带 `reasoning: {effort: "xhigh", summary: "auto"}`；端点回的思考摘要按顺序作为思考写进会话日志，这一问照常交卷。`config set providers.custom.api openai-responses` 后，没写推理档时 `show` 写明“Responses 接口，没有推理档就不要思考摘要”；写别的值是用法错误（退出 2），不写盘。网页里一轮的思考在过程里逐步显示。
24. **问题里的引用（确定性）。** 问题写 `[地狱猫](entity://<南嘉鱼的 id>) 在 [37.8](paragraph://37.8) 做了什么？`：模型第一次请求里有这句原样的问题与读引用的规则；模型用这个 id 调 `card`，得到南嘉鱼的人物卡而不是查询失败。
25. **作答方式（确定性）。** Markdown 对话：模型看到的工具里没有 `answer`，系统提示词是 Markdown 的那组规则；会话快照里没有 `answer`，续问之后仍没有。结构化对话照旧有 `answer`。配置的 `qa.answer` 决定新对话的方式。快照是 Profile 版本 3 的对话：续问前就报不能续问（输出 38）。
26. **出处复查（确定性）。** Markdown 回复的出处都读过：不复查，只有一次运行。有一处没读过：日志里有一条 `nb-story.reply-check`，第三次请求的最后一条用户消息写着这处出处，模型读了它再回复，结果是第二次的回复、`recheck` 为 `rewritten`；每次工具调用只有一条进度。第二次仍写没读过的：照旧列出，不再复查。第二次出错：保留第一次的回复、`failed`；第二次被取消：保留第一次的回复、`aborted`。结构化对话的文字回复不复查。`ask --json` 的进度写明出处检查，结果带 `recheck`（输出 39）。
27. **每一轮的模型（确定性）。** 第一轮选 `test/other`：记录写这个引用；续问不选时接着用它，选了就换；不在候选里的引用在开始前报 `qa_unconfigured`、命令行是用法错误。同一个对话依次用 Chat Completions、Responses、Chat Completions 的自定义服务商：本机端点收到的三次请求分别是这三种形状，第一轮的日志条目不变（输出 40）。
28. **选模型的接口（确定性，真实服务）。** `qa.start` 给不在候选里的模型、模型不支持的推理档、只给推理档、续问带作答方式：都是 `invalid_params`，端点没有收到请求，列表里没有运行。选了候选里的模型与档：运行与记录都写这个引用，端点收到的是这个模型名。快照是 Profile 版本 3 的记录：`qa.get` 照常给记录（作答方式为结构化），能不能续问为否、原因写明早先版本。`models.catalog` 的第一家是配置里的自定义服务商，密钥变量有值，认得的模型名补上了上下文、单价为空；目录有全部服务商，deepseek 的密钥变量是 `DEEPSEEK_API_KEY`，anthropic 是 `login`；没有配置文件时只有目录。`models.discover` 读到两个模型，认得的那个带目录参照，请求带着变量里的密钥，结果里没有它；路径不对得到 404 的 `not_supported`、变量没值时不带认证头；接口写 `anthropic-messages` 或变量名像密钥是 `invalid_params`。

Smoke：在真实书库上用 100 章样例书与真实模型跑 `nbstory ask` 一问（图当目录），答案带出处、记录可以用 `nbstory qa` 列出与显示；网页问答页里问一题、追问一题、中途停止一次、刷新后接上；接口设为 Responses 时过程里有思考摘要。

## 实现合同

- **公开入口**：命令行 `nbstory ask`、`nbstory qa`、`nbstory config`（包 `@notnotype/nb-story` 的 bin）；独立服务的 `qa.*`、`config.*` 与 `GET /api/qa/events`（`src/server/qa-service.ts`、`src/server/http.ts`，合同 `src/contract/contract.ts` 的 `QA_METHODS` 与 `QaFrame`）；问答引擎 `askQuestion` 与分两步的 `prepareQuestion`（`src/qa/engine.ts`）；问答记录的读写经包入口导出的 `QaRecords`。
- **owner 与依赖方向**：nb-story。问答（`src/qa`）依赖 `@notnotype/nb-harness`、`@notnotype/nb-profile`、`@notnotype/nb-session` 与本包的查询接口；查询与查看器不依赖问答；独立服务依赖它（网页问答），并经 nb-harness 的 `onProcessTermination` 在终止信号上收口。答案、一轮与配置的 schema 在不碰 node 的 `src/contract/`（`qa-record.ts`、`config-schema.ts`），记录层、服务与网页共用。`config init` 的交互依赖 `@clack/prompts`，只在交互时加载。
- **关键不变量**：
  - 记录与会话日志成对：每轮的日志写成新文件，只靠记录那一次改名发布；发布前核对轮数、发布后复查代号与新日志还在（`core/qa-records.test.ts` 的多轮保存、读写交错分组）。
  - 续问的书、代、P、做法与章数上限都取记录里的；会话日志按记录里的摘要核对，恢复不了的在发请求之前报 F8（`engine.test.ts` 的对话与追问分组）。
  - 阅读位置在一问开始时由程序落定，查询与读原文工具都按它裁剪，Agent 的参数改不了它；交卷的出处逐条对照已读范围与阅读位置校验（`engine.test.ts` 的防剧透、作答校验分组）。
  - 已读章的登记在同一条模型消息的并发工具调用之间也只算一次，超上限整次拒绝、不计入（`engine.test.ts` 的章数上限分组）。
  - 一问运行期间不写书库；结束时按开始时固定的那一代保存记录，那一代已经不在就不保存（`engine.test.ts` 的运行中删除书分组）。
  - 密钥只在发请求时从环境变量读取，不进记录、会话日志与任何输出；`config test` 不输出模型回的正文（`ask.test.ts`、`cli/config.test.ts`）。
  - 配置写盘先整份过 schema，再写同目录临时文件并改名；配置里只有密钥环境变量名，所有写入路径共用同一条变量名写法检查；程序写入在跨进程锁里比对摘要（`cli/config.test.ts`、`qa/config.test.ts`）。
  - 引擎的观察者（网页用的事件与日志条目回调）出错不改变这一轮的结果与保存；开始前的错误都在准备时抛出，放弃的一轮不发请求、不写记录（`engine.test.ts` 的网页分组）。
  - 服务里一个对话一次一轮；删除、删书、停服先关门再等范围内的全部轮次收口；推送的快照与日志帧接起来就是存下的日志，合并的更新不越过结算（`server/qa.test.ts`）。
