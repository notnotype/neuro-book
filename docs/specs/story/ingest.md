# 剧情图谱：导入原文并抽取

## 目标与非目标

让用户把一本小说的 TXT 原文交给 nb-story，由程序按章切分、逐章调用模型抽取成 V9 记忆图，抽完的部分随抽随看。命令行与网页都能发起、查看进度、停止与接着抽；书有了新章时能接着往后抽。抽出的数据经 [`story.queries`](queries.md) 查询，和导入现成的 V9 数据文件得到的书用法相同。

明确不承诺：

- 只收 UTF-8 编码的 TXT；EPUB、GBK 等格式不做转换。
- 不支持改稿：已经保存的章内容变了时拒绝，不重抽。
- 不估总价。普通章的请求只详列与本章相关的已有记录；整理在全量材料超过上限后只带上一次整理以来的一段（输出 4）。单章费用随章数只缓慢增长，整理的请求有固定的上限。
- 抽取质量只在 gpt-6-luna 上验证过；换了模型不保证质量。
- 不提供人工修正记录；记录标明“自动抽取，以原文为准”（见 [`story.viewer`](viewer.md)）。
- 同一章不抽两份比对，不给记录打“待核实”标记。
- 网页不能停止别的进程（命令行）运行的任务；也不能删除正被别的进程抽取的书。

## 术语与参与者

- **书**、**一代**、**阅读位置**、**抽取进度**：见 [`story.queries`](queries.md#术语与参与者)。
- **抽取记录**：发起抽取后为一个书 id 保存的原文（切好的章）、已提交的章与整理结果、用量与任务状态。
- **抽取任务**：一个书 id 从某一章开始往后逐章抽取的一次运行。同一个书 id 同时至多一个。
- **章的提交**：一章的记录通过检查后，与它引起的书的数据更新一起生效的那一刻（输出 6）。提交之前这一章的任何结果都不算数。
- **整理**：每隔 5 章与原文最后一章做的一步，产出对象的去重合并、对象各方面的归纳与当前一批主线。全量材料不大时从头重写；超过上限后改为增量：模型只写上一次整理以来的变化，程序把它并到最近一批主线上，得到完整的新一批（输出 4、7）。
- **原文文件**：用户交来的 TXT。

## 输入与前置条件

### 命令

| 命令 | 用途 |
|---|---|
| `nbstory ingest <原文文件> [--title <书名>] [--id <书 id>] [--preview] [--no-ledger] [--no-secrets]` | 新建并开始抽取；已有这个书 id 的抽取记录时接着抽，或把文件里多出的章追加后接着抽；`--preview` 只切章、列出结果，不调用模型；`--no-ledger`、`--no-secrets` 见输出 18 |
| `nbstory ingest --book <书 id>` | 不给文件，用保存的原文接着抽 |
| `nbstory ingest --status [--book <书 id>]` | 看抽取进度：不给书 id 时列出全部有抽取记录的书 |

- 都接受 `--library <目录>`、`--config <文件>` 与 `--json`。
- 书名不给时取原文文件的文件名（去掉扩展名）；书 id 不给时由书名得到，规则同 [`story.queries`](queries.md) 的导入。换了文件名而要接着抽同一本书，用 `--id` 或 `--book`。

### 网页

独立服务提供下面几个方法（HTTP 形式同 [`story.queries`](queries.md#边界与兼容)，要求会话），网页的导入与进度画面见 [`story.viewer`](viewer.md)：

| 方法 | 参数 | 结果里必须有的字段 |
|---|---|---|
| `ingest.preview` | `content`（原文文件的字节，base64）、可选 `title`、`id`、`features` | `id`、`title`、`action`（`new`、`resume`、`append`、`done`）、`chapters`（每章：章号、标题、字数）、`preambleChars`、`volumeLines`、`newChapters`、`features`（生效的开关，见输出 18） |
| `ingest.start` | `content`、可选 `title`、`id`、`features`；或给 `book`（用保存的原文接着抽）与可选 `features` | `id`、`action` |
| `ingest.stop` | `book` | — |
| `ingest.status` | 可选 `book` | 每个书 id：见输出 9 |

### 原文与切章

- 原文文件须是 UTF-8（开头的 BOM 去掉），解码前不超过 32 MiB（网页经 base64 提交，同一个上限按解码后的字节算）；换行统一按 `\n` 处理。全角数字（０到９）按阿拉伯数字认。
- 每行先去掉首尾空白。**标题候选**是不超过 40 字、且不以句号或收尾的引号（。”」』）结尾的行。以“！”“？”“…”结尾的仍是候选：网文的章标题常这样写（“第36章 抓猫！”）。
- **章标题行**是下面两种标题候选：
  1. `第` + 数字 + `章`、`回`或`节`开头，数字是阿拉伯数字或零〇一二三四五六七八九十百千万两，`第`、数字、标记之间可以有空白；标记是`回`时后面一个字不能是`合`（“第三回合”不是章标题）。标记之后的部分是标题，可以为空、可以紧接着写（“第一章绯红”）。前面可以带一段同一行的卷标题（“第一卷 小丑 第一章 绯红”，卷名不超过 20 字）。
  2. 整行就是 `序章`、`序言`、`楔子`、`引子`、`尾声`、`后记`、`番外` 之一，或以其中之一开头、后面紧跟空白或`：:、·—-`之一（“番外 一”“楔子：雨夜”）。“序言里提到的那个人”不是。
- **卷标题行**：`第` + 数字 + `卷` 开头的标题候选，且不是章标题行。它不算章也不算段落，切章结果里数进 `volumeLines`。
- 每个章标题行开始新的一章，章号按出现顺序从 1 编，不用标题里的数字；重复的标题照样是不同的章。章标题是这一章的第 1 段，之后每个非空行是一段；只有标题、没有正文的章也是一章。
- 第一个章标题之前的文字不算正文，它的字数是 `preambleChars`。一个章标题也没有时报 `ingest_bad_text`。
- 字数一律按去掉空白后的字符数计。

### 抽取模型

配置文件与 [`story.qa`](qa.md#配置) 是同一份。抽取用 `ingest.model`；没有这一节时用问答的默认模型（其中的推理档不用），只在它是 `openai-completions` 接口的自定义服务商时成立：抽取只会 OpenAI Chat 协议，也不加载 OMP 目录。不成立时开始抽取以 `qa_unconfigured` 失败，说明要单独写 `ingest.model`。挑相关说法（输出 4）默认关，`ingest.recall.enabled` 为 `true` 时开；开着时用 `ingest.recall.model`，没有时用抽取的模型（整节继承，不逐字段混用）。

```ts
type IngestConfig = {
    ingest?: {
        model?: {
            baseUrl: string;
            id: string;
            apiKeyEnv: string;
            contextWindow?: number;
            maxTokens?: number;
            price?: {input: number; output: number; cacheRead?: number; currency: string};
        };
        recall?: {
            enabled?: boolean;
            model?: {baseUrl: string; id: string; apiKeyEnv: string; contextWindow?: number; maxTokens?: number; price?: {input: number; output: number; cacheRead?: number; currency: string}};
        };
    };
};
```

- 推理档由程序按步骤固定：挑相关说法、写时间点和段落块用最低档（`minimal`），其余步骤用中档（`medium`）。端点 400 明确拒绝当前档位、并列出 `Supported values are` 时，改用列出的档位里最近的一档（同距离优先更高的一档）重发一次，进度里写明换了档；换过仍被拒绝、或没有列出档位时按 F4 停下（`provider`），不再换档，也不省略。
- 挑相关说法的请求按挑选模型的单价记费用。
- 配置了 `price` 时按它算费用，并记下当时的单价与币种；没有时费用为空，只报 token 数。

## 输出与可观察行为

### 发起

1. **一条命令兼管新建、接着抽与追加。** `nbstory ingest <原文文件>`（网页的 `ingest.start` 同理）先切章，再按书 id 找：
   1. 书库里既没有这个 id 的书，也没有它的抽取记录：新建抽取记录，从第 1 章开始（`action: "new"`）。
   2. 有这个 id 的抽取记录（不论第 1 章提交了没有）：原文文件前面的章与保存的原文逐章相同（标题与每一段都相同）时，从第一个没提交的章接着抽（`resume`）；文件比保存的多出章时，把多出的章接在后面一起抽（`append`）；全部提交、也没有多出的章时什么都不做，退出码 0（`done`）。
   3. 保存的某一章与文件里的不同，或文件比保存的少了章：`ingest_text_changed`，写明第一处不同在第几章第几段，什么都不改。
   4. 书库里这个 id 是导入现成数据文件得来的书：`book_exists`。反过来，有抽取记录（第 1 章还没提交也算）的 id，`book.import` 同样得到 `book_exists`。
2. **预览。** `--preview` 与 `ingest.preview` 只切章并判断会做哪一种（输出 1），不调用模型、不写书库：列出章数、每章的章号、标题与字数、`preambleChars`、`volumeLines`，`append` 时多出几章。
3. **一个书 id 一个任务。** 这个 id 已有抽取任务在运行（本进程或别的进程）时，再发起得到 `ingest_running`；两个任务同时发起时恰有一个开始。

### 抽取

4. **逐章抽取。** 按 [V9 记忆图提案](../../proposals/novel-memory-v9.md#七抽取管线)的抽取管线逐章往后抽：每章先写时间点与段落块，再写其余记录，然后程序检查、按清单让模型核对补漏与修复，仍修不好的记录丢弃；每到第 5 的倍数章、以及原文的最后一章，提交这一章前先做整理。一章的模型请求只含抽取规则、截至上一章已提交的记忆图生成的已有记录与这一章原文。整理的全量材料（全量的已有记录加全部情节的概括）不超过 60,000 字时照旧给全量、从头重写，超过时改为增量，只给“这一段”的材料（本条最后一项），每次按当次的大小判断；普通章的已有记录只详列与本章相关的行：
   - 这本书关掉了数值或秘密时（输出 18），对应的一节不列，整理的材料里也不列状态变动、指向秘密的知情。
   - 相关对象是本章原文里出现了它此时的称呼（至少两个字）的对象，同一称呼属于几个对象时都算，加上最近 3 章有提及的对象（包括只用代称提及、没有称呼的）。名册详列相关对象，其余对象在“其他对象”里每个一行，写编号、类别、当前称呼与整理标签。
   - 秘密只列涉及相关对象、或有相关对象知情记录（指向秘密本身或它列的说法）的；当前状态只列相关对象的量；未解的疑问只列最近 20 章里提出或有进展的；时间点只列最后 20 个；最近的情节照旧。
   - 说法先列不针对任何对象、秘密的（世界设定、作者声明），再列挂在列出的秘密上的与列出的疑问的答案，再从新到旧补足，各自从新到旧，合计不超过 8,000 字。
   - 挑相关说法开着时，说法改列挑出的那些。每章写时间点与段落块之前先挑一次（第 1 章没有已提交的记录，不挑）：候选依次是不针对具体对象的、挂在列出的秘密与疑问上的、涉及相关对象（`about`、说话人、持有人）的，各自从新到旧，合计不超过 25,000 字；没有候选时不发请求。回复是 `{"ids": [...]}`：不是字符串数组算不成形（重发一次，与其他步骤相同）；不在候选里的去掉、重复的去掉，超过 40 条按回复的先后留前 40 条。两次都不成形时这一章的说法退回规则缩减，问题记进这一章；停止、渠道失败、重试用完照常按输出 9、10 停下，不退回。一章作废重做时重新挑选。
   - 增量整理的材料只给“这一段”：对象与记录从上一次被接受的整理之后算，情节从最近一批主线之后算，都最多回看 10 章。分五节，各有字数上限，超出时按固定顺序少列（少列的主线照样留下）：当前的主线（最近一批，每条一行，已结束的只写编号与标题，6,000 字）；这一段的情节（带参与者与它连到的前面情节属于哪条主线，8,000 字，超出时留最近的）；这一段的对象（有提及的、新建的、被这一段的说法、知情、状态变动涉及的，按提及次数排序，前 15 个列各方面的现有归纳，合计 10,000 字，其余每个一行，3,000 字）；这一段的记录（说法、手写的知情、状态变动，10,000 字，先留涉及列了归纳的对象的，再按从新到旧）；合并候选（同类别、称呼相同或互相包含且较短的至少三个字、两者没有身份同一的说法，至少一方是这一段新建或新增了称呼的，至多 30 对；没有就不出这一节）。
5. **提交的章都合格。** 一章提交时，书的整份数据（不只是这一章）没有错误：形状合格，引用的记录都存在，出处都在原文范围内且属于本章（知情记录例外：按 V9 规则，后面才建的秘密可以给前面已经知情的人补记，出处引用当时的原文；这条知情记录、以及只由前面各章的说法组成的新秘密，读完被写下的这一章才可见），时间点的先后不自相矛盾。这一章新带来的错误由丢弃这一章的相关记录消除，丢弃的条数计入这一章（输出 13）；已提交的章不改。丢弃后仍有错误时，这一章不提交，任务以 `ingest_bad_reply` 停下。
6. **章的提交。** 一章的记录、它触发的整理结果、书的查询数据（章数、`extractedThrough` 与全部记录）与抽取记录里的进度在同一个提交点生效：进程在任何时刻被杀，之后的查询与接着抽看到的都是同一个状态，要么提交前、要么提交后。第 1 章提交时书出现在书库里（新的一代），可以查询，阅读位置最远到它的最后一段；之后每提交一章，书的数据随之更新，仍是同一代（见 [`story.queries`](queries.md#状态与转换)）。第 1 章提交之前，书不在书库里，只在 `ingest.status` 里。
7. **整理的结果跟提交走。** 整理产出的对象合并、各方面的归纳与主线，随它所在的那一章一起提交并保存；接着抽、追加时已提交的整理不重做、不改。追加后原文的新末章另做一次整理，原先末章的那一批仍保留。整理的回复不合格时跳过这一次（这一章照常提交，问题记进这一章），下一次整理照常做，跳过的那几章由它补上（最多回看 10 章，见输出 4）。
   - 增量整理的新一批主线由最近一批合成：模型写到的已有主线按它写的更新标题、概括、进行中或已结束，追加新归入的情节；没写到的原样带过来，编号不变；新主线另编号。最近一批的记录不变，较早的阅读位置仍看到旧的那一版。
   - 对象的归纳按方面替换：模型写了某个对象的某个方面，这个方面以它为准，没写的方面沿用以前的。增量整理时只有材料里列了现有归纳的对象可以改写已有的方面，别的对象只能补还没有的方面。
   - 增量整理的合并只接受材料里列出的候选。超出范围的合并、归纳与主线情节，以及归纳里没有有效依据的句子去掉，问题记进这一章。被合并掉的对象名下以前写的归纳，改记到合并后的对象上。
   - 全量整理与 2026-10-21 之前保存的整理都是整批写法（每次给出全部主线），按原样编出同样的书；之后的增量整理在它的最近一批上接着合成。
8. **称呼从被认出的那一刻起可见。** 抽取得来的书里，一个称呼在某个位置之前不出现在任何结果里（人物卡的称呼、原文段落里的名字、搜索、计数）：这个位置取模型标注的这个称呼的成立位置；同一章里更早的单独出现可以把它往前提，但不跨到更早的章。新章提交后，较早位置的结果可以因新章的记录而变（例如对象的显示说明），但仍守 [`story.queries`](queries.md) 输出 1 的不剧透。

### 失败

9. **渠道失败自己重试。** 一次模型请求遇到超时、连接或流中断、服务端 5xx，或回复在一段内容之后只剩连续 2000 个以上的空白字符（“跑飞”，此时立即中止这次请求）时，等 30、60、120、180、300 秒依次重发，同一次请求连同第一次合计至多 6 次 HTTP 尝试；仍失败时任务以 `model_failed` 停下（`kind` 按 [`agent.harness`](../agent/harness.md#失败与恢复) 的归类），已提交的章都保留，可以接着抽。认证失败、额度用尽、密钥环境变量没设置时不重发，直接停下。推理档被拒绝时：400 里列出了合法档位就换一次档立即重发（不计入重发等待表，进度里写明），换过仍失败、或没有列出档位时以 `provider` 停下。
10. **回复不成形。** 模型正常回复、但不是 JSON、被截断、缺本章、或没有段落块时，这一步重发一次（不计入输出 9 的次数）；仍不成形，任务以 `ingest_bad_reply` 停下，这一章不提交，接着抽时从头重做这一章。

### 停止与接着抽

11. **随时可停。** 命令行收到中断信号（Ctrl-C）、网页对独立服务里的任务调用 `ingest.stop`、或运行任务的独立服务停止时，任务停下：正在进行的模型请求中止，没提交的那一章作废（接着抽时从头重做），已提交的章都保留。命令行以 130 退出。进程被强行结束时同样只丢没提交的那一章。
12. **抽取期间照常可用。** 独立服务里运行抽取任务（含章的检查与提交）时，同一服务对查询、进度与停止的响应时间不因抽取而超过 1 秒；停止请求在 5 秒内让任务不再发起新的模型请求、不再提交新的章。

### 进度

13. **进度。** `ingest.status` 与 `nbstory ingest --status` 对每个有抽取记录的书 id 给出：
    - 状态：`running`（运行中，另给由谁运行：命令行或独立服务）、`stopped`（停下，另给原因：用户停止、失败码与说明、运行它的进程已退出）、`done`（原文的章全部提交）；
    - 原文总章数、已提交的章数、正在抽的章与步骤（只在运行中；步骤是 `recall`、`beats`、`draft`、`review`、`repair`、`consolidation` 之一）、正在等待的重试（第几次、还要等多久）；
    - 这次任务与历次合计的用时、token 用量（输入、输出、缓存命中）、费用；每章平均用时与费用（分子含失败与作废的尝试，分母是已提交的章数）；
    - 每个已提交的章：用时、费用（含这一章作废过的尝试）、丢弃的记录条数。
    - 这本书的开关（`features`，输出 18）。
    - 用量与费用只累计实际发出的请求；有任何一次请求的用量拿不到（中止、流中断、跑飞），对应的合计标为“不完整”（数值是下界），不当作 0。
14. **命令行的输出。** 运行中进度逐条写到标准错误：每章开始、每一步、每章提交（用时、费用、丢弃几条）、重试（等多久）。结束时标准输出给人读的小结（书 id、提交到第几章、共几章、这次的用时与费用）；`--json` 时标准输出只有 `{"ok": true, "data": <小结>}` 或 `{"ok": false, "error": {"code", "message", "kind"?}}`。
15. **退出码。** 0：抽完，或 `done`、`--preview`、`--status`；1：书库类失败（`book_exists`、`ingest_text_changed`、`ingest_running`、`ingest_bad_text`、书库查询失败）与配置不合格（`qa_unconfigured`）；2：用法错误（含输出 18 的开关与保存的不同）；4：抽取失败停下（`model_failed`、`ingest_bad_reply`）；130：被停止。

### 与书的其他操作

16. **删除。** `book.remove`（`nbstory remove <书 id>`）删除这个 id 的书与抽取记录（第 1 章还没提交的也能删）。这个 id 的任务正在同一个独立服务里运行时，先让它停下再删；正在别的进程里运行时得到 `ingest_running`，书与抽取记录不变（先在那个进程里停下它）。删除成功之后，旧任务不会再写入任何东西，同 id 再发起是 `new`。
17. **问答记录与阅读状态跟书走。** 章的提交不影响这本书的问答记录与阅读状态；它们只随删除书而删除。

### 按书开关

18. **按书关闭数值与秘密。** 新建时可以关掉数值（`--no-ledger`，网页 `features.ledger: false`）与秘密（`--no-secrets`，`features.secrets: false`），两项互相独立，默认都开。
    - 关掉数值：抽取不写状态变动；已有记录不列“当前状态”；核对清单不开对账类的条目（原文有钱数、任务、道具而草稿没记）。
    - 关掉秘密：抽取不写秘密、说法不挂秘密，也不写指向秘密的知情；指向说法的知情与身份类说法照常抽取，程序照常生成知情；已有记录不列“秘密与知情”，也不再提醒“身份说法没有秘密”。
    - 模型仍写出关掉的那类记录时，提交前去掉；这一章的问题里记一条去掉了几条，不计入丢弃的条数（输出 13）。
    - 两项都开时，发给模型的每个请求与没有这项设置时逐字相同。
    - 开关只在新建时定，保存在抽取记录里，之后不改：接着抽、追加、已抽完时不给就沿用；给了与保存值不同的项，得到 `invalid_params`（命令行退出码 2），什么都不改。第 1 章还没提交的书也一样。要换设置，删除这本书后重抽。
    - `ingest.preview`、`ingest.status`、`books.list` 与 `book.info` 给出生效的开关（[`story.queries`](queries.md#边界与兼容)）；查看器与问答按它隐藏对应的页面与查询（[`story.viewer`](viewer.md)、[`story.qa`](qa.md)）。

## 状态与转换

一个书 id 的抽取：

| 状态 | 进入 | 书库里 |
|---|---|---|
| 未提交 | 发起后、第 1 章提交前 | 没有书；`ingest.status` 列出它，id 已被占用 |
| 运行中 | 发起或接着抽 | 第 1 章提交后可以查询 |
| 停下 | 用户停止、失败、运行它的进程退出 | 可以查询已提交的部分 |
| 抽完 | 原文的最后一章提交 | 可以查询全书 |

追加新章（`append`）把“抽完”带回“运行中”。

时序与寿命：

- 章的提交对查询原子可见：一次查询（以及一问，见 [`story.qa`](qa.md#状态与转换)）固定在它开始时的数据上，期间又提交一章不影响它；提交之后开始的查询，无论在哪个进程，读到新的数据。
- 任务停下后 `ingest.status` 立即报 `stopped`；进程被强行结束时，下一次查看进度或发起时识别出运行它的进程已不在，报 `stopped`（运行它的进程已退出），可以接着抽。判断依据是任务本身是否仍在运行，不是进程号是否存在。
- 独立服务里发起的任务随服务停止而停下；服务重新启动后不自动接着抽，要在网页上点继续或用命令行发起。
- 网页只能停止独立服务里运行的任务；命令行运行的任务在网页上显示为运行中（由命令行运行），用 Ctrl-C 停止。

## 副作用与数据

- **抽取记录**：发起后在书库里为这个书 id 保存原文（切好的章）、每个已提交的章的最终记录与问题清单、这一章的说法怎么选的（规则缩减、挑出的编号、退回规则，或没有可选的：第 1 章、没有候选；较早提交的章没有这一项，表示那一章带的是全部已有记录）、每次提交的整理结果、用量（每次请求的 token 数、当时的单价与币种）与任务状态。它不是书的查询数据，书库版本 1 的读者忽略它；随删除书一起删除。模型的原始请求与回复不保存。
- **开关**（输出 18）：新建时写进抽取记录的原文那一份，并随每次提交写进书的数据（`book.features`）与书的元数据；没有这一项的旧记录按都开算。
- **书的数据**：第 1 章提交时创建书目录与新的一代；之后每次提交原子地换成包含新章的数据（只含已提交章的原文）。书的数据由已提交的章与整理结果确定性地得到：同样的已提交内容总是得到同样的书。
- **模型请求**：只发往配置里的服务地址。密钥只从配置指定的环境变量读出交给 HTTP 客户端，不出现在抽取记录、书的数据、输出与错误里。
- 书库格式版本不认识时按 [`story.queries`](queries.md#副作用与数据) 只读不写：发起得到 `unsupported_format`。

## 失败与恢复

| 编号 | 码 | 含义 | 调用方怎么办 |
|---|---|---|---|
| F1 | `ingest_bad_text` | 原文不是 UTF-8、超过 32 MiB，或一个章标题也没有 | 转成 UTF-8；检查章标题的写法（用 `--preview` 看切章结果） |
| F2 | `ingest_text_changed` | 保存的某一章与原文文件不同，或文件少了章 | 改稿重抽不支持：换一个书名（得到新 id）重新抽，或删除这本书后重抽 |
| F3 | `ingest_running` | 这个书 id 已有抽取任务在运行；或要删除的书正被别的进程抽取 | 等它结束，或在运行它的地方停下它 |
| F4 | `model_failed` | 模型请求失败，重试用完或不可重试；`kind` 同 [`story.qa`](qa.md#失败与恢复) F2；换档后仍不接受推理档时为 `provider` | 按 `kind` 处理后接着抽；不接受推理档且没有可换的档位时换模型 |
| F5 | `ingest_bad_reply` | 模型的回复重发一次后仍不成形，或丢弃这一章的记录后书的数据仍有错误 | 接着抽（重做这一章）；反复出现时换模型 |

另沿用：配置缺失或不合格为 [`story.qa`](qa.md#失败与恢复) 的 `qa_unconfigured`；`book_exists`、`book_not_found`、`unsupported_format` 同 [`story.queries`](queries.md#失败与恢复)。

## 边界与兼容

- **公开接口**：`nbstory ingest` 的参数、`--json` 的输出形状与退出码；`ingest.*` 方法的参数与结果；配置文件的 `ingest` 一节。新增可选字段不算破坏兼容。
- 抽取得来的书与导入数据文件得来的书，查询接口与数据格式相同。导入现成数据文件得来的书不受输出 8 约束（数据文件里已经定了称呼的位置）。
- **信任边界**：原文文件与模型回复都是外部输入：原文在切章时校验编码与大小，模型回复只经程序检查后才提交，不合格的记录丢弃。

## 验收与 Smoke

“确定性”的场景用本机的 OpenAI 兼容端点回放事先录下的模型回复（按“第几章、哪一步”回放，遇到认不出的请求立即失败），不调用真实模型。

1. **新建、停止、接着抽（确定性）。** 用样例书前 10 章的原文发起：第 1 章提交时 `books.list` 列出这本书、`extractedThrough` 在第 1 章末；第 3 章的草稿请求进行中按 Ctrl-C：退出码 130，书里是 2 章，`ingest.status` 为 `stopped`（用户停止）；再跑同一条命令：`resume`，抽到第 10 章，书的一代代号始终不变，期间写下的问答记录与阅读状态都还在；第 5、10 章提交时带了整理，`arcs.list` 有归纳到第 10 章的主线。每次提交后书的整份数据没有错误。
2. **追加、改稿与第 1 章前停下（确定性）。** 5 章抽完后（第 5 章是末章，有一批整理），交一份多出第 6 到 10 章的原文：`append`，抽完后书是 10 章，第 5 章那批整理与对象 id 不变、不再请求，第 10 章另有一批；交一份改了第 2 章一段的原文：`ingest_text_changed` 写明第 2 章第几段，书不变；交原样的 10 章：`done`，不调用模型。另一个书 id 在第 1 章请求中停下：书库里没有书、`ingest.status` 列出它，`book.import` 同 id 得到 `book_exists`，再发起是 `resume`，`nbstory remove` 能删除它。
3. **提交的原子性（确定性）。** 在第 3 章提交的各个阶段强行结束进程，之后查询与接着抽看到的章数一致（要么 2 章、要么 3 章），接着抽的结果与不中断时相同；已经开始的查询在提交后继续读到 2 章的数据，提交后新开始的查询（另一个进程、以及预先查询过这本书的同一进程）读到 3 章；第 3 章提交前取的分页游标在提交后得到 `cursor_invalid`；一问跨过这次提交，所有工具仍读到 2 章的数据，下一问读到 3 章。
4. **一个书 id 一个任务（确定性）。** 命令行任务运行中，网页 `ingest.start` 同一个 id 得到 `ingest_running`，网页进度显示它由命令行运行；网页 `book.remove` 这本书得到 `ingest_running`，书不变；两个任务同时发起恰有一个开始；强行结束运行任务的进程后，`ingest.status` 报 `stopped`（运行它的进程已退出），可以接着抽。独立服务同时抽两本书，停止或删除其中一本，另一本照常。
5. **重试、跑飞与不成形（确定性，注入时钟）。** 端点对草稿请求先回两次 503、再回正常：这一章照常提交，进度里有两次重试，端点共收到 3 次 HTTP 请求；一直回 503：端点共收到 6 次后以 `model_failed` 停下，退出码 4，已提交的章保留；回 401：不重试，立即停下；拒绝 `minimal` 但列出 `low`：改用 `low` 重发，这一章照常提交；拒绝且不列档位：以 `model_failed`（`provider`）停下；回一段坏 JSON 后接着发空白：2000 个空白后中止、按跑飞重发；回非 JSON、被截断、没有段落块：重发一次后以 `ingest_bad_reply` 停下，这一章不提交；这一章的时间点与前一章的构成先后矛盾、且由丢弃这一章的时间点能消除：照常提交，问题数计入；整理回复不合格：这一章照常提交、问题记进这一章。中止与跑飞的请求让用量标为不完整。
6. **切章（确定性）。** 一份含书名与简介、“第一卷 小丑”、“楔子”、“第1章”、“第 2 章”、“第３章”、“第二十三章绯红”、“第三回合开始了”、“序言里提到的那个人”、40 字与 41 字的标题样的行、以“」”结尾的短行、以“！”“？”“……”结尾的章标题、只有标题的章、两个同名标题的原文：`--preview` 的章、`preambleChars`、`volumeLines` 都与 Spec 的规则一致（“第三回合开始了”“序言里提到的那个人”、41 字的行、以“」”结尾的行留在所在章里，以“！”“？”“……”结尾的章标题各开一章）。样例书 100 章拼回的原文切回 100 章。不是 UTF-8 的文件、没有章标题的文件得到 `ingest_bad_text`。
7. **称呼与回补知情的可见位置（确定性）。** 第 1 章原文里出现“北斗星”这个字串、第 2 章才交代它是林晚的代号：第 2 章提交后，阅读位置在第 1 章时林晚的人物卡、第 1 章原文段落的名字与搜索里都没有“北斗星”；阅读位置在第 2 章时有。第 6 章建的秘密只由第 3 章的说法组成，并给第 3 章已知情的人补记知情：阅读位置在第 5 章、第 6 章中间时这个秘密与这条知情都不可见，读完第 6 章可见。
8. **删除（确定性）。** 网页发起的任务运行中删除这本书：任务停下，书与抽取记录都不在了，`ingest.status` 不再列出它，之后没有任何文件被旧任务写回；同 id 再发起是 `new`。
9. **密钥与配置（确定性）。** 用可辨认的假密钥跑场景 1：端点收到它，抽取记录、书的数据、标准输出与标准错误里都没有它。只有问答模型（第 1 版的 `model`，升级后是自定义服务商 `custom`）时抽取用它；用 `config set ingest.model '<JSON>'` 建抽取模型后用新的那个，`config unset ingest.model` 后回到问答的默认模型。
10. **服务响应（确定性）。** 独立服务抽取一本 100 章的书（回放）期间，每次章提交时对另一本书的查询、`ingest.status` 与 `ingest.stop` 都在 1 秒内返回。
11. **真实模型（回归）。** 用 gpt-6-luna 把样例书前 20 章独立抽三次：每次每章都提交、书的整份数据没有错误；用 20 章 53 条关键记录的尺子（见“证据”）各打一次分，三次合计不低于 360（满分 477；抽取管线定型时中档三次合计 384）；记下每次的用时、费用与每章丢弃的记录数。

Smoke：在真实书库与独立服务上，网页导入样例书前 3 章的原文，用真实模型抽完，抽取中途停止一次再继续，抽完后在查看器里打开。

## 实现合同

- **公开入口**：命令行 `nbstory ingest`（包 `@notnotype/nb-story` 的 bin）；独立服务 `nbstory serve` 的 `ingest.preview`、`ingest.start`、`ingest.stop`、`ingest.status`（合同 `INGEST_METHODS`，与查询方法同一份 `src/contract/contract.ts`）；配置的 `ingest.model`、`ingest.recall` 与 `nbstory config test --ingest`。
- **owner 与依赖方向**：nb-story。抽取（`src/ingest`）依赖本包的核心库（`src/core`，只经注入的 id 协调者与它交互）与 `openai` SDK；不依赖 nb-harness，抽取线程与 `nbstory ingest` 不加载 OMP。核心库不依赖抽取。
- **关键不变量**：
  - 一章的提交是书目录里 `book.json` 的一次改名，新版本的数据文件先写好；提交前整本书编译没有错误（`runner.test.ts` 的提交先后、`chapter.test.ts` 的整理带来的错误）。
  - 导入、抽取的发起与删除拿同一把不随书删除的 id 锁，锁由主线程持有；删除先停本进程这个 id 的任务（含正在启动的）（`runner.test.ts`、`server/ingest.test.ts` 的删除与停服分组）。
  - 发给模型的文字（提示词、规则）与抽取管线定型时录下的请求逐字相同：普通章的请求把已有记录换回全量后逐字相同，并与封存的请求基线逐字相同；全量整理的请求同样与封存的请求基线逐字相同，增量整理的请求与另一份封存的基线逐字相同（基线见 `tests/fixtures/README.md`）（`context.test.ts`、`chapter.test.ts` 的回放）。整理的材料见输出 4（`consolidation-context.test.ts`），旧的整批整理稿编出的书与改前相同（`compile.test.ts` 的各前缀对照）。普通章已有记录的选法见输出 4（`context.test.ts` 的小书），质量由真实模型回归验证（见“证据”的批准依据）。
  - 每次 HTTP 尝试先写“开始”再发请求，结束再结算；拿不到用量的合计标不完整（`runner.test.ts` 的强行结束、用量与用时分组）。
