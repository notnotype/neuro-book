# 剧情图谱：书库与按阅读位置的查询

## 目标与非目标

给查看器、命令行和以后的 NeuroBook 插件一份共同的查询接口：把抽好的 V9 小说记忆图收进本机书库，按“读到哪里”回答人物、身份、谁知道什么、数值、悬念、时间线、情节、原文、搜索与图的查询，每条结果都能回到原文的“章.段”。同一份方法清单有两种调用形式：进程内直接调用（命令行用）与独立服务的 HTTP（网页用）；以后插件的 Agent 工具也按这份清单提供。

明确不承诺：

- 查询不修改图里的记录。用户对图的修订由 [`story.revisions`](revisions.md) 另存，查询看到的是套用修订之后的数据（没有修订的书与以前逐字相同）。导入（`book.import`）只收已经抽好的数据；从原文抽取见 [`story.ingest`](ingest.md)，抽出的书经本 Spec 查询，用法相同。
- 不含问答本身：内置问答见 [`story.qa`](qa.md)，它把本 Spec 的方法当作答 Agent 的工具；外部 Agent 经 [`story.cli`](cli-skill.md) 的命令行与 Skill 问答。
- 不给图排版：图的方法只给点与线，位置由使用方算。
- 独立服务只供本机使用：不监听局域网，不支持多用户。
- 书库管理只有列出、导入与删除。
- 数据里推不出的身份不补：抽取没有以确定事实连起来的两个对象，不当作同一人。
- 记录等级（输出 23 到 27）是给人看的排序提示，不是事实判断。已知限制：规则表与阈值只在两本书（样例书与西游记 100 回）上校准过；后文用词与这条说法不同（转述、文白差别）时回响偏低；同一条说法的等级随阅读位置与后文变化。抽取时模型给的先验偏保守：样例书前 5 章的两次真实抽取里先验 3 级约占一成（事后标注同一本书约一成六到一成八），情节的先验多是 1 级，所以新抽的书默认折叠的说法不多。

## 术语与参与者

- **书库**：本机上存放书的目录；一本书一个子目录。
- **书的一代**：一次成功的导入，或一次抽取写进书里的第 1 章。删除后再用同一个书 id 导入或抽取，是新的一代；每一代有不复用的代号。
- **抽取进度**：抽取得来的书在同一代内抽完的章数（见 [`story.ingest`](ingest.md)）；每抽完一章，书的数据更新一次，仍是同一代。导入数据文件得来的书没有抽取进度的变化。
- **阅读位置**（`at`）：读到第几章，或第几章第几段。记作 `章` 或 `章.段`，例如 `38`、`38.57`。只给章时表示读完这一章。
- **可见**：一条记录在阅读位置 P 可见，当且仅当它在原文中成立的位置（记录的 `at`）不晚于 P。
- **视角**：按谁知道的事回答。默认是读者；也可以是书里的某个角色。
- **身份连接**：数据里把两个对象说成同一人的身份类说法；一个身份秘密名下列出它所依据的若干条这样的说法。**确定的身份连接**指确定性为确定、且是旁白明说或角色认为（数据的 fact 或 belief）的那些；确定性为候选的，以及只是角色的说法（claim，角色可能说谎）的，是不确定的。
- **出处**：“章.段”或“章.段—章.段”，指向原文。
- **记录标记**：每条说法与知情记录带的“明说、角色的说法、角色认为”（对应数据的 fact、claim、belief）与是否推断。

## 输入与前置条件

### 书库与导入

- 书库默认在用户数据目录下的 `nbstory/`（Linux 是 `~/.local/share/nbstory/`），调用方可以另指定。
- 导入的输入是 V9 记忆图数据文件（`schema` 为 `neurobook.memory.v9`，含原文）。其它 `schema` 拒绝导入。

### 阅读位置的规则

| 输入 | 含义 |
|---|---|
| 不给 `at` | 读到全书已抽取的最后位置 |
| `at = {chapter}` | 读完这一章 |
| `at = {chapter, paragraph}` | 读到这一章的这一段（含） |
| 章或段超出全书范围、或为 0 与负数 | `position_out_of_range` |

### 方法清单

- **书级方法**的参数一律带 `book`（书库只有一本书时可省略）与可选的 `at`、`perspective`（默认 `"reader"`，或一个角色的对象 id；不适用视角的方法忽略它）。**书库级方法** `books.list` 与 `book.import` 不带这些参数。
- 对象参数可以写对象 id，也可以写名字或称呼；按 P 可见的名字与称呼解析，对应不止一个对象时得到 `entity_ambiguous`，错误里列出候选（id、显示名、简短说明）。
- 长列表带 `cursor` 与 `limit`（默认 50，上限 500），结果附 `next` 与 `total`。
- 每个方法的参数与结果有一份机器可读的 schema，随包公开，命令行、独立服务与以后的插件通道都按它校验；下表列出结果里必须有的字段，schema 可以多、不可以少。

| 方法 | 主要参数 | 结果里必须有的字段 |
|---|---|---|

关系图的公开类型：

```ts
type Position = {chapter: number; paragraph?: number};
type Ref = string; // "38.57" 或 "38.50—38.81"
type Perspective = "reader" | EntityId;
type IdentityState = "uncertain" | "unaware" | "no-record" | "heard" | "believes" | "suspects";

type RelationNode = {id: NodeId; label: string; kind: EntityKind; mentions: number; entities: EntityId[]; names?: string[]};  // names：其他称呼（别名），见输出 16；核心库总是给，旧的生产者可以不给，使用方按空数组处理
// 一对点一条线，几种联系合在一起给
type RelationEdge = {
    a: NodeId; b: NodeId;
    relation: {word: string | null; statements: number} | null; // 关系说法
    together: number;                                           // 同场的情节数，低于门槛时为 0
    knows: {ab: number; ba: number} | null;                     // a 知道关于 b 的条数、b 知道关于 a 的条数；角色视角下为 null
    identity: IdentityState | null;                             // 两点之间的身份连接状态，见输出 4、5
};
```

## 输出与可观察行为

### 阅读位置与视角

1. **不剧透。** 任何方法在阅读位置 P 的结果里，不出现 P 之后才成立的记录、称呼、身份连接与合并、秘密揭晓、数值变动、悬念与悬念进展、情节、主线归纳、时间点与段落概要，也不出现 P 所在章之后各章的标题；所有计数与排序都只按可见的记录算。结果里引用的关联对象（时间关系的另一端、知情记录所指的说法或秘密、情节连接的另一段）不可见时，这个引用省略，不把关联对象原样带出。过滤在核心库里做，两种调用形式结果相同。唯一的例外见输出 14：P 所在章里 P 之后段落的原文。
2. **统计。** `book.stats` 的 `visible` 按 P 计；`chapters` 逐章给出成立在这一章的可见说法、知情记录、情节、数值流水、新提出与解答的悬念条数，只到 P 所在章；`cast` 取 P 之前出场最多的至多 12 个人物，给出各自逐章的出场次数（只数 P 之前的称呼出现）；`extraction` 是全书抽取过程的统计（草稿写了多少条、程序生成了多少条），不随 P 变，结果里标明它覆盖全书。
3. **读者视角的身份合并。** 两个对象在 P 被合并成一个人，当且仅当 P 之前有一条连接它们的确定的身份连接；合并有传递性。只有不确定身份连接的两个对象不合并，二者之间给 `identity: "uncertain"`。合并后的点带上组成它的全部对象 id。
4. **显示名。** 一个点的显示名是它的代表对象 P 时可见的主名（代表是点里 P 之前出现次数最多的人物，没有人物时取第一个成员；点 id 也是代表对象的 id）；没有可见主名时，取 P 之前出现次数最多的称呼；一个称呼也没有时，显示“未具名身份”。两个不同的点显示名相同时，次要的一个在名字后加简短说明以示区分。
5. **角色视角。** 以角色 C 为视角时：
   1. C 自己的几个对象总是合并；别的两个对象，当且仅当连接它们的确定的身份连接在 P 时被 C 知道（C 对这条身份说法或对应的身份秘密，P 之前最新的知情状态为知道或读到）才合并。同一位置既有对秘密的知情记录、又有对说法的知情记录时，以对秘密的为准。
   2. 只用 C 在 P 时知道、听说或认为的说法；`knows` 为 `null`。
   3. 读者视角下合并、C 却不合并的两个点之间，`identity` 取 C 对这条身份连接的状态：`"unaware"`（明确不知道）、`"heard"`、`"believes"`、`"suspects"`，或 `"no-record"`（没有任何记录）。读者视角下也不确定的连接在角色视角里不给。
   4. 可选的视角是 P 时至少有一条知情记录的人物。

### 各组查询

6. **名册。** `entities.list` 按 P 之前的出场次数排序，可按类别筛、按名字或称呼搜。
7. **人物卡。** `entity.card` 给出全部可见称呼与各自首次出现的出处、读者此时知道的同一身份、各方面的概况（取 P 之前最新的一次归纳）、知道的秘密（每个秘密一格，没有记录时写“没有记录”）与各列表的条数；长列表另用 `entity.knowledge`、`entity.statements`、`entity.episodes` 分页取。
8. **记录标记。** 说法与知情记录都带记录标记；推断出的记录照常返回并标明推断。
9. **秘密矩阵。** 读者一行：这个秘密名下的身份说法里有一条在 P 之前是确定的身份连接、或读者最新的知情状态为知道或读到时，格为“知道”，出处取最早成立的那一条；否则取读者最新的知情状态。人物各行取 P 之前这个人对这条秘密的最新状态与出处（同一位置以对秘密的知情记录为准）；没有记录的格给“没有记录”，不推断为不知道。有知情记录的格另给它的“怎么知道的”。人物列带读者在 P 时知道的这个人的其他身份名（例如苏天晴在第 8 章起带“心月狐”）。
10. **数值对账。** `ledger.track` 的流水按出处先后排好、逐笔累加。原文直接报出余额的一笔以原文为准，`gap` 给出与累加值的差额；第一笔不是原文报数时，起始金额未知，余额以相对值给出，`relative` 为真。
11. **悬念。** 状态是未解、有进展、已解，取 P 之前的最新进展；每条带提出与每次进展的出处。到 P 为止没有任何进展、且只在提出它的那一章被提到的悬念，`trivial` 为真。相关情节是出处与这条悬念的提出或可见进展的出处有重叠的可见情节，按章排序。
12. **时间线。** 时间点按故事时间（第几天、时段、同一天内的先后）排序，也可按出处排序；故事时间更早、却在后面的章才写到的点标为补叙；日子未知的点单独成组，不参与补叙判断。每个点带故事时间是它的可见情节（标题、参与者、地点）。
13. **情节与主线。** 情节按章分组，带参与者（以及以什么身份出场，例如“以地狱猫的身份”，没有记录时为空）、地点、故事时间（所挂的时间点，不可见时为空）、步骤（各带出处）、结果与它和前面情节的连接（接着、在其后、起因、动机、前提、重述，带数据里的说明）。主线取 P 之前最近的一批归纳（归纳到的章数最大、不晚于 P 的那一批），作为当前的完整主线列表，不与更早的批次累计；同一条主线在后面的批次里沿用编号，各批的标题、概要与所含情节可以不同；P 之前、这一批里没有的情节标为“未归入主线”。`graph.book` 按主线聚合时用同一批。
14. **原文。** `source.read` 给出 P 所在章及之前各章的原文。P 所在章里 P 之后的段落照常给原文（这是输出 1 唯一的例外），但这些段落的 `recordCount` 为 0、`names` 只含 P 时已可见的名字，`source.records` 对它们返回空列表。段落概要只在它所概括的整段范围在 P 时都可见（概要本身可见）时给出，P 落在范围中间时不给。请求 P 所在章之后的章得到 `beyond_position`。
15. **搜索。** `search` 只在可见的内容里搜（原文只搜到 P 为止）；结果分对象（名字与称呼）、说法、原文三类，每条带出处。`query` 按空白与标点拆成若干词（去掉空词与重复的词）；一条内容含其中任一个词就算命中；各类内按含的不同词数从多到少排，词数相同的按出现先后；原文片段截在第一个命中的词周围。只有一个词时，等同于找含这个词的内容。
16. **关系图。** `graph.relations` 按视角给点与线：点可按类别筛；一对点只有一条线（`RelationEdge`）。关系词取记忆图对这一对的归纳；数据里没有这项时，按亲属类说法、社交类说法中的关系称谓、所属类说法的先后推断，推断不出时为 `null`；亲属类说法里找不到亲属词（姐妹、父女、母亲、祖母、同父异母……，或“亲属、亲人、亲戚、家人”；带方向的词写成对称的“亲子”“祖孙”，不单凭一个字，所以“弟子”不算）时不写“亲属”，往下看社交称谓与所属（魔女的师承辈分“直系后辈”不是血亲）。`view` 写明这个视角用了多少条说法、有哪些身份连接这个视角不合并（各带 `identity` 状态）。每个点带 `names`：点里各对象在阅读位置之前已出现的其他称呼（去重、不含显示名，之后才揭晓的称呼不带出），供图上的搜索按别名查；`graph.book` 的对象点同样带，别的类型的点没有。
17. **全书图。** `graph.book` 给对象、主线（或逐段情节，由 `grain` 选择）、秘密、悬念四类点与它们之间的线，可按类型筛；按主线聚合时，主线与对象之间的线带这个对象在这条主线里出场的情节数。
18. **故事线。** `graph.storyline` 给若干行（主要人物或事物，交汇最多的排在中间，与它交汇多的排在两侧）与每段情节在各行上的点；行的选择与顺序在同一代数据、同一位置下固定。

### 阅读状态

19. **阅读状态跟书走。** `reading.set` 用新的阅读位置与界面状态（使用方定义的 JSON，至多 64 KiB）整份替换这本书存的阅读状态；返回成功即已写入书库，之后任何调用方的 `reading.get` 都读到它（或更晚的一次）。书从没存过时，`reading.get` 返回全书开头、界面状态为空。
20. **关系一览。** `entity.relations` 列出这次视角下和这个对象有联系的每个对象：两人之间的说法（about 同时落到两人）、一起出场的情节（参与者按输出 13 的出场身份解析）、认知（只在读者视角）、身份连接，任一种都算。每项给最强的一种联系，从强到弱是身份连接（两头都是人物时）、关系说法（亲属、交往、所属）、态度、其他说法、同场、认知，按这个顺序再按联系多少排；带关系词（同输出 16）、各种联系的条数、一句说明（只涉及这两人的说法优先，其中最近的关系说法、再是态度、再是任一条）与最近一段一起出场的情节。人物卡的关系条数等于这份列表的长度。
21. **两人之间。** `entity.relation` 给出两个对象之间的全部说法（带类别、短标签、持有人、记录标记与出处，按出处先后）、一起出场的情节、各自知道的关于对方的事（各取最近的至多 20 条，只在读者视角），以及关系词与身份连接。
22. **泛称与无名对象。** 不指向具体某个人、只说身份或类别的称呼是泛称（学姐、新生、老师、少女、女人、男生……，前面带“那个”“一位”等指示词的同样算；整个词是泛称，或整个词能完全拆成几个泛称（“志愿者学姐”）才算，“墨学姐”“绯烟老师”带专名不是泛称）。名字是泛称的称呼不计入出场（草稿手工指定了归属的出现除外，有这种出现的对象也不是无名对象）（对象的出场数、同场权重不含它们），阅读页里也不把原文里的泛称链到对象；人物、马甲、组织里，阅读位置时可见的称呼全是泛称（或没有称呼）的对象是无名对象。`graph.relations` 默认不画无名的点，参数 `includeAnonymous: true`（命令行 `--include-anonymous true`）时画出；对象的连线说明与人物卡小图要解释用户正在看的某个对象，总是带 `includeAnonymous: true`；点与 `entities.list` 的行带 `anonymous: true`（有专名的不带）。对象列表照列无名对象，出场数低、自然排在后面。

### 记录等级

等级是 1（主线必需）、2（有用）、3（次要）三级，由模型抽取时写的**先验**（说法与情节的 `tier`，见 [`story.ingest`](ingest.md)）与程序在阅读位置 P 算的**后验证据**按规则表合并。

23. **后验证据。** 只对说法算，只用 P 以前的数据，不依赖视角：
    1. 后文引用：引用方所在章大于这条说法所在章、且在 P 以前成立的确认、反驳、修订（别的说法的 `rel`），后来得知它的人（草稿写的知情，不含程序推出的，按人去重），收录它的后文秘密，以它为解答的后文悬念进展。同一章里写的引用不算。
    2. 回响：这条说法文字里的 4 字词组（按标点切开，不跨句；碰到说法里 P 时已出现的称呼的、与称呼互相包含的不算），在 P 以前出现过的章数（原文与记录文字都算，P 所在章只算 P 以前的段）至少 2、至多“P 所在章号的 40%，至少 5”，并且在说法所在章之后出现过。
    3. 证据：后文引用至少 1 处，或回响词组至少 5 个，为“强”；否则 P 所在章号减去说法所在章号小于 5 时为“未知”；否则有回响为“有一点”，没有为“没有”。
24. **合并规则。** 有先验时查表一，没有先验时按说法的类别查表二；表一的两格另带标记 `tierFlag`：先验 1 级而证据“没有”为 `unconfirmed`（待证实），先验 3 级而证据“强”为 `foreshadow`（伏笔候选），其余为 null。

    表一（有先验）：

    | 先验＼证据 | 未知 | 没有 | 有一点 | 强 |
    |---|---|---|---|---|
    | 1 | 1 | 2（待证实） | 1 | 1 |
    | 2 | 2 | 2 | 2 | 1 |
    | 3 | 3 | 3 | 3 | 2（伏笔候选） |

    表二（没有先验）：

    | 类别＼证据 | 未知 | 没有 | 有一点 | 强 |
    |---|---|---|---|---|
    | identity、rule、goal、kinship | 2 | 2 | 1 | 1 |
    | event、social、membership、possession、trait、other | 2 | 3 | 2 | 1 |
    | attitude、location | 2 | 3 | 3 | 2 |

    数据里的先验不是 1 到 3 的整数时，按没有先验算。
25. **人物卡的说法。** `entity.statements` 每条带 `tier` 与 `tierFlag`；`maxTier` 只留等级不高于它的说法，保持原有顺序，`total` 是过滤后的条数；页里的 `tiers` 是满足 `query` 的说法里 1、2、3 级各几条，不随 `maxTier`、`limit` 与游标变。同一条说法在读者与角色视角下等级相同。
26. **情节的等级。** 情节只有先验：`entity.episodes`、`episodes.list`、`entity.relation`、`questions.list` 里的情节带 `tier`，就是数据里的先验，没有为 null。对象不分级。
27. **依据。** `tier.explain` 给一条 P 时可见的说法或情节的等级与依据：`kind`、`tier`、`prior`、`flag`；说法另有证据 `ev`、窗口 `window`（P 所在章号减去说法所在章号）与 `signals`（后文引用分来源的计数；回响词组的个数，以及给人看的至多 5 句回响词句：说法里相邻或重叠的回响词组连成一句），情节这几项为 null。P 时不可见或不存在的 id 一律得到 `record_not_found`。只给结构化的数，文字由使用方写。

## 状态与转换

书的状态：

| 状态 | 进入 | 可见性 |
|---|---|---|
| 导入中 | `book.import` 开始 | 不出现在 `books.list` 里，按 id 查询得到 `book_not_found` |
| 可用 | 导入完成，或抽取写进第 1 章，得到新的一代 | 全部查询可用 |
| 可用，数据更新 | 抽取又抽完一章 | 同一代；章数与 `extractedThrough` 变大，查询读到新数据 |
| 已删除 | `book.remove` | 不再出现；开始于删除之前的查询照常完成 |

时序与寿命：

- 查询结果是阅读位置、视角、书的一代与抽取进度的纯函数：同一代、同一抽取进度、同一参数总是得到同一结果（含排序与分页）。抽取进度变了，较早阅读位置上的结果也可能变（例如新学到的称呼在前文的出现次数）。
- 一次查询固定在它开始时的那一代与抽取进度上完成；删除、同 id 重新导入或又抽完一章都不影响已经开始的查询，也不会让它读到之后的数据。
- 导入在完成之前对任何调用方都不可见；导入失败或中途退出不留下半本书。同一个书 id 的两次并发导入恰有一次成功，另一次得到 `book_exists`。
- `cursor` 绑定书的一代、抽取进度与一组参数，跨进程、跨服务重启都有效；书被删除、换了一代、抽取进度变了或参数不同时，用它得到 `cursor_invalid`，从第一页重新取即可。
- `reading.set` 按到达书库的先后生效，后写入的整份覆盖先写入的；两次并发写入都返回成功，`reading.get` 读到后写入的那一次。
- 独立服务：登录口令随服务启动生成，在服务停止前可以反复用来登录（换浏览器也可以）；会话在服务停止前一直有效，没有闲置超时；服务停止后口令与全部会话作废，进行中的请求随连接断开结束。

## 副作用与数据

- 书库目录 `<书库>/<书 id>/`：书的信息（含这一代的代号）、导入的数据文件、阅读状态。书库格式版本 1；遇到不认识的版本，只读不写，写入类方法得到 `unsupported_format`。
- 只有 `book.import`、`book.remove`、`reading.set`、[`story.ingest`](ingest.md) 的抽取与 [`story.revisions`](revisions.md) 的写入类方法写书的数据；其余方法只读。抽取更新书的数据时原子替换数据文件，不改阅读状态与问答记录。问答记录由 [`story.qa`](qa.md#副作用与数据) 写在书目录的 `qa/` 下，随书删除。独立服务的运行登记由 [`story.cli`](cli-skill.md#副作用与数据) 规定，不属于书的数据。
- 原文、图与阅读状态都只在本机书库里；独立服务不向外发请求。

## 失败与恢复

| 编号 | 码 | HTTP | 含义 | 调用方怎么办 |
|---|---|---|---|---|
| F1 | `book_not_found` | 404 | 书不存在、已删除或还在导入 | 用 `books.list` 查可用的书 |
| F2 | `book_ambiguous` | 400 | 省略了 `book`，书库里有不止一本 | 指定 `book` |
| F3 | `book_exists` | 409 | 导入时书 id 已被占用（含还在抽取、第 1 章没提交的 id，见 [`story.ingest`](ingest.md)） | 换书名或指定新 id |
| F4 | `unsupported_format` | 415 | 导入文件不是 V9 记忆图，或它的 `book.features` 关掉了数值（或秘密）却带着这类记录；或书库版本不认识 | 换文件；升级程序 |
| F5 | `position_out_of_range` | 400 | 阅读位置超出全书范围或不合法 | 改正位置 |
| F6 | `beyond_position` | 403 | 请求了阅读位置之后的章 | 先把阅读位置往后拨 |
| F7 | `entity_not_found` | 404 | 对象在这本书里不存在，或在阅读位置还没出现 | 用 `entities.list` 或 `search` 查 |
| F8 | `entity_ambiguous` | 409 | 名字或称呼对应不止一个对象 | 从错误里列出的候选中改用 id |
| F9 | `invalid_params` | 400 | 参数不符合方法的 schema | 按 schema 改正 |
| F10 | `cursor_invalid` | 410 | 分页游标对应的书已删除、换了一代、抽取进度变了，或参数不同 | 从第一页重新取 |
| F11 | `state_too_large` | 413 | 界面状态超过 64 KiB | 缩小界面状态 |
| F12 | `unauthorized` | 401 | 独立服务：请求没有有效的会话，或登录口令不对 | 用服务启动时打印的登录链接重新登录 |
| F13 | `record_not_found` | 404 | `tier.explain` 的 id 在阅读位置不可见或不存在 | 用列表里给出的 id |

## 边界与兼容

- **公开接口**：方法清单与各方法参数、结果的 schema；新增方法与可选字段不算破坏兼容。
- **按书开关**：书的数据里可选的 `book.features: {ledger?: boolean, secrets?: boolean}` 说这本书记不记数值与秘密，由 [`story.ingest`](ingest.md) 输出 18 在新建时定；缺这一项或缺某一项时按开算，所以开关之前的书与不写它的数据文件照旧。`books.list`、`book.info` 的 `features` 是补齐后的生效值。书里没有关掉的那类记录（导入时由 F4 保证），其余方法不按开关另做判断：`secrets.matrix` 没有行，`ledger.tracks` 没有轨道，`ledger.track` 给任何轨道名都得到 `entity_not_found`。
- **独立服务的 HTTP**：
  - `POST /api/rpc/<方法名>`，请求体是参数的 JSON；成功返回 200 与结果，失败返回上表的 HTTP 状态码与 `{code, message}`（`entity_ambiguous` 另带 `candidates`）。
  - 登录链接是 `http://127.0.0.1:<端口>/login?token=<口令>`。这是唯一不要求会话的地址：口令对时建立会话（浏览器 Cookie，只供 HTTP、同站）并跳转到查看器首页；口令不对时返回 401 页面。
  - 其余地址（含静态网页资源）都要求会话；没有会话的页面请求返回 401 页面，RPC 返回 `unauthorized`。
- **信任边界**：独立服务只监听本机回环地址。
- **以后接入 NeuroBook**：插件通道与 Agent 工具按同一份方法清单与 schema 提供，错误码不变。

## 验收与 Smoke

1. **不剧透（全量）。** 用已抽好的 100 章样例书（《转生反派萝莉，找茬魔法少女》），在第 1、8、38、100 章与 38.57 几个位置调用全部只读方法：结果中出现的每条记录、称呼、合并、引用、主线与章标题，其成立位置都不晚于阅读位置；唯一的例外是 38.57 时第 38 章第 58 段以后的原文。
2. **身份随位置合并。** 读者视角下：6.95 时苏天晴与视频里的魔法少女狐狐是两个点，6.96 起是一个点；花铃与白色少女在 27.90（苏天晴确认）起是一个点；南嘉鱼与地狱猫在 37.8 起是一个点；只有角色自称连着的深蓝色的倩影与地狱猫之间是 `identity: "uncertain"`。
3. **角色视角。** 第 38 章、以苏天晴的视角：南嘉鱼与地狱猫是两个点，二者之间 `identity` 为 `"unaware"`（她对相应秘密最新的知情状态）；以南嘉鱼的视角：风信子与南小风之间为 `"no-record"`；两个视角下 `knows` 都为 `null`。
4. **秘密矩阵的读者行。** 第 38 章，“深蓝猫娘是南嘉鱼的反派身份”一行的读者格为“知道”，出处是第 37 章第 8 段的旁白，而不是第 30 章的“怀疑”。
5. **数值对账。** 第 38 章的神典石流水里，38.36 原文报数 1300 的一笔 `gap` 为 +800。
6. **主线批次。** 第 38 章 `arcs.list` 只给归纳到第 35 章的那一批；第 1 章第一段情节只属于这一批里的一条主线，不重复出现。
7. **原文边界。** 阅读位置 38.57 时：读第 39 章得到 `beyond_position`；第 38 章第 60 段有原文、`recordCount` 为 0；从第 48 段开始、到第 81 段才完整的段落概要不出现在第 48 段上。
8. **两种调用形式一致。** 同一参数下，进程内调用与 `POST /api/rpc/<方法>` 的结果逐字段相同。
9. **一代与游标。** 取 A 的第一页 → 删除 A → 同 id 导入 B → 用旧游标取下一页，得到 `cursor_invalid`；删除前已开始的查询返回的仍是 A 的数据。
10. **导入原子性。** 导入中途结束进程后，书库里没有这本书，`books.list` 不列出它；同 id 并发导入两次，恰有一次成功。
11. **登录。** 新的浏览器配置打开登录链接后能取页面与调用 RPC；用同一个链接在第二个浏览器也能登录；服务重启后旧会话的请求得到 `unauthorized`，新链接可用。
12. **等级不剧透。** 样例书在第 10、20、35 章末与第 20 章中间，全量数据算出的每条说法的等级与依据，等于把数据（记录、称呼、悬念进展、原文）截到这个位置后在同一位置算出的。

Smoke：在真实书库与独立服务上，用 100 章样例书跑场景 1、7、8、11。

## 实现合同

- **公开入口**：包 `@notnotype/nb-story` 的核心库入口（`createStoryApi`、`Library` 与数据类型）；方法清单与 schema `@notnotype/nb-story/contract` 的 `STORY_METHODS`（插件通道用的 `storyContract` 同在其中）；独立服务 `nbstory serve` 的 `POST /api/rpc/<方法名>` 与登录链接。
- **owner 与依赖方向**：nb-story。核心库（`src/core`）只依赖本包的合同、TypeBox 与 `@notnotype/nb-runtime/remote`，不依赖命令行、服务、网页、问答与抽取；它们都经 `createStoryApi` 调用核心库。
- **关键不变量**：
  - 所有查询只经同一个按阅读位置投影的只读视图取数；记录的成立位置取它自身位置与全部出处终点里最晚的那个，引用不可见记录的字段整项省略（`spoiler.test.ts`、`projection.test.ts`）。
  - 一次查询在开始时固定书的一代与数据版本；导入把写好的整个书目录一次改名放进书库，抽取的每次提交是 `book.json` 的一次改名，查询读不到半份数据（`library.test.ts` 的固定一代、导入中途结束进程）。
  - 游标只编码“代号:数据版本”、参数摘要与偏移，不含进程状态，所以跨进程、跨服务重启都有效（`api.test.ts` 的游标四组）。
  - 身份合并只按确定的身份连接；角色视角另按这个角色对身份连接的最新知情状态重算（`identity.test.ts`）。
  - 进程内调用与 HTTP 走同一份方法实现与 schema 校验，结果逐字段相同（`server.test.ts` 的 RPC 一组）。
  - 记录等级不存盘：与位置无关的底稿（词组、词组出现的章、后文引用）每个索引建一次，某个位置的表按位置截取，每个索引留最近 8 个位置；底稿里每个量带自己的位置，所以截断对照成立（`tiers.test.ts`）。
