# 资源寻址与文件服务

## 目标与非目标

用 `方案://路径` 统一寻址项目、用户资产、临时目录、Agent 会话工作目录与参考文档等资源。文件服务按方案把请求分派给提供者，提供者声明自己的能力；读写、列出、glob、grep、监视都经文件服务，写入记录来源并发出变更事件。资源管理器、编辑器、Agent 文件工具与 History 等插件都是它的使用方。

非目标：远程文件系统提供者；全文索引与搜索服务；回收站与文件操作撤销；普通文件的稳定身份与引用维护（只有活页夹章节有稳定身份，见 [workspace.folder-kinds](folder-kinds.md)）；`chapter://`、`plot://` 的具体提供者（随剧情改造另定）。

## 术语与参与者

- **资源地址**：`方案://路径`，路径用 `/` 分隔，相对该方案的根；不包含服务端绝对路径。
- **提供者**：实现某个方案的读写、列出、监视等操作的对象，由内置插件或插件注册。
- **真实目录型提供者**：方案根对应一个真实目录，可以给出资源的真实路径。
- **虚拟提供者**：数据不在真实目录中（例如数据库），没有真实路径。
- **能力声明**：提供者对读、写、列出、glob、grep、监视、真实路径（bash 可用）的逐项声明。
- **文件服务**：按方案分派请求、记录写入来源、汇总变更事件的唯一入口。
- **来源**：一次写入的发起方，取值为写作者（人）、Agent 会话（带会话 id）、系统、外部。
- **使用方**：资源管理器、编辑器、Agent 文件工具、插件等经文件服务访问资源的调用者。

## 输入与前置条件

- 请求携带资源地址与操作；写入还携带来源。来源由宿主依调用路径填写（界面操作为写作者，Agent 工具为其会话，系统任务为系统），调用方不能自称为其它来源。
- 本能力首批方案：

  | 方案 | 根 | 类型 | 说明 |
  |---|---|---|---|
  | `project://` | 本窗口当前 Project 的工作区根 | 真实目录型 | 当前 Project 与切换事件由 `nbook.project` 的浏览器部分按窗口提供 |
  | `user://` | 状态目录下的用户资产根 | 真实目录型 | 跨项目共享 |
  | `tmp://` | 按系统映射的临时目录 | 真实目录型 | |
  | `local://` | Agent 会话的工作目录 | 真实目录型 | 只在 Agent 会话上下文中有效 |
  | `docs://` | 产品参考文档目录 | 真实目录型，只读 | |

- 插件可以注册新方案；同一方案只能有一个提供者，重复注册被拒绝。
- 访问 `project://` 需要有效的 Project 绑定（见 [workspace.files](files.md)）；绑定失效时不回退到其它根。

## 输出与可观察行为

**能力矩阵：** 每个操作只在提供者声明了对应能力时可用，否则返回“能力不支持”，不静默降级。

glob 与 grep 的能力模型待讨论（见[设计稿的后续讨论](../../../packages/neuro-book/docs/proposals/project-file-foundation.md#后续重构不在本次)）：本表虚拟提供者一列的写法在讨论结论前不实施。

| 操作 | 真实目录型 | 虚拟提供者 |
|---|---|---|
| 读 | 返回内容与磁盘基线 | 返回实体的文本呈现 |
| 写 | 经文件服务写入并记录来源 | 只接受结构化写入（专用工具或命令），不接受改文本后解析回写 |
| 列出 | 返回一层目录项 | 由提供者枚举 |
| glob | 支持 | 由提供者枚举后匹配 |
| grep | 支持，可直接在真实路径上运行 | 由提供者实现，或声明不支持 |
| 监视 | 文件监视 | 提供者自行发出事件 |
| 真实路径（bash） | 可解析为真实路径 | 不可，见下 |

- **bash：** Agent 的 bash 工具只接受能解析为真实路径的方案，工作目录为 `local://`。对虚拟方案返回明确错误，提示改用读写工具；需要时可导出只读快照到 `tmp://`。
- **写入来源：** 每次经文件服务成功写入都带来源；bash 等绕过文件服务的写入由文件监视发现，来源记为外部，能按会话工作目录确定会话时记为该会话。
- **变更事件：** 文件服务对每个方案发出新建、修改、改名（带旧地址与新地址）、删除事件，附来源。改名事件只在经文件服务的改名时产生；外部改名表现为删除加新建。事件用于刷新与记账，不保证逐条可靠投递，消费方断线后按当前状态重新核对。
- **按需读取：** 列出一层目录不读取文件内容，也不解析 frontmatter。

## 状态与转换

本能力不引入持久状态。提供者注册随所属插件的激活与关闭登记和撤销；方案在提供者撤销后不可用，进行中的请求按 [runtime.plugins](../runtime/plugins.md) 的关闭规则结算。

| 状态/事件 | 结果 |
|---|---|
| 方案未注册 | 请求返回“方案不存在” |
| 提供者注册 | 方案可用，按能力声明受理请求 |
| 提供者撤销 | 新请求被拒；订阅收到结束通知 |
| Project 切换 | `project://` 指向新的 Project；旧绑定下的请求结果不投递给新绑定 |

## 副作用与数据

- 写入、改名、删除改变提供者背后的数据；读取、列出、监视无业务写入副作用。
- 文件监视由文件服务按订阅持有，订阅释放后停止。
- 变更事件交给订阅方（资源管理器、History 等）；事件本身不持久化，持久记账由订阅方负责（例如 History）。
- 不向浏览器暴露服务端绝对路径、数据库对象或凭据。

## 失败与恢复

- 方案不存在、能力不支持、地址越界、权限不足、资源不存在、写入冲突、提供者不可用各自可区分。
- 只读方案（`docs://`）拒绝写入；`user://` 对 Agent 默认只读，写入需 Profile 显式授权，未授权时拒绝而不是降级为其它根。
- 提供者异常不影响其它方案；监视中断时通知订阅方失同步，恢复后由订阅方重新核对。

## 边界与兼容

- owner：workspace-files（文件服务与首批提供者）。真实目录型提供者建立在 [platform.files](../platform/files.md) 的受根约束能力之上，`nbook.platform-files` 进入产品清单。
- 文件操作的语义（批量、冲突、逐项结果）沿 [workspace.files](files.md)；文件夹类型与清单沿 [workspace.folder-kinds](folder-kinds.md)。
- 提供者注册与能力声明是插件接口，遵守 [插件公开 API](../runtime/plugin-api.md) 的远程形态约束；浏览器经 [插件通道](../runtime/plugin-channel.md) 调用。
- Agent 文件工具（读、写、列出、glob、grep、bash）的入参改为资源地址；旧的路径参数随该切片迁移。

## 验收与 Smoke

1. 对 `project://`、`user://`、`tmp://`、`local://`、`docs://` 分别读、列出、glob、grep；`docs://` 写入被拒；未注册的方案返回“方案不存在”。
2. 写作者、Agent 会话、系统分别写入同一 Project，订阅方收到的变更事件带正确来源；调用方无法冒充其它来源。
3. Agent 用 bash 在 `local://` 修改 `project://` 下的文件：文件监视发出事件，来源为外部或按工作目录确定的会话。
4. 一个测试插件注册虚拟方案，只声明读与列出：读、列出可用；写、grep 返回“能力不支持”；bash 返回明确错误。重复注册同一方案被拒；插件关闭后方案不可用。
5. 经文件服务改名产生带新旧地址的改名事件；外部改名产生删除加新建。
6. Project 切换后，旧请求的迟到结果不投递到新 Project；`project://` 指向新根。
7. 列出 3000 个文件的项目根与任意一层目录，不读取文件内容（以读取计数或文件访问记录核对）。
