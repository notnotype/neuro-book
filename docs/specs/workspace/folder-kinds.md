# 文件夹类型与清单

## 目标与非目标

文件夹分三类：普通文件夹、内容文件夹与活页夹。类型由文件夹名后缀决定，列出父目录即可知道，不读目录内部。内容文件夹与活页夹的展示名、顺序、图标与编排写在文件夹根上的一份 XML 清单里，展开时只读这一个文件；普通文件夹不读任何文件的 frontmatter。

非目标：活页夹在剧情中的语义（场景挂章、章级写作指令，随剧情改造另定）；把现有项目迁移到新布局（由项目迁移脚本完成，业务代码不带兼容分支）；跨文件夹的引用维护。

## 术语与参与者

- **普通文件夹**：名字没有下述后缀的文件夹。只显示真实文件名，按[名字排序](#输出与可观察行为)规则排序。
- **内容文件夹**：名字以 `.content` 结尾（例如 `lorebook.content/`），根上有清单 `content.xml`。其中的子目录是内容节点：节点的正文是其 `index.md`。
- **活页夹**：名字以 `.binder` 结尾（例如 `manuscripts.binder/`），根上有清单 `binder.xml`，由剧情插件创建、管理与渲染。
- **清单**：描述整棵子树的 XML 文件。一个内容文件夹只在根上放一份，子目录不再有自己的清单。
- **未列入项**：磁盘上存在、清单里没有的子项。**缺失条目**：清单里有、磁盘上不存在的条目。
- **渲染者**：为某类文件夹提供资源管理器呈现的一方。普通文件夹与内容文件夹由文件底座渲染，活页夹由剧情插件渲染。

## 输入与前置条件

- 类型只看文件夹名后缀，不看目录内容；后缀之外的部分是显示时使用的名字（`lorebook.content` 显示为 `lorebook`）。
- 内容文件夹清单：

  ```xml
  <content>
    <item name="chen-yao" title="陈瑶" icon="user">
      <item name="portrait.png" title="立绘"/>
    </item>
    <item name="lin-feng" title="林峰"/>
  </content>
  ```

  `item` 的 `name` 是真实文件名或文件夹名，按出现顺序排序；嵌套表示子目录；`title`、`icon` 可选，缺省用真实名字与默认图标。

- 活页夹清单：

  ```xml
  <binder nextId="4">
    <group title="第一卷 青石镇">
      <chapter id="1" title="初到青石镇"/>
      <chapter id="3" title="旧账"/>
    </group>
    <chapter id="2" title="夜雨"/>
  </binder>
  ```

  活页夹目录平铺章节文件，文件名为五位编号加章名（`00001-初到青石镇.md`）。编号是章节的稳定身份；`group` 表示卷等分组，不对应目录；`nextId` 是下一个可分配编号。
- 清单不合法（XML 无法解析或不符合上述结构）时按[失败与恢复](#失败与恢复)处理。

## 输出与可观察行为

| 行为 | 普通文件夹 | 内容文件夹 | 活页夹 |
|---|---|---|---|
| 子项名字 | 真实文件名 | 清单 `title`，缺省真实名字 | 清单中章节 `title` |
| 顺序 | 目录在前，按名字排序 | 清单顺序，未列入项按名字排序排在末尾 | 清单顺序（分组可嵌套），未列入的章节文件进入“未编排”分组 |
| `index.md` | 普通文件 | 子目录节点隐藏其 `index.md`，点节点打开正文；缺少 `index.md` 的节点可“创建内容” | 不适用（章节是平铺文件） |
| 清单文件本身 | — | 资源管理器默认隐藏，可开关显示；`ls` 可见 | 同左 |
| 读取开销 | 只列目录 | 展开时读一次清单 | 展开时读一次清单 |

- **名字排序：** 普通文件夹与未列入项用同一个比较：目录在前；名字按中文自然排序（`Intl.Collator("zh-CN", {numeric: true, sensitivity: "base"})`），比较相等时按 UTF-16 码元次序。例：`chapter-2.md` 在 `chapter-10.md` 前，`第2章.md` 在 `第10章.md` 前，`A.md` 在 `a.md` 前；这个规则把汉字开头的名字排在拉丁字母开头的前面。
- **正文入口：** 列出内容文件夹或它任意深度的子目录时，每个子目录带“有无正文”（它的 `index.md` 是否为普通文件，只看目录项，不读正文、不列子目录）；内容节点自己的 `index.md` 标为正文。视图据此在点击前区分“打开正文”与“创建内容”。
- **清单读取与校验：** 每次展开内容文件夹或其子目录都重新读一次所属内容根的清单，不跨请求缓存。`item` 的 `name` 必须是单个目录项名（不含 `/`，不是 `.` 或 `..`），同一层重名为不合法。清单不存在、是目录或读不出，与 XML 不合法分开报告，都按普通文件夹显示，不让整次列出失败。
- **章节文件名同步：** 活页夹中章名以清单 `title` 为准，章节文件名中的章名部分由剧情插件按清单同步；只改了文件名中章名部分的章节仍按编号识别。
- **编号分配：** 由剧情插件加锁分配（取 `nextId` 后递增），外部产生的重复编号被检测并提示，不自动改写文件。
- **经文件服务的操作同步清单：** 在内容文件夹内经文件服务新建、改名、移入、移出、删除、复制进来子项时，同一操作同步更新所属内容根的清单：新建、移入与复制进来追加条目或放到指定位置，移出与删除去掉条目，改名更新 `name`。条目的子树（嵌套 `item` 的展示名与图标）随目录一起搬：移到另一个内容树时带过去，复制时复制一份。节点自己的 `index.md` 是正文，不进清单。调整顺序与修改展示名只改清单，不移动、不改名文件。清单的修改与其它文件一样带来源、发出变更事件。
- **清单编辑：** 文件服务提供调整一层的顺序、修改一项的展示名与图标、把磁盘上已有的未列入项加入清单、从清单移除一个条目（缺失条目或用户要移出清单的项，不动磁盘）四种只改清单的操作（方法见 [workspace.files](files.md) 的“文件操作”）。名字不在清单或重复为 `invalid-order`。清单在锁内按当前字节重新解析后修改，注释与条目顺序保留，缩进统一为两格。
- **操作锁：** 只锁清单文件的读改写不能保证清单与文件的先后一致（两个窗口交错改名 `a→b`、`b→c` 会两次都成功而清单只剩 `b`）。所以经文件服务、涉及内容树的操作对所在内容根取一把跨进程的操作锁，覆盖“读源条目、提交文件、更新清单、发出事件”；两个内容根之间的移动按真实路径的次序依次取锁；复制只在读源条目与最后提交时持锁，复制过程本身不持锁。等锁超时为 `busy`。普通文件夹里的操作不取锁。
- **外部改动不同步清单：** bash、文件管理器等外部增删由未列入与缺失规则兜底，不丢失、不报错。
- **转换：** 给普通文件夹加上 `.content` 后缀即转为内容文件夹：没有 `content.xml` 时排他新建，条目按当前子项的真实名字与普通文件夹的排序生成（不含清单本身）；已有时原样保留，不论合法与否（来回转换保留用户的清单，不合法的照常在列出时报告）。去掉后缀即退回普通文件夹，清单文件作为普通文件保留，由用户决定是否删除。加或去后缀是排他改名，父目录在内容树里时父清单里的条目名随之改。
- **渲染贡献点：** 插件可以为某个后缀注册资源管理器渲染者；没有渲染者认领的后缀（例如剧情插件未启用时的 `.binder`）按普通文件夹显示，并提示需要对应插件。

## 状态与转换

清单是持久状态，保存在文件夹根上。

| 事件 | 结果 |
|---|---|
| 展开内容文件夹或活页夹 | 读取清单，按清单与磁盘合并显示 |
| 经文件服务的子项操作 | 文件与清单在同一操作中更新；任一步失败按 [workspace.files](files.md) 报告结果 |
| 外部增删子项 | 文件监视触发刷新，按未列入与缺失规则显示 |
| 外部修改清单 | 文件监视触发重读 |
| 改名去掉或加上后缀 | 类型随之改变 |

## 副作用与数据

- 清单是文件夹内的普通可见文件，随文件夹复制、移动、归档；它的修改进入 History。
- 本能力不修改文件内容，也不读取或写入 frontmatter。
- 现有项目中由 `index.md` frontmatter 表达的展示名、顺序与图标，以及目录改名（加后缀），由项目迁移脚本一次性迁移；业务代码只认清单与后缀。

## 失败与恢复

- 清单无法解析或结构不合法：该文件夹按普通文件夹显示真实名字，并提示清单错误，不改写清单；修复清单后自动恢复。
- 清单与磁盘不一致：按未列入与缺失规则显示，不自动修复清单；用户可以在资源管理器中把未列入项加入清单或移除缺失条目。
- 经文件服务的操作中，文件已改而清单不合法、只读或写入失败：清单不改，结果为部分完成并指明是哪份清单（`manifests`，见 [workspace.files](files.md) 的“文件操作”），不发出清单的变更事件；下次展开按未列入与缺失规则显示，不回滚已完成的文件操作。跨两个内容树的移动两份清单分别报告。
- 活页夹编号冲突：检测并提示，两个文件都保留可访问。

## 边界与兼容

- owner：workspace-files 负责类型识别、内容文件夹清单与渲染贡献点；活页夹的清单维护、编号分配与渲染归剧情插件（剧情改造时登记对应 Spec）。
- 资源寻址、来源与变更事件沿 [workspace.resources](resources.md)；文件操作语义沿 [workspace.files](files.md)；资源管理器呈现沿 [workbench.files-explorer](../workbench/files-explorer.md)。
- 清单格式使用 XML，由 XML 解析库读取；格式变化需要版本标记与迁移脚本。
- 后缀方案改变了既有目录名（`lorebook/` → `lorebook.content/`、`manuscript/` → `manuscripts.binder/`），内置资产与代码中的旧路径随路径迁移一并更新；用户自定义资产中写死的旧路径不会自动更新，安装器只能提示。

## 验收与 Smoke

1. 准备普通文件夹、`lorebook.content/`（含嵌套子目录与清单）、`manuscripts.binder/`：列出父目录即得到三种类型；普通文件夹显示真实名字且不读任何文件内容；内容文件夹按清单显示展示名、顺序与图标，展开只读一次清单。
2. 内容文件夹中加入一个未列入的文件、删除一个已列入的文件：未列入项按真实名字排在末尾，缺失条目被标出，清单未被改写。
3. 在内容文件夹内经资源管理器新建、改名、移出、删除、拖动排序与修改展示名：文件与清单同步，排序与改展示名不改动任何文件。
4. 清单写成非法 XML：文件夹退回普通显示并提示错误；修复后恢复。
5. 给普通文件夹加 `.content` 后缀并生成清单后按内容文件夹显示；去掉后缀后退回普通文件夹。
6. 未启用剧情插件时，`manuscripts.binder/` 按普通文件夹显示并提示；启用后由剧情插件渲染，未编排的章节文件出现在“未编排”分组。
7. 内容文件夹中缺少 `index.md` 的节点可以“创建内容”，排他创建空白 `index.md`。
8. 把未列入项加入清单、移除缺失条目，磁盘不变；把带展示名子树的目录移到另一个内容文件夹，展示名随之过去；两个窗口交错改名同一内容树里的项，结束后清单与磁盘一致。
9. 清单只读或不合法时经文件服务新建子项：文件已建，清单原字节不变，结果指明这份清单未更新；来回转换一个文件夹，原有清单字节不变。
