# NeuroBook Markdown 方言

## 目标与非目标

规定 NeuroBook 怎样读、写作品里的 Markdown 文件：在 CommonMark 与 GFM 之上的几条通用规则（中文的强调、换行、删除线），项目方言（批注、注音、双语对照、对齐、文字标记、可渲染 HTML），以及富文本编辑后写回原文的规则。富文本编辑器、字数统计与之后的导出、Agent 读写都按这一份理解同一个文件。界面上怎样编辑（菜单、快捷键、浮动菜单）归 [workbench.editor](../workbench/editor.md)。

项目方言由插件贡献：哪些方言生效、什么时候生效由 [workspace.markdown-syntaxes](markdown-syntaxes.md) 规定；没生效的方言，它的写法按输出 9 原样保留。

不承诺：

- 实时预览与源码模式（源码用默认的文本编辑器打开）。
- 脚注、数学公式、`[[维基链接]]` 与 Obsidian 的 `%%注释%%` 的渲染与编辑：按输出 9 原样保留。
- 音频、视频的写法。
- 批注的回复、作者、时间与“已解决”状态；批注的存放位置以后可能改变（见“边界与兼容”）。
- 与其它工具显示一致：输出 5、6、7 是 NeuroBook 自己的规则，同一份文件在 GitHub、Obsidian、Typora 里可能显示不同；输出 8 列出这些差异。
- 粘贴网页内容时转成 Markdown 的规则（随编辑器的粘贴另定）。

## 术语与参与者

- **原文**：磁盘上文件的字节。
- **块**：CommonMark 意义上的顶层块（段落、标题、列表、引用、代码块、表格、分割线、HTML 块、引用定义），以及本方言的块级标签（输出 11、13、14、16、23）。块的文字不含结尾的换行；块与块之间的换行与空行是**间隔**。富文本里块与块之间的空段落是间隔在编辑器里的样子，个数只由间隔里的换行数决定（与前后是什么块无关）：两块之间 `k` 个空段落对应 `k + 1` 个空行；文件开头 `k` 个空段落对应开头的 `k` 个换行；最后一块之后的 `k` 个空行对应 `k` 个空段落，文件末尾有没有换行另外保持。引用、列表项、提示块、块批注、双语、对齐这些容器里，子块之间不保留空段落；容器里只剩一个空段落时（例如新建的空引用）它是容器的占位，写成容器的空写法（`>`、开闭标签之间一个空行）。
- **规范写法**：一种语法在新建时写出的样子。同一语法能读的其它写法称为**变体**。
- **原样块**、**原样片段**：NeuroBook 不认识或表达不了的语法，读进来以块或行内片段的形式显示它的源码，写回时字节不变。
- **往返**：读入原文、在富文本里编辑（或不编辑）、写回原文。
- **读者**：按本方言理解文件的一方：富文本编辑器、字数统计（[workbench.editor](../workbench/editor.md) 输出 27）、导出与 Agent 工具（随各自的 Spec 接入）。

## 输入与前置条件

- **适用的文件**：`project://` 与 `user://` 下扩展名为 `.md`、`.markdown` 的文件，包括内容节点的 `index.md` 与活页夹的章节文件（[workspace.folder-kinds](folder-kinds.md)）。
- **编码**：UTF-8，可以带 BOM；换行可以是 LF 或 CRLF，可以混用。
- **frontmatter**：文件开头 `---` 独占一行、到下一个独占一行的 `---` 为止的部分是 YAML frontmatter；没有闭合的分隔线时不是 frontmatter。它不属于正文，读者不按 Markdown 解释它。
- **基础语法**：[CommonMark 0.31.2](https://spec.commonmark.org/0.31.2/)，加上 [GFM](https://github.github.com/gfm/) 的表格、删除线（按输出 7 只认 `~~`）、任务列表与自动链接，再按下文的输出修改。
- **项目方言一览**（详见输出 11–17）：

  | 方言 | 规范写法 | 形态 |
  |---|---|---|
  | 批注 | `<comment body="意见">正文</comment>` | 行内；开闭标签各占一行时为块 |
  | 注音 | `<ruby text="hàn zì">汉字</ruby>` | 行内 |
  | 双语对照 | `<bilingual text="译文">`、正文、`</bilingual>` 各占一行 | 块 |
  | 对齐 | `<align value="center">`、正文、`</align>` 各占一行 | 块 |
  | 文字颜色 | `<span style="color: #ef4444">文本</span>` | 行内 |
  | 高亮 | `<mark>文本</mark>`，或带 `style="background-color: …"`；也能读 `==文本==`（输出 24） | 行内 |
  | 提示块 | `> [!NOTE] 标题` 开头的引用（输出 23） | 块 |
  | 上标、下标 | `<sup>文本</sup>`、`<sub>文本</sub>` | 行内 |
  | 可渲染 HTML | `<html>`、内容、`</html>` 各占一行 | 块 |

## 输出与可观察行为

### 往返

1. **不编辑不改字节**：打开后不编辑，保存、切走或关闭都不改变原文的任何字节（含 BOM、frontmatter、换行符、文件末尾有没有换行）。
2. **以块为单位写回**：编辑后写回时：
   - 没有被编辑的块字节不变；两侧的块都没被编辑、仍然相邻、中间的空段落数也没变的间隔字节不变；其余间隔按空段落数重新写出，文件末尾有没有换行按原文。整篇只剩一个空段落时写成空正文。重新写出的块与间隔用原文里用得多的那种换行符。
   - 被编辑的块重新写出，按它原来的写法：列表符号（`-`、`*`、`+`）、有序列表的分隔符（`.`、`)`）与编号方式（全写同一个数，或按顺序编号）、强调符号（`*` 或 `_`）、标题写法（`#` 或下划线式，含 `#` 式结尾的 `#`）、代码围栏的符号与长度、分割线的写法、硬换行的写法（输出 5）、链接的形式（行内、引用式与它的标签、自动链接、尖括号地址）、行内 HTML 的标签名、大小写与属性顺序。块里新加的内容（新的列表项、新加的粗体）跟随同一块已有的写法，前提是这样写读得回来（例如汉字中间的 `__` 读不成粗体，这时用规范写法）；块里没有可跟随的写法时用规范写法（输出 10）。新加的内容一旦写回，它的写法就固定下来，之后再重写这一块时保持。
   - 一块的意思依赖别处时，所依赖的内容变了，这一块也重新写出：引用式链接依赖它的定义（同名的定义取全篇第一条；定义被删掉、或同名定义换了先后使地址变了，引用写成行内链接）；分截批注的 `body` 写在第一截（输出 11）。
   - 写回成功之后，这次写出的字节就是新的原文：之后没再编辑的块按它保持。更早的原文仍然记着：撤销回到某一块以前的样子时，这一块写回它那时的字节（没被编辑、只因上下文变了而重新写出过的块，例如分截批注的各截，写回的是读得回同样内容的某一次的字节）；撤销回打开时的状态再写回，字节与打开时相同。
3. **写回必须读得回来**：每个重新写出的块与重新写出的间隔，连同前后各一块，按本方言再读一遍，得到的块数、块的边界与内容（文字、格式、结构）必须与编辑器里的一样。读不回来时依次改用读得回来的写法：跟随的写法改用规范写法；两个相邻的同一种列表读回合成了一个时，换其中一个的符号（`-`、`*`、`+` 轮换，有序列表换 `.` 与 `)`），换成与它前后两个都不同的，优先换重新写出的那个、两个都重新写出时换后一个；相邻的、没被编辑的块（原样块除外）也重新写出（例如补上没闭合的代码围栏）；加转义（输出 4）；把强调与删除线写成 HTML 形式（`<strong>`、`<em>`、`<del>`，输出 25）。仍做不到时是**写不出**（失败码 `unrepresentable`）：这次输入不交给文档，原文不变，编辑器说明是哪一块（[workbench.editor](../workbench/editor.md) 输出 61）；被前面没闭合的原样块（例如没闭合的 HTML）吞掉时，说明里写出这个原因。
4. **最小转义**：正文里的字符只在不转义就会被读成语法时才转义：
   - 行首会被读成标题、列表、引用、分割线、代码围栏、表格的文字（例如 `1. `、`# `、`- `、`> `）：转义行首的那个字符；
   - 会被读成强调、行内代码、链接、图片、删除线、高亮、自动链接（包括 `www.`、`http://`、`https://` 开头的网址与邮箱地址）、数学、HTML 标签或实体的字符：转义那个字符（网址与邮箱只转义开头的一个字符）；例如文字 `5*3*2=30` 写成 `5\*3*2=30`（能少转义时从后往前去掉多余的，所以保留的是靠前的那个）；
   - 其余字符原样写出，例如 `第1~2章`、`a_b_c`、`5*3=15`、`a < b`、`甲 & 乙`，以及全篇没有 `[注]: …` 定义时的 `[注]`。

   行内代码与代码块里的内容不转义。不间断空格（U+00A0）与零宽字符写成实体（`&nbsp;`、`&#x200B;`）；读入时会被去掉的空白写成实体：行首的第一个与行尾的最后一个空格（`&#x20;`），标题、表格单元格首尾与只有空白的一行里的全角空格（`&#x3000;`）；制表符写成 `&#9;`（列表项里的制表符会被换成空格）。其余字符写成字符本身。列表项里原有的制表符读成空格，所在的块被编辑后写成空格。
5. **段内单换行是换行**：段落里的单个换行显示为换行，不连成一行（CommonMark 把它当作空格，见输出 8）。行尾两个空格、行尾反斜杠与 `<br>` 也是换行，读进来与单换行一样显示，写回时保持各自原来的写法。在富文本里按 Shift+Enter（表格单元格里按 Enter，输出 20）新建的换行写成单个换行；在段首、段末与挨着另一个换行时写成 `<br>`，相邻的几个写在同一行（单个换行在这些位置读不回来）；按 Enter 新起一段，段与段之间写一个空行；在两段之间留出的空段落按输出 2 写成空行。连续的多个空行原样保留。
6. **中文友好的强调**：强调符号（`*`、`_`、`**`、`__`）、删除线 `~~` 与高亮 `==` 的开闭判定按 [CJK 友好的强调规则](https://github.com/tats-u/markdown-cjk-friendly/blob/main/specification.md)：紧挨中日韩文字或全角标点时也能开、能闭。例如 `他说：**“走吧。”**然后离开。` 中的“走吧。”连引号是粗体，`他说：~~“走吧。”~~然后` 中的是删除线。
7. **删除线只认两个波浪线**：`~~文本~~` 是删除线；单个 `~` 是普通文字，`约5~6人，走了7~8天。` 不出现删除线。
8. **与其它工具的已知差异**：输出 5（段内换行）、6（强调）、7（单个波浪线）与项目方言在 GitHub、Obsidian、Typora 里可能显示不同：前三条在那里分别显示为连成一行、显示出星号、可能出现删除线；项目方言显示为 HTML 或源码。这些差异只影响显示，不改变文件内容。
9. **认不出的语法原样保留**：下面这些读成原样块或原样片段，显示源码，可以整块删除或复制，不能在富文本里编辑其中的文字；写回时字节不变：
   - 脚注的引用 `[^1]`（原样片段）与定义 `[^1]: …`（原样块）；
   - 数学公式 `$…$` 与 `$$` 块；
   - 引用定义 `[标签]: 地址`（原样块；引用式链接照常读成链接）；
   - 本方言之外的 HTML 标签（能读的见输出 15、25 与各方言）：完整的块级片段为原样块，行内标签与没闭合的残片为原样片段；HTML 注释 `<!-- … -->` 为原样块。尖括号里的网址与邮箱（`<https://例子>`、`<me@例子.cn>`）是自动链接，不是标签；
   - 读入时对不上任何块的原文（例如同名的第二条引用定义，Markdown 解析器会丢掉它）为原样块；
   - 原样片段以会开启 HTML 块的写法（HTML 注释、块级标签）开头、又落在段首时（例如在它前面拆段），写不出（输出 3）：一行以它开头会被读成 HTML 块；在段中换行之后时换行写成 `<br>`，留在同一行。单个完整标签（开标签或闭标签）的原样片段独占一行时也会被读成 HTML 块：挨着它的换行写成 `<br>`，整段只有它时写不出；整段只有几个原样片段时（例如 `<kbd>` 与 `</kbd>` 之间的字被删光）也可能被读成 HTML 块而写不出；一对能配上的开闭标签片段落进同一段、中间有别的内容时（例如合并两段），读回会合成一个原样片段，写不出；开标签片段落在段首、后面（可以隔着空行）有配对的闭标签时，读回从它到闭标签是一个原样块，同样写不出；
   - `[[维基链接]]`、`%%注释%%`、`++文字++` 不是语法，按普通文字读写（输出 4 保证 `[[`、`%%`、`++` 不被转义）；
   - 读进来的结构不合编辑器的约束（例如嵌套方式编辑器表达不了）时，那一块整体成为原样块，不进入编辑器的正常内容。
10. **规范写法**：新建内容写成：

    | 语法 | 规范写法 |
    |---|---|
    | 标题 | `# ` 到 `###### ` |
    | 无序列表 | `- `，子列表缩进两格 |
    | 有序列表 | `1. `，按顺序编号 |
    | 任务列表 | `- [ ] `、`- [x] ` |
    | 粗体、斜体、粗斜体 | `**文本**`、`*文本*`、`***文本***` |
    | 删除线 | `~~文本~~` |
    | 行内代码 | `` `代码` ``，内容含反引号时加长包围的反引号 |
    | 代码块 | ```` ``` ```` 加语言名，内容含三个反引号时加长 |
    | 引用 | `> ` |
    | 分割线 | `---` |
    | 链接、图片 | `[文字](地址)`、`![说明](地址)`；地址含空格或括号时写成 `<地址>` |
    | 表格 | GFM 表格，表头下一行写对齐，列宽不对齐 |
    | 换行 | 单个换行（输出 5） |

### 项目方言

11. **批注**：一条批注是一段被批注的正文加一条意见（`body`），正文显示为带波浪线的文字。
    - **行内**：`<comment body="意见">正文</comment>`，开闭标签在同一段里；段内的换行（输出 5）可以在里面。
    - **块**：开标签 `<comment body="意见">` 独占一行、闭标签 `</comment>` 独占一行，中间是一块或连续的多块。
    - **分截**：一条批注跨段、且起点或终点在段落中间时，每段写一截行内批注，各截带同一个 `id`，`body` 只写在第一截上：

      ```
      123<comment id="c1" body="意见">one</comment>

      <comment id="c1">two</comment>

      <comment id="c1">three</comment>
      ```

      读的时候，同一个 `id` 的各截合成一条批注，意见取带 `body` 的那一截。
    - **形态**：写回时保持批注原来的形态（行内、块或分截），开标签按 `id`、`body` 的顺序写；一条批注有一截所在的块被编辑时，这条批注涉及的块都重新写出（意见只在第一截）。结构使原形态写不出时改为分截（例如在行内批注中间按 Enter 拆成两段），并分配 `id`。在富文本里新建批注时，选区正好是连续的几个完整块写成块，只在一段里写成行内，其余写成分截。两条批注重叠时，在重叠的边界处拆成截，保证标签正确嵌套。
    - **id**：分截的批注才需要 `id`；在富文本里新建时，取这个文件里还没用过的最小的 `c` 加数字（`c1`、`c2`……）。读到的其它 `id` 写回时保留。粘贴进来的批注与文件里已有的 `id` 相同时换一个新的。
    - **残缺的分截**：带 `body` 的那一截被删掉时，写回把 `body` 挪到剩下的第一截；只剩没有 `body` 的截时（例如文件在外部被改过），读成意见为空的批注；没有 `body` 的截属于文件顺序上在它之前、最近的带 `body` 的同 `id` 截（之前没有时属于之后第一个）；所以同一个 `id` 的几截带着不同的 `body` 时，读成几条批注，写回时都保留。
    - 属性值里的 `"`、`&`、`<` 写成 `&quot;`、`&amp;`、`&lt;`，换行写成 `&#10;`；`` ` ``、`[`、`]`、`\` 也写成数字实体（解析器判断链接文字的范围时会把属性值里的它们当成语法）。
    - 旧写法 `<inline-comment …>…</inline-comment>` 能读，等价于行内批注；所在的块被编辑时改写成 `<comment>`。
    - 批注的正文里可以有其它格式。
12. **注音**：`<ruby text="注音">正文</ruby>`。正文上方显示小字注音。标准 HTML 写法 `<ruby>正文<rt>注音</rt></ruby>` 能读，写回时保持原来的写法（输出 2）。注音的正文里只能是纯文字：在富文本里给注音里的一部分文字加格式时，格式不进入注音（写在 `<ruby>` 外面，注音在格式的边界处断开成两个同样的注音，读回来仍是一个）；读进来的注音正文里有格式时，那个注音整体为原样片段。
13. **双语对照**：开标签 `<bilingual text="译文">` 独占一行、闭标签独占一行，中间是原文（一段或多段）。原文上方显示弱色的译文行。
14. **对齐**：开标签 `<align value="…">` 独占一行、闭标签独占一行，`value` 是 `center`、`right`、`justify` 之一，中间的块按此对齐。`value="left"` 的块保持原样，显示为左对齐；在富文本里取消对齐时去掉标签。`value` 不是这几个值时整体为原样块。行内写法 `<align value="center">文本</align>`（开闭标签在同一行）能读，等价于只含一段的块。
15. **文字标记**：
    - 文字颜色：`<span style="color: 颜色">文本</span>`；
    - 高亮：`<mark>文本</mark>`，或 `<mark style="background-color: 颜色">文本</mark>`；
    - 上标、下标：`<sup>文本</sup>`、`<sub>文本</sub>`；
    - 颜色是合法的 CSS 颜色值（`#…`、`rgb()`、`hsl()` 与颜色名），不能是 `var()`、`url()` 这类引用；`style` 里有别的属性、颜色不合法，或者是不带颜色的 `<span>` 时，整体为原样片段。在富文本里新加的颜色写成 `#rrggbb`。
16. **可渲染 HTML**：开标签 `<html>` 独占一行、闭标签 `</html>` 独占一行，中间是 HTML。默认显示为源码卡片，用户选择渲染后在沙箱里显示：脚本能运行，拿不到应用的页面、存储与接口。这是本方言里唯一会被渲染的 HTML。内容里有独占一行的 `</html>` 时写不出（输出 3）。（planned）页面里的相对引用按文件所在目录解析到作品里的文件，联网规则与 [workbench.html-preview](../workbench/html-preview.md) 输出 5 相同。
17. **宽容写法**：块级方言标签（批注、双语、对齐、可渲染 HTML）的开标签黏在正文后面、紧跟换行（`正文<comment body="…">` 换行……换行 `</comment>`）时，读成“正文”一段加一个标准的块；所在的块被编辑后按标准写法写回，与前面的正文之间补一个空行。只在同时满足以下条件时这样读：开标签在行尾；往下有独占一行的配对闭标签；不在代码块里；开标签前面有真实的正文（只有引用符号 `>` 或列表符号时是正常的嵌套，不改）。不满足时按输出 9 原样保留。一段末尾黏着方言开标签、读入时因为下面没有闭标签而没拆开的段落，挪到配对的闭标签上面后，再读就会拆开：写回时这一段重新写出，开标签后面的换行写成 `<br>`；开标签就在段末时写不出（输出 3）。

### 链接、图片与其它

18. **链接与图片的地址**：
    - 相对地址（`../设定/林雪.md`、`images/a.png`）按当前文件所在目录解析；以 `/` 开头的地址按作品根（`user://` 下按用户资产根）解析；带方案的地址（`https:`、`mailto:` 等）是外部链接。
    - 在富文本里新建指向作品里文件的链接或图片时，写相对当前文件的地址；`@` 引用插入的也是这种普通链接。（planned）
    - 富文本里显示图片时按上面的规则读出作品里的文件；解析出作品根以外的地址时不显示，显示说明。
    - 标题（`[文字](地址 "标题")`）以反斜杠结尾时写不出（输出 3；Markdown 解析器的限制）。
    - 图片的说明是纯文字：说明里的格式与转义读成文字（`![*甲* &amp; 乙](a.png)` 的说明是“甲 & 乙”）；所在的块被编辑后，说明按纯文字写出，引用式图片写成行内图片。
    - 旧应用推荐的不带 `/` 的作品根路径（例如 `lorebook/location/initial-stage/`）在这里按相对当前文件解析，这类旧链接要作者自己改。
19. **任务列表**：`- [ ] 事项`、`- [x] 事项`（`[X]` 也能读）。富文本里显示复选框，点击切换；写回时按输出 2 保持原来的大小写。有序列表里的 `1. [ ] 事项` 不是任务项，按文字读写。
20. **表格**：GFM 表格，要求有表头行。单元格里只有一段：在单元格里按 Enter 是换行，写成 `<br>`；单元格文字里的 `|` 写成 `\|`；单元格里的行内代码与链接、图片的标题含“反斜杠加竖线”时写不出（输出 3；切单元格时它总被当作转义的竖线）。对齐写在表头下一行。不支持合并单元格；用 HTML 写的表格是原样块；某一行的单元格比表头多时（多出的格 GFM 不显示），整张表是原样块。
21. **代码**：行内代码与代码块里的文字原样读写，不解释其中的任何语法（包括方言标签）。行内代码外面可以有格式（`` [`代码`](地址) ``、`` **`代码`** ``），写在反引号外面；格式只盖住一部分代码时，代码在格式的边界处断开。行内代码不能在注音里。链接文字里的行内代码含反引号或反斜杠时写不出（输出 3；Markdown 解析器在链接文字里只认单个反引号成对的代码，并把其中的反斜杠当作转义）。
22. **frontmatter**：原样保留，不进入富文本的正文；它的编辑另定。
23. **提示块**：引用块的第一行是 `[!类型]`，后面可以跟标题（`> [!WARNING] 伏笔`），其余行是提示块的内容（与 GitHub、Obsidian 的写法相同）：
    - 类型不分大小写。`NOTE`、`TIP`、`IMPORTANT`、`WARNING`、`CAUTION` 五种各有图标与颜色；其它类型（包括 Obsidian 的 `info`、`todo`、`question` 等）显示为 `NOTE` 的样式，标题缺省时显示类型名。
    - 类型后紧跟 `-` 时默认折叠、`+` 时默认展开，可以点标题展开或折叠；折叠状态不写回文件。光标进到折叠的内容里、或一次编辑改到了折叠的提示块（例如在下一段段首退格并了进去）时，它自动展开：看不见的内容不会被悄悄改掉。
    - 写回时保持原来的类型写法、大小写与折叠标记；标题按原文写回，不解释其中的 Markdown。在富文本里新建的提示块写成 `> [!NOTE]`。
    - 内容里可以有任意块；`[!类型]` 不在引用的第一行时，是普通引用。
24. **`==高亮==`**：`==文本==` 读成高亮，与不带颜色的 `<mark>文本</mark>` 相同。开闭判定与 `~~` 相同，并按输出 6 对中文放宽：`a == b` 这类两侧有空格的不是高亮。写回时保持原来的写法（输出 2）；在富文本里新加的高亮写成 `<mark>`（GitHub 等工具也能显示），带颜色的高亮总是 `<mark style="…">`。
25. **HTML 形式的强调与换行**：`<strong>`、`<b>` 是粗体，`<em>`、`<i>` 是斜体，`<del>`、`<s>` 是删除线，`<br>` 是换行；写回时保持原来的标签。`<u>` 与其它行内标签按输出 9 是原样片段。
26. **没有下划线**：NeuroBook 没有下划线格式；`++文字++` 是普通文字，`<u>` 是原样片段。
27. **引用的目标分类**：链接、图片与 Composer 里引用的目标按以下顺序归为一类，三种界面（编辑器、[ui.markdown-display](../ui/markdown-display.md)、[ui.prompt-editor](../ui/prompt-editor.md)）按同一分类显示：
    - **作品里的文件**：相对地址、以 `/` 开头的地址（按输出 18 解析）与 `project://` 地址；
    - **用户资产**：`user://` 地址；
    - **附件**：`session://attachments/` 下的地址（Composer 的会话附件，[`agent.resources`](../agent/resources.md)）；
    - **外部**：`http:`、`https:`、`mailto:` 方案；
    - **其它**：别的方案（包括旧应用的 `chapter://` 等领域地址）。
    作品里的文件与用户资产显示为引用小块，按文件扩展名取图标；外部链接显示为普通链接；其它显示为不带文件图标的引用小块。分类只影响显示，写回的地址不变。

## 状态与转换

一个打开的文件在往返中，每一块要么是**原样未动**的（写回它最近一次读入或写回时的字节，含撤销回到的更早的样子），要么是**被编辑过**的（按输出 2、3 重新写出）。用户把文字改回原样但不是撤销时，按被编辑过处理，写出的结果可能与原文的写法细节不同（例如表格的列宽对齐）。

时序与寿命：

- 宽容写法的整理（输出 17）发生在读入时：打开文件、外部修改后重新读入、粘贴 Markdown。流式写入（Inline AI）的中间结果不整理。
- 外部修改后重新读入、同一文档另一个视图的输入被接受后重新读入时，“哪些块被编辑过”按新的原文重新开始计。
- 写回在每次把输入交给文档时进行（停手、失焦、切走、保存与资源管理器操作之前的结算）；写不出按输出 3。

## 副作用与数据

- 本方言不新增文件，也不在文件里写版本标记；读写只改动编辑过的块。
- 字数统计（[workbench.editor](../workbench/editor.md) 输出 27）按本方言去掉不计的内容再数：
  - 不计：标签本身与属性（批注的 `body`、注音、双语的译文、颜色、对齐，`<br>` 当作换行）；原样块与原样片段（输出 9：方言之外的 HTML 连同成对标签中间的字、HTML 注释、数学、脚注的引用与定义、引用定义）；可渲染 HTML 的内容；标准写法注音里 `<rt>` 的小字；提示块的类型（`[!NOTE]`）与任务项的勾选框；
  - 计入：方言标签中间的正文、提示块的标题、行内代码与代码块里的字（其中的标签与实体按文字计）；实体按解码后的字计；
  - 标签类方言计不计由它的声明决定，提示块与可渲染 HTML 的规则在核心扫描里、不随方言是否生效变化；方言的实现在浏览器里没加载成功时，字数仍按声明计（[workspace.markdown-syntaxes](markdown-syntaxes.md) 输出 9）；
  - 字数统计不经编辑器读入，与编辑器读出的正文有已知的偏差：链接与图片的地址和标题、图片的说明、引用式链接的标签、有序列表的编号照常计入；写法不合法而整体成为原样的方言标签（不合法的颜色、注音的正文里有格式、`value` 不合法的对齐）中间的字照常计入；缩进代码块里的标签当作标签。

## 失败与恢复

| 码 | 含义 | 调用方怎么办 |
|---|---|---|
| `unrepresentable` | 有被编辑过的块写不出读得回来的 Markdown（输出 3） | 编辑器进入写不出状态（[workbench.editor](../workbench/editor.md) 输出 61）：这次输入不交给文档，保存被挡，关闭只能不保存或取消；用户定位到那一块修改，或采用当前正文 |

读入不会失败：认不出或表达不了的部分按输出 9 原样保留。

## 边界与兼容

- 本方言是作品文件的格式，对外的承诺是“NeuroBook 怎样理解这些写法”。以后新增方言时，不改变已有文件的含义：新语法只占用现在读成普通文字或原样保留的写法。
- 旧应用写出的文件（包括 `<inline-comment>`、标准 HTML 的 ruby）都能读。现在的编辑器在连续空段落处写过独占一行的 `&nbsp;`：这样的一段读成只含一个不间断空格的段落，字节不变。
- 批注写在正文里；以后若改成存在别处，要提供从正文迁移的方式，并继续能读正文里的批注。
- 可渲染 HTML 的沙箱是安全边界：文件里的 HTML 视为不可信内容。

## 验收与 Smoke

1. Given 一份含 frontmatter、CRLF 换行、`*` 列表、`_斜体_`、下划线式标题、`~~~` 代码块、引用式链接、脚注、表格（含 `\|`）、数学公式与全部项目方言的文件，When 打开、不编辑、保存，Then 字节不变；When 只改列表的第二项，Then 只有那一个列表重新写出，列表仍是一个、符号仍是 `*`，其余字节不变，文件里不出现控制字符。
2. Given 一段 `他说：“走吧。”然后离开。`，When 在富文本里给“走吧。”连引号加粗并保存、关闭再打开，Then 仍是粗体，原文是 `他说：**“走吧。”**然后离开。`。
3. Given 富文本里新打的一段 `1. 不是列表，约5~6人，a_b_c，[注]`，When 保存再打开，Then 仍是一段普通文字，原文只在行首的 `1.` 处有一个转义。
4. Given 一个任务列表，When 打开、在列表里回车加一项、勾选一项、保存，Then 编辑器不出错，原文的复选框都在，新加的项是 `- [ ] `。
5. Given 一份含原样块（未知 HTML、脚注定义）的文件，When 编辑别的段落并保存，Then 原样块字节不变；When 删除整个原样块并保存，Then 它从原文里消失，其余不变。
6. Given 三段 `123one`、`two`、`three`，When 在富文本里选中 `one` 到 `three` 加一条批注并保存，Then 原文是三截同一 `id` 的行内批注、`body` 只在第一截；When 关闭再打开，Then 是一条批注；When 删掉第一段再保存，Then `body` 挪到 `two` 那一截；When 在 `two` 中间回车拆段并保存，Then 仍是一条批注，多出一截。
7. Given 选中完整的两段加批注，When 保存，Then 原文是一个块批注；When 再选中其中一段的后半句加另一条批注并保存，Then 两条批注的标签正确嵌套，重新打开后仍是两条。
8. Given 文末有几条引用定义、正文里有引用式链接的文件，When 在最后一段后面接着写一段并保存，Then 定义原样在文末、链接仍是链接；When 删掉其中一条定义并保存，Then 引用它的链接写成行内链接。
9. Given 一个新建的空文件，When 打开、点进正文再点出、切走，Then 文件仍是空的；When 打一段、按两次 Enter、再打一段并保存，Then 两段之间是两个空行；When 把中间的空段落删掉并保存，Then 两段之间是一个空行。
10. Given 正文 `她抬头<comment body="节奏太快">看了他一眼</comment>，按 <kbd>Ctrl</kbd> 保存。`，When 编辑器状态栏与书架统计字数，Then 都是 11：批注意见与原样片段不计。

Smoke：往返语料测试（每条输出与以上场景各有样例）、字数与编辑器读出的正文逐块对照的一致性测试，与编辑器区的真实浏览器 e2e。

## 实现合同

- 公开入口：`@notnotype/nb-markdown/language` 的 `codecFor(schema, language)`（`read`、`write`、`reload`）、`defaultMarkdownLanguage()`（核心语法、原样保留与各项目方言的语法模块）与 `createMarkdownLanguage`；neuro-book 里用它们的是 `nbook.markdown` 的组件，别的插件经服务 `markdownKey` 交出的组件使用（编辑器区的 Markdown 控件）。字数是 `nbook/plugins/markdown/shared/contracts` 的 `countWords(text)`，前后端共用。
- owner 与依赖方向：读写规则、语法模块与编解码器归 nb-markdown；方言的贡献、作品文件的目标分类与字数归 `nbook.markdown`。编解码器只经语言对象使用语法模块；Markdown 控件只经编解码器读写正文，不直接调用 markdown 解析库，只按类型引用编辑器区的控件合同；字数与语法模块共用 nb-markdown 纯 TS 入口里 `markdown-dialect.ts` 的标签名与判据，不依赖编辑器。
- 不变量：没被编辑过的块写原文，撤销回原来内容的块同样写原文（`codec.test.ts`、`editing.test.ts`）。
- 不变量：每次写出都读回比对，读回不等就降级，最后一级仍不等时整篇写不出、不交出正文（`write.test.ts`、`properties.test.ts`）。
- 不变量：写出被接受后回填写法，之后不再编辑时写出字节不变；重载时批注的身份按出现顺序对齐，不因重新读入而变（`editing.test.ts`）。
