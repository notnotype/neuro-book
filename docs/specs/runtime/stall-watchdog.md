# 主线程卡死看门狗与自动重启

## 目标与非目标

第三方插件与宿主同线程运行，主线程上的同步计算无法被打断，宿主自己的超时定时器也会停摆。服务端主线程卡死超过阈值时，看门狗写出卡死报告并以专用退出码结束进程；Manager 确认进程已退出后释放它遗留的租约锁，按上限自动重启，Desktop 呈现重启过程；下次启动时提示禁用嫌疑插件，反复卡死时自动进入安全模式。

明确不承诺：

- 不打断或恢复卡死的计算，只结束进程。
- 浏览器端不设看门狗（浏览器自身会提示页面无响应）。
- 不判定卡死的确切原因；报告只给出按可信度分级的嫌疑。
- 不改变租约本身的合同（[`agent.session-store-lease`](../../archived/specs/agent/session-store-lease.md)）。

## 术语与参与者

- **心跳**：主线程定期写入共享内存的时间戳。
- **看门狗**：服务端宿主启动的一个 worker，读取心跳判断卡死。
- **阈值**：10 秒。必须小于 Session Store 租约的心跳间隔 15 秒：卡死若发生在一次续期之前，锁约 15 秒后即可被其它进程接管。
- **卡死报告**：记录卡死时刻、持续时间、在途插件调用与嫌疑分级的文件。
- **嫌疑分级**：`direct`（卡死时正在执行的同步调用属于该插件）、`candidate`（卡死时有该插件的在途调用）、`weak`（最近有该插件的调用）、`unknown`（无插件在途）。
- **退出码 76**：主线程卡死被看门狗结束。

## 输入与前置条件

- 服务端运行实例启动完成后才开始计时。
- 开发模式默认关闭；检测到调试器连接时停用（断点只暂停主线程，会被误判为卡死）。
- 在途插件调用来自内核的跨插件调用包装（[`runtime.plugin-hot-plug`](plugin-hot-plug.md)）。

## 输出与可观察行为

1. **检测。** 心跳停止超过 10 秒判定卡死。整个进程被暂停（例如系统睡眠）时看门狗自身的时钟同样跳变，识别为暂停并重新计时，不判定卡死；暂停期间租约是否已失效由 Session Store 租约合同判定，失效时按退出码 75 停止。主线程穿插数百毫秒的同步任务不误报。
2. **卡死时的动作**，按顺序：
   1. 以原子写入把卡死报告写到 `<State Root>/logs/hang-reports/`；
   2. 以退出码 76 结束整个进程，即使主线程仍在执行同步计算。无法以专用退出码结束时退回强制结束，此时父进程看到的退出码不是 76，报告仍然写出。

   看门狗不删除租约锁：锁只能在旧进程确定已不存在之后释放，否则卡死的主线程在删锁与进程结束之间恢复时，会与新的锁持有者同时写入。
3. **报告内容。** 卡死开始时间与持续时间、产品版本、在途插件调用列表（插件 id、版本、入口、调用类型、已运行时长、嫌疑分级）；不含用户内容与密钥。
4. **Manager 重启。** 产品在就绪之后退出、且这次退出不是由 Manager、Desktop 或它们转发的停止请求引起时（例如退出码 76、75 或其它意外退出），Manager 在确认进程已退出后删除该进程遗留的 Session Store 租约锁，再用同一端口自动重启，不重跑迁移；由停止请求引起的退出从不自动重启。5 分钟内最多自动重启 3 次，两次重启之间依次退避 1 秒、5 秒、15 秒。超过上限时停止重启，报告失败并建议以安全模式启动。重启时遇到租约仍被占用，按锁的过期时间等待后再试。前台运行的 `start` 命令不自动重启，只输出退出码与报告路径。
5. **Desktop 呈现。** 重启期间窗口显示“正在重启”，重启后再次就绪时自动恢复；超过重启上限时显示失败并提供“以安全模式启动”。
6. **下次启动的提示。** 内核启动时读取未处理的卡死报告，向打开的窗口推送“插件 X 可能导致服务端卡死，是否禁用”的提示（只针对 `direct` 与 `candidate`），然后把报告标为已处理。
7. **自动进入安全模式。** 同一插件连续 2 次卡死报告被判为 `direct` 或 `candidate` 时，下一次重启自动进入安全模式，并在界面说明原因。

## 状态与转换

| 当前 | 事件 | 结果 |
|---|---|---|
| 未布防 | 启动完成且未连接调试器、非开发模式 | 布防计时 |
| 布防 | 心跳正常 | 保持 |
| 布防 | 识别到整个进程暂停 | 重新计时 |
| 布防 | 心跳停止超过 10 秒 | 写报告 → 以 76 结束 |
| 布防 | 进程开始有序停止 | 解除布防 |
| 布防 | 调试器连接 | 停用 |

Manager 的重启计数在 5 分钟窗口内累计；窗口外的退出重新计数。

## 副作用与数据

- 卡死报告写入 `<State Root>/logs/hang-reports/`，处理后保留供诊断，按现有日志保留策略清理。
- 租约锁由 Manager 在确认旧进程退出后删除；看门狗与产品进程不删除。
- 看门狗 worker 的开销约 0.13% 单核 CPU、10MB 内存（G2 实测）。

## 失败与恢复

- 报告写入失败：仍然结束进程，退出码 76。
- Manager 删锁失败，或产品不由 Manager 启动（例如容器直接运行）：重启后的实例等待锁过期后取得租约。
- 看门狗 worker 自身崩溃：记录诊断，本次运行不再有卡死保护，不影响服务。
- 重启超过上限：停止重启，等待用户以安全模式或正常模式手动启动。

## 边界与兼容

- **owner**：application-runtime（检测、报告、结束进程、下次启动提示）、neuro-book-manager（重启策略与文案）、desktop（Electron 与 Tauri 的呈现）。
- **合同变化**：产品运行时合同新增退出码 76；Manager 取得删除已退出产品遗留租约锁的职责；Desktop 监督事件增加“产品已退出、正在重启”与“重启后再次就绪”；Manager 为 76 给出附报告路径的文案。
- **分期**：阶段 1 可以只启用记录模式（检测与报告照常，不删锁、不结束进程），也可以暂不启用；记录模式不满足本规范的验收。完整行为随阶段 3 的第三方插件加载器一起交付。
- **平台**：Windows 上从 worker 以专用退出码结束进程依据文档与源码，尚未实测，交付前须在 Windows 上验证。

## 验收与 Smoke

1. **卡死结束。** 示例插件在主线程上执行死循环：约 10 秒后进程以 76 退出，报告中该插件为 `direct`。
2. **不误报。** 主线程穿插 200 至 500 毫秒的同步任务运行 10 分钟，不触发。
3. **暂停不误报。** 暂停整个进程 30 秒后恢复，不触发。
4. **租约交接。** 卡死结束后，Manager 重启的实例在 1 秒内取得租约；在 Manager 删锁之前，没有其它进程能取得租约。
5. **Manager 重启与上限。** 用测试构建提供的钩子连续触发不归属任何插件的卡死（嫌疑 `unknown`，不触发自动安全模式）：前 3 次自动重启，第 4 次停止并建议安全模式；Desktop 在重启期间显示“正在重启”。
6. **下次启动提示与自动安全模式。** 示例插件在主线程死循环一次，重启后窗口出现禁用该插件的提示；再触发一次（连续两次为 `direct`），下一次重启自动进入安全模式。
7. **停止请求不重启。** 就绪后经 Desktop 停止产品，Manager 不重启。
8. **调试器与开发模式** 下不布防。

Smoke：生产构建在 Bun 下由 Manager 启动，用示例插件触发场景 1、4、5、6；Windows 上单独核对场景 1。
