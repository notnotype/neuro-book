# 运行作用域与资源生命周期

## 目标与非目标

目标是让任何外部消费者都能判断：某项运行资源由谁拥有、当前处于什么阶段、关闭是否真正完成、以及失败后系统停在什么状态。本能力定义所有运行位置共用的作用域阶段、资源登记与唯一所有权、在途操作的取消与结束语义、清理失败与迟到发布的收口规则，且不依赖任何产品领域。

明确不承诺：

- 不定义具体领域状态机（Project 就绪与代次、文档 dirty/save、Job 终态、认证撤销、Storage 数据）；这些由对应领域 Spec 拥有。
- 不定义服务键解析与依赖图（由 [`runtime.services`](./services.md) 拥有）、插件描述与激活（由 [`runtime.plugins`](./plugins.md) 拥有）、应用清单与启动门禁（由 `runtime.application` 拥有）。
- 不提供任意在线热卸载、代码热替换或跨进程对象共享，不改变任何用户数据格式，不承诺数据删除策略。
- 不提供恶意代码沙箱；本能力服务于受信内置代码的所有权正确性，本身不是权限系统。

## 术语与参与者

- **运行位置**：执行代码的环境（浏览器标签页/renderer、后端进程、桌面进程、受管 Worker）。本能力按位置分别建立作用域，不建立跨位置的父子作用域。
- **运行实例**：某次启动的具体环境实例，拥有自己的作用域树。刷新、重启或再次启动产生新的运行实例。
- **作用域**：拥有运行资源的边界，也是资源登记与关闭发生的单位；创建作用域的参与者是它的唯一 owner。
- **资源**：具有独立寿命的运行对象，如连接、文件句柄、订阅、监听器、计时器、Worker、租约、注册表条目。
- **owner**：唯一负责关闭资源的参与者（通常是创建该资源的作用域）。**borrower（借用者）**：通过使用关系引用资源但不拥有它的参与者；借用者只释放自己的使用关系，使用关系不等于所有权。
- **资源登记**：在资源取得的同一步把它记入 owner 的行为；登记使创建中途失败也能收口。
- **收口（closing）**：失败或停止时释放本轮已登记资源并记录结果的动作；收口不是回滚，也不恢复已发生的对外副作用；收口未完成时作用域保持停止中。
- **取消请求**：调用方不再等待、或接纳方不再要求完成的请求；只改变等待与接纳语义，不代表执行方已终止，也不代表已发生副作用被撤销。
- **终止**：执行方实际停止推进操作的时刻；只有执行方终止（或被证明不再可能返回）后，操作占用的资源才可进入释放流程。
- **关闭门禁**：报告已关闭必须满足的条件——全部已登记资源释放成功，且没有受管获取仍待返回、没有在途操作仍占用资源；门禁未满足时作用域保持停止中并记录原因。
- **迟到发布**：作用域已停止或创建已取消之后，在途初始化/获取才成功并试图对外交出句柄、贡献或可用能力。

## 输入与前置条件

- 任何资源必须在某个作用域内创建或取得。无 owner 的全局资源不在合同内：模块顶层创建全局资源、或先把资源留在局部变量里等待流程末尾统一登记，都违反本合同。
- 创建/初始化流程开始前必须取得该作用域的取消信号与登记入口；资源在取得的同时登记，不允许延迟登记。
- 作用域进入可用前，其必需资源必须完成创建并登记；可选资源失败不阻止可用，但必须留下可诊断结果。
- 借用必须携带精确的资源身份；操作接纳时记录目标（必要时含代次/身份），不能依赖稍后读取“当前目标”。
- 跨位置边界只有显式协议：本能力不传递对象引用，也不假装一个位置的作用域覆盖另一个位置。

## 输出与可观察行为

外部消费者（不读取内部私有字段）可以观察到以下行为：

1. **管理阶段**：作用域报告创建中、可用、停止中、已关闭四种阶段之一，对同一作用域全局一致。“关闭未完成”是停止中阶段的收口结果，不是第五种阶段：收口失败或超时时作用域仍报告停止中，并保留失败资源、owner 与失败记录。创建失败先进入停止中收口；只有满足关闭门禁（全部已登记资源释放成功，且没有受管获取仍待返回、没有在途操作仍占用资源）才可报告已关闭，否则不得报告已关闭。
2. **唯一 owner**：每个资源同一时刻只有一个关闭 owner。borrower 释放借用只结束自己的使用关系，不关闭共享资源（例如一个窗口退出不关闭其他窗口仍在使用的共享服务）。owner 请求关闭后，机制等待或取消已接纳的借用；调用方不再等待（取消、超时或断线）不等于使用方已终止，仍被未结束使用占据的资源不得按正常成功路径提前释放，也不得转交新 owner。
3. **关闭请求语义**：进入停止中后拒绝新业务操作与新资源创建为可用资源；已接纳的操作与在途获取按各自领域合同取消或等待，且都以实际结束为准：取消请求只改变等待与接纳语义，在途操作可在取消竞态中成功，获取必须先完成登记再被收口。内部清理仍可使用尚未关闭的依赖，不被“拒绝新业务”的闸门封死。
4. **关闭顺序**：消费者先收口，提供者最后关闭；无依赖关系的资源可以并行关闭；仍在被未结束操作使用的资源或租约最后释放。
5. **重复关闭**：对停止中或已关闭的作用域重复请求关闭，不重复副作用，并返回同一次关闭的结果；普通重复请求不另起清理，显式恢复才另起一次关闭尝试，且不得与仍 pending 的清理并发重入。
6. **取消语义与执行方分离**：取消请求后等待方得到的观察结果为已取消或结果未知，并停止等待；这描述的是等待方，不证明执行方已终止，也不缩短“使用未结束不得释放”的约束。执行方可在取消竞态中成功，成功结果同样有效、不回滚、也不改记为已取消；操作占用资源的释放以执行方终止为准。机制不自动重放、不自动撤销已发生的写入或外部副作用；调用方断线不证明远端已终止。
7. **失败可见**：创建失败、收口失败与超时都留下可查询的失败记录，包含作用域、阶段与原因；因关闭门禁未满足而保持停止中时，也能查询待返回的受管获取与仍占用资源的在途操作；诊断不携带凭据、secret 或文件内容。

## 状态与转换

作用域：

| 状态 | 事件 | 下一状态 | 结果 |
| --- | --- | --- | --- |
| 创建中 | 必需资源创建并登记完成 | 可用 | 对外交出可用能力 |
| 创建中 | 创建失败、取消或上级停止 | 停止中 | 收口本轮已登记资源（含仍可能返回的受管获取）；不发布半成品 |
| 可用 | 收到关闭请求 | 停止中 | 拒绝新业务与新资源；收口已接纳操作与在途获取 |
| 停止中 | 全部已登记资源释放成功，且没有受管获取待返回、没有在途操作仍占用资源 | 已关闭 | 报告本次关闭结果：关闭完成 |
| 停止中 | 任一资源释放失败或超时 | 停止中 | 本次结果为“关闭未完成”；保留失败资源、owner 与失败记录；不得报告已关闭 |
| 停止中 | 无显式恢复操作 | 停止中 | 本次结果为“关闭未完成”；不自动循环重试失败资源 |
| 停止中 | 显式恢复：对失败且无在途清理的资源发起新的关闭尝试并成功 | 已关闭 | 报告关闭完成 |
| 停止中 | 显式恢复的目标资源仍有 pending 清理 | 停止中 | 不重入、不并起第二次释放；先等待在途清理结算 |
| 停止中/已关闭 | 普通重复关闭请求 | 不变 | 不重复副作用；返回同一次关闭结果 |
| 已关闭 | 再次关闭请求 | 已关闭 | 返回同一次已关闭结果；不复活作用域 |

资源：

| 状态 | 事件 | 下一状态 | 结果 |
| --- | --- | --- | --- |
| 创建中 | 取得资源 | 已登记 | 立即记入 owner；失败/取消时可被收口 |
| 创建中 | 作用域停止或创建失败 | 收口中 | 资源被释放，不对外发布 |
| 已登记 | 作用域停止 | 关闭中 | 拒绝新借用；已接纳借用结束后释放 |
| 关闭中 | 释放成功 | 已释放 | — |
| 关闭中 | 释放失败或超时 | 关闭中 | 本次结果为“关闭未完成”；保留 owner 与失败记录；不交给新 owner |
| 关闭中 | 该释放仍在 pending 清理中 | 关闭中 | 不重入、不并起第二次释放；等待结算 |
| 关闭中 | 显式恢复重试无在途清理的失败资源且成功 | 已释放 | — |

在途操作：

| 状态 | 事件 | 下一状态 | 结果 |
| --- | --- | --- | --- |
| 已接纳 | 开始执行 | 执行中 | 记录目标身份/代次；占用资源计入关闭门禁 |
| 执行中 | 执行方正常结束 | 已结算 | 按领域合同提交或报告错误；释放该操作占用的资源 |
| 执行中 | 取消请求、调用方断线或作用域停止 | 执行中（等待方已结束） | 等待方得到已取消或结果未知且不再等待；不代表执行方终止，资源不提前释放 |
| 执行中（等待方已结束） | 执行方实际终止 | 已结算 | 释放该操作占用的资源；不自动重放、不回滚已发生副作用 |
| 执行中（等待方已结束） | 取消竞态中执行方成功 | 已结算（成功） | 成功有效；不回滚，也不改记为已取消 |
| 已结算 | — | — | 该操作不再计入关闭门禁 |

并发语义：关闭是同一作用域的单一幂等结果——普通重复关闭共享同一次结果，显式恢复才另起关闭尝试，且不得与仍 pending 的清理并发重入；超时只记录本次“关闭未完成”，不重入在途清理。停止中不允许新资源成为可用，但登记入口必须继续接受迟到资源的登记以便收口，closed 前不存在待返回的受管获取；空闲轮询、下一次渲染或周期任务不得重新触发失败资源的清理尝试。

## 副作用与数据

- 本能力在运行实例内维护作用域与资源登记的内存状态；不引入持久状态，不改变任何用户数据格式，不删除持久记录。
- 资源释放只影响当前运行实例的内核对象；文件、数据库、日志、Project 目录等持久数据的寿命由各自领域合同管理，关闭作用域不删除它们。
- 机制不拥有 I/O 语义：创建与释放的实际 I/O 由资源提供者执行；机制只保证登记、顺序与失败留痕。
- 关闭结果与失败记录通过运行时诊断通道暴露；机制不要求完整日志能力可用才能报告最小关闭失败。

## 失败与恢复

- **创建失败收口**：过程中取得的资源必须能被 owner 收口；失败的作用域不发布任何半成品句柄、贡献或可用能力。
- **收口失败与超时**：独立清理继续执行，错误聚合到失败记录；不报告已关闭；失败资源保持可诊断状态且不被新 owner 接管；只有显式恢复操作重试失败资源，不自动循环重试。超时只把本次尝试记为“关闭未完成”，不撤销仍 pending 的清理：该资源有在途清理时不得重入或并起第二次释放，必须先等待其结算。
- **关闭门禁**：未完成的受管获取与仍占用资源的在途操作计入关闭门禁；获取必须先完成登记再被收口，closed 前不得存在待返回的受管获取；在途操作未终止（或被证明不再可能返回）前不释放其占用资源。门禁未满足时作用域保持停止中并记录原因，不以超时或重复关闭代过。
- **取消非回滚**：取消只改变等待与接纳语义。已提交的写入、已调用的 Provider、已发出的外部请求不回滚；非幂等动作断线后可能结果未知，是否重放由拥有该操作的领域合同决定，机制不自动重放。
- **迟到发布阻断**：作用域停止、创建失败或取消后，在途初始化/获取成功返回的结果不得发布；迟到资源仍必须完成登记并由 owner 收口，在其仍可能返回之前作用域不得报告已关闭；不复活已关闭作用域，不因迟到成功改变已结算的关闭结果。
- **强制终止**：进程信号、崩溃、浏览器卸载不保证清理回调执行，也不承诺 dirty flush；此类终止不得被报告为正常关闭，恢复由领域合同负责。

## 边界与兼容

- **owner 与依赖方向**：本能力 owner 为 runtime；不依赖任何产品能力，不 import 产品领域（Files、Storage、Config、World、Plot、UI）、框架适配或数据库驱动，以便在浏览器、后端进程与受管 Worker 等不同 host 上复用。
- **相邻合同**：服务解析与依赖图见 [`runtime.services`](./services.md)；插件描述、激活与贡献见 [`runtime.plugins`](./plugins.md)；应用清单、启动门禁与跨位置装配见 `runtime.application`。本 Spec 不重复这些语义。
- **权限与安全**：持有资源引用不代表被授权；本能力不是权限系统，也不提供沙箱。根能力与 secret 由宿主以最小能力注入，诊断输出保持脱敏。
- **兼容与迁移**：允许 clean cutover（迁移全部调用方并删除旧入口），但本 Spec 不批准数据格式或迁移策略变化，不新增发布包，不引入第三方 SDK；既有 implemented 合同在切换前继续描述当前行为。

## 验收与 Smoke

以下场景在隔离运行实例中以机制公开可观察的结果判定；不读取内部私有字段，不使用产品页面或浏览器断言代替。

1. **创建中途失败收口**：给定一个创建流程依次取得两个资源、第二个获取失败；第一个资源被释放且无残留监听/句柄，作用域不报告可用，失败记录包含阶段与原因，后续不发生自动重试。
2. **唯一 owner 与借用**：两个窗口绑定同一共享资源，窗口 A 释放其借用；共享资源仍可用且窗口 B 继续工作；只有 owner 的作用域关闭才释放共享资源。
3. **取消与终止分离、非回滚**：在途操作被取消后，等待方得到已取消或结果未知且不再等待；执行方实际终止前其占用资源不释放、作用域不报告已关闭；取消竞态中执行方成功时结果有效且不回滚；已发生的副作用保持存在，机制不产生补偿写入；是否重放由该领域合同单独验证。
4. **收口失败/超时**：一个资源释放抛错、另一个正常释放；作用域仍报告停止中、本次结果为未完成而非已关闭，正常资源已释放，失败资源保留 owner 与失败记录；重复关闭返回同一未完成结果且不重复副作用；失败资源仍有在途清理时显式恢复不重入，结算后重试成功才报告已关闭。
5. **关闭门禁与迟到发布阻断**：关闭请求后一个在途初始化/获取才成功；作用域不得报告已关闭，不发布句柄/贡献，迟到资源仍被登记并收口；在途操作未终止前其占用资源不释放；门禁放行后作用域为已关闭且不能复活。
6. **两种作用域 × 两个 host 复用**：同一机制在两种不同寿命的作用域（实例级共享作用域与操作级短寿命作用域）和两个不同 host（浏览器运行实例与后端进程实例）上装配：各自独立创建、独立关闭，短寿命作用域关闭不影响实例级资源；机制实现不含产品领域 import。
7. **强制终止**：模拟无清理回调的终止；不产生正常关闭报告，下一次启动按领域合同恢复（本能力不承诺回调执行）。

Smoke 以场景操作序列为主，通过公开查询与宿主观察结果判定；具体场景入口与执行脚本由实施计划确定，本 Spec 不把尚未存在的脚本列为证据。
