# 桌面壳

## 目标与非目标

桌面壳让写作者不装 Bun、不碰命令行就能用 NeuroBook：从开始菜单、桌面或便携目录打开它，它用随包的 Bun 拉起应用包里的服务端（或连上已在运行的同版本实例），在应用自己的窗口里加载工作台；关窗时先经页面的关闭前询问，最后一个窗口关闭、服务端归它时有序停止服务端。壳只管窗口与服务端的寿命，产品逻辑都在服务端与页面里。更新见 [`runtime.desktop-update`](desktop-update.md)。

不承诺：

- 第一版只有 Windows 10、11 的 x64；macOS 与 Linux 以后做。
- 有界面的安装程序（安装位置、快捷方式的选择）、自定义标题栏、开机自启、系统托盘、系统通知：以后另做。
- 窗口不记大小与位置，每次以缺省大小居中打开。
- 不在后台常驻：没有窗口时壳退出（服务端归它时先停止服务端）。
- 被强行结束、注销、关机时不保证有序停止（输出 22）。
- 已知限制：
  - 壳连的是别人起的服务端（例如 `nbook start`），那个服务端中途停止时，桌面窗口按 [`runtime.browser-host`](browser-host.md) 离线并重连；壳不接管、不另起服务端，要关掉 NeuroBook 再打开。
  - 服务端归壳时，用 `nbook start` 在浏览器里打开的页面随最后一个桌面窗口关闭而离线。
  - 开发服务与桌面版都用 4217 起的一组端口，同时运行时必有一方顺延；端口一变，按来源存在浏览器存储里的客户端身份随之换新，布局与打开的标签页回到这个来源上次的样子（数据不删，端口恢复后回来）。主题与语言以状态根的设置为准，不受影响。
  - 便携版的 WebView2 浏览器数据留在本机，不随目录走；作品登记记绝对路径，目录挪走或盘符变了以后要重新打开作品。
  - 安装包与便携包没有代码签名，第一次运行 setup 时系统显示“未知发布者”。

## 术语与参与者

- **桌面壳**（下称壳）：桌面版的主进程，运行在随包的 Bun 上，拥有全部桌面窗口。一份安装或一个便携目录是一份壳程序；同一状态根上同一时间只有一个壳在运行。
- **托管入口**：应用包里服务端的产品入口，壳用随包的 Bun 以 `--stop-stdin` 运行它（[`runtime.server-host`](server-host.md)）。
- **自有服务端**：壳自己拉起的那个服务端进程。连上的已有实例不是自有服务端，壳不停止它。
- **桌面锁**：壳在状态根派生的地址上的单实例认领，与服务端的实例认领做法相同、地址分开（输出 1）。
- **开窗转交**：后启动的壳经桌面锁请已在运行的壳开一个新窗口，然后自己退出。
- **启动页**：壳自带的本地页面，在还没有可加载的工作台时显示：正在启动、正在停止、正在更新、等待中，以及各种不能继续的原因。
- **产品窗口**：加载了服务端页面的桌面窗口。只显示启动页的窗口不是产品窗口。
- **关闭前询问**：壳在关闭产品窗口之前问页面能不能关；页面一侧的合同见 [`runtime.browser-host`](browser-host.md) 输出 9 到 11。询问的原因是 `window`（只关这一个窗口）或 `quit`（关掉以后自有服务端会停止）。
- **便携标记**：便携包根目录里的文件 `NeuroBook.portable`，只由发布流程打便携包时写入，安装包里没有。

## 输入与前置条件

- 系统：Windows 10 或 11，x64；已装 Microsoft Edge WebView2 运行时（Windows 11 自带）。具体的最低系统版本以 Electrobun 与 WebView2 的要求为准，写进下载页。
- 一次性的标识（发出去以后不改）：应用标识 `io.github.notnotype.neurobook`，发布频道 `stable`。安装版装在 `%LOCALAPPDATA%\io.github.notnotype.neurobook\stable`，WebView2 的浏览器数据在同一标识的目录下。
- 状态根按下面的顺序取第一个：

| 来源 | 状态根 |
|---|---|
| 环境变量 `NBOOK_STATE_ROOT`（空串算没给） | 它的值，相对路径按壳的工作目录解析 |
| 程序根目录里有便携标记 | 程序根目录下的 `data\` |
| 都没有 | [`runtime.cli`](cli.md) 的平台缺省：`%LOCALAPPDATA%\NeuroBook`，与 `nbook` 共用 |

- 壳的版本即产品版本，与随包的应用包版本相同。
- 启动参数：没有面向用户的参数。

## 输出与可观察行为

**单实例与开窗转交：**

1. **桌面锁。** 壳确定状态根之后、做任何别的事之前（更新的换上除外，[`runtime.desktop-update`](desktop-update.md) 输出 8）取桌面锁。地址是 `<状态根>/desktop.sock`，Windows 是 `\\.\pipe\nbook-desktop-<状态根真实路径的 sha256 前 16 位>`；取锁、残留文件、几个同时取锁恰好一个成功、被暂停时不接管的规则同服务端的实例认领（[`runtime.server-host`](server-host.md) 的“实例认领”）。壳退出时放下锁；被强行结束时锁随进程释放。
2. **锁上的协议。** 一行 JSON 请求，一行 JSON 应答后关闭连接：`{"type":"hello"}` 回 `{schema: 1, pid, version, status}`，`status` 是 `starting`、`running` 或 `stopping`；`{"type":"open-window"}` 回 `{ok: true}`（已开出一个窗口并置前）或 `{ok: false, code: "stopping"}`。请求不带地址或参数，接收的壳只开自己服务端的页面。不认识的请求回 `{ok: false, code: "unknown-request"}`。请求与应答各限 64 KB，连上之后 3 秒内不发完请求的连接被断开。这个协议跨版本使用：`hello` 的字段只加不改。
3. **锁已被别的壳持有。** 先发 `hello`：
   - 版本相同、`starting` 或 `running`：发 `open-window`，收到 `ok: true` 后自己以 0 退出，不开窗口；
   - 版本相同、`stopping`，或 `open-window` 回 `stopping`：显示启动页“正在退出上一个 NeuroBook”，等它放下锁后自己取锁、照常启动；60 秒内没放下时启动页说明并给“重试”“退出”；
   - 版本不同：启动页说明“已在运行的是 NeuroBook <版本>，先关掉它再打开”，只给“退出”；不发开窗请求；
   - 连上了但 3 秒内没有应答：启动页说明“另一个 NeuroBook 没有响应”，给出它的 pid，只给“退出”。

**连接服务端：**

4. **问状态根上的服务端。** 拿到桌面锁后，用服务端认领上的 `hello`（[`runtime.server-host`](server-host.md) 的应答协议）问状态根上的实例，判定与 `nbook start` 相同（[`runtime.cli`](cli.md) 的“状态与转换”）：

| 问到 | 壳做什么 |
|---|---|
| 没有实例 | 用随包的 Bun 以 `--stop-stdin` 运行托管入口，环境变量 `NBOOK_STATE_ROOT` 设为状态根，成为它的拥有者；被别的进程抢先认领了就重问 |
| 就绪的产品实例，版本相同 | 开窗口连它，不拥有它 |
| 产品实例启动中或停止中，版本相同 | 启动页显示“正在启动”或“正在停止”，等它变化后重问；60 秒内没有变化时说明并给“重试”“退出” |
| 版本不同 | 启动页说明运行中的版本与本程序的版本，提示先停掉它（例如在运行 `nbook` 的终端里按 Ctrl-C）再打开，只给“退出”；不碰那个实例 |
| 开发实例 | 启动页说明这个状态根正由开发服务使用，只给“退出” |
| 连上了但没有应答 | 启动页说明并给出那个进程的 pid，只给“退出” |

5. **就绪与地址。** 自有服务端的就绪与页面地址都从认领应答读（`status` 为 `ready` 时的 `url`），不解析服务端标准输出的文字；启动期间启动页显示“正在启动”。自有服务端启动失败（就绪前退出）时启动页显示退出码与日志目录，给“重试”“打开日志目录”“退出”。
6. **端口。** 壳不给服务端指定端口，服务端用缺省端口与成对顺延（[`runtime.server-host`](server-host.md) 的启动参数）。
7. **服务端的输出。** 自有服务端的标准输出与标准错误写进 `<状态根>/logs/desktop/server-output.log`，文件超过 10 MB 时改名为 `server-output.1.log`（覆盖旧的）后重新开始。壳自己的日志在同一目录。

**窗口：**

8. **第一个窗口。** 启动时开一个窗口，先显示启动页，服务端就绪后加载它的页面地址；加载前检查 WebView2（输出 20）。
9. **再开窗口。** 开窗转交（输出 2）与页面请求的新窗口（输出 12）都开一个新的产品窗口，加载服务端的首页（不带项目参数），置前。壳正在停止时不再开新窗口。
10. **窗口标题与大小。** 窗口标题是页面的标题；缺省大小 1280×800 逻辑像素，放不下时取工作区的九成，居中；可以调整大小、最大化。
11. **导航。** 产品窗口只允许导航到启动页与当前服务端页面地址的精确来源（协议、主机、端口都相同）；页面里对其它来源的整页导航被拒绝，`http`、`https` 的交给系统默认浏览器打开，`file` 与其它协议拒绝。
12. **新窗口。** 页面请求打开新窗口（脚本打开、`target="_blank"` 的链接）时：同一来源的地址开一个新的产品窗口加载它；`http`、`https` 的外部地址交给系统默认浏览器；其它拒绝。
13. **页面能用的壳接口。** 产品窗口里，页面只能经壳回答关闭前询问（输出 14）与接收更新提示（[`runtime.desktop-update`](desktop-update.md)）；页面不能经壳读写文件、执行命令、开别的窗口或调用其它原生能力。

**关闭窗口：**

14. **关闭前询问。** 用户关一个产品窗口时（标题栏的关闭、Alt+F4），壳先拦下关闭，再问这个窗口的页面，原因按输出 16 定：
    - 页面在 3 秒内接下询问，之后不限时，等它的回答：`allow` 就关，`deny` 就不关、窗口照旧；
    - 3 秒内没有接下（脚本卡死、页面还没就绪、正在显示宿主页以外的出错页）时，壳弹原生对话框“NeuroBook 没有响应”：“继续等待”（再等 3 秒）、“取消关闭”、“强制关闭（未保存的内容可能丢失）”；
    - 已接下、还没回答时用户再次关这个窗口：弹同一个原生对话框，“继续等待”不重置已接下的询问；
    - 不把超时或连接断开当作同意。
15. **一窗一个询问。** 每个窗口同一时间至多一个待决询问，询问带代次；壳只认当前代次的回答，迟到、过期的回答丢弃。“取消关闭”与“强制关闭”都结束当前代次。
16. **原因与最后一个窗口。** 关的是最后一个仍存活的产品窗口、且服务端是自有服务端时，原因是 `quit`；否则是 `window`。关闭由壳逐个提交：真正关掉最后一个仍存活的产品窗口之前，壳重新判断原因；这个窗口的询问是以 `window` 回答的（询问期间别的窗口关掉了），就以 `quit` 重新询问一次。
17. **没有产品页面的窗口。** 只显示启动页的窗口直接关，不询问。最后一个窗口关掉后，自有服务端按输出 18 停止，壳退出。

**停止：**

18. **停止自有服务端。** 最后一个窗口关掉后，壳往自有服务端的标准输入写一行 `stop`，等它退出；连上的不是自有服务端时直接退出，不碰它。
19. **三态。** 壳的状态是运行中、停止中、已停止。没到已停止时，每一次退出请求（包括框架自己的末窗退出与系统发给应用的退出请求）都被拦下；停止中收到的开窗转交回 `stopping`。停止的截止是 90 秒（不短于服务端自己的停止预算：排空 20 秒加项目子进程的停止截止）：到时强制结束服务端进程树，并在 `<状态根>/logs/desktop/` 记一条“没有正常停止”，下一次启动时启动页先说明“上次退出时服务端没有正常停止”，给“打开日志目录”“继续”。服务端以非 0 退出码结束时同样记这一条。

**异常：**

20. **WebView2。** 创建网页视图之前检查 WebView2 运行时；没有时用系统对话框说明，给出官方下载地址，只给“打开下载页”“退出”，不显示空白窗口。
21. **自有服务端意外退出。** 运行中（没有请求停止）自有服务端退出时，壳弹原生对话框“NeuroBook 的服务意外退出（退出码 N）”，给“重新启动服务”“稍后”，并给出日志目录；窗口保持，页面按 [`runtime.browser-host`](browser-host.md) 离线。“重新启动服务”按输出 4 重新拉起，已打开的页面重连后显示“服务端已重启”页（未保存的正文可取回）。“稍后”只关掉对话框：窗口照旧离线，用户可以从页面复制未保存的内容；之后关窗照常经关闭前询问，原因一律是 `window`，最后一个窗口关掉后壳直接退出（没有要停止的服务端）。
22. **壳被强行结束。** 壳被强行结束、注销、关机时，自有服务端随之被结束，不保证有序停止：服务端已提交的数据（SQLite 事务、原子写入的文件）保留；还在页面里、没交给服务端的输入可能丢失。下一次启动照常，不提示。

**便携：**

23. **便携版的状态根。** 有便携标记时状态根是程序根目录下的 `data\`（不存在时建出来）。程序根目录不可写（只读介质、没有权限）时，启动页显示实际路径，说明便携版要放在可写的位置，只给“退出”；不改用安装版的状态根。

## 状态与转换

| 当前 | 事件 | 结果 |
|---|---|---|
| 启动中 | 取到桌面锁 | 问服务端（输出 4） |
| 启动中 | 锁被同版本的壳持有 | 开窗转交后退出（输出 3） |
| 启动中 | 服务端就绪 | 运行中，第一个窗口加载页面 |
| 运行中 | 关一个产品窗口 | 关闭前询问（输出 14 到 16） |
| 运行中 | 最后一个窗口关掉，服务端自有 | 停止中，写 `stop` |
| 运行中 | 最后一个窗口关掉，服务端不是自有 | 已停止，退出 |
| 运行中 | 自有服务端意外退出 | 原生对话框（输出 21）；选“稍后”时之后的关窗按服务端不是自有处理 |
| 停止中 | 服务端退出或 90 秒到 | 已停止，放下桌面锁，退出 |
| 停止中 | 任何退出请求、开窗转交 | 拦下；开窗转交回 `stopping` |

时序与寿命：

- 桌面锁先于问服务端：同一状态根上不会有两个壳各起一个服务端，也不会有两个壳分别拥有同一个服务端的窗口。
- 壳只在认领应答的 `status` 为 `ready` 之后加载页面地址，加载时服务端已能处理请求。
- 关闭前询问的回答只对它的代次有效；窗口关掉之后，这个窗口的待决询问作废。
- 写 `stop` 之后壳不再开窗口；服务端退出之后才放下桌面锁，所以后启动的壳在锁放下之后问到的是“没有实例”，不会撞上停止中的旧服务端认领。
- 壳退出时，标准输入随之关闭；服务端读到标准输入结束同样有序停止（[`runtime.server-host`](server-host.md)），所以壳在任何路径上退出都不会留下自有服务端。

## 副作用与数据

- 状态根由服务端读写，格式不变；壳只写 `<状态根>/logs/desktop/` 与桌面锁的套接字文件。
- WebView2 的浏览器数据（按来源的本地存储、缓存）在应用标识的目录下，卸载时选“应用和数据”会一并删除；状态根不在这个目录里，卸载不删作品登记与设置。
- 壳不删除任何用户数据。

## 失败与恢复

| 情形 | 呈现 | 用户怎么办 |
|---|---|---|
| 同状态根上已有不同版本的壳 | 启动页说明（输出 3） | 关掉它再打开 |
| 已有壳或服务端不应答 | 启动页给出 pid（输出 3、4） | 结束那个进程后再打开 |
| 服务端是别的版本或开发实例 | 启动页说明（输出 4） | 停掉它再打开 |
| 等待超过 60 秒 | 启动页给“重试”“退出” | 看日志，稍后再试 |
| 自有服务端启动失败 | 启动页给退出码与日志目录（输出 5） | 看日志，重试 |
| 便携目录不可写 | 启动页说明（输出 23） | 复制到可写的位置 |
| 没有 WebView2 | 系统对话框（输出 20） | 装好后再打开 |
| 服务端停止超时 | 下一次启动时提示（输出 19） | 看日志 |
| 自有服务端意外退出 | 原生对话框（输出 21） | 重新启动服务或退出 |

## 边界与兼容

- 公开接口：桌面锁的地址与协议（输出 2；跨版本使用，字段只加不改）、便携标记的文件名、应用标识与发布频道（一次性，发出去以后不改）。
- 依赖的合同：服务端的 `--stop-stdin` 与认领应答（[`runtime.server-host`](server-host.md)）、页面一侧的关闭前询问（[`runtime.browser-host`](browser-host.md) 输出 9 到 11）。
- 信任边界：服务端只监听回环；产品窗口只信任当前服务端的精确来源，页面能经壳做的只有输出 13 列出的两件事。
- 与 `nbook` 共用状态根与服务端：桌面壳起的服务端是 `product` 种类的实例，`nbook start` 看到它时按自己的规则报告并在浏览器里打开。

## 验收与 Smoke

用 Windows 上的真实安装包或便携包：

1. **同版本复用。** 壳在运行时再从开始菜单打开：多出一个窗口、置前，后启动的进程以 0 退出，进程列表里只有一个壳。
2. **异版本拒绝。** 旧版本的壳在运行时打开新版本：新版本的启动页说明已在运行的版本，不发开窗请求，旧版本照常。
3. **同时启动。** 两次打开几乎同时发生：只有一个壳、一个服务端，最后有两个窗口。
4. **连已有实例。** 先 `nbook start` 起同版本的服务端，再打开桌面版：窗口连它；关掉全部桌面窗口后服务端仍在运行，浏览器里的页面不受影响。版本不同时启动页说明并只给“退出”。
5. **任意顺序关窗。** 三个窗口按任意顺序关掉；两个窗口的关闭前询问重叠（第一个还在问时关第二个）：只有关最后一个时以 `quit` 询问，最后服务端有序停止、以 0 退出。
6. **编辑中关窗。** 自动保存开着时输入后立即关窗：磁盘上是新正文；自动保存关着时：页面询问，“取消”后窗口与正文都在；保存失败：不关；页面卡死：3 秒后原生对话框，“取消关闭”后窗口还在，“强制关闭”后窗口关掉。
7. **有任务在跑时关最后一个窗口。** 一个 Agent 会话在运行：页面提示关闭会中断它，“取消”后一切照旧；“仍然关闭”后服务端有序停止，会话按中断收口。服务端不归壳时关最后一个窗口不提示。
8. **写入中强行结束。** 打开作品、正在保存时结束壳的进程树：重新打开后已提交的数据完整，服务端认领与桌面锁都能重新取得。
9. **开发服务与桌面版并行。** `bun run dev` 运行时打开桌面版：两者都能用，一方的端口顺延。
10. **便携。** 便携包解压到 A 目录运行、新建作品、关闭，挪到 B 目录再运行：书架上还在，作品要重新打开；`data\` 在程序目录下；安装版的状态根没有被写。放到只读目录运行：启动页说明。
11. **导航与新窗口。** 页面里点外部链接：在系统浏览器打开，窗口不离开工作台；同来源的新窗口请求开出一个产品窗口。
12. **自有服务端意外退出。** 结束服务端进程：对话框出现，“重新启动服务”后页面显示“服务端已重启”，刷新后可用。

Smoke：发布流水线的 Windows 作业对安装版与便携版各跑一遍：静默安装（便携版解压到别处）、直接启动应用到页面就绪、打开一部作品并执行一条 Agent 的内嵌 shell 命令、经关闭前询问关窗、服务端有序停止并以 0 退出、卸载。
