# 桌面壳

## 目标与非目标

桌面壳让写作者不装 Bun、不碰命令行就能用 NeuroBook：从开始菜单、桌面或便携目录打开它，它用随包的 Bun 拉起应用包里的服务端（或连上已在运行的同版本实例），在应用自己的窗口里加载工作台；关窗时先经页面的关闭前询问，最后一个窗口关闭、服务端归它时有序停止服务端；设置为留在系统托盘时改为留在后台，从托盘再打开或退出（输出 28 到 31）。壳只管窗口与服务端的寿命，产品逻辑都在服务端与页面里。更新见 [`runtime.desktop-update`](desktop-update.md)。

不承诺：

- 第一版的完整支持只有 Windows 10、11 的 x64；macOS（Apple Silicon，未签名）是尽力而为的预览，范围见输出 35，没有在真机上验证过；Linux 以后做。
- 安装程序用 Electrobun 自带的：按当前用户安装、不要管理员权限，没有选项页，界面只有英文的进度框与卸载对话框。安装位置固定在“输入与前置条件”写的目录，不能选（Electrobun 2.0.6 的安装、更新器与卸载都认这个位置）；快捷方式、开机自启这些选择放在首次启动向导里（输出 34，planned）。
- 系统通知：以后另做。
- 窗口不记大小与位置，每次以缺省大小居中打开。
- 缺省不在后台常驻：没有窗口时壳退出（服务端归它时先停止服务端）。只有设置为留在系统托盘时才在后台运行（输出 28）；缺省设置下关最后一个窗口时，即使有工作在跑也不提供留在后台。
- 被强行结束、注销、关机时不保证有序停止（输出 22）。
- 已知限制：
  - 壳连的是别人起的服务端（例如 `nbook start`），那个服务端中途停止时，桌面窗口按 [`runtime.browser-host`](browser-host.md) 离线并重连；壳不接管、不另起服务端，要关掉 NeuroBook 再打开。
  - 服务端归壳时，用 `nbook start` 在浏览器里打开的页面随最后一个桌面窗口关闭而离线。
  - 开发服务与桌面版都用 4217 起的一组端口，同时运行时必有一方顺延；端口一变，按来源存在浏览器存储里的客户端身份随之换新，布局与打开的标签页回到这个来源上次的样子（数据不删，端口恢复后回来）。主题与语言以状态根的设置为准，不受影响。
  - 便携版的 WebView2 浏览器数据留在本机，不随目录走；作品登记记绝对路径，目录挪走或盘符变了以后要重新打开作品。
  - 安装包与便携包没有代码签名，第一次运行 setup 时系统显示“未知发布者”。
  - 页面里的 `window.open` 与带 `target` 的链接经壳按输出 12 处理；其它弹出入口（例如内嵌页面里的弹窗）可能由 WebView2 自己开一个不受输出 11 约束的窗口。
  - 桌面专属设置（输出 25 到 27）：卸载安装版不会删开机自启的登记（Electrobun 的卸载程序没有挂钩子的接口），留下的一项指向已删的程序，登录时静默失败，设置说明里提示卸载前先关掉；焦点在 HTML 预览的内嵌页面里时按的缩放键走 WebView2 自带的缩放，不进设置。
  - 自己画的标题栏（输出 10）：悬停最大化按钮不弹出 Windows 11 的贴靠布局（Win+Z 照常）；窗口换到缩放比例不同的显示器后，窗口图标不按新的比例重新加载，由系统缩放；模态对话框开着时整个窗口不能拖动；工作台标题栏左上角的标志是按钮，那一块不能拖窗口。
  - 托盘与后台（输出 28 到 31）：托盘图标左键、右键都弹出菜单，没有“左键直接打开”；Explorer 重启后图标不回来，从开始菜单再打开、或注销后恢复；Windows 11 的新图标缺省在任务栏的溢出区里；图标尺寸取建图标那一刻主显示器的缩放比例，之后改缩放、换主显示器不重建；留在后台时注销、关机由系统结束（输出 22），不保证有序停止；托盘的菜单、提示与壳的对话框只有中文。
  - 最小尺寸（输出 10）：小屏幕上半屏比 800 窄时（例如 1920×1080 开 150%、1366×768 开 100%），拖到屏幕边缘贴成半屏时窗口宽不小于 800、与另一半重叠（按最小跟踪尺寸的规则推断，未在这样的屏幕上实测）；启动页窗口被拖得比最小值小、之后换成产品页时，不会自动放大到最小值。

## 术语与参与者

- **桌面壳**（下称壳）：桌面版的主进程，运行在随包的 Bun 上，拥有全部桌面窗口。一份安装或一个便携目录是一份壳程序；同一状态根上同一时间只有一个壳在运行。
- **托管入口**：应用包里服务端的产品入口，壳用随包的 Bun 以 `--stop-stdin` 运行它（[`runtime.server-host`](server-host.md) 的“托管宿主”）。
- **自有服务端**：壳自己拉起的那个服务端进程（连同它的项目子进程）。连上的已有实例不是自有服务端，壳不停止它。
- **桌面锁**：壳在状态根派生的地址上的单实例认领，与服务端的实例认领做法相同、地址分开（输出 1）。
- **开窗转交**：后启动的壳经桌面锁请已在运行的壳开一个新窗口，然后自己退出。
- **启动页**：壳自带的本地页面，在还没有可加载的工作台时显示：正在启动、正在停止、正在更新、等待中，以及各种不能继续的原因。
- **对话框**：壳自己开的小窗口，加载壳自带的本地页面，不经产品页面；开着时壳照常应答锁上的请求、计时与收页面的回答。缺 WebView2 的提示（输出 20）是系统消息框。
- **产品窗口**：加载了服务端页面的桌面窗口。只显示启动页的窗口不是产品窗口；服务端就绪后，正显示“正在启动”的窗口都转为产品窗口。
- **关闭前询问**：壳在关闭产品窗口之前问页面能不能关；页面一侧的合同见 [`runtime.browser-host`](browser-host.md) 输出 9 到 11。询问的原因是 `window`（只关这一个窗口）或 `quit`（关掉以后自有服务端会停止）。
- **最后一次关闭**：以 `quit` 询问的那次关闭，从询问开始到窗口关掉、壳进入停止中（或被取消）为止。
- **后台**：壳有自有服务端、没有窗口、不在停止中，服务端照常运行；只在设置为留在系统托盘、且托盘图标显示着时进入（输出 29）。
- **应用级退出**：要整个 NeuroBook 退出的请求，来自托盘菜单的“退出”或系统与框架发给应用的退出请求（输出 19、31）。
- **便携标记**：便携包根目录里的文件 `NeuroBook.portable`，只由发布流程打便携包时写入，安装包里没有。

## 输入与前置条件

- 系统：Windows 10 或 11，x64；已装 Microsoft Edge WebView2 运行时（Windows 11 自带）。具体的最低系统版本以 Electrobun 与 WebView2 的要求为准，写进下载页。
- 一次性的标识（发出去以后不改）：应用标识 `io.github.notnotype.neurobook`，发布频道 `stable`。安装版装在 `%LOCALAPPDATA%\io.github.notnotype.neurobook\stable`，WebView2 的浏览器数据在同一标识的目录下。
- 状态根按下面的顺序取第一个，这次运行一直用它：

| 来源 | 状态根 |
|---|---|
| 环境变量 `NBOOK_STATE_ROOT`（空串算没给） | 它的值，必须是完整路径（Windows 上带盘符，或是 UNC；只有根、没有盘符的 `\foo` 不算）；不是时启动页显示这个值、要求改成完整路径，只给“退出”（壳的工作目录是安装里的程序目录，更新时整个被替换） |
| 程序根目录里有便携标记 | 程序根目录下的 `data\` |
| 都没有 | [`runtime.cli`](cli.md) 的平台缺省：`%LOCALAPPDATA%\NeuroBook`，与 `nbook` 共用 |

- 壳的版本即产品版本，与随包的应用包版本相同。
- 启动参数：没有面向用户的参数。

## 输出与可观察行为

**单实例与开窗转交：**

1. **桌面锁。** 壳确定状态根之后、做任何别的事之前（更新的换上除外，[`runtime.desktop-update`](desktop-update.md) 输出 8）取桌面锁。地址是 `<状态根>/desktop.sock`，Windows 是 `\\.\pipe\nbook-desktop-<状态根真实路径的 sha256 前 16 位>`；取锁、残留文件、几个同时取锁恰好一个成功、被暂停时不接管的规则同服务端的实例认领（[`runtime.server-host`](server-host.md) 的“实例认领”）。壳退出时放下锁；被强行结束时锁随进程释放。
2. **锁上的协议。** 一行 JSON 请求，一行 JSON 应答后关闭连接：`{"type":"hello"}` 回 `{schema: 1, pid, version, status, kind, url, rpcUrl}`（与服务端认领应答的基础字段相同，`kind` 是 `product`，`url` 与 `rpcUrl` 为 null），`status` 是 `starting`、`ready` 或 `stopping`；`{"type":"open-window"}` 立即回 `{ok: true}`（已开出一个窗口并置前：服务端已就绪时是产品窗口，还在启动时是显示“正在启动”的窗口，就绪后转为产品窗口）、`{ok: false, code: "closing"}`（最后一次关闭进行中，这次没有开窗，见输出 16）或 `{ok: false, code: "stopping"}`。请求不带地址或参数。不认识的请求回 `{ok: false, code: "unknown-request"}`。每个请求都在 3 秒内应答；请求与应答各限 64 KB，连上之后 3 秒内不发完请求的连接被断开。这个协议跨版本使用：`hello` 的字段只加不改。
3. **锁已被别的壳持有。** 先发 `hello`：
   - 版本相同、`starting` 或 `ready`：发 `open-window`，收到 `ok: true` 后自己以 0 退出，不开窗口；收到 `closing` 时显示启动页“另一个 NeuroBook 窗口正在确认关闭”，只给“退出”，每秒重发一次 `open-window`，直到得到 `ok: true` 或 `stopping`（这一步不设截止，等的是那边用户的决定）；某次连不上锁的地址（那边已经关掉、放了锁）时，回到输出 1 重新取锁，按取到与否照常往下走；
   - 版本相同、`stopping`，或 `open-window` 回 `stopping`：显示启动页“正在退出上一个 NeuroBook”，等它放下锁后自己取锁、照常启动；60 秒内没放下时启动页说明并给“重试”“退出”；
   - 版本不同：启动页说明“已在运行的是 NeuroBook <版本>，先关掉它再打开”，只给“退出”；不发开窗请求；
   - 连上了但某个请求 3 秒内没有应答：启动页说明“另一个 NeuroBook 没有响应”，能从锁的地址取得对方进程号时一并给出，取不到就说明取不到；只给“退出”。

**连接服务端：**

4. **问状态根上的服务端。** 拿到桌面锁后，用服务端认领上的 `hello`（[`runtime.server-host`](server-host.md) 的应答协议）问状态根上的实例，判定与 `nbook start` 相同（[`runtime.cli`](cli.md) 的“状态与转换”）：

| 问到 | 壳做什么 |
|---|---|
| 没有实例 | 用随包的 Bun 以 `--stop-stdin` 运行托管入口，环境变量 `NBOOK_STATE_ROOT` 设为状态根、`NBOOK_WEB_ROOT` 设为随包应用包的 `web/`，成为它的拥有者；被别的进程抢先认领了就重问 |
| 就绪的产品实例，版本相同 | 开窗口连它，不拥有它 |
| 产品实例启动中或停止中，版本相同 | 启动页显示“正在启动”或“正在停止”，等它变化后重问；60 秒内没有变化时说明并给“重试”“退出” |
| 版本不同 | 启动页说明运行中的版本与本程序的版本，提示先停掉它（例如在运行 `nbook` 的终端里按 Ctrl-C）再打开，只给“退出”；不碰那个实例 |
| 开发实例 | 启动页说明这个状态根正由开发服务使用，只给“退出” |
| 连上了但没有应答 | 启动页说明，能取得那个进程的进程号时一并给出；只给“退出” |

5. **就绪与地址。** 自有服务端的就绪与页面地址都从认领应答读（`status` 为 `ready` 时的 `url`），不解析服务端标准输出的文字；启动期间启动页显示“正在启动”。自有服务端启动失败（就绪前退出）时启动页显示退出码与日志目录，给“重试”“打开日志目录”“退出”。
6. **端口。** 第一次拉起时壳不给服务端指定端口，服务端用缺省端口与成对顺延（[`runtime.server-host`](server-host.md) 的启动参数）；重新启动服务（输出 21）时用上一次的两个端口。
7. **服务端的输出。** 自有服务端的标准输出与标准错误写进 `<状态根>/logs/desktop/server-output.log`，文件超过 10 MB 时改名为 `server-output.1.log`（覆盖旧的）后重新开始。壳自己的日志在同一目录。

**窗口：**

8. **第一个窗口。** 启动时开一个窗口，先显示启动页，服务端就绪后加载“启动时打开”的路由（输出 9 的规则，进上次的作品或书架）；创建网页视图之前检查 WebView2（输出 20）。
9. **开窗转交开的窗口。** 开窗转交（输出 2）开一个新窗口，置前。壳正在停止时不再开窗。启动、开窗转交、托盘“打开”（输出 30）与 macOS 的 Dock（输出 35）都经同一处开窗，地址按同一条规则定：开它时没有别的、不在关闭中的窗口，加载“启动时打开”的路由 `/api/nbook.projects/resume`（[`runtime.projects`](projects.md) 输出 23，进上次的作品或书架）；已有窗口时加载服务端的首页（书架，不带查询参数）。启动期间转交来的再开的启动页同样按开它那一刻算，服务端就绪后只有第一个进上次的作品。
10. **窗口、标题栏与图标。** 窗口标题（任务栏与 Alt+Tab 里的文字）是页面的标题；缺省大小 1600×1000 逻辑像素，放不下时取工作区的九成，居中；可以调整大小、最大化。
    - **没有系统标题栏**：Windows 上 WebView2 的主版本不低于 123 时，产品窗口与启动页窗口没有系统标题栏，保留拉伸边框与阴影；窗口按钮与标题栏由页面画（页面一侧见 [`runtime.browser-host`](browser-host.md) 的“窗口外框”）。页面用 CSS `app-region` 标出拖动区域，拖动、双击最大化与还原、拖到屏幕边缘贴边分屏、Alt+Space 的系统菜单都由系统处理（窗口背景选了磨砂的窗口没有系统菜单，见输出 32）。壳在页面脚本之前定义只读的能力标记 `__nbookDesktopFrame`，页面据此画按钮；它只是渲染信号，不是安全边界。WebView2 更旧时（没有非客户区支持）窗口退回系统标题栏、不定义标记，页面照旧只画工作台自己的标题栏。对话框窗口（输出 15 的“没有响应”、输出 21）保留系统标题栏。
    - **最大化**：落在显示器的工作区里，不压任务栏。壳在创建窗口后给它补上系统菜单与最小化、最大化按钮的窗口样式（Electrobun 的无标题栏样式缺这几位，缺了最大化会铺满整个显示器）；补不成时窗口照常可用，记诊断 `desktop.frame.adopt-failed`。
    - **最小尺寸**：产品窗口（有没有系统标题栏都算）的客户区最小 800×560（CSS 像素，按窗口所在显示器的 DPI 换算；界面缩放不影响），但不超过窗口所在显示器的工作区。它限制用户拖动改大小；窗口打开时外框就不小于它（工作区不够时以工作区为准）。启动页与对话框不受限。Electrobun 2.0.6 没有这个接口，壳在运行时编译一个窗口过程子类化产品窗口；编译或安装失败时写壳日志 `desktop.window.min-size-unavailable`，窗口照常可用、只是没有最小尺寸。
    - **窗口按钮**：页面经壳最小化、在最大化与还原之间切换、关闭；关闭与系统的关闭同一条路（输出 14、17）。壳把“是不是最大化”推给页面（窗口大小变化、页面报就绪、页面查询时），它严格等于 Win32 的最大化状态：贴边分屏不算最大化。
    - **图标**：程序、安装程序与窗口的图标是应用图标（品牌成品的 `desktop/windows/neurobook.ico`，16 到 256 各档都从同一份 SVG 渲染）；窗口图标按窗口所在显示器的缩放比例取尺寸。
11. **导航。** 产品窗口只允许导航到启动页与当前服务端页面地址的精确来源（协议、主机、端口都相同）；页面里对其它来源的整页导航被拒绝，`http`、`https` 的交给系统默认浏览器打开，`file` 与其它协议拒绝。
12. **页面请求的新窗口。** 页面以网页的方式请求打开新窗口（脚本打开、`target="_blank"` 的链接）时：同一来源的地址开一个新的产品窗口，原样加载这个地址（路径、查询参数与片段都保留，例如带 `project` 参数打开作品）；`http`、`https` 的外部地址交给系统默认浏览器；其它拒绝。
13. **页面能用的壳接口。** 除了输出 12 这种网页本来就有的新窗口请求，页面只能经壳回答关闭前询问（输出 14）、收发更新提示（[`runtime.desktop-update`](desktop-update.md)）、按窗口按钮与查询窗口是否最大化（输出 10）、交桌面专属设置的有效值（输出 25）、收这次运行的安装事实与请壳打开状态根（输出 34，planned）；页面不能经壳读写文件、执行命令、开任意窗口或调用其它原生能力。

**关闭窗口：**

14. **关闭前询问。** 用户关一个产品窗口时（标题栏的关闭、Alt+F4），壳先拦下关闭，再问这个窗口的页面，原因按输出 16 定：
    - 页面在 3 秒内接下询问，之后不限时，等它的回答：`allow` 就关，`deny` 就不关、窗口照旧；
    - 3 秒内没有接下（脚本卡死、页面还没就绪、显示的是加载失败的错误页）时，壳弹对话框“NeuroBook 没有响应”：“继续等待”（再等 3 秒）、“取消关闭”、“强制关闭（未保存的内容可能丢失）”；
    - 已接下、还没回答时用户再次关这个窗口：弹同一个对话框，“继续等待”不重置已接下的询问；
    - 不把超时或连接断开当作同意。
15. **一窗一个询问。** 每个窗口同一时间至多一个待决询问，询问带代次；壳只认当前代次的回答，迟到、过期的回答丢弃。“取消关闭”“强制关闭”与窗口关掉都结束当前代次，并通知页面这次询问已结束（页面一侧怎么收口见 [`runtime.browser-host`](browser-host.md) 输出 10）。
16. **原因与最后一次关闭。** 关的是最后一个仍存活的产品窗口、且服务端是自有服务端时，原因是 `quit`，这次关闭成为最后一次关闭；否则是 `window`。设置为留在系统托盘时，最后一个窗口的原因按输出 29 的表定。关闭由壳逐个提交：
    - 真正关掉一个窗口之前，壳重新判断原因；这个窗口的询问是以 `window` 回答的、而此刻按规则应是 `quit`（询问期间别的窗口关掉了，或输出 29 的条件变了），就以 `quit` 重新询问一次；以 `quit` 得到的同意一律停止，询问期间设置改成留在托盘也一样；
    - “没有响应”对话框里的“强制关闭”：这次询问的原因与此刻的原因有一个是 `quit`，就按 `quit` 提交；
    - 最后一次关闭进行中时，开窗转交回 `closing`、不开窗（输出 2、3），页面请求的新窗口被拒绝；所以以 `quit` 得到的同意一定对应真正的最后一个窗口，同一次停止不会问两遍；
    - 最后一次关闭被同意时，关掉窗口与进入停止中是同一步，中间不会再开出窗口。
17. **没有产品页面的窗口。** 只显示启动页的窗口直接关，不询问。最后一个窗口关掉后按输出 18 收尾（进入后台的情形见输出 29）；启动还没完成时按输出 23。

**停止：**

18. **停止自有服务端。** 最后一个窗口关掉后，壳往自有服务端的标准输入写一行 `stop`，等它真实退出；连上的不是自有服务端时直接退出，不碰它。
19. **三态与截止。** 壳拿到桌面锁之后的状态是运行中、停止中、已停止。拿到锁之后、到已停止之前，每一次退出请求（包括框架自己的末窗退出与系统发给应用的退出请求）都被拦下；停止中收到的开窗转交回 `stopping`。停止的截止是排空上限 20 秒加服务端实际使用的项目子进程停止截止（`NBOOK_PROJECT_STOP_MS`，缺省 20 秒），再加 50 秒余量，缺省共 90 秒：到时壳强制结束服务端进程树，等这棵树真实结束再进入已停止；强制结束后 10 秒仍没结束时写一条诊断，继续等，不放桌面锁。超时、强制结束或服务端以非 0 退出码结束时，在 `<状态根>/logs/desktop/` 记一条“没有正常停止”，下一次启动时启动页先说明“上次退出时服务端没有正常停止”，给“打开日志目录”“继续”。

**异常：**

20. **WebView2。** 创建网页视图之前检查 WebView2 运行时；没有时用系统对话框说明，给出官方下载地址，只给“打开下载页”“退出”，不显示空白窗口。
21. **自有服务端意外退出。** 运行中（没有请求停止）自有服务端退出时，壳弹对话框“NeuroBook 的服务意外退出（退出码 N）”，给“重新启动服务”“稍后”，并给出日志目录；窗口保持，页面按 [`runtime.browser-host`](browser-host.md) 离线。“重新启动服务”用上一次的两个端口重新拉起（输出 6），已打开的页面重连后显示“服务端已重启”页（未保存的正文可取回）；端口被占用、拉起失败时对话框说明原因，窗口仍保持离线，可以再试。“稍后”只关掉对话框：窗口照旧离线，用户可以从页面复制未保存的内容；之后关窗照常经关闭前询问，原因一律是 `window`，最后一个窗口关掉后壳直接退出（没有要停止的服务端）。在后台时对话框照旧弹出，正文里“窗口保持离线”换成“现在没有打开的窗口”；“重新启动服务”成功后留在后台；选“稍后”时壳退出，对话框开着时已开出了窗口的照上面的规则、不退出。
22. **非合作结束。** 壳被强行结束、注销、关机时，自有服务端随壳的进程树一起被结束，不保证有序停止：服务端已提交的数据（SQLite 事务、原子写入的文件）保留；还在页面里、没交给服务端的输入可能丢失。下一次启动照常，不提示。
23. **启动中关掉最后一个窗口。** 服务端就绪之前用户关掉最后一个窗口（只有启动页）：这次启动作废，壳不再拉起服务端、不再重试、不再开窗；已经拉起的自有服务端（含还在拉起中的）按输出 18、19 停止并等它真实退出；在等的是别人的实例时不碰它。之后放下桌面锁、退出。

**便携：**

24. **便携版的状态根。** 有便携标记时状态根是程序根目录下的 `data\`（不存在时建出来）。程序根目录不可写（只读介质、没有权限）时，启动页显示实际路径，说明便携版要放在可写的位置，只给“退出”；不改用安装版的状态根。

**桌面专属设置：**

25. **值从哪来。** 内置插件 `nbook.desktop` 声明只在桌面里有意义的配置项（界面缩放、登录 Windows 时打开、关掉最后一个窗口时（输出 28）、窗口背景（输出 32）、在桌面放快捷方式（输出 33，planned）），只允许用户层（[`settings.configuration`](../settings/configuration.md) 输出 22 的暂行），设置窗口里的“桌面窗口”分区只在桌面壳的窗口里列出（[`settings.window`](../settings/settings-window.md) 输出 2）。设置的拥有者是服务端的 `nbook.settings`；页面从配置服务读出有效值，在激活时与值变化时交给壳（直接改设置文件时拥有者推给页面，页面同样交给壳）。壳不读设置文件，只把最后收到的值缓存在 `<状态根>/logs/desktop/settings-cache.json`（按到达顺序串行写，缩放必须是档位之一），下次启动时在页面交来值之前先用缓存；缓存读不了或内容不合法按缺省并记诊断（逐项判断：缺的或不合法的项取缺省，其余照用）。几个窗口交来同样的值时壳只处理一次。
26. **界面缩放。** 缩放应用到所有产品窗口（启动页与对话框不缩放），每次页面就绪时按当前值重设。档位是 50% 到 200% 的一组（50、67、75、80、90、100、110、125、150、175、200）。桌面窗口里 Ctrl 加数字行或小键盘的加、减号放大、缩小，Ctrl+0 复位；Ctrl+滚轮不换界面缩放：它在图片查看器里缩放图片、在 Markdown 与源码编辑器上改编辑器字号（[`workbench.editor`](../workbench/editor.md) 输出 67），这两处自己处理；其余地方按 Ctrl 滚动鼠标什么也不改，只拦下事件，WebView2 自带的页面缩放不叠加（沙箱 iframe 里的 HTML 预览到不了页面，是已知限制）。命令面板里有“放大”“缩小”“重置缩放”（`nbook.view.zoom-in`、`nbook.view.zoom-out`、`nbook.view.zoom-reset`，只在桌面里可用）。快捷键先按物理键位认，认不到再按字符（别的键盘布局），输入法组字时不接管，NumLock 关着时小键盘的 0 不算复位；页面离开前还没写回的档位立刻写。用户层此刻不可用或无效时页面不向壳交值（读到的是缺省值）。改档立即生效，随后写进用户层；复位删掉这个键；写入失败时说明原因并回到配置服务里的值。浏览器里这些都不接管，浏览器自己的缩放照旧。
27. **开机自启。** 打开“登录 Windows 时打开 NeuroBook”时，壳在 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 下以应用标识为值名，登记安装目录里 `launcher.exe` 的命令行；关掉时删掉这一项。只对安装版、并且状态根来自缺省位置的运行生效：便携版、开发构建、设了 `NBOOK_STATE_ROOT` 的运行不登记，也不删已有的登记（那可能是缺省状态根那边开的），开着时在壳的日志里说明。壳在这次运行第一次收到页面交来的值时同步一次，之后随值变化同步；读写注册表失败记诊断，不影响运行；读不出现状时这次不写也不删。

**托盘与后台：**

28. **设置与托盘图标。** `nbook.desktop` 的配置项“关掉最后一个窗口时”（`closeLastWindow`）：“退出 NeuroBook”（`quit`，缺省）或“留在系统托盘（服务继续运行）”（`tray`），说明写明“留在托盘时，注销或关机会由系统结束 NeuroBook，只保证已保存的内容”。壳有自有服务端、设置是 `tray`、不在停止中时在通知区域显示托盘图标（应用图标），否则不显示：缺省设置下看不到它，连的是别人的实例、服务端意外退出后选了“稍后”时也没有。提示文字：有窗口时“NeuroBook”，在后台时“NeuroBook（在后台运行）”，托盘退出正在检查在跑的工作时“NeuroBook（正在检查在跑的工作）”。停止中图标消失；壳退出前先删掉图标，通知区域不留残影。图标建不出来时记诊断，这时按没有托盘处理（输出 29 的最后一行）。
29. **最后一个窗口关掉之后。** 原因按下表定，提交关窗时按这次询问的原因决定停不停（输出 16）：

    | 情形 | 原因 | 关掉之后 |
    |---|---|---|
    | 服务端不是自有的（别人的实例，或意外退出后选了“稍后”） | `window` | 壳退出，不碰服务端 |
    | 应用级退出进行中（输出 31） | `quit` | 停止、退出 |
    | 设置是 `tray`，托盘图标此刻显示着 | `window` | 进入后台 |
    | 其余（设置是 `quit`，或设置是 `tray` 而图标没显示出来） | `quit` | 停止、退出 |

    以 `window` 询问时页面照常问参与方与未保存的正文，不提示在跑的工作（[`runtime.browser-host`](browser-host.md) 输出 10）。窗口都关完的那一刻，不在停止中、不在应用级退出、服务端自有、设置是 `tray` 且图标显示着，才进入后台，否则按输出 18 收尾。启动中关窗（输出 23）没有产品窗口，不进后台。
30. **托盘菜单。** 左键、右键都弹出菜单：“打开 NeuroBook”、分隔线、“退出 NeuroBook”。
    - **打开**：有不在关闭中的产品窗口时，把最近获得焦点的那个还原（最小化的）并置前；没有时开一个新窗口，与开窗转交同一条路、同样的规则（最后一次关闭或应用级退出进行中不开，停止中不响应）。开出窗口即离开后台。
    - **退出**：有窗口时是应用级退出（输出 31）。没有窗口、服务端已意外退出（对话框开着或选过“稍后”）时直接退出。没有窗口时先向自有服务端取一次在跑的工作（[`runtime.server-host`](server-host.md) 的“在跑的工作”，截止 8 秒），这段里再点“退出”不理，点“打开”或开窗转交开出了窗口就作废这次退出：取到没有工作就经应用级退出停止；有工作、有取不到的或整个取不到时弹壳的对话框“NeuroBook 有工作在跑，退出会中断它们”，有工作时写出项数（另有取不到的部分时补一句“另有部分工作无法确认”），整个取不到时写“无法确认是否有工作在跑”，给“取消”（缺省）、“打开 NeuroBook”、“仍然退出”；关掉对话框等于“取消”；对话框开着时开出了窗口就关掉对话框、作废这次退出；对话框开着时再点“退出”把它置前。“仍然退出”经应用级退出停止。
31. **应用级退出与后台时的事件。** 应用级退出进行中，开窗转交回 `closing`、页面请求的新窗口被拒、托盘“打开”不开窗；每个窗口各自询问，最后一个以 `quit` 询问；任何一个询问以 `deny` 或“取消关闭”收口，这次应用级退出就结束；剩下的窗口都已在关闭中时，最后一个关掉就停止；没有窗口时直接进入停止中。后台时：开窗转交照常开窗；系统或框架发来的退出请求直接进入停止中（没有页面可问）；自有服务端意外退出见输出 21；更新只在壳启动时换上（[`runtime.desktop-update`](desktop-update.md)），后台期间的提示等有窗口就绪再交。

32. **窗口背景（实验）。** `nbook.desktop` 的配置项“窗口背景”（`windowBackdrop`）：`off`（缺省）、`mica`（壁纸色调的底，不随背后的窗口变）、`acrylic`（背后的内容模糊着透出来）。只在 Windows 11 22H2（build 22621）以上、窗口有自画外框时生效，别的情形设置照样存着、窗口按普通窗口建，不报错。
    - **建窗口时定。** Electrobun 的 `transparent` 只能在窗口创建时设，所以壳在建每个窗口（产品窗口与启动页窗口，后者之后换成产品页）前按此刻缓存的值定这个窗口要不要透明、要哪一种；改了设置只对之后新开的窗口生效，已开的窗口不变。
    - **窗口怎么变。** 透明窗口建好后壳设 `DwmExtendFrameIntoClientArea(-1)` 与 `DWMWA_SYSTEMBACKDROP_TYPE`（Mica 为 2、Acrylic 为 3），并去掉 `WS_SYSMENU`：不去掉的话，DWM 在非客户区画的系统标题按钮会从透明的页面里透出来、叠在页面自己画的那组按钮后面成为重影。代价是没有系统菜单（Alt+空格，也没有标题栏图标的菜单）：键盘用户改用 Alt+F4 关闭、Win+方向键最小化与还原；标题栏样式与最小化、最大化框留着，圆角、阴影不变。设不成功的项写日志 `desktop.backdrop.failed`，窗口照常可用；背景没设成时不去掉 `WS_SYSMENU`。已知限制：`transparent` 与页面的 `data-window-backdrop` 在建窗口时就定了、之后改不了，背景没设成的窗口页面仍按磨砂画（底透明、面板半透明），只是看不到系统背景；Windows 11 22H2 以上设这两项不会失败，所以不为此另加回退机制。
    - **页面怎么变。** 预加载脚本在 `<html>` 上设 `data-window-backdrop`（值是这个窗口实际的背景），样式据此把窗体底做成透明并罩一层淡淡的主题底色、外层面板半透明、编辑器与内容面板仍不透明（[`runtime.browser-host`](browser-host.md) 的“窗口外框”）；高对比度偏好下样式不生效；“减少透明”偏好下两层罩色盖满，底与面板不透明。页面把当前明暗（文档根的 `data-nb-appearance`）经 `window-appearance` 消息交给壳，壳设 `DWMWA_USE_IMMERSIVE_DARK_MODE`，意图是磨砂的底色与页面主题同向；明暗变了再交。微软的公开合同允许这个属性跟随系统深色，系统与页面明暗相反时实际材质是否同向没有实测（实验功能，已知限制）。样式不生效的情形（高对比度、强制颜色）下，根上仍有不透明的主题底色，不透出系统背景。

**桌面快捷方式与首次启动向导：**

33. **桌面快捷方式。（planned）** `nbook.desktop` 的配置项“在桌面放快捷方式”（`desktopShortcut`，缺省开）。Electrobun 的安装程序，以及每次更新换上之后，都在桌面与开始菜单各建一个快捷方式（稳定频道的文件名是 `NeuroBook.lnk`，指向安装目录里的 `launcher.exe`）。
    - **关着时**，壳确保桌面上没有它：这次运行第一次收到页面交来的值、或值变成关时做一次（第一次收到时把更新换上后又出现的那个删掉；几个窗口交来同样的值不重复做）。只删同名、是快捷方式、目标是本安装 `launcher.exe` 的文件；用户改过目标的、不是快捷方式的不动。
    - **在这次运行里从关改成开时**，桌面上没有就建一个，目标、工作目录与图标同 Electrobun 建的；同名文件已存在就不动。“上一次的值”只算这次运行里收到的，不取缓存：启动时值为开不补建，用户自己删掉的不补。
    - 几次改动按收到的顺序一次做一件，桌面上的结果跟最后一次的值一致；每次在同一条命令里重查文件再删或建。壳进入停止中后不再做新的，在做的那一次至多等 5 秒。
    - 开始菜单里的快捷方式不受影响。只对安装版、并且状态根来自缺省位置的运行生效（安装版的判据见输出 34 的“安装事实”；便携版、开发构建、设了 `NBOOK_STATE_ROOT` 的运行不建也不删），开机自启（输出 27）用同一个判据。桌面目录取系统的“桌面”已知文件夹（可能重定向到 OneDrive）；读写失败、取不到桌面目录都记诊断，不影响运行，这次不写也不删。
    - 已知限制：Electrobun 的更新照样重建桌面快捷方式，会把用户改过目标的同名快捷方式改回本安装（关着时随后被删）；重查与删除、建立之间仍有毫秒级的窗口，其间别的程序换了同名文件不受保护。
34. **首次启动向导。（planned）** 状态根第一次在桌面版里打开时，引导用户定外观与桌面习惯。
    - **何时出现。** 桌面壳的产品窗口里，在页面根上打开（书架与工作台页都挂，[`ui.workbench-shell`](../ui/workbench-shell.md) 输出 41 的浮层），按用户层存储里 `nbook.desktop` 的记录 `first-run`（用户范围、各客户端共用）定：

      | 记录 | 用户层配置 | 结果 |
      |---|---|---|
      | 还没读到、读取失败 | 任意 | 等，不开 |

    - **已知限制**：原生全屏时左上角的 80px 留位仍在；红绿灯的位置与留位的宽度按 macOS 的缺省尺寸估，没有在真机量过；没有签名与公证，第一次打开要在“隐私与安全性”里允许。

| 当前 | 事件 | 结果 |
|---|---|---|
| 启动中（未取锁） | 有可换上的更新 | 更新交接（[`runtime.desktop-update`](desktop-update.md) 输出 8）；交接期间退出不拦 |
| 启动中 | 取到桌面锁 | 问服务端（输出 4） |

| 停止中 | 截止到 | 强制结束进程树，等它真实结束后已停止 |
| 停止中 | 任何退出请求、开窗转交 | 拦下；开窗转交回 `stopping` |

时序与寿命：

- 桌面锁先于问服务端：同一状态根上不会有两个壳各起一个服务端，也不会有两个壳分别拥有同一个服务端的窗口。
- 壳只在认领应答的 `status` 为 `ready` 之后加载页面地址，加载时服务端已能处理请求。
- 关闭前询问的回答只对它的代次有效；窗口关掉之后，这个窗口的待决询问作废。
- 最后一次关闭从开始询问到进入停止中，窗口集合只会变少：开窗转交排队、页面请求的新窗口被拒。应用级退出进行中同样。
- 后台与停止中不重叠：进入停止中时托盘图标先消失；托盘退出的各条路都经应用级退出进入停止中，没有另外的停止入口。
- 写 `stop` 之后壳不再开窗口；服务端真实退出（包括被强制结束之后）才放下桌面锁，所以后启动的壳在锁放下之后问到的是“没有实例”，不会撞上停止中的旧服务端认领。
- 合作退出（输出 18、19、23）都经 `stop` 并等服务端真实退出；非合作结束（输出 22）靠壳的进程树一起结束，不经标准输入，只保证已提交的数据。

## 副作用与数据

- 状态根由服务端读写，格式不变；壳只写 `<状态根>/logs/desktop/` 与桌面锁的套接字文件。
- WebView2 的浏览器数据（按来源的本地存储、缓存）在应用标识的目录下，卸载时选“应用和数据”会一并删除；状态根不在这个目录里，卸载不删作品登记与设置。
- 壳不删除任何用户数据。

## 边界与兼容

- 公开接口：桌面锁的地址与协议（输出 2；跨版本使用，字段只加不改）、便携标记的文件名、应用标识与发布频道（一次性，发出去以后不改）。
- 依赖的合同：服务端的托管合同（[`runtime.server-host`](server-host.md) 的“托管宿主”）、页面一侧的关闭前询问（[`runtime.browser-host`](browser-host.md) 输出 9 到 11）。
- 信任边界：服务端只监听回环；产品窗口只信任当前服务端的精确来源，页面能经壳做的只有输出 13 列出的几件事。
- 与 `nbook` 共用状态根与服务端：桌面壳起的服务端是 `product` 种类的实例，`nbook start` 看到它时按自己的规则报告并在浏览器里打开。

## 验收与 Smoke

用 Windows 上的真实安装包或便携包：

1. **同版本复用。** 壳在运行时再从开始菜单打开：多出一个窗口、置前，后启动的进程以 0 退出，进程列表里只有一个壳。
2. **异版本拒绝。** 旧版本的壳在运行时打开新版本：新版本的启动页说明已在运行的版本，不发开窗请求，旧版本照常。
3. **同时启动。** 两次打开几乎同时发生，服务端超过 3 秒才就绪：只有一个壳、一个服务端，两个窗口先显示“正在启动”，就绪后都是工作台；服务端启动失败时两个窗口都显示失败。
4. **连已有实例。** 先 `nbook start` 起同版本的服务端，再打开桌面版：窗口连它；关掉全部桌面窗口后服务端仍在运行，浏览器里的页面不受影响，关窗不提示任务。版本不同时启动页说明并只给“退出”。
5. **任意顺序关窗。** 三个窗口按任意顺序关掉；两个窗口的关闭前询问重叠（第一个还在问时关第二个）：只有关最后一个时以 `quit` 询问，最后服务端有序停止、以 0 退出。最后一次关闭的询问进行中再打开一次 NeuroBook，新启动的进程显示“正在确认关闭”：用户过了 90 秒才取消关闭，之后多出一个窗口、新进程退出；用户同意关闭，新进程等旧壳退出再自己启动（包括旧壳在两次重试之间就已退出）；`quit` 只问了一次；新进程在等的时候点“退出”，不留下窗口。
6. **编辑中关窗。** 场景见 [`workbench.editor`](../workbench/editor.md) 场景 45、46；另验页面卡死：3 秒后原生对话框，“取消关闭”后窗口还在，“强制关闭”后窗口关掉。
7. **有工作在跑时关最后一个窗口。** 分别有：运行中的 Agent 会话、会话已空闲但它启动的后台命令还在跑、后台会话、后台任务、只有项目子进程里登记的工作；最后一个窗口分别是工作台、书架页、“项目已关闭”页。每种都提示关闭会中断它们，“取消”后一切照旧；“仍然关闭”后服务端有序停止，它们按中断收口。
8. **写入中强行结束。** 打开作品、正在保存时结束壳的进程树：重新打开后已提交的数据完整，服务端认领与桌面锁都能重新取得，没有残留的服务端或项目子进程。
9. **开发服务与桌面版并行。** `bun run dev` 运行时打开桌面版：两者都能用，一方的端口顺延。
10. **便携。** 便携包解压到 A 目录运行、新建作品、关闭，挪到 B 目录再运行：书架上还在，作品要重新打开；`data\` 在程序目录下；安装版的状态根没有被写。放到只读目录运行：启动页说明。
11. **导航与新窗口。** 页面里点外部链接：在系统浏览器打开，窗口不离开工作台；页面以新窗口打开一部作品（带 `project` 参数的同来源地址）：新窗口里是那部作品。
12. **自有服务端意外退出。** 结束服务端进程：对话框出现，“重新启动服务”后页面显示“服务端已重启”，刷新后可用；先占住原来的端口再“重新启动服务”：对话框说明端口被占用，窗口保持离线、未保存的正文仍可复制。
13. **停止超时。** 让服务端在停止时卡住：到截止后进程树被结束，结束之前新打开的 NeuroBook 一直等待、不会连到旧服务端；下一次启动提示“上次退出时服务端没有正常停止”。
14. **启动中关窗。** 分别在等别人的实例、自有服务端拉起中、还没就绪时关掉启动页：壳退出，没有残留的服务端，别人的实例不受影响。
15. **标题栏。** 工作台窗口只有一条标题栏，右端是最小化、最大化、关闭三个按钮：拖动标题栏空白处移动窗口，双击最大化、再双击还原，拖到屏幕边缘贴边；最大化后页面底部不被任务栏盖住；按钮的名字在“最大化”“还原”之间跟着变；点关闭与 Alt+F4 一样经关闭前询问，询问期间还能最小化；Alt+Space 出系统菜单（普通窗口；磨砂窗口没有，见场景 18）。拖动边框缩小窗口，客户区停在 800×560，最大化与还原照常。书架首页与启动页也能拖、能用三个按钮。程序、任务栏与 Alt+Tab 里是应用图标。WebView2 低于 123 时窗口有系统标题栏、页面里没有窗口按钮。
16. **桌面专属设置。** 设置里的“桌面窗口”只在桌面窗口里有，浏览器里没有。界面缩放改成 125%：所有桌面窗口一起变，新开的窗口也是 125%，关掉再开仍是 125%；按 Ctrl+加号、Ctrl+减号、Ctrl+0 各改一档或复位，WebView2 自带的缩放不叠加；在页面空白处与编辑器之外按 Ctrl+滚轮，缩放不变；在图片查看器里按 Ctrl+滚动缩放的是图片，在编辑器上改的是编辑器字号。直接改设置文件，窗口跟着变。安装版打开“登录 Windows 时打开”后 Run 下有以应用标识为名的一项，关掉后没有；设了 `NBOOK_STATE_ROOT` 的运行不登记。

17. **托盘与后台。** 设置改成留在系统托盘：通知区域出现图标（Windows 11 在溢出区里也能找到），左右键都弹菜单，点外面菜单收起。关最后一个窗口（有未保存的正文时先问）：窗口关掉、图标提示“在后台运行”，服务端还在；从托盘“打开”、从开始菜单再打开都多出窗口；最小化的窗口经托盘“打开”还原并置前；后台 30 分钟后再打开照常。后台时从托盘“退出”：没有工作时有序停止、图标消失不留残影；有工作在跑时对话框给出项数，“取消”后照旧、“打开 NeuroBook”开出窗口、“仍然退出”有序停止。有窗口时从托盘“退出”：各窗口经关闭前询问，最后一个以 `quit` 询问。后台时结束服务端进程：对话框说明没有打开的窗口，“稍后”后壳退出。设置改回退出 NeuroBook：图标消失，关最后一个窗口照常退出。开机自启叠加留在托盘：登录后图标出现。

18. **窗口背景（实验）。** 设置里窗口背景选 Acrylic：之后新开的窗口是磨砂的（背后的窗口模糊着透出来），已开的窗口不变；选 Mica 再开一个：壁纸色调的底；选回关再开一个：普通窗口。磨砂窗口里窗口按钮没有重影，标题栏拖动、双击最大化、拖到屏幕边缘贴边、Alt+F4 照常，没有系统菜单；页面切到深色主题后磨砂的底色变深。Windows 10 或 22H2 以下：设置存着、窗口是普通窗口。

19. **首次启动向导与桌面快捷方式（planned）。** 新的状态根第一次打开安装版：书架上出现向导；第二步选暗色与 macOS，界面当场换；第三步关掉“桌面快捷方式”，桌面上的 `NeuroBook.lnk` 消失，开始菜单的还在；走到“开始写作”关掉。关掉再打开：不再出现。用上一个版本的更新换上新版本后：桌面上的快捷方式又被删掉，向导不出现。把开关打开：桌面上出现快捷方式。命令面板里“打开桌面版欢迎向导”能再打开。便携版第一次打开：第三步没有前两行。浏览器里打开同一状态根：不出现。

20. **macOS 预览（真机上跑）。** 在 Apple Silicon 的 macOS 上打开 DMG 里的应用（第一次在“隐私与安全性”里允许）：窗口左上角是红绿灯、垂直在标题栏正中，标题栏里没有最小化、最大化、关闭三个按钮；红绿灯与工作台左端的标志之间有空隙，拖标题栏空白处移动窗口、双击缩放；Cmd+C、Cmd+V、Cmd+A 在编辑器与输入框里照常；Cmd+W 经关闭前询问关窗，Cmd+Q 退出；设置选“留在系统托盘”后关最后一个窗口，Dock 里的图标仍在、点它开回窗口。

## 实现合同

- **公开入口**：壳的流程核心 `DesktopShell`（`packages/neuro-book/src/desktop/shell.ts`），只依赖 `ShellPorts`（窗口、启动页、对话框等端口）与时钟，不依赖 Electrobun；对外的合同只有桌面锁的地址与协议、便携标记、应用标识（见“边界与兼容”），核心里的符号不是包的公开接口。
- **owner 与依赖方向**：owner 是 `desktop-shell`。核心 `src/desktop/` 依赖服务端的实例查询（`src/server/instance.ts`）、`@notnotype/nb-host/server` 的状态根认领、`@notnotype/owned-process` 与 `src/cli/state-root.ts` 的平台缺省；Electrobun 适配层 `packages/neuro-book/desktop/`（主进程、预加载脚本、启动页）依赖核心、实现它的端口、把窗口事件送进来，核心不反向依赖它；页面一侧经 `src/shared/desktop-bridge.ts` 的消息形状与壳通信（[`runtime.browser-host`](browser-host.md) 输出 9、10）。
- **关键不变量**：
  - 桌面锁是状态根上的另一种认领（套接字名 `desktop`），与服务端的认领互不相干；同版本的后来者经 `open-window` 让持有者开窗，版本不同不发请求，锁已放下就回去取锁（`lock.test.ts`、`shell.test.ts`）。
  - 就绪只认认领应答里 `pid` 等于自己目标进程的 `ready`：被 `nbook start` 抢先认领时交回 `taken`、连那个实例，不当作崩溃（`owned-server.test.ts`）。
  - 每个窗口至多一个待决询问，带代次，只认当前代次的回答；3 秒内没有接下才弹“没有响应”，接下之后不限时（`windows.test.ts`）。
  - 最后一次关闭进行中，开窗转交回 `closing`、页面的新窗口被拒；询问期间别的窗口关掉使它成了最后一个时，以 `quit` 重问一次；同意与进入停止中是同一个同步段（`windows.test.ts`、`shell.test.ts`）。
  - 停止的截止按绝对时间分段排，每段不超过 `setTimeout` 的上限，缺省共 90 秒；到时结束整棵进程树，等树真实结束才交回、才放桌面锁（`deadline.test.ts`、`owned-server.test.ts`）。
  - 托盘与后台（输出 28 到 31）：核心的协调器（`windows.ts`）按输出 29 的表定最后一个窗口的原因并决定停不停，应用级退出与后台各条路都经它进入停止中；`tray.ts` 是图标显示与否、提示文字与托盘退出取在跑的工作（8 秒截止）；`shell.ts` 的 `trayOpen`、`trayQuit` 把托盘菜单接到协调器；适配层（`desktop/src/bun/index.ts`）按托盘视图建与删 `Tray`，图标建不出来记 `desktop.tray.create-failed` 并按没有托盘处理，退出前先删图标。壳的退出对话框是 `desktop/src/views/shell/index.html` 的 `quit-work`（`windows.test.ts`、`shell.test.ts`、`tray.test.ts`）。
  - 无标题栏的窗口经 `bun:ffi` 补窗口样式、设窗口图标（`desktop/src/bun/win32.ts`）：调用跑在 Bun 主线程，窗口归 Electrobun 的原生 UI 线程；Electrobun 的窗口回调都是不等返回值的线程安全回调，UI 线程不同步等 Bun，所以从 Bun 同步调窗口函数不成环，仍尽量用不等待的写法（`SWP_ASYNCWINDOWPOS`、`PostMessageW`）。这依赖 Electrobun 2.0.6 对 `hiddenInset` 的处理（`WM_NCCALCSIZE` 去掉标题区、`WM_GETMINMAXINFO` 只管 `WS_POPUP`），升级 Electrobun 时复测。
