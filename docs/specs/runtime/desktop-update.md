# 桌面版的更新

## 目标与非目标

装好的桌面版自己发现新版本、经用户同意后在后台下载，下一次启动时换上；只升不降。便携版不自动更新，只提示有新版本并打开下载页。壳的其余行为见 [`runtime.desktop-shell`](desktop-shell.md)。

不承诺：

- 不降级：远端版本不高于本地时什么都不做；回到旧版本要用户手动重装（状态根与作品数据不随之回滚，旧版本可能读不了新版本写过的数据）。
- 不在关窗或运行中换文件；没有“现在重启并更新”。
- 更新包的真实性只靠 HTTPS 与发布账号的安全：更新清单里的摘要只防传输损坏，不防冒充（不签名）。
- 没有更新频道的选择（只有 `stable`）、没有预发布版本、没有关闭自动检查的设置。
- npm 包 `@notnotype/neuro-book` 的更新不在本 Spec：`nbook` 由用户自己升级。

## 术语与参与者

- **更新源**：本仓库 GitHub Releases 里最新 Release 的下载地址；里面有更新清单（版本、包的摘要）与完整包、增量补丁。
- **远端版本**：更新清单里写的产品版本。版本按语义化版本比较，只比较稳定版本号。
- **已下载的更新**：下载、校验完、等着换上的更新包，放在安装目录之外由更新器管理的位置。
- **换上**：用已下载的更新替换安装目录里的程序文件，然后启动新版本。
- **安装级排他**：换上时没有别的进程在用这份安装目录里的程序。

## 输入与前置条件

- 只对安装版生效：有便携标记（[`runtime.desktop-shell`](desktop-shell.md) 的术语）的是便携版，按输出 10。
- 环境变量 `NBOOK_STATE_ROOT` 指定的状态根不影响更新：更新针对安装目录，不针对状态根。

## 输出与可观察行为

1. **何时检查。** 壳进入运行中（第一个窗口加载了页面）之后在后台检查一次，之后运行期间每 24 小时检查一次。检查失败（网络、更新源不可用、清单不合格式）只写壳的日志，不打扰用户，下一次按时再查。
2. **只升不降。** 远端版本高于本地版本才算有更新；等于或低于时什么都不做，即使包的摘要不同。远端版本缺失或不是稳定版本号时当作检查失败。
3. **提示。** 有更新时，在最近一次获得焦点的产品窗口里显示一条常驻的工作台通知“NeuroBook <远端版本> 可以更新”，带“下载”“以后”（[`workbench.notifications`](../workbench/notifications.md)）。“以后”在这次运行里不再提示同一个版本；更高的版本出现时照常提示。用户还没选时关掉这个窗口，通知移到另一个产品窗口；没有产品窗口时不提示。
4. **下载。** 选“下载”后在后台下载；本地版本有现成的增量补丁时下载补丁，否则下载完整包。下载期间通知显示进度，可以关掉通知，下载照常继续。
5. **目标移动。** 下载或校验失败时重新检查一次：远端已是更高的版本（检查之后又发了新版本）时，按新版本重新提示；仍是同一个版本时说明下载失败，给“重试”。
6. **下载完成。** 下载并校验完以后，通知改为“<远端版本> 已下载，下次打开 NeuroBook 时安装”，没有按钮；这次运行不再检查。
7. **已下载的更新保留。** 已下载的更新保留到换上为止；之后发现更高的版本时，用新版本的更新替换它。
8. **下次启动时换上。** 壳启动后、取桌面锁之前，发现有已下载的更新且版本高于本地：
   - 先确认安装级排他：这份安装目录里的程序没有别的进程在运行（包括另一个状态根上的壳与它的服务端）；
   - 排他成立：启动页显示“正在更新到 <版本>”，换上并启动新版本，这次启动由新版本接着完成，旧进程退出；
   - 排他不成立：这次不换，照常启动旧版本，已下载的更新保留，下一次启动再试；
   - 换上失败：照常启动旧版本，写壳的日志，在第一个产品窗口里通知“更新没有完成”，丢弃这份已下载的更新，之后按输出 1 重新检查。
9. **更新之后。** 新版本第一次启动、进入运行中之后，在第一个产品窗口里通知一次“已更新到 <版本>”。
10. **便携版。** 便携版照常检查（输出 1、2），有更新时通知“NeuroBook <版本> 可以下载”，带“打开下载页”（在系统默认浏览器打开最新 Release 的页面）与“以后”；不下载、不换上。

## 状态与转换

| 当前 | 事件 | 结果 |
|---|---|---|
| 空闲 | 检查到更高的版本 | 提示中 |
| 提示中 | “以后” | 空闲；这次运行不再提示同一版本 |
| 提示中 | “下载” | 下载中 |
| 下载中 | 下载与校验完成 | 已下载；不再检查 |
| 下载中 | 失败，重新检查到更高的版本 | 提示中（新版本） |
| 下载中 | 失败，仍是同一版本 | 提示中（下载失败，“重试”） |
| 已下载 | 下一次启动，排他成立 | 换上，新版本启动 |
| 已下载 | 下一次启动，排他不成立 | 旧版本照常启动，保留更新 |

时序与寿命：

- 换上发生在取桌面锁之前：新版本的壳取锁、问服务端，旧版本不会和新版本同时拥有窗口。
- 换上之前，同一安装目录里的程序没有在运行，所以不会替换正在使用的文件。
- 通知只在产品窗口里出现；启动页上不提示更新，“正在更新”除外。

## 副作用与数据

- 更新只改安装目录与更新器的下载位置，不读写状态根。
- 已下载的更新至多一份；换上后删除。

## 失败与恢复

| 情形 | 呈现 | 恢复 |
|---|---|---|
| 检查失败 | 只写日志 | 下一次按时检查 |
| 下载或校验失败 | 通知说明，给“重试”，或改提示更高的版本 | 重试；下一次启动再查 |
| 换上时安装被占用 | 不换，旧版本照常启动 | 下一次启动再试 |
| 换上失败 | 旧版本启动，通知“更新没有完成” | 重新检查、重新下载 |

## 边界与兼容

- 更新源、应用标识与发布频道是一次性的选择（[`runtime.desktop-shell`](desktop-shell.md) 的“输入与前置条件”），发出去以后不改。
- 信任边界：能改本仓库 GitHub Release 的人能给已装用户推更新；HTTPS 防中途篡改，清单摘要防传输损坏。
- 页面只显示壳交来的提示、把用户的选择交回壳（[`runtime.desktop-shell`](desktop-shell.md) 输出 13），不能让壳下载别的地址。

## 验收与 Smoke

用 Windows 上的真实安装包与本地的更新源（与 GitHub Releases 同样的文件布局）：

1. **升级。** 装 A，更新源放 B：运行中出现提示，“下载”后通知已下载；关掉再打开：启动页“正在更新”，之后是 B，通知“已更新到 B”；状态根与作品不变。
2. **拒绝降级。** 装 B，更新源放 A：不提示、不下载。
3. **目标移动。** 提示 B 之后、下载之前更新源换成 C：下载失败后提示 C；下载的是完整包。
4. **安装被占用。** 已下载 B，另一个状态根（`NBOOK_STATE_ROOT`）上的同一份安装还在运行时再打开：不换，旧版本启动；都关掉后再打开：换上。
5. **便携。** 便携版发现 B：通知带“打开下载页”，不下载。

Smoke：发布流水线的 Windows 作业用上一版本的安装包与本次构建出的更新文件跑场景 1、2。
