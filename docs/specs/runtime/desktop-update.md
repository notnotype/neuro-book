# 桌面版的更新

## 目标与非目标

装好的桌面版自己发现新版本、经用户同意后在后台下载，下一次启动时换上；只升不降。便携版不自动更新，只提示有新版本并打开下载页。壳的其余行为见 [`runtime.desktop-shell`](desktop-shell.md)。

不承诺：

- 不降级：远端版本不高于本地时什么都不做；回到旧版本要用户手动重装（状态根与作品数据不随之回滚，旧版本可能读不了新版本写过的数据）。
- 不在关窗或运行中换文件；没有“现在重启并更新”。
- 更新包的真实性只靠 HTTPS 与发布账号的安全：更新清单里的摘要只防传输损坏，不防冒充（不签名）。
- 没有更新频道的选择（只有 `stable`）、没有预发布版本、没有关闭自动检查的设置。
- npm 包 `@notnotype/neuro-book` 的更新不在本 Spec：`nbook` 由用户自己升级。

## 术语与参与者

- **更新源**：本仓库 GitHub Releases 里最新 Release 的下载地址；里面有更新清单（版本、包的摘要）与完整包、增量补丁。
- **远端版本**：更新清单里写的产品版本。版本按语义化版本比较，只比较稳定版本号。
- **已下载的更新**：下载、校验完、等着换上的更新包，放在安装目录之外由更新器管理的位置；至多一份。
- **换上**：用已下载的更新替换安装目录里的程序文件，然后启动新版本。
- **安装的使用与换上**：运行这份安装里程序的壳（连同它的服务端）在整个运行期间都算在用这份安装。壳只在没有别的壳在用时才发起换上。真正替换程序文件的是更新器的换上程序：它在发起换上的壳退出之后替换整个程序目录、启动新版本，失败时把程序目录还原、重新启动旧版本。从壳退出到新版本起来的这段时间里，如果又有人打开了旧程序，正在运行的程序文件换不掉，这次换上失败并还原（输出 8），不会留下新旧混杂的程序文件。

## 输入与前置条件

- 只对安装版生效：有便携标记（[`runtime.desktop-shell`](desktop-shell.md) 的术语）的是便携版，按输出 10。
- 更新针对安装目录，不针对状态根。设了环境变量 `NBOOK_STATE_ROOT` 的启动不自动下载、不换上，按输出 10 只提示（换上之后由新版本接着启动，新版本拿不到这次启动的环境）。

## 输出与可观察行为

1. **何时检查。** 壳进入运行中（第一个窗口加载了页面）之后在后台检查一次，之后运行期间每 24 小时检查一次。检查失败（网络、更新源不可用、清单不合格式）只写壳的日志，不打扰用户，下一次按时再查。
2. **只升不降。** 远端版本高于本地版本才算有更新；等于或低于时什么都不做，即使包的摘要不同。远端版本缺失或不是稳定版本号时当作检查失败。
3. **提示。** 有更新时，在最近一次获得焦点的产品窗口里发一条常驻的工作台通知“NeuroBook <远端版本> 可以更新”，唯一的动作是“下载”（[`workbench.notifications`](../workbench/notifications.md)）；用户点关闭（通知的 `onClose`，同上输出 18）就是“以后”：页面把它交回壳，这次运行里不再重发同一个版本的提示，更高的版本出现时照常提示；这个窗口通知中心里留下的“下载”照样能点。用户还没选时这个窗口关掉或刷新，壳把通知重新发到最近获得焦点的产品窗口（刷新的页面就绪后也算）；没有产品窗口时等有了再发。
4. **下载。** 选“下载”后在后台下载；本地版本有现成的增量补丁时下载补丁，否则下载完整包。下载期间另发一条“正在下载”的通知（更新器不报下载的百分比，进度条是不确定的），可以关掉，下载照常继续；窗口关掉或刷新时，进度通知按输出 3 的规则重新发。
5. **目标移动。** 下载或校验失败时重新检查一次：远端已是更高的版本（检查之后又发了新版本）时，按新版本重新提示；仍是同一个版本时发一条“更新没有下载成功”的通知，动作是“重试”。
6. **下载完成。** 下载并校验完以后，进度通知改为“<远端版本> 已下载，下次打开 NeuroBook 时安装”，没有动作。之后的检查只在远端版本高于已下载的版本时才提示。
7. **已下载的更新至多一份。** 已下载的更新保留到换上为止。之后发现更高的版本、用户选“下载”时，旧的那份从此不再换上（更新器开始准备新的时把它删掉；准备开始之前就失败的，旧的文件可能还在，但不会再被换上）；新的下载失败时这次运行没有可换上的更新，下一次检查再来。远端版本不高于已下载的版本时不替换。
8. **下次启动时换上。** 壳启动后、取桌面锁之前，发现有已下载的更新、版本高于本地、这次启动不是只提示的启动（输出 10）：
   - 先取得这份安装的独占（术语“安装的使用与换上”）：有别的壳在用这份安装（包括另一个状态根上的壳）时取不到，这次不换，照常启动旧版本，已下载的更新保留，下一次启动再试；取到之后再核对一次已下载的更新（别的壳可能刚换过）；
   - 取到了：启动页显示“正在更新到 <版本>”，交给更新器换上，旧进程退出，由更新器启动新版本接着完成这次启动；这期间壳的退出不被拦下（[`runtime.desktop-shell`](desktop-shell.md) 的“状态与转换”）；
   - 换上进行中又打开 NeuroBook：旧程序照常启动，这次换上因此失败并还原（下一条）；
   - 换上失败（发起不了、换不了文件、新版本起不来）：旧版本照常启动（更新器还原后重新启动它，或者壳发起不成时自己接着启动），写壳的日志，在第一个产品窗口里通知一次“更新没有完成”；这份已下载的更新不再自动换上，之后按输出 1 重新检查，检查到同一个或更高的版本时照常提示，用户选“下载”后下一次启动再换。
   - 新版本起来以后崩溃不算换上失败：更新器只确认新版本已经启动，不确认它运行正常。
9. **更新之后。** 新版本第一次启动、进入运行中之后，在第一个产品窗口里通知一次“已更新到 <版本>”。
10. **只提示的启动。** 便携版、设了 `NBOOK_STATE_ROOT` 的启动照常检查（输出 1、2），有更新时通知“NeuroBook <版本> 可以下载”，动作是“打开下载页”（在系统默认浏览器打开最新 Release 的页面），关掉就是“以后”；不下载、不换上。设了 `NBOOK_STATE_ROOT` 时通知另说明“不设这个环境变量打开 NeuroBook 时可以自动更新”。

## 状态与转换

| 当前 | 事件 | 结果 |
|---|---|---|
| 空闲 | 检查到更高的版本 | 提示中 |
| 提示中 | 关掉通知（“以后”） | 空闲；这次运行不再提示同一版本 |
| 提示中 | “下载” | 下载中 |
| 下载中 | 下载与校验完成 | 已下载；之后的检查只在远端高于已下载的版本时提示 |
| 下载中 | 失败，重新检查到更高的版本 | 提示中（新版本） |
| 下载中 | 失败，仍是同一版本 | 提示中（下载失败，“重试”） |
| 已下载 | 检查到比已下载更高的版本 | 提示中（新版本）；选“下载”时丢弃旧的 |
| 已下载 | 下一次启动，取到独占 | 换上，新版本启动 |
| 已下载 | 下一次启动，有人在用 | 旧版本照常启动，保留更新 |
| 已下载 | 下一次启动是只提示的启动 | 旧版本照常启动，保留更新，不换上 |

时序与寿命：

- 换上发生在取桌面锁之前：新版本的壳取锁、问服务端，旧版本不会和新版本同时拥有窗口。
- 在用与发起换上互斥：发起换上时没有别的壳在用这份安装。壳退出之后、新版本起来之前新打开的旧程序，靠操作系统的文件占用让这次换上失败、还原，不会替换正在使用的文件。
- 通知只在产品窗口里出现；启动页上不提示更新，“正在更新”除外。

## 副作用与数据

- 更新只改安装目录与更新器的下载位置，不读写状态根。
- 已下载的更新至多一份；换上后删除，下载更高的版本前先删旧的（输出 7）。

## 失败与恢复

| 情形 | 呈现 | 恢复 |
|---|---|---|
| 检查失败 | 只写日志 | 下一次按时检查 |
| 下载或校验失败 | 通知说明，给“重试”，或改提示更高的版本 | 重试；下一次启动再查 |
| 换上时安装被占用 | 不换，旧版本照常启动 | 下一次启动再试 |
| 换上进行中再打开 | 旧程序启动，这次换上失败并还原，通知“更新没有完成” | 重新检查、再选下载，下一次启动再换 |
| 换上失败 | 旧版本启动，通知“更新没有完成” | 重新检查、重新下载 |

## 边界与兼容

- 更新源、应用标识与发布频道是一次性的选择（[`runtime.desktop-shell`](desktop-shell.md) 的“输入与前置条件”），发出去以后不改。
- 信任边界：能改本仓库 GitHub Release 的人能给已装用户推更新；HTTPS 防中途篡改，清单摘要防传输损坏。
- 页面只显示壳交来的提示、把用户的选择交回壳（[`runtime.desktop-shell`](desktop-shell.md) 输出 13），不能让壳下载别的地址。

## 验收与 Smoke

用 Windows 上的真实安装包与本地的更新源（与 GitHub Releases 同样的文件布局）。A、B、C 是同一条发布链构建出的、只差版本号的包（首个桌面版本之前就能构建，不依赖已发布的版本）：

1. **升级。** 装 A，更新源放 B：运行中出现提示，“下载”后通知已下载；关掉再打开：启动页“正在更新”，之后是 B，通知“已更新到 B”；状态根与作品不变，没有在安装目录或缺省位置之外建出新的状态根。
2. **拒绝降级。** 装 B，更新源放 A：不提示、不下载。已下载 C 之后更新源换成 B：不提示，C 照常在下次启动时换上。
3. **目标移动。** 提示 B 之后、下载之前更新源换成 C：下载失败后提示 C；下载的是完整包。
4. **安装被占用。** 已下载 B，另一个状态根（`NBOOK_STATE_ROOT`）上的同一份安装还在运行时，不设环境变量再打开：不换，旧版本启动；都关掉后再打开：换上。换上进行中再打开一次：要么新版本已经起来（这次打开转交给它），要么这次换上失败、还原，旧版本运行并通知“更新没有完成”；安装目录里没有新旧混杂的程序文件。
5. **便携。** 便携版发现 B：通知带“打开下载页”，不下载。
6. **设了状态根。** 已下载 B，设了相对路径的 `NBOOK_STATE_ROOT` 打开：不换，旧版本用这个状态根启动；更新源放 C 时只提示“可以下载”，不下载。
7. **“以后”。** 提示 B 后用户点关闭：刷新页面、换到另一个窗口都不再弹出 B 的提示；通知中心里点“下载”照样开始下载。

Smoke：发布流水线的 Windows 作业用本次构建的包与同一链路构建的、版本号更高的测试包跑场景 1、2；有了上一个正式的桌面版本以后，另用它到本次版本跑一遍场景 1。
