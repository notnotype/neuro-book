# 插件安装、卸载、兼容、安全模式与热升级

## 目标与非目标

用户从本地文件夹安装第三方插件，不修改 NeuroBook 源码、不重新构建；安装、卸载与升级都即时生效，不需要重启。不兼容或损坏的插件不影响其它插件；插件拖垮启动时可以用安全模式恢复。

明确不承诺：

- 不做插件市场、在线分发、签名与权限沙箱；第一版完全信任。
- 内置插件不可安装、卸载或单独升级，它们随 NeuroBook 升级（NeuroBook 升级需要重启）。
- 不回滚插件自己迁移过的数据。
- 不支持多个用户各自安装插件：服务端部署时插件集合对整个实例生效。

## 术语与参与者

- **安装目录**：`<State Root>/plugins/<插件 id>/<版本>/`，一个版本一个目录。
- **插件登记表**：`<State Root>/plugins/plugins.json`，记录每个已安装第三方插件的 id、当前版本与用户状态（已启用、已禁用或卸载中），以及被用户禁用的内置插件。未出现在表中的第三方插件为“未安装”；内置插件缺省为已启用，NeuroBook 升级后保留用户对内置插件的禁用。
- **插件管理接口**：内置插件 `nbook.plugins` 经插件通道提供的合同端点：列表、影响预览、安装、启用、禁用、卸载。
- **插件所有者**：启用认证时为 `admin` 角色的用户；未启用认证时（本机单用户）为本机访问者。
- **安全模式**：本次启动不加载任何第三方插件代码的启动方式。
- **热升级**：已安装插件换到另一版本，不重启。

## 输入与前置条件

- 列表对已登录用户可见；安装、启用、禁用、卸载与升级只允许插件所有者执行，其它用户得到 403。操作对整个实例生效。
- **安装的输入**是服务端可读的一个本地文件夹路径，文件夹根目录有插件清单 `package.json`。Desktop 由本机文件选择器取得路径；服务端部署时路径位于服务器上。
- 复制范围：清单有 npm 的 `files` 字段时按它复制（总是包含 `package.json`）；没有时复制整个文件夹，但排除 `node_modules` 与 `.git`。复制后必须包含全部入口文件。
- 路径边界：`files` 中的项必须是相对路径且不越出源文件夹；复制范围内出现符号链接时安装被拒绝；源文件夹不得位于 `<State Root>/plugins/` 之内。
- 插件 id 已安装、版本不同时，安装请求按热升级处理；版本相同时拒绝（“已安装相同版本”），开发者需要提高版本号，或先卸载再安装。
- 安全模式由环境变量 `NEURO_BOOK_SAFE_MODE=1` 开启；Manager 与 Desktop 提供“以安全模式启动”的入口，最终以该环境变量启动产品进程。

## 输出与可观察行为

1. **列表。** 返回全部内置与第三方插件：id、版本、来源、用户状态、汇总运行状态与原因（见 [`runtime.plugin-manifest`](plugin-manifest.md)），以及不兼容、清单无效、安全模式未加载等不登记原因。
2. **安装。**
   1. 校验清单（[`runtime.plugin-manifest`](plugin-manifest.md) 的全部规则）与 `engines.neurobook`；第三方 id 以 `nbook.` 开头时拒绝。
   2. 安装确认界面必须说明完全信任的后果：插件可以访问全部作品、服务器与本机资源。
   3. 用户确认后复制（不链接）到安装目录，写入插件登记表为已启用，立即登记并按激活事件激活，声明层在服务端与所有窗口出现。
3. **卸载**（只限第三方插件）。先给出影响预览（与禁用相同，见 [`runtime.plugin-hot-plug`](plugin-hot-plug.md)），确认界面让用户选择是否同时删除插件的私有存储、配置与密钥（默认保留）。确认后按禁用流程停止，从插件登记表移除，删除安装目录；按选择删除私有数据。依赖它的入口以 `missing-service` 受阻。
4. **启用与禁用**：见 [`runtime.plugin-hot-plug`](plugin-hot-plug.md)；启动必需的内置插件不能禁用，其它内置插件可以禁用。
5. **热升级。**
   1. **准备：** 新版本复制到自己的版本目录，与旧版本并存；校验清单与 `engines.neurobook`。依赖它的插件如果在 `pluginVersions` 中声明的范围不接受新版本，列出这些插件，由用户确认升级后它们受阻。版本低于已安装版本时，确认界面另外提示降级可能遇到新版本已迁移过的数据。
   2. **切换：** 旧版本按禁用执行三步停止，依赖它的入口先停；登记新版本。旧版本的入口原先已激活的，新版本的对应入口立即激活，否则只登记；依赖者重新激活，取得新版本的导出 API。确认界面提示依赖者会短暂停止、在途调用会被中断。
   3. **两端同步：** 服务端经插件集合变化事件通知所有窗口；窗口停止旧的浏览器入口、注销旧代码、加载新版本，页面不刷新。切换瞬间的在途通道请求由版本校验兜住（[`runtime.plugin-channel`](plugin-channel.md)）。
   4. **成功判定与失败回滚：** 升级只在服务端判定。成功的条件是：新版本登记成功；旧版本中已激活、且新版本中仍有同一入口 id 的服务端入口全部激活成功；新版本声明 `onStartup` 的服务端入口全部激活成功。任一条件不满足时自动切回旧版本并报告原因。
      - 新版本删除了旧版本的某个入口是允许的，依赖该入口所提供服务的入口随之受阻，这在影响预览中列出。
      - 浏览器入口在某个窗口中加载或激活失败，不触发回滚，按窗口失败呈现；只有浏览器入口的插件在登记成功时即判定升级成功。离线窗口不参与判定，重连后对齐。
      - 升级不是跨运行位置的原子操作。
   5. **数据：** 私有存储、配置与密钥跨版本保留。数据格式的迁移由插件自己完成；激活时 SDK 提供上一次成功激活的版本号（首次安装为空）。回滚后旧版本可能读到新版本迁移过的数据，内核不回滚数据。
   6. **回收旧代码：** 按 [`runtime.plugin-code-loading`](plugin-code-loading.md) 尽力回收旧版本代码。
6. **不兼容与无效插件。** 不登记，原因可在列表中查询；其它插件与内置插件照常。NeuroBook 升级后变得不兼容的已安装插件在启动时不登记，用户状态保持不变，重新兼容后自动恢复。
7. **安全模式。** 第三方插件的代码与声明都不加载，在列表中显示为“安全模式未加载”；用户可以在安全模式下禁用或卸载它们（写入插件登记表并删除目录），但不能激活。界面持续显示“安全模式”标识。内置插件照常运行。

## 状态与转换

| 当前用户状态 | 事件 | 下一状态 | 说明 |
|---|---|---|---|
| 未安装 | 安装成功 | 已启用 | 登记并按激活事件激活 |
| 未安装 | 安装相同 id 与版本 | 不变 | 拒绝 |
| 未安装 | 安装校验失败或用户取消 | 未安装 | 不留下任何文件或登记表记录 |
| 已启用、已禁用 | 卸载 | 未安装 | 已启用时先停止 |
| 已启用、已禁用 | 热升级成功 | 保持原用户状态，版本更新 | 已禁用的插件只替换文件与登记，不激活 |
| 已启用 | 热升级失败 | 已启用，旧版本 | 自动回滚 |
| 任意 | 启动时不兼容或清单无效 | 用户状态不变，不登记 | 原因可查询 |

- 同一插件的安装、升级、卸载、启停请求串行执行；执行中收到的同一插件的新请求等待前一个完成。
- 插件登记表的写入是原子的（写临时文件后替换）。每个操作有一个提交点，重启后以登记表为准：

| 操作 | 提交点 | 提交前中断，重启后 | 提交后中断，重启后 |
|---|---|---|---|
| 安装 | 复制与校验完成后写入登记表 | 未安装；残留目录删除 | 已安装并按用户状态登记 |
| 升级 | 服务端判定成功后，登记表改指新版本 | 旧版本；新版本目录作为残留删除 | 新版本；旧版本目录作为残留删除 |
| 卸载 | 登记表把插件标为卸载中，并记下是否删除私有数据 | 保持原状态 | 不加载该插件，继续删除安装目录与（按记录）私有数据，最后移除记录 |

## 副作用与数据

- 写入 `<State Root>/plugins/<插件 id>/<版本>/` 与 `<State Root>/plugins/plugins.json`。
- 插件的私有存储、配置与密钥的位置与格式归 [`runtime.plugin-api`](plugin-api.md)；卸载时按用户选择删除。
- 插件写入作品的内容属于用户数据，任何操作都不删除。
- 安装、卸载、升级、回滚各写一条诊断记录（插件 id、版本、结果、原因）。

## 失败与恢复

- **复制中途失败**（磁盘满、权限、源文件被移除）：删除已复制的部分，不写登记表，报告原因。
- **登记表写入失败**：本次操作失败，已复制的目录删除，运行状态回到操作前。
- **进程在安装、升级或卸载中途崩溃**：按上表的提交点恢复；登记表中没有记录的版本目录视为残留并删除；登记表指向的版本目录缺失或清单无效时，该插件以“清单无效”不登记，用户可以卸载。
- **升级失败回滚后**：报告失败原因与已回滚；新版本目录删除。
- **安全模式外的启动被第三方插件拖垮**：用户以安全模式启动后禁用或卸载该插件；反复卡死时的自动进入见 [`runtime.stall-watchdog`](stall-watchdog.md)。

## 边界与兼容

- **owner**：runtime（加载器与安装）。清单规则归 `runtime.plugin-manifest`，启停流程归 `runtime.plugin-hot-plug`，代码装载归 `runtime.plugin-code-loading`。
- **信任与授权**：安装即授予插件完全信任；安装确认界面是唯一的告知点，不可跳过。服务端部署时只有插件所有者（部署者的 `admin` 身份）能安装与管理插件。
- **路径**：安装只接受服务端本地路径，不接受 URL，不从网络下载。
- **兼容**：`<State Root>/plugins/` 的目录布局与 `plugins.json` 是持久格式，变化时需要迁移说明。第三方 id 不得以 `nbook.` 开头，保证内置插件的命名空间。
- **迁移**：现有 State Root 没有 `plugins/` 目录，首次需要时创建；不影响现有用户数据。

## 验收与 Smoke

1. **从本地文件夹安装。** Given 一个位于产品源码之外、已构建的示例插件文件夹；When 安装并确认；Then 不重启即出现其命令菜单、视图、Agent 工具与设置项；`<State Root>/plugins/<id>/<版本>/` 中没有 `node_modules`。
2. **拒绝不合格插件。** 清单无效、`engines.neurobook` 不兼容、id 以 `nbook.` 开头的文件夹安装失败，原因可见，不留下目录与登记表记录。
3. **卸载。** 卸载后插件的全部声明消失，安装目录被删除；选择保留数据时私有存储仍在，重新安装后插件读到原数据。
4. **热升级成功。** Given 0.1.0 正在运行且其视图在两个窗口中打开；When 安装 0.2.0；Then 两个窗口不刷新即切到 0.2.0，SDK 提供的上一版本号为 0.1.0，旧版本目录被删除。
5. **热升级回滚。** 新版本的服务端入口激活时抛错：自动回到旧版本并报告原因，旧版本功能照常，新版本目录被删除。
6. **依赖者版本范围。** 插件 C 的 `pluginVersions` 要求 B `^1.0.0`，升级 B 到 2.0.0 时确认界面列出 C 将受阻，确认后 C 以 `version-mismatch` 受阻。
7. **启动时不兼容。** 把已安装插件的 `engines.neurobook` 改为不兼容后重启：插件不登记、列表显示不兼容，用户状态不变，其它插件正常。
8. **安全模式。** 以 `NEURO_BOOK_SAFE_MODE=1` 启动：第三方插件代码不执行、声明不出现，列表显示“安全模式未加载”，可以卸载；内置插件正常。
9. **崩溃恢复。** 在复制新版本期间结束进程：重启后残留目录被删除，插件保持旧版本；在卸载中（已标记删除私有数据）结束进程：重启后插件不加载，安装目录与私有数据被删除。
10. **授权与路径。** `user` 角色的用户安装插件得到 403；源文件夹含指向外部的符号链接时安装被拒绝；安装已安装的相同版本被拒绝。
11. **内置插件禁用持久。** 禁用 `nbook.api-docs` 后重启，它仍为已禁用。

Smoke：阶段 3 的示例外部插件完成场景 1、3、4、5、8，在真实服务端与 Chromium 上运行，使用临时 State Root（[测试与临时根合同](../../testing/README.md)）。
