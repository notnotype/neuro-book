# 插件代码的装载与回收

## 目标与非目标

在服务端与浏览器两个运行位置装载第三方插件的预构建代码，不重新构建 NeuroBook；插件的浏览器代码与宿主共享同一份 Vue、nb-ui 与 SDK；入口停止后尽力回收插件代码与内存（热插拔 L2）。

明确不承诺：

- 不保证代码一定被回收：回收依赖运行时行为，失效时退回“旧代码保留到重启”，热插拔 L1 的承诺不受影响。
- 不在 State Root 中解析 `node_modules`，不在运行期编译 TypeScript、Vue SFC 或 JSX。例外：用户自己写的 Agent Profile 在运行期打包（[`agent/contributions.md`](../agent/contributions.md) 输出 9），外部导入的检查与本 Spec 相同。
- 内置插件的代码随产品构建静态进入镜像，不经本能力装载。
- 第一版不隔离第三方界面（不使用 iframe）；以后引入隔离时公开 API 不变。

## 术语与参与者

- **服务端入口代码**：SDK 构建预设生成的单文件 ESM，只导出 `activate`（入口的声明以清单为准）；依赖打进文件，SDK、`@vue/reactivity`、TypeBox 与 Node、Bun 的内置模块留作外部引用，由宿主以运行期模块提供同一份。
- **浏览器入口代码**：构建预设生成的登记工厂：CommonJS 模块体包在工厂函数 `factory(module, exports, require)` 里，脚本执行时调用宿主的登记函数交出工厂；入口每次激活，宿主调用一次工厂，得到一份新的模块实例。工厂同步执行，浏览器入口的代码不能用顶层 await（构建失败并说明原因，放进 `activate`）；工厂函数体是严格模式（与作者写的 ES 模块、服务端产物一致）；`import.meta.url` 是这个脚本的 URL；产物压缩，带 source map（源文件路径相对作者目录）。插件自己的动态导入内联进同一个文件，共享模块的动态导入与静态导入一样经工厂的 `require` 取。
- **宿主模块表**：两端宿主给插件代码的共享模块。浏览器在第一次装载第三方入口时建立并冻结（没有第三方浏览器入口的窗口不取它；取不到时下一次激活重新取），含 `vue`、`@vue/reactivity`、`typebox`、`typebox/value`、`typebox/compile`、SDK 的全部子路径（`@notnotype/nb-plugin-sdk` 与 `/text`、`/text/browser`、`/state`、`/storage`、`/settings`、`/settings/browser`、`/commands`、`/workbench`、`/components`；组件与 `/text/browser` 的 `useText` 是宿主自己用的那一份 nb-ui，`useText` 注入的键因此与窗口根上提供翻译端口的是同一个值）；服务端与项目实例含 `@vue/reactivity`、TypeBox 的这三个说明符与 SDK 里服务端能用的子路径（根入口与 `/text`、`/state`、`/storage`、`/settings`、`/commands`、`/agent`、`/agent/jsx-runtime`；后端不加载界面框架）。服务端入口导入了只给浏览器的子路径时，“未共享”的报错附上原因。TypeBox 的其它子路径不共享。SDK 的子路径在模块表里各占一项，名单与 SDK 的子路径表一致。Vue 与 `@vue/reactivity` 必须是宿主那一份：两份响应式系统互相看不见，`computed` 不更新、`watch` 不触发，也不报错。
- **纯度检查**：构建预设按打包器的模块图检查两端的产物：打进了宿主那一份 Vue（`vue`、`@vue/reactivity`、`@vue/runtime-core`、`@vue/runtime-dom`）、nb-ui、SDK、内核或 TypeBox 的实现，或者外部引用（静态与动态导入）不在本位置的宿主模块表里（“未共享”），构建失败。其它无状态的 `@vue/*` 工具包（`@vue/shared`、`@vue/devtools-api`）照常打进插件。
- **位置核对**：插件描述的 `locations` 与实际导出了插件定义的入口位置要一致：有入口的位置没写进 `locations`，或写了却没有那个位置的入口，构建失败并说明改哪里。只在没有别的构建问题时核对（入口模块读不出来时不另报一条误导的位置问题）。
- **插件样式**：清单的 `style` 指向一份样式表。构建预设把各入口的样式合并后包进 `@layer components`（与宿主组件样式同层，宿主的原子类仍能覆盖插件组件），并为插件用到的 Lucide 图标类（`i-lucide-<名字>`）生成规则：宿主只为自己源码里出现过的类名生成规则，插件不能依赖宿主的原子类。扫描清单本身（声明里的图标）与各位置入口模块图里的源码（含打进来的依赖）；别的图标集的类名给构建警告，拼接出来的类名找不到。
- **插件文件端点**：`GET <挂载前缀>/plugins/<插件 id>/files/<内容摘要>/<相对路径>`，提供插件的浏览器代码、样式与静态资源。挂载前缀由平台档案给出（[`runtime.plugin-manifest`](plugin-manifest.md) 的术语），NeuroBook 是 `/api/runtime`。内容摘要是本次启动时算出的版本目录全部文件的摘要。
- **消息目录端点**：`GET <挂载前缀>/plugins/<插件 id>/catalogs/<内容摘要>/<语言>.json`，提供插件清单 `l10n.locales` 列出的消息目录（[`runtime.plugin-manifest`](plugin-manifest.md) 输出 12）。内容摘要与插件文件端点的相同。

## 输入与前置条件

- 入口激活前，其代码文件已按 [`runtime.plugin-install`](plugin-install.md) 位于安装目录；清单已按 [`runtime.plugin-manifest`](plugin-manifest.md) 登记。
- 浏览器入口的代码经插件文件端点加载，端点要求已登录。
- 插件 SDK 声明插件编译所用 Vue 的版本范围，与共享的 nb-ui 入口一起纳入 `engines.neurobook` 的兼容范围。

## 输出与可观察行为

1. **服务端装载。** 入口激活时从安装目录装载其 `main`：先删除模块缓存里这个插件的条目（按版本目录的真实路径，状态根经过符号链接时同样有效），再按固定路径装载。同一插件的几个入口不共享模块实例（构建预设把每个入口打成一个文件，浏览器同样每个入口一个工厂），入口之间共享状态经服务。入口模块上一次求值失败（顶层抛错）时，重试强制重新求值；入口导入的其它模块求值失败后要重启服务端才会重新执行。同一代次内只装载一次；入口停止后再次激活（重新启用、失败后重试、热升级回滚）总是执行一份新的模块实例，模块顶层状态不跨代次共享，即使旧代码尚未被回收。装载不改宿主模块的实例。
2. **浏览器装载。** 窗口中入口首次激活时，同一文件只插入一次同源 `<script src>`（文件来自插件文件端点），脚本执行时登记工厂；入口每次激活调用一次工厂，经宿主提供的 `require` 从宿主模块表取共享模块，所以重试与依赖恢复后的再激活同样是新的模块实例，与服务端一致。只缓存登记成功的工厂，失败后重试重新取回。入口在取回期间停止时，这次激活立刻以停止的原因结束，不等脚本或超时；同一文件再没有激活在等时撤下脚本，之后迟到的登记被忽略。不改写 `index.html`、不使用 import map、不需要 `unsafe-eval`，开发与生产构建路径相同。插件有样式时，窗口登记这个插件就加入它的样式表，不等入口激活：清单里的声明（例如设置分区的图标）在激活前就要显示。
3. **共享同一份 Vue。** 插件组件的响应式更新、宿主提供的 i18n 与主题（`inject`）、nb-ui 浮层与宿主组件表现一致。
4. **表外模块。** 插件 `require` 宿主模块表之外的模块时，在求值时得到结构化错误 `module-not-shared`，入口激活失败，其它插件不受影响。服务端在装载插件目录下的每个脚本时检查它的导入：裸说明符不是共享模块、也不是 Node 与 Bun 的内置模块时同样以 `module-not-shared` 失败，即使安装目录的上级有一份同名的包；相对导入的文件不存在为 `code-load-failed`。
5. **纯度检查。** 构建插件时，服务端与浏览器的产物中打包了宿主那一份 Vue、nb-ui、SDK 或内核则构建失败，并指出被打包的模块（直接导入了 nb-ui 时提示改用 `@notnotype/nb-plugin-sdk/components`）；外部引用（含动态导入）不在本位置的宿主模块表里时同样失败，写明“该入口未共享”和引入它的模块。插件自带一份 Vue 时界面会静默失效，所以在构建与装载时都拦截。远程合同与贡献点的 schema 不是纯 JSON Schema 时构建失败（[`runtime.plugin-manifest`](plugin-manifest.md) 的输入表）。
6. **回收。** 回收的范围跟随入口，不牵连同一插件仍在运行的入口：
   - 一个入口停止时，只撤回该入口拥有的资源（视图、worker 调用、订阅、定时器）；
   - 一个插件在服务端的全部入口都停止后，服务端不再持有该插件的任何模块；
   - 一个窗口中该插件的全部浏览器入口都停止后，该窗口依次注销其模块表项、移除其样式；
   - 引用撤回完成后，插件代码与闭包可被垃圾回收。
7. **开发模式验证。** 开发模式可以验证 L2：反复启用、禁用与升级同一插件 40 次，堆内存不随次数增长；卸载后的弱引用检查在若干轮 GC 后确认回收（浏览器端等 Vue 开发构建缓冲的前 3 秒组件事件清空后再检查）。
8. **插件文件端点。** 只返回本次启动集合里已登记的插件当前版本目录（`<State Root>/plugins/<插件 id>/<版本>/`）内的普通文件，按扩展名给出内容类型；已登录才可访问（planned：认证实现之前，服务端只监听回环地址并核对 `Host`）。路径按原始路径的 `/` 切段、逐段解码，解码后的段含 `/`、`\`、NUL，或等于 `.`、`..`、空串时返回 400；逐段核对不跟随符号链接。插件未登记、摘要不是当前摘要或文件不存在时返回 404。响应带 `Cross-Origin-Resource-Policy: same-origin` 与 `X-Content-Type-Options: nosniff`，别的网页不能用 `<script>` 跨源探测装了哪些插件。
9. **错误边界。** 插件视图在 workbench 的组件树内渲染，外包错误边界：渲染、生命周期与组件事件处理中的错误只影响该视图，视图原位显示错误，其它视图与插件照常。生产构建另存组件名与错误信息供诊断（Vue 生产构建只给出错误参考链接）。不在 Vue 调用路径上的错误由 SDK 的作用域定时器与异步包装捕获（[`runtime.plugin-api`](plugin-api.md)）。
10. **消息目录端点。** 只为本次启动集合里写了 `l10n` 的插件、当前摘要、清单 `l10n.locales` 列出的语言返回 `locales/<语言>.json` 的原样内容（内容类型 JSON），不执行插件代码，所以只有后端入口、不在浏览器登记的插件也取得到它的目录。访问要求与安全响应头同插件文件端点。路径不是“插件 id、摘要、语言标签加 `.json`”的形状时返回 400；插件不在集合里、没有 `l10n`、摘要不是当前摘要、语言不在列表里或文件不存在时返回 404；文件读不了时返回 500 并记一条诊断。端点不检查内容，内容的检查由取目录的一方做（[`runtime.browser-host`](browser-host.md) 输出 8）。

## 状态与转换

| 当前 | 事件 | 下一状态 |
|---|---|---|
| 未装载 | 入口首次激活 | 已装载（服务端：模块已求值；浏览器：工厂已登记） |
| 已装载 | 该插件在本运行位置（浏览器为本窗口）的全部入口停止且引用撤回完成 | 已注销，等待回收 |
| 已装载、已注销 | 同一入口停止后再次激活 | 执行一份新的模块实例，不复用旧实例 |
| 已装载 | 装载或求值失败 | 入口激活失败（`runtime.plugins` 的失败状态），已登记的部分注销 |

- 同一窗口中同一插件同时只有一份已装载的浏览器代码；热升级时先注销旧版本再装载新版本。

## 副作用与数据

- 本能力不写持久数据；只读安装目录。
- 浏览器装载会向页面加入插件样式，注销时移除。
- 插件文件端点的响应可以长期缓存：URL 含版本目录的内容摘要，升级与同版本重装（卸载、重启后再装同一版本）都换摘要，旧 URL 返回 404，浏览器不会执行缓存里的旧代码。浏览器引导的修订号同样并入摘要（[`runtime.browser-host`](browser-host.md)）。消息目录端点的成功响应同样可以长期缓存，失败响应不缓存。

## 失败与恢复

- 构建时执行描述与入口定义模块抛错：构建失败，问题的路径是堆栈里第一个落在作者目录（不在 `node_modules`）的位置“文件:行:列”，消息是错误消息；找不到作者的位置时路径是正在执行的入口文件、消息后面带堆栈的第一个位置。缺省不打印打包器的日志；构建预设的 `verbose`（作者工具的 `--verbose`）打印日志并在消息后附完整堆栈。

- 代码文件缺失、语法错误或模块顶层抛错：入口激活失败，原因可查询，不影响其它入口。
- 旧模块无法释放：记录诊断，旧代码保留到重启，只影响内存回收（L2）；再次激活仍执行新的模块实例，入口的启停、引用撤回与代次隔离不受影响。
- 浏览器装载失败：该窗口中入口激活失败，原位显示原因并可重试，其它窗口与服务端不受影响。原因带插件 id、入口 id 与文件 URL：`code-load-failed`（脚本加载出错、30 秒内没有登记，或宿主模块表没有取到）、`code-shape`（脚本执行了但没有登记，或工厂没有导出 `activate`）、`code-threw`（工厂或 `activate` 抛出）、`module-not-shared`。
- 插件样式注销遗漏：页面刷新后消失；开发模式检查报告残留样式。

## 边界与兼容

- **owner**：runtime（加载器）。视图宿主与错误边界的呈现归 workbench；宿主模块表的建立时机归 [`runtime.browser-host`](browser-host.md)。
- **共享入口即兼容承诺。** 模块表共享哪些 nb-ui 入口，就对插件作者承诺哪些 API 保持兼容。第一版共享组件，经 SDK 的 `@notnotype/nb-plugin-sdk/components` 给出：nb-ui 是不发布的私有包，作者装不到它，组件的构建期实现与类型都随 SDK 包分发。文字的纯数据层与翻译端口（nb-ui 的 `./text`、`./text-port`）随后经 SDK 的 `/text`、`/text/browser` 共享（[`ui/i18n`](../ui/i18n.md)）。其余入口按需增加，每次增加都是 `engines.neurobook` 兼容范围的变化。
- **安全**：插件代码与已安装插件列表不对未登录用户公开；插件代码同源加载，请求自带登录 Cookie。第一版完全信任，不隔离插件代码。
- **运行时依赖**：服务端的“新代次新实例”与回收依赖删除 `require.cache` 里的条目后重新装载 ESM 能得到新实例、旧实例无人引用后可回收（Bun 1.4.2 实测，未文档化；加查询串也能得到新实例，但旧实例永不回收，不用）；宿主模块经 Bun 的运行期插件登记。升级 Bun 时要回归验证场景 4 至 7。
- **体积**：共享使宿主对 Vue 与 nb-ui 失去 tree-shaking，体积影响须在阶段 3 测量并记录。

## 验收与 Smoke

1. **共享 Vue。** Given 源码树外构建的示例插件视图；When 在开发与生产构建中装载；Then 点击后计数更新，i18n 与主题取自宿主，nb-ui 浮层位置正确。
2. **纯度检查。** 把 Vue 打进示例插件时构建失败并指出 `vue`；引用 nb-ui 的其它入口或绕过 SDK 引用内核时构建失败并写明未共享。
3. **表外模块。** 插件 `require('lodash')` 时入口激活失败，原因为 `module-not-shared`，其它插件正常。
4. **回收。** 禁用后，服务端不再持有该插件的模块；浏览器模块表中没有该插件的项，样式被移除；Chromium 堆快照中不再有插件组件的实例。
5. **入口粒度。** 插件的 `tts` 入口因依赖消失而停止时，同一插件 `main` 入口的 worker 调用、视图与样式不受影响。
6. **新代次新实例。** 在模块顶层保存计数的示例入口禁用后再启用，计数从初始值开始。
7. **L2。** 开发模式下反复启用、禁用、升级 40 次，服务端与浏览器的堆内存不随次数增长。
8. **文件端点。** 未登录请求返回 401（planned）；含编码的分隔符或 NUL（`..%2F`、`%5C`、`%00`）的路径返回 400，明文 `..` 拿不到版本目录外的文件；旧摘要（升级或同版本重装之前的）返回 404。
9. **错误边界。** 插件视图渲染时抛错，只有该视图显示错误，其它视图可用。
10. **消息目录端点。** 已安装、写了 `l10n` 的插件：当前摘要下列出的语言返回目录原文；不在列表里的语言、旧摘要返回 404；语言段不是语言标签加 `.json` 时返回 400。只有服务端入口的插件同样取得到。
