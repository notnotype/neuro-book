# 服务装配与依赖解析

## 目标与非目标

目标是让运行实例内的每项服务能力都有可查询的声明来源与唯一解析结果：消费者能知道谁提供、在什么位置与作用域提供、依赖是必需还是可选，并在失败时得到稳定、可诊断的结果，而不是随机取得某个实现或半成品实例。

明确不承诺：

- 不提供跨进程服务总线、通用 RPC 或对象代理；跨位置装配与协议归 `runtime.application` 与各能力合同。
- 不为第三方或不可信代码提供注册、沙箱或权限隔离；装配清单是受信内置代码的所有权边界。
- 不定义资源所有权与关闭推进（[`runtime.lifecycle`](./lifecycle.md)）、插件描述与激活（[`runtime.plugins`](./plugins.md)）以及各服务自身的领域行为。

## 术语与参与者

- **服务键**：稳定标识一项能力合同的标识；解析以“服务键 + 解析作用域”为单位。
- **声明**：入口对提供或消费的静态描述，包含服务键、运行位置、作用域与必需性。
- **提供者**：声明提供某服务键的绑定；其服务实例是一个资源，owner 由声明的作用域承担。
- **消费者**：声明消费某服务键的入口或插件；消费不取得关闭该服务的权力。
- **解析作用域**：在哪个作用域内解析该服务键；实例的 owner 作用域由提供者声明固定。子作用域的消费者解析声明在祖先作用域的提供者时，命中祖先作用域上的同一实例，不因每个消费者子作用域重复初始化。
- **失败闭包（必需消费者闭包）**：以缺失或失败的提供者为起点，沿必需依赖边反向（消费者方向）传递可达的消费者集合；闭包内消费者被拒绝，闭包外的健康提供者与消费者继续工作。
- **必需 / 可选**：必需依赖缺失或初始化失败会拒绝失败提供者自身及其必需消费者闭包；可选依赖缺失只使对应能力显式不可用。
- **初始化**：首次解析时创建服务实例的过程；同一提供者作用域的并发首次解析共享同一次初始化，单个等待方取消不取消共享初始化。
- **运行期绑定**：在一次操作期间取得的精确资源身份/代次（如 Project 代次）；绑定不构成对资源消费者的反向激活，也不允许稍后改读“当前目标”。
- **装配诊断**：描述声明、冲突、缺失、环与初始化失败的运行实例内记录。

## 输入与前置条件

- 每个入口提交声明：所提供/消费的服务键、运行位置、作用域与必需性；静态依赖边与运行时等待边都算依赖。
- 声明中的服务键、位置与作用域必须来自受信登记表；无法识别或字段不合法的声明在装配阶段被拒绝，且不产生业务副作用。静态预校验只能保证校验与声明阶段无副作用，不保证后续动态激活阶段无副作用：动态等待环在已开始激活后才发现时按收口与阻断发布处理。
- 提供者的服务实例必须创建在一个已存在的作用域内，并遵守 [`runtime.lifecycle`](./lifecycle.md) 的登记与收口。
- 运行期绑定必须由资源 owner 按精确身份/代次签发；绑定回调自身解析服务或等待激活时，该等待边同样进入依赖检查。

## 输出与可观察行为

外部消费者（不读取内部私有字段）可以观察到以下行为：

1. **声明可查询**：任何实现被激活前即可查询声明集合与依赖检查结果；查询不实例化服务、不触发业务副作用。
2. **唯一提供者**：同一服务键在同一解析作用域默认只有一个选定提供者；出现重复或身份冲突时隔离全部冲突声明，不按声明顺序挑选，消费者得到不可用原因。
3. **解析结果**：成功时交出可调用实例；失败时返回结构化原因（缺少必需依赖、存在依赖环、冲突未决、初始化失败、绑定失效），不交出半成品或空实现。
4. **可选缺失显式化**：可选依赖缺失时报告“能力不存在”，不静默创建第二个默认提供者；受影响范围仅限该能力，无关消费者继续工作。
5. **必需失败闭包**：必需依赖缺失或初始化失败时，被拒绝的是失败提供者自身、以及沿必需依赖边反向可达的必需消费者闭包（依赖该键的消费者及其传递依赖者）；闭包内的入口不产生新的业务副作用，也不发布半成品。健康的上游提供者不被隔离：只要不再依赖失败键，相关消费者继续工作。闭包涉及启动必需能力时，宿主不得进入业务接纳（门禁与呈现归 `runtime.application`）。
6. **初始化去重**：同一提供者作用域的并发首次解析只发生一次初始化，所有等待者收到同一结果（同一成功实例或同一失败）；某个等待方取消或断线只结束它自己的等待，不取消共享初始化、不改变其他等待者的结果；共享初始化只由提供者 owner 作用域的停止/取消或初始化自身失败收口。
7. **作用域内失败稳定**：初始化失败后，同一解析作用域的后续解析稳定返回同一失败结果，不因下一次渲染、轮询或重试调度自动再次初始化；恢复必须来自显式操作或新的作用域/代次，且不与仍 pending 的收口并发。
8. **寿命合法性**：解析只在消费者所在作用域及寿命更长的作用域内取得实例。长寿命作用域不得依赖、持有或捕获更短寿命作用域的实例（包括不得把短寿命作用域实例存入长寿命服务）；反向借用允许：短寿命（操作级）作用域可通过显式操作借用寿命更长的精确资源身份/代次（例如精确 Project 代次），借用必须携带精确身份/代次，不构成所有权，也不延长资源寿命。指向更短寿命作用域的隐式解析、已关闭作用域或旧代次的绑定解析失败，不返回已关闭实例，也不静默改投新目标。
9. **精确 factory 绑定**：工厂只被登记，不因登记或查询而实例化、也不因此等待目标资源 ready；操作期间取得的绑定指向精确代次；目标换代后旧绑定不可用，重连/重开产生新代次。
10. **诊断脱敏且可查询**：装配诊断包含位置、作用域、服务键、阶段与原因；不包含 secret、凭据、令牌、文件内容或用户数据；诊断在最小依赖下可用，不要求完整日志能力成功才能报告装配错误。

## 状态与转换

以“服务键 + 解析作用域”为单位的解析状态（实例归提供者声明的作用域）：

| 状态 | 事件 | 下一状态 | 结果 |
| --- | --- | --- | --- |
| 未解析 | 首次解析请求 | 初始化中 | 开始唯一一次初始化；并发请求加入同一等待 |
| 初始化中 | 初始化成功 | 可用 | 全部未取消的等待者（含子作用域发起者）获得同一实例 |
| 初始化中 | 初始化失败 | 失败（稳定） | 全部未取消的等待者获得同一失败；无半成品发布；不自动重试 |
| 初始化中 | 某个等待方取消/断线 | 初始化中 | 只结束该等待方自己的等待；不取消共享初始化、不影响其他等待者 |
| 初始化中 | 提供者 owner 作用域停止或取消 | 停止中 | 已登记资源收口；迟到成功不发布 |
| 可用 | 作用域停止 | 停止中 | 拒绝新解析；消费者先收口，提供者最后释放 |
| 停止中 | 生命周期关闭门禁满足 | 已释放 | 报告释放结果；存在未完成资源/获取/操作时仍停止中，保留原因与owner |
| 失败（稳定） | 作用域停止 | 停止中 | 保留失败原因，不为失败实例重新初始化；收口完成进入已释放 |
| 失败（稳定） | 显式恢复且上次失败资源全部收口完成 | 未解析 | 允许重新初始化；不与仍 pending 的收口并发；不自动循环 |
| 已释放 | 再次解析请求 | 已释放 | 拒绝并返回已关闭原因；已关闭作用域不重新激活，恢复需新的存活作用域/代次 |

声明依赖检查：

| 状态 | 事件 | 结果 |
| --- | --- | --- |
| 待检查 | 收集全部声明 | 形成静态依赖边与运行时等待边 |
| 通过 | 所有必需依赖有唯一可用提供者 | 相关消费者可解析 |
| 失败 | 缺少必需提供者、存在环或冲突未决 | 拒绝相关绑定与必需消费者闭包，记录失败/缺失服务键与受影响服务键/消费者 |
| 部分可用 | 仅可选依赖缺失 | 对应能力不可用；其他消费者不变 |

并发语义：初始化的 single-flight 按提供者声明的作用域（实例 owner 作用域）隔离，而不是按发起解析的消费者作用域隔离；子作用域解析祖先提供者复用祖先作用域上的同一次初始化，不按每个 consumer 子树重复实例化。解析的 single-flight 与插件激活的 single-flight 相互协作（见 [`runtime.plugins`](./plugins.md)）：并发解析同一未激活提供者只触发一次激活，激活完成后等待者取得同一实例。不同运行实例、不同窗口、不同提供者作用域不共享初始化结果。作用域停止后拒绝新的解析业务操作；运行期绑定的有效性以签发时的身份/代次为准。

## 副作用与数据

- 解析与登记是运行实例内的内存状态；本能力不引入持久状态，不写用户数据，不改变数据格式。
- 服务实例创建产生的 I/O（连接、文件、租约）由该服务及其 owner 合同负责；机制只登记、解析与报告。
- 诊断记录的保留与输出通道归运行时诊断能力；机制保证其可查询与脱敏，不要求它先于最小启动报告可用。
- 查询声明、依赖图与诊断不触发实例化，不产生网络请求。

## 失败与恢复

- **缺少必需依赖**：拒绝失败提供者与依赖它的必需消费者闭包，记录缺失服务键；健康上游提供者不受影响；不得用默认实现、空实现或惰性占位换取成功。
- **可选缺失**：对应能力明确不可用，无关能力继续；不得悄悄创建第二个默认提供者。
- **重复提供/身份冲突**：隔离全部冲突声明；消费者不可用并得到原因；不按顺序挑选一个。
- **依赖环**：静态依赖与运行时激活等待边共同成图检测；不允许用惰性解析隐藏环。静态环在装配阶段拒绝，不产生业务副作用、无入口被激活；运行时等待环可能在相关入口已开始激活后才发现，此时不回滚已发生的副作用，而是阻断受影响解析的发布与后续等待，并按 [`runtime.lifecycle`](./lifecycle.md) 收口本次已登记资源；不得把动态环报告为“无入口被激活”。
- **初始化失败**：失败稳定且不发布半成品；重试需显式策略或新的作用域/代次，且失败资源必须已收口完成，不得与仍 pending 的收口并发重入。
- **作用域停止/取消**：拒绝新解析与新激活；已接纳解析按 [`runtime.lifecycle`](./lifecycle.md) 的取消/收口推进；某个等待方取消不取消共享初始化（只有提供者 owner 作用域停止/取消才收口共享初始化）；迟到初始化成功不发布。
- **绑定失效**：旧代次绑定返回 stale/失效原因，不自动绑定到新目标；调用方经显式协议重新确认代次后才能继续。

## 边界与兼容

- **owner 与依赖方向**：owner 为 runtime；依赖 [`runtime.lifecycle`](./lifecycle.md)；[`runtime.plugins`](./plugins.md) 依赖本能力。不得 import 产品领域实现、框架 hook 或数据库驱动；机制必须能在两个不同 host 与两种不同作用域上复用。
- **服务依赖不等于权限**：可解析性、目录可见性都不是授权；真实副作用边界由目标能力按身份与代次重新校验。本能力不定义权限模型。
- **底层适配器**：适配器仍是有 owner 的显式服务提供者，不因名称绕过依赖检查；运行期绑定表示精确资源代次，不表示反向激活资源消费者。
- **相邻合同**：资源所有权与收口见 [`runtime.lifecycle`](./lifecycle.md)；插件描述与激活见 [`runtime.plugins`](./plugins.md)；启动清单与跨位置装配见 `runtime.application`。
- **兼容与迁移**：允许 clean cutover 且必须迁移全部调用方；不新增发布包，不引入第三方 SDK，不改变数据格式或迁移策略；既有 implemented 合同在切换前有效。

## 验收与 Smoke

以下场景在隔离运行实例中由外部消费者可观察的解析结果与诊断判定，不读取内部私有字段。

1. **并发首次解析**：两个消费者在同一提供者作用域并发首次使用同一服务键；初始化只发生一次，两者拿到同一实例；另一个运行实例或另一个提供者作用域解析同一键得到互不相同的实例；子作用域消费者解析祖先提供者拿到祖先作用域上的同一实例，不重复实例化；解析等待期间取消其中一个等待方，不取消共享初始化，其他等待者仍拿到同一结果。
2. **缺依赖闭包**：消费者声明缺失或失败的必需依赖；失败提供者自身与依赖它的必需消费者闭包被拒绝且无新的业务副作用；健康上游提供者与不再依赖该键的消费者继续可用；可选依赖缺失时该能力明确不可用，其他消费者继续可用。
3. **重复提供隔离**：两个提供者声明同一服务键；两个冲突声明都被隔离、诊断列出冲突，消费者不可用而不是随机挑一个。
4. **依赖环检查**：静态依赖环在装配阶段被检测并拒绝，无入口被激活且无业务副作用；运行时等待环在已开始激活后被检测时，阻断受影响解析的发布与后续等待、按合同收口，不声称“无入口被激活”，也不回滚已发生副作用。
5. **初始化失败稳定**：初始化中途抛错或被取消；已登记资源收口、等待者得到同一失败、不发布半成品；同一作用域再次解析得到同一失败；显式恢复只在失败资源收口完成后重试，不和在途收口并发，也不自动循环。
6. **寿命合法性**：长寿命作用域请求解析短寿命作用域、捕获短寿命实例或使用已关闭代次的绑定；明确失败且不返回已关闭实例；短寿命（操作级）消费者解析长寿命服务、并按显式操作借用精确代次（如精确 Project 代次）正常完成。
7. **精确绑定**：工厂登记后不因查询而实例化；操作期间取得的绑定指向精确代次；目标换代后旧绑定的操作失败为 stale，不自动改投新目标。
8. **诊断脱敏**：声明与错误上下文包含敏感字段时，查询到的诊断只含位置/作用域/服务键/阶段/原因，不含敏感值。
9. **两种作用域 × 两个 host 复用**：同一机制在两个 host（浏览器运行实例与后端进程实例）与两种作用域（实例级、操作级）上装配：各自独立解析、独立失败、互不串实例；机制实现不含产品领域 import 与框架适配依赖。

Smoke 以解析结果、依赖检查与诊断等外部可观察结果为准；场景入口与执行方式由实施计划确定，本 Spec 不把尚未存在的脚本列为证据。
