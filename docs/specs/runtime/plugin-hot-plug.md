# 插件运行期启用、禁用与引用撤回

## 目标与非目标

插件的启用与禁用在运行中即时生效，不需要重启。禁用后，插件的全部可见效果与它经内核交出的全部引用被撤回，调用方不会被卡住，在途工作在有界时间内结束或被放弃，迟到的结果不会发布。安装、卸载与升级复用本能力的停止与启动流程（[`runtime.plugin-install`](plugin-install.md)）。

热插拔的承诺分三档：

| 档位 | 内容 | 本能力的承诺 |
|---|---|---|
| L1 即时生效 | 启用、禁用立即生效；撤回全部可见效果与经内核交出的引用；在途工作结束或被放弃 | 承诺 |
| L2 回收代码与内存 | 反复启用、禁用不使内存增长 | 尽力而为，见 [`runtime.plugin-code-loading`](plugin-code-loading.md) |
| L3 保证恢复到启用前 | 无论插件如何实现都完全干净 | 不承诺；重启应用即完全干净 |

明确不承诺：

- 不撤回插件绕过内核留下的引用与状态：全局变量、修改宿主原型、裸定时器、`process.on`、向共享库写入的状态。第一版完全信任，这一层只由开发模式检查发现、由重启兜底。
- 不打断主线程上的同步计算；主线程卡死由 [`runtime.stall-watchdog`](stall-watchdog.md) 兜底。
- 不回滚插件已产生的外部副作用与数据。
- 不定义各贡献点拥有者如何清理自己的派生状态（例如 workbench 删除布局项），只规定它们会收到撤回通知。

## 术语与参与者

- **用户状态**：已启用、已禁用、未安装三种，持久化，只由用户操作改变。本能力处理已启用与已禁用之间的转换。
- **声明层与实现层**：声明层是插件启用或禁用使其清单中的声明出现或消失；实现层是入口激活或停止。声明在而实现不在时可以显示，用到时激活；声明不在时不显示。
- **引用账本**：内核为每个入口记录它经内核交出和借入的全部引用：导出 API 以转发器交出，贡献实现以句柄交出，事件订阅以登记在订阅方作用域上的句柄交出，宿主 API 以转发器交给插件。
- **转发器**：交给使用方的代理对象。撤销后它不再引用提供方，调用返回 `plugin-unavailable`。
- **跨插件调用**：导出 API 调用、贡献调用、命令执行、插件通道请求。每次调用都经内核包装：合成终止信号并登记为在途调用。
- **合成终止信号**：调用方传入的信号、调用方入口被中止、提供方入口被中止，三者任一触发即触发。“被中止”指入口进入三步停止的第 2 步；第 1 步只停止接纳新调用，不触发信号。
- **三步停止**：等待、中止、放弃，见“状态与转换”。
- **连带受阻**：依赖被停止入口所提供服务的入口，按 [`runtime.plugin-manifest`](plugin-manifest.md) 的规则受阻。

## 输入与前置条件

- 触发：插件所有者（启用认证时为 `admin` 角色，见 [`runtime.plugin-install`](plugin-install.md)）在插件管理中启用或禁用一个插件，其它用户得到 403；[`runtime.plugin-install`](plugin-install.md) 的安装、卸载、升级流程内部调用同一启动与停止流程。
- 启动必需的内置插件不能禁用，请求被拒绝。
- 禁用前先请求“影响预览”，预览不改变任何状态。
- 服务端是用户状态与有效插件集合的唯一 owner；浏览器窗口只跟随服务端推送的插件集合变化。

## 输出与可观察行为

1. **影响预览。** 返回：将被停止的入口（被禁用插件的全部入口，以及连带受阻的其它插件入口，按插件分组，并标明同一插件中仍保持可用的入口）、每个受影响入口的在途调用数。例如“禁用 nbook.editor：文生图的 editor-ui 停用，generator 继续提供 Agent 工具”。
2. **禁用。** 用户确认后：
   - 受影响的入口一起执行三步停止，之后按依赖逆序关闭，连带受阻的入口先于被禁用插件的入口关闭；
   - 被禁用插件的声明层从服务端与所有窗口消失：菜单、视图、命令、Agent 工具、端点、路由、设置项、上下文键；各贡献点拥有者收到声明撤回通知；
   - 连带受阻插件的声明保留，但实现不可用，界面原位显示受阻原因；
   - 用户状态写为已禁用，即使停止未完全结束也立即写入。
3. **引用撤回。** 入口停止后：它交出的转发器与贡献句柄失效，调用返回 `plugin-unavailable`；它登记的事件订阅被移除；它订阅的事件句柄关闭；它持有的宿主 API 转发器被撤销，此后插件代码再调用宿主 API 一律失败。使用方仍持有转发器也不阻止提供方被回收。
4. **在途调用的结果。**

   | 提供方的实现 | 调用方看到 | 提供方一侧 |
   |---|---|---|
   | 配合终止信号 | 最迟在三步停止结束时得到 `interrupted` | I/O 被中止，资源立即释放 |
   | 不响应终止信号的异步工作 | 同上 | 在后台继续执行；再调用宿主 API 时失败；结果被丢弃 |
   | CPU 工作在 worker 池中 | 同上 | worker 被终止（限制见 [`runtime.plugin-api`](plugin-api.md)） |
   | 同步 CPU 工作在主线程上 | 计算结束前整个宿主无响应 | 由看门狗处理 |

   命令调用方在调用时得到结果；事件发出方不等待监听者，不参与在途记账。
5. **启用。** 用户状态写为已启用；插件的声明层在服务端与所有窗口出现；入口按激活事件激活；因它而受阻的入口解除受阻，按各自的激活事件重新激活，代次加一。
6. **窗口同步。** 服务端经事件流把插件集合变化推送到所有窗口；每个窗口按同样的依赖逆序停止、按依赖顺序启动自己的浏览器入口，视图组件由 workbench 在撤回时卸载。离线窗口重连后按当时的插件集合对齐。
7. **开发模式检查。** 入口停止后，用弱引用确认其激活上下文已被回收，未回收时报告“插件卸载后仍被引用”；跨插件调用的参数与结果做一次结构化克隆，提前暴露传递活对象的违规。检查只在开发模式运行，不改变生产行为。

## 状态与转换

一次启停操作中受影响的全部入口（被禁用插件的入口与连带受阻的入口）同时进入每一步，时间预算按整次操作计算，不按入口累加：

| 阶段 | 行为 | 结束条件 |
|---|---|---|
| 1 等待 | 停止接纳新调用（新调用立即得到 `plugin-unavailable`）；按声明逆序撤回它交出的贡献；等待在途调用自然完成 | 在途调用清零，或达到等待上限 5 秒 |
| 2 中止 | 触发本入口的合成终止信号 | 在途调用清零，或达到中止宽限 2 秒 |
| 3 放弃 | 仍未结束的调用由内核替调用方结算为 `interrupted`；撤销本入口持有的全部宿主 API 转发器 | 立即完成 |

- 三步结束后，受影响的入口按依赖逆序（依赖者先、提供者后）关闭并收口资源（[`runtime.lifecycle`](lifecycle.md)），再按 [`runtime.plugin-code-loading`](plugin-code-loading.md) 回收代码；收口未完成时如实报告关闭未完成。
- 因此从用户确认禁用到全部在途调用结算，最长约 7 秒，与受影响入口的数量和依赖深度无关。
- 迟到的结果、进度与事件一律丢弃，不发布、不改变已结算的调用结果。

插件的用户状态：

| 当前 | 事件 | 下一状态 | 说明 |
|---|---|---|---|
| 已启用 | 禁用（已确认） | 已禁用 | 触发全部入口与连带入口的三步停止 |
| 已禁用 | 启用 | 已启用 | 登记声明层，按激活事件激活 |
| 已启用 | 禁用启动必需的内置插件 | 拒绝 | 状态不变 |

并发语义：

- 重复禁用或重复启用幂等，观察同一次操作的结果。
- 停止进行中收到启用请求：先完成停止，再按启用处理；启动进行中收到禁用请求：取消未完成的激活（迟到成功不发布，沿用 `runtime.plugins`），再按禁用处理。
- 两个插件的启停并发进行时，每个入口的停止与激活仍按依赖图排序；不因操作到达顺序违反“依赖者先停、提供者后停”。

## 副作用与数据

- 用户状态持久化在已安装插件的启用列表中（格式归 [`runtime.plugin-install`](plugin-install.md)）；运行状态、账本与在途表是内存状态。
- 禁用不删除插件的私有存储、配置与密钥，也不删除插件写入作品的内容。
- 诊断记录每次停止的三步耗时、被放弃的调用数，以及开发模式下“卸载后仍被引用”的报告。

## 失败与恢复

- 某个入口在停止中抛错：记录错误，继续完成三步，不阻塞其它入口的停止。
- 贡献点拥有者处理撤回通知失败：记录错误，撤回照常生效（被撤回的实现已不可调用）。
- 窗口离线或处理插件集合变化失败：只影响该窗口；服务端的禁用结果不因此回退。窗口重连或刷新后对齐。
- 被放弃的工作在后台继续执行不算失败，但其宿主 API 调用全部失败，结果丢弃。
- 进程在启停中途崩溃：下次启动按持久化的用户状态重新登记，不假设上次撤回已执行。

## 边界与兼容

- **owner**：runtime。依赖 `runtime.plugins`（激活与普通关闭）、`runtime.services`（依赖闭包）、`runtime.lifecycle`（作用域收口）、`runtime.plugin-manifest`（受阻推导）。
- **四条规则**：登记跟随作用域（贡献实现、命令处理函数、事件订阅、上下文键、借用的导出 API 都登记在登记方的激活作用域上，作用域关闭即撤回）；撤回由内核推送（拥有者不轮询）；三步停止；声明层与实现层分开变化。
- **跨插件引用只经内核建立。** 插件不在运行时 import 其它插件的模块；这样的引用内核看不见，不属于本能力的承诺范围。
- **在途工作不依赖插件作者自觉来保证宿主正确**：调用方不会被卡住，被放弃的工作无法再经宿主 API 产生副作用，迟到结果不会发布。只有效率（后台空转、外部费用）依赖插件把终止信号传给自己的 I/O。
- **性能**：在把调用包装用于每次按键都会触发的路径之前，先测量它对单次调用的开销。
- **兼容**：`plugin-unavailable` 与 `interrupted` 是公开错误码，属于 [`runtime.plugin-api`](plugin-api.md) 的错误合同。

## 验收与 Smoke

1. **Agent 工具在执行中被禁用。** Given 文生图的 `generate_illustration` 正在执行（配合终止信号，需要 30 秒）；When 用户确认禁用文生图；Then 第 5 秒时工具收到终止信号，Agent 在确认后 7 秒内得到 `interrupted`，工具从下一轮可用工具中消失，迟到的图片结果不写入。
2. **不配合中止的工具。** Given 工具实现忽略终止信号并在 20 秒后返回；Then 调用方在三步停止结束时得到 `interrupted`；工具在后台完成后调用宿主 API 写资产时失败，没有写入发生。
3. **持有的转发器失效。** Given 插件 C 的入口借用了插件 B 导出的服务并保存了转发器；When 禁用 B；Then C 的该入口先于 B 停止并受阻；若 C 在别处残留该转发器，调用得到 `plugin-unavailable`；开发模式下 B 的激活上下文被确认回收。
4. **影响预览。** 禁用 `nbook.editor` 的预览列出文生图 `editor-ui` 将停用、`generator` 保持可用，并给出在途调用数；预览前后状态不变。
5. **声明层。** 禁用 Files 后，所有窗口中资源管理器视图、`explorer/context` 菜单与 Files 命令消失，workbench 删除其布局项；重新启用后视图回到贡献声明的初始位置。
6. **连带受阻原位显示。** 禁用 `nbook.models` 后，依赖它的插件视图保留在原位并显示受阻原因，命令调用返回 `plugin-unavailable`。
7. **再启用新代次。** 禁用后再启用，入口以新代次激活；旧代次交出的句柄仍然失效。
8. **并发。** 停止进行中收到启用请求，最终插件为已启用且只有一个新代次在运行；连续两次禁用只执行一次停止。
9. **窗口。** 两个窗口同时打开时禁用插件，两个窗口都移除其浏览器入口；离线窗口重连后移除。
10. **启动必需插件** 的禁用请求被拒绝，状态不变；`user` 角色的禁用请求得到 403。
11. **依赖链不累加。** A ← B ← C 三层依赖且每层都有不配合中止的在途调用时，禁用 A 后全部调用在 7 秒内结算。

Smoke：在真实服务端与 Chromium 上用示例外部插件（两端入口、一个命令、一个视图、一个 Agent 工具、一个配合与一个不配合终止信号的长调用）执行启用、禁用、再启用，核对场景 1、2、5、7、9；开发模式下核对“卸载后仍被引用”检查与内存不随 40 次启停增长。
