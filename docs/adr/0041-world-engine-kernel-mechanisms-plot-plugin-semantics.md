# ADR 0041：世界引擎的内核只加通用机制，剧情的语义放进剧情插件

- 日期：2026-11-05
- 决策者：开发者
- 关联工作：[w00039 t32](../../.agents/works/w00039-novel-writing-plugins/tasks/t32-plot-side/README.md)
- 相关文档：[作者视角的世界引擎：剧情侧（第一版）](../proposals/world-engine-plot-side.md)（行为细节、例子与取舍都在提案里）

## 背景

内核（ADR 0037、0039，包 nb-canon 在分支 `feat/w00039-t29-canon-kernel` 上实现）有条目、剧情变更、计划与修订。剧情侧要加时间、世界线、在场、知情、伏笔、目标与态度、决策与章级写作指示，以及写手的简报与写完后的检查。全放进内核，每加一种叙述手法就要改一次日志格式与引擎；全放进插件，插件又做不对只有内核能做的事：在 nb-canon 上跑知情与伏笔的例子，实测还原不列出依赖、文字字段里的临时 id 不替换，因为内核不知道哪些字段是引用。ADR 0027 定领域能力皆为插件。提案经三轮设计审查后接受。

## 决策

1. **内核只加通用机制**（开发者 2026-11-04）：条目引用与引用声明；讲述的发生点（id 与段位置）与通用标注；剧情变更的参与者（在场）；时间说法与无依赖的新包 `nb-time`；世界线（ADR 0042）；未决问题扩成决策，作者原话的来源由宿主签发；标注种类与诊断两个贡献点。
2. **剧情插件拥有语义**（开发者 2026-11-04）：知识点、知情、伏笔、目标、态度、决策的 Component 与规则，读者的知情、账本、写手简报、窄问题与各种检查。内核的 Spec 在 `docs/specs/canon/`，剧情插件的在 `docs/specs/plot/`。
3. **两个贡献点**：标注种类登记 id、版本、载荷的 schema 与载荷里哪些路径是引用，内核据此校验、替换临时 id、查还原依赖；诊断登记 id、版本、输入、输出与稳定键，在读取时算出、不落盘。作者对一条诊断的处理（有意为之、以后不再提）记成挂在诊断键上的决策，不另建对象（开发者 2026-11-04）。
4. **停用与版本按 Component 现有的规则**（开发者 2026-11-05）：插件停用时标注原样保留、只读，诊断不再算出，作者的处理保留；标注的版本对不上时只读、带诊断；作者的处理绑定诊断的版本，插件升版改了诊断的规则或键就重新报，附上旧的处理供作者一键沿用，不自动继承。

## 备选方案

- **剧情的语义都进内核**（提案第一版草稿）：每加一种叙述手法就改一次日志格式与内核。开发者 11-04 看过第一轮审查后改成分界。
- **内核什么都不加，全在插件里做**：引用替换、还原依赖、讲述的段位置要每个插件各写一份，上面两个实测缺口就出在这里。
- **新增第七种对象（知情记录、伏笔账本）**：位置、世界线、计划、撤销与修订都要为它重做一遍。

## 后果

- 以后加一种叙述手法（新的标注种类、新的检查），只改插件，不改日志格式。
- 内核多维护两个贡献点的合同与版本规则。诊断不落盘，每次读取都要算，开销写进 Spec 的预算。
- 剧情插件的 Spec 依赖内核 `canon/model`、`canon/components` 的新增条目，实施先后见提案的待定项。
