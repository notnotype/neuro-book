# ADR 0057：服务商只有一种模板化实例；模型清单由设置与来源缓存加 OMP 元数据合成；发送前核对实例身份；网络出口只选路

- 日期：2026-11-20
- 决策者：开发者
- 关联工作：[w00032 t43](../../.agents/works/w00032-agent-integration/tasks/t43-models-ux/README.md)（计划见同目录 `plan.md`，决定 1 至 25）
- 相关文档：[`models/service.md`](../specs/models/service.md)、[`models/settings-pages.md`](../specs/models/settings-pages.md)、[`harness/models.md`](../specs/harness/models.md)
- 取代：w00032 t09 决定 11、12 里“目录服务商与自定义服务商之分”

## 背景

开发者 2026-11-20 要改模型设置与选择器的体验：服务商从模板建、带图标，协议能探测，网络能配代理，模型目录不升级应用也能拿到新版，角色能定默认思考档。这几件事牵动四个底层选择：模型清单从哪来、发现与缓存归谁做、请求用什么身份发出、出口规则放哪。它们互相依赖，先定下来，三个阶段（A 推理档与选择器，B 服务商模板化与模型来源，C 网络与代理）才不会各自假设。

## 决策

1. **服务商只有一种**：都从模板复制，名称、协议、地址、图标都能改；模板只决定初始值与去哪查模型能力。不再分“目录服务商”与“自定义服务商”。
2. **模型清单的真相源**：设置里的覆盖与成员记录（手加、来源模型的覆盖、冻结成员），加上状态根里的来源缓存（成员行带物化所需字段），再加上 OMP 的元数据（打包目录与在线目录，按“模板的 provider 加模型 id”查）。同一份设置在两台机器上可能得到不同的清单：这是“不升级也能拿到新模型”的代价。不把目录快照存进设置。
3. **发现与缓存由我方做，OMP 只提供元数据、映射函数与请求传输**：不用 OMP 的 `ModelManager` 与目录工厂，它们按 OMP 自己的 provider 身份做缓存与认证，不认实例改过的地址、认证与协议。在线目录自己取（ETag、大小上限、`200`、`304`、失败、取消四种结果），只复用映射函数。
4. **模型身份与发送前核对**：pi-ai 按 `Model.provider` 走各家专用处理，并会按进程环境变量改写请求地址。实例的协议与地址都跟随模板时，`Model.provider` 用模板的 OMP id；改了协议或地址、或空白模板时用中性身份 `nbook-compatible`。无论哪种，最内层的发送在发出前核对：请求的源必须等于实例有效地址的源，且该实例当前的部署身份仍与本次解析相同，否则不发并报 `endpoint-mismatch`（防环境变量改址、防解析后换了地址再读到新密钥）。对外引用是 `<实例 id>/<模型 id>`；每次响应带 `origin`（provider、api、model、deployment）写进会话日志，`deployment` 是实例 id 加有效地址与协议的哈希，不含凭据；还原签名要求整组相同，没有 `origin` 的旧日志按旧规则。不改上游：让 pi-ai 不按 provider 分支要改几十处。
5. **网络出口只选路**：出口规则、系统代理读取与按次的 `fetch` 放在与应用无关的 `@notnotype/nb-host/network`，`nbook.network` 插件只持有设置项、服务键与页面。不做本机中继；SOCKS5 地址拒收，提示改用代理软件的 HTTP 端口。出口不做重定向：模型请求 `redirect: "error"`，列表与探测 `manual`，网页工具保持现状。
6. **角色的默认思考档是一次解析的属性**（阶段 A 已实现）：角色可设 `effort` 与 `icon`；`ModelResolution` 带 `defaultEffort`，不写进按模型缓存的信息；请求的档位按“会话选的、角色默认档、不发”解析。

理由：

- 决策 2、3：OMP 的目录工厂与缓存把“服务商身份”当作键，而我们的实例可以改地址、认证与协议，用它会把别人的缓存与凭据套到实例上；元数据与映射函数是纯数据，复用没有这个问题。
- 决策 4：请求落到哪里取决于 `Model.provider` 与环境变量两处隐含输入，只在解析时核对管不住解析之后的变化，所以在最后一层核对。
- 决策 5：本机中继要多一个常驻进程与一套信任边界，收益只是 SOCKS5；Bun 的按次代理足够 HTTP 代理与直连。
- 决策 6：同一个模型绑给两个角色时各用各的默认档，缓存里只能放模型的事实。

代价：同一份设置的清单随机器的来源缓存而异；模型请求多一层发送前核对与响应上的 `origin` 字段（会话日志加可选字段，向后兼容）；不支持 SOCKS5。

## 后果

- 阶段 A 先合入决策 6；决策 1 至 5 在阶段 B、C 实现，各自改 Spec 时引用本 ADR。
- 角色设置写了 `effort` 或 `icon` 之后再装回旧版本，旧版本会把整个角色设置项当成无效丢弃；不做保护，发布说明写明（`models/service.md` 的“降级”）。
