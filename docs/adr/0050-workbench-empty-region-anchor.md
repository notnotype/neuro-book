# ADR 0050：空区域由它的锚来画：区域显示着又没有分节时锚进呈现树，被拖空才自动隐藏，隐藏由布局库保证

- 日期：2026-11-12
- 决策者：开发者（试用 t24 后要求右栏拖空后还能打开；实现方式经 t25 计划确认，设计审查后修订）
- 关联工作：[w00026 t25](../../.agents/works/w00026-layout-package/tasks/t25-container-feedback/README.md)
- 部分取代：[ADR 0046](0046-workbench-view-containers.md) 决策 1 里“锚永远不进呈现树”这一句；0046 的其余决定不变，锚仍不收标签、不移动，区域的隐藏、拖到零、入口顺序、当前容器仍记在锚上。

## 背景

ADR 0046 让三片具名面板当区域的锚，锚永远不进呈现树，区域里没有分节时它就不占地方。t24 照此实现，并在工作台的归整里让区域一个容器都没有时隐藏锚。右栏、底部面板的入口条排在第二步，于是用户把右栏唯一的视图拖走以后，右栏隐藏，标题栏的开关点了也打不开（区域里没有东西可显示），只能用“移动到”的“新容器（右栏）”把视图放回去。开发者 2026-11-12 试用后报了这个问题，选了 VS Code 的做法：开关照样打开空区域，里面写“把视图拖到这里”，整块是落点。

## 决策

1. **空区域由锚来画**。区域显示着、里面一个分节都没有时，锚进呈现树，画成一块空面板；区域里有分节时锚照旧不进。可见判定仍只有一个（0046 决策 3），锚的那一条改成“没隐藏、区域里没有分节”。
2. **空区域整块是一个落点**，放下去在这个区域成为一个容器的唯一分节：来源是它容器唯一的视图时，整个容器搬过去，容器 id 不变；否则是宿主给的新容器（同活动栏入口之间新建的容器）。整窗拖动不在空区域停靠。
3. **区域在被拖空的那一次结构操作里自动隐藏，这是布局库的不变量**：库的结构操作收尾时比较操作前后，区域原来有分节、现在没有，就隐藏它的锚。用户自己打开的空区域没有“拖空”这一步，留着，刷新后还在。提交、拖动预览、判定几何都经过库的操作，所以预览里区域被拖空时同样收起。同一次操作先把区域拖空、又放回同一区域的复合操作，要自己显示区域。
4. **区域没有当前容器时，落进去的容器就是它的当前容器**，库在写归属时一并排进入口顺序。拖动预览里放进空区域的新分节因此看得见；这不算 0046 决策 5 说的“预览切换当前容器”：区域本来没有当前容器，没有从哪个容器切走，判定几何里也不会缺了谁。

## 备选方案

- **开关在区域空着时变灰**：模型不动，但右栏、底部面板拖空后只能经“移动到”放回，开发者否决。
- **区域空了不隐藏**：拖走最后一个视图后留下一块空面板，多数时候用户要再点一次开关才收起；VS Code 也是拖空即收起。
- **给空区域放一个内置的占位视图**：占位视图要进容器、进入口顺序、能被拖动，处处要排除它。
- **“拖空就隐藏”放在工作台的提交里**（t25 计划第一稿）：判定只用文档自己的字段，放在工作台就要让每个产出“将要显示的文档”的地方各接一次（提交、各条预览路径、判定几何、库内的落点指示、Lab 夹具），漏一处就是预览与提交不一致。t24 放在工作台归整里没有记录的理由，推断是那时锚永远不显示、隐不隐藏只影响“显示”按钮的结果。

## 后果

- 读“锚不显示”的地方要认空区域里的这块面板：投影（区域节点就是锚这片叶时也是区域，拖到零照常）、落点（空区域单独一个规则，先问接受矩阵，编辑器标签与文件在这里是被拒绝）、放不下时的收走顺序、区域占用（标题栏开关、公开状态）。卡片四边、场景图、焦点与读屏按投影走，自动认它。
- nb-layout 的落点输入加宿主给的新容器 id，外缘落点可以带容器。
- 工作台的归整只剩入口顺序与当前容器，不再隐藏区域。只经归整、不经结构操作的路径（读记录、视图目录变化）不会清空区域：插件被禁用时分节留着显示占位。打开着的空区域只来自用户打开与布局模板：模板里存着打开的空区域时，新项目照它显示空面板。
