# ADR 0059：官方站第一版一个进程，账号与统计按能拆成服务的边界写

- 日期：2026-11-24
- 决策者：开发者
- 关联工作：[w00037 t03](../../.agents/works/w00037-official-site/tasks/t03-architecture/README.md)；提案 [官方站重写](../proposals/official-site-rewrite.md)

## 背景

开发者决定重写官方站，要求以后能把某一块单独拆出去、甚至换语言重写，并要求后端测试在换语言重写后仍能用。开发者先提出用微服务的思想搭，随后定第一版不拆进程、注意解耦、让以后想拆时不困难。机器按 2 核 2 GB 估算，不设硬性验收口径。

## 决策

1. 第一版是一个 Bun 进程，装着账号与统计两个模块；代码放在本仓库，技术栈与仓库一致（Bun、TypeScript、Hono、TypeBox、Vue 3、nb-ui）。
2. 每个模块是一个工作区包，另有它的合同包（只依赖 TypeBox）。模块包只许依赖自己的合同包与通用包，不许依赖另一个模块的实现包，由读 `package.json` 的测试守住。
3. 每个模块只经自己的连接写自己的库；跨模块的读写只经对方的 HTTP 接口。
4. 模块对外的合同是 HTTP：每个模块是挂在自己路径前缀下的 Hono 子应用，进程入口只做装配。
5. 模块之间只有一个接口“问身份”，从第一版起就是账号模块的一个 HTTP 端点；第一版里统计模块在进程内调用同一个处理函数。
6. 合同测试是黑盒：单独一个测试包，只经 HTTP 与被测进程说话，被测进程由进程入口包的启动命令起；一条源码守卫禁止它 import 合同包之外的任何包。
7. 出现下面任一情况再拆进程：统计写入拖慢了登录；某个模块要换语言；市场的扫描任务上线。

## 备选方案

- **第一版就拆成两个服务**：有进程级隔离；要多做令牌签发与验签、多进程的本地开发与部署，每个进程多占约 100 MB。
- **不分模块的单体**：最省事；以后拆分与换语言时没有现成的边界与测试。
- **合同放在实现包的子路径里**：少两个包；实现包换语言重写或删掉时，前端依赖的合同跟着没。
- **合同测试放在合同包里**：合同包不依赖实现包，仓库按依赖关系选测试时，只改实现选不中它。

## 后果

- 第一版没有进程级隔离：统计入口被刷会连带登录变慢。靠反向代理对统计入口限流、限请求体大小来挡，两个模块的请求耗时分开记。
- 仓库新增七个包与一类要起服务进程的测试。
- 拆分时加第二个入口文件，反向代理的转发鉴权指向“问身份”端点；浏览器看到的合同不变。
