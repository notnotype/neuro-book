# ADR 0048：配方按节组织，节的种类由系统定、同种可以有几个；预设是引用加按项的差异，更新预设不改配方文件

- 日期：2026-11-10
- 决策者：开发者
- 关联工作：[w00042 t03](../../.agents/works/w00042-image-generation/tasks/t03-core-contracts/README.md)、[t07](../../.agents/works/w00042-image-generation/tasks/t07-prompt-workbench/README.md)
- 相关文档：[图像生成第一版：工作台、配方与标签库](../proposals/image-generation-v1.md) 的“配方、节、预设、片段”一节

## 背景

社区提示词有稳定的结构：主体、画风、质量、内容、自然语言、负面。各部分变化的快慢不同：画风串、质量词、负面一用几个月，被整段复制到很多张图里，又常常在某一张图上微调。一半的 V5 社区提示词靠空行分节，因为输入框没有分节的办法。

压力测试拿一万多条社区提示词套进模型，得出几条：
- 如果每种节只许一个，拆进各节再拼回去，词序不变的只有 5% 到 10%；
- 约九成的负面、八成的画风节，和另一条只差不超过 5 项；
- 画师相同的两条提示词，负面里的画师、压制词、质量词、采样参数有 61% 到 98% 也相同。

## 决策

1. **配方的组成。** 配方是作品里的一个文件，带 id，由四部分组成：有序的节、角色框、参数、底图（预留）。
2. **节的种类。** 节的种类由系统定：主体、画风、质量、内容、自然语言、通用、负面。同一种节可以有几个，可以起名；负面缺省分三节。种类决定这些事：内容进请求的哪一部分、能套哪种预设、体检怎样判断放错节、联想与粘贴把词放进哪一节。
3. **预设挂在节上。** 预设是一种节或参数的一份有名字的内容，挂在具体的某一节上，一节最多一个。
4. **引用加按项的差异。** 配方只记引用了哪个预设、改了哪几项。项按规范化后的文字认，改动只有三种：加一项（带锚点）、去一项、改值。
5. **更新预设只写预设文件。** 没改过的项自然跟着变，改过的保持配方自己的值。预设里没了的项，针对它的改动在配方打开或展开时算作作废并提示；不为此去写别的配方文件。
6. **风格组合。** 风格组合是“节的种类与名字，对应一个预设”的一组引用，一次套上；“本书默认”就是默认的组合。
7. **片段。** 片段是纯引用，只记关掉了哪几个陪衬词，不加差异层。
8. **快照。** 每一批生成都存配方当时的样子，以及所引用预设与片段的内容快照。恢复与收藏都从快照取“当时的内容”。

## 备选方案

- **节的种类与个数：**
  - 每种只许一个：粘贴进来的提示词九成以上会被改掉词序。
  - 种类由用户自定义：体检、拆分、联想、跨书复制、Agent 都失去“这一节是什么意思”的依据。
- **套预设就是复制：** 改进画风要改每一份配方。从复制升级到引用时，复制品不记得出处，只能靠猜。
- **一份预设跨几节：** 差异、更新确认、预设库复制都要处理跨节的情况，组合用一组引用就够了。
- **更新预设时顺手改写受影响的配方：** 会和打开着、有没保存修改的配方撞磁盘冲突，编辑器只能“重新载入”或“覆盖”，总要丢一样。

## 后果

- 数据从第一版起就是有序的节列表；界面先只在作者自己加、或粘贴时为了保住词序，才出现多个同种节。
- 每次打开或展开配方，都要和预设当前的内容对一次差异，作废的改动在那时才发现。
- 生成记录要存配方与预设、片段的内容快照，按哈希去重。
- 预设在书里，另有跨书的“我的预设库”；拿进书里是复制一份并记来源，官方预设只读。
