# ADR 0046：工作台加回视图容器：三片具名面板当区域的锚，容器身份记在分节上，不放在树的分支上

- 日期：2026-11-10
- 决策者：开发者
- 关联工作：[w00026 t24](../../.agents/works/w00026-layout-package/tasks/t24-view-containers/README.md)
- 相关文档：[工作台的视图容器](../proposals/workbench-view-containers.md)
- 部分取代：[ADR 0044](0044-workbench-single-layout-tree.md) 的决策 3（“取消 ViewContainer”）；0044 的其余决定不变，一棵树、规范形（决策 1）照旧。

## 背景

ADR 0044 取消容器的理由是“内置视图目前不依赖多视图容器”，那时要解决的是“布局分成几棵树、移动要跨树”。开发者 2026-11-09 要求活动栏一个图标切换侧栏的一整块内容（例如会话与资源管理器一起显示，记住位置与展开收起），右栏、底部面板也一样；容器既能由插件声明，也能由用户拖出来。“不依赖”不再成立；跨树移动仍然不能回来。

两轮设计审查排除了两种放法：容器做成树上“一次显示一个子节点”的分支，会被规范形塌掉（单子分支塌陷、分支上存不了身份）；容器的成员单独存一份清单，每个结构操作（浮出换 id、关掉占位删面板、拖出区域）都要同步它。

## 决策

1. **具名面板是区域的锚**。`sidebar`、`auxiliarybar`、`panel` 三片具名面板留在树上，没有标签，不属于任何容器，永远不进呈现树；骨架判定照旧按锚的位置判。区域的隐藏、拖到零、入口顺序、当前容器记在锚的记录上。
2. **分节是普通的工具面板，一个分节一个标签，容器归属记在分节自己的记录上**。容器的身份不放在树的分支上，规范形怎么塌都不影响它；归属跟着面板记录走，不另外同步。
3. **可见只有一个判定**：没被隐藏；是分节的话，所在容器是区域的当前容器、区域没隐藏。所有读 `hidden` 的地方走这一个判定。
4. **容器身份沿用 [外壳抽象第 3 节](../proposals/workbench-shell-abstractions.md#3-容器身份审查第-14-条)**：隐式容器 `view:<id>`、声明的容器、用户容器 `custom:<UUID>` 三类 id；按实际成员决定出不出现；标题与图标按固定顺序求，不存。
5. **拖动预览从不切换当前容器**：判定的几何是拿起时量的，不活动容器的分节那时不在页面上。

## 备选方案

- **容器是树上的分支**：规范形要开例外，分支要带身份，nb-layout 多一种节点，尺寸求解、停放、焦点、键盘候选逐处认它。
- **容器清单单独存**：每个结构操作都要同步清单。
- **不活动的容器整棵存在树外**：拖进不活动的容器、命令移到别的容器要在树与树外之间搬，就是 0044 取消的跨树移动。
- **区域状态存进新的顶层字段、取消具名面板**：空区域在树上没有位置，要给 nb-layout 加“在骨架的这个位置建一列”的操作，骨架判定要允许几种形状。

## 后果

- 按具名面板名字写的规则（工作台约 36 行、nb-layout 约 10 行）改成按区域问，区域由锚定位；投影给区域在呈现树里的节点配收起策略。
- 布局记录不加版本号；旧记录（锚上有标签、区域里有多标签面板）回落默认布局并覆盖，开着的编辑器标签带过去。回滚代码时要连同清掉布局记录，否则旧代码会把所有容器的分节摊开显示。
- 插件多一个贡献点 `workbench.viewContainers`，视图声明多一个 `container?`。
- 右栏、底部面板的入口条怎么进几何（作树上的条节点有六处冲突）留到第二步另行设计。
