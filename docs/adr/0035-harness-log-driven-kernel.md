# ADR 0035：Agent harness 以会话日志为唯一真相源，内核自写循环，扩展只做四件事

- 日期：2026-10-31
- 决策者：开发者
- 关联工作：[w00032 t20](../../.agents/works/w00032-agent-integration/tasks/t20-hooks/README.md)
- 相关文档：[提案：Agent harness 的事件模型](../proposals/agent-harness-event-model.md)、[`harness/session.md`](../specs/harness/session.md)、[`harness/extensions.md`](../specs/harness/extensions.md)

## 背景

接入 Agent（w00032）时，Profile 的上下文机制与钩子在同一时刻都能往上下文里加东西，钩子点越加越多，回退、重启、预览、压缩各要单独处理。master 的 `nb-harness` 与内核分支 `feat/w00002-harness-kernel` 都把循环套在 OMP 的 `Agent` 上：`Agent` 自己维护一份上下文，harness 每次请求前按日志重新渲染，再等它的异步事件投递。

提案经五稿、四轮审查与一个能跑的原型（53 个场景），实施计划又经两轮审查（第一轮六位审查者 108 条），开发者 2026-10-31 接受。

## 决策

### 1. 会话日志是唯一真相源

一个会话的全部状态（各扩展的状态、输入缓冲区、运行到哪了、批准记忆、标题）都由只追加的日志归约得出，没有另存的状态文件，也没有只在内存里的状态。请求是状态的视图，调用模型与执行工具是副作用，结果写回日志。

日志是会话目录里的 JSONL，几条事件作为一个写入批原子写入；一个会话同时只有一个写者（进程内一条队列，进程间一把目录锁）。

理由：会话是树，回退、fork、重启、压缩、预览都要求“任一节点上的状态”能确定地重建。存在内存里，回退与重启不对；另存状态文件，要给树上每个节点存一份。由日志归约只有一个来源，回退只换叶子。JSONL 保留 t03 定的“会话是文件、可读可拷”，`sessions://<id>/` 映射整个会话目录（t14）。

代价：扩展的归约必须是纯函数（不读时钟、随机数、外部数据），外部数据要先写成事件；日志格式成了长期合同，晚改要迁移。打开会话要从头归约，长会话的性能靠预算（2 万条事件打开 1 秒内）守住，超出时再加检查点快照（快照是缓存，不改格式）。

### 2. 循环由内核自己写，与服务商通信只用 OMP 的 `streamSimple`

不再套 OMP 的 `Agent`（`pi-agent-core`）。模型请求、工具执行、等用户、中止与恢复都由内核按日志驱动；OMP 只负责把与服务商无关的请求发出去、把事件流交回来。

理由：“一条事件的反应全部完成后才算下一次请求”“模型调用可以重试与换模型”“日志是唯一的上下文”三条，与 `Agent` 自己的上下文和异步投递的事件对着干；master 的模块头注释里已经写着为此做的等待。

代价：循环、工具并发、中止宽限期、恢复要自己写、自己测。改了 t02 决定 1 的“代码以分支为主体”：运行时这一层按语义参照分支，存储写入与工具参数校验的调用方式仍取自分支。

### 3. Profile 与插件都是“扩展”，只做四件事

扩展只有四种能力：归约（事件 → 自己的状态）、反应（事件写入后补记事件，可做 I/O）、视图（状态 → 请求的片段）、拦截（输入、模型调用、工具、压缩之前或之后改或挡）。对话记录本身也是内置扩展；Profile 是拦截链最里层、地位最高的扩展。常见写法（提醒、开场、缺省布局、常见的提交写法）做成只用公开接口写成的 helper，不做成字段。

理由：一个模式解释全部扩展点，回退与压缩后的正确性由“状态从日志归约”统一给出，不靠每个钩子各自处理；Profile 的特殊地位只体现在顺序上，不需要第二套机制。

代价：插件要写的概念变多（片、作用域、契约与依赖），靠两级文档与 helper 缓解；扩展是受信任代码（ADR 0022），请求可被任意修改，靠修改记录追查。

## 后果

- `nb-harness` 里新写 `src/kernel/`，迁移 Task 把 nb-story 与 nb-agent-ui 改到新内核后删旧实现，`nb-session`、`nb-profile` 停更。
- 日志格式（事件名、会话头、写入批、大块内容）在 [`harness/session.md`](../specs/harness/session.md) 定，格式版本从 1 起。
- 让这条决定失效的条件：要在多个进程里同时写一个会话，或要求不经日志的临时状态（例如只在内存里的流式状态影响下一次请求）。
