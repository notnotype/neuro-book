# ADR 0063：账号的登录、注册、改密码与管理操作由账号模块自己做，Better Auth 只管会话与协议

- 日期：2026-11-24
- 决策者：开发者（主会话汇报了这一做法与代价之后，开发者答“都按照你推荐就行”）
- 关联工作：[w00037 t07](../../.agents/works/w00037-official-site/tasks/t07-identity-core/plan.md)（计划第 9 节的 13 个探针、文末“主会话的审定”与两节设计审查的处理）
- 细化：[ADR 0060](0060-official-site-identity-on-better-auth.md) 决策 1、4 的做法。部分取代：ADR 0060 决策 5 第二条；其余决定不变。

## 背景

ADR 0060 定了账号建在 Better Auth 上、库的私有协议由自家路由包一层。写 t07 的计划时，在真实的 Better Auth 1.7.27 与 bun:sqlite 上探出“包一层库的端点”有四处不是小补丁：

- 库的注册把算密码哈希包在跨 `await` 的事务里。账号库只有一条业务连接，事务跨 `await` 时别处的写会被收进它的事务、随它回滚。
- 库的登录在账号没有密码时不算哈希，响应时间能分辨账号是否存在。
- 库删会话与写审计不在一个事务里，而审计要求与操作同时生效。
- 库没有注入时间的口子，合同测试拨不动会话到期。

设计审查又查出库的登出会吞掉删会话的失败、照样回成功，库读会话遇到到期的行会自己删。

## 决策

1. 登录、注册、改密码、资料、同意、邀请码与管理操作由账号模块自己的路由做：自己校验、自己算哈希（事务之外）、用自己的 SQL 写库的表，存法与库的一致。
2. 库只负责：发会话与设 Cookie、认 Cookie，以及 t08 的协议部分（社交登录与对外的 OIDC）。模块在发会话时经库的内部接口（建会话、设 Cookie、开库的事务）把自己的写与发会话放进同一个事务。登出不经库的端点：模块在写事务里删会话行，再取清除 Cookie 的响应头。
3. 自己改密码时保留当前会话、其余会话失效；改角色、管理员重置密码、封禁删掉全部会话。这取代 ADR 0060 决策 5 第二条里“改密码删掉全部会话”的写法。
4. 库的版本钉死在评估过的那一个。升级时重跑账号包里覆盖库内部接口、库的表的存法与库内行为的用例，并比对库导出的表结构与包里的基准文件。

## 备选方案

- **照 ADR 0060 原来的做法，包一层库的端点**：四处问题的补丁要散在密码回调、请求级状态与钩子三处，每次升级都要重新确认补丁仍然成立。
- **会话也自己做，账号核心完全不用库**：t08 的社交登录与 OIDC 插件建在库的会话上，那样 t08 也要自己接会话或也不用库，等于推翻 ADR 0060。

## 后果

- 依赖库的四个内部接口（建会话、设 Cookie、开库的事务、取事务上下文），库的版本因此钉死。
- t08 的社交注册由库在它自己开的事务里建账号，模块扣码与建账号的代码要跑在库的事务里；库里不取当前事务的调用（已知 `reserveVerificationValue`）列进 t08 的接缝与升级清单。
- ADR 0060 后果最后一条里没核对的三项，前两项因此有了结论：登录后把旧哈希换成新算法由模块做（条件更新，不覆盖期间被改的密码，t07 探针 p4）；限流由模块自己做、不用库的限流。刷新令牌在封禁与重置密码之后的行为仍归 t08。
- 账号模块的代码比“包一层”多，但会话之外的规则都在自己的代码里，测试能注入时间、能核对失败的耗时。
