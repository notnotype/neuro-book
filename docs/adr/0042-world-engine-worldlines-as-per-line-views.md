# ADR 0042：世界线是每条线一份线性视图，复用现有引擎；日志加线与分叉

- 日期：2026-11-05
- 决策者：开发者
- 关联工作：[w00039 t32](../../.agents/works/w00039-novel-writing-plugins/tasks/t32-plot-side/README.md)
- 相关文档：[作者视角的世界引擎：剧情侧（第一版）](../proposals/world-engine-plot-side.md) 的“世界线”小节；原型与实测在 t32 的 `evidences/worldline-prototype.txt`
- 部分取代：[ADR 0037](0037-world-engine-story-change-log.md)“后果”里“以后加故事时间、世界线时，换掉位置模块，日志与补丁的形状不变”：世界线不换位置模块，而是日志加线与分叉、引擎不改；0037 的其余决定不变。[ADR 0039](0039-world-engine-segmented-revision-log.md) 的分段日志与重放不变，日志的格式版本加一

## 背景

回溯、平行世界、梦境、IF 线与 RP 读档都要世界线。第一轮设计审查指出：把引擎改造成认识世界线，结果、快照、缓存都要加一维“线”，两个引擎与差分测试整体重写。开发者 2026-11-04 说明世界线的条数不多（不超过三位数，绝大部分只有几条），问进内核为什么会贵。按线过滤的原型在分支上的真实引擎上跑通了回溯、多层分叉、跨线计划与增量更新。

## 决策

1. **世界线是有 id 的对象**，根线是主线，不复用剧情线。线由分叉产生，分叉是一种剧情变更（父线、切口、触发、往回多久、种类、带过去的地址、结束方式）；剧情变更与核对点的安放、读取位置都带线（开发者 2026-11-04）。
2. **每条线一份线性视图，交给现有引擎原样算**：一条线看到的世界 = 祖先线上安放不晚于切口的变更与核对点 + 带过去的值 + 本线的变更。带过去的值是内部事件（取父线在触发处的值，排在切口之后），不是作者的记录。子线自己的变更必须安放在切口之后，越界的写入拒收。
3. **计划按写下的先后跨线**：安放在切口之前的，以及安放在切口之后、分叉之前已经写下的计划，随子线走、在子线上只读；改计划本身（取消、改内容、挪安放）看得到它的线都变；替换是新写的计划，只在它写下的线上（开发者 2026-11-05）。
4. **哪些线要更新，在更新时按值比对**：按线树从父到子，变了的变更出现在这条线改动前或改动后的视图里，或者带过去的值变了，就更新这条线；带过去的合成事件由线层换算进变更引用。不预先推算：原型复现了预先推算的两处漏算（变更挪过触发处、只改列表元素的子字段），按值比对后与从头重建一致。
5. **当前线常驻**，别的线用到才建、按最近使用留几份；淘汰只丢派生的缓存，重建后与没淘汰时逐字相同。

## 备选方案

- **把引擎内部改造成认识世界线**：结果、快照、缓存都加一维“线”，两个引擎与差分测试整体重写。按给定的线数，线性视图就够。
- **用“恢复”变更代替世界线**：回溯与读档都能承接、内核更省，但原线不能接着写，平行世界与 IF 线做不了。
- **分支做成独立的世界副本**：内核不变，但存储翻倍、两份日志各自演化，改父线的设定传不到副本。

## 后果

- 引擎与差分测试照旧，按线跑；新写的是线层：视图过滤、带过去的值、计划的跨线规则、按值比对的更新、越界拒收。
- 改初值这类影响前缀的写入，要重算每一条已建好的线，所以只让当前线常驻。原型：1000 章、第 500 章分叉，建一条线与建整本相当，内存按前缀算。要同时常驻很多条线，或者线数远超三位数时，这个取舍要重新评估。
- 两条线合回一条不在第一版。
