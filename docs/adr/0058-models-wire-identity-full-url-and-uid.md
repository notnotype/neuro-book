# ADR 0058：发送前核对比完整线地址，部署身份认实例的 `uid`，签名型协议另带凭据身份

- 日期：2026-11-22
- 决策者：开发者（w00032 t43 第三轮计划审查后的决定 26 至 29，与同轮审查结论里主 Agent 定、开发者没有异议的办法）
- 关联工作：[w00032 t43](../../.agents/works/w00032-agent-integration/tasks/t43-models-ux/README.md) 段 B1（计划见同目录 `plan.md`，审查处理见 `evidences/design-review-r3-disposition.md`，核对见 `evidences/b1-probes.txt`）
- 相关文档：[`models/service.md`](../specs/models/service.md) 输出 21 至 24、[`harness/models.md`](../specs/harness/models.md) 输出 21、22
- 部分取代：[ADR 0057](0057-models-ux-sources-identity-egress.md) 决策 4 里“核对请求的源”“`deployment` 是实例 id 加有效地址与协议的哈希、不含凭据”与中性身份的名字 `nbook-compatible`；其余决定不变。

## 背景

0057 决策 4 定了在最内层发送前核对、回复带 `origin`、还原签名要求整组相同。第三轮计划审查与 B1 开工时的核对（`b1-probes.txt`）查出几处不够：

- pi-ai 按环境变量改址时，有的只改路径、主机不变（`MOONSHOT_BASE_URL` 指向同主机的另一条路径）：只比源拦不住，密钥会发到同一主机上用户没配置的路径。
- 用实例 id 做部署身份：用户删了服务商再用同名、同址重建，新实例拿到旧实例的 id，旧日志里的签名会被当成同一个部署送回。
- 签名绑定凭据的协议（Anthropic、Gemini、OpenAI Responses）：同一地址换了密钥（换了账号）后，旧签名对新账号无效，送回会被服务商拒绝或串号。
- 中性身份的 id 进 nb-harness：nb-harness 的应用中立检查不许出现应用名，`nbook-compatible` 被拒。
- 实现审查又查出：只比较 OMP 身份与部署时，同一实例从一个型号换到另一个型号会带着旧型号的签名；认证头换了账号而密钥没变时，凭据身份与“解析后是否变过”都看不出来。

## 决策

1. **核对完整线地址**：每个请求发出前核对源、路径与查询：必须是这一协议在有效地址下会请求的那几个（各协议的固定后缀与允许的查询参数），地址里不能带用户信息；不认识的后缀一律拒绝。另核对解析之后实例的 `uid`、有效协议与地址、认证方式与密钥都没变。
2. **部署身份认 `uid`**：每个服务商实例创建时生成随机 128 位的 `uid`，永不复用；`deployment` 是 `uid`、有效协议与有效地址的哈希。v1 设置里的服务商读作 `legacy:<id>`。
3. **凭据身份**：签名绑定凭据的协议（OpenAI 兼容的 completions 之外），`origin` 另带 `credential`：认证输入（密钥与生效的服务商、模型请求头——自定义的 `Authorization` 这类头能盖过密钥）经安装密钥（状态根里随机生成的文件，0600）做的 HMAC，不含原文、不进展示。安装密钥丢失或损坏时重新生成，代价是旧回复的签名不再送回。
4. **中性身份叫 `generic-endpoint`**。
5. **作答的模型也在身份里**：还原签名比较 `origin` 的 OMP 身份、协议、模型、部署与凭据；同一实例换了模型，旧签名不送回。没有 `origin` 的旧日志只核对实例，模型 id 照历史交给 OMP，由它按模型再判。
6. **拦下即结束**：发送前核对拦下一个请求时，整次调用立即结束（不让 OMP 对本地抛错按退避重试）。

## 取舍

- 完整地址按协议列白名单，宁可误拒（用户改地址、去掉改址的环境变量），也不把密钥发到配置之外的路径。代价是 pi-ai 以后给某个协议换了请求路径时要跟着改白名单（测试会先失败）。
- 凭据身份用随机的安装密钥做 HMAC，不用无密钥的哈希：日志里的值不能被拿去离线猜短密钥。

## 后果

- `harness/models.md` 输出 21、22 与 `models/service.md` 输出 24 按本 ADR 写；0057 的其余决定（模板化实例、清单的真相源、发现与缓存自己做、出口只选路、角色默认档）照旧。
- 解析之后改了服务商的协议、地址、认证方式或密钥，进行中的会话下一次请求为 `endpoint-mismatch`，下一轮重新解析即恢复。
