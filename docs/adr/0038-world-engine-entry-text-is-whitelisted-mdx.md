# ADR 0038：世界引擎条目的主文字用 MDX，按白名单解释语法树、不执行代码；给 Agent 的渲染用带值写法

- 日期：2026-11-02
- 决策者：开发者
- 关联工作：[w00039 t02](../../.agents/works/w00039-novel-writing-plugins/tasks/t02-story-model/README.md)
- 相关文档：[作者视角的世界引擎内核（第一版）](../proposals/world-engine-kernel.md) 第四部分第 7 节；MDX 实测在 t02 证据 `mdx-probe-2026-11-02.txt`

## 背景

条目的主文字既是作者写的设定，也是这个条目的主视图，要能引用本条目与别的条目的字段（`{panel.魔力}`），让作者写的视图参与 Agent 的上下文。条目的文字是项目数据，可能来自模板或别人分享的世界观，不能像 Profile 那样直接执行。三轮审查里，审查者两次推荐改用项目已有的 Markdown 方言加一小块插值：MDX 与章节的方言不一致（中文标点旁的 `**` 不成粗体、方言的标签与“认不出就原样保留”在 MDX 里没有），作者的编辑器要另做一套。开发者看过这些证据后，两次确认继续用 MDX。

## 决策

1. **条目的主文字用 MDX，不复用项目的 Markdown 方言**（开发者 2026-11-02，第二轮审查后再次确认）。理由：表达力更强；条目里的 MDX 大多由插件作者和 AI 写，AI 会写 MDX。
2. **条目里的 MDX 按白名单解释，不执行 JS**：只放行取字段、字面量、比较、逻辑、条件、少数内置函数，标签只有内置的几个；程序自己解释语法树，结果只取决于输入；写入时编译检查（白名单由主会话提出，开发者未反对）。插件随包发布的 MDX 与插件代码同样受信任（ADR 0027）。
3. **给 Agent 的渲染用带值写法**：`{地址 = 值}` 是可以改的字段，`{表达式 -> 值}` 是只读的计算结果（开发者 2026-11-01 认可带值写法）。带值写法是一种独立的可读格式，有自己的解析与回写协议，不当作 MDX 解析。
4. **作者在界面里怎么编辑主 MDX，先不考虑**（开发者 2026-11-02），以后另找办法。

## 备选方案

- **项目 Markdown 方言加 `{路径}` 插值与少数标签**（审查推荐）：与章节同一个编辑器，复用 nb-markdown 的扩展点与往返保证。开发者选 MDX 的表达力，不采用。
- **真 MDX，表达式在隔离环境里执行**：`Date.now()`、死循环、全局对象让结果不确定，隔离与限额的代价高。不采用。
- **只要字段占位、不要表达式**：表达力太弱，条件与格式化都写不了。不采用。

## 后果

- 条目与章节的写法不一致：同一句带中文引号的粗体，在章节里是粗体，在 MDX 里星号留着（有第三方插件 remark-cjk-friendly 可补）；方言的批注、高亮等标签在条目里不能用。
- 作者编辑主 MDX 的界面是一项另外的工作，量级与现有方言的编解码相当；在找到办法之前，条目的主文字主要由 Agent 与插件模板写。
- 白名单的文法、地址写法、块的切分、带值写法的解析与回写，在 Spec 里写定。
