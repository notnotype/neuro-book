# ADR 0047：图像提示词存成每项带数值权重的项序列，不是括号树；展开结果与后端写法分开

- 日期：2026-11-10
- 决策者：开发者
- 关联工作：[w00042 t03](../../.agents/works/w00042-image-generation/tasks/t03-core-contracts/README.md)
- 相关文档：[图像生成第一版：工作台、配方与标签库](../proposals/image-generation-v1.md) 的“提示词模型”与“生成”两节

## 背景

图像生成插件要编辑、检查、拆分、复用 Danbooru 标签式的提示词。

NovelAI 的写法看着像括号嵌套，其实是线性的：
- 每个 `{` 或 `]` 给右边全部内容乘 1.05，每个 `}` 或 `[` 除以 1.05；
- 括号可以不配对，`::` 关闭所有括号；
- 一个权重可以跨几个标签，甚至半句话。

社区提示词里，约 36% 有一个权重同时管着几段不同用途的词。V5 时期的数值写法 `1.2::词::` 已占加权写法的大多数，负权重也很常见。

插件还要接 SD 与 ComfyUI。SD 的圆括号表示加权，方括号是除以 1.1；V4 以前的 NovelAI 模型不认数值权重。

## 决策

1. **提示词是一串项。** 项有词、句子、片段引用、随机选项、图中文字几种。每项带自己的数值权重，可以为负，缺省是 1。数据上留出“不是文字的项”，给以后的 LoRA、参考图。
2. **不存括号结构。** 读入时按来源写法的规则，算出每个词的实际权重。NovelAI 写法是缺省的读法，圆括号是普通字符，Danbooru 里有大量带圆括号的标签名。识别到 SD 写法，或作者指定时，才按 SD 读。
3. **一节自成一段。**
   - 写出时一律闭合，不写连写的数值权重。
   - 原文本身闭合、又没改过的一节，原样写回；其它按规范写法写出。
   - 跨节的权重在拆节时按每个词的实际权重切开。
4. **展开与写法分开。** 展开配方得到与后端无关的“词加权重”序列；由各后端的适配器按自己声明的能力写成该后端的写法。后端不支持的写法，在界面上提示怎样降级。

## 备选方案

- **括号树：** 表达不了不配对、跨段的权重。读入要猜作者的意图，改一处权重会牵动整棵树。
- **只存原文，用时再解析：** 体检、拆节、预设差异都要在原文上反复解析，跨节的权重也拆不开。
- **展开时直接写成 NovelAI 写法：** 接 SD、ComfyUI 时要把展开逻辑再写一份，旧模型不认数值权重的问题也没有统一的地方处理。

## 后果

- 拆过或改过的节，在“原文”视图里显示规范写法，不再是作者粘进来的样子。这改了工作台第 1 轮静态稿“读进来的原文原样写回”的约束。
- 写出不依赖 NovelAI 对连写数值权重的语义；读入还要等 t02 实测“替换还是相乘”。
- 适配器成为接新后端的唯一扩展点，能力声明要细到模型加档位。
