# ADR 0061：官方站每个模块一个 SQLite 文件

- 日期：2026-11-24
- 决策者：开发者
- 关联工作：[w00037 t03](../../.agents/works/w00037-official-site/tasks/t03-architecture/README.md)（设计审查与第三、四轮探针）；提案 [官方站重写](../proposals/official-site-rewrite.md)

## 背景

提案第一稿用 PostgreSQL：按模块分 schema 与数据库角色、原始上报按月分区、拆进程后支持多个写者。设计审查指出这些理由大多是为以后拆进程预付的，最初选它是上一轮调研为了兼容 Cloudflare，这条路已降为可选。探针确认身份库在 SQLite 上能建表、保留数字 id、验旧哈希、走通对外 OAuth，并且注册码的消费与建账号在同一个事务里。

## 决策

1. 每个模块一个 SQLite 文件（WAL），只有它自己打开；一条源码守卫禁止把别的模块的文件附加进来。
2. 迁移是每个模块自带的纯 SQL 文件，只往前；每个版本的迁移必须让上一个版本照常运行，破坏性的改动拆到下一个版本。
3. 备份用 SQLite 的在线备份方式每晚复制一份留在本机；统计模块的原始上报表不进备份。
4. 合同测试每个测试文件一个临时目录放自己的库文件，不起数据库容器。
5. 某个模块真的需要多个进程或多个副本同时写时，那个模块单独换数据库。

## 备选方案

- **PostgreSQL**：能按角色分权、支持多个进程与多个副本同时写；常驻内存约 200 到 300 MB（估算），合同测试与 CI 要起数据库容器，测试底座要处理实例级的角色。

## 后果

- 一个库文件同一时间只有一个进程写；拆进程之后每个服务各写自己的文件，仍然成立。
- 同一份数据做不了多副本同时写。
- 备份与库在同一台主机上，主机丢失时一起丢；异地副本另定。
