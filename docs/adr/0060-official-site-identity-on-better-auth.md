# ADR 0060：官方站的账号建在 Better Auth 上，对外合同只有自家路由、标准 OAuth 端点与社交回调

- 日期：2026-11-24
- 决策者：开发者
- 关联工作：[w00037 t02](../../.agents/works/w00037-official-site/tasks/t02-selection/README.md)（选型与探针）、[t03](../../.agents/works/w00037-official-site/tasks/t03-architecture/README.md)（审查后的探针）；提案 [官方站重写](../proposals/official-site-rewrite.md)

## 背景

第一版的账号要：用户名或邮箱加密码登录、Google 与 GitHub 登录、凭注册码注册、对外提供 OAuth 服务、管理员管理用户，并导入旧站的账号（数字 id、scrypt 哈希）。协议部分不手写。四轮探针在真实数据库上核对了 Better Auth 1.7.27。

## 决策

1. 身份库用 Better Auth；Google、GitHub 用它的通用 OAuth 插件接入（上游地址可配），生产与测试走同一条代码路径。
2. 账号要邮箱：新注册必填、唯一，第一版不验证、不发邮件；旧账号导入时填 `.invalid` 结尾的占位值并打“邮箱待补”的标记。
3. 对外合同只有三类：自家路由、标准 OAuth 端点、Google 与 GitHub 的回调。库的其余端点不可从外部到达：挂载处用“方法加路径”的精确白名单，默认拒绝。
4. 库私有的协议不进合同：社交登录的发起、授权确认、授权中途登录的续接、回调错误，都由自家路由包一层；合同测试只断言自家形状与标准 OAuth 端点。
5. 库的四处默认行为另外收紧：
   - 登记 OAuth 客户端只许管理员（库默认任何登录用户都可以）；
   - 改角色、改密码、管理员重置密码都删掉该用户的全部会话（库默认只有封禁会删）；
   - 不按邮箱自动合并账号（打开 `disableImplicitLinking`）；
   - 密码注册与社交注册共用同一套用户名规则与可读的错误码。
6. 注册码的检查与消费、建账号在同一个事务里：注册码表与库的表放在同一个库文件里。
7. 用户的数字 id 是稳定的：导入时保留旧站的 id，新账号接着往后发。

## 备选方案

- **自己写账号核心、协议部分用小库**：OAuth 客户端库 arctic 已被作者弃用；可用的授权服务器库要么建在 Koa 上、没有现成的关系库适配器，要么存储全要自己接。
- **单独部署现成的身份服务**（Logto、Keycloak、Zitadel、Authentik、Casdoor、Ory）：前四个与本站同机放不下或基本占满 2 GB；后两个的界面与注册流程要按它们的模型来，用不上 nb-ui。
- **前端直接用库自带的路由与客户端**：省掉包一层；换语言重写时要逐字复刻库的私有协议，合同测试不能原样用。

## 后果

- 每个账号必须有邮箱，这是库的要求。
- 换语言重写时账号模块整体换实现。自己拥有、要迁走的是用户 id、用户名、邮箱、密码哈希（scrypt 与 argon2id 两种前缀）、上游身份的关联、注册码与邀请码、同意记录；会话与库内部的表可以丢。
- 库升级带表结构变化时，重新导出表结构、与上一份比对、手写增量迁移。
- 没有经探针核对的：登录后把旧哈希换成新算法、取不到真实 IP 时库的限流行为、刷新令牌在封禁与重置密码之后的行为。
