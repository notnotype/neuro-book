# ADR 0024：多实例运行时拓扑：项目子进程、内核路由的远程服务与专用 RPC 端口

- 日期：2026-10-07
- 决策者：开发者
- 关联工作：[w00017](../../.agents/works/w00017-application-runtime-architecture/README.md)
- 相关文档：[多实例运行时拓扑](../proposals/multi-instance-runtime-topology.md)（完整方案、走查与切片）、[插件的数据与状态](../proposals/plugin-data-model.md)、[ADR 0022](0022-extensible-platform-and-plugin-trust.md)、[ADR 0023](0023-v2-frontend-backend-stack.md)

## 背景

新应用的内核已在服务端与浏览器各运行一个实例。继续推进 Files 之前，开发者指出三处不足：多个项目同时打开时，一个服务端实例里的插件要自己按项目分开管理数据；设计只考虑了服务端与浏览器，没有 TUI；插件通道只能由浏览器调用服务端，Agent 无法操作界面。插件访问 Storage 与配置的方式也与 t49 命令系统的做法不一致。

## 决策

### 1. 一套内核，按角色运行多个实例

运行位置由宿主声明，内核不列举。实例分服务端（应用级，每个服务端进程一个）、项目（每个打开的项目一个）、浏览器客户端（每个窗口一个）、TUI 客户端（每个会话一个，连到服务端进程）。插件按需为各位置声明入口。

### 2. 项目由内核与宿主管理，运行在子进程

内核提供通用的子实例机制：创建与停止、父先启动后停止、使用者租约、实例身份即代次。服务端宿主定义项目：目录校验、与路径无关的项目身份、项目登记表、锁、为每个打开的项目启动一个子进程并在其中运行项目实例。最后一个租约释放并经过宽限期后关闭项目，子进程退出；服务端停止时先封闭新握手、子实例创建与租约取得，再停止项目与自身。插件的项目级入口只服务一个项目，代码里不出现项目参数。外部请求与数据读取不得隐式打开项目。

选子进程而不是 worker：Bun 的 `worker.terminate()` 打断不了原生阻塞调用（t27 G2），子进程可以单独结束，崩溃与内存不波及服务端。

### 3. 客户端一生只绑定一个项目

浏览器窗口与 TUI 会话启动时绑定一个项目代次或不绑定，直到结束不变；切换项目即重启客户端实例。断线重连时原项目代次已结束，同样重启客户端实例，不把旧绑定改投新代次。客户端插件不处理项目切换。

### 4. 插件之间两种通信：本地服务与内核路由的远程服务

同一实例内用本地服务，可传任意 JS 值。跨实例只用远程服务：TypeBox 声明的合同、内核路由、任意实例之间可达（客户端之间也由内核经服务端转发）、调用方由路由标记（含入口激活代次）、结构化结果与按请求阶段区分的失败码（写请求派发后无法确认结果时为 `unknown-outcome`）、按需以 `onRemote:<服务 id>` 激活，不进入激活依赖图（NeuroBook 自己的弱依赖决定，激活期间的远程调用须有限超时）。插件通道成为远程服务的特例。所有跨实例的边使用同一套对称 RPC 协议，传输可替换：客户端用 WebSocket，项目子进程用进程间通信。内核依赖 TypeBox。

### 5. 内核拥有 RPC 专用端口，HTTP 端口归 `nbook.http`

插件通信不经过 `nbook.http`；`nbook.http` 重启不影响插件通信。`nbook.http` 只服务浏览器原生加载与外部调用方。本条补充 ADR 0023 决策 3：`nbook.http` 仍拥有 HTTP 监听，但不再承载插件通道。

### 6. 插件经服务访问 Storage、配置与密钥

内核为每个调用方入口激活生成各自的服务门面，数据按插件归属，Storage 与配置据此隔离数据；客户端的受控代理经内核签发的消费上下文代表原消费插件访问，上下文不能由业务参数自报。`ctx.storage`、`ctx.config`、`ctx.secrets` 不再由内核注入。密钥归配置插件，只在服务端。所有已声明的配置项可只读访问，写入只限声明者。本条与 t49 把命令移出内核 `ctx` 的决定一致，补充 ADR 0022 决策 2。

### 7. Agent 会话在服务端，可同时操作多个项目

Agent 会话运行在服务端实例，一个会话可同时持有多个项目的租约。`projects://` 列出与指向所有已登记项目，项目身份与路径分离。需要项目里的数据的工具写在插件的项目级入口，项目参数由 harness 注入并经租约路由到对应项目实例；不需要打开项目的工具（例如 shell）写在应用级。

## 放弃的方案

- **单服务端实例，接口显式携带项目身份**：每个插件各自做多路复用与清理，容易串项目、漏清理。
- **项目实例与服务端同一进程**：不能单独结束卡在原生调用里的项目，内存泄漏积累到服务端。
- **worker**：同上，`terminate()` 打断不了原生阻塞调用。
- **插件逐跳转发、内核不路由**：每个插件都要为跨端通信写转发代码；开发者 2026-10-07 改为内核路由。
- **RPC 走 `nbook.http` 的端口**：插件通信依赖一个可重启的插件。
- **把远程协议拆成独立包**：协议就是内核路由的一部分；子路径导出已能满足不跑内核的外部程序。
- **Agent 会话放在项目实例里**：不能跨项目，不开项目就不能用 Agent，关闭项目即中断会话。

## 后果

- 内核增加子实例、远程服务、路由与协议，以及对 TypeBox 的依赖；`nb-runtime` 不再零依赖。
- 每个打开的项目多一个子进程，启动时间与内存需实测并在 Spec 中给出边界。
- 两个端口来源不同：RPC 端口必须校验 `Origin`；https 部署需为两个端口配置证书或由代理分流。
