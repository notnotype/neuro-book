# 判定口径（criteria）

> 本文件定义评测的「尺子」：维度判据、严重度、判定类别、证据要求。所有旅程共用，调整时只改这里。

## 1. 评测维度与判据

六条维度是审视每条旅程的「镜头」，不单独打分。每个维度的判据与实例：

| 维度 | 通过判据 | 记问题判据 | 实例 |
| --- | --- | --- | --- |
| 功能正确性 | 操作完成，结果符合教程/设计预期，产物落盘 | 无反应、报错、结果与预期不符 | writer 写完章节文件存在（通过）；章节文件为空（P1） |
| 可发现性 | 不靠文档提示能找到入口，名字表意 | 入口藏太深、名字歧义 | 顶栏入口逐个点开有内容（通过）；「变更」入口看不出用途（P2 文案） |
| 反馈与状态 | 进行中/完成/失败都有明确提示且是人话 | 无提示、内部术语堆砌、错误重复弹出 | 停止后显示「已停止生成」（通过）；把「Command aborted」原文抛给用户（P2） |
| 错误恢复与数据保全 | 失败可恢复、半截产物保留、刷新不丢 | 刷新丢内容、半截正文消失、恢复死循环 | 刷新后先显示「正在恢复对话」再恢复会话（通过）；失败后重复恢复（P1） |
| 视觉与布局 | 无溢出、无错位、窄屏无横向滚动 | 溢出、错位 | 390×844 下配置中心无文档级横向溢出（通过）；Profile 详情面板窄屏仅约 46px 可见需横向滚动（P2，Task 141 实测） |
| 感知性能 | 加载与操作响应可接受，长操作有进度提示 | 长时间无反馈、无进度 | 首次渲染约 5 秒后完成（记录实测数字，可否接受由用户定） |

## 2. 问题严重度

| 级别 | 定义 | 实例 |
| --- | --- | --- |
| P0 | 阻断继续使用、数据丢失/损坏、安全或隐私问题（发布阻塞） | 创建项目后无法进入工作区；删除/写入误伤无关文件 |
| P1 | 主要功能不可用或明显受损、有数据风险、无可用绕行 | 正文只留在聊天未落盘；刷新后会话内容丢失；停止生成无反馈（Task 140 已记录的 P1 之一） |
| P2 | 体验问题、有绕行、不影响主要目标 | 窄屏 Profile 详情面板需横向滚动（Task 141 实测）；错误原文直抛内部术语 |
| 观察项 | 现象已见但未定性（如乱码、布局抖动），不升级为确定缺陷 | 中文文件名上传显示乱码（Task 141 观察到） |

## 3. 判定类别

| 类别 | 定义 |
| --- | --- |
| 通过 | 页面完成对应操作，并取得可见结果或明确状态变化 |
| 部分通过 | 旅程内部分检查项通过、部分未验证或发现问题（旅程级判定用） |
| 未验证 | 页面可用，但本轮未完成该项操作（缺 provider、缺前置数据等）——不等于失败 |
| 环境阻塞 | 浏览器/服务无法稳定到达功能，不能据此判断业务对错 |
| 发现问题 | 能稳定复现且与产品行为相关，附复现步骤与证据 |

## 4. 问题条目格式与置信度

每条问题必须包含：**场景**（用户在什么情况下遇到）→ **影响**（坏结果）→ **证据**（截图/console/network/文件旁证）→ **原因**（如已定位）→ **位置**（`file:line` 作附注）→ **置信度**。

置信度三档：

- **已验证**：在本次评测中复现或实测。
- **从代码推断**：未复现，依据代码路径推断。
- **猜测**：无直接依据。

## 5. 证据要求

按 [浏览器工具选择](../README.md#浏览器工具) 收集证据，体系不重复定义操作细节；下表仅为使用 CLI 备用入口时的示例，不要求从内置浏览器切换工具：

| 证据类型 | 用途 | CLI 备用示例 |
| --- | --- | --- |
| 页面快照 | 页面结构与可达性 | `playwright-cli snapshot` |
| 截图 | 视觉证据（含窄屏 390×844） | `playwright-cli screenshot --filename=...` |
| 控制台 | JS 错误 | `playwright-cli console` |
| 网络请求 | 失败请求、接口状态 | `playwright-cli requests` |
| 录屏 | 复杂交互流（停止/恢复、Workflow 多 Run） | `playwright-cli video-start` / `video-stop` |
| 文件系统旁证 | 产物是否落盘（章节文件、lorebook 条目、World 时间线） | 读取 Project Workspace 对应路径 |

- 证据存放：临时评测放系统 Temp 下的 Agent 受控目录；current 正式任务放 `.agents/works/<work>/tasks/<task>/evidences/`，legacy Task 继续写原 `.agents/tasks/` evidence 目录。
- 证据进入 Issue/PR 前必须脱敏（CONTRIBUTING 要求）。
- 未验证项不得用 focused 测试或静态分析结果冒充浏览器证据。

## 6. 执行环境约定

- 使用**隔离 State Root + 临时 Project**（Task 141 先例：`NEURO_BOOK_STATE_ROOT` 指向系统 Temp 下的 Agent 受控目录，Source Dev 用独立端口），不触碰用户真实 Project 与在途改动。
- 需要真实数据（真实 World Engine Project、已有 Session）的步骤，在用户明确允许后使用指定 Project；否则标「未验证」。
- 真实 provider 可用性决定 Skill 初始化/章节写作/Agent 会话的验证深度；不可用就如实标注。
- 评测过程不改业务代码、不清理用户数据、不合并/关闭 PR。
