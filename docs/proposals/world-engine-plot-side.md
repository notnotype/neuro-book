# 作者视角的世界引擎：剧情侧（第一版）

[内核提案](world-engine-kernel.md)定了条目、剧情变更日志、修订与 Component，已在分支 `feat/w00039-t29-canon-kernel` 上实现为 nb-canon。本提案补上剧情侧：时间与世界线、谁在场、谁知道什么、伏笔、角色的目标与态度、决策与章级写作指示，以及它们怎样合成给写手的上下文与写完后的检查。讨论、原型与审查在 w00039 t32（`.agents/works/w00039-novel-writing-plugins/tasks/t32-plot-side/`）。

这是第二版。第一轮深入审查（六路，156 条）的核实与归类见 t32 `evidences/design-review-round1-resolution.txt`；开发者 2026-11-04 据此定了四条（第八节决策记录），本版照改。

## 一、问题

开发者 2026-11-04：之前讨论的是内核架构与设定，剧情方面没有仔细考虑。缺口：

1. **时间只有章序**：说不出“过了多久”，放不进“十五岁那年”“三百年前”，不认同一天的平行视角，表达不了开发者自己故事里的“回溯”。
2. **全知问题**：写手拿到全知的上下文，作者借国王与贤者的对话写出勇者的特征，下一章 AI 让卫兵一眼认出勇者；一株草药拿给铁匠和药师，没有地方记“按常理谁认得”。开发者认为这不是 AI 的错：作者不可能一开始把想法全记下来。
3. **记录的精度**：作者记不全也不愿记全，但问到时能当场想出来。
4. **规划剧情的工具没有**：伏笔埋在哪、多久没提、打算在哪回收；角色想要什么、谁和谁冲突；“为什么这样写”的决定与给写手的约束；每章的写作要求。
5. **两种视角**：nb-story（读者视角，已发布）以后最好也建在 nb-canon 上，NeuroBook 既能按作者视角也能按读者视角看（不强求）。

## 二、目标与非目标

目标：

1. 时间能精确记、也能粗略记，能查；支持自定义历法。世界线覆盖回溯、平行世界、梦境与 IF 线，条数不多（开发者 11-04：不超过三位数，绝大部分只有几条）。
2. 谁在场、谁知道什么、什么时候、怎么知道的；读者知道什么单独算；减少全知问题，重要的设定不被写手推出来。
3. 伏笔有账本与检查；角色的长期目标与态度随剧情变；决策带理由与约束；每章有写作指示。
4. 写手的上下文按场景与视角拼出；写完以后程序圈候选、再问窄问题，查穿帮、泄底与违约。
5. 内核只加通用的机制，剧情的语义放进剧情插件（ADR 0027：领域能力皆为插件）。
6. 作者自己的书，读者视图以 nb-canon 为准；与 nb-story 共用时间说法与讲述的公共类型。

非目标：按故事时间读状态（“王历 612 年霜月 5 日那天她有多少钱”）；两条世界线合回一条；角色按自己的目标自主行动（模拟，不在本 Work）；中文时间说法的自动解析；自动发现新伏笔与目标冲突；同一部作品几套历法并存（第二版）；自动改正文。

## 三、当前行为与证据

- **nb-canon**：剧情变更（描述、安放、讲述、涉及、剧情线、补丁、生效状态）、计划与兑现、剧情线条目、待定与核对点、未决问题；位置是一条全序；讲述只有来源、章与原句，没有 id 与段位置，多出来的键原样存下、不校验；字段种类没有“条目引用”，临时 id 替换与还原依赖按一张固定的键表。
- **旧应用**（[对照](../../.agents/works/w00039-novel-writing-plugins/research/2026-11-04-legacy-plot-vs-canon.md)）：bigint 秒的精确时刻、一刻一切面；信息控制是章上 4 个手填文本；伏笔账本与决策没有真实使用的证据。
- **nb-story**（[对照](../../.agents/works/w00039-novel-writing-plugins/research/2026-11-04-nb-story-vs-canon.md)）：天数不能让模型累加；知情最不稳；“读者知道被当成角色知道”是知情题最大的错因；程序圈候选再问窄问题有效。
- **原型**（t32 `prototype/`、`evidences/`）：
  - 时间约束网络与自定义历法（`time-examples.txt`）；
  - 知情、伏笔直接在分支上的 nb-canon 跑例子，确认能做的与要补的（`knowledge-kernel-run.txt`、`foreshadow-kernel-run.txt`）；
  - 世界线：每条线一份按线过滤的线性世界，现有引擎原样不改，回溯两条线各自读对；1000 章时建一条线与建整本相当（`worldline-prototype.txt`）；
  - nb-story 样例书 100 章转进 nb-canon：对象、秘密的知情、悬念与进展、账本的大部分装得下，说法（占 74%）与它推出的知情装不下（`nbstory-coverage.txt`）。
- **模型实测**（第一轮审查的 F1、F2，deepseek-flash）：按程序从真实内核生成的简报，写卫兵那场与星瑾视角各三遍，没有一遍泄露保密事项；窄问题查出了埋好的两处穿帮；记账与答案文件逐项对上。样本小，t26 仍要正式量漏记率与静默错记率。

## 四、方案

### 1. 总原则

- **三种视角**：真相（作者定的）、某个角色（他在场的、知道的、误信的、记得的）、读者（读到哪为止讲出来的）。
- **两种先后**：故事里的事实（状态、在场、知情、目标）按**安放**（作者排定的故事先后：前史序号、章序、章内排序键，以及世界线）折叠；读者看到的东西（揭示、伏笔节点）按**讲述**（读者读到的先后：活页夹章序、段）算。安放缺省是第一次讲到的那一章，所以不写时间、不写补叙的书，两种先后重合。
- **精度三档**：精确（结构化字段、核对）、粗略（一句话、模糊的时间、一条规则）、没记（用到再补：先问作者，或推一个标“推断，作者未确认”）。推断分两档：只对这一场有效的细节（不进世界）与要进世界的设定（进待处理等确认）。每条记录带来源：作者定的、正文写明的、推断的。
- **一条规则**：没记的可以推，推出来的标出来；重要的标保密，保密的不许推。
- **检查分级**：程序能确定的进待处理；有意为之常见的只提示；要判断文字的，程序先圈候选，再让记账 Agent 回答窄问题（引原句），不自动改正文。

### 2. 内核与剧情插件的分界

开发者 11-04 定：内核只加通用的机制，剧情的语义放进剧情插件。

| 放在内核（nb-canon） | 放在剧情插件 |
|---|---|
| 条目引用（第 4 小节） | 知识点、知情、伏笔、目标、态度、决策的 Component 与语义 |
| 讲述的发生点与通用标注（第 3 小节） | 标注的种类：揭示、伏笔节点；它们的校验 schema |
| 在场（第 5 小节） | 读者的知情、伏笔账本、目标表、决策表、写手简报 |
| 时间说法与 `nb-time`（第 6 小节） | 穿帮、泄底、传话链、前提变了、伏笔与决策的检查 |
| 世界线：分叉记录、按线的读取（第 7 小节） | 窄问题的候选与问法 |
| 诊断的贡献点：插件登记的检查在读取时算出、进待处理或提示 | 写作指示的读取（随 t19 定的文件） |
| 决策的存储（未决问题扩成决策，第 11 小节） | 决策的守卫与检查 |

剧情插件的 Spec 放在 `docs/specs/plot/`，内核的放在 `docs/specs/canon/`。以后加一种叙述手法（新的标注种类、新的检查），只改插件、不改内核格式。

### 3. 讲述的发生点与标注

- **讲述有稳定的发生点**：讲述加 id 与段位置（写入时由原句在章内定位算出：第几段、段内偏移），同一章里按段与偏移排先后。改稿后原句找不到的标“失联”，进提示，标注保留。
- **通用标注**：一处讲述可以带几个标注 `{kind, ...}`；`kind` 由插件登记，载荷由插件的 schema 校验，内核只负责存、校验引用、在还原时查依赖。揭示（哪个知识点、暗示或明说）与伏笔节点（哪个伏笔、什么角色、给写手的指示）是剧情插件登记的两种。
- **“只是讲到”的记录**：只是提了一句、世界没变的讲述（一句预言、一处意象），记成剧情变更的一个新种类“叙述”（没有补丁，不进时间网络），情节视图缺省过滤掉它。
- 读者位置细到段：读者读到第 N 章第 M 段为止看过的讲述。

### 4. 条目引用

- 一种统一的引用值 `{ref: 条目 id}`，以及“引用声明”：Component 的字段、列表元素的 id、标注的载荷里哪些路径是引用、允许指向什么种类的条目。内核据这份声明统一做：临时 id 替换、写入时校验存在、删除后的墓碑显示、改动记录按条目筛选、还原时的依赖闭包。
- 第一批要声明为引用的：知情行的元素 id（知识点）与“谁告诉的”、揭示与伏笔节点里的知识点与伏笔、伏笔的答案与依赖的物件、目标的基于与冲突、态度行的元素 id（对象）、决策挂的对象、在场的参与者。原型实测的两个缺口（还原不列依赖、文字字段里的临时 id 不换）都由这一条覆盖。

### 5. 在场

开发者 11-04 定第一版就做。

- 剧情变更记**参与者**：`{who: 条目引用, role: 在场 | 被提到}`，可以附“以什么身份”（马甲）。`involves` 保留为“涉及”（补丁与描述涉及的条目），参与者是它的细化。
- 来源：先写后记时由记账从正文记；先记后写时由计划带出，写完核对。缺省不猜：没记参与者的变更，穿帮检查对它降级为提示，不当作“没人在场”。
- 用处：
  - 简报与穿帮的“在场的人”；有限视角的对白层；
  - 知情可以由在场推出：一条变更标“让在场的人知道了某个知识点”（`揭示给在场的人`），在场的人自动得到“亲历”的知情行，不用逐人写；
  - **经历**：某人在某个位置的经历 = 他在场的变更，加他知道的知识点；角色对话与回溯者的记忆都由它算出；
  - 以后的世界推演：谁和谁在一起决定谁会遇到谁（地点 Component 仍以后做）。

### 6. 时间

- 时间是剧情变更上可选的说法，可以几条，同时成立，精度不限：日历上的日子（到年、月、日、时段或时，可以带“约”）；在另一件事之后或之前、间隔的范围；持续多久；某人几岁那年。每条带原话与依据。出生、建国这类锚点是前史里的剧情变更；年龄是查出来的，不存字段。模糊词表是作品级设置。
- **计算**用时间约束网络（Simple Temporal Network）：说法是“两件事相差 lo 到 hi”，最短路给出最早、最晚可能的时间与依据，负环就是矛盾。日期的精度、约、不确定、开放区间借用 EDTF（ISO 8601-2）的分法，不用它的字符串格式。
- **局部降级**：网络按连通分量算；有矛盾的分量里，环上的说法标“打架”，这个分量的事件返回“不可确定”并列出原因，其余分量照常给范围。新历法里不成立的说法（删掉的月、超出月长的日子）单独标出，不进网络。改了历法或模糊词表，所有范围与依据重算。
- **时间不决定折叠**：状态仍按安放折叠，安放的先后不放进网络（一处安放错了不会让整张网失效）。安放与时间对不上（按安放 A 在 B 前，时间上 B 一定更早）单独报出来，提示挪安放、标平行或改前史序号。前史的序号在写入时按时间在邻居之间取一个数。
- **章的时间方式**：章可以声明“承接”（缺省）、“与第 M 章同时”（平行视角）、“补叙：讲的是某处安放的事”。补叙章的简报按它声明的那个安放读状态，不读“现在”。
- **历法**是作品设置里的数据（一天几小时、各月名字与天数、闰年规则、纪年名、时段名），带版本。存的是作者说的话（按历法的写法），不存换算结果；内存里的绝对时间是从历元起的整数分钟（JS 的数；跨度极长的世界可以把最小单位设成时或天）。
- **查询**：某件事、某章的范围与依据；某段时间里可能、一定发生的事；两件事相差多久；某人当时几岁；某章写到的故事时间；按纪、年、月、日逐级浏览。
- 历法、说法、网络与查询放进无依赖的新包 `nb-time`，nb-canon 与 nb-story 共用。

### 7. 世界线

开发者 11-04 问“世界线进内核为什么会贵”并说明条数不多；原型验证了下面的做法（t32 `evidences/worldline-prototype.txt`）。

**数据**

- **世界线**是一个有 id 的对象（不复用剧情线），根线叫主线。线由**分叉**产生，分叉是一种剧情变更，记：新线的 id 与名字、父线、切口（父线上哪条变更之后）、触发的事、往回多久（回溯时）、种类（回溯、分支、梦境、IF）、带过去的地址、结束方式（继续、回到父线、终止）。
- 剧情变更、核对点的安放带线（缺省主线）；读取位置带线（缺省见下）。
- **带过去的东西**：缺省是回溯者的知情与经历；Component 字段可以声明“回溯时随回溯者保留”（回溯次数、魔力这类消耗：用掉的不回来），分叉时缺省带上，作者可以加减。

**计算：每条线一份线性视图**

- 一条线看到的世界 = 祖先线上安放不晚于切口的变更与核对点 + 带过去的地址（取父线在触发处的值，记成切口处一条合成的赋值）+ 本线的变更。它仍是一条线性的先后，交给现有的引擎算；结果、核对点、嫌疑记录、待处理、按计划模式自然按线分开，差分测试照旧按线跑。
- **当前线常驻**，别的线用到才建，按最近使用留几份。写入只更新已经建好、而且看得到这条变更的线；改初值这类影响前缀的写入，要重算每一条已建好的线，所以只让当前线常驻。线视图随写入增量维护（原型每次从头过滤，约 30 ms）。
- 原型：1000 章、第 500 章分叉，回溯后的线建引擎与不分线整本相当，前 500 章的原线约一半；补记一次只更新看得到的那条线，与不分线同一量级；内存按前缀算（整本 34 MB，半本 14 MB）。
- **回溯者的记忆**：她在原线上从切口到触发处“在场”的变更，加带过去的知情，由程序算出、进她的经历与简报；条目页上显示“记得原线上的……”。

**读取与读者**

- 读取位置带线；缺省是这一章最后一件事所在的线。被抹掉的那段留在原线上：按原线读、或者按“原线上从切口到触发处的变更”列出来看。
- 读者按活页夹的章序读：读者的知情取活页夹里所有章的讲述，不分线；回溯章里被抹掉的那段读者读过就算读过。没有排进活页夹的线（RP 里放弃的分支、作者试写的 IF）不算读者读过。
- 时间网络里，子线上的事不早于“触发处往回多久”的那一刻，只和父线上切口之前的事比先后；兄弟线之间不比。

**改与还原**

- 改分叉的参数（切口、往回多久、带过去什么）先给波及面预览：哪些变更跨过了切口、哪些计划不再成立、哪些已写的讲述受影响。
- 还原的依赖跨线：还原分叉或切口之前、被子线继承的父线变更时，列出子线上受影响的变更，作者选连同还原或保留并进待处理。
- 由分叉自动得到的结果（存款回到原值）不是计划项，审稿不为它要原句。

**作者怎么用**（第 8 章回溯为例）：

- 先记后写：细纲写“回溯到早上”，主 Agent 提的计划里就有一次分叉，预览里看到“星瑾不记得”“存款回到 20,000”“今天的回溯用掉了”；这类章自动走分场推进（第 15 小节），分叉前后各一份简报。
- 先写后记：记账多问一句“这一章有没有时间倒回或跳回”，有就提出分叉，回执里列出切口、往回多久、带过去的东西，作者确认或改；认不出时不静默，进提示。
- 平行世界是两条线都往下走、各章的事各标在哪条线上；梦境与 IF 线结束后回到父线，梦里带回现实的东西用父线上一条普通变更记；多次回溯就是分叉再分叉。

### 8. 知情

- **知识点**是条目（种类“知识点”），挂在它说的那个条目下面，命题写在一句话描述里。只有建成知识点的事才有知情，其余靠常理。保密分四档：常识；行内（按一句规则推）；保密（没记下来的人一律当作不知道，写手不许推）；绝密。
- **绝密**：写手平时只知道“有一件涉及某某的绝密设定”；本章计划要暗示或揭示它时，才把内容给写手，并写明只能写到什么程度（开发者 11-04 定）。
- **知情记在人物（或组织）身上**：一行一个知识点（元素 id 是知识点的引用，一人一点一行），记程度、他以为的那句（误信时）、怎么知道、谁告诉的。程度的含义：知道（认为这件事为真）；误信（在这件事上信了一个错的版本，记在“他以为的”里，可以指向别人，例如“以为凶手是园丁”）；怀疑（觉得这件事可能为真）；不知道；忘了。只听过别人的说法、并不相信的，不加行，可以在“听过的说法”里记一句。
- 知情行由剧情变更加或改；也可以由在场推出（第 5 小节）。传话的“谁告诉的”在那个位置上必须已经知道，否则报“传话链断了”。
- **读者**不是条目：讲述上的揭示标注（明说或暗示）决定读者从哪一段起知道（暗示算怀疑）。不从“角色在讲出来的场景里知道了”自动推读者。
- **提议建知识点**：先记后写时主 Agent 从细纲里提议（“星瑕能回溯”要不要建、标什么档）；先写后记时，正文里有人说出或按一件没建成知识点的事行动，记账提议建（问作者），并报“正文里有人知道却没有记录”。
- 服务端过滤：写手与角色的只读工具绑定视角人物、章与线，由服务端按知情过滤；保密以上的知识点对不知道的人返回占位；被拒的查询记下来。

### 9. 伏笔

- 伏笔是条目（种类“伏笔”）：名字写“许了读者什么”，主文字写打算怎么回收（回收那一章才给写手）。字段：种类（埋设回收、悬念、预言、意象）、重要程度、作者的意图（进行、放弃）、悬念的答案（知识点）、依赖的物件（条目引用，例如那座钟）、参考间隔。
- **节点是讲述上的标注**：埋下、呼应、误导、部分回收、回收，可以带给写手的指示；位置是那处讲述的发生点（章与段）。一章里可以有几个节点。阶段由节点算出、不另存：未埋、已埋、呼应中、部分回收、已回收（误导算呼应，不往回拉）；放弃的显示“放弃（已埋）”。
- **计划**：细纲那处讲述带节点标注；兑现计划的已写变更，按讲述发生点继承计划上的节点（自己标了的除外）。
- **悬念连答案知识点**时，读者对答案的揭示自动算节点（暗示算呼应、明说算回收）。一个知识点被几个悬念认领时都算，并提示作者确认。
- **检查**：进待处理的是没埋就回收、计划的节点那一章写完了却没有、回收以后又埋、泄底（见第 13 小节的读者层）；只提示的是已埋没排回收、太久没提、放弃了但正文还留着埋下的句子、没有悬念认领的暗示、**依赖的物件在回收之前被动过**（钟被拨了）。

### 10. 角色的目标与态度

- 只结构化长期目标，只给主要角色建。目标是条目（种类“目标”），挂在持有者下面，和别的状态一样按安放折叠：状态（进行、受挫、达成、放弃）、轻重、层次（想要或需要）、为什么、基于（知识点）、冲突（一行一个对方目标）、后继。隐秘的目标同一个条目再加知识点的 Component。
- **态度**是人物上按对象的列表（元素 id 是对象的引用）：态度（语义档）与起因（知识点）。内核要放开：列表元素的子字段允许语义档（补丁与归纳缓存按元素地址记）。
- **弧光**是几条计划加一条剧情线。
- **检查**：前提变了（目标基于的知识点，持有者那一行变了而目标之后没被触及）进待处理；缺一步、停滞只提示；行为与动机不符不自动查，作者点了才问窄问题。

### 11. 决策与章级写作指示

**决策：未决问题长大**

- 还是内核六种对象之一，状态只由修订改变。状态：待定（候选、最晚第几章前要定）、已定（结论、理由、风险、约束、可选的守卫）、被取代（指向新的）、放弃；已定可以重新打开。挂的对象是引用的联合（条目、剧情变更、地址、章、另一条决策），可以限定章的范围。每个状态的必填字段与允许的转换写成表，在 Spec 里定。
- **作者原话的来源**：已定、放弃、重新打开都要带一个不可伪造的来源：作者在对话里的某条消息（消息 id、会话、原文与引用范围），或作者在界面上的确认。只有系统能从这两种来源生成；Agent 只能建待定的候选，或“作者未确认”的建议。理由没说的不许编。
- **守卫**：某个地址在范围内不准取某些值，在范围内每一条变更之后检查（不只章末）；按计划模式另给一份结果。守卫也可以挂在读者的知情上（“第 20 章之前读者对‘管家是凶手’不得是知道”），由读者层的计算检查。
- **检查**：违反已定的约束、写死了未定的事、到期没定（写正文前拦一下，作者可以选照写）、悬空；泄底与穿帮的诊断附上相关的决策。

**章级写作指示**

- 挂在活页夹的章上、和细纲放在一起，不进世界；文件、版本与并发随 t19、t11 的项目布局定。nb-canon 与剧情插件只消费“章的写作指示快照”，写手与记账任务固定开始时的那一版。
- 字段（都可选）：读完这一章读者该有什么变化、视角人物与视角方式（第一人称、有限、全知）、章的时间方式（承接、平行、补叙）、语气、开场、结尾、不写的、其他（重写要求）。
- 旧版的四项信息控制不再手填：由揭示、知情、保密分档与计划推出。能写成世界状态的进计划；计划与指示矛盾时并列报出；同一条指示在几章反复出现，建议升成决策。剧情线上的写作指示是一条挂在线上的已定决策。

### 12. 写手的上下文

由程序拼，不由模型生成。第一轮 F1 的体验（`design-review-F1-writer.txt`）定下这些规则：

- 组成：写作指示 + 细纲 + 本章计划（只写细纲没有的：状态变化、谁知道了什么、节点；不给可能被抄进正文的摘要句）+ 简报 + 涉及条目的样子 + 上一章末尾一段正文 + 目标字数。
- 简报：在场每个人此刻在追的目标与为什么、对在场其他人的态度、他知道与误信的保密事项（误信给他以为的那句）、行内规则；本章要埋、呼应、回收的伏笔（回收时才给真相），还不能回收的只给“许了什么”与“不要点破”；涉及本章的已定决策与待定事项；“读者已知”一行（读者已经知道、角色还不知道的，反讽在哪）。
- 有限视角下，叙述对人的称呼用视角人物知道的身份（星瑾只知道“哥哥”，叙述不出现“星瑕”），由马甲与“甲就是乙”的知识点算出。
- 保密的真相只在知情一段出现一次，不散在“在场的人”里。
- “本章允许新增什么”（场景细节可以编、不许新增世界事实或改变结果）与自陈的格式：新出现的名字与事实、拿不准的、偏离细纲的。
- 回溯、补叙这类章：分叉前后、补叙所在的安放各一份简报。

### 13. 写完以后的检查

- **窄问题分层**，每层的候选由程序圈出，记账 Agent 逐条回答（引原句）：
  - 在场层：本章涉及的保密以上知识点 × 在场且不知道（或误信）的人；问法分“有没有按真相说话或行动”与“有没有按他的误信”，并问误信的来源；
  - 叙述层：有限视角下，视角人物不知道、误信的保密事项，问“叙述有没有写出她不知道、看不到的”；
  - 读者层：有揭示计划的保密以上知识点，在计划揭示之前的每一章问“读完这一章，读者能不能确定……”，答能就报泄底（强暗示不会因为被标成“暗示”而漏掉）；
  - 伏笔物件层：本章碰到伏笔依赖的物件时，问“这里动到了伏笔的前提吗”；
  - 时间层：本章有没有时间倒回或跳回（认分叉）。
- **上限与优先**：每章窄问题有上限，按绝密、保密、读者层、伏笔、其它排；超出的合并成一条提示。
- **待处理**：每种诊断有稳定的键（规则、对象、线、讲述发生点、范围）、根因与生命周期；同源的合并成一项；作者处理（确认、改、标“有意为之”）后不再报；提示有升级与抑制规则。新的种类：可能穿帮、提前泄底、传话链断了、正文里有人知道却没有记录、前提变了、违反已定的决定、写死了未定的事、到期没定、违反写作指示（视角越界等）、伏笔的几种、时间说法打架、安放与时间对不上、分叉的时间与切口对不上。
- 读取视图：保密账本（每个知识点：谁知道、读者从哪一段起知道）、读者现在知道什么、改揭晓章的依赖（哪些计划、节点、决策、写作指示提到它）。

### 14. Agent 与系统

依据写作流程草稿（t19，开发者未定稿）与一个 Sonnet 子代理的独立设计（t32 `evidences/agents-independent-design.md`），细节在 t20 定：

- 主 Agent 是作者唯一的对话对象；写手与记账是插件的后台任务（程序备料、一次生成或几步管线），审稿是记账管线的预览（结果按正文与世界版本缓存，记账可以复用）；角色对话与以后的推演、RP 是会话，只读，按角色视角过滤。
- 工具：内核原有的六个，加时间的查询与写作任务；知情、伏笔、目标、决策并进 `read` 的地址（账本、谁知道某件事、某章的简报预览、某章的工作单），找不到时再拆成单独的工具。
- 上下文与书长无关：输入都按位置与涉及的条目取，没有读全书的路径；返回有条数与字数上限、续读游标；用法说明首次出现与压缩之后补一次；每章有调用预算，回执写花了多少。
- 防乱写：写手没有写权，自陈不当事实；推断标出来等确认；已定的决策 Agent 不能改；写手任务固定开始时的世界版本，发布前比对；第 N 章没记账不写第 N+1 章。

### 15. 一章怎么转起来

- **先记后写**（细纲在手）：讨论细纲 → 主 Agent 审细纲（吃书、吃设定、严谨，加决策到期、前提变了、会不会泄底、要不要建知识点）并提出计划，作者看预览 → 写手按细纲写 → 审稿（计划逐条要原句，查穿帮、泄底、违约）→ 记账以计划为底只核差额。
- **先写后记**（粗纲，写手自由发挥）：主 Agent 写粗纲加“自由度的边界”（保密名单、已定的决策、不许动的状态与伏笔）→ 写手自由发挥、交自陈 → 审稿（多看自陈）→ 完整记账（新设定标推断）→ 作者确认推断。
- **分场推进**：粗纲拆成几场，每场写一小段场计划、写这一场、记这一场。回溯、补叙、揭晓这类章缺省走它；RP 的一轮就是一场。
- 作者自己写的章走先写后记的记账与确认。

### 16. 对以后功能的检验

- **世界推演**：每个角色只看到自己的那一份（在场、知情、目标、态度，按视角过滤）；推演结果先落成计划，作者挑改；比较几种走向时每次推演开一条 IF 线。要补：修订里记“某 Agent 扮演某角色”、“当时的想法”的落点（人物上的语义档字段，不当世界事实）、**地点**、推演的编排（工作流）与预算。
- **角色对话**：某个位置、某条线上的角色 = 条目、知情、目标、态度、经历（第 5 小节），只读；角色在对话里说出、作者认可的，可以一键记成设定（推断，作者确认）。
- **RP 模式**：一轮是分场推进的一场；天道给的方向是计划；用户扮演的角色也有自己的知情；存档点是分叉点，读档就是从那里开一条新线，原来那条留着可以回看；不排进活页夹的分支不算读者读过。要补：每轮记账的费用与延迟、几轮自动合成一章、主持 Agent 与回合制的会话形态（w00032）、RP 项目模板（t12）。

### 17. 与 nb-story

- 数据层不换：作者自己的书，读者视图以 nb-canon 为准，不再用 nb-story 抽一遍；第三方的书走 nb-story。
- 作者视角投影只保证：对象与状态、在场、知识点的知情与揭示、伏笔、时间说法。nb-story 的带渠道的说法（“某人说”“某人认为”，样例书里占说法的 74%）与它推出的知情、先验等级、整理稿留在 nb-story。
- 共用：`nb-time`（nb-story 的 `day`、`part`、`rel` 映射成相对历法上的说法）、讲述与发生点的公共类型。
- 评测：先做 nb-canon 到 V9 的投影，复用 nb-story 的问答引擎与题库做对照（问答只能证明“不比 V9 差”）；nb-canon 的价值用 t26 的漏记率与静默错记率量。计划与预算在 t32 记录。

### 18. 备选与取舍

- **精确时间轴**（旧 WorldEngine）：逼作者编造精确值，撞时刻就失败。没选。
- **时间决定折叠顺序**：大量事件没写时间，补叙与回溯会让相对加减断掉。没选。
- **安放的先后放进时间网络**：一处安放错了会让整张网矛盾。没选。
- **把引擎内部改造成认识世界线**：结果、快照、缓存都要加一维“线”，两个引擎与差分测试整体重写（第一轮 A 2）。按开发者给的线数，每条线一份线性视图就够，没选。
- **“恢复”变更代替世界线**：回溯与读档都能承接，内核更省；但原线不能接着写，平行世界与 IF 线做不了。线性视图的做法几乎不增加成本，没选。
- **分支做成独立的世界副本**：内核不变，代价是存储与两份日志各自演化，改父线的设定不会传到副本。没选。
- **知情记在知识点上**：反查直接；写一场戏要扫全表，回溯要选择器而不是地址。没选。
- **知情完全由在场推出**：稠密、适合推演；但大多数知识的来源不是在场（传闻、读到、推断），而且会给每个命题建条目、污染条目树。采用“显式的行，加‘揭示给在场的人’从在场推出”的折中。
- **读者从角色的知情推**：场景讲出来了，读者不一定知道。没选。
- **伏笔节点做成补丁**：伏笔条目删了会让真实事件的补丁套不上，位置也成了安放而不是讲述。没选。
- **新增第七种对象（知情记录、伏笔账本）**：要重做位置、世界线、计划、撤销与修订。没选。
- **态度用每个对象一个实例字段**（t16 原型）：对象只是字段名里的文字，改名就断。没选。

## 五、影响

- **数据格式**：讲述加 id、段位置与标注；剧情变更加参与者、时间说法、“叙述”种类与分叉种类；安放与读取位置加线；未决问题扩成决策；字段加引用声明、列表元素允许语义档。nb-canon 还没合并，v2 没有用户数据：世界日志的格式版本加一，旧版本的实现读到新格式拒读（不静默算错），不做迁移。
- **内核要补的**：
  1. 条目引用与引用声明（实测缺口）；
  2. 讲述的发生点与通用标注（实测缺口）；
  3. 在场；
  4. 时间说法与 `nb-time`，局部降级；
  5. 世界线：分叉记录、线视图（引擎原样复用）、线视图的增量维护、读取位置带线、跨线的还原依赖与时间下界；
  6. 列表元素的语义档；
  7. 未决问题扩成决策、作者原话的来源；
  8. 诊断的贡献点。
- **剧情插件**：知识点、知情、伏笔、目标、态度、决策的 Component 与语义；读者的知情、账本、简报、窄问题、检查。
- **接口**：世界服务与远程合同加按线读取、时间查询、简报与账本、诊断；写手与角色的只读视图带视角，由服务端过滤。Agent 工具的参数在 t20 定。
- **成本**：计算都是程序；模型调用只在记账的窄问题（每章有上限）与语义档的归纳。
- **安全**：绝密与保密的内容按视角在服务端过滤，不靠提示词。
- **发布与回滚**：都在内核分支上，合并之前随时可以改。
