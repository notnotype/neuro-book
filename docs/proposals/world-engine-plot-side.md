# 作者视角的世界引擎：剧情侧（第一版）

[内核提案](world-engine-kernel.md)定了条目、剧情变更日志、修订与 Component，已在分支 `feat/w00039-t29-canon-kernel` 上实现为 nb-canon。本提案补上剧情侧：时间与世界线、谁知道什么、伏笔、角色的目标与态度、决策与章级写作指示，以及它们怎样合成给写手的上下文与写完后的检查。讨论与原型在 w00039 t32（`.agents/works/w00039-novel-writing-plugins/tasks/t32-plot-side/`），每一项都先由主会话与一个只拿到目标的子代理各出一版，再合并、交开发者定。

## 一、问题

开发者 2026-11-04：之前讨论的是内核架构与设定，剧情方面没有仔细考虑。具体缺口：

1. **时间只有章序**。nb-canon 的位置是前史的序号加章序与章内排序键，说不出“过了多久”，放不进“十五岁那年”“三百年前”，不认同一天的平行视角，表达不了开发者自己故事里的“回溯”。
2. **全知问题**。写手拿到的是全知的上下文：作者借国王与贤者的对话写出勇者的特征，下一章 AI 让卫兵一眼认出勇者，而作者的意思是特征隐秘；一株草药拿给铁匠和药师，按常理铁匠不认识、药师可能认识，没有地方记这种“按常理推”的边界。开发者认为这不是 AI 的错：作者不可能一开始把想法全记下来。
3. **记录的精度**。作者不可能把每件事、每个人物的一生都记全，也嫌枯燥；但问到时能当场想出来。
4. **作者规划剧情的工具没有**：伏笔埋在哪、多久没提、打算在哪回收；角色想要什么、谁和谁冲突；“为什么这样写”的决定与给写手的约束；每章的写作要求。
5. **两种视角**。nb-story（读者视角，已发布）以后最好也建在 nb-canon 上，NeuroBook 既能按作者视角也能按读者视角看（开发者 11-04，不强求）。

## 二、目标与非目标

目标：

1. 时间能精确记，也能粗略记，能查（记账的 Agent 在很长的时间轴里缩小查找范围）；支持自定义历法；世界线覆盖回溯、平行世界、梦境与 IF 线。
2. 谁知道什么、什么时候、怎么知道的；读者知道什么单独算；减少全知问题，重要的设定不被写手推出来。
3. 伏笔有账本与检查；角色的长期目标与态度随剧情变；决策带理由与约束；每章有写作指示。
4. 写手的上下文按场景与视角拼出；写完以后由程序圈候选、再问窄问题查穿帮与违约。
5. 尽量用现有的条目、Component、补丁、计划与讲述表达，不加新的存储对象种类。
6. 与 nb-story 共用一层骨架：一件事、涉及谁、出处、在故事的哪里；读者视角从作者的数据按讲述投影出来。

非目标：按故事时间读状态（“王历 612 年霜月 5 日那天她有多少钱”）；角色按自己的目标自主行动（模拟，不在本 Work）；中文时间说法的自动解析；自动发现新伏笔与目标冲突；同一部作品几套历法并存（第二版）；自动改正文。

## 三、当前行为与证据

- **nb-canon**：剧情变更（描述、安放、讲述、涉及、剧情线、补丁、生效状态）、计划与兑现、剧情线条目、待定与核对点、未决问题；位置是全序；讲述的形状不限多出来的键（原样存下、不校验）；字段种类没有“条目引用”。
- **旧应用**（[对照](../../.agents/works/w00039-novel-writing-plugins/research/2026-11-04-legacy-plot-vs-canon.md)）：bigint 秒的精确时刻、全库唯一、一刻一切面，Agent 门槛高、写入撞时刻报错；信息控制是章上 4 个手填文本，“谁知道什么”留作以后设计；伏笔账本与决策的真实项目实测降成了单测，10 条规划检查没实现。
- **nb-story**（[对照](../../.agents/works/w00039-novel-writing-plugins/research/2026-11-04-nb-story-vs-canon.md)）：有故事时间（模型只写相对关系、程序排序）、知情、悬念的分次进展；评测经验：天数不能让模型累加；知情最不稳（同配置抽三次，53 条里 22 到 29 条不一致）；“读者知道被当成角色知道”是知情题最大的错因；自动找错不可靠（准确率 5% 到 27%），程序圈候选再问窄问题有效。
- **原型**（t32 的 `prototype/` 与 `evidences/`）：时间约束网络与自定义历法的原型；知情与伏笔直接在分支上的 nb-canon 跑例子，确认能做的与要补的。

## 四、方案

### 1. 总原则

- **三种视角**：真相（作者定的）、某个角色（他知道、误信、记得的）、读者（读到第几章为止讲出来的）。知情、记忆、误信、秘密、悬念、反讽都是“某个视角在某个时刻认为什么是真的”。
- **两个钟**：故事里的事实（状态、角色的知情与目标）按安放（故事时间与世界线）算；读者看到的东西（揭示、伏笔的节点）按讲述所在的章序算。nb-story 把两者放进一张表，正是它最大错因的来源。
- **精度三档**：精确（结构化字段、核对）、粗略（一句话、模糊的时间、一条规则）、没记（用到再补：先问作者，或推一个标“推断，作者未确认”，答了或写进正文就记下）。每条记录带来源：作者定的、正文写明的、推断的。
- **一条规则**：没记的可以推，推出来的标出来；重要的标保密，保密的不许推。
- **检查分级**：程序能确定的进待处理；有意为之常见的只提示；要判断文字的，程序先圈候选，再让记账 Agent 回答窄问题（引原句），不自动改正文。

### 2. 时间

- 时间是剧情变更上可选的“说法”，可以几条，同时成立，精度不限：日历上的日子（到年、月、日、时段或时，可以带“约”）；在另一件事之后或之前、间隔的范围（“三天后”“觉醒后不久”）；持续多久（“离家那几年”）；某人几岁那年。每条带原话与依据。出生、建国这类锚点就是前史里的剧情变更（补丁可以为空）；年龄是查出来的，不存字段。
- 模糊词表是作品级设置（“几年”“几天”“不久”换成范围），所有 Agent 用同一份。
- **计算用时间约束网络**（Simple Temporal Network，Dechter、Meiri、Pearl 1991）：每条说法是“两件事相差 lo 到 hi”，最短路给出每件事最早、最晚可能的时间，负环就是矛盾，环上的说法就是打架的那几条。范围带依据（最早、最晚各是哪几条说法定的）。推不出的一端，用安放上最近的、写了时间的邻居补上，只用于查询。日期的“精度、约、不确定、开放区间”借用 EDTF（ISO 8601-2）的分法，不用它的字符串格式（它只管公历）。
- **时间不决定状态的折叠顺序**：状态仍按安放（前史序号、章序、章内排序键）折叠；安放的先后不放进网络（一处安放错了不会让整张网矛盾）。安放与时间对不上（按安放 A 在 B 前，时间上 B 一定更早）单独报出来，提示挪安放、标平行或改前史的序号。章可以标“与第 M 章同时”。前史的序号在写入时按时间在邻居之间取一个数。不写时间的书，行为与现在完全一样。
- **历法**是作品设置里的数据：一天几小时、一小时几分、各月的名字与天数、闰年规则、纪年名、一天里的时段；缺省是“相对公历”（开篇那天是第 1 天）。存的是作者说的话（按历法上的写法），不存换算结果：改了历法，所有说法自动按新历法理解，不用重新换算；新历法里不成立的说法报诊断。
- **内存里的绝对时间**是从历元起的整数分钟，用 JS 的数（2^53 分钟约 171 亿年；更长跨度的世界可以把最小单位设成时或天）。旧 WorldEngine 用 bigint，是因为它把绝对时刻当唯一真相存进数据库；这里不落盘。
- **查询**：某件事、某章的时间范围与依据；某段时间里可能、一定发生的事；两件事相差多久；某人在某事时几岁；某章写到的故事时间；按纪、年、月、日逐级浏览。原型里 5 万件事时一致性检查、全部范围、按时间查都在几十毫秒内；按“王历 590 年前后”在 428 件事里筛出 5 件候选。
- 历法、说法、网络与查询放进一个新的无依赖包（暂名 `nb-time`），nb-canon 与 nb-story 共用。

### 3. 世界线

- 分叉是一种剧情变更：父线、切口（父线上哪件事之后，按安放）、触发的事、往回多久（回溯）、种类（回溯、分支、梦境、IF）、带过去的地址（例如她的知情）。
- 某条线某个位置的状态 = 父线到切口为止的变更 + 带过去的地址取父线在触发处的值 + 本线到这个位置的变更；仍按安放折叠，增量引擎在切口处取父线的快照。读取位置带线；回溯以后，后面各章缺省读新线。
- 时间网络里，新线上的事不早于“触发处往回多久”的那一刻；不同线上的事不比先后。
- 原型：第 8 章回溯约 6 小时，新线上存款回到 20,000、回溯次数用掉一次、她的记忆带过去；不分线时报“安放与时间对不上”。
- **作者怎么用**（以第 8 章回溯为例）：
  - 先记后写：细纲写“回溯到早上”，主 Agent 提出的计划里就有一次分叉（回到哪件事之后、往回约 6 小时、带过去什么），作者在预览里看到“星瑾不记得”“存款回到 20,000”；
  - 先写后记：正文写了回溯，记账提出分叉，回执里列出切口、往回多久、带过去的东西，作者确认或改；
  - 带过去的东西缺省是回溯者的知情，作者可以加（例如回溯次数、身上的伤），也可以去掉；分叉之后的新变化（回溯次数减一、这次没买包）照常记在新线上；
  - 条目页的位置选择多一项线：“第 8 章末尾 · 回溯后”与“原来那条线”；缺省是这一章最后一件事所在的线。被抹掉的那几个小时留在原线上，随时能看；
  - 读者的钟不分线：抹掉的那几个小时读者读过就算读过，里面埋的伏笔照算；
  - 平行世界是两条线都往下走，各章的事各标在哪条线上；梦境与 IF 线是一条支线，结束后回到父线，梦里带回现实的东西用父线上一条普通变更记；多次回溯就是分叉再分叉。两条线合回一条（世界融合）第一版不做。
- [ADR 0037](../adr/0037-world-engine-story-change-log.md) 说“以后加故事时间与世界线，换掉位置模块，日志与补丁的形状不变”。时间部分成立（时间不改折叠）；世界线不成立：安放与读取位置要带线，折叠要沿着线走。要另写一份 ADR 部分取代它。

### 4. 知情

- **知识点**是条目（种类“知识点”），挂在它说的那个条目下面，命题写在一句话描述里。只有建成知识点的事才有知情，其余靠常理。保密分四档：常识；行内（按一句规则推，“药师、草药商认识，普通人不认识”）；保密（没记下来的人一律当作不知道，写手不许推）；绝密（写手只知道“有一件涉及某某的保密设定”，不给内容）。设了马甲时提示建“甲就是乙”的知识点。
- **知情记在人物（或组织）身上**：人物上的列表，一行一个知识点（元素 id 就是知识点的条目 id，一人一点一行），记程度（知道、误信、怀疑、不知道、忘了）、误信时他以为的那句、怎么知道（亲历、听说、推断、读到、传闻、本人）、谁告诉的。谁在哪章知道了，是一条剧情变更加一行或改程度，沿用折叠、来历、撤销；回溯时分叉带过去“她的知情”一个地址。
- **读者**不是条目：正文某处讲述标“揭示了哪个知识点”（明说或暗示），读者从那一章起知道（暗示算怀疑）。不从“角色在讲出来的场景里知道了”自动推读者。
- **检查**：可能穿帮（程序圈出“本章涉及的保密知识点 × 在场而不知道的人”，逐对问窄问题）；提前泄底；传话链断了（告诉别人的人自己在那时还不知道）；正文里有人知道却没有记录。

### 5. 伏笔

- 伏笔是条目（种类“伏笔”）：名字写“许了读者什么”，主文字写打算怎么回收（回收那一章才给写手）。字段：种类（埋设回收、悬念、预言、意象）、重要程度、作者的意图（进行、放弃）、悬念的答案（知识点）、参考间隔。
- **节点是讲述上的标记**：埋下、呼应、误导、部分回收、回收，可以带给写手的指示；位置是那处讲述所在的章。不用补丁记节点：伏笔是写法，不是故事里的状态，补丁套不上会连累同一条变更里的真实事件。只是提了一句的，记一条没有补丁的剧情变更。
- **计划**：细纲那处讲述带节点标记；兑现计划的已写变更默认继承计划上的节点。
- **悬念连答案知识点**时，读者对答案的揭示自动算节点（暗示算呼应、明说算回收），不重复记；所以只有明说早于计划的回收才报泄底，有悬念认领的暗示是有意的。
- 阶段由节点算出，不另存：未埋、已埋、呼应中、部分回收、已回收；放弃的显示“放弃（已埋）”。
- **检查**：进待处理的是没埋就回收、计划的节点那一章写完了却没有、回收以后又埋、泄底；只提示的是已埋没排回收、太久没提、放弃了但正文还留着埋下的句子、没有悬念认领的暗示。“像伏笔的句子”不自动猜，只问两种窄问题：计划里本章有节点的；进行中的伏笔的名字或别名出现在本章的。

### 6. 角色的目标与态度

- 只结构化长期目标，只给主要角色建（每人三五条）；场景里的小目标、策略不进结构。
- **目标是条目**（种类“目标”），挂在持有者（人物或组织）下面，按安放（故事时间）折叠：状态（进行、受挫、达成、放弃）、轻重、层次（想要或需要）、为什么、基于（知识点：这个目标成立依赖他对这件事的看法）、冲突（一行一个对方目标）、后继（目标变了时指向新的）。隐秘的目标同一个条目再加知识点的 Component。
- **态度**是人物上按对象的列表（元素 id 是对象的条目 id）：态度（语义档，记一句发生了什么、由小模型归纳）与起因（知识点）。
- **弧光**是几条计划加一条剧情线。
- **检查**：前提变了（目标基于的知识点，持有者那一行变了而目标没被触及）进待处理；缺一步（计划里要和好，而那时她还误信）、停滞只提示；行为与动机不符不自动查。

### 7. 决策与章级写作指示

- **决策是未决问题长大**，还是六种对象之一：待定（候选、最晚第几章前要定）→ 已定（结论、理由、风险）→ 被取代或放弃。已定必须带作者原话出处；Agent 不能自己定、不能改作者定的事（只能新建一条待定的指向旧的）；记账不关闭决策；理由没说的不许编。挂在条目、剧情变更、地址、章或另一条决策上，可以限定章的范围。约束是一句祈使，可选带**守卫**（某个地址在范围内不准取某些值，程序检查）。
- **决策的检查**：违反已定的约束、写死了未定的事、到期没定（写正文前拦一下）、悬空；泄底与穿帮的诊断附上相关的决策。
- **章级写作指示**挂在活页夹的章上、和细纲放在一起，不进世界：读完这一章读者该有什么变化、视角人物与视角方式、语气、开场、结尾、不写的、其他。旧版的四项信息控制不再手填（由揭示、知情、保密分档与计划推出）。能写成世界状态的进计划；计划与指示矛盾时并列报出。剧情线上的写作指示就是一条挂在线上的已定决策。
- **视角**：有限视角下，叙述只写视角人物知道的；穿帮检查分对白层（按在场的人）与叙述层（只查视角人物不知道、误信的保密事项）。

### 8. 写手的上下文

由程序拼，不由模型生成：写作指示 + 细纲 + 本章计划 + 简报（在场每个人此刻在追的目标与为什么、对在场其他人的态度、他知道与误信的保密事项、行内规则；本章要埋、呼应、回收的伏笔，还不能回收的只给“许了什么”；涉及本章的已定决策与待定事项）+ 涉及条目在本章开头的样子 + 最近一两章正文。绝密的不给内容。各段的上限在 t20 定。

### 9. 与 nb-story 共用骨架

- 共用的是：一件事、涉及谁、出处（讲述，含揭示与节点的标记）、在故事的哪里（时间说法与世界线，`nb-time`）、读者位置的计算。
- 作者自己的书，读者视角从 nb-canon 按讲述过滤出来，不再抽一遍；nb-story 继续负责导入第三方的书。nb-story 的 `day`、`part`、`rel` 映射成相对历法上的说法，知情状态拆成程度与来源，悬念对应伏笔里的悬念。
- 让 nb-story 改用 nb-canon 存（做法 A）代价最大（已发布的独立书库、不依赖项目导入整本书、“起始金额未知”的流水都要改），只在第三方的书也要用作者的工具时才值得。

### 10. Agent 与系统怎么用

依据：内核提案第四部分第 9 节的六个工具与记账规则；[写作流程草稿](../../.agents/works/w00039-novel-writing-plugins/tasks/t19-writing-workflow/flow-draft.md)（开发者还没定稿）；一个 Sonnet 子代理的独立设计（t32 `evidences/agents-independent-design.md`），下面按它合并。

**角色与形态**

| 角色 | 形态 | 读 | 写 |
|---|---|---|---|
| 主 Agent（写作助手） | 会话，作者唯一的对话对象 | 世界工具 | 经 `write` 写世界（开局、计划、作者让它改的）；细纲、手记；派写作任务 |
| 写手 | 插件的后台任务：程序拼好上下文、一次生成，不是通用子代理 | 程序拼的上下文；自由发挥时另有只读的 `lookup`、`read`，至多 6 次，按视角人物过滤 | 章节的新一版，加一份“自陈”：新出现的名字与事实、拿不准的、偏离粗纲的地方。写手不写世界 |
| 记账 | 管线：程序备料、一次起草、程序校验、最多一次修复、发布 | 程序备料 | 一次修订、回执、待处理 |
| 审稿 | 记账管线的预览：做到校验与窄问题，不发布；结果按“正文与世界版本”缓存，正文没变时记账直接复用，不再付一次钱 | 同记账 | 报告 |
| 找旧写法 | 后台会话（要自己检索） | 检索、读 | 正文建议 |
| 角色（以后的角色对话、推演、RP） | 会话 | 只读工具，按这个角色的视角过滤 | 见第 12 节 |

**工具**（主 Agent 共 12 个）

- 内核的六个：`lookup`、`read`、`changes`、`search`、`tree`、`write`。
- 时间两个：`time_of`（某件事、某章的时间范围、依据、某人当时几岁）、`time_find`（某段时间里可能、一定发生的事，可按条目筛）。参数是结构化的，不让模型拼日历字符串。
- 写作四个：按细纲写、按粗纲写、审稿、本章写完。前两个共用实现，只换上下文的档与写手的工具；都返回任务号。
- 知情、伏笔、目标、决策**不另加工具**，并进 `read` 的地址：条目自己的视图里带知情、目标、态度，伏笔与知识点条目带阶段与节点；跨条目的列表用地址读：伏笔账本、目标表、决策表、某个知识点谁知道、某章的写手简报预览、某章的工作单（阶段、计划几条、待处理几条、到期的决策）。实测模型找不到时，再把账本拆成单独的工具。
- 由程序备料、不给工具的：写手的上下文、在场角色的状态、本章计划、涉及条目的样子、名字预查、依赖兜底（前几章没记先补记）、窄问题的候选、计划与正文的差额。

**上下文的节省**

- 所有输入都按位置与涉及的条目取，没有读全书的路径；随章增长的只有“最近的正文”，固定取上一章末尾一段加前一章要点。所以三百万字时一次调用的材料与第 10 章相同。
- 每次返回都有条数与字数上限，写明共几条、显示几条，给续读游标；位置参数按场景缺省（讨论或审第 N 章取开头，记账与审稿取末尾）；账本只列进行中的，已结束的折成一个数。
- 自动预查：用户消息里的名字按当前位置匹配，每个一行；另认“第 N 章”（注入一行工作单）与伏笔名。注入总量有上限。
- 用法说明（知情、伏笔、目标、决策各一小段）首次出现与压缩之后补一次，不进系统提示词。
- 压缩后不丢：世界状态、决策、作者原话都在世界里，不在对话里；本章的工作单由压缩后的恢复流程放回。
- 每章有预算：写手至多 2 次生成，记账至多 4 次调用，窄问题至多 12 条；回执写这一章花了多少。估算（没实测，t26 的基线来量）：写手按细纲约 9000 字的输入，按粗纲约 6500 字加至多 6 次读，记账约 1 万字。

**防乱写**：写手没有写权；自陈不当事实；推断的必须标出来，等作者确认；已定的决策 Agent 不能改；绝密不进上下文；记账默认生效但整章可以还原；写手任务固定开始时的世界版本，发布前比对；第 N 章没记账不写第 N+1 章。

### 11. 一章怎么转起来

世界在一章里只在两个点被写：写前的计划、写后的记账。写手不写世界。

**路一：先记后写**（细纲在手，适合要紧的章）

| 步 | 谁 | 做什么 | 作者拍板 |
|---|---|---|---|
| 1 | 作者与主 Agent | 讨论细纲；看写手简报的预览缺什么 | |
| 2 | 主 Agent | 审细纲（吃书、吃设定、严谨，加决策到期、前提变了、会不会泄底）；把细纲提成计划（状态变化、谁知道了什么、伏笔节点、分叉），先预览 | 看计划的预览 |
| 3 | 程序 | 依赖兜底；拼写手的上下文 | |
| 4 | 写手（按细纲） | 一次生成 | |
| 5 | 审稿 | 对计划逐条问“引出做到它的原句，或者答没写”；查穿帮、泄底、违反决定 | 接受、带指示重写、或者自己改 |
| 6 | 记账 | 以计划为底，只核差额（数以正文为准，没写到的拆成新计划） | 处理待处理 |

**路二：先写后记**（粗纲，大部分剧情由写手自由发挥）

| 步 | 谁 | 做什么 | 作者拍板 |
|---|---|---|---|
| 1 | 主 Agent | 写粗纲（这一章大概要发生什么）加“自由度的边界”：保密名单、已定的决策、不许动的状态与伏笔；不写计划 | |
| 2 | 写手（按粗纲） | 生成，可以按需查设定；交正文与自陈 | |
| 3 | 审稿 | 备料多带自陈，候选更多：自陈与世界冲突的、新名字没有条目的 | 接受、重写或改 |
| 4 | 记账 | 完整五步；自陈只当候选，新定下的设定标“推断，作者未确认” | |
| 5 | 作者 | 在待处理里确认或改推断 | 处理待处理 |

**路三：分场推进**（回溯、揭晓这类关键章，或者很长的章）：粗纲拆成几场，每场主 Agent 写一小段场计划、写手写这一场、记账只记这一场，下一场的上下文读到新账。世界每场落一次，偏差不会累积；调用多，由作者开启。

作者自己写的章走路二的第 4、5 步；RP 模式是路三的变体（第 12 节）。

| | 世界什么时候被写 | 计划怎么兑现 | 审稿查什么 |
|---|---|---|---|
| 先记后写 | 写前的计划，写后补差额 | 逐条对照计划 | 兑现、穿帮、泄底、违反决定 |
| 先写后记 | 只在记账 | 没有计划，只核作者标了“必须”的少数几条 | 穿帮、泄底、违反决定、自陈与世界冲突 |
| 分场推进 | 每场一次 | 场计划 | 同先记后写，按场 |

### 12. 对以后功能的检验

开发者 11-04 列了以后要做的四样，逐个看这套设计能不能承接（推断，没有原型）。

**世界推演**（让势力、角色按作者的要求动起来；每个角色由单独的 Agent 扮演，有自己的记忆，能存下当时的想法；预算可配）

- 承接得住的：任意位置上的世界状态（折叠）；每个角色只看到自己的那一份（知情记在人物身上、读工具按角色视角过滤，就是写手简报里“按视角”的同一个投影）；角色的目标、态度、信念；推演出来的东西先落成**计划**（还没写的变更），作者挑、改、删，满意的再写成正文，所以推演不会直接改世界；要比较几种走向时，每次推演开一条 IF 线，留一条。
- 要补的：角色 Agent 的身份（修订的“谁写的”里记“某 Agent 扮演某角色”）；“当时的想法”的落点（人物上的一个语义档字段，或者计划上附的一段内心，不当世界事实）；**地点**（谁和谁在一起决定谁会遇到谁，地点与地图 Component 原定第一版不做，推演要先有它）；推演的编排（一步推多久、谁先动）是工作流，不在 nb-canon；预算是 Agent 配置。
- 结论：数据模型承接得住，缺的是地点 Component 与编排。

**角色对话**（把某个时间点的角色拿出来，作者直接和他对话；不需要长期记忆）

- 承接得住：角色在某个位置、某条线上的样子 = 他的条目与 Component（外貌、性格、说话方式在主文字里）+ 他的知情（知道的、误信的）+ 他的目标与态度 + 他的经历（他亲历的事与他知道的事）。对话只读世界，不写。
- 要补的：**按角色视角的经历**（涉及他、他在场的事，加他知道的知识点；需要情节上记“在场”的角色，现在的 `involves` 分不出来）。
- 顺带的好处：这是“作者问到时能当场想出来”的最好入口：角色在对话里说出的、作者认可的，可以一键记成“推断，作者确认”的设定，记录跟着用而长出来。

**RP 模式**（类似 SillyTavern、跑团：用户拿到只有基础设定与开局的项目，扮演一个角色或当“天道”给剧情走向，NeuroBook 推演并写文；先写后记；要能回溯）

- 承接得住：
  - 一轮就是路三的一场：用户的输入（以角色行动，或以天道给方向）→ 主持的 Agent 决定结果（其他角色由角色 Agent 按各自的视角回应）→ 写手写这一场 → 记账（先写后记）→ 下一轮；
  - 天道给的方向就是计划；
  - 用户扮演的角色也有自己的知情，其他角色的 Agent 读不到用户“角色外”的知识；
  - **读档**：每轮都是修订，可以连同之后的一起还原；更好的做法是把存档点当作分叉点，读档就是从那里开一条新线，原来那条留着可以回看；正文的版本在 nb-history。
- 要补的：每轮记账的费用与延迟（记账是模型调用，按场记、窄问题限量）；章的自动划分（几轮合成一章写进活页夹）；主持 Agent 与回合制的会话形态（w00032）；RP 项目模板（t12）。
- 结论：事件溯源加世界线正好是 RP 的“存档、读档、分支”；瓶颈在每轮的模型费用，不在数据结构。

**用 nb-canon 重写 nb-story**：见第 13 节。

### 13. 用 nb-canon 重写 nb-story（尽力而为）

依据：一个 Sonnet 子代理的功能对照（t32 `evidences/nbstory-on-canon.md`），样例书 100 章：176 个对象、1739 条说法、1356 条知情、247 个情节、186 条账本、257 个悬念。

- **能直接做、而且更强的**：数值账本与对账（核对点、嫌疑区间）、修订与撤销、追加新章。
- **要补一点的**：知情（剧情侧已含）、悬念（伏笔节点）、时间线（`nb-time`）、情节（剧情变更装得下事件，步骤、化名、情节之间的连接没有）、身份按视角合并、导入。
- **做不了的**：
  - 带渠道的说法（“某人说”“某人认为”）与说法之间的印证、反驳：样例书里 belief 672 条、claim 612 条，占说法的 74%；nb-canon 不记角色说的话（作者知道真相，渠道是读者端的不确定性）。
  - 知情的来源不同：nb-story 1356 条知情里 1019 条（75%）是程序从台词与心理推出来的；nb-canon 只管建成知识点的事。
  - 记录的先验等级与“伏笔候选”：依赖读者端的后文回响。
- **补不补**：只有“读者位置到段”建议补进内核（讲述加段号，写入时由原句在章内定位算出）；身份按视角合并做成读者视图里的函数；说法与印证反驳做成 nb-canon 上的插件或留在 nb-story；先验等级、整理稿、主线整理不搬；“起始金额未知”用带“估计”的初值；不依赖项目的整本导入放 nb-story 的适配器；情节因果看评测再定。
- **关键判断**：nb-story 的查询、查看器、问答、命令行都只读 V9 数据文件。最省的“重写”不是换存储，而是写一个 nb-canon 到 V9 的投影（缺的说法、等级留空），问答引擎与评测脚本原样复用（投影能不能过 V9 的校验是推断，要核实）。
- **评测怎么用**：样例书 100 章，题库 72 题（12 类题型），判分器与回归脚本都在（题库与判分器在未合并的 w00005 worktree 里，要先复制进 master）。数值、悬念、认人、摘要几类直接适用；知情题要读者那一行；来源可信度一类不适用。第一份证据最便宜：写 V9 转 nb-canon 的转换器，出“装不下清单”与占比，零模型费用。第一个问答实验：前 50 章、36 题，V9 图当目录对 nb-canon 投影当目录，各 3 次，约 ¥10 到 20（推断），判据是答错率不高于 V9 加 3 个百分点。
- **局限**：问答只能证明“不比 V9 差”（100 章内全读最准）；nb-canon 的价值在作者端，要用 t26 的漏记率与静默错记率量，以及用 nb-canon 重新记账前 20 章、对照 V9 的费用与准确率。
- **结论**：数据层不换，作者自己的书走 nb-canon，第三方的书走 nb-story；用投影共享问答与查看器，用评测量 nb-canon 有没有用。

### 14. 备选与取舍

- **精确时间轴**（旧 WorldEngine）：每件事一个全局唯一时刻。没选：逼作者编造精确值，撞时刻就失败。
- **时间决定折叠顺序**：没选：大量事件没写时间，补叙与回溯会让相对加减断掉。
- **安放的先后放进时间网络**：没选：一处安放错了会让整张网矛盾，什么都查不了。
- **知情记在知识点上**：反查直接；没选：写一场戏要扫全表，回溯要选择器而不是地址。
- **读者从角色的知情推**：没选：场景讲出来了，读者不一定知道。
- **伏笔节点做成补丁**：内核改动小；没选：伏笔条目删了会让真实事件的补丁套不上，位置成了安放而不是讲述。
- **新增第七种对象（知情记录、伏笔账本、决策）**：没选：要重做位置、世界线、计划、撤销与修订，也会让同一件事在两处各记一遍（旧应用的手工双维护）。
- **态度用每个对象一个实例字段**（t16 原型）：现在就能用；没选：对象只是字段名里的文字，改名就断，查不到“谁对她冷淡”。

## 五、影响

- **数据**：剧情变更加时间说法；安放与读取位置加世界线；分叉是新的一种剧情变更；讲述加标记（揭示、伏笔节点）；未决问题扩成决策；字段加条目引用、列表元素允许语义档。nb-canon 在分支上还没合并，v2 没有用户数据，日志格式直接改，不做迁移。
- **内核要补的**（知情与伏笔的原型实测确认的标“实测”）：
  1. 条目引用（实测）：知情行的元素 id、“谁告诉的”、讲述上的标记、伏笔的答案、目标的基于与冲突都要算作引用：写入时校验存在，改名、删除跟得上，还原时查得到依赖（实测还原“建知识点”“建伏笔”时没有列出依赖），同一次写入里的临时 id 也要换成真实 id（实测文字字段里不换）。
  2. 讲述上的标记（实测）：揭示与节点正式加进讲述的形状，并校验（实测现在原样存下、不校验）。
  3. 时间说法与 `nb-time`；安放与时间的对照诊断。
  4. 世界线：分叉、按线折叠、读取位置带线。
  5. 列表元素的子字段允许语义档（补丁与归纳缓存按元素地址记）。
  6. 按读者章序的计算与新的待处理种类：读者的知情、伏笔账本、简报、窄问题的候选。由 nb-canon 或剧情插件提供，与待处理一样在读取时算出。
  7. 未决问题扩成决策；守卫的检查。
- **接口**：世界服务与远程合同加时间查询、简报、账本与新的待处理；Agent 工具（t20）的参数随之定。
- **成本**：时间、知情、伏笔、目标、决策的计算都是程序；模型调用只在记账时的窄问题（每章有上限）与语义档的归纳。
- **安全**：无新的信任边界。绝密内容不进写手的上下文。
- **发布与回滚**：都在内核分支上，合并之前随时可以改。
