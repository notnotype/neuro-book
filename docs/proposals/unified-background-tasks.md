# 统一后台任务：一份清单、按归属分类，会话收提示

## 一、问题

1. **后台任务分在两处，互相看不见**。插件的长任务（安装 Skill 的依赖）在 `nbook.tasks` 的清单里，工作台有视图、状态栏与通知；Agent 的后台命令与子代理运行在 `nbook.agent` 的任务中心里，只在对话里的卡片上看得到。用户切到别的对话，就不知道哪个会话还挂着一条命令。Agent 的运行本身（ReAct 循环）不是任务，只在对话与会话列表里看得到。以后还会有更新、带进度的计算、定时任务（cron）、HTTP 服务、端口转发，按现在的做法每样都要再找个地方挂。
2. **Agent 不知道后台任务结束了**。转后台的命令、后台子代理结束后，结果等 Agent 自己调 `wait` 才取得；Agent 这一轮已经结束的话，没人提醒它。
3. **插件没法给会话递一句“你该知道的事”**。eval 的内核因空闲被回收或意外退出时，只记下原因，等模型下一次调 eval 才在结果第一行看到“内核已重置”；模型不调 eval 就一直不知道。后台任务结束、文件被外部改了，都是同一类需要：一条不是用户说的、下一次请求带给模型的提示。

## 二、目标与非目标

目标：

- `nbook.tasks` 是应用里所有后台任务的一份清单：插件的长任务、Agent 的后台任务、Agent 的运行，以后的服务与定时也在这里。每件任务有来源（谁登记的）、归属（应用、项目或会话）、形态（一次性、服务、定时）与种类。
- 内核的输入缓冲区多一种“提示”：下一次模型请求带上，排在插话前面；可以选在会话空闲时唤起一次运行。
- Agent 取异步结果有两条路：自己 `wait`；或者结果作为提示进缓冲区（必要时唤起）。
- 给 t24（Workflow 与 Agent 的对接）与 w00043 t10（`nbook.schedule`）一个现成的地方：Agent 启动的 Workflow 是一件属于会话的任务；日程的条目是定时形态的任务。

非目标：

- 服务与定时形态的完整实现：本提案只定它们在清单里的位置与存盘的归属，实现等第一个用到的插件（日程是 w00043 t10）。
- 任务表持久化：清单仍只在服务进程的内存里；要跨重启的是服务与定时的定义，由登记它的插件存（第四节第 4 小节）。
- Monitor（把输出逐行推给 Agent）、后台命令的 stdin、eval 单元自动转后台。
- 周期任务本身、宿主消息的来源说明与授权：在 [bot 提案](neurobot.md)第四节第 6 小节；缓冲区的状态与放行：在 [缓冲区提案](agent-input-buffer-states.md)。

## 三、当前行为与证据

- `nbook.tasks`（[`workbench/background-tasks.md`](../specs/workbench/background-tasks.md)）：服务端入口调 `start` 登记，任务按登记它的插件入口记；清单只在内存，结束的至多留 50 件；窗口有“后台任务”视图、状态栏条目、结束通知；向宿主报“在跑的工作”。“不承诺”里明写 Agent 的后台工作不进这份清单，理由只是当时归 w00032 t22（t34 决定 2）。
- Agent 的任务中心（[`agent/jobs.md`](../specs/agent/jobs.md)）：`nbook.agent` 服务端入口里的一张内存表，按启动它的会话记；`wait`、`kill`、`jobs` 三个工具；“不承诺”里有结束时不通知、不唤起，跑久了不自动转后台，没有活动面板。它也单独向宿主报“在跑的工作”（[`agent/sessions.md`](../specs/agent/sessions.md) 输出 20）。
- 内核的缓冲区（[`harness/runtime.md`](../specs/harness/runtime.md) 输出 3、28、103–110，w00043 t14 已实现）：插话下一个边界取走、排队一轮结束时取走；条目有就绪与留着两种状态；发出者有用户、会话、宿主。内核自己写的提醒（`notice{code: "tools-changed"}` 等）在请求之前写进日志，外部没有入口。
- eval（[`agent/eval.md`](../specs/agent/eval.md) 输出 11、12）：重置原因记在插件里，下一次 eval 的结果第一行写出。
- 参照：omp 18.14.1 把后台任务的结果作为一条消息送回启动它的会话，空闲时开新的一轮，用户打断之后不自动唤起（`session/async-job-delivery.ts`、`session/agent-session.ts`）；Claude Code 的后台命令结束时宿主唤起 Agent。
- 第一版方案（把结果当宿主的插话送进会话、Agent 的任务镜像进清单）做过一轮设计审查，27 条里多半出在“两套状态”与“结果是用户角色的话”上（[w00032 t22 的审查](../../.agents/works/w00032-agent-integration/tasks/t22-background-work/evidences/design-review.txt)）。

## 四、方案

### 1. 缓冲区的“提示”

缓冲区里每种话按自己的时机发出（开发者 2026-11-19）：

| 模式 | 什么时候取走 | 给模型的样子 |
|---|---|---|
| 提示 `notice` | 下一次对话的模型请求，排在插话与新话前面 | `<system-reminder>`，带来源行 |
| 插话 `steer` | 下一个边界 | 用户（或来源行标明的发出者）的话 |
| 排队 `followup` | 一轮结束时或下一次运行 | 同上，开一轮 |

- 只有会话与宿主能发提示（用户的话本来就是新话）。正文有长度上限（Spec 定，例如 16 KiB），发出方自己把长内容存成文件、提示里写地址。
- 提示一直是就绪的：会话回到空闲、停止、出错都不把它变成留着，也不用放行。会话空闲时它等着，下一次运行（不论谁开的）的第一次请求带上它。回退、换分支不影响它（缓冲区是会话级的）。
- 取走与请求在单写者的同一项里：写 `inputConsumed` 与一条路径事件 `notice{by, text}`，之后照常进压缩、回退与 fork。只压缩的运行的请求不取提示。
- 给模型时包在 `<system-reminder>` 里，前面一行来源说明，格式同 bot 提案的宿主消息（“[系统 · <label> …]”），写死在 `runtime.md`；正文里的 `<system-reminder>` 标签转义。提示不是用户的话：不算授权依据，不解除运行守卫的停止。
- 同一个发出者带同一个 `key` 发的新提示替换还没取走的那条（例如“内核已重置”不叠两条）。
- **唤起**：发提示时可以带 `wake: "after-completed"`。会话有运行在取输入时照常等下一次请求；空闲时，只有叶子上最后一次对话运行以 `completed` 收口（或还没有对话运行）才开一次运行，这次运行没有新话，第一次请求带上提示。上一次是停止、出错（含循环保护与费用上限）、进程中断或暂停的，不唤起，提示照样等着，随用户下一句话进去（开发者 2026-11-19）。运行不再取输入时（停止已受理、已决定收口、只压缩），唤不唤起在收口的那一批里按同样规则判。判定都在内核的单写者里做：在内核外先读状态再发，挡不住“用户刚按了停止、运行还没收口”的那一刻。
- 界面：排队区显示还没取走的提示（来源加一行摘要），用户能取消；取走之后在对话里是过程中的一行，点开看全文。

和 bot 提案的关系：bot 提案定了“宿主消息不另开一种输入类型”，那是对“要求 Agent 去做事”的消息说的，日程照旧发排队或插话。提示是另一类：只告诉、不要求，不开一轮、不用放行，所以要一条自己的取走规则。

### 2. 清单里的一件任务

`nbook.tasks` 的任务加三样：

- **归属** `owner`：`{kind: "app"}`、`{kind: "project", project}` 或 `{kind: "session", session}`。会话的任务另记启动它的那次工具调用（`invocation`），子代理会话的任务能顺着会话关系归到根会话下。
- **种类** `kind`：`<登记的插件>.<名字>`，由服务按调用方门面盖章，例如 `nbook.skills.install`、`nbook.agent.shell`、`nbook.agent.subagent`、`nbook.agent.run`、`nbook.schedule.entry`；带一个给人看的 `label`。
- **形态** `form`：
  - **一次性**：跑完就结束，状态同现在（在跑、成功、失败、已取消、已中断）。可以声明“结束即移出”，不留成已结束的一行（Agent 的运行用它）。
  - **服务**：一直跑到被停，状态是启动中、在跑（可带“已就绪”与地址，例如监听的端口）、已停、出错；有停止与重启。
  - **定时**：一个按时触发的条目，状态是生效、暂停、出错，带下一次触发的时刻与上一次的结果；每次触发由登记它的插件决定做什么（日程是往会话发消息，见 bot 提案）。

另加：`open`（打开它的去处，例如它所在的对话，一个命令 id 加参数）；`notify`（结束时要不要弹通知，缺省要）；`attention`（在跑但等用户处理，行上标出，第一版不弹通知）；发起方自己可以把任务记成已中断（`interrupted()`）。远程合同升到版本 2。

### 3. Agent 怎么接

- **Agent 的后台任务就是清单里属于会话的一次性任务**：`async` 的命令、自动转后台的命令、子代理的运行、别的插件的工具起的任务，都登记进 `nbook.tasks`，归属是启动它的会话。任务中心不再是一张单独的表，收窄成 Agent 自己的取件记录：每件任务有没有前台调用在等、有没有 `wait` 在看、有没有在送达、取过没有；`wait`、`kill`、`jobs` 与上限（`backgroundJobs`）都按它。
- **结果的两条路**：Agent 自己 `wait`；或者任务结束时，Agent 把结果作为一条提示送进启动它的会话，带 `wake: "after-completed"`，算取过。正被前台调用或 `wait` 等着的不另送；送达与 `wait` 在任务中心里同步领取，一件只交一次。每段结果有长度上限，长的写地址。子代理会话的任务也送，但不唤起（子会话等父 Agent 下次发话时一起带上），不改“一个任务对应一次运行”。
- **别的插件的工具起的任务**：Agent 给工具的服务里有一个登记入口，会话与 `invocation` 取自这次调用，只在调用结算之前能用；结束时插件交出给模型的文字，之后 Agent 不再找它要东西；插件停止时它的在跑任务记为已中断。t24 的 Workflow 就这样登记。
- **Agent 的运行**：每次在跑的对话运行是一件“结束即移出”的一次性任务，归属是它的会话，能停（只停这一次运行：内核的 `abort` 带 `runId`）、能打开对话；等用户的审批或提问时带 `attention`，不弹通知（开发者 2026-11-19）。
- **eval**：内核因空闲被回收、意外退出时，当场给会话发一条提示（带 `key`，不唤起）；换 Profile、切分支、换目录、服务重启这类调用时才发现的，仍写在那次 eval 的结果里（开发者 2026-11-19）。
- **`shell` 自动转后台**：前台跑过门槛（缺省 60 秒，设置可调，0 为关）就转成后台任务，结果按上面送达；时限照原来的（缺省 300 秒，开发者 2026-11-19）；子代理会话里不转。

### 4. 存盘与重启

- 清单只在内存：一次性任务随进程结束，在跑的记为已中断，同现在。
- 服务与定时要跨重启的是**定义**，由登记它的插件存在自己的数据里（[插件的数据与状态](plugin-data-model.md)：数据归拥有它的插件），插件激活时重新登记进清单；进程本身活不过应用重启。重启之后服务按插件的设置自己起来或标成已停，定时重新排上，错过的怎样补由插件定（日程的规则在 bot 提案）。
- `nbook.tasks` 不替插件存：它不知道怎样起一个服务、怎样算下一次触发。

### 5. 界面

- “后台任务”视图按归属分组：当前项目、应用、各会话（子代理归在根会话下）；组里先在跑的、再结束的；按形态筛选。会话组的头能打开那个对话。
- 状态栏条目只数在跑的一次性任务；服务与定时常驻，不算进“N 个任务”，在视图里单独一组。
- 结束的一次性任务仍是全局至多 50 件；“结束即移出”的不占。
- “在跑的工作”只由 `nbook.tasks` 报：Agent 不再另报后台任务与运行，免得停止前的确认里同一件出现两次。

### 6. 备选方案与取舍

- **两套状态，Agent 的任务镜像进清单**（t22 第 1、2 稿）：镜像要处理前台续用、标题预算、取消停错一轮、插件停止时谁来收口、“在跑的工作”报两次，审查找出的问题大半在这里。改成一份清单，Agent 只留取件记录。
- **结果作为宿主的插话送进会话**（t22 第 1、2 稿）：模型看到的是用户角色的消息，命令输出的权威被抬高；停过之后还要定谁来放行、回退之后会不会被别的送达带走。提示不进对话的一轮、不用放行，没有这些问题。
- **由扩展在请求时自己拼提醒**（事件模型的 `reminder()`）：每个发出方都得是装在会话里的扩展，还要自己记“说过没有”；eval、任务、以后的文件变更各写一遍。缓冲区的提示由内核保证恰好取走一次，任何插件经会话视图都能发。
- **`nbook.tasks` 自己存服务与定时**：它不知道怎样起服务、怎样算触发，存下来也只能交回给插件；归属拥有它的插件更清楚。

## 五、数据、接口、安全、迁移、发布与回滚影响

- 日志：新的缓冲区模式 `notice` 与路径事件 `notice{by, text}`；旧内核读到得 `log-corrupt`，同缓冲区提案的规则，不做降级。
- 接口：`nbook.tasks` 的服务输入与远程合同（版本 2，旧页面得版本不符后重载）；Agent 的远程 `jobs`、`jobsChanged`、`jobTail`、`killJob` 保留，数据改从清单与取件记录来；nb-harness 套件的 `shell` 加一个可选的自动转后台接口，原来的 `async` 接口不变。
- 安全：提示不算用户的授权、不解除运行守卫；任务的种类由服务盖章，插件冒充不了别的插件；会话任务的 `invocation` 取自真实的调用。
- 迁移：没有持久数据要迁；`nbook.agent` 停止的顺序（先关门、再停在跑的命令、再收口子代理）改成对清单里自己的任务做。
- 回滚：提示与唤起是内核的新能力，回滚要连同日志格式；清单的版本 2 随应用一起发布。
