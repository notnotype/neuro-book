# Agent 内核的输入缓冲区：每条带状态，留着与放行由内核定

起因是 [NeuroBook 的 bot](neurobot.md) 的三轮设计审查：周期任务要往会话的输入缓冲区发消息，而“运行收口后缓冲区里的话归谁取”三轮都找出了新的漏洞（[w00043 t01 第三轮处理](../../.agents/works/w00043-neurobot/tasks/t01-direction/evidences/bot-proposal-review-r3-disposition.md)）。开发者 2026-11-18 选了“直接改内核的缓冲区逻辑”。第一稿按收口方式逐行列表，审查又找出表外的路径；本稿是第二稿，改成只在“会话回到空闲”一处定（[第一轮处理](../../.agents/works/w00043-neurobot/tasks/t01-direction/evidences/buffer-proposal-review-r1-disposition.md)）。它改的是 nb-harness 内核，对所有会话生效，bot 提案引用它。本文不能作为当前行为的依据。

## 一、问题

输入缓冲区放着“提交了还没被取走”的话，每条是插话（`steer`）或排队（`followup`）。现在的规则（[`harness/runtime.md`](../specs/harness/runtime.md) 输出 2–4、7、28–30、34）：运行中每个边界取走全部插话；一轮正常结束时取最早一条排队，在同一次运行里接着开下一轮；一轮以出错或中止结束时不取排队的；中止缺省清空缓冲区、`keepQueue` 保留；重启后缓冲区留着、不自动发出。后几条来自开发者 2026-10-28 在 [w00032 t07](../../.agents/works/w00032-agent-integration/tasks/t07-run-control/README.md) 的决定 1、3。界面上的停止一律保留排队（开发者 2026-11-05，[`agent/conversation.md`](../specs/agent/conversation.md) 输出 6）。

毛病有三类，都已用真实内核复现（证据在 [t01 的证据目录](../../.agents/works/w00043-neurobot/tasks/t01-direction/evidences/)，文件名以 `bot-proposal-review-r*` 与 `buffer-proposal-review-r1-` 开头）：

1. **会话空闲了，缓冲区里却还有话、没人取**：只压缩的运行压完、以收尾工具交出结果、带结果要求的会话以文字收口、正常退出时进程内写下的中断、空闲时排进来的话。普通会话里手动压缩时用户发的话，现在就会这样卡住。
2. **“不处理”不是一种状态**：出错、停止、重启之后留着的话，下一次不管谁开运行，都会被取走；停止进行中到达的话，指令已经交回成功，随后又被清空。只有用户会开运行时，这碰巧就是“等用户”；一旦系统也往缓冲区发消息，系统开的一次运行就会把用户留着的话一起带走。
3. **指令不看发出者**：`edit`、`remove`、`abort` 谁都能用；`inputEdited` 换了内容却保留原来的发出者；`start` 不记谁开的。

## 二、目标与非目标

目标：

- 缓冲区里每条话有明确的状态，取不取、什么时候放行都由内核一处决定，新的收口方式不会漏。
- 把 t07 决定 1、3、2026-11-05 的“停止时排队留着”与 2026-11-18 的“等恢复”写成同一种状态，重启后照样成立。
- 恢复时“留着的先跑”，恢复方式由用户选（开发者 2026-11-18）。
- 指令按发出者有权限，发出者在日志里不失真。

非目标：

- 周期任务本身、宿主消息的来源怎样盖章、给模型的来源说明、算不算用户的授权：在 bot 提案。
- 缓冲区条目的过期：发出者要撤回过时的话，自己取消。
- 降级：旧内核读到新事件得 `log-corrupt`，同现有规则（[`harness/session.md`](../specs/harness/session.md) 的“边界与兼容”）。
- 对话视图的外观：由各自的设计评审定。
- 改插话与排队的基本含义、一条排队开一轮的规则（[Agent harness 的事件模型](agent-harness-event-model.md)待定项 15、16）。

## 三、当前行为与证据

- 一轮正常结束时取排队的、同一次运行接着跑：`kernel/run/loop.ts`；只压缩的运行、交出结果、文字收口都直接写 `runEnded`，不看缓冲区。
- 恢复：打开会话时把没收口的运行以 `interrupted` 收口，缓冲区留着（输出 34）；正常退出时进程内已经写下 `runEnded{interrupted}`，重开时不再走恢复。
- 发出者只有用户与会话（`kernel/api/basics.ts`），用户发的不写 `by`（输出 85）；`edit`、`remove`、`abort`、`start` 不收发出者（`kernel/run/commands.ts`）。
- 界面：停止走 `abort{keepQueue: true}`；“上次运行已中断，按回车继续”，空着回车走 `start`，写了字走 `send`；错误气泡的“重试”与“编辑重发”也走 `start`（`plugins/agent/web/session-host.ts`）；乐观消息按先后确认（`nb-agent-ui` 的 `kernel-transcript.ts`）。
- 子代理：父 Agent 用 `agent_send` 往子会话发话，空闲时开新一轮，在跑时缺省插话；父会话连带中止子会话时保留队列（[`agent/subagents.md`](../specs/agent/subagents.md) 输出 10、16）。

## 四、方案

### 1. 一条规则：会话回到空闲时，剩下的话都留着

- 缓冲区里的每条话是**就绪**或**留着**。
- **会话回到空闲的那一刻**，缓冲区里还在的话全部算留着。不论这次运行怎样收口：正常结束、只压缩、交出结果、文字收口、出错、停止、进程内中断、打开会话时的恢复。原因记这次运行的收口方式与码，停止的另记谁停的。
- **空闲时排进来的话**（`enqueue`）也算留着，原因是“空闲时排的”。
- **运行只取就绪的**：内核读缓冲区的每一处都只看就绪的（边界取插话、一轮结束取排队、`start` 取第一条、“缓冲区还有插话就不结束这一轮”、预览的投影、快照的排队、空闲判断、恢复），第六节列全。
- **留着由日志推出**：看一条话进缓冲区之后、被取走或移除之前，有没有一次回到空闲、之后有没有放行。不写单独的“转成留着”事件；新旧日志同一条规则。
- 一轮正常结束时取排队、同一次运行接着跑，照旧：这时会话没有回到空闲，不受影响。

### 2. 停止

- 缺省沿用 2026-11-05 的决定：停止时排队的留着（`keepQueue: true`），原因是“停止”，并记下谁停的。
- 输入框的停止按钮在缓冲区不空时多给一个“停止并清空排队”（开发者 2026-11-18）。清空只清这次停止受理之前排着的；停止进行中才到的话，按第 1 小节在回到空闲时留着。审批向导里的“终止本轮”、子代理浮层里的停止走缺省。

### 3. 放行

- **用户**：发新话（`send`）或点继续（`resume`），放行全部留着的。留着的先跑（开发者 2026-11-18）。
- **排话的人**：以自己的身份发新话或用 `release`，放行自己排的那几条，不碰别人的。日程插件出错后放行它自己的周期任务、父 Agent 再用 `agent_send` 发话时放行它排给子代理的，都靠这一条。
- **例外**：用户选“停止，排队的留着”留下的，只有用户能放行（开发者 2026-11-18）。父会话连带中止子会话、或父 Agent 停掉子代理时留下的，停的是父会话，父 Agent 能放行。
- **继续与重试分开**：
  - `resume`：放行留着的并开运行；开不起来（只读、没有模型）时失败，话仍留着。
  - `start`：照旧只“接着跑”中断或失败的那一轮，错误气泡的“重试”用它；它不放行、不取留着的。
  - 输入框只有一个入口：有留着的话时是“继续”（`resume`），没有而上次中断时是“接着跑”（`start`）。
- 放行时会话空闲就开运行，第一条开第一轮；在跑就把它们转成就绪，按取的规则在之后的边界或一轮结束时取。
- **用户自己发起的压缩**：压完会话回到空闲，压缩期间用户发的话留着；用户自己点的压缩，压完由 NeuroBook 自动 `resume`，系统发起的压缩压完留着（开发者 2026-11-18）。
- **交出结果之后**：子代理以收尾工具或文字交出结果后，排着的话留着，不接着跑，因为结果已经交给父 Agent。这偏离了 t07 决定 1 的“completed 后按序取”，开发者 2026-11-18 没有异议。

### 4. 恢复方式

用户在设置里选，宿主（NeuroBook）按它调用内核（开发者 2026-11-18：“合并一起发（默认）、保留原 steer、followup 顺序”）：

| 恢复方式 | 宿主怎么调 | 结果 |
|---|---|---|
| 合并一起发（缺省） | `send({input, replaces: [留着的用户的话]})` | 宿主把留着的用户的话按原顺序与新话拼成一条；内核在同一个受理批里移除那几条（`inputRemoved{reason: "replaced"}`）、放行其余留着的、送进这条新输入 |
| 保留原插话与排队 | `send({input, release: "keep"})` | 放行全部留着的，各保持原模式，排在新话前面 |
| 按排队顺序 | `send({input, release: "followups"})` | 放行全部留着的、都转成排队，一条一轮，排在新话前面 |

- 只合并用户自己的话；宿主的消息不合并，按原顺序在合并的那一条前面放行。
- 拼法（分隔、附件的先后、原文与脱敏）由宿主定，内核只看到一条普通的新输入，输入拦截照常经过它。
- 点继续、没有新话时，`resume({mode})` 同样三种；合并时只合并留着的几条。

### 5. 发出者与指令的权限

- **内核加一种发出者 `host`**：`{kind: "host", source: {plugin, label, ref?, at?}}`。日志里的输入记 `by: {kind: "host", source}`。判等按种类与身份：会话按会话 id，宿主按 `source.plugin`。`source.plugin` 由宿主应用按调用方盖章、给模型的来源说明、算不算用户的授权，都在 bot 提案。
- 权限表：

  | 指令 | 用户 | 会话、宿主 |
  |---|---|---|
  | `edit` | 任何一条，宿主排的除外 | 只能改自己排的 |
  | `remove` | 任何一条 | 只能取消自己排的 |
  | `release` | 任何一条 | 只能放行自己排的，用户停止留下的除外 |
  | `abort` | 能 | 只能停自己派出的子会话（连带中止） |
  | `resume` | 能 | 只放行自己排的 |
  | `start` | 能 | 能（例如 bot 重启后的自动接续） |

- 不允许时得 `not-allowed`。`inputEdited` 记下编辑者；`runStarted` 记下开这次运行的发出者（`send`、`start`、`resume` 都算）。
- 应答审批与提问的规则不变（输出 41）。

### 6. 日志、快照与远程合同

- 新事件只有一种：`inputReleased{ids, by, mode}`，会话级，回退与 fork 不撤销，同现在的 `inputQueued`、`inputRemoved`。`inputRemoved` 加原因 `replaced`。
- `send` 加可选的 `replaces` 与 `release`；新增指令 `resume({mode?})`、`release({inputIds})`。
- 快照与远程合同里，缓冲区的每条带 `by` 与 `state`：就绪，或留着与原因（收口方式与码、空闲时排的、停止与谁停的）。
- 乐观消息按 `send` 交回的 `inputId` 确认，不再按先后：留着的先跑时，先到的是旧话。

### 7. 对话视图

- 排队区每条带发出者；留着的显示“已暂停”与原因，文案按原因码取。“继续”放在排队区头上，与输入框的入口是同一个。
- 状态栏的 Agent 活动条把“有留着的话”算进“等你处理”。
- 停止的两个选项见第 2 小节。
- 恢复方式放在 Agent 对话的设置里，缺省“合并一起发”。

### 8. 备选方案与取舍

- **不改内核，周期任务只在会话空闲、缓冲区为空时发**（bot 提案第三轮后主 Agent 的另一条路）：内核不动，代价是周期任务不能设成插话，排着的周期任务也不在排队区里显示。开发者 2026-11-18 问“直接改内核的缓冲区逻辑呢，架构上会不会更好？”，比较后选了本方案。
- **按收口方式逐行列表**（第一稿）：审查又找出文字收口、进程内中断、空闲时排队三条表外的路径；改成“回到空闲”一处。
- **合并做进内核**（第一稿）：合成的那一条要定内容、附件、原文、输入拦截，事件形状一发布就不能改；放到宿主拼，内核只做“移除几条、送进一条”。
- **单独写“转成留着”的事件**（第一稿）：同一状态有两个来源；改成由日志推出。
- **压完在同一次运行里接着开一轮**（第一稿）：已写下的压缩运行里出现对话轮，对话视图与运行结果的含义都要改；改成压完留着、用户自己点的压缩由宿主自动放行。

## 五、数据、接口、安全、迁移、发布与回滚影响

- 数据：会话日志多一种会话级事件；旧日志照读，状态按同一条规则推出。
- 接口：内核的 `resume`、`release`、`send` 的两个选项、宿主发出者、指令按发出者校验、`runStarted` 与 `inputEdited` 记发出者，快照与远程合同的缓冲区条目加 `by` 与 `state`；NeuroBook 加一项用户设置、对话视图的“继续”“已暂停”、停止的第二个选项、用户压缩后的自动放行。
- 普通会话的行为变化：
  - 停止后留着的话：现在用户再发一条时新话先跑、留着的跟在后面；改成留着的先跑，缺省与新话合成一条，新话在最后。
  - 出错、重启之后排着的话：现在下一次运行会顺手带走；改成留着，用户发话或点继续时先跑。
  - 手动压缩时发的话：现在卡住；改成压完自动放行。
  - 子代理交出结果后、空闲时排进来的话：留着，等放行。
  - 错误气泡的“重试”不再顺带发出排着的话。
- 安全：发出者不能再改写或取消别人的话，宿主的话不会被别的发出者顺手带走。
- 迁移与回滚：无数据迁移；不支持降级，回滚要连同写过新事件的会话一起处理（同现有规则）。

- `harness/session.md`：`inputReleased`、`inputRemoved` 的新原因。
- `agent/sessions.md`：远程合同的 `resume`、`release` 与 `send` 的选项，缓冲区条目的 `by`、`state`。
- `agent/conversation.md`：输出 6、9 的停止、继续与重试，恢复方式的用户设置，用户压缩后的自动放行。
- `agent/subagents.md`：输出 10、16 的交出结果后留着、`agent_send` 放行自己排的、连带中止的放行。
