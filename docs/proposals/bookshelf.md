# 书架页：没打开项目时的首页

2026-10-10 起草。开发者要求重新设计没打开项目时的书架页，更贴合 NeuroBook 的产品与风格，不照搬旧应用。本稿只给方向与取舍；方向选定后，先在 Lab 里做出静态稿给开发者看，再写 Spec 与实施计划（[t75](../../.agents/works/w00017-application-runtime-architecture/tasks/t75-bookshelf/README.md)）。

## 问题

新应用没打开项目时，窗口显示的是一个空的工作台：侧栏是资源管理器的用户资产，编辑器区是空态，选项目只能靠命令面板里的“打开项目”。这有三个问题：

- 用户第一眼不知道该做什么；
- 已有作品看不到全貌；
- 新建作品没有入口。

旧应用有书架页（`ProjectPickerView`）：2:3 封面网格、新建对话框、封面管理。它的问题是：

- 封面网格要求每本书都有封面，而大多数作品没有，只好退化成生成的占位封面；
- 信息只有书名与简介，看不出写到哪了、上次停在哪；
- 页面是一个独立的“选择器”，打开作品后它就消失了，与写作本身没有连接。

## 目标与非目标

**目标**：

- 打开应用最常见的动作是接着写，所以要一步回到上次的位置；
- 一眼看到全部作品与各自的进展，作品多了也不乱；
- 新建作品、加入已有目录都有直接入口；
- 视觉上是 NeuroBook 自己的样子。依据 [设计语言](../../packages/nb-ui/docs/design-language.md)：器械用黑体、稿面用宋体，暖色稿面与冷色器械分家。

**非目标**：

- 这一版不做云同步、协作、封面生成；
- 不在书架上删除作品目录。“从书架移除”只取消登记，删除文件留给文件管理器。

## 当前行为与证据

- `nbook.projects` 的远程合同只有“列出”和“登记”，见 `packages/neuro-book/src/plugins/projects/shared/contracts.ts`。列出结果只有名字、路径、运行状态与代次。
- [`runtime/projects.md`](../specs/runtime/projects.md) 把书架页、最近打开、新建项目、移除登记、重命名列为 `nbook.projects` 的后续范围。
- 项目身份写在项目目录的 `.nbook/project.json`。打开项目要起一个子进程，所以书架不能为了显示字数去逐个打开项目。

## 方案

### 推荐：书房（继续写作 + 书脊书架）

页面不是一个选择器，而是一间书房。

**上半部分：继续写作。** 显示最近打开的一部作品，内容依次为：

- 书名；
- 最后编辑的章节名；
- 那一章最后一段的前两三行，用宋体排成稿面；
- 今天和最近写了多少字；
- 一个“继续写作”按钮：直接打开项目，并在编辑器里定位到那一章的末尾。

**下半部分：书脊书架。** 每部作品是一根竖立的书脊：

- 书名竖排，用宋体；
- 书脊厚度随字数增长，有上下限，一眼看出哪部写得多；
- 颜色取作品的主题色，没有就按书名生成，在当前配色里取和谐的色阶；
- 悬停或键盘聚焦时书脊前移，旁边展开扉页，显示简介、字数、章节数、最近编辑时间与路径，操作有打开、在新窗口打开、编辑信息、从书架移除；
- 书架末尾是“新建作品”和“加入已有目录”两根空白书脊。

```text
┌──────────────────────────────────────────────────────────────┐
│  继续写作                                                     │
│  《长夜行》 · 第十七章 雪线                    今天 1,240 字   │
│  ┌────────────────────────────────────────┐                   │
│  │ 他把灯放低一些，雪落在灯罩上，化成……   │   [ 继续写作 ]    │
│  └────────────────────────────────────────┘                   │
├──────────────────────────────────────────────────────────────┤
│  书架                                    [书架 | 列表]  排序 ▾ │
│  ┃长┃┃北┃┃雾┃ ┃无┃┃短┃       ┊新┊┊加┊                          │
│  ┃夜┃┃方┃┃中┃ ┃名┃┃篇┃       ┊建┊┊入┊                          │
│  ┃行┃┃以┃┃城┃ ┃稿┃┃集┃       ┊作┊┊目┊                          │
│  ┃  ┃┃北┃┃  ┃ ┃  ┃┃  ┃       ┊品┊┊录┊                          │
└──────────────────────────────────────────────────────────────┘
```

**为什么推荐它**：

- 中文书名竖排是出版物自己的样子，也直接体现“稿面用宋体”；
- 书脊比封面窄，几十部作品也放得下，而且不需要封面图；
- 厚度和“继续写作”把“写到哪了”放在第一眼，旧版没有这层信息。

**另一视图：列表（扉页列表）。** 书架右上角可以切换。每部作品一行，像文学期刊的目录：

- 宋体大书名、一行简介；
- 字数、章节、最近编辑时间；
- 可选一条最近 30 天的写作量细条。

列表适合作品多、要按名字或时间找的时候，也是窄屏（390px）下的默认呈现。窄屏下书脊会太细，竖排书名放不下。

### 备选：封面网格（旧版的做法）

2:3 封面网格最常见、最容易理解。不推荐作为主视图：

- 多数作品没有封面，生成的占位封面缺少信息量；
- 网格每行只放得下四五本书。

以后支持封面图时，可以作为扉页里的一张图出现，不另做一种视图。

## 影响

**数据**：书架要显示的字段分两类，来源不同。

- **作品自己的信息**：书名、简介、主题色。写在项目目录的 `.nbook/project.json`，随目录移动、复制。修改它不需要打开项目，服务端直接读写这个文件，并按现有规则核对项目身份。
- **统计**：字数、章节数、最近编辑的章节与片段、每日字数。
  - 由项目实例在运行中计算，在项目关闭和定时节点交给服务端，存进 user 分区的 Storage 记录；
  - 书架只读缓存，不为显示统计而启动项目子进程；
  - 从没打开过的作品显示“尚未统计”；
  - 统计依赖章节文件的识别规则（[`workspace/folder-kinds.md`](../specs/workspace/folder-kinds.md) 的内容文件夹），具体口径在 Spec 里定。

**接口**：`nbook.projects` 的远程合同加三类方法，合同版本随之升级：

- 新建：在给定位置建目录、写 `.nbook/project.json`、按模板建初始文件夹，然后登记；
- 修改作品信息；
- 从书架移除：只取消登记。

**页面**：

- 没打开项目时，`/` 显示书架页，而不是空工作台；
- 打开项目后照旧是工作台；
- 工作台标题栏的项目切换（t74）与书架共用同一份作品列表。

**回滚**：书架页是一个独立的页面贡献，撤掉后回到现在的空工作台与“打开项目”命令。

## 对 Spec 的预期改动

- `runtime/projects.md`：新建、修改信息、从书架移除，三项的输入、失败码与验收；`.nbook/project.json` 增加书名、简介、主题色字段。
- 新建 `workbench/bookshelf.md`：书架页的布局与两种视图、继续写作的定位规则、键盘操作、窄屏呈现、空书架与统计缺失时的呈现、各种失败时的提示。
- 项目统计的口径与缓存，写在 `runtime/projects.md` 或单独的 Spec。

## 待定项

1. **方向**：推荐“书房”（继续写作 + 书脊书架，另有列表视图）。选定前，先在 Lab 做出两个方向的静态稿给开发者看。
2. **新作品放在哪**：推荐默认放在用户设置的“作品目录”下（首次新建时询问并记住），也可以每次自选位置。
3. **每日写作量**：需要按天记字数，依赖项目实例记录写作历史。推荐第一版只显示“今天”和总字数，按天的细条等写作历史有了再加。
4. **封面图**：推荐第一版不支持，用主题色书脊；以后作为扉页里的图加入。
