# 官方站重写：一个进程、两个模块、按能拆开的边界写

## 一、问题

现有官方站 `neuro-book-site`（`nbook.notnotype.com`，另一个仓库）是 Nuxt 全栈加 Prisma 与 SQLite 的单体，承载账号、设备码关联、对外 OAuth、云备份、工坊与管理后台。开发者决定重写它（2026-11-23、2026-11-24），原因与要求是：

- 不再背旧版的历史包袱；以后要承载市场、小说发布、论坛，需要能把某一块单独拆出去、甚至换语言重写；
- 遥测（[w00053](../../.agents/works/w00053-telemetry-feedback-stats/README.md)）需要一个服务端，开发者要它落在官方站里；
- 旧站的前端依赖用链接方式引 `nb-ui`，干净的构建机装不上（[Task 128](../../.agents/tasks/128-neuro-book-site-deployment/README.md) 的记录）；nb-ui 是本仓库不发布的工作区包。

## 二、目标与非目标

目标：

1. 第一版交付账号与管理：用户名或邮箱加密码登录、Google 与 GitHub 登录、凭注册码注册、对外提供 OAuth 服务、管理面板（用户、注册码与邀请码、OAuth 客户端、统计看板、审计）。
2. 第一版交付统计模块的服务端：收事件、聚合、给看板查询。收集哪些数据、给用户看的条款不在本稿，由 w00053 的提案定。
3. 第一版是一个进程，但账号与统计按“以后能拆成两个服务”的边界写，拆分时对外合同不变。
4. 后端的合同测试是黑盒的，换语言重写后原样可用。
5. 旧站的数据不丢：账号类数据导入新站，其余原样留存，重建对应功能时再导入。
6. 代码放在本仓库，技术栈与仓库一致（Bun、TypeScript、Hono、TypeBox、Vue 3、nb-ui）。

非目标：

- 第一版不做市场（工坊）、云备份、设备码关联、小说发布、论坛。
- 不保持旧应用与旧站之间的接口兼容；llmlint 已废弃，旧站 OAuth 服务没有要保留的客户端。
- 第一版不发邮件：没有邮箱验证与自助找回密码。
- 不做网站自身的访问量统计，不做 Agent 与用户反馈的收件箱。
- 不对机器规格与并发量设硬性验收口径（开发者 2026-11-24）。设计时按 2 核 2 GB 的机器估算，不写成验收条件。

## 三、当前行为与证据

- 旧站的模块与数据：账号（`username` 唯一且不可改、可空的密码哈希、角色、状态）、上游身份（GitHub）、注册码、邀请码、工坊条目与版本及互动、设备码关联与令牌、实例备份、OAuth 客户端与令牌；工坊压缩包与加密备份是数据卷里的文件。密码哈希是 `scrypt:<盐>:<十六进制>`。生产已开放凭注册码的密码注册，不能假定只有站点所有者一个账号。来源：旧站仓库的 `prisma/schema.prisma`、`server/utils/password.ts`、`PROJECT-STATUS.md`（2026-11-24 读取）。
- 新应用 `packages/neuro-book` 里没有调用官方站的代码：搜 `nbook.notnotype.com` 只在旧应用与 llmlint 的部署配置里命中。
- 身份库的选型与两轮探针见 [w00037 的 t02](../../.agents/works/w00037-official-site/tasks/t02-selection/README.md)：Better Auth 1.7.27 在真实 PostgreSQL 上走通了保留数字用户 id、验旧站的 scrypt 哈希、注册码闸门、对外 OAuth 服务（授权码加 PKCE、`client_secret_basic`、`/userinfo`）、封禁即失效、接仿真上游的社交登录、邮箱撞号时不自动合并、授权中途登录接自家登录路由。
- 探针量到的内存：进程初始化后空闲 85 MB，跑过 argon2 哈希后 165 MB。

## 四、方案

### 4.1 形态：边界照微服务，第一版一个进程

开发者先提出用微服务的思想搭，随后定第一版不拆进程、注意解耦、让以后想拆时不困难（2026-11-24）。本稿据此定四条规则，每一条要么能机检，要么写错了会直接报错：

1. **模块只经公开入口互相导入。** 每个模块是一个工作区包，仓库已有的“跨包只经包名与公开入口”检查直接生效。
2. **数据库分开。** 同一个 PostgreSQL 实例里，每个模块一个 schema、一个数据库角色与连接池；没有跨 schema 的 JOIN、外键与事务。运行时角色只有自己 schema 的读写权限，写错了报没权限。
3. **合同是 HTTP。** 每个模块是一个挂在自己路径前缀下的 Hono 子应用，接口的 schema 在它的合同包里；进程入口只负责把模块装起来。拆分时加第二个入口文件。
4. **合同测试是黑盒。** 测试只认服务地址，不知道后面是一个进程还是两个；拆完后同一套测试跑通，就是拆对了的证据。

模块之间只有一个接口：统计模块声明它需要一个“问身份”的函数（给请求，返回用户 id 与角色，或空），由进程入口把账号模块的实现接进去。第一版在进程内调用，浏览器对两个模块都用同源的会话 Cookie；拆分时把它换成反向代理的转发鉴权或令牌，浏览器看到的合同不变。

第一版少掉的是进程级隔离：统计入口被刷会连带登录变慢，一处内存泄漏影响全部。靠反向代理对统计入口限流、限请求体大小来挡。出现下面任一情况再拆：统计写入拖慢了登录；某个模块要换语言；市场的扫描任务上线（它本来就得是独立进程）。

### 4.2 包

| 包 | 内容 |
|---|---|
| `nb-site-identity-contract` | 账号模块的接口 schema 与它的合同测试；只依赖 TypeBox |
| `nb-site-identity` | 账号模块的实现：Hono 子应用、“问身份”的函数、迁移 |
| `nb-site-telemetry-contract` | 统计模块的接口 schema（事件写入口与看板查询）与它的合同测试；只依赖 TypeBox。NeuroBook 里的遥测插件用它的事件 schema |
| `nb-site-telemetry` | 统计模块的实现 |
| `nb-site-server` | 进程入口：读配置、建连接池、挂模块、健康检查、迁移命令、管理员初始化命令、旧站数据导入命令；镜像与部署脚本 |
| `nb-site-web` | 前端 |

合同单独成包，有三个理由：实现包换语言重写或删掉时，前端依赖的合同还在；合同测试所在的包不依赖实现包，没法 import 被测代码，黑盒由依赖关系保证；NeuroBook 应用要用事件 schema，但不该依赖一个带数据库驱动的服务端包。

### 4.3 进程与部署

- 一个 Bun 进程加一个 PostgreSQL，Docker Compose；反向代理用生产主机上已有的 Nginx。
- 前端的构建产物打进同一个镜像，由这个进程发静态文件：接口与页面永远同一个版本，升级与回滚都是换一个镜像。
- 镜像在 CI 里从本仓库构建；主机按固定摘要升级，升级前导出一次数据库，健康检查不过就换回上一个镜像。
- 迁移是每个模块自带的纯 SQL 文件，只往前；进程启动前由入口命令执行。迁移用属主角色。
- 配置只来自环境变量，启动时校验，缺密钥不启动。日志是 JSON，写标准输出。
- 健康检查分两个：进程活着；数据库可达且迁移已全部执行。

### 4.4 地址布局

- 站点域名：`/` 前端；`/api/identity/v1/*` 账号模块自家接口；`/api/identity/auth/*` 只放行标准 OAuth 端点与 Google、GitHub 回调；`/.well-known/*` 发现文档；`/health/*`。
- 统计的写入口单独一个域名，第一版指向同一台机器。发出去的客户端里地址改不了，单独的域名让写入口以后能独立搬走。
- OAuth 的签发者地址与端点路径在第一个外部客户端接入之前可以改，之后不能。

### 4.5 账号模块

- **库**：Better Auth。登录、注册、资料、管理这些接口写自家路由、内部调库；库在这套插件组合下登记了 83 个端点，挂载处用白名单只放行标准 OAuth 端点与社交登录回调。Google、GitHub 用库的通用 OAuth 插件接入（上游地址可配），生产与测试走同一条代码路径。
- **登录方式**：用户名或邮箱加密码、Google、GitHub。
- **注册**：一律要注册码。沿用旧站的两种码：管理员发的注册码管准入，用户发的邀请码只记是谁邀请的。Google、GitHub 首次登录不自动建账号，要带注册意图、注册码与用户名。
- **邮箱**：新注册必填、唯一，第一版不验证。因为本地邮箱没验证过，不按邮箱自动合并账号：社交登录的邮箱撞上已有账号时拒绝，提示先登录再到账号设置里关联。
- **找回密码**：第一版由管理员在面板里重置。
- **会话**：存数据库；封禁、改角色、改密码都让已有会话立即失效。
- **密码**：新密码用 argon2id；旧站的 scrypt 哈希照验，登录成功后换成 argon2id；哈希限并发，防止同时登录占满内存与 CPU。
- **对外 OAuth 服务**：客户端只能由管理员在面板里登记；授权码加 PKCE、授权确认页、不透明访问令牌、可选的刷新令牌。第一版没有真实的外部客户端，做到合同测试用测试客户端走通标准流程为止。设备码流程等 NeuroBook 应用要接登录时再加。
- **管理接口**：用户列表与搜索、封禁、改角色、踢下线、重置密码；注册码与邀请码；OAuth 客户端；管理操作写进审计表。
- **限流**：登录按 IP 加用户名，注册按 IP；第一版记在进程内存里，拆进程或多副本时换成共享存储。

### 4.6 统计模块的结构

- 写入口一次收一批事件，不带登录；每条事件带客户端生成的 id，重发不重复计数。
- 事件名与属性按登记表校验：不认识的事件名丢弃并计数（新客户端不被旧服务端拒掉），属性不合格只拒那一条。
- 原始事件表按月分区，留若干个月后整月删除；每日聚合表长期保留，看板只查聚合表。聚合由进程内的定时任务做，重算最近两天，可重复执行。
- 不存 IP，IP 只在内存里用于限流。
- 看板第一版是固定的几张图，不做自定义查询。

### 4.7 前端

- 一个单页应用：登录、注册、社交注册补全、账号设置（资料、邮箱、密码、已关联的 Google 与 GitHub、会话）、OAuth 授权确认页、管理（用户、注册码与邀请码、OAuth 客户端、统计看板、审计）。
- Vue 3、Vite、vue-router、nb-ui、Tailwind 4；中英双语，沿用仓库的消息目录做法。
- 接口类型直接取合同包里的 schema，不做代码生成。
- 界面按仓库的设计评审流程：先出静态稿与评审板，开发者定了再实现。

### 4.8 合同与测试

- 合同测试起真实进程、真实 PostgreSQL 与仿真的 Google、GitHub，只用 HTTP；每个测试文件一个随机名的库，跑迁移，用完删掉。
- 造状态只经公开接口、管理接口与管理员初始化命令，不直接改库。与时间有关的行为用环境变量把时限配短，测试等可观察的过期状态。
- 旧站五份集成测试里的场景（注册码并发双花、封禁、限流、OAuth 流程等）是验收场景的来源。
- 服务内部只留少量纯逻辑的单元测试。

### 4.9 旧站数据

- 一次性的导入命令：只读旧站的 SQLite 快照，写进新库。
- 导入：用户（id、用户名、显示名、角色、状态、时间不变；邮箱填 `.invalid` 结尾的占位值并打标记，登录后提示补填）、密码哈希、GitHub 身份、注册码与邀请码及其使用关系。
- 不导入：会话（所有人重新登录）、设备码与令牌、旧 OAuth 客户端与令牌、工坊、备份。后几样连同文件卷原样留在快照里；用户的数字 id 不变，以后导入工坊与备份时靠它关联。
- 切到新站后，工坊页面、云备份、旧应用的设备码关联在重建之前不可用（开发者 2026-11-24 确认）。
- 先在副本上演练并核对条数；切换是停旧站、取快照、导入、起新站、改反向代理；退回是把反向代理指回旧站。

### 4.10 安全与运维

- Cookie 设 HttpOnly、Secure、SameSite=Lax；改状态的请求核对来源；只信任来自反向代理的转发头；请求体有上限。
- 遥测由 NeuroBook 的后端进程发出，不从浏览器发，写入口不开跨域。
- 第一个管理员由命令行创建，密码从标准输入读。
- 数据库每晚导出一份留在本机。

### 4.11 备选与取舍

- **真正拆成两个服务**（主会话最初的提议）：有进程级隔离，但要多做令牌签发与验签、多进程的本地开发与部署，每个进程多占约 100 MB。开发者定第一版不拆，按 4.1 的规则留好拆分的路。
- **不分模块的单体**（[w00053 调研](../../.agents/works/w00053-telemetry-feedback-stats/research/2026-11-23-telemetry-feedback-and-stats.md)推荐过模块化单体）：本稿与它的差别是把模块边界落到包、数据库角色与合同测试上。
- **自己写账号核心、协议部分用小库**：OAuth 客户端库 arctic 已被作者弃用；可用的授权服务器库要么建在 Koa 上、没有 PostgreSQL 适配器，要么存储全要自己接。自写量最大。
- **单独部署现成的身份服务**：Logto、Keycloak、Zitadel、Authentik 与本站同机放不下或基本占满 2 GB；Casdoor、Ory 可能放得下，但界面与注册流程要按它们的模型来，用不上 nb-ui。
- **部署 Umami 看统计**：它是 Next.js 应用，事件属性限 500 字符、不适合承载以后的反馈文本（w00053 调研）；开发者要的是官方站里自带的、类似 Umami 的收集与看板。
- **SQLite**：旧站的做法，单写者、零常驻内存。选 PostgreSQL 是为了按模块分 schema 与角色、分区表、以后拆进程时多个写者，代价是常驻约 200 到 300 MB（估算）。

选 Better Auth 的代价：每个账号必须有邮箱（开发者已定账号要邮箱，旧账号导入时填占位值）；换语言重写时账号模块要整体换实现，靠“对外只有标准 OAuth 端点加自家接口”与合同测试守住。

## 五、数据、接口、安全、迁移、发布与回滚影响

- **数据**：新增一个 PostgreSQL 实例，两个 schema。旧站的 SQLite 与文件卷保留为快照。
- **接口**：官方站的对外接口全部换新；旧应用的关联、备份与工坊发布不再可用。新应用目前不调用官方站，不受影响。
- **安全**：账号、会话、OAuth 服务是安全边界，实现要经独立审查；库的端点靠白名单收窄。
- **迁移**：一次性导入加演练，见 4.9。导入后旧密码仍可登录。
- **发布与回滚**：换镜像；切换当天的退回是把反向代理指回旧站，退回会丢掉切换之后在新站产生的注册与修改。
- **仓库**：新增六个工作区包，按 [`packages/AGENTS.md`](../../packages/AGENTS.md) 与 [模块边界](../modules/monorepo-boundaries.md) 登记；部署脚本进入本仓库。

## 六、对 Spec 的预期改动

在 `docs/specs/` 下新开官方站一栏，接受后先写 `planned`：

- 账号：注册（注册码、邀请码、邮箱唯一）、登录与会话失效、社交登录（注册意图、邮箱撞号）、资料与密码、管理操作与审计、限流；每条编号验收对到合同测试。
- 对外 OAuth 服务：客户端登记、授权码加 PKCE、授权确认、令牌与 `/userinfo`、失败语义。
- 统计：写入口的输入、去重、未知事件与不合格属性的处理、保留期、看板查询。收集的字段与事件清单引用 w00053 的 Spec。
- 运行与部署：配置项、健康检查、迁移、管理员初始化、旧站数据导入的输入输出与核对。

## 七、待定项

1. **OAuth 签发者地址的形态**：推荐在第一个外部客户端接入前定为站点根地址，不带路径；现在不用定。
2. **异地备份**：推荐第一版只做本机每晚导出，开放大量注册前再定异地方案。
3. **图表库**：做看板时选，推荐先看体积小的。
4. **原始事件留几个月**：随 w00053 的收集范围与条款一起定。
