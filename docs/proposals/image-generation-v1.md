# 图像生成第一版：工作台、配方与标签库

给 NeuroBook 加文生图的第一版：作者在编辑区里的提示词工作台上搭提示词、抽卡、挑图，把好图收藏或收进书里。本稿把 [w00042](../../.agents/works/w00042-image-generation/README.md) 到 2026-11-10 为止开发者定下的决定连同取舍收到一处：提示词工作台四轮静态稿的 22 条（[t07](../../.agents/works/w00042-image-generation/tasks/t07-prompt-workbench/README.md#已定)），提示词与配方的能力地图与假设，以及产物管理、模型灵活度与图片存储三次讨论（[t03](../../.agents/works/w00042-image-generation/tasks/t03-core-contracts/README.md#产物管理与模型灵活度2026-11-10-开发者都按推荐)）。插图方言与生图管线（t09、t10）、Agent 工具（t08）、角色视觉档案（t11）、局部重绘（t12）各自另写，本稿只给它们留接口。

## 问题

1. **生图在写作软件之外，产物会丢。** 作者现在在 NovelAI 网页版或法典图鉴这类站点上搭提示词，靠复制粘贴拼进输入框。NovelAI 网页版的历史只在页面会话里，刷新即清空；参数只写在下载的文件里。抽到的好图、它的提示词、它配的是哪一章，全靠作者手工对应。
2. **提示词有结构，输入框没有。** 一半的 V5 社区提示词用空行分节，有人写 `<style>` 标记；画风串整段复制到很多张图里；负面从几份流传的“标准负面”出发各自增删（[社区提示词的结构](../../.agents/works/w00042-image-generation/research/2026-11-10-community-prompt-structure.md)）。复用靠复制，改进一处要改很多处。
3. **标签难找、难懂、写法乱。** 标签是英文的 Danbooru 词，作者多半用中文想画面；权重写法从数括号变成写数值；社区提示词里重复的词、下划线写法、SD 写法、没闭合的权重都很常见。
4. **产物多到管不住。** 一下午几百张，三个月几 GB 到二十几 GB（估计，见[纸面模拟](../../.agents/works/w00042-image-generation/research/2026-11-10-artifacts-and-model-stress-test.md)）。大部分是失败品，少数好图要留，进书的图要跟着书走；清理时不能把要用的图连带清掉。

## 目标与非目标

**目标（第一版）**

- **提示词工作台：** 编辑区里一个标签页编辑一份配方；提示词按节组织，预设是引用加差异，有片段与风格组合；结果与历史在右边。
- **标签系统：** 中文、英文、别名都能搜的打字联想；标签块（一词一块，下面一行中文，权重按数值）；体检；粘贴拆到各节；相近的词。
- **生成：** 首发后端（推荐 NovelAI，取决于 t02），全局排队，取消与失败，费用估算。
- **产物：** 书里的生成记录与缩略图；应用级的图片仓库与空间管理；收藏；书里的插图；图库页。
- **数据形状一次定对：** 以后加 LoRA、参考图、“几选一”、插图方言时，不用迁移已有的配方、预设与记录。

**非目标**

- 插图方言与生图管线（t09、t10）。本稿只定书里的图长什么样（`.image` 文件夹），正文怎么引用另写。
- Agent 工具（t08）。本稿只保证配方、预设、片段是 Agent 用文件工具读得懂的文件，并且检索条件与图库共用一种结构；工具本身另写。
- 角色视觉档案（t11）；局部重绘、放大与它们的谱系（t12）。
- “只换画风”的对比抽卡：开发者 11-10 定第一版不做，要比画风时固定种子、换风格组合再生成。
- 自然语言类后端（gpt-image 等）；ComfyUI 与 SD 的 LoRA、区域提示词。
- 收藏跨机器同步、按画面内容找图、导出细则、按新设定自动重出。

## 方案

### 1. 插件、进程与数据放在哪

一个内置插件（暂名 `nbook.images`），依赖凭据插件 `nbook.credentials`（t04）。它就是 Work 决定里“按媒介各设一个门面”的图像那一个。几块（提示词模型、配方、标签库、生成、图片库、工作台）共用同一套数据形状，现在拆成几个插件只会多出插件之间的合同，还没有独立的第二个使用方；等 Agent 工具或别的后端插件要单独用某一块时再拆。

| 运行位置 | 做什么 |
|---|---|
| 服务端 | 调后端（凭据只在服务端）、全局生成队列、图片仓库与空间管理、标签库查询 |
| 项目实例 | 书里的生成记录、缩略图、`.image` 插图文件夹；配方、预设、片段是普通文件，经文件服务读写 |
| 浏览器 | 工作台编辑器、侧栏词库、图库页、设置里的“图片空间”、`.image` 文件夹在资源管理器里的显示 |

| 数据 | 放在哪 | 跟着书走 | 进 Git |
|---|---|---|---|
| 配方、本书的预设与片段、风格组合 | 作品目录里看得见的文件 | 是 | 是 |
| 书里的图 | 作品目录里的 `.image` 文件夹，缺省放 `插图/` | 是 | 是，建议用 LFS |
| 生成记录 | `.nbook/images/log/` | 是 | 建议提交 |
| 缩略图 | `.nbook/images/thumbs/` | 是 | 可选 |
| 图片仓库（全部原图与收藏） | 本机，图像插件的私有目录（状态根下） | 否 | 不在书里 |
| 我的预设库 | `user://` | 否 | 不在书里 |
| 标签库 | 应用级，t05 定 | 否 | 不在书里 |
| 凭据 | 凭据库（t04） | 否 | 不在书里 |

### 2. 提示词模型

- **一段提示词是一串项：** 词、句子、片段引用。每项带自己的数值权重，可以为负，缺省是 1。第一版的项都是文字；数据上留出“不是文字的项”，以后放 LoRA、参考图。
- **不是括号树。** NovelAI 的花括号、方括号每层乘或除 1.05，可以不配对，可以跨半句话（[权重语法](../../.agents/works/w00042-image-generation/research/2026-11-06-tag-sources-and-novelai.md#权重语法)）。读入时按 NovelAI 的规则把每个词的实际权重算出来；写出时把相邻同权重的词合成一段 `数值::…::`。
- **写法：** 读 NovelAI 的花括号、方括号、`数值::…::`、单独的 `::`、负权重，也读 SD 的圆括号写法；写出 NovelAI 的规范写法。没拆过、没改过的节原样写回；拆过或改过的按规范写法写出。这改了第 1 轮静态稿“读进来的原文原样写回”的约束：约 36% 的社区提示词有一个权重同时管着几节的词，拆节以后原样写回做不到。
- **随机写法** `||a|b||`（NovelAI 的 Prompt Randomizer）在本地抽签，历史记抽到的是哪个。
- **图中文字**（NovelAI 的 `Text:`）单独一项，展开时总放在主提示词最末。官方文档要求它在最末，否则后面的词可能被画成文字。
- **只靠语法能查出的毛病：** 权重没闭合、重复的词、下划线写法、SD 写法、界面设置混进提示词。

### 3. 配方、节、预设、片段

| 概念 | 是什么 |
|---|---|
| 配方 | 一张图“要生成什么”：有序的节、角色框、参数（含尺寸、张数、种子）、底图（预留：源图、遮罩、强度）。作品里的一个文件，带程序写的 id，打开就是工作台标签页；复制出来的换新 id。配方不存历史 |
| 节 | 配方里按用途分的格子，生成时按顺序拼成主提示词或负面提示词 |
| 角色框 | 一个角色（或一个物体、一格分镜）自己的正面与负面提示词，对应 NovelAI 的角色提示词 |
| 预设 | 一种节的一份有名字的内容，节引用它，再记自己的改动 |
| 风格组合 | 画风、质量、负面、参数四份预设的一组，一次套上 |
| 片段 | 有名字的一小组词，哪一节都能嵌 |

**节。** 种类由系统定：主体、画风、质量、内容（原叫“场景与构图”）、自然语言、通用；负面也分几节：官方段、我的负面、要避开的画师。同一种节可以有几个，可以起名，例如“服装”“光照”两个内容节；新建的配方每种一节，多个同种节只在作者自己加、或粘贴时为了保住词序才出现。节和项都可以临时停用。“通用”节不参与“放错节”的检查。

**角色框。** 每个角色框有自己的正面与负面（NovelAI 叫角色的 Undesired Content），可以装文字、物体或一格分镜，标题可改。主体数量只按开头是 `girl`、`boy`、`other` 的角色框自动填。

**预设。** 画风、质量、负面、参数四种节能套，一节最多引用一个。

- **引用加差异：** 配方记着引用了哪个预设、在上面改了哪几项。一位画师、一个年份、一个词、一个参数字段各算一项。改动只有三种：加一项（记着加在哪一项后面，那一项没了就加到末尾）、去一项、改值。
- **更新预设：** 预设的内容在配方里改，点“更新预设”才写回。写回前列出受影响的配方：没改过那一项的跟着变，自己改过的保持自己的值；预设里已经没了的项，针对它的改动作废并提示一次。给一节换预设时照同样的规则处理。
- **其它：** 预设记着在哪个模型上调的，配方换了模型时对不上的节提示一句，不拦。参数预设不含尺寸、张数、种子。画风预设的样图从结果里挑一张，在预设里存一份缩小的副本。“压制”是画风节里权重为负的项：词进哪一节看词的类别，不看权重的正负（`-1::hat::` 是去掉帽子，属于内容）。

**风格组合。** 画风、质量、负面、参数四份预设的一组，一次套上；“本书默认”就是默认的那一组，新配方从它开始。画师相同的两条社区提示词，负面里的画师、压制词、质量词、采样参数有 61% 到 98% 也相同，随机两条只有 1% 到 34%：换画风时这几样多半要一起换。

**片段。** 核心词加陪衬词，陪衬词可以不带；用途是固定的一组，和文件夹分开。一个片段可以分成主提示词一段，加对应各角色框的几段（法典里三成的片段带角色框的内容）。片段是引用，只记关掉了哪几个陪衬词，不加差异层；要大改就拆开成普通词。

**书与预设库。** 预设、片段、风格组合跟着书走，配方只引用本书里的。另有跨书的“我的预设库”（`user://`，原叫“我的书架”，和书架页重名所以改名）：拿进书里是复制一份，并记下来源。官方预设每本书直接可用，只读。

**展开。** 点“生成”时：

1. 每一节如果引用了预设，先取预设的内容，按项套上配方自己的差异；
2. 片段展开成词，去掉关掉的陪衬词；随机写法抽签；
3. 写成 NovelAI 的写法；
4. 按节的顺序拼成主提示词，图中文字放最末；负面各节拼成负面提示词；角色框进角色提示词（各带自己的负面）；参数节进请求参数；
5. 发出去，同时把每一节展开后的内容记进生成记录（第 6 节）。

**备选与取舍**

- **节的种类与个数。** 每种只能一个：拆进各节再拼回，词序不变的社区提示词只有 5% 到 10%。种类由用户自定义：体检、粘贴拆分、联想、跨书复制、Agent 都要先知道“这一节是什么意思”，种类由用户造，这些都会失去依据。取“种类固定、同种可以多个”，数据从第一版起就是有序列表。
- **套预设是复制还是引用。** 复制以后改进画风要改每一份配方；取引用加差异。约九成的负面、八成的画风节离另一条不超过 5 项，差异读得懂。
- **一份预设跨几节，还是组合。** 一份预设跨几节，会让差异、更新确认、预设库复制都复杂很多；组合只是一组引用。
- **片段要不要差异层。** 被改着用的片段约一半，但片段只有十几个词，拆开成普通词比维护差异便宜。

### 4. 标签系统

- **标签库**（t05）：
  - Danbooru 的基础数据：类别、使用次数、别名，起步用 tagcomplete 的数据（MIT）。并入 NovelAI 官方的特殊标签、改名表、各模型自动追加的质量词与负面预设。
  - 中文名第一版必带：标签块下面那行中文和中文联想都靠它。
  - 相近的词（同组、常一起出现）第一版要；来源与授权见“待定项”。
  - 构建时拉取数据，运行时不依赖外部站点。NovelAI 的 `suggest-tags` 作在线增强，能不能用等 t02。
  - 使用次数是 Danbooru 的图片数，只作粗略参考；模型认不认识一个词，不能靠它判断。
  - 成人标签不隐藏；涉及未成年人性内容的标签在构建时去掉。
- **打字联想：** 中文、英文、别名都能搜，片段在同一个列表里；选到属于别的节的词（例如画师），放进它该去的节，当前节是同种或“通用”节时留在原处。
- **标签块：** 一词一块，下面一行中文，权重写成倍率；同一权重的几个词合成组框；每个提示词框可以切回原文。块上的操作：改权重（数值，可以为负）、压掉、相近的词、移到负面、收藏的词、删除。
- **体检：** 第 2 节的语法毛病，加上要用词库才能查的：没收录、放错节、别名、改名表里的旧名。本地检查，不调模型；能自动改的一键整理。
- **粘贴拆到各节：**
  - 一次收整套：主提示词、负面、角色框与角色负面、参数。
  - 默认按原文的段落分节、保住词序（实测中位拆成 3 到 4 节，约两成的词落进“通用”节）；勾“存成画风预设”时才把画风词归拢成一节，并提示要挪动几个词。
  - 负面先和已有的预设比，差得少时提议“套用加改动”。
  - 把 NovelAI 生成的图拖进来，读图里的元数据，走同一张预览。
- 体检与拆分界面与 Agent 共用一套（`images/checks`）。

### 5. 生成

- **后端能力声明**细到“模型加档位”：例如 V5 Full 的 Medium 档固定步数与采样器，不能自定义负面。
- **全局队列：** 点生成时拿当时的配方内容（含没保存的修改）入队，关掉标签页不丢结果；状态栏显示进行中与排队的批次。
- **取消、失败、部分失败**都写进生成记录。
- **费用：** 生成前显示估算，记录里记实际花费。Opus 订阅免费的范围等 t02。
- **首发后端：** 推荐 NovelAI，等 t02 用真实令牌验证。

### 6. 产物：生成记录、图片仓库、收藏与书里的图

| 层 | 放什么 | 在哪 | 清不清 |
|---|---|---|---|
| 生成记录 | 每一批生成了什么，以及之后的标记 | 书里 `.nbook/images/log/` | 不清 |
| 缩略图 | 每张图一张小图 | 书里 `.nbook/images/thumbs/` | 不清 |
| 图片仓库 | 本机生成过的全部原图；收藏的图在这里钉住 | 本机，应用级 | 没收藏的归空间上限管 |
| 书里的图 | 用作插图或被引用的图，带版本与来历 | 书里 `.image` 文件夹 | 不归空间管理 |

- **生成记录。** 每一批记：
  - 来源：配方 id，以后加管线的请求与 Agent 会话；
  - 每一节展开后的内容，连同节的 id、种类与名字；
  - 引用的预设与片段，加上它们当时内容的哈希；
  - 参数、模型、每张的种子与图片哈希、费用。
  
  之后的标记（收藏、删除、清理、收进书里）也追加一行。只追加；按天、按机器分文件，两台机器经 Git 合并时不冲突。
- **图片仓库。** 本机、应用级，全部原图按内容哈希存，同一张只存一份。仓库目录不对作者开放，作者不在里面挪文件：现有图库软件最常见的故障，就是文件被挪走、索引对不上。浏览器经插件自己的读图路径取图。
- **收藏**是应用级的：
  - 收藏的图在仓库里钉住，出现在跨书的“我的收藏”里，书删了也还在。
  - 收藏时另存一份完整来历：按节的提示词、当时预设与片段的名字和内容、参数、模型、种子、来自哪本书哪份配方。原图字节不改，NovelAI 写在图里的元数据留作备份。
  - 第一版只存本机，提供“导出收藏”：文件名可读，附来历说明。跨机器同步等平台的[同步提案](storage-service-and-sync.md)。备份整个状态根会连明文的凭据库一起带走，所以导出是收藏唯一的备份手段。
- **书里的图。**
  - 一张图一个 `.image` 文件夹（`<说明>-<短 id>.image/`），里面是各个版本（`v1.png`、`v2.png`……）与 `image.json`（id、说明、当前版本、各版本的来历快照）。
  - 资源管理器经[文件夹类型](../specs/workspace/folder-kinds.md)已有的渲染贡献点，把它显示成一张图；整个文件夹能拷到别的书。
  - 持久的引用（正文的插图、定妆图、配方的源图与参考图）只指向书里的图：一张仓库里的图一被这样引用，就自动收进书里。收藏的图拿到别的书里用，也是复制进那本书。同一张图在仓库和书里各一份，是有意的。
- **引用一律按 id。** 配方、预设、片段、风格组合、书里的图都带程序写的 id；复制出来的换新 id；改名、移动都不影响引用。
- **历史与恢复。**
  - 结果区默认显示最近一批。
  - 历史缩略图带按天分段，带角标（收藏、在书里、花过点数、原图已清），可以只看收藏的。
  - 点一批只看那批图；“恢复这批的配方”另有一个按钮，先显示和当前配方的差异；恢复是编辑器里可撤销的一次编辑。
  - 恢复时仍引用原来的预设，差异按当时的内容重算；找不到的预设或片段，按当时展开的内容恢复成普通词，并提示一句。
- **图库页。** 编辑区里的一个页面标签，一本书一个。全书的图按天分段排成网格，按配方（含已删除的）、日期、状态筛选。检索条件是一种数据类型，以后 Agent 工具用同一种。

一张图生成以后的去向：

1. **生成：** 原图进仓库，书里追加一条记录、存一张缩略图。
2. **收藏：** 在仓库里钉住，进“我的收藏”。
3. **用作插图，或被引用：** 复制进书里的 `.image` 文件夹。
4. **什么都不做：** 算失败品，到空间上限时按顺序清掉。
5. **删掉这张：** 立刻删，记录里标一行。

原图被清掉以后，书里的缩略图与记录还在：能看到抽过什么，能恢复配方，只是没有原图。

### 7. 空间管理

照 Telegram 的“存储用量”。设置里一个“图片空间”分区（page 分区，[设置窗口](../specs/settings/settings-window.md)）：

- **占用：** 分可清理的原图、收藏、缩略图三块；书里的图单列一行，只显示，不归这里清。
- **按书列出：** 每本书在仓库里占多少、最早的图是哪天的，可以单清一本；已移出书架的书单列一组。
- **只有一个开关：上限，** 缺省 40 GB，只管没收藏的原图。收藏与书里的图不会被自动删，所以不放进会自动清的上限里，占用单独显示。
- **到上限自动清：** 最久没看过的先清，清到上限的九成；最近 7 天生成的、等审阅的候选（t10）不清；状态栏提示一次清了多少。也可以手动清：按书、按时间，先预览再确认。

和 Telegram 的不同：Telegram 清掉的缓存能从云端重新下载，这里清掉的原图就没了。同一个种子能不能重新抽出同一张图，要等 t02 实测。所以有两样补偿：7 天的保护期；收藏键一按，好图就不会被清。

按模拟的用量估计，40 GB 在重度抽卡下约能存 5 个月，角色设计约 1 年，连载配图好几年。

**备选与取舍（第 6、7 节）**

| 备选 | 为什么不取 |
|---|---|
| 历史写进配方文件 | 作者没保存时写回批次就是磁盘冲突，编辑器只能“重新载入”或“覆盖”，总要丢一样；每批约 2.5 KB，常用的配方两三周就超过作品文件约 960 KiB 的正文上限；Git diff 被生成记录淹没 |
| 历史放在配方旁边的同名文件 | 在资源管理器里改名、移动配方时落下它 |
| 配方做成文件夹（配方加历史） | 编辑器要把文件夹当成一份文档打开，这是新能力；“配方是一个文件”也得改 |
| 原图放书里（`.nbook/cache/images/`） | 拷书能带走全部，但书三个月涨几 GB 到二十几 GB，Git 必须忽略，同步盘被撑爆；`.nbook/` 下的文件浏览器也读不到，读图路径照样要另开 |
| 好图搬进书的控制目录、随书走 | 书多约 0.7 GB（重度抽卡三个月），还要跨进程搬文件；改成应用级收藏加导出 |
| 书里的图平铺，另放一份总清单 | 别的工具看得见图，但在资源管理器里移动、改名以后清单就对不上了 |
| 到上限只提醒、不自动清 | 一张都不会意外丢，但不理提醒的话会一直涨到磁盘满 |
| 再加按时间保留（Telegram 有） | 多一套状态，收益不大 |

### 8. 工作台界面

界面已在[评审板](../../.agents/works/w00042-image-generation/tasks/t07-prompt-workbench/artifacts/review/index.html)上定稿，要点：

- **布局：** 工作台是编辑区里的一个标签页，一个标签页一份配方。提示词在左、结果在右，各占一半；结果默认显示最近一批的大图，看大图进灯箱。
- **词库：** 在外壳的侧栏，和资源管理器换着用，分“本书”和“我的预设库”。预设页只做管理：改名、复制、放进预设库、删除、看用在哪。
- **收起：** 参数只露一行摘要，点开才展开；套了预设的节默认收起成一行，写着预设名和改了几处。
- **窄屏**（390 宽）：分段切换“提示词”与“结果”，生成后自动切到结果；词库是底部抽屉。
- **Agent** 不嵌进工作台，留在对话视图里经工具读写（t08）。
- **后端差异：** 静态稿按 NovelAI 的形态画；SD、ComfyUI 缺的部分在界面上标出。

## 影响

- **数据与格式：**
  - 新的持久化格式：配方、预设、片段、风格组合的文件；生成记录；`.image` 文件夹与 `image.json`；图片仓库与收藏记录；缩略图。
  - 第一版就按“节是有序列表、权重在每一项上、项可以不是文字”的形状存，以后加功能不迁移。
  - 文件的具体格式在 `images/recipes` 与 `images/library` 里定。
- **宿主能力与接口：**
  - 插件私有目录：[`runtime/plugin-api`](../specs/runtime/plugin-api.md) 写的是“另定”，[插件的数据与状态](plugin-data-model.md) 里大文件要走的“文件或资产服务”也还没有，图像插件是第一个使用方。
  - 生成在服务端跑（凭据在那里），原图由服务端写；生成记录、缩略图与插图文件夹由项目实例写。两步之间崩溃会留下没有记录的原图，所以仓库启动时要对一次账。
  - 用到的已有贡献点：编辑器（工作台）、侧栏视图（词库）、设置的 page 分区、状态栏、文件夹类型的渲染贡献点（`.image`）。另要插件自己的读图路径。
- **安全：**
  - 凭据只在服务端，不进浏览器（t04 改模型服务的规则）。
  - 写进图片的元数据只写白名单字段，不写凭据与本机路径：ComfyUI 把整个工作流嵌进图，有人从公开图片里扫出了几百个有效的 API key。
  - 成人标签不隐藏；涉及未成年人性内容的标签在构建时去掉。
- **跨 Work：**
  - **canon**（w00039）：定妆图第一版存具体版本文件的路径，换当前版本时问一句再写 canon。以后再议让 `image` 字段存图片 id。
  - **文件访问与改动记账**（w00032 t13）：`.image` 文件夹里的图只记哈希，不再全量存一份；插件代作者执行的写入（收进书里、换版本）进不进审查收件箱，要一起定。
  - **插图方言**（t09）：`<image-gen>` 加一个程序写的 id；`<image-generated id>` 解析到 `.image` 文件夹的当前版本。
  - **编辑器：** 接受候选要往打开着的文档里改一处，现在没有这个入口（随 t10）。
- **迁移：** 新功能，没有要迁移的数据。
- **体积：** 进书的图每三个月几百 MB，建议用 Git LFS；给作者一张“哪些进 Git”的表和建议的 `.gitignore`。
- **发布与回滚：** 内置插件，可以停用。停用后书里的配方是文本文件、插图是装着图片的文件夹，别的工具照样能打开；图片仓库留在本机，重新启用后接着用。
