# 本机统计、遥测与反馈：按“能不能认出人”分级

## 一、问题

NeuroBook 现在不知道有多少人在用、用的是哪个版本、哪些功能有人用、哪里最常出错；用户也看不到自己的字数、模型用量这些统计。开发者要两类互补的能力（2026-11-23）：给用户自己看的本机统计，与给产品改进用的匿名使用数据与反馈。

约束有三条：

- 用户是小说作者，正文、设定与对话内容不能离开本机。
- [`runtime/diagnostics`](../specs/runtime/diagnostics.md) 规定诊断不联网、不是遥测平台；遥测必须是独立的插件与通道。
- 收集要站得住规则：个人信息保护法对同意、告知与出境的要求，以及面向欧盟分发时的同意规则。调研见 [w00053 的三份报告](../../.agents/works/w00053-telemetry-feedback-stats/README.md)。

## 二、目标与非目标

目标：

1. 一个本机统计插件：记字数、模型用量、功能使用等，给用户看仪表盘（含日历热力图），不联网。
2. 一个遥测插件：默认发一份不带标识的匿名基础信息与在线心跳；用户同意后再发使用统计；每一档有独立开关，用户能看到将要发送的内容。
3. 反馈通道：诊断报告与用户写的反馈，后者每次确认才发；以后加调查问卷。
4. 两份文字：应用里的遥测说明，官方站的隐私政策与服务条款。
5. 服务端落在官方站的统计模块，见 [官方站重写](official-site-rewrite.md)。

非目标：

- 不带持久的安装标识，不跨天跟踪同一个安装。
- 不发逐条带时间的操作事件流。
- 不把匿名数据与账号关联。
- 第一版不把遥测开放给第三方插件（[w00053 t03](../../.agents/works/w00053-telemetry-feedback-stats/tasks/t03-telemetry-for-plugins/README.md)，搁置）。
- 给 OpenRouter 的应用归属请求头不属于遥测，由模型服务一侧做（[w00032 t45](../../.agents/works/w00032-agent-integration/tasks/t45-openrouter-app-attribution/README.md)）。

## 三、当前行为与证据

- 新应用没有任何对外上报；首次启动向导（`FirstRunWizard`）第 1 步可以点“跳过”或按 Esc。
- 已有的数据源：项目实例算好的字数统计 `projects.stats`（[`runtime/projects`](../specs/runtime/projects.md)）；每次模型请求的 token 与费用（[`agent/request-trace`](../specs/agent/request-trace.md)）。
- 桌面版的自动更新向 GitHub Releases 检查（[桌面发行](desktop-distribution.md)），不经过官方站。
- 官方站的生产主机在境外（开发者 2026-11-24）。
- 调研的要点（子代理查一手来源，主会话只核对了个人信息保护法的条文原文）：
  - 国内的认定方法把“以默认选择同意等非明示方式征求同意”列为未经同意收集；国家标准把主动勾选或点击作为明示同意的动作；个人信息保护法第十三条没有“正当利益”，第四条把匿名化处理后的信息排除在个人信息之外。
  - 欧盟：依赖同意时预先勾选无效；应用外发设备上的信息落入 ePrivacy 第 5(3) 条，不以是否个人信息为界。
  - Chrome 的更新协议用“距上次上报过了几天”算活跃数，不需要稳定标识；Go 工具链的遥测与 Homebrew 都不带标识。
  - Mozilla 的 Glean 是每天一份汇总加单独的事件上报；Syncthing 在报告结构变动时提高版本号并重新询问。

## 四、方案

### 4.1 分级：看能不能认出人

分界看三件事：能不能把两次上报认成同一个人、里面有没有用户写的内容、有没有绑到账号。

| 档 | 内容 | 怎么开 |
|---|---|---|
| 匿名档 | 每天一份基础信息；应用开着时每 15 分钟一次在线心跳 | 默认发；首次启动的告知显示之前不发；设置里有独立开关 |
| 一级 使用统计 | 当天各项的计数与分档 | 向导里的开关，默认不勾选；用户在向导里同意后才写设置，设置没开就不发；向导被跳过保持关闭 |
| 二级 诊断报告 | 崩溃与错误的详情 | “以后自动发送”的开关，默认关；没开时每次崩溃后问一次 |
| 三级 含内容的反馈 | 用户写的文字与他选择附上的内容 | 没有长期开关，每次提交都要看过并确认 |
| 账号档 | 登录官方站后的账号数据 | 注册时主动同意条款；见官方站的隐私政策 |

匿名档成立的三个条件：不带任何持久标识；服务端不存 IP，反向代理对写入口不记访问日志里的 IP；每一项只有少数几种取值，合在一起也不足以把一个安装从人群里区分出来。每份上报带一个只用于重发去重的随机编号，下一份换新的。

使用统计放在要同意的一边，是因为它项目多，用户不多时组合起来有可能把一个安装区分出来。

### 4.2 收什么

**匿名档，每天最多一份**：应用版本、发行渠道、运行形态；操作系统及大版本、架构；界面语言；大区（客户端由本机时区换算成七八个取值之一，不发时区本身）；距上次上报过了几天（分档）；安装所在周；“使用统计”“自动发送诊断”两个开关各自是否开着；首次启动向导的结果。

**匿名档，在线心跳**：应用版本、运行形态。客户端按整 15 分钟的时间段每段至多发一次，服务端只给那一段的计数加一，不存单条记录。

**一级**：

1. 功能使用：固定、公开的名单里每一项当天的使用次数分档。
2. 每一项功能距上次使用过了几天（分档）。
3. 里程碑（这份安装至今是否做过）：建过项目、写满一千字、配过模型、发过第一次 Agent 请求、装过第三方插件、登录过官方站。
4. Agent 用量分档：会话数、请求数、失败请求数、工具调用数、输入与输出与缓存 token；模型提供方类别；公开名单内的模型名，其余记“其他”。
5. 稳定性：按“拥有者加错误码”的次数、崩溃次数、升级结果。崩溃与升级失败另在下次启动时立即补发一条，只有错误码与次数。
6. 耗时分档：启动、打开项目、Agent 首次回应。
7. 规模分档：项目数、最大一部作品的字数、总字数、当天净增字数、累计活跃天数。
8. 第三方插件数量分档、界面主题（内置名单内的名字，其余记“自定义”）。

**二级**：错误码、堆栈（函数名与行号）、去掉用户名的路径、出错前的操作类别序列（不含内容）、应用版本与环境。

**三级**：用户写的文字、类别、用户选择附上的日志片段与截图与对话片段、用户愿意留的联系方式、应用版本与环境。自动附带的内容在提交前可见、可逐项取消。Agent 代写的反馈先落在本机，写的时候不阻塞当前对话、不自动上传，由右下角的非阻塞通知请用户审阅后确认。

**永不收**：正文、设定、提示词、对话内容、文件名、项目名、密钥、模型服务的地址、硬件指纹。

能回答与回答不了的问题见 [w00053 t02](../../.agents/works/w00053-telemetry-feedback-stats/tasks/t02-collection-scope-and-terms/README.md) 的“数据清单与能做的分析”。回答不了的主要是：按天的精确留存、操作的先后与漏斗、同一个安装跨天的变化、国家一级的地域；一级的结论只代表同意的人。

### 4.3 上报形态

每天一份计数汇总为主，少数事件（崩溃、升级失败）立即发。不发逐条带时间的事件流：汇总没有时间点、整份可以给用户预览、每个安装每天一个请求、与本机统计直接共用计数；代价是次日才看到、看不到操作的先后、事后不能换一种方式分析。

### 4.4 三个插件与埋点怎么做

| 插件 | 职责 | 联网 |
|---|---|---|
| `nbook.stats` 本机统计 | 提供记数的服务与指标登记，存本机的按日计数，给用户看仪表盘 | 从不 |
| `nbook.telemetry` 遥测 | 发匿名档与一级；向导里的开关、设置页、“查看将要发送的内容” | 是 |
| `nbook.feedback` 反馈 | 诊断报告、用户与 Agent 的反馈、以后的调查问卷 | 是，每次经用户确认或按二级的开关 |

埋点的接口由统计插件提供，不由遥测插件提供：

- **声明**：每个内置插件在自己的合同里声明它的指标（id 以插件 id 开头、类型、名称与说明、分档方式）。类型有四种：计数、带标签的计数、耗时分布、里程碑。
- **记数**：拥有这个行为的插件在发生处调用统计服务记一次。已经有权威数据的不重复记：字数由项目插件作为提供方从 `projects.stats` 交出，token 与费用由 Agent 插件从请求记录交出。
- **错误码**：由抛出失败的地方经统计服务记数，不从诊断日志里读，诊断仍然不联网。
- **多个实例**：统计服务在服务端实例里，项目子进程与窗口经远程服务调用，攒一小批再发；进程崩溃丢掉最后一小批可以接受。
- **存储**：按“日期、指标、标签”存每天的值，长期留在本机给用户看；遥测读的是昨天那一天的值，不需要清零。
- **遥测只读**：遥测插件经统计插件的只读接口取数，再按合同包里的收集清单筛一遍、分档。一个指标要进上报，得同时满足“插件声明了它”与“收集清单里有它”。第三方插件可以往统计插件记数、给用户自己看，但进不了收集清单。
- **依赖方向**：内置插件依赖统计插件的合同；遥测与反馈依赖统计插件；没有插件依赖遥测。“统计插件不联网”由架构测试守住。

匿名档的字段来自运行时信息，不经统计插件。

### 4.5 用户的控制

- 首次启动向导有一页说明与“使用统计”的开关（默认不勾选）；点了“完成”才写设置。
- 设置页：匿名档、在线心跳、使用统计、自动发送诊断各一个开关；每一项收什么的说明；“查看将要发送的内容”显示下一份上报的原文。
- 关闭后不再发送，本机的统计照常记、照常给用户看。
- 收集清单带版本号。清单变了，客户端在重新告知用户之前暂停上传；一级新增类别要重新取得同意。

### 4.6 服务端

- 写入口三个：每日上报、在线心跳、立即事件；另有诊断报告与反馈的收件（第二阶段，与问卷一起）。
- 原始的每日上报留 90 天后整月删除；聚合结果长期保留。
- 收集清单是合同包里的 schema，每个字段带中英文说明；服务端校验、应用里的说明、官网的“我们收集什么”页面都由它生成。

### 4.7 条款

1. **应用里的遥测说明**：一句话说明目的与能关；分档表；“我们明确不收集”单独一节；每一档怎么关、关了有什么代价；存在哪、存多久；清单版本与变更怎么通知；发给第三方的信息（用户自己配置的模型服务会收到请求内容；OpenRouter 的应用归属请求头）；联系方式。
2. **官方站的隐私政策**：处理者与联系方式；账号数据逐项列出用途与保存期限；Google 与 GitHub 登录时取哪些数据；会话与 Cookie；怎样查看、更正、删除与注销；变更怎么通知；**数据存放在境外**一节。
3. **主动反馈与问卷一节**：不公开、只用于改进产品；附带了什么；保留多久。
4. **服务条款**：账号规则、禁止的行为、服务可用性与免责；不面向不满十四周岁的未成年人。

主机在境外的后果：匿名档与一级不带标识，不涉及个人信息出境；账号档的邮箱等是个人信息，适用个人信息保护法第三十八、三十九条，注册时要单独告知并取得单独同意，另需满足出境条件。出境条件对小规模是否有豁免没有核实，定稿前找懂的人确认。

条款由主会话起草中英两版，不是法律意见。

### 4.8 备选与取舍

- **带随机安装标识**（讨论稿第一版）：能做按安装的留存与跨天分析；国家标准的示例把唯一设备识别码与软件使用记录列为个人信息，默认发就站不住。放弃。
- **使用统计默认勾选**（开发者 2026-11-23 的决定）：参与率高；国内与欧盟的规则都不认预选的同意。开发者 2026-11-24 改为默认不勾选。
- **逐条事件流**：见 4.3。
- **由遥测插件提供埋点接口**：内置插件就会依赖联网的那个插件，关掉遥测也关掉了用户自己的统计，“不联网”的承诺也没处落。
- **部署 Umami 或其它现成的分析服务**：见官方站重写提案的备选。

## 五、数据、接口、安全、迁移、发布与回滚影响

- **数据**：本机新增按日计数的存储；服务端新增每日上报的原始表与聚合表、心跳的计数表。
- **接口**：新增统计插件的服务与指标登记、遥测的三个写入口。收集清单是公开合同，带版本。
- **安全与隐私**：见 4.1 的三个条件与 4.7。写入口不带登录，靠限流与请求体上限防刷；没有标识，伪造的上报无法按安装去重。
- **发布**：遥测说明与隐私政策要先于第一次上报上线；Google 登录上线前要有公开的主页与同域名的隐私政策。
- **回滚**：客户端的开关关掉即停；服务端可以整表删除原始上报。

## 六、对 Spec 的预期改动

- 新增本机统计的 Spec：指标的声明与类型、记数与提供方、存储与保留、仪表盘与贡献点、“不联网”的边界。
- 新增遥测的 Spec：分级、每一档的字段与分档、上报时机与重发、开关与向导的关系、收集清单版本与重新告知、“查看将要发送的内容”。
- 新增反馈的 Spec：诊断报告的内容与脱敏、反馈的审阅与确认、Agent 代写反馈不阻塞对话。
- [`runtime/diagnostics`](../specs/runtime/diagnostics.md) 不改；在新 Spec 里写明遥测不经诊断出口。
- 首次启动向导的组件文档加一页。
- 官方站统计模块的 Spec 引用收集清单。

## 七、待定项

1. **同意率过低时怎么办**：推荐先上线看匿名档里“开关是否开着”的比例；不够用时再评估把一两个是否项挪进匿名档，并更新告知。
2. **面向欧盟分发时匿名档是否默认关**：推荐到时按大区判断，默认关。
3. **调查问卷的范围与时机**：推荐在统计与遥测做完后与主动反馈一起做（[w00053 t04](../../.agents/works/w00053-telemetry-feedback-stats/tasks/t04-surveys/README.md)）。
4. **条款是否另找人做法律审阅**：推荐至少把“数据存放在境外”一节交给懂的人确认。

## 八、决策记录

- 2026-11-23，开发者：要做自动匿名使用统计、Harness 错误与反馈上报（Agent 写反馈不阻塞、不自动上传、用户确认后才传）、给用户自己看的统计插件；隐私开关放在首次启动流程里，默认匿名并勾选。
- 2026-11-24，开发者：收什么分等级，不敏感、不需要持续上报的可以默认收；向导被跳过保持关闭；用户自己要能看模型使用统计、日历热力图、字数统计，其它图不是重点，先有底层数据；要有主动反馈通道；登录后是另一档，有对应的条款。
- 2026-11-24，开发者：使用统计的开关默认不勾选，不勾选时只发匿名、合规的那部分（改掉 11-23 的“默认勾选”）；用户在向导里同意后才写设置，设置没开就不发。
- 2026-11-24，开发者：在线状况给用户看已登录的设备，给开发者看同时在线人数；同意分级（匿名档、要同意的三级、账号档）、使用统计放在要同意的一边、在线心跳每 15 分钟一次默认发；生产主机在境外。
- 2026-11-24，开发者：数据清单与能做的分析“都没问题”；OpenRouter 的应用归属由别的插件负责；把遥测提供给插件先记下并搁置；还要有调查问卷。
