# 工作台布局：一棵树、按矩形摆放与 nb-layout

本稿取代 [工作台外壳的抽象](workbench-shell-abstractions.md) 里的拓扑、容器与布局记录（第 2、3、6、7、8 节）。它的原则（工作台是布局的唯一写者、声明与实例分开、渲染只消费求值结果）和视图合同（第 5 节）沿用。过程与证据见 [w00026](../../.agents/works/w00026-layout-package/README.md) 的 t01、t02，第一轮审查见 [t03 的归类](../../.agents/works/w00026-layout-package/tasks/t03-design/evidences/design-review-triage.txt)。

## 问题

1. **布局分成几棵树，移动就要跨树。** 外壳是七个固定 Part 的网格，工具区域里每个容器又一棵，编辑区再一棵。编辑器的节点没法自然地移到外层，每种移动各写一套规则。
2. **递归 DOM 限制了拖动手感。** `NestedGrid` 每个分支一个 Splitter，叶子嵌在里面。结构一变节点就要换父元素，浏览器会清掉滚动和焦点，外壳靠三层 Teleport 和 `TeleportMemory` 补救，邻居实时让位做不到丝滑。递归 DOM 当初的来由是 reka-ui 的嵌套分割原语，2026-09-20 的改造后它已不再承担拖动、命中、键盘与收起（[`workbench-view-host.md`](workbench-view-host.md) 的改造记录），这个理由已经不成立。
3. **同一件事写了几份。** 工作台视图、编辑器标签、资源树各写了一份拖动手势（共 1110 行，门槛和取消规则相同，已开始走样），拖影也是三套。
4. **同一个位置有几种结果。** `(A | B) | C` 里把 D 放到 B、C 之间，B 的右缘、缝、C 的左缘各是一种结果，落点指示又是按面板的一半估算的，和结果对不上。
5. **窄屏只是压扁。** 390×844 下活动栏占一列，资源管理器和编辑区上下各一半，编辑区只有约 46% 的高度。
6. **布局工具在 nb-ui 里。** 这部分占 nb-ui 非测试代码约三成半，定制时要改库。

## 目标与非目标

**目标**

- 除标题栏外，工作台是一棵树：活动栏、状态栏、工具视图、编辑组都是树上的节点。
- 内容按矩形摆放在同一层，移动只改矩形，实例不重建、滚动和焦点不丢。
- 两种拖动手感，实时布局和落点指示，做成用户设置，缺省实时布局。
- 同一条线上只有一个结果，落点指示画的就是提交后的矩形。
- 应用内浮动，单位是带标签的组，工具视图和编辑器标签都能浮动。
- 窄屏（小于 600）一次显示一个部件。
- 布局工具全部进 `@notnotype/nb-layout`，反馈样式是参数，调样式不用改库。

**非目标**

- 操作系统级窗口：这次只验证两种实现（t12），[`ui/workbench-shell.md`](../specs/ui/workbench-shell.md) 的不承诺项到选型后再改。
- 手机呈现的软键盘适配、触摸拖动与真机验收：这次是验证级。
- 节点种类不开放给插件；反馈外观的插槽等第二个使用方出现再加。

## 当前行为与证据

- **拓扑**：七个固定 Part，“集合与拓扑固定，不可贡献”。外壳设计稿把“Part 的任意重排、状态栏换位”列为以后再做。
- **代码量**：工作台浏览器代码约 1 万行（不含测试），测试约 5900 行；编辑器的组与标签另有约 2000 行。查过 w00025、27、28、32、39 的本地分支，都没有动这些路径。
- **视图的使用**：从代码看，内置视图里显式声明位置的只有资源管理器，多视图容器目前没有依赖。
- **原型**：[t02](../../.agents/works/w00026-layout-package/tasks/t02-prototype/README.md) 的一次性原型经开发者试过认可，提交在草稿分支 `chore/w00026-t02-prototype-drafts`。
  - **验证了**：跨面板搬动后滚动、输入、光标、动画都在，没有实例重建；`solveSashDrag`、`collectSashHits` 不改就能接到按矩形摆放的渲染上，十字交汇和拖动收起都能用；每标签一实例的 JS 堆增量可接受（DOM 占用没有计入）。
  - **限制**：原型靠编辑区边界让 `(A | B) | C` 只有一个结果，本稿取消了这个边界，改由第 1 节的规范形保证，实现时要重新验证；不等长的相邻两块本来就有两种结果（第 3 节）；帧率是无头软件渲染，同条件各轮能差到 35 到 59 帧，真实手感由开发者判断。
- **Trellis 的动画**（[逐帧采样](../../.agents/works/w00026-layout-package/tasks/t02-prototype/evidences/trellis-easing.txt)）：让位由 JS 逐帧驱动，曲线接近 `1-(1-t)^5`，约 470ms。
- **浏览器基线**：[`runtime/browser-host.md`](../specs/runtime/browser-host.md) 写的是 Chrome、Edge 119，Firefox 124，Safari 17.4。`reading-flow` 从 Chrome 137 才有，Firefox、Safari 没有，所以不能依赖它。

## 方案

### 1. 模型

```text
Workbench（每个窗口一个，nbook.workbench 拥有，布局的唯一写者）
├─ TitleBar ──── 树外，固定在最上面
└─ LayoutDoc
   ├─ tree ───── createGrid 的快照：结构、id、ref、两轴尺寸意图
   ├─ panels ─── 面板 id → 角色、名字、标签顺序、活动标签、隐藏、收起
   └─ floats ─── 浮动的面板与矩形，后面的压在前面的上面
```

```ts
interface LayoutDoc {
    version: 1;
    tree: GridSnapshot;                     // 叶的 ref：`panel:<id>` 或 `bar:activitybar`、`bar:statusbar`
    panels: Record<string, PanelRecord>;    // 树里的面板和浮动的面板都在这里
    floats: ReadonlyArray<{panel: string; rect: Rect}>;
    currentEditor: string | null;           // 活动编辑组
}
interface PanelRecord {
    role: "tool" | "editor";
    name?: "sidebar" | "auxiliarybar" | "panel";
    tabs: ReadonlyArray<TabRef>;            // 顺序就是显示顺序
    active: string | null;
    hidden?: boolean;                       // 只有具名面板会隐藏
    collapsed?: boolean;
    restoreSize?: number;
}
type TabRef =
    | {kind: "view"; viewId: string}                  // 工具视图，每个视图只有一个实例
    | {kind: "tab"; type: string; tabId: string};     // 动态标签，例如 type 为 nbook.editor
```

| 对象 | 是什么 | 取代什么 |
|---|---|---|
| **面板** | 带标签的组，树的叶子，也可以浮动 | 工具区域、Switcher 加 ViewContainer、编辑组 |
| **具名面板** | 默认布局里名叫 `sidebar`、`auxiliarybar`、`panel` 的面板。标题栏开关、命令和 `location` 都认这个名字 | 三个 ToolPart |
| **编辑组** | `role: "editor"` 的面板，不是单独的区域，取消编辑区这个子树 | Editor Part、`groups.ts` 的那棵树 |
| **条** | 活动栏、状态栏。固定厚度，不可调、不可收起，只能在四条外边 | ActivityBar、StatusBar 的固定拓扑 |

**与 `createGrid` 的关系。** 树继续用它算尺寸：叶的 `ref` 编码面板或条；运行约束（最小最大、fixed 或 weight、收起策略）不进快照，由宿主的 `resolveRef` 按 `PanelRecord` 与第 4 节的约束表给出；条是 fixed 且最小最大相等；条两侧的缝宽为 0，这是现有的“不可交互接缝”。结构操作外面再包一层领域操作（见下）。256 节点、16 层的上限照旧，超限的操作失败、不改文档。

**规范形。** 每次结构操作之后：同轴嵌套展平，单子分支塌陷，条在最外层。所以 `(A | B) | C` 只会存成 `H[A, B, C]`。`createGrid` 现在只塌陷单子分支、不展平，要补这一步。

**条的位置。** 嵌套顺序固定：状态栏在外，活动栏在内；所以角归状态栏，同一边时活动栏在内。竖向时文字用 `writing-mode: vertical-rl`，图标不转；条目的主轴预算由外壳量，放不下的收进“⋯”；状态栏不是卡片。

**活动栏改成工具条。** 列出全部工具视图，点击时显示、隐藏或聚焦这个视图，不管它停在哪；底段仍放贡献的全局项。手机底部导航用同一份数据。

**ViewContainer 取消。** 标签组就是面板，多个视图同屏就是树里分开的几个面板，可以收成标题行。失去的是“点一个入口，一组视图一起切换”。

**具名面板不删除。** 拖空或关掉最后一个标签时隐藏（不占空间，也没有缝），留在树里，它记住的位置就是“默认位置”。声明 `location: "sidebar"` 的新视图加进这个面板的标签末尾；面板隐藏着就保持隐藏，直到用户打开。具名面板可以被整块拖走，名字跟着走。

**不变量由领域操作保证。** 这些操作是纯函数，失败时整批不改：

- 树里至少有一个编辑组，可以是空的。最后一个编辑组被整块浮动时，同一次操作在原位补一个空组。
- 没有名字的工具面板拖空后移除；具名面板隐藏；编辑组拖空后移除，最后一个除外。
- 接受矩阵（第 3 节）在提交时再验一次，不只在渲染层拒绝。

### 2. 所有权

**工作台拥有摆放，插件拥有内容。**

| | 工作台 | 编辑器插件 |
|---|---|---|
| 持有 | 树、面板、浮动、标签顺序、活动标签、活动编辑组 | 地址、编辑器、语言、preview、固定、光标、dirty、文档 |
| 记录 | `workbench.layout` | `editor.tabs` |
| 写入 | 只有它写；插件经服务提交结构意图 | 只有它写 |

结构变更的先后：

- **打开**：编辑器决定打开什么、复用哪个标签，再调工作台的 `openTab({type, tabId, panel?, position?})`。`group` 参数解析成面板 id，`"side"` 是活动编辑组右侧相邻的编辑组，没有就拆一个。
- **关闭**：工作台先调这个类型的 `requestClose(tabId)`，编辑器结算 dirty 后 resolve 是否关闭，同意才移除。关闭进行中，这个标签的再次关闭被忽略。
- **preview 替换**：编辑器结算输入后调 `replaceTab(oldId, newId)`，一次写完，不经过中间态。
- **固定**：编辑器把标签的分区告诉标签条；顺序由工作台存，分区限制由编辑器给（第 5 节）。
- **拖动**：只改摆放，编辑器不参与，实例不重建。
- **恢复**：工作台先读文档，显示标签占位；编辑器入口交付后才渲染内容。`editor.tabs` 里没有的 `tabId` 显示原因并可以关闭；文档里没有的 `tabId` 由编辑器丢弃。编辑器入口未交付或撤回时标签仍在，显示不可用的原因，再次交付后恢复。

**未知条目留在树上。** 插件暂时缺失时，它的视图和标签显示占位，写明原因，可以关闭。不做“呈现时过滤、写回时合并”的两层模型：文档就是所见的样子，别的操作写回时自然不丢。这改变了现行“未知引用只在呈现中忽略”的做法。

**实例身份两种，不混。** 工具视图按视图 id，沿用现有的 `generation` 与声明、实现、实例三层；动态标签按 `tabId`。命令与落点的目标都带身份，执行时重验，过期返回 `unavailable`。动态标签类型先只给内置插件用，不进 SDK。

**实例回收。** 内容首次激活才建，切走隐藏不卸载。工作台可以回收不可见的实例，回收不丢光标、滚动、撤销（沿用现有的视图状态槽）。第一版每种编辑器保留最近 20 个，其余卸载。

### 3. 拖动

**手势会话只有一份，指针和键盘都走它。** 指从拿起到放下、与拖的是什么无关的部分。

- **指针**：起拖门槛（鼠标与笔 6px，触摸按住 200ms）、逐帧更新、吞掉末尾的 click。捕获由渲染层根元素持有，来源被预览卸载不算取消。
- **键盘**：沿用现行外壳三输出 23：空格拿起，Tab 在落点区域间循环，方向键逐个位置移动，Enter 放下，Esc 取消，焦点回到源；拖动源的可访问名称与描述保留。键盘拖动一律用落点指示的反馈。
- **取消**：Esc、指针取消或丢失、失焦、页面隐藏、销毁，都不写。
- **窗口外**：以 pointerup 的坐标超出视口为准，算无落点。t01 在无头 Chrome 里实测能收到；别的浏览器在实现时试。
- **播报**：落点文字走 `aria-live`，只在语义变化时更新。

**判定分三层。**

1. **遮挡**（会话，读 DOM）：`elementsFromPoint` 找最上层的业务元素，被菜单、对话框挡住的不接收；反馈元素不挡命中；标了 `data-no-drop` 的按钮区不接收。
2. **几何**（纯函数）：输入是摘掉来源之后的树按当前尺寸算出的几何，窗口尺寸变化时重算；标签条的插入位按当前 DOM 量，滚动后也对。预览不进输入，否则让位会把落点从指针下挪走。
3. **规则**（纯函数）：下面的有序规则，加宿主给的接受矩阵。

**有序规则**，先命中的算：

| | 指针在哪 | 结果 |
|---|---|---|
| 1 | 工作台外、标题栏 | 无落点 |
| 2 | 浮动窗：标签条、中央 | 插入标签、添加为标签 |
| 3 | 条与外圈 | 只有拖动条才算落点（移到这一边） |
| 4 | 缝 | 归最近的那块，按下面继续判，缝本身不是落点 |
| 5 | 标签条 | 插入位 |
| 6 | 正文外缘（四角按对角线分），这条边对面是同一分支的相邻兄弟 | 放到两块之间：新块只从这两块按比例取。这条边、缝、对面那块的边是同一个落点 |
| 7 | 正文外缘，对面没有同一分支的兄弟 | 拆这一块，新块取一半 |
| 8 | 正文中央 | 添加为标签；空面板整块都是这个落点 |

规则 5 到 8 被接受矩阵拒绝时：这个东西允许浮动就算无落点，否则取消。**无落点就在松手处浮动打开**，拖影提前写“浮动打开”。

验收用的两个例子：

- `H[A, B, C]`（`(A | B) | C` 的规范形）：B 的右缘、缝、C 的左缘都是“放到 B、C 之间”，A 不动。
- `H[V[A, B], C]`：B 的右缘是拆 B，新块只有 B 那么高；C 的左缘与缝的右半是放到 `V` 与 C 之间，新块整高。两块不等长，放下去确实不同，开发者认可保留。

**接受矩阵**（工作台给策略，库不知道角色的含义）：

| 被拖的 | 工具面板的标签条、中央 | 编辑组的标签条、中央 | 任意面板的外缘 | 外圈 |
|---|---|---|---|---|
| 工具视图 | 接受 | 拒绝 | 接受 | 拒绝 |
| 编辑器标签、文件 | 拒绝 | 接受 | 接受（拆出新编辑组） | 拒绝 |
| 整个面板 | 同它的标签 | 同它的标签 | 接受 | 拒绝 |
| 条 | 拒绝 | 拒绝 | 拒绝 | 接受 |

所以编辑器标签可以拆到工具面板旁边，工具视图也可以夹在编辑组之间，但两者不进同一组标签。视图声明 `floatable: false` 时被拒绝就是取消。

**浮动窗经过面板**：只有标签条和外缘窄带（14%）能停靠，经过中央继续浮着。

**两种手感共用手势与判定，只是反馈不同。**

| | 实时布局 | 落点指示 |
|---|---|---|
| 拖动中 | 卡片跟手，邻居真实让位，来源收起；落点稳定 150ms 才换预览，标签条内不等 | 小拖影跟手（图标加文字），布局不动 |
| 落点反馈 | 空位是一块空面板加一圈边框，不铺遮罩 | 提交后矩形的区域，或插入线 |
| 分区（开关） | 在卡片后面，淡线，不写字 | 压暗内容（不透明度加调暗，不模糊），线和字都醒目 |
| 粘滞 | 指针在已显示的空位内（含 8px 边距）时候选不变，空位是稳定目标 | 没有 |
| 松手 | 提交指针下的候选，不等预览稳定，卡片飞向结果 | 与最后显示相同才提交 |
| 取消 | 卡片飞回 | 反馈消失 |

- **标签条内**：两种模式都不拿起卡片。实时布局下只有标签跟手、其余标签滑开、内容留在面板里，离开标签条才撕下。
- **指示画真实结果**：区域矩形用提交时的同一个函数算，不估算。
- **结构变化**：拿起时记下文档的结构键（树的拓扑、标签集合、来源是否还在），只比已提交的文档，预览不算；别的来源改了它（另一窗口不算，见第 8 节；插件撤回、文件被删关掉标签算）就整场取消，还原显示。

**资源树。** 树内是文件操作，保持落点指示。一场拖动归工作台的会话，资源树提供两个钩子：树内解析（返回树内落点，或 null 表示指针在树外）和自动滚动。指针出树后按上面的规则走，来源是文件。

- **目标**：编辑器向工作台登记“文件”这种来源的接受与提交，放下时对每个能打开的文件调 `open`，最多 10 项；目录跳过，只有目录时无落点就是取消。资源树不再读 `data-editor-group`，这个标记退役。
- **窗口外**：拖动 5 秒内可以开操作系统级窗口（t12 定），否则落成应用内浮动。

### 4. 尺寸

沿用 `sash-drag` 的求解器、`sash-hit-area` 的命中和 `useSashGesture` 的键盘、悬停线、光标：指针位移相对按下基线、十字交汇同时调两轴、拖动收起与展开。渲染层只提供矩形。

| 面板 | 约束 | 收起 |
|---|---|---|
| `sidebar`、`auxiliarybar` | 沿用现行宽度限制，fixed | 左右拖到零；上下收成标题行 |
| `panel` | 沿用现行，fixed | 同上 |
| 其它工具面板 | 取自所在方向的默认值，fixed | 同上 |
| 编辑组 | 至少 220×120，weight，吸收余量 | 不可收起 |
| 条 | 固定厚度 | 不可收起 |

- **视图声明的最小最大尺寸**：面板取所有标签的并（最大的最小值），切标签不改布局。
- **找回**：收成标题行的点标签展开；拖到零的靠分隔线拉回，或点工具条。
- **最大化**：对任意面板，占满树除条以外的区域，其余面板停放，瞬时、不落盘。去掉“拖过编辑器最小尺寸就最大化”的手势，保留按钮和命令。
- **放不下时只改呈现**：先压工具面板到最小，再收起工具面板，最后压编辑组；给诊断，不写文档。

### 5. 标签条

`nb-layout` 提供标签条，覆盖工具面板和编辑组两个使用方：

```ts
interface TabStripProps {
    tabs: ReadonlyArray<{id: string; partition?: string}>;
    partitions?: ReadonlyArray<{id: string; layout: "scroll" | "wrap"; maxRows?: number}>;
    overflow: "scroll" | "wrap" | "adapt";   // adapt 是工具面板现有的四档让位
    active: string | null;
    canInsert?(tabId: string, partition: string, index: number): boolean;   // 固定标签的分区限制
}
// 插槽：tab（内容，含状态位）、trailing（标题动作与框架按钮）
// 事件：activate、close、reorder、context-menu；撕下走手势会话
```

库负责 `tablist` 语义、方向键、Home、End、Alt 加方向键改顺序、菜单键，以及多行时的纵向导航和插入判定。编辑器的固定、未保存标记、面包屑都走插槽与分区，`EditorTabBar` 只剩内容。`adapt` 复用 nb-ui 现有的 `tabs-adapt.ts`。

面板头的顺序：标签条、当前视图的动作、面板框架按钮（收起、最大化、隐藏、浮动）。“移动到”放在标签右键。

### 6. 渲染

面板外框、分隔线、视图内容、条都是同一父元素的绝对定位子元素，用 `transform` 加宽高摆放，矩形来自树的布局结果。视图内容按实例身份建一次，不换父元素。

- **取整**：对每条边按设备像素取整，宽高由边相减；缝宽是令牌值，不参与取整。否则三块等分时缝会在 3、4、5px 之间跳（审查实测）。
- **过渡**：外框做过渡，内容一开始就是最终尺寸，只排一次版，`will-change` 只给正在动画的元素。拖分隔线、改窗口尺寸不做过渡。系统减少动态效果时归零。100k 字章节相邻让位时的单帧耗时要量，写进验收。
- **停放**：收起、拖到零、隐藏、切走时，内容不随外框降到零，保持最后一个非零尺寸，`visibility: hidden` 加 `inert`，展开时不重排。否则滚动锚定会改写滚动位置（`teleport-memory.ts` 记着这个教训）。焦点在被停放的内容里时，移到同一面板的标签条或最近的框架控件；焦点在外壳之外时不抢，沿用现行输出 10。
- **Tab 与读屏顺序**：面板内按 DOM 顺序走；走出一块时由布局层接管，按树的先后跳到下一块（标签条、内容、下一个面板），浮动窗排在树之后。F6、Shift+F6 在面板之间循环。Monaco 这类自己用 Tab 的内容靠 F6 离开。读屏顺序用外层的 `aria-owns`。不依赖 `reading-flow`。
- **有效可见**（`ViewContext.visible`）：在已提交的文档里、面板不隐藏不收起不是零尺寸、是活动标签、手机呈现下是当前部件。被浮动窗盖住仍算可见。预览不改可见性，只有提交后才变；从零拉回的拖动中按几何算，同现行输出 8。
- **外观**：缝、圆角、整缝与半缝、活动栏与侧栏合成一张卡片，都改成按矩形邻接算，输入是节点种类与相邻关系，取代按固定拓扑算的 `cards.ts`。节点的布局矩形含缝，卡片画在内缩之后的矩形里，落点预览与浮动窗用同一规则。活动栏与相邻且等长的工具面板相连。悬停线两端的连接与 DPR 对齐也按邻接重算。macos 主题仍是平铺。

### 7. 浮动与呈现

**浮动**：

- **矩形**是相对树区域的 CSS px，呈现时夹取，标签条总能抓到，夹取不写回。
- **移动**：拖标签条空白处，或单标签浮动窗的标签。多标签时拖标签是撕下。整个窗停靠时全部标签一起并入。
- **缩放**：边和角的手柄，键盘缩放；复用 `useFloatingWindow` 的几何，抽不出来时写明原因。最小尺寸取角色的约束。
- **叠放**：点击或聚焦提到最前。全部浮动窗放在一层，用 DOM 顺序叠放，不按窗分层；在 `z-index.ts` 登记 `workbenchFloat`，高于外壳、低于下拉菜单（60）。

**手机呈现**（外壳容器宽小于 600，门槛由宿主传入）：

- 一次显示一个部件，也就是一个面板的活动标签，默认活动编辑组。当前部件是内存状态。
- 底部工具条列工具视图，加一个“编辑器”入口；所有编辑组的标签合成一条横向滚动的标签条。
- 浮动窗也是入口，整屏打开，有返回。状态栏隐藏，没有拖动与分隔线。
- 只改呈现，不写文档；回到宽屏时树不变。

**紧凑呈现取消。** 600 以上走树，放不下时按第 4 节降级。

### 8. 持久化

| 记录 | 分区 | 内容 | 写入时机 |
|---|---|---|---|
| `workbench.layout` | 绑定项目 project / local，否则 user / local | `LayoutDoc` | 手势结束；打开、关闭、切换标签（合并，最多 1 秒一次） |
| `workbench.layout-template` | user / local | 去掉动态标签的 `LayoutDoc` | 同上，失败不影响主记录 |
| `editor.tabs` | project / local，未绑定只在内存 | `tabId` → 地址、编辑器、语言、preview、固定、光标 | 编辑器自己的节奏，光标约 1 秒一次 |

- **容量**：16 组、每组 200 标签时 `workbench.layout` 约 250KB，低于 1MiB 上限。
- **行为变化**：工具视图的摆放从跨项目共享变成每个项目一份，现行验收 9 改写。新项目的初始布局取 `workbench.layout-template`，没有就用默认树。
- **多窗口：整棵树后写胜出。** 条件保存冲突时重读 revision，用本窗口的文档覆盖，不合并；另一窗口保存后本窗口的显示不被强改。现行验收 8、39 改写。
- **切换**：都是新 key，旧的 `layout-sizes-side`、`layout-sizes-panel`、`views-customizations`、`editor.session` 不读、不写、不删。首次启动用默认树。已有用户的布局、尺寸和打开的标签丢一次。
- **回滚**：回到旧版本读到的是升级前的旧记录，新版本里的调整和标签都不会带回去。
- **沿用**：损坏或版本不支持时回落默认布局并记诊断，原件保留，普通保存不覆盖；手势中不写。

### 10. nb-layout

| 入口 | 内容 |
|---|---|
| `.` | 纯 TS，不依赖 Vue 与全局 `window`、`document`：布局模型与领域操作、Grid、尺寸求解器、落点规则、手势状态机（事件与时钟注入）。取代 `@notnotype/nb-ui/grid`、`./layout` |
| `./vue` | DOM 适配与组件：渲染层、Splitter、标签条、浮动层、反馈、`useSashGesture`。依赖 nb-ui（主题、层级、翻译端口、`tabs-adapt`），用 `ownerDocument` 取文档 |
| `./locales` | 库产生的文字：分隔线、标签条、浮动窗手柄 |
| `./lab-sources` | 组件文档与 Lab 模块 |

**库与宿主的边界：**

| | `nb-layout` | 工作台（宿主） |
|---|---|---|
| 模型 | `LayoutDoc` 的形状、规范形、结构操作 | 默认树、具名面板、记录 |
| 规则 | 有序规则与几何 | 接受矩阵、尺寸约束、是否可浮动、面板拖空后怎么办（经策略对象给） |
| 外观 | 反馈组件与 CSS 变量 | 主题取值 |
| 内容 | 标签条的语义与插槽 | 视图、标签内容、命令 |

**参数分两类：**

- **视觉**：空位、分区、压暗走主题的角色层 CSS 变量（`--layout-*`，写进 `tokens.css`），两种手感各一组；动画时长与曲线进 motion 令牌（`--motion-layout`、`--ease-layout`）。
- **行为**：外缘比例、稳定时长、起拖门槛由宿主经配置对象传入，不读 CSS。

**样式**只用作用域 CSS 加变量，不用原子类，所以不需要 `./tailwind.css`，宿主不用多一行 `@import`。

**随迁：**源码、同名 `.md`、单元测试、nb-ui 的扫描类门禁（令牌消费、默认文字、翻译键）的等价物。`splitter.spec.ts`、`nested-grid.spec.ts` 与验收页并进应用的 Lab 与 `e2e/`，不另建 playground。

**Splitter 统一进 `nb-layout`，分隔线核心也一起搬。** nb-story、dev-panel 不急着迁：`nb-ui` 暂留一份冻结的 Splitter 与分隔线核心给它们，不再加功能。单列一个 Task 用子代理迁完，然后删掉这一份。迁移那时 nb-story 的发布依赖从 8 个包变成 9 个，要写新 ADR 部分取代 ADR 0029。

## 备选与取舍

| 选择 | 备选 | 不选的理由 |
|---|---|---|
| 一棵树 | 外壳树加编辑区子树（现状） | 跨树移动要各写规则，开发者决定编辑器节点要能自然移到外层 |
| 按矩形摆放 | 保留递归 DOM，只加过渡 | 每换一次落点就搬一次节点，滚动和焦点靠补救 |
| 自写 | dockview | 停靠时搬 DOM；多行标签、固定标签、键盘导航是付费档；GitHub 识别不出许可证。golden-layout、Lumino 没核实 |
| 自写 | Trellis | 许可证与 AGPL 不兼容（判断，不是法律意见），只借交互想法 |
| 浮动是树外的列表 | 浮动节点进树 | 浮动窗没有兄弟，进树只多特殊情况 |
| 取消 ViewContainer | 保留 | 标签组和同屏分栏都能表达；内置视图目前不依赖 |
| 每标签一实例 | 每组一个控件换绑定 | 卡片要带真内容走；每标签的状态本来就各存一份 |
| 编辑器状态单独一条记录 | 全进布局文档 | 光标约 1 秒一次，不能和拖动抢保存；内容的所有者是编辑器 |
| 整棵树后写胜出 | 按节点合并 | 移动、拆分、删除的合并规则很复杂，两个窗口同时调布局很少见 |
| 布局层管 Tab 顺序 | `reading-flow`；重排 DOM | 前者不在浏览器基线内；后者原型实测滚动会丢 |

## 影响

- **数据**：见第 8 节。
- **接口**：见第 9 节。
- **发布**：nb-story 的依赖变化发生在迁移 Task。
- **确认点**：拆包、手势、渲染层各自独立交付。一棵树（t07）开工前，开发者用真实产品的手感再确认一次；这一段合入后回退，用户在新布局里的调整会丢。
- **排期**：条移到四边单列一个 Task，排在一棵树之后。两种手感是否长期都发，发布一版后再看。
- **能力缩减**（开发者接受）：面板横跨左右侧栏这类摆法没有拖动入口；左右方向的 32px 竖条取消；拖动手势版最大化取消。
- **风险**：
  - 一棵树那段影响面最大：要重写外壳二、三的大部分 Spec，改约 1 万行工作台代码与编辑器的组和标签。进行中的 Work 新加视图不受影响，改外壳代码的要排先后。
  - 每标签一实例的 DOM 占用、重内容让位的重排耗时都没有真实数据。
  - 布局层管 Tab 顺序还没有验证。
