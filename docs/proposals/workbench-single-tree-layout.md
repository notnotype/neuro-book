# 工作台布局：一棵树、按矩形摆放与 nb-layout

本稿取代 [工作台外壳的抽象](workbench-shell-abstractions.md) 里的拓扑、容器与布局记录（第 2、3、6、7、8 节）。它的原则（工作台是布局的唯一写者、声明与实例分开、渲染只消费求值结果）和视图合同（第 5 节）沿用。过程与证据见 [w00026](../../.agents/works/w00026-layout-package/README.md) 的 t01、t02。

## 问题

1. **布局分成几棵树，移动就要跨树。** 外壳是七个固定 Part 的网格，工具区域里每个容器又一棵，编辑区再一棵。编辑器的节点没法自然地移到外层，每种移动各写一套规则。
2. **递归 DOM 限制了拖动手感。** `NestedGrid` 每个分支一个 Splitter，叶子嵌在里面。结构一变节点就要换父元素，浏览器会清掉滚动和焦点，外壳靠三层 Teleport 和 `TeleportMemory` 补救。邻居实时让位做不到丝滑。
3. **同一件事写了几份。** 工作台视图、编辑器标签、资源树各写了一份拖动手势（共约 1100 行，门槛和取消规则相同，已开始走样），拖影也是三套。
4. **同一个位置有几种结果。** `(A | B) | C` 里把 D 放到 B、C 之间，B 的右缘、缝、C 的左缘各是一种结果，落点指示又是按面板的一半估算的，和结果对不上。
5. **窄屏只是压扁。** 390×844 下活动栏占一列，资源管理器和编辑区上下各一半，编辑区只有约 46% 的高度，也不能浮动。
6. **布局工具在 nb-ui 里。** 这部分占 nb-ui 非测试代码约四成（10 月审查的数字），定制时要改库。

## 目标与非目标

**目标**

- 工作台（除标题栏）是一棵树，活动栏、状态栏、工具视图、编辑组都是树上的节点。
- 内容按矩形摆放在同一层，移动只改矩形，实例不重建、滚动和焦点不丢。
- 两种拖动手感：实时布局（布局真实让位，卡片跟手）和落点指示（布局不动，画落点）。
- 同一条线上只有一个结果，落点指示画的就是提交后的矩形。
- 应用内浮动，单位是带标签的组，工具视图和编辑器标签都能浮动。
- 窄屏一次显示一个部件。
- 布局工具拆成 `@notnotype/nb-layout`，反馈样式全部是参数，调样式不用改库。

**非目标**

- 操作系统级窗口：这次只验证两种实现（t12），[`ui/workbench-shell.md`](../specs/ui/workbench-shell.md) 的不承诺项到选型后再改。
- 手机呈现的软键盘适配、触摸拖动与真机验收：这次是验证级。
- 第三方布局库：Trellis 的许可证与 AGPL 不兼容（判断，不是法律意见），只借交互想法；没有换库的计划。
- Part 贡献：树上的节点种类不开放给插件。

## 当前行为与证据

- **拓扑**：七个固定 Part，“集合与拓扑固定，不可贡献”。外壳设计稿把“Part 的任意重排、状态栏换位”列为以后再做。
- **代码量**：工作台浏览器代码约 1 万行（不含测试），测试约 5900 行；编辑器的组与标签另有约 2000 行。查过 w00025、27、28、32、39 的本地分支，都没有动这些路径。
- **视图的使用**：从代码看，内置视图里显式声明位置的只有资源管理器，多视图容器目前没有依赖。
- **原型**：[t02](../../.agents/works/w00026-layout-package/tasks/t02-prototype/README.md) 的一次性原型经开发者试过认可，提交在草稿分支 `chore/w00026-t02-prototype-drafts`。实测结果：
  - 跨面板搬动后滚动、输入、光标、一直在跑的动画都在，没有实例重建。
  - 现有的 `solveSashDrag`、`collectSashHits` 不改就能接到按矩形摆放的渲染上，十字交汇和拖动收起都能用。
  - `reading-flow` 加 `reading-order` 让 Tab 跟视觉顺序走，读屏顺序要另加 `aria-owns`，都不搬节点（只试过 Chrome）。
  - 每个标签一个编辑器实例：普通章节的 JS 堆增量在噪声内，第二个 Monaco 约 6MB，DOM 占用没有计入。
  - 帧率不可靠：无头软件渲染，同条件各轮能差到 35 到 59 帧，真实手感由开发者判断。
- **Trellis 的动画**（[逐帧采样](../../.agents/works/w00026-layout-package/tasks/t02-prototype/evidences/trellis-easing.txt)）：让位由 JS 逐帧驱动，曲线接近 `1-(1-t)^5`，约 470ms。

## 方案

### 1. 对象模型

```text
Workbench（每个窗口一个，nbook.workbench 拥有，布局的唯一写者）
├─ TitleBar ──────────── 树外，固定在最上面
└─ LayoutDoc
   ├─ 树（沿用 createGrid：两轴尺寸意图、fixed 与 weight、收起策略、快照）
   │  ├─ 分支 ─────────── 一个轴上排列子节点
   │  ├─ 面板 ─────────── 带标签的组，叶子；role 是 tool 或 editor
   │  └─ 条 ───────────── 活动栏、状态栏，叶子；固定厚度，不可调、不可收起
   ├─ 浮动列表 ────────── 面板 + 矩形，后面的压在前面的上面
   └─ 视图实例表 ──────── 实例 id → {type, params}
```

| 对象 | 是什么 | 取代什么 |
|---|---|---|
| **面板** | 带标签的组，树的叶子 | 工具区域、Switcher 加 ViewContainer、编辑组 |
| **具名面板** | 默认布局里名叫 `sidebar`、`auxiliarybar`、`panel` 的面板。标题栏开关、命令和 `location` 都认这个名字；被用户拖空后，下次需要时在默认位置重建 | 三个 ToolPart |
| **编辑组** | `role: "editor"` 的面板。树里至少有一个，可以是空的。不是单独的区域，取消编辑区这个子树 | Editor Part、`groups.ts` 的那棵树 |
| **条** | 活动栏、状态栏。只能在四条外边上，同一边时活动栏在内 | ActivityBar、StatusBar 的固定拓扑 |
| **视图实例** | `{type, params}`。工具视图的 `type` 是视图 id，只有一个实例；编辑器标签的 `type` 是 `nbook.editor`，`params` 是地址、编辑器、preview、固定与光标 | 编辑器自己的标签列表、`editor.session` |

**ViewContainer 取消。** 标签组就是面板，多个视图同屏就是树里分开的几个面板，可以收成标题行。失去的是“点一个入口，一组视图一起切换”。

**活动栏改成工具条。** 列出全部工具视图，点击时显示、隐藏或聚焦这个视图，不管它停在哪（面板里、浮动里、被隐藏）；底段仍放贡献的全局项。手机底部导航用同一份数据。

**条随所在的边改方向。** 布局把 `orientation` 传给条的内容，条目自己适应。竖向时文字用 `writing-mode: vertical-rl`（中文竖排），图标不转，放不下的条目收进“⋯”；实现时在 Lab 出稿给开发者看。

### 2. 渲染：按矩形摆放

面板外框、分隔线、视图内容、条都是同一父元素的绝对定位子元素，用 `transform` 加宽高摆放，矩形来自树的布局结果。视图内容按实例 id 建一次，不换父元素，移动就是改矩形。

- **过渡**：外框做过渡，内容一开始就是最终尺寸，只排一次版。缺省 `cubic-bezier(.23,1,.32,1)` 配 470ms；拖分隔线、改窗口尺寸不做过渡。遵守系统减少动态效果。
- **Tab 与读屏顺序**：DOM 顺序不跟视觉走。Tab 用 `reading-flow: source-order` 加 `reading-order`，读屏用外层的 `aria-owns`，顺序由树的先后算出。
- **Splitter**：独立的 `Splitter` 留给 nb-story 与 dev-panel，不再兼任 Grid 的内部件，`branchId`、`sashLineEnds` 从公开 props 拿掉。

**备选：保留递归 DOM，只加过渡。** 改动小，但每换一次落点就搬一次节点，滚动和焦点靠补救，重内容容易卡，达不到实时布局的手感。不采用。

### 3. 拖动

**手势会话只有一份。** 指从按下到松手、与拖的是什么无关的部分：起拖门槛（鼠标与笔 6px，触摸按住 200ms）、指针捕获、逐帧更新、取消（Esc、指针取消或丢失、失焦、页面隐藏、销毁）、吞掉末尾的 click。落点、反馈和提交由场景给。

**落点判定只有一份纯函数。** 输入是摘掉来源之后的树与几何，整场拖动都按这份固定几何判定，预览只影响显示。否则让位会把落点从指针下挪走，来回抖。

| 指针在哪 | 结果 |
|---|---|
| 标签条 | 插入位。不拿起卡片，只有标签跟手，其余标签滑开，内容留在面板里；离开标签条才撕下 |
| 面板正文的外缘（28%，四角按对角线分） | 该方向拆分，新块取这块的一半 |
| 与同一层兄弟的共享边 | 这条边、缝、对面那块的边是同一个落点，新块只从相邻两块按比例取 |
| 面板正文中央 | 添加为标签。工具视图到编辑组、编辑器标签到工具面板的中央不接受 |
| 缝 | 归最近的那块，不是单独的落点 |
| 不接受的位置、标题栏、窗口外 | 这个东西允许浮动就浮动打开，否则取消 |

- **浮动窗经过面板**：只有标签条和外缘窄带（14%）能停靠，经过中央继续浮着，不吸附。
- **最外层**：贴着外圈放到整个工作台旁边，普通面板不开；条只有这一种落点。把缝当落点（整段插入外层）模型支持，工作台不开。
- **资源树**：树内是文件操作，保持落点指示；拖出树后走上面这张表，作为“打开的文档”。目录不能打开，拖到无落点是取消；多个文件开成一个浮动窗里的多个标签，最多 10 项。落点改成统一登记，取代资源树读 `data-editor-group`。
- **提交**：实时布局松手提交指针下的候选，不等预览稳定；落点指示沿用“与最后显示相同才提交”。外壳与编辑器现行的“结构变了整场取消”两种模式都保留。

**两种手感共用手势与判定，只是反馈不同。** 做成用户设置，缺省实时布局。

| | 实时布局 | 落点指示 |
|---|---|---|
| 拖动中 | 卡片跟手，邻居真实让位，来源收起；落点稳定 150ms 才换预览 | 小拖影跟手，布局不动 |
| 落点反馈 | 空位是一块空面板加一圈边框，不铺遮罩 | 区域或插入线 |
| 分区（开关） | 在卡片后面，淡线，不写字 | 压暗内容（不透明度加调暗，不模糊），线和字都醒目 |
| 卡片大小 | 在原面板范围内保持原大小，离开缩成小卡 | 没有卡片 |
| 取消 | 卡片飞回 | 反馈消失 |

**指示画真实结果。** 区域矩形用提交时的同一个函数算，不另外估算。

**反馈样式是参数。** 空位、分区、压暗、动画时长与曲线落到 CSS 变量，主题和宿主可以覆盖；卡片、拖影和分区的外观可以经插槽替换。调样式不用改库。

### 4. 尺寸手势

沿用 `sash-drag` 的求解器与 `sash-hit-area` 的命中，不重写：指针位移相对按下基线、十字交汇同时调两轴、拖动收起与展开。上下方向收成标题行，左右方向拖到零，点收起面板的标签也能展开。条两侧的缝不可交互。

### 5. 标签条

`nb-layout` 负责标签的顺序、拖动、插入位与撕下，默认外观可以替换，标签内容经插槽由宿主画。编辑器的固定、未保存标记与多行都走这里；多行的插入判定和固定标签的分区限制在库里支持，由宿主给规则。

### 6. 编辑器

- **每个标签一个内容实例**，首次激活才建，切走时隐藏不卸载。同一文档开在两个组就是两个实例，共用正文、各有撤销历史，同现在。现在“每组每种编辑器一个控件、换绑定”的做法取消，`MarkdownControl`、`MonacoControl` 的绑定合同跟着改。
- **面包屑、标题动作**留在编辑器插件，经面板插槽显示。
- **`editor.session` 取消**，组与标签进布局文档（见第 8 节），恢复时编辑器插件按视图实例的 `params` 打开文档，读不到的标签仍显示原因。
- **`nbook.editor.open` 不变**：`group` 是编辑组面板的 id，`"side"` 含义不变。

### 7. 呈现

宽度小于 800 时是手机呈现，否则是树。手机呈现只改呈现，不写文档：

- 一次一个部件占满屏幕，默认编辑组；
- 活动栏固定在底部，状态栏隐藏；
- 浮动窗整屏打开；没有拖动与分隔线。

紧凑呈现取消，`nbook.workbench/nonCompact` 换成表示“不在手机呈现”的键。宽屏下放不下时沿用现有的降级（压缩、标题行、诊断）。

### 8. 持久化

- **一条记录**，取代 `layout-sizes-side`、`layout-sizes-panel`、`views-customizations`、`editor.session`。绑定项目时存在 project / local，否则 user / local；每次手势结束写一次。
- **新项目的初始布局**：取 user / local 那份最近的布局，去掉编辑器标签；没有就用默认布局。
- **旧记录不迁移**：已有用户的布局和尺寸丢一次。旧记录留在原处不删，回滚时还能用。
- **沿用**：损坏或版本不支持时回落默认布局并记诊断，原件保留；未知视图只在呈现时忽略，原件不删；手势中不写。

### 9. 插件与命令

SDK 不变：`workbench.views` 的声明不改形状，`location` 的含义变成“第一次放到哪个具名面板”，用户移动后以布局文档为准。`ViewContext.location` 给视图所在的具名面板，不在具名面板里时给声明的默认值。新增可选的 `floatable`（缺省真），资源管理器声明为假。

| 现有 | 处理 |
|---|---|
| `nbook.view.set-panel-position`、`set-panel-alignment`，状态键 `panelPosition`、`panelAlignment`、`panelHorizontal` | 删除，拖动就能摆 |
| `set-panel-hidden`、`set-part-hidden` | 合并成一条，作用于具名面板与条 |
| `set-panel-collapsed` | 作用于任意面板，改名 |
| `toggle-panel-maximized`，`panelMaximized`、`panelMaximizable` | 对任意面板生效，改名；瞬时、不落盘，同现在 |
| `nbook.view.move-view` | 保留，目标改成面板，另加“浮动”“新建面板” |
| 新增 | 浮动、停靠、把条移到某一边（条的右键菜单也走它） |
| 预备区 | 保留：拖动时隐藏的具名面板浮出预备区，否则放不进隐藏的侧栏 |

### 10. nb-layout

包名 `@notnotype/nb-layout`。`.` 是纯 TS，不依赖 Vue 与全局 `window`、`document`，取代 `@notnotype/nb-ui/grid`；`./vue` 依赖 nb-ui（主题、层级、翻译端口），结构同 nb-form；`./locales` 放分隔线的文字。

- **搬走**：Grid、分隔线手势、Splitter、NestedGrid、落点几何、`DropFeedbackOverlay` 及相关件、`useGridLayout`、`useLayoutExtent`。
- **新增**：手势会话、落点判定与登记、按矩形摆放的渲染层、标签条、浮动层。
- **留在 nb-ui**：Collapsible 一族、ScrollArea、OverlayScrollbar、Separator。
- **留在应用**：具名面板、视图声明、记录、命令。
- **不重导出**：`./vue` 依赖 nb-ui，重导出会循环依赖，使用方（24 个文件）一次改完。

## 影响

- **数据**：布局记录换一条，旧记录不迁移、不删除。
- **接口**：SDK 形状不变；删除的命令与状态键按上表，`data-editor-group` 标记保留，资源树不再依赖它。
- **发布**：nb-story 的发布依赖从 8 个包变成 9 个，[ADR 0029](../adr/0029-workspace-packages-publish-source-to-npm.md) 要更新。
- **回滚**：新记录与旧记录互不覆盖。拆包、手势、渲染层、一棵树可以分段合入；一棵树那段合入后再回退，用户在新布局里的调整会丢。
- **风险**：
  - **一棵树那段影响面最大**：要重写外壳二、三的大部分 Spec，改约 1 万行工作台代码与编辑器的组和标签。进行中的 Work 新加视图不受影响，改外壳代码的要排先后。
  - **`reading-flow` 只在 Chrome 上验证过**：别的浏览器上 Tab 顺序可能退回创建顺序。
  - **每标签一实例的 DOM 占用没有量过**：开很多标签时可能要加回收。
  - **帧率没有真机数据**：只能靠开发者手感和状态栏读数。
