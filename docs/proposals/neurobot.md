# NeuroBot（暂名）：常驻、有记忆的 AI 员工，第一版

需求原文、开发者已定的事与三份调研都在 [w00043](../../.agents/works/w00043-neurobot/README.md)。开发者 2026-11-09 看过要点、同意了待定项的推荐，本文在设计审查中，不能作为当前行为的依据。

## 一、问题

现在和 Agent 打交道的单位是会话：用户自己开会话、切会话，会话之间不共享记忆，一段对话写长了要用户自己处理。开发者要的是另一种关系：

- 用户面对的是一个 bot，像面对一个真人员工。bot 有名字、有长期记忆，可以从多个渠道联系；会话由系统管，用户不感知。
- bot 能替用户办事：日程、周期任务（例如每周整理某个领域的简报）、主动提醒。
- 以后 bot 之间能协作、能被拉进群、能派子代理、能创建子 bot，组成一个小公司。

第一个用户是 NeuroBook 的看板娘，充当 NeuroBook 的 AI 运营官。

## 二、目标与非目标

第一版的目标：

- 看板娘一个 bot，在 web 上能像和真人一样长期聊下去：不开会话、不切会话，上下文由系统维持。
- 保留原始记录：之后换记忆系统、做记忆评测，都能从原始记录重放。
- 简单的长期记忆：bot 自己维护的 Markdown 记忆文件，加检索。
- 日程与周期任务：用户和 bot 一起维护；到点 bot 主动找用户，或自己去干活。
- 应用与 NeuroBook 同在一个 monorepo，建在 nb-runtime 与 nb-harness 上。

非目标（第一版不做，见第四节第 9 小节的路线）：

- QQ 等外部渠道（定了用 LLOneBot，第二步做）、TUI、手机 app；
- 多个 bot、bot 之间的对话与群、子 bot、组织架构、分身；
- 共享知识库、做梦整理、nb-memory；
- 远端设备；社交媒体运营；
- 第三方插件的安装（只有内置插件）；远程访问与多用户。

## 三、当前行为与证据

- 仓库里能复用的：nb-runtime（生命周期、服务、插件、远程服务）、nb-harness（日志驱动的内核、压缩流程、审批钩子）、nb-agent-ui（对话视图，核心带 harness 适配器）、nb-ui。Agent 的压缩方法、审批判定、会话句柄表、通用工具现在在 NeuroBook 的 `nbook.agent` 插件里，由 [w00032 t32](../../.agents/works/w00032-agent-integration/tasks/t32-harness-backfill/README.md) 补回 nb-harness；NeuroBot 第一版依赖它（[仓库内现状](../../.agents/works/w00043-neurobot/research/2026-11-09-repo-survey.md)）。
- NeuroBook 的压缩只在超过阈值、服务商报溢出、手动三种情况下触发（[`agent/compaction.md`](../specs/agent/compaction.md)）；没有空闲时的压缩。
- NeuroBook 的会话由用户在界面上开，一个视图一个会话（w00032 t17）。
- 同类产品（[商业产品](../../.agents/works/w00043-neurobot/research/2026-11-09-commercial-bots.md)、[开源实现](../../.agents/works/w00043-neurobot/research/2026-11-09-open-source-architecture.md)）：
  - OpenClaw：会话键由“哪个 agent、在哪里聊”算出，私信默认汇入一个滚动的主会话，每个群一个会话，靠压缩维持；压缩前可跑一个静默回合让 agent 把要紧的事写进记忆文件；记忆是 Markdown 文件加 SQLite 索引。
  - nanobot：空闲 15 分钟自动压缩。OpenClaw 没有空闲压缩，但在服务商缓存过期后裁掉旧的工具结果。
  - Grok Bot：例行任务由时间表或事件触发；主 bot 主动找用户汇报。Muse：记忆是用户能编辑、下载的几个 Markdown 文件。

## 四、方案

### 1. 概念

- **bot**：一个常驻的员工。有身份（名字、头像、人设）、用哪个 Profile、用哪个模型角色、自己的记忆、自己的对话。开发者的原话是“用户感知的是 bot（或者说 profile）”；讨论后同意分开（2026-11-09）：Profile 是岗位定义（工具、提示词），bot 是在岗的人，以后两个工程师 bot 可以共用一个 Profile；用户感知的仍然只有 bot。
- **对话场所**：bot 在哪里和谁聊。第一版只有一种：web 上用户与 bot 的私聊。以后加 QQ 私聊、QQ 群、bot 之间的私聊与群。
- **对话**：一个 bot 在一个对话场所里的全部往来，对用户是一条不断的消息流。
- **会话**：harness 的会话，是对话在模型那一侧的载体。用户看不到它；它由系统按对话开、压缩、必要时轮换。
- **adhoc**：用一次就丢的子代理，没有长期记忆（w00032 t14 的子代理，第一版不用）。

### 2. 进程与拓扑

沿用 NeuroBook 的多实例拓扑（[ADR 0024](../adr/0024-multi-instance-runtime-topology.md)），角色对照：

| NeuroBot 的说法 | 对应 | 第一版 |
|---|---|---|
| gateway | 服务端实例：常驻进程，持有 bot、对话、会话、日程与调度 | 做，只监听本机 |
| web | 浏览器客户端实例，经内核远程服务连 gateway | 做 |
| tui、app | 其它客户端实例 | 不做 |
| QQ 等外部渠道 | gateway 里的渠道插件：把外部消息转成某个对话场所的入站消息，把回复发回来源渠道 | 不做，预留入站接口 |
| device | 远端主动连上 gateway、提供能力的实例（配对、按命令授权） | 不做 |

没有项目子进程：NeuroBot 不打开作品。

### 3. 应用包与依赖

- 新应用包 `packages/neuro-bot`（暂名），技术栈同 NeuroBook（[ADR 0023](../adr/0023-v2-frontend-backend-stack.md)）：后端 Bun，前端 Vue 与 Vite，校验用 TypeBox。
- 依赖：nb-runtime、nb-harness（t32 之后）、nb-agent-ui、nb-ui、nb-markdown。不依赖 `@notnotype/neuro-book`。
- 只用内置插件，第一版不搬 NeuroBook 的 `src/plugin-platform/`（[ADR 0030](../adr/0030-plugin-platform-layering.md) 定的是出现第二个使用插件模式的应用时搬，第三方插件进来时再搬）。
- NeuroBook 的 HTTP、存储、设置也是应用里的插件。NeuroBot 第一版自己写够用的最小版；两边重复明显时再决定抽不抽，和“把 harness 装成 nb-runtime 插件的接线”一样先不抽。

### 4. 对话与上下文

**会话由对话决定。** 每个对话一个当前会话。用户发消息就进当前会话；用户没有“新建会话”的入口。

**压缩触发点**：沿用阈值、溢出、手动三种，再加两种，都是为了省钱（开发者 2026-11-09）：

- **缓存过期前压缩**：一次运行结束后，在服务商的提示词缓存过期之前一点，如果还没有新消息、上下文又超过一定比例，就趁缓存还在压缩一次。压缩时读上下文按缓存价算；下一条消息从短的上下文开始，不用按全价重读长上下文。
- **空闲压缩**：空闲很久、缓存已经过期时，下一条消息本来要按全价重读整段上下文；空闲时先用“压缩”角色的模型把上下文压短，下一条消息只读短的。前提是压缩模型比会话模型便宜，否则压缩本身就按全价读了一遍长上下文，不省钱；所以只用走“压缩”角色的方法。（这是主 Agent 对“空闲压缩为了省钱”的理解，开发者没有逐字确认。）

两种都加在 nb-harness 的压缩流程里，NeuroBook 也能用；触发条件与数值在 Spec 里定。

**压缩前刷记忆**：压缩前先跑一个静默回合，让 bot 把这段对话里要长期记住的事写进记忆文件（OpenClaw 的做法），失败不影响压缩。

**会话轮换**：会话日志只追加，一直写会越来越大。超过一定大小时开新会话，新会话从上一次的摘要开始，对用户不可见。

**界面**：web 上一个 bot 一条对话流，跨越压缩与轮换连续显示；压缩在流里显示成一条分隔线，可以展开看摘要。

### 5. 原始记录与记忆

**原始记录**是真相源：每个对话场所一份只追加的消息记录，记每条入站与出站消息（时间、来源、内容），与会话日志分开。分开的理由：

- 压缩改写的是会话里给模型看的内容，原始记录不受影响；
- 以后群里没有 @ bot 的消息也要记，它们不一定进会话；
- 记忆评测要从原始记录重放，换记忆系统时也从它重建。

bot 行动的细节（工具调用与结果）在会话日志里，两者合起来是完整的原始记录。

**记忆**（第一版）：

- 每个 bot 一个记忆目录，放 Markdown 文件，bot 用读写工具维护；
- 一份核心记忆（例如关于用户、关于自己的要点）每次请求都放进提示词，有长度上限；其余按需用检索工具查，第一版用关键词检索；
- 用户在 web 上能看记忆文件。

记忆分层（私有、组织、共享知识库）、做梦整理、nb-memory 的取舍，等 bot 跑一段后用真实记录做评测再定（开发者 2026-11-09）。

### 6. 日程与周期任务

做成内置插件。

- 两种条目：一次性的（某时开会）与周期的（每天几点、每周几）。用户在 web 上改，bot 用工具改；一个工具只做一件事（w00032 t14 决定 6）。
- 第一版存在 NeuroBot 自己的数据里；接外部日历或 Todoist 以后做成同步插件。
- 到点的动作两种：**提醒**（bot 在对话里主动发一条消息给用户）与**任务**（bot 去干活，例如每周简报）。
- 任务在单独的会话里跑，带这个 bot 的身份与记忆；做完把结果作为一条消息发进 bot 与用户的对话。这样任务的工具调用与长输出不挤占主对话的上下文。

### 7. 电脑与工具

- bot 与电脑的对应可配置，缺省所有 bot 共享一台（开发者 2026-11-09）。第一版的电脑就是 gateway 所在的本机。
- 工作目录缺省在 NeuroBot 数据目录下的 `workspace/`。
- 工具用 t32 补回 nb-harness 的通用工具；文件访问接口由 NeuroBot 实现，直接读写本机。
- 审批沿用 harness 的审批判定：shell 与工作目录外的写入缺省要用户在 web 上批准，记忆目录内的读写放行。由另一个 bot 判定工具调用（开发者 2026-11-09）放到多 bot 那一步。

### 8. 数据

数据目录缺省 `~/.neurobot/`，可配置。里面按 bot 分：身份与设置、记忆目录、各对话的原始记录与会话；另有日程数据与工作目录。具体布局在 Spec 里定。模型密钥沿用 OMP 凭据库（w00032 t09）。

### 9. 第一版之后的路线

方向记录，不是承诺；每一步开工前另行讨论：

1. **QQ**：LLOneBot（OneBot v11）渠道插件；渠道到 bot 的路由规则；群里没有 @ bot 的消息作为背景记进原始记录，bot 可以选择插话；外部消息一律当作不可信内容，不能改变权限。
2. **记忆**：用真实记录建评测（谁是谁、约过什么、会议几点、哪个梗用得对），比较 nb-memory 与其它方案；共享知识库（梗、平台风向、写作技巧，带来源与时效）；做梦整理，写入长期记忆前检查来源。
3. **多 bot**：bot 之间的私聊与群聊、防止 bot 之间无限对话的限流、子代理（w00032 t14）、创建子 bot（不审批）与同级 bot（用户审批）、bot 判定别的 bot 的工具调用、分身共享记忆。
4. **组织**：组织、岗位、工单、会议几样东西，组成小公司的结构。
5. **设备与渠道**：手机作为设备；TUI、app；bot 自己的邮箱。
6. **社交媒体运营**：经浏览器插件（w00034）在 B 站、X 上看帖、回复；开工前先核对各平台对自动化账号的条款与风控。

### 10. 备选方案与取舍

开发者 2026-11-09 选了上面的方案（monorepo 里的新应用，nb-runtime 上自建，借 OpenClaw 的设计），没有说明不选其它方案的理由。下面是讨论时主 Agent 列出的各方案代价，不是开发者的理由，以后不要当作约束引用：

- **装 OpenClaw，NeuroBot 写成它的插件**：最快能用。代价：它跑在 Node 上、有自己的插件体系，nb-runtime 与 w00032 的成果用不上；仓库约 6.6 万个文件、更新很快；bot 不是会话、组织、子 bot、分身这类要改核心的东西，不一定能做成插件。fork 它的维护负担更大。
- **做成 NeuroBook 的一组插件**：不用抽包。代价：NeuroBook 是按作品打开的写作工作台，NeuroBot 是常驻的多渠道服务，产品与发布会绑在一起。
- **独立仓库**：代价是 nb-runtime、nb-harness、nb-ui 都要经 npm 版本跨仓库改，跨包改动不能一次提交。

## 五、数据、接口、安全、迁移、发布与回滚影响

- 数据：新的数据目录，与 NeuroBook 的数据互不读写。原始记录与会话日志只追加。
- 接口：新应用自己的远程合同；NeuroBook 的接口不变。依赖 t32 补回 nb-harness 的接口，t32 本身保证 NeuroBook 行为不变。
- 安全：gateway 第一版只监听本机，没有登录；bot 能在本机执行命令，靠审批兜底，执行命令与工作目录外的写入缺省要批准。远程访问、外部渠道进来之后要重新评估（不可信输入、谁能给 bot 下指令）。
- 迁移：无。
- 发布：第一版只从仓库运行，不发 npm、不进 CI 的打包。
- 回滚：新包独立，删掉不影响 NeuroBook。
