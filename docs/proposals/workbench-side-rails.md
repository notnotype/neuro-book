# 侧栏的侧轨：右栏入口条竖排、视图段与展开

## 问题

消息视图停靠在右栏时，界面接得不顺（开发者 2026-11-25，w00043 t19）：

- 右栏的入口条横在卡片顶上一行，当前容器只有一节时那一节的头并进来（[`ui/workbench-layout.md`](../specs/ui/workbench-layout.md) 输出 47）；消息视图窄版在自己的内容里画一列 52 像素的头像列（[`agent/conversation.md`](../specs/agent/conversation.md) 输出 51）。头横跨整行、下沿没有线，头像列的分隔线与气泡边框都在头下沿被切断。
- 头像列顶上的“≡”打开抽屉，在桌面侧栏里看不出开的是什么；抽屉盖掉聊天区大半。
- 左边的活动栏占满侧栏卡片的高度，头只盖在内容上；右边是另一套画法，两边不对称。

开发者喜欢头像列，要它像左边活动栏那样贴在右边缘、通到顶，并且两个侧栏共用一种做法、不给活动栏与消息视图各写特例。

## 目标与非目标

目标：

1. 左右两个侧区域共用一种**侧轨**：贴窗口外缘的竖条，上段是区域的容器入口。左边的活动栏就是左侧栏的侧轨；右栏的横入口条改成右边缘的侧轨。
2. 视图可以把自己的一段（**视图段**）放进所在区域的侧轨：消息视图的 bot、新对话、最近会话与底部两个按钮。
3. 侧轨能**展开**：收着 48 像素只有图标；展开时变宽，挤编辑区、区域内容的宽度不变，宽度能拖。消息视图展开的视图段就是完整列表（搜索、作品范围、筛选、Bot 与会话），不再另做列表栏、抽屉、对话目录或弹窗。
4. 视图浮出时视图段跟着视图走，画在浮动窗的右边缘；区域的入口不跟着走。
5. 消息视图只放在左右侧栏、独占自己的容器、浮动时只能单独一个标签，所以它总有地方放视图段。
6. 浮动、回到停靠、展开、收起都有过渡，且不卡：位置与宽度的变化走工作台已有的布局过渡与尺寸求解，不在每一帧用脚本量位置、改样式。

非目标：

- 左右整列对调（主侧在右）：另开 Task；本方案的几何不能挡住它（见“影响”）。
- 左边活动栏的展开：底层支持（同一个厚度回调、同一份状态），这次不开放入口。
- 底部面板：入口条照旧横在卡片顶上一行。
- 第三方插件：视图段与位置限制的声明是内置视图的内部合同，不进插件 SDK。
- 按消息内容搜索会话：另做。

## 当前行为与证据

- **活动栏是布局树上的条节点**：骨架判定要求 body 横向分支恰 4 个子、第一个是活动栏（`packages/neuro-book/src/plugins/workbench/web/state/default-tree.ts` 的 `fitsSkeleton`），布局记录校验只认活动栏与状态栏两个条（`packages/nb-workbench-layout/src/layout-doc-validate.ts`）。ADR 0044 决策 1。
- **右栏入口条是呈现里才有的叶**：投影给右栏与底部面板的区域节点包一层 `[入口条叶, 内层]`，入口条叶只在呈现里，包装沿用区域节点的 id（`packages/nb-workbench-layout/src/layout-project.ts`；w00026 t27）。这样避开了把入口条做成条节点的六处冲突（[工作台的视图容器](workbench-view-containers.md) 第 3 节）。
- **卡片相连、圆角与接缝写死为左边一条活动栏**：`packages/neuro-book/src/plugins/workbench/web/shell/adjacency.ts` 只看左邻是不是活动栏；`WorkbenchSurface.vue` 的角接过去（`capLeaves`）、最大化避让（`maximizedCardEdges`、`BARS`）都按 `ACTIVITY_BAR` 写。
- **浮动窗**是不在树里的一片叶，文档里只有 `{panel, rect}`；单标签、视图声明了自绘头且就绪时视图自绘头（[`workbench/views.md`](../specs/workbench/views.md) 输出 19 的“自绘头”，输出 39）。
- **消息视图**有宽窄两版：宽版常驻列表栏（可拖宽、可收成头像列），窄版头像列加抽屉（`packages/nb-agent-ui/src/vue/messages/AgentMessages.md`）。
- 调研全文：w00043 t19 [`evidences/foundation-research.txt`](../../.agents/works/w00043-neurobot/tasks/t19-messages-view-ui-polish/evidences/foundation-research.txt)；顾问与拉远看报告、各轮评审板与原型在同一个 Task。

## 方案

### 1. 三个词

- **入口条**：属于一个区域，在这个区域的几个容器之间切换（输出 22、47）。左侧栏的入口条是活动栏上段。入口条永远不浮动。
- **侧轨**：左右侧区域的入口条竖着贴在窗口外缘，加上视图段与底段。左边的侧轨就是活动栏。
- **视图段**：视图自己的一段内容（消息视图的 bot、新对话、最近会话，展开后的完整列表）。停靠时借住在所在区域的侧轨里；浮动时由视图画在窗的右边缘。

### 2. 几何：右轨是呈现里和活动栏同形的叶

右轨是投影在 body 横向分支里、右栏一列外侧插入的一片**呈现专属的叶**，和活动栏同一种形状：`fixed`、厚度由宿主回调给（收着 48，展开时是展开宽度）、两侧缝 0。布局文档、骨架判定与校验都不变，活动栏仍是树上的条。

不放进右栏的包装分支：包装的尺寸取区域意图，回写时按区域节点 id 取的是含轨的宽度，每次落账都多记一份轨宽、越用越宽；而且展开挤掉的是区域内容，不是编辑区。放成 body 里的兄弟叶，区域意图天然不含轨，展开只改这片叶的厚度，余量由编辑组吸收（输出 7）。

**显示**：右栏有成员容器时右轨就在，区域隐藏、拖到零时照样在（同活动栏：点上面的入口或视图段就把区域打开到那里）；右栏一个容器都没有（例如唯一的视图浮出去了）时，右轨跟着区域收走。

**放不下**（输出 10）：先把展开的侧轨按收着算，再按现有顺序压工具面板、收分节。

**相连、圆角、接缝、最大化**：`adjacency.ts` 与 `WorkbenchSurface.vue` 里按活动栏写的规则改成按“侧轨列表”与左右两侧算：右栏卡片与右轨相连时右侧两个角不圆、不留缝，接缝短线在内侧；最大化时右轨同活动栏一样不被盖住。

### 3. 侧轨的内容

从上到下：

1. **容器入口**：这个区域里有成员的容器，一个容器一项，按入口顺序（输出 41），点击、拖动、右键同活动栏上段（输出 22、44–46）。右栏卡片顶上那一行横的入口条与“并进来的头”去掉，分节的头照常画在卡片里。
2. **视图段**：区域此刻显示的分节恰好一节、它的视图声明了视图段且实例就绪时，工作台在这里给视图一块位置。
3. **底段**：视图段的固定项（消息视图的“全部 bot”“会话历史”），主侧那条再加全局项（账号、设置，`workbench.activitybar-items`）。

侧轨整条是一个地标、F6 的一站。读屏与 F6 按从左到右：左轨在左侧栏之前，右轨在右栏之后（输出 18 改写）。

### 4. 展开

- 侧轨的厚度有两档：收着 48；展开时是展开宽度。展开按钮在底段最下面；视图段里的按钮也能请求展开（消息视图的“全部 bot”“会话历史”：展开并切到那一页、聚焦搜索）。
- 展开宽度能拖：展开时侧轨的内侧边是一条分隔线，拖动改宽度，下限与上限由视图段声明（消息视图缺省 260，范围 200–420）；收着时这条线不能拖。
- 记在哪：右栏的锚上加两个可选字段 `railExpanded?: true`、`railWidth?: number`。旧版本读得进、原样写回（校验只查列出的键），回滚不丢布局；不往 `hiddenBars` 里加名字（旧版本会判整份记录不合法、回落默认布局）。“只展开或收起”要进形状比较，否则被当成没变不提交。
- 左轨（活动栏）走同一条路径：厚度回调读同一种状态。这次不给左轨展开的入口。

### 5. 给视图的接口

内置视图的内部合同，和 `VIEW_HEAD`、`VIEW_OWN_HEAD` 一样不进插件 SDK：

```ts
/** 视图声明自己有视图段：展开宽度的缺省、下限、上限（CSS px）。 */
export const VIEW_RAIL: unique symbol;
export interface ViewRailOptIn {
    readonly [VIEW_RAIL]: {readonly expandedWidth: {readonly initial: number; readonly min: number; readonly max: number}};
}

/** 视图这一代实例的视图段。 */
export interface ViewRail {
    /** 工作台此刻给视图段的位置（侧轨中段、底段）；null 时视图自己画（浮动窗的右边缘）。 */
    readonly slots: Readonly<Ref<{readonly main: object; readonly foot: object} | null>>;
    /** 侧轨此刻展开着没有。 */
    readonly expanded: Readonly<Ref<boolean>>;
    /** 请求展开或收起（视图里的按钮用）。 */
    setExpanded(expanded: boolean): void;
}
```

视图段由视图自己画、用 `Teleport` 送进工作台给的位置：头像、未读点、搜索框、长列表都是活的，留在视图的组件树里，状态、注入与出错兜底与视图共用；收着与展开是同一个组件按宽度换画法，不是两份 DOM。工作台只管侧轨的框、宽度、容器入口、底段、展开按钮、F6 与拖放。`slots` 为 null 时视图把同一个组件画在自己内容的右边缘。

不选“视图交声明式条目、工作台画”：展开后的完整列表（搜索、筛选、行菜单、改名、上万行的滚动）条目装不下，工作台要为一个用户另写一套可搜索列表；收着用条目、展开用 Teleport 又是两条渲染路径，切换时整块换、过渡难做。

`Teleport` 换目标就是换父元素，会丢滚动与焦点：停靠与浮动之间换的时候，视图按自己的状态恢复列表的滚动位置与选中，验收覆盖。

### 6. 浮动与回到停靠

- 消息视图浮出时，视图段跟着视图：浮动窗里视图在右边缘画它（同一个组件），顶上一格让给工作台盖在右上角的“回到停靠”。区域的入口不跟着走；右栏空了，右轨跟着右栏收走。
- 浮动窗里展开：窗向外长出展开的差值，聊天区宽度不变；矩形按收着的宽记，展开多出的只在呈现时加，夹取按呈现后的宽；浮动窗记录加可选字段 `railExpanded?: true`、`railWidth?: number`。
- **过渡**：窗的飞行沿用现有的布局过渡。视图段从侧轨到窗边（与反过来）在提交那一刻按前后两个位置做一次只改 `transform` 的过渡（FLIP），时长与曲线同布局过渡；不在每帧量位置、改样式，也不给外壳的宽度加 CSS 过渡（那会让网格每帧重算）。右轨收走与回来是它那片叶的厚度变化，走网格自己的布局过渡。

### 7. 位置限制

内置视图可以声明位置限制（内部合同，同上不进 SDK）：只停左右侧栏；所在的容器不接收别的视图（不和别的视图分屏）；浮动窗里只能是唯一的标签（别的标签放不进来，它也放不进别的窗）。接受矩阵（输出 26）、“移动到”菜单、打开视图的命令与默认布局都按它判；放不进的地方没有落点，松手是取消。消息视图声明它，所以它所在的位置总有视图段的家。

### 8. 消息视图

- 去掉宽窄两版、可拖的列表栏、收成头像列、抽屉与“≡”：视图里只剩聊天（头、消息、输入框），外加视图段。
- 视图段收着：bot 头像与未读点一组；一条短线；新对话与最近会话一组（会话写标题首字的方块，当前会话一圈描边）。底段：“全部 bot”“会话历史”。
- 视图段展开：顶上搜索，Bot 与会话两页，作品范围与筛选，行菜单（改名、归档），即现在的列表组件。选中一项在消息视图打开，侧轨保持展开、焦点留在列表。
- 头只写标题与动作，“新对话”从头的左边挪进视图段。

### 备选与取舍

| 备选 | 为什么不选 |
|---|---|
| 右轨做成布局树上的新条节点 | 骨架、校验、`hiddenBars` 都要改，旧记录全部回落；提案“工作台的视图容器”查出的六处冲突原样回来 |
| 右轨放进右栏的包装分支 | 区域宽度意图每次回写多记一份轨宽；展开挤区域内容而不是编辑区 |
| 头像列留在视图里贴右边（不改工作台） | 只是消息视图自己的样子，左右共用、对调与别的视图都用不上（第 3 轮开发者选了工作台的侧轨） |
| 完整列表做成抽屉、整页切换、锚定浮层、居中弹窗或单独的对话目录视图 | 开发者在第 1 到 5 轮逐个否掉，定为展开的侧轨直接当完整列表 |
| 视图交声明式条目、工作台画 | 见第 5 节 |

## 影响

- **数据**：布局记录多四个可选字段（右栏锚与浮动窗各两个）。不加版本号；旧版本读得进、原样写回；回滚代码不丢布局。
- **接口**：工作台内部合同加 `VIEW_RAIL`/`ViewRail` 与位置限制；不进插件 SDK。
- **代码**：投影（右轨叶、厚度回调、放不下时先收回展开）；外壳的相连、圆角、接缝、最大化改成按侧轨列表；侧轨组件由活动栏组件扩展（竖向入口、底段、展开、内侧分隔线）；右栏横入口条与并进来的头去掉；拖放与落点按侧轨的方向；浮动窗的视图段位置与展开；消息视图重写版式。
- **对调**：右轨与活动栏同形，对调时在投影里把 body 一层镜像即可，文档与骨架不动；本方案不做。
- **性能**：位置与宽度变化走网格的布局过渡，视图段的飞行是一次 `transform` 过渡；没有逐帧的脚本。
- **测试**：布局投影与回写的单元测试（展开不漂移、放不下先收回）；e2e 覆盖停靠、浮动、回到停靠、展开、收起、拖宽、右栏隐藏、拖到零、最大化、位置限制的落点；真实页面看过渡。

- 2026-11-25（开发者，w00043 t19 评审板第 1 到 5 轮与会话）：头像列在右边缘、通到顶；两个侧栏共用一种做法，左右能对调；做成工作台的侧轨；不用抽屉、整页切换、浮层或弹窗；展开的侧轨直接当完整列表，不另做对话目录；展开时加宽、挤编辑区，宽度能拖；左边活动栏也要能展开（底层支持，可以不开放）；右栏隐藏或拖到零时右轨常驻，右栏空了右轨收走；视图浮出时视图段跟着视图；消息视图不和别的容器分屏、不放到没有侧轨的地方；左右对调只做整列交换、另开 Task、活动栏不挪出布局树；按原型的方案做，代码重写，浮动切换要流畅。改底层设计要交 gpt 审一轮。
