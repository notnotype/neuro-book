# 侧栏的侧轨：右栏入口条竖排、视图段与展开

第三稿（2026-11-25）：第二稿按第 1 轮 gpt 设计审查与 UI 审查改，第三稿按第 2 轮 gpt 审查补全预算算法、容器切换、浮窗按钮与字段合同（处理见 w00043 t19 [`evidences/design-review-rails-disposition.md`](../../.agents/works/w00043-neurobot/tasks/t19-messages-view-ui-polish/evidences/design-review-rails-disposition.md)）。状态与动作的逐条清单在同一 Task 的 [`rail-states.md`](../../.agents/works/w00043-neurobot/tasks/t19-messages-view-ui-polish/rail-states.md)。

## 问题

消息视图停靠在右栏时，界面接得不顺（开发者 2026-11-25，w00043 t19）：

- 右栏的入口条横在卡片顶上一行，当前容器只有一节时那一节的头并进来（[`ui/workbench-layout.md`](../specs/ui/workbench-layout.md) 输出 47）；消息视图窄版在自己的内容里画一列 52 像素的头像列（[`agent/conversation.md`](../specs/agent/conversation.md) 输出 2 的消息视图一段）。头横跨整行、下沿没有线，头像列的分隔线与气泡边框都在头下沿被切断。
- 头像列顶上的“≡”打开抽屉，在桌面侧栏里看不出开的是什么；抽屉盖掉聊天区大半。
- 左边的活动栏占满侧栏卡片的高度，头只盖在内容上；右边是另一套画法，两边不对称。

开发者喜欢头像列，要它像左边活动栏那样贴在右边缘、通到顶，并且两个侧栏共用一种做法、不给活动栏与消息视图各写特例。

## 目标与非目标

目标：

1. 左右两个侧区域共用一种**侧轨**：贴窗口外缘的竖条，上段是区域的容器入口。左边的活动栏就是左侧栏的侧轨；右栏的横入口条改成右边缘的侧轨。
2. 视图可以把自己的一段（**视图段**）放进所在区域的侧轨：消息视图的 bot、新对话、最近会话与底部两个按钮。
3. 侧轨能**展开**：收着 48 像素只有图标；展开时变宽，挤编辑组、区域内容的宽度不变，宽度能拖。消息视图展开的视图段就是完整列表，不再另做列表栏、抽屉、对话目录或弹窗。
4. 视图浮出时视图段跟着视图走，画在浮动窗的右边缘；区域的入口不跟着走。
5. 消息视图只停右栏、独占自己的容器、浮动时只能单独一个标签，所以它总有地方放视图段。
6. 浮动、回到停靠、展开、收起、拖宽都有过渡且不卡，满足“性能预算”一节的可测判据。

非目标：

- 左右整列对调（主侧在右）：另开 Task；本方案的投影不能挡住它（见“影响”）。
- 左轨（活动栏）的展开：底层支持（同一种厚度来源、同一种状态），这次不开放入口；左边没有视图段的用户。
- 底部面板：入口条照旧横在卡片顶上一行。
- 第三方插件：视图段与位置限制是内置视图的内部合同，不进插件 SDK。
- 按消息内容搜索会话；普通会话的未读数（没有权威数据）；拖会话出去浮动；悬停预览展开；新的快捷命令（只加“搜索会话”一个）。

## 方案

### 1. 三个词

- **入口条**：属于一个区域，在这个区域的几个容器之间切换（输出 22、47）。左侧栏的入口条是活动栏上段。入口条永远不浮动。
- **侧轨**：左右侧区域贴窗口外缘的竖条：入口条、视图段、底段。左边的侧轨就是活动栏。
- **视图段**：视图自己的一段内容。停靠时借住在所在区域的侧轨里；浮动时由视图画在窗的右边缘。

### 2. 几何

**右轨是投影里的呈现专属叶。** 投影遍历规范树的 `body` 横向分支时，在右栏一列的外侧插入一片叶（id 是 `rail:auxiliarybar`；保留名单 `collidesWithPresentedIds` 同时覆盖树节点 id 与 `panels` 的键：读入时撞上的记录按现有规则当不合法，校验与投影共用这一份名单），它和其它孩子一起参加过滤、单子塌陷与缝的计算；不在投影结果上补。形状同活动栏：`fixed`，厚度由宿主给，两侧缝 0，不进文档、不进意图回写。底部面板旧的 `[入口条, 内层]` 包装另用判定，不和横向侧轨混。布局文档、骨架判定、校验都不变，活动栏仍是树上的条。

不放进右栏的包装分支：包装的尺寸取区域意图，回写会把轨宽记进区域，越用越宽；展开也会挤区域内容而不是编辑组。

**口径**：48、200、260、420 都指侧轨卡片的宽；叶厚按活动栏的算法（卡片宽加缝），投影、预算、手柄的数值、浮动窗的差值都用同一个换算。

**右轨在不在**由右栏的成员决定：右栏有成员容器时在，区域隐藏、拖到零时照样在（同活动栏）；右栏一个成员都没有时不在。用户显式打开的空右栏（标题栏开关、命令、模板，ADR 0050）照常呈现、可落入，没有右轨。左轨（活动栏）的显隐照旧只看 `hiddenBars`，与成员无关。

**相连、圆角、接缝、最大化**改成按“侧轨列表”与左右两侧算：右栏卡片与右轨相连时相连的两个角不圆、不留缝，接缝短线在内侧；最大化不盖侧轨（`BARS` 加右轨），每条轨按它的相邻边单独算过渡裁切。

### 3. 宽度预算

- **算在哪一层**：工作台的投影选项（给网格的尺寸与约束）在求解之前集中算一次，网格本身不知道“展开”；不靠两个分支各自的分隔线调整。
- **算法**：先按所有侧轨收着求出基线布局（编辑组宽 `E`、右栏宽 `R`、编辑组最小 `Emin`）。展开要多出 `D = 请求宽 − 48`。编辑组可让 `Se = E − Emin`；右栏可让 `Sr = max(0, R − 320)`（320 是消息视图声明的展开时聊天下限，只在这次预算里用，不改右栏平时的最小值与意图）。
  - `D ≤ Se`：照请求宽展开，编辑组让出 `D`。
  - `Se < D ≤ Se + Sr`：照请求宽展开，编辑组让出 `Se`，右栏这次呈现成 `R − (D − Se)`（呈现覆盖，不写意图）。
  - `D > Se + Sr`：能给的宽 `48 + Se + Sr`；不小于视图段声明的下限（200）时按它展开，否则不展开。
  - 拖宽手柄用同一个算法夹取：拖到可给的最大宽即停。
- 展开被拒或只能部分满足时：有效状态是收着（或能给的最宽），记录里的用户意图不改；窗口变化时按同一算法重算；展开按钮 `aria-expanded=false`，悬停与读屏给“窗口太窄”；窗口变宽时自动恢复。只有高度不足时不收轨（收轨不省高度）。
- 别的面板最大化时，从侧轨展开、打开或新建对话先退出最大化（同“显示被盖住的面板”，输出 13）。最大化期间侧轨照样露着，轨宽手柄不可用、不进 Tab。
- 放不下（输出 10）的降级先算“展开按收着”，再按现有顺序压面板、收分节；右栏被收走时右轨（有成员）留收着的 48。

### 4. 侧轨的内容与落点

从上到下：

1. **入口条**：右栏里有成员的容器，一个一项，按入口顺序（输出 41）；点击、拖动、右键同活动栏上段（输出 22、44–46）。右栏卡片顶上那一行横的入口条与“并进来的头”去掉，分节的头照常画在卡片里。
2. **视图段**：见第 6 节的借用条件。
3. **底段**：视图段的固定项（消息视图的“全部 bot”“会话历史”）；主侧那条再加全局项（账号、设置）；最下面是展开按钮（只在当前容器有视图段时有）。

三段的高度预算：底段与当前容器的入口总在；入口多了按现有规则收进“更多”；视图段在中间独立滚动。高度连入口与底段都放不下时（极矮的窗口），整条侧轨作为一个滚动区，Tab 与 F6 走到的项先滚进可见处；这是最后的后备，不追求好看。

**落点**：只有入口条那一带是落点（两个入口之间新建容器、入口上并入），沿轨的纵轴量；视图段与底段是“拒绝”，在那里松手是取消，不是“空白处开新窗”。键盘拿起时的候选只停在入口带。

**F6 与读屏**按从左到右：左轨在左侧栏之前，右轨在右栏之后（输出 18 改写）。侧轨整条是一个地标（`navigation`，名称写区域，“右侧栏”），F6 的一站。

### 5. 展开与轨宽

- **状态的所有者**：按容器记在锚上：`rail?: {[containerId]: {expanded?: true; width?: number}}`（可选字段）。当前容器没有视图段（别的容器、加载中、渲染出错、交付撤回）时，侧轨按收着呈现，记录不改；加载中保留视图段的骨架、厚度不变，出错才收。左轨同一种结构，这次不开放入口。
- **字段合同**：`rail` 是锚记录与浮动窗记录上的正式可选字段（类型、校验与归一里显式写出），形状比较把它算进去；所有重建记录的路径都保留它：模板应用、放弃更改的恢复、去掉与带回动态标签、浮出（新建浮动窗记录从锚上该容器的项带过去）、归位（带回锚上）、重置位置（清掉这个容器的项）。每条路径有测试。
- **读入**：`expanded` 只认 `true`；`width` 只认有限正数，按当前视图段的声明范围在呈现时夹取；不认的值局部当缺省并给诊断，不让整份记录失效。只改轨状态提交一次；回到原状零写入；形状比较把这两个字段算进去。旧版本读得进、原样写回，回滚不丢布局；不往 `hiddenBars` 里加名字。
- **展开、收起**：展开按钮；视图段里的请求（第 6 节的 `request`）。厚度变化走网格的布局过渡（同一叶只改厚度时网格已能识别）。
- **切换容器**：两端的有效轨宽相同时照输出 42 原地滚动；不同时不走原地滚动，整次切换走一次布局过渡（轨宽、右栏位置与内容同一条时长与曲线），入口的按下底块照常滑；快速反向从当前画面接着走；减少动态效果时直接到位。
- **轨宽手柄**：展开时侧轨的内侧边是一个专用手柄，不复用网格分隔线：只改轨宽，只由编辑组补偿（预算同第 3 节），触界即停，不触发区域的收起阈值，Enter 不收起区域。`role=separator`，可聚焦，`aria-valuenow/min/max`，方向键每次 10 像素，Home 与双击回缺省；拖动跟手、松手不回弹；一次原子提交只写这个容器的 `width`；Esc、失去指针捕获、目标或布局版本在手势中变化时整场取消、零写入；一帧至多一次预览求解。收着时手柄不在、不进 Tab。

### 6. 给视图的接口

**声明**（内置视图的内部合同，不进插件 SDK）：

```ts
/** 视图声明自己有视图段：展开宽度的缺省、下限、上限（卡片宽，CSS px）。 */
export const VIEW_RAIL: unique symbol;
export interface ViewRailOptIn {
    readonly [VIEW_RAIL]: {readonly expandedWidth: {readonly initial: number; readonly min: number; readonly max: number}};
}
```

**借用**：宿主按已提交的位置、容器、实例代际发放一份借用，换代、换位置、撤回时收回；旧代际与旧归属的请求一律拒绝。借用的条件：视图停在区域里、区域里显示的分节恰好一节且是它、实例已就绪；区域隐藏或拖到零时，已就绪的实例的视图段照样借给侧轨（点了会先揭示区域），冷开就隐藏、还没加载的实例不为视图段提前加载，侧轨只有入口。

```ts
export type RailPlacement =
    | {readonly kind: "rail"; readonly main: object; readonly foot: object}   // 借住在侧轨里
    | {readonly kind: "window"}                                               // 浮动窗：视图画在窗的右边缘
    | {readonly kind: "none"};                                                // 此刻没有地方（加载前、被收走、撤回）

export interface ViewRail {
    readonly placement: Readonly<Ref<RailPlacement>>;
    /** 此刻生效的展开状态（可能因窗口窄而与用户意图不同）。 */
    readonly expanded: Readonly<Ref<boolean>>;
    /** 请求展开或收起；结果回报给视图，视图据此决定切页与聚焦。 */
    request(expanded: boolean): Promise<"done" | "too-narrow" | "revoked">;
}
```

视图段由视图自己画、用 `Teleport` 送进 `main`、`foot`：头像、未读、搜索框、长列表都是活的，状态、注入与出错兜底与视图共用。收着与展开是同一个组件，按**已提交的** `expanded` 换画法，不看过渡中的实时宽度；收着的方块与头像留在左边 48 一列不动，名字随宽度淡入、延迟约三分之一时长，收起时先淡出再收窄。

**焦点**：宿主负责跨位置与消失的交接（换容器、浮出、归位、撤回、窗口变窄收起）：焦点在被搬走或收起的视图段里时，交给仍可达的触发器（展开按钮、容器入口），再不行交给窗的标题或聊天输入框；焦点已经去了别处（对话框）时不抢回。视图负责列表内控件的身份、滚动与选中，换位置后自己恢复。

不选“视图交声明式条目、工作台画”：展开后的完整列表条目装不下，收着用条目、展开用 Teleport 又是两条渲染路径。`Teleport` 换目标会丢滚动与焦点，由上面两条接住，验收覆盖。

### 7. 浮动与回到停靠

- 消息视图浮出时，视图段跟着视图（借用变为 `window`），视图在窗的右边缘画它。区域的入口不跟着走；右栏没别的成员时右栏与右轨一起收走。
- **矩形**：记录矩形是收着的；呈现矩形是记录矩形加展开差值；窗的手柄只结算用户动的边与轴（展开时拉右边 10 像素，记录宽加 10），轨的内侧手柄只结算轨宽；两种预览用同一个坐标换算与夹取。浮动窗的轨宽拖动是网格里一种新的手势事务（现有的浮动窗接口只能整窗移动）：拿起时冻结基线与布局版本，连续预览，夹取与停靠时相同的预算（窗向外长、靠屏幕边往左挪），Esc、失去捕获或版本变了整场取消，松手一次原子提交。夹取保证展开后右边的视图段与“回到停靠”可达：窗靠屏幕右边时展开，呈现位置往左挪，记录位置不改；宽度不够时按收着呈现，展开请求回报 `too-narrow`。浮动窗记录加 `rail?: {expanded?: true; width?: number}`，读入规则同第 5 节。
- **顶格与按钮的所有者**：声明了视图段的视图浮动时，“回到停靠”由宿主画在窗内视图段的顶格里（视图段位置上方留一格给宿主），自绘头的右端不再为框架按钮留位；视图声明的与插件贡献的标题动作由宿主照常交给自绘头，排在聊天头右端，按聊天头实际宽度预算，放不下进“⋯”。悬停“回到停靠”写出去向（“回到右栏”）。
- **过渡**：窗的飞行沿用现有布局过渡。右栏随之收走时（常见情形）视图段随窗整块飞，不单独动；右栏还有别的容器时，视图段在一个非交互的过渡层里从当前画面的位置飞到求解后的终点（不对随窗移动的子元素直接套两端屏幕坐标），只有一份可访问的列表。浮动窗只改宽度（展开、收起）与右轨离场（离场时保留没有内容的外框、厚度缩到零再摘）要加进网格的过渡名单。中断与减少动态效果复用同一个收口，不依赖 `transitionend` 一定到达。

### 8. 揭示与动作

侧轨与列表里打开、新建对话共用一个“定位到消息视图”的揭示通道：区域隐藏或拖到零时显示区域，别的面板最大化时先退出最大化，然后在消息视图里打开；不经“上次的对话位置”（编辑区的对话页开着也不在那里打开）。已经在途的打开不在新选择之后覆盖它。“看到”仍按聊天的有效可见、窗口焦点与没有盖层提交。打开或新建之后焦点交给聊天输入框。

### 9. 位置限制

视图声明里加一项工作台侧的限制（内部合同，建树、补位、读入前就能判，不靠视图实例）：只停右栏；只用自己的隐式容器（不进声明的容器，别的视图也进不来）；浮动时只能是唯一的标签。

- **提交时校验**：所有改归属的操作在提交出口按当下文档判（标签拖放、相邻容器入口并入、“移动到”、`move-view` 等命令、整容器移动、整窗停靠、归位），候选、预览与提交共用一份规则；违反的操作拒绝、零写入。
- **读入时归整**：旧记录里已经违反的（消息在底部面板、在左侧栏、和别的视图同在一个容器、在多标签浮动窗里），读入时只把受限视图分离到右栏自己的容器（或单独浮出），其余布局原样保留；声明目录还没就绪时不按未知限制写回。
- 实时拖放期间侧轨的有效几何冻结到手势结束，落点指示按最新矩形重判。

### 10. 消息视图

- 去掉宽窄两版、可拖的列表栏、收成头像列、抽屉与“≡”：视图里只剩聊天（头、消息、输入框），外加视图段。头只写标题与动作，“新对话”挪进视图段。
- **收着**：bot 一组（圆头像；当前 bot 是头像侧边一条竖条；未读是数字徽标；等你处理是 warning 色、形状与未读不同）；一条短线；新对话与最近会话一组（方块写标题首字、悬停与键盘聚焦都给全名；当前会话是描边；普通会话不画未读）。当前会话永远占位，其余按最近使用、数目随高度只在末尾增减，bot 太多并成“+N”。区域隐藏或拖到零时“当前”退成弱描边。底段“全部 bot”带汇总徽标（未读合计，有等你处理时是 warning 色）、“会话历史”、展开按钮。
- **展开**：就是现有的列表组件（搜索、Bot 与会话两页、作品范围、筛选、行菜单的改名与归档与恢复、新建），排序与搜索范围照现有，不按日期分组。“全部 bot”“会话历史”展开并切到对应页、聚焦搜索；已展开时只切页，对应按钮显示按下。搜索词两页各自保留；Esc 先清搜索，搜索已空时把焦点交回聊天输入框，不收起。
- **最近会话**由一个独立的查询供给（顶层、未归档、本作品范围，按最近活动），不靠完整列表顺带刷新、不受历史筛选影响。
- 没有打开会话时，Bot 页的首屏盖层照旧（输出 2），给一个按钮（等同“全部 bot”）。
- 键盘：收着的侧轨是纵向工具条（roving tabindex，上下方向键、Home、End）；展开的列表是它自己的区域，保留搜索框、`tablist`、行菜单原有的按键。加命令“搜索会话”（展开并聚焦搜索）。

### 性能预算

- 程序变化（浮动、归位、展开、收起、容器切换）：每次有限次布局求解与测量，不随帧数增长。
- 拖宽：一帧至多一次预览求解，指针停住不空转。
- 视图段在过渡中用稳定尺寸或裁切，不逐帧改列表宽；宽度观察只看真正需要的那一轴。
- 判据：用长章、多编辑组、长会话列表在真实页面采样布局发布次数、样式与布局次数、帧耗时，和现在的版本比较；没有浏览器采样前不下帧率结论。

## 影响

- **数据**：右栏锚与浮动窗记录各多一个可选字段 `rail`。不加版本号；旧版本读得进、原样写回；回滚代码不丢布局；坏值局部缺省。受限视图的违规位置在读入时局部归整。
- **接口**：工作台内部合同加 `VIEW_RAIL`、`ViewRail`、位置限制；不进插件 SDK。
- **代码**：投影（右轨叶、厚度、预算、放不下的次序）；外壳的相连、圆角、接缝、最大化；侧轨组件由活动栏组件扩展（竖向入口带、视图段的位置、底段、展开按钮、轨宽手柄）；右栏横入口条与并进来的头去掉；拖放与落点（入口带、拒绝区、冻结）；接受规则在所有提交出口；浮动窗的矩形、夹取、顶格与过渡；网格过渡名单；消息视图重写版式与最近会话的查询。
- **对调**：右轨与活动栏同形，对调时在投影里把 body 一层镜像；右轨叶的 id 与底部旧包装的判定分开，镜像后不会被当成旧包装。本方案不做。
- **测试**：投影与回写的单元测试（展开不漂移、预算次序、放不下先收回、坏值读入、违规归整、相邻并入被拒）；e2e 覆盖停靠、浮动、归位、展开、收起、拖宽、键盘调宽、右栏隐藏、拖到零、最大化、位置限制的各条路径、焦点落点；真实页面看过渡的首帧、中间帧、末帧与性能采样。
