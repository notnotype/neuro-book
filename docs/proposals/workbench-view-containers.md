# 工作台的视图容器

本稿在 [工作台布局：一棵树、按矩形摆放与 nb-layout](workbench-single-tree-layout.md) 之上加回“容器”这一层：活动栏、右栏、底部面板的一个入口切换的是一整块内容，不是一个视图。一棵树、按矩形摆放、两种拖动手感都不变。过程见 [w00026 t24](../../.agents/works/w00026-layout-package/tasks/t24-view-containers/README.md)。

## 问题

1. **活动栏一个图标只对应一个视图。** 开发者 2026-11-09：“ActivityBar 的一个图标切换的是侧栏这一整个面板，例如第一个图标显示的是‘会话’和‘资源管理器’（也要记住这两个视图的位置和展开收起关系），第二个图标显示的是‘对话’。”现在点一个图标只显示它所在的那块面板、激活这一个视图；几个视图同时摆在侧栏里，只能靠把这一列上下分开，而分开之后它们一直都在，没法用一个图标整体换走。
2. **右栏、底部面板没有“一组”的概念。** 它们的头是视图的标签条，想在两组视图之间切换，只能把视图一个个拖来拖去。
3. **单树提案取消容器时的理由只覆盖了当时的用法。** 它写“内置视图里显式声明位置的只有资源管理器，多视图容器目前没有依赖”（[当前行为与证据](workbench-single-tree-layout.md#当前行为与证据)）。取消容器解决的是“布局分成几棵树、移动要跨树”，不是“用户不需要一组视图”。这次要的是后者，前者不能回来。

## 目标与非目标

**目标**

- 侧栏、右栏、底部面板三处各是一个“容器栏”：一次显示其中一个容器，入口切换整个容器。侧栏的入口是活动栏，右栏、底部面板的入口在各自的头上。
- 容器里可以有几个视图，同时可见；它们的位置、大小、展开收起由这个容器自己记住，切走再切回来还是原样。
- 容器既可以由插件声明，也可以由用户拖出来（开发者 2026-11-09 定：两者都有）。
- 仍是一棵树：容器是树上的节点，拖动、按矩形摆放、实时布局不另写一套。

**非目标**

- 容器嵌套容器。
- 插件声明新的容器栏（三处之外再开一处）。
- 编辑区：编辑组不进容器。
- 浮动窗里放容器：浮动的单位仍是带标签的组（单树提案第 7 节）。

## 当前行为与证据

- **模型**：侧栏这一列是一个上下分的分支，具名面板 `sidebar` 加从它分出来的无名面板，每块面板带标签条（[`ui/workbench-layout.md`](../specs/ui/workbench-layout.md) 输出 1、22）。活动栏上段列这一列的全部视图，按树序、面板内按标签序；点一个视图显示它所在的面板并激活它（输出 22）。
- **收起与停放已经有了**：面板能收成标题行（输出 20），看不见的内容停放、不卸载（输出 10、16、17）。容器切走时它的视图同样停放，不需要新机制。
- **骨架**：活动栏、侧栏、编辑区、右栏的顺序固定，侧栏只上下分、面板只左右分（输出 26）；不合骨架的旧记录回落默认树（输出 32 前后的读取规则，2026-11-06 起）。
- **视图声明**：`location: "sidebar" | "auxiliarybar" | "panel"` 只决定第一次放到哪个具名面板（[`workbench/views.md`](../specs/workbench/views.md) 的输入）。
- **参照**：VS Code 的 View Container（`viewsContainers` 贡献点，活动栏、面板各一组），容器里的视图是上下排列、各自可折叠的分节；Trellis 没有容器，只有带标签的组。

## 方案

### 1. 模型：容器栏是“一次显示一个子节点”的分支

```text
树
├─ activitybar（条）
├─ 侧栏位置：容器栏 sidebar ── 子节点是容器，一次显示一个
│   ├─ 容器 c1（声明的“项目”）── 上下排列的分节
│   │   ├─ 分节：会话
│   │   └─ 分节：资源管理器
│   └─ 容器 c2（声明的“对话”）── 一个分节：对话
├─ 编辑区
├─ 右栏位置：容器栏 auxiliarybar
└─ 底部：容器栏 panel
```

- **容器栏**是树上的一种分支：子节点全是容器，同时只显示 `active` 那一个，别的子节点整棵停放（同输出 10 的停放：不卸载、不进 Tab 顺序、`visible` 为假）。三个容器栏在骨架上的位置不变，取代现在的具名面板 `sidebar`、`auxiliarybar`、`panel`。
- **容器**是容器栏的子节点，自己是一个沿容器栏方向排列的分支（侧栏、右栏上下排，底部面板左右排）。它带一份身份：`{id, origin: "declared" | "user", title?, icon?}`。
- 选择切换（点入口）只改容器栏的 `active`，不改任何尺寸，切回来时容器里的分节位置、大小、展开收起都是原样（问题 1 里“记住”的部分）。
- 隐藏与显示仍按容器栏整体（现在的隐藏侧栏、右栏、面板）。

为什么是树上的一个分支，而不是把不活动的容器存在树外：放在树外，拖进一个不活动的容器、命令把视图移到别的容器，都要在“树”和“树外的存放”之间搬，单树提案取消的正是这种跨树移动。放在树上，不活动的容器只是看不见的子树，结构操作照旧。

### 2. 容器里是什么：推荐分节（待定项 1）

**推荐：分节。** 容器里每个视图是一个分节：一个可以折叠成标题行的面板，头只写标题，没有标签条；分节沿容器方向排列，大小按分隔线调。实现上就是现有的工具面板加上“只有一个标签、头只写标题”的限制，收成标题行（输出 20）就是折叠，不另造一种节点。

- 一个容器只有一个分节时，分节不画自己的头，标题由入口与容器栏的头给出，和现在只有一个视图的面板一样。
- 拖动：分节之间的缝、分节标题是插入位（放成新分节）；分节正文的中央不再是“添加为标签”，因为分节没有标签。

**备选：面板加标签**（容器里仍是现在的工具面板，能上下分、每块带标签条）。代价：右栏、底部面板的头已经是容器的入口条，下面每块面板再有一行标签条，就是两行标签；侧栏里同理，活动栏选容器、面板头再选标签，同一件事两层选择。开发者的例子（会话和资源管理器一起显示、记住展开收起）两种都能做，分节更直接。

### 3. 入口：活动栏与两个头

- **侧栏**：活动栏上段列侧栏的容器，按容器栏里的顺序；点一个：不是当前的就换成它（侧栏隐藏着就显示），是当前的就隐藏侧栏（同现在的行为）。底段的全局项不变。
- **右栏、底部面板**：头上是容器的入口条（右栏用图标，底部面板用标题，同 VS Code）；只有一个容器时头只写它的标题。
- **图标**（待定项 2）：推荐：声明的容器用声明里的图标；用户拖出来的容器用它第一个分节的视图的图标，悬停写它包含的视图标题。

### 4. 容器从哪来

- **声明**：插件贡献 `workbench.viewContainers`：`{id, title, icon, location: "sidebar" | "auxiliarybar" | "panel", order?}`。视图声明加 `container?`（容器 id），不写时按 `location` 放进那一处的缺省容器。默认树按声明建：每个声明的容器带上声明属于它的视图。
- **用户拖出来**：把视图拖到入口条两个入口之间（活动栏两个图标之间、右栏或底部面板头上两个入口之间），就在这里新建一个只含它的容器；拖到一个入口上，就放进那个容器（作为最后一个分节，实时布局下预览就是切到那个容器、它出现在末尾）。
- **空了的容器**：用户拖出来的，最后一个视图拿走就删掉；声明的保留但入口不显示，有视图回来再显示。

### 5. 拖动规则的变化

- 入口条变成容器的插入位与落点（上面一节），取代现在活动栏“插入到某个视图之前”。
- 容器里的分节之间可以换序、上下分（侧栏、右栏）或左右分（底部面板），跨容器移动就是从一个容器的子树搬到另一个容器的子树，都在一棵树上。
- 输出 26 的骨架约束不变；“侧栏只上下分”变成“容器沿容器栏方向分”。
- 实时布局：拖到不活动容器的入口上，预览切到那个容器；吸收、来源收起一次、限位排序（t23）照旧。

### 6. 持久化

- 布局记录加容器栏与容器两种节点，格式版本加一。
- **旧记录不迁移**：按输出 32 前后的读取规则，不合新骨架的记录回落默认树并给诊断（2026-11-06 的先例）。v2 还没发布，旧记录只在开发者本机（待定项 3）。

## 影响

- **数据**：布局记录格式版本加一；旧记录回落默认树，原件保留。
- **接口**：插件新增 `workbench.viewContainers` 贡献点，视图声明加 `container?`；`ViewContext.location` 的含义从“具名面板的名字”改成“所在容器栏”。
- **nb-layout**：树要支持“一次显示一个子节点”的分支（停放已有）；分节就是现有面板加限制，库里不加新的叶子种类。
- **命令**：“移动到”菜单的目标从面板变成容器（含“新容器”）；“重置视图位置”回到声明的容器。
- **回滚**：格式版本退回即回落默认树，不影响作品数据。

## 待定项

1. **容器里是分节，还是面板加标签？** 推荐分节（第 2 节）：右栏、底部面板不会出现两行标签，开发者的例子正是分节的样子；实现复用现有面板。
2. **用户拖出来的容器用什么图标？** 推荐用第一个分节的视图的图标，悬停写包含的视图（第 3 节）。
3. **旧的布局记录要不要迁移？** 推荐不迁移，回落默认树（第 6 节）：v2 未发布，迁移规则（现在侧栏这一列拆成几个容器）没有明显正确的答案。
4. **右栏、底部面板的入口条放在哪？** 推荐放在各自的头上，右栏用图标、底部面板用标题（第 3 节）；另一种是右栏也有一条竖的活动栏。

## 决策记录

- 2026-11-09 开发者：右栏、底部面板也做容器；容器既有插件声明的，也能由用户拖出来。容器里怎么排（分节或面板）、一个容器有几个视图时图标用谁的，暂时定不下，等本稿给出推荐再定。
- 2026-11-10 开发者：待定项“都先按推荐”：容器里是分节；用户拖出来的容器用第一个分节的视图的图标；旧的布局记录不迁移、回落默认树；右栏、底部面板的入口条放在各自的头上，右栏用图标、底部面板用标题。
