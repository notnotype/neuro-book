# 工作台的视图容器

本稿在 [工作台布局：一棵树、按矩形摆放与 nb-layout](workbench-single-tree-layout.md) 之上加回“容器”这一层：活动栏、右栏、底部面板的一个入口切换的是一组视图，不是一个视图。一棵树、按矩形摆放、两种拖动手感都不变。接受后另写一份 ADR，部分取代 [ADR 0044](../adr/0044-workbench-single-layout-tree.md) 的决策 3（“取消 ViewContainer”），决策 1（一棵树、规范形）不动。过程见 [w00026 t24](../../.agents/works/w00026-layout-package/tasks/t24-view-containers/README.md)，第一轮两份审查的归类在那里。

## 问题

1. **活动栏一个图标只对应一个视图。** 开发者 2026-11-09：“ActivityBar 的一个图标切换的是侧栏这一整个面板，例如第一个图标显示的是‘会话’和‘资源管理器’（也要记住这两个视图的位置和展开收起关系），第二个图标显示的是‘对话’。”现在几个视图同时摆在侧栏里只能把这一列上下分开，分开之后它们一直都在，没法用一个图标整体换走。
2. **右栏、底部面板没有“一组”。** 想在两组视图之间切换，只能把视图一个个拖来拖去。
3. **ADR 0044 取消容器的理由是“内置视图目前不依赖”。** 那条决策解决的是“布局分成几棵树、移动要跨树”；用户要成组切换是另一件事，开发者这次的要求推翻了“不依赖”。跨树移动不能回来。

## 目标与非目标

**目标**

- 侧栏、右栏、底部面板三处，各一次显示一个容器；点入口切换整个容器。容器里的几个视图同时可见，位置、大小、展开收起由这个容器记住，切走再切回来是原样。
- 容器由插件声明，也能由用户拖出来（开发者 2026-11-09 定）。
- 树、规范形、节点种类都不变，拖动、按矩形摆放、实时布局不另写一套。
- 分两步交付：先侧栏（入口就是活动栏，不用新的头），再右栏与底部面板。

**非目标**

- 容器里隐藏单个视图（VS Code 的视图右键“隐藏”），容器嵌套容器，插件开新的容器栏，编辑组进容器。
- 浮动窗是容器：浮动的单位仍是带标签的组。

## 当前行为与证据

- **规范形会吃掉分支上的身份**：每次结构操作都把同轴嵌套展平、单子分支塌陷（`packages/nb-layout/src/layout-doc.ts` 的 `normalizeTree`、`detachNode`），分支快照只有 id、方向、尺寸、子节点（`grid-types.ts` 的 `GridSnapshotBranch`）。所以容器不能是树上的分支：只有一个分节的容器下一次操作就塌了。
- **隐藏的面板不进呈现树**（`layout-project.ts`），停放的内容不卸载（输出 10、16、17）。不活动容器的分节照此处理，不需要新机制；但现在“隐藏”只有具名面板能用，判定散在约 13 处直接读 `hidden` 的地方。
- **按具名面板名字挂的规则约 37 处**：宽度约束、放不下时的收走顺序（`COLLAPSE_ORDER`）、骨架判定（`fitsSkeleton`）、`focusedPart`、视图的 `location` 等。
- **旧记录**：合法但不合骨架的记录回落默认树、下次保存覆盖（`layout-doc-store.ts` 的 `outsideSkeleton`，2026-11-06 起）；而版本不对的记录走“损坏”那条路，之后这个窗口不再保存（`guarded`）。
- **已有一份审查过的容器身份设计**：[工作台外壳的抽象](workbench-shell-abstractions.md#3-容器身份审查第-14-条) 第 3 节的三类容器、id 命名空间、按实际成员决定出不出现、标题与图标的回落。本稿沿用它，只把它放进单树模型。
- **视图**：内置三个：资源管理器、会话（侧栏），对话（右栏）。

## 方案

### 1. 模型：容器是记录里的一份清单，树上只有普通面板

- 树照旧：侧栏、右栏、底部面板是骨架上的三个**区域**，区域里是普通的工具面板。容器的身份不放在树上，放在布局记录的 `containers` 里：`{id, region, members: 面板 id[], ...}`，每个区域另记当前的 `active` 容器。规范形怎么塌分支都不影响身份。
- **分节**就是区域里的一块面板，属于一个容器。容器里分节的先后就是它们在树里的先后。
- **可见**只有一个判定：面板没被隐藏、所在容器是它区域的当前容器。现在直接读 `hidden` 的地方先全部改走 `isNodeShown`（切片 0，行为不变），容器的条件只加在这一处。
- **区域**取代具名面板的名字：`regionOf(doc, panel)` 给出 `sidebar`、`auxiliarybar`、`panel` 或 null。宽度约束、收走顺序、骨架判定、`focusedPart`、视图的 `location` 都改按区域，不再按面板名。
- **区域的约束**来自区域本身与当前容器里视图声明的并（取并的规则同现在）。切换容器不改尺寸意图；新容器的约束更紧时呈现时夹，切回来恢复。
- **容器身份**照 [外壳抽象第 3 节](workbench-shell-abstractions.md#3-容器身份审查第-14-条)：
  - 三类 id 互不重叠：没写 `container` 的视图属于自己的**隐式容器** `view:<视图 id>`；**声明的容器**用插件给的 id；**用户拖出来的** `custom:<UUID>`。
  - 容器出不出现看实际成员：没有成员的不显示入口，不单独记“存在”。用户拖出来的容器空了就从记录里删掉。
  - 标题与图标按固定顺序求：声明的容器用声明的；隐式与用户的容器取第一个可见成员视图的（开发者 2026-11-10 定），悬停写包含的视图。
  - 所以缺省时每个视图各占一个入口，和现在一样；要成组，靠声明或用户拖。

### 2. 分节

- 分节是只有一个标签的工具面板，头只写标题（同现在只有一个视图的面板），视图的标题动作在头上。容器只有一个分节时，头照旧画，标题与动作都在。
- **一个分节一个标签**由文档操作保证：往区域里放标签只会新建分节，不会并进已有分节的标签条。
- **折叠**：侧栏、右栏（上下排）的分节能收成标题行（输出 20）；底部面板（左右排）的分节只能调宽，不能折叠。
- **浮动**：分节浮出来是一个单标签的组；多标签的浮动窗停靠进区域时，每个标签成一个分节，按原顺序。

### 3. 入口

- **侧栏**：活动栏上段列侧栏的容器，按记录里的顺序。点一个：不是当前的就切到它（侧栏隐藏时显示）；是当前的、侧栏可见就隐藏侧栏，侧栏被拖到零或隐藏着就展开（同输出 22 现在对视图的规则）。按下态是“当前容器且侧栏可见”。右键菜单是容器的：移到右栏或底部面板、重置。
- **右栏、底部面板**：区域顶上一条**入口条**，是树上的一个条节点（同活动栏、状态栏，条已有 `barThickness`），右栏是图标、底部面板是标题。条节点给拖动一个现成的排除矩形与插入位，不用另造几何来源。只有一个容器时入口条只写它的标题。
- **活动栏隐藏时**：侧栏的容器只能经命令切换（“切换侧栏容器”），这一步不在侧栏头上另画入口条，写进已知限制。

### 4. 声明

- 插件贡献 `workbench.viewContainers`：`{id, title, icon, location: "sidebar" | "auxiliarybar" | "panel", order?}`。视图声明加 `container?`，可以写别的插件声明的容器；写的容器不存在（插件没装或被禁用）时落回自己的隐式容器，记一条诊断。`location` 只决定隐式容器第一次放在哪个区域。
- 默认布局按声明建：每个出现的容器在它的区域里，成员是声明属于它的视图，各成一个分节。

### 5. 拖动

- **入口条是标签条**（同 t23 的吸收）：拖到两个入口之间，入口滑开留出位置，放下在这里新建一个只含它的用户容器；拖到一个入口上，入口高亮（同并入的盖层），放下成为那个容器最后一个分节。实时布局下**不预览切容器**：判定的几何是拿起时量的，不活动容器的分节那时不在页面上，切过去就判不准（与“隐藏的侧栏在预览里不展开”同一个理由）；放下才切。
- **分节上**：分节的正文沿区域方向分成前后两半，落在哪半就插在它前面或后面，成新分节；没有“添加为标签”。分节标题行同前半。
- **拖入口**：在入口条里换序，或拖到另一个区域的入口条，整个容器搬过去；不能拖进分节区域。
- 当前容器写进拖动的结构键：拖动中被命令切走容器，这一场取消。文档比较（`sameLayoutShape`）也比容器与当前容器，只切换容器的操作照常提交。
- 当前容器被拖空：切到入口条上它前面的那个容器，没有就后面的；区域没有容器时隐藏。

### 6. 持久化

- 记录加 `containers` 与每个区域的 `active`，**不加版本号**。没有这两项、或者区域里有多标签的面板的记录，按“合法但不合骨架”那条路读：默认布局、外壳根写一条诊断、下次保存覆盖它（开发者 2026-11-10 定不迁移）。不走版本不对的路：那条路之后不再保存。
- 用户拖出来的容器连同成员、顺序存在记录里，标题与图标不存，按第 1 节求。

### 7. 命令

- “移动到”的目标是容器或“新容器（某区域）”；`move-view` 的参数随之改。“重置视图位置”回到它声明的容器或隐式容器。
- 打开或聚焦一个视图：切到它的容器，区域隐藏时显示。
- 显示、隐藏侧栏与面板（`set-part-hidden`）不变；`focusedPart` 按区域。

## 备选与取舍

| 做法 | 代价 |
|---|---|
| 容器是树上的分支，一次显示一个子节点 | 规范形要为它开例外，分支要带身份与当前项，nb-layout 多一种节点；尺寸求解、停放、焦点、键盘候选逐处认它 |
| **容器是记录里的清单，树上只有面板（本稿）** | 可见判定多一个条件（收在一处）；按面板名字的规则改按区域 |
| 不活动的容器整棵存在树外 | 拖进不活动的容器、命令移到别的容器，都要在树与树外之间搬，就是单树提案取消的跨树移动 |

## 影响

- **数据**：记录加两项，不加版本号；旧记录回落默认布局并覆盖，原件不备份（同 11-06 的先例）。
- **接口**：插件新增 `workbench.viewContainers`，视图声明加 `container?`；`ViewContext.location` 的含义改成所在区域；`move-view` 的目标改成容器。
- **nb-layout**：可见判定收到 `isNodeShown`；不加节点种类。
- **ADR**：接受时另写一份，部分取代 ADR 0044 决策 3。
- **回滚**：去掉两项字段即回到现在的模型，记录按“不合骨架”回落默认布局。

**验收场景**（写进 Spec 的验收）：

1. 侧栏当前容器有两个分节，一个收成标题行、一个调过高度；切到别的容器再切回来，两个分节原样。
2. 把视图拖到活动栏两个图标之间：图标滑开留出位置，预览里侧栏不切；放下多一个图标，图标是这个视图的，侧栏切到它。
3. 把视图拖到一个图标上：图标高亮，侧栏不切；放下侧栏切到那个容器，它在最后一个分节。
4. 用户拖出来的容器最后一个视图拿走，入口消失、记录里没有它；声明的容器空了入口隐藏，视图回来入口回来。
5. 旧记录（没有容器字段）：打开是默认布局，外壳根有诊断，改一下布局能保存，刷新后是新的布局。
6. 拖动中用命令切侧栏容器：这一场取消，零写入。

## 待定项

1. **默认怎么排：照开发者的例子吗？** 推荐照例子声明一个侧栏容器“项目”，成员是会话与资源管理器；对话现在声明在右栏，推荐不动（例子里它是侧栏第二个图标，搬过来右栏就空了，请开发者确认）。
2. **活动栏隐藏时只能用命令切换侧栏容器**（第 3 节）：推荐先这样，有需要再在侧栏头上画入口条。
3. **切换容器时尺寸**（第 1 节）：推荐不改尺寸意图，新容器的约束更紧时只在呈现时夹。

## 决策记录

- 2026-11-09 开发者：右栏、底部面板也做容器；容器既有插件声明的，也能由用户拖出来。容器里怎么排（分节或面板）、一个容器有几个视图时图标用谁的，暂时定不下，等本稿给出推荐再定。
- 2026-11-10 开发者：待定项“都先按推荐”：容器里是分节；用户拖出来的容器用第一个分节的视图的图标；旧的布局记录不迁移、回落默认树；右栏、底部面板的入口条放在各自的头上，右栏用图标、底部面板用标题。
