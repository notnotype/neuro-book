# 工作台的视图容器

本稿在 [工作台布局：一棵树、按矩形摆放与 nb-layout](workbench-single-tree-layout.md) 之上加回“容器”这一层：活动栏、右栏、底部面板的一个入口切换的是一组视图，不是一个视图。一棵树、规范形、按矩形摆放、两种拖动手感都不变。接受后另写一份 ADR，部分取代 [ADR 0044](../adr/0044-workbench-single-layout-tree.md) 的决策 3（“取消 ViewContainer”），决策 1 不动。过程见 [w00026 t24](../../.agents/works/w00026-layout-package/tasks/t24-view-containers/README.md)，两轮审查的归类在那里。

## 问题

1. **活动栏一个图标只对应一个视图。** 开发者 2026-11-09：“ActivityBar 的一个图标切换的是侧栏这一整个面板，例如第一个图标显示的是‘会话’和‘资源管理器’（也要记住这两个视图的位置和展开收起关系），第二个图标显示的是‘对话’。”现在几个视图同时摆在侧栏里只能把这一列上下分开，分开之后它们一直都在，没法用一个图标整体换走。
2. **右栏、底部面板没有“一组”。** 想在两组视图之间切换，只能把视图一个个拖来拖去。
3. **ADR 0044 取消容器的理由是“内置视图目前不依赖”。** 那条决策解决的是“布局分成几棵树、移动要跨树”；用户要成组切换是另一件事，开发者这次的要求推翻了“不依赖”。跨树移动不能回来。

## 目标与非目标

**目标**

- 侧栏、右栏、底部面板三处，各一次显示一个容器；点入口切换整个容器。容器里的几个视图同时可见，位置、大小、展开收起由这个容器记住，切走再切回来是原样。
- 容器由插件声明，也能由用户拖出来（开发者 2026-11-09 定）。
- 树、规范形、节点种类都不变。
- 分两步交付：第一步侧栏（入口就是活动栏），第二步右栏与底部面板（它们的入口条另做一轮设计，见第 3 节）。

**非目标**

- 容器里隐藏单个视图（VS Code 的视图右键“隐藏”），容器嵌套容器，插件开新的容器栏，编辑组进容器。
- 浮动窗是容器：浮动的单位仍是带标签的组。

## 当前行为与证据

- **规范形会吃掉分支上的身份**：每次结构操作都把同轴嵌套展平、单子分支塌陷（`packages/nb-layout/src/layout-doc.ts` 的 `normalizeTree`、`detachNode`），分支快照只有 id、方向、尺寸、子节点。所以容器不能是树上的分支。
- **三片具名面板是骨架的锚**：`sidebar`、`auxiliarybar`、`panel` 拖空只隐藏、不移除，默认树里一直在，所以骨架判定（`fitsSkeleton`）能按固定形状写；区域的隐藏只能写在具名面板上（`setPanelHidden`）。产品里没有 `location: "panel"` 的视图，底部区域默认就是空的；视图目录陆续交进来，启动的一瞬间三个区域都空。
- **隐藏的面板不进呈现树**（`layout-project.ts`），停放的内容不卸载（输出 10、16、17）。现在直接读 `hidden` 的地方有 13 行。
- **收起策略只配给叶**（`layout-project.ts` 的 `assignByParent`），分支没有；grid 本身支持分支带收起（`GridBranch.collapse`）。
- **按具名面板名字挂的规则**：工作台约 13 个文件 36 行，nb-layout 另有 10 行。
- **旧记录**：合法但不合骨架的记录回落默认树、下次保存覆盖（`layout-doc-store.ts` 的 `outsideSkeleton`）；版本不对的记录走“损坏”那条路，之后不再保存。回落时 `carryDynamicTabs` 能把开着的编辑器标签带过去。
- **已有一份审查过的容器身份设计**：[工作台外壳的抽象](workbench-shell-abstractions.md#3-容器身份审查第-14-条) 第 3 节。本稿沿用它，只把它放进单树模型。
- **视图**：内置三个：资源管理器、会话（侧栏），对话（右栏）。

## 方案

### 1. 模型：锚、分节、容器

- **锚**：三片具名面板留在树上，只当区域的锚：没有标签，不属于任何容器，**永远不进呈现树**。骨架判定照旧按锚的位置判。区域的状态都记在锚的记录上：隐藏（`hidden`，同现在）、拖到零（区域级的收起）、入口顺序、当前容器。
- **分节**：区域里与锚同一列（底部面板是同一排）的普通工具面板，只有一个标签，属于一个容器。归属记在分节自己的面板记录上（`container`）。分节的 id、记录跟着结构操作走，归属不用另外同步：搬出区域时清掉，搬进区域时写上目标容器。容器里分节的先后就是它们在树里的先后。
- **可见**只有一个判定：面板没被隐藏；是分节的话，所在容器是区域的当前容器、区域没隐藏。直接读 `hidden` 的 13 行先改走 `isNodeShown`（切片 0，行为不变），容器的条件只加在这一处。投影、收走队列、份额、缝、键盘候选、有效可见、停放随之成立（第二轮审查用实验核过）。
- **区域**：`regionOf(doc, panel)` 按“和哪片锚同一列（排）”给出 `sidebar`、`auxiliarybar`、`panel` 或 null；原来按面板名字的规则改成按区域问，区域由锚定位。
- **区域级的拖到零**：投影把收起策略配给区域在呈现树里的那个节点（一块叶或一个分支），零宽记在锚上；分节自己的 `collapsed` 只表示“收成标题行”。切换容器时清掉区域的零宽，区域展开。
- **区域的约束**来自区域本身与当前容器里视图声明的并。切换容器不改尺寸意图，新容器的约束更紧时呈现时夹，切回来恢复（开发者 2026-11-10 定）。
- **容器身份**照 [外壳抽象第 3 节](workbench-shell-abstractions.md#3-容器身份审查第-14-条)：
  - 三类 id 互不重叠：没写 `container` 的视图属于自己的**隐式容器** `view:<视图 id>`；**声明的容器**用插件给的 id；**用户拖出来的** `custom:<UUID>`。
  - 容器出不出现看实际成员：没有成员的不显示入口。用户拖出来的容器空了，从锚的入口顺序里删掉。
  - 标题与图标按固定顺序求，不存：声明的容器用声明的；隐式与用户的容器取第一个可见成员视图的，悬停写包含的视图（开发者 2026-11-10 定）。

### 2. 分节

- 分节的头只写标题（同现在只有一个视图的面板），视图的标题动作在头上；容器只有一个分节时头照旧画。
- **一个分节一个标签**由文档操作保证：往区域里放标签只新建分节，不并进已有分节。新分节的 id 在提交时生成并存进记录；默认布局按声明建的分节 id 由视图 id 定（同一份声明算出同一棵树）。
- **折叠**：侧栏、右栏（上下排）的分节能收成标题行（输出 20）；底部面板（左右排）的分节只能调宽，不折叠。
- **浮动**：分节浮出来是一个单标签的组；多标签的浮动窗停靠进区域时，每个标签成一个分节，按原顺序（nb-layout 加一个“拆成几块”的操作）。

### 3. 入口

- **侧栏**（第一步）：活动栏上段列侧栏的容器，按锚上的入口顺序。点一个：不是当前的就切到它，区域隐藏或拖到零时展开；是当前的、侧栏可见就隐藏侧栏，侧栏拖到零就展开（同输出 22 现在对视图的规则）。按下态是“当前容器且侧栏可见”。右键菜单是容器的：移到右栏或底部面板、重置。
- **活动栏隐藏时**：侧栏的容器只能经命令切换，是已知限制（开发者 2026-11-10 定）。
- **右栏、底部面板**（第二步）：入口条放在各自的头上，右栏用图标、底部面板用标题（开发者 2026-11-10 定）。几何怎么来留给第二步的设计：第二轮审查查出“入口条作树上的条节点”和现有的条规则有六处冲突（条两侧的缝不能拖、区域拖不到零、放不下时只收面板不收条、校验写死两个条、默认右栏多一行重复的标题），第二步先解决这些再做。

### 4. 声明

- 插件贡献 `workbench.viewContainers`：`{id, title, icon, location: "sidebar" | "auxiliarybar" | "panel", order?}`。视图声明加 `container?`，可以写别的插件声明的容器；写的容器不存在（插件没装或被禁用）时落回自己的隐式容器，记一条诊断。`location` 只决定隐式容器第一次放在哪个区域。
- 默认布局按声明建。内置声明一个侧栏容器“项目”，成员是会话与资源管理器；对话留在右栏，是它的隐式容器（开发者 2026-11-10 定）。默认的底部区域没有容器，锚隐藏着。

### 5. 拖动

- **活动栏是侧栏容器的入口条，也是标签条**（同 t23 的吸收）：拖到两个入口之间，入口滑开留出位置，放下在这里新建一个只含它的用户容器；拖到一个入口上，入口高亮（同并入的盖层），放下成为那个容器最后一个分节。
- **预览从不切换当前容器**：判定的几何是拿起时量的，不活动容器的分节那时不在页面上，切过去就判不准（与“隐藏的侧栏在预览里不展开”同一个理由）。来源是当前容器唯一的分节、来源收起后容器空了时，预览里区域就是空的，放下才切到相邻的容器。
- **分节上**：正文沿区域方向分成前后两半，落在哪半就插在它前面或后面，成新分节；没有“添加为标签”。分节标题行同前半。要改 nb-layout 的三处接口（落点规则、落点分区、键盘候选）。
- **拖入口**（推荐，见待定项 1）：只含一个视图的入口，拖它就是拖这个视图的标签（现在的验收 14 不变）；含几个视图的入口只能在入口条里换序，或拖到另一个区域的入口条，整个容器搬过去，用落点指示，不进实时布局。
- 当前容器写进拖动的结构键：拖动中被命令切走容器，这一场取消。文档比较（`sameLayoutShape`）也比归属与当前容器，只切换容器的操作照常提交。
- 当前容器被拖空（放下之后）：切到入口条上它前面的那个容器，没有就后面的；区域没有容器时锚隐藏。

### 6. 持久化

- 不加版本号。锚的记录加入口顺序与当前容器，分节的记录加 `container`。锚上有标签、区域里有多标签面板、分节没有归属的记录，按“合法但不合骨架”读：默认布局，开着的编辑器标签带过去（`carryDynamicTabs`），外壳根写一条诊断，下次保存覆盖它（开发者 2026-11-10 定不迁移）。
- 用户拖出来的容器只以它的 id 出现在入口顺序与分节的归属里，标题与图标按第 1 节求。

### 7. 命令

- “移动到”的目标是容器或“新容器（某区域）”；`move-view` 的参数随之改。“重置视图位置”回到它声明的容器或隐式容器。
- 打开或聚焦一个视图：切到它的容器，区域隐藏或拖到零时展开。
- 显示、隐藏侧栏与面板（`set-part-hidden`）不变，仍写锚的 `hidden`；`focusedPart` 按区域。
- 最大化、浮动作用于分节；切换容器时焦点留在原处，原来的焦点在被切走的分节里时交给新容器的第一个分节。

## 备选与取舍

| 做法 | 代价 |
|---|---|
| 容器是树上的分支，一次显示一个子节点 | 规范形要为它开例外，分支要带身份与当前项，nb-layout 多一种节点；尺寸求解、停放、焦点、键盘候选逐处认它 |
| **锚加分节，归属记在分节上（本稿）** | 可见判定多一个条件（收在一处）；按名字的规则改按区域；投影给区域配收起策略 |
| 容器清单单独存，列出成员面板 id | 每个结构操作（浮出换 id、关掉占位删面板、拖出区域）都要同步清单（第二轮审查 R5） |
| 不活动的容器整棵存在树外 | 拖进不活动的容器、命令移到别的容器，都要在树与树外之间搬，就是单树提案取消的跨树移动 |

## 影响

- **数据**：锚与分节的记录各加字段，不加版本号；旧记录回落默认布局并覆盖，开着的编辑器标签带过去。
- **接口**：插件新增 `workbench.viewContainers`，视图声明加 `container?`；`ViewContext.location` 的含义改成所在区域；`move-view` 的目标改成容器。
- **nb-layout**：可见判定收到 `isNodeShown`；投影给区域节点配收起策略；落点规则、落点分区、键盘候选支持“前后两半”；加“把多标签组拆成几块”的操作。不加节点种类。
- **ADR**：接受时另写一份，部分取代 ADR 0044 决策 3。
- **回滚**：代码退回后，旧代码会把新记录原样读入（锚与分节都合它的骨架），所有容器的分节摊开显示；回滚时要连同清掉布局记录（回到默认布局）。v2 未发布，记录只在开发者本机。

**验收场景**（写进 Spec 的验收；其余单条行为由输出条目验收）：

1. 侧栏当前容器有两个分节，一个收成标题行、一个调过高度；切到别的容器再切回来，两个分节原样。
2. 把视图拖到活动栏两个图标之间：图标滑开留出位置，预览里侧栏不切；放下多一个图标，图标是这个视图的，侧栏切到它。
3. 把视图拖到一个图标上：图标高亮，侧栏不切；放下侧栏切到那个容器，它在最后一个分节。
4. 用户拖出来的容器最后一个视图拿走，入口消失；声明的容器空了入口隐藏，视图回来入口回来。
5. 默认布局的侧栏（“项目”两个分节）能拖到零；拖到零后点它的图标展开。单分节的容器拖到零、切走再点回来，侧栏是展开的。
6. 当前容器唯一的视图拖到别处：预览里侧栏是空的、不切容器；放下后切到相邻的容器。
7. 旧记录（锚上有标签）：打开是默认布局，开着的编辑器标签还在，外壳根有诊断，改一下布局能保存，刷新后是新的布局。
8. 底部区域没有容器：“移动到”选它能放进去并显示；拿走最后一个分节后其余布局不变、还能保存。
9. 拖动中用命令切侧栏容器：这一场取消，零写入。

## 待定项

1. **拖入口能去哪**（第 5 节，第二轮审查 R7）：推荐只含一个视图的入口拖它就是拖视图，含几个视图的入口只能在入口条之间走（换序、换区域），不能拖进分节区域，也不进实时布局。另一种是多视图的入口也能拖进别的区域的分节里，那要一种新的拖动来源（整组分节）和它的预览，部件多不少。

## 决策记录

- 2026-11-09 开发者：右栏、底部面板也做容器；容器既有插件声明的，也能由用户拖出来。容器里怎么排（分节或面板）、一个容器有几个视图时图标用谁的，暂时定不下，等本稿给出推荐再定。
- 2026-11-10 开发者：待定项“都先按推荐”：容器里是分节；用户拖出来的容器用第一个分节的视图的图标；旧的布局记录不迁移、回落默认树；右栏、底部面板的入口条放在各自的头上，右栏用图标、底部面板用标题。
- 2026-11-10 开发者：第一轮审查后的改稿（容器是记录里的清单、缺省一个视图一个入口、拖到入口不预览切容器、分节规则、旧记录不加版本号）与三个新待定项“都按推荐”：默认声明侧栏容器“项目”（会话、资源管理器），对话留在右栏；活动栏隐藏时只用命令切换侧栏容器；切换容器不改尺寸意图，只在呈现时夹。
