# 通用编码基线

本文件只保存所有源码改动都必须应用的规则；语言和领域规则由 [`README.md`](README.md) 路由。

## 实现

- 先读相邻实现、测试、配置和公开合同，沿用已有模块、命名、错误、日志和测试工具。抽象必须减少真实重复、复杂度或所有权歧义；单调用 wrapper 不进入代码库。
- 外部输入在系统边界解析、校验和归一化。失败尽早、明确且可诊断；缺配置、权限、引用或前置产物时返回现有错误合同。
- 保存、网络、进程、迁移和跨语言边界必须定义成功、失败、清理与重试所有权。迁移完整切换消费者并删除旧入口。
- 热路径避免可省的分配、复制、序列化、目录扫描和重复计算；缓存必须有失效与所有权合同。
- 日志使用结构化字段和自然语言消息；秘密和大正文只记录尺寸、摘要或脱敏标识。
- 判“还是原来那个目录或文件”时，身份不能只比设备号与 inode：删除后重建可能复用 inode（ext4 上实测），要连创建时间一起比；比较两个同时存在的对象（打开的 fd 与它的路径）不受影响。

## 注释

注释写给之后读代码的人和 Agent：他们看得到代码，看不到写代码时的推理。

- **写什么**：代码里看不出来的原因与约束——调用合同、所有权、时序、平台差异、安全边界、资源生命周期、非显然的取舍，以及让这条理由失效的条件。公开接口写用途与失败语义（何时拒绝、返回 null 表示什么、调用方还需不需要做什么）。
- **不写什么**：复述代码在做什么；复述 Spec 的行为规则（链接 Spec，只写 Spec 里没有的实现事实）；中间尝试与改动经过（属于提交信息）；推测的后续工作。
- **写在哪里**：写在拥有这条原因的地方。模块头写职责和贯穿全文件的约束；公开接口写调用方需要的语义；分支与异步回调写“为什么在这里、为什么是这个先后”。读者要推演几个回调的先后、或要找全一个变量的所有写入点才能看懂的代码，先改结构消除它（例如把分散的状态改写收拢成一处计算），改不掉再写清楚。
- **用词**：用平常的中文和代码里的英文标识符；Promise 的 resolve、reject、settle 直接写英文或写“完成”“失败”，不另造译名（如“兑现”）；Spec 里已在用的词（如“收口”“结算”）按 Spec 的含义沿用，不再引入新的自造词。一句只说一件事，不在一句里套多层括号。
- **命名先于注释**：名字说清楚做什么，注释说清楚为什么。两个名字只差一个词、语义却不同时改名，不靠注释区分。
- **例外：示例插件**：`packages/neuro-book/plugin-sdk/examples/` 的注释是教学材料，读者是第一次写插件的人。可以逐步讲解这一步做什么、为什么、不这样会怎样，并链接 Spec（写 Spec 路径与条目编号）；讲解放在代码旁，随场景测试一起改，示例的 `README.md` 只做目录、概念与阅读顺序，不贴代码片段。产品代码的注释规则不变。

样例：`packages/neuro-book/src/server/start.ts`（退出码在一处由事实算出，两条启动失败通知的先后写在它们的定义处，取值规则链接 Spec）。

## 文字用哪种语言

依据 [ADR 0034](../../adr/0034-language-policy.md)；这里只列写代码时要遵守的部分。

- 给用户看的文字（界面文字、失败说明）经消息目录本地化；目录机制落地前沿用现有写法（[w00028](../../../.agents/works/w00028-i18n/README.md)）。
- 开发诊断（异常 message、诊断事件 message、日志）用英文。现有的中文诊断在 [w00031 t04](../../../.agents/works/w00031-language-policy/tasks/t04-migration/README.md) 迁移前保持原样，不顺手改。
- 程序需要区分的失败用所属错误域的稳定码；结构化诊断用既有的 `event`；不按诊断文案分支。
- 界面不拿原始 `Error.message` 和诊断性的 `reason`、`detail` 当主文案，它们只能放进“详情”；经界面投影生成的用户文字不在此列。
- 领域工具的失败在 `details` 里给结构化的 `code`；OMP 原生 `read`、`edit` 的错误文本不改。给模型的其它文字按 ADR 0034 决策 4。
- 给模型的文字的长期目标是 i18n，以后可以为不同语言各备一套提示词；现在系统提示词、工具说明这类新写的提示词用中文，是因为方便。以后改造的难度不大，只是工作量大，这个代价可以接受（开发者 2026-10-28）。所以写提示词时不要把中文写死进程序逻辑：不按提示词文字分支，提示词集中放在 Profile、规则文件或常量里，方便以后整套替换。

## 模块与职责

- 新职责进入拥有该职责的现有模块。除已登记硬上限外，按所有权、状态机和平台边界判断是否拆分，不用机械行数代替设计审查。

完成标准：本次改动沿用一个现有所有权模型，每个外部边界、失败路径和资源生命周期都有实现或测试证据。
