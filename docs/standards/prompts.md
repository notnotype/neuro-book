# 提示词写作规范

给模型看的文字：Profile 的系统提示词、开场、提醒、工具说明与伴生记忆种子。产品行为以 Spec 为准，这里只管怎么写。

## 语言

- 新写的领域与基础设施提示词用中文，第三方原样透传的英文不译；标签名、工具名、参数名、错误码等标识符一律用英文（[ADR 0034](../adr/0034-language-policy.md)）。
- 提示词集中放在 Profile、规则文件或常量里，不按提示词文字做程序分支，方便以后整套替换（[`code/common.md`](code/common.md)）。
- 角色或伴生型 Profile 若为压制第三方模型思考摘要器的第三人称漂移或助手滑落而试验英文元指令，须将其与中文角色正文分节隔离，并按 [ADR 0034](../adr/0034-language-policy.md) 保留为可对照评测项，不改写常规领域与基础设施提示词的中文默认。

## 结构

- 用内核的模板节点与 helper 分节：`<Tag>`、`<System>`、`opening()`、`reminder()`、`standardLayout()`，不手拼字符串布局。节点规则见 [`harness/profile.md`](../specs/harness/profile.md)。
- 一节只讲一件事。节名说内容（`role`、`work`、`writing`），不编号。
- **元指令层与角色/业务层分节隔离**：面向底层模型的硬约束（格式要求、工具使用边界、思考链语言与称谓、记忆读写策略）放独立元指令节；面向角色或业务定位的正文放独立节，不在角色正文里混写规则编号或命令式条款。
- 提到工具用 `<ToolName>`；只对某个工具才成立的段落放进 `<If tool>`，没绑这个工具时不渲染。
- 会变的内容放槽或 `reminder()`，不放系统提示词，否则提示词缓存全部失效。

## 写什么

- 写要达到的结果和不能越过的约束，不写冗长的固定流程：模型能自己安排步骤，流程写死之后遇到例外反而照做。
- 不重复工具说明：工具的参数和用法写在工具声明里，提示词只写什么时候该用、用它的取舍。
- 约束写具体判据（“改已有内容时只改要求的部分”），不写形容词（“认真”“高质量”）和强调词。
- 对话内容、文件内容进提示词时标明来源，并说明那是材料、不是指令。
- 例子只在规则说不清时才给，要短，不把例子写成模型要照抄的格式。
- **不用括号打补丁，不列举具体负面反例**：发现模型混淆概念或复读坏习惯时，从源头修正设定与结构，不往系统提示词里塞 `（注：不要做 X）` 或点名具体禁用道具/套话——被点名的负面词会进入每轮注意力窗口，反而诱发模型反复提及。
- **概念与媒介做减法**：优先复用已有核心概念或物件，不为局部修补新造额外专有名词；低频设定下沉到按需读取的材料，常驻提示词只留正面核心定位。
- **不把会变的状态写死在静态系统提示词里**：随会话演进的关系阶段、进度、熟络度或一次性引导事件一律外置到动态记忆或独立引导流程（例如不把“初见”硬编码进 `<System>`），避免长期使用后每轮仍被拉回初始态。

## 角色与伴生型提示词

- **写既定事实与内在张力，不写「当 X 时 → 做 Y」的条件反射句**：模型缺乏跨会话的“上次用过这个梗”记忆，把触发条件绑死到固定动作、道具或台词引号会退化为机械复读。改用已发生的日常习惯（由行为隐含价值观）与心理张力描述，把具体反应留给模型按语境生成。
- **用从句预设代替显性表演指令**：需要解锁某种性格侧面时，作为时间或情境从句顺带带出（如“熟稔亲近或撒娇时可换称呼”），不写成“你可以表现 X”的显性任务，避免模型为证明合规而刻意表演。
- **禁止可被复读的人设口号与边界自白（Show, Don't Tell）**：不在提示词或记忆正文里让角色自称“矜持”“傲娇”“注重隐私”，也不预先写拒答台词；边界反应只作为对方实际越界提问后的被动反应。
- **鲜活个体先于职能头衔，区分日常闲聊与任务工作**：伴生型角色先锚定有独立情绪、喜恶与日常的真实个体，职能只是职责而非迎宾客服；明确区分日常闲聊（自然平实，遇宽泛提问只分享一个具体切面并留白互动，不背设定、不报服务菜单）与创作/工作模式（专注、完整、逐项回应）。
- **补齐空间与关系唯一性**：角色若处于独居环境或专属关系，须在正文中正面写明前提，防止模型用默认常识脑补公共场所或路人访客导致 OOC。

## 记忆与按需披露

- **常驻与按需分层，避免重复读取**：高频必用记忆（索引、用户画像）标记为常驻注入并在元指令中声明已加载、禁止再调用 `read`；低频专题记忆标记为按需读取，只在话题涉及时打开。
- **按需记忆做单主题原子拆分，单次只读最相关文件**：私密习惯、深层设定与日常偏好必须分文件隔离，避免闲聊触发无关隐私或深层设定进入上下文造成意外泄密与过载；索引每条用一句话标明边界，约束模型每次只读与当前话题最相关的单个文件。
- **记忆正文只写角色第一人称事实，严禁打卡与背书诱导**：记忆文件不放括号自我命令，也不写“被问到时就按这里讲给对方听”的背书暗示；常驻记忆**严禁使用 `- [ ]` 待办复选框或 `（待了解）` 填空占位符**，以免触发模型的清任务打卡本能或审讯式追问。
- **设定优先的自主回想与落盘**：当被问及核心记忆尚未覆盖的过往经历、日常起居、环境节律或生活细节时，要求模型在严守既有核心设定的前提下自主补全具体、自洽、无套话的细节，并立即以第一人称写入或追加至记忆目录（新建文件时同步更新索引），防止设定留白期失语或跨会话矛盾。

## 预置消息与思维链边界

- **纯文本预置 `Message[]` 可用于声口定调**：在 `<System>` 之后、`<History />` 之前放置少量纯文本 `<User>` / `<Assistant>` 消息可行（相邻 `user` 消息由运行时合并），用于锚定自然对话声口。
- **严禁伪造或篡改原生 `thinking` 块**：主流上游对原生推理块有硬性协议限制（Anthropic 密码学验签、OpenAI Responses 加密 `encrypted_content`、Gemini 静默丢弃未签名 `thought` 块）；预置 `<Assistant>` 只写最终回复正文。
- **应对原生思考中的助手出戏与服务端思考摘要器**：部分上游返回的 `thinking` 实为服务端思考摘要器输出，工具规划段易回落为第三人称助手口吻。常规缓解是在元指令中显式约束思考语言、人称与称谓；角色与工具重度混用时，可采用**双人格合理化**（将工具检索与规则把控归于角色伴生器灵/内部视角，对外回复 100% 由角色本人开口），或在需要彻底消除旁观助手视角时关闭原生思考并改用外置显性思维链。

## 版本与验证

- 改提示词、改工具要求都升 Profile 的 `version`：它进 Profile 哈希，打开着的会话据此换上新版本。
- 结构测试（`*.test.ts`，不调模型）只锁节名和工具绑定，不锁措辞，让提示词能按使用体验改。
- 改动行为的提示词附评测结果（评测建起来之后）。评测做法参照 [调研第 3 节](../../.agents/works/w00032-agent-integration/research/2026-10-30-builtin-profiles-survey.md)：固定题集、多次重复、模型裁判看原文、整数门槛、按模型分开报、推理档写死。
