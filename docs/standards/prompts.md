# 提示词写作规范

给模型看的文字：Profile 的系统提示词、开场、提醒、工具说明。产品行为以 Spec 为准，这里只管怎么写。

## 语言

- 新写的提示词用中文，第三方原样透传的英文不译（[ADR 0034](../adr/0034-language-policy.md)）。
- 提示词集中放在 Profile、规则文件或常量里，不按提示词文字做程序分支，方便以后整套替换（[`code/common.md`](code/common.md)）。

## 结构

- 用内核的模板节点与 helper 分节：`<Tag>`、`<System>`、`opening()`、`reminder()`、`standardLayout()`，不手拼字符串布局。节点规则见 [`harness/profile.md`](../specs/harness/profile.md)。
- 一节只讲一件事。节名说内容（`role`、`work`、`writing`），不编号。
- 提到工具用 `<ToolName>`；只对某个工具才成立的段落放进 `<If tool>`，没绑这个工具时不渲染。
- 会变的内容放槽或 `reminder()`，不放系统提示词，否则提示词缓存全部失效。

## 写什么

- 写要达到的结果和不能越过的约束，不写冗长的固定流程：模型能自己安排步骤，流程写死之后遇到例外反而照做。
- 不重复工具说明：工具的参数和用法写在工具声明里，提示词只写什么时候该用、用它的取舍。
- 约束写具体判据（“改已有内容时只改要求的部分”），不写形容词（“认真”“高质量”）和强调词。
- 对话内容、文件内容进提示词时标明来源，并说明那是材料、不是指令。
- 例子只在规则说不清时才给，要短，不把例子写成模型要照抄的格式。

## 版本与验证

- 改提示词、改工具要求都升 Profile 的 `version`：它进 Profile 哈希，打开着的会话据此换上新版本。
- 结构测试（`*.test.ts`，不调模型）只锁节名和工具绑定，不锁措辞，让提示词能按使用体验改。
- 改动行为的提示词附评测结果（评测建起来之后）。评测做法参照 [调研第 3 节](../../.agents/works/w00032-agent-integration/research/2026-10-30-builtin-profiles-survey.md)：固定题集、多次重复、模型裁判看原文、整数门槛、按模型分开报、推理档写死。
