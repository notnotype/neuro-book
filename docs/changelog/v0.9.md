# 0.9.x 更新日志

更早和更晚的版本见[更新日志索引](./index.md)。当前版本说明位于仓库根目录的 `RELEASE.md`。

## 0.9.0-canary - 2026-08-02

这一版把 AI 助手从「一问一答」变成了「能接整活儿」：写正文、逐条挑毛病、按意见改稿这一整套流程，现在可以打包成一条命令交给它，跑的时候还能看进度、随时叫停。打开应用会先进入作品书架，也可以直接把图片交给 AI；另外新增了 NeuroBook 账号和云备份，文档站上线了英文版。

### 新功能

**作品入口改成书架**

打开 NeuroBook 后先进入作品书架，不再自动闯进某一本书。可以从这里新建、删除或打开作品，管理封面，并进入用户资产。

**把图片直接交给 AI**

现在可以把图片拖进聊天框、从剪贴板粘贴或通过文件选择器添加，也可以重新插入当前对话或作品中的图片。多张图片会按正文中的顺序发送；上传失败时可以重试或移除，点击缩略图后可以查看或下载原图。

**AI 助手配置更容易查找**

模型设置改成左右分栏：左边搜索并选择助手，右边只显示当前助手的模型和运行设置。列表会标出编译状态、覆盖项、未保存修改和当前默认项，切换助手不会丢掉尚未保存的草稿。

**让 AI 跑完一整套写作流程**

新增「工作流」——把多个步骤打包成一条命令，AI 会一步步跑完，不用你在旁边一句句催。内置七条：四条给写小说用（整章的「写 → 审 → 改」循环、跨章节一致性检查、拆书分析——把一本书按章拆开逐章看钩子和爽点、角色 200 问批量深挖），三条通用（多角度并行脑暴、按章提摘要、写完自动评审再改一轮）。AI 想启动工作流要先问过你；你也可以自己发起。会写 TypeScript 的话，把自己的流程放进作品目录下的 `.nbook/agent/workflows/`，也会被认出来。

**顶栏多了「任务」面板**

工作流在后台跑，不占着聊天窗口。顶栏图标会显示当前有几个在跑，点开能看每个任务的进度、取消它、复制结果、清掉已经完成的。聊天里也会出现一张卡片，实时显示流程走到了哪一步。

**写作助手从 15 个精简到 9 个**

原来的助手（技能）名字长、职责碎，得自己记住该按什么顺序用。现在开新书用一个 `novel-setup` 就走完「建项目 → 写世界设定 → 立角色 → 铺时间线」；写正文用一个 `novel-writing` 就走完「规划 → 写 → 改」。不知道该用哪个，看 `novel-guide`，它是整条写作路线的地图，AI 每次开工都会先读它。

**查小说榜单（需要你自己跑数据服务）**

新增 `novel-data` 工具。如果你本机运行着 NovelScope 这个榜单服务，AI 就能查它缓存的起点、番茄榜单和单本书详情，用来做选题参考。查到的数据是缓存快照，会带上抓取时间，太旧会标出来。服务地址默认取 `http://localhost:3000`，可以用环境变量 `NOVEL_DATA_BASE_URL` 改。NeuroBook 自己不提供这个数据服务，官网也没有，没跑服务的话这个工具用不了。

**NeuroBook 账号与云备份**

设置里新增「NeuroBook 账号」，用设备码关联官网账号后，可以把本地实例备份到云端。

两点要先说清楚：备份的是**整个实例**，里面包含配置文件中的 API 密钥，不只是你的稿子；恢复目前也**不是一键完成**的——下载的备份会解压到一个临时目录，需要你先停掉服务再手动替换过去。

**看得见 AI 的上下文里装了什么**

聊天输入框上方那个用量条现在能点开了，打开的是一个可以和聊天并排摆着的浮动窗口，两个标签页：

- **组成**：这一轮发给模型的内容由哪几块构成、各占多少 token，能一层层展开到「具体哪个文件占了多少」。自动压缩会在什么位置触发也标出来了。
- **缓存**：最近几次请求命中缓存的情况，以及没命中的原因，比如「距上次请求 12 分钟，超过 5 分钟的保留期，前缀缓存已过期」。

面板只陈述观察到的现象和原因，不对你下指令。「缓存数据没上报」和「命中率 0%」会分开显示——这两件事在诊断上完全不同。旧会话也能看，只是第一轮里有部分内容分不出类别，面板顶部会说明这一点。

**文档站有英文版了**

文档站新增 12 个页面，覆盖世界引擎、剧情工作台、Markdown 编辑器、llmlint、工作流、AI 的三种模式、运维、设置中心、配色、文件变更历史、账号与备份。首页按「创意写作 IDE」重写，加了站内搜索和 4 张流程图，全站同时提供英文版。

### 改进

- 聊天框里输入 `/fork` 可以用同一个助手另开一条新对话，并记住它是从哪个对话来的。**注意它不会把历史复制过去，新对话是空的**；想在同一个对话里试另一个版本，用消息上的分支切换。
- 书架打开明显变快，因为不再实时统计卷数、章节数、字数和设定条目数。**代价是这些数字暂时从书架上消失了**，改成显示简介。
- 正文检查升级到 3.0.0，内置 360 条规则、默认启用 266 条。规则可以分别检查引号外叙述和引号内对白，并加入密度与句式检查，减少把正常对白混进叙述问题。
- 更新带依赖的写作检查工具时，会继续复用已经安装的依赖，不再因为普通规则或提示词更新重复安装；工具列表现在也会显示版本号。
- AI 配置预览、类型检查和编译使用的临时缓存现在分别受限，完成或失败后立即清理，异常中断留下的目录会在过期后回收。在开发机上，这轮受控清理一次性回收了 17.34 GB。
- Windows 内置运行镜像不再整棵复制开发依赖和文档生成物：核心运行文件从早期约 3 万个、1.2 GB 收敛到 3,231 个、约 127 MiB，本地编译 AI 配置、数据库和图片处理能力仍然保留。
- 安装、更新、启动或卸载同时发生时，后来的操作会明确停下；上一次操作意外中断后，管理工具会先恢复到可确认的版本，再继续新的操作。
- 发布页会等 Windows、Linux、macOS 安装包和容器镜像都完成校验后再公开。构建失败的候选仍会保留给开发者排查，但不会出现在普通下载入口，也不会占用正式容器版本号。
- 打开作品时会显示“准备作品数据、建立连接、加载文件、恢复内容”等真实阶段；断线重连会显示单独状态，不再用假百分比。
- 重新整理下载与安装说明，Windows 免安装包、Linux/macOS 安装器和已有 Bun 的安装方式现在更容易区分。
- 想反馈问题或提功能，GitHub 上现在有中英文贡献指南和按类型分好的提交表单，不用自己想该写什么。安全漏洞请走 GitHub 的私密报告入口，不要发公开 issue。

### 修复

- 重试或改写一条消息后，AI 回复上方终于会出现「‹ 1/2 ›」这样的分支切换器，可以左右切回上一个版本。以前它几乎从来不出现——每次运行都会先记一条内部的「开始运行」记录，正好挡在岔路口，界面就认不出这是一条分支了。跑挂之后重试也算一条分支，所以换了模型重跑成功，仍然能切回去看之前的报错。
- 消息上偶尔冒出来的假分支消失了。以前 AI 调用子助手时留下的内部记录会被当成一条岔路，切过去会把对话截断在那条记录上。
- 消息工具条上的「回退」改名为「从这里分叉」，图标也换成了分支图标。它本来就不删除任何内容——后面的对话会保留成另一条分支，随时能切回来，只是原来的名字和红色图标看着像会删东西。
- 首次展开 AI 面板就会恢复已有对话；没有对话、对话已归档、助手不可用或恢复失败时，会显示准确原因和对应操作，不必先关闭再打开一次。
- 切换作品时会先退出当前编辑工作面，等目标作品真正打开后才加载配置、文件树和写作工具。快速切换作品或对话时，旧请求、旧连接和迟到错误也不会再覆盖当前页面。
- 创建、删除作品或修改封面的结果一时无法确认时，会先重新读取书架，再决定是否允许重试，避免重复创建或重复删除。
- 旧版升级中被误标为“需要确认”的三份 AI 会话会自动修复，原来的作品归属和真实最后活动时间会恢复；真正无法确定归属的会话可以在作品选择页重新绑定，或明确改为不绑定某本书。
- AI 执行命令时设的超时终于真的生效了。以前设 30 秒，实际可能一直跑到 5 分钟。
- 修复自动给对话起标题时会失败的问题：负责写摘要的内置助手原来会跨对话写回结果，被安全检查拦下，标题就一直没生成。
- 缓存命中率之前算错了：分母漏掉了「写入缓存」的那部分，而且用的是整个会话的累计值——第一轮要把全部内容写进缓存，会永久性地把这个数字压低，导致后面看到的读数没有参考价值。现在全应用统一口径。
- 修复窄聊天框中模型选择器挤压工具栏和发送按钮的问题。
- 图片上传、文件快照和 AI 读取图片现在共用解码上限；超大或伪装成图片的文件会在保存前拒绝。
- Windows 便携版关掉命令行窗口后不会再残留进程占着端口，下次启动不会因为「端口被占用」失败。
- 从源码启动开发版时，关闭或中断启动命令也会收掉它启动的后台进程；如果另一个实例仍占用会话数据，现在会提示占用进程和最近活动时间，不再只显示一段锁文件报错。
- Windows 便携版现在可以从包内管理工具卸载自己。默认卸载会保留`data`目录；只有明确选择“同时删除数据”才会连同作品、配置和账号信息一起删除。
- 修复了更新在文件切换、数据升级或清理阶段中断后，下一次操作可能拿到旧安装信息、删错候选文件或无法继续恢复的问题。
- 修复了内置 AI 配置在某些情况下整个编译中断的问题。

### 升级须知

- 使用 NeuroBook 管理工具安装、更新或启动时，会先检查升级计划，再自动备份并升级应用数据库、图片附件和 AI 会话；只有新版本通过启动与版本检查后才确认升级，失败会停止本次新进程并恢复旧数据和旧版本。
- 如果你直接运行源码或解压后的运行包，没有经过管理工具，先执行 `bun run migrate:application-state -- --plan` 查看计划，再执行 `bun run migrate:application-state -- --apply`。迁移中断时不要重新开始，按输出的 runId 选择 `--resume` 或 `--rollback`。
- 使用旧版管理工具  安装的实例需要重新安装程序文件，不能复制旧的`.deploy`目录；Windows便携版请先备份并完整复用`data`目录。
- 如果项目里已有 `.agent/llmlint/session.json`，请先另存想保留的旧审稿记录，再删除该文件；新版审稿台账不会自动迁移旧格式。
- 远程文本检测会把本地缓存未命中的正文片段发送到你配置的外部服务。关闭本地贡献记录不会关闭远程检测；不希望正文离机时，不要运行远程检测。
- 这一版的新功能大多还没做过完整的人工验收（工作流、账号与云备份、上下文检查面板、文档站英文版尤其如此），建议先在不重要的项目上试。
